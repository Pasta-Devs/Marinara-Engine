## What exists today

The shared Pino logger in `lib/logger.ts`, the Logging section of `CONTRIBUTING.md`, the regression runner, the atomic write and backup design in `file-backed-store.ts`, the ordered shutdown in `index.ts`, and the rate-limit handling in `RateLimitAwareProvider` all work well. This PR builds on each of them.

## What this adds

Details for every piece are in `docs/contrib/engine-foundations-overview.md`. Logging rules are in `docs/development/logging.md`, linked from the Logging section of `CONTRIBUTING.md`.

## What stays exactly the same

- No upstream API, export or file is renamed or rewritten. New parameters and fields are optional.
- The `logger` export, `protectTerminalLogger`, `logDebugOverride`, `LOG_LEVEL` and `LOG_DISABLE_REQUEST_LOGGING`. Fastify's `LogController` is extended through a subclass.
- `CONTRIBUTING.md` is only added to: shared logger, error object first, format specifiers and the level table all still apply.
- With an unchanged `.env`, prompts, stored data, storage writes, shutdown and provider retries behave as before.

Default-on changes, for review: internal `app.inject()` calls made before `buildApp` returns are held until registration ends, a package's `activate()` and `selfCheck()` get `InjectDuringRegistrationError` at once if they call an internal route during startup, and a host Fastify lifecycle error (instance already booted or listening) during activation logs one warning and keeps the package's installed version and status instead of rolling it back or persisting `"error"`; the `reqId` field is now `requestId`; request lines drop query strings; a `Client aborted request` line at info; a boot step whose own time is over 15 s logs at warn; `windowsHide` on the Windows probes; named runtime-stop stages are logged; two silent catches now log at warn; the regression runner overrides the three storage variables for each file; for a stored lorebook scan entry that has no text (only old scans), Active Context now shows the entry's stored text instead of an empty string, and agent retries keep such an entry with its stored text instead of dropping it.

## How to turn it off / revert

Opt-in pieces: leave the setting unset. Logging: `LOG_DISABLE_REQUEST_LOGGING=true` and `LOG_LEVEL=warn` as today. The startup inject gate has no switch (`MARINARA_INJECT_DURING_REGISTRATION` is the error code, not a setting); revert its commit to remove it. Each piece is its own commit, newest last: `f69091359` test harness, `dd5845a0a` logging, `e2fbe83b9` performance, `7b43489e6` robustness, `12f4b2552` startup inject gate; the docs commit follows. Revert newest first. The robustness areas touch separate files and can be split into their own PRs if that is easier to review.

The last commit, `feat(tools): add a Dev MCP for inspecting a local Marinara engine`, adds `tools/dev-mcp`: a stdio MCP server that reads prompts and cache reports, follows a request through the logs by `errorId` or `requestId` (using the request trail from the logging commit), checks engine status and runs typechecks and regressions. It is outside the pnpm workspace (`pnpm-workspace.yaml` is unchanged), its `node_modules` and local `.dev-mcp/` state are ignored, and `tools/` is excluded from the Docker image. To check it: `cd tools/dev-mcp && npm install && node test/smoke.mjs`. To leave it out: drop that one commit; nothing else depends on it.

## Open points

- This is a stacked series. The performance commit (`e2fbe83b9`) and the robustness commit (`7b43489e6`, `file-backed-store.ts` and `agent-activation-questions.ts`) log through `logRateLimited` from the logging commit (`dd5845a0a`), so neither can go up as a standalone PR on `staging` without that commit, and the robustness regressions rely on the runner isolation from `f69091359`. Splitting a robustness area out means landing those two first. The startup inject gate (`12f4b2552`) edits the activation `catch` block that the robustness commit extends, so it applies on top of it.
- The host lifecycle handling also covers a package activated from the UI after the server is listening that adds a route the running server lacks: the new version now stays installed and activates on the next start, instead of rolling back. The caller still gets the error. If maintainers prefer the old rollback there, the new handling can be limited to startup with a check on `app.server.listening`.
- `SHUTDOWN_EARLY_FLUSH` and `SHUTDOWN_RUNTIME_STOP_BUDGET_MS` apply to signal shutdowns only. The Advanced Settings restart can use them too if maintainers want that.
- Regression isolation has no opt-out. A `MARINARA_REGRESSION_INHERIT_STORAGE=1` switch can be added on request.
