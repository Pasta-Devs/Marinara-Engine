# 正则脚本

本指南介绍 Marinara Engine 里的正则脚本。正则脚本就是一条查找替换规则，会自动改写聊天里的文字。下面会讲清楚正则脚本能做什么、怎么新建一条、它们在哪个环节生效，以及怎么把它限定给某一个角色。

## 什么是正则脚本

Regex 是“regular expression”（正则表达式）的缩写。正则表达式是一种搜索模式，它按规则找出文字，正则脚本再把找到的文字换成别的内容。不会写代码也能用。

每当一条消息在聊天里流转，正则脚本都会自动跑一遍。它可以在 AI 回复显示出来之前先做清理，可以在你的消息发送之前先改一遍，也可以改动模型实际收到的文字。模式只需要设置一次，之后每条命中的消息都会照做。

看一个简单的前后对比。有些模型会用星号把动作包起来，像这样：

```
*She smiles* Hello there.
```

如果查找模式写 `\*([^*]+)\*`，替换内容写 `$1`，星号就被去掉了，中间的文字保留下来：

```
She smiles Hello there.
```

替换内容里的 `$1` 表示“模式在第一对圆括号里捕获到的那段文字”。`$1`、`$2` 这类记号会经常用到。

常见用途包括：去掉星号、删掉圆括号里的出戏说明、屏蔽某个词，以及修掉某个角色反复出现的排版怪癖。

## 正则脚本在哪里

全局正则脚本都放在 **Presets**(预设) 面板里。点击顶栏的 **Presets** 按钮打开面板，找到标题为 **Regexes** 的板块。板块说明写的是“Find/replace patterns applied to AI output or user input”。

列表里的每一行会显示：

- 脚本名称。
- 一个 **AI** 或 **User** 小标签，表示脚本在哪一侧生效。
- 模式本身，写成 `/pattern/flags` 的形式。
- 一个启停开关。开关即时生效，不用打开编辑器。
- **Edit regex**(编辑正则) 按钮（铅笔图标）。
- **Delete regex**(删除正则) 按钮（垃圾桶图标）。

一条脚本都没有时，列表显示“No regexes yet”。拖动行首的把手可以调整执行顺序。这个列表只显示全局脚本，绑定到单个角色的脚本单独存放，见下面的“角色限定的正则脚本”。

板块标题栏上还有三个图标按钮：

- **Create regex**(新建正则)：打开一条空白的新脚本。
- **Import regexes from JSON**(从 JSON 导入正则)：从文件读取脚本。
- **Export regexes to JSON**(导出正则为 JSON)：把所有全局脚本保存到一个文件里。

## 新建一条正则脚本

新建全局脚本的步骤：

1. 打开 **Presets** 面板，找到 **Regexes** 板块。
2. 点击 **Create regex**，完整的正则脚本编辑器就会打开。
3. 在顶部的输入框里填名称。新脚本的默认名称是“New Regex Script”。
4. 填写下面介绍的各个字段。
5. 点击 **Save**(保存)。会有一个绿色的 **Saved** 提示短暂出现。

编辑器包含以下字段。

### Find Pattern (Regex)

**Find Pattern (Regex)**(查找模式) 就是搜索模式，写的时候不要加两侧的斜杠。占位文字给出了一个示例：`\*([^*]+)\*`。模式无效或者不安全时，输入框下方会出现红色报错，并且无法保存。参见下面的“安全与性能”。

### Replace With

**Replace With**(替换为) 是用来替换每一处命中的文字。留空就等于把命中的文字删掉。捕获到的文字可以用 `$1`、`$2` 等等复用。在捕获记号前面加大小写转换符可以改变字母大小写：

- `\u$1` 把捕获内容的首字母变成大写。
- `\U$1\E` 把整段捕获内容变成大写。
- `\l$1` 把捕获内容的首字母变成小写。
- `\L$1\E` 把整段捕获内容变成小写。

字面意义上的反斜杠文本，比如 `C:\Users` 这样的 Windows 路径，会原样保留。

### Regex Flags

**Regex Flags**(正则标志) 是一组开关按钮，用来改变模式的匹配方式。新脚本默认开启 `g` 和 `i`：

- `g`(全局)：替换所有命中，而不是只替换第一处。
- `i`(忽略大小写)：字母大写小写都能匹配。
- `m`(多行)：让 `^` 和 `$` 能在换行处匹配。
- `s`(dotAll)：让 `.` 也能匹配换行符。
- `u`(unicode)、`y`(粘连) 和 `d`(匹配位置) 属于特殊场景下用的高级标志。

### Trim Strings

**Trim Strings**(裁剪字符串) 是一份可选的纯文本列表，替换完成之后会把这些文字剔除掉。点击 **Add trim string**(添加裁剪字符串) 增加一行，点击 **X** 按钮删除一行。有些固定的文字直接打出来比写模式匹配更省事，这时候就很好用。

### Live Test

**Live Test**(实时测试) 可以在保存之前先验证模式。把示例文本粘进框里，结果会显示在下方的 **Result:** 处。Live Test 只验证查找、替换和裁剪这套逻辑，不检查生效环节、启停状态、角色范围和深度。框下方的说明也是这么写的：“Pattern preview only: placement, enabled state, character scope, and depth are evaluated at runtime”。

模式、替换内容和裁剪字符串里都可以使用 `{{user}}`、`{{char}}` 这类宏。在 Live Test 里它们会解析成示例值，在真实聊天里则解析成真实的名称和文字。想进一步了解宏，参见[宏](../prompts/macros.md)。

## 生效环节：AI Output 还是 User Input

**Apply To**(应用于) 字段决定脚本盯着聊天的哪一侧，至少要保留一个选项，两个也可以同时选。

- **AI Output**(AI 输出)：脚本在 AI 回复显示出来之前生效。
- **User Input**(用户输入)：脚本在你的消息发送出去之前生效。

想整理模型写出来的内容就用 **AI Output**，想修正或重塑自己写的文字就用 **User Input**。

在使用**Individual**(单独回复)群聊模式的**Roleplay**(角色扮演)聊天中，选择**Only Prompt**或**Both**时，应用范围以接收提示词的角色为准：你的消息和其他角色的消息使用**User Input**，即将回复的角色自己此前的回复使用**AI Output**。同一轮群聊中较早生成的回复也遵循这条规则。角色限制仍然决定谁会收到改写后的提示词，因此，如果隐藏想法的脚本排除了旁白，旁白仍会收到原本的想法。要保留已保存的聊天原文，选择**Only Prompt**。

## Apply Mode：Only Display、Only Prompt 还是 Both

**Apply Mode**(应用模式) 选择器在 **Advanced Options**(高级选项) 里面，决定改写在什么时候生效。它和生效环节是两回事。新脚本默认是 **Only Display**。

- **Only Display**(仅显示)：只改你在聊天里看到的内容。保存下来的消息，以及后续回合里模型收到的文字，都不受影响。
- **Only Prompt**(仅提示词)：只改模型收到的内容。聊天显示和保存下来的消息都不变。应用内的提示词预览里看到的也是这一份。
- **Both**(两者)：显示内容和提示词文字都改。

### 该选哪个 Apply Mode

可以按这几条快速判断：

- 只想让回复在屏幕上好看一点：选 **Only Display**。纯外观的调整，这是最稳妥的选择。
- 想改模型读到的内容，比如把模型老是照抄的某个标记去掉：选 **Only Prompt**。
- 想让改动同时体现在屏幕上和模型的上下文里：选 **Both**。

关于自己发出的消息有一点要注意。**User Input** 脚本设成 **Only Display** 或 **Both** 时，改写发生在消息发送出去的前一刻。也就是说，它改掉的是真正保存和发送出去的那条消息，不只是事后的显示效果。自己发出的消息没有“只改显示”这种模式。

## Execution Order 和 Depth

这两项设置都在 **Advanced Options** 里。

**Execution Order**(执行顺序) 是一个数字，数字小的先跑。多条脚本可能命中同一段文字时，这个顺序就很关键。新脚本的初始值是 0，保存时应用会自动分配下一个空闲编号，所以新建的脚本不会互相撞车。也可以在 **Regexes** 列表里拖动行来调整顺序。

**Depth Range**(深度范围) 用 **Min**(最小) 和 **Max**(最大) 两个数字输入框，限定脚本往前追溯多远。深度从最新的消息倒着数：最新的一条是深度 0，再往前一条是深度 1，以此类推。两个框都留空就是不限深度。最小值大于最大值时无法保存。

## 角色限定的正则脚本

正则脚本可以只属于一个或几个特定角色，而不是到处都跑。把脚本限定给角色有两种做法。

第一种在编辑器里操作。开启 **Apply To** 卡片里的 **Specific Characters**(指定角色) 开关，然后在网格里挑选一个或多个角色。开关关闭时，脚本状态是“Applies to all characters”。开关开启后至少要选中一个角色。

第二种是按角色来做。打开一个角色，切到 **Advanced**(高级) 选项卡，找到标题为 **Regex Scripts**(正则脚本) 的卡片。这张卡片只列出绑定到该角色的脚本，并且有自己的 **Create regex**、导入和导出按钮。角色必须先保存，才能给它添加限定脚本。角色尚未保存时，卡片里会有相应提示。

从这张卡片打开完整编辑器会离开角色编辑器。角色有未保存的改动时，应用会先提示，以免改动丢失。

### 按聊天生效的 Scoped Regex Scripts 设置

角色限定脚本不会自动在每个聊天里生效，得由一项按聊天的设置来控制。打开某个聊天的 **Chat Settings**(聊天设置) 面板，只有当这个聊天里至少有一个角色带限定脚本时，标题为 **Scoped Regex Scripts**(限定正则脚本) 的板块才会出现。它有三种模式：

- **Disabled**(禁用)（默认）：关闭角色限定脚本，只跑全局脚本。
- **Exclusive**(独占)：每条限定脚本只改动它所属角色发出的消息。
- **Chat**(全聊天)：每条限定脚本改动聊天里的每一条消息。

模式按钮下方会逐个列出带限定脚本的角色，可以针对当前聊天单独开关每条脚本。这项设置管的是显示侧的脚本。提示词侧的脚本永远跟着实际生成回复的那个角色走。

## 从 SillyTavern 导入正则脚本

Marinara 能读取打包在 SillyTavern 角色卡里的正则脚本。导入角色卡时会出现标题为 **Imported regex scripts**(已导入的正则脚本) 的板块，给出两个选择：

- **Character only**(仅该角色)（默认）：脚本只限定给这一个角色。
- **Global**(全局)：脚本加入 **Presets**，在所有聊天里生效。

单个角色的导入窗口和批量的 **Import from SillyTavern Folder**(从 SillyTavern 文件夹导入) 流程都会出现这个选择。随卡打包的脚本如果模式为空，或者没通过安全检查，导入时会被跳过。也可以用 **Regexes** 板块里的 **Import regexes from JSON** 按钮，导入一个纯 JSON 格式的脚本文件。完整的导入步骤参见[从 SillyTavern 导入](../data/importing-from-sillytavern.md)。

## 安全与性能

每条模式在保存和运行之前都会先经过检查。有些模式极有可能跑得很慢，把应用整个卡住，Marinara 会直接拦下来，并显示这条提示：“Regex pattern is unsafe: avoid nested quantifiers, ambiguous quantified alternatives, and oversized patterns.”改好之前都无法保存。

说得直白一点，避开这几种写法：

- 长度超过 1000 个字符的模式。
- 一个可重复的分组套在另一个可重复的分组里面，比如 `(a+)+`。
- 两个宽泛的通配写法连在一起，比如 `.*.*` 或者 `\s*\w*`。宽泛的通配写法指 `.*`、`\s*`、`\w+` 这类能匹配任意长文字的记号。
- 同一条模式里出现三个及以上的宽泛通配写法，中间夹着别的文字也算。

只有一处重复，比如 `a+` 或者 `(a+)`，没有问题。单独一个宽泛通配写法，比如只有一个 `.*`，也没有问题。

即便模式本身是安全的，应用还会限制单次替换在较长消息上能花的时间。某条脚本在某条消息上耗时过久，应用只会在这条消息上跳过这条脚本，然后继续往下走。脚本不会被关闭，下一条消息还会照常尝试。稳妥起见，新模式启用之前，先用短的示例文本在 **Live Test** 里测一遍。
