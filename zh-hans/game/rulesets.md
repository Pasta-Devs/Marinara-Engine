# Game Mode：使用规则集游玩

规则集告诉 Game Mode 桌面系统如何运作：检定掷什么骰子、人物卡有哪些内容、消耗哪些资源、休息恢复什么，以及某些规则集如何进行整场战斗。本指南介绍如何获取规则集、为游戏选择规则集，以及使用规则集游玩后有哪些变化。没有规则集的游戏采用 Marinara 自身规则，其他 Game Mode 指南介绍了这些规则。

<a id="getting-a-ruleset"></a>

## 获取规则集

规则集有两个来源。5e (SRD 5.1) 等官方规则集从 **Agent Organizer(智能体管理器)** 安装，在那里标为 **Rules**。社区规则集从文件或作者的 GitHub 仓库导入，并按来源归档，例如 `local/ember-roads` 或 `alice/v20`。导入使用的开关和导入智能体相同，即 **Allow custom Agent imports**(允许导入自定义智能体)。这个开关关闭时，导入的规则集不会出现在新游戏中，已经在用的游戏照常运行。使用导入规则集的游戏始终按创建时的确切版本来玩。想自己编写，见[编写 Game Mode 规则集](../extending/writing-rulesets.md)。

### 语言

规则集自身的文本，如技能名称、法术和给游戏主持人（GM）的文本，采用 **Settings**(设置) 中设定的语言。官方规则集只下载该语言的译文，切换语言时再获取新语言的译文，尚无对应翻译时则回退到英语。从文件导入的规则集只保留导入时所用语言的译文；要切换语言，需要重新导入文件。

<a id="choosing-a-ruleset-for-a-game"></a>

## 为游戏选择规则集

**Rules**(规则) 只在安装了至少一个规则集、且正在创建新游戏时出现。它与 **Combat Preference** 分开设置：前者决定检定和人物卡如何运作，后者决定战斗如何呈现。

- 默认的 **Marinara's own rules**(Marinara 自身规则) 使用内置 d20 检定和六属性人物卡。
- **5e (SRD 5.1)** 等**规则集**会显示覆盖范围的简述，以及一行战斗方式说明。自行结算战斗的规则集会明确说明。只提供人物卡的规则集会说明：战斗采用 Marinara 的战斗系统，使用人物卡自身的生命、能量和能力。两者都不提供的规则集会说明战斗采用 Marinara 的战斗系统，并标出你选择的 **Combat Preference**。

规则集在创建游戏时确定，并一直随该游戏保留。之后不能更换或添加。

有些规则集提供 **layers**(层)：Low magic 或 Hard winter 这类具名变体，以开关形式显示在规则集下方，每个都附一行说明其作用。一个层可以让难度更严苛、缩小人物卡上的某项选择、把一些现成条目从人物卡编辑器的选择列表中去掉，并给 Game Master 额外的指令，包括它在设置阶段构建世界时的指令。有些层彼此排斥，向导会禁用你不能再选的那个。游戏开始后层就固定下来，和规则集本身完全一样；人物卡上已经在用、但被某个层去掉的内容会保留。

选好规则集之后，**Party** 步骤会在选择器下方列出你的用户角色和队伍成员，并标明谁 **Has a sheet**(已有人物卡)、谁 **Starts on a blank sheet**(从空白人物卡开始)。人物卡在角色或用户角色编辑器的 **Stats**(属性) 下添加（见[规则集人物卡](../characters/colors-and-stats.md#ruleset-sheets)）。生成世界时，游戏会复制每张人物卡。你在游戏里做的任何改动都不会写回角色或用户角色。没有人物卡的成员会得到一张空白人物卡，所有数值都是规则集的默认值；世界生成绝不会编造数值。

共享的设置文件会记住它的规则集。如果你导入的设置文件用的规则集你没有，或者你的版本更旧，向导会告诉你它用的是哪个规则集，游戏会使用 Marinara 自身规则，除非你安装并选中那个规则集。

<a id="what-happens-in-battles"></a>

## 战斗中会发生什么

规则集在战斗中的作用取决于它的编写方式。设置向导中规则集下方的那行文字会说明它属于以下哪种情况。

| 规则集 | 战斗 |
| --- | --- |
| 自行结算战斗，如 5e (SRD 5.1) | 按规则集自身规则，在自己的战斗界面上进行。见[按规则集战斗](fighting-on-a-ruleset.md)。 |
| 为战斗提供人物卡 | 采用 Marinara 自身的战斗系统，使用人物卡的生命值、法术位和能力。见下文。 |
| 未声明战斗相关内容 | 采用 Marinara 自身的战斗系统，与没有规则集的游戏完全相同。见[战斗](combat.md)。 |

当规则集为战斗提供人物卡时，每个队伍成员开战时都会带着规则集为战斗设定的那个资源池和法术位，数量与人物卡当前的记录一致。他们从规则集目录里选的能力，只要 Marinara 的战斗能够使用，就会变成技能：只描述战斗之外事情的条目、反应，以及战斗无法扣除其消耗的条目都会被略过。生命值按占最大值的比例传递，而不是照搬人物卡上的数字：人物卡上生命值剩一半的角色，开战时就是战斗界面给他的那条生命条的一半，因为战斗中的数值是 Marinara 的。人物卡上只有 9 点生命的角色，不会走进一场一击就打掉 12 点的战斗。战斗结束时，失去或恢复的生命值会按同样的方式写回，花掉的法术位和资源则按实际数量写回。战斗的其余部分不变：骰子计算仍然是 Marinara 的（见[战斗计算的原理](combat.md#how-combat-math-works)），不套用桌面系统的攻击检定、豁免和专注。通过删除发起战斗的那条消息而离开的战斗不会写回任何东西，因为它没有发生过。

<a id="checks-on-a-ruleset"></a>

## 规则集中的检定

使用规则集时，游戏主持人（GM）会像在任何游戏中一样要求检定（见[技能检定](dice-and-skill-checks.md#skill-checks)），但如何掷骰由规则集决定：

- Game Master 仍然只指定技能或豁免名称并设定难度。它收到的是规则集自身的难度阶梯，而非内置阶梯。难度可以达到该阶梯的上限，甚至超过 Marinara 自身规则允许的 1 到 40。但有一条路径仍限制为 1 到 40：为已保存回合补掷尚欠检定的回退路径。
- Engine 掷规则集的骰子，并加上角色**规则集人物卡**中的调整值。构成取自规则集声明：技能或豁免指定属性时的属性调整值、训练等级加值（熟练加值的倍数、固定数值或两者都有），以及人物卡中填写的额外加值。不使用内置技能加值和属性。
- 检定可以针对队友。Game Master 在标签中添加 `who="Name"`，Engine 就使用该角色的人物卡。没有 `who` 时检定玩家。尚无人物卡的队友使用所有数值均为规则集默认值的空白人物卡。名字未匹配任何队员或被两个队员共用时，不加任何调整值。唯一例外是你自己的角色名：即使队友同名，该名字仍指你并使用你的人物卡。Engine 绝不会借用其他人的人物卡。
- 天然出目遵循规则集。5e (SRD 5.1) 的检定与豁免中，天然 20 和天然 1 没有特殊效果，因此天然 20 若未达难度也会失败。这是有意与 Marinara 自身规则区分。
- 不信任 Game Master 自行填写的数字。即使标签看似完整，只要调整值与人物卡不符、骰子数量或面数与规则集不同、采用的骰子不是掷骰模式应保留的那颗，或声称规则集没有的天然出目效果，就会重新掷骰并替换。
- 你在检定前自行掷出的骰子，仅在规则集掷单颗 d20 时使用。采用 2d6 或骰池等其他骰子的规则集会忽略它并正常掷骰。
- Game Master 可以添加 `with="Ability"`，让技能或豁免使用不同于常规的属性。只有规则集声明的属性有效；其他名称会被忽略，保留原属性。
- Game Master 可以不写数字，而是用难度阶梯里的名称指定难度，例如 `difficulty="Hard"`。Engine 会按那一级的数值掷骰，保存下来的检定显示的是这个数值。阶梯里没有的名称会被忽略。
- 掷骰占位符可以引用规则集的属性、技能和豁免；若有熟练加值，也可以使用 `PROF`。
- 如果规则集包缺失，或版本比创建游戏时更旧，检定会不带数值保存，继续保持待处理状态。绝不会改用另一个系统的规则掷骰。
- 如果人物卡上的某项会改变掷骰，例如将失败骰重掷的护符，Game Master 会在检定中点名，剩下由 Engine 完成：扣除护符消耗、应用效果并掷骰。未选取或无力支付的护符既无效果也无消耗。
- 如果规则集允许消耗资源来稳定掷骰，Game Master 会在检定本身注明，Engine 一并扣点、添加买到的效果并掷骰。资源池不足时不扣任何点，仍按原本方式掷骰。记录显示的是实际支付量，而非请求量。一次检定最多能买多少由规则集决定：一个固定数值、人物卡上的某个数值，或者与检定的骰子数相同。
- 如果规则集规定人物卡上的某个数值会附加到特定掷骰上，例如每次 Brawn 掷骰都要计入的沉重背包，Engine 会把它加到所有适用的检定中，骰子卡片也会注明人物卡加了什么。
- 规则集可以规定你在某项技能上未受训练时检定会怎样：可能扣掉骰子或点数，难度提高一级，或者根本无法进行。未受训练就无法尝试的检定不会掷骰，叙述会直接说明这一点，而不是显示结果。在你受训之前，人物卡上不会显示这类技能的数值。
- 如果规则集有伤势轨道并规定其惩罚作用于掷骰，受伤会让每次检定更难。骰池规则会减去相应骰子数，但不低于规则集允许的最小骰池，有些系统的最小值为零。求和规则则施加固定惩罚。两者都会在检定中说明实际应用量，让你知道为何少掷了骰子。参见[规则集人物卡](#the-ruleset-sheet)。
- Game Master 还会维护每个角色人物卡中的资源、状态和休息，Engine 会拒绝人物卡不允许的修改。参见[规则集人物卡](#the-ruleset-sheet)。

### 使用骰池的规则集

有些系统不在掷骰上加调整值，而是把人物卡数值作为掷骰数量，再数出足够高的骰子。这种方式也可以编写为规则集，其游戏表现略有不同：

- **人物卡数值代表骰子数。** 评级 3 加专业技能 2 就掷五颗骰子。编辑器和 Game Master 读取的人物卡均显示“5 dice”，而非“+5”。
- **难度是成功次数。** 困难任务需要三次成功，而不是总和 15。每个难度等级需要多少次成功，由规则集的难度阶梯规定。
- **Engine 负责掷骰和计数。** 哪些点数算成功，高点数会额外掷骰还是计作两次，低点数是否抵消成功，以及何种情况算失误或杰出成功，全取自规则集。骰子卡片展示每颗实际掷出的骰子，区分达标与未达标者，并显示实际成功次数与要求次数。较大的骰池换行展示而非缩小，卡片绝不会显示一个未实际求和的总数。
- **Game Master 可以调整单次检定**，前提是规则集允许：提高或降低单颗骰子的目标值，按情境增减骰子，以及调低触发重掷或计作两次的点数。每一项都限制在规则集声明的范围内。难度阶梯的某一级可以自带单颗骰子的目标值，Game Master 选中那一级时就会生效。如果检定在规则集惯常点数以外的点数上重掷或计作两次，骰子卡片会注明。
- **骰子可以重掷**，前提是规则集有相应规则：情境需要时，Game Master 会在检定中点名，掷出低点的骰子就会重掷，重掷一次或一直掷到更高为止。花费资源也能买到同样的效果。一次掷骰只按一种方式重掷；两种都适用时，采用涉及骰子更多的那种。
- **两种属性可以合并掷骰**，前提是规则集这样规定：属性检定可以加上第二种属性的骰子，让两个评级合成一个骰池掷出。
- **有些规则集会在结果之外另出差错。** 在把半数或更多骰子掷出低点算作失误的规则集里，仍然达到所需成功次数的检定会保留其结果，骰子卡片会另外注明同时出了差错。一次成功都没有时，就是大失败。
- **Game Master 从不提供数值。** 叙述中写出的骰池结果总会被 Engine 自己的掷骰替换。优势不适用，你在检定前自行掷出的骰子也不适用。
- **让 Game Master 看到每种面数的一颗骰子不适用于这些检定。** 它看到的骰子是二十面骰；骰池检定由 Engine 在不预先展示结果的情况下掷出，并按其他盲掷方式叙述。

### 规则集的其他掷骰方式

规则集还可以用其他方式进行检定。掷骰仍由 Engine 完成，骰子卡片也按规则集显示：

- **保留最高的骰子。** 掷一把骰子，按规则集的规定读取最高的一颗、两颗或三颗。
- **对照人物卡掷骰。** 掷出不高于人物卡上某个数值（例如技能百分比）的结果，而不是给骰子加上加值。
- **自带骰面的骰子。** 骰面代表的可以不是它的数字，例如减号、空白和加号。有些骰子用符号代替数字，例如成功、优势以及它们的反面。
- **分档结果。** 检定可以落入几种结果之一，例如大成功或付出代价的成功，而不只是简单的通过或失败。骰子卡片会标出落入的档位，由 Game Master 叙述。
- **少数检定另用一种掷法。** 规则集可以让大多数检定用一种方式掷骰，并指定少数几种用另一种方式。

<a id="the-ruleset-sheet"></a>

## 规则集人物卡

在使用规则集的游戏里，每张人物卡都以一个 **Ruleset sheet**(规则集人物卡) 区块开头。它的布局来自规则集，所以 5e 的人物卡和其他系统的人物卡看起来不一样。没有规则集的游戏没有这个区块。

- **Resources**(资源)，例如生命值、法术位或职业资源，显示剩余量和上限。用减号和加号按钮，或者直接输入数字。带临时缓冲的资源还会显示一个 **Temp**(临时) 框。
- **Tracks**(轨道)，例如力竭，在自己的范围内逐级升降。
- **Wound tracks**(伤势轨道) 用一排格子代替数字，适用于标记伤害而不是计数的系统。每个格子都写明这一级伤势叫什么，以及会从你的掷骰里扣掉多少。规则集有不止一种伤害时，先选伤害类型，再用 **Mark**(标记) 或 **Clear one**(清除一个)。你也可以点击下一个空格添加标记，或者点击最后一个已标记的格子清除一个；其他格子不响应点击。更重的标记会占据更高的格子，把较轻的标记往下挤，下方那一行会写明当前生效的惩罚，以及完全放不进轨道的部分。有些规则集给格子编号而不是命名，有时格子数和角色自己的等级一样多；有些规则集会把每个标记放在它瞄准的那个格子上：这类轨道上你可以点击任何一个空格，**Clear one** 清除的是最高格子上最轻的那个标记，而轨道满了以后会拒绝新的标记，而不是让旧标记变重。规则集还可以根据你人物卡上的某个列表给轨道添加格子，并让一次休息或治疗只清除某一种伤害。如果规则集这样规定，这项惩罚会作用于你的掷骰：从骰池里减去骰子，或加到求和掷骰上，骰子卡片会写明实际应用了多少。
- **Notes**(备注)，例如角色正在专注什么，是简短的文本框。
- **Conditions**(状态) 是可以开关的按钮。
- **States**(形态)，例如变身或姿态，一次只能取列表里的一个值。从列表里选择这个值。形态可以改变它后面的数值，例如某种姿态给你的掷骰加的骰子；休息也可能把它恢复到起始值。
- **Rest buttons**(休息按钮) 执行规则集的某一种休息。休息恢复什么由规则集规定，休息还可以恢复角色携带的道具的充能，例如魔杖的充能；按钮下方那一行会写明恢复了什么。在 5e (SRD 5.1) 下，长休会恢复生命值和法术位，并恢复角色一半的生命骰，至少一颗。
- 下方是配置的简短汇总：属性调整值、受过训练的技能和豁免，以及规则集挑选的几个数值，例如护甲等级。

Game Master 在叙述时会同步更新这张人物卡。角色花费资源、受到伤害、得到治疗、获得或失去状态、改变形态或休息时，它会记录这些改动，引擎再对照人物卡检查。不可能发生的改动，例如没有剩余法术位却施法，会被拒绝：什么都不会改变，并有一条通知告诉你。

角色使用从规则集目录里选的东西时，例如一个法术或一项职业特性，Game Master 会说出它的名字，引擎则支付全部代价：规则集规定的消耗，加上随它而来的每个计数器各一次使用次数。消耗法术位的法术，从规则集为它指定的环级支付，Game Master 也可以要求用更高的环级。引擎永远不会自行升到更高的环级。代价中只要有任何一部分付不起，整个操作就会被拒绝，什么都不扣。不花费任何东西的效果，例如戏法，只是叙述出来。

人物卡上有些数值属于规则集而不属于你。上限随等级变化的职业资源，或随某项属性值变化的使用次数，由规则集设定，你编辑人物卡时它们会保持正确。

有些计算值跟随游戏进程本身：规则集可以根据某项资源或轨道的当前状态算出一个数值，为形态的每个取值给出一个数值，或者把某个列表的一列加总，例如你打包的装备的重量。它还可以用这样的数值给某项技能设上限，于是资源低时技能也会缩水。这些值在游戏的人物卡上显示当前值，检定或战斗使用的是它发生那一刻的值。角色卡上的人物卡编辑器没有游戏可读，会显示它们在游戏开始时的样子。

这些实时数值属于它们发生时所在的那条消息。如果你切换到某个回合的另一个版本，或者重新生成它，人物卡会回到那个回合之前的样子，所以任何东西都不会被花掉两次。

点击 **Edit sheet**(编辑人物卡) 修改配置本身，例如升级之后：属性值、字段、法术之类的列表，以及技能和豁免的训练。计算值会随输入更新。它与角色卡上的编辑器是同一个，所以这里也能从规则集目录添加行，规则集维护的单元格会显示但不能输入，规则集原文有变化的列表会提供 **Review**(审查) 按钮。如果规则集有分步构建器，编辑器会在 **All fields**(全部字段) 旁边提供 **Guided**(引导)。**Guided** 带你逐项完成每个选择，例如属性值、技能和初始装备，并说明每一步还在等待什么。**All fields** 一次显示全部内容。完成后点击 **Save sheet**(保存人物卡)。这只会修改这局游戏里的人物卡副本。游戏永远不会改动保存在角色或用户角色上的人物卡。

单独的 **Edit Sheet** 按钮（见[手动编辑人物卡](party-and-npcs.md#edit-a-sheet-by-hand)）仍然编辑通用人物卡（职业、能力、优势等），不会动规则集人物卡。

如果规则集的包被移除了，或者已安装的版本比创建游戏时用的版本旧，这个区块会改为显示一条通知，在重新安装这个包之前无法掷检定。

## 队伍人物卡和进度时钟

有些规则集会为整支队伍保留一张人物卡，例如一支船员或一个佣兵团。它显示在游戏画面上地图附近，使用规则集自己给它起的名字。点击名字即可打开。Game Master 会像更新每个角色的人物卡一样更新它，在规则集允许的地方，你也可以编辑它。如果你编辑时有别人保存了队伍人物卡，它会显示对方的版本：**Save**(保存) 用你的版本替换它，**Cancel**(取消) 保留对方的版本。

规则集还可以使用 **Progress clocks**(进度时钟)：分成若干段的圆圈，Game Master 会随着某件事逐渐累积而填满它，例如警报逐步升级。它们显示在地图附近，各自写明填了多少段，填满后显示 **Done**(完成)。
