# Game Mode：入门

Game Mode(游戏模式) 把 Marinara Engine 变成一款由 AI 主持的单人角色扮演游戏。本指南先介绍 Game Mode 是什么、开始前要准备什么，然后带着走完设置向导，并指出每项玩法功能各自在哪。通读一遍，先开一局，想深入某个专题时再看文末的链接。

## Game Mode 是什么

Game Mode 是 Marinara 的聊天模式之一，另外两种是 Conversation(对话模式) 和 Roleplay(角色扮演)。

在 Game Mode 里，由 AI 扮演游戏主持人（GM），为你主持一个故事。游戏主持人就是负责讲述世界、扮演遇到的每一个角色、决定接下来发生什么的那个 AI，作用和桌面跑团里的 DM 一样。

引擎会跨回合替你追踪游戏状态，包括地图、队伍、非玩家角色（NPC，即玩家之外的角色）、物品、任务、世界内的时间和天气。一局游戏会持续很多回合。一场长游戏可以拆成若干个**会话**，就像跑团团队把一条战役分到好几个晚上来跑。战役指的是整条持续推进的故事线。

所有机制都不是必须用的。有的玩家完全跳过战斗和骰子，只把 Game Mode 当成偏剧情、偏画面的玩法。RPG 系统随时待命，想用再用。

## 开始之前

开一局游戏只需要一样东西：给 GM 用的 AI 服务商连接。连接负责把 Marinara 接到 AI 服务商，这样才能生成文字。还没配过的话，见[连接 AI 服务商](../connections/connecting-to-a-provider.md)。

其余全是可选项，默认关闭，随时可以后补：

- **图像生成。** Game Mode 有一套带背景和角色画面的视觉布局。要把画面填满，就需要一个图像生成连接。向导里的 **Visual Generation**(视觉生成) 默认关闭，得自己打开。不开也能正常玩，故事、状态追踪和战斗都在，只是视觉区域是空的。
- **跑场景效果的本地模型。** Marinara 可以在自己的机器上跑一个小模型，界面上叫 **Local Model (Gemma)**。它负责背景和音乐建议，不产生额外费用，也是向导里的默认选项。见[本地模型设置](../connections/local-model.md)。
- **Storyboard 智能体。** 从 **Agents > Download Agents** 安装，想要静态或动态分镜时，再到 **Chat Settings > Agents** 里为建好的游戏启用它。
- **视频生成连接。** 只有要做场景视频或动态分镜时才需要。
- **音乐。** **Music DJ** 智能体可以播放游戏音乐，需要 Spotify 或者一个本地音乐文件夹，默认关闭。

## 设置向导

新建 Game Mode 聊天时会打开一个**设置向导**，一共七步。唯一必填的是第一步的 GM 连接，其他每一项都有合理的默认值。可以快速点过去，剩下的交给 Marinara 填。

七步分别是：

1. **Connection。** 选择 **Game Mode**(游戏玩法)：**Overworld RPG**(大地图 RPG) 或 **Classic**(经典)。Overworld RPG 还没有完成，所以目前新游戏都以 **Classic** 开始。参见 [Classic 还是 Overworld RPG](#classic-or-overworld-rpg)。设置游戏名称，选择 GM 连接，可以再选一个跑场景效果的连接。场景效果默认用 **Local Model (Gemma)**。
2. **World。** 设置类型、背景、基调、难度、内容分级和语言。背景下方以及之后目标下方给出的点子，来自不同类型的背景设定，每次打开向导都会重新组合。在 **Combat Preference**(战斗偏好) 中选择 **Classic**(菜单战斗) 或 **Tactical**(网格战斗)。Tactical 游戏还提供可选的战场种子、尺寸和地形指引。安装了 Game Mode 规则集后，下方会出现 **Rules**(规则)：保留 **Marinara's own rules**(Marinara 自身规则)，或选择规则集。参见[选择规则](#choosing-rules)。在 Overworld RPG 中，再往下是 **Setting kit**(设定包) 和 **Your world**(你的世界)。参见[选择设定包](#choosing-a-setting-kit)和[创建世界](#making-a-world)。
3. **Party。** 选择你的用户角色（也就是你扮演的角色）、**Game Master Mode**(游戏主持人模式)，以及队伍成员。**GM intro message**(GM 开场消息) 设置游戏的第一条消息。参见 [GM 开场消息](#the-gm-intro-message)。
4. **Goals。** 告诉 GM 你想从这场冒险里得到什么。
5. **Lorebooks。** 挂上世界书，里面的设定 GM 会当作正典。世界书就是一组世界背景设定条目。见[世界书](../lorebooks/overview.md)。
6. **Features。** 开启可选系统，比如 Visual Generation、Music DJ 和 HUD 小组件。可安装的智能体要等游戏建好之后，从 Chat Settings 里启用。
7. **GM。** 在生成世界之前，选择呈现方式并检查 GM 的高级指令。

填完之后点击 **Start Game**(开始游戏)。

在 Tactical 游戏中留空战场选项，GM 会选择符合场景的简述，引擎据此生成棋盘。固定种子可在遭遇输入相同时复现生成结果；地形指引则向 GM 请求残墙或林间空地等要素。移动规则、地形加成和生成失败说明见 [Game Mode：战斗](combat.md#tactical-battles-and-terrain)。

<a id="classic-or-overworld-rpg"></a>

### Classic 还是 Overworld RPG

新游戏以两种 Game Mode 玩法之一进行，在第一步选定，并在这局游戏的所有会话中保持不变：

- **Overworld RPG**：完成之后会成为默认选项。它是一个为你的背景打造的世界，在大地图上行走，有城镇可以造访，有地方可以探索，还有地下城可以深入。它需要一个设定包和一个世界；在你选定设定包之前，会采用与你第一个类型对应的设定包（没有对应设定包的类型用高奇幻），并为它随机生成一个世界。
- **Classic**：Game Mode 一直以来的玩法。故事一个场景接一个场景地讲述，有场景地图和战斗，没有设定包、世界、大地图、城镇或地下城地图。

在有这个选项之前创建的游戏会照原样继续：有世界的是 Overworld 游戏，没有世界的是 Classic 游戏。

Overworld RPG 仍在完善中。在它准备好之前，它的卡片是灰色的，并附有说明“Overworld games, with a setting kit and a generated world, are not ready yet. New games start as Classic games.”这时每个新游戏都是 Classic，下面的设定包和世界选项也不会出现。它们描述的是 Overworld RPG 游戏。

<a id="choosing-rules"></a>

### 选择规则

**Rules**(规则) 只在安装了至少一个规则集、且正在创建新游戏时出现。它与 **Combat Preference** 分开设置：前者决定检定和人物卡如何运作，后者决定战斗如何呈现。

- 默认的 **Marinara's own rules**(Marinara 自身规则) 使用内置 d20 检定和六属性人物卡。
- **5e (SRD 5.1)** 等规则集会显示覆盖范围的简述，以及一行战斗方式说明。自行结算战斗的规则集会明确说明。只提供人物卡的规则集会说明：战斗采用 Marinara 的战斗系统，使用人物卡自身的生命、能量和能力。两者都不提供的规则集会说明战斗采用 Marinara 的战斗系统，并标出你选择的 **Combat Preference**。

规则集自行结算战斗时，战斗界面也属于该规则集：菜单是角色自己的攻击和能力，每项都说明消耗规则集自身行动额度和资源池中的哪些部分；下方显示行动顺序、轮次、以规则集名称标示的所有人状态，以及各项额度的余量；日志打印真实算式，例如“Juno attacks Rust jackal with Road axe: 8 (5 + 3) + 3 = 11 against Guard 6, a hit.”每个行动生效时立即写入人物卡，因此中途关闭标签页也不会丢失结果，之后 Game Master 会获知数值已经结算。如果规则集还规定了战场一格相当于它自身单位的多少距离，**Combat Preference** 就决定战斗的显示方式：**Classic** 不使用位置，**Tactical** 则在棋盘上进行，你可以在上面行走、按规则集自己的单位测量触及范围和射程，并把范围形状瞄准某一格。参见[战斗](combat.md#games-whose-ruleset-resolves-its-own-fights)。未提及距离的规则集会保留这一偏好，但不使用它。

规则集在创建游戏时确定，并一直随该游戏保留。之后不能更换或添加。

有些规则集提供 **layers**(层)：Low magic 或 Hard winter 这类具名变体，以开关形式显示在规则集下方，每个都附一行说明其作用。一个层可以让难度更严苛、缩小人物卡上的某项选择、把一些现成条目从人物卡编辑器的选择列表中去掉，并给 Game Master 额外的指令，包括它在设置阶段构建世界时的指令。有些层彼此排斥，向导会禁用你不能再选的那个。游戏开始后层就固定下来，和规则集本身完全一样；人物卡上已经在用、但被某个层去掉的内容会保留。

规则集有两个来源。官方规则集从 **Download Agents** 安装，在那里标为 **Rules**。社区规则集从文件或作者的 GitHub 仓库导入，并按来源归档，例如 `local/ember-roads` 或 `alice/v20`。导入使用的开关和导入智能体相同，即 **Allow custom Agent imports**(允许导入自定义智能体)。这个开关关闭时，导入的规则集不会出现在新游戏中，已经在用的游戏照常运行。使用导入规则集的游戏始终按创建时的确切版本来玩。想自己编写，见[编写 Game Mode 规则集](../extending/writing-rulesets.md)。

选好规则集之后，**Party** 步骤会在选择器下方列出你的用户角色和队伍成员，并标明谁 **Has a sheet**(已有人物卡)、谁 **Starts on a blank sheet**(从空白人物卡开始)。人物卡在角色或用户角色编辑器的 **Stats**(属性) 下添加（见[规则集人物卡](../characters/colors-and-stats.md#ruleset-sheets)）。生成世界时，游戏会复制每张人物卡。你在游戏里做的任何改动都不会写回角色或用户角色。没有人物卡的成员会得到一张空白人物卡，所有数值都是规则集的默认值；世界生成绝不会编造数值。

共享的设置文件会记住它的规则集。如果你导入的设置文件用的规则集你没有，或者你的版本更旧，向导会告诉你它用的是哪个规则集，游戏会使用 Marinara 自身规则，除非你安装并选中那个规则集。

<a id="choosing-a-setting-kit"></a>

### 选择设定包

**Setting kit**(设定包) 给 Game Master 提供书写你这类世界所用的词汇：各种地方叫什么、聚落最大能有多大、有哪些类型的团体、一个地方可能以什么闻名、人们怎样出行、一年和一天叫什么、各个民族怎样给自己起名、打赢一场战斗会掉落什么、它的货币和日常售卖的东西、它的元素、战斗发生的场所，以及它使用哪一系的美术、音乐和音效（见[游戏素材](game-assets.md#a-settings-own-art-and-music)）。它还规定世界里有哪些类型的变化，比如竞争、犯罪、战争或灾难，以及世界自行变化的速度。关闭的变化类型绝不会作为背景事件出现，场景也不会升级成这种变化，所以一场争吵可以始终只是争吵。

它只在新的 Overworld RPG 游戏中提供，而这种游戏总会有一个设定包：在你选定之前，会采用与你第一个类型对应的设定包。一开始有八个可选：高奇幻、武侠与仙侠、现代、现代超自然、1920 年代、赛博朋克、太空歌剧和末日废土。现代设定包默认很温和，没有犯罪、冲突或灾难，节奏缓慢，适合日常向的故事。

在选择类型之前先选设定包，会设定与之相符的类型，比如赛博朋克设定包对应 **Cyberpunk**，武侠与仙侠对应 **Wuxia**，之后背景和目标的点子会先列出设定包自己的。你自己选的类型保持不变。

选好之后，**Write it for my setting**(按我的背景改写) 会让你的 Game Master 连接按你选的类型、背景和基调改写它。如果模型写出的内容前后不一致，会附上原因再请求一次；之后向导会告诉你哪里出了问题，并保留你原来的设定包。**Change its words**(修改用词) 会打开设定包里的每一个词供你编辑。列表写在一行里，用逗号分隔。有问题的设定包，比如名称为空或没有聚落，会说明哪里有错，修好之前游戏无法开始。

游戏会保留创建时的设定包。Game Master 每回合都会读它，世界生成也会用它的词汇。共享的设置文件同样带着它的设定包。

Experience 可以自带**地图包**：一个设定包、现成的地图和它自己的图块。开启那个 Experience 后，设置界面会把它的设定包显示为已设定（无需选择设定包），如果它带有地图，还会提供可供挑选的 **Map**(地图)；游戏会在那张地图上进行，并用这个 Experience 的图块绘制。关闭这个 Experience，你自己的选择就会回来。

**Download this kit**(下载这个设定包) 会把设定包保存成文件（`.worldkit.json`）以便分享，**Import a kit file**(导入设定包文件) 则把文件读回来。**Import a world file**(导入世界文件) 会一次导入整个世界（见下文）。

<a id="making-a-world"></a>

### 创建世界

选好设定包后，**Your world** 会在游戏开始前用设定包的词汇铺开整个世界：它的地区、设定包规模阶梯上各种大小的聚落、每个地方以什么闻名，以及它们之间的通路（道路、河流、海上航线、跃迁航道），并标明每段旅程要走多少天。每个新的 Overworld RPG 游戏都有一个世界，由一个可以更改的种子随机生成。

世界由 **World seed**(世界种子) 生成。相同的种子、设定包和纲要总会生成相同的世界，所以 **Roll**(随机) 会给你另一个世界，把数字输回去就能找回原来那个。下方的预览就是游戏将要使用的世界：一张画出地面和聚落的小地图、队伍的出发地点，以及按地区列出的所有聚落。

- **Start from this lore**(以这些设定为起点) 会读取你勾选的世界书，提取其中写明的地点和带日期的事件，每一项都严格按设定原样保留，并附上它们出自的条目。**Build around the lore**(围绕设定扩建) 会在它们周围把世界补充完整；**Only the lore's places**(只用设定里的地点) 则除此之外什么都不生成。
- **Write the world's brief**(撰写世界纲要) 会请你的 Game Master 连接写出其余部分：游戏开始时的当下局势、主要地点、当下局势所围绕的团体（各自想要什么、盟友和对手是谁），以及世界生成的地点和人物所用的名字，每个名字都符合设定包中各民族自己的发音和语序。无论模型写什么，设定里的地点都会保留；不符合设定包的内容会被去掉并计数，那几个模型总是反复使用的名字也一样。**Change the brief**(修改纲要) 会打开纲要的文字供你编辑，包括每个民族的名字和姓氏。

没有纲要时，世界就只有设定包和设定里的地点，它生成的地点会以编号命名，直到纲要给它们起名。

世界也有过去。游戏开始之前，世界自己的引擎会从建立之初逐年推演：每个聚落被建立并成长到现在的规模，纲要里的团体在各自的驻地成立，更换领袖，彼此结交或反目；在有这些变化的世界里，盗匪、战争和饥荒会留下痕迹，有些地方因此消失。严重的变化只会在酝酿一段时间之后才发生（战争前先有紧张局势，饥荒前先有旱季），而且只使用设定包允许的变化类型：温和世界的过去也是温和的。你的设定写明的、或纲要提到的带日期事件，会在它们所说的时间和地点发生。相同的种子和纲要总会给出相同的过去。

Game Master 会获知过去最值得注意的事件、队伍所在地点由谁掌控、谁领导他们，以及这个地点自己的过去。至于其他任何地点或团体，它都可以询问，并在下一回合得到答案。

每个聚落都有自己的居民，在队伍抵达时由种子生成：地方越大人越多，每个人都有出自自己文化名单的名字、与这个地方闻名之处相符的职业、性格、在意的事情、说话方式和外貌，还有一些人来自别处。Game Master 会看到当前地点几位队伍还没见过的居民，有新面孔进入场景时就从中引入一位。它叫出全名的人会加入游戏追踪的角色，并记下其职业和外貌，这样同名的两个人也能区分开。没有纲要提供的名字列表时，居民以职业相称。

游戏中，Game Master 总是知道队伍在哪里、从那里能去哪里，以及每条路要走多久。它用地点标签指明队伍去往何处。世界列出的地点保持世界给它的规模。在带有市场的规则集中，它还会对应市场规模阶梯上相应的规模，所以世界的首都就是市场里最大的地方。世界没有列出的地点，比如一座农舍或一处营地，保留 Game Master 给它起的名字。游戏开始后，世界的过去就固定了。它的布局也固定下来，手动编辑除外（见下文）。共享的设置文件带着世界最初生成时的样子。

队伍对世界做的事会一直生效。当队伍帮助或妨碍某个团体、让两个团体结为朋友或敌人、站到某个团体一边或背叛它、改善或破坏某个地方、为某个团体夺取一个地方、消灭一个团体、扶某人当上团体首领，或让某个地方沦为废墟时，Game Master 会在回复中记下这件事，就像它记下故事引入的地点或团体一样。每一项都会对照世界检查：属于设定包已关闭类型的变化（比如在温馨的现代世界里打仗），或者提到世界里没有的地点或团体的变化，都会被拒绝。从那以后，Game Master 得知的就是故事留下的世界：这个地方的现状、谁掌控它、谁领导他们、队伍在那里做过什么、队伍与打过交道的每个团体的关系，以及游戏开始以来发生了哪些变化。故事加入的地点就是队伍可以前往的地点。变化属于产生它的那条回复，所以备选回复、重新生成或删除消息都会连同那条回复一起把它撤回。

没有队伍，世界也会继续运转。当 Game Master 说时间流逝（一段旅程、一夜休息、一次长时间等待）时，世界会以一周为单位自行推进，而且只发生设定包里有的变化类型：兴衰起落，新人定居，团体走近或成为对手，首领卸任；在有这些变化的世界里，麻烦会找上处境艰难的地方，两个团体之间的紧张局势在酝酿一季之后可能变成战争。灾难绝不会自行发生；只有 Game Master 能讲述灾难，就像它可以讲述队伍之外的任何事件一样，如果这类变化已关闭则会被拒绝。队伍所在之处不会自动定下任何结果：那里即将发生的事会留给场景来演绎。消息会传播：远方的变化要等道路所需的天数过去之后，Game Master 才会以传闻的形式听说；附近正在酝酿的事它能直接看到，这样队伍就能介入。只有当一场酝酿中的战争对这个世界毫无道理，或者会在队伍根本没有机会阻止的情况下毁掉游戏时，它才可以压下这场战争。队伍名声越大，所作所为的分量越重：陌生人的帮助改变不了多少，大名鼎鼎的队伍出手则影响深远。

世界还可以保留**手动编辑**。手动编辑是你用世界编辑器做出的改动，世界编辑器是一种在世界生成之后修改它的工具。你可以重命名或移动地点、绘制地面，以及添加地点和人物。你还可以绘制某个地点的战术战场（见[战斗](combat.md#tactical-battles-and-terrain)），以及手动布置一座城镇（见[城镇](map-time-weather.md#the-town)）。游戏的每个部分都会立刻看到这些编辑：Game Master、大地图、城镇和 World 标签页。改名的地点仍然认得它的旧名，Game Master 也会得知它曾经叫什么。

手动编辑只改变世界从现在起的样子，绝不改变它的过去。世界的历史，以及它自行发生的变化，都保持原样。你添加的聚落会保持你添加时的样子。城镇保留它的布局，所以你添加的地点和人物会放在它下一块空闲的建筑用地和下一间空闲的住宅里。

世界可以作为文件传递。**Your world** 下的 **Download this world**(下载这个世界) 会保存你正在制作的世界，游戏 World 标签页上的 **Download the world**(下载世界) 会把这局游戏的世界连同手动编辑一起保存成 `.world.json` 文件。设定包旁边的 **Import a world file** 会把文件读进新游戏的设置：它会选用文件里的设定包，并生成文件里的世界及其手动编辑。**Your worlds**(你的世界库) 对保存在你资料库里的世界做同样的事，比如在任何游戏之外用 Pixelforge 这类制作工具做出的世界。

世界文件还可以带上世界的**故事**：创作者为它编写的事件和场景。故事随世界一起提供，并以同样的条件保留。游戏中，故事的场景会按原样出现在 Game Master 回复之前的叙述里。故事显示出任务目标后，这些目标会列在日志 World 标签页的 **Story**(故事) 下。想自己编写，见[编写 Game Mode 故事脚本](../extending/writing-story-scripts.md)。

手动编辑和故事是为那个种子和纲要制作的，所以只要更改其中任何一个，它们就会被去掉。无法读取的文件会被拒绝，向导会说明原因。世界文件还带有世界生成时的原样，所以由其他版本的世界生成器制作的世界会完全按原样打开。缺少这部分的旧文件会被拒绝。如果文件里有内容不符合设定包，它会被去掉，向导会说明去掉了什么。

在有 Game Mode 玩法选项之前创建、没有世界的游戏，以后也可以拥有一个世界，前提是你想要：日志的 **World**(世界) 标签页提供 **Make a world for this game**(为这局游戏创建世界)，设定包和世界的选项与新游戏相同。世界从下一回合开始生效；游戏过去的回合、地图和人物保持原样。Overworld RPG 尚未准备好时，这个按钮是灰色的，附有与设置界面相同的说明。

游戏会保留世界生成时的样子。地点、人物、城镇和历史会在游戏开始时、以及每次保存手动编辑时随游戏一起保存，所以改变世界生成方式的更新绝不会改变已经在玩的世界。新会话、分支和导出的聊天都保留同一个世界，世界在之前的会话中如何演变（兴衰、统治者和战争）也会按实际发生的样子保留。由更早版本的世界生成器生成的世界会按原样继续玩，但无法再编辑。

有世界的游戏会在**大地图**上打开。大地图把世界画成一张像素地图，你可以沿着世界的通路带队伍从一个聚落走到另一个聚落，并进入队伍所在的城镇；切换一下就能回到场景视图。见[大地图](map-time-weather.md#the-overworld)。

<a id="the-gm-intro-message"></a>

### GM 开场消息

**Party** 步骤中的 **GM intro message** 决定游戏如何开场：

- **None**(无)：默认选项。Game Master 按自己的判断开场。
- **Defined**(固定)：把第一条消息原样输入。游戏会严格以这条消息开场，重新生成也会得到相同的文字。
- **Guided**(引导)：描述开场应该怎样进行，比如从哪里开始、有谁在场、先发生什么。Game Master 会据此写出开场。

文字最多 8,000 个字符。其中不能包含双花括号，**Guided** 的文字也不能包含方括号。文字无法使用时，输入框会说明。世界的故事可以自带开场。故事锁定开场时，输入框会显示它，并附上“Set by this Experience and locked, so the game opens as its creator meant.”，而且无法更改。

### 值得先了解的默认值

下面是 **World**、**Party**、**Features** 三步里的初始值，全部都能改。

| 设置项 | 默认值 | 说明 |
|---|---|---|
| Genre | Fantasy | 可多选，也能自己加条目；先选的设定包会设定它自己的类型 |
| Tone | Heroic | 可多选 |
| Difficulty | Normal | Casual、Normal、Hard 或 Brutal；越高战斗越难熬 |
| Content Rating | SFW | SFW 或 NSFW；NSFW 只是允许成人内容，不会强制出现 |
| Language | English | 游戏内所有文字都用这个语言书写 |
| Game Master Mode | Standalone GM | Standalone GM 会替你造一个 GM；Character GM 用你的某张角色卡当 GM |
| Visual Generation | Off | 想要图像就打开；需要图像生成连接 |
| Game Presentation | Standard | **Storyboard Optimized** 用 Storyboard Game Prompt 来塑造 GM 的叙述；它不会安装也不会启用 Storyboard 智能体 |
| Music DJ | Off | 需要 Spotify 或本地音乐文件夹 |
| Custom HUD Widgets | On | 使用新世界里由 AI 生成的状态小组件 |
| Start Muted | Off | 开局时静音 |

第一次玩 Game Mode 的话，**Game Master Mode** 就留在 **Standalone GM**。Marinara 会造一个公正、偶尔毒舌的 GM，先摸清这个模式的路数，再考虑自己写 GM 角色卡。

想让 GM 的回合写成可拍摄的视觉段落时，在最后一步选 **Storyboard Optimized**(分镜优化)。它会为 GM 的叙述选中内置的 **Storyboard Game Prompt**。它不会安装或启用 Storyboard 智能体，不会打开图像生成或视频生成，不会改动已选的连接，也不会替换这个智能体自带的规划器和格式化器默认值。游戏建好之后，另行安装并启用 Storyboard，再到 **Chat Settings > Agents > Storyboards** 里配置它的关键帧、规划器、图像和视频设置。

设置完成后，另一套动画单镜组合依然可用：Animation Planner 选 **Anime Episode Director**，Storyboard Video Prompt 选 **Anime Game Video**。

**GM Prompt**(GM 提示词) 编辑器会按当前选中的呈现方式预览实际生效的提示词。选中 **Storyboard Optimized** 时打开编辑器，看到的就是 Storyboard Game Prompt，其中包含关键帧数量的宏。不动这段文字，内置预设就保持选中；一旦编辑，就会生成一个自定义提示词，覆盖掉呈现方式自带的预设。

## 三种 AI 调用

Game Mode 会发起三种不同的 AI 调用。搞清楚它们，就知道费用和报错分别出在哪。

1. **世界生成。** 点击 **Start Game** 时只跑一次。GM 连接会返回一份很大的结构化文档，格式叫 JSON。这份文档里有世界总览、初始地图、NPC、队伍的人物卡，以及屏幕上的小组件。JSON 是一种严格的文本格式，AI 必须一字不差地返回，否则游戏读不了。这是要求最高的一步，所以模型选得好不好，在这里影响最大。
2. **游戏回合。** 每发一条消息，都会带上当前状态重新组一份提示词，然后由 GM 叙述并更新世界。战斗回合的数值由引擎计算，不交给模型，结果才公平、稳定。
3. **会话摘要。** 结束一个会话时，GM 会写一份结构化的回顾和连贯性备注。开始新会话时，它会写一小段承接消息，让下一章顺畅接上。更早的会话会被压缩成摘要，这样长战役也不会把模型撑爆。

## 发言对象：你在跟谁说话

输入栏里，附件按钮旁边有一个小小的对话气泡按钮，提示文字是 **Choose who to address**(选择发言对象)。这个按钮决定消息发给谁，有三种状态。

- 默认情况下，消息进入场景，算作一次普通的游戏内行动或台词，GM 和队伍会在故事里作出回应。
- **Talk to Party**(对队伍说) 会加上 `[To the party]` 标记，直接对同伴说话。适合“我们该怎么办”这类战术讨论。只有队伍非空时才会出现这个选项。
- **Talk to GM**(对 GM 说) 会加上 `[To the GM]` 标记，以角色之外的身份向 GM 提问。适合“我的角色知道那座神庙吗”这类问题，或者调整节奏的请求。

当前生效的模式会在菜单里显示 **On** 标记。想关掉 **Talk to Party** 或 **Talk to GM**，再点一次同一个菜单项即可，消息就会回到场景里。

<a id="optional-tool-planning-and-lore-searches"></a>

## 可选的工具规划与世界设定搜索

游戏中打开 **Chat Settings → Function Calling**(聊天设置 → 函数调用)。**Let the GM search lore**(允许 GM 搜索世界设定) 让 GM 按含义查找信息，无须同时启用所有其他可选工具。请先为相关世界书开启向量化，并将条目向量化。搜索会遵循已启用的世界书、文件夹以及当前聊天的条目开关，使用配置好的嵌入连接，也可能增加一次后续模型请求。

Game 聊天通过工具查询世界书时，即使开启了 **Enable Tool Use**，也仍然需要 **Let the GM search lore**。该选项关闭时，工具选择器中的 `search_lorebook` 不可用；已选中的条目会继续显示并附上说明，方便你移除它或重新开启设定搜索。

**Game tool connection**(游戏工具连接) 默认为 **Same as narrator**(与旁白相同)，保留通常的工具调用循环。选择其他连接后，会在叙述前单独执行一次规划请求。由该模型选择工具，旁白则以文本形式收到工具的真实结果。额外请求由所选连接计费；更便宜的模型可能降低工具成本，但也可能选择不同的工具。这一次规划无法根据第一次搜索的结果继续发起第二次查询。如果希望旁白经过多轮工具调用来推理（每回合最多四轮，之后它会用已有的结果进行叙述），请使用 **Same as narrator**。

Claude 和 Grok 订阅连接不支持原生工具调用。相关控件会说明原因，并在选中受支持的 Game 工具连接前保持禁用。文本命令和骰子标签仍可使用。如果独立连接不存在或请求失败，该回合会报告失败，不会悄悄略过请求的工具工作后继续叙述。

**Finish rolled turns in one request**(用一次请求完成掷骰回合) 改变上面的第二类调用。掷骰回合通常需要两次请求：先草稿，再按真实数字重写。启用后，Game Master 盲写结果，引擎随后填入数值，因此只需一次请求。默认关闭。仍有两种情况会额外请求：**Enable Tool Use** 启用时调用骰子工具，以及始终发起自身规划请求的独立 **Game tool connection**。参见 [Game Mode：骰子与技能检定](dice-and-skill-checks.md#finishing-a-rolled-turn-in-one-request)。

如果本地模型共享的 GPU 显存有限，打开 **Chat Settings → Agents** 并启用 **Run Game tasks one at a time**(逐个执行 Game 任务)。在该 Game 聊天内，旁白、智能体和场景媒体会互相等待完成。此选项默认关闭，也不会阻止其他聊天或应用使用 GPU。执行或等待时，现有的取消操作仍然可用。

## 开启智能体

智能体是可选的 AI 帮手，和 GM 并行运行。要在游戏里用它们，玩的过程中打开 **Chat Settings**(聊天设置)，进入 **Agents**(智能体) 部分，打开 **Enable Agents**(启用智能体)。智能体会额外发起调用，因此会增加费用。

Game Mode 里有两个智能体值得了解：

- **Game Session Keeper** 帮忙维持各个会话之间的连贯性。
- **Music DJ** 负责挑选背景音乐，需要 Spotify 或本地音乐文件夹。

Game Mode 还会用到 **Review Agent Outputs**(查看智能体输出)，方便检查智能体产出了什么。想全面了解智能体，见[智能体：聊天里的 AI 帮手](../agents/agents-overview.md)。

## 怎么选模型

世界生成是 Game Mode 里最难的一环，要求模型一口气输出一份又长又严格、一个字段都不能缺的 JSON。日常聊天表现不错的模型，在这一步照样可能翻车。

世界生成建议用付费连接上当下能力最强的一线模型。截至 2026 年，玩家反馈几家主流服务商的旗舰档位效果都不错，比如 Anthropic Claude、OpenAI GPT 和 Google Gemini。具体型号名变动频繁，这里只是举例，不是固定名单。

后续的游戏回合有时可以降级到便宜一些的模型，因为回合要的是叙述，不是严格的 JSON。一旦 GM 开始忘记 NPC 或者和前面的细节自相矛盾，就换回更强的模型。

世界生成不要用免费模型或自动路由模型，它们可能把请求路由到一个小模型，产不出合法的世界生成 JSON。小参数量的开放权重模型通常也过不了这一关。

完整的参数说明见[生成参数](../prompts/generation-parameters.md)。

<a id="the-games-controls"></a>

## 游戏控件

在电脑上，游戏控件通过聊天右上角附近的按钮打开。在手机上，它们在可移动的 **Chat tools**(聊天工具) 三点菜单里：

- **Game controls**(游戏控制)（游戏手柄）：
  - **Retry turn**、**Retry scene analysis**、Music DJ 负责游戏音乐时的 **Retry Music DJ**，以及 **Retry assets image generation**。
  - 分镜作为游戏背景播放时，这里还有重播、播放/暂停和静音。
  - 在有世界的游戏里，**Show the scene**(显示场景) 和 **Show the overworld**(显示大地图) 用来切换视图，**Show the map**(显示地图) 会回到打开着的地下城、洞穴或空间站地图。
  - **Edit game data**(编辑游戏数据) 可以手动修正游戏保存的数据（见[手动编辑游戏数据](sessions-and-saves.md#editing-game-data-by-hand)），**Checkpoints**(检查点) 可以让游戏回到更早的某个时刻（见[游戏如何保存](sessions-and-saves.md#how-your-game-saves)）。
- **Session**(会话)（羽毛）：会话历史、日志和会话控制。见 [Game Mode：会话与存档](sessions-and-saves.md)。
- **Volume**(音量)（扬声器）：**Master**、**Music**、**Sound Effects**、**TTS** 和 **Ambient** 的音量。
- **Game Assets**(游戏素材)（文件夹）：场景媒体和 Asset Browser。见[游戏素材](game-assets.md)。
- **Connected chat**(所连聊天)：游戏关联到 Conversation 时显示。见[所连聊天](../chats/connected-chats.md#switching-between-connected-chats)。

选择一个工具，电脑上会在可移动窗口中打开它的控件，手机上则打开全宽面板。在电脑上，拖动按钮即可移动它。在手机上，可以移动三点菜单，或者解锁后重新排列里面的工具。关闭窗口或面板后，可以从原来的位置再次打开这个工具。见[控制窗口及其按钮](../chats/chat-settings.md#control-windows-and-their-buttons)。

也可以把这些控件放进 **Chat Settings**。打开控件的窗口，选择 **Put back in Chat Settings**，它就会变成其中的可展开区域。用该区域的弹出按钮可以再变回独立窗口。每局游戏都会保存你的选择，**Reset View** 会恢复初始布局：电脑上是按钮，手机上是 Chat tools 里的条目。

**Character Profiles**(角色资料) 在电脑和手机上都留在 Chat tools 之外。把它的头像按钮拖到任意位置，然后打开它，选择一位队伍成员，查看或编辑其人物卡。在手机上，**Map**(地图) 也有自己的可移动按钮。两者都会跟随你的聊天小组件样式，为这局游戏保存位置，并且可以在打开的窗口里锁定。电脑上的地图保留原有的地图面板控件。

## 故障排查

### 世界生成报 JSON 错误或 422 错误

最常见的原因就是模型没能产出完整的结构化 JSON。按顺序试试下面几步。

1. 看看 GM 用的是哪个连接。如果指向免费模型或自动路由模型，换成能力过关的付费模型。
2. 再试一次。有些失败是偶发的，同样的配置第二次就成了。
3. 把过长的背景设定或偏好内容缩短。输入太长，留给模型输出 JSON 的余地就少了。

如果这次调用其实差一点就成了，只是 JSON 有小毛病，Marinara 会提供一个 **Repair JSON**(修复 JSON) 窗口。它会打开一个带行号的编辑器，里面是模型的原始输出。状态行会告诉你 JSON 是否合法，或者显示解析错误。点击 **Format**(格式化) 可以把合法的 JSON 整理整齐，然后点击 **Apply Repaired JSON**(应用修复后的 JSON)，直接用改好的版本，不必再花一次完整重试的钱。会话摘要和其他结构化调用出问题时，同样会出现 **Repair JSON** 选项。

更多症状和解决办法见 [Marinara Engine 故障排查](../TROUBLESHOOTING.md)。

### 明明选了黑暗基调，GM 却讲得很欢快

有些模型不管什么基调都保持乐观。有两个办法：在向导的偏好栏里写一条明确的指令，比如“叙述保持阴郁，失败不要美化”；或者换一个默认口吻更贴合目标基调的模型。
