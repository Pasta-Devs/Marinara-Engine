# Game Mode：骰子与技能检定

本指南介绍 Marinara Engine 的 Game Mode(游戏模式) 里怎么掷骰子，包括快捷骰子菜单、自定义骰子写法，以及自定义掷骰的上限。此外还会说明游戏主持人（GM）如何按难度等级（DC）判定一次技能检定。

## 掷骰

Game Mode 聊天的消息输入栏里有一个骰子按钮，它的提示文字是 **Roll dice**(掷骰)。点击它就会打开快捷骰子菜单。

菜单里有 8 个一键预设：

| 预设 | 掷出的骰子 |
|---|---|
| d20 | 1 颗 20 面骰 |
| d6 | 1 颗 6 面骰 |
| 2d6 | 2 颗 6 面骰 |
| d10 | 1 颗 10 面骰 |
| d100 | 1 颗 100 面骰 |
| d4 | 1 颗 4 面骰 |
| d8 | 1 颗 8 面骰 |
| d12 | 1 颗 12 面骰 |

快速掷一次骰子的步骤：

1. 在 Game Mode 聊天里打开消息输入栏。
2. 点击骰子按钮。
3. 在 8 个预设里点一个，比如 **d20**。
4. 输入栏里会出现一个小标记，形如 `🎲 d20`。

掷骰不会立刻发出，而是先排进队列。想取消已排队的掷骰，点标记上的清除按钮，它的提示文字是 **Clear queued roll**(清除排队的掷骰)。

骰子的运算在发送下一条消息时才执行。应用会把结果作为一个标记加在消息末尾。单颗骰子、没有加值时是这样：

```
[dice: d20 = 14]
```

多颗骰子或者带加值的掷骰还会列出各个部分：

```
[dice: 3d8+2 = 18 (4, 6, 6 +2)]
```

GM 会读取这个标记，围绕结果展开叙述。

游戏主持人在同一回合中多次掷骰时，每张骰子卡都会单独排队。关闭一张卡后就能看到下一张。所有掷骰都保存在该回合当前选中的备选回复里，重新加载后仍可在 **Logs**(日志) 中查看。继续当前回合会保留之前的掷骰，重新生成则会为新的备选回复建立独立的一组结果。

游戏主持人也可以在叙述中用 `[dice: 3d8+2]` 请求掷骰。引擎会给出真实数值，并显示相同的动画卡片。这也适用于仅支持文本的连接，包括 Claude 和 Grok 订阅连接。使用的记法和限制与骰子菜单相同。

## 自定义骰子写法

骰子菜单里还有一个输入框，可以填自定义掷骰，用的是标准的 `NdM` 写法。`N` 是要掷几颗骰子，`M` 是每颗骰子有几面。末尾可以加上加值或减值。

输入框的占位文字给了一个例子：`3d8+2`。意思是掷 3 颗 8 面骰，总和再加 2。

自定义掷骰的用法：

1. 点击骰子按钮打开菜单。
2. 在输入框里输入写法，比如 `2d6+1`。
3. 按 Enter，或者点输入框旁边的小纸飞机（发送）按钮。
4. 掷骰会以标签形式排进队列，随时可以发送。

还可以这样写：

- `d20` 掷一颗 20 面骰。
- `4d8-1` 掷四颗 8 面骰，再减去 1。
- `2d6+3` 掷两颗 6 面骰，再加上 3。
- `4d6kh3` 掷四颗 6 面骰，保留点数最高的三颗。`kl` 保留点数最低的骰子，而 `dh` 和 `dl` 则分别舍弃点数最高或最低的骰子，所以 `2d20kl1` 是带劣势的掷骰，`4d6dl1+2` 则舍弃点数最低的骰子，再加上 2。每颗掷出的骰子都会记录，但只对保留的骰子求和。

有两个硬性上限：一次最多掷 100 个骰子，每个骰子最多 1000 面。如果普通掷骰请求超出上限，应用会将其缩减到上限，而不是拒绝，并在结果卡片中显示调整后的记法。因此输入 `500d6` 会得到 `100d6` 卡片，表示实际掷出的一百个骰子。带保留或舍弃规则的掷骰如果超出上限，例如 `101d6kh3`，则会被拒绝，并显示超出范围的错误，因为缩减骰子数会改变保留哪些骰子。如果输入不是有效的骰子记法（即 `NdM` 或类似 `d20` 的单独 `dM`，其后可以加上 `kh`、`kl`、`dh` 或 `dl` 以及一个数字），掷骰会失败，并显示说明所需格式的错误。

<a id="symbol-dice-by-name"></a>

### 按名称掷符号骰

如果游戏的规则集使用符号骰（例如 Genesys 风格系统的 `symbol-pool` 规则集），自定义输入框也接受这些骰子的名称。为每种骰子写出数量和名称，例如 `2 ability 1 proficiency vs 2 difficulty`。名称可以是骰子的 ID 或标签，不区分大小写，之间可以用空格、逗号、`+` 或 `vs` 分隔。

卡片会显示每颗骰子的骰面符号，再列出相互抵消后剩下的符号，以及是否成功。加在消息里的标记也包含相同内容，例如 `[dice: 2 ability vs 1 difficulty = 1 Success, 1 Advantage; success]`。一次最多可以指定 40 颗骰子。GM 使用骰子工具掷骰时也可以使用这些名称。在所有游戏里，普通的 `NdM` 写法仍按上文的方式掷骰。

<a id="skill-checks"></a>

## 技能检定

技能检定用来判断有风险的行动能不能成功，比如潜行、发现线索、说服 NPC(玩家之外的角色)。技能检定不由你发起，而是 GM 在叙述里提出要求。应用随后把它变成一次带动画的 d20 掷骰，并给出结果横幅。

通过文本请求的检定从尝试行动开始。引擎算出掷骰结果后，会携带真实结果额外请求模型一次，让游戏主持人在同一回合内写完结果。这也会纠正在掷骰前就猜测结果的草稿。额外请求会再次发送提示词，消耗更多输入和输出 Token。若请求失败，该回合会保留已经确定的结果，但不会保存猜测或未写完的结果叙述。该回合会保留提示和 **Regenerate turn**(重新生成回合)按钮，重新加载聊天后也一样。

在 **Chat Settings → Function Calling**(聊天设置 → 函数调用)中关闭 **Narrate dice outcomes immediately**(立即叙述骰子结果)，就会保留真实结果供下一轮使用，不再发出这次额外请求。此设置默认开启。没有产生实际掷骰的请求不会触发额外叙述请求。

还有第三种选择，可以省去第二次请求，同时把结果保留在同一回合。参见下方[用一次请求完成掷骰回合](#finishing-a-rolled-turn-in-one-request)。

在支持骰子工具的连接上，游戏主持人可以在生成过程中获得真实掷骰结果。工具返回后，骰子卡立即出现；完成的检定会记录该结果，不会重复掷骰。每个已经结算的技能检定都有独立的结果横幅，排在待显示的骰子卡之后。

横幅上会显示技能名和目标数值，比如 **Stealth Check**(潜行检定) 后面跟着 **DC 15**。DC 是 Difficulty Class(难度等级) 的缩写，也就是掷骰结果必须达到或超过的数字。

### 结果怎么算出来

检定会掷 1 颗 20 面骰，再加上两个调整值：

- 技能调整值，来自游戏为你的角色记录的技能等级。如果游戏还没有这项技能的等级，这个调整值就是 0。
- 属性调整值，来自这项技能对应的主导属性。

骰面加上这两个调整值就是总值。总值达到或超过 DC，检定成功；没达到就是失败。每项技能都会自动对应一个主导属性，比如 Stealth 对应 Dexterity，Perception 对应 Wisdom，Persuasion 对应 Charisma。应用不认识的技能一律按 Intelligence 算。

### 大成功与大失败

有两种骰面会直接覆盖上面的算法：

- 自然 20(骰面本身就是 20) 算 **CRITICAL SUCCESS**(大成功)，哪怕 DC 很高也必定通过。
- 自然 1(骰面本身就是 1) 算 **CRITICAL FAILURE**(大失败)，哪怕调整值很高也必定失败。

横幅会显示四种结果之一：**CRITICAL SUCCESS**、**SUCCESS**(成功)、**FAILURE**(失败) 或 **CRITICAL FAILURE**。

### 其他骰子系统

游戏主持人可以指定其他记法，例如 `[skill_check: skill="Endurance" dc="12" dice="3d6+2"]`。这类检定使用记法中的固定修正值，而非角色表的 d20 修正值；总和达到 DC 就算成功。自然 1 和自然 20 的规则仅适用于上面介绍的标准 d20 检定。

成功数骰池必须同时指定每颗骰子的成功门槛和所需的成功次数：`[skill_check: skill="Intimidation" dc="4" dice="6d10" resolution="successes" threshold="6"]` 会掷六颗 d10，每颗结果至少为 6 的骰子计一次成功，至少获得四次成功才通过。引擎不会猜测缺失的门槛，也不实现爆骰、botch 规则或其他特殊骰池规则。没有有效门槛的骰池会保持未结算状态，模型编造的数值会被移除。

这是**没有规则集**的游戏所用的骰池，保持不变。采用骰池规则集的游戏则不同，其规则确实由引擎持有；参见[规则集中的检定](rulesets.md#checks-on-a-ruleset)。

检定的 `dice=` 属性只接受普通的 `NdM`。在这里请求 `4d6kh3`、`3d6!` 或 `4dF` 等记法不会掷骰。引擎会记录不支持的记法，并从检定记录中删除编造的数值。这些结果会保持未定；引擎不会悄悄替换成另一套骰子系统。

### 优势与劣势

GM 可以让一次检定带优势，也可以让它带劣势。同一次检定不会两者兼有。

- 带优势时，应用掷 2 颗 20 面骰，取点数较高的那颗。
- 带劣势时，应用掷 2 颗骰子，取点数较低的那颗。

如果 Game Master 同时要求优势和劣势，应用会保留该检定不作处理，不会猜测其意图，因此不会显示对应的结果横幅。

只要其中一种生效，横幅就会在 DC 旁边标出当前模式，并标明实际采用的是哪一颗骰子。

### 先掷好自己的骰子

检定发生之前，可以先从骰子菜单里排一个自己的 `d20`。这样一来，技能检定会直接用你掷出的点数，不再重新掷一颗新骰子。技能调整值和属性调整值仍然照常叠加。

<a id="games-that-use-a-ruleset"></a>

## 使用规则集的游戏

在使用规则集（例如 5e (SRD 5.1)）的游戏中，检定按规则集的方式掷骰：使用它自身的骰子、难度阶梯和人物卡调整值，有些规则集则使用骰池或符号骰。见[规则集中的检定](rulesets.md#checks-on-a-ruleset)。

<a id="finishing-a-rolled-turn-in-one-request"></a>

## 用一次请求完成掷骰回合

不开启时，掷骰回合需要两次模型请求：一次写草稿，一次根据实际数字重写结果。**Chat Settings → Function Calling**(聊天设置 → 函数调用) 中的 **Finish rolled turns in one request**(用一次请求完成掷骰回合) 会省去第二次请求。默认开启；在某个聊天里关闭它，该聊天就会改为按真实数值重写每个掷骰回合。

其原理是 Game Master 在任何数字产生之前就确定文字。它在决定发生什么之前看不到掷骰，因此无法根据拿到的点数引导结果。引擎随后掷骰，最终保存引擎的记录。

开关启用时，Game Master 会被要求根据结果本身的性质，从以下三种方式中选择一种书写检定。

**结果分成两种时，两种都写。** 先写不带数值的检定，再写包含成功和失败文本的块。引擎掷骰后保留结果选中的一半，在你读到回合前删去另一半。你看到的只有一个结果，如同先掷骰再写一样。

**结果只是数字时，写占位符后继续。** 对伤害、治疗、金币、时长、数量、距离等，Game Master 在句中写 `[[roll: 2d6+3]]`，引擎将数字填入。占位符也能引用人物卡调整值，例如 `[[roll: 1d8+STR]]`，由引擎自行添加；只有游戏确实有可读取的人物卡时才提供该形式，无法解析的名称会被拒绝，而不是当作零。悬停于占位符生成的数字可查看背后的骰子；每个数字也会在 **Logs**(日志) 中作为独立掷骰行显示。

**数字本身必须在三种以上结局中选择时，请求数值并停止。** 这就是 Game Master 现有的不带数值的简略检定或 `[dice:]` 请求。引擎掷骰并记录，回合不叙述结果就结束。Game Master 会在下一回合开头说明数字的含义，与关闭 **Narrate dice outcomes immediately**(立即叙述骰子结果) 时相同。

不符合这些形式的检定也会回退到同样的行为，因此不会放任未解决的检定，也不会编造结果。

启用前还需了解几点。

- **开启期间不使用 Narrate dice outcomes immediately。** 它仍显示，但被禁用并附有说明。保存值不变，关闭单次请求掷骰后会恢复原设置。
- **已有回合不会改变。** 开关只影响启用后生成的回合，已保存的记录读起来完全不变。
- **两种情况下仍可能需要多次请求。** 如果启用了 **Enable Tool Use**(启用工具使用) 且工具列表包含骰子工具，Game Master 仍可调用它，每次工具调用需要完整的额外往返。并且 **Game tool connection**(游戏工具连接) 只要不是 **Same as narrator**(与叙述者相同)，就总会发起自己的规划请求。两者都不是此开关省去的结果重写。
- **无法掷骰时会通知你。** 无法读取的数字会被短提示替换，不会填入编造值；无法读取的分支会保留掷骰记录但删去两半文字。无论哪种情况，**Logs** 都会用一行说明省略了什么。
- **回合写作期间**，占位符和分支块暂不进入流式文本，因此你不会看到数字出现后又改变。回合完成时才显示完整句子。

### 让 Game Master 看到每种面数的一颗骰子

下方还有 **Let the Game Master see one die of each size**(让 Game Master 看到每种面数的一颗骰子)，默认关闭。它针对两种盲写形式都无法处理的情况：数字本身必须从三种以上结局中选择，例如成功幅度、命中部位表或反应掷骰。不启用时，这类检定必须结束回合，在下一回合开头叙述。

启用后，引擎会在回合前为每种标准面数掷一颗骰子，并向 Game Master 展示各自的下一个值，让它消耗一颗并在同一次处理中写出其含义。

**请仔细理解这一取舍。** Game Master 在决定检定什么、难度多高之前就看到了数值。因此，它可以进行盲写形式无法进行的结果引导：选择拿到的点数能通过的难度，或在握着坏点数时干脆不要求检定。引擎无法判断难度是否符合故事，也就无法识别这种行为。不知道 Game Master 看过骰子的玩家，可能会把异常英勇的一局视为运气好。

引擎无需 Game Master 配合就会强制执行以下规则：

- **数值按顺序使用，绝不重复。** 引擎维护队列，无论回合怎样声称，都只发出下一个值。
- **记录中的所有数字都来自引擎。** 掷骰、调整值、总和与结果都依据队列和人物卡重新计算。Game Master 写出的不符数值会被替换，并在 **Logs** 留下一行说明。
- **难度有界限。** 它限制在 1 到 40，过去书写式检定并无此限制。使用规则集的游戏则可达到自身难度阶梯的上限。
- **再次请求不会改善运气。** 同一回合的滑动切换、重新生成和续写都面对同一批值，因此无法反复重掷直到好运出现。
- **只展示每种面数的下一个值。** 这由 **Values shown per size**(每种面数的展示数量) 控制，默认 1。同一回合之后再次掷相同面数时不会提前展示，改在下一回合叙述。
- **未消耗的骰子过一段时间会重掷。** 这由 **Rethrow after idle turns**(闲置回合后重掷) 控制，默认 3。没有它，Game Master 只需一直避开该面数，低值就可能在整场聊天中始终占据队首。设为 0 会关闭重掷，恢复这种行为。
- **请求超过队列容量的掷骰不会生成新骰子。** 检定保留问题、去掉所有数字，并在下一回合叙述。**Logs** 会说明发生在哪一回合。
