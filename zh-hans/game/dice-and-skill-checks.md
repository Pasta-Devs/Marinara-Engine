# Game Mode：骰子与技能检定

在 Game Mode(游戏模式) 里，用骰子按钮为游戏主持人（GM）掷骰。本指南还会说明 GM 如何按难度等级（Difficulty Class，DC）判定技能检定，DC 就是掷骰结果必须达到或超过的数字。

## 掷骰

消息输入栏里有一个骰子按钮，它的提示文字是 **Roll dice**(掷骰)。

1. 点击骰子按钮，打开快捷骰子菜单。
2. 点击一个预设：d20、d6、2d6、d10、d100、d4、d8 或 d12。
3. 输入栏里会出现一个小标签，形如 `🎲 d20`。这次掷骰已排进队列，还没有发出。
4. 发送消息。Marinara 会掷骰，并把结果作为一个标记加到消息末尾，GM 会读取它并围绕结果展开叙述。

想在发送前去掉已排队的掷骰，点击小标签上的 **Clear queued roll**(清除排队的掷骰)。

单颗骰子、没有加值时是这样：

```text
[dice: d20 = 14]
```

多颗骰子或者带加值时，还会列出各个部分：

```text
[dice: 3d8+2 = 18 (4, 6, 6 +2)]
```

GM 也可以在叙述里用 `[dice: 3d8+2]` 请求掷骰。Marinara 会给出真实数值，并显示同样的动画卡片。这在仅支持文本的连接上也有效，包括 Claude 和 Grok 订阅。GM 在一个回合里多次掷骰时，每张骰子卡会依次排队：关掉一张才能看到下一张。所有掷骰都保存在该回合当前选中的备选回复里，重新加载后仍保留在 **Logs**(日志) 中。继续这个回合会保留之前的掷骰。重新生成则会为新的备选回复建立一组新的结果。

## 自定义掷骰

骰子菜单里有一个输入框，可以用 `NdM` 写法填写自定义掷骰：`N` 颗骰子，每颗 `M` 面，末尾可以加上加值或减值。输入框里显示的例子是 `3d8+2`(3 颗 8 面骰，再加 2)。

1. 打开骰子菜单。
2. 输入写法，比如 `2d6+1`。
3. 按 <kbd>Enter</kbd>，或者点击纸飞机按钮。这次掷骰会以小标签的形式排进队列。

| 写法 | 含义 |
| --- | --- |
| `d20` | 一颗 20 面骰 |
| `4d8-1` | 四颗 8 面骰，减 1 |
| `4d6kh3` | 掷四颗 6 面骰，保留最高的三颗 |
| `2d20kl1` | 保留最低的一颗：带劣势的掷骰 |
| `4d6dl1+2` | 舍弃最低的一颗，加 2 |

`kh` 和 `kl` 保留点数最高或最低的骰子，`dh` 和 `dl` 则舍弃它们。每颗掷出的骰子都会记录，但只对保留的骰子求和。

如果没有成功：不是 `NdM` 或单独 `dM` 的文字（后面可以跟 `kh`、`kl`、`dh` 或 `dl` 以及一个数字）会失败，并显示说明所需格式的错误。

一次最多掷 100 颗骰子，每颗骰子最多 1000 面。超出上限的普通掷骰会被缩减到上限，卡片上显示缩减后的写法，所以 `500d6` 会得到一张 `100d6` 卡片。超出上限的保留或舍弃掷骰，例如 `101d6kh3`，会被拒绝，并显示超出范围的错误，因为缩减会改变保留哪些骰子。

## 技能检定

技能检定用来判定有风险的行动，比如潜行、发现线索或说服 NPC(玩家之外的角色)。检定不由你发起，而是 GM 在叙述里提出，Marinara 再把它变成一次带动画的 d20 掷骰，并给出结果横幅。横幅上显示技能和目标，比如 **Stealth Check**(潜行检定) 和 **DC 15**。每个已结算的检定都有自己的横幅，排在已排队的骰子卡之后。

<a id="how-the-result-is-decided"></a>

### 结果怎么判定

检定掷一颗 d20，再加上两个调整值：

- 技能调整值，来自游戏为你的角色记录的技能等级。如果游戏还没有这项技能的等级，这个调整值就是 0。
- 属性调整值，来自这项技能主要依赖的属性。具体使用哪些属性取决于游戏，见下文。

在共享游戏中，每次检定都会读取检定所指角色的属性。

<a id="mrpg-games"></a>

#### MRPG 游戏

采用 **MRPG** 职业的游戏（也就是所有新游戏）使用角色的 MRPG 属性调整值，也就是当前职业提供的属性（见 [MRPG 职业](mrpg-classes.md#what-the-stats-mean)）。升级后角色卡上仍保留的 Legacy 属性不会使用。每项技能主要依赖一个属性：

| 属性 | 技能 |
| --- | --- |
| Strength | Athletics、Intimidation |
| Speed | Acrobatics、Stealth |
| Skill | Sleight of Hand、Investigation、Perception、Medicine、Survival、Animal Handling，以及此处未列出的所有技能 |
| Defense | Endurance、Constitution |
| Magic | Arcana、History、Nature、Intelligence |
| Resistance | Insight、Religion、Wisdom |
| Luck | Persuasion、Deception、Performance、Charisma |

检定会加上该属性的五分之一（向下取整），最多 +5。对于新角色最强的属性，这通常约为 +1；到 10 级时约为 +2 或 +3；达到最高等级时为 +5。较弱的属性不提供任何加值。由于属性随当前职业变化，切换职业也会改变这些加值。

<a id="legacy-games"></a>

#### Legacy 游戏

在 **Legacy** 游戏中，调整值来自人物卡上这项技能的主导属性。每项技能都会自动对应一个属性：Stealth 对应 Dexterity，Perception 对应 Wisdom，Persuasion 对应 Charisma。Marinara 不认识的技能一律使用 Intelligence。

<a id="the-result"></a>

#### 结果

总值达到或超过 DC，检定就成功。有两种骰面会直接覆盖这套算法：

- 自然 20 算 **CRITICAL SUCCESS**(大成功)，必定通过。
- 自然 1 算 **CRITICAL FAILURE**(大失败)，必定失败。

横幅会显示 **CRITICAL SUCCESS**、**SUCCESS**(成功)、**FAILURE**(失败) 或 **CRITICAL FAILURE**。

### 优势与劣势

GM 可以让一次检定带优势（掷两颗 d20，取较高的那颗）或劣势（取较低的那颗）。横幅会在 DC 旁边标出当前模式，并标明实际采用的是哪颗骰子。如果 GM 同时要求优势和劣势，Marinara 不会去猜，而是不处理这次检定，所以不会显示它的横幅。

### 先掷好自己的 d20

在检定发生之前，先从骰子菜单里排一个 `d20`。这样检定会直接用你掷出的点数，不再重新掷一颗新骰子。技能调整值和属性调整值仍然照常生效。

GM 在掷骰后如何写完一个回合，以及这样做要花多少，见[掷骰回合怎么叙述](#how-a-rolled-turn-is-narrated)。

<a id="games-that-use-a-ruleset"></a>

### 使用规则集的游戏

在使用规则集（例如 5e (SRD 5.1)）的游戏里，检定使用规则集自己的骰子、难度阶梯和人物卡调整值，有些规则集还会用骰池或符号骰。见[规则集中的检定](rulesets.md#checks-on-a-ruleset)。

## 参考

<a id="how-a-rolled-turn-is-narrated"></a>

### 掷骰回合怎么叙述

GM 在文字里要求检定时，Marinara 会结算骰子，并有三种方式写完结果。这三种都在 **Chat Settings → Function Calling**(聊天设置 → 函数调用) 里。

| 设置 | 默认值 | 效果 |
| --- | --- | --- |
| **Finish rolled turns in one request**(用一次请求完成掷骰回合) | 开启 | 一次请求。GM 写下不带数字的结果，由 Marinara 填入数字。见下文。 |
| **Narrate dice outcomes immediately**(立即叙述骰子结果) | 开启 | 两次请求。GM 先写草稿，Marinara 掷骰，然后再发一次请求，带着真实结果重新发送提示词，让 GM 在同一回合内写完结果。这会消耗更多输入和输出 Token。 |
| 两者都关闭 | | 真实结果留到下一回合使用，不额外请求。 |

使用 **Narrate dice outcomes immediately** 时，如果额外请求失败，该回合会在日志里保留已结算的结果，但不会保存猜测的或写了一半的结果。回合上会保留一条带 **Regenerate turn**(重新生成回合) 按钮的提示，重新加载后也一样。没有实际掷骰的请求绝不会触发额外请求。

在支持骰子工具的连接上，GM 也可以改为在生成过程中拿到真实掷骰。工具一返回，骰子卡就会出现，完成的检定会记录这个结果，不会再掷一次。

<a id="finishing-a-rolled-turn-in-one-request"></a>

#### 用一次请求完成掷骰回合

不开启时，掷骰的回合要花两次请求。**Finish rolled turns in one request** 会省去第二次。它默认开启。在某个聊天里关闭它，这个聊天就会改为按真实数值重写每个掷骰回合。

它之所以可行，是因为 GM 在任何数字产生之前就定下了文字。它在决定发生什么之前看不到掷骰，所以无法引导结果。Marinara 随后掷骰，并保存自己的记录。开关开启时，GM 会用以下三种方式之一写检定：

- **两种结果。** GM 先写不带数字的检定，再写一行成功文字和一行失败文字。Marinara 掷骰后保留掷骰选中的那一半，并在你读到这个回合之前删掉另一半。
- **只有一个数字。** 对于伤害、治疗、金币、时长、数量或距离，GM 会在句中写一个占位符，比如 `[[roll: 2d6+3]]`，由 Marinara 把数字填进去。占位符可以引用人物卡调整值，例如 `[[roll: 1d8+STR]]`。只有游戏确实有可读取的人物卡时才提供这种形式；Marinara 无法解析的名称会被拒绝，而不是当作零。把鼠标悬停在占位符生成的数字上，可以看到它背后的骰子。每个数字也会在 **Logs** 里显示为一条独立的掷骰记录。
- **三种或更多结局。** GM 请求数值后就停下。Marinara 掷骰并记录，回合在没有结果的情况下结束，GM 会在下一回合开头叙述这个数字意味着什么。

不符合这几种形式的检定会回退到最后一种行为，所以不会有检定悬而未决，也不会有结果被编造。

- 开启期间不使用 **Narrate dice outcomes immediately**。它仍会显示，但处于禁用状态；它保存的值不变，等你关闭这个开关时再用。
- 已有回合不会改变。开关只影响开启之后生成的回合。
- 有两种情况下，一个回合仍可能花不止一次请求：开启了 **Enable Tool Use**(启用工具调用)，且工具列表里有骰子工具（每次工具调用都要多一整轮往返）；或者 **Game tool provider**(游戏工具服务商) 设成了 **Same as narrator**(与旁白相同) 以外的选项（它总会发起一次规划请求）。
- 无法掷骰时，数字会被一条简短提示代替，绝不会填入编造的值。**Logs** 会说明省略了什么。
- 回合写作期间，占位符和分支块不会进入流式文本，所以你不会看到数字变来变去。

<a id="symbol-dice-by-name"></a>

### 按名称掷符号骰

如果游戏的规则集使用符号骰（`symbol-pool` 规则集，例如 Genesys 风格的系统），自定义输入框也接受按名称填写这些骰子。为每种骰子写出数量和名称，例如 `2 ability 1 proficiency vs 2 difficulty`。名称可以是骰子的 id 或标签，不区分大小写，用空格、逗号、`+` 或 `vs` 分隔。一次掷骰最多可以指定 40 颗骰子。

卡片会显示每颗骰子的骰面符号，再列出相互抵消后剩下的符号，以及是否成功。消息里的标记也包含同样的内容，例如 `[dice: 2 ability vs 1 difficulty = 1 Success, 1 Advantage; success]`。GM 的骰子工具也接受这些名称。普通的 `NdM` 在所有游戏里仍然有效。

### 技能检定中的其他骰子

GM 可以指定其他写法，例如 `[skill_check: skill="Endurance" dc="12" dice="3d6+2"]`。这类检定使用写法中的固定调整值，而不是 d20 的人物卡调整值，总值达到 DC 即成功。自然 1 和自然 20 的规则只适用于标准的 d20 检定。

成功数骰池必须同时给出每颗骰子的成功门槛和所需的成功次数：`[skill_check: skill="Intimidation" dc="4" dice="6d10" resolution="successes" threshold="6"]` 会掷六颗 d10，每颗结果至少为 6 的骰子计一次成功，至少获得四次成功才通过。Marinara 不会猜测缺失的门槛，也不实现爆骰、botch 规则或其他特殊骰池规则。没有有效门槛的骰池会保持未结算状态，编造的数值会被移除。

这是没有规则集的游戏所用的骰池。以骰池为基础的规则集游戏则不同：见[规则集中的检定](rulesets.md#checks-on-a-ruleset)。

检定的 `dice=` 属性只接受普通的 `NdM`。`4d6kh3`、`3d6!` 或 `4dF` 这类请求不会掷骰：Marinara 会记录不支持的写法，删除编造的数值，结果保持未定。

### 让 Game Master 看到每种面数的一颗骰子

**Let the Game Master see one die of each size**(让 Game Master 看到每种面数的一颗骰子) 在 **Finish rolled turns in one request** 下方，默认关闭。它服务于盲写形式无法处理的一种情况：数字本身必须在三种或更多结局之间选择，例如成功幅度或命中部位表。不开启时，这类检定会结束回合，在下一回合叙述。

开启后，Marinara 会在回合开始前为每种标准面数各掷一颗骰子，并把每种的下一个值展示给 GM，让它在同一次生成中写出这个值意味着什么。

> **警告：** 这样一来，GM 在决定检定什么、难度多高之前就看到了数字。它可以挑一个手里那颗骰子能通过的难度，或者在握着坏点数时干脆不要求检定。Marinara 无法判断某个难度是否符合故事，所以发现不了这种情况。一局英勇得可疑的游戏，可能是在操纵运气。

无需 GM 配合，Marinara 就会强制执行以下规则：

- 数值按顺序给出，没有一个会出现两次。
- 记录里的每个数字都来自 Marinara。掷骰、调整值、总值和结果都会依据队列和你的人物卡重新计算。对不上的数字会被替换，**Logs** 也会注明。
- 难度限制在 1 到 40 之间。使用规则集的游戏可以达到其规则集难度阶梯的上限。
- 同一回合的切换备选回复、重新生成或续写都面对同一批值，所以无法靠重掷碰运气。
- **Values shown per size**(每种面数的展示数量) 决定 GM 每种面数能看到几个值，默认是 1。同一回合里之后再掷这种面数时，GM 看不到，结果在下一回合叙述。
- **Rethrow after idle turns**(闲置回合后重掷，默认 3) 会在闲置这么多回合后，把没用掉的骰子重新掷一次。没有它，一个低值可能在整个聊天剩下的时间里一直排在最前面。设为 0 会关闭重掷。
- 如果 GM 请求的掷骰比队列里存的多，这次检定会保留问题、去掉所有数字，并在下一回合叙述。**Logs** 会说明是哪一回合。
