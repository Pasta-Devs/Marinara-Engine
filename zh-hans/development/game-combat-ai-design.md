## 1. 维护者要求什么

- 普通敌人由引擎控制，以**一个性格形容词加一个战斗职责**描述行为，例如 Reckless Bruiser 或 Cautious Spellcaster。
- **只有首领级敌人才由 GM 逐回合控制。** 引擎仍决定哪些动作合法并结算结果。首领控制指战斗中选择动作，不是仅在开战前生成脚本。
- 分配性格时综合熟练程度/等级、战斗职责、已知个性和适量随机性。有经验的敌人应更常拥有适合职责的习惯，但不能让所有老兵都一样。
- **每个 Beast 和 Monstrosity 都是 Mindless。** 它们沿最短合法路线追击最近队员，忽略目标生命值及地形利弊。首领和具名生物也不能被悄悄豁免。
- 提高策略乐趣、行为可信度和重玩价值，尤其是 Tactical 及未来的桌游式玩法。本次 AI 改动无须同时实现 5e 或 V20 规则。
- 保留详细设计以供以后实施。最初的探索范围此后扩展到普通 AI和同伴控制；请参阅上面的范围更新。

相关方向见[战斗路线图](game-combat-roadmap.md)：战场规则、队伍/召唤参与方式、桌游规则档案各自独立，敌人战术也应如此。Summoning 优先级靠后。

### 仍需设计确认的建议默认值

1. 首批使用八个形容词：Mindless、Reckless、Cautious、Opportunistic、Protective、Supportive、Disciplined、Cowardly。
2. 在敌人详情中显示性格和战斗职责，并附简短解释。常规 UI 不显示概率、效用权重或原始个性分析。
3. Mindless 的最短路线指**合法空间步数最少**，并非地形移动成本最低。即使绕行开阔地更快，它仍可能选择较短的森林路线；实际移动照常支付地形成本。
4. Beast/Monstrosity 首领仍为 Mindless。GM 只能在符合指定目标与追击行为的合法动作中选择。
5. 普通行为档案只抽取一次并保存。再次出现的具名 NPC 保留已确定的性格，升级本身不重新随机性格。
6. 按更新后的范围，同时在 Tactical 和 Classic 实现普通 AI。完整需求还包括真正的 GM 首领回合，不能把仅由引擎控制的阶段成果说成全部功能。

## 2. 重构前的源码审计

维护者的第二个猜测最接近事实：每个正在使用的战斗引擎都有一套共同的自动策略。GM 负责创建遭遇，不在当前 Game Mode 战斗界面中选择每个单位的行动。

| 区域 | Classic Game Mode | Tactical Game Mode |
| ----------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 行动顺序 | 先攻掷骰加速度；所有战斗单位参与 | 新游戏按先攻行动（一次一个单位，顺序每场战斗只掷一次，combat C6c）；旧游戏按阵营行动（玩家阶段，然后敌人按速度行动） |
| 敌人策略 | 共用技能启发式，否则随机选择存活对手 | 共用先治疗、再按评分攻击、最后接近的策略 |
| 职业差异 | 没有职业专属决策策略 | 六个职业改变射程、移动和暴击，但共用决策策略 |
| 性格与熟练程度 | 未保存战术性格或训练模型 | 未保存战术性格或训练模型 |
| 首领决策 | 普通策略加支持的脚本机制 | 普通策略；首领标签影响站位和 UI |
| 逐回合 GM 控制 | 当前结算器中没有 | 当前结算器中没有 |
| 可复现性 | 决策和掷骰使用无种子的随机数 | 种子与动作计数器控制决策和战斗掷骰 |
| 持久化 | 客户端恢复战斗快照；轮次/动画状态未完全保存 | 完整 Tactical 快照存于聊天元数据 |

此外还有独立的遭遇弹窗系统，使用模型驱动的 `/encounter/action` 路由和战斗动作类型。普通聊天的 `EncounterModal` 通过 `useEncounter` 使用它，当前 Game Mode 的 `GameCombatUI` 并不使用。该模型可以返回改写后的战斗状态，不能原样复用为由引擎校验的首领控制器。复用或删除前先追踪实际调用方。

Classic 另有显式 **Special**(特殊动作)，请 GM 裁决叙事动作，并允许受支持的状态/元素标签。它不结算普通轮次，也不选择常规敌方动作。修改 GM 提示词时保留此区别：“仅首领获得回合控制”不妨碍生成遭遇、叙事裁决或战后旁白。

### Classic 策略

在 `combat.service.ts` 中，`resolveCombatRound` 为自动行动的盟友和敌人调用 `chooseAutoSkill`：

1. MP 足够且冷却通过按轮次取模的检查时，技能被视为可用。
2. 若有治疗技能，治疗符合条件且 HP 不超过 75% 的、受伤最重的盟友。
3. 否则，有 45% 的几率选择随机的非治疗技能和随机的敌方目标。
4. 否则攻击随机对手。

敌人传入的盟友列表只有自身，因此这套策略暂时不会治疗其他敌人。非治疗技能还包括增益、攻击和减益；替换策略应检查各技能适用的阵营，不能保留这一粗分组。实际上，下述生成敌人 MP 丢失问题会阻止它们使用有正成本的技能，只剩随机选目标的普攻。玩家方第一个存活单位接收玩家提交的命令，其余盟友自动行动。修改敌方策略时，不能悄悄改变同伴控制方式或玩家身份。

生成的机制在普通动作后单独处理。目前只执行 `round_interval` 和 `hp_threshold`；虽然接受 `on_hit`、`on_attack`、`passive` 触发器，却不执行它们。HP 阈值机制会在之后满足条件的轮次重复触发，`damage_one` 选择首个敌对目标。这不是 GM 实时选择首领动作。改造前明确区分一次性和重复效果。

Classic 还通过偏向伤害的路径结算非治疗技能。增益/减益不等同于 Tactical 的支援操作，虽然命中可附加具名状态。宣称 Classic 支持这些行为前，需要真正的支援/控制语义和逐次使用的冷却状态。自动防御/等待也需要结算器支持；当前防御在玩家的先攻位置生效，更快的敌人会先行动。当前难度通过通用结算器缩放双方伤害，不改变决策质量。保留或修改此行为，应与性格调参分开。

还有一个独立的玩家控制不一致问题，需要单独验证：索引为零的单位 KO 后，服务器将命令交给首个存活盟友，UI 的活动玩家索引却仍为零；不可用的技能 ID 还可能回退为普攻。应单独记录并修复，不要与敌人性格混在一起。

### Tactical 策略

`packages/shared/src/features/tactical-combat/ai.ts` 当前：

1. 若两格内 HP 比例最低的盟友不超过 60% HP，尝试第一个就绪治疗技能。不会先移动到治疗范围内。
2. 针对存活对手，评估可达的移动终点及可执行的普攻、已就绪攻击技能。
3. 攻击评分为 `1000 * likelyKill + expectedDamage - 0.75 * counterRisk`。likelyKill 指预测伤害达到当前 HP 且命中率至少 50%，并不保证击杀。
4. 偶尔把最佳非致命攻击替换为随机合法攻击。概率依次为 casual 60%、normal 30%、hard 10%、brutal 0%；接受治疗的概率分别为 50%、80%、100%、100%。
5. 无可用攻击时，向曼哈顿距离最近的对手靠近，并选择距其最近的可达格。这不是全棋盘最短路径追击，可能无法绕过障碍。

地形影响移动和伤害/命中预测，但该策略没有对单位在下一个玩家阶段将暴露在哪里进行总体评估。它不会刻意选择增益、减益、防御或物品。技能范围被简化。生成的 AoE 描述并不构成完整的空间 AoE 结算器。

职业包括 Fighter、Knight、Rogue、Archer、Mage 和 Healer。推导职业时使用显式提示、治疗技能、名称/技能关键词、元素攻击及属性启发式。职责标签本身不授予能力。

### 会破坏性格系统的基础缺口

以下结论来自源码检查，并非已经在浏览器中复现：

| 缺口 | 证据与后果 | 最小下一步 |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 生成敌人没有 MP | `generatedEnemyToCombatant` 未传递 MP/maxMP；生成的非普攻技能有正 MP 成本。两个引擎都将缺失 MP 当作零，因此无法使用这些技能 | 以实际蓝图转换添加回归证明；保留显式资源或采用有文档说明的生成敌人资源规则，不能给无限施法 |
| 等级由 HP 推算 | 生成敌人的等级通常取舍入后的 maxHP/20；耐打不等于受过战术训练 | 增加有界的熟练程度提示；等级只能是明确说明的回退值，直到规则档案提供合适训练数据 |
| 首领身份依赖启发式 | Tactical 在至少两个敌人中按 maxHP + level\*10 + attack 选最强者，单个敌人不会被标为首领 | 明确指定每个敌人的首领身份；遭遇音乐等级不能确定谁获得 GM 行动 |
| 生成的首领机制未传入 Tactical | Classic 接收机制 props；Tactical 不使用生成的机制列表 | 映射为已验证的 Tactical 操作，保存阶段/触发状态；标明不支持的机制，不把它们叙述成已经执行 |
| 生物类型与个性不在运行时契约中 | 敌人描述存于蓝图，却在转换时丢失；Beast/Monstrosity 不是类型化类别 | 在全部转换和持久化边界保留显式类别及有界分配输入 |
| Tactical 的视线和掩护是共享的（combat C6）| 无论原生战斗还是规则集战斗，墙或山都会遮挡视线，掩护也按同一套检测分级（半掩护、四分之三掩护）：预览、动作、反击、区域、反应、威胁叠层和 AI 都使用 `hasLineOfSight` 和 `coverTier` | 所有调用方都只用一套视线检测和一套掩护检测 |
| AI 候选动作预测读取候选格 | 两种 AI 都从它们将要出手的那一格来预测攻击及其可能招致的反击，因此掩护（combat C6a-2）会按实际掷骰时的情况来权衡 | 预测和结算都只用同一个 `hitChance` |

另一个转换缺口影响两个引擎：攻击类型按名称/描述中的英文关键词推断，遭遇文本却可能是其他语言。蓝图的 `AoE`/`both` 标志也没有保留为实际多目标行为。未来职责推导应依赖经过校验的显式能力字段，不能由翻译后的名称决定法术是治疗还是攻击。

不要把完整战斗重写塞进这些前置修复。添加最小可运行证明，修好相关流程，复用现有移动、预测、技能就绪和动作结算函数。

## 3. 分离能力、性格与控制方式

每个敌人都需要回答不同的问题：

| 方面 | 意义 | 例子 |
| ------------------- | ------------------------------------------------ | ---------------------------------------------------------------------- |
| 生物类别 | 应用强制类别规则 | Beast 强制使用 Mindless |
| 战斗职责 | 实际能力组合适合做什么 | Supporter 具有可用治疗/增益技能 |
| 性格 | 选择合法动作时重视什么 | Cautious 重视避免暴露于危险 |
| 熟练程度 | 执行自身习惯的稳定性 | 资深 Reckless Bruiser 仍冒险，但减少无效行动 |
| 控制器 | 谁选择行动 | 普通敌人由引擎控制，明确指定的首领由 GM 控制 |
| 遭遇目标 | 各方想达成什么 | 目前击败队伍；未来可保护、逃离、俘获 |

起步只用一个主要形容词。不要加入任意叠加特质、个性向量编辑器、行为树依赖或通用规划框架。围绕共用合法候选动作使用一张小型行为档案表即可。

### 基于能力的战斗职责

现有 Tactical 职业继续作为空间规则和属性预设。实际能力允许时，可用小型策略职责映射作进一步区分：

| 建议职责 | 能力依据 | 典型任务 | 倾向的形容词 |
| ------------- | -------------------------------------------------- | ---------------------------------------------------- | ------------------------------------ |
| Bruiser | 强力近战攻击 | 接近并交换伤害 | Reckless、Disciplined、Opportunistic |
| Bulwark | 耐打的近战能力组合 | 在脆弱盟友附近占住有用位置 | Protective、Disciplined、Cautious |
| Skirmisher | 机动能力和有效近战伤害 | 选择有利交锋 | Opportunistic、Cautious、Reckless |
| Marksman | 稳定的远程攻击，可能有最小射程 | 保持有效射击距离 | Cautious、Disciplined、Opportunistic |
| Spellcaster | 可用的进攻法术及其资源池 | 远程施压而不浪费有限技能 | Cautious、Disciplined、Opportunistic |
| Controller | 可用的减益/控制效果 | 削弱相关威胁 | Disciplined、Opportunistic、Cautious |
| Supporter | 可用的治疗/增益能力 | 维持队伍效能 | Supportive、Protective、Cautious |

这些是先验偏好，并非限制。Cowardly Fighter 和 Reckless Spellcaster 仍须可选；穿甲且能近战的 Cleric 可以是 Bulwark，治疗者可以偏好后排。不能只凭职业刻板印象推断性格。暂时耗尽 MP 只改变合法动作，不改变保存的职责或性格。不能给从未具备支援能力的单位分配 Supportive。

## 4. 性格形容词目录

### 首批八种

| 形容词 | 目标偏好 | 定位与风险 | 技能/资源行为 | 玩家可以学到什么 |
| ----------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| **Mindless** | 按第 6 节规则选择最近且存活、可达的队员 | 最短合法空间路线，忽略地形收益、受威胁程度和阵形 | 简单合法攻击该目标，不作治疗优先级、集火或资源优化 | 用距离、地形和瓶颈诱导 |
| **Reckless** | 即时伤害和可达的压迫目标，不必是最弱者 | 激进接近，容忍反击和危险站位 | 乐于使用强力攻击，很少停下防御 | 惩罚过度深入，诱导不利换血 |
| **Cautious** | 可施压且受反击伤害有限的目标 | 重视安全终点、有效射程和防御地形 | 普攻效果接近时节省稀缺资源；需要时治疗/防御 | 压缩其安全区域，利用其不愿冒进的习惯 |
| **Opportunistic** | 受伤、暴露或已受牵制的目标，以及可靠的收割机会 | 愿意为具体机会承担一定风险 | 重视创造或利用机会的技能 | 保护脆弱队友，避免被轻易收割 |
| **Protective** | 威胁指定脆弱盟友或附近受保护群体的敌人 | 保持支援距离，合法时占住有用的阻挡格 | 为保护对象使用防御/支援；不急需保护时攻击 | 分散其队伍或从多方向进攻 |
| **Supportive** | 队友生命和有效增益优先于自身输出 | 移动到合法支援范围，避免无谓暴露 | 治疗实际缺失的 HP，避免过量治疗和重复增益；支援收益低时攻击 | 压制支援单位，或将其与队友分隔 |
| **Disciplined** | 适合职责的目标及合理收割机会 | 平衡伤害、安全、站位与资源，适度保持目标 | 稳定执行职责基础，不偏执于单一极端 | 打乱其职责，迫使其面对不利选择 |
| **Cowardly** | 安全可达且不会招致反击的目标 | 受伤或局部人数劣势时更重视保命，退向安全友方区域 | 更愿意自疗/防御，避免高代价投入 | 切断安全退路，持续远程压制 |

Protective 不会凭空转移伤害、嘲讽、拦截攻击或获得反应。现有占格规则允许靠站位阻挡，更强的保护必须有实际能力。Cowardly 可撤退防御，但 Tactical 现有的 `flee` 会结束整场战斗。**绝不能用全局 flee 让单个敌人逃跑。** 单位独立撤退/投降需要明确的新规则。

Cautious 与 Cowardly 应产生不同结果：健康的 Cautious Marksman 占据良好射击位置，受伤的 Cowardly Marksman 则可能为自保放弃好机会。Protective 与 Supportive 也不同：前者保护人员或位置，后者追求有效支援。

### 扩展候选：必须有独特行为与验证

| 形容词 | 独特的行为 | 发布前提 |
| ----------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Vengeful | 盯住上次攻击者或亲眼看到的队友击杀者，即使别的目标略优 | 少量持久战斗记忆；目标不可用时合法换目标 |
| Patient | 占住有价值位置，等待敌人进入有利射程 | 有界的等待/交锋规则和防止无限等待的进展保护 |
| Predatory | 追踪孤立目标，有机会时发起进攻 | 需要孤立程度指标，不能覆盖 Beast/Monstrosity 强制 Mindless 的规则 |
| Fanatical | 为明确仪式、领袖或任务牺牲安全 | 遭遇目标必须有可见进度与失败条件 |
| Methodical | 构建受支持的减益/攻击序列，而不是追逐即时伤害 | 显式组合依赖、有限记忆以及与 Disciplined 的明显区别 |
| Coordinated | 考虑盟友意图，减少重复攻击/支援 | 仅使用有限团队意图，不能全知地完美协作 |
| Territorial | 防守某处，越过边界后停止追击 | 保存区域/目标，并提供易懂的脱离行为 |
| Deceptive | 使用真正的佯攻、诱饵或隐藏能力来误导 | 支持欺骗/感知机制；仅靠叙述无法产生效果 |

避免推出评分完全相同的同义性格。除非规则有独特目标，Cruel 基本等于 Opportunistic。Strategic 应保留给真正的有界规划，而非“各方面都更强”的标签。勇气与智力不必是同一标尺的两端。

## 5. 分配行为档案：职责、经验、个性，再加入有种子的随机性

### 优先级

1. 校验显式生物类别。Beast/Monstrosity 无论等级、个性、难度或首领身份都必须为 Mindless。丢弃冲突的模型性格提示并记录分配来源；作者或导入数据明确指定的已定档案若冲突，则给出可操作错误，不能悄悄改写已保存选择。
2. 恢复遭遇时保留已确定且有效的行为档案。有稳定身份时，保留已知常驻 NPC 的既定性格。
3. 对其他生物，尊重与能力相容的作者指定档案。不支持或冲突的显式输入应报明确校验错误；缺失输入才用默认值。
4. 从实际能力推导职责；能力不明确时使用经过校验的职责提示。
5. 计算熟练程度、职责先验和有界的个性调整。
6. 通过有种子的加权抽样选定一个行为档案，并保存结果与策略版本。

初期普通随机分配不包含 Mindless。未来作者指定的亡灵/构装体行为可使用它，但 Beast/Monstrosity 的强制规则不变。旧敌人类别不明时用显式 `unknown`；名字含“beast”不等于声明了生物分类。

### 熟练程度不等于 HP、难度或道德评价

优先采用规则档案的训练层级或可靠 NPC 人物卡，其次使用经过校验的显式遭遇提示。两者都缺失时才回退到等级，并记录来源。目前由 HP 推算的等级只是弱回退值，不能悄悄变成衡量智力的权威。

初期不绑定规则集时，可将新手/受训/资深/大师映射为熟练程度 `c = 0, 0.35, 0.7, 1`。临时引擎等级回退示例为 1–2 级新手、3–7 级受训、8–14 级资深、15+ 大师。这是可调的游戏设计曲线，不是桌游规则；标记来源为 `level-fallback`，尤其是等级由 HP 推算时。映射固定在分配版本中，有规则档案映射时替换。不能把 5e 挑战等级等同角色等级，也不能给 V20 式游戏强加等级层级。

经验**既**影响首次分配时获得适合职责性格的概率，也影响遵循该性格的稳定程度。普通本地 AI 不因此获知隐藏能力或排队命令。GM 首领按第 16 节知晓更完整的队伍人物卡，但两者都看不到未来随机掷骰或尚未确认的玩家选择。幸存者倾向可作为世界观偏好，不代表所有资深法师都谨慎。

### 具体权重模型

使用小型职责/性格表和有界公式。以下起始值仍须实战测试：

```text
w[a] = baseRoleWeight[role,a] * exp(1.2*c*roleAffinity[role,a] + 1.5*q*personalityMatch[a])
P[a] = 0.94 * w[a]/sum(w) + 0.06/N
```

- `c`：能力，0..1。
- `roleAffinity`：作者指定的职责匹配度，范围 -1..1；同一性格可适合多个职责。
- `personalityMatch`：由有界证据映射到 -1..1，并非模型可任意给出的数字。
- `q`：对已知人格的置信度，0..1；未知时为零。
- `N`：相容性格的数量；归一化前排除不相容档案。若全部被排除，采用已校验的 Disciplined/基础回退并记录输入问题。
- 6% 混合项让每种相容但少见的档案都有小概率出现，绝不弱化强制类型规则。

示例：**具有支援技能的多面手施法者**，没有个性证据：

| 形容词 | 基础权重 | 角色亲和力 | 新手概率 | 大师概率 |
| ------------- | ----------- | ------------- | ------------------ | ------------------ |
| Cautious | 4 | 1 | 23.0% | 35.8% |
| Disciplined | 4 | 1 | 23.0% | 35.8% |
| Opportunistic | 3 | 0.5 | 17.4% | 15.2% |
| Supportive | 1 | 0 | 6.4% | 3.5% |
| Protective | 1 | 0 | 6.4% | 3.5% |
| Reckless | 2 | -1 | 11.9% | 2.4% |
| Cowardly | 2 | -0.5 | 11.9% | 3.7% |

因四舍五入，总和可能不精确等于 100%。已知鲁莽个性即使在高熟练程度下也会增加 Reckless 权重。具名 NPC 的既定性格不能每次升级都重新抽取。数字用于展示期望趋势，并非最终平衡。

### 无须每次普通行动调用模型的个性提取

沿用现有遭遇生成调用，将已知角色/NPC 个性解释为最多三个封闭枚举提示，分别带低/中/高置信度及有限来源引用。例如忠诚、喜好风险、自我保护、富同情心、耐心。引擎再映射为数值权重；不要求模型发明任意概率或运行时代码。

有真实已知个性时才使用。“伤痕累累的法师”等外表不是谨慎的证据；“并不懦弱”不能增加 Cowardly 倾向。多语言及矛盾描述需要回归场景。提取缺失、格式错误或不受支持时，不作个性调整，职责、熟练程度与 RNG 已足够。仅靠关键词匹配不能宣称理解语义。

保存解释分配所需的已接受提示和来源，不保存模型推理过程。稳定 NPC 身份来自现有实体引用，不能只看显示名。重复出现的匿名怪物可获得新遭遇档案；具名常驻角色必须先有身份关联档案，才能承诺跨会话一致。

### 随机性边界

- 从遭遇种子、稳定敌人 ID 和分配版本派生 AI 分配种子，并与地形生成、战斗掷骰作域分离。
- 仅枚举/评分候选动作或渲染预览时，不消耗战斗 RNG。
- 保存已确定的档案。刷新、重试、导入、检查点回退或重开同一场战斗，不能意外重抽性格。
- 新遭遇/种子可以改变阵容和性格；显式重抽应产生新遭遇修订，不能暗改进行中的战斗。
- Tactical 目前对决策与结果共用随机种子游标。改变其使用方式属于需版本化的行为变更；保留旧进行中战斗的策略，或提供明确且经过测试的迁移。
- Classic 的未设种子结算器需要一个单独的 RNG/持久化适配器，然后才能在那里进行精确重播。

## 6. Mindless：精确追击契约

这是 Beast/Monstrosity 的项目规则，不代表官方桌游规则或真实动物行为必然如此。

### 目标及路线

1. 考虑存活队员，以及生物用指定简单攻击可以攻击各队员的合法位置。目标已占用的格子不能作为落点。
2. 步行时，在整个棋盘上搜索按**格子步数**计的最短合法路线，排序忽略地形额外成本。墙、水和山地仍阻挡普通步行者；现行规则允许穿过盟友，但不能停在已占用格。
3. 优先选择走最少步数即可获得合法攻击位置的队员。可攻击目标同样可达时，先按空间距离，再按稳定目标 ID 和坐标排序。绝不按 HP、防御、闪避、等级或预测伤害打破平局。
4. 沿所选路线走到本回合实际移动预算允许的位置。森林仍消耗两个移动点；选择该路线上最远的合法空落点，不为战术利益偏离路线走更便宜的捷径。
5. 移动后若在合法射程内，使用指定简单攻击打该目标，否则移动后等待。默认普攻；也可在创建时指定经过校验的固有招牌攻击。不能搜索伤害最高技能，或为 AoE 聚集目标而换位。
6. 下次行动从更新后的棋盘重算。路线被堵则找下个可达目标；都不可达则等待。不能隔着障碍攻击、非法抄近路或无限循环。

目标是思路简单的追击者，不是寻路失败者。绕 U 形墙可能需要暂时增大曼哈顿距离，全棋盘搜索应能找到这条路线。

**地形示例：**路线 A 穿过森林，需要三个合法步数；路线 B 经过平原，需要五步。即使移动点成本更高，Mindless 也选 A。若停在森林，它照常获得防御/闪避收益，也支付森林移动成本。Cautious 可能主动追求森林防御位置，Mindless 只是顺带获得同样收益。

飞行和传送遵循各自真实移动契约。飞行可越过阻挡地面和已占用格，并停在原本不可步行的地形；传送可跨过中间障碍，但落点地形必须合法。两者都不能停在已占用格。当前平面网格使用曼哈顿距离，不是“一跳到任意位置”。跨多个行动的传送追击需要由合法、可达落点组成的路径，不能选择隔着超过全部合法跳跃范围的缺口、看似很近的目标。所有移动方式仍受地形防御/闪避影响。

不要为 Mindless 另写一套略有差异的通行权限。提取/复用现有移动判断；路线偏好可以忽略成本，执行仍遵守正常合法性和成本。

### 硬排除和首领优先级

Mindless 不会按目标 HP 选受害者，不优化击杀率、不挑掩护地形、不协调集火、不治疗受伤盟友、不因恐惧撤退，也不因另一职业更有价值而换目标。难度和熟练程度不能重新启用这些行为。

Mindless 首领的 GM 菜单必须限制在已选目标与必需追击行为内；合法招牌/阶段动作也不能绕过限制。只剩一个动作时直接执行，无须无意义模型调用。未来若要让聪明的 Beast/Monstrosity 首领例外，须由维护者明确同意改变产品规则，不能以实现方便为由豁免。

Classic 没有空间距离，无法忠实实现“最近目标、最短路径”。建议改用保存的、由种子决定的遭遇交战顺序，选首个存活单位，不考虑 HP/地形。**更新后的非空间实现采用此抽象**，必须明确标注；它不满足精确空间要求。不能把排列顺序说成距离，真正的最近目标规则需要未来的阵形/位置模型。以后可通过前后排阵形实现，不能悄悄赋予排列顺序距离含义。Tactical 路径规则仍是本提案的标准 Mindless 行为。

## 7. 普通敌人决策

### 复用结算器，改变优先级

先生成合法候选动作，再按职责和性格权重评分。复用现有移动、预测和就绪检查，仅补充引擎 AI 与 GM 单位都需要的最小合法性函数。不要把未经验证的模型输入传给仅负责修改状态的 `performUnitAction`。

候选动作应包括：

- 基本攻击和可用的攻击技能，包括合法的移动然后行动目的地。
- 针对正确一侧的治疗、增益和减益动作，包括进入支援范围。
- 当没有可用的攻击/支援行动时，进行防御、等待和有目的的移动。

只纳入结算器真实支持的机制。敌人用物品首先需要真实物品栏和数量核算。评分器不能凭空创造 AoE 几何、召唤、嘲讽、新反应、借机攻击、掩护或逃跑。Tactical 已有反击、防御和等待；Classic 需补齐自动防御/等待及真正的增益/减益操作后，才能提供对应档案。这是结算器工作，不只是改评分权重。

对预期伤害、收割概率、有效治疗/支援、即时反击风险、下一阶段受威胁程度、接近职责所需距离的进展和资源成本使用统一量纲，再乘以小型档案权重表。过大的通用击杀奖励会抹去性格差异，因此新策略应使用有界、随档案变化的收割价值。

这是一套小型效用评分：以统一尺度比较合法动作，按性格改变优先级。David “Rez” Graham 的 [An Introduction to Utility Theory](https://www.gameaipro.com/GameAIPro/GameAIPro_Chapter09_An_Introduction_to_Utility_Theory.pdf) 介绍了总体方法和决策惯性；这里的具体档案、公式、默认值及集成计划是 Marinara 的设计建议。

### 实际约束

- 从假设终点及其地形计算预测，不改当前状态、不消耗 RNG。反击概率应符合真实命中、生存和反击规则；不能将命中率 50% 的攻击标为必杀。
- 按当前可观察位置和已知攻击估算下一阶段危险。不能偷看未来 RNG 或待提交的玩家命令。深入搜索前，先采用有界的单次行动威胁估算。
- 避免无意义地反复治疗：综合有效治疗量、紧迫性、机会成本和 MP。只少一个 HP 不能自动压过重要行动，也不要无收益地刷新仍有用的增益。
- 避免频繁换目标：除非另一个选择明显更好，否则保留有效目标/保护对象。仅保存真正使用的少量记忆。Mindless 遵循最近目标契约，不采用这种战术黏着性。
- 防止无限风筝/防御：若支援或撤退没有实际进展，倾向有用的交锋。使用有界停滞保护，不能仅为缩短回合就逼 Cowardly 自杀冲锋。
- 不要让所有单位执行同一个预先计算的阶段计划。按现有顺序结算，每次从更新状态评估下一单位，减少浪费治疗和攻击已败目标。
- Protective 根据职责/需求选择存活盟友，保留保护对象直到其无效或明显不再合适。保护明确首领可作为设置提示，但不是所有随从的通用行为。
- 在**既定性格**的近优动作内使用少量有种子的变化。不能沿用当前从所有攻击中均匀随机挑选的方式，否则会抹掉性格。

初步调参建议：将策略效用归一到固定尺度；新手从距本档案最高分 0.15 以内的选项中选择，大师范围为 0.03，中间熟练程度插值。可加有文档说明的小幅难度调整，但限制幅度，不能让难度改写性格。这些阈值需要模拟和实战，并非已验证平衡值。

## 8. 由 GM 控制首领回合

### 身份与责任

在遭遇数据中明确每个单位是否为首领，不能自动把每组最强者变为 GM 首领。建议阶级为普通、精英、首领；精英仍由引擎控制，除非显式设为首领。现有整场遭遇的音乐分类保持独立。

GM 根据首领既定性格、遭遇目标、当前战场、队伍技能/资源/物品和已支持的机制选择合法动作。更广泛的信息用于预测，不能读取玩家尚未确认的选择；第 16 节规定信息与中断契约。引擎决定射程、移动、资源、掷骰、伤害、状态和行动预算。即使首领在场，普通随从仍由引擎控制。

建议完整功能发布后，默认给新游戏启用新战术系统，并提供说明清楚的 **GM directs bosses**(GM 控制首领) 设置，使用已配置的 GM 连接。解释首领决策可能需要等待模型，并产生通常的服务商用量费用。旧游戏在用户主动启用前保持原行为；遭遇开始时固定选择。仅引擎/离线选项使用同样的首领档案。不要新增不同的战斗风格枚举，也不能悄悄改变进行中战斗的控制器。

### 回合编排

将服务商调用保留在服务器编排服务中，位于纯共享引擎之外：

1. 接受带有遭遇身份、操作 ID 和预期修订的玩家操作。根据接受的战斗状态进行验证。
2. 按现有顺序前进到下一个普通行动或中断决定。将声明与效果解析分开，以便反应可以中断待定的施法；不要解决整个回合然后重写它。
3. 保存待处理的行动/窗口：单位 ID、修订、回合游标、触发/待处理动作、策略版本和有界合法候选菜单。
4. 向 GM 连接请求结构化的候选 ID 或跳过。按照第 16 节传入当前队伍人物卡快照、首领意图、支持机制和本窗口允许的动作信息。可选的短叙述不能修改状态。
5. 检查回复格式、当前修订、单位、候选归属和当前动作合法性。原子记录决策，并且只执行一次。
6. 从更新状态继续暂停的动作/行动，再处理剩余单位。中断后重新校验；各预算/效果只在所属规则边界推进一次，然后交还玩家控制。

候选 ID 必须标识由引擎完整定义的动作，不是模型随意给出的坐标。大地图可能产生许多近似候选，应构建确定且有界的菜单，保留招牌技能、攻击目标、支援、防御和移动等有效类别。可先以约 8–16 个不同候选作为测量目标；不要在 GM 看到前，用单一通用档案剪掉所有替代方案。

### 延迟、失败和重复请求

最初上限是每个独立首领决策窗口调用一次服务商；普通随从、单纯点选和没有有效选择的窗口不调用。普通行动、预判、回合后传奇动作和触发反应可能各有窗口，因此还须限制多个首领的总行动/阶段延迟。初始可配置目标为每次约五秒软目标、十秒硬超时，再按实际服务商调节。这是设计目标，不是实测响应保证。总预算用尽后记录确定性回退或跳过，不无限调用。

超时、服务商不可用、输出格式错误或候选无效时，采用同一份已保存的确定性回退策略。回退也保存为决定，迟到回复不能替换它或多走一回合。UI 保持响应，显示简单的首领思考状态，并允许取消等待、采用已接受的回退，无须重启整个遭遇。

相同动作 ID 重试时返回已存结果。刷新后的标签页重新接入待处理决定；并发标签不能让同一首领前进两次。切换聊天不能把回复挂到另一场遭遇。检查点回退/分支应创建或恢复一致的战斗身份和决策历史，不能因重播动画就重复外部调用。

**持久化前提：**当前 Tactical 接收客户端状态并返回快照，没有权威服务器行动账本。Classic 同样接收完整的客户端战斗单位/机制，没有对照权威存档轮次。只在浏览器保存候选 ID 无法解决重试或并发。任一模式发布外部首领决策前，先用现有存储队列等机制建立最小的服务器战斗版本/决策记录。是否调用模型由服务器拥有的遭遇设置与已接受首领身份决定，不能由客户端标记启用。在选用 `game_engine_state` 前审计 turn-game/Experience 命名空间。这是有限的战斗状态改动，不应重构全部游戏存储。

### 首领机制和可读性

仅将支持的生成机制转换为结构化操作。一次性阶段转换应有稳定 ID 并保存触发状态。区分普通动作、阶段转换和明确支持的额外动作；华丽描述不能凭空造成伤害。

机制要求预警时，在结算前通过 UI/日志提示大型攻击。GM 可围绕已接受事件润色叙述，但必须描述真实结果。即使合法选择不同，玩家熟悉的首领性格和招牌能力在重玩时仍应可辨认。

GM 控制关闭或不可用时，明确标示采用引擎回退，不能声称决定来自 GM。GM 的可复现性指重放已存选择和掷骰，不是期待同一种子让新的模型回复完全相同。

## 9. 数据和集成契约

优先在现有战斗流程中传递小型共享元数据对象。已确定档案的结构示例：

```ts
type ResolvedEnemyTactics = {
  version: 1;
  creatureCategory: "beast" | "monstrosity" | "other" | "unknown";
  role: EnemyRole;
  adjective: EnemyAdjective;
  proficiency: "novice" | "trained" | "veteran" | "master";
};
```

最小类别只区分所需规则，不冒充完整 5e 生物分类。其他地方引入更完整的规范类别时应予保留。遭遇阶级单独保存，不用性格编码首领身份；由阶级与固定的遭遇首领控制设置推导控制器，避免两套可独立编辑的事实来源。

蓝图中的分配提示与已确定的运行时数据属于不同契约。蓝图可包含有界的职责、熟练度、个性提示和稳定 NPC 引用。引擎只解析一次，形成保存的档案；分配来源在遭遇中保存一次，仅为确实需要的策略存少量决策记忆，不要每次行动给每个单位重复保存原始个性描述。

Classic 还须经 `sanitizeCombatantForRound`、轮次请求 schema 和 `CombatantStats` 传递档案。当前快照有意省略轮次/先攻/动作队列，所以仅保存性格无法实现可恢复的 GM 行动、真实冷却或确定性重放。持久化这些功能必需的权威轮次/行动状态；动画应消费已接受结果，不能再次触发结算。

追踪完整边界：

```text
known NPC/card data + scene
  -> encounter prompt/schema and generated blueprint
  -> accepted assignment inputs and explicit boss identity
  -> generatedEnemyToCombatant / fallback encounter construction
  -> Classic request OR Tactical start request
  -> resolved units + pinned AI version + encounter identity
  -> action resolution / optional server boss decision
  -> snapshot, checkpoint/branch restore, import/export, post-combat summary
```

每个外部边界都校验枚举和有界数值。`.passthrough()` 不等于校验新 AI 字段。兼容旧存档缺失字段；显式值错误时给出有用错误，不能悄悄换性格。新策略版本不能意外改变旧快照的含义。

进行中的旧遭遇默认保留旧策略，新系统用于新战斗。缺类别的旧快照无法事后可靠分类，不能假装已经检查强制类型规则。新策略中的已知 Beast/Monstrosity 必须确定为 Mindless。

每条敌人创建路径都须检查，包括生成遭遇、手动/回退战斗、恢复存档及未来召唤物。不能只在 TypeScript 接口加字段，却在显式复制属性时丢掉它们。

## 10. 趣味性、真实性和可重玩性检查

**乐趣：**敌人的习惯应能被玩家识别和利用。把 Protective 守卫与 Supportive 治疗者分开而获胜，比万能评分器随机选坏动作更有成就感。避免把所有敌人变成完美集火机器。

**真实感：**采用符合敌人身份的可信目标、有限信息与熟练程度。胆怯、忠诚、进攻性和训练是不同特质。Mindless 是对两类生物的既定简化。未来士气/目标系统可加入投降、守区和逃跑，不能假装它们已经存在。

**重玩价值：**不同种子改变档案和遭遇阵容，但同一战斗及常驻 NPC 的身份要稳定。地形、职责组合、敌方资源和目标应带来超越暴击骰差异的变化。难度应可预测地改变挑战，不能让 Mindless Beast 突然开始追杀治疗者。

同一张地图上的遭遇示例：

- Reckless Bruiser 离开安全格，压迫可达的前排单位。
- Protective Bulwark 留在 Supportive 施法者附近，不跟着冲锋。
- Cautious Marksman 保持射击通路，避开危险落点。
- Mindless Beast 沿较短森林路线接近最近可达队员，忽略更远的受伤施法者。
- 具名类人首领获得一次 GM 决策，在合法的招牌压制动作和保护退路之间选择；其随从继续采用各自档案。

不同种子可生成 Cowardly Bruiser 和 Opportunistic Marksman，从而改变交锋。刷新不能做到这一点。同一具名首领再次出现时，应保留既定习惯，除非剧情或明确编辑改变了它们。

## 11. 建议的实现阶段

这是大型功能，涉及持久化契约、提示词、敌方决策及异步编排。先确认设计，再基于当前 staging 分成小而可审查的阶段实现。

| 阶段 | 交付内容 | 完成证据 |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| A. 能力与身份基础 | 证明并修复生成敌人资源丢失；显式类别/阶级/熟练程度提示；所有创建路径保留字段 | 生成施法者能使用并消耗真实资源；单独首领身份在恢复后保留 |

| C. Tactical 普通敌人 | 共用合法候选、准确的 Mindless 追击、八个独立档案、详情文案 | 行为矩阵、预测一致性、移动/浏览器证据、受控性能 |

## 12. 验收和验证计划

在现有的运行器中使用小型可运行的 `*.regression.ts` 证明。不要保留临时 `.test.ts` 文件。断言应该展示行为，而不仅仅是反映权重常数。

| 场景 | 必需结果 |
| ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Beast/Monstrosity 具有冲突性格、大师熟练程度、已知个性或首领身份 | 生成提示始终确定为 Mindless；冲突的作者/导入已定档案以有用错误拒绝 |
| 最近健康坦克与较远受伤施法者 | Mindless 追击坦克；Opportunistic 可选施法者 |
| 较短森林路线与较长开阔路线 | Mindless 选择更少步数并支付真实移动成本，照常获得顺带的地形收益 |
| 绕墙需暂时远离目标，或对手不可达 | 找到合法绕路或另一可达目标，不陷入曼哈顿距离死锁 |
| 飞行/传送 Mindless 单位 | 遵守各自通行、落点、占格和每次行动范围；不产生不可能的连续落点路径 |
| 受伤盟友在当前治疗范围之外 | Supportive 能合法移动再治疗；MP 耗尽或冷却阻止技能 |
| Protective 没有嘲讽或拦截技能 | 只靠站位，不能虚构伤害转移 |
| 受伤 Cowardly 敌人 | 可以撤退/防御，绝不触发整支玩家队伍逃跑 |
| 固定大批种子上的高熟练度 | 更常分配适合职责的档案，稀有但兼容的档案仍可能出现；每个种子的结果稳定 |
| 已知个性、否定特质、矛盾提示、缺失/非法提示、非英语文本 | 调整有界且有文档说明，不给任意数字控制，也不误称仅支持英语 |
| 暂时耗尽 MP | 职责和性格不变，仅合法动作选项变化 |
| 两敌人瞄准受伤单位，首个已将其击败 | 第二个评估更新状态，不攻击死者或重复预留治疗 |
| 目的地地形与起点不同 | 候选预测与实际反击在位置、地形和规则上相符 |
| GM 虚构坐标、技能、免费行动、目标 ID 或非法资源 | 不修改状态；只接受已保存的合法回退或有效候选 |
| GM 超时后迟到成功、刷新、重复请求或并发标签 | 只接受一次首领动作和一次资源扣除，丢弃过期回复 |
| 敌方阶段暂停期间队伍胜利/失败 | 正确结束战斗；结束后不再执行首领或随从行动 |
| 检查点恢复、分支、导入/导出、旧存档、常驻 NPC | 保留已接受档案及正确战斗身份，不意外重抽或重复外部决策 |
| Classic Mindless 和 GM 首领 | 明确的非空间目标规则和正确的先攻位置；没有声称网格/地形行为 |

在支持的 40 单位 / 64×64 请求边界下，以混合移动方式、多技能和密集障碍测量决策成本。合理时缓存单次决策的移动/威胁计算，状态变化后失效。先在桌面及代表性移动设备上分析现有引擎，再定可测量的普通阶段时间预算。不能未经测量就宣称固定毫秒预算，也不要在性能分析前加入深度前瞻。

实施时先运行 `pnpm install`，再运行 `pnpm check` 和定向战斗/路由回归；修改提示词时运行 `pnpm regression:prompt`，修改 UI 文案时运行 `pnpm localization:check`。浏览器回归覆盖真实战斗流程、刷新、首领等待/失败、键盘、小屏幕及明暗主题。补充 `[Unreleased]` 更新记录；客户端修改前阅读 `packages/client/.instructions.md`。通过现有调试设施和 Pino 记录服务商提示词/结果，不暴露无关秘密。

## 13. 当前普通 AI 实现边界

已实现的策略词汇为 Mindless、Reckless、Cautious、Opportunistic、Protective、Supportive、Disciplined、Cowardly、**Patient、Methodical 和 Coordinated**。下文其他性格只是构想，不是隐藏的运行时设置。

共享的 `features/combat-ai.ts` 契约将保存的职责、性格、训练等级、种子与控制方式分离。新战斗保存分配结果；恢复的旧战斗若无档案则保留原自动策略。切换同伴控制器不重抽性格。生成的有限 MP 和明确技能类型/成本进入运行时；未提供敌人 MP 时，使用与未设属性盟友相同的临时 `20 + 3 × level`，但保留明确的零值。这是通用引擎回退，不是桌游资源规则。

v1 分配有意比第 5 节公式更简单：相容档案从正权重开始，职责偏好的档案获得随训练变化的加成，可选封闭枚举个性提示提供有界偏好。类别优先级强制 Mindless，显式 Mindless 提示也能让其他类别使用此行为。现有遭遇生成调用可提供不同语言的提示，引擎自身不分析个性散文。其他性格提示是偏好而非保证；模型对否定和多语言刻画的理解仍须服务商评估。完整来源记录及跨遭遇、绑定 NPC 身份的个性尚待实现。无提示时，从 HP 推算的等级仍只是训练程度的弱替代指标。

各模式枚举可执行普攻、技能及防御，再对伤害、收割、有效治疗、支援、成本及相关战术因素评分。普通回合不新增模型调用，档案不会授予不可用能力、无限 MP、额外行动或不存在的地形机制。

- **Classic：**不作空间评分。Mindless 按稳定的种子顺序选择存活对手，与 HP 无关。支援使用正确盟友池，增益/减益应用实际具名防御修正，不再仅近似成伤害。新档案有逐次使用冷却。手动同伴为自身先攻位置排入攻击/技能/防御；队伍物品和叙事动作仍由当前队长操作。其他同伴默认 AI，沿用 Classic 原交互。提交命令明确行动者，原队长 KO 后也如此。
- **Tactical：**合法可达的攻击/支援位置供策略评分。Mindless 走最少步数路线，但支付实际移动费用；飞行/传送保持各自通行和落点限制。支援者可以先移动再施法。新反击预测使用预期终点，保守的公开状态可达性估算用于衡量危险，但不是完整的下一次行动寻路。墙或山会遮挡每一次打击的视线（combat C6）。
- **Patient：**在不利交锋前偏好有限防御等待；Classic 等待即将就绪的冷却，而不是虚构移动。有有效动作时不能无限等待。
- **Methodical：**优先真实支持的减防铺垫，保留目标，在状态已可利用时攻击；不虚构连招树或搜索未来骰子。
- **Coordinated：**考虑盟友记录的目标和有效减益支援，每次接受动作后重算；没有全知团队规划器，也不预留尚未提交的玩家动作。
- **同伴：**战斗内提供本地化的逐成员 Player/AI 选择，当前队长仍手动控制。Tactical 同伴在剩余手动命令之后或选择 End Turn 时行动，行动前仍可手动接管。控制器变化、档案和记忆随战斗单位/Tactical 快照保存。
- **Classic 持久化：**在表现动画前，把已接受轮次结果和下一轮编号交给现有快照回调；逐次使用的冷却能跨此保存/恢复保留。Classic 仍使用原有随机战斗掷骰，不是精确骰子重放或服务器幂等账本。多标签页保证属于后续权威首领系统工作。

首个里程碑未包含首领服务商调用及反应；第 16 节记录后续实现。剩余限制包括单位独立逃跑、嘲讽、更丰富目标、规则集专属先攻、完整人物卡资源归一化及常驻 NPC 档案注册表。原提案未实现部分仍属待验收工作，不能暗示已发布。桌面合成基准不等于真实移动设备性能校准。

## 14. 更多性格及随职业变化的行为

保留一个可见性格形容词和基于能力推导的职责。这些代表不同优先级，不是“聪明”的同义词；允许少见但机制上合法的组合。

| 形容词 | Fighter / Knight | Rogue / Archer | Mage / Healer | 区别和前提 |
| --- | --- | --- | --- | --- |
| **Frugal** | 先用普攻，再考虑有限战斗技巧 | 为重要目标保留特殊弹药或爆发技能 | 使用高效法术，明显缺 HP 时才用昂贵治疗 | 即使安全也重视资源效率，与 Cautious 不同；需要真实有限的资源成本 |
| **Relentless** | 持续压制选定敌人 | 追逐或持续远程压制同一目标 | 对同一威胁继续支持的伤害/控制链 | 强烈保持目标，而非 Reckless 式冒险；需要保存目标及目标无效/无法推进时的退出规则 |
| **Disruptive** | 使用真实可用的缴械、中断或限制动作的打击 | 打断暴露施法者受支持的引导，或施加减益 | 优先有效驱散、沉默、净化或控制 | 阻止有价值的行动而非追求最大伤害；只开放真实支持效果，不能按名字虚构沉默 |
| **Vengeful** | 报复伤害自身或击倒保护对象的敌人 | 标记最近攻击者，寻找合法机会 | 诅咒该敌人或保护其准备攻击的对象 | 由事件引发怨恨，不是找最弱目标；需要有限的最近攻击者/盟友倒下记忆 |
| **Adaptive** | 观察到抗性或交锋失败后换策略 | 停止重复无效攻击 | 按已观察结果更换元素或支援计划 | 只从公开证据学习；需有界观察历史，不能读取隐藏抗性表 |
| **Opportunistic**（已包含） | 选择安全收割，而非继续长时间决斗 | 利用受伤/暴露目标 | 用法术抓住真实机会 | 现有档案为基准，不另加评分相同的“Cruel” |
| **Resolute** | 低生命时仍履行职责 | 压力下维持有效射击位置 | 完成重要治疗或受支持引导 | 低生命时沉着，不同于 Reckless 的进攻性；需要意图/承诺及紧急失效条件 |
| **Territorial** | 守卫明确设定的门口或保护区 | 监视指定入口，越界后停止追击 | 支援守区内的盟友 | Tactical 需要真实目标/活动边界；Classic 守护具名目标，不使用虚构坐标 |
| **Zealous** | 明确指定的领袖/事业优先于生存 | 将稀缺爆发资源用于威胁该目标的敌人 | 冒个人风险为任务投入支援/资源 | 忠于特定目标，不是泛化的 Supportive；需要目标/等级元数据 |
| **Deceptive** | 使用真实支持的佯攻或姿态变化 | 使用真实隐蔽、诱饵或误导目标能力 | 使用受支持幻象或诱敌能力 | 需感知/欺骗机制及易懂的应对方式，光靠叙事声称无效 |
| **Merciful** | 选择受支持的非致命终结 | 可投降时使敌人失去能力而非杀死 | 克制、控制并接受投降 | 需要非致命结局和投降规则；不攻击已败目标，也不虚构仁慈效果 |
| **Selective** | 需要时才召唤耐打的保护者 | 根据当前机会召唤追击者或远程单位 | 选择适合可见威胁的元素/支援召唤物 | 未来的召唤阵容策略，而非又一伤害偏好；需要召唤资源核算 |

现有十一种之后，优先考虑 **Frugal、Relentless、Disruptive 和 Vengeful**。前两者只需少量状态改动即可利用现有能力；Disruptive 需要真实限制/驱散语义，Vengeful 需要事件记忆。Adaptive 和 Territorial 重玩价值高，但前置工作更多。公开词汇扩展前，先检查 Resolute 与 Zealous 是否和已有性格重叠。

此次要求的三个新增性格也会随职业变化：

| 形容词 | Bruiser / Bulwark | Skirmisher / Marksman | Spellcaster / Supporter |
| --- | --- | --- | --- |
| Patient | 等待不利换血条件改善，Tactical 中守住重要入口 | 等待合法且有效的射程，不勉强打弱攻击 | 为即将冷却完成的法术留行动，或避免无效治疗；不等待不存在的法力回复 |
| Methodical | 先以真实技能削弱，再攻击同一目标 | 爆发前施加受支持的弱点 | 先减益再伤害，或准备受支持防御链；不重复施加仍有用的效果 |
| Coordinated | 压迫盟友当前目标或提供有效铺垫 | 收割队友已在威胁的目标 | 提供不重复的支援，或盟友可利用的减益；每次动作后重算 |

这些描述是调参目标。首版使用通用且已支持的防御增益/减益模型；更丰富的职业连招需要对应能力与回归场景。

## 15. Summoning 设计扩展

先不使用网格。召唤物是实际战斗单位，具有稳定遭遇 ID、主人引用、阵营、档案、控制器、持续时间、资源成本和明确行动预算。职业决定合法能力，性格如 Classic 一样决定优先级。

把召唤者的**召唤选择**与召唤单位的**战斗策略**分开。Patient 召唤者可为后续威胁保留名额；Protective Knight 通过真实支持的动作保护队友；Methodical Mage 先施加减益；Coordinated 治疗者避免重复治疗。按当前规则，即使友方 Beast/Monstrosity 召唤物也必须是 Mindless。

规则集决定指挥是否花主人动作、召唤物立即或下轮行动、是否共用先攻，以及无人指挥时做什么。建议通用默认值：召唤花一次主人普通动作，新单位下轮首次行动，除非明确可控，否则使用引擎 AI。不能靠遣散/重召同一单位获得额外普通回合。加入群体召唤能力前，先限制数量，并稳定核算每轮最多一次行动。

主人 KO、魅惑/阵营改变、遣散、到期、队伍战败和遭遇结束，都需明确清理规则。刷新/导入保留归属和剩余持续时间；已败召唤物不是物品或永久队员。创建获接受时，法术/MP 成本只扣一次。召唤物动作不能在已固定首领修正项的资格规则之外制造传奇窗口。

## 16. GM 首领、传奇动作与反应

### 已实现的通用引擎适配器

设置向导创建的新游戏启用服务器调度战斗。**GM directs bosses** 控制是否调用服务商，普通敌人和 AI 同伴仍在本地决策。没有 `combatDirector` 的旧游戏保留原结算器。遭遇创建时固定 GM 开关、难度、种子、地形和能力，途中改设置不重写已接受规则。生成器必须明确设定 `boss`；高 HP 或视觉首领标记本身不授予额外动作。支持单独一个首领。

`combat-director.routes.ts` 在现有游戏引擎状态存储的 `experience:marinara-engine.combat` 下保存带版本、由服务器拥有的快照，以遭遇开始消息为锚点。快照含先攻游标、待处理效果栈、可选动作、反应/传奇预算、资源、已接受请求 ID 和近期事件。命令带遭遇 ID、存储实例 ID 和修订；重复或过期提交返回已接受状态。物品消耗与战斗保存共用事务；服务商回复还须匹配已存行身份、修订和窗口，迟到回复不能越过回退、检查点恢复或分支。

- **Classic：**在各先攻位置等待手动角色或首领决定。调度器逐个结算行动者，随后将现有轮末机制/状态推进一次。旧游戏保留原来排队处理整轮的控制。
- **Tactical：**查看/选择棋子免费。**Begin [name]'s turn**(开始 [name] 的回合) 确认开始行动并开放适用的预判机会。单纯移动不产生新行动或传奇窗口。AI 同伴和敌人沿用阶段结构；已接受地形简报、遭遇种子与设置尺寸仍具权威性，新遭遇忽略过期战役种子偏好。
- **首领：**初始设定通常为三个传奇点，每个额外动作都有正成本。首领普通行动开始时恢复点数；预判与回合后机会共用此资源，额外动作/反应不会自己生成传奇动作链。生成器设置合法攻击、防御、移动和技能成本。Mindless 首领遵守追击限制，只有一个合法选项时本地执行。
- **服务商：**使用配置的 GM 工具连接，缺失时回退至聊天连接。传入双方当前技能、资源、物品数量、状态、档案、位置和已接受事件，不能传入私有待提交命令、RNG 状态或键入/悬停选择。GM 只返回合法候选 ID，不改写状态。沿用宿主调试日志。单次决策十秒超时，目前每轮共十二次调用；普通行动回退到本地 AI，可选传奇窗口则跳过。UI 标明回退，也可在 GM 等待时主动采用本地回退。这些是固定初始限制，不是可配置延迟保证。
- **反应：**显式标记的 `counterspell`、`guard` 技能有触发窗口。手动角色获得能力/目标/成本选择及 **Pass**(跳过)；本地 AI 评估威胁与资源稀缺，GM 首领按相同服务商契约选择。每单位一次反应，在自身行动开始时恢复，显式冷却仍生效。Counterspell 本身也可为法术并被反制。稳定单位顺序和已保存父栈将结算限制在四十单位遭遇上限内，跳过不消耗资源。
- **成本：**反应前预留/花费所声明技能的 MP 或一个精确等级法术位，结算时不重复扣费。通用适配器即使法术或 Counterspell 失败也消耗此成本。反应还消耗反应次数，传奇技能同时花技能资源和传奇点。法术位是可选的显式能力数据，不从职业或技能名推断；尚无升环施法或版本专属返还规则。
- **通用效果：**Counterspell 的有种子成功率为 `clamp(65% + 3% × level difference, 20%, 95%)`，仅取消尚未结算效果。Guard 暂时给此次攻击威胁的一个盟友应用现有防御减伤。Tactical 反应检查明确射程和共享视线（combat C6），与普通攻击相同。明确的 `areaRadius`、`friendlyFire` 开启 Tactical 区域攻击；Classic 的 `targetScope: all-enemies` 用一次付费施法作用于敌方群体。这些有意采用通用规则，不是任一版本的 5e Counterspell。
- **控制：**现有战斗界面呈现权威的已接受状态、反应/传奇预算和获得焦点、可用键盘操作的选择面板。Tactical 物品栏提供真正支持的物品，不再使用旧版无限占位药水。重载恢复待决窗口；恢复前重置的修复保留遭遇锚点和机制，包括 React 开发模式重复挂载。战斗回顾包含资源总量。

**当前限制：**调度器尚无自由形式 **Special** 或原地重开，因为还没有权威动作/回退契约；旧战斗仍保留这些控制。恢复使用现有剧情/检查点功能。GM 最多十六个普通/传奇候选，仅提供少量换位终点。Guard 只减伤，不移动、拦截或产生借机攻击。Tactical 原有还击仍是独立自动交锋，不是法术反应。Classic 保留当前随机骰子和脚本机制覆盖；Tactical 不会获得 Classic 脚本机制。尚无完整桌游适配器、复活、召唤归属、通用专注、升环施法或常驻 NPC 档案注册表。完整人物卡归一化和跨遭遇持久资源仍属于规则集工作。服务商决策质量和真实设备节奏仍需实测。

### 已接受的设计要求

**已接受：**明确设定的首领可使用传奇动作，与是否选择 5e 规则集无关。GM 知道队伍战斗能力/资源，可在普通动作前按合理预测行动。AI 单位自动评估可选反应，也可为保存资源而跳过。它们已有首个通用引擎实现，与普通回合策略分离。

### GM 知情范围与预测

向 GM 提供绑定修订的人物卡快照：各队员技能/法术、合法射程及支持的区域形状、当前/最大 HP 和 MP/法术点、按等级分类的法术位、冷却、状态、装备、可用物品数量与剩余使用次数。还包括共享物品归属/访问权、适用的位置、召唤物、近期已接受动作，以及开始行动的单位。缺失数据表示未知，不是零或无限；取自已接受人物卡和物品栏，不能由模型编造摘要。可读取队伍物品不代表首领可使用或删除它们。

GM 可用更完整的遭遇信息预测威胁，并按首领性格与熟练程度决策；普通本地 AI 保留原信息边界。两者都不能读取未来 RNG、私人输入草稿、悬停技能/目标，或其他单位尚未声明的排队命令。实际法术声明只公开规则允许的触发信息；知道法术列表不等于知道将选哪项。服务器可校验完整状态，同时过滤控制器决策上下文。

**Fireball 示例：**选中法师有 Fireball、足够资源和不会伤及其盟友的合法爆炸范围，可威胁首领。GM 可判断其施放概率较高，花传奇点合法换位、设防或施压，但可能猜错，也应考虑单体法术或其他动作更好的理由。不能虚构闪避、沉默或免费移动。预测使用引擎真实 AoE、友军伤害及可见性规则；原单目标近似不足以支持空间预测，现在调度器支持显式设定攻击区域。Classic/Summoning 使用真实非空间目标组与威胁，不虚构网格射程。

### 三个不同的时间窗口

参考 [2014 传奇动作规则](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/monsters)：传奇动作在另一生物回合后执行，在首领自己回合恢复预算。于新选法师行动**之前**预判是 Marinara 的明确扩展，不是标准 5e 时机。通过遭遇固定的首领修正项提供，与规则集独立；忠实的 5e 档案仅在开启该自订规则时改变原时机。不能悄悄混入 [2024 怪物规则](https://www.dndbeyond.com/sources/dnd/br-2024/how-to-use-a-monster)。

| 窗口 | 触发及可用信息 | 预算与后续流程 |
| --- | --- | --- |
| 预判传奇动作 | 其他单位行动开始；GM 看见行动者、人物卡和当前状态，不看未确认动作 | 消耗现有传奇资源，然后让行动者选择/重新验证动作 |
| 触发反应 | 发生受支持事件，如开始施法；只公开允许的触发信息 | 消耗反应次数和技能 MP/法术位/使用次数，再按规则继续或取消待处理动作 |
| 回合后传奇动作 | 其他单位完成普通行动 | 消耗同一传奇池，再推进到下一普通行动 |

Tactical 中，查看/选择单位与**确认开始其行动**必须分开。首次确认可在移动/动作前开放预判，每次行动仅一次。接受后，重选、取消菜单、刷新或切换输入方式都不能重开窗口，也不能换行动者刷决定。单纯查看仍免费。让这次确认清楚可见；中断后，原单位仍有普通动作，除非真实失能效果阻止。简短解释比每点一次就被首领攻击更合适。

Classic 目前先收集命令，再结算整轮先攻；输入命令时选单位不等于真正开始行动。未来结算器须在对应先攻位置暂停，公开行动者但不泄露排队命令，结算预判后再校验并处理声明。中断使原选择非法时，在开始施法前请求新手动选择或重评 AI。不能每点菜单就调用 GM，也不能提前执行未来先攻位。AI 同伴及未来召唤物使用同一生命周期。

建议通用修正项默认值：

- 编写明确的首领身份和小型合法传奇菜单；不要从最高的 HP 推断 GM 权限。
- 起始可见预算 3 点，动作花费 1–3 点，在首领普通行动开始时恢复。遭遇开始时固定初始预算及突袭/失能政策。这是 Marinara 调参提案，不要求照抄已出版怪物。
- 每次合格的其他单位行动，每首领至多一次预判和一次回合后传奇选择，共用有限池。这样满足预判需求而不增加点数。跳过也关闭窗口；开始下一行动前先结算前一回合后窗口。
- Tactical 的回合后窗口跟在移动加动作或 Wait 后，不跟随移动点击、逐次打击、反击、动画帧或整段玩家阶段。Classic 跟在已结算先攻位后。End Turn 对每个合格的跳过行动最多关闭一次；召唤物按已固定资格规则处理。
- 提供 `pass` 及预算内合法候选。传奇动作不打开另一传奇窗口，不授予速度翻倍。传奇施法仅在所选规则适配器支持时触发 Counterspell，两类预算仍独立。
- 请求决定前及接受决定前，都重验首领存活/可行动、目标合法性和战斗结局。已败首领不能消耗迟到回复；Mindless 目标/追击约束也覆盖传奇选项。
- 普通动作、反应、传奇动作、巢穴/阶段事件各有预算和触发，不能凭描述制造伤害或免费行动。
- 普通随从使用本地 AI。只有首领窗口且存在有意义的选择才调用 GM。复用第 8 节的连接、调试日志、保存的回退及总延迟限制。

### Counterspell 与其他可选反应

**自动评估，选择性消耗。**拥有 Counterspell 不等于每逢施法都使用。触发后在合格反应与 `pass` 中选择；普通敌人与 AI 同伴按能力、性格、熟练程度、资源余量和阻止该效果的价值本地决策。GM 首领在相同合法窗口使用 GM 控制器。玩家单位获得注明成本的 React/Pass 选择，不能只因有能力就暗耗稀缺法术位。强制被动效果沿用自身规则，不伪装成可选反应。

评分考虑预防的伤害/控制、避免队友倒下、阻止有价值的敌方治疗/铺垫、成功率，以及资源和失去下一次恢复前反应机会的成本。规则允许时，Counterspell 也可针对治疗或功能法术，不限攻击。不能读取未来掷骰或仍私有的选择。对无害法术的昂贵反应可输给跳过，而为避免团灭花最后一个法术位可能值得。除非玩家明确设硬限制，储备只是软优先级。

| 风格 / 能力组合 | 反应优先级示例 |
| --- | --- |
| Protective Knight 或 Mage | 有对应真实能力时，拦截威胁盟友的打击或反制致命法术 |
| Cautious 或 Patient Mage | 跳过弱法术，留反应与稀缺资源应对严重威胁 |
| Methodical Mage | 阻止会破坏既定计划的受支持净化、治疗或控制法术 |
| Coordinated 支援施法者 | 其他盟友反应后重评；不反制已消除法术，也不重复预留反应 |
| Reckless 施法者 | 更愿消耗资源维持攻势，但资源/反应预算耗尽后不能施法 |
| Frugal 施法者（建议性格） | 偏好足够有效的低成本回应或跳过；权衡最后法术位与后续治疗/伤害需要 |

使用能力 ID 及显式触发/效果元数据，不按翻译后的“Counterspell”文字判断。每个反应须定义触发、时机、目标/视线要求、资源成本、反应成本/恢复规则和结算操作。MP、法术点、法术位保持区别。Counterspell 在施法开始且效果结算前触发，选择法师或打开菜单不够。[2014 Counterspell](https://www.dndbeyond.com/spells/2051-counterspell) 与 [2024 Counterspell](https://www.dndbeyond.com/spells/2619072-counterspell) 成功/资源结果不同，适配器应明确规定。Traditional 需自己有文档说明的中断公式与费用，不意外混用版本。

提交前重验触发事件、存活/可行动状态、视线/射程、目标和资源。即使反制失败，选定反应也只扣费一次，除非已实现规则明确返还。原始待施法的成本与动作消耗按其规则单独处理，不能与反制者费用混淆；跳过两者都不花。取消动画不自动返还。Traditional 建议每单位一次反应，初始可用，除非遭遇明确禁止，在其普通行动开始时恢复。其他适配器定义各自数量/恢复边界，中断或速度追击不隐式恢复。Tactical 现有交锋反击不是自动的法术反应，显式规则映射前保持原语义。

### 中断结算与持久化

[PR #6110](https://github.com/Pasta-Devs/Marinara-Engine/pull/6110) 提供有用先例：保留原尝试动作，展示已接受中断，立即更新后续上下文，防止恢复/重试覆盖后续变化。其 Roleplay 实现按经过校验的字面短语截断文本；该解析器不是战斗时机或资源引擎。复用持久化和可见性原则，不用截断文本决定伤害是否发生。

普通动作表示为保存的声明、待结算效果和结果。建议顺序：行动开始/预算恢复 → 可选预判 → 合法声明/资源承诺 → 合格反应窗口 → 剩余效果 → 行动结束 → 回合后传奇窗口。Counterspell 只取消待结算效果，不撤销已接受伤害。反应改变状态后重验目标、射程和行动限制。施法前失效的排队选择可无消耗重选；施法开始后的取消/返还遵循所选规则。日志和 GM 叙述只描述已接受事件，不把未执行的后半段写成发生过。

多个合格反应者按规则规定的稳定顺序处理，每次接受回应后重新检查合法性。反制 Counterspell 等嵌套反应须有明确规则能力及有界待处理栈。每项带父/触发 ID，单位对同一触发最多回应一次且必须有剩余反应。耗尽、取消或已结算的触发须关闭；不能无限递归、反复询问跳过、重复扣费或形成传奇到传奇的连锁。首版若有意限制，应公开不支持的反应链，不能宣称完整 5e 行为。

最小保存契约包括遭遇 ID、修订、行动 ID/游标、已确认行动者、窗口类型/ID、触发事件、待处理动作/父 ID、控制器上下文与候选修订、合格/已处理反应者顺序、传奇/反应预算、预留/提交/返还的资源变化、已接受选择/跳过、结算状态、服务商请求/回退结果及剩余效果。决定、成本与结果一起原子接受；迟到或重复答复不能再扣费。恢复继续待决窗口或重放已接受结果；分支/回退隔离整本战斗账本，不只隔离旁白。纯文本 Restore 不会退还已接受反应。下述服务器账本提供首版实现，第 8 节保留长期契约。

UI 显示剩余传奇点、反应可用性和候选技能成本，区分预判与触发反应，解释中断原因以及原法术会成功、失败还是需要重选。以无障碍方式提供思考/等待、重试/回退与取消；需要时预告蓄力攻击。不能把本地回退说成 GM 的决定。内部评分和提示词不进入玩家动作菜单。

所需证明：GM 中队伍法术/资源/物品准确；资源耗尽预测；合理但错误的 Fireball 预判；无草稿/排队命令泄漏；不能靠点选/重选刷机会；预判后玩家可改合法动作；5e 原时机与自订规则；Counterspell 仅在合法施法触发后；跳过弱法术、反制致命法术；反应/MP/法术位耗尽；失败反制只扣费一次；原法术按规则返还；射程/视线限制；多个反应者和反制 Counterspell；移动/追击/反应不额外开传奇窗口；Classic 正确先攻位置；失效排队命令；Tactical 跳过单位/召唤资格；传奇预算耗尽；只恢复一次；等待期间死亡/结束；重复请求；超时后迟到成功；刷新、多标签页、分支/回退与设置变化。确定性路由测试后补充真实服务商和典型移动设备节奏验证。

## 17. 遭遇环境智能体交接

游戏创建中的 **Terrain guidance**(地形指导) 文本框及摘要行已移除。旧设置文件可为兼容保留字段，但遭遇生成不再每战注入。Battlefield Size 仍是可复用设置；新战斗各获内部种子，保存地图和重开保留已接受种子。Tactical 标签只说明移动、地形和预测，不提另一款游戏。

未来的 **Battlefield Scout** 智能体应该在准备遭遇时运行，使用玩家的当前位置、最新场景/环境、明确定义的地图详细信息、天气和相关的近期事件。它会在遭遇生成之前向 GM 发送一份简明的环境简介，而不是在世界创建时，也不是每个普通回合发送一次。

边界：

| 所有者 | 工作 |
| --- | --- |
| `Pasta-Devs/Marinara-Agents`、`staging` | 智能体定义、默认提示词、包运行时、目录/清单、资产、该智能体拥有的设置 |
| Marinara Engine、`staging` | 遭遇准备 hook、有界场景输入契约、校验后的智能体结果交付、配置服务商路由、缓存与回退、保存地形来源 |

输入须带遭遇/位置修订，并区分观察事实和不确定建议。输出为简短的受支持环境摘要、适用时按现有 `TacticalBattlefieldBrief` schema 表示的有界地形特征及来源引用。不得含可执行规则、任意格坐标、虚构资源、首领权限或 HP 改动。Classic 可接收描述性危险/上下文，结算器未支持时不能获得网格修正。

GM 接收已接受上下文并继续生成遭遇，引擎校验最终地形。按遭遇/位置修订缓存，旅行或场景改变后丢弃旧答复，重试避免重复付费调用。关闭、缺失或超时时，使用当前遭遇上下文及常规程序地形回退。保存已接受地形，不因重载重生成。添加调试提示词日志及 schema/超时/过期位置测试。这里只记录该智能体设计，未在 Engine 内实现或暗中安装。

### 第一次实施的验证记录

本地基线 `pnpm check`、定向战斗 AI 回归、现有混合地形路由/设置/引擎回归和 `pnpm regression:prompt` 均通过。实际 Classic/Tactical 路由的浏览器测试覆盖同伴选择、排队手动命令、自动同伴行动、已接受轮次持久化与重载。设置/数据还原检查覆盖移除地形指导、种子零、明确的非英语法术类型及明确的零 MP。桌面浅色与 Android 尺寸深色 Chromium 通过；WebKit 因缺系统库无法启动。截图是本地测试产物，未作为文档素材提交。

在本机，混合步行/飞行/传送单位及支援技能的 40 单位、64×64 合成开放棋盘，一个普通敌方阶段约耗时 400–440 ms。这不是密集障碍最坏预算或实体手机测量，平衡和完整遭遇节奏仍需实战。测量只覆盖首个里程碑，不能证明首领窗口延迟或未来规则集性能。

`pnpm check` 和 `pnpm regression:prompt` 通过，原有无关的 `GameNarration` hook 警告仍在。普通 AI、调度器、路由和服务商回归覆盖确认开始行动、保留普通行动、嵌套反制、跳过、失败反制扣费、MP/法术位耗尽、区域保护、墙阻挡反应、禁用行动、物品事务、重复/过期命令、真实硬超时、每轮调用上限及检查点/分支身份。服务商适配器对本地 HTTP 测试服务运行，检查实际出站上下文及拒绝畸形/未知选择。这证明集成，不证明付费模型的策略质量。

十六项桌面/移动 Chromium 检查通过，覆盖旧版及调度式 Classic/Tactical 同伴控制、真实菜单、普通轮次完成、待决反应重载、最后法术位只扣一次、生成技能还原和设置清理。已查看桌面浅色/移动深色截图，反应面板可见、获得焦点且可操作。实体设备性能、当前 WebKit 覆盖及真实服务商决策质量/节奏尚未验证。扩展路由证明实际运行十秒超时并拒绝迟到回复，验证未调用真实游戏模型。维护者随后将外部 CodeRabbit 审查授权为正常工作流，首轮本地审查产生 15 项发现。


### 本地 CodeRabbit 跟进

首轮审查促成这些修复：Classic 重试/跳过后的已接受物品消耗、Tactical 技能力量预测、兼容旧行为的公共 AI 入口、仅敌方首领元数据、错误状态查询和导入决策成本、缺失的自动敌方阶段事件、最大 MP 归一化、非法受控单位 ID、仅反应技能菜单、服务商测试夹具清理，以及服务层共用连接解析。物品报告误以为多个队员有物品菜单；目前只有队长有，但移除过期物品引用确实修复了放弃重试的问题。消耗现按已接受命令及实际结果处理。

以下建议经审查后未改动，依据如下：

- 法术位有意只接受 1–9 级。暗丢生成蓝图中不支持的键可能掩盖非法作者设定；现有 schema 会拒绝它。戏法及具名规则集行为属于独立规则契约。
- 当没有提供最大值时，普通 AI 成本现在从最大值 MP 回落到当前的 MP。反应稀缺性故意除以**剩余** MP：即使在大型原始池中，花费最后几个点的 Counterspell 也必须被视为昂贵。
- 首领候选枚举已只构建一次可达格列表，每个候选仍通过权威动作校验。删除重复合法性检查或加独立校验缓存需要性能证据，并须保留此边界。这是性能建议，不是已观察到的非法动作缺陷。
- `CombatAttackResult` 尚无失败原因标记。新档案结算器执行前拒绝不可用技能，调度器扣费前校验。仅为旧版无效果回退新增结果/UI 协议暂留作展示改进；该回退既无效果，也不耗资源。

第二轮完整本地审查发现六项问题。修复独立 Classic 界面的已接受法术位合并和过期 props 重置，在创建单位时直接分配档案，从角色卡字段而非序列化元数据提取 GM 性格，在两个旧普通命令路径与自动选择中屏蔽仅反应技能，并对畸形存档读取返回可恢复错误。

其余蓝图建议不适用：共享类型 `CombatAttack[]`、生成提示词及 `combatSkillsFromGeneratedAttacks` 均要求有名称的攻击对象。纯字符串条目没有支持的数据还原行为，所以保持严格对象 schema，不接受战斗界面无法使用的数据。

这些修复后 `pnpm check`、`pnpm regression:prompt` 通过，四项战斗回归及混合地形路由回归通过，包括从真实服务商上下文排除角色卡评论/编辑备注。首批修复后十六项桌面/移动战斗检查通过；最后八项 Classic 检查也通过，明确覆盖物品重试、跳过物品和最后法术位耗尽。一次早期浏览器运行受构建刷新冲突影响，构建结束后重跑成功。第三轮审查指出 Classic 仅反应技能导致空面板，两个布局均已修复；对应旧 Tactical 治疗/结算路径也拒绝仅反应技能。最终验证见下文。


其他审查处置：

- Tactical 操作端点已通过 `applyTacticalTurn` 和 `applyAction` 路由控制更改； `applyAction` 拒绝将 AI 分配给第一个活着的队伍单位。现在，路由回归测试实际调用该请求并验证 HTTP 400 以及手动控制队长错误。在路线中复制相同的规则将创建第二处事实来源。
- AI 提示与中断字段可省略，但提供时须符合显式 schema。默默捕获并丢弃非法能力会无解释地改变生成的 Counterspell、费用或首领能力。让所有可选能力容忍非法值属于刻意改变行为，并非缺少保护。
- 收窄导出的 `TacticalUnitAction` 是类型清理建议。运行时控制处理已在 `applyAction` 中提前返回，不进入普通校验/执行；调度器动作 schema 排除控制。此项不阻碍功能，未来可在不改变行为的前提下收窄内部联合类型。


旧版物品栏持久化仍需独立跟进。审查指出 `GameCombatUI` 在旧版轮次结果后异步调用物品回调；基线已有该行为，也使用 `void onInventoryItemUsed?.(usedItemName)`。仅加 await 不是幂等修复：`handleUseCombatInventoryItem` 内部处理失败，旧轮次也没有可重试的权威请求/结果事务。新调度式战斗绕过此回调，由服务器账本原子扣物品并保存已接受状态。旧战斗保留原边界，要一起迁移轮次与物品持久化，需要明确兼容迁移。此处只记录限制，不宣称物品重试/排队命令修复已解决它。

反应可用性标签现在使用本地化目录的单复数形式。小范围反应保护修复后，定向战斗回归、客户端类型、工作区 lint 和队长控制路由证明通过；原有 `GameNarration` hook 警告仍在。


最终验证还为没有保存档案或已无敌人的 Classic 单位补充了确定性普攻/防御回退，并限制队伍命令 ID 必须对应存活队员。相关回归和服务器类型检查通过，反应数量复数的本地化验证也通过。

其余非行为建议暂缓：去重法术位 schema、同步声明后直接返回待处理动作 ID 而非读取最新记录、收窄内部动作类型，以及用最小值扫描替换传送前沿排序。当前边界明确，保留逐动作校验，插入和读取待处理记录之间无交错声明，这些建议未证明战斗结果改变。类似地，旧版冷却 0/缺失暂存为 1，在同一整轮结算结束时减一，下次行动即可用；调度器的独立逐行动扣费路径直接用 0。保持相同可用性无须统一中间值。


缓存建议假设 `/director/start` 不幂等，实际它对已接受聊天/锚点幂等：串行路由在创建或扣费前返回已有账本，路由回归证明带旧客户端单位数据重放 start 仍精确返回已接受会话。保留重挂载/重连刷新使客户端看见恢复或更新的服务器状态；关闭会滞留旧缓存战斗。仍可显式刷新，重试已禁用。

第四轮本地审查有 15 项发现，含重复及可选清理。剩余行为修复是尊重其他/未知生物类别的显式 Mindless 提示；回归先复现提示被忽略，再验证修复。已存档案不变。建议把待处理映射限制为 40 会拒绝合法终端栈项：声明先插入，数量超过 40 后才停止新增反应任务，因此保存上限为 41。区域半径 0 有意表示不扩展，与两种结算器一致。把连接辅助函数继承的动态服务商导入改为静态是可选清理。未宣称审查零发现，上述旧物品持久化跟进仍未解决。

全部审查修复后，`pnpm check` 通过，包括本地化、格式、类型、lint 和生产构建；战斗 AI 回归先展示 Mindless 提示失败，再确认通过。此前提示词、调度器/路由/服务商及桌面/移动浏览器结果如上。最后小修复经本地验证，准备 PR 时再作外部审查。
