# 可选多人模式

实现跟踪：[#6790](https://github.com/Pasta-Devs/Marinara-Engine/issues/6790)。本文记录实现边界与验证要求，并不表示多人模式已经可用，也不表示某个平台已通过测试。

<a id="smallest-architecture"></a>

## 最小架构

一位房主拥有全新的共享聊天、保存的游戏状态和 AI 连接。房主选择人类与 AI 阵容，没有固定的参与者或角色卡数量上限。Conversation、Roleplay 和 Game 保留各自现有模式。邀请不会把以前的私有聊天记录变为共享内容。

选用的传输方式是独立 HTTPS 监听器，处理小型 JSON 操作和有上限的长轮询。Fastify、Node HTTPS 和 Zod 已经安装。WebRTC 会增加信令、ICE/TURN 配置和移动房主标签页生命周期的问题；WebSocket 则需要额外服务器依赖和流式解析器。私人共享聊天直接复用 HTTPS，不增加这两套机制。这是唯一的房间传输方式。监听器只注册房间操作，绝不注册普通 Engine API。访客与房主直接连接，没有中央中继。邀请不会让任何一方访问对方的文件、库、设置、凭据或无关聊天。普通 Engine 管理端口应保持私有；邀请只应包含独立房间端口。

访客自己信任的 Engine 连接到房主。TLS 必须通过证书链和主机名验证；邀请还固定房主证书的指纹。发送密码或 persona 前先验证绑定。不得跟随重定向、降级到 HTTP、关闭证书验证或自动配置路由器转发。房主使用已有 TLS 功能配置 HTTPS 地址和证书。

访客视图是可信的内置代码，运行于不透明来源的沙箱，没有网络、下载、导航、存储、原生桥接或管理钩子。经过身份验证的 MessageChannel 只传递已验证的房间投影视图和小型、明确的操作集合。父页面提供本地显示偏好；对端不能提供样式、资源、代码、待请求 URL 或任意 API 调用。对端文本按纯文本显示。现有富聊天渲染器位于此边界之外。Android 封装会向每个 frame 注入原生桥接，因此在实现无桥接上下文并通过实机验证前，必须禁止作为访客使用。

<a id="trust-boundaries"></a>

## 信任边界

| 边界 | 执行方式 |
| --- | --- |
| 本地管理员到房间控制器 | 保留现有 Basic Auth、CSRF、主机验证和原生本地身份验证检查。 |
| 访客 Engine 到对端监听器 | HTTPS、指纹绑定、独立房间密码、批准、会过期的随机会话、有上限的请求。 |
| 对端到可信访客 | 双方接收端使用严格的版本化 schema、纯文本投影、不透明沙箱和限制性 CSP。 |
| 参与者到聊天/游戏状态 | 从已认证会话推导身份与所有权；绝不接受对端指定的角色、路由或生成请求。 |
| 房间到生成与工具 | 房主管理的操作映射、现有生成锁、明确的房间命令/工具策略和 Game 就绪屏障。 |
| 共享状态到记录 | 只允许明确列出的可见字段；排除凭据、调试提示词、推理、私有笔记、无关库和隐藏 GM 状态。 |

已认证的对端仍然不可信。提示词文本保持原样；授权由代码执行，而不是转义提示词或让模型“注意安全”。房主及其配置的 AI 服务商可以读取共享内容。与任何直接连接一样，该设计也会向房主暴露连接 Engine 的 IP 地址。访客的其他库或设备数据不属于协议内容。它不承诺抵御所有浏览器或操作系统缺陷。

<a id="activation-and-lifetime"></a>

## 启用与生命周期

`MULTIPLAYER_ENABLED=true` 是只在重启时生效的前提条件。缺失、false 或无效值都会禁用多人模式。还需在 Settings 单独启用；两种设置都不会自行启动网络。主持和加入各自需要明确操作。重启绝不会恢复活动房间。Stop、Kick 和 Leave 撤销相应凭据，阻止后续操作和迟到的数据交付。

任一条件关闭时，都没有多人会话扫描、证书可用性检查、房主/访客轮询或自主房间任务。服务器读取启用标志，客户端缓存一次可用性查询；明确的 Settings 操作可以刷新它。对禁用 API 的直接请求仍会被拒绝。保存会话的清理推迟至启用后，不会恢复网络。

<a id="proof-before-enabling-the-feature"></a>

## 启用前的验证

- 证明在支持的访客上下文中，恶意对端文本无法执行、获取资源、导航、下载、访问本地 API 或调用原生桥接。
- 证明关闭的开关、未认证入场、所有权、私有状态投影、流量限制和撤销机制会拒绝不被允许的操作。
- 通过唯一的房主协调器复用生成、命令和自主行为。发布逐命令兼容性表并明确限制。
- 证明两位 Game 玩家都提交或明确跳过后才产生一轮；重试、断线、取消和重启不能重复应用状态。
- 在桌面和移动端操作已有设置、抽屉、侧栏和输入框，包括清晰的 Leave/Stop 与恢复控件。记录实机验证缺口。

未完成的增量仍须禁用。在三个模式及其安全边界全部完成前，不能将 #6790 视为完成。

<a id="command-and-feature-compatibility"></a>

## 命令与功能兼容性

房间操作经过已认证的房主协调器。此表说明的是边界，不是允许在对端运行任意命令。被拒绝的命令会在输入框中说明原因；访客绝不会执行它。

| 功能 | 调用方与执行 | 共享结果与轮次规则 |
| --- | --- | --- |
| 人类消息、`/send` | 已获准参与者；房主创建标明作者的用户消息。`/send` 会阻止自动回复。 | 公开文本。Conversation/Roleplay 将获准帖子与生成串行处理；忙碌时发送者保留草稿。Game 只能经轮次收集器提交。 |
| `/roll`、`/r`、`/dice` | 已获准参与者；现有的限额 Engine 骰子解析与掷骰器在房主执行。 | 标明作者的文本结果。Game 掷骰在轮次结束前一直是该玩家已提交的行动。 |
| 生成、`/trigger` | 已获准参与者；一个持久化的房主生成执行权和现有生成锁。 | 已提交且经过过滤的 AI 叙述。Game 拒绝独立触发；只有就绪状态能触发轮次结算。 |
| 其他斜杠命令 | 在审核并明确添加房间授权前不可用。 | 不允许插入系统角色、冒充、导航/编辑私有聊天、图库操作、设备操作或任意本地命令执行。 |
| 群组回复 | 房主选择的已批准 AI 阵容，以及现有顺序/Smart/手动生成行为。 | AI 身份与人类 persona 快照分离。`{{user}}` 使用审核后的房主 persona，绝不是最后发言的访客。 |
| Conversation 日程与自主行为 | 现有服务器调度器、候选/意图逻辑、冷却和忙碌延迟；通过同一房间执行权调度。 | 没有访客调度器。停止/暂停的房间和 Game 不能由计时器生成。45 秒内未见人类视图或已获准对端，房间自主行为即暂停。 |
| Conversation `schedule_update`、`memory`、`react` | 房间策略下的现有 Engine 处理器。 | 日程/记忆变更局限于房间；反应必须指向本聊天且不能包含自定义图片资源。无全局角色记忆或在线状态更新。 |
| Roleplay 笔记、提醒、掷骰和悄悄话 | 现有命令解析与房主处理器；用已批准的参与者 ID 确定接收者。 | 私有笔记仍私有。悄悄话只出现在接收者的过滤快照中；房主仍拥有保存的数据。房间智能体从不读取悄悄话，因为每位参与者都能看到它们的输出。 |
| 跨聊天场景和浏览器提醒 | 受限，因为正常流程会创建/打开关联私有聊天，或使用浏览器本地计时器。 | 在共享记录中描述场景；自主消息使用房主协调的 Conversation 日程。任何收到的命令都不能创建私有聊天或本地提醒。 |
| 世界书与记忆 | 房主审核的附加/房间所有世界书，以及房间内对话记忆。 | 仅作提示词上下文，不是库导出。排除隐式全局书、关联私有聊天和全局角色卡记忆。 |
| Engine 追踪器、骰子、状态、摘要和变量 | 在真实工具/智能体执行器中使用明确允许列表，而不只是提示模型。 | 可投影安全公开字段；原始智能体输出、隐藏推理、调试提示词和私有 GM 字段不公开。Game 效果必须受轮次执行权约束。 |
| Game 行动、选项、检定、物品栏和角色表 | 房主设置/启动 Game 和现有生成机制；确定性的回合后效果只提交一次。 | 人类行动所有权来自已认证参与者。选项只填入草稿，绝不绕过提交就绪条件。 |
| 媒体、自定义/包工具、Game Experiences 和设备集成 | 房间生成不可用。 | 不允许对端文件、图片、音频、视频、远程样式、下载、原生命令或包提供的访客 UI。需要单独的安全增量。 |

初始共享 Game 是同步的叙述/行动流程。纯客户端战术/小游戏界面、自定义 Game Experiences 和场景/媒体展示不会被宣传为访客能力。复用标准 Game 设置时会明确限制这些选项。不会加载房主提供的渲染器来填补兼容性缺口。

<a id="recovery-and-limits"></a>

## 恢复与限制

每个已认证参与者都有持久化的单调递增行动序号和有上限的操作回执。重试返回先前结果；即使回执离开 128 条缓存，重放仍被判为过时。玩家后来更换 persona 不会改变消息中的 persona 快照。人类与 AI 的 persona 名称必须无歧义，才能定向发送悄悄话或进行检定。

显示名称和 persona 名称是公开的，所以它们永远无法证明席位归谁所有。离开或沉默的玩家，只有当其 Engine 出示该席位的私有重新加入密钥时，才能拿回原来的席位：这个密钥就是首次入座时那次入场的会话 Token，作为新加入请求的 bearer 再次发送。没有它，使用相同名称的请求会收到名称冲突，该席位的会话保持不变。两个 Engine 都只在内存中保存这个密钥。访客 Engine 重启后，房主要先移除旧席位，那位玩家才能再次使用同一个 persona。

Game 的 persona 变更在下一轮边界生效。已有角色表、实时数值、物品栏所有权和追踪器隐私键跟随稳定的参与者身份；历史消息保留原作者。若 NPC 在边界前占用了请求的名称，旧 persona 继续生效，并向玩家显示名称冲突。房主的跳过、移除、暂停和恢复都会在同一记录中留下本地化事件。

Game 在现有聊天元数据中保存必需参与者、每次提交修订和唯一的结算执行权。收集提交和保存标明作者的消息先通过元数据队列，再进入存储事务。服务商工作在事务之外运行。Stop 取消可信操作信号；迟到的房间写入仍必须匹配其活动执行权。中断回合不自动重试。明确恢复会进入下一次收集边界，不重放已提交效果。设置失败则停在大厅，等待明确检查/重启。

没有固定的人类或 AI 阵容上限。协议版本 1 将每个操作限制为 16 KiB、快照限制为 256 KiB 和最近 100 条消息、文本消息限制为 8,000 个字符。待批准队列、监听套接字、请求、长轮询、会话、密码派生和生成工作均有上限。每个会话只有一个活动对端轮询，每个访客 Engine 只有一个连接器轮询。不接受压缩或重定向。密码/令牌绝不放入 URL 或共享快照。

较大房间取决于房主资源、连接吞吐量和模型上下文。不会为了塞进更新而悄悄删除阵容成员。共享更新超出传输预算时，访客保留最后有效状态并可离开；房主仍能管理房间、减少共享数据，使轮询恢复。

<a id="verification-record"></a>

## 验证记录

自动验证使用一次性存储、本地测试 CA 和模拟模型服务商，不修改用户的证书、数据或 AI 连接。

- `multiplayer-peer-security.regression.ts`：HTTP 信息披露前的 TLS 链/主机名/指纹检查，畸形、超大、重定向响应和取消。
- `multiplayer-peer-server-security.regression.ts`：仅房间路由、正文/头部/输出/速率/并发限制，以及立即关闭监听器。
- `multiplayer-seat-key-security.regression.ts`：复制的名称或错误的重新加入密钥永远无法占用席位或获取其悄悄话；密钥持有者回到同一个席位，密钥也永远不会到达其他参与者或已保存的聊天数据。
- `multiplayer-room.regression.ts`：两个 Engine、入场、所有权、过滤历史、撤销/重放、串行生成和双人 Game 轮次/恢复。
- `multiplayer-session-flows.regression.ts`：HTTPS 上的两个 Engine，真实生成与 Game 运行时，模拟服务商，以及完整 Conversation、Roleplay、Game 轮次。
- `multiplayer-generation-policy.regression.ts` 与 `generation-output.regression.ts`：执行器限制、排除私有库、提示词内身份、共享生成锁和完成语义。
- `multiplayer-autonomy-security.regression.ts`：复用现有调度器、房间活动时钟、唯一控制权和 Stop 竞态。
- `multiplayer-game-runtime.regression.ts`：Game 设置/启动/开场、确定性回合效果、过时写入和设置中断。
- `multiplayer-game-persona.regression.ts` 与 `multiplayer-game-projection.regression.ts`：persona 所有权迁移、冲突恢复、受众过滤和有上限的公开追踪器。
- `e2e/multiplayer-guest-isolation.e2e.ts`：在桌面 Chromium、移动 Chromium 和移动 WebKit 中，向生产访客包施加恶意文本和本地/网络/原生访问尝试。
- 专项设置与控件浏览器用例涵盖入场警告、Players、Game 大厅、触摸布局、明暗主题和草稿/重试行为。

合并前，在最终候选版本上重新运行 `pnpm check`、相关 Node 回归测试、`pnpm regression:prompt`、`pnpm smoke:ui` 和专项浏览器矩阵。在 PR 中记录真实命令结果与修订版本，完成 CodeRabbit 和专项安全审查，并验证支持的实机。浏览器模拟不是实体 iPhone/iPad 主屏幕或 Android 验证。Android 原生封装继续禁止作为访客。实机结果在记录前均视为待验证；不能从视口预设推断支持。

访客构建为传统 IIFE，因为从不透明来源加载 ES 模块会要求放宽 CORS。生产和开发启动都会构建固定本地访客资源；在开发服务器运行时修改访客源码后，运行 `node packages/client/scripts/build-multiplayer-guest.mjs` 并刷新访客视图。启动器完整性检查包含两个隔离资源。
