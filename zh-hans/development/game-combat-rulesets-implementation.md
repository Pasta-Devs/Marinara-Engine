# 版本化战斗规则集：实现交接

> **状态补充，2026 年 9 月 19 日。** 本文预留的 `5e-2014` 适配器正在实现为数据驱动的战斗类型，而非每个系统各写一个 TypeScript 适配器：规则集声明可选的 `combat` 块，Engine 拥有负责结算的类型，与检定结算类型的归属方式相同。理由、架构和分阶段工作见 `game-rulesets-and-sheets-implementation.md` 的 Real ruleset combat 节，工作由[议题 #6361](https://github.com/Pasta-Devs/Marinara-Engine/issues/6361) 跟踪。本文其余内容仍有效：Traditional 规则集及已接受的速度行为、产品契约、难度属于规则集且不能变成伤害倍率的规则、导演唯一的服务端账本、反应与传奇动作窗口，以及存档、UI 和推出契约。C3a 阶段已接通：战斗作为 `classic` 和 `tactical` 之外的第三种 `style`，在导演现有账本上结算，使用相同的修订、幂等、互斥锁和单次“选择候选 ID”模型调用。C3b 阶段已显示：声明 `combat` 的游戏在 Classic 外壳中使用规则集自身菜单、术语和真实计算日志，人物卡在战斗进行时写入而非事后写入。C4a 阶段具备位置：声明 `combat.distance` 的规则集能在战术引擎自己生成的棋盘上作战，移动、触及范围、射程、爆发、锥形、直线、视线、掩护和对离开者的攻击都按规则集数值结算，对手也会移动。C4b 阶段棋盘已显示：带位置的战斗使用战术样式自己的地形，能走到哪些格子、各自消耗、路径、会招惹谁、可以选谁为目标以及形状能瞄准哪里，都依据服务端视图绘制，并使用规则集自己的距离描述。反应和特色动作窗口仍是 C5 的后续工作。
> 战场从 C4b 阶段起显示在屏幕上。C5a 阶段的一回合能实现桌面游戏回合的行为：一击可附带第二段伤害，一次行动可换多次攻击，能力可免耗额度、返还额度或以另一额度购买标准动作，附加效果可自动作用于一定期间内首次合格命中，状态可以调整自身豁免、将所有伤害减半、阻止攻击或接近施加者、仅在施加者可见时有效，或在其倒下时结束。C5b 阶段战斗可保留在等待状态：离开他人触及范围的移动停在原地，询问对方是否攻击而非自动攻击；行动者之间会暂停，询问每个有点数的区块是否购买其自身动作。窗口打开时其余一切停下，之后从暂停点准确继续。C5c 阶段目录条目会声明等待的时刻：`aimed` 在效果落到持有者之前，可取消该效果；`harmed` 在受伤之后，指向造成伤害者。询问任何人之前已经支付成本，因此取消的是效果发生，而非购买行为。连锁仍待实现：战斗保留单个窗口而非栈，因此反制本身无法再次被反制。

状态：2026 年 9 月 17 日的实现提案。AI 重构未实现这些规则集。Traditional 的速度追击已获产品方向认可，下文阈值和其他默认值仍是待调提案。检查关联工作后，基于当前 `staging` 实现。

## 产品契约

保持四种选择独立：

| 选择 | 控制内容 | 示例 |
| --- | --- | --- |
| 呈现方式 | 空间信息和输入 | Classic 菜单；Tactical 网格 |
| 参与方式 | 谁参战 | 队伍；未来 Summoning |
| 规则集 | 合法动作、资源、行动时机、结算 | Traditional；明确版本的 5e；V20 |
| 控制器 | 谁选择合法动作 | 玩家；本地 AI；GM 首领 |

Cautious Mage 在任何呈现方式中都应谨慎。换规则改变其可做的事，不改变性格。Summoning 是参与系统，不是第三套规则引擎，首版可不涉及空间。没有位置模型时，任何模式都不能虚构网格距离。

产品 UI 使用易懂说明。Traditional 和 Tactical 的描述不与其他游戏比较。以已实现系统命名的规则集必须写明支持的具体版本与覆盖范围。

### 难度属于规则集

当前引擎敌方伤害倍率 Casual 0.6、Normal 1、Hard 1.3、Brutal 1.6 仅为 Traditional 设计。实现 5e、V20 等适配器时重新审视，不能自动继承；难度应由各自遭遇与结算模型定义。敌人 AI 决策调参与伤害算术缩放分开。增加适配器回归，证明选择其他规则不暗用 Traditional 表。此说明不把旧机制冒充为已实现的 Traditional 规则集。

## 当前代码与限制

- `packages/shared/src/types/game.ts`：`Combatant`、`CombatSkill`、Classic 结果与快照。当前属性为通用数字，`speed` 不是桌游敏捷值或英尺移动距离。
- `packages/server/src/services/game/combat.service.ts`：Classic 每轮掷先攻、每参与者结算一条命令，采用通用伤害公式。旧游戏经客户端往返传状态，新向导游戏使用服务器战斗调度账本。
- `packages/shared/src/features/tactical-combat/{engine,math,types}.ts`：队伍/敌人交替阶段、职业射程、速度派生移动、反击，尚无速度追击。
- `packages/shared/src/features/combat-ai.ts` 与模式适配器：合法动作的优先级。普通 AI 保留知识边界；GM 首领获得人物卡/资源作预判，但两者都看不到未来骰子或未声明的玩家选择。
- `packages/server/src/routes/combat-director.routes.ts` 与 `services/game/combat-director.service.ts`：版本化权威遭遇状态、行动游标、待处理反应、传奇预算、重复/过期答复保护。规则适配器应扩展此接受动作路径，不新建第二本账。当前 Counterspell 概率、法术位扣费和取消成本是通用引擎策略，不是 5e。
- `packages/server/src/routes/game.routes.ts`：旧轮次/开始/动作验证。`GameCombatUI`、`TacticalCombatUI`、`use-game.ts`：输入、预览、接受结果与持久化。
- `GameSurface.tsx`：生成蓝图的数据还原与快照。`encounter.routes.ts`：遭遇生成提示词。`game-setup-share.ts`：可复用设置导入/导出。

未实现并验证已接受的速度行为前，不能把现有伤害公式改称 Traditional。d20 加当前引擎属性也不代表符合 5e。

## 最小架构

从内置纯 TypeScript 适配器的封闭注册表开始，不添加脚本语言或任意可执行规则包。尽量复用现有合法动作/结果类型，只有两个调用方确有需要才提取共用函数。

在每个新遭遇保存固定引用：

```ts
type RulesetRef = {
  id: "engine-legacy" | "traditional" | "5e-2014" | "v20";
  version: number;
  options: Record<string, boolean | number | string>;
};
```

各适配器验证自己的封闭选项 schema，不能无限接受示例 record。列出支持能力：移动、反击、法术位、血池消耗、召唤、首领反应。明确但不支持的选项返回有效错误。缺少规则数据意味着 `engine-legacy`，绝不自动迁移到 Traditional。

小型接口应涵盖：

1. 验证/归一化规则专用人物卡，不猜测转换。
2. 开始遭遇，在规则指定时间掷骰或确定一次顺序。
3. 开始行动，恢复允许的预算，推进相应状态。
4. 枚举合法动作和可选反应，包含目标集、射程、成本、时机及跳过。
5. 生成只读预测，不消耗 RNG。
6. 接受动作声明，记录资源承诺，在效果结算前开放支持的触发窗口。
7. 将待处理效果/反应结算为有序事件与资源变化，仅在启用时开放行动开始/结束后的首领窗口。
8. 所有参与者完成后结束一轮，轮次限制效果只推进一次。

同一适配器服务玩家输入、普通 AI、GM 候选菜单和预览。GM 不能提供最终 HP、虚构技能 ID、新行动顺序或免费资源变化。合法性取自已接受状态，决策上下文仅透露控制器和时机允许的信息。GM 首领知道队伍技能、法术点/位、冷却和可用物品以预测威胁。未确认选择与其他排队动作在声明前仍私有。预测报告期望值，不泄露未来骰子结果。

各规则的人物卡采用可判别联合类型，不把全部资源塞入 `mp`：MP、法术位、Blood Pool、Willpower、每轮支出和休息前使用次数语义不同。UI 资源条与技能成本读取所选适配器描述。当前量与最大值分开保存，名称只为展示归一，不作为资源身份。

## Traditional v1：已接受的速度行为

**每个存活且合格的参与者每轮最多获得一次普通行动机会，在其中最多主动发起一次交锋。速度追击只是该交锋内的追加打击，并非新的普通行动机会。**

建议起始平衡：

| 规则 | v1 提案 |
| --- | --- |
| 先攻 | 有效 Speed 降序，同速按稳定遭遇顺序；高速度或同速不增加行动 |
| Tactical 调度 | 队伍阶段后敌方阶段；玩家可选未行动队员，自动单位按速度 |
| Classic 调度 | 统一有效 Speed 降序；UI 排入手动命令，每个先攻位重新确认当前合法目标 |
| 移动 | 明确预算，独立于 Speed；建议默认 4 格，职业/能力可作有界调整 |
| 攻击速度 | 有效 Speed，加减已明确建模的修正，不虚构武器重量 |
| 追击阈值 | 攻击者攻击速度至少为防御者 + 5；只通过已验证规则选项配置 |
| 适用动作 | 普通攻击或明确标记 `allowsSpeedFollowUp` 的技能；技能默认 false |
| 交锋 | 发起者打击 → 存活防御者合法反击 → 存活发起者合格追击 |
| 更快防御者 | v1 仅一次合法反击；防御者追击为独立平衡选项，默认关闭 |
| MP | 明确资源池及技能成本，选定技能行动扣一次；追击费用须由技能明确规定 |
| 移动恢复 | 下次普通行动时恢复一次；反击/追击不恢复 |

阈值 5 和交锋顺序是 Marinara 提案，并非宣称复刻某游戏。维护者要求更快攻击者打两次，没有要求防御方翻倍。

每次打击之间重验存活、目标、射程、失能状态和剩余预算。被反击击杀者不能追击；首击未命中不自动取消速度追击。目标已败后不能再次攻击或暗换目标，不能反击再递归反击。反击既不花费也不补充防御者普通发起机会。治疗、增益、物品、召唤、传奇动作都不翻倍，除非明确支持的能力规定例外。

交锋开始时按已接受有效属性确定资格。中途失能立即生效，但中途加速不追溯增加打击。把结果写入事件，预测显示一次/两次打击与反击资格。动画中刷新只重放接受事件，不再次掷骰或扣费。

Classic 没有移动距离，应省略移动或另定义交锋模型。Classic 中 Traditional 反击须有明确 `canCounter` 规则，不能把数组索引当网格距离。建议 v1 在定义近战/远程接敌前关闭 Classic 反击，但保留攻击者速度追击。

## 5e 档案：先确定版本再写代码

建议首个目标为 `5e-2014`，固定到 SRD 5.1。未来 2024/SRD 5.2 使用独立 ID、版本和测试，不暗混版本。官方 [SRD 索引](https://www.dndbeyond.com/srd) 发布各版本，[SRD 5.1](https://media.wizards.com/2023/downloads/dnd/SRD_CC_v5.1.pdf) 是首个目标的原始依据。

实现前审计原文：敏捷先攻、距离移动、动作/附赠动作/反应、法术位、专注和状态、区分攻击检定与豁免。需要专用人物卡字段和结算测试，通用引擎等级/攻击/防御不能替代。法术点是明确选用的变体，须有独立审阅来源和限制，不能只把法术位池改名。

先发布如基础武器攻击、移动、Dodge 和少量法术的诚实支持子集，未支持动作不可选。不能凭一个先攻公式宣称完整 5e。关闭 Traditional 翻倍，额外攻击只能来自已实现的档案能力。

## V20 档案：需要专门审计

目标为 Vampire: The Masquerade 20th Anniversary Edition，不是 V5 或 V20 Dark Ages。实现准确的先攻、声明顺序、多重动作、Celerity、伤害/吸收、伤势惩罚和支出限制前取得正确原文。此交接未批准任何精确 V20 公式。

为 Attributes/Abilities、健康等级、Blood Pool、Willpower 保留规则专用人物卡，并按支持范围限制每回合支出。不能把血池换成 MP，或把 Celerity 换成 Traditional 速度翻倍。测试注明版本与规则段落；论坛答复或 Dark Ages 预览不是现代 V20 的充分依据。分发复制文本/属性块前，按实际来源解决复用权和署名；本文不提供此类内容。

## 传奇动作、预判与反应

已接受方向：GM 首领即使在 Traditional 或非 5e 规则下也可使用传奇动作。它是明确的**首领遭遇修正项**，与普通先攻、性格、参与方式独立。详见 AI 设计的首领章节。

适配器开放 `afterActivation`，启用 Marinara 预判修正项后，在行动者确认开始时还可开放 `activationStarted`。两种传奇窗口消耗**同一**有限资源池。单纯点击、检查、取消菜单或刷新不增开窗口。GM 可按法师当前能力/资源和真实区域/友伤规则，在玩家声明前预测 Fireball，但不能读取未来命令。这是固定在遭遇上的 5e 回合后时机扩展；忠实档案在未启用修正项时保持原时机。

Traditional 一次发起规则针对普通行动。明确的传奇动作不授予普通行动或速度追击。Classic 须在实际先攻位暂停，不能在 UI 收集整轮命令时提前打断。中断后重验排队命令，若在提交前失效则请求替代。Tactical 须有独立开始行动确认，使浏览单位安全，不能靠重选刷中断。

Counterspell 等反应属于受支持的**事件触发器**，与传奇身份无关。至少定义事件、效果前/后时机、视线/距离、资源成本、反应次数/恢复、结果及原动作取消/返还。首领 GM 和普通 AI 使用相同合法窗口，手动单位获得 React/Pass 选择。AI 自动评估，可按性格、威胁、成功率、MP/法术位稀缺和失去反应的成本选择跳过。可用不意味着必须花费；普通单位反应也不成为首领。

Counterspell 要求待处理施法，不能只选中法师。MP、法术点和法术位保持不同类型。[2014 法术](https://www.dndbeyond.com/spells/2051-counterspell) 用法术等级/检定；[2024 法术](https://www.dndbeyond.com/spells/2619072-counterspell) 用体质豁免，并规定成功打断的原法术不消耗法术位。不能把 2024 原法术返还套到所有版本或反制者费用上。Traditional 需要明确调好的中断操作，V20 应映射自己的反应能力，不能只因名字继承 Counterspell。

与接受声明/反应一起原子地预留和扣除资源，规则专属返还单独记录。Traditional 建议每单位一次反应，初始可用，除非明确遭遇条件阻止；普通行动开始时恢复。其他适配器定义各自次数/恢复边界。传奇动作和追击不隐式恢复。旧交锋反击保持独立，除非显式映射。传奇选项施法时，只开放规则允许的法术反应。

用保存的有界待处理动作栈支持嵌套反应，包含父/触发 ID、稳定反应顺序和每次回应后的重验。已取消施法不能再被反制；跳过关闭该单位对该触发的机会。受限适配器披露不支持的反制链。已接受事件只结算一次并驱动叙述；[PR #6110](https://github.com/Pasta-Devs/Marinara-Engine/pull/6110) 的可逆文字中断是持久化/上下文参考，不允许通过截断文字回滚战斗。完整生命周期与验收矩阵见 AI 设计第 16 节。

## 存档、UI 与发布契约

- 快照固定规则 ID、版本、有效选项、控制器、人物卡、初始顺序、当前/已确认行动、传奇/反应预算及恢复点、动作栈、触发/决策 ID、资源承诺/返还、冷却、RNG 和已接受中断。
- 异步 GM 前必须有服务器版本/动作账本；拒绝过期并发提交，重试幂等。浏览器候选 ID 不足。
- 设置变化只影响下次遭遇。导入、检查点/分支恢复、重连、更新后，当前战斗仍保留固定规则。
- 未结束旧战斗继续 `engine-legacy`。未来战斗转换需明确操作，并预览未映射属性/资源，不能暗改人物卡或资源池。
- 未知规则版本只读且可恢复，不能暗按最新版本解释。
- 本地化 **Combat rules**(战斗规则) 选择器独立于 **Combat presentation**(战斗呈现方式) 和未来 **Participation**(参与方式)。简述顺序、资源、关键行为，开战前显示兼容限制。
- 缺少必需人物卡字段时先请求补充，仅通过明确选择使用旧规则，不能让生成模型虚构权威属性。
