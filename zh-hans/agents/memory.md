# 记忆功能与聊天摘要

本指南介绍搜索历史消息的 **Memory Recall**(记忆功能)、用于自动管理 Roleplay 上下文的可选功能 **Advanced Memory Recall**(高级记忆功能)、**Chat Summary**(聊天摘要)，以及 Conversation 中的 **Automatic Summarization**(自动摘要)。

## 两套记忆机制

每个 AI 模型一次能读的文字量都有上限，这个上限叫上下文窗口。聊天一长，最早的消息就会掉出窗口，AI 也就忘了它们。Marinara Engine(下文简称 Marinara) 为此准备了两套彼此独立的机制。

- **Memory Recall** 会在较早的消息里找出和你刚说的话最相关的片段，悄悄补回提示词里。所有聊天模式都能用。
- **摘要**把旧消息压缩成简短的回顾，在提示词里取代原始消息。Roleplay 聊天用 **Chat Summary**，Conversation 聊天用 **Automatic Summarization**。

Game Mode(游戏模式) 聊天只有 **Memory Recall**，两种摘要功能都没有。

两套机制可以同时开着。它们各管各的，不会互相冲突。

## 配置 Memory Recall

**Memory Recall** 会从聊天早先的内容里挑出相关片段，作为记忆注入提示词。它依靠嵌入，也就是把一条消息的含义变成一串数字指纹。Marinara 拿新消息的指纹去和已存的历史消息指纹比对，再把最接近的几条补进去。

### 开启 Memory Recall

1. 打开一个聊天，点击 **Chat Settings**(聊天设置) 按钮。它最初位于聊天右上角。
2. 找到 **Memory Recall** 一节（图标是一个大脑）。
3. 开启 **Enable Memory Recall** 开关。

**Enable Memory Recall** 是按聊天分别保存的设置，默认值取决于模式：

- Conversation 聊天默认开启。
- 已经有活动场景的 Roleplay 或 Game 聊天默认开启。
- 其余聊天默认关闭。

关闭开关后，回忆到的记忆就不再注入提示词，但已经存下来的内容一样都不会删。

### 嵌入来源

Memory Recall 需要一个嵌入来源来生成这些含义指纹。它配置在连接上，不在聊天设置里。连接就是保存下来的一套 AI 服务接入信息。

1. 打开 **Connections**(连接) 面板，编辑一个连接。
2. 找到 **Semantic Search (Embeddings)** 一节。
3. 在模型输入框里填入嵌入模型名称，例如 `text-embedding-3-small`。
4. 需要时可以填 **Embedding Endpoint URL**，覆盖默认地址。
5. 也可以用 **Embedding Connection** 下拉菜单借用另一个连接的密钥和地址，选项有 **Same as this connection** 和 **Local Model (sidecar)**。

有些服务商不提供嵌入。这种情况下 Marinara 会提示另选一个专门的嵌入连接，比如 OpenAI 兼容连接、Google 或 Local Model。

完全没有配置嵌入连接时，Marinara 会退回内置的本地嵌入模型。这个模型只下载一次，之后在自己的机器上运行，不需要 API 密钥。内置模型的更多说明见[本地模型设置](../connections/local-model.md)。

同一处 **Semantic Search (Embeddings)** 设置也驱动世界书的语义搜索，配置一次两个功能都受益。

### Memories for This Chat

要查看聊天记住了什么，打开 **Chat Settings**，进入 **Memory Recall** 部分，点击 **Access memories for this chat**。启用 Advanced Memory 时，查看器会留在 Roleplay 设置抽屉中；否则会打开 **Memories for This Chat** 弹窗。

窗口里显示已存记忆块的数量和大致的 Token(模型切分文本的最小单位) 用量。每张记忆块卡片显示它覆盖的日期范围、消息条数、状态，以及创建时间。状态有三种：

- **Vectorized**：指纹已经生成，可以参与搜索。
- **Waiting for vector**：指纹还在生成中。
- **Embedding unavailable**：没有可用的嵌入来源，指纹生成不了。

工具栏上有导出记忆、导入记忆、重建记忆和清空全部记忆的图标。每个记忆块还有自己的垃圾桶图标，可以只忘掉这一块。

- 点击某个记忆块的垃圾桶图标会弹出 **Forget Memory** 窗口，点击 **Forget** 确认。
- 工具栏的清空图标会弹出 **Clear Memories** 窗口，点击 **Clear** 确认。这只会清掉回忆用的记忆，聊天消息不受影响。
- 刷新图标会用当前的聊天消息重建全部记忆块。换过嵌入模型之后就该用它。
- 导出会保存一个 `.marinara.json` 文件。导入接受 `.json` 或 `.marinara` 文件，并把内容合并进现有记忆。

### Memory Recall 的行为细节

以下几点值得留意：

- 只要有可用的嵌入来源，Marinara 就会在后台存记忆块，**Enable Memory Recall** 关着也照存。这个开关只决定存下来的记忆要不要注入。想彻底不存，就去掉嵌入来源，或者定期清空记忆。
- 至少要攒够 5 条新消息才会生成一个记忆块，不够的批次会等到下一次回复。
- 回忆出来的片段要通过相似度检查才算数。关系不够近的会被跳过，所以哪怕已经存了记忆，也可能一条都回忆不出来。
- 提示词里留给记忆的预算很小，最终只会补进最相关的那么几条。
- 已经存了记忆之后再换嵌入模型，旧记忆块就对不上了，用重建图标重做一遍。
- 删掉一个聊天的消息，它的记忆块也会一起删除。

Marinara 的部分容器构建版本叫 Marinara Lite，它把 Memory Recall 完全关闭了。这些版本里根本不会出现 **Memory Recall** 一节。

## Advanced Memory Recall（Roleplay）

打开 **Chat Settings → Memory Recall**，启用 **Advanced Memory Recall**。也可以在 Roleplay 设置向导的 Agents 下方启用 **Automatic context and memory handling**(自动管理上下文和记忆)。这个可选模式会一起管理保留原文的近期历史窗口、维持剧情连贯的摘要，以及相关的旧片段。桌面端和移动端都可以在向导和 Chat Settings 抽屉中查看设置与准备进度。存档查看器仍位于 Chat Settings 抽屉内。

### 设置

- 将 **Maximum allowed context before compression (tokens)** 设在聊天模型支持的上下文范围内。该上限计算预计发送的提示词，包括指令、消息、召回内容、工具和附件，聊天请求与记忆处理请求都适用。回复 Token 和安全余量另算。模型的总上下文限制仍然有效；这不是精确的分词器计数或计费上限。
- 在上述上限内设置 **Summary and recall budget (tokens)**(摘要与召回预算)。启用的常驻摘要以不超过该值的 **70%** 为目标。优先顺序是常驻摘要、所选场景摘要、消息摘录。需要时，整个记忆块可多用至多 **2,000 个 Token**，但不能超过完整上下文上限。例如，10k 的设置对应最多 7k 的常驻摘要目标和最多 12k 的总记忆；其他设置也按相同比例计算。当前消息不计入常驻摘要份额，也不会触发常驻摘要合并。
- 默认情况下： **Helper model**(辅助模型)负责独立场景判断、场景摘要和连续性压缩。默认使用智能体连接，否则使用聊天连接。首次历史场景检测可用主模型或辅助模型；摘要始终使用辅助模型。准备前会显示实际选用的模型。
- 所有记忆摘要调用都使用 **Chat Summary → Maximum output size**，至少预留 **8,196 个输出 Token**，为推理留出空间。场景摘要和常驻摘要合并都适用；更大的设置会保留。辅助连接的普通回复上限不会覆盖这个值。输入与输出预留仍须放得进模型的总上下文。
- 每个场景摘要请求只包含摘要指令、该场景可访问的消息、适用的消息范围修正和 JSON 输出格式。过大的场景分批处理并保存，然后合并。场景回顾要求 **2–3 段**。默认提示词只回顾历史，不写当前局势或未解决冲突的章节；在 **Summaries** 中选择的自定义提示词仍生效。Advanced Memory 独立于 Agents 总开关运行，无须下载智能体。
- **Maximum recalled scenes**(最多召回场景数)默认为**3**，只是上限，较弱匹配会被跳过。设为**0**可关闭可选场景召回，同时保留必要的连续性。每个选中场景提供摘要，后跟最多一个消息片段。
- **Moving context**(移动上下文)控制每个片段的消息数，默认**3–10**。两个限制都设为**0**则只用摘要；仅最小值设为**0**则片段可选。相关性、角色权限和空间可能使消息数更少，甚至为零。每个召回的场景都会先得到最小长度的片段，然后才会加长任何片段。如果某个召回的场景仍然没有片段，回忆记录会说明原因：放入摘要后已没有剩余空间，或者它的消息都无法引用。

对于已有的 Individual(独立) 群聊，请一次性确认缺失的角色知识范围。角色第一次发言，并不能证明其知道此前的所有内容。只有当某个实际角色应绕过参与范围限制时，才将其选为 **Narrator**(叙述者)。按角色隐藏和已确认的知识范围仍会限制记忆。全局 **Hide from AI**(对 AI 隐藏)，无论手动设置还是由自动摘要设置，都只将回合从当前对话记录移除：Advanced Memory 仍会扫描它、确定场景参与者、生成摘要，并为获准召回建立索引。起点标记会裁剪当前对话记录。你可以稍后修正这些范围；新加入的角色需要单独确认。

已有聊天请先点击 **Prepare existing history**(准备现有历史)。如果恢复的历史改变了手动修正所覆盖场景的边界，请禁用该记忆以保留文本供参考，或将其删除，然后重新准备历史。**Fix**(修复)（见[修复记忆问题](#fixing-memory-problems)）会跳过这个场景并把它列出来，而不会因此中止。再次保存同一修正并不能安全地把其文本分配到不同源范围。准备会分批处理旧历史，并在 Professor Mari 的仓鼠转轮旁显示当前阶段。**Cancel**(取消) 保留已完成工作；**Resume**(继续) 可在关闭抽屉、重启服务器或更新应用后接着处理。模型调用失败会保留此前有效的记忆，并显示可重试的错误。不要为了恢复失败调用而重置记忆：继续操作会复用已完成的摘要和未变化的场景检测。最后一个进行中的场景保持开放，结束后才生成摘要；若其当前消息超过上下文上限，则使用有界的源消息摘录。

在**Access memories for this chat**中打开摘要，选择底部的**Delete summary**(删除摘要)，确认摘要及受众。旧版**Continuity**(连续性)和**Ongoing scene**(进行中场景)条目也支持删除。常规准备不会重新生成已删除的场景摘要。原始消息保持完整。新常驻摘要位于**Chat Summaries**，复用现有编辑、启用、合并和删除功能；记忆库中的旧版连续性不再作为额外常驻摘要使用。

<a id="fixing-memory-problems"></a>

### 修复记忆问题

聊天记忆出了问题时，不用打开记忆设置也能看到。**Chat Settings** 按钮的一角会出现一个强调色的常亮圆点，同时弹出通知，说明有多少个场景存在问题。每组问题只通知一次；圆点会一直保留，直到这些问题解决。在 **Chat Settings → Memory Recall** 中，同样的问题会列在设置上方，**Access memories for this chat** 中也会显示同样的圆点。

在通知或该列表中点击 **Fix**，即可一次修复所有被标记的场景。它使用 **Helper model** 和常规的进度条。**Pause processing**(暂停处理) 会让它停下，**Resume processing**(继续处理) 会接着完成这次 Fix；已完成的工作会保留。Fix 会：

- 对标记为 **Check who was there**(核对谁在场) 的场景，再次询问辅助模型谁在场，并保存明确的答案。如果辅助模型仍然判断不出，不会有人新获得访问权限：该场景只保留原有角色中辅助模型没有排除的那些，同时会列出来供你检查；
- 对参与者检查功能出现之前保存的旧场景，核对有谁在场，包括自动检查失败的场景；
- 为消息、隐藏消息、角色名称或所依据的摘要发生变化的场景，以及还没有摘要的已结束场景，生成新摘要。你删除的摘要保持删除，不会恢复；
- 继续因出错而中断的记忆处理。

Fix 绝不会重写你手动编辑过的摘要。如果这类摘要已与其消息不符、漏掉了重新显示的消息，或其场景边界已经移动，Fix 不会动它，而是把它列在 **need your review**(需要你检查) 下，然后继续处理其他场景。它无法替你更改的设置，例如确认每个角色的知识范围或选择可用的 Decision 连接，会一直列出，直到你自己更改。

Fix 完成后，会显示 **Fixed N scenes**(已修复 N 个场景)，并用场景编号列出 **need your review** 的场景。点击编号，即可在 **Access memories for this chat** 中打开该场景。如果当时 Chat Settings 已关闭，会弹出一条带 **Show**(显示) 按钮的通知，点它就能跳转到 Fix 的结果。Fix 无法判断的场景，下次 Fix 时不会再询问；请自己保存它的角色访问权限。

### 可选的 Decision 模型

在 Advanced Memory 中启用 **Use Decision model**(使用决策模型)，然后在 **Memory Decision connection**(记忆决策连接) 中选择一个模型。**Local models**(本地模型) 下列出的本地模型与全局 **Decision model**(判定模型) 中的相同，例如在 **Local Model**(本地模型) 中运行的 **Primary local model**(主本地模型)。暂时无法回答的模型会以灰色显示并说明原因；已停止的模型会在 Advanced Memory 向它发出询问时启动。**Connections** 下列出你已保存的决策连接。在 **Connections** 中使用 TypeSafe、OpenRouter 或兼容的决策来源创建连接，参见[决策模型](../connections/decision-models.md)。此选项默认关闭，按 Roleplay 聊天保存。这里的选择独立于全局默认决策模型。

所选模型在历史准备和聊天期间的检查中识别场景边界。新回复前，它分两轮选择记忆。普通回忆先通过文本匹配（有已保存的向量时也用嵌入）筛选出最多 24 个场景摘要；如果 **Maximum recalled scenes** 更高，就以它为上限。模型从这份候选名单中挑出相关场景，再从每个选中场景的原始消息里取文本匹配度最高的至多 12 条逐一判断，以选定该场景的摘录。评价最高的那条作为中心，其余被选中的消息会把摘录加长，最多到 **Maximum messages per excerpt**(每段摘录最多消息数) 为止。如果某个场景的消息一条都没被采纳，就由文本匹配确定摘录中心，回忆记录也会注明这一点。如果某个场景的这些消息中没有任何一条能单独放进摘要剩下的空间，该场景就无法获得摘录，因此模型不会判断它的消息；如果所有选中的场景都是这种情况，就不会发出第二轮请求。边界不确定时，场景会保持开放。所有摘要和连续性更新仍由**Helper model**撰写。场景数量、摘录长度、角色访问权限和词元预算仍遵循现有限制。有效的决策也可以不选择任何记忆。

托管服务会收到最近的对话和候选名单中待评估的场景摘要或消息，一次回复可能产生多次收费请求。发送候选内容前，回忆功能会检查角色访问权限并处理摘要私有部分的条件。它只发送回忆该场景的角色在聊天中看到过的原始消息，每个角色也仍然只会拿到摘要中写给自己的部分。请求按连接的上下文预算拆成有限批次，不会假定Jev聊天路由器宣传的上下文大小适用于决策请求。

每一轮回忆决策各有 10 秒时限。连接缺失、答案不完整、候选内容过大、错误或超时都会回退到普通回忆：由候选名单自身的排序选择场景，由文本匹配选择摘录；场景决策不可用时则使用现有场景检查。启用期间，准备过程只建立文本索引，不创建新嵌入。已有向量仍可用于回退搜索。关闭后，如需为决策模式下准备的记录生成嵌入，请使用**Reindex**。

提示词检查仍为只读，使用普通回忆进行预览，不调用决策服务。在 **Peek Prompt → Decision diagnostics**(Peek Prompt → 决策诊断) 中，**Advanced Memory activity**(Advanced Memory 活动) 会显示最近一次检索和场景结束检查的已保存结果：模型、用时、分数、选中的记忆或结束位置、备用处理状态，以及召回的场景为何没有摘录。报告从本次更新后的新调用开始记录，每份最多保留 128 个结果，选中的结果优先。这是过去的活动记录，不是对预览的预测；打开面板或测试提示词语句不会重新执行记忆决策。Decision 模型的场景结束检查始终使用独立请求，与追踪器和智能体的批量请求分开。回忆记录会标明决策及回退情况。兼容的回复变体和续写会复用已保存的选择；更改这些设置会使不兼容的记忆快照失效。

<a id="deciding-who-sees-new-messages"></a>

### 决定谁能看到新消息

在角色逐个回复的 Roleplay 群聊里，Advanced Memory 可以决定每条新消息由哪些角色看到，这样就不必为离开场景的角色一条条手动隐藏消息。在 Advanced Memory 中开启 **Decide who sees new messages**(决定谁能看到新消息)。它默认关闭，只在角色逐个回复的群聊里出现；合并回复的群聊和单角色聊天没有这个选项。

开启后，每条新消息（无论是你的还是角色的）都会对不在该场景中的角色隐藏。隐藏方式和消息自身的按钮相同，都是按角色设置的 **Hide from AI**，所以划掉的眼睛图标会显示谁看不到这条消息。你自己的消息一发出就会立即决定，即使没有角色回复也是如此。下一个角色回复之前，前面的消息都已经决定好了，因此这个角色绝不会读到不该看到的内容。

- 这里选定的 **Narrator**，以及在 **Roleplay Commands**(Roleplay 命令) 下选定的 **Narrator character**(旁白角色)，始终能看到每条消息。消息的作者始终能看到自己的消息。不在场景中的耳语收件人收不到消息的其余部分，但仍会收到耳语。
- 开启 **Use Decision model** 时，会让 Decision 模型针对每个角色判断其是否明显看不到也听不到这条消息，例如该角色身在别处或已经离开。故事从未让其出现在场景中的角色，算作身在别处。人在场、只是没被包括在耳语中的角色，仍能看到消息的其余部分。否则由 **Helper model** 决定。无论哪种方式，只有模型确定时才会隐藏消息；模型不确定时，该角色仍能继续看到。如果回复后正好到了场景检查的时间，同一个请求也会回答谁在场，因此这些消息不会产生额外调用。
- 模型会读取当前场景到目前为止的消息，并且始终至少会读到这条消息之前的最后几条，即使新场景刚刚开始也是如此。它还会收到一份当前场景开始以来发过言的角色名单。这份名单只是提示：在一旁默默旁听的角色即使一句话也没说，也仍算在场。
- 如果你在自动选择之前或之后亲自更改某条消息的 **Hide from AI**，或对它使用 `/hide` 或 `/unhide`，就以你的选择为准，Advanced Memory 不会再改动这条消息。你之前已经对某个角色隐藏的消息，它也不会改动。
- 每条消息只决定一次。如果模型出错或没能及时回答，这条消息不会对任何角色隐藏，错误会记录在服务器日志里。

### 聊天过程

场景检测在 Roleplay 主回复保存后运行。**Standalone scene check interval (messages)** 默认为 **5**。检查模型收到带编号的最近消息、再往前一条作为上下文的消息、场景指令和输出格式。它指出每个场景结束的准确消息编号；如果场景仍在继续，就不返回结束点。用户角色和角色的消息都计数。频率不受跟踪智能体时间表影响；关闭决策模式时，到期检查在来源可见性和上下文预算允许时，共用生成后的跟踪智能体调用，否则单独调用辅助模型。新范围从上一场景结束后的消息开始，到新指出的结束消息为止。只有检测到结束，才在后台准备已结束场景的摘要和消息索引，包括最新回复正好结束场景的情况。不明确的转场会让场景保持开放。**Chat Settings → Agent activity** 以 **Advanced Recall** 显示进度、错误和恢复操作，即使普通智能体已关闭也一样。只有记忆任务运行时才轮询进度；准备好的档案不会在空闲时轮询。启用决策模式后，由选定的决策连接执行此检查。

关闭决策模式时： 普通召回读取已准备的记忆。可选的查询嵌入有较短超时，不可用时回退到文本匹配。文本匹配会提高最新用户消息中特征词的权重，让简短的细节也能找到较长的场景摘要。消息里提到的名字（比如宠物的名字）权重最高；但正在回复的角色和你的用户角色的名字不加权，出现在大多数记忆里的名字也不加权。即使关闭片段输出，也能通过已索引的原始消息找到场景。这两项都不会增加模型调用。召回仅用于 Roleplay 主生成：智能体调用、手动重跑和辅助试运行不会触发它，也不会接收返回的摘要或片段。主提示词检查保持只读。

重新生成的候选回复复用该回复最早保存的兼容记忆，包括连续性、场景摘要和完全相同的片段。没有变化的候选不会重新搜索或调用摘要辅助模型。续写保留回复最初使用的记忆。旧回复若没有快照，会在下次生成时保存并随后复用，无需重置。后台增加或合并常驻摘要会保留兼容快照。用户修改历史、访问设置、摘要或记忆会使不兼容快照失效。当前上下文上限始终生效。自该回复生成以来，如果其角色可召回的某个较早场景被保存、编辑、启用或停用，重新生成备选回复时也会再次召回。仍属于这条备选回复聊天历史的场景暂时还不能召回，因此保存它不会再触发召回。

主生成立即读取已保存的记忆，绝不启动或等待连续性摘要生成，即使后台辅助模型仍在工作。当发出的提示词达到上限，**所有角色**的当前窗口都会重置到最新场景开头，然后随新消息增长，直到再次达到上限。自动截断显示在现有 **Mark as new start** 中，且 **All** 已选中；取消 All 即可撤销。个人起点标记仍然生效。如果未结束的场景或过大的常驻摘要放不下，请求会使用明确标注的来源摘录，同时保留最新消息。这种临时调整不会另建持久标记，也不会覆盖已保存的摘要或原始消息。

主回复结束后，Advanced Memory 只为尚未覆盖的已归档消息扩展现有按范围划分的 **Chat Summaries**，尽可能复用已完成的场景回顾。现有条目（包括停用的条目）都算已处理范围。当符合条件且启用的常驻摘要超过 **Summary and recall budget** 的 70% 时，**Updating continuity** 在回复后仅合并这些摘要文本，使用选定辅助模型和 **Chat Summary → Maximum output size**。与当前消息重叠的常驻摘要不计入此预算，也不参与压缩；旧版无范围摘要仍符合条件。跨过阈值的回复照常使用已有的合格摘要生成，不等待压缩。额外 2,000 个 Token 属于整个记忆块，不属于常驻份额。Advanced Memory 撰写的摘要中，如果有用 `{{#if char == "Name"}}…{{/if}}` 段落写给部分角色的私密部分，就会与同一批角色读取的其他摘要一起合并。辅助模型收到的这些摘要会带着这些条件，并附上你的 **Combine prompt**(合并提示词)；它必须让每个私密部分仍然只属于当初知道它的那些角色，不多也不少。如果它的结果会改变谁能读到某个私密部分，结果就不会保存：这些摘要保持原样，只缩短其他摘要。你自己撰写或编辑过的摘要，以及宏在不同角色下展开成不同内容的其他摘要，保持不变；若仅这些摘要就超过目标，需要手动编辑。其他组收到按比例分配的长度指导，而非硬性拒绝阈值。更短且完整的替代摘要以消息范围命名，保存时同时停用被替换的条目。失败或未完成的输出不保存；现有条目仍可使用，**Resume processing** 只重试未完成工作。场景回顾留在记忆库中。

档案可以召回相关场景摘要和原文对话，保留原消息编号与说话者。一个 **Recalled Scenes** 部分按顺序放置每个摘要及其可用摘录，每段摘录只用一个范围标题；没有摘录的场景也留在此部分。记忆块注明当前历史范围和最后一条用户消息编号。只有场景的全部来源都在发送的当前历史之外，才会召回该场景；原文摘录也排除当前消息。按范围划分的 **Chat Summaries** 只要还有任一覆盖消息位于上下文内，也会暂时省略。它们仍然保存并启用，整个范围离开窗口后再次符合条件。合格常驻摘要优先于可选召回，并保留角色条件。先为所有已选场景摘要预留空间，再添加消息摘录。角色访问权限和历史来源限制继续生效。召回消息及新摘要输入会省略插图附件和图片说明，保留可读的文本附件。用户角色与角色消息都计数。历史重新生成只使用目标回复之前的来源，即使目标早于当前受管理窗口。编辑、切换回复、隐藏或删除来源后，会在使用前重新检查受影响的派生记忆。

在同一抽屉中打开 **Access memories for this chat**，可以搜索按时间顺序编号的场景摘要，查看故事中的时间范围和可访问角色，编辑 **Summary text**(摘要正文)，或通过 **Inspect source messages**(查看源消息)阅读完整的原始消息。内部使用的原文片段不会单独列为场景摘要。召回的上下文会附带有来源依据的故事时间范围；未知日期仍标为未知。你可以禁用回忆记录、重建索引、导出或导入，也可以确认 **Delete all memories**(删除所有记忆)，在保留原始聊天和设置的同时重新准备记忆。对原始手动摘要的修正会保留，并使依赖它的连续性摘要失效。要阻止召回某个场景，请禁用其记忆记录。按角色隐藏源消息仍然控制谁能访问；全局隐藏不会将其从档案中移除。

每份场景摘要还会记录参与者。参与者名字与角色卡不同时，例如用“Kaito”指 **Kaito Nakamura**，只要它恰好对应一个角色、且不可能是你的用户角色的名字，就仍然算数。两个角色共用的名字、角色与你的用户角色共用的名字、“Kaito's sister”这样的描述，以及带“(mentioned)”之类备注的名字，都不会给任何角色访问权限。你的用户角色自己的名字不算错误，但也不会给任何角色访问权限。如果辅助模型没有说明谁参与了场景，该场景会分配给所有角色：单角色聊天里就是那唯一的角色，群聊里则是全部角色。在群聊里，Advanced Memory 会把这种情况算作记忆问题，并在 **Access memories** 中把该场景标记为 **Check who was there**，你可以用 **Edit character access**(编辑角色访问权限) 移除不在场的角色，也可以让 **Fix** 再次询问辅助模型。名字对不上任何角色时，不会给出访问权限，该场景也会以同样方式标记，方便你设置参与者。辅助模型明确列出只有你在场的场景，仍仅限旁白访问。参与者检查功能出现之前保存的场景摘要，在检查前一直仅限旁白访问：**Fix** 和 **Prepare existing history** 会检查全部这类摘要，每条结束场景的回复也会顺带检查至多三份。自动检查失败的场景会等待 **Fix** 或 **Prepare existing history**。

只参加了部分场景的角色也可以与其他参与者共享该场景的记忆访问权限，即使其中有些消息对该角色隐藏。没有任何可访问原始消息的场景仍不可用。新的摘要指令会说明消息可见性，用普通文字描述共同经历，仅对私密部分使用 `{{#if character == "Name"}}…{{/if}}`。提到不在场的角色不会使其成为参与者。如果来源可见性改变，或撰写摘要时所针对的某个角色改了名字，旧摘要会暂时对仅有部分访问权限的读者隐藏，直到你重新准备该场景（**Fix** 会对所有这类场景执行这一步），或检查其私密条件并保存修正后的文本。之后才加入聊天的角色不算作改变，除非该场景只有一部分对其可见。早期版本保存的摘要没有记录当初针对哪些角色撰写，因此有角色加入后，需要执行一次 **Fix**。未保存可见性信息的旧摘要也需要经过同样检查，才能允许部分访问；仅修改受众不代表已确认文本内容。能访问全部原始消息的读者仍可召回该记忆，手动修正的文本也绝不会被悄悄重写。这些检查不会在召回期间调用模型。场景日期和时间范围是所有已分配参与者共享的元数据，即使部分原始消息被隐藏也是如此。原文片段绝不包含对角色隐藏的消息或耳语。含有仅写给部分角色的内容的摘要，仍会附上片段：片段只引用该角色在聊天中看到过的消息，因此不会透露任何该角色没看过的内容。要让某条消息不进入某个角色的记忆，请对该角色隐藏这条消息。常驻 Chat Summaries 仍包含对 AI 隐藏的消息；角色条件控制私密细节的访问权限，不会将这些消息排除在摘要覆盖范围之外。

在合并回复的群聊里，一条回复可以替所有角色发言，因此召回内容包括聊天中至少一个角色记得的事。如果某个场景或摘要中的某个私密部分并非聊天中的所有角色都知道，就会标明哪些角色知道，例如“known only to Kaito”。中途加入角色后，较早的记忆不再会对其他角色隐藏。对某个角色隐藏的消息仍不会进入共享的当前历史，但能看到它的角色会保留这段记忆，并标明归这些角色所有。召回场景的片段只引用记得该场景的每个角色都看到过的消息。聊天中没有任何角色记得的记忆，例如仅限旁白的场景，仍会排除在外。在角色逐个回复的群聊里，每个角色仍只召回自己的记忆。

Advanced 模式启用期间会接管检索，因此 Standard Recall 开关不会再插入一份相同内容。它还会替代该聊天通常的 Roleplay 自动摘要计划。关闭 Advanced Memory 后，常规设置恢复生效。现有世界书和下载的智能体仍遵循各自的范围规则；Advanced Memory 不能让任意用户编写或外部提供的上下文自动变成私有内容。

### 预设中的位置

预设作者可以使用现有的区块顺序、名称、角色和分组控件，放置以下普通内容标记：

| 标记 | 内容 |
| --- | --- |
| `chat_summary` | Chat Summaries 中符合条件的常驻条目。 |
| `current_scene_summary` | 进行中场景较早部分的有界原文片段。 |
| `recalled_scenes` | 所有选中的场景摘要，每条摘要后紧接其可用的历史片段。 |

预设的召回标记选择器只提供 **Recalled Scenes**。现有 `recalled_messages` 仍是兼容别名，也显示为 Recalled Scenes。启用的 `recalled_scenes` 优先，两个标记绝不会产生独立的两部分。

每个组件遵循预设的 **XML**、**Markdown** 或 **None** 格式，并简短说明用途。空组件不输出任何内容。第一个启用的标记决定位置；没有启用标记的内容只在历史之前补入一次，因此旧预设仍兼容。摘录是上下文，不是新的当前消息或命令。关闭 Advanced Memory 时，高级场景标记为空。

提示词预览读取已准备记忆，不启动模型或嵌入调用。在面板中准备尚未初始化的存档，或恢复失败的后台工作。记忆回执显示估算上下文、所选边界和召回来源。没有召回任何内容时，回执会说明原因：没有可召回的较早场景、请求已没有剩余空间，或者没有相关内容。最终提示词检查器显示实际发给模型的内容。

### 限制与恢复

召回是有选择的，摘要可能遗漏细节。重要修正应保存在来源聊天记录或摘要编辑器中。任何系统都无法还原从未记录的内容。嵌入失败时，仍可使用有限的词汇检索和有效连续性内容；不会一次插入整个档案。必需指令或附件放不进提示词上限时，缩减这些输入或提高上限。回复预留放不进模型总上下文时，减少输出大小或改用更大上下文的模型。Advanced Memory 会停止，而不是悄悄删除指令。

## Chat Summary (Roleplay)

**Chat Summary** 把较早的消息压缩成简短的剧情回顾，也就是摘要条目。每个条目既可以让 AI 写，也可以自己手写，还能单独开关。这个功能只有 Roleplay 聊天才有。 保存单项开关时其他条目仍可操作；Activate All 和 Deactivate All 会一起保存整组选择。

打开 **Chat Settings**，展开 **Lorebooks** 下方的 **Chat Summary**。在电脑上还可以把它弹出为独立窗口，见[聊天设置概览](../chats/chat-settings.md#popping-a-section-out-into-its-own-window)。

### 新建摘要条目

1. 在 **Summary Scope** 下选 **Last** 摘要最近的消息，或者选 **Range** 指定一段消息范围。
2. 点击 **Generate**，让 AI 按这个范围写一条条目。
3. 也可以点击 **Write** 新建一条空条目，自己动手写回顾。

列表里每个条目会显示标题、来源范围或消息条数，以及预估的 Token 大小。条目可以启用或禁用、展开，也可以点 **Edit** 修改或 **Delete** 删除。批量按钮可以一次 **Show Inactive** 或 **Hide Inactive**，也可以一次 **Activate All** 或 **Deactivate All**。

勾选条目即可选中；在电脑上，按住 Shift 点击另一个条目，可以选中两者之间可见范围内的所有条目。然后用 **Enable selected**(启用所选) 或 **Disable selected**(禁用所选)，只更改选中的条目。

在合并回复的群聊里，一条回复可以替所有角色发言。条目中为特定角色撰写的部分，例如 `{{#if char == "Kaito"}}…{{/if}}`，会为聊天中所有适用的角色保留，并标明哪些角色知道，例如“known only to Kaito”。只有 Advanced Memory 的 **Narrator** 才能看到的部分仍会排除在外。在角色逐个回复的群聊和单角色聊天里，每个角色照常读取这些条目。

### Automatic Summaries

**Automatic Summaries** 面板会在你继续聊的过程中不断更新摘要。它只出现在 Roleplay 聊天里。

- 开启 **Automatic Summaries** 面板里的 **Enabled** 开关。
- 用 **Every** 输入框设置运行频率，单位是用户消息条数。默认 5，范围 1 到 200。
- 点击 **Backfill Summary**，可以给一个从来没做过摘要的老聊天补齐。它会分批处理整个聊天，运行时显示进度条。想中途停下就点 **Stop**。

### Summary Prompt 模板

**Summary Prompt** 面板控制 AI 写摘要时使用的指示。点击 **Edit** 修改当前生效的提示词。点击 **Templates** 打开模板管理器，里面的 **New template** 可以保存一个带名字的提示词。每个已保存的模板都有各自的 **Duplicate**、**Edit** 和 **Delete**。

保存下来的模板是全局设置，对整个应用生效。在某个 Roleplay 聊天里编辑或选用一个模板，所有 Roleplay 聊天的摘要提示词都会跟着变。

### Summary Connection 与输出长度

**Summary Connection** 面板决定由哪个连接来写摘要。它的默认值显示为 **Agent default (falls back to chat connection)**，意思是优先用默认的智能体连接，其次才用聊天自己的连接。

**Maximum output size** 输入框设置一条生成摘要的最大长度。默认 4096 个 Token，范围 1 到 32768。

### 显示选项

**Chat Summary** 里的 **Display** 一组控件决定被摘要过的消息在屏幕上怎么显示：

- **Hide summarised messages**：一旦有摘要覆盖了某些原始消息，就把它们藏起来。默认关闭。
- **Recent message tail**：即使开了隐藏，也保留这么多条最新消息完整可见。默认 10，接受任何非负整数。设成 0 会把整批被摘要的消息都藏起来。数值越大，提示词越长，模型费用也越高。
- **Collapse hidden messages**：控制被隐藏的消息在聊天记录里的样子。

如果聊天要求智能体写入前先审批（这是 Agents(智能体) 里另外一项设置），AI 生成的摘要要等你过目之后才会生效。

## Automatic Summarization (Conversation)

Conversation 聊天用的是另一套机制，叫 **Automatic Summarization**。它先把每个自然日收尾成一份日摘要，再把已经结束的整周日摘要合并成一份周摘要。之后提示词只发送周摘要、本周的日摘要和今天的消息，这样每次请求都不会太大。

这个功能自动运行，Conversation 聊天里无法关闭。

### 打开编辑器

1. 打开一个 Conversation 聊天，点击 **Chat Settings**。
2. 找到 **Automatic Summarization** 一节（图标是一本日历）。
3. 点击 **Edit Summaries** 打开 **Automatic Summarization** 窗口。

窗口里先列出周条目，再列出还没并入某一周的零散日期。展开一个条目就能编辑它的 **Summary** 文本和 **Key Details** 列表，列表里的行可以增删。

### Day Rollover Hour 与 Recent Message Tail

**Automatic Summarization** 一节里有两项设置决定一天怎么划分：

- **Day Rollover Hour**：对摘要来说新的一天从几点开始。默认 4 AM，可以选 12 AM(午夜) 到 11 AM 之间的任意整点。在这个时刻之前发出的消息算作前一天。挑一个自己肯定不在聊天的时间点，免得熬夜的那一段被从中间切开。
- **Recent Message Tail**：今天最新的多少条消息即使已经被摘要，也仍然逐字保留。默认 10，接受任何非负整数。数值越大，提示词越长，模型费用也越高。

已经生成过摘要之后再改 **Day Rollover Hour**，Marinara 会提醒你旧摘要是按之前的设置算出来的。

### 补上缺失的日期

有时候某一天没能生成摘要，比如刚导入一个旧聊天之后。窗口里的 **Missing Summaries** 面板有一个 **Backfill** 按钮，会重试最近那些没有摘要的日期，一次最多往回找 14 天。

换掉写摘要用的连接或模型，不会重写已经存在的日摘要和周摘要。

## 故障排查

### Memory Recall 什么都回忆不出来

- 先确认嵌入来源已经配好。如果 **Memories for This Chat** 里的记忆块显示 **Embedding unavailable**，就去配置某个连接的 **Semantic Search (Embeddings)** 一节，或者干脆用内置的本地模型。见[本地模型设置](../connections/local-model.md)。
- 如果记忆块显示 **Waiting for vector**，稍等一会儿。指纹是在回复之后才生成的。
- 回忆只会补进和最新消息密切相关的记忆。没有相关内容时，它就什么都不加，这是正常的。
- 刚换过嵌入模型的话，在 **Memories for This Chat** 里点重建图标，让旧记忆块对上新模型。

### 摘要生成不出来

- 确认聊天有一个可用的文本连接。Chat Summary 用的是 **Summary Connection**，Automatic Summarization 用的是解析出来的摘要连接。一个都不可用时，生成就会被跳过。
- 如果聊天要求智能体写入前先审批，AI 摘要要等你批准之后才会生效。
- 生成失败的摘要会在延迟之后自动重试。要是一直卡着，就手动跑一次 **Backfill Summary**(Roleplay) 或 **Backfill**(Conversation)。
