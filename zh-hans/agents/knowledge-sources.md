# 知识源：Knowledge Retrieval 与 Knowledge Router 智能体

本指南介绍 Marinara Engine 里的两个知识类智能体：**Knowledge Retrieval**(知识检索) 和 **Knowledge Router**(知识路由)。它们都只在场景真正用得上的时候，才把世界书里的设定取出来放进聊天，这样就不必把每一个细节都塞进每一次的提示词。

## 这两个智能体做什么

世界书就是提前写好的一组世界设定或角色设定笔记，其中每一条叫作条目。聊天越写越长，如果每一回合都把全部条目发过去，就会白白浪费 Token。Token 是 AI 读取文本的最小单位，用得越多花费越高。全都发过去还容易让 AI 抓不住重点。

知识类智能体用 RAG 解决这个问题。RAG 是 retrieval-augmented generation(检索增强生成) 的缩写，意思是应用先找出符合当前场景的条目，再把这些条目单独加进这一回合的提示词。

Marinara 为此提供了两个可选智能体：

- **Knowledge Retrieval** 读取选定的知识源，把重要的事实概括出来，再把摘要加进提示词。
- **Knowledge Router** 读一份简短的条目清单，挑出符合场景的条目，然后原样加入这些条目。

两个智能体都只在 **Roleplay**(角色扮演) 聊天里生效，Conversation Mode 和 Game Mode 里加不了。两个都不是默认开启的，想用哪个就自己加到聊天里。

## Knowledge Retrieval 与 Knowledge Router 怎么选

可以先用这张表对比。做决定之前再读一遍表格下面的说明。

| 问题 | Knowledge Retrieval | Knowledge Router |
|---|---|---|
| 内容怎么加进来 | 先把知识源概括成摘要 | 把选中的条目原样加入 |
| 每回合的花费 | 较高 | 较低 |
| 能不能读上传的文件 | 能 | 不能 |
| 适合什么情况 | 知识源较小，或者想要一份干净的摘要 | 条目描述写得好的大型世界书 |

**Knowledge Retrieval** 会读完所选世界书里每一条启用的条目，外加上传文件的全部正文，然后请 AI 针对最近的消息写一段简短的事实摘要。因为 AI 要通读全部原始材料，所以每回合花费更高。

**Knowledge Router** 是更省钱的选择。它会给条目建一份小目录，每一行包含一个 ID、一个名称、几个关键词和一句摘要。AI 读这份目录，挑出符合场景的条目，再由 Marinara 把这些条目完整加入。AI 从来不会通读每一条条目的全文，所以世界书再大，路由的开销也很低。

两个智能体可以同时加进同一个聊天，但加进来的内容可能重叠，Token 花费也会跟着涨。两个都配置好时，智能体编辑器会给出提醒。想让提示词干净一些，就只留一个。

## 把知识类智能体加进聊天

要在 **Roleplay** 聊天里操作。

1. 打开 **Chat Settings**(聊天设置)。
2. 找到 **Agents**(智能体) 一节。
3. 开启 **Enable Agents**(启用智能体)。智能体列表随之解锁。
4. 点击 **Add Agent**(添加智能体)。
5. 展开 **Writer Agents**(写作智能体) 分组。
6. 选择 **Knowledge Retrieval** 或 **Knowledge Router**。

这时会弹出一个设置窗口，可以马上挑选知识源。添加完成后，它的设置卡片会出现在 **Agents** 一节里，之后每一个新回合都会自动运行。

**Knowledge Retrieval** 运行期间，进度提示里可能出现 **Retrieving knowledge...** 这个阶段。

注意：重新生成已有回复时，这些智能体不会再跑一次，它们只在新回合运行。

## 为 Knowledge Retrieval 上传文件

只有 **Knowledge Retrieval** 能读取上传的文件，**Knowledge Router** 只用世界书。

在 **Knowledge Retrieval** 的设置里可以看到一个文件列表和一个 **Upload file**(上传文件) 按钮。上传的文件对每一个用到 **Knowledge Retrieval** 的聊天都有效，不只是当前这个。

支持的文件类型有 .txt、.md、.csv、.json、.xml、.html、.htm、.log、.yaml、.yml、.tsv 和 .pdf，其他类型在文件选择器里选不了。列表里每个文件会显示名称和大小，旁边有一个删除按钮。

有几点限制要记住：

- 除 PDF 之外的文件都按纯文本读取。实际上不是文本的文件，比如把图片改名成 .txt，虽然能上传，但加进来的只会是一堆读不了的乱码。
- 扫描件或者纯图片的 PDF 没有文字层，智能体读不出内容。提取失败时，智能体会插入一段占位内容来代替真实内容。请使用文字可以选中的 PDF。

## 选择知识源：固定指定还是跟着聊天走

两个智能体的设置卡片里，知识源控件是同一套。

**Use chat-active lorebooks**(使用聊天中已启用的世界书) 开关默认开启。智能体编辑器里同一个开关叫 **Use this chat's active lorebooks**。开关开着、又没有选任何固定世界书时，智能体就用当前聊天启用的世界书。

开关下面是 **Fixed source override**(固定来源覆盖)，在设置窗口里显示为 **Fixed Source Lorebooks**。在这里选一个或多个世界书，就能把智能体锁死在这一组上。只要选了固定世界书，它就一定压过聊天启用的世界书，对每一个用到这个智能体的聊天都是如此。

想让某个智能体永远读同一本参考世界书时，就用固定知识源。想让它跟着聊天走，就保持开关开启、不选任何固定世界书。

## 把条目描述写好

这一节对 **Knowledge Router** 最重要。路由读每个条目的 **Description**(描述) 来决定加什么，描述写得好不好，直接决定它挑得准不准。

描述在世界书条目编辑器的 **Description** 输入框里填写。内容要短、要具体，说清这条条目讲的是什么。路由只拿这段文字来挑条目，不会把它当作故事内容发给主 AI。

条目没有描述时，路由会退而使用条目正文的开头部分，准确度会差一些。所以想让路由找得到的条目，都把描述填上。

给路由选好知识源世界书之后，**Fixed source override** 旁边会出现一个小小的描述完成度角标，用百分比和数量显示有多少条目写了描述，比如 **75% described (9/12)**。圆点在 75% 及以上是绿色，25% 到 74% 是琥珀色，低于 25% 是红色。所选世界书里没有条目时，它显示 **No entries yet**。目标是拿到绿色。

## 可选的语义候选筛选

**Knowledge Router** 还能按含义而不只是按关键词来找候选条目，这叫语义匹配。它要用到嵌入模型，也就是一个把文本转成数字、方便应用比较含义的小模型。这一步是可选的，不用它路由照样能跑。

要启用它，先给世界书做向量化。向量化就是应用对每个条目跑一遍嵌入模型，并把结果保存下来。打开世界书编辑器，找到 **Semantic Search (Embeddings)**(语义搜索) 一节，选一个带嵌入模型或设置了 **Embedding Connection**(嵌入连接) 的连接。如果你在 **Connections**(连接) 的 **Defaults**(默认值) 下选过 **Embeddings** 默认值，这里会自动替你选上它，除非你之前选过别的来源。向量化之前先确认选中的来源，并且使用和聊天连接相同的嵌入来源；维度不同的向量在语义匹配时会被跳过。然后点击 **Vectorize N missing**，其中 N 是还缺向量的条目数。也可以点 **Re-vectorize** 把所有条目重做一遍。详情见下面链接的语义搜索指南。

世界书没有向量，或者没有可用的嵌入模型时，路由会退回关键词匹配来生成候选清单。功能不会坏，只是完全靠关键词。
