# 世界书的 Token 预算与递归扫描

本指南介绍 Marinara Engine 如何限制送进 AI 的世界书文字量，涵盖每本世界书自己的 **Token Budget**(Token 预算) 和 **Entry Limit**(条目上限)，以及整个聊天共用的 **Lorebook Token Budget**(世界书 Token 预算)。此外还会讲预算占满时 Marinara 怎么裁剪条目，以及 **Recursive**(递归) 扫描的作用。

Token 是模型切分文本的最小单位，一个 Token 大致相当于几个字符。每个模型的上下文窗口都有上限，也就是它一次能读进去的文字总量。设预算就是为了不让世界书把这个窗口塞满，把真正的聊天内容挤出去。

## 两种 Token 预算

Marinara 每次组装提示词时都会同时套用两种 Token 预算。只要某个条目会让其中任意一个预算超标，Marinara 就跳过它。

1. 每本世界书都有自己的 **Token Budget**，限制这一本在单次回复里最多能加多少文字。
2. 每个聊天有一个 **Lorebook Token Budget**，限制该聊天里所有启用的世界书加起来的文字总量。

两个上限同时生效。一个条目可能卡在世界书预算上，也可能卡在聊天预算上，或者两个预算都满了。

## 设置世界书的 Token Budget 和 Entry Limit

从 **Lorebooks**(世界书) 面板打开一本世界书，切到 **Overview**(总览) 选项卡。扫描设置附近有两个数字输入框。

- **Token Budget**(默认 **2048**)：这本世界书在单次回复里最多能加的 Token 数。填 **0** 表示不限。
- **Entry Limit**(默认 **100**)：这本世界书在单次回复里最多能加的条目数，可以设为 **1** 到 **1000**。

**Entry Limit** 和 Token 预算是各自独立的两个上限，它算的是条目数，不是 Token 数。哪怕 Token 预算还有余量，世界书一旦达到这个条目数就不再往下加。反过来，世界书还没到 **Entry Limit** 时，Token 预算照样会跳过条目。

举个例子，一本世界书的 **Token Budget** 是 **2048**，里面有一个 3000 Token 的条目，那这个条目永远进不去。只有当某本世界书占的位置太多时才调低预算；重要条目老是被跳过，就把预算调高。

## 聊天级的 Lorebook Token Budget

聊天级的上限在聊天的 **Settings**(设置) 面板里，位于 **Lorebooks** 分区。

1. 打开一个聊天。
2. 打开聊天的 **Settings** 面板。
3. 找到 **Lorebooks** 分区。
4. 填写 **Lorebook Token Budget** 输入框。

默认值是 **8192**，填 **0** 表示不限。这个预算是本次聊天里所有启用世界书的总量，叠加在每本世界书自己的 **Token Budget** 之上。

## Marinara 怎么裁剪条目

匹配到的条目超出预算允许的量时，Marinara 会留下最重要的，丢掉其余的。裁剪之前它先给条目排序，好让你最可能需要的那些留下来。

- **Constant** 条目排在最前。这类条目设置成只要世界书处于启用状态就每次注入。
- 接下来是匹配到最新一条消息的条目。
- 其余条目按正常的注入顺序排在后面。

Marinara 顺着这份列表往下走，把还塞得下的条目逐个加进去。如果某个条目会让预算超标，就跳过它继续往下。被跳过的条目下面的每一条仍然会挨个检查，所以大条目被跳过之后，小条目照样有机会进来。

## 在 Active Context 里查看被跳过的条目

哪些条目被丢掉了，不用靠猜。打开 **Chat Settings**，展开 **Active Context**(活动上下文)，就能看到最近一次世界书扫描的实时结果。

如果有匹配上的条目被跳过，面板顶部会出现一条琥珀色提示，内容是“N matching lore entries were skipped by token budget.”，展开就能看到每一个被跳过的条目。

每条被跳过的记录都会写明它出自哪本世界书，以及被拦下的原因。原因有三种：

- **lorebook budget**：这个条目塞不进那一本世界书的 **Token Budget**。
- **chat budget**：这个条目塞不进聊天级的 **Lorebook Token Budget**。
- **lorebook and chat budgets**：两个上限都已经满了。

展开某个被跳过的条目还能看到更多细节：匹配到的关键词、估算的 Token 大小，以及预算已经用掉了多少。如果大本的世界书总是被跳过，**Active Context** 会建议改用 **Knowledge Retrieval**(知识检索) 或 **Knowledge Router**(知识路由) 智能体，它们通常比单纯调高上限更适合装下大世界书。

## 递归扫描

一般情况下，Marinara 只在最近的几条消息里找关键词。开启 **Recursive** 扫描后，它还会扫描刚刚激活的条目正文。这样一来，已激活的条目就能把正文里出现关键词的相关条目一并拉进来。

开关在世界书的 **Overview** 选项卡里。

1. 打开世界书。
2. 打开 **Overview** 选项卡。
3. 打开 **Recursive** 开关，默认是关闭的。
4. 想调整连锁能走多远，就设置 **Max Depth**(最大深度)。

**Max Depth**(默认 **3**) 决定额外跑多少轮扫描。每一轮都会在新激活的条目里继续找关键词匹配。可以设为 **1** 到 **10**。数值越大，挖出的关联设定越多，消耗的处理量也越大。

递归也可以在单个条目上单独开启。展开条目后的面板里有一个 **Recursion**(递归) 开关，它决定这个条目的内容能不能触发更多条目，默认是关闭的。除非确实希望这个条目连锁带出别的设定，否则就让它关着。条目的全部控件见[世界书条目：关键词、位置与时机](entries.md)。

递归不会绕开预算。递归过程中找出来的条目，同样要计入 **Token Budget**、**Entry Limit** 和聊天级的 **Lorebook Token Budget**，和其他条目一视同仁。
