# Game Mode 전투 개발 계획

이 문서는 [하이브리드 지형 #6265](https://github.com/Pasta-Devs/Marinara-Engine/issues/6265)와 후속 전투 작업의 합의된 방향을 기록합니다. 계획된 동작과 현재 게임을 구분합니다. 구현은 `staging`에서 시작하며, 아래 기능이 모두 출시되었다는 뜻은 아닙니다.

## 참여 방식과 전장 규칙 분리

현재 `combatStyle` 값은 `classic`과 `tactical`입니다. 이 값을 유지하세요. 향후 소환은 별도의 참여 설정으로 다루고, 이전 설정과 저장 데이터에서는 파티 전투를 기본값으로 사용하세요. 생성 프리셋으로 두 값을 함께 설정하면 새로운 영구 모드 열거형이 필요하지 않습니다.

| 프리셋 | 참여 | 전장 |
| --- | --- | --- |
| 파티 | 플레이어와 동료 | Classic 메뉴 |
| 소환(계획) | 조종하는 생물, 조련사는 전투 밖 | Classic 메뉴 |
| 전술 | 플레이어와 동료 | Tactical 격자 |
| 전술 소환(추후) | 조종하는 생물, 조련사는 전투 밖 | Tactical 격자 |

미완성 조합은 노출하지 마세요. 서사 속 동료와 전투 유닛은 서로 다릅니다. 파티 배열의 첫 번째 위치가 조종 대상의 영구 식별 규약이 되면 안 됩니다.

## 현재 구현 우선순위: 하이브리드 지형

GM은 장면에 근거한 작은 구조화 개요를 제공합니다. 엔진은 시드로 정확한 지형과 시작 위치를 정하고 전장을 검증해 저장합니다. 이후 GM이 승인된 전장을 서술합니다. 일반 이동과 공격에는 모델 호출이 필요하지 않습니다.

기존 환경 및 대형 처리에 선택적 지도 크기, 장면의 주요 지점, 플레이어의 지형 지침, 재사용 가능한 시드를 추가하세요. 이전 설정의 유효성을 유지하세요. 승인된 격자와 생성 출처를 저장해 향후 생성기 변경이 기존 전장을 다시 그리지 않게 하세요. 저장된 시드는 개요와 전투원이 같을 때 생성을 재현할 뿐, 임의의 모델 출력을 결정적으로 만들지는 않습니다.

연결성을 확보하기 위해 생성 지형을 보정할 수 있지만 작성자의 제약을 조용히 없애면 안 됩니다. 모델 출력, 타일 수, 유닛 수와 요소 크기를 제한하세요. 불가능한 배치는 대응 방법을 알 수 있는 이유와 함께 거부하고, 생성 지형을 쓰는 명시적 대안을 제공하세요. 완전한 그리기 및 배치 편집기와 임의의 제작 지도는 후속 작업이며 같은 검증 규칙을 사용해야 합니다.

### 이동 능력

걷기, 비행, 순간이동에는 명확한 이동 규칙이 필요합니다. 비행과 순간이동은 벽, 물, 산을 넘어가며 숲의 추가 이동 비용을 무시할 수 있습니다. 지형 방어 및 회피 보너스는 이동 방식과 독립적으로 유지하세요.

이동 방식이 생략된 이전 조우에는 걷기를 적용합니다. 명시적으로 지정된 미지원 방식은 오류로 거부하세요. 요청된 능력을 조용히 걷기로 바꾸면 안 됩니다. 이 검증 규약은 생성된 설계와 전술 API 입력 모두에 적용됩니다.

통과, 합법적 목적지, 점유 여부를 구분하세요. 벽을 통과하는 순간이동이 벽 안에서 멈출 권한을 뜻하지는 않습니다. 초기 평면 격자는 고도, 천장, 주문별 시야 조건이나 비행 시간 제한을 표현하지 못합니다. 완전한 테이블톱 이동 규칙이라고 주장하지 말고 한계를 문서화하세요. 미리보기, 판정, 경로 애니메이션과 적 AI에서 같은 이동 유효성 규칙을 재사용하세요.

## 테이블톱 규칙: 내장 프로필과 GM 참고 도구

완전한 생물 수집 게임보다 5e 및 V20와 비슷한 플레이를 우선하세요. 범위가 제한되고 버전이 관리되는 규칙 프로필은 후속 변경에서 추가하세요. 특정 규칙 체계의 구현이라고 부르기 전에 정확한 판본과 지원 범위를 정하세요.

엔진이 실제 주사위, 합법적 대상, 이동, 행동 예산, 자원 소모와 숫자 결과를 관리해야 합니다. GM은 서사를 해석하고 지원되는 작업을 선택하며 NPC 의도를 제공하고 실제 결과를 이야기합니다. 검색한 로어북 텍스트는 참고 자료와 캠페인 규칙을 제공할 수 있지만 판정기를 우회하거나 주사위 결과를 바꾸면 안 됩니다.

[이슈 #5955](https://github.com/Pasta-Devs/Marinara-Engine/issues/5955)는 로어북 의미 검색과 선택적으로 사용하는 도구 경로를 다룹니다. 검색은 보완 수단입니다. GM이 관련 정보를 찾도록 돕고, 명시적 규칙 프로필은 일반적인 규칙을 일관되고 테스트 가능하게 만듭니다. 평범한 주사위마다 별도 검색을 하지 마세요.

지원되는 판정, 턴, 자원 기본 동작부터 시작하세요. d20 중심 프로필과 d10 주사위 풀 프로필에는 다른 판정 규칙이 필요하며 이름만 바꾼 동일한 프로필이 아닙니다. 이후 우선권, 대항 판정, 피해와 경감, 상태와 자원 사용을 포함해야 합니다. 미지원 사례를 문서화하고 GM의 재량 판정을 명시하세요.

전술 테이블톱 작업에는 공통 시야선 및 엄폐 규칙도 필요합니다. 현재 격자는 벽을 통한 이동을 막지만 거리를 기준으로 한 원거리 공격은 벽을 넘을 수 있습니다. 판정기, AI, 반격, 예측과 위협 표시를 함께 업데이트하세요. 현재 파티 및 적 단계는 유지하고 개별 우선권은 별도로 선택하는 규칙 프로필로 두세요.

## 소환: 설계 유지와 큰 시스템의 연기

첫 단계는 작게 유지할 수 있습니다. 진영마다 활성 생물 하나, 보유한 예비 생물, 비전투 조련사, 명령을 소모하는 자발적 교체, 기절 후 교체 대기 상태의 저장으로 시작하세요. 배치 가능한 생물이 없으면 패배합니다. 조련사 아이템이 생물에게 추가 행동을 주면 안 됩니다.

안정적인 ID로 관리하는 명단 하나와 활성 슬롯 ID를 유지하세요. 서로 경쟁하는 배열 대신 예비 생물과 기절 상태를 명단에서 계산하세요. 보유 생물의 HP, 자원과 상태는 지속되며 조우 생성이 매 전투마다 이 능력치를 다시 만들면 안 됩니다. 예비 생물의 상태 진행 시점을 명확히 정하세요.

포획, 진화, 번식, 더블 전투, 임시 소환 지속 시간과 전술 소환은 별도 추가 사항입니다. GM 요약은 기절한 생물과 다친 조련사를 구분해야 합니다.

## 영속성과 검증

전투 시작 시 적용 규칙을 고정하세요. 새 선택적 필드는 이전 Classic 및 Tactical 저장 데이터를 보존해야 합니다. 설정 가져오기, 불변 생성 스냅샷과 요약은 새 선택을 유지해야 합니다. 새로고침, 재시작, 다음 세션으로 넘기기, 응답 후보 전환, 분기와 체크포인트 복원을 각각 명시적으로 검증하세요.

향후 서버가 관리하는 전투 상태는 조우 ID, 리비전, 멱등적 행동 ID를 사용해 전투와 명단 변경을 함께 적용해야 합니다. 적절한 기존 쓰기 대기열을 재사용하세요. `game_engine_state` 재사용 전에 턴제 게임과 Experience 네임스페이스를 점검하세요. 자동으로 안전한 전투 저장소가 되는 것은 아닙니다.

새 규칙마다 거부되는 행동과 이전 입력을 포함하는 최소 실행 가능 `*.regression.ts` 검증을 추가하세요. 브라우저 검증은 설정, 실제 전술 행동, 새로고침, 작은 화면, 테마 대비, 포커스와 키보드 접근, 유용한 오류 상태를 다뤄야 합니다. 현지화와 사용자 문서를 구현과 함께 유지하세요.

## 이전 작업과 기여 시작 지점

`feat/game-mode-combat-expansion`의 [병합 없이 닫힌 PR #4391](https://github.com/Pasta-Devs/Marinara-Engine/pull/4391)은 전투 세션, 전술 행동, 목표와 보스를 폭넓게 확장한 작업입니다. 유용한 선행 자료이지만 현재 staging의 동작은 아닙니다. 다시 시작하기 전에 담당자와 상태를 확인하고, 지형의 선행 조건으로 전체 확장을 병합하지 마세요.

주요 Engine 파일은 `packages/shared/src/features/tactical-combat/`, `packages/server/src/routes/encounter.routes.ts`, `packages/server/src/routes/game.routes.ts`, `packages/client/src/components/game/GameSetupWizard.tsx`, `GameSurface.tsx`, `TacticalCombatUI.tsx`입니다. 후속 작업이 다운로드 가능한 에이전트 및 Experience 정의나 패키지 전용 프롬프트를 건드린다면 해당 변경은 Marinara-Agents에 속합니다.
