# 선택적 멀티플레이어

구현 추적: [#6790](https://github.com/Pasta-Devs/Marinara-Engine/issues/6790). 이 문서는 구현 경계와 필요한 검증을 기록합니다. 멀티플레이어가 사용 가능하거나 특정 플랫폼이 테스트를 통과했다는 뜻은 아닙니다.

<a id="smallest-architecture"></a>

## 최소 아키텍처

한 호스트가 새 공유 채팅, 저장된 게임 상태, AI 연결을 소유합니다. 호스트가 사람과 AI 명단을 선택하며 참여자나 카드 수에 고정 상한은 없습니다. Conversation, Roleplay, Game은 기존 모드를 유지합니다. 초대로 과거 비공개 기록이 공유되지는 않습니다.

전송 방식은 작은 JSON 동작과 제한된 롱 폴링을 사용하는 전용 HTTPS 리스너입니다. Fastify, Node HTTPS, Zod는 이미 설치되어 있습니다. WebRTC는 시그널링, ICE/TURN 설정, 모바일 호스트 탭의 수명 문제를 더하고, WebSocket은 추가 서버 의존성과 스트리밍 파서를 요구합니다. 비공개 공유 채팅은 이런 추가 없이 HTTPS를 재사용합니다. 방 전송 방식은 이것 하나입니다. 리스너는 방 작업만 등록하며 일반 Engine API는 등록하지 않습니다. 중앙 릴레이 없이 게스트가 호스트에 직접 연결합니다. 초대는 상대의 파일, 라이브러리, 설정, 자격 증명, 무관한 채팅에 대한 접근을 주지 않습니다. 일반 Engine 관리 포트는 비공개로 유지하고 초대에는 별도 방 포트만 넣으세요.

게스트 자신의 신뢰할 수 있는 Engine이 호스트에 연결합니다. TLS 인증서 체인과 호스트명 검증을 통과해야 하며 초대는 호스트 인증서 지문도 고정합니다. 비밀번호나 페르소나를 보내기 전에 이 연결을 확인하세요. 리디렉션을 따르거나 HTTP로 전환하거나 인증서 검증을 끄거나 공유기 전달을 자동 설정하지 않습니다. 호스트가 기존 TLS 기능으로 HTTPS 주소와 인증서를 구성합니다.

게스트 화면은 신뢰할 수 있는 번들 코드로, 불투명 출처의 샌드박스에서 실행됩니다. 네트워크, 다운로드, 탐색, 저장소, 네이티브 브리지, 관리 훅은 없습니다. 인증된 MessageChannel은 검증된 방 투영과 작고 명시적인 동작 집합만 전달합니다. 부모 화면은 로컬 표시 환경설정을 제공하며, 상대는 스타일, 자산, 코드, 가져올 URL, 임의 API 호출을 제공할 수 없습니다. 상대 텍스트는 텍스트로 렌더링합니다. 기존 리치 채팅 렌더러는 이 경계 밖에 있습니다. Android 래퍼는 모든 프레임에 네이티브 브리지를 주입하므로, 브리지 없는 컨텍스트를 구현하고 실제 기기에서 검증하기 전까지 게스트로 사용할 수 없어야 합니다.

<a id="trust-boundaries"></a>

## 신뢰 경계

| 경계 | 적용 방식 |
| --- | --- |
| 로컬 관리자에서 방 컨트롤러 | 기존 Basic Auth, CSRF, 호스트 검증, 네이티브 로컬 인증 검사를 유지합니다. |
| 게스트 Engine에서 상대 리스너 | HTTPS, 지문 결합, 별도 방 비밀번호, 승인, 만료되는 무작위 세션, 제한된 요청. |
| 상대에서 신뢰할 수 있는 게스트 | 양쪽 수신부의 엄격한 버전 스키마, 텍스트 전용 투영, 불투명 샌드박스, 제한적 CSP. |
| 참여자에서 채팅/게임 상태 | 인증된 세션에서 신원과 소유권을 구하며 상대가 선택한 역할, 경로, 생성 요청은 받지 않습니다. |
| 방에서 생성 및 도구 | 호스트 소유 작업 매핑, 기존 생성 잠금, 명시적 방 명령/도구 정책, Game 준비 완료 장벽. |
| 공유 상태에서 기록 | 보이는 필드의 허용 목록. 자격 증명, 디버그 프롬프트, 추론, 비공개 메모, 무관한 라이브러리, 숨겨진 GM 상태는 제외합니다. |

인증된 상대도 신뢰 대상은 아닙니다. 프롬프트 텍스트는 그대로 유지하며 권한은 프롬프트 이스케이프나 모델에게 안전을 부탁하는 방식이 아닌 코드로 강제합니다. 호스트와 설정된 AI 제공자는 공유 내용을 읽을 수 있습니다. 직접 연결이므로 호스트에 연결 Engine의 IP 주소도 드러납니다. 다른 게스트 라이브러리나 기기 데이터는 프로토콜에 포함되지 않습니다. 모든 브라우저 또는 운영체제 결함에 대한 보호를 약속하지 않습니다.

<a id="activation-and-lifetime"></a>

## 활성화와 수명

`MULTIPLAYER_ENABLED=true`는 재시작이 필요한 전제 조건입니다. 누락, false 또는 잘못된 값은 멀티플레이어를 끕니다. 별도 Settings 활성화도 필요하며 어느 설정도 네트워크를 시작하지 않습니다. 호스팅과 참여는 각각 명시적 동작이 필요합니다. 재시작은 활성 방을 복원하지 않습니다. Stop, Kick, Leave는 해당 자격 증명을 취소하고 이후 동작이나 늦은 전달을 막습니다.

두 조건 중 하나라도 꺼져 있으면 세션 검색, 인증서 가용성 검사, 호스트/게스트 폴링, 자율 방 작업이 없습니다. 서버는 활성화 플래그를 읽고 클라이언트는 한 번의 가용성 조회를 캐시합니다. 명시적 Settings 동작으로 갱신할 수 있습니다. 비활성 API에 대한 직접 요청도 거부됩니다. 저장된 세션 정리는 활성화까지 미루며 네트워크를 재개하지 않습니다.

<a id="proof-before-enabling-the-feature"></a>

## 활성화 전 검증

- 지원되는 게스트 컨텍스트에서 악성 상대 텍스트가 실행, 자산 가져오기, 탐색, 다운로드, 로컬 API 접근, 네이티브 브리지 호출을 할 수 없음을 증명하세요.
- 비활성 조건, 미인증 입장, 소유권, 비공개 상태 투영, 제한된 트래픽, 권한 취소가 허용되지 않은 접근을 차단함을 증명하세요.
- 한 호스트 조정자를 통해 기존 생성, 명령, 자율 동작을 재사용하세요. 명시적 제한을 포함한 명령별 호환성 표를 공개하세요.
- Game 플레이어 둘 모두 제출하거나 명시적으로 패스한 뒤에만 한 라운드가 생기며, 재시도, 연결 끊김, 취소, 재시작이 상태를 이중 적용하지 않음을 증명하세요.
- 데스크톱과 모바일에서 기존 설정, 드로어, 사이드바, 입력창과 명확한 Leave/Stop 및 복구 컨트롤을 확인하세요. 실제 기기 검증의 빈틈을 기록하세요.

미완성 단계는 비활성 상태로 둡니다. #6790을 완료로 간주하려면 세 모드와 보안 경계가 모두 필요합니다.

<a id="command-and-feature-compatibility"></a>

## 명령 및 기능 호환성

방 동작은 인증된 호스트 조정자를 거칩니다. 표는 이 경계를 설명하며 상대에서 임의 명령을 실행할 권한이 아닙니다. 거부된 명령은 입력창에서 이유를 설명하며 게스트가 실행하지 않습니다.

| 기능 | 호출자 및 실행 | 공유 결과와 라운드 규칙 |
| --- | --- | --- |
| 사람 메시지, `/send` | 승인된 참여자. 호스트가 작성자를 표시한 사용자 메시지를 만듭니다. `/send`는 자동 답변을 억제합니다. | 공개 텍스트. Conversation/Roleplay는 수락된 게시물과 생성을 직렬화하며 바쁜 발신자는 초안을 유지합니다. Game은 라운드 수집기를 통해서만 게시합니다. |
| `/roll`, `/r`, `/dice` | 승인된 참여자. 기존의 제한된 Engine 주사위 파서와 굴리기를 호스트에서 실행합니다. | 작성자가 표시된 텍스트 결과. Game 굴리기는 라운드가 닫힐 때까지 그 플레이어의 제출 행동입니다. |
| 생성, `/trigger` | 승인된 참여자. 영속화된 호스트 생성 실행권 하나와 기존 생성 잠금을 사용합니다. | 필터링된 저장 완료 AI 서술. Game은 독립 트리거를 거부하며 준비 완료만 라운드 처리를 시작합니다. |
| 다른 슬래시 명령 | 방 권한을 감사하고 명시적으로 추가하기 전에는 불가합니다. | 시스템 역할 삽입, 사칭, 비공개 채팅 탐색/편집, 갤러리 작업, 기기 동작, 임의 로컬 명령 실행은 없습니다. |
| 그룹 답변 | 호스트가 선택한 승인 AI 명단과 기존 순차/Smart/수동 생성. | AI 신원은 사람 페르소나 스냅샷과 구분됩니다. `{{user}}`는 검토된 호스트 페르소나이며 마지막 발언 게스트가 아닙니다. |
| Conversation 일정과 자율 동작 | 기존 서버 스케줄러, 후보/의도 로직, 대기 간격과 사용 중 지연. 같은 방 실행권으로 전달합니다. | 게스트 스케줄러는 없습니다. 중지/일시 정지된 방과 Game은 타이머로 생성하지 않습니다. 사람 화면이나 승인된 상대가 45초간 확인되지 않으면 자율 동작이 멈춥니다. |
| Conversation `schedule_update`, `memory`, `react` | 방 정책 아래 기존 Engine 핸들러. | 일정/기억 변경은 방 내부에 한정됩니다. 반응은 이 채팅을 대상으로 하며 사용자 지정 이미지가 없어야 합니다. 전역 캐릭터 기억이나 접속 상태는 갱신하지 않습니다. |
| Roleplay 메모, 알림, 굴리기, 귓속말 | 기존 명령 파싱과 호스트 핸들러. 승인된 참여자 ID가 수신자를 결정합니다. | 비공개 메모는 비공개입니다. 귓속말은 수신자의 필터링된 스냅샷에만 보이지만 호스트는 여전히 저장 데이터를 소유합니다. 모든 참여자가 방 에이전트의 출력을 보므로 방 에이전트는 귓속말을 절대 읽지 않습니다. |
| 채팅 간 장면과 브라우저 알림 | 일반 흐름이 연결된 비공개 채팅을 만들거나 열고 브라우저 로컬 타이머를 사용하므로 제한합니다. | 장면은 공유 기록에서 설명하고 자율 메시지에는 호스트가 조정하는 Conversation 일정을 사용하세요. 받은 명령은 비공개 채팅이나 로컬 알림을 만들지 않습니다. |
| 로어북과 기억 | 호스트가 검토한 첨부/방 소유 책과 방 내부 대화 기억. | 프롬프트 컨텍스트만 제공하며 라이브러리를 내보내지 않습니다. 암묵적 전역 책, 연결된 비공개 채팅, 전역 카드 기억은 제외합니다. |
| Engine 추적기, 주사위, 상태, 요약, 변수 | 모델 프롬프트만이 아니라 실제 도구/에이전트 실행부의 명시적 허용 목록. | 안전한 공개 필드는 투영할 수 있지만 원시 에이전트 출력, 숨겨진 추론, 디버그 프롬프트, 비공개 GM 필드는 숨깁니다. Game 효과는 라운드 실행권 아래에 둡니다. |
| Game 행동, 선택, 판정, 인벤토리, 시트 | 호스트 Game 설정/시작과 기존 생성. 결정적 턴 후 효과는 한 번만 저장합니다. | 사람 행동의 소유권은 인증된 참여자에서 옵니다. 선택은 초안만 채우며 제출 준비 완료를 우회하지 않습니다. |
| 미디어, 사용자 지정/패키지 도구, Game Experiences, 기기 통합 | 방 생성에서 사용할 수 없습니다. | 상대 파일, 이미지, 오디오, 비디오, 원격 스타일, 다운로드, 네이티브 명령, 패키지 제공 게스트 UI는 없습니다. 별도 보안 단계가 필요합니다. |

초기 공유 Game은 동기화된 서술/행동 흐름입니다. 클라이언트 전용 전술/미니게임 화면, 사용자 지정 Game Experiences, 장면/미디어 표현을 게스트 기능으로 안내하지 않습니다. 표준 Game 설정을 재사용하되 해당 옵션을 명시적으로 제한합니다. 호환성의 빈틈을 채우려고 호스트 제공 렌더러를 로드하지 않습니다.

<a id="recovery-and-limits"></a>

## 복구와 제한

인증된 참여자마다 영속화된 단조 증가 동작 순서와 제한된 작업 영수증이 있습니다. 재시도는 이전 결과를 반환하며 영수증이 128개 캐시에서 빠진 뒤에도 재전송은 오래된 것으로 유지됩니다. 플레이어가 나중에 페르소나를 바꿔도 메시지의 페르소나 스냅샷은 바뀌지 않습니다. 대상 귓속말/판정을 위해 사람과 AI 페르소나 이름은 모호하지 않아야 합니다.

표시 이름과 페르소나 이름은 공개되므로 좌석의 소유자를 증명하지 못합니다. 나갔거나 응답이 없던 플레이어는 자신의 Engine이 그 좌석의 비공개 재입장 키를 제시할 때만 이전 좌석을 되찾습니다. 이 키는 처음 좌석을 배정받은 입장에서 받은 세션 토큰이며, 새 입장 요청의 bearer로 다시 보냅니다. 키가 없으면 같은 이름을 쓴 요청은 이름 충돌이 되고 그 좌석의 세션은 건드리지 않습니다. 두 Engine 모두 키를 메모리에만 보관합니다. 게스트 Engine이 다시 시작되면 호스트는 그 플레이어가 같은 페르소나를 다시 쓰기 전에 이전 좌석을 제거합니다.

Game 페르소나 변경은 다음 라운드 경계에 적용됩니다. 기존 시트, 현재 능력치, 인벤토리 소유권, 추적기 개인정보 키는 안정된 참여자 신원을 따르며 과거 메시지는 원래 작성자를 유지합니다. 그 전에 NPC가 요청한 이름을 차지하면 이전 페르소나를 유지하고 이름 충돌 메시지를 표시합니다. 호스트의 패스, 제거, 일시 정지, 재개는 같은 기록에 현지화된 이벤트를 남깁니다.

Game은 필수 참여자, 각 제출 개정판, 고유 처리 실행권을 기존 채팅 메타데이터에 저장합니다. 제출 수집과 작성자 메시지 저장은 기존 메타데이터 큐를 거친 뒤 저장소 트랜잭션으로 진행합니다. 제공자 작업은 그 밖에서 실행합니다. Stop은 신뢰된 작업 신호를 취소하며 늦은 방 쓰기도 활성 실행권과 일치해야 합니다. 중단된 턴을 자동 재시도하지 않습니다. 명시적 재개는 이미 저장된 효과를 반복하지 않고 다음 수집 경계로 이동합니다. 설정 실패는 로비에 남겨 명시적 확인/재시작을 기다립니다.

사람이나 AI 명단에 고정 상한은 없습니다. 프로토콜 버전 1은 동작당 16 KiB, 스냅샷당 256 KiB와 최근 100개 메시지, 텍스트 메시지당 8,000자로 제한합니다. 승인 대기열, 리스너 소켓, 요청, 롱 폴링, 세션, 비밀번호 파생, 생성 작업도 제한됩니다. 세션당 상대 폴링 하나, 게스트 Engine당 커넥터 폴링 하나가 활성화됩니다. 압축과 리디렉션은 받지 않습니다. 비밀번호/토큰은 URL이나 공유 스냅샷에 넣지 않습니다.

큰 방은 호스트 자원, 연결 처리량, 모델 컨텍스트에 좌우됩니다. 업데이트에 맞추려고 명단 항목을 조용히 제거하지 않습니다. 공유 업데이트가 전송 한도를 넘으면 게스트는 마지막 유효 상태를 유지하고 나갈 수 있습니다. 호스트는 방을 계속 관리하고 공유 데이터를 줄여 폴링을 복구할 수 있습니다.

## 검증 기록

자동 검증은 일회용 저장소, 로컬 테스트 CA, 모의 모델 제공자를 사용합니다. 사용자 인증서, 데이터, 설정된 AI 연결은 변경하지 않습니다.

- `multiplayer-peer-security.regression.ts`: HTTP 정보 공개 전 TLS 체인/호스트명/지문 확인, 잘못되거나 과도하거나 리디렉션된 응답과 취소.
- `multiplayer-peer-server-security.regression.ts`: 방 전용 경로, 본문/헤더/출력/속도/동시성 제한, 즉각적인 리스너 종료.
- `multiplayer-seat-key-security.regression.ts`: 복사한 이름이나 잘못된 재입장 키로 좌석이나 그 좌석의 귓속말을 차지하지 못함, 키 소유자의 같은 좌석 복귀, 다른 참여자나 저장된 채팅 데이터로 키가 전달되지 않음.
- `multiplayer-room.regression.ts`: 두 Engine, 입장, 소유권, 필터링된 기록, 취소/재전송, 생성 직렬화, 두 플레이어 Game 라운드/복구.
- `multiplayer-session-flows.regression.ts`: HTTPS의 두 Engine과 실제 생성/Game 런타임, 모의 제공자, 완전한 Conversation, Roleplay, Game 라운드.
- `multiplayer-generation-policy.regression.ts`와 `generation-output.regression.ts`: 실행부 제한, 비공개 라이브러리 제외, 프롬프트 내부 신원, 공유 생성 잠금, 완료 의미.
- `multiplayer-autonomy-security.regression.ts`: 기존 스케줄러 재사용, 방 활동 시계, 단일 권한, Stop 경합.
- `multiplayer-game-runtime.regression.ts`: Game 설정/시작/도입, 결정적 턴 효과, 오래된 쓰기, 설정 중단.
- `multiplayer-game-persona.regression.ts`와 `multiplayer-game-projection.regression.ts`: 페르소나 소유권 이전, 충돌 복구, 대상 필터링, 제한된 공개 추적기.
- `e2e/multiplayer-guest-isolation.e2e.ts`: 데스크톱 Chromium, 모바일 Chromium, 모바일 WebKit에서 운영용 게스트 번들에 악성 텍스트와 로컬/네트워크/네이티브 접근 시도를 가하는 검증.
- 집중 설정/컨트롤 브라우저 사례는 입장 경고, Players, Game 로비, 터치 배치, 밝음/어두움, 초안/재시도를 다룹니다.

병합 전 최종 후보에서 `pnpm check`, 관련 Node 회귀, `pnpm regression:prompt`, `pnpm smoke:ui`, 집중 브라우저 매트릭스를 다시 실행하세요. 실제 명령 결과와 리비전을 PR에 기록하고 CodeRabbit 및 집중 보안 검토를 마친 뒤 지원하는 실제 기기를 확인하세요. 브라우저 에뮬레이션은 실제 iPhone/iPad 홈 화면이나 Android의 증거가 아닙니다. Android 네이티브 래퍼는 게스트로 비활성 상태를 유지합니다. 실제 기기 결과는 기록 전까지 미확인입니다. 뷰포트 프리셋만으로 지원을 추정하지 마세요.

게스트는 고전적 IIFE로 빌드합니다. 불투명 출처의 ES 모듈 로드는 CORS를 완화해야 하기 때문입니다. 운영 및 개발 시작 시 고정된 로컬 게스트 자산을 빌드합니다. 개발 서버가 실행 중일 때 게스트 소스를 수정했다면 `node packages/client/scripts/build-multiplayer-guest.mjs`를 실행하고 게스트 화면을 새로 고치세요. 런처 완전성 검사는 두 격리 자산을 모두 포함합니다.
