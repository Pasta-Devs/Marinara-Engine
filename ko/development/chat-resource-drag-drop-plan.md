# 채팅 리소스 드래그 앤 드롭 계획

## 진행 상태

Phase 1부터 Phase 4까지는 `drag-me-baby-one-more-time`에 구현되었고 `staging`에 병합되었습니다. 이후 작업(#7362)으로 라이브러리 행을 손잡이 없이 끌 수 있고, 터치 사용자가 두 번째 손가락으로 탭해 호환되는 리소스를 묶음으로 모을 수 있으며, 순서를 바꿀 때 삽입 틈이 표시됩니다.

리졸버 자동 검증은 동작 중입니다. 캐릭터 배정과 페르소나 교체를 다루는 데스크톱 Playwright 검증도 추가했지만, 지금 개발 컨테이너에서는 Chromium이 `libnspr4.so`를 불러오지 못해 로컬 실행이 막혀 있습니다. 이 브라우저 케이스는 CI나 Playwright 시스템 의존성이 갖춰진 환경에서 실행해야 합니다.

남은 Phase를 시작하기 전에 저장소의 협업 규칙을 따르세요:

1. 채팅 리소스 드래그 앤 드롭을 다루는 기존 이슈, 이슈에 연결된 브랜치, 초안 PR, 프로젝트 항목이 있는지 확인하세요.
2. 이슈에 담당자를 드러나게 표시하세요.
3. 구현을 시작할 때 `staging`을 대상으로 초안 PR을 여세요.

## 목표

채팅 설정을 거치지 않고도 지원되는 리소스를 오른쪽 패널에서 현재 채팅으로 끌어다 놓을 수 있게 합니다.

가운데 영역에는 목적지가 될 수 있는 곳이 두 군데 있습니다:

- **채팅 화면:** 현재 채팅에 계속 유지되는 설정을 바꿉니다.
- **입력창:** 지원되는 첨부 파일을 현재 초안에 추가합니다.

이 두 곳이 아무 드롭이나 받아 주는 것은 아닙니다. 끌고 온 항목이 그 자리에서 실제로 지원되는 동작을 가질 때만 목적지가 나타납니다.

## 제품 규칙

드래그는 리소스와 목적지를 고르는 동작일 뿐입니다. 앱은 채팅 데이터 모델과 생성 파이프라인에 이미 들어 있는 동작만 수행합니다.

- 유효한 추가 동작이 하나뿐이면 즉시 적용하고 실행 취소를 제공합니다.
- 유효한 교체 동작이 하나뿐이면 기존 값을 덮어쓰게 될 때 확인을 받습니다.
- 실제로 지원되는 동작이 여럿이면 그 동작들만 담은 작은 선택 창을 띄웁니다.
- 유효한 동작이 없으면 목적지를 활성화하지 않습니다.
- 이미 적용된 리소스는 중복해서 드롭할 수 없게 합니다.
- 짐작에 기댄 한 턴짜리 컨텍스트, 감춰진 프롬프트 주입, 지어낸 언급, 장식용 칩은 만들지 않습니다.

## 현재 계약

기존 `Chat` 계약과 `ChatMetadata` 계약이 지원하는 영구 저장 동작은 다음과 같습니다:

- 캐릭터: `Chat.characterIds`를 갱신합니다.
- 페르소나: `Chat.personaId`를 갱신합니다.
- 프롬프트 프리셋: `Chat.promptPresetId`를 갱신합니다.
- 연결: `Chat.connectionId`를 갱신합니다.
- 로어북: `ChatMetadata.activeLorebookIds`를 갱신합니다.
- 에이전트: `ChatMetadata.activeAgentIds`를 갱신하고, 동의를 받은 경우 `ChatMetadata.enableAgents`도 갱신합니다.
- 채팅 배경: `BackgroundPicker`가 쓰는 것과 같은 지정 경로로 기존 채팅 배경 메타데이터를 갱신합니다.

기존 입력창은 파일 첨부를 지원합니다. 메시지 단위로 캐릭터, 로어북, 에이전트, 페르소나, 프리셋, 연결을 참조하는 기능은 아직 없습니다.

## 지원 동작 표

기능 리졸버는 현재 채팅 모드의 제약과 리소스 사용 가능 여부도 함께 강제해야 합니다. 아래 표는 현재 모드에서 기존 UI가 이미 허용하는 경우의 동작을 설명합니다.

| --- | --- | --- | --- |
| 캐릭터 | `characterIds`에 ID 추가 | 없음 | 즉시 추가하고 실행 취소가 달린 토스트 표시 |

| 사용자 지정 함수 또는 도구 | 없음 | 없음 | 채팅 범위 지정 계약이 생기기 전까지 목적지 없음 |

### 모드 규칙

드래그 핸들러에 모드 정책을 다시 구현하지 마세요. 드롭 기능 리졸버는 기존 채팅 준비 화면 및 설정 UI와 같은 판정 함수를 써야 합니다.

최소한 다음을 지켜야 합니다:

- 프롬프트 프리셋은 `PresetsPanel`과 마찬가지로 Conversation 모드에서 계속 쓸 수 없습니다.
- 에이전트 드롭은 그 에이전트가 설치돼 있고, 사용할 수 있으며, 현재 모드에서 유효할 때만 받아들입니다.
- 캐릭터, 페르소나, 로어북, 연결, 배경 동작은 기존 지정 컨트롤을 쓸 수 있는 자리에서만 제공합니다.
- 활성 ID가 없는 채팅에는 리소스 드롭 목적지를 만들지 않습니다.
- 스트리밍이나 에이전트 처리가 진행 중이라는 이유로 안전한 메타데이터 갱신을 막지 마세요. 기존 뮤테이션 경로가 이미 막고 있을 때만 예외입니다. 교체 확인은 적용하기 전에 현재 채팅 상태를 다시 읽어야 합니다.

## 상호작용 설계

### 드래그 시작

지원되는 패널 행은 모두 버전이 붙은 리소스 페이로드 하나를 씁니다:

```ts
type ChatResourceDragPayload = {
  version: 1;
  kind: "character" | "lorebook" | "agent" | "persona" | "preset" | "connection" | "background";
  ids: string[];
  label: string;
};
```

사용자 지정 MIME 타입 하나를 씁니다. 예를 들면 `application/x-marinara-chat-resource`입니다. 옮겨 가는 동안에도 기존 폴더 MIME 페이로드는 남겨 두세요. 폴더 순서 변경은 같은 드래그를 해석하는 또 하나의 유효한 방법으로 남기 때문입니다.

리소스 드래그 효과는 `copyMove`로 알려야 합니다:

- 폴더 목적지는 그 드래그를 이동으로 해석합니다.
- 채팅 목적지는 복사 또는 지정으로 해석합니다.

내부 리소스 동작에 `text/plain`을 쓰지 마세요. 뜻이 모호하고, 지금은 ID만 그대로 들어 있습니다.

### 목적지 표시

드롭 안내는 평소에 숨겨 둡니다.

알아볼 수 있는 리소스 드래그가 가운데 영역에 들어오면 다음 순서로 처리합니다:

1. 타입이 붙은 페이로드를 파싱하고 검증합니다.
2. 가장 최근의 현재 채팅을 기준으로 유효한 동작을 판정합니다.
3. 유효한 목적지만 표시합니다.
4. 뭉뚱그린 `Drop here` 대신 `Add Maris to this chat`처럼 동작을 그대로 밝히는 문구를 씁니다.
5. 유효하지 않은 영역은 그대로 두고 드롭도 받지 않습니다.

지원되는 파일을 끌면 입력창만 강조합니다. 캐릭터, 로어북, 에이전트, 페르소나, 프리셋, 연결, 배경을 끌면 첫 릴리스에서는 채팅 화면만 강조합니다.

### 채팅 화면 드롭

드롭을 받는 영역은 현재 대화 화면 전체이며, 메시지 기록의 스크롤 위치와는 상관없습니다. 예전 메시지 위에 놓아도 기록이 끼어들거나 컨텍스트가 소급해서 바뀌지 않습니다.

드롭하면 다음 순서로 처리합니다:

1. 현재 채팅 ID와 채팅 데이터를 다시 읽습니다.
2. 낡은 동작이나 중복 동작을 막기 위해 기능을 다시 판정합니다.
3. 추가 동작이고 해석이 갈리지 않으면 즉시 적용합니다.
4. 교체이거나 에이전트를 켜야 할 때는 그 내용만 담은 확인 창을 엽니다.
5. 성공하면 번역된 토스트와 실행 취소 동작으로 알립니다.
6. 뮤테이션이 실패하면 메시지 기록은 그대로 둔 채 알립니다.

설정 변경을 기록하려고 사용자, 어시스턴트, 내레이터, 시스템 메시지를 만들지 마세요. 메시지 모델에는 활동 이벤트 전용 타입이 없고, 설정 이벤트가 모델에 보이는 기록에 들어가서도 안 됩니다.

### 입력창 드롭

`ChatInput`과 `ConversationInput` 양쪽에서 지금의 파일 동작을 그대로 유지합니다:

- 지원되는 형식과 20 MB 용량 제한을 검사합니다.
- 이미지는 `prepareImageAttachment`로 준비합니다.
- 지원되는 텍스트 파일과 PDF 파일은 지금의 첨부 경로로 읽습니다.
- 채팅별 대기 중 첨부 초안 동작을 유지합니다.

입력창의 드래그 감지를 더 좁히세요. 내부 리소스 드래그가 파일 드롭 강조만 켜 놓고 아무 일도 하지 않는 상황을 막기 위해서입니다.

### 확인

결과가 뚜렷하게 달라지는 동작에서만 확인을 받습니다:

- 활성 페르소나를 교체할 때.
- 활성 프롬프트 프리셋을 교체할 때.
- 활성 연결을 바꿀 때.
- 에이전트를 추가하면서 에이전트 기능을 켤 때.
- 기존 배경 지정 경로가 이미 선택이나 교체 확인을 요구할 때.

확인 창에는 해당하는 경우 현재 값과 바뀔 값을 함께 밝혀야 합니다. 새 채팅 시작, 에이전트 한 번 실행, 메시지에서 리소스 참조처럼 관계없는 동작을 넣어서는 안 됩니다.

### 실행 취소

실행 취소는 드롭 직전의 값을 그대로 되돌립니다. 짐작으로 다시 만든 값이 아닙니다.

- 캐릭터: 이전 `characterIds` 배열 전체를 복원합니다.
- 로어북: 이전 `activeLorebookIds` 배열 전체를 복원합니다.
- 에이전트: `activeAgentIds`와 `enableAgents`를 모두 복원합니다.
- 페르소나, 프리셋, 연결, 배경: 이전 값을 복원합니다.

실행 취소를 수행하기 전에, 드롭으로 넣은 값이 현재 채팅에 그대로 남아 있는지 확인하세요. 그 사이에 다른 편집이 같은 필드를 바꿨다면 덮어쓰지 마세요. 낡은 실행 취소를 없애고 채팅이 바뀌었다고 알립니다.

## 아키텍처

### 공용 클라이언트 유틸리티

역할을 좁게 잡은 클라이언트 모듈을 추가합니다. 이름은 임시로 `packages/client/src/lib/chat-resource-drag.ts`이며 다음을 담습니다:

- MIME 상수.
- 페이로드 타입과 런타임 파서.
- `writeChatResourceDragPayload(dataTransfer, payload)`.
- 파일 드래그 감지.
- 리소스 종류 가드.

첫 릴리스에서는 페이로드를 클라이언트 안에만 둡니다. API 계약이 아니라 브라우저 상호작용 상태이기 때문입니다.

### 기능 리졸버

순수 함수로 된 리졸버를 추가합니다. 이름은 임시로 `packages/client/src/lib/chat-resource-drop-capabilities.ts`입니다:

```ts
type ChatResourceDropAction =
  | { type: "add-characters"; ids: string[] }
  | { type: "add-lorebooks"; ids: string[] }
  | { type: "add-agents"; ids: string[]; mustEnableAgents: boolean }
  | { type: "set-persona"; id: string; replacesId: string | null }
  | { type: "set-preset"; id: string; replacesId: string | null }
  | { type: "set-connection"; id: string; replacesId: string | null }
  | { type: "set-background"; id: string };
```

입력은 파싱한 리소스 페이로드, 현재 채팅, 정규화된 메타데이터, 현재 모드, 사용할 수 있는 리소스 ID입니다. 출력은 구체적인 동작 하나이거나 `null`입니다.

리졸버가 담당하는 일은 다음과 같습니다:

- 중복 차단.
- 모드 제약.
- 여러 ID 걸러내기.
- 설치 여부와 사용 가능 여부 확인.
- 교체 여부 판별.
- 화면에 보일 동작 키 선택.

리졸버는 뮤테이션을 수행하지도, UI를 렌더링하지도 않습니다.

### 뮤테이션 조정자

채팅 화면 가까이에 훅 하나를 추가합니다. 이름은 임시로 `use-chat-resource-drop.ts`이며 다음 일을 합니다:

- 드롭 시점에 React Query와 Zustand에서 가장 최근의 현재 채팅을 읽습니다.
- 채팅 최상위 필드에는 `useUpdateChat`을 호출합니다.
- 로어북과 에이전트에는 `useUpdateChatMetadata`를 호출합니다.
- 배경 지정은 기존 뮤테이션 경로를 재사용합니다.
- 기존 app-dialog 헬퍼로 번역된 확인 창을 엽니다.
- 성공 토스트와 오류 토스트, 그리고 보호 장치가 붙은 실행 취소 동작을 만듭니다.

비동기 뮤테이션 로직을 Zustand 스토어에 넣지 마세요.

### 드롭 오버레이

표시만 담당하는 컴포넌트 하나를 공용 가운데 채팅 경계에 추가합니다. 메시지 기록마다 따로 구현하지 마세요:

- 현재 드래그 페이로드와 판정된 동작을 받습니다.
- 입력창을 가리지 않으면서 대화 화면을 덮습니다.
- 자식 요소를 지날 때 깜빡이지 않도록 `dragenter`와 `dragleave` 깊이를 세어 관리합니다.
- 아이콘, 리소스 이름, 번역된 동작 문구를 표시합니다.
- 포인터 종류와 테마에 맞춰 반응합니다.

Conversation 화면과 Roleplay/Game 화면 모두 같은 조정자를 거쳐야 합니다. 화면별 래퍼가 배치 정보를 제공하는 것은 괜찮지만, 기능 정책을 다시 구현해서는 안 됩니다.

### 패널 통합

드래그할 수 있는 행은 차례대로 옮깁니다:

1. 캐릭터.
2. 로어북.
3. 에이전트.
4. 페르소나.
5. 프리셋.
6. 연결.
7. 기존 지정 계약을 깔끔하게 재사용할 수 있다면 배경.

각 행은 기존 폴더 드래그 페이로드를 그대로 두고 채팅 리소스 페이로드를 더합니다. 폴더 이동 동작은 바꾸지 마세요.

## 출시 단계

### Phase 1: 드래그 계약과 가운데 오버레이

- 타입이 붙은 페이로드 유틸리티와 파서를 추가합니다.
- 캐릭터, 로어북, 에이전트를 다루는 순수 기능 리졸버를 추가합니다.
- 가운데 채팅 화면 오버레이와 뮤테이션 조정자를 추가합니다.
- 캐릭터, 로어북, 에이전트 패널 행을 연결합니다.
- 동작, 확인, 성공, 오류, 중복, 실행 취소 문구를 번역 가능한 형태로 추가합니다.
- 내부 리소스 드래그가 입력창의 파일 강조를 켜지 않도록 합니다.

이 단계에서 이 기능이 요청받은 핵심 추가 워크플로가 성립하는지 확인합니다.

### Phase 2: 교체형 리소스

- 페르소나, 프리셋, 연결 페이로드를 추가합니다.
- 교체 판별과 번역된 확인 창을 추가합니다.
- 기존 모드 제약과 뮤테이션 훅을 재사용합니다.
- 교체 동작에도 보호 장치가 붙은 실행 취소를 추가합니다.

### Phase 3: 배경 지정

- 기존 배경 선택 흐름이 정책을 다시 구현하지 않고도 드롭된 배경 ID를 받아들일 수 있는지 판단합니다.
- 같은 채팅 범위 지정 동작을 재사용할 수 있을 때만 배경 드래그를 추가합니다.
- 그렇지 않으면 배경은 지원하지 않는 상태로 두고, 막힌 이유를 이슈나 PR에 기록합니다.

### Phase 4: 터치와 드래그 없는 방식의 동등성

데스크톱 HTML 드래그 앤 드롭이 첫 구현 대상입니다. 모바일이 패널을 넘나드는 정밀한 드래그에 의존해서는 안 됩니다.

- 지원되는 행마다 기존 동작 메뉴에 `Add to active chat`을 추가합니다.
- 같은 기능 리졸버, 확인 창, 뮤테이션, 실행 취소 동작을 그대로 재사용합니다.
- 터치 드래그를 남긴다면 기존 터치 드래그 손잡이를 쓰고, 가운데 목적지는 `elementFromPoint`로 판정합니다.
- 폴더 길게 누르기 동작에 기능을 덧씌워 정리 기능을 못 믿게 만들지 마세요.

모바일에서 이 기능이 완성됐다고 말하려면 이 단계를 반드시 마쳐야 합니다.

### 순수 함수 회귀 검증

기능 리졸버를 위한 영구 검증은 기존에 지원되는 회귀 테스트 위치와 형식에만 추가합니다:

- 캐릭터가 없음 -> 추가 동작.
- 캐릭터가 이미 있음 -> 동작 없음.
- 여러 캐릭터가 섞인 페이로드 -> 빠져 있는 유효한 ID만 추가.
- 로어북이 없음 -> 추가 동작.
- 로어북이 이미 활성 상태 -> 동작 없음.
- 에이전트가 없고 에이전트 기능이 켜져 있음 -> 추가 동작.
- 에이전트가 없고 에이전트 기능이 꺼져 있음 -> 활성화가 필요한 추가 동작.
- 에이전트를 쓸 수 없음 -> 동작 없음.
- 현재 페르소나가 없는 상태의 페르소나 -> 교체가 아닌 지정 동작.
- 다른 페르소나를 교체하는 페르소나 -> 교체 동작.
- 지원되지 않는 모드의 프리셋 -> 동작 없음.
- 현재 연결과 같은 연결 -> 동작 없음.
- 잘못된 버전, 알 수 없는 종류, 형식이 깨진 ID, 크기가 너무 큰 페이로드 -> 거부.

### 브라우저 스모크 검증

가능한 범위에서 `pnpm smoke:ui`를 확장합니다:

- 패널에서 캐릭터를 채팅 화면으로 끌어다 놓고 지정되는지 확인합니다.
- 실행 취소한 뒤 이전 캐릭터 목록이 복원되는지 확인합니다.
- 캐릭터를 입력창 위로 끌어도 파일 드롭 표시가 나타나지 않는지 확인합니다.
- 지원되는 파일을 입력창 위로 끌어 첨부 동작이 그대로인지 확인합니다.
- 이미 활성 상태인 리소스에는 드롭 목적지가 열리지 않는지 확인합니다.
- 교체 확인을 취소하면 아무것도 바뀌지 않는지 확인합니다.
- 교체를 확인하면 채팅이 실제로 바뀌는지 확인합니다.
- 폴더 드래그 앤 드롭으로 패널 안에서 리소스가 여전히 옮겨지는지 확인합니다.

### 수동 확인

데스크톱에서 지원되는 범위에 한해 Conversation, Roleplay, Game 모드에서 다음을 확인하세요:

- 어두운 테마와 밝은 테마.
- 오른쪽 패널을 연 상태에서 메시지 기록이 길거나 스크롤된 경우.
- 추가 드롭, 중복 드롭, 교체, 취소, 실패, 실행 취소, 낡은 실행 취소.
- 메시지 기록의 중첩된 요소 위를 지날 때 오버레이가 깜빡이지 않는지.
- 기존 패널의 폴더 이동.
- 두 입력창의 기존 파일 및 이미지 드롭.

모바일 화면과 정밀도가 낮은 포인터 환경에서 다음을 확인하세요:

- 드래그 없이 쓰는 `Add to active chat`이 같은 결과를 내는지.
- 기존 폴더 터치 드래그를 여전히 쓸 수 있는지.
- 확인 창이 화면에 들어오고 닫을 수 있는지.
- 글자나 컨트롤이 겹치지 않는지.

반드시 실행해야 하는 명령:

```bash
pnpm localization:check
pnpm check
pnpm regression:prompt
pnpm smoke:ui
```

`pnpm regression:prompt`는 병합 전에 반드시 실행해야 합니다. `LorebooksPanel.tsx` 변경이 로어북 활성화에 영향을 주고, 그 결과가 프롬프트 조립으로 이어지기 때문입니다.

## 위험과 대응

### 기존 폴더 드래그와의 충돌

위험: 같은 행이 이미 드래그 앤 드롭으로 항목을 폴더에 넣는 데 쓰이고 있습니다.

대응: 기존 폴더 MIME 타입을 유지하고, 타입이 구분되는 채팅 리소스 MIME 타입을 따로 추가해서, 각 목적지가 자기 페이로드만 해석하게 합니다. `copyMove` 동작과 폴더 기능 회귀를 확인하세요.

### 입력창의 잘못된 강조

위험: 지금의 입력창 `dragover` 핸들러는 내부 리소스 ID를 포함해 어떤 드래그에도 반응합니다.

대응: `DataTransfer.types`나 `DataTransfer.items`가 파일이나 명시적으로 지원되는 다른 첨부 페이로드를 가리킬 때만 입력창 표시를 켭니다.

### 낡은 채팅 상태

위험: 드래그 시작, 드롭, 확인, 실행 취소 사이에 현재 채팅이나 지정된 리소스가 바뀔 수 있습니다.

대응: 드롭 시점에 현재 상태로 판정하고, 뮤테이션과 실행 취소 직전에 한 번 더 판정합니다. 실행 취소가 더 새로운 변경을 덮어쓰지 않도록 막습니다.

### 모드 정책의 어긋남

위험: 드래그 앤 드롭이 준비 화면이나 설정 UI에서 금지한 지정을 허용할 수 있습니다.

대응: 기존 지정 흐름에서 공용 판정 함수를 빼내거나 재사용합니다. 패널 컴포넌트 안에 두 번째 정책 표를 하드코딩하지 마세요.

### 감춰진 동작 확대

위험: 입력창이 리소스를 받아들이는 것처럼 보이면, 서버가 실제로는 처리하지 않는 한 턴짜리 컨텍스트가 있는 것처럼 오해를 줄 수 있습니다.

대응: 메시지 범위 컨텍스트 계약을 따로 설계하기 전까지는 리소스를 입력창에 드롭하는 기능을 꺼 둡니다.

### 대량 선택 드롭

위험: 선택 모드에서 끌면 예상보다 많은 캐릭터, 로어북, 에이전트가 한꺼번에 추가될 수 있습니다.

대응: 유효하지 않거나 이미 활성 상태인 ID를 걸러 내고, 기존 서버 제한과 모드 제한을 지키며, 여러 항목을 한 번에 드롭해 기존 한도를 넘게 되면 확인을 받습니다. 근거 없는 제한을 새로 만들지 마세요.

## 명확한 제외 범위

- 지난 메시지 위에 리소스 드롭하기.
- 프롬프트 기록을 소급해서 바꾸기.
- 설정 변경을 메시지 기록에 메시지로 남기기.
- 한 턴짜리 캐릭터, 로어북, 페르소나, 프리셋, 연결, 에이전트.
- 입력창에 드롭해서 에이전트 실행하기.
- 가운데 화면 드롭으로 새 채팅 시작하기.
- 아무 설정이나 채팅으로 끌어다 놓기.
- 첫 릴리스에서 범용 플러그인 드롭 API 제공하기.
- 한 채팅의 메시지 기록에서 다른 채팅으로 끌어다 놓기.

## 수락 기준

Phase 1은 다음 조건을 모두 만족하면 완료로 봅니다:

- 캐릭터, 로어북, 에이전트를 오른쪽 패널의 행에서 유효한 현재 채팅 화면으로 끌어다 놓을 수 있습니다.
- 메시지 기록에 메시지를 만들지 않고 알맞은 기존 채팅 필드가 갱신됩니다.
- 이미 활성 상태이거나 쓸 수 없는 리소스는 받아들이지 않습니다.
- 에이전트 기능이 꺼진 상태에서 에이전트를 추가하려면 명시적인 확인을 거쳐야 합니다.
- 성공한 모든 뮤테이션에 보호 장치가 붙은 실행 취소가 제공됩니다.
- 리소스 드래그는 입력창의 첨부 표시를 켜지 않습니다.
- 두 입력창 모두에서 기존 파일 첨부 드롭이 그대로 동작합니다.
- 기존 폴더 드래그 앤 드롭 동작이 달라지지 않습니다.
- 새로 화면에 보이는 문구가 모두 지역화되어 있습니다.
- 모바일이 패널을 넘나드는 드래그 대신 메뉴 동작을 쓰더라도, 데스크톱과 모바일이 같은 동작을 제공합니다.
- `pnpm localization:check`, `pnpm check`, 그리고 관련 UI 스모크 테스트가 통과합니다.

기능 전체는 Phase 2의 교체형 리소스와 필수 모바일 동등성까지 마쳐야 완료로 봅니다. 배경 지정은 기존 방식을 정책 중복 없이 재사용할 수 있다고 Phase 3에서 확인하기 전까지 선택 사항으로 남습니다.

## 나중으로 미룬 확장

나중에 메시지 범위 컨텍스트 기능이 생기면 캐릭터, 로어북, 에이전트, 페르소나, 프리셋, 연결도 입력창에 드롭할 수 있게 될지 모릅니다. 그 작업에는 저장 방식, 프롬프트 조립, 토큰 예산, 제공자 라우팅, 표시, 초안 복원, 메시지 기록 처리 방식을 정의하는 별도의 shared/server 계약이 필요합니다. 클라이언트에만 있는 칩으로 이 기능에 슬쩍 끼워 넣어서는 안 됩니다.
