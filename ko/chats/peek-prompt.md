# Peek Prompt: AI가 받은 내용 확인하기

Peek Prompt는 Marinara Engine이 답변을 받으려고 모델에 보낸 텍스트를 그대로 보여 주거나, 다음 답변에 쓸 프롬프트를 실시간으로 미리 보여 줍니다. 답변이 예상과 달라서 모델이 무엇을 보았는지 알고 싶을 때 쓰세요.

프롬프트는 Marinara가 모아서 보내는 지시 내용과 채팅 기록 전체입니다. 모델은 이를 읽고 답변을 씁니다.

## Peek Prompt 열기

**Assembled Prompt**(프롬프트 구성) 창을 여는 방법은 두 가지입니다.

메시지에서 열기:

1. 가장 최근 AI 메시지를 탭해 동작 막대를 표시하세요.
2. **Peek prompt**(프롬프트 미리보기)를 클릭하세요. 돋보기 아이콘입니다.

이 버튼은 마지막 AI 메시지에만 나타납니다. 그보다 앞선 메시지에는 표시되지 않습니다.

입력란에서 열기(AI 답변이 아직 없어도 쓸 수 있습니다):

1. 메시지 입력란에 다음 텍스트를 그대로 입력하세요: `{{prompt}}`
2. <kbd>Enter</kbd>를 누르거나 **Send**(전송)를 클릭하세요.

Marinara는 메시지를 보내는 대신 입력란을 비우고 창을 엽니다. `{{prompt_preview}}`와 `{{preview_prompt}}`도 똑같이 동작합니다.

## 창에 표시되는 내용

제목 옆의 배지는 지금 읽고 있는 프롬프트가 어떤 버전인지 알려 줍니다.

| 배지 | 의미 |
| --- | --- |
| **Exact Text Model Request** | 모델에 실제로 보낸 요청 그대로입니다. |
| **Live Preview** | 지금 이 자리에서 만든 미리보기입니다. |
| **Raw Messages** | 가공하지 않은 메시지 목록입니다. |
| **Prompt Preview** | 일반적인 미리보기입니다. |
| **Decision test preview**(결정 테스트 미리보기) | Decision 테스트의 답으로 만든 프롬프트입니다. 채팅 모델에는 보내지 않았습니다. |

그 아래 정보 패널에는 서비스와 모델, 예상 토큰 수, 답변이 끝난 뒤의 실제 프롬프트 토큰 수가 표시될 수 있습니다. 토큰은 모델이 단어 대신 세는 작은 텍스트 조각입니다. 패널에는 **Temperature**(온도), **Max Output Tokens**(최대 출력 토큰), **Thinking**, **Reasoning**(추론), **Verbosity**(상세도), **Service Tier**(서비스 티어), **Assistant Prefill**(어시스턴트 프리필)처럼 이번에 쓰인 값의 태그와, **Top P**, **Top K**, **Min P** 같은 샘플링 값도 표시됩니다. **Service Tier**와 **Assistant Prefill** 같은 태그와 샘플링 값은 고급 모델 설정입니다. 처음에는 신경 쓰지 않아도 됩니다. 첫 번째 모델이 실패해 대체 모델이 답변을 썼다면, 패널에 실패한 모델과 "key rejected"나 "rate limited" 같은 짧은 이유가 표시됩니다.

나머지 부분은 접었다 펼 수 있는 섹션으로 나뉜 프롬프트이며, 섹션마다 대략적인 토큰 추정치가 따로 붙습니다. 채팅 메시지는 **Chat History**(채팅 히스토리) 아래에 모여 있습니다. 저장된 요청을 그대로 보는 경우 서비스가 여러 채팅 턴을 블록 하나로 합쳤을 수 있으므로, 각 블록을 펼쳐 텍스트를 모두 확인하세요. 섹션 헤더를 클릭하면 열리고 닫힙니다.

### 프롬프트 복사하기

닫기 버튼 옆의 복사 버튼을 클릭하세요. 닫힌 섹션까지 포함해 모든 섹션과 메시지를 보낸 순서대로 일반 텍스트로 복사합니다. 각 메시지는 `[system]`, `[user]`, `[assistant]`처럼 역할을 나타내는 줄로 시작합니다. 저장된 요청을 그대로 보는 경우에는 요청을 보낸 그대로 복사합니다. 복사해도 아무것도 보내지 않습니다.

### 프롬프트 안의 텍스트 찾기

위쪽의 **Find**(찾기) 필드를 쓰거나, 창 안에서 <kbd>Ctrl</kbd>+<kbd>F</kbd>를 누르세요(Mac에서는 <kbd>Cmd</kbd>+<kbd>F</kbd>). 찾기는 대소문자를 구분하지 않고, 닫힌 섹션과 채팅 기록을 포함한 프롬프트 전체를 검색합니다. 카운터에는 "2 of 5"처럼 현재 일치 항목이 표시됩니다. 위아래 버튼이나 <kbd>Enter</kbd>와 <kbd>Shift</kbd>+<kbd>Enter</kbd>로 일치 항목 사이를 이동하세요. 양쪽 끝에 도달하면 반대쪽 끝으로 이어집니다. **Find**에 텍스트가 있는 동안에는 창에 메시지 전체 텍스트가 표시됩니다. 필드를 비우면 섹션 보기로 돌아갑니다.

## Reply checkup으로 답변 점검하기

Marinara가 답변이 좋지 않은 원인으로 보이는 것을 찾으면, 창의 프롬프트 위에 **Reply checkup**(응답 점검) 패널이 표시됩니다. 패널은 다음과 같은 내용을 알려 줄 수 있습니다.

- **Large character card**(큰 캐릭터 카드): 캐릭터 카드가 커서 프롬프트 예산을 많이 차지합니다.
- **Cut off**(잘림): 답변이 토큰 한도에 걸려 문장 중간에 멈췄습니다.
- **Empty reply**(빈 응답): 모델이 화면에 보이는 텍스트를 하나도 돌려주지 않았습니다.
- **N older messages not sent**(이전 메시지 N개 전송 안 됨): 프롬프트에 다 들어가지 않아 이전 메시지를 보내지 않았습니다.
- **N lorebook entries left out**(로어북 항목 N개 제외됨): 로어북 항목이 일치했지만 예산에 들어가지 못했습니다.
- **Reply limit cut**(응답 한도가 줄어듦): 프롬프트 공간을 확보하려고 답변 한도를 낮췄습니다.

도움이 되는 경우에는 **Max output tokens**(최대 출력 토큰)나 **Lorebook token budget**(로어북 토큰 예산)처럼 바꿔야 할 설정으로 바로 가는 링크가 표시됩니다.

## 예상과 다른 답변 진단하기

**Assembled Prompt**를 열고 다음을 확인하세요.

- **빠진 정보.** 로어북 항목, 기억, 페르소나 정보가 어느 섹션에도 없다면 모델은 그 내용을 본 적이 없습니다.
- **파라미터 태그.** **Temperature**가 높으면 답변이 산만해질 수 있고, **Max Output Tokens**가 낮으면 답변이 짧게 잘릴 수 있습니다.
- **Chat History.** 있어야 할 메시지가 올바른 순서로 모두 있는지 확인하세요.
- **토큰 수.** 프롬프트가 크면 오래된 메시지가 모델의 한도 밖으로 밀려날 수 있습니다.

그런 다음 원인을 바로잡으세요. 캐릭터 카드를 고치거나, 로어북 항목을 손보거나, 생성 설정을 바꾸면 됩니다. [생성 파라미터](../prompts/generation-parameters.md)를 참고하세요.

방향을 잡아 준 답변의 지침을 보려면 메시지의 **Stored guidance**(저장된 지침)를 쓰세요. [지침 기반 생성과 Impersonate](guided-and-impersonate.md#read-stored-guidance)를 참고하세요.

## Decision 문 테스트

[Decision 모델](../connections/decision-models.md)은 로어북 같은 기능을 위해 예/아니요 질문에 답합니다. Peek Prompt 안의 **Decision diagnostics**(결정 진단)에서는 현재 채팅의 그런 질문을 살펴보고 테스트할 수 있습니다.

1. Peek Prompt를 열고 **Decision diagnostics**를 찾으세요.
2. 패널을 열거나 **Preview inputs**(입력 미리보기)를 클릭하면 어떤 모델에도 묻지 않고 요청 본문을 준비합니다. **Prepared request bodies**(준비된 요청 본문)를 펼치면 최근 메시지, 해석된 문, 선택지, 요청 형식을 볼 수 있습니다.
3. **Test decisions**(결정 테스트)를 클릭하면 대상이 되는 질문을 Decision 모델에 묻습니다.

**Test decisions**는 실제 요청을 보내므로 호스팅 모델은 요금을 청구할 수 있습니다. 채팅 답변을 쓰거나, 에이전트를 실행하거나, 게임 상태를 바꾸거나, 답과 타이머를 채팅에 저장하지 않습니다. 뒤쪽 로어북 문은 앞선 문에 답이 나온 뒤에야 도달할 수 있습니다. 명시적인 테스트는 일반적인 답변 전 결정이 미뤄진 상태에서도 로컬 추론 모델을 기다릴 수 있습니다. 이 동작은 실제 답변에 쓰는 설정을 바꾸지 않습니다.

각 결과에는 점수가 있으면 점수, 예/아니요 문의 임계값, 그리고 답이 표시됩니다. "yes"나 "no"만 돌려주는 모델은 그렇게 표시되며, 그 답은 확률로 표시되지 않습니다. Choice 결과에는 선택된 옵션이 표시됩니다. 보류, 지연, 한도 초과, 사용 불가, 실패한 결정에는 각각 별도의 설명이 있습니다.

테스트 뒤에는 아래 프롬프트가 테스트의 답을 사용합니다. 처음 열었던 내용으로 돌아가려면 **Show original prompt**(원본 프롬프트 표시)를, 다시 전환하려면 **Show tested prompt**(테스트된 프롬프트 표시)를 클릭하세요. **Requests sent and results**(보낸 요청과 결과)는 실제 요청 본문과 결과를 보여 주며, 인증 헤더는 포함하지 않습니다.

작동하지 않는 경우: **Could not prepare the decision test. Check the chat connection and try again.** 이 메시지가 보이면 채팅에 작동하는 모델이 있는지 확인한 다음 다시 시도하세요.

이전 답변에서 Peek Prompt를 열었더라도 테스트는 현재 채팅과 설정을 사용합니다. 원래 결정 요청을 다시 만들지 않습니다. 테스트 대상은 프롬프트 문과 로어북 결정이며, 에이전트 활성화나 답변 후 결정은 포함하지 않습니다.

Advanced Memory(Marinara의 장기 기억 기능, [Memory Recall과 채팅 요약](../agents/memory.md) 참고)에서 **Use Decision model**(판단 모델 사용)이 켜져 있으면 패널에 **Advanced Memory activity**(고급 기억 활동)도 표시됩니다. 이 저장된 보고서는 최근 회상과 장면 종료 확인을 모델, 시간, 점수, 선택 결과, 대체 처리 상태와 함께 보여 줍니다. 현재 미리보기가 아니라 과거 호출을 설명하며, 프롬프트에 Decision 문이 없어도 나타날 수 있습니다. 호환되는 스와이프는 이전 회상 보고서를 다시 사용할 수 있습니다. 보고서마다 선택된 결과를 먼저 두어 최대 128개 결과를 보관하고, 나머지는 개수만 셉니다. 새 보고서는 다음 적격 Decision 모델 호출 뒤에 나타납니다. 보고서를 보는 것만으로는 모델 요청을 보내지 않습니다.
