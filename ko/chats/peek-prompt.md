# Peek Prompt: AI가 받은 내용 확인하기

Peek Prompt는 Marinara Engine이 답변을 받기 위해 AI 모델에 보낸 텍스트를 그대로 보여 줍니다. 아무것도 보내기 전에 프롬프트를 실시간으로 미리 볼 수도 있습니다. 이 가이드에서는 이 뷰어가 무엇을 보여 주는지, 어떻게 여는지, Stored guidance를 어떻게 읽는지, 답변을 진단할 때 어떻게 쓰는지 설명합니다.

프롬프트는 Marinara가 모아서 모델에 보내는 지시 내용과 채팅 기록 전체를 말합니다. 모델은 이 프롬프트를 읽고 답변을 씁니다. Peek Prompt는 조립이 끝난 이 덩어리를 그대로 보여 주므로, 답변이 왜 그렇게 나왔는지 짐작할 필요가 없습니다.

## Peek Prompt가 보여 주는 것

Peek Prompt를 열면 **Assembled Prompt**(프롬프트 구성) 창이 열립니다. 이 창은 세 부분으로 나뉩니다.

제목 옆 맨 위에는 소스 배지가 있습니다. 지금 보고 있는 프롬프트가 어떤 버전인지 알려 줍니다.

- **Exact Text Model Request**: 모델에 실제로 보낸 요청 그대로입니다.
- **Live Preview**: 지금 이 자리에서 새로 만든 미리보기입니다.
- **Raw Messages**: 가공하지 않은 메시지 목록입니다.
- **Prompt Preview**: 일반적인 미리보기입니다.
- **Decision test preview**: 명시적으로 실행한 Decision 테스트의 답으로 조립한 프롬프트입니다. 채팅 모델에는 보내지 않았습니다.

배지 아래에는 생성 정보 패널이 있습니다. 제공자와 모델 이름, 예상 토큰 수를 볼 수 있고, 답변이 끝난 뒤에는 실제 프롬프트 토큰 수까지 표시됩니다. 토큰은 모델이 단어 대신 세는 단위로, 글을 잘게 나눈 조각입니다. 이 패널에는 이번 생성에 쓰인 값도 작은 태그로 함께 표시됩니다. **Temperature**(온도), **Max Output Tokens**(최대 출력 토큰), **Thinking**, **Reasoning**(추론), **Verbosity**(상세도), **Service Tier**(서비스 티어), **Assistant Prefill**(어시스턴트 프리필) 등입니다. **Top P**, **Top K**, **Min P** 같은 샘플링 값도 여기에 나타날 수 있습니다.

창의 나머지 부분이 프롬프트 본문이며, 접었다 펼 수 있는 섹션으로 나뉘어 있습니다. 각 섹션에는 라벨과 대략적인 토큰 추정치가 따로 붙습니다. 채팅 메시지는 **Chat History**(채팅 히스토리) 섹션 하나에 모여 있습니다. 저장된 요청을 그대로 보는 경우, 제공자가 여러 채팅 턴을 제공자 블록 하나로 합쳤을 수 있습니다. 각 블록을 펼치면 그 안에서 모델이 본 텍스트를 전부 확인할 수 있습니다. 섹션 헤더를 클릭하면 열리고 닫힙니다.

프롬프트 전체를 다른 곳으로 가져가려면 창 위쪽의 닫기 버튼 옆에 있는 복사 버튼을 클릭하세요. 열지 않은 섹션까지 포함해 모든 섹션과 채팅 메시지를 보낸 순서대로 일반 텍스트로 복사합니다. 각 메시지는 `[system]`, `[user]`, `[assistant]`처럼 역할을 나타내는 줄로 시작합니다. 저장된 요청을 그대로 보는 경우에는 그 저장된 요청을 보낸 그대로 복사합니다. 복사해도 모델에 아무것도 보내지 않으며 프롬프트도 바뀌지 않습니다.

## Peek Prompt 열기

뷰어를 여는 방법은 두 가지입니다.

첫 번째는 메시지 동작 막대를 쓰는 방법입니다. 다음 단계를 따르세요.

1. 채팅에서 가장 최근 AI 메시지 위에 마우스를 올리세요.
2. **Peek prompt**(프롬프트 미리보기) 동작을 찾으세요. 아이콘은 돋보기 모양입니다.
3. 클릭하세요. **Assembled Prompt** 창이 열립니다.

**Peek prompt** 동작은 채팅의 마지막 AI 메시지에만 나타납니다. 그보다 앞선 메시지에는 표시되지 않습니다.

두 번째는 입력란에 단축 문구를 치는 방법입니다. AI 답변이 아직 하나도 없어도 쓸 수 있어서 프롬프트를 먼저 미리 볼 수 있습니다. 다음 단계를 따르세요.

1. 메시지 입력란을 클릭하세요.
2. 다음 텍스트를 그대로 입력하세요.

```
{{prompt}}
```

3. Enter 키를 누르거나 Send를 클릭하세요.

그러면 Marinara는 메시지를 보내는 대신 입력란을 비우고 Peek Prompt 뷰어를 엽니다. `{{prompt_preview}}`와 `{{preview_prompt}}`도 똑같이 동작합니다.

## Stored guidance 읽기

지침 기반 생성을 쓰면 캐릭터 밖에서 내리는 지침으로 답변의 방향을 잡을 수 있습니다. 저장된 방향으로 만들어진 메시지에는 **Stored guidance**(저장된 지침) 동작이 따로 붙습니다. 아이콘은 작은 두루마리 모양입니다. 이 동작은 `/impersonate` 명령으로 만든 메시지에도 나타납니다.

**Stored guidance**를 클릭하면 그 메시지에 쓰인 방향을 보여 주는 창이 열립니다. 지침 기반 생성으로 만든 메시지라면 방향이 어디에서 왔는지도 함께 표시됩니다.

- **/guided**: `/guided` 슬래시 명령어를 쓴 경우입니다.
- **Guided regenerate**: 방향을 입력해서 메시지를 재생성한 경우입니다.
- **Game start**: Game Mode(게임 모드) 설정에서 넘어온 방향입니다.

**Copy /guided**(/guided 복사) 버튼은 **/guided**와 **Guided regenerate** 방향에만 나타납니다. 이 버튼은 방향을 `/guided` 명령 형태로 다시 복사해 줍니다. 나중에 그 명령을 붙여넣어 같은 방향으로 다시 유도할 수 있습니다. **Game start** 방향에는 이 버튼이 없습니다.

Impersonate로 만든 메시지라면 창에 방향 하나가 아니라 Impersonate에 쓰인 세부 정보가 나옵니다. 지침 기반 생성과 Impersonate의 전체 사용법은 아래 링크의 가이드를 참고하세요.

## Peek Prompt로 답변 문제 진단하기

예상과 다른 답변이 나왔을 때 원인을 파악하기에 가장 좋은 도구가 Peek Prompt입니다. 캐릭터가 무언가를 잊거나, 규칙을 무시하거나, 성격에 맞지 않게 행동할 때 써 보세요.

**Assembled Prompt** 창을 열고 다음을 확인하세요.

- 빠진 정보가 없는지 보세요. 로어북 항목, 기억, 페르소나 정보가 어느 섹션에도 없다면 모델은 그 내용을 본 적이 없습니다.
- 파라미터 태그를 확인하세요. **Temperature**가 지나치게 높으면 답변이 산만해지고, **Max Output Tokens** 값이 낮으면 답변이 중간에 잘립니다.
- **Chat History** 섹션을 펼치세요. 있어야 할 메시지가 모두 있는지, 순서는 맞는지 확인하세요.
- 답변이 끝난 뒤 실제 토큰 수를 읽어 보세요. 프롬프트가 너무 커지면 오래된 메시지가 모델의 한도 밖으로 밀려납니다.

모델이 실제로 무엇을 받았는지 알면 원인을 바로잡을 수 있습니다. 캐릭터 카드를 고치거나, 로어북 항목을 손보거나, 생성 파라미터 값을 바꾸면 됩니다.

## Decision 문 테스트

Peek Prompt에서 **Decision diagnostics**(Decision 진단)를 열어 현재 채팅의 프롬프트 문과 로어북 결정을 살펴보세요. 패널을 열거나 **Preview inputs**(입력 미리보기)를 선택하면 Decision 모델에 묻거나 로컬 모델을 시작하지 않고 요청 본문을 준비합니다. **Prepared request bodies**(준비된 요청 본문)를 펼치면 최근 메시지, 해석된 문, 선택지와 모델별 요청 형식을 볼 수 있습니다. 일부 로어북 문은 앞선 결정에 답이 나온 뒤에야 도달할 수 있습니다.

**Test decisions**(결정 테스트)를 선택하면 대상 질문을 선택한 Decision 모델에 보냅니다. 실제 결정 요청이므로 호스팅 모델은 요금을 청구할 수 있습니다. 채팅 답변을 생성하거나 에이전트를 실행하거나 게임 상태를 바꾸지 않으며, 테스트의 답과 타이머를 채팅에 저장하지 않습니다.

명시적인 테스트는 일반적인 답변 전 결정이 미뤄진 상태에서도 로컬 추론 모델을 기다릴 수 있습니다. 실제 답변에 대한 설정은 바뀌지 않으며, 입력 미리보기만으로는 여전히 모델 요청을 보내지 않습니다.

각 결과에는 가능한 경우 점수, 예/아니요 문에 사용한 임계값과 최종 답이 표시됩니다. 예/아니요 단어만 돌려주는 모델은 그렇게 표시하며, 그 답을 확률처럼 제시하지 않습니다. Choice 결과에는 선택된 옵션이 표시됩니다. 유지 중, 지연, 한도 초과, 사용 불가, 실패한 결정에는 별도 설명이 있어 답이 없는 상태를 낮은 점수와 혼동하지 않게 합니다.

테스트 뒤에는 아래 프롬프트가 테스트의 답을 사용합니다. **Show original prompt**(원본 프롬프트 표시)로 처음 열었던 내용으로 돌아가거나 **Show tested prompt**(테스트 프롬프트 표시)로 다시 전환하세요. **Requests sent and results**(보낸 요청과 결과)는 실제 결정 요청 본문과 반환된 결과를 보여 주며, 인증 헤더는 포함하지 않습니다.

이전 답변에서 Peek Prompt를 열었더라도 테스트는 현재 채팅과 현재 설정을 사용합니다. 원래 결정 요청을 재구성하지 않습니다. 프롬프트 문과 로어북 결정을 테스트하며, 에이전트 활성화나 답변 후 결정은 실행하지 않습니다. 일반 Peek Prompt는 **Test decisions**를 명시적으로 선택하기 전까지 수동적인 조회 상태를 유지합니다.

Advanced Memory에서 **Use Decision model**(Decision 모델 사용)이 켜져 있으면 패널에 **Advanced Memory activity**(Advanced Memory 활동)도 나타납니다. 저장된 보고서는 최근 기억 검색과 장면 종료 확인의 모델, 시간, 점수, 선택 결과 및 대체 처리 상태를 보여 줍니다. 프롬프트에 Decision 문이 없어도 나타날 수 있습니다. 현재 미리보기나 선택한 과거 답변의 재실행이 아니라 실제 과거 호출 기록입니다. 호환되는 스와이프는 이전 기억 검색 보고서를 다시 사용할 수 있습니다. 보고서마다 선택된 결과를 먼저 두어 최대 128개 결과를 저장하고, 생략한 결과 수를 집계합니다. 다음 적격 Decision 모델 호출 뒤에 새 보고서가 나타나며, 보고서를 보는 것만으로 모델 요청을 보내지 않습니다.
