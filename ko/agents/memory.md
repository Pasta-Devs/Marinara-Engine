# Memory Recall과 채팅 요약

이 가이드는 지난 메시지를 검색하는 **Memory Recall**(기억 회상), Roleplay 컨텍스트를 자동으로 관리하는 선택 기능 **Advanced Memory Recall**(고급 기억 회상), **Chat Summary**(채팅 요약), Conversation의 **Automatic Summarization**(자동 요약)을 설명합니다.

## 두 가지 기억 기능

AI 모델은 한 번에 정해진 분량의 글만 읽을 수 있습니다. 이 한계를 컨텍스트 창이라고 부릅니다. 채팅이 길어지면 오래된 메시지부터 컨텍스트 창 밖으로 밀려나고, AI는 그 내용을 잊어버립니다. Marinara Engine(이하 Marinara)에는 이 문제를 해결하는 기능이 두 가지 있습니다.

- **Memory Recall**은 방금 입력한 내용과 가장 관련이 깊은 부분을 지난 메시지에서 찾아내 프롬프트에 조용히 되돌려 놓습니다. 모든 채팅 모드에서 작동합니다.
- 요약은 오래된 메시지를 짧은 줄거리로 압축해서 프롬프트에 원본 메시지 대신 넣습니다. Roleplay 채팅은 **Chat Summary**를, Conversation 채팅은 **Automatic Summarization**을 사용합니다.

Game Mode 채팅에서는 **Memory Recall**만 쓸 수 있습니다. 두 요약 기능은 모두 없습니다.

두 기능은 함께 켜 두어도 됩니다. 하는 일이 서로 달라서 충돌하지 않습니다.

## Memory Recall 설정

**Memory Recall**은 채팅 앞부분에서 관련 있는 조각을 찾아 기억으로 프롬프트에 주입합니다. 이때 임베딩을 사용합니다. 임베딩은 메시지의 의미를 숫자로 나타낸 지문 같은 것입니다. Marinara는 새 메시지의 지문을 저장해 둔 지난 메시지의 지문과 비교한 뒤, 가장 가까운 것을 골라 넣습니다.

### Memory Recall 켜기

1. 채팅을 열고 채팅 안의 **Chat Settings**(채팅 설정) 버튼을 클릭하세요. 처음 위치는 오른쪽 위입니다.
2. **Memory Recall** 섹션을 찾으세요. 두뇌 모양 아이콘이 붙어 있습니다.
3. **Enable Memory Recall**(이전 기억 불러오기) 토글을 켜세요.

**Enable Memory Recall**은 채팅마다 따로 저장되는 설정입니다. 기본값은 모드에 따라 다릅니다.

- Conversation 채팅에서는 기본으로 켜져 있습니다.
- 장면이 활성화되어 있는 Roleplay 또는 Game 채팅에서도 기본으로 켜져 있습니다.
- 그 밖의 채팅에서는 기본으로 꺼져 있습니다.

토글을 끄면 불러온 기억이 프롬프트에 들어가지 않습니다. 이미 저장된 내용이 지워지지는 않습니다.

### 임베딩 소스

Memory Recall이 의미 지문을 만들려면 임베딩 소스가 필요합니다. 임베딩 소스는 채팅 설정이 아니라 연결에서 지정합니다. 연결은 AI 제공자에 접속하는 데 필요한 정보를 한데 저장해 둔 것입니다.

1. **Connections**(연결) 패널을 열고 연결을 편집하세요.
2. **Semantic Search (Embeddings)**(시맨틱 검색) 섹션을 찾으세요.
3. 모델 입력란에 임베딩 모델 이름을 입력하세요. 예를 들면 `text-embedding-3-small`입니다.
4. 주소를 따로 지정하려면 **Embedding Endpoint URL**(임베딩 엔드포인트 URL)을 입력하세요.
5. 다른 연결의 키와 주소를 빌려 쓰려면 **Embedding Connection**(임베딩 연결) 드롭다운을 사용하세요. **Same as this connection**과 **Local Model (sidecar)** 등을 고를 수 있습니다.

임베딩을 제공하지 않는 제공자도 있습니다. 그럴 때 Marinara는 임베딩 전용 연결을 고르라는 안내를 표시합니다. OpenAI 호환 연결, Google, Local Model 중에서 선택하면 됩니다.

임베딩 연결을 전혀 지정하지 않으면 Marinara는 내장 로컬 임베딩 모델로 대체합니다. 이 모델은 처음 한 번만 다운로드하고 이후에는 컴퓨터에서 직접 실행되며, API 키도 필요 없습니다. 내장 모델은 [Local Model 설정](../connections/local-model.md)에서 더 자세히 확인할 수 있습니다.

같은 **Semantic Search (Embeddings)** 설정이 로어북 시맨틱 검색에도 쓰입니다. 한 번만 설정해 두면 두 기능에 모두 적용됩니다.

### Memories for This Chat

채팅이 무엇을 기억하고 있는지 보려면 **Chat Settings**를 열고 **Memory Recall** 섹션에서 **Access memories for this chat**(이 채팅의 기억에 접근)을 클릭하세요. Advanced Memory가 켜져 있으면 Roleplay 설정 서랍 안에 뷰어가 표시되고, 그렇지 않으면 **Memories for This Chat**(이 채팅의 기억) 창이 열립니다.

이 창에는 저장된 기억 조각의 개수와 대략적인 토큰 추정치가 표시됩니다. 각 조각 카드에는 포함하는 날짜 범위, 메시지 개수, 상태, 만들어진 시각이 나옵니다. 상태는 다음 세 가지 중 하나입니다.

- **Vectorized**: 지문이 만들어져 검색할 준비가 끝났습니다.
- **Waiting for vector**: 지문을 아직 만드는 중입니다.
- **Embedding unavailable**: 지문을 만들 임베딩 소스가 없습니다.

도구 모음에는 기억 내보내기, 기억 가져오기, 기억 다시 만들기, 전체 삭제 아이콘이 있습니다. 조각마다 붙어 있는 휴지통 아이콘으로 그 조각만 지울 수도 있습니다.

- 조각의 휴지통 아이콘을 클릭하면 **Forget Memory**(기억 잊기) 창이 열립니다. **Forget**(잊기)을 눌러 확인하세요.
- 전체 삭제 휴지통 아이콘을 클릭하면 **Clear Memories**(기억 지우기) 창이 열립니다. **Clear**(지우기)를 눌러 확인하세요. 불러오기용 기억만 지워지고 채팅 메시지는 남습니다.
- 새로고침 아이콘은 현재 채팅 메시지를 바탕으로 모든 기억 조각을 다시 만듭니다. 임베딩 모델을 바꾼 뒤에 사용하세요.
- 내보내기는 `.marinara.json` 파일로 저장합니다. 가져오기는 `.json` 또는 `.marinara` 파일을 받아 기존 기억에 합칩니다.

### Memory Recall의 동작 방식

다음 내용을 기억해 두면 좋습니다.

- Marinara는 임베딩 소스만 있으면 **Enable Memory Recall**이 꺼져 있어도 백그라운드에서 기억 조각을 저장합니다. 토글은 저장된 기억을 주입할지만 결정합니다. 저장 자체를 멈추려면 임베딩 소스를 지우거나 기억을 이따금 비우세요.
- 새 메시지가 5개는 모여야 조각 하나가 만들어집니다. 그보다 적으면 다음 답변까지 기다립니다.
- 불러온 조각은 유사도 검사를 통과할 만큼 관련이 깊어야 합니다. 관련성이 약하면 건너뛰기 때문에, 기억이 있어도 아무것도 불러오지 않을 수 있습니다.
- 불러온 기억에 쓰는 프롬프트 분량은 아주 적습니다. 그래서 가장 관련 깊은 몇 개만 들어갑니다.
- 기억이 이미 쌓인 뒤에 임베딩 모델을 바꾸면 예전 조각은 더 이상 맞지 않습니다. 다시 만들기 아이콘으로 새로 만드세요.
- 채팅 메시지를 지우면 그 채팅의 기억 조각도 함께 지워집니다.

Marinara Lite라고 부르는 일부 컨테이너 빌드에서는 Memory Recall이 완전히 꺼져 있습니다. 이런 빌드에서는 **Memory Recall** 섹션 자체가 보이지 않습니다.

## Advanced Memory Recall(Roleplay)

**Chat Settings → Memory Recall**을 열고 **Advanced Memory Recall**를 켜세요. Roleplay 설정 마법사의 Agents 아래에서도 **Automatic context and memory handling**(자동 컨텍스트 및 기억 관리)를 켤 수 있습니다. 이 선택적 모드는 원문으로 유지하는 기록 범위, 연속성 요약, 관련된 과거 발췌를 함께 관리합니다. 데스크톱과 모바일 모두 마법사와 Chat Settings 서랍에서 설정과 준비 진행 상황을 확인할 수 있습니다. 보관함 뷰어는 Chat Settings 서랍 안에 표시됩니다.

### 설정

- **Maximum allowed context before compression (tokens)**를 채팅 모델이 지원하는 컨텍스트 범위 안에서 설정하세요. 송신 프롬프트가 이 크기에 도달하면 오래된 컨텍스트를 잘라내고, 채팅 기록은 그 지점부터 다시 늘어납니다. 잘라낸 내용은 요약되어 회상할 수 있는 기억에 추가됩니다. 이 상한은 지침, 메시지, 불러온 기억, 도구, 첨부 파일을 포함한 예상 송신 프롬프트에 적용되며 채팅과 기억 처리 요청 모두에 해당합니다. 응답 토큰과 안전 여유분은 별도입니다. 모델의 전체 컨텍스트 제한도 계속 적용되며, 정확한 토크나이저 수치나 과금 한도가 아닙니다.
- 그 상한 안에서 **Summary and recall budget (tokens)**(요약 및 회상 예산)을 선택하세요. 이 값은 컨텍스트 중 얼마를 기억에 쓸지 정하며, 최대 허용 컨텍스트의 10% 이상을 권장합니다. 활성 상시 요약의 목표는 이 값의 최대 **70%**입니다. 우선순위는 상시 요약, 선택한 장면 요약, 켜져 있을 때의 [캐릭터 회고](#character-recollections), 메시지 발췌 순입니다. 필요하면 전체 기억에 **2,000토큰을 추가**할 수 있지만 전체 컨텍스트 상한을 지켜야 합니다. 10k 설정이면 상시 요약 목표는 최대 7k, 전체 기억은 최대 12k이며 다른 값에도 같은 비율을 적용합니다. 현재 메시지는 상시 요약 몫에 포함되지 않으며 통합을 유발하지 않습니다.
- 기본 동작: **Helper model**(보조 모델)은 독립적인 장면 판단, 장면 요약과 연속성 압축을 담당합니다. 에이전트 연결을 우선하고 없으면 채팅 연결을 씁니다. 최초 과거 장면 탐지는 주 모델이나 보조 모델을 쓸 수 있지만 요약은 항상 보조 모델을 씁니다. 적용 모델은 준비 전에 표시됩니다.
- 모든 기억 요약 호출은 **Chat Summary → Maximum output size**를 사용하며 추론 공간을 위해 최소 **8,196 출력 토큰**을 확보합니다. 장면 요약과 상시 요약 통합 모두에 적용되고 더 큰 설정은 유지됩니다. 보조 연결의 일반 응답 한도로 대체하지 않습니다. 입력과 출력 예약은 모델 전체 컨텍스트에 들어가야 합니다.
- 각 장면 요약 요청에는 요약 지침, 해당 장면의 접근 가능한 메시지와 적용 가능한 범위별 수정, JSON 출력 형식이 들어갑니다. 너무 큰 장면은 저장 가능한 묶음으로 처리한 뒤 합칩니다. 장면 요약은 **2–3문단**을 요청합니다. 기본 프롬프트는 현재 상황이나 미해결 긴장 항목 없이 과거를 정리합니다. **Summaries**에서 선택한 사용자 프롬프트도 계속 적용됩니다. Advanced Memory는 Agents 전체 스위치와 독립적으로 작동하며 다운로드 에이전트가 필요하지 않습니다.
- **Maximum recalled scenes**(최대 회상 장면 수)는 기본 **3**이며 약한 일치를 제외하는 상한입니다. **0**은 선택적 장면 회상만 끄고 필요한 연속성은 유지합니다. 장면마다 요약과 그 뒤에 최대 하나의 발췌문을 제공합니다.
- **Moving context**(이동 컨텍스트)는 발췌문당 메시지 수이며 기본 **3–10**입니다. 발췌문은 회상된 장면의 메시지를 그대로 가져온 것으로, 그 장면의 요약 바로 뒤에 추가됩니다. 두 한도를 **0**으로 하면 요약만, 최소값만 **0**이면 선택적으로 발췌합니다. 관련성, 캐릭터 접근권과 공간에 따라 메시지가 없을 수도 있습니다. 발췌문을 늘리기 전에 회상된 모든 장면이 먼저 최소 발췌문을 받습니다. 그래도 발췌문이 없는 회상 장면이 있으면 회상 기록에 그 이유가 표시됩니다. 요약을 넣은 뒤 남은 공간이 없었거나, 그 장면의 메시지를 하나도 인용할 수 없는 경우입니다.

기존 Individual(개별) 그룹 채팅에서는 누락된 캐릭터 지식 범위를 한 번 확인하세요. 캐릭터의 첫 대사가 그 이전의 모든 내용을 알았다는 증거는 아닙니다. 참여 범위 제한을 건너뛰어도 되는 경우에만 실제 캐릭터를 **Narrator**(나레이터)로 선택하세요. 캐릭터별 숨김과 확인된 지식 범위는 계속 메모리를 제한합니다. 전역 **Hide from AI**(AI에서 숨기기)는 수동으로 설정하든 자동 요약이 설정하든 턴을 현재 대화 기록에서만 제외합니다. Advanced Memory는 여전히 해당 턴을 스캔하고 장면 참여자를 판단하며 요약한 뒤 허용된 회상을 위해 색인합니다. 시작 마커는 현재 대화 기록을 잘라냅니다. 범위는 나중에 수정할 수 있으며, 새로 추가한 캐릭터는 별도로 확인해야 합니다.

기존 채팅에서는 먼저 **Prepare existing history**(기존 기록 준비)를 클릭하세요. 복구한 기록이 수동 수정이 적용된 장면의 경계를 바꾸면, 참고용 텍스트를 남기도록 해당 메모리를 비활성화하거나 삭제한 뒤 기록을 다시 준비하세요. **Fix**(복구)는 그런 장면을 건너뛰고, 작업을 멈추는 대신 목록에 표시합니다([기억 문제 해결하기](#fixing-memory-problems) 참고). 같은 수정을 다시 저장해도 그 텍스트를 다른 원본 범위에 안전하게 배정할 수는 없습니다. 준비는 오래된 기록을 배치로 처리하고 Professor Mari의 쳇바퀴 옆에 현재 단계를 표시합니다. **Cancel**(취소)은 완료된 작업을 유지하고 **Resume**(재개)은 서랍을 닫거나 서버를 재시작하거나 앱을 업데이트한 뒤에도 이어갑니다. 모델 호출이 실패하면 기존 유효한 메모리를 보존하고 재시도할 오류를 표시합니다. 실패한 호출을 복구하려고 메모리를 초기화하지 마세요. 재개는 완료된 요약과 변경되지 않은 장면 탐지를 재사용합니다. 마지막 진행 중 장면은 열린 채 유지하다 닫히면 요약하며, 현재 메시지가 컨텍스트 상한을 넘으면 제한된 원문 발췌를 사용합니다.

**Access memories for this chat**에서 요약을 열고 아래의 **Delete summary**(요약 삭제)를 선택한 뒤 요약과 대상을 확인하세요. 이전 **Continuity**(연속성)와 **Ongoing scene**(진행 중 장면) 항목도 삭제할 수 있습니다. 일반 준비는 삭제한 장면 요약을 다시 만들지 않습니다. 원본 메시지는 유지합니다. 새 상시 요약은 **Chat Summaries**에 있으며 기존 편집, 활성화, 합치기와 삭제 기능을 씁니다. 보관함의 이전 연속성은 추가 상시 요약으로 사용하지 않습니다.

### 기억 문제 해결하기

채팅의 기억에 문제가 생기면 기억 설정을 열지 않아도 알 수 있습니다. **Chat Settings** 버튼의 한쪽 모서리에 강조 색상의 점이 깜박이지 않고 계속 표시되고, 문제가 있는 장면이 몇 개인지 알려 주는 알림이 나타납니다. 같은 문제는 한 번만 알리며, 점은 문제가 정리될 때까지 남아 있습니다. **Chat Settings → Memory Recall**에서는 같은 문제가 설정 위에 나열되고, **Access memories for this chat**에도 같은 점이 표시됩니다.

알림이나 그 목록에서 **Fix**를 누르면 문제가 표시된 장면을 한 번에 모두 복구합니다. **Helper model**과 평소의 진행 막대를 사용합니다. **Pause processing**(처리 일시 중지)으로 멈추고 **Resume processing**(처리 재개)으로 Fix를 이어 갈 수 있으며, 이미 끝난 작업은 유지됩니다. Fix는 다음 작업을 합니다.

- **Check who was there**(누가 있었는지 확인)로 표시된 장면에 누가 있었는지 보조 모델에게 다시 묻고, 분명한 답이 나오면 저장합니다. 보조 모델이 여전히 판단하지 못하면 아무도 새로 접근 권한을 얻지 않습니다. 장면에는 기존 캐릭터 중 보조 모델이 빼지 않은 캐릭터만 남으며, 직접 확인할 수 있도록 목록에 표시됩니다.
- 참가자 확인 기능이 생기기 전에 저장된 오래된 장면에 누가 있었는지 확인합니다. 자동 확인에 실패한 장면도 포함합니다.
- 메시지, 숨긴 메시지, 캐릭터 이름이나 바탕이 되는 요약이 바뀐 장면과 요약이 없는 끝난 장면의 요약을 새로 씁니다. 삭제한 요약은 삭제된 상태로 둡니다.
- 오류로 멈춘 기억 작업을 재개합니다.

Fix는 직접 편집한 요약을 절대 다시 쓰지 않습니다. 그런 요약이 메시지와 더 이상 맞지 않거나, 다시 표시되는 메시지가 빠져 있거나, 장면 경계가 바뀌었으면 그대로 두고 **need your review**(검토 필요) 아래에 표시한 뒤 다른 장면을 계속 처리합니다. 각 캐릭터의 지식 범위 확인이나 동작하는 판단 연결 선택처럼 Fix가 대신 바꿀 수 없는 설정은 직접 바꿀 때까지 목록에 남습니다.

Fix가 끝나면 **Fixed N scenes**(장면 N개 복구됨)와 **need your review**에 해당하는 장면을 장면 번호로 보여 줍니다. 번호를 선택하면 그 장면이 **Access memories for this chat**에서 열립니다. Chat Settings가 닫혀 있었다면 **Show**(보기)가 있는 알림으로 그곳에 갈 수 있습니다. Fix가 판단하지 못한 장면은 다음 Fix에서 다시 묻지 않으므로 캐릭터 접근 권한을 직접 저장하세요.

### 장면 다시 검사하기

장면이 끝나지 않아 새로 요약된 내용이 없을 때처럼 장면 변화를 놓쳤다면 **Chat Settings → Memory Recall**의 **Re-scan scenes**(장면 다시 검사)를 사용하세요. 검사할 첫 메시지 번호와 마지막 메시지 번호를 입력한 다음 **Re-scan**(다시 검사)을 누르세요. 처음에는 진행 중인 장면이 범위로 입력되어 있습니다. Advanced Memory는 **Use Decision model**이 켜져 있으면 Decision 모델로, 아니면 Helper model로 해당 메시지에서 장면 변화를 다시 찾고, 바뀐 장면을 요약합니다. 해당 메시지 밖의 장면은 경계와 요약을 그대로 유지하며, 응답마다 하는 평소 검사도 이전처럼 계속됩니다. 직접 편집한 요약이 바뀌게 되면 준비 과정과 마찬가지로 다시 검사를 멈추고 해당 장면을 알려 줍니다.

### 선택 사항인 Decision 모델

Advanced Memory에서 **Use Decision model**(판단 모델 사용)을 켠 다음 **Memory Decision connection**(기억용 판단 연결)에서 모델을 고르세요. **Local models**(로컬 모델) 아래에는 전역 **Decision model**(판정 모델)과 같은 로컬 모델이 나열됩니다. **Local Model**(로컬 모델)에서 실행하는 **Primary local model**(주 로컬 모델)이 그 예입니다. 아직 답할 수 없는 모델은 회색으로 표시되고 그 이유가 함께 나오며, 중지된 모델은 Advanced Memory가 요청할 때 시작됩니다. **Connections** 아래에는 저장해 둔 판단 연결이 나열됩니다. **Connections**에서 TypeSafe, OpenRouter 또는 호환되는 판단 소스로 판단 연결을 만드세요. [판단 모델](../connections/decision-models.md)을 참고하세요. 기본값은 꺼짐이며 Roleplay 채팅별로 저장됩니다. 이 선택은 전역 기본 판단 모델과 별개입니다.

선택한 모델은 기록 준비와 채팅 중 검사에서 장면 경계를 식별합니다. 새 응답 전에는 두 단계에 걸쳐 기억을 고릅니다. 먼저 일반 회상이 텍스트 검색과, 저장된 벡터가 있으면 임베딩으로 장면 요약을 최대 24개까지 후보로 추립니다. **Maximum recalled scenes**가 더 크면 그 값까지 추립니다. 모델은 이 후보 중에서 관련 장면을 고른 뒤, 고른 장면마다 텍스트 검색 결과가 가장 좋은 원본 메시지를 최대 12개까지 평가해 그 장면의 발췌를 고릅니다. 가장 좋은 선택이 발췌의 중심이 되고, 나머지 선택은 **Maximum messages per excerpt**(발췌당 최대 메시지 수)까지 발췌를 늘립니다. 장면의 메시지를 하나도 채택하지 않으면 텍스트 검색으로 발췌 중심을 정하고 회상 기록에 그렇게 표시합니다. 요약이 남긴 공간에 그 메시지 중 어느 하나도 단독으로 들어가지 않는 장면은 발췌를 받을 수 없으므로, 모델이 그 장면의 메시지를 평가하지 않습니다. 고른 장면 모두가 이에 해당하면 두 번째 요청을 보내지 않습니다. 새 메시지마다 이야기가 다른 장소나 시간으로 넘어가는지, 다른 곳에 있는 캐릭터들로 전환되는지, `***` 같은 장면 구분선이나 캐릭터 밖에서 쓴 시점 메모 뒤에 이어지는지 확인합니다. 이때 직전 메시지 3개와 각 메시지의 작성자를 함께 봅니다. 경계가 불확실하면 장면을 열린 상태로 둡니다. 모든 요약과 연속성 갱신은 **Helper model**이 계속 작성합니다. 장면 수, 발췌 길이, 캐릭터 접근 권한, 토큰 예산의 기존 제한을 유지합니다. 유효한 판단이라도 아무것도 선택하지 않을 수 있습니다.

호스팅 서비스에는 최근 대화와 평가 대상으로 추린 장면 요약이나 메시지가 전송되며 응답 하나에 여러 요청 요금이 발생할 수 있습니다. 후보를 보내기 전에 캐릭터 접근 권한을 확인하고 비공개 요약 부분의 조건을 적용합니다. 장면을 회상하는 캐릭터들이 채팅에서 본 원본 메시지만 보내며, 각 캐릭터는 여전히 요약 중 자신을 위한 부분만 받습니다. 요청은 연결의 컨텍스트 예산 안에서 제한된 묶음으로 나눕니다. Jev 채팅 라우터에 표시된 컨텍스트 크기가 판단 요청에도 적용된다고 가정하지 않습니다.

회상 단계마다 판단 제한 시간이 각각 10초입니다. 연결 누락, 불완전한 답변, 너무 큰 후보, 오류, 시간 초과 시 일반 회상을 사용합니다. 이때 장면은 후보 목록 자체의 순위로, 발췌는 텍스트 검색으로 고릅니다. 장면 판단을 사용할 수 없으면 기존 장면 검사를 사용합니다. 옵션이 켜져 있으면 준비 과정에서 새 임베딩 없이 텍스트를 색인합니다. 기존 벡터는 대체 검색에 계속 사용할 수 있습니다. 끈 후 판단 모드에서 준비한 기록의 임베딩이 필요하면 **Reindex**를 사용하세요.

프롬프트 검사는 읽기 전용으로 유지되며 판단 제공자를 호출하지 않고 일반 회상을 미리 보여 줍니다. **Peek Prompt → Decision diagnostics**(Peek Prompt → Decision 진단)의 **Advanced Memory activity**(Advanced Memory 활동)에는 최근 기억 검색과 장면 검사의 저장된 결과가 표시됩니다. 모델, 시간, 점수, 선택된 기억이나 장면 시작 지점, 대체 처리 상태, 회상된 장면에 발췌가 없는 이유를 볼 수 있습니다. 보고서는 이 업데이트 이후의 새 호출부터 기록되며 선택된 결과를 먼저 두어 최대 128개 결과를 보관합니다. 미리 보기에 대한 예측이 아니라 과거 활동입니다. 패널을 열거나 프롬프트 문을 테스트해도 기억 결정을 다시 실행하지 않습니다. Decision 모델의 장면 검사는 항상 트래커와 에이전트의 일괄 요청과 분리된 자체 요청을 사용합니다. 회상 기록에는 판단과 대체 처리 여부가 표시됩니다. 호환되는 응답 변형과 이어 쓰기는 저장된 선택을 재사용하며, 설정을 바꾸면 호환되지 않는 저장된 기억 스냅샷이 무효화됩니다.

<a id="deciding-who-sees-new-messages"></a>

### 새 메시지를 볼 대상 정하기

캐릭터가 한 명씩 차례로 답하는 Roleplay 그룹 채팅에서는 Advanced Memory가 새 메시지마다 어떤 캐릭터가 볼지 정할 수 있습니다. 그래서 장면을 떠난 캐릭터에게서 대사를 하나하나 숨기지 않아도 됩니다. Advanced Memory에서 **Decide who sees new messages**(새 메시지를 볼 대상 결정)를 켜세요. 기본값은 꺼짐이며, 캐릭터가 한 명씩 답하는 그룹 채팅에만 나타납니다. 병합된 그룹 채팅과 캐릭터가 하나인 채팅에서는 이 옵션을 제공하지 않습니다.

켜져 있으면 내 메시지든 캐릭터의 메시지든 새 메시지마다 그 장면에 없는 캐릭터에게서 숨깁니다. 결과는 메시지 자체의 버튼과 같은 캐릭터별 **Hide from AI**를 사용하므로, 눈 가림 표시로 누가 볼 수 없는지 확인할 수 있습니다. 내 메시지는 아무 캐릭터도 답하지 않더라도 보내는 즉시 판단합니다. 다음 캐릭터가 답하기 전에 앞선 메시지의 판단이 이미 끝나 있으므로, 그 캐릭터가 봐서는 안 되는 대사를 읽는 일은 없습니다.

- 여기에서 고른 **Narrator**와 **Roleplay Commands**(Roleplay 명령)에서 고른 **Narrator character**(내레이터 캐릭터)는 항상 모든 메시지를 봅니다. 메시지 작성자는 항상 자신의 메시지를 봅니다. 장면에 없는 귓속말 수신자는 메시지의 나머지 부분은 받지 못하지만 귓속말은 그대로 받습니다.
- **Use Decision model**이 켜져 있으면 Decision 모델에게 캐릭터마다 그 메시지를 보거나 들을 수 없는 것이 분명한지 묻습니다. 예를 들어 다른 곳에 있거나 자리를 떠난 경우입니다. 이야기에서 한 번도 장면에 나오지 않은 캐릭터는 다른 곳에 있는 것으로 봅니다. 그 자리에 있지만 귓속말 대상에서 빠진 캐릭터는 메시지의 나머지 부분을 그대로 봅니다. Decision 모델을 쓰지 않으면 **Helper model**이 판단합니다. 어느 쪽이든 모델이 확신할 때만 메시지를 숨기며, 확신하지 못하면 캐릭터는 그 메시지를 계속 봅니다. 응답 후 장면 검사를 할 차례이면 같은 요청이 누가 있는지도 함께 답하므로, 해당 메시지에는 추가 호출이 발생하지 않습니다.
- 모델은 현재 장면에서 지금까지 나온 메시지를 읽으며, 새 장면이 막 시작되었더라도 적어도 직전 메시지 몇 개는 항상 읽습니다. 현재 장면이 시작된 뒤 말한 캐릭터 목록도 받습니다. 이 목록은 참고용일 뿐입니다. 조용히 듣고 있는 캐릭터는 아무 말도 하지 않았어도 그 자리에 있는 것으로 봅니다.
- 자동 선택 전이든 후든 메시지의 **Hide from AI**를 직접 바꾸거나 그 메시지에 `/hide` 또는 `/unhide`를 사용하면 직접 고른 설정이 유지되며, Advanced Memory는 그 메시지를 다시 바꾸지 않습니다. 이미 누군가에게서 숨겨 둔 메시지는 그대로 둡니다.
- 메시지마다 한 번만 판단합니다. 모델이 실패하거나 제때 답하지 않으면 그 메시지는 아무에게서도 숨기지 않으며, 오류는 서버 로그에 표시됩니다.

Advanced Memory가 켜져 있으면 새 캐릭터 답변이 `***`, `---`, `* * *` 같은 구분선으로 장면이나 시점을 바꿀 수 있습니다. 이때 답변은 부분마다 하나씩, 같은 캐릭터가 보낸 별도의 메시지로 저장됩니다.

- 부분마다 볼 수 있는 대상이 따로 정해집니다. **Decide who sees new messages**, **Hide from AI**, 귓속말은 각 부분에 따로 적용됩니다.
- 답변을 쓴 캐릭터는 자신의 다른 메시지와 마찬가지로 모든 부분을 계속 봅니다. 그 캐릭터가 보면 안 되는 부분은 직접 숨기세요.
- 구분선은 그 뒤 부분의 맨 위에 남습니다. 코드 블록이나 `<details>` 패널 같은 HTML 블록 안에 있는 구분선은 구분선으로 보지 않습니다.
- 답변의 사고 내용은 첫 부분에 표시됩니다. **Exclude Past Reasoning**(과거 추론 제외)이 꺼져 있어도 이 내용은 모델에 다시 보내지 않습니다.
- 메시지 정보, 트래커, 에이전트 결과는 마지막 부분에 붙습니다.
- Prose Guardian을 비롯한 재작성 에이전트는 각 부분을 따로 재작성하며, 구분선은 맨 위에 그대로 남습니다. **Hold Message Until Rewrite**(리라이트까지 메시지 보류)를 켜 두면 각 부분이 자신의 재작성을 기다립니다. 한 부분의 재작성이 실패하면 그 부분은 원래 쓴 그대로 남고 나머지 부분은 여전히 재작성됩니다.
- 음성 자동 재생은 모든 부분을 순서대로 읽습니다.
- 부분을 스와이프하거나 재생성하면 그 메시지만 새 버전이 만들어집니다. 앞쪽 부분이라면 새 버전에는 첫 구분선 앞의 텍스트만 남습니다. 그 뒤의 장면은 이미 각자의 메시지가 있기 때문입니다.
- 이어 쓰기와 Impersonate는 답변을 나누지 않습니다.

### 캐릭터 회고

Advanced Memory에서 **Character recollections**(캐릭터 회고)를 켜면 각 캐릭터가 장면에 대한 자신만의 기억을 갖게 됩니다. 기본값은 꺼짐입니다.

- 장면이 끝날 때마다 그 장면에 있던 캐릭터는 각자 그 장면에 대한 짧은 기억을 하나씩 얻습니다. 약 50–100단어 분량으로, 캐릭터 자신의 말투로 1인칭으로 쓰며, 그 장면을 떠올릴 때 무슨 생각을 하는지와 무엇이 가장 기억에 남았는지를 담습니다. 무엇을 눈여겨볼지는 캐릭터 카드가 정하므로, 논리적인 캐릭터는 다른 사람의 감정을 신경 쓰는 캐릭터와는 다른 것을 기억합니다. **Narrator**와 내 페르소나, 다른 곳에 있던 캐릭터는 회고를 받지 않습니다.
- 모델은 각 캐릭터가 알 수 있었던 내용만 사용하라는 지시를 받습니다. 요청에는 캐릭터에게 숨긴 메시지가 모두 표시됩니다. 캐릭터별 숨김(**Decide who sees new messages** 포함)으로 숨긴 메시지와 그 캐릭터의 지식 범위가 시작되기 전의 메시지가 여기에 해당합니다. 일부 캐릭터만을 위해 쓴 요약 부분(`{{#if char == …}}`)은 그 캐릭터들만의 것으로 다룹니다. 전역 **Hide from AI**로 모두에게서 숨긴 메시지는 요약에서와 마찬가지로 장면의 일부로 남습니다. 캐릭터가 알 수 없었던 내용에서 네 단어를 연달아 그대로 옮긴 회고는 제외합니다. 다만 그 캐릭터가 그 표현을 채팅의 다른 곳이나 자신의 카드에서 읽었거나, 그 표현의 모든 단어를 여러 메시지에서 읽었다면 제외하지 않습니다. 다른 말로 바꿔 전한 사실은 이 방법으로 잡아내지 못하며, 지시로만 막을 수 있습니다.
- 회고는 그 캐릭터가 읽을 수 있는 내용이 회고를 쓸 때와 정확히 같을 때만 유효합니다. 나중에 장면의 메시지가 그 캐릭터에게서 숨겨지거나 그 캐릭터에게 보이게 되면, 생성된 회고는 다시 쓰고, 직접 편집한 회고는 확인하고 다시 저장할 때까지 프롬프트에서 제외합니다.
- 새 장면의 회고는 그 장면의 요약과 같은 요청에서 작성됩니다. 이때 요청에는 장면의 일부라도 읽을 수 있었던 모든 캐릭터의 캐릭터 카드 전체도 들어가므로, 요청이 추가로 생기지 않습니다. 카드를 넣으면 카드가 없을 때보다 장면을 더 많은 부분으로 나눠야 하는 경우에는 요약을 카드 없이 쓰고, 회고는 별도 요청으로 이어서 씁니다. 여러 카드 때문에 장면을 나눠야 할 때는 한 번에 한 캐릭터씩 씁니다. 카드가 그 장면에 쓸 수 있는 보조 모델의 공간을 절반 넘게 차지하는 캐릭터는 회고를 받지 않습니다. 여러 부분으로 나눠 요약하는 긴 장면도 결국 캐릭터마다 회고는 하나입니다.
- 회고만 쓰는 요청에는 그 장면을 다루는 **Chat Summaries**와, 장면 요약을 직접 편집했다면 그 요약도 함께 들어가므로 회고가 내 수정 내용을 따릅니다.
- 장면이 이미 요약된 채팅에서 이 설정을 켜면 그 장면들에 회고를 추가합니다. 장면마다 요청을 하나씩 보내며, 진행 상황은 **Writing character recollections**(캐릭터 회고 작성 중)로 표시됩니다. 직접 편집한 요약을 포함해 장면 요약은 바뀌지 않습니다. 이미 회고가 있는 장면은 건너뜁니다. 한 장면이 실패해도 나머지 장면은 회고를 받으며, **Resume**이 실패한 장면을 다시 시도합니다.
- 모델이 어떤 캐릭터에 대해 쓸 만한 내용을 쓰지 못하면 장면에는 그 캐릭터의 빈 회고가 남으며, 장면 요약이나 그 캐릭터가 읽을 수 있는 내용이 바뀔 때까지 다시 요청하지 않습니다. **Access memories for this chat**에서 직접 쓸 수 있습니다.
- 회고는 회상된 장면에만 표시되며, 장면 요약 바로 아래, 발췌 앞에 캐릭터마다 한 줄씩 `Kaito's personal recollections from this scene: *…*`처럼 들어갑니다. 캐릭터가 한 명씩 답하는 그룹 채팅에서는 각 캐릭터가 자신의 회고만 보며, 혼자 답하는 **Narrator**는 아무 회고도 보지 않습니다. 병합된 답변에서는 채팅에 있는 캐릭터 중 그 장면을 기억하는 모든 캐릭터의 회고가 이름과 함께 표시되며, 내레이터가 답변을 함께 쓸 때도 마찬가지입니다.
- 회고는 **Summary and recall budget**에 포함됩니다. 장면 요약이 먼저, 그다음 회고, 그다음 발췌 순입니다. 공간이 부족하면 발췌를 먼저 줄이고, 그다음 회고를 통째로 뺍니다. 회고를 중간에 자르지는 않습니다.
- 회고는 **Chat Summaries**에 복사되지 않으며, 어떤 장면을 회상할지 고르는 데에도 쓰이지 않습니다.
- 직접 편집했거나 다시 작성되어 장면 요약이 바뀌면, 그 장면의 생성된 회고는 오래된 것이 되어 프롬프트에서 제외됩니다. 응답이 끝날 때마다 Chat Summaries가 최신 상태가 되면 최대 3개 장면의 회고를 최신 장면부터 다시 씁니다. **Prepare**(준비), **Re-scan scenes**, **Resume**은 오래된 회고를 모두 다시 씁니다. 응답 후 요청이 실패한 장면은 **Prepare**나 **Resume**을 기다립니다.
- **Access memories for this chat**에서 장면을 열면 **Character recollections** 아래에서 각 캐릭터의 회고를 읽고 편집할 수 있습니다. 편집한 회고에는 **Manually edited**(수동 편집됨) 표시가 붙으며 다른 회고로 대체되지 않습니다.
- 설정을 끄면 저장된 회고는 유지하지만 프롬프트에서는 제외합니다. 회고 작성이 중간에 멈춘 채팅에서 설정을 다시 켜면 그 작업을 다시 시작합니다. 내보내기, 가져오기, 분기에도 회고가 포함됩니다.

### 채팅 중 동작

장면 감지는 Roleplay 주 응답을 저장한 뒤 실행됩니다. **Standalone scene check interval (messages)**의 기본값은 **5**입니다. 새 메시지가 그만큼 쌓이면 검사 모델에는 마지막 검사 이후의 모든 메시지(간격의 두 배까지), 비교를 위해 마지막 검사가 끝난 지점의 메시지, 장면 지침과 출력 형식을 보냅니다. 각 장면이 끝나는 정확한 메시지 번호를 지정하며, 비교용으로 받은 그 이전 메시지가 종료 지점이 될 수도 있습니다. 계속되는 장면이면 종료 지점을 반환하지 않습니다. 페르소나와 캐릭터 메시지를 모두 셉니다. 주기는 추적 에이전트 일정과 독립적입니다. 판단 모드가 꺼져 있을 때는 소스 가시성과 예산이 허용하면 생성 후 추적 호출을 공유하고 아니면 보조 모델을 별도로 호출합니다. 새 범위는 이전 종료 다음부터 새로 지정한 종료 메시지까지입니다. 종료를 감지한 경우에만 완료 장면의 요약과 메시지 인덱스를 백그라운드에서 준비하며, 최신 응답에서 끝나도 적용됩니다. 불확실한 전환은 장면을 열린 상태로 둡니다. **Chat Settings → Agent activity**(채팅 설정 → 에이전트 활동)는 일반 에이전트가 꺼져 있어도 **Advanced Recall**로 진행률, 오류, 복구를 표시합니다. 기억 작업 중에만 진행률을 조회하며 준비된 아카이브는 유휴 상태에서 폴링하지 않습니다. 판단 모드를 켜면 선택한 판단 연결이 이 검사를 수행합니다.

판단 모드가 꺼져 있을 때: 회상은 준비된 메모리를 읽습니다. 선택적 질의 임베딩에는 짧은 시간 제한이 있으며 사용할 수 없으면 텍스트 검색으로 전환합니다. 텍스트 검색은 최신 사용자 메시지의 특징적인 단어에 더 큰 가중치를 주므로 짧은 단서로도 긴 장면 요약을 찾을 수 있습니다. 반려동물 이름처럼 메시지에 언급된 이름이 가장 큰 가중치를 받습니다. 응답하는 캐릭터와 내 페르소나의 이름, 대부분의 기억에 나오는 이름은 여기에 해당하지 않습니다. 발췌 출력을 꺼도 색인된 원본 메시지로 장면을 찾을 수 있습니다. 어느 쪽도 모델 호출을 추가하지 않습니다. Roleplay 주 생성에만 적용됩니다. 에이전트 호출, 수동 재실행과 보조 시험 생성은 회상을 시작하지 않고 반환된 요약이나 발췌문도 받지 않습니다. 주 프롬프트 검사는 읽기 전용입니다.

재생성한 스와이프는 해당 응답의 가장 이른 호환 저장 메모리를 재사용합니다. 연속성, 장면 요약과 정확한 발췌문을 포함합니다. 변경 없는 스와이프는 검색이나 요약 보조 모델을 다시 호출하지 않습니다. 이어 쓰기도 시작 시점의 메모리를 유지합니다. 저장 스냅샷이 없는 이전 응답은 다음 생성에 저장하고 이후 재사용하므로 초기화가 필요 없습니다. 백그라운드 요약 추가와 통합은 호환 스냅샷을 유지합니다. 사용자가 기록, 접근 설정, 요약이나 메모리를 바꾸면 호환되지 않는 스냅샷은 무효화됩니다. 현재 컨텍스트 한도는 항상 적용됩니다. 그 응답 이후 해당 캐릭터가 회상할 수 있는 이전 장면이 저장되거나 편집되거나 켜지거나 꺼졌다면 스와이프에서도 회상을 다시 실행합니다. 스와이프한 응답의 채팅 기록에 아직 들어 있는 장면은 아직 회상할 수 없으므로, 그 장면을 저장해도 회상을 다시 실행하지 않습니다.

주 생성은 저장된 기억을 즉시 읽습니다. 보조 모델이 백그라운드에서 작동해도 연속성 생성을 시작하거나 기다리지 않습니다. 송신 프롬프트가 상한에 도달하면 **모든 캐릭터**의 현재 창을 최신 장면 시작으로 재설정하고 다시 상한에 도달할 때까지 늘립니다. 함수 호출과 굴림의 후속 생성은 상한 계산에 들어가지 않으며 재설정도 일으키지 않습니다. 자동 절단은 기존 **Mark as new start**에서 **All**이 선택된 상태로 표시됩니다. All을 해제하면 취소됩니다. 개인별 시작 플래그도 계속 적용됩니다. 미완료 장면이나 너무 큰 상시 요약이 들어가지 않으면 명확히 표시한 소스 발췌를 사용하면서 최신 메시지를 유지합니다. 이 임시 조정은 별도의 영구 플래그를 만들지 않습니다. 저장된 요약과 원본 메시지는 덮어쓰지 않습니다.

주 응답 후 Advanced Memory는 아직 어떤 요약에도 포함되지 않은 아카이브 메시지에 대해 **Chat Summaries**를 추가하며, 가능하면 완료된 장면 요약을 재사용합니다. 비활성 항목도 포함된 것으로 셉니다. 캐릭터가 한 명씩 차례로 답하는 그룹 채팅에서는 장면 요약을 읽은 모든 캐릭터가 그 장면에 대한 요약 하나를 공유합니다.

한 캐릭터가 읽는 활성 요약이 **Summary and recall budget**의 70%를 넘으면 **Updating continuity**가 응답 후 선택한 보조 모델과 **Chat Summary → Maximum output size**를 사용해 그 요약들을 통합하고 줄입니다. 응답 자체는 이 작업을 기다리지 않습니다. 각 캐릭터의 몫은 따로 계산하며, 병합된 그룹 채팅에서는 공유 프롬프트에 담기는 양이 그 몫입니다. 누군가의 현재 기록에 있는 메시지를 아직 포함하는 요약은 그 메시지가 현재 기록에서 빠질 때까지 기다립니다. 추가 2,000토큰은 전체 기억용이지 이 몫에 속하지 않습니다.

서로 다른 캐릭터가 읽는 요약은 하나로 통합되며, 직접 작성하거나 편집한 요약도 마찬가지입니다. 비공개 부분은 `{{#if char == "Name"}}…{{/if}}` 구역에 그대로 남아 그 내용을 알던 캐릭터에게만 정확히 적용됩니다. 보조 모델의 결과 때문에 어떤 부분을 읽을 수 있는 캐릭터가 달라지면 그 결과는 저장하지 않고 더 작은 그룹으로 다시 시도합니다. 채팅을 떠난 캐릭터를 위한 부분은 조건을 유지하므로, 그 캐릭터가 돌아오면 여전히 그 캐릭터의 것입니다. `{{user}}` 이외의 매크로를 쓰는 요약, 또는 그런 부분이 있어 이제 내레이터만 읽는 요약은 그대로 둡니다. 이런 요약만으로 한 캐릭터의 몫이 차면 직접 줄이거나 예산을 늘리세요. 대체된 항목은 직접 작성한 항목을 포함해 비활성화되므로 다시 켤 수 있습니다. 실패하거나 끝나지 않은 출력은 저장하지 않으며, **Resume processing**이 다시 시도합니다. 장면 요약은 기억 보관함에 남습니다.

캐릭터의 프롬프트에 표시되는 요약의 메시지 범위와 날짜는 그 캐릭터가 볼 수 있는 메시지만을 기준으로 합니다. Advanced Memory의 **Narrator**는 혼자 답할 때 모든 요약의 모든 부분을 한 번씩 읽습니다. 변수에도 의존하는 부분, 또는 `{{char}}`로 둘 이상의 캐릭터를 가리키는 부분은 여전히 조건을 따릅니다.

아카이브는 관련 장면 요약과 정확한 대화를 원래 메시지 번호 및 화자와 함께 불러옵니다. 하나의 **Recalled Scenes** 안에 각 요약과 사용 가능한 발췌를 바로 이어 놓으며 발췌마다 범위 제목 하나를 씁니다. 발췌 없는 장면도 같은 부분에 남습니다. 현재 기록 범위와 마지막 사용자 메시지 번호도 표시합니다. 장면의 모든 소스가 전송하는 현재 기록 밖에 있을 때만 장면을 불러오며, 발췌에서도 현재 메시지를 제외합니다. 범위가 있는 **Chat Summaries**도 포함 메시지가 하나라도 현재 컨텍스트에 남으면 생략합니다. 저장 및 활성 상태는 유지하고 전체 범위가 창 밖으로 나가면 다시 사용합니다. 유효한 상시 요약은 선택적 회상보다 우선하며 캐릭터 조건을 유지합니다. 모든 선택 장면 요약의 공간을 확보한 뒤 발췌를 추가합니다. 캐릭터 접근과 과거 소스 제한도 유지합니다. 일러스트 첨부와 이미지 설명은 회상 메시지 및 새 요약 입력에서 제외하며 읽을 수 있는 텍스트 첨부는 유지합니다. 페르소나와 캐릭터 메시지가 모두 대상입니다. 과거 재생성은 관리 창 이전이더라도 대상 응답 이전 소스만 사용합니다. 소스 편집, 스와이프, 숨김, 삭제는 관련 파생 기억을 사용 전에 다시 검사하게 합니다.

같은 서랍에서 **Access memories for this chat**을 열면 시간순으로 번호가 붙은 장면 요약을 검색하고, 이야기 속 시기와 접근 가능한 캐릭터를 확인하고, **Summary text**(요약 본문)를 편집할 수 있습니다. **Inspect source messages**(원본 메시지 확인)에서는 원본 메시지 전체를 읽을 수 있습니다. 내부에서 사용하는 원문 발췌는 별도의 장면 요약 항목으로 표시하지 않습니다. 불러온 컨텍스트에는 출처에 근거한 이야기 속 시기가 함께 표시되며, 알 수 없는 날짜는 그대로 미상으로 둡니다. 회상 레코드를 비활성화하거나 다시 색인하거나 내보내고 가져올 수 있습니다. **Delete all memories**(모든 기억 삭제)를 확인하면 원본 채팅과 설정을 유지하면서 기억 준비를 다시 시작할 수 있습니다. 원래 수동 요약을 수정한 내용은 유지되며, 그 요약에 의존하는 연속성 정보는 무효화됩니다. 장면을 회상에서 제외하려면 해당 메모리 레코드를 비활성화하세요. 캐릭터별 원본 숨김은 계속 접근 대상을 제어하며, 전역 숨김은 아카이브에서 제거하지 않습니다.

장면 요약마다 참여한 캐릭터도 기록합니다. **Kaito Nakamura**를 "Kaito"라고 적은 경우처럼 참가자 이름이 캐릭터 카드와 달라도, 정확히 한 캐릭터에만 맞고 내 페르소나의 이름일 수 없으면 참가자로 인정합니다. 두 캐릭터가 함께 쓰거나 캐릭터와 내 페르소나가 함께 쓰는 이름, "Kaito's sister" 같은 설명, "(mentioned)"처럼 주석이 붙은 이름은 어떤 캐릭터에게도 접근 권한을 주지 않습니다. 내 페르소나의 이름은 오류가 아니며 어떤 캐릭터에게도 접근 권한을 주지 않습니다. 보조 모델이 누가 참여했는지 말하지 않으면 장면은 모든 캐릭터에게 배정됩니다. 캐릭터가 하나인 채팅이면 그 캐릭터, 그룹 채팅이면 모든 캐릭터입니다. 그룹 채팅에서는 Advanced Memory가 이를 기억 문제로 간주하고 **Access memories**에서 장면에 **Check who was there** 표시를 붙입니다. 그러면 **Edit character access**(캐릭터 접근 권한 편집)로 그 자리에 없던 캐릭터를 빼거나, **Fix**가 보조 모델에게 다시 묻게 할 수 있습니다. 어느 캐릭터에도 맞지 않는 이름은 접근 권한을 주지 않으며 같은 방식으로 표시되므로 장면의 참가자를 지정할 수 있습니다. 보조 모델이 나만 있었다고 분명히 밝힌 장면은 내레이터 전용으로 남습니다. 참가자 확인 기능이 생기기 전에 저장된 장면 요약은 확인할 때까지 내레이터 전용으로 남습니다. **Fix**와 **Prepare existing history**는 이 요약을 모두 확인하고, 장면을 끝내는 응답도 나올 때마다 최대 3개씩 확인합니다. 자동 확인에 실패한 장면은 **Fix**나 **Prepare existing history**를 기다립니다.

장면의 일부에 참여한 캐릭터는 일부 메시지가 숨겨져 있어도 다른 참가자와 그 기억에 대한 접근을 공유할 수 있습니다. 접근 가능한 원본 메시지가 하나도 없는 장면은 계속 사용할 수 없습니다. 새 요약 지침은 메시지의 가시성을 표시하고, 공유된 사건은 일반 문장으로 쓰며, `{{#if character == "Name"}}…{{/if}}`는 비공개 부분에만 사용합니다. 자리에 없는 캐릭터를 언급해도 참가자가 되지는 않습니다. 원본의 가시성이나 요약을 작성할 때 대상으로 삼은 캐릭터의 이름이 바뀌면 장면을 다시 준비하거나(**Fix**는 이런 장면을 모두 다시 준비합니다) 비공개 조건을 검토하고 수정한 텍스트를 저장할 때까지 부분 접근만 가능한 독자에게 기존 요약을 제공하지 않습니다. 나중에 채팅에 참여한 캐릭터는 그 캐릭터에게 장면의 일부만 보이는 경우가 아니면 변경으로 보지 않습니다. 이전 버전에서 저장한 요약은 어떤 캐릭터를 대상으로 작성했는지 기록하지 않으므로, 캐릭터가 참여한 뒤 **Fix**를 한 번 실행해야 합니다. 가시성 정보가 저장되지 않은 오래된 요약도 부분 접근을 허용하기 전에 같은 검토가 필요합니다. 대상 캐릭터만 바꾸는 것은 텍스트를 확인한 것으로 간주하지 않습니다. 모든 원본 메시지에 접근할 수 있는 독자는 계속 기억을 불러올 수 있고, 직접 수정한 텍스트는 알리지 않고 다시 쓰지 않습니다. 이 검사는 회상 중 모델을 호출하지 않습니다. 장면의 날짜와 기간은 일부 원본 메시지가 숨겨져 있어도 지정된 모든 참가자가 공유하는 메타데이터입니다. 원문 발췌에는 캐릭터에게 숨긴 메시지나 귓속말이 절대 포함되지 않습니다. 일부 캐릭터만을 위한 부분이 있는 요약도 발췌를 받습니다. 그 발췌는 해당 캐릭터가 채팅에서 본 메시지만 인용하므로, 이미 본 것 외에는 아무것도 드러내지 않습니다. 어떤 메시지를 캐릭터의 기억에서 빼려면 그 캐릭터에게서 메시지를 숨기세요. 상시 Chat Summaries에는 AI에게 숨긴 메시지도 계속 포함됩니다. 캐릭터 조건으로 비공개 정보에 대한 접근을 제어하며 해당 메시지를 요약 범위에서 제외하지 않습니다.

병합된 그룹 채팅에서는 답변 하나가 모든 캐릭터를 대신해 말할 수 있으므로, 채팅에 있는 캐릭터 중 적어도 한 명이 기억하는 내용을 회상에 포함합니다. 채팅의 모든 캐릭터가 알지는 못하는 장면이나 요약의 비공개 부분에는 "known only to Kaito"처럼 누가 아는지 표시합니다. 도중에 캐릭터를 추가해도 더 이상 다른 캐릭터에게서 이전 기억을 숨기지 않습니다. 한 캐릭터에게서 숨긴 메시지는 여전히 공유되는 현재 기록에서 빠지지만, 그 메시지를 볼 수 있었던 캐릭터는 그 기억을 유지하며, 기억에는 그 캐릭터의 것이라는 표시가 붙습니다. 회상된 장면의 발췌는 그 장면을 기억하는 모든 캐릭터가 본 메시지만 인용합니다. 내레이터 전용 장면처럼 채팅에 있는 어느 캐릭터도 기억하지 못하는 내용은 포함하지 않습니다. 내레이터가 다른 캐릭터들과 병합된 답변을 함께 쓸 때도 요약은 같은 방식으로 표시되며, 내레이터는 혼자 답할 때만 모든 부분을 읽습니다. 캐릭터가 한 명씩 답하는 그룹 채팅에서는 여전히 각 캐릭터가 자신의 기억만 회상합니다.

Advanced 모드가 켜져 있는 동안은 이 모드가 검색을 담당하므로 Standard Recall 스위치가 같은 내용을 두 번 넣지 않습니다. 해당 채팅의 일반적인 Roleplay 자동 요약 일정도 대신합니다. Advanced Memory를 끄면 기존 설정으로 돌아갑니다. 기존 로어북과 다운로드하는 에이전트에는 각각의 범위 규칙이 적용됩니다. Advanced Memory가 임의의 사용자 작성 컨텍스트나 외부 컨텍스트를 비공개로 바꾸지는 못합니다.

### 프리셋 배치

프리셋 제작자는 기존 섹션 순서, 이름, 역할, 그룹 설정으로 다음 일반 콘텐츠 마커를 배치할 수 있습니다.

| 마커 | 콘텐츠 |
| --- | --- |
| `chat_summary` | Chat Summaries의 사용 가능한 상시 항목. |
| `current_scene_summary` | 진행 중 장면의 오래된 부분에서 가져온 제한된 원문 발췌. |
| `recalled_scenes` | 선택한 모든 장면 요약과 각 요약 바로 뒤에 오는 사용 가능한 과거 발췌문. |

프리셋의 회상 마커 선택에는 **Recalled Scenes**만 있습니다. 기존 `recalled_messages`는 호환 별칭으로 남고 Recalled Scenes로 표시됩니다. 활성 `recalled_scenes`가 우선하며 두 개의 별도 섹션을 만들지 않습니다.

각 구성 요소는 프리셋의 **XML**, **Markdown**, **None** 형식을 따르고 목적을 짧게 설명합니다. 빈 구성 요소는 아무것도 출력하지 않습니다. 처음 활성화된 마커가 위치를 정하고, 활성 마커가 없으면 기록 앞에 한 번만 추가되어 기존 프리셋도 작동합니다. 발췌는 컨텍스트이며 새 현재 메시지나 명령이 아닙니다. Advanced Memory가 꺼져 있으면 고급 장면 마커는 비어 있습니다.

프롬프트 미리보기는 모델이나 임베딩 호출 없이 준비된 메모리를 사용합니다. 패널에서 아카이브를 초기 준비하거나 실패한 백그라운드 작업을 재개하세요. 메모리 내역은 추정 컨텍스트, 경계와 출처를 표시합니다. 아무것도 회상하지 않았으면 회상할 이전 장면이 없었는지, 요청에 남은 공간이 없었는지, 관련된 내용이 없었는지 알려 줍니다. 최종 검사기는 실제 전송 내용을 보여 줍니다.

### 한계와 복구

회상은 선택적이며 요약은 뉘앙스를 놓칠 수 있습니다. 중요한 수정은 원본 기록이나 요약 편집기에 남기세요. 기록하지 않은 세부 정보는 복원할 수 없습니다. 임베딩이 실패해도 제한된 어휘 검색과 유효한 연속성은 사용 가능하며, 아카이브 전체를 삽입하지 않습니다. 필수 지침이나 첨부가 프롬프트 상한에 들어가지 않으면 줄이거나 상한을 늘리세요. 응답 예약이 모델 전체 컨텍스트에 들어가지 않으면 출력 크기를 줄이거나 더 큰 컨텍스트 모델을 선택하세요. Advanced Memory는 지침을 몰래 지우지 않고 중단합니다.

## Chat Summary(Roleplay)

**Chat Summary**는 오래된 메시지를 요약 항목이라고 부르는 짧은 줄거리로 압축합니다. 각 항목은 AI가 쓸 수도 있고 직접 쓸 수도 있으며, 항목마다 따로 켜고 끌 수 있습니다. 이 기능은 Roleplay 채팅에만 있습니다. 한 항목의 전환을 저장해도 다른 항목을 사용할 수 있으며 Activate All과 Deactivate All은 선택을 함께 저장합니다.

**Chat Settings**를 열고 **Lorebooks** 아래의 **Chat Summary** 섹션을 펼치세요. 컴퓨터에서는 별도 창으로 꺼낼 수 있습니다([채팅 설정 개요](../chats/chat-settings.md#popping-a-section-out-into-its-own-window) 참고).

### 요약 항목 만들기

1. **Summary Scope**(요약 범위)에서 최근 메시지를 요약하려면 **Last**를, 특정 메시지 구간을 고르려면 **Range**를 선택하세요.
2. 그 범위로 AI에게 항목을 쓰게 하려면 **Generate**(생성)를 클릭하세요.
3. 직접 쓰려면 **Write**(작성)를 클릭해 빈 항목을 만들고 줄거리를 입력하세요.

목록의 각 항목에는 제목, 출처 범위 또는 메시지 개수, 예상 토큰 크기가 표시됩니다. 항목을 활성화하거나 비활성화할 수 있고, 펼쳐 볼 수 있으며, **Edit**(편집)로 고치거나 **Delete**(삭제)로 지울 수 있습니다. 일괄 처리 버튼으로 비활성 항목을 **Show Inactive**(비활성 표시) 또는 **Hide Inactive**(비활성 숨기기) 할 수 있고, 한 번에 **Activate All**(전체 활성화) 또는 **Deactivate All**(전체 비활성화) 할 수도 있습니다.

항목에 체크해 선택하세요. 컴퓨터에서는 Shift를 누른 채 다른 항목을 클릭하면 그 사이에 보이는 항목을 모두 선택할 수 있습니다. 그런 다음 **Enable selected**(선택한 항목 활성화)나 **Disable selected**(선택한 항목 비활성화)를 사용하면 선택한 항목만 바뀝니다.

병합된 그룹 채팅에서는 답변 하나가 모든 캐릭터를 대신해 말할 수 있습니다. `{{#if char == "Kaito"}}…{{/if}}`처럼 특정 캐릭터를 위해 쓴 항목의 일부는 채팅에 있는 캐릭터 중 그 부분이 적용되는 모든 캐릭터에게 유지되며, "known only to Kaito"처럼 누가 아는지 표시됩니다. Advanced Memory의 **Narrator**만 받는 부분은 포함하지 않습니다. 캐릭터가 한 명씩 답하는 그룹 채팅과 캐릭터가 하나인 채팅에서는 각 캐릭터가 이전과 같이 항목을 읽으며, Advanced Memory의 **Narrator**는 어느 캐릭터를 지정한 부분이든 모든 부분을 읽습니다.

### Automatic Summaries

**Automatic Summaries** 패널은 채팅을 이어 가는 동안 요약을 계속 최신 상태로 유지합니다. Roleplay 채팅에만 나타납니다.

- **Automatic Summaries** 패널 안의 **Enabled**(활성화) 토글을 켜세요.
- 실행 주기는 **Every** 입력란에서 사용자 메시지 개수 단위로 설정합니다. 기본값은 5이고 1에서 200까지 지정할 수 있습니다.
- 요약이 한 번도 없던 예전 채팅을 따라잡으려면 **Backfill Summary**(요약 백필)를 클릭하세요. 채팅을 여러 묶음으로 나눠 처리하며, 진행하는 동안 진행 막대가 나타납니다. 도중에 멈추려면 **Stop**(중지)을 클릭하세요.

### Summary Prompt 템플릿

**Summary Prompt**(요약 프롬프트) 패널에서는 AI가 요약을 쓸 때 따르는 지시를 관리합니다. 현재 프롬프트를 고치려면 **Edit**를 클릭하세요. 템플릿 관리자를 열려면 **Templates**(템플릿)를 클릭하세요. 관리자에서 **New template**(새 템플릿)을 누르면 이름을 붙여 프롬프트를 저장할 수 있습니다. 저장한 템플릿마다 **Duplicate**(복제), **Edit**, **Delete** 컨트롤이 있습니다.

저장한 템플릿은 앱 전체에 적용되는 설정입니다. 한 Roleplay 채팅에서 템플릿을 고치거나 선택하면 모든 Roleplay 채팅의 요약 프롬프트가 바뀝니다.

### Summary Connection과 출력 크기

**Summary Connection**(요약 연결) 패널에서는 요약을 작성할 연결을 고릅니다. 기본값은 **Agent default (falls back to chat connection)**입니다. 기본 에이전트 연결을 먼저 쓰고, 그다음으로 채팅 자체의 연결을 쓴다는 뜻입니다.

**Maximum output size**(최대 출력 크기) 입력란은 생성된 요약의 최대 길이를 정합니다. 기본값은 4096 토큰이고 1에서 32768까지 지정할 수 있습니다.

### 표시 옵션

**Chat Summary**의 **Display**(표시) 컨트롤은 요약된 메시지를 화면에 어떻게 보여 줄지 결정합니다.

- **Hide summarised messages**(요약된 메시지 숨기기): 요약이 포함하는 원본 메시지를 숨깁니다. 기본값은 꺼짐입니다.
- **Recent message tail**(유지할 최근 메시지 수): 숨기기가 켜져 있어도 최신 메시지를 이 개수만큼은 그대로 보여 줍니다. 기본값은 10이고 0 이상의 정수를 넣을 수 있습니다. 0으로 두면 요약된 묶음 전체가 숨겨집니다. 값이 클수록 프롬프트가 커지고 모델 비용도 늘어납니다.
- **Collapse hidden messages**(숨겨진 메시지 접기): 숨겨진 메시지를 채팅 기록에서 어떤 모습으로 표시할지 정합니다.

채팅에 에이전트 쓰기 승인이 필요하도록 설정되어 있으면(**Agents**의 별도 설정입니다) AI가 만든 요약은 검토를 거친 뒤에야 적용됩니다.

## Automatic Summarization(Conversation)

Conversation 채팅은 **Automatic Summarization**이라는 다른 기능을 사용합니다. 하루가 끝날 때마다 그날의 요약을 만들고, 한 주가 끝나면 그 주의 일별 요약을 묶어 주간 요약을 만듭니다. 그리고 프롬프트에는 주간 요약, 이번 주의 일별 요약, 오늘 메시지만 담습니다. 덕분에 요청 하나하나가 작게 유지됩니다.

이 기능은 스스로 작동하며, Conversation 채팅에서는 끌 수 없습니다.

### 편집기 열기

1. Conversation 채팅을 열고 **Chat Settings**를 클릭하세요.
2. **Automatic Summarization** 섹션을 찾으세요. 달력 모양 아이콘이 붙어 있습니다.
3. **Edit Summaries**(요약 편집)를 클릭해 **Automatic Summarization** 창을 여세요.

이 창에는 주간 항목이 먼저 나오고, 아직 주간으로 묶이지 않은 날짜가 그 뒤에 나옵니다. 항목을 펼치면 **Summary** 본문과 **Key Details**(주요 내용) 목록을 고칠 수 있고, 목록에 줄을 추가하거나 삭제할 수 있습니다.

### Day Rollover Hour와 Recent Message Tail

**Automatic Summarization** 섹션의 설정 2가지가 하루를 나누는 기준을 정합니다.

- **Day Rollover Hour**(하루 시작 시간 설정): 요약에서 새 하루가 시작되는 시각입니다. 기본값은 4 AM이고, 12 AM(자정)부터 11 AM까지 고를 수 있습니다. 이 시각 이전에 보낸 메시지는 전날에 포함됩니다. 채팅을 하지 않는 시간대로 정해야 늦은 밤 세션이 둘로 잘리지 않습니다.
- **Recent Message Tail**: 요약이 끝난 뒤에도 오늘 메시지 중 몇 개를 원문 그대로 남길지 정합니다. 기본값은 10이고 0 이상의 정수를 넣을 수 있습니다. 값이 클수록 프롬프트가 커지고 모델 비용도 늘어납니다.

요약이 이미 쌓인 뒤에 **Day Rollover Hour**를 바꾸면 Marinara가 예전 요약은 이전 설정을 기준으로 만들어졌다고 알려 줍니다.

### 빠진 날짜 채우기

예전 채팅을 가져온 뒤처럼 어떤 날의 요약이 만들어지지 않는 경우가 있습니다. 창의 **Missing Summaries**(누락된 요약) 패널에 있는 **Backfill**(백필) 버튼을 누르면 요약이 없는 최근 날짜를 다시 시도합니다. 한 번에 최대 14일 전까지 거슬러 올라갑니다.

요약에 쓰는 연결이나 모델을 바꿔도 이미 만들어진 일별 항목과 주간 항목을 다시 쓰지는 않습니다.

## 문제 해결

### Memory Recall이 아무것도 불러오지 않을 때

- 임베딩 소스가 설정되어 있는지 확인하세요. **Memories for This Chat**의 조각이 **Embedding unavailable** 상태라면 연결의 **Semantic Search (Embeddings)** 섹션을 설정하거나 내장 로컬 모델을 사용하세요. [Local Model 설정](../connections/local-model.md)을 참고하세요.
- 조각이 **Waiting for vector** 상태라면 잠시 기다리세요. 지문은 답변이 끝난 뒤에 만들어집니다.
- 불러오기는 최근 메시지와 관련이 깊은 기억만 넣습니다. 관련된 내용이 없으면 아무것도 넣지 않습니다. 정상 동작입니다.
- 최근에 임베딩 모델을 바꿨다면 **Memories for This Chat**의 다시 만들기 아이콘을 사용해 예전 조각을 새 모델에 맞추세요.

### 요약이 생성되지 않을 때

- 채팅에 정상 작동하는 텍스트 연결이 있는지 확인하세요. Chat Summary는 **Summary Connection**을 사용하고, Automatic Summarization은 자동으로 결정된 요약용 연결을 사용합니다. 쓸 수 있는 연결이 하나도 없으면 생성을 건너뜁니다.
- 채팅에 에이전트 쓰기 승인이 필요하도록 설정되어 있으면 AI 요약은 승인을 받은 뒤에 적용됩니다.
- 실패한 요약은 잠시 뒤 자동으로 다시 시도합니다. 그래도 진행되지 않으면 **Backfill Summary**(Roleplay)나 **Backfill**(Conversation)을 직접 실행해 보세요.
