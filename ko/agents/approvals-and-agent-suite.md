# 에이전트 승인과 Agent Suite

에이전트는 채팅에 로어북 항목, 요약, 캐릭터 카드 편집 같은 내용을 기록할 수 있습니다. 이 가이드에서는 이런 기록을 저장되기 전에 검토하는 방법과, **Agent Suite**(에이전트 모음)로 에이전트가 저장한 내용을 읽고 고치는 방법을 설명합니다.

## 저장되기 전에 에이전트 기록 검토하기

기본값에서는 일부 에이전트 기록이 자동으로 저장됩니다. **Review Agent Outputs**(에이전트 출력 검토)는 기록 하나하나가 승인을 기다리게 합니다.

1. 채팅을 열고 **Chat Settings**(채팅 설정)를 클릭하세요.
2. **Agents**(에이전트) 섹션까지 스크롤하세요.
3. Roleplay 채팅에서는 **Trackers Control**(트래커 제어)을 여세요. Game에서는 이 단계를 건너뛰세요.
4. **Review Agent Outputs**를 켜세요.

켜져 있으면 로어북 업데이트, 요약 업데이트를 비롯해 검토 대상인 쓰기 에이전트의 출력이 승인을 기다립니다. 꺼져 있으면 로어북과 요약 업데이트가 자동으로 저장될 수 있습니다.

캐릭터 카드 편집은 **Review Agent Outputs**가 꺼져 있어도 항상 먼저 승인을 요청합니다. 이 확인은 끌 수 없습니다.

### 로어북 또는 요약 업데이트 검토하기

에이전트가 기록을 제안하면 **Review Lorebook Update**(로어북 업데이트 검토) 또는 **Review Summary Update**(요약 업데이트 검토)라는 제목의 창이 열립니다. 창에는 에이전트 이름과 직접 고칠 수 있는 **Proposed Text**(제안된 텍스트) 입력란이 표시됩니다. 로어북 기록일 때는 각 항목을 `###` 제목 아래에 두라는 안내도 표시됩니다.

- **Accept**(수락)는 고친 내용을 포함해 텍스트를 저장합니다.
- **Regenerate**(재생성)는 그 에이전트만 다시 실행해 새 제안을 받습니다.
- **Discard**(변경 취소)는 제안을 저장하지 않고 버립니다.

대기 중인 제안이 더 있으면 창에 그 개수가 표시됩니다. 지금 제안을 처리하면 다음 제안으로 창이 다시 열립니다.

**Create character cards**(캐릭터 카드 생성) 기능이 있는 에이전트는 새 캐릭터 카드를 제안할 수도 있습니다. 이때 카드 텍스트가 담긴 검토 창이 열립니다. 수락하기 전에는 아무것도 저장되지 않습니다.

### 캐릭터 카드 업데이트 검토하기

**Card Evolution Auditor** 에이전트는 롤플레이에서 일어난 일을 바탕으로 캐릭터 카드 편집을 제안합니다. Conversation에서는 내장 `update_about_me` 도구도 공개 About Me 변경을 제안할 수 있습니다. 어느 쪽도 카드를 스스로 고치지 않습니다. 둘 다 **Review Character Card Updates**(캐릭터 카드 업데이트 검토)를 엽니다.

창에는 제안된 편집마다 대상 카드 필드, 에이전트가 이유를 밝혔다면 그 짧은 이유, 현재 텍스트를 보여 주는 **Before**(변경 전) 블록, 직접 고칠 수 있는 **After**(변경 후) 입력란이 표시됩니다.

- **Approve**(승인)는 편집을 적용합니다. 버튼의 숫자는 적용될 편집 개수입니다. 승인하면 캐릭터의 버전 번호가 올라가고 버전 기록 항목이 저장됩니다.
- **Regenerate**는 에이전트를 다시 실행해 새 제안을 받습니다.
- **Reject**(거부)는 카드를 바꾸지 않고 제안을 닫습니다.

에이전트가 제안을 쓴 뒤에 카드가 바뀌었다면 그 편집에 오래됨 표시가 붙고 흐리게 보입니다. 그러면 개수가 적힌 **Override stale**(오래된 항목 덮어쓰기) 버튼이 나타납니다. 그 텍스트를 그래도 원할 때만 쓰세요. Marinara가 확인을 요청한 뒤, 더 이상 일치하지 않는 텍스트를 바꾸는 대신 오래된 텍스트를 해당 필드에 덧붙입니다.

## 에이전트가 저장한 내용 보기와 고치기

**Agent Suite**는 이 채팅의 에이전트가 저장한 모든 내용을 보여 줍니다. 현재 장면, 등장 중인 캐릭터, 페르소나 능력치 같은 트래커 데이터와 사용자 지정 에이전트가 저장한 출력이 여기에 들어갑니다. 잘못된 이름을 바로잡거나 능력치를 고치거나 엉킨 텍스트를 정리할 때 쓰세요.

1. **Chat Settings**를 열고 **Agents**까지 스크롤하세요.
2. **Agent Suite**를 클릭하세요.
3. 왼쪽 목록에서 에이전트를 고르세요.

오른쪽에는 고칠 수 있는 블록이 최대 세 묶음으로 표시됩니다. **Stored Memory**(저장된 기억), **Tracker Data**(트래커 데이터, 트래커 에이전트만 해당), **Recent Outputs**(최근 출력, 사용자 지정 에이전트만 해당)입니다. 데이터를 추적하지 않는 에이전트는 **Stored Memory**만 표시합니다.

각 블록은 텍스트 편집기 또는 JSON 편집기입니다. JSON 블록에는 줄 번호가 표시되며, 잘못된 JSON은 바로 알려 줍니다. JSON을 해석할 수 있을 때까지 **Save**(저장)는 꺼져 있습니다. 모든 트래커 데이터를 검색하거나 필드로 편집하려면 **Tracker Data** 헤더에서 **Open in State Editor**(상태 편집기에서 열기)를 클릭하세요. [State Editor](../roleplay/hud-and-trackers.md#the-state-editor)를 참고하세요.

블록을 고친 뒤에는 **Save**를 클릭해 유지하거나 **Reset**(초기화)을 클릭해 저장된 값으로 되돌리세요.

### AI로 블록 다시 쓰기

1. 블록에서 **AI Edit**(AI 편집)를 클릭하세요.
2. 일부만 바꾸려면 그 텍스트를 먼저 선택하세요. 아무것도 선택하지 않으면 블록 전체를 다시 씁니다.
3. 지시를 입력하세요. 예를 들면 "깨진 캐릭터 이름을 고치세요. 그 캐릭터의 이름은 Mira입니다."처럼 씁니다.
4. 선택 사항: **Add Context**(컨텍스트 추가)를 클릭해 캐릭터 카드나 로어북 항목을 붙이면 AI가 데이터의 의미를 알 수 있습니다.
5. 다시 쓰기를 맡을 연결(AI 서비스와 모델)을 고르세요.
6. **Rewrite**(재작성)를 클릭하세요.

결과는 저장되지 않은 초안으로 블록에 들어갑니다. 확인한 다음 **Save** 또는 **Reset**을 클릭하세요.

- 이 채팅의 에이전트가 아직 실행 중이면 실행이 끝날 때까지 저장이 보류됩니다.
- **Clear memory**(기억 지우기)는 에이전트가 저장한 데이터가 있을 때만 **Stored Memory**에 나타납니다. 그 에이전트가 이 채팅에 저장한 내용을 한 번에 모두 삭제하며, 되돌릴 수 없습니다. Marinara가 먼저 확인을 요청합니다.
- **Narrative Director**에서는 저장된 스포일러가 가려져 있습니다. 보고 고치려면 **Reveal spoilers**(스포일러 보기)를 사용하세요.

## 캐시된 프롬프트 삽입 보기

답변이 생성되기 전에 일부 쓰기 에이전트가 프롬프트에 텍스트를 덧붙입니다. **Prose Guardian**, **Narrative Director**, 사용자 지정 주입 에이전트에서 흔한 일입니다. **Cached prompt injections**(캐시된 프롬프트 삽입) 패널은 가장 최근 답변에 덧붙은 그 텍스트를 보여 줍니다. 문제 해결용 화면입니다.

시작하기 전에: **Debug mode**(디버그 모드)를 켜세요([에이전트: 채팅을 도와주는 AI](agents-overview.md#tell-whether-an-agent-ran) 참고). Roleplay 채팅에서 **Agent activity**(에이전트 활동)의 **Injections** 탭을 여세요. [에이전트 활동](../roleplay/getting-started.md#agent-activity)을 참고하세요.

주입마다 펼쳐서 텍스트를 읽고 고치거나, **Save** 아이콘을 클릭해 고친 내용을 저장하거나, **Re-run**(다시 실행) 아이콘을 클릭해 그 에이전트가 새 주입을 쓰게 할 수 있습니다.

**Knowledge Retrieval**과 **Knowledge Router**의 주입은 여기서 다시 실행할 수 없습니다. 고친 내용과 다시 실행한 결과는 같은 답변을 재생성해야 반영됩니다. 다시 실행할 때는 그 시점까지의 채팅 기록을 쓰며, 이후 메시지는 쓰지 않습니다.
