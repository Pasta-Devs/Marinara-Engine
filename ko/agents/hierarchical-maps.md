# World Maps: 설정, 제작, 이동

> **현재 호환 버전:** 이 가이드는 World Maps **1.3.1** 기준입니다. 이 패키지는
> Marinara Engine **2.3.5~3.x**를 지원하며 Roleplay와 Game 채팅에서 작동합니다.
> Marinara Engine **2.4.1**은 이동 스트림의 연계 정리와 휴대용 가져오기 뒤
> Lorebooks의 즉시 새로고침을 추가합니다. Engine **2.3.5~2.4.0**도 호환되지만
> 가져온 뒤 Lorebooks를 수동으로 새로고쳐야 하며 해당 스트림 정리는 없습니다.

World Maps는 Roleplay와 Game에 지속되는 세계 상태를 더해 줍니다. 현재 위치를 자유
입력 문구 하나로 두는 대신, 세계를 겹겹이 중첩된 장소로 표현합니다.

```text
The Shattered Coast
└── Brinewatch
    ├── Harbor District
    │   ├── Tideglass Inn
    │   └── Quest Hall
    └── Old Sewers
```

Marinara는 이 계층 안에서 현재 위치 하나를 기준값으로 관리합니다. 현재
브레드크럼(현재 위치까지의 경로), 정확한 장소 정보, 근처 목적지, 조건을 만족하는
연결 로어가 다음 응답의 근거가 될 수 있습니다. 가장 최근 사용자 메시지가 이동이나
발견을 분명히 정하면 Maps가 그것을 따라갑니다. 화면에 보이는 AI 서술은 그 결과를
묘사할 수 있을 뿐, 스스로 지도를 옮기거나 없는 장소를 만들어 내지는 못합니다.

지도는 채팅마다 따로 둘 수도 있고, 계정에 속한 공유 세계 하나에 연결할 수도
있습니다. 템플릿은 이후에 각자 달라져도 되는 깨끗한 사본을 만듭니다. 반면 공유
세계는 정본 계층과 아트워크 모음을 하나로 유지하면서, 연결된 채팅은 저마다 현재
위치, 이동 기록, 스냅샷, Game 바인딩을 따로 갖습니다.

## 기능 한눈에 보기

World Maps 1.3.1가 제공하는 기능입니다.

- 지역, 정착지, 장소, 건물, 층, 방의 중첩 구조
- 브레드크럼과 기준이 되는 현재 이야기 위치
- 하위 장소를 목록, 배치 지도, 순서가 있는 레이어로 보는 방식
- 상위/하위 이동, 직통 연결로, 여러 턴에 걸친 경로 계획
- 가장 최근 사용자 메시지가 정한 이동과 발견의 검증
- Roleplay와 Game 채팅에 걸쳐 연결할 수 있는 계정 소유 공유 세계
- 게시, 폐기, 충돌 처리, 분리를 갖춘 채팅별 검토 초안
- 직접, AI, 가져오기로 만드는 계정 전체 지도 템플릿
- 설정이나 선택한 로어를 근거로 삼는 AI 지도 초안과 확장
- 공개 장소 설명, 비공개 모델 기억, 정확한 장소 로어
- 장소마다 선택적으로 지정하는 채팅 또는 Global Gallery 참조 이미지 1개
- 배치 지도를 쓰는 하위 지도마다 따로 두는 채팅 또는 Global Gallery 배경
- 빠진 장소 아트워크를 검토 후 일괄 생성하는 기능
- 변수로 짜는 전역 Maps 아트워크 프롬프트 재정의
- Roleplay 삽화와 Game 스토리보드의 장소 참조 지원
- 가져오기, 내보내기, 보관, 기록을 고려한 편집, Game 지도 바인딩
- AI 지도 제작과 런타임 장소 삽입을 위한 전역 프롬프트 라이브러리

이동할 수 있는 목적지는 모델 컨텍스트에 함께 들어갑니다. 따라서 CYOA 선택지를
켜 두면 모델이 현재 하위 장소나 연결된 장소를 다음 선택지로 제시할 수 있습니다.
실제 선택지 문구는 모델이 만듭니다.

## 지도를 어떻게 둘지 고르기

라이브러리에는 계정에 속한 재사용 자원이 두 가지 있고, 채팅은 저마다 자기 런타임
위치와 기록을 따로 갖습니다. 자원의 이름은 식별자가 아닙니다. 새로 저장한 자원이 기존
자원과 이름이 겹치면 World Maps 1.3.1가 **(copy)**를 붙이거나 번호를 매깁니다.

| 자원 또는 상태 | 소유자 | 이럴 때 고르세요 | 이후 편집이 미치는 범위 |
| --- | --- | --- | --- |
| **Independent chat map** | Roleplay 또는 Game 채팅 하나 | 이 이야기만의 세계가 필요할 때 | 그 채팅만 |
| **Independent template** | 계정 | 재사용할 출발점이 필요할 때 | 새 사본만. 이미 만든 채팅은 갱신되지 않습니다 |
| **Canonical shared world** | 계정 | 여러 채팅이 관리되는 계층 하나를 함께 써야 할 때 | 연결된 채팅이 쓰는 공유 정의 |
| **Linked-chat draft** | 게시하기 전까지 연결된 채팅 하나 | 연결된 이야기에서 발견하거나 고친 내용이 공유 세계에 들어갈 수도 있을 때 | **Publish**를 고르기 전까지 다른 채팅에는 영향이 없습니다 |
| **Detached independent copy** | 한때 연결되어 있던 채팅 하나 | 현재 지도는 그대로 두되 공유 세계의 수정은 더 받지 않으려 할 때 | 분리된 그 채팅만 |

사본을 만드는 것과 연결하는 것은 다릅니다. **Use template**, **Add to chat**,
**Independent copy**는 각각 별개의 지도를 만듭니다. Game 설정 과정의 **Use shared
world**와 라이브러리의 **Link to chat**은 채팅을 정본 공유 세계에 붙입니다.

## 빠르게 시작하기

1. **Agents**(에이전트)를 열고 **Download Agents**(에이전트 다운로드)를 클릭한 뒤
   **World Maps**를 설치하세요.
2. 안내가 나오면 Marinara를 다시 시작하세요. 이 패키지에는 서버 코드가 들어
   있습니다.
3. Roleplay 또는 Game 채팅을 여세요.
4. Engine이 지원한다면 전용 **World Maps** 지구본 아이콘을 열고, 그렇지 않으면
   **Agents → World Maps**를 열어 현재 채팅에서 활성화하세요. 해당 채팅의 **Chat
   Settings**(채팅 설정) **→ Agents** 항목에서 켤 수도 있습니다.
5. **Use template**, **Create with AI**, **Build manually** 중 하나로 지도를
   만드세요. 이미 있는 채팅이라면 지도 파일을 가져올 수도 있습니다.
6. 작업 중인 계층을 검토하고 시작 위치를 고른 다음, 지도를 활성화하고
   **Save**(저장)를 클릭하세요.
7. 채팅하는 중에 **Story map**을 여세요. 갈 수 있는 목적지를 선택하고 다음 턴을
   보내거나, 보내는 메시지에서 파티의 이동을 직접 밝혀서 Maps가 도착을 검증하고
   반영하도록 하세요.
8. 필요하면 장소에 **Gallery**(갤러리) 아트워크를 지정하거나, **Location
   artwork**로 빠진 이미지를 검토하고 생성하세요.

템플릿, AI 초안, 가져온 파일을 적용해도 편집기의 작업 사본만 바뀝니다. 계층을
활성화하고 저장하기 전까지는 답변에 영향을 주지 않습니다.

## 패키지 설치와 활성화

오른쪽 사이드바의 Sparkles 탭에서 **Agents**를 여세요. **Download Agents**를
클릭하고 **World Maps**를 선택한 뒤 **Install**(설치)을 클릭하세요. 이어서 목록에
**Update**(업데이트)가 보이면 그것도 설치하세요. 패키지를 쓰기 전에 다시 시작하라는 안내를 따르세요.

World Maps 페이지는 설치된 패키지 버전과 준비 상태를 알려 주고, 계정 전체 세계 지도
라이브러리를 제공하며, 지금 대상이 된 채팅의 이름과 그 채팅의 지도 상태를 보여 줍니다.
패키지를 설치하면 쓸 수 있는 상태가 될 뿐, 모든 채팅에서 자동으로 켜지지는 않습니다.

### Roleplay

1. Roleplay 채팅을 여세요.
2. 톱니바퀴 버튼으로 **Chat Settings**를 여세요.
3. **Enable Agents**(에이전트 활성화)를 켜세요.
4. **Tracker Agents**(추적 에이전트) 아래에서 **World Maps**를 활성화하세요.
5. **Edit world map** 또는 **World map library**를 여세요. 지원되는 Engine
   빌드에서는 데스크톱 상단 막대의 지구본 아이콘이 같은 라이브러리를 엽니다.
   모바일에서는 Chats 패널의 지구본 아이콘을 쓰세요.

라이브러리는 메인 Agents 페이지에서 열든 Roleplay의 Chat Settings에서 열든 똑같이
동작합니다. 독립된 템플릿 사본을 만들려면 **Add to chat**을, 계속 유지되는 공유
세계에 붙이려면 **Link to chat**을 쓰세요.

### Game

Game 설정 과정에서 World Maps를 고른 다음, 설정 방식을 하나 선택하세요.

- **Create with AI**는 생성된 계층을 검토용으로 준비합니다.
- **Use template**은 Game을 만들기 전에 세계 라이브러리를 엽니다.
- **Build manually**는 편집할 수 있는 빈 계층에서 시작합니다.

**Use template**을 고르면 선택 창에 **Shared worlds**가 먼저, **Independent
templates**가 그다음에 나옵니다.

- **Use shared world**는 새 Game을 계정에 속한 그 정본 세계에 연결합니다. 그래도
  Game은 자기 현재 위치, 기록, 스냅샷, 바인딩, 아직 게시하지 않은 발견 내용을 따로
  갖습니다.
- **Use template**은 검토용으로 Game이 소유하는 작업 사본을 만듭니다. 계정 템플릿은
  절대 건드리지 않습니다.

선택한 자원의 장소가 계층형 시작 세계가 됩니다. 대체용 일반 Game 지도가 그 자리를
대신 차지하지는 않습니다.

이미 만들어 둔 Game에 나중에 World Maps를 추가하려면 **Chat Settings →
Agents**에서 하면 됩니다.

## 지도 템플릿 만들기와 재사용

**World Maps → Open world library**를 여세요. 템플릿은 채팅 하나가 아니라
계정에 속하기 때문에, 여러 번 재사용하는 팬덤 세계, 캠페인 배경, 던전, 도시, 개인용
시작 지도에 적합합니다.

라이브러리에서 할 수 있는 일입니다.

- 템플릿을 직접 만들기
- **Create with AI**로 초안 만들기
- `.hierarchical-map.json` 파일 가져오기
- 템플릿 검색, 보기, 편집, 내보내기, 삭제
- 열려 있는 Roleplay 또는 Game 채팅에서 **Add to chat** 사용
- Game 설정 과정에서 **Use template** 선택

적용할 때마다 독립된 작업 사본이 만들어집니다. 나중에 템플릿을 고쳐도 이미 복사해
간 채팅은 바뀌지 않고, 채팅에서 고친 내용도 템플릿에 반영되지 않습니다.

템플릿은 계정 전체에서 쓰는 Global Gallery 아트워크 참조를 유지합니다. 채팅에서
**Save as template**을 쓰면 Maps가 참조된 채팅 아트워크를 Global Gallery로 올리고,
똑같은 공유 이미지가 이미 있으면 그것을 재사용합니다. 그러면 템플릿을 적용한 모든
채팅이 갤러리 사본을 또 만들지 않고 같은 공유 아트워크를 가리킵니다.

공유되는 것은 아트워크뿐입니다. 적용된 지도 정의는 여전히 독립된 작업 사본이라,
템플릿을 고쳐도 이미 채팅에 추가된 지도는 갱신되지 않습니다.

## 여러 채팅을 공유 세계 하나에 연결하기

여러 Roleplay 또는 Game 채팅이 같은 정본 계층을 읽어야 한다면 World map
library의 **Shared worlds**를 쓰세요. 빈 공유 세계를 만들거나, 파일을 가져오거나,
기존 템플릿을 **Make shared**로 승격하거나, 저장된 채팅 지도를 열어 **Make
shared**를 고르면 됩니다. 마지막 방법은 참조된 채팅 아트워크를 Global Gallery로
올리고, 계정 소유 세계를 만든 뒤, 원래 채팅을 거기에 다시 연결합니다.

라이브러리의 대상 채팅 표시에 이름이 나온 채팅을 붙이려면 **Link to chat**을
고르세요. 현재 위치와 캠페인 기록이 이미 사용한 장소 ID가 모두 공유 세계에 있어야
합니다. 그렇지 않다면 **Independent copy**를 쓰거나, 채팅의 현재 지도를 새 공유
세계로 먼저 옮기세요.

연결된 채팅이 공유하는 것은 지도 정의와 Global Gallery 아트워크뿐입니다. 메시지,
현재 위치, 이동 스냅샷, Game 상태, Game 지도 바인딩, 제공자 연결, 인증 정보는
공유되지 않습니다.

연결된 채팅 안에서 편집하거나 새로 발견한 내용은 그 채팅의 게시 전 초안으로
저장됩니다. **Publish**를 고르기 전까지는 정본 세계도, 다른 채팅도 바뀌지
않습니다. 초안을 **Discard**(변경 취소)하거나, **Detach and keep copy**로 채팅의 현재
버전을 유지한 채 공유를 그만둘 수도 있습니다. 초안이 남아 있는 동안 정본 세계가 바뀌면
Maps가 충돌을 알리고, 어느 한쪽을 조용히 덮어쓰는 대신 분리나 폐기를 요구합니다.

라이브러리에서 공유 세계를 편집하면 정본 정의가 바로 갱신됩니다. 공유 세계 편집기에는
장소를 영구 삭제하는 기능이 없습니다. 안정적인 ID가 남아 있도록 장소를 보관 처리하세요.
연결된 채팅에서도 **Detach and keep copy**를 고르기 전에는 어떤 장소도 영구 삭제할 수
없습니다. 또한 연결된 채팅을 모두 분리하거나 다시 연결하기 전에는 공유 세계 자체를
삭제할 수 없습니다.

공유 세계와 템플릿은 이미지 파일을 채팅마다 복사하지 않고 Global Gallery 아트워크
참조만 유지합니다. 저장된 템플릿, 공유 세계, 독립 채팅 지도, 연결된 채팅의 초안 중
하나라도 참조하고 있으면 Marinara가 해당 Global Gallery 이미지의 삭제를 막습니다.
자산 자체를 지우려면 아트워크 연결부터 해제하세요.

## 분리하기, 교체하기, 처음부터 다시 만들기

아래 동작은 서로 다른 상황을 위한 것입니다.

- 공유는 그만두면서 연결된 채팅의 현재 계층은 남기고 싶다면, 편집기에 남은 변경 사항을
  저장하거나 폐기한 다음 **Detach and keep copy**를 고르세요. 그 채팅은 독립 상태가
  되고 정본 갱신을 더 받지 않습니다.
- 공유는 계속하면서 다른 정본 세계를 쓰고 싶다면, 대상 채팅 이름이 표시된 세계
  라이브러리를 열고 새로 쓸 세계에서 **Link to chat**을 고르세요. 기록 호환성 검사는
  그대로 적용됩니다.
- 독립 채팅 지도를 갈아 끼우려면 그 편집기를 열고 **Replace / start over**를
  고르세요. 먼저 템플릿으로 저장하거나 백업을 내보낼 수 있고, 그다음 **Create with
  AI**, **Use template or shared world**, **Import map file**, **Start blank**
  중에서 고르면 됩니다.
- 채팅에 전혀 다른 지도를 주고 싶을 때도 같은 교체 흐름을 쓰세요. 에이전트를 지웠다가
  다시 추가하는 것은 지도 초기화가 아닙니다.

교체한 내용은 **Save** 전까지 작업 사본으로만 남습니다. 교체를 저장하면 예약된
목적지나 경로가 지워집니다. 메시지 기록이 장소 ID를 참조하기 시작한 뒤에는, 과거
브레드크럼을 지키려고 Maps가 관계없는 교체를 거부할 수 있습니다. 그럴 때는 독립 사본을
유지하면서 기존 지도를 확장하거나 보관 처리하세요.

## 지도 편집기 이해하기

데스크톱에서는 편집기가 세 개의 패널로 나뉩니다. 화면이 좁을 때는
**Hierarchy**, **Local**(로컬), **Details**(세부 정보) 탭으로 전환하세요.

- **Hierarchy**는 전체 트리를 보여 줍니다. 장소를 선택하면 그 장소를 편집합니다.
  **Enter**는 계층에서 보고 있는 위치만 바꿀 뿐, 이야기를 이동시키지는 않습니다.
- **Local**은 현재 장소의 바로 아래 하위 장소를 목록, 배치 지도, 순서 레이어 중
  하나로 보여 줍니다.
- **Details**에서는 장소 설명, 계층, 로어, 아트워크, 연결로, 상태, Game 지도
  바인딩을 편집합니다.

편집기 상단에는 AI 제작 컨트롤, **Templates**(템플릿), **Export**(내보내기), **Import**(가져오기), Enabled
스위치, **Save**가 있습니다. 저장하지 않은 변경 사항에는 **Unsaved** 표시가
붙습니다. 저장하지 않은 채 나가려고 하면 폐기할지 묻습니다.

### 장소에 담을 수 있는 것

장소마다 다음을 가질 수 있습니다.

- 상위 장소 1개와 개수 제한 없는 하위 장소
- Region, Settlement, Place, Building, Floor, Room 중 하나의 유형
- 이름과 아이콘
- 공개 설명과 비공개 모델 기억
- 짧은 인지 요약
- 정확한 장소에 붙는 로어북 연결
- 다른 장소로 이어지는 단방향 또는 양방향 직통 연결로
- List, Map, Layers 중 하나의 하위 장소 표시 방식
- 장소 참조 이미지와 선택적인 이미지 사용 토글
- Map 표시 방식을 쓸 때 따로 두는 하위 지도 배경
- 활성 또는 보관 상태

**Map** 표시 방식에서는 하위 장소를 끌어다 놓거나 X, Y 좌표를 0에서 100까지 정확히
입력하세요. 선택한 상위 장소는 하위 장소 뒤에 깔릴 갤러리 이미지도 가질 수
있습니다. **Layers**에서는 하위 장소마다 서로 다른 레이어 순서를 지정하세요.

직통 연결로는 계층 안의 어떤 장소끼리도 이을 수 있습니다. 마을과 마을을 잇는 나룻배,
특정 층끼리 이어지는 계단, 세계와 세계를 잇는 관문, 서로 다른 건물의 방을 잇는 비밀
통로 모두 가능합니다.

25층짜리 탑이라면 보통 층을 25단계 상위-하위 사슬로 만들지 말고, 탑 하나 아래
형제 장소로 두는 편이 좋습니다. Maps는 장소 500개, 계층 20단계까지 지원합니다.

## AI로 지도 초안 만들기와 확장하기

지도가 비어 있으면 **Create with AI** 또는 **Draft with AI**(AI로 초안 작성)를 클릭하세요. 이미 지도가
있으면 **Expand with AI**를 클릭하세요.

### 참고할 자료 고르기

**Build from**(생성 기준) 아래에서 다음 중 하나를 고르세요.

- **Game setup**은 현재 설정과 캐릭터를 참고합니다. Game에서는 세계 개요와 파티
  캐릭터가 여기에 포함됩니다.
- **Selected lore**는 선택한 로어북을 참고합니다. **Strict canon**은 로어에 근거가
  있는 장소만 만듭니다. **Canon + expansion**은 어울리는 장소를 덧붙이도록
  허용합니다.

지도를 만드는 기능은 턴 기록을 읽지 않습니다. 설정이나 로어에 없는 내용은 **What
should this world include?** 또는 **What should be added?**에 직접 적으세요.

크기를 고르세요.

| 크기 | 대략적인 결과 |
| --- | --- |
| **Small** | 장소 8개 |
| **Medium** | 장소 16개 |
| **Large** | 장소 28개 |

생성 결과는 초안이며, 저장된 지도가 아닙니다. 전체 미리보기를 검색하거나 펼쳐 보고,
장소를 선택해 경로, 설명, 비공개 모델 기억, 로어 출처를 확인하세요. 이어서 진행하기
전에 **Edit prompt**(프롬프트 편집), **Regenerate**(재생성), **Discard draft**(초안 버리기)를 쓸 수 있습니다.

새 지도라면 **Continue to editor**를, 확장이라면 **Add to working map**을
클릭하세요. 캠페인 기록이 장소 ID를 참조하기 시작한 뒤에는, Maps가 그 참조를
지키려고 통째로 갈아엎는 대신 확장만 허용합니다.

## 지도를 직접 만들고 편집하기

지도가 비어 있으면 **Build manually**를 클릭하세요. Maps가 넓은 범위의 시작 장소
하나를 만듭니다. 계층에서 그 장소를 선택한 다음 아래 기능을 쓰세요.

- **Add child**는 선택한 장소 안에 새 장소를 만듭니다.
- **Add sibling**은 같은 상위 장소 아래, 옆자리에 새 장소를 만듭니다.
- **Duplicate**(복제)는 장소와 그 아래 구조를 복사해 두고 편집할 때 씁니다.
- **Archive**는 과거 참조를 지우지 않고 장소를 보관 상태로 바꿉니다.

이야기의 처음 장소는 **Set as starting location**으로 정하세요. 계층을 활성화하려면
활성 상태의 시작 장소가 반드시 있어야 합니다. 편집기가 알려 주는 문제를 모두 해결한
뒤 **Enabled**(활성화)를 켜고 **Save**를 클릭하세요.

## 모델에 전달되는 내용 이해하기

활성화된 지도가 저장되어 있으면 생성할 때마다 기준이 되는 공간 컨텍스트 블록 하나가
전달됩니다. 블록에는 다음이 담깁니다.

- 현재 브레드크럼 경로
- 정확한 현재 장소 ID와 공개 설명
- 현재 장소의 비공개 모델 기억(있을 때)
- 한 번에 갈 수 있는 목적지
- 알려진 활성 장소와 그 정확한 ID를 담은 제한된 목록

이 알려진 장소 목록 덕분에 응답이 저장된 세계의 다른 곳에 도착했다는 사실을 알아볼
수 있습니다. 근처 목적지는 평범한 서술이나 CYOA 선택지의 재료가 되기도 합니다.

상위 장소의 이름은 위치 감각을 주지만, 상위 장소의 설명, 비공개 기억, 아트워크,
연결된 로어는 물려받지 않습니다. 현재 위치가 `Tower → Floor 7 → Alchemy Lab`이라면
연구실의 정보만 활성화되고, 탑과 층은 브레드크럼에 이름만 더합니다.

**Private model memory**는 저장해 두는 AI 전용 메모이며, 스스로 갱신되는 기억
기능이 아닙니다. 비밀, 분위기, 계속 남는 위험 요소, 그곳만의 규칙처럼 정확히 그
장소에서만 살아 있어야 하는 정보에 쓰세요. 모델에 꼭 전달해야 하는 정보는 인지
요약에만 맡기지 말고 공개 설명이나 비공개 모델 기억에 적으세요.

## 이야기 도중에 이동하기

Maps는 예약한 이동, 계획한 경로, 사용자 메시지가 이끄는 도착의 검증을 지원합니다.
이동은 턴과 함께 저장되므로, 위치는 선택한 메시지 기록과 스와이프를 따라갑니다.
Marinara를 다시 시작해도 현재 위치가 일부러 초기화되지는 않습니다. 다른 메시지 분기나
스와이프로 옮기면 그 기록과 함께 저장된 공간 스냅샷이 복원됩니다.

### 목적지 직접 예약하기

목적지를 선택하면 이동이 예약될 뿐, 바로 이동하지는 않습니다. 이동은 다음 메시지를
보낼 때 확정되므로 위치와 턴이 어긋나지 않습니다.

한 번에 갈 수 있는 목적지는 다음과 같습니다.

- 현재 장소의 상위 장소
- 현재 장소의 활성 하위 장소
- 사용할 수 있는 직통 연결로로 이어진 장소

한 턴에 확정되는 계층 이동은 한 단계뿐입니다. 예약을 취소하려면 예약된 목적지의 X를
누르세요. 메시지를 보내기 전에 지도가 수정되거나 현재 위치가 바뀌면 예약된 이동은
**Needs review** 상태가 됩니다.

### 여러 턴에 걸친 경로 계획하기

세계 지도에서 멀리 있는 활성 장소를 선택하세요. 상위/하위 관계와 사용할 수 있는
연결로로 길이 이어진다면 Maps가 최단 경로를 보여 주고 **Plan route**를 제안합니다.

경로를 지정하면 첫 단계가 예약됩니다. 이후 사용자 턴을 보낼 때마다 한 단계씩 확정하고
다음 단계를 예약하는 식으로 목표에 도착하며, 따로 진행 버튼은 없습니다. 경로는 언제든
취소할 수 있습니다. 지도나 현재 위치가 예상 밖으로 바뀌면 경로는 새 길을 짐작하지 않고
**Needs review** 상태가 됩니다.

예를 들어 Floor 1에서 형제 장소인 Floor 25로 가려면 보통 탑으로 나가는 데 한 턴,
Floor 25로 들어가는 데 한 턴이 듭니다. 직통 연결로가 있으면 한 단계로 끝납니다.

### 사용자 메시지가 이끄는 이동 따라가기와 새 장소 발견하기

지도를 자동으로 바꿀 권한은 가장 최근 사용자 메시지에 있습니다.

- 이야기의 중심이 되는 파티가 현재형이나 명령형으로 직접 움직이면 도착이 성립합니다.
  "Kitchen으로 간다", "그녀가 야외 구역으로 이동하고, 우리도 따라간다" 같은 문장은
  이름이 맞는 알려진 장소로 이동시킬 수 있습니다.
- 이름이 있고 계속 남으며 다시 찾아갈 수 있는 의미 있는 장소에 분명히 도착하거나 그런
  장소를 발견하면 세계에 추가할 수 있습니다. "숨겨진 방을 발견한다" 같은 문장은 그
  장소를 만들고 그곳으로 들어갈 수 있습니다.
- 화면에 보이는 응답이 그 결과를 서술할 수는 있지만, AI 서술만으로는 이동도 새 장소도
  결코 인정되지 않습니다.
- 앞으로의 계획, 실패했거나 끝나지 않은 이동, 단순한 언급, NPC만의 이동, 상상 속 장소,
  임시 야영지, 복도, 탈것을 비롯해 스쳐 가는 요소는 장소를 만들지도 옮기지도 않습니다.

문장의 뜻을 읽어 내고 숨은 Maps 지시를 만드는 일은 여전히 모델의 몫이며, 그 결과를 앱이
검증합니다. 애매한 문장에서는 언어 모델마다 판단이 갈릴 수 있습니다. 다음 턴에 반드시
이동해야 할 때는 **Set destination**(목적지 설정)을, 이미 저장된 상태를 고칠 때는
**Set current story location**(현재 이야기 위치 설정)을 쓰세요.

검증을 마친, 사용자 메시지가 이끈 도착은 한 단계 이동 제한을 넘어설 수 있습니다.
필요하면 Maps가 현재 장소에서 이어지는 직통 연결로를 기록합니다. 이미 예약된 목적지가
있었다면 그 이동이 먼저 사용자 메시지와 함께 저장되고, 이어서 사용자 메시지가 이끈
도착이 어시스턴트 응답의 최종 위치가 되며 한 번짜리 예약은 지워집니다. 계획한
경로에서는 다음 예정 단계에 도착하면 평소대로 진행됩니다. 다른 곳에 도착하면 경로의
뒷 단계로 건너뛴 경우까지 포함해 경로가 **Needs review** 상태가 되고, Maps는 계획을
조용히 고쳐 쓰지 않습니다. 그럴 때는 도착한 현재 위치에서 경로를 취소하거나 다시
계획하세요.

### 시작 위치와 현재 이야기 위치의 차이

**시작 위치**는 새 이야기를 시작할 때 쓰는 기본 위치입니다. **현재 이야기 위치**는
지금 이 채팅이 있는 곳입니다. 시작 위치를 바꿔도 이미 진행 중인 채팅의 현재 위치는
고쳐지지 않습니다.

저장된 상태를 고치려면 편집기의 **Details** 패널에서 활성 장소를 선택하고 **Set
current story location**을 고르세요. 이것은 서술된 이동이 아니라 관리용 정정입니다.
**Save**를 클릭할 때 반영되고, 예약된 목적지나 경로를 지우며, 앞선 메시지를 고쳐 쓰지는
않습니다.

### Roleplay에서의 이동

메시지 입력란 위에 **Story location**(스토리 위치) 컨트롤이 나타납니다.

1. 스토리 지도를 열어 계층과 현재 브레드크럼을 확인하세요.
2. 장소를 선택해 설명을 읽으세요.
3. 이동하지 않고 둘러보려면 **Explore inside**, **Browse up** 또는 브레드크럼을
   쓰세요.
4. 갈 수 있는 장소에는 **Set destination**을, 멀리 있는 도달 가능한 목표에는 **Plan
   route**를 클릭하세요.
5. 다음 메시지를 보내 예약된 단계를 확정하세요.

### Game에서의 이동

Game Mode(게임 모드)에는 **Hierarchical world map**(계층형 세계 지도)이 더해집니다. **You are
here**가 현재 이야기 위치를 표시합니다. 둘러보기, 중앙 맞추기, 살펴보기는 파티를
움직이지 않습니다. 목적지나 경로를 예약한 다음 Game의 다음 턴을 보내세요.

가장 최근 사용자 메시지가 파티의 도착을 분명히 정하면, 생성된 Game 응답이 계층 위치를
갱신하는 숨은 명령을 낼 수 있습니다. 그러면 현재 장소 정보가 GM, 파티, 장면 아트,
조건을 만족하는 스토리보드 참조의 근거가 됩니다.

## 계층형 세계 지도와 일반 Game 지도의 차이

Game에는 두 가지 지도 체계가 함께 있을 수 있습니다.

- **World Maps**는 `The Shattered Coast → Brinewatch → Tideglass Inn`처럼 기준이
  되는 이야기 위치, 즉 세계 위치를 다룹니다.
- 일반 Game의 격자 지도나 노드 지도는 그 이야기 위치 안의 국지적, 전술적 세부를
  다루며 Game의 시간과 날씨에도 관여합니다.

World Maps가 Game 시작을 맡으면, 선택한 템플릿이나 검토를 마친 초안이 시작 세계를
제공합니다. 일반 Game 지도는 프롬프트 입력으로 재사용되지도, 대체 계층으로 승격되지도
않습니다.

고급 설정에서는 계층 위치를 Game 지도 전체, 격자 칸 하나, 노드 하나에 바인딩할 수
있습니다. 바인딩된 Game 위치를 선택하면 그에 대응하는 계층 이동이 예약되고, 바인딩되지
않은 위치는 평소의 전술적 동작을 유지합니다. 바인딩을 편집하기 전에 계층을 저장하세요.
바인딩을 해제해도 두 지도 중 어느 쪽도 삭제되지 않습니다.

## 장소에 시각적 개성 더하기

장소 참조 이미지와 하위 지도 배경은 같은 갤러리 이미지를 쓰더라도 서로 별개입니다.

| 아트워크 | 용도 | 이미지 생성에 전달되나요? |
| --- | --- | --- |
| **Location reference image** | 정확한 현재 장소의 시각적 개성을 붙잡아 둡니다. 채팅 아트나 공유 Global Gallery 아트를 고르거나 AI로 만들 수 있습니다. | 전달됩니다. **Use for Roleplay illustrations and Game storyboards**가 켜져 있고 요청이 조건을 만족할 때입니다. |
| **Child map background** | Map 표시 방식을 쓰는 상위 장소에서 옮길 수 있는 하위 장소 뒤에 깔립니다. 지도 레이어마다 배경을 따로 둘 수 있습니다. | 전달되지 않습니다. 화면 표시 전용입니다. |

캐릭터나 페르소나 참조가 누가 있는지를 지켜 준다면, 장소 참조는 장면이 어디에서
벌어지는지를 지켜 줍니다. 제공자가 지원한다면 둘을 함께 쓸 때 캐릭터와 배경이 여러
이미지에 걸쳐 일관되게 유지됩니다.

조건을 만족하는 장소 참조가 첨부되면 이미지 파이프라인이 다음 지시를 덧붙입니다.

> Location handling: an attached location reference image is available. Use it
> to set the scene location.

제공자마다 참조 이미지 개수 제한이 다릅니다. 요청에 직접 넣은 참조와 캐릭터 참조가
많으면 자동 참조가 들어갈 자리가 줄어듭니다.

### 장소 참조 이미지 지정하기

편집기에서 장소를 선택하고 **Location reference image**를 여세요.

- **Choose artwork**는 현재 채팅이나 공유 Global Gallery에서 검토를 마친 이미지를
  지정합니다. 선택 창에 출처가 표시됩니다.
- **Create with AI**는 편집할 수 있는 장소 소개 이미지 프롬프트를 열고, 사용할지
  정하기 전에 결과를 갤러리에 저장합니다.
- **Use for Roleplay illustrations and Game storyboards**는 선택한 이미지를 조건을
  만족하는 생성에 참여시킬지 정합니다.

Map 표시 방식을 쓰는 상위 장소에서는 **Child map background**를 따로 여세요. 갤러리
이미지를 고른 뒤 하위 장소 표시 뒤에 위치를 맞추면 됩니다. 이 이미지는 지도에 보인다는
이유만으로 제공자에게 전달되지는 않습니다.

### 빠진 장소 아트워크 일괄 생성하기

편집기의 **Location artwork** 항목은 참조 이미지나 하위 지도 배경이 없는 장소를
찾아 줍니다.

1. **Review requests**를 클릭하세요.
2. 제공자 요청을 쓰기 전에 요청 개수를 확인하세요.
3. 이미지 연결, 모델, Engine 스타일, 캠페인 아트 스타일 사용 여부, 저장된 이미지
   지시, 출력 크기를 확인하세요.
4. 필요하면 긍정 프롬프트와 부정 프롬프트를 모두 편집하세요.
5. 검토를 취소하거나, **Generate N images**를 클릭해 확정하세요.
6. 작업 중인 지도에서 생성된 아트워크를 확인하고 **Save**를 클릭하세요.

빠진 이미지 하나하나가 별도의 제공자 요청입니다. 큰 세계일수록 느리거나 비쌀 수 있어서
검토 화면은 스크롤할 수 있고 요청 개수도 계속 보입니다. 가능하면 기존 아트워크를 다시
써서 요청을 아낍니다. 새로 만든 이미지는 장소 참조가 되고, 그 지도에 배경이 필요하면
하위 지도 배경으로도 쓰입니다.

검토 화면에 보이는, 편집을 마친 긍정 프롬프트와 부정 프롬프트가 그대로 제공자에게
전달됩니다. 긍정 프롬프트의 내용이 부정 프롬프트로 복사되지는 않습니다.

## 자동 아트워크 프롬프트 바꾸기

**Settings**(설정) **→ Generations → Prompt Overrides**를 열고 **Maps location
artwork**를 선택하세요. 이것은 Maps가 자동 장소 아트워크를 미리 보고 생성할 때 쓰는
전역 틀입니다. 변수는 `${variableName}` 형태이며 편집기에서 삽입할 수 있습니다.

| 변수 | 의미 |
| --- | --- |
| `${locationName}` | 장소 이름 |
| `${locationDescription}` | 정확한 장소의 공개 설명 |
| `${locationType}` | Region, Settlement, Place, Building, Floor, Room 중 하나 |
| `${locationPrompt}` | Maps가 준비한 기본 장소 소개 프롬프트 전문 |
| `${parentLocationName}` | 바로 위 상위 장소 이름. 최상위에서는 빈 값 |
| `${parentLocationDescription}` | 바로 위 상위 장소의 공개 설명. 없으면 빈 값 |
| `${locationPath}` | 최상위부터 현재 장소까지의 전체 브레드크럼 |
| `${genre}` / `${genreLine}` | Game 장르의 원문 또는 문장 부호가 붙은 형태. Game 밖에서는 빈 값 |
| `${campaignArtStyle}` / `${campaignArtStyleLine}` | **Use campaign art style**(캠페인 아트 스타일 사용)이 켜져 있을 때만 캠페인 스타일 |
| `${imageInstructions}` / `${imageInstructionsLine}` | Chat Settings에 저장한 이미지 지시의 원문 또는 정리된 형태 |

기본 틀은 정확한 장소 프롬프트에 장르, 캠페인 스타일, 저장된 이미지 지시를 선택적으로
더합니다. 상위 장소의 설명과 전체 경로는 의도적으로 기본값에서 빼 두었습니다. 그래야
탑 같은 상위 지형지물이 모든 하위 장소나 층 이미지에 억지로 끼어들지 않습니다.

자주 하는 수정입니다.

- 자동 지도 아트워크에 Game 장르가 나오지 않게 하려면 `${genreLine}`을 지우세요.
- 채팅별 **Use campaign art style** 토글이 그 내용을 좌우하게 하려면
  `${campaignArtStyleLine}`만 남기세요. 토글이 꺼져 있으면 이 변수는 빈 값이 됩니다.
- `${parentLocationName}`, `${parentLocationDescription}`, `${locationPath}`는
  제공자에게 더 넓은 컨텍스트가 필요할 때만 추가하세요.
- 기본 틀로 되돌리려면 **Reset to default**(기본값으로 초기화)를 쓰세요.

Engine 스타일 프로필과 전역 긍정, 부정 이미지 설정은 이 틀 다음에 적용됩니다. 이
설정들은 Maps 전용이 아니라 Illustrator와 이미지 워크플로 전체가 함께 쓰는
부분입니다. 부정 프롬프트에 예상하지 못한 문구가 남아 있다면 전역 부정 이미지 설정과
검토 화면의 편집란을 확인하세요.

## 장소에 로어 연결하기

World Maps는 로어를 두 가지 방식으로 씁니다.

1. AI 제작 기능이 초안을 만들거나 확장할 때 선택한 로어북을 읽습니다.
2. 저장된 장소는 정확히 그 장소에 있는 동안 항목을 활성화할 수 있습니다.

런타임 로어를 붙이려면 장소를 선택하고 **Linked lore**를 연 다음, 사용할 수 있는
항목을 검색해 원하는 항목을 붙이고 저장하세요.

연결된 로어북 항목을 열면 지도 편집기에서 나가게 됩니다. 다른 편집 내용을 남겨 두고
싶다면 지도를 먼저 저장하고, 그렇지 않다면 폐기해도 괜찮은지 확인하세요. World Maps
1.3.1는 그 동작으로 저장하지 않은 지도 변경 사항이 사라질 수 있을 때 미리 알려 줍니다.

하위 장소는 상위 장소에 연결된 항목을 물려받지 않습니다. Brinewatch에 붙인 로어는 Tideglass
Inn에도 따로 붙이지 않는 한 그곳에서 활성화되지 않습니다.

현재 장소 로어는 키워드가 맞을 필요는 없지만, 로어북 설정을 건너뛰지도 않습니다.
비활성화됐거나 채팅에서 제외된 로어북과 항목은 여전히 쓸 수 없고, 항목의 조건, 시점,
확률, 토큰 예산도 그대로 적용됩니다. 참조가 끊어진 항목은 편집기에 계속 보이므로
고치거나 연결을 해제할 수 있습니다.

## Maps의 고급 프롬프트 설정

메인 **Agents → World Maps** 페이지는 두 가지 전역 프롬프트 체계를 관리합니다.

- **Generation prompt**는 AI 지도 초안과 확장에 쓰는, 이름이 붙은 Roleplay/Game
  라이브러리입니다. 채팅마다 원하는 항목을 따로 고를 수 있습니다. 결과 미리보기는
  모델에 요청을 보내지 않고 실제 설정, 캐릭터, 로어, 지도 컨텍스트를 사용합니다.
- **Turn prompt insert**는 평범한 턴에서 현재 위치를 알려 주는 전역 Roleplay/Game
  시스템 문구를 관리합니다. Marinara는 앱이 관리하는 `<spatial_context>` 태그와
  필수 기준 변수를 그 주위에 그대로 유지합니다.

같은 페이지의 **Connection Override**(연결 재정의)는 AI 지도 초안과 확장에 영향을 줍니다. 현재
채팅의 연결을 쓰려면 비워 두세요. 이 설정들은 전역 Generation 설정 아래의 별도 항목인
**Maps location artwork** 재정의를 대신하지 않습니다.

이 컨트롤들은 고급 사용자를 위한 것입니다. 필수 변수를 지우지 말고, 저장하기 전에 결과
미리보기로 확인하세요.

## 안전하게 가져오기, 내보내기, 보관하기

### 휴대 가능한 지도 내보내기

채팅, 템플릿, 공유 세계 편집기에서 **Export**를 쓰면 작업 중인 계층을
`.world-map.json` 파일로 다운로드합니다. 먼저 연결된 로어를 얼마나 포함할지 고르세요.

| 로어 옵션 | 파일 내용 |
| --- | --- |
| **Map only** | 계층과 읽을 수 있는 장소-로어 출처 정보만 포함하며 로어북 내용은 없습니다. 빠진 항목을 다시 만들 수 없습니다. |
| **Map + linked entries** | 지도가 연결한 항목과 정리에 필요한 폴더 경로만 포함합니다. 권장 휴대 옵션입니다. |
| **Map + complete lorebooks** | 연결된 로어북의 모든 항목과 폴더를 포함하며 지도와 무관한 내용도 들어갑니다. |

공유하기 전에 로어북 목록, 항목 수, 예상 크기, 펼칠 수 있는 장소-로어 대응을 확인하세요. 전체 로어북에는 비공개이거나 무관한 메모가 있을 수 있습니다.
참조된 장소 이미지와 하위 지도 배경까지 한 파일에 묶으려면 **Include map artwork**를
켜 둔 채로 두세요. 가벼운 백업에는 이 옵션을 끄세요. 예전
`.hierarchical-map.json` 파일도 계속 가져올 수 있습니다.

### 지도를 가져와 휴대 로어 복원하기

계층을 채팅 작업 사본, 독립 템플릿, 공유 세계로 불러오려면 **Import**를 쓰세요. 함께
파일에 로어북 내용이 있으면 **Restore portable map lore**가 **Exact IDs**, **Unique content**, **Need a choice**, **New entries** 네 그룹을 미리 보여 줍니다.

정확한 항목 ID가 확정적인 것은 대상 로어북에 속할 때뿐입니다. 다른 출처의 ID는 모호하므로 올바른 `Lorebook → Entry (ID)` 행이나 **Import a new copy**를 선택하세요. ID가 없으면 휴대 내용과 설정 전체가 단 하나와 일치할 때만 재사용하며 이름만으로는 부족합니다.

예상 결과를 보고 전략을 고르세요.

- **Import separate copies**는 항목을 재사용하지 않고 `Original Lorebook - Map Name (World Map)` 같은 독립 로어북을 만들며 이름 충돌에는 **(copy)** 또는 **(copy N)**을 붙입니다.
- **Reuse matches & import the rest**는 정확하고 유일한 일치를 유지하고 모호한 행의 선택을 적용하며 남은 항목에만 새 로어북을 만듭니다.

Maps는 재사용하고 만든 로어북을 나열합니다. 만든 사본은 지도를 지워도 라이브러리에 남습니다. Engine **2.4.1** 이상은 Lorebooks를 즉시 새로고치며 **2.3.5~2.4.0**에서는 복원 후 Marinara를 한 번 새로고치세요.

묶인 아트워크도 복원하고 다시 매핑합니다. 채팅 아트워크는 대상 Gallery로 돌아가고 공유 아트워크는 Global Gallery에서 재사용하거나 한 번만 추가합니다. 결과를 확인하고 **Save**하세요. 가져오기만으로는 저장되지 않습니다. **Map only**는 출처와 기존 정확한 ID 연결을 유지하지만 내용이 없어 삭제된 로어북이나 항목을 다시 만들 수 없습니다.

캠페인 기록이 지도를 참조하기 시작하면, 가져오는 내용도 기존 장소 ID를 유지해야
합니다. 관계없는 ID로 계층을 통째로 바꾸지 말고 장소를 추가하거나 갱신하세요.

### 장소 보관 또는 영구 삭제하기

보관은 예전 참조를 지켜 줍니다. 장소를 보관하기 전에 다음을 처리하세요.

- 활성 하위 장소를 옮기거나 함께 보관하세요.
- 필요하다면 다른 활성 시작 위치를 고르세요.
- 그 장소가 현재 런타임 위치라면 대신할 활성 장소를 고르세요.

보관한 장소는 Details 패널에서 되돌릴 수 있습니다. World Maps 1.3.1는 보관한
장소나 전부 보관된 가지를 안전하게 지울 수 있을 때 **Delete permanently**도
제공합니다. 그 장소가 저장된 시작 위치나 현재 이야기 위치이거나, 메시지 기록에
나오거나, Game 지도 바인딩이 있거나, 예약된 목적지나 경로에 들어 있거나, 아직 공유
세계에 연결된 채팅에 속해 있으면 편집기가 이 기능을 막습니다. 공유 세계 편집기와
템플릿 편집기에는 장소를 영구 삭제하는 기능이 없습니다. 편집기가 알려 주는 의존 관계를
먼저 정리하거나, 필요하다면 연결된 채팅을 분리하거나, 그 장소를 보관 상태로 두세요.

영구 삭제는 **Save**를 클릭할 때 작업 초안에서 장소를 지우고 그 계층과 직통 연결로
참조까지 정리합니다. 저장하지 않고 닫으면 삭제도 취소됩니다. 지운 장소는 더 이상
내보내기에 들어가지 않습니다. 보호되어 남은 보관 장소는 안정적인 ID가 기록과 연결
데이터를 뒷받침할 수 있도록 계속 내보내기에 포함됩니다. 이 보호 장치를 피하려고 내보낸
JSON을 고치지 마세요.

## 문제 해결

### Chat Settings에 World Maps가 없습니다

패키지가 설치되어 있고 Marinara를 다시 시작했는지 확인하세요. 현재 채팅은 Roleplay나
Game이어야 합니다. **Enable Agents**를 켠 다음 **Tracker Agents** 아래에서 **World
Maps**를 활성화하세요.

### 세계 라이브러리에 Add to chat이나 Link to chat이 없습니다

라이브러리를 열기 전에 지원되는 Roleplay나 Game 채팅을 먼저 여세요. 라이브러리는 대상
채팅의 이름을 보여 주고, 템플릿에는 **Add to chat**을, 공유 세계에는 **Link to
chat**을 제공합니다. Game 설정 과정에서는 같은 역할을 **Use template**과 **Use shared
world**가 합니다.

Game 설정 과정에서 공유 세계 목록은 나오는데 **Use shared world**가 보이지 않는다면,
브라우저가 아직 업데이트 전의 옛 패키지 클라이언트를 쓰고 있을 수 있습니다. 열려 있는
지도 편집기가 있으면 지도를 저장하거나 초안을 폐기하기로 정한 다음 편집기를 닫으세요.
관계없는 작업까지 저장하고 Marinara를 한 번 강제로 새로고침한 뒤 Game 설정을 다시
여세요. 최신 Engine 빌드는 패키지 업데이트에 새로고침이 필요할 때 그 사실을 직접 알려
줍니다.

### Game 설정이 엉뚱하거나 대체용 장소를 썼습니다

**Use template**을 고른 다음, Game 설정을 마치기 전에 독립 사본을 원하면 **Use
template**을, 정본에 연결하고 싶으면 **Use shared world**를 확인하세요. Game 지도를
검토하고 저장하세요. 템플릿은 그대로 남고, 연결된 Game은 **Publish**를 고르기 전까지
변경 내용을 게시하지 않은 채로 둡니다.

### 연결된 채팅에 예전 공유 세계가 계속 표시됩니다

게시한 브라우저 탭에 캐시된 깨끗한 연결 채팅 편집기는 자동으로 새로고침됩니다. 저장하지 않았거나 게시하지 않은 변경이 있는 채팅은 초안을 유지하고 충돌을 표시합니다. 다른 탭이나 창의 채팅은 다시 열어 새 정본 리비전을 가져오세요.

### 지도를 활성화할 수 없습니다

활성 장소를 최소 하나 만들고 활성 상태의 시작 위치를 지정하세요. 편집기 위쪽에 표시된
문제를 모두 해결한 다음 다시 활성화하고 저장하세요.

### AI 지도 생성을 쓸 수 없습니다

채팅이나 Maps의 **Connection Override**에 동작하는 언어 모델 연결이 있는지
확인하세요. AI 제작 기능을 다시 열기 전에 편집기의 변경 사항을 저장하거나 폐기하세요.
확장할 때는 활성 상태의 대상을 고르세요. 로어를 근거로 생성하려면 활성화되어 있고
채팅에서 제외되지 않은 로어북을 최소 하나 선택하세요.

### AI 지도 생성에서 불완전하거나 잘못된 JSON을 보고합니다

완전한 JSON이 나오기 전에 응답이 끝났다면 연결의 **Max Output Tokens**를 높이거나 더 작은 지도 크기를 선택하고 다시 생성하세요. World Maps는 불완전한 응답을 복구하는 데 추가 요청을 쓰지 않습니다.

잘못된 JSON이라면 구문만 고치는 복구를 이미 한 번 시도했습니다. 다시 생성하고, 같은 모델이 반복해서 실패하면 다른 연결이나 모델을 사용하세요. **Max Output Tokens** 변경은 불완전한 출력에만 해당합니다.

### 메시지를 보냈는데 현재 위치가 따라오지 않습니다

자동 이동은 가장 최근 사용자 메시지가 중심 파티의 도착을 직접 정하고, 모델이 올바른
숨은 Maps 지시를 만들어야 일어납니다. AI 서술만 있는 경우, 의도, 논의, 실패한 이동,
NPC만의 이동, 잠깐 머무는 장소는 표시를 옮기지 않습니다. "Kitchen으로 간다"처럼
직접적인 문장을 써 보세요. 다음 턴에 반드시 이동시키려면 **Set destination**을 쓰세요.

### 채팅을 다시 열었더니 현재 위치가 바뀌었습니다

어떤 메시지 분기와 스와이프가 선택되어 있는지 확인하세요. 현재 위치는 그 기록과 함께
저장된 공간 스냅샷을 따라갑니다. 선택된 기록은 맞는데 표시가 틀렸다면, 지도 편집기를
열고 올바른 활성 장소를 선택한 다음 **Set current story location**을 고르고
**Save**를 클릭하세요.

### 목적지나 경로가 Needs review로 표시됩니다

이동을 예약한 뒤에 지도가 수정되거나 현재 위치가 바뀐 경우입니다. 스토리 지도를 열어
현재 경로를 확인하고 목적지나 경로를 다시 선택하세요. 표시된 목적지가 아직 예약된
상태라면 다시 선택하기 전에 예약을 취소하세요.

### 계획한 경로가 진행되지 않습니다

사용자 턴을 보낼 때마다 표시된 다음 단계가 확정되고 그다음 단계가 예약되어야 합니다.
따로 진행 컨트롤은 없습니다. 턴을 한 번 마쳤는데도 경로가 나아가지 않으면 경로를
취소하고 현재 위치에서 다시 계획하세요. 저장된 위치 자체가 이미 틀렸다면 **Set current
story location**을 쓰고 **Save**를 클릭하세요. 이 관리용 정정이 남아 있던 경로를
지웁니다.

### 이 채팅에 전혀 다른 지도를 쓰고 싶습니다

지도 편집기를 열고 **Replace / start over**를 고르세요. 필요하다면 먼저 템플릿으로
저장하거나 내보낸 다음, 새 지도를 만들거나 가져오거나 복사하거나 연결하세요. 채팅이
연결된 상태이고 현재 계층을 그대로 남겨야 한다면 **Detach and keep copy**를 먼저
쓰세요. World Maps를 지웠다가 다시 추가해도 그 지도는 지워지지 않습니다.

### 멀리 있는 장소를 선택할 수 없습니다

활성 상태의 상위/하위 관계나 연결로로 길이 이어진다면 **Plan route**를 쓰세요. 길이
없다면 직통 연결로를 새로 만들거나, 갈 수 있는 장소를 한 턴에 하나씩 거쳐 이동하세요.
둘러보기 컨트롤은 이야기를 이동시키지 않습니다.

### 자동 아트워크 프롬프트에 Game 장르가 계속 들어갑니다

**Settings → Generations → Prompt Overrides → Maps location artwork**를 열고 틀에서
`${genreLine}`을 지우세요. 재정의를 저장한 뒤 아트워크 검토를 다시 여세요.

### 꺼 두었는데도 캠페인 스타일이 나옵니다

**Chat Settings → Illustrator → Use campaign art style**을 확인하세요. 이 토글이 꺼져
있으면 `${campaignArtStyle}`과 `${campaignArtStyleLine}`은 빈 값이 됩니다. 검토 요약에
캠페인 아트 스타일이 **Off**로 표시되어야 합니다.

### 상위 지형지물이 모든 하위 장소 이미지에 나옵니다

꼭 필요한 경우가 아니면 전역 아트워크 틀에서 `${parentLocationDescription}`과
`${locationPath}`를 쓰지 마세요. 기본 장소 프롬프트는 정확한 장소만 다루도록 범위를
좁혀 두었고, 그 넓은 항목들은 빼 두었습니다.

### 부정 이미지 프롬프트에 예상하지 못한 내용이 들어 있습니다

확정하기 전에 부정 프롬프트란을 확인하고 편집하세요. 그다음 함께 쓰이는 전역 부정
이미지 설정을 확인하세요. Maps 아트워크 틀은 긍정 프롬프트를 만들 뿐, 그 내용이 부정
프롬프트란으로 복사되지는 않습니다.

### 장소 참조가 이미지나 스토리보드에 쓰이지 않습니다

갤러리 이미지가 아직 남아 있는지, 그리고 정확한 현재 장소에서 **Use for Roleplay
illustrations and Game storyboards**가 켜져 있는지 확인하세요. 하위 지도 배경은 화면
표시 전용이라, 같은 갤러리 이미지를 장소 참조로도 지정하지 않는 한 참조를 대신할 수
없습니다.

### 모델이 지도를 무시합니다

현재 채팅에서 World Maps가 활성 상태인지, 계층이 **Enabled**인지, 최근 변경 사항을
저장했는지, Story location 컨트롤에 현재 위치가 보이는지 확인하세요. 더 자세히
진단하려면 **Turn prompt insert**의 결과 미리보기를 쓰세요.

### 연결한 로어가 활성화되지 않습니다

항목이 정확히 현재 장소에 붙어 있는지 확인하세요. 그리고 항목과 로어북이 활성화되어
있는지, 로어북이 해당 채팅에서 제외되지 않았는지 확인하세요.

**World Maps 1.3.1의 추가 규칙:** 안내 생성, 재생성, 이어 쓰기는 새 사용자 턴을 만들지 않으므로 예약한 목적지나 경로 단계를 소비하지 않습니다. **Impersonate**는 사용자 메시지를 만듭니다. 성공한 턴은 이동을 한 번 확정하고, 제공자 실패는 아무것도 확정하지 않으며, 오래된 이동은 **Needs review**로 돌아갑니다.

Marinara Engine **2.4.1** 이상에서는 완전한 Maps 이동·발견 지시를 스트리밍 본문과 저장 메시지에서 제거하되 일반 대괄호 문장과 간격은 바꾸지 않습니다. 원시 Maps 지시가 보이면 Engine과 World Maps를 업데이트하고 요청될 때 재시작한 다음 해당 메시지를 재생성하거나 제거하세요.

Gallery 이미지 하나가 두 역할을 맡을 때 **Remove reference only**는 하위 지도 배경으로 남기고, **Reject both and create replacement**는 둘 다 교체하며, **Use for both**는 새 이미지를 두 역할에 할당합니다. 저장된 Gallery 링크의 이미지가 사라진 경우도 누락입니다. 편집 중 완료된 생성 결과는 여전히 비어 있는 역할만 채우며 새 교체 이미지, 참조 토글, 배경 위치, 보관 상태나 다른 초안 변경을 덮어쓰지 않습니다.

연결 로어의 **Open**은 지도 작업 공간을 떠나 로어북을 엽니다. 깨끗한 초안은 바로 닫고, 저장하지 않은 변경이 있으면 먼저 저장하거나 폐기를 확인합니다. 가져온 로어가 활성화되지 않으면 요약을 확인하세요. **Map only**에는 복원할 내용이 없습니다. **Map + linked entries** 또는 **Map + complete lorebooks**를 사용하고 정확한 일치, 모호한 대상, 별도 사본 중 하나를 고르세요. 상위 장소에 연결된 로어는 하위 장소가 상속하지 않습니다.
