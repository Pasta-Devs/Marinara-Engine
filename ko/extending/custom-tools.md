# 사용자 지정 도구와 기능 호출

이 가이드에서는 Marinara Engine의 사용자 지정 도구, 즉 Functions를 설명합니다. 사용자 지정 도구는 채팅 중에 AI가 작은 동작을 실행하도록 가르치는 장치입니다. 정해진 문구를 돌려주거나, 바깥의 웹 주소를 호출하거나, 서버에서 짧은 스크립트를 실행할 수 있습니다. 도구를 만드는 방법, 채팅에서 도구 사용을 켜는 방법, 스크립트 도구를 안전하게 다루는 방법을 알 수 있습니다.

## 기능 호출이란

기능 호출은 AI가 앱에 동작 실행을 요청하고 그 결과를 답변에 활용하는 방식입니다. 앱에는 주사위 굴림, 로어북 검색, 게임 상태 갱신 같은 기본 제공 도구가 이미 들어 있습니다. 사용자 지정 도구는 그 기본 제공 도구들과 나란히 같은 **Function Calling**(기능 호출) 체계 안에서 동작합니다.

사용자 지정 도구는 예를 들어 이런 일에 쓸 수 있습니다.

- 가게 영업시간이나 하우스 룰처럼 정해진 정보를 돌려줍니다.
- 날씨나 스마트 홈 기기 상태처럼 실시간 데이터를 바깥 서비스에 물어봅니다.
- 숫자 더하기나 특별한 결과 굴리기처럼 간단한 계산을 합니다.

사용자 지정 도구는 캐릭터 카드에 붙는 것이 아닙니다. 채팅마다 켜서 쓰거나 에이전트에 붙여서 씁니다. 에이전트는 채팅과 함께 돌아가는 보조 기능입니다. 두 방법 모두 아래에서 설명합니다.

네이티브 함수 호출에는 도구를 지원하는 연결이 필요합니다. Claude와 Grok 구독 전송 방식은 네이티브 도구 정의를 무시하므로 Chat Settings에 사용 가능 여부가 안내되고 해당 연결의 도구 컨트롤이 비활성화됩니다. 텍스트 명령과 주사위 태그는 계속 사용할 수 있습니다. Game 채팅에서는 별도의 도구 계획 연결을 선택할 수 있습니다. 비용과 동작은 [선택적 도구 계획과 로어 검색](../game/getting-started.md#optional-tool-planning-and-lore-searches)을 참조하세요.

로어북 검색은 활성화된 항목에 호환되는 벡터가 있으면 의미 기반 순위를 사용합니다. 의미 검색을 사용할 수 없으면 Conversation과 Roleplay는 텍스트 일치를 유지합니다. Game 로어 검색은 별도로 켜야 하며 벡터 누락이나 비호환성을 알립니다. 로어북을 자동으로 벡터화하지는 않습니다.

## Functions 섹션

사용자 지정 도구는 **Presets**(프리셋) 패널에서 만들고 관리합니다.

1. 상단 바를 열고 **Presets**를 클릭하세요.
2. **Functions**(기능) 섹션을 찾으세요. 아이콘은 렌치 모양입니다.
3. 헤더 아래에 **Custom function calls available from Chat Settings**라는 설명이 보입니다.

섹션 헤더에는 아이콘 버튼이 세 개 있습니다.

- **Create function**(더하기 아이콘)은 비어 있는 도구 편집기를 엽니다.
- **Import functions from ZIP or JSON**(다운로드 아이콘)은 파일 선택 창을 엽니다.
- **Export functions to ZIP**(업로드 아이콘)은 만들어 둔 도구 전체를 파일 하나로 저장합니다. 도구가 하나도 없으면 회색으로 비활성화됩니다.

목록의 각 도구에는 이름과 작은 표시 두 개(유형, 파라미터 개수)가 나옵니다. 짧은 설명, 켜기/끄기 스위치, **Edit function**(함수 편집) 버튼, **Delete function**(함수 삭제) 버튼도 함께 표시됩니다. 서버에서 스크립트 도구를 꺼 놓았다면 **Script** 도구에는 주황색 **Script disabled** 표시가 붙습니다. 켜는 방법은 아래 실행 유형: Script에서 설명합니다. 손잡이를 끌어서 목록 순서를 바꿀 수 있습니다. 순서는 표시용일 뿐이라 동작에는 영향을 주지 않습니다. 도구가 아직 하나도 없으면 목록에 **No functions yet**이 표시됩니다.

도구 관리(만들기, 편집, 삭제, 순서 바꾸기, 켜기/끄기 스위치)는 앱의 보호된 영역을 사용합니다. 서버가 돌아가는 컴퓨터가 아닌 다른 기기에서 도구를 관리하려면 먼저 관리자 비밀 문자열을 저장해야 합니다. [서버 설정 참고 문서](../CONFIGURATION.md)와 아래 스크립트 안전 항목의 안내를 확인하세요.

## 도구 만들기

다음 순서대로 도구를 만드세요.

1. **Functions** 섹션에서 **Create function**을 클릭하세요. 전체 도구 편집기가 열립니다.
2. 맨 위 이름 입력란에 소문자 snake_case로 이름을 입력하세요. AI가 도구를 호출할 때 쓰는 이름과 정확히 같습니다. 올바른 이름은 소문자로 시작하고, 그다음부터는 소문자, 숫자, 밑줄만 사용합니다. 예: `check_weather`.
3. **Description**(설명) 입력란을 채우세요. AI가 이 글을 읽고 언제 도구를 호출할지 판단하므로, AI에게 주는 지시처럼 쓰세요. 예: `Get the current weather for a city the user names.`
4. 도구에 필요한 **Parameters**(파라미터)를 추가하세요(다음 항목 참고).
5. **Execution Type**(실행 유형)을 고르세요. **Static Result**, **Webhook**, **Script** 중 하나입니다.
6. 고른 유형에 해당하는 입력란을 채우세요.
7. **Save**(저장)를 클릭하세요. 버튼 근처에 초록색 **Saved** 표시가 잠깐 나타납니다.

알아 두면 좋은 규칙이 몇 가지 있습니다.

- 이름은 1자에서 100자까지, 설명은 1자에서 500자까지입니다.
- 두 도구가 같은 이름을 쓸 수 없습니다. 기본 제공 도구의 이름도 쓸 수 없습니다(아래 예약된 이름 참고).
- 저장하지 않은 변경 사항을 남긴 채 편집기를 벗어나면 **Keep editing**(계속 편집), **Discard**(변경 취소), **Save & close**(저장 & 닫기) 중에서 고르는 배너가 나타납니다.

## Parameters 빌더

파라미터는 AI가 도구를 호출할 때 함께 넘기는 입력값입니다. 각 파라미터에는 이름, 유형, 필수 여부, 설명이 있습니다.

1. **Parameters** 그룹에서 **Add Parameter**(매개변수 추가)를 클릭하세요.
2. `city`처럼 파라미터 이름을 입력하세요.
3. 드롭다운에서 유형을 고르세요. `string`, `number`, `boolean`, `array`, `object` 중 하나입니다.
4. AI가 이 값을 항상 보내야 한다면 **Required**(필수)를 켜세요.
5. 그 값이 무엇을 뜻하는지 AI에게 알려 주는 설명을 쓰세요. 예: `The city name to look up, such as Tokyo.`

**Add Parameter**로 줄을 더 추가하거나, 각 줄의 빼기 버튼으로 줄을 지울 수 있습니다. 이름이 비어 있는 줄은 저장할 때 사라집니다. AI는 파라미터 설명을 보고 무엇을 보낼지 배우므로, 설명을 잘 쓰는 것이 중요합니다.

도구가 도무지 호출되지 않는다면 파라미터 설정이 잘못된 경우가 많습니다. 대개는 파라미터 설정이 올바르지 않은, 손으로 고친 파일에서 도구를 가져올 때 생깁니다. 이럴 때 앱은 생성 과정에서 해당 도구를 조용히 건너뛰고 서버 로그에만 기록을 남깁니다.

## 실행 유형: Static Result

**Static Result** 도구는 AI가 호출할 때마다 정해진 문구를 그대로 돌려줍니다. 바깥 서비스가 필요 없어서 누구나 바로 쓸 수 있습니다. 카드에는 **Returns a fixed string when called.**라고 적혀 있습니다.

입력란은 여러 줄을 넣을 수 있는 **Static Result** 하나뿐입니다. 여기에 입력한 내용이 도구 호출 시 AI에게 돌아갑니다. 비워 두면 도구는 `OK`를 돌려줍니다.

예제를 보겠습니다. 파라미터 없이 `store_hours`라는 도구를 만드세요. **Static Result** 상자에 다음을 입력하세요.

```
We are open Monday to Friday, 9am to 5pm. We are closed on weekends.
```

이제 AI가 `store_hours`를 호출하면 그 문구를 받아서 영업시간을 알려 줄 수 있습니다. AI는 그 문구만 따로 보는 것이 아니라 도구 이름 및 자신이 보낸 인자와 함께 봅니다.

## 실행 유형: Webhook

**Webhook** 도구는 도구 호출 내용을 바깥 웹 주소로 보내고, 그 서비스의 답을 AI에게 돌려줍니다. 웹훅은 데이터를 받아서 데이터를 돌려주는 웹 주소입니다. 카드에는 **Sends a POST request to an external URL.**이라고 적혀 있습니다.

입력란은 **Webhook URL**(웹훅 URL) 하나뿐입니다. 앱은 그 주소로 POST 요청을 보냅니다. POST 요청은 웹 서비스에 데이터를 보내는 방식입니다. 요청 본문은 구조화된 데이터를 담는 일반 텍스트 형식인 JSON이며, 모양은 다음과 같습니다.

```
{ "tool": "your_tool_name", "arguments": { ... } }
```

서비스는 JSON이나 일반 텍스트로 답해야 합니다. 그 답이 AI에게 전달됩니다.

예제를 보겠습니다. `city`라는 필수 string 파라미터 하나를 가진 `check_weather` 도구를 만드세요. **Webhook URL** 입력란에는 직접 운영하는 서비스 주소를 넣습니다.

```
https://api.example.com/weather
```

AI가 `city`를 Tokyo로 지정해 `check_weather`를 호출하면, 서비스가 요청을 받아 날씨를 찾아보고 답을 돌려줍니다. AI는 그 답을 메시지에 활용합니다.

웹훅에 관해 알아 둘 점은 다음과 같습니다.

- 답의 크기는 512 KB로 제한됩니다.
- 호출마다 서버가 정한 시간 제한이 있습니다. 기본값은 60초입니다.
- 기본적으로 `https://` 주소만 허용됩니다. `localhost`나 가정용 네트워크 주소처럼 사설 주소와 로컬 주소는 차단됩니다. 로컬 주소를 허용하려면 서버 관리자가 설정을 켜야 합니다. [서버 설정 참고 문서](../CONFIGURATION.md)를 확인하세요.
- 호출이 실패하거나 시간이 초과되어도 채팅이 멈추지 않고 AI가 오류 결과를 받습니다.

## 실행 유형: Script

**Script** 도구는 서버에서 짧은 JavaScript 코드를 실행하고 결과를 돌려줍니다. JavaScript는 널리 쓰이는 프로그래밍 언어입니다. 카드에는 **Runs a JavaScript expression server-side.**라고 적혀 있습니다.

스크립트 도구는 안전을 위해 기본적으로 꺼져 있습니다. 서버에서 켜 놓지 않았다면 **Script** 카드가 회색으로 비활성화되고 경고가 나타납니다. 스크립트를 켜려면 서버 관리자가 서버의 `.env` 파일에 다음 줄을 넣고 앱을 다시 시작해야 합니다.

```
CUSTOM_TOOL_SCRIPT_ENABLED=true
```

입력란은 **Script Body**(스크립트 본문) 하나뿐입니다. 스크립트는 AI가 보낸 값인 `args`를 읽을 수 있고, 결과를 반드시 `return`해야 합니다. `JSON`, `Math`, `Date`도 사용할 수 있습니다.

예제를 보겠습니다. `x`와 `y`라는 필수 number 파라미터 두 개를 가진 `add_numbers` 도구를 만드세요. **Script Body** 상자에 다음을 입력하세요.

```
const result = args.x + args.y;
return { sum: result };
```

AI가 `x`를 2로, `y`를 3으로 지정해 `add_numbers`를 호출하면 도구는 합계 5를 돌려줍니다. 스크립트에서 오류가 나도 앱이 멈추지 않고 AI가 오류 결과를 받습니다. 스크립트를 켜기 전에 아래 스크립트 안전 항목을 읽어 보세요.

## 숨은 채팅 컨텍스트 함께 보내기

**Webhook** 도구와 **Script** 도구는 숨은 컨텍스트 객체를 받을 수 있습니다. 도구 입력값으로는 AI에게 보이지 않는 추가 채팅 데이터입니다. 도구 편집기에서 **Include hidden chat context**(숨겨진 채팅 컨텍스트 포함) 스위치를 켜세요. 기본값은 꺼짐입니다.

이 스위치를 켜면 웹훅이나 스크립트가 인자와 함께 `context` 값을 받습니다. 여기에는 채팅 모드, 사용 중인 페르소나 이름, 채팅에 등장하는 캐릭터 이름이 들어갈 수 있습니다. 저장된 채팅 변수와 Game Mode(게임 모드)의 게임 상태도 포함될 수 있습니다. 덕분에 AI가 그 데이터를 일일이 넘기지 않아도 도구가 결과를 상황에 맞게 다듬을 수 있습니다.

## 채팅에서 도구 사용 켜기

도구를 만들었다고 해서 AI가 바로 쓰지는 않습니다. 채팅에서 도구 사용도 켜야 합니다.

1. 채팅을 열고 톱니바퀴를 클릭해 **Chat Settings**(채팅 설정)를 여세요.
2. **Function Calling** 섹션을 여세요. 아이콘은 렌치 모양입니다.
3. **Enable Tool Use**(도구 사용 활성화)를 켜세요. 설명에는 **Allow AI to call functions (dice rolls, game state, etc.)**라고 적혀 있습니다. 새 채팅에서는 기본적으로 꺼져 있습니다.

**Enable Tool Use**를 켜고 아래에 도구를 따로 추가하지 않으면, 채팅은 전역으로 활성화된 도구를 모두 쓸 수 있습니다. 주사위 굴림이나 로어북 검색 같은 기본 제공 도구에 더해, **Functions** 섹션에서 켜 둔 사용자 지정 도구 전부가 여기에 해당합니다. 채팅에서 쓸 도구를 고른 것만으로 제한하려면 특정 도구를 추가하세요.

1. **Add Functions**(함수 추가)를 클릭하세요. 검색 상자가 있는 선택 창이 열립니다.
2. 원하는 도구를 체크하세요. 목록에는 기본 제공 도구와 직접 만든 사용자 지정 도구가 함께 나옵니다.
3. **Add Selected**(선택 항목 추가)를 클릭해 추가하세요.

도구를 하나라도 추가하면 그 채팅에서는 추가한 도구만 동작합니다. 선택 창에서 **New Custom Function**(새 사용자 지정 함수)을 클릭하면 도구 편집기로 바로 넘어갈 수도 있습니다. 선택 창의 검색 상자는 설명이 아니라 도구 이름만 검색합니다.

## 에이전트에 도구 붙이기

채팅 대신 에이전트에 도구를 줄 수도 있습니다. 에이전트는 로어북 관리자나 음악 선곡 담당처럼 생성 과정에서 함께 돌아가는 반자율 보조 기능입니다.

1. **Agents**(에이전트) 패널을 열고 에이전트를 하나 여세요.
2. **Tools / Function Calling**(도구 / 기능 호출) 그룹을 여세요.
3. 그 에이전트가 쓸 도구를 켜세요.

에이전트를 설정했더라도 채팅의 **Function Calling** 섹션에서 **Enable Tool Use**를 켜는 일은 그대로 해야 합니다. 문구에 관해 한 가지 짚어 둘 점이 있습니다. 에이전트 편집기 아래쪽 안내문에는 "Enable Function Calling"을 켜라고 적혀 있지만, 실제로 클릭하는 스위치의 이름은 **Enable Tool Use**입니다. 둘은 같은 컨트롤을 가리킵니다. 에이전트를 더 자세히 알아보려면 [사용자 지정 에이전트 만들기](../agents/custom-agents.md) 문서를 참고하세요.

## 스크립트 안전

**Script** 도구는 서버에서 실제 코드를 실행하므로 조심해서 다뤄야 합니다. 앱은 각 스크립트를 샌드박스 안에서 실행합니다. 샌드박스는 코드가 할 수 있는 일을 제한하는 격리 공간입니다. 제한은 다음과 같습니다.

- 네트워크 접근 불가. 스크립트는 인터넷이나 어떤 웹 주소도 호출할 수 없습니다.
- 파일 접근 불가. 스크립트는 서버의 파일을 읽거나 쓸 수 없습니다.
- 환경 변수와 서버의 비밀 정보에 접근할 수 없습니다.
- 시간 제한. 오래 도는 스크립트는 중단됩니다. 기본 제한은 60초입니다.

이 방식은 사고를 막고 네트워크 접근과 파일 접근을 차단합니다. 다만 운영체제 수준의 완전한 격리는 아닙니다. 도구를 만들 수 있는 사람이라면 서버의 CPU나 메모리를 낭비하는 스크립트를 작성할 여지가 남아 있습니다. 스크립트 도구는 믿을 수 있는 서버에서만 켜세요. 다른 사람이 작성한 스크립트 도구를 가져올 때는 특히 주의하세요.

다른 기기에서 도구를 관리하는 일도 보호되어 있습니다. 서버가 돌아가는 컴퓨터가 아니라면 **Settings**(설정) → **Advanced**(고급) → **Admin Access**(관리자 접근)에서 관리자 비밀 문자열을 저장하세요. 이 값은 서버 쪽 설정과 일치해야 합니다. 서버 쪽 설정은 [서버 설정 참고 문서](../CONFIGURATION.md)를 확인하세요.

## 내보내기와 가져오기

도구는 설치본 사이에서 옮길 수 있습니다.

- 도구 하나를 내보내려면 그 도구를 열고 **Export function**(함수 내보내기)을 클릭하세요. `.json` 파일로 저장됩니다.
- 도구 전체를 내보내려면 **Functions** 섹션에서 **Export functions to ZIP**을 클릭하세요.
- 가져오려면 **Import functions from ZIP or JSON**을 클릭하고 `.json` 또는 `.zip` 파일을 고르세요. 몇 개를 가져왔는지 메시지로 알려 줍니다.

가져온 Webhook 도구와 Script 도구는 파일이 두 권한 중 하나를 요청하더라도 항상 비활성화 상태로, **Include hidden chat context**는 꺼진 채로 저장됩니다. 가져오기가 끝나면 Marinara는 실행 유형, 해당하는 경우 웹훅 대상, 그리고 파일이 요청한 권한을 보여 줍니다. 가져온 실행형 도구를 하나씩 열어 내용을 확인한 뒤, 믿을 수 있을 때만 켜세요. Static 도구는 가져온 파일에 담긴 활성화 상태를 그대로 유지합니다.

가져오기는 기존 도구나 기본 제공 도구와 이름이 겹치는 도구를 건너뜁니다. 에이전트 패키지에는 사용자 지정 도구가 함께 담기지도, 함께 가져와지지도 않습니다. 믿을 수 있는 함수는 따로 내보내고, **Function Calls**에서 확인한 다음, 에이전트를 가져온 뒤 직접 붙이세요.

## 예약된 이름

사용자 지정 도구의 이름은 기본 제공 도구의 이름과 같을 수 없습니다. 기본 제공 이름에는 `roll_dice`, `update_game_state`, `set_expression`, `trigger_event`, `search_lorebook`, `web_search`, `update_about_me` 등이 있습니다. 이런 이름으로 저장하려고 하면 다음 메시지가 나옵니다.

```
"your_name" is a reserved built-in tool name.
```

사용자 지정 도구 두 개가 같은 이름을 쓸 수도 없습니다. 이름을 다시 쓰면 같은 이름의 도구가 이미 있다는 메시지가 나옵니다.

## 문제 해결

AI가 도구를 전혀 호출하지 않습니다.

- 채팅의 **Function Calling** 섹션에서 **Enable Tool Use**가 켜져 있는지 확인하세요.
- 채팅에 특정 도구를 추가했다면 만든 도구가 그 목록에 들어 있는지 확인하세요.
- **Functions** 섹션에서 해당 도구의 켜기/끄기 스위치가 켜져 있는지 확인하세요.
- AI가 언제 도구를 호출해야 할지 알 수 있도록 **Description**과 파라미터 설명을 더 분명하게 쓰세요.
- 도구를 가져왔다면 파라미터 설정이 잘못되어 앱이 건너뛰었을 수 있습니다. 파라미터를 직접 다시 만드세요.

Script 카드가 회색으로 비활성화되어 있습니다.

- 이 서버에서는 스크립트가 꺼져 있습니다. 관리자에게 `CUSTOM_TOOL_SCRIPT_ENABLED=true`를 설정하고 다시 시작해 달라고 요청하세요. [서버 설정 참고 문서](../CONFIGURATION.md)를 확인하세요.

웹훅이 실패하거나 시간이 초과됩니다.

- 주소가 `https://`로 시작하고 접속 가능한지 확인하세요.
- 관리자가 로컬 주소를 허용하지 않으면 로컬 주소는 차단됩니다. [서버 설정 참고 문서](../CONFIGURATION.md)를 확인하세요.
- 느린 서비스는 60초 시간 제한에 걸릴 수 있습니다.

휴대전화나 다른 기기에서 도구를 만들거나 편집할 수 없습니다.

- **Settings** → **Advanced** → **Admin Access**에서 서버와 일치하는 관리자 비밀 문자열을 저장하세요.
