# 생성 파라미터

생성 파라미터는 **Temperature**(온도)와 **Max Output Tokens**(최대 출력 토큰)처럼 모델이 답변을 쓰는 방식을 조절하는 설정입니다. 프리셋과 계정이 기본값을 제공하며, **Chat Settings**(채팅 설정)의 **Advanced Parameters**(고급 매개변수) 섹션에서 채팅 하나에 한해 덮어쓸 수 있습니다. 평범한 채팅과 롤플레이에는 기본값이 잘 맞으므로, 특정한 문제를 해결할 때만 바꾸세요.

## 찾는 위치

| 항목 | 위치 |
| --- | --- |
| 프리셋의 시작 값 | **Presets**(프리셋)에서 프리셋을 열고 **Parameters**(파라미터) 탭 |
| 계정에 저장된 값 | **Connections**(연결)에서 계정을 열고 **Chat defaults**(채팅 기본값) 섹션 |
| 채팅 하나의 덮어쓰기 | **Chat Settings**의 **Advanced Parameters** 섹션 |

프리셋은 컨텍스트나 출력 토큰 한도를 설정하지 않습니다. 컨텍스트 창은 **Connections**에서, 출력 한도는 **Connections**나 **Advanced Parameters**에서 설정하세요. 이전 프리셋 파일도 계속 불러올 수 있지만, 저장된 토큰 한도는 무시됩니다. 기본 제공 **Marinara's Universal Preset**(Marinara 범용 프리셋)은 생성 파라미터를 제공하지 않습니다.

채팅 하나의 파라미터를 덮어쓰려면 다음과 같이 하세요.

1. 채팅을 여세요.
2. **Chat Settings**를 여세요.
3. **Advanced Parameters**를 찾아 클릭해서 펼치세요.
4. **Temperature** 같은 파라미터를 찾아 새 값을 입력하세요.
5. 이름 옆의 작은 스위치를 확인하세요. 꺼져 있으면 켜세요. 스위치가 꺼진 파라미터는 전송되지 않으므로 값을 바꿔도 아무 효과가 없습니다. **Temperature**는 스위치가 꺼진 상태로 시작합니다([전송 스위치](#the-send-switch) 참고).

"Change generation settings for this chat only. Leave these alone unless you know what they do."라는 안내 문구가 보입니다. **Advanced Parameters**는 Conversation(대화), Roleplay(롤플레이), Game(게임) 채팅에서 쓸 수 있습니다.

## 파라미터별 쉬운 설명

숫자 파라미터마다 입력란과 전송 스위치가 하나씩 있습니다(아래 참고).

| 파라미터 | 하는 일 | 범위 |
| --- | --- | --- |
| **Temperature** | 무작위성입니다. 낮을수록 초점이 맞고 예측 가능해집니다. 높을수록 창의적이 됩니다. 1 근처가 흔히 쓰는 중간값입니다. | 0에서 2 |
| **Max Output Tokens** | 모델이 한 턴에 쓸 수 있는 가장 긴 답변입니다. 토큰은 글을 잘게 나눈 조각입니다. 답변이 잘리면 올리세요. | 정해진 상한 없음 |
| **Top P** | 모델은 확률이 가장 높은 단어들 중에서, 그 확률의 합이 이 값에 이를 때까지의 후보만 놓고 고릅니다. 1이면 모든 단어를 고려합니다. | 0에서 1 |
| **Top K** | 각 단계에서 확률이 가장 높은 몇 개의 단어로 후보를 제한합니다. 0이면 꺼집니다. 이 설정을 무시하는 서비스가 많습니다. | 0에서 500 |
| **Frequency**(빈도 패널티) | 이미 많이 나온 단어일수록 더 강하게 억제합니다. 양수 값은 같은 단어의 반복을 줄입니다. | -2에서 2 |
| **Presence**(존재 패널티) | 한 번이라도 나온 단어를 억제합니다. 양수 값은 새로운 화제로 옮겨 가게 합니다. | -2에서 2 |

**Frequency**와 **Presence**를 반복 페널티라고 합니다.

**Reasoning Effort**(추론 강도)는 사고가 가능한 모델에게 답하기 전에 얼마나 추론할지 알려 줍니다. 사고가 가능한 모델이란 먼저 감춰진 단계에서 문제를 풀어 보는 모델입니다. 선택지는 **Off**, **Low**(낮음), **Medium**(중간), **High**(높음), **Extra high**(매우 높음), **Maximum**(최대)입니다. 고른 단계를 모델이 지원하지 않으면 Marinara가 그 모델이 허용하는 가장 높은 단계로 낮춥니다. 모델을 고르면 버튼 이름이 그 모델이 받는 단계에 맞춰 바뀌므로, **Maximum**이 **Max**(최대), **Extra high**, **High**로 보일 수 있습니다.

- 전송 스위치가 켜져 있으면, 모델이 사고 끄기를 지원한다고 알려진 경우 **Off**는 서비스에 사고를 끄도록 요청합니다. 일부 모델은 사고를 끌 수 없어 여전히 추론을 돌려줄 수 있습니다. 사고가 반드시 없어야 한다면 추론 모델이 아닌 모델을 고르세요.
- 전송 스위치가 꺼져 있으면 추론에 관한 설정을 보내지 않고, 서비스가 자체 기본값을 씁니다.

**Verbosity**(상세도)는 답변의 길이와 자세함을 정합니다. 선택지는 **None**, **Low**, **Medium**, **High**입니다. 이 설정을 쓰는 모델은 일부뿐입니다.

## 조정 요령

무엇이 효과가 있었는지 알 수 있도록 한 번에 하나씩만 바꾸세요. 이것은 경험에서 나온 요령이며, 모델마다 다릅니다.

| 문제 | 시도해 볼 것 |
| --- | --- |
| 답변이 딱딱하거나 반복적입니다 | **Temperature**를 1.1에서 1.3 사이로 조금 올리세요. |
| 답변이 두서없거나 주제에서 벗어납니다 | **Temperature**를 0.7에서 0.9 사이로 낮추세요. |
| 답변이 잘립니다 | **Max Output Tokens**를 올리세요. |
| 캐릭터가 같은 표현을 반복합니다 | **Frequency**나 **Presence**를 0.3에서 0.6 사이로 조금 올리세요. |

어떤 메시지에 어떤 파라미터가 전송되었는지 보려면 **Peek Prompt**(프롬프트 미리보기)를 쓰세요. 조립된 프롬프트와 함께 모델, temperature, 최대 토큰, 추론 강도 등을 보여 줍니다.

## 전송 스위치

모든 숫자 파라미터와 **Reasoning Effort**, **Verbosity**에는 이름 옆에 작은 스위치가 있습니다. 글자 라벨은 없습니다. 마우스를 올리면 "This parameter is sent to the model" 또는 "This parameter is not sent to the model."이 표시됩니다.

- 켜짐: Marinara가 요청에 파라미터를 포함합니다.
- 꺼짐: Marinara가 파라미터를 빼고, 서비스가 자체 기본값을 씁니다. 0이나 1 같은 값을 지정하는 것과는 다릅니다. 값을 지정하면 무엇을 쓸지 서비스에 여전히 알려 주는 셈입니다.

서비스가 두 설정을 함께 쓸 수 없다고 할 때(하나를 끄세요), 또는 오류가 어떤 파라미터를 받을 수 없다고 하거나(끄세요) 반드시 필요하다고 할 때(켜세요) 이 스위치를 쓰세요.

채팅의 **Advanced Parameters**에서는 **Max Output Tokens**와 **Reasoning Effort**만 기본으로 전송됩니다.

## 기본값

아래 값은 편집기에 표시되는 값이며, 항상 그대로 전송되는 것은 아닙니다. 프리셋이 없으면 계정과 채팅의 덮어쓰기를 적용하기 전에 출력 4096토큰으로 생성을 시작합니다. 활성 장면에서는 8192를 쓸 수 있습니다. **Effective**(적용) 줄에는 최종적으로 결정된 값이 표시됩니다.

| 파라미터 | 시작 값 | 기본 전송 여부 |
| --- | --- | --- |
| Temperature | 1 | 아니요 |
| Max Output Tokens | Conversation은 4096, Roleplay는 8192; Game 덮어쓰기 없음 | 예 |
| Top P | 1 | 아니요 |
| Top K | 0(꺼짐) | 아니요 |
| Frequency | 0 | 아니요 |
| Presence | 0 | 아니요 |
| Reasoning Effort | Maximum | 예 |
| Verbosity | High | 아니요 |

전송 스위치가 꺼져 있어도 값은 입력란에 그대로 보입니다. 스위치를 켜기 전에는 전송되지 않습니다.

## 프리필과 추론 태그

**Assistant Prefill**(어시스턴트 프리필)은 AI 답변의 맨 앞에 덧붙이는 선택 사항 텍스트입니다. 모델이 지원하지 않는다면 비워 두세요.

- 프리필은 가장 마지막에 전송됩니다. 내 메시지와 그 뒤에 오는 모든 지시보다도 뒤입니다.
- 채팅이 AI 답변으로 끝나고 **Post-Processing Messages**(메시지 후처리)가 **Apply**(적용)이면, 프리필은 그 답변의 끝에 덧붙습니다.
- 일부 모델은 AI 자신의 말로 끝나는 프롬프트를 거부합니다. 어떤 모델을 쓰든 **Claude (Subscription)**도 여기에 해당합니다. 이런 모델에서는 Marinara가 프리필을 AI의 마지막 답변 맨 앞에 대신 덧붙이므로, 새 답변은 프리필로 시작하지 않습니다.
- 아직 AI 답변이 없는 채팅에서는 프리필이 맨 끝에 내 메시지로 전송됩니다.

**Assistant Reasoning Prefill**(어시스턴트 추론 프리필)은 화면에 보이는 답변보다 앞서, AI 추론의 맨 앞에 덧붙이는 선택 사항인 숨겨진 텍스트입니다. Kimi K3처럼 별도의 추론 프리필을 지원하는 모델에만 쓰세요. **Assistant Prefill**과 함께 쓸 수 있습니다.

**Thinking Tags**(추론 태그)는 모델이 일반 텍스트 안에서 감춰진 추론을 어떻게 표시하는지 Marinara에 알려 주어, 그 추론을 **View model thoughts**(모델의 생각 보기) 뒤에 숨길 수 있게 합니다. 한 줄에 감싸개 하나씩 적고, 가운데에 숨겨진 텍스트가 들어갈 자리를 두세요. think, thinking, thought, 파이프, 채널, 대괄호 쌍처럼 흔한 감싸개는 이미 인식합니다. 특이한 감싸개를 쓸 때만 필요합니다.

## Custom Parameters

**Custom Parameters**(사용자 지정 매개변수)를 쓰면 Marinara에 입력란이 없는 설정을 그대로 넣을 수 있습니다. JSON 객체를 입력하면 Marinara가 요청에 합쳐 줍니다.

- 계정 기본값으로 저장하면 그 계정을 쓰는 모든 텍스트 생성에 전송됩니다. Conversation, Roleplay, Game, Noodle, 요약, 에이전트, 설치한 에이전트 패키지가 모두 포함됩니다. 내 컴퓨터에서 돌아가는 사용자 지정 엔드포인트도 마찬가지입니다.
- 채팅별 Custom Parameters는 그 채팅에만 더해지며, 같은 키가 있으면 계정 값을 덮어씁니다.
- 키를 잘못 쓰면 서비스가 요청을 거부할 수 있습니다. `true`, `false`, `null`은 소문자로 쓰세요. 서비스의 가이드가 키를 넣으라고 안내하지 않는 한 비워 두세요.

## Service Tier

**Service Tier**(서비스 티어)는 채팅의 계정이 OpenRouter나 NanoGPT를 쓸 때만 나타납니다. 서비스가 요청을 어떤 경로로 처리할지 고릅니다. **Default**(기본값)는 티어를 보내지 않습니다. **Flex**는 더 저렴하지만 느릴 수 있습니다. **Priority**는 더 빠르지만 비용이 더 들 수 있습니다.

## 컨텍스트 메시지 제한

**Limit Context Messages**(메시지 컨텍스트 제한)는 채팅 전체 대신 마지막 N개의 메시지만 보냅니다. **Context message limit**(컨텍스트 메시지 제한)이라는 라벨로도 표시됩니다. 기본값은 꺼짐입니다. 켜면 개수가 50에서 시작하고, 1에서 9999까지 지정할 수 있습니다. 숫자가 작을수록 비용이 낮아지고 속도가 빨라지지만, AI가 기억하는 내용도 줄어듭니다.

**Advanced Memory Recall**(고급 기억 회상)을 켠 Roleplay 채팅에서는 이 제한을 쓰지 않습니다. Advanced Memory Recall은 **Maximum allowed context before compression (tokens)**(압축 전 최대 허용 컨텍스트)로 보낼 기록의 양을 정합니다. 보내는 기록을 줄이려면 **Chat Settings → Memory Recall**(채팅 설정 → 기억 회상)에서 그 설정을 낮추세요. [Advanced Memory Recall](../agents/memory.md#advanced-memory-recall-roleplay-and-game-mode)을 참고하세요.

## Exclude Past Reasoning

**Exclude Past Reasoning**(과거 추론 제외)은 기본적으로 켜져 있습니다. 이전 턴에 저장된 추론을 새 프롬프트에서 뺍니다. 예전 추론을 모델에 다시 넣어야 할 분명한 이유가 없다면 켜 두세요.

이 옵션을 끄면 **Past reasoning blocks**(이전 추론 블록)가 표시됩니다. 기본값은 1이며, 사용 가능한 가장 최근 추론 블록 하나를 유지합니다. 0이면 사용 가능한 모든 블록을 포함합니다. 저장된 생각이 삭제되지는 않으며, 현재 계정이 지원하는 추론만 다시 보낼 수 있습니다.

## Image captioning

**Image captioning**(이미지 캡셔닝)을 켜면 Marinara가 이미지를 보내는 대신 다른 모델로 첨부된 이미지를 하나씩 글로 설명합니다. 이미지를 볼 수 없는 모델에 쓰세요. 기본값은 꺼짐입니다.

1. **Advanced Parameters**에서 **Image captioning**을 켜세요.
2. **Captioning model**(캡션 연결) 드롭다운에서 모델을 고르세요.
3. 필요하면 이미지마다 함께 보내는 지시인 **Captioning Prompt**(캡션 프롬프트)를 고치세요. 초기화 버튼을 누르거나 입력란을 비우면 기본값으로 돌아갑니다. 프롬프트는 이 채팅에만 저장되며, **Save as Connection Default**(연결 기본값으로 저장)로는 복사되지 않습니다.

작동하지 않는 경우: 캡션 계정이 고장 났거나 삭제되었거나 아무것도 돌려주지 않아서 캡션 생성에 실패하면, 답변이 **Image captioning failed** 오류와 함께 중단됩니다. Marinara가 이미지를 대신 보내지는 않습니다. 캡션 모델을 고치거나 바꾸거나, **Image captioning**을 끄세요.

## Save as Connection Default

**Advanced Parameters** 맨 아래의 **Save as Connection Default**는 현재 값을 계정에 기록합니다. 그 뒤로 그 계정을 쓰는 새 채팅은 이 값에서 시작합니다. 이 버튼은 저장된 일반 계정에만 나타납니다. 무작위 풀과 내장 모델에서는 보이지 않습니다.

**Reset to Defaults**(기본값으로 초기화)는 채팅별 변경을 모두 지우고 채팅을 상속된 설정으로 되돌립니다. 상속된 전송 스위치는 선택한 계정을 따릅니다. 직접 바꾼 전송 스위치는 초기화할 때까지 채팅별 덮어쓰기로 남습니다.

## 기본값이 겹치고 덮어쓰이는 순서

Marinara는 각 파라미터를 다음 목록 순서로 결정합니다. 뒤의 항목이 앞의 항목을 덮어씁니다.

1. 프리셋의 **Parameters**. 프리셋을 쓰지 않으면 내장 기본값입니다. 프리셋은 출력 한도를 설정할 수 없으므로 출력은 4096토큰에서 시작합니다. Roleplay에서는 계정의 프리셋 덮어쓰기가 채팅에서 선택한 프리셋보다 우선합니다.
2. 계정의 **Chat defaults**.
3. 이 채팅의 **Advanced Parameters**.
4. 모드 규칙. 활성 장면 채팅은 출력을 8192, 추론을 **Maximum**, 상세도를 **High**로 설정합니다. Game은 저장된 계정 및 채팅 파라미터를 쓰며, 샘플링, 추론, 최소 출력 크기를 강제하지 않습니다.
5. 출력 한도. Game은 모델의 알려진 출력 한도를 적용하고, 계정의 **Max output tokens override**(최대 출력 토큰 재정의)는 모든 모드에서 요청을 제한합니다. 사용 가능한 컨텍스트에 따라 예산이 더 줄어들 수 있습니다.

파라미터 옆의 **Effective** 줄에는 최종적으로 적용되는 값과 그 값이 나온 계층이 표시됩니다. 예를 들어 **Effective: 16384 · this chat**으로 표시되거나, 계정 상한이 적용되면 **Effective: 4096 · output token cap**으로 표시됩니다. 전송 스위치를 끄면 **not sent**(전송되지 않음)로 표시됩니다. 그래도 서비스는 파라미터를 요구하거나 지원하지 않는 값을 조정할 수 있습니다. Custom Parameters와 컨텍스트 맞춤 과정에서 최종 요청이 바뀔 수도 있습니다. 채팅 파라미터를 초기화하면 이 채팅의 덮어쓰기(3번 항목)만 지워집니다. 그러면 값은 계정의 **Chat defaults**가 설정되어 있으면 거기서, 아니면 프리셋에서 옵니다. 모드 규칙과 출력 한도(4번과 5번 항목)는 그 뒤에도 적용됩니다.

## 에이전트용 파라미터

에이전트 호출은 실행에 쓰는 계정에 저장된 **Chat defaults**를 따릅니다. 에이전트 자체 계정을 쓰며, 에이전트에 계정이 없으면 채팅의 계정을 씁니다. 전송 스위치와 모델 한도는 채팅 답변과 똑같이 적용됩니다. 아래의 온도 규칙을 제외하면, 프리셋과 채팅의 **Advanced Parameters**는 에이전트 호출을 바꾸지 않습니다.

- **에이전트에 전송하는 설정:** Temperature, Top P, Top K, Frequency, Presence, Reasoning Effort, Verbosity, Service Tier, Custom Parameters, 사용자 지정 헤더, 그리고 **Settings**(설정), **Advanced**(고급), **Parameters** 순서로 열어 추가한 추가 파라미터(Top A나 시드 등)입니다. 전송 스위치가 꺼진 파라미터는 전송하지 않습니다.
- **에이전트에 전송하지 않는 설정:** Max Output Tokens, 정지 시퀀스, 프리필, Thinking Tags와 그 밖의 프롬프트 형식 설정입니다. 각 에이전트는 자신의 **Max Output Tokens**를 유지합니다.
- **Temperature:** 에이전트는 계정의 온도를 쓰며, 저장된 값이 없으면 0.7을 씁니다. Beholder는 항상 0을 쓰고, Illustrator의 프롬프트 작성기는 자체 값을 씁니다. 채팅 답변 중에는 채팅 계정을 쓰는 에이전트가 채팅에서 결정된 온도와 전송 스위치를 따릅니다. 재시도에는 계정에 저장된 값을 씁니다.
- **Reasoning Effort:** 고른 단계나 **Off**는 그 계정에서 이 설정을 받는 모델을 쓰는 모든 에이전트에 적용됩니다. **Use custom defaults for this model**(이 연결에 사용자 지정 기본값 사용)을 쓰면 대부분의 계정에서 Reasoning Effort가 **Maximum**으로 시작합니다(Codex에서는 **Default**). 그래서 에이전트가 가장 높은 단계로 사고하며, 시간이 더 걸리고 비용도 더 듭니다. 사고를 줄이려면 더 낮은 단계를 고르거나 전송 스위치를 끄세요. 저장된 단계가 없으면 JSON으로 답하는 에이전트는 사고를 끄도록 요청하고, 다른 에이전트는 모델 기본값을 그대로 둡니다. Gemini 4 Argon과 Carbon은 사고를 끌 수 없으므로 Google AI Studio와 Vertex에서는 해당 에이전트가 대신 **Medium**을 전송합니다.
- **추론용 여유 공간:** 계정에 Reasoning Effort가 저장되어 있거나 모델이 Gemini 4 Argon 또는 Carbon이면, Marinara는 계정의 출력 상한, 모델 한도, 남은 컨텍스트 범위 안에서 에이전트의 **Max Output Tokens**에 추론용 여유를 더합니다. 사용자 지정 엔드포인트는 단계를 전송하지 않을 때도 이 여유를 받습니다.

설치한 에이전트 패키지도 같은 계정 값을 따릅니다. 계정이 저장하고 전송하는 값은 패키지가 요청한 값을 대신하며, 설정하지 않은 항목은 패키지 자체 설정을 유지합니다. 계정에서 꺼 둔 **Reasoning Effort**나 **Max Output Tokens**는 패키지가 요청해도 전송하지 않습니다. Temperature와 Verbosity는 꺼진 상태로 시작하므로 패키지 자체 값이 유지됩니다.

## 일부 파라미터를 무시하는 모델도 있습니다

모든 모델이 모든 파라미터를 받아들이지는 않습니다. 어떤 모델이 설정을 거부한다는 사실을 Marinara가 알고 있으면 그 설정을 요청에서 뺍니다. 컨트롤은 그대로 보이지만, 값을 바꿔도 아무 효과가 없습니다. temperature 같은 샘플링 설정을 거부하는 추론 모델에서 흔한 일입니다. 매번 답하는 모델이 바뀌는 자동 라우팅 모델을 쓰면 파라미터가 턴마다 다르게 동작할 수 있습니다. 동작을 일정하게 유지하려면 모델 하나를 고정하세요.
