# Marinara Engine को अपडेट करना

इस गाइड में बताया गया है कि Marinara Engine को नए वर्ज़न पर कैसे अपडेट करें। इसमें हर तरह के इंस्टॉल, ऐप के अंदर मौजूद अपडेट टूल, और अपडेट फ़ेल होने पर क्या करें, सब शामिल है। अपडेट के बाद भी आपकी चैट और सेटिंग्स वैसी ही रहती हैं।

## आपका डेटा सुरक्षित रहता है

अपडेट करने से Marinara Engine आपका डेटा नहीं मिटाता। चैट, कैरेक्टर, पर्सोना, लोरबुक, प्रीसेट, कनेक्शन और सेटिंग्स सब अपनी जगह बनी रहती हैं।

Marinara आपका डेटा उसी मशीन के एक लोकल डेटा फ़ोल्डर में रखता है जिस पर सर्वर चलता है। Docker और Podman इसे `marinara-data` वॉल्यूम में रखते हैं। अपडेट सिर्फ़ ऐप का कोड बदलता है, यह डेटा फ़ोल्डर या वॉल्यूम नहीं।

अगर पुराने वर्ज़न में फ़र्स्ट-पार्टी एजेंट, मैप, कॉल या Conversation गेम साथ आते थे, तो अपडेट के बाद पहली शुरुआत पर उनके मिलते-जुलते वैकल्पिक पैकेज आधिकारिक कैटलॉग से डाउनलोड हो जाते हैं। चैट में किए गए चुनाव, एजेंट की सेटिंग्स, सेव किया हुआ रनटाइम डेटा और हिस्ट्री सब बनी रहती है। उस पहली शुरुआत के समय सर्वर को ऑनलाइन रखें। कैटलॉग तक पहुँच न बने, तो Marinara आपका सेव किया हुआ कॉन्फ़िगरेशन मिटाने या बंद करने के बजाय अगली शुरुआत पर माइग्रेशन दोबारा आज़माता है।

अगर आप कोई डाउनलोड की हुई डॉक्यूमेंटेशन भाषा इस्तेमाल करते हैं (**Settings** (सेटिंग्स) → **General** → **Documentation Language**), तो अपडेट के बाद पहली शुरुआत पर उस भाषा पैक में बदलाव भी जाँचे जाते हैं और वह अपने आप रिफ़्रेश हो जाता है। डाउनलोड सोर्स तक पहुँच न बने, तो Marinara आपका इंस्टॉल किया हुआ पैक वैसा ही रखता है (जो गाइड उसमें नहीं हैं, वे अंग्रेज़ी में दिखती हैं) और अगली शुरुआत पर दोबारा कोशिश करता है। भाषा का आपका चुनाव किसी अपडेट से कभी रीसेट नहीं होता।

आपका डेटा कहाँ रहता है और उसकी कॉपी कैसे सेव करें, यह जानने के लिए देखें [Marinara का बैकअप और रिस्टोर](data/backup-and-restore.md)।

## पहले बैकअप लें

अपडेट सुरक्षित हैं, फिर भी बैकअप रख लेना समझदारी है। दो वर्ज़न के बीच बड़ी छलाँग से पहले एक बैकअप ज़रूर बना लें।

1. **Settings** खोलें।
2. **Advanced** टैब पर जाएँ।
3. **Backup & Export** सेक्शन ढूँढें।
4. **Download Backup** पर क्लिक करें।
5. `.zip` फ़ाइल किसी सुरक्षित जगह सेव करें।

काम चलने के दौरान बटन बदलकर **Creating backup…** दिखता है। पूरा होने पर ब्राउज़र आपके डेटा का `.zip` आर्काइव सेव कर देता है।

बैकअप और रिस्टोर के पूरे स्टेप यहाँ हैं: [Marinara का बैकअप और रिस्टोर](data/backup-and-restore.md)।

## प्लैटफ़ॉर्म के हिसाब से अपडेट

वही सेक्शन चुनें जो आपके Marinara इंस्टॉल करने के तरीके से मेल खाता हो। नीचे "git checkout" का मतलब है Git टूल से इंस्टॉल की गई कॉपी। "clone" यानी Git से डाउनलोड की गई कॉपी।

### Windows

Windows इंस्टॉलर या git checkout इस्तेमाल किया हो, तो लॉन्चर आपको अपने आप अपडेट कर देता है।

1. Marinara Engine बंद करें।
2. इसे Start Menu शॉर्टकट से दोबारा खोलें, या `start.bat` चलाएँ।

लॉन्चर नया कोड लाता है, जो बदला है उसे दोबारा इंस्टॉल करता है, ऐप को फिर से बनाता है और नया वर्ज़न शुरू कर देता है। यह इंस्टॉलर और मैन्युअल clone, दोनों पर काम करता है।

सिर्फ़ एक बार शुरू करने के लिए `start.bat --skip-update` चलाएँ। हर बार शुरू करने पर इंस्टॉल किया हुआ Engine वर्ज़न बनाए रखना हो, तो प्रोजेक्ट के `.env` में `AUTO_UPDATE_ENABLED=false` सेट करें। इससे सिर्फ़ अपने आप होने वाले Engine अपडेट बंद होते हैं; मैन्युअल कमांड और **Settings → Advanced → Check for Updates** पहले जैसे उपलब्ध रहते हैं।

लॉन्चर कहे कि Node.js बहुत पुराना है, तो Node.js 24 LTS इंस्टॉल करें और Marinara दोबारा शुरू करें। LTS यानी Long Term Support, Node.js का सुझाया गया स्थिर रिलीज़।

सबसे नया इंस्टॉलर GitHub Releases पेज से डाउनलोड करके भी चला सकते हैं। वह भी वही git वाला रास्ता इस्तेमाल करता है, इसलिए आगे के अपडेट लॉन्चर से ही होते रहेंगे।

### macOS और Linux

Marinara Engine बंद करें, फिर अपने Marinara फ़ोल्डर से लॉन्चर चलाएँ।

```bash
./start.sh
```

लॉन्चर नया कोड लाता है, बदली हुई डिपेंडेंसी दोबारा इंस्टॉल करता है, ऐप फिर से बनाता है और नया वर्ज़न शुरू कर देता है।

सिर्फ़ एक बार के लिए `./start.sh --skip-update` इस्तेमाल करें, या हमेशा के लिए बंद रखना हो तो `.env` में `AUTO_UPDATE_ENABLED=false` सेट करें। मैन्युअल अपडेट कमांड और ऐप के अंदर के अपडेट कंट्रोल पहले जैसे उपलब्ध रहते हैं।

Node.js के बहुत पुराने होने का संदेश दिखे, तो Node.js 24 LTS इंस्टॉल करें और लॉन्चर दोबारा चलाएँ।

### Docker या Podman

कंटेनर वाले इंस्टॉल नई इमेज खींचकर अपडेट होते हैं, लॉन्चर से नहीं। यह कमांड उसी फ़ोल्डर से चलाएँ जिसमें आपकी Compose फ़ाइल है।

```bash
docker compose down && docker compose pull && docker compose up -d
```

Podman के लिए वही कमांड `podman` के साथ इस्तेमाल करें।

```bash
podman compose down && podman compose pull && podman compose up -d
```

रिलीज़ इमेज `ghcr.io/pasta-devs/marinara-engine:X.Y.Z` और `:latest` के नाम से पब्लिश होती हैं, साथ में उनसे मिलते `-lite` टैग भी। जान-बूझकर किसी पुराने रिलीज़ पर न रहना हो, तो `:latest` या सबसे नया वर्ज़न टैग खींचें। `marinara-data` वॉल्यूम में रखे आपके डेटा को pull छूता तक नहीं।

### Android (Termux)

Termux, Android के लिए एक टर्मिनल और Linux एनवायरनमेंट है। इसका लॉन्चर हर बार चलाने पर Marinara को अपडेट कर देता है।

1. Termux खोलें।
2. लॉन्चर चलाएँ।

```bash
cd Marinara-Engine
./start-termux.sh
```

लॉन्चर कोड अपडेट करता है, ज़रूरत पड़ने पर Node.js को नया करता है, ऐप फिर से बनाता है और लोकल सर्वर शुरू कर देता है।

कोई अपडेट खराब निकले और आपको अपनी मौजूदा कॉपी पर ही रुकना हो, तो अपडेट जाँच को छोड़ दें।

```bash
cd Marinara-Engine
./start-termux.sh --skip-update
```

हमेशा के लिए बंद रखना हो, तो प्रोजेक्ट के `.env` में `AUTO_UPDATE_ENABLED=false` सेट करें। इसका असर सिर्फ़ लॉन्चर वाले Engine अपडेट पर पड़ता है; मैन्युअल अपडेट और ऐप के अंदर के अपडेट कंट्रोल पहले जैसे उपलब्ध रहते हैं।

Android ऐप आइकन (यानी APK) इस्तेमाल करते हों, तो [नया APK डाउनलोड करें](https://github.com/Pasta-Devs/Marinara-Engine/releases/latest/download/marinara-engine-android.apk) और डाउनलोड की गई फ़ाइल खोलें, ताकि Android रैपर ऐप को अपडेट करे। फिर Marinara Engine खोलकर **Install / Start Marinara** टैप करें, जिससे पीछे की Termux कॉपी अपडेट होकर शुरू हो। ऐप अपना निजी localhost क्रेडेंशियल अपने-आप बचाकर अदला-बदली करता है; अपडेट कभी साइनिंग क्रेडेंशियल या वह सीक्रेट नहीं माँगता।

### iPhone और iPad

iPhone और iPad पर Marinara सर्वर नहीं चलता। वे Safari के ज़रिए किसी दूसरे डिवाइस पर चल रहे सर्वर को खोलते हैं। Home Screen वाली कॉपी एक PWA है, यानी Progressive Web App। PWA एक वेबसाइट होती है जिसे Home Screen पर जोड़ लेने से वह ऐप की तरह खुलती है।

1. वह कंप्यूटर, Docker होस्ट या Android डिवाइस अपडेट करें जिस पर असल में आपका Marinara सर्वर चलता है। उसी डिवाइस का ऊपर वाला सेक्शन देखें।
2. अपने iPhone या iPad पर Home Screen वाला PWA या Safari टैब दोबारा लोड करें।

होस्ट अपडेट होने के बाद भी Safari पुराना बिल्ड दिखाता रहे, तो कैश की हुई कॉपी रीसेट करें।

1. Home Screen आइकन हटाएँ।
2. Marinara होस्ट के लिए Safari का वेबसाइट डेटा क्लियर करें।
3. इसे दोबारा Home Screen पर जोड़ें।

## ऐप के अंदर अपडेट जाँचना और लगाना

Marinara ऐप के अंदर से ही GitHub पर नया वर्ज़न जाँच सकता है। कुछ इंस्टॉल तो ब्राउज़र से ही अपडेट लगा भी सकते हैं।

1. **Settings** खोलें।
2. **Advanced** टैब पर जाएँ।
3. **Updates** सेक्शन ढूँढें।

### Release Channel

**Release Channel** ड्रॉपडाउन तय करता है कि आप कौन से बिल्ड पर नज़र रखेंगे। इसमें दो विकल्प हैं।

- **Latest Stable**: `vX.Y.Z` टैग वाले रिलीज़ पर चलता है। ज़्यादातर लोगों के लिए यही सामान्य विकल्प है।
- **Staging/UAT**: टेस्टर के लिए बने प्री-रिलीज़ बिल्ड पर चलता है। ये अधूरे हो सकते हैं। इन्हें इस्तेमाल करने से पहले अपना डेटा बैकअप कर लें।

**Staging/UAT** चुनने पर एक चेतावनी दिखती है: "Staging builds are pre-release tester builds. Back up your app data before applying them."

चैनल बदलना जान-बूझकर लिया गया फ़ैसला माना जाता है। सर्वर वाली मशीन के ब्राउज़र से कोई दूसरा चैनल चुनने पर अपडेट बटन बदलकर **Switch to** और उसके आगे चैनल का नाम दिखाने लगता है, और यह तब भी काम करता है जब ऐप के अंदर के सामान्य अपडेट बंद हों। चलते समय वह **Switching…** दिखाता है। एक ही चैनल के सामान्य अपडेट के लिए नीचे Apply Update में बताया गया सेटअप अब भी ज़रूरी है, और रिमोट डिवाइस के लिए तो हमेशा।

### Check for Updates

**Check for Updates** पर क्लिक करें। काम चलने के दौरान बटन **Checking…** दिखाता है।

बटन के नीचे आपका **Release** वर्ज़न और **Build** कमिट कोड दिखता है। ब्रांच पता हो, तो एक **Branch** पंक्ति भी आती है।

- आप नए वर्ज़न पर हों, तो हरे टिक वाली पंक्ति आपके वर्ज़न के साथ "You're on the latest ... target" कहती है।
- नया वर्ज़न मौजूद हो, तो एक कार्ड "vX.Y.Z available" और साथ में **Release notes** लिंक दिखाता है।
- git इंस्टॉल सिर्फ़ पीछे छूटा हो, तो कार्ड उसकी जगह "N commits behind" दिखाता है। कमिट यानी कोड में सेव किया गया एक बदलाव, इसलिए इस गिनती में बिना रिलीज़ हुआ काम भी शामिल हो सकता है।

अपडेट जाँच के नतीजे कैश होते हैं। रिलीज़ वर्ज़न की जाँच लगभग 15 मिनट तक कैश रहती है। "commits behind" की गिनती लगभग 5 मिनट तक कैश रहती है। तुरंत दोबारा **Check for Updates** पर क्लिक करने पर वही आँकड़े दिख सकते हैं।

### Apply Update

**Apply Update** बटन सिर्फ़ तभी दिखता है जब आपका इंस्टॉल ब्राउज़र से ही खुद को अपडेट कर सकता हो। इसके लिए ये दोनों बातें ज़रूरी हैं।

- इंस्टॉल git वाला हो (Docker और पैकेज किए हुए इंस्टॉल इस तरह अपडेट नहीं हो सकते)।
- सर्वर के मालिक ने सर्वर की `.env` फ़ाइल में `UPDATES_APPLY_ENABLED=true` सेट किया हो। `.env` फ़ाइल में सर्वर की सेटिंग्स रहती हैं।

सर्वर वाली मशीन पर ही **Apply Update** क्लिक करें, तो इतना ही काफ़ी है। वहाँ किसी सीक्रेट की ज़रूरत नहीं पड़ती।

किसी दूसरे डिवाइस से अपडेट लगाना डिफ़ॉल्ट रूप से बंद रहता है। इसके लिए ये तीनों बातें ज़रूरी हैं।

- सर्वर के मालिक ने `.env` में `UPDATES_ALLOW_REMOTE_APPLY=true` सेट किया हो।
- सर्वर के मालिक ने `.env` में `ADMIN_SECRET` (सुरक्षित कामों के लिए एक पासवर्ड) सेट किया हो।
- आपने वही सीक्रेट अपने डिवाइस पर **Settings -> Advanced -> Admin Access** में सेव किया हो।

**Apply Update** पर क्लिक करने पर बटन **Updating...** दिखाता है। सर्वर नया कोड लाता है, डिपेंडेंसी दोबारा इंस्टॉल करता है, ऐप फिर से बनाता है और फिर बंद हो जाता है। इसके बाद दिखता है: "Update applied successfully. Please relaunch the app to use the new version." काम पूरा करने के लिए Marinara दोबारा शुरू करें।

**Apply Update** उपलब्ध न हो, तो Marinara बताता है कि ऐसा क्यों है और उसकी जगह क्या करें।

- कंटेनर वाले इंस्टॉल इमेज टैग और होस्ट पर चलाने वाला `docker compose pull && docker compose up -d` कमांड दिखाते हैं।
- जिन git इंस्टॉल में apply बंद है, वे कॉपी करने लायक एक मैन्युअल अपडेट कमांड दिखाते हैं।
- बाकी इंस्टॉल GitHub रिलीज़ का **Download** लिंक दिखाते हैं।

जाँच खुद ही फ़ेल हो जाए, तो दिखता है: "Could not check for updates. Try again later." इसकी वजह आम तौर पर नेटवर्क या GitHub की कोई दिक्कत होती है, इसलिए थोड़ी देर बाद दोबारा कोशिश करें।

## Refresh App बटन

**Refresh App** बटन उसी **Updates** सेक्शन में रहता है। यह सर्वर का अपडेट नहीं है। यह सिर्फ़ आपके मौजूदा ब्राउज़र में ऐप को रिफ़्रेश करता है।

**Refresh App** सर्विस वर्कर का रजिस्ट्रेशन हटाता है, ब्राउज़र के कैश साफ़ करता है और फिर पेज दोबारा लोड कर देता है। सर्विस वर्कर एक छोटी स्क्रिप्ट है जिससे ब्राउज़र ऐप को तेज़ी से और ऑफ़लाइन भी लोड करता है। आपकी सेव की हुई चैट, सेटिंग्स और बाकी लोकल डेटा जस का तस रहता है।

**Refresh App** तब इस्तेमाल करें जब अपडेट के बाद ऐप पुराना दिखे या खाली स्क्रीन दिखाए, जबकि सर्वर पर नया वर्ज़न पहले से चल रहा हो। यह अटके हुए वेब पेज को ठीक करता है। यह सर्वर का कोड नहीं बदलता, इसलिए असली अपडेट की जगह नहीं ले सकता।

काम चलने के दौरान बटन **Refreshing…** दिखाता है, फिर ऐप दोबारा लोड हो जाता है।

## पुराने वर्ज़न पर वापस जाना

Upgrade हमेशा सुरक्षित होते हैं, लेकिन सीधे पीछे जाना हमेशा संभव नहीं होता। Marinara के नए वर्ज़न चैट संदेशों को डिस्क पर नए फ़ॉर्मेट में रखते हैं, और डेटा फ़ॉर्मेट से पुराना वर्ज़न उसे पढ़ नहीं सकता। आपकी चैट हिस्ट्री बचाने के लिए लॉन्चर असंगत वर्ज़न पर ले जाने वाली auto-update छोड़ देता है, और इन-ऐप updater उसे लगाने से मना कर देता है।

अगर फिर भी पुराने वर्ज़न की ज़रूरत है, तो एक कमांड पहले डेटा को पुराने फ़ॉर्मेट में बदल देती है। चरणों के लिए [पुराने वर्ज़न पर जाने के बाद चैट में संदेश नहीं दिखते](TROUBLESHOOTING.md#chats-show-no-messages-after-switching-to-an-older-version) देखें।

## अपडेट फ़ेल हो जाए तो

अपडेट की ज़्यादातर दिक्कतें पुराने Node.js वर्ज़न, अधूरे डाउनलोड या ब्राउज़र के पुराने कैश से आती हैं।

- लॉन्चर बताए कि Node.js बहुत पुराना है, तो Node.js 24 LTS इंस्टॉल करें और दोबारा शुरू करें।
- सर्वर अपडेट होने के बाद ऐप टूटा हुआ दिखे, तो ऊपर बताया **Refresh App** बटन आज़माएँ।
- git इंस्टॉल साफ़-सुथरे तरीके से अपडेट न हो पाए, तो अपने प्लैटफ़ॉर्म की इंस्टॉल गाइड में दिए मैन्युअल अपडेट कमांड चलाएँ।

एरर संदेश और स्टेप-दर-स्टेप हल के लिए देखें [Marinara Engine की समस्याएँ सुलझाना](TROUBLESHOOTING.md)।
