# कंटेनर से चलाना (Docker / Podman)

इस गाइड में बताया गया है कि Marinara Engine को Docker या Podman के कंटेनर में कैसे चलाया जाता है। कंटेनर यानी एक अपने-आप में पूरा पैकेज, जिसमें ऐप और उसे चलने के लिए ज़रूरी सारी चीज़ें एक साथ आती हैं। Node.js या दूसरे टूल अपने कंप्यूटर पर इंस्टॉल करने की ज़रूरत नहीं पड़ती। अगर आप नए हैं और बस Marinara चलाना चाहते हैं, तो यही सबसे आसान रास्ता है।

## पहले से क्या चाहिए

शुरू करने से पहले, जिस मशीन पर Marinara चलेगा उस पर इनमें से कोई एक इंस्टॉल करें:

- Docker Desktop (Windows या macOS) या Docker Engine (Linux)। Docker सबसे आम कंटेनर टूल है।
- या फिर Podman। Podman सीधे Docker की जगह ले लेता है। यह किसी बैकग्राउंड सेवा के बिना चलता है और रूट एक्सेस के बिना भी अच्छा काम करता है।

नीचे इस्तेमाल हुए कुछ शब्द:

- **Image** (इमेज): डाउनलोड होने वाला, सिर्फ़ पढ़ा जा सकने वाला टेम्पलेट, जिसमें Marinara Engine होता है। इमेज को चलाने पर चालू कंटेनर बनता है।
- **Volume** (वॉल्यूम): स्टोरेज की एक जगह, जिसे कंटेनर टूल खुद संभालता है। कंटेनर मिटाकर दोबारा बनाने पर भी वॉल्यूम में आपका डेटा बचा रहता है।
- **LAN**: आपका लोकल नेटवर्क (घर या दफ़्तर का Wi-Fi या तार वाला नेटवर्क)।

Marinara की आधिकारिक इमेज `ghcr.io/pasta-devs/marinara-engine` पर पब्लिश होती हैं।

## पुल करना और चलाना

रिपॉज़िटरी में प्रोजेक्ट की रूट में तैयार `docker-compose.yml` फ़ाइल पहले से मौजूद है। Compose इसी फ़ाइल को पढ़कर कंटेनर चालू कर देता है। Marinara चलाने का यही सुझाया हुआ तरीका है।

1. रिपॉज़िटरी की एक कॉपी लें। अगर Marinara Engine का चेकआउट पहले से है, तो उसी फ़ोल्डर में टर्मिनल खोलें। नहीं तो पहले क्लोन करें:

```bash
git clone https://github.com/Pasta-Devs/Marinara-Engine.git
```

2. फ़ोल्डर के अंदर जाएँ:

```bash
cd Marinara-Engine
```

3. कंटेनर को बैकग्राउंड में चालू करें:

```bash
docker compose up -d
```

`docker-compose.yml` फ़ाइल `ghcr.io/pasta-devs/marinara-engine:latest` इमेज इस्तेमाल करती है और यह कमांड पहली बार चलाने पर उसे डाउनलोड कर लेती है। पहले डाउनलोड में कुछ मिनट लग सकते हैं।

## जाँच लें कि सब चल रहा है

1. अपना वेब ब्राउज़र खोलें।
2. इस पते पर जाएँ:

```text
http://127.0.0.1:7860
```

Marinara Engine की होम स्क्रीन दिखनी चाहिए। दिख जाए तो समझिए कंटेनर चल रहा है। पते में `127.0.0.1` का मतलब है "यही कंप्यूटर", और `7860` वह डिफ़ॉल्ट पोर्ट है जिस पर Marinara सुनता है।

अगर पेज नहीं खुलता, तो नीचे समस्या-समाधान वाला हिस्सा देखें।

## आपका डेटा कहाँ रखा जाता है

आपका डेटा (चैट, कैरेक्टर, अपलोड, फ़ॉन्ट और डिफ़ॉल्ट बैकग्राउंड) सादी फ़ाइलों के रूप में सेव होता है। Marinara फ़ाइल-आधारित स्टोरेज इस्तेमाल करता है, यानी डेटा किसी एक डेटाबेस फ़ाइल के अंदर नहीं, बल्कि आम फ़ाइलों के रूप में रहता है। Compose इन फ़ाइलों को `marinara-data` नाम के वॉल्यूम में रखता है।

Compose वॉल्यूम के नाम से पहले प्रोजेक्ट फ़ोल्डर का नाम जोड़ देता है, इसलिए असली नाम `PROJECT_marinara-data` जैसा बनता है। अपनी मशीन पर सही नाम पता करने के लिए वॉल्यूम की लिस्ट देखें:

```bash
docker volume ls --filter name=marinara-data
```

फिर लिस्ट में से उसी को इंस्पेक्ट करें और देखें कि वह कहाँ है:

```bash
docker volume inspect PROJECT_marinara-data
```

`PROJECT_marinara-data` की जगह पिछली कमांड से मिला नाम लिखें।

कंटेनर हर बार चालू होते समय डेटा फ़ोल्डर तैयार करता है। डिफ़ॉल्ट रूप से कंटेनर रूट के तौर पर शुरू होता है। यह फ़ोल्डर की ओनरशिप ठीक कर देता है ताकि ऐप उसमें लिख सके, और फिर सुरक्षा के लिए नॉन-रूट यूज़र पर चला जाता है। यह मरम्मत नाम वाले वॉल्यूम पर भी चलती है और होस्ट से माउंट किए गए फ़ोल्डर पर भी। इसका मतलब है कि पुराने सेटअप बिना कोई ओनरशिप कमांड चलाए फ़ाइल-आधारित स्टोरेज पर आ सकते हैं।

Marinara पहली बार चलने पर वॉल्यूम के अंदर `/app/data/.env` पर एक खाली सेटिंग्स फ़ाइल भी बना देता है। सर्वर की सेटिंग्स बाद में यहीं जोड़ी जाती हैं। यह वॉल्यूम में रहती है, इसलिए कंटेनर रीस्टार्ट और इमेज अपडेट के बाद भी आपकी सेटिंग्स बनी रहती हैं। पूरी सूची के लिए [सर्वर कॉन्फ़िगरेशन रेफ़रेंस](../CONFIGURATION.md) देखें।

## Marinara को अपने LAN पर खोलना

डिफ़ॉल्ट रूप से Compose आपको Marinara तक सिर्फ़ उसी कंप्यूटर से पहुँचने देता है। यही सुरक्षित डिफ़ॉल्ट है। अगर Marinara को अपने फ़ोन या नेटवर्क के किसी दूसरे कंप्यूटर पर खोलना है, तो दो काम करने होंगे। पोर्ट मैपिंग बदलें, और लॉगिन चालू करें ताकि अनजान लोग वहाँ तक न पहुँच सकें।

दूसरे डिवाइस को Marinara इस्तेमाल करने से पहले लॉगिन चाहिए। Marinara को लॉगिन के बिना कभी अपने नेटवर्क पर न खोलें।

1. `docker-compose.yml` को किसी टेक्स्ट एडिटर में खोलें।

2. पोर्ट वाली पंक्ति ढूँढें। वह ऐसी दिखती है:

```yaml
ports:
  - "127.0.0.1:${PORT:-7860}:7860"
```

3. `127.0.0.1:` वाला हिस्सा हटा दें, ताकि ऐप दूसरे डिवाइस से भी खुले:

```yaml
ports:
  - "${PORT:-7860}:7860"
```

4. उसी फ़ाइल में `environment:` लिस्ट में एक एडमिन सीक्रेट जोड़ें। अपनी वैल्यू इस्तेमाल करें:

```yaml
environment:
  - ADMIN_SECRET=another-long-random-value
```

5. फ़ाइल सेव करें और कंटेनर रीस्टार्ट करें:

```bash
docker compose up -d
```

अब `PORT` सेट न होने पर नेटवर्क के दूसरे डिवाइस Marinara तक `http://YOUR_COMPUTER_IP:7860` से पहुँच सकते हैं। अगर `PORT` सेट किया है, तो `7860` की जगह वही होस्ट पोर्ट लिखें। उन्हें लॉगिन माँगने वाला पेज दिखता है। इसे सेट करने के लिए `docker logs <container> 2>&1 | grep "setup code"` से एक बार वाला सेटअप कोड खोजें। उस पेज पर वह कोड नए यूज़रनेम और पासवर्ड के साथ टाइप करें। बाद में साइन इन किए हुए ब्राउज़र में **Settings → Advanced → Access** (सेटिंग्स → एडवांस्ड → एक्सेस) से लॉगिन बदल सकते हैं। पासवर्ड भूल जाएँ, तो `docker exec <container> node scripts/reset-login.mjs` चलाएँ। इससे `BASIC_AUTH_USER` और `BASIC_AUTH_PASS` वाला लॉगिन नहीं बदलता; उन्हें compose फ़ाइल में बदलें और कंटेनर दोबारा बनाएँ। आप `environment:` लिस्ट में `BASIC_AUTH_USER` और `BASIC_AUTH_PASS` से compose फ़ाइल में भी लॉगिन सेट कर सकते हैं।

Docker Desktop, OrbStack और rootless Docker पर हर डिवाइस कंटेनर तक एक ही पते से पहुँचता है, आपका अपना ब्राउज़र भी। इसलिए लॉगिन सेट होते ही यह कंप्यूटर भी लॉगिन माँगता है, और IP अलाउलिस्ट डिवाइस में फ़र्क नहीं कर पाती। `127.0.0.1:` हटाने से पहले लॉगिन सेट करें। इन रनटाइम पर इस कंप्यूटर पर Marinara को `http://localhost:7860` पर खोलें और **Settings** इस्तेमाल करें, या compose फ़ाइल में `BASIC_AUTH_USER` और `BASIC_AUTH_PASS` सेट करें। लॉगिन के बिना `127.0.0.1:` कभी न हटाएँ: इन रनटाइम पर Marinara दूसरे डिवाइस और इस कंप्यूटर में फ़र्क नहीं कर सकता। सिर्फ़ चुनिंदा डिवाइस को अनुमति देने के अच्छे तरीके जानने के लिए, और एडमिन सीक्रेट का काम समझने के लिए [रिमोट एक्सेस: लॉगिन और IP अलाउलिस्ट](../REMOTE_ACCESS.md) पढ़ें।

## इमेज चुनना: latest, staging या lite

Marinara कई इमेज टैग पब्लिश करता है। अपनी ज़रूरत के हिसाब से चुनें।

- `latest` सुझाया हुआ स्टेबल रिलीज़ है। `docker-compose.yml` फ़ाइल डिफ़ॉल्ट रूप से यही इस्तेमाल करती है।
- `X.Y.Z` एक तय वर्ज़न है, जैसे `ghcr.io/pasta-devs/marinara-engine:2.0.6`। जब किसी एक रिलीज़ पर टिके रहना हो, तब इसे चुनें।
- `staging` सबसे नए डेवलपमेंट कोड से बना अस्थिर टेस्ट बिल्ड है। इसे सिर्फ़ बिना रिलीज़ हुए बदलाव आज़माने के लिए इस्तेमाल करें। यह टूट सकता है, बिना किसी नोट के व्यवहार बदल सकता है, और हो सकता है कि इसमें डाला डेटा वापस किसी स्टेबल बिल्ड में न ले जाया जा सके।
- `lite` छोटी इमेज है। इसके बारे में अगले हिस्से में बताया गया है।

अगर आप `staging` इमेज चलाते हैं, तो अलग वॉल्यूम इस्तेमाल करें ताकि कोई अस्थिर बिल्ड आपके स्टेबल डेटा में बदलाव न कर सके:

```bash
docker run -d --name marinara-staging -p 127.0.0.1:7860:7860 -v marinara-staging-data:/app/data ghcr.io/pasta-devs/marinara-engine:staging
```

### lite इमेज

lite इमेज एक छोटा रूप है, जो कुछ ऑफ़लाइन सुविधाएँ छोड़कर बदले में काफ़ी छोटा डाउनलोड देता है। यह Wolfi पर बनी है, जो कंटेनर के लिए बनाया गया एक बेहद हल्का Linux बेस है।

lite इमेज में वे सुविधाएँ हटा दी गई हैं जिनके लिए बड़ी लोकल फ़ाइलें चाहिए:

| lite में हटाया गया | क्या नहीं मिलेगा |
| --- | --- |
| Local Model (Gemma, आपकी मशीन पर चलता है) | अपने ही हार्डवेयर पर AI मॉडल नहीं चला सकते। |
| लोकल एम्बेडिंग मॉडल | डिवाइस पर टेक्स्ट एम्बेडिंग नहीं बनतीं। |
| Memory Recall (सिमैंटिक सर्च) | यह लोकल एम्बेडिंग मॉडल पर निर्भर है। |
| लोकल Whisper वॉइस इनपुट | Conversation कॉल के लिए स्पीच-टू-टेक्स्ट नहीं रहता। |
| अवतार का मूड पढ़ने वाला मॉडल | 2D और 3D Avatars भाव पहचानने वाले छोटे लोकल मॉडल की जगह शब्दों की एक लिस्ट से चेहरे चुनते हैं। |

बाकी सब वैसे ही चलता है: चैट, Roleplay, Game Mode, एजेंट, लोरबुक, कैरेक्टर और रिमोट AI प्रोवाइडर से कनेक्शन। lite इमेज में कोई भी AI सुविधा इस्तेमाल करने के लिए बाहरी प्रोवाइडर से कनेक्ट करना ज़रूरी है (जैसे OpenRouter, OpenAI या खुद होस्ट किया हुआ मॉडल)। देखें [किसी AI प्रोवाइडर से कनेक्ट करना](../connections/connecting-to-a-provider.md)।

lite टैग `ghcr.io/pasta-devs/marinara-engine:lite` है, और हर रिलीज़ के साथ वर्ज़न पर टिका lite टैग भी आता है, जैसे `ghcr.io/pasta-devs/marinara-engine:X.Y.Z-lite`। इसे चलाने के लिए:

```bash
docker run -d --name marinara-lite -p 127.0.0.1:7860:7860 -v marinara-data:/app/data ghcr.io/pasta-devs/marinara-engine:lite
```

कुछ पुरानी lite इमेज Raspberry Pi 4 और उस जैसे ARM कंप्यूटर पर क्रैश हो सकती हैं। बाहर जाने वाली AI प्रोवाइडर कॉल के दौरान `SIGILL` एरर (प्रोसेसर की तरफ़ से आने वाला अवैध-निर्देश एरर) दिखता है। ऐसा कोई डिवाइस इस्तेमाल कर रहे हैं, तो उसकी जगह सामान्य `latest` इमेज चलाएँ। ताज़ा जानकारी के लिए [Marinara Engine की समस्याएँ सुलझाना](../TROUBLESHOOTING.md) देखें।

## अपडेट करना

कंटेनर इमेज खुद से अपडेट नहीं होतीं। नई इमेज पुल करके कंटेनर खुद रीस्टार्ट करना पड़ता है। पहले बैकअप बना लें, ताकि ठीक उसी जगह लौट सकें जहाँ आप थे। देखें [Marinara का बैकअप और रिस्टोर](../data/backup-and-restore.md)।

Docker Compose के लिए यह एक कमांड चलाएँ:

```bash
docker compose pull && docker compose up -d
```

Podman Compose के लिए यह एक कमांड चलाएँ:

```bash
podman compose pull && podman compose up -d
```

अपना वर्ज़न ऐप के अंदर भी देख सकते हैं। **Settings** (सेटिंग्स) खोलें, **Advanced** टैब पर जाएँ और **Updates** सेक्शन ढूँढें। **Check for Updates** पर क्लिक करें। कंटेनर इंस्टॉलेशन में Marinara खुद पहचान लेता है कि वह Docker में चल रहा है, और रिलीज़ इमेज टैग के साथ होस्ट पर चलाने वाली कमांड दिखा देता है। ब्राउज़र के अंदर से अपडेट लागू नहीं हो सकता, इसलिए ऊपर वाली कमांड होस्ट पर ही चलानी पड़ती है।

किसी पुराने रिलीज़ पर वापस जाने के लिए `docker-compose.yml` की `image:` वाली पंक्ति में उसका वर्ज़न टैग लिखें, जैसे `ghcr.io/pasta-devs/marinara-engine:2.5.0`, फिर `docker compose up -d` चलाएँ। 2.5.0 पर वापस जाना काम करता है और आपकी चैट सामान्य रूप से खुलती हैं, लेकिन नई सुविधाओं ने जो सेटिंग्स और गेम डेटा जोड़ा है, उसे 2.5.0 नहीं पहचानता। 2.5.0 जो भी चैट या कनेक्शन सेव करता है, उसका यह डेटा खो जाता है, और दोबारा अपडेट करने से यह वापस नहीं आता। देखें [2.5.0 पर वापस जाना](../UPGRADING.md#going-back-to-250)।

## Podman

Podman वही इमेज चलाता है जो Docker चलाता है। ज़्यादातर मामलों में ऊपर दी गई कमांड में `docker` की जगह `podman` लिख देना काफ़ी है।

Compose से शुरू करने के लिए:

```bash
podman compose up -d
```

Compose के बिना अकेला कंटेनर चलाने के लिए:

```bash
podman run -d -p 127.0.0.1:7860:7860 -v marinara-data:/app/data ghcr.io/pasta-devs/marinara-engine:latest
```

`podman compose` कमांड के लिए `podman-compose` हेल्पर चाहिए। इसे अपने सिस्टम की कमांड से इंस्टॉल करें।

Fedora पर:

```bash
sudo dnf install podman-compose
```

Debian या Ubuntu पर:

```bash
sudo apt install podman-compose
```

pip से:

```bash
pip install podman-compose
```

## इमेज खुद बनाना

अगर इमेज डाउनलोड करने के बजाय उसे सोर्स से बनाना पसंद हो:

```bash
docker build -t marinara-engine .
```

फिर अपना बनाया हुआ बिल्ड चलाएँ:

```bash
docker run -d -p 127.0.0.1:7860:7860 -v marinara-data:/app/data marinara-engine
```

lite इमेज सोर्स से बनाने के लिए Docker को lite बिल्ड फ़ाइल की तरफ़ भेजें:

```bash
docker build -f Dockerfile.lite -t marinara-engine:lite .
```

## समस्या-समाधान

**पेज नहीं खुलता, या पोर्ट पहले से इस्तेमाल में है।** हो सकता है कोई दूसरा प्रोग्राम पहले से पोर्ट `7860` इस्तेमाल कर रहा हो। `ports:` लिस्ट में पोर्ट मैपिंग बदलकर कोई खाली पोर्ट कर दें, जैसे `8080:7860`। फिर `docker compose up -d` से रीस्टार्ट करें और `http://127.0.0.1:8080` खोलें।

**Marinara फ़ाइलें नहीं लिख पाता, या परमिशन एरर दिखते हैं।** कंटेनर हर बार चालू होते समय डेटा फ़ोल्डर की ओनरशिप ठीक करता है। यह नाम वाले वॉल्यूम पर भी चलता है और होस्ट से माउंट किए गए फ़ोल्डर पर भी। कुछ होस्ट फ़ाइल सिस्टम पर यह मरम्मत नाकाम हो सकती है, और `MARINARA_SKIP_DATA_CHOWN=true` सेट करने पर इसे छोड़ दिया जाता है। एरर फिर भी आते रहें, तो डिफ़ॉल्ट `marinara-data` नाम वाला वॉल्यूम इस्तेमाल करें। सबसे भरोसेमंद यही है।

**lite इमेज Raspberry Pi 4 पर क्रैश हो जाती है।** ऊपर lite इमेज वाला नोट देखें। उस हार्डवेयर पर सामान्य `latest` इमेज इस्तेमाल करें।

और मदद के लिए [Marinara Engine की समस्याएँ सुलझाना](../TROUBLESHOOTING.md) पढ़ें।
