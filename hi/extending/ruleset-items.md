# नियमसेट के आइटम

यह पेज [Game Mode के नियमसेट लिखना](writing-rulesets.md) का हिस्सा है। पार्टी क्या साथ रखती है: श्रेणियाँ, हथियार, कवच, गोला-बारूद, लूट, पैसे, शुरुआती सामान और बाज़ार।

कवच, हथियार, पोशन, सामान, गोला-बारूद और पैसे आइटम हैं। वैकल्पिक `items` ब्लॉक वे शब्द घोषित करता है जिनमें आपके नियमसेट का हर आइटम लिखा जाता है, और `holds: "items"` वाला कैटलॉग खुद आइटम सूचीबद्ध करता है। दोनों को Capability API 1.49 चाहिए; Game Master के गढ़े आइटम को नियंत्रित करने वाले ब्लॉक के `rarityCaps` और `propose` को 1.51 चाहिए, कैरेक्टर के पास मौजूद आइटम पढ़ने वाले मान (`itemStat`) को 1.52, पहने या साथ रखे होने पर आइटम चेक पर क्या करता है, ब्लॉक की `bonus` सीमाओं के साथ, उसे 1.53, आइटम अपने पहनने वाले से क्या माँगता है और कौन सी एबिलिटी बदलता है, उसे 1.54, हथियार के `attack` को 1.55, आइटम लड़ाई में क्या करता है, उसे 1.56, हथियार क्या चलाता है और कितना भरा रखता है, उसे 1.57, हथियार के मोड, दूसरे हाथ के अटैक, नुकसान की निचली सीमा और हिट पर स्थितियों को 1.58, लड़ाई में आइटम इस्तेमाल करने के असर को, उसमें मौजूद चार्ज के साथ, 1.59, पूल वापस भरने वाले इस्तेमाल को 1.60, आराम पर वापस मिलने वाले चार्ज या खाली होने पर टूटने वाले आइटम को 1.61, पहले चेक माँगने वाले इस्तेमाल (`gate`) को 1.62, लूट टेबल और जीव की लूट को 1.63, सिक्के गिराने वाली लूट लाइन या सिक्के हटाने वाली लेयर को 1.64, बाज़ार, आइटम की `sold` जगह और `service` को 1.65, बाज़ार के दिन (बटुआ, `buyBack`, विक्रेता का `stock`, `limited` गिनती, या किसी जगह का नाम न देने वाला `sold`) को 1.69, हाथ में पकड़े हथियारों पर चलने वाले अतिरिक्त प्रभाव (`weapons`) को 1.70, शुरुआती सामान (`startingGear`) को 1.78, जोखिम भरे आइटम, नकली आइटम या बेईमान विक्रेता को 1.79, और बाज़ार के `unsold` (या लेयर के `items`) को 1.813 चाहिए।

## आइटम ब्लॉक

ब्लॉक फ़ाइल के सबसे ऊपरी स्तर पर `items` में जाता है। यह Ember Roads का है, थोड़ा छोटा करके:

```json
"items": {
  "categories": [
    { "id": "weapon", "label": "Weapon" },
    { "id": "armor", "label": "Armor" },
    { "id": "ammunition", "label": "Ammunition" }
  ],
  "rarities": [
    { "id": "common", "label": "Common" },
    { "id": "storied", "label": "Storied" }
  ],
  "tags": [
    { "id": "thrown", "label": "Thrown" },
    { "id": "ranged", "label": "Ranged" },
    { "id": "two_handed", "label": "Two-handed" },
    { "id": "arrow", "label": "Arrow" }
  ],
  "stats": [
    { "id": "bulk", "label": "Bulk", "type": "number", "min": 0, "max": 10, "default": 0 },
    { "id": "guard", "label": "Guard", "type": "number", "min": 0, "max": 4, "default": 0 },
    { "id": "damage", "label": "Damage", "type": "dice", "example": "1d6" },
    { "id": "swing", "label": "Rolls with", "type": "enum", "values": ["brawn", "wits", "heart"], "default": "brawn" },
    { "id": "reach", "label": "Reach", "type": "enum", "values": ["close", "near", "far"], "default": "close" }
  ],
  "slots": [
    { "id": "body", "label": "Body", "count": 1 },
    { "id": "hands", "label": "Hands", "count": 2 }
  ],
  "carry": { "stat": "bulk", "encumberedAbove": { "derived": "load" }, "limit": { "const": 12 } },
  "rarityCaps": [
    { "rarity": "common", "stats": { "guard": 1 }, "bonus": 1 },
    { "rarity": "storied", "stats": { "guard": 3 }, "bonus": 2 }
  ],
  "currencies": [
    {
      "id": "coin",
      "label": "Coin",
      "perWeight": 100,
      "units": [
        { "id": "bit", "label": "bits", "value": 1 },
        { "id": "mark", "label": "marks", "value": 10 },
        { "id": "sovereign", "label": "sovereigns", "value": 100 }
      ]
    },
    {
      "id": "salt",
      "label": "Salt",
      "perWeight": 10,
      "units": [
        { "id": "pinch", "label": "pinches", "value": 1 },
        { "id": "cake", "label": "cakes", "value": 20 }
      ]
    }
  ]
}
```

- `categories`: एक से 24। हर आइटम की ठीक एक श्रेणी होती है, जैसे कवच, हथियार या पोशन।
- `rarities`: वैकल्पिक, अधिकतम 12। इन्हें सबसे आम से सबसे दुर्लभ के क्रम में लिखें।
- `tags`: वैकल्पिक, अधिकतम 48। ऐसे गुण जो किसी आइटम में हो सकते हैं, जैसे फेंका जाने वाला या चाँदी चढ़ा।
- `stats`: वैकल्पिक, अधिकतम 24। वे संख्याएँ और शब्द जो आइटम में होते हैं, बिल्कुल सूची के कॉलम की तरह घोषित: `number`, `text`, `boolean`, `enum` या `dice`, जहाँ टाइप में हों वहाँ दायरे, मानों और डिफ़ॉल्ट के साथ। `promptVisible` (डिफ़ॉल्ट `true`) बताता है कि Game Master को आइटम के साथ यह स्टैट दिखाया जाए या नहीं। जो चीज़ सिर्फ़ खिलाड़ी को दिखनी चाहिए, जैसे आइटम कहाँ छिपा है, उसके लिए इसे `false` करें।
- `slots`: वैकल्पिक, अधिकतम 12। आइटम कहाँ पहना या पकड़ा जाता है, और कैरेक्टर के पास वह स्लॉट कितने हैं, 1 से 20 तक।
- `binding`: वैकल्पिक। एट्यूनमेंट, इन्वेस्टिचर, या ऐसी कोई भी चीज़ जो सीमित करती है कि एक कैरेक्टर एक साथ कितने आइटम बाइंड कर सकता है। `label` उसका नाम है, और `max` कैरेक्टर की शीट से पढ़ा गया मान है, जैसे `{ "abilityScore": "nerve" }` या कोई निकाला गया मान। यह लाइव स्टेट नहीं पढ़ सकता, क्योंकि कैरेक्टर कितने आइटम बाइंड कर सकता है, यह हर वार के साथ नहीं बदलता।
- `carry`: वैकल्पिक। `stat` उस नंबर स्टैट का नाम देता है जो आइटम का वज़न है, जिसका `min` 0 या उससे ज़्यादा है। `encumberedAbove` बताता है कि कैरेक्टर बोझ से दबने से पहले कितना उठा सकता है, और `limit` (वैकल्पिक) बताता है कि वह कुल मिलाकर ज़्यादा से ज़्यादा कितना उठा सकता है। दोनों `binding.max` की तरह शीट से पढ़े जाते हैं। `carry` के बिना वज़न का कोई मतलब नहीं होता और कोई कभी बोझ से नहीं दबता। `unit` (वैकल्पिक, अधिकतम 12 अक्षर, Capability API 1.791) वह इकाई है जिसमें वज़न गिना जाता है, जैसे `"lb"`: इन्वेंटरी का बोझ, शुरुआती सामान पिकर के वज़न और किट के विकल्प का वज़न संख्या के बाद इसे दिखाते हैं।
- `currencies`: वैकल्पिक, सिक्कों के अधिकतम छह परिवार, हर एक में एक से दस सिक्के।
  - एक परिवार के सिक्के `value` के हिसाब से एक-दूसरे में बदलते हैं, जो परिवार के सबसे छोटे सिक्के में गिना जाता है। इसलिए सबसे छोटे सिक्के का मूल्य 1 है, और एक परिवार के कोई भी दो सिक्के बराबर मूल्य के नहीं होते।
  - दो परिवार कभी एक-दूसरे में नहीं बदलते। दूसरे देश का सिक्का, या किसी सेटिंग के एहसान, अपना अलग परिवार हैं।
  - सिक्के का ID सभी परिवारों में अनोखा होता है, क्योंकि आइटम की कीमत सिर्फ़ सिक्के का नाम देती है।
  - सिक्के का `label` उसकी किसी भी संख्या के लिए उसका नाम है (`pennies`); `one` (Capability API 1.89) ठीक एक सिक्के के लिए उसका नाम है (`penny`), जो हर उस जगह कहा जाता है जहाँ कीमत, बटुआ या बाज़ार एक सिक्के का नाम लेता है। इसके बिना `label` एक के लिए भी चलता है।
  - `perWeight` (वैकल्पिक, और सिर्फ़ `carry` के साथ) बताता है कि परिवार के कितने सिक्कों का वज़न carry स्टैट की एक इकाई होता है।
  - सिक्के पार्टी के पैसे हैं, जो किसी भी आइटम की तरह थैलों में रखे जाते हैं (नीचे पैसे देखें)।
- `rarityCaps`: वैकल्पिक, हर दुर्लभता के लिए अधिकतम एक। उस दुर्लभता पर Game Master का गढ़ा आइटम ज़्यादा से ज़्यादा क्या दे सकता है: `stats` में बताए हर नंबर स्टैट का सबसे बड़ा मान, उस स्टैट के अपने दायरे के अंदर, और पूर्णांक लेने वाले स्टैट के लिए पूर्णांक, और `bonus` (Capability API 1.53), यानी उसका कोई पहनने या साथ रखने वाला मॉडिफ़ायर ज़्यादा से ज़्यादा कितना स्थिर बोनस जोड़ सकता है। `bonus` वाली दुर्लभता पर डाइस में दिया बोनस छोड़ दिया जाता है, क्योंकि डाइस को किसी संख्या तक सीमित नहीं किया जा सकता; पेनल्टी कभी सीमित नहीं होती। गढ़ा गया आइटम इसके दायरे में रखा जाता है; आपके कैटलॉग में सूचीबद्ध आइटम आपके हैं और कभी सीमित नहीं होते।
- `propose`: डिफ़ॉल्ट रूप से `true`। `false` Game Master को आपके नियमसेट के आइटम गढ़ने से रोकता है।
- `native`: डिफ़ॉल्ट रूप से `true`। `false` आपके नियमसेट वाले गेम में Game Mode के अपने बिना टाइप वाले आइटम बंद कर देता है (**आइटम कौन पढ़ता है** देखें)। Game Master फिर भी आइटम गढ़ सकता है, आपके नियमसेट के शब्दों में लिखे हुए।
- `freeform`: खिलाड़ी का टाइप किया आइटम क्या बनता है। `"plain"` (डिफ़ॉल्ट) उसे बिना नियमों वाले आइटम के रूप में रखता है, जैसा आज होता है। `"refuse"` सिर्फ़ आपके नियमसेट के आइटम की इजाज़त देता है।
- `lootTables` (Capability API 1.63): वैकल्पिक, अधिकतम 24। जीती हुई लड़ाई के जीव और Game Master का `[loot:]` क्या गिराते हैं (नीचे लूट देखें)।

## एक आइटम

आइटम कैटलॉग कोई `feeds` घोषित नहीं करता:

```json
{ "id": "outfitter", "label": "Outfitter", "holds": "items", "entries": [] }
```

हर एंट्री में `rows` या `creature` के बजाय `item` होता है:

```json
{
  "id": "hunting-bow",
  "label": "Hunting bow",
  "summary": "Yew, waxed string, and a grip worn smooth by someone else's hand.",
  "item": {
    "category": "weapon",
    "rarity": "common",
    "tags": ["ranged", "two_handed"],
    "stats": { "bulk": 2, "damage": "1d8", "swing": "wits", "reach": "far" },
    "slots": { "hands": 2 },
    "cost": { "amount": 3, "unit": "sovereign" }
  }
}
```

- `id`, `label`, `summary` और `filters` वैसे ही काम करते हैं जैसे किसी भी एंट्री के लिए। लेबल आइटम का नाम है।
- `category` ज़रूरी है। `rarity` और `tags` वैकल्पिक हैं, और तीनों ब्लॉक के अपने ID का नाम देते हैं। आइटम की दुर्लभता तभी हो सकती है जब ब्लॉक कुछ दुर्लभताएँ घोषित करे।
- `stats`: ब्लॉक के स्टैट के मान। हर एक ऐसा मान है जो उसका स्टैट रख सके।
- `slots`: आइटम हर स्लॉट में से कितने लेता है, कैरेक्टर के पास मौजूद से कभी ज़्यादा नहीं।
- `stack`: एक स्टैक में ज़्यादा से ज़्यादा कितने आते हैं, 1 से 999,999 तक। इसके बिना एक स्टैक में उतने आते हैं जितने Game Mode के किसी भी स्टैक में। `charges` रखने वाला आइटम एक स्टैक में एक ही होता है।
- `cost`: एक सिक्के की पूर्णांक `amount`, जिस सिक्के का नाम उसके `unit` ID से दिया जाता है। पिकर इसे दिखाता है, और Game Master इसे आइटम के साथ देखता है (नीचे पैसे देखें)।
- `sold` (Capability API 1.65): `{ "place": "city" }`, आपके बाज़ार की वह सबसे छोटी जगह जो आइटम बेचती है, किसी भी ऐसे नियम से ऊपर जो कुछ और कहे; 1.69 के साथ यह इसके बजाय, या साथ में, यह भी बता सकता है कि कोई जगह एक दिन में उसके कितने रखती है (`"limited": 2` या `"limited": "1d3"`) (नीचे बाज़ार देखें)।
- `service` (Capability API 1.65): ठहरने की जगह, सफ़र या आशीर्वाद के लिए `true`: आइटम की तरह खरीदा जाता है और कभी साथ नहीं रखा जाता। इसे खरीदना सिर्फ़ भुगतान करता है; कोई और चीज़ इसे थैले में नहीं डालती (इसे जोड़ना `service` के रूप में अस्वीकार होता है), और पिकर सेवाओं को छोड़ देता है। सेवा में `cost` होता है, और उसे साथ रखने या इस्तेमाल करने की कोई बात नहीं (`slots`, `stack`, `binds`, `worn`, `carried`, `requires`, `attack`, `use`, `charges`)।
- `binds`: पहने होने पर कुछ भी करने से पहले आइटम को बाइंड करना ज़रूरी है। `restriction` (वैकल्पिक) शब्दों में बताता है कि उसे कौन बाइंड कर सकता है, और `cursed: true` ऐसे आइटम को चिह्नित करता है जो छोड़ता नहीं। सिर्फ़ `binding` वाले नियमसेट में बाइंड होने वाले आइटम हो सकते हैं।
- `worn` और `carried` (वैकल्पिक, Capability API 1.53): आइटम पहने होने पर, और सिर्फ़ साथ रखे होने पर, अपने धारक के चेक और सेव पर क्या करता है, (1.54) कौन सी एबिलिटी सेट करता या बढ़ाता है, और (1.56) लड़ाई में क्या करता है। [लड़ाई के बाहर चेक](#checks-outside-a-fight) और [लड़ाई में कवच और पहनने के असर](#armor-and-worn-effects-in-a-fight) देखें।
- `requires` (वैकल्पिक, Capability API 1.54): आइटम अपने पहनने वाले से क्या माँगता है, और कमी रहने तक क्या लागू होता है। [लड़ाई के बाहर चेक](#checks-outside-a-fight) देखें।
- `attack` (वैकल्पिक, Capability API 1.55): पहने होने पर आइटम लड़ाई में हथियार के रूप में क्या करता है, (1.57) वह क्या चलाता है और कितना भरा रखता है, और (1.58) उसके दूसरे मोड, दूसरे हाथ का अटैक, उसके नुकसान की निचली सीमा और हिट पर लगने वाली स्थितियाँ। [लड़ाई में हथियार](#weapons-in-a-fight), [गोला-बारूद और रीलोड](#ammunition-and-reloading) और [मोड, दूसरा हथियार, निचली सीमा और हिट पर स्थितियाँ](#modes-a-second-weapon-a-floor-and-conditions-on-a-hit) देखें।
- `toggle` (वैकल्पिक, Capability API 1.170): आइटम पर एक स्विच, `{ "label", "budget" }`। लड़ाई इसे उस बजट पर एक विकल्प के रूप में देती है ("Turn on Flame Tongue: Flames"), इन्वेंटरी लेबल वाले बटन के रूप में, और उसे जिस तरह छोड़ा गया वह लड़ाइयों के बीच स्टैक पर वैसा ही रहता है; यह बंद शुरू होता है। स्विच वाला आइटम चालू रहते एक स्टैक में अकेला होता है। हथियार का `when: "toggled"` वाला `plus` खंड सिर्फ़ चालू रहते लगता है। 5e का flame tongue: `"toggle": { "label": "Flames", "budget": "bonus" }` और `"plus": [{ "dice": "2d6", "type": "fire", "when": "toggled" }]`।
- `use` और `charges` (वैकल्पिक, Capability API 1.59): आइटम इस्तेमाल करने से क्या होता है, लड़ाई में और उसके बाहर, और उस इस्तेमाल में खर्च होने वाले उसके चार्ज, और (1.60) वह पूल जिसे वह वापस भरता है। [लड़ाई में आइटम इस्तेमाल करना](#using-items-in-a-fight) और [लड़ाई के बाहर आइटम इस्तेमाल करना](#using-items-outside-a-fight) देखें।

आइटम में कोई `mechanics` नहीं होता: वह क्या करता है, यह उसके `item` ब्लॉक में लिखा होता है।

## आइटम कौन पढ़ता है

ऊपर की हर चीज़ नियमसेट इंपोर्ट होते समय जाँची जाती है, और आपके आइटम कैटलॉग उसके साथ आते हैं। गेम में Game Mode की इन्वेंटरी उन्हें पढ़ती है:

- **आपके आइटम थैले में होते हैं।** स्टैक आपका कोई आइटम हो सकता है, और खिलाड़ी उसे कुछ भी कहे, वह वही आइटम रहता है। इन्वेंटरी का **From the ruleset** (नियमसेट से) बटन आपके कैटलॉग में सूचीबद्ध हर आइटम का पिकर खोलता है, कैटलॉग की खोज और फ़िल्टर के साथ, और जो लेयर किसी एंट्री को छिपाती है वह उसे वहाँ भी छिपाती है।
- **नाम आपके आइटम ढूँढ़ते हैं।** खिलाड़ी का टाइप किया नाम, या Game Master का `[inventory: action="add"]` में लिखा नाम, जो आपके किसी आइटम का `label` हो, छोटे-बड़े अक्षर कुछ भी हों, वही आइटम जोड़ता है। जब दो आइटम का लेबल एक हो, तो नाम उस आइटम को ढूँढ़ता है जो आपके कैटलॉग में पहले सूचीबद्ध है।
- **`stack`** का पालन होता है: इससे आगे जोड़ना, सेट करना, मिलाना या देना स्टैक भर देता है और नया शुरू करता है।
- **`freeform: "refuse"`** खिलाड़ी के लिए सिर्फ़ आपके आइटम छोड़ता है: पिकर, और ऐसे नाम जो आपके आइटम हैं।
- **`native: false`** Game Master के लिए सिर्फ़ आपके आइटम और उसके गढ़े आइटम छोड़ता है: ऐसा नाम जो इन दोनों में से कुछ नहीं है, अस्वीकार होता है (`not-ruleset-item`), जबकि पहले से मौजूद किसी चीज़ की और मात्रा अब भी जोड़ी जा सकती है, और उसके निर्देश यही बताते हैं। लड़ाई अब किसी मॉडल से नहीं पूछती कि इन्वेंटरी के आइटम क्या करते हैं, इसलिए सिर्फ़ आपके आइटम लड़ते हैं: नियमसेट वाली लड़ाई में आपके पकड़े हुए हथियार और आपके आइटम के इस्तेमाल (नीचे लड़ाई में हथियार देखें), और Classic या Tactical बैटल में `use` वाले आपके आइटम (नीचे Classic और Tactical बैटल में आइटम देखें)। खिलाड़ी जो टाइप करता है वह अब भी `freeform` के मुताबिक चलता है, और पार्टी जो साथ ले गई थी वह हर हाल में नए सेशन में वापस आता है।
- **आइटम क्या है**, यह चुने गए स्टैक पर दिखता है: उसकी श्रेणी, दुर्लभता और टैग उनके लेबल से, उससे मिलने वाले स्टैट, उसका सारांश और एक स्टैक में कितने आते हैं। पिकर उसका `cost` भी दिखाता है। Game Master अपने पास मौजूद आपका हर आइटम उसकी श्रेणी, दुर्लभता, टैग और उन स्टैट के साथ देखता है जिन्हें आपने `promptVisible` रखा है, जैसे `Hand axe [Weapon, Common, Thrown; Damage 1d6, Reach close]`।

- **`slots`**: स्लॉट लेने वाला आइटम उसे साथ रखने वाला कोई भी इक्विप कर सकता है, जब तक उसके वे स्लॉट खाली हों, और बड़े स्टैक का एक आइटम पहनने के लिए उसके अपने अलग स्टैक में निकाल लिया जाता है। इन्वेंटरी हर कैरेक्टर के इस्तेमाल में मौजूद हर स्लॉट दिखाती है।
- **`binding`**: `binds` वाला आइटम बाइंड किया जा सकता है, `binding.max` तक, जो उसके धारक की अपनी शीट से पढ़ा जाता है (बिना शीट वाला कैरेक्टर खाली शीट पढ़ता है)। `cursed` आइटम एक बार बाइंड होने के बाद बाइंड ही रहता है: खिलाड़ी उसे अनबाइंड नहीं कर सकता, उतार नहीं सकता, किसी को दे नहीं सकता या हटा नहीं सकता, और सिर्फ़ Game Master श्राप खत्म कर सकता है।
- **`carry`**: आइटम का वज़न उसके `carry.stat` के मान जितना होता है (बिना इसके वाले आइटम का कोई वज़न नहीं), और कैरेक्टर का बोझ उसके थैले का वज़न है, जिसकी तुलना उसकी अपनी शीट से पढ़े `encumberedAbove` और `limit` से होती है। इन्वेंटरी के साझा व्यू में जोड़ा गया आइटम, खिलाड़ी का या Game Master का बिना `who=` के जोड़ा हुआ, उसके पास जाता है जो बोझ से दबे बिना उसे उठा सके (पहले खिलाड़ी, फिर पार्टी क्रम से), और जब कोई भी पूरा न उठा सके तो हर एक की बची जगह के हिसाब से बाँट दिया जाता है। कुछ भी किसी की `limit` से आगे नहीं जाता: जो कोई नहीं उठा सकता वह पीछे छूट जाता है और Game Master को बताया जाता है। पाउंड के चौथाई जैसे वज़न के लिए वज़न वाले स्टैट को `"integer": false` दें।
- **Game Master आपके शब्दों में आइटम गढ़ता है।** जब तक आप `propose: false` सेट न करें, उसका `[inventory: action="add"]` नए आइटम का वर्णन कर सकता है: शुरुआत के लिए आपके किसी आइटम का `like=`, फिर `category=`, `rarity=`, `tags=`, `stats=` (`id=value` जोड़ियाँ), `slots=` (`id=count`), `binds=` (`yes`, `cursed` या `no`), `worn=` और `carried=` (`;` से अलग किए बदलाव, हर एक `+N`, `-N`, `advantage`, `disadvantage` या सेव के लिए `fails`, नाम से स्किल या सेव पर, या उन सब के लिए `checks` या `saves` पर, एबिलिटी के नाम पर उसे बढ़ाने या घटाने के लिए `+N` या `-N`, और जहाँ आपके पास लड़ाइयाँ हैं, अटैक पर `+N`, `-N`, एडवांटेज या डिसएडवांटेज और डिफ़ेंस या उसके लिए आपके शब्द पर `+N` या `-N`: `worn="+1 Sneak; disadvantage on Sway checks"`, `carried="+1 Brawn"`, `worn="+1 Guard"`, या `none`) और `summary=` में से कोई भी, हर हिस्सा अपने ID या लेबल से। जिस आइटम स्टैट को आपका डिफ़ेंस पहले से गिनता है (Ember Roads का Guard पहनी हुई चीज़ों का `guard` जोड़ता है), वही कवच के डिफ़ेंस बढ़ाने का तरीका है, इसलिए ऐसे स्टैट के साथ डिफ़ेंस में पहनने वाला बदलाव छोड़ दिया जाता है और जवाब यह बताता है: छोटा मॉडल एक ही +1 के लिए `guard=1` और `+1 Guard` दोनों लिखता है। यह वह भी पढ़ता है जो छोटा मॉडल अक्सर इसके बजाय लिखता है: नाम के बाद संख्या (`Brawn +1`), अटैक या डिफ़ेंस के बाद "bonus" (`+1 attack roll bonus`), टैग, स्टैट या स्लॉट की खाली सूची के लिए `none`, और जब आपके पास उस नाम का स्टैट न हो तो `stats=` के अंदर `worn=`, `carried=` या `summary=`। Engine सिर्फ़ वही रखता है जो आपके ब्लॉक में है: अनजान श्रेणी, टैग, स्टैट, स्लॉट, स्किल या सेव छोड़ दिया जाता है, आपके पास न होने वाली दुर्लभता आपकी सबसे निचली बन जाती है, संख्या अपने स्टैट के दायरे में और फिर अपनी दुर्लभता के `rarityCaps` में रखी जाती है, पहनने या साथ रखने का बोनस अपनी दुर्लभता के `bonus` में (वह हिस्सा भी जिससे `like` ने शुरू किया), और जो नाम आपका कोई आइटम है वह बस वही आइटम है। जवाब Game Master को बताता है कि क्या बदला (उस स्टैट के बारे में कभी नहीं जो आप उसे नहीं दिखाते), और आइटम का ब्योरा खिलाड़ी को हर बदलाव दिखाता है। गेम आइटम को रखता है, इसलिए बाकी गेम में वही नाम वही आइटम है, और जब तक किसी के पास वह है, नया सेशन उसे रखता है।
- जब आपके पास `slots` हों तो Game Master अपनी इन्वेंटरी कमांड से आपके आइटम `equip` और `unequip` कर सकता है, और जब `binding` हो तो `bind` और `unbind`: उसे सिर्फ़ वही बताए जाते हैं जो आपके नियमसेट में हैं। वह हर कैरेक्टर का बोझ, बाइंड किए आइटम और स्लॉट देखता है, और यह कि क्या पहना या बाइंड किया हुआ है।

- **पहने या साथ रखे होने पर आइटम क्या करता है**, यह चुने गए स्टैक पर और पिकर में दिखता है ("While worn: -1 on checks (Sneak)"), और Game Master इसे आइटम के साथ देखता है (`worn: -1 on checks (Sneak)`)। लड़ाई के बाहर के चेक इसे लागू करते हैं (नीचे लड़ाई के बाहर चेक देखें)।
- **हथियार क्या करता है**, यह भी इसी तरह दिखता है ("Attack (Action): Brawn to hit, 1d6 + Brawn cut damage"), और जब तक वह पकड़ा हुआ है, लड़ाई उसे देती है (नीचे लड़ाई में हथियार देखें)।
- **आइटम इस्तेमाल करने से क्या होता है**, यह भी इसी तरह दिखता है ("Use (Action): heals 1d4 + 1, range 0 paces, used up"), उसके बचे हुए चार्ज के साथ। लड़ाई इसे देती है, और इन्वेंटरी का **Use** (इस्तेमाल करें) बटन और Game Master का `[inventory: action="use"]` भी (नीचे लड़ाई में आइटम इस्तेमाल करना और लड़ाई के बाहर आइटम इस्तेमाल करना देखें)।

Classic या Tactical बैटल में `use` वाला आपका हर आइटम वहाँ वही करता है जो वह कहता है, और बिना इसके वाला नहीं दिया जाता (नीचे Classic और Tactical बैटल में आइटम देखें)। `native` कुछ भी कहे, शीट आपके आइटम पढ़ सकती है (नीचे), नियमसेट वाली लड़ाई में पकड़ा हुआ हथियार एक अटैक है जो थैले से लिया गया चलाता है, पहने या साथ रखे होने पर आइटम जो करता है वह उसमें गिना जाता है (नीचे लड़ाई में कवच और पहनने के असर देखें), `use` वाला आइटम अपने नियमों से इस्तेमाल होता है, लड़ाई में और उसके बाहर (नीचे लड़ाई में आइटम इस्तेमाल करना और लड़ाई के बाहर आइटम इस्तेमाल करना देखें), और आपकी `currencies` पार्टी के पैसे हैं (नीचे पैसे देखें)।

## शीट पर आइटम

वैल्यू रेफ़रेंस `itemStat` (Capability API 1.52) से कैरेक्टर के पास मौजूद आइटम पढ़ सकता है। Ember Roads यात्री के पहने कवच का guard उसके Guard में जोड़ता है, जिसे किसी वार को पार करना होता है:

```json
{
  "id": "guard",
  "label": "Guard",
  "op": "sum",
  "of": [{ "const": 6 }, { "abilityMod": "wits" }, { "itemStat": { "stat": "guard", "from": "worn", "pick": "sum" } }]
}
```

- `from`: `"worn"` कैरेक्टर पर मौजूद आइटम हैं: स्लॉट लेने वाला आइटम जब तक इक्विप है, `binds` वाला जब तक बाइंड है, और दोनों करने वाला जब तक दोनों हैं। जो आइटम इनमें से कुछ नहीं करता, वह कभी पहना हुआ नहीं होता। `"carried"` उसके पास का बाकी सामान है, और `"all"` दोनों।
- `pick`: `"sum"` हर आइटम का मान उसकी संख्या से गुणा करके जोड़ता है, `"max"` और `"min"` सबसे ऊँचा या सबसे नीचा अकेला मान पढ़ते हैं, और `"count"` आइटम गिनता है, उनकी संख्या के हिसाब से।
- `stat` आपके किसी आइटम स्टैट का नाम देता है। `sum`, `max` और `min` को `number` स्टैट चाहिए। `count` हर आइटम गिनने के लिए इसे छोड़ सकता है, या सिर्फ़ वह स्टैट देने वाले आइटम गिनने के लिए कोई भी स्टैट बता सकता है।
- `slot`, `category` और `tag` (हर एक वैकल्पिक) सिर्फ़ वे आइटम रखते हैं जो वह स्लॉट लेते हैं, उस श्रेणी के हैं, या उस टैग वाले हैं।
- `default` (वैकल्पिक, छोड़ने पर 0) वह मान है जो तब पढ़ा जाता है जब कोई आइटम न चुना जाए, या उनमें से कोई वह स्टैट न दे।

आइटम खेल में बदलते हैं, इसलिए `itemStat` पर लाइव रीड वाला ही नियम लागू होता है: पूल या ट्रैक का `max`, दक्षता बोनस, `binding.max`, `carry` की संख्याएँ, और कैटलॉग का scaled कॉलम या स्केलिंग इसे नहीं पढ़ सकते, निकाले गए मान के रास्ते भी नहीं। बाकी हर जगह, जहाँ कोई संख्या पढ़ी जाती है, यह पढ़ा जा सकता है: निकाला गया मान, चेक का `adjust`, स्किल का `cap`, लड़ाई का डिफ़ेंस, सोखना या इनिशिएटिव।

कैरेक्टर के आइटम वे हैं जो उसके अपने थैले में हैं। खिलाड़ी का कार्ड (जिसके नाम से चैट खेलती है, वरना पहला) खिलाड़ी का थैला पढ़ता है, और हर दूसरा कार्ड अपना। सिर्फ़ आपके नियमसेट के आइटम गिने जाते हैं, क्योंकि साधारण आइटम में पढ़ने को कोई स्टैट नहीं होता। स्क्रीन पर शीट, चेक, Game Master का शीट ब्लॉक, और शुरू होती लड़ाई, सब वही पढ़ते हैं जो उस समय हर कैरेक्टर के पास है। गेम के बाहर, शीट एडिटर या इंपोर्ट की समीक्षा में, किसी के पास कुछ नहीं होता और `itemStat` अपना `default` पढ़ता है।

## लड़ाई के बाहर चेक

लड़ाई के बाहर Game Master का माँगा चेक या सेव शीट से ज़्यादा पढ़ता है: कैरेक्टर की अपनी सक्रिय स्थितियाँ, उसके पहुँचे हुए स्तर, पहने या साथ रखे होने पर उसके आइटम क्या करते हैं, और पहने आइटम की शर्त पूरी न होने तक उसकी क्या कीमत है। यह वही शब्दावली है जो लड़ाई की स्थितियाँ इस्तेमाल करती हैं (आइटम कुंजियों और सीमित करने के लिए Capability API 1.53)।

आइटम `worn` से बताता है कि वह क्या करता है, जो उसके पहने होने पर लागू होता है (और बाइंड होने पर, जहाँ वह बाइंड होता है), और `carried` से, जो सिर्फ़ साथ रखे होने पर लागू होता है। Ember Roads का चमड़े का कोट दबे पाँव चलते समय चरमराता है, और waystone कारवाँ वालों को आप पर भरोसा करवाता है:

```json
"worn": { "modifiers": [{ "to": "checks", "skills": ["sneak"], "flat": -1 }] }
```

```json
"carried": { "modifiers": [{ "to": "checks", "skills": ["sway"], "flat": 1 }] }
```

हर एक में स्थिति के वे हिस्से होते हैं जिन्हें चेक पढ़ता है:

- `effects`: `own-checks-advantage`, `own-checks-disadvantage`, `own-saves-advantage` और `own-saves-disadvantage`।
- `modifiers`: चेक या सेव के लिए `to` वाले बदलाव, `flat`, `dice` (और `minus`), `mode`, और उनके अपने `skills` या `saves` के साथ, बिल्कुल स्थिति की तरह।
- `failsSaves`: वे सेव जिनमें धारक बिना रोल के विफल होता है।
- `skills` और `saves`: असर, और ऐसे मॉडिफ़ायर जो अपनी कोई स्किल या सेव नहीं बताते, किन स्किल या सेव के बारे में हैं।
- `abilities` (Capability API 1.54): वह जिन एबिलिटी को बदलता है, ID से, हर एक `{ "set": N }` (कम से कम N: ऊँचा स्कोर बना रहता है) या `{ "add": N }` (ऋणात्मक संख्या उसे घटाती है)। ये शीट निकाले जाने से पहले लागू होते हैं, इसलिए एबिलिटी पढ़ने वाली हर चीज़ बदली हुई एबिलिटी पढ़ती है: स्क्रीन पर शीट, निकाले गए मान, चेक, Game Master का शीट ब्लॉक और शुरू होती लड़ाई। पहले जोड़ लगते हैं, फिर सबसे ऊँचा `set`, और एबिलिटी के अपने `min` और `max` लागू रहते हैं। पूल या ट्रैक का अधिकतम और दक्षता बोनस सिर्फ़ शीट से निकाले जाते हैं, इसलिए आइटम उन्हें नहीं हिलाता।

Ember Roads के बैल की खाल के दस्ताने कमज़ोर पकड़ को गाड़ीवान जैसी पकड़ देते हैं:

```json
"worn": { "abilities": { "brawn": { "set": 2 } } }
```

आइटम लड़ाई में क्या करता है (डिफ़ेंस, अटैक, रफ़्तार, लड़ाई के दूसरे असर, और वह कौन सा नुकसान और स्थितियाँ दूर रखता है), यह [लड़ाई में कवच और पहनने के असर](#armor-and-worn-effects-in-a-fight) में है; लड़ाई के बाहर चेक सिर्फ़ ऊपर के हिस्से पढ़ता है। किसी के पास एक आइटम के कितने भी स्टैक हों, एक आइटम एक बार लागू होता है।

आइटम `requires` से अपने पहनने वाले से कुछ माँग भी सकता है: उसकी शीट का कोई मान (`value`, कोई भी वैल्यू रेफ़रेंस, जिसे खेल की हर चीज़ की तरह पढ़ा जाता है), वह कम से कम कितना हो (`atLeast`), और कमी रहने तक क्या लागू होता है (`otherwise`, उसी शब्दावली में, सिवाय इसके कि यह कोई एबिलिटी नहीं बदल सकता, क्योंकि उसकी माँग किसी एबिलिटी को पढ़ सकती है)। अधिकतम चार। Gravewatch की कब्र खोदने वाली कुदाल कमज़ोर वार्डन के लिए भारी काम है:

```json
"requires": [
  {
    "value": { "abilityScore": "sinew" },
    "atLeast": 3,
    "otherwise": { "modifiers": [{ "to": "checks", "skills": ["dig"], "flat": -1 }] }
  }
]
```

शर्त एबिलिटी को वैसे पढ़ती है जैसा पहनने वाले के आइटम उसे छोड़ते हैं, इसलिए Sinew को 3 पर सेट करने वाले दस्ताने कुदाल की शर्त पूरी कर देते हैं।

चेक पर:

- उसके बारे में हर मॉडिफ़ायर अपनी संख्या जोड़ता है, और उसके डाइस रोल होते हैं: जोड़ वाले चेक पर स्थिर संख्या, पूल पर डाइस। एबिलिटी चेक, और ऐसा चेक जिसका नाम नियमसेट नहीं दे सकता, सिर्फ़ वह पढ़ते हैं जो किसी खास चीज़ तक सीमित नहीं किया गया, और सेव सिर्फ़ वह पढ़ता है जो सेव के बारे में है।
- हर स्रोत से एडवांटेज और डिसएडवांटेज, Game Master का `mode=` भी, एक-दूसरे को रद्द करते हैं: दोनों में से हर एक कम से कम एक हो, तो चेक एक बार रोल होता है। सिर्फ़ वह नियमसेट किसी ओर झुकता है जो दो बार रोल करता ही है (`resolution.advantage`)।
- जिस सेव में कोई स्थिति या आइटम विफल करता है, वह बिना रोल के विफल होता है, और उस पर कुछ खर्च नहीं होता।
- रिकॉर्ड बताता है कि उसे किसने बदला: संख्या के लिए `effects="-1"`, जिसने भी बदला उसके लिए `from="Leather coat"`, और बिना रोल के विफल हुए सेव के लिए `automatic="true"`। डाइस कार्ड भी यही दिखाता है, और Game Master अगले टर्न इसे पढ़ता है। उसे बताया जाता है कि Engine ये लागू करता है, इसलिए वह इन्हें दोबारा नहीं जोड़ता।

Gravewatch पूल पर यही दिखाता है: बाइंड की गई Dawn bell, Ward में एक डाइस जोड़ती है, और Rattled, Soothe और Barter से एक घटाती है।

## स्थितियों, स्तरों, आइटम और शीट पंक्तियों से प्रकार वाले बचाव

`combat.conditions[]` और `combat.levels[]` `resist`, `vulnerable`, `immune` (हर एक 1–30 एंट्री) और `conditionImmunities` (1–40 स्थिति ID) दे सकते हैं। ये तब लागू होते हैं जब स्थिति लागू हो या स्तर की सीमा तक पहुँचा जा चुका हो। नई मिली स्थिति इम्यूनिटी उस स्थिति को खत्म कर देती है अगर वह पहले से सक्रिय हो, और उसे फिर लगने से रोकती है। इम्यूनिटी प्रतिरोध पर भारी पड़ती है; प्रतिरोध और कमज़ोरी एक-दूसरे को रद्द करते हैं। कई प्रतिरोध कभी नुकसान को दो बार आधा नहीं करते।

`resist` और `immune` जीव वाला रूप इस्तेमाल करते हैं: नुकसान का शब्द या `{ "type": "bludgeoning",
"except": ["magical"] }`। वार पर कोई भी नामित टैग उस एंट्री को पार कर जाता है। `vulnerable` साधारण नुकसान के शब्द ही रहता है। अपवाद का यही रूप आइटम के `worn` और `carried` असर पर भी चलता है। अपवाद के टैग `items.tags` में घोषित करें और उन्हें हथियार या स्पेल की qualities पर रखें। उदाहरण के लिए, Stoneskin एक स्थिति की मैपिंग है:

```json
{
  "condition": "stoneskin",
  "resist": [
    { "type": "bludgeoning", "except": ["magical"] },
    { "type": "piercing", "except": ["magical"] },
    { "type": "slashing", "except": ["magical"] }
  ]
}
```

Armor of invulnerability अपने `worn` असर के अंदर वही `resist` ऐरे इस्तेमाल करता है। Protection from Energy `resist: ["fire"]` दे सकता है; Brave जैसा गुण `conditionImmunities: ["frightened"]` दे सकता है। स्तर अपनी सीमा पर `resist: ["poison"]` दे सकता है। जब `combat.damageTypes` शब्दावली घोषित करता है, तो अनजान स्थिर नुकसान शब्द बताए जाते हैं, जैसे जीवों के लिए; उस घोषणा के बिना नुकसान के शब्द खुला टेक्स्ट हैं।

ancestry या कैटलॉग गुणों के लिए, `combat.sheetHides` में अधिकतम आठ स्रोत होते हैं (खाली ऐरे मंज़ूर है)। हर एक शीट की किसी सूची, उस सूची के एक text या enum कॉलम, और चार प्रकारों में से एक का नाम देता है। ऐसे dwarf के लिए जिसकी traits पंक्ति के `resistance` कॉलम में `"poison"` है:

```json
"sheetHides": [{ "list": "traits", "column": "resistance", "kind": "resist" }]
```

हर पंक्ति कॉमा से अलग किए शब्द देती है, जिन्हें आसपास की खाली जगह हटाकर छोटे-बड़े अक्षर के फ़र्क के बिना मिलाया जाता है; खाली शब्द छोड़ दिए जाते हैं। `"fire"` वाली पंक्ति जोड़ने पर आग का प्रतिरोध जुड़ता है; उसे हटाने पर वह स्रोत हट जाता है। प्रतिरोध और इम्यूनिटी के शब्दों में `except` हो सकता है, जैसे `"bludgeoning except magical silvered"` में। कमज़ोरियाँ और स्थिति इम्यूनिटी साधारण शब्द हैं। शीट टेक्स्ट में अनजान घोषित नुकसान शब्द अनदेखे होते हैं, अनजान स्थिति ID की तरह; स्थिति इम्यूनिटी वाले enum कॉलम को इंपोर्ट पर सिर्फ़ स्थिति ID घोषित करने चाहिए। शीट, बैटल और Game Master के सारांश में ये बचाव और उनके अपवाद शामिल होते हैं।

## लड़ाई में हथियार

आइटम हथियार हो सकता है (Capability API 1.55)। उसका `attack` वैसा ही होता है जैसी combat ब्लॉक की [अटैक पंक्तियाँ](ruleset-combat.md#combat-a-fight-your-own-rules-resolve) होती हैं, कॉलम की जगह मानों के साथ, और [नियमसेट वाली लड़ाई](ruleset-combat.md#combat-a-fight-your-own-rules-resolve) उसे अटैक के रूप में तब तक देती है जब तक आइटम पहना हुआ है: जितने हाथ वह लेता है उनमें पकड़ा हुआ, और जहाँ बाइंड होता है वहाँ बाइंड। रख दिया गया या सिर्फ़ साथ रखा आइटम कुछ नहीं देता, और अटैक पंक्तियाँ और जीव के अपने एक्शन बिल्कुल पहले जैसे काम करते हैं। Ember Roads की हाथ वाली कुल्हाड़ी:

```json
"attack": {
  "budget": "act",
  "toHit": { "abilities": { "stat": "swing" } },
  "damage": { "dice": { "stat": "damage" }, "abilities": { "stat": "swing" }, "type": "cut" },
  "reach": 2,
  "range": { "normal": 10, "long": 20 }
}
```

- `budget`: वह जो बजट खर्च करता है, `combat.economy.budgets` में से एक।
- `toHit`: हिट के लिए वह क्या जोड़ता है। `abilities` एक या ज़्यादा एबिलिटी ID हैं, और उनमें से सबसे अच्छी गिनी जाती है (फ़ाइनेस हथियार दो सूचीबद्ध करता है)। `skill` उतना जोड़ता है जितना उस स्किल का चेक जोड़ता है, स्किल की अपनी एबिलिटी की जगह अटैक की एबिलिटी के साथ, जैसे अटैक पंक्ति करती है। `proficiency` धारक की शीट का मान है: जहाँ यह 0 से ऊपर पढ़ा जाए, वहाँ नियमसेट का दक्षता बोनस जुड़ता है (हमेशा के लिए `{ "const": 1 }`)। `bonus` एक संख्या है। `sheetBonus` धारक की शीट से पढ़ी गई संख्या है जो जैसी है वैसी जुड़ती है, उस चीज़ के लिए जो धारक किसी तरह के हर हथियार में लाता है, न कि जो हथियार खुद है: 5e की Archery fighting style हर दूरी वाले हथियार को `{ "derived": "archery" }` देती है, यानी ऐसा निकाला गया मान जो archer के लिए 2 और बाकी सबके लिए 0 है (Capability API 1.95; आइटम के तथ्य इसे शीट पर इसके नाम से बताते हैं)। `target` इस हथियार के अटैक के लिए पूल वाली लड़ाई का अपना हर डाइस का लक्ष्य है (Gravewatch की कुदाल पूल के 7 के बजाय 6 से हर डाइस गिनती है), और सिर्फ़ वही `dice-pool` नियमसेट इसे दे सकता है जिसका `target` बदल सकता हो; जोड़ वाली लड़ाई में उसका `bonus` यही बात कहता है।
- `damage`: वह जो `dice` लगाता है, उसकी नुकसान वाली `abilities` में से सबसे अच्छी जोड़कर, एक `bonus`, और एक `type`। जोड़ वाली लड़ाई को `dice` चाहिए; पूल वाली लड़ाई में हिट अपनी सफलताएँ नुकसान के रूप में देता है और `dice` पूल के अपने डाइस में से उतने और जोड़ता है। `sheetBonus` (Capability API 1.97) धारक की शीट से पढ़ी संख्या है जो `toHit` वाली की तरह नुकसान में जुड़ती है, और `"oneHanded": true` के साथ सिर्फ़ तब गिनी जाती है जब हथियार एक हाथ में पकड़ा हो: दो हाथों से चलाया गया `versatile` हथियार नहीं, और न ऐसा जो किसी स्लॉट के दो लेता हो। 5e का Dueling `{ "derived": "dueling" }` देता है, यानी एक हथियार पकड़े duelist के लिए 2। `rerollUpTo` (Capability API 1.98) धारक की शीट का एक मान है: हथियार के अपने नुकसान डाइस जो उसके बराबर या नीचे हों, एक बार फिर फेंके जाते हैं और नया फलक रहता है, क्रिटिकल के अतिरिक्त डाइस भी, सिर्फ़ तब जब हथियार दो हाथों से चलाया जा रहा हो (खाली हाथों वाला `versatile` हथियार, या ऐसा जो किसी स्लॉट के दो लेता हो) और सिर्फ़ जोड़ वाली लड़ाई में। 5e का Great Weapon Fighting `{ "derived": "great_weapon_fighting" }` देता है, इस स्टाइल के साथ 2।
- `reach` और `range` (`normal`, और जितना आगे तक वह फिर भी जाता है उसके लिए `long`) आपकी `combat.distance` इकाई में हैं, और उसे ज़रूरी बनाते हैं। दोनों वाला हथियार फेंका जाता है, जैसे अटैक पंक्ति: पास में वार, उससे आगे फेंकना। दोनों में से कुछ न हो तो वह एक सेल तक पहुँचता है।
- `versatile`: वह `dice` जो वह इसके बजाय तब लगाता है जब उसके लिए हर स्लॉट में, धारक के पहने सामान के बीच, उतनी ही और जगह हो: एक हाथ में भाला, दूसरा हाथ खाली।
- `strikes`: एक खर्च कितने वार खरीदता है, धारक की शीट से, जैसे अटैक पंक्ति का `strikes`। इसके बिना हथियार हर खर्च पर एक वार है, उसके चलाने वाले के पास कितने भी अटैक हों।

इनमें से कोई भी संख्या या शब्द इसके बजाय आइटम का अपना स्टैट पढ़ सकता है: `{ "stat": "damage" }` आइटम का `damage` है, और जिस स्टैट को आइटम कुछ नहीं देता, वह ऐसा है मानो मान लिखा ही न गया हो। `abilities` और `skill` ऐसा enum स्टैट पढ़ते हैं जिसके शब्द एबिलिटी या स्किल ID हैं, और `type` टेक्स्ट या enum स्टैट। इसलिए Game Master का किसी हथियार के `like=` गढ़ा आइटम भी हथियार है, अपने स्टैट से लड़ता है, और किसी भी स्टैट की तरह `rarityCaps` में रखा जाता है (आपका लिखा मान जैसा है वैसा कॉपी होता है)। बिना स्लॉट और बिना बाइंडिंग के गढ़ा आइटम कभी पहना नहीं जाता, इसलिए वह अटैक के बिना बनता है। छोटा मॉडल अक्सर हथियार का वर्णन करता है और `like=` छोड़ देता है, इसलिए आपके हथियारों की किसी श्रेणी में बिना शुरुआती आधार के गढ़ा आइटम उस श्रेणी के आपके उस हथियार की तरह लड़ता है जो नाम से उससे सबसे ज़्यादा मिलता है (किसी भी दिशा में साझा शब्द, इसलिए crossbow, bow जैसा है), या उनमें से पहले की तरह, और उस अटैक में पढ़ा जाने वाला हर वह स्टैट लेता है जो प्रस्ताव में छूट गया, और जवाब यह बताता है ("It fights as Hand axe does.")। Game Master का प्रस्ताव फ़ॉर्म भी उसे बताता है कि किसी हथियार जैसा बना हथियार उसी की तरह लड़ता है।

हथियार के टैग वही हैं जो उसके वार साथ ले जाते हैं। जीव की `resist` या `immune` एंट्री बता सकती है कि उसके पार क्या जाता है: `{ "type": "tearing", "except": ["silver"] }` `silver` टैग वाले हथियार से पूरा लिया जाता है, और बाकी किसी भी चीज़ से उसका प्रतिरोध होता है। Gravewatch का grave wight ऐसे ही लिखा गया है, और उसी नियमसेट की चाँदी की ताबूत-कील उसके पार जाती है। जो नुकसान हथियार आइटम से नहीं आता, वह `qualities` (Capability API 1.101) से, उन्हीं आइटम टैग में, बताता है कि वह क्या साथ ले जाता है: कैटलॉग एंट्री के `mechanics` पर (स्पेल) और जीव के एक्शन के `damage` पर (deva की mace)। 5e का "nonmagical अटैक से bludgeoning, piercing और slashing का प्रतिरोध" `{ "type": "slashing", "except": ["magical"] }` है, बाकी दो के लिए भी वैसा ही, साथ में उसके जादुई हथियारों के टैग पर `magical` और उसके स्पेल पर और SRD जिन जीव अटैक को जादुई कहता है उन पर `"qualities": ["magical"]`।

हथियार का ब्योरा और Game Master की लाइन बताते हैं कि वह क्या करता है: `attack (Action): Brawn to hit, 1d6 + Brawn cut, reach 2 paces, range 10 to 20 paces`, Ember Roads के जंगली सूअर वाले भाले के लिए `1d8 with a hand free` के साथ, और Gravewatch की कुदाल के साथ `at 6`।

### गोला-बारूद और रीलोड

हथियार कुछ चला सकता है, और अपने अंदर भरी हुई गिनती रख सकता है (Capability API 1.57)। Ember Roads का शिकारी धनुष तीर चलाता है, और Gravewatch की पहरे वाली पिस्तौल एक गोली रखती है, जो वार्डन के छर्रे और बारूद से भरी जाती है:

```json
"ammo": { "tag": "arrow", "recover": 0.5 }
```

```json
"ammo": { "tag": "shot" },
"clip": { "max": 1, "reload": "act" }
```

- `ammo`: हथियार क्या चलाता है, आपके आइटम `tags` में से एक से। हर अटैक धारक के साथ रखे उस टैग वाले आइटम में से `perAttack` (कुछ न कहे तो 1) लेता है, पहने हों या नहीं, उसके थैले के ऐसे पहले स्टैक से, फिर अगले से। हथियार तभी दिया जाता है जब उसके पास काफ़ी हों, और लड़ाई का मेनू बताता है कि कितने बचे हैं। पार्टी के जीतने वाली लड़ाई के बाद, हर एक ने जितने चलाए उनका `recover` (0 से 1 तक) हिस्सा उसी स्टैक में लौट आता है जिससे वे आए थे: हिस्सा पूरी लड़ाई पर जोड़ा जाता है और हर स्टैक के लिए एक बार नीचे राउंड होता है, इसलिए एक तरकश से चलाए पाँच तीरों का आधा दो है। हारी हुई लड़ाई, या जिससे भागे, कुछ वापस नहीं देती।
- `clip`: हथियार में ही रखी भरी हुई गिनती। `max` बताता है कि उसमें कितने आते हैं, लिखा हुआ या आइटम के किसी नंबर स्टैट से पढ़ा हुआ, और `reload` वह बजट है जो रीलोड में खर्च होता है। अटैक थैले से लेने के बजाय भरा हुआ खर्च करता है, और हथियार तभी दिया जाता है जब उसमें एक अटैक लायक भरा हो। लड़ाई के मेनू पर **Reload** (रीलोड) विकल्प `reload` खर्च करके उसे भरता है: जहाँ `ammo` है वहाँ थैले से (थैले में कम हो तो जितना है उतना), और जहाँ नहीं है वहाँ पूरा। गिनती हथियार के इन्वेंटरी स्टैक पर रखी जाती है, इसलिए एक लड़ाई में खाली हुई पिस्तौल अगली में भी खाली रहती है। जिस हथियार को अभी तक किसी ने नहीं चलाया वह भरा हुआ है, और वह भी जिसे खिलाड़ी उसी हथियार के कई वाले स्टैक में डाल देता है, क्योंकि भरी हुई गिनती एक हथियार की होती है। लड़ाई के बाद क्लिप की गोलियाँ उठाई नहीं जातीं, इसलिए `recover` बिना क्लिप वाले हथियार के लिए है।

लड़ाई जो चलाती, भरती और उठाती है, वह हर कदम के साथ इन्वेंटरी में लिखा जाता है, जैसे पार्टी का स्वास्थ्य, और जर्नल बताता है कि क्या इस्तेमाल हुआ। जिस कदम का स्टैक नहीं रहा, या जिसमें लड़ाई की गिनती से कम हैं, वह अस्वीकार होता है, जैसे खर्च हुआ ऐसा आइटम जिसे लड़ाई नहीं ढूँढ़ पाती। लड़ाई का लॉग हर शॉट, रीलोड और उठाना बताता है ("Hunting bow: 2 left to shoot.", "Ada loads 1 into Watch pistol: 1 of 1 loaded."), और आइटम का ब्योरा और Game Master की लाइन बताते हैं कि हथियार क्या चलाता है और कितना रखता है: `ammunition Arrow (1 an attack, 50% picked up after a won fight)` और `holds 1, reload (Act)`।

### मोड, दूसरा हथियार, निचली सीमा और हिट पर स्थितियाँ

हथियार के पास अटैक करने के दूसरे तरीके, दूसरे हाथ में एक जोड़ीदार, कम से कम लगने वाला नुकसान और जिस पर लगे उस पर डाली जाने वाली स्थितियाँ हो सकती हैं (Capability API 1.58)। Ember Roads का शिकारी धनुष बौछार (volley) चला सकता है, और Gravewatch की चाँदी की ताबूत-कील हर हाथ में एक पकड़ी जा सकती है और जिसे गहरा काटती है उसे चिह्नित करती है:

```json
"modes": [{ "id": "volley", "label": "Volley", "ammo": 2, "toHit": -2, "targets": 2 }]
```

```json
"offHand": true,
"onHit": [{ "condition": "marked", "atLeast": 2, "rounds": 2 }]
```

- `modes`: अटैक करने के अधिकतम छह दूसरे तरीके, हर एक `id`, `label` और उसके बदलाव के साथ। `ammo` बताता है कि उसमें एक अटैक कितने चलाता है, इसलिए हथियार के पास चलाने के लिए `ammo` या `clip` होता है। `toHit` बताता है कि वह हिट के लिए क्या जोड़ता है, पूल वाली लड़ाई में डाइस और जोड़ वाली में संख्या। `target` पूल वाली लड़ाई का हर डाइस का लक्ष्य इतना बदलता है (हथियार के अपने से, वरना पूल के; `+1` कठिन है), जहाँ पूल का लक्ष्य बदल सकता है। `targets` बताता है कि उसे कितनों पर चलाया जा सकता है, हर एक का अपना अटैक रोल। अटैक चुनने के बाद लड़ाई का मेनू पूछता है कि किस तरीके से (जहाँ इनिशिएटिव शैलियाँ हैं, वहाँ शैली के बाद), हर एक के साथ उससे अपेक्षित नतीजा, और सिर्फ़ वे मोड देता है जिनके लिए धारक के पास शॉट हैं। Engine का खेला पार्टी सदस्य एक लक्ष्य पर चलाए हर मोड को तौलता है, और कई लक्ष्यों वाला मोड खिलाड़ी पर छोड़ता है। विंडो में अटैक वैसे ही होता है जैसा वह है।
- `offHand`: दूसरे हाथ का हथियार। combat ब्लॉक बताता है कि दूसरा अटैक कौन सा बजट खर्च करता है, और क्या उसका नुकसान धनात्मक एबिलिटी रखता है:

  ```json
  "offHand": { "budget": "quick", "ability": "full" }
  ```

  जब धारक इस टर्न `offHand` चिह्नित किसी एक हथियार से अटैक कर चुका हो, तो वह जो भी दूसरा ऐसा हथियार पहनता है, वह उस बजट पर दूसरा अटैक देता है, जिसका नाम मेनू पर "Silver coffin nail, off hand" होता है। `ability` या तो `full` (डिफ़ॉल्ट) है या `penalty-only`, जो नुकसान वाली एबिलिटी तभी जोड़ता है जब वह कुछ घटाती हो, जैसे 5e की दो-हथियार लड़ाई करती है। दूसरे हाथ का अटैक एक वार है, मुख्य अटैक कितने भी वार खरीदे, और दूर जाते किसी व्यक्ति पर वार कभी नहीं। `offHand` चिह्नित हथियार को combat ब्लॉक का `offHand` चाहिए। `fullWhen` (Capability API 1.97) लड़ाके की शीट का एक मान है: 0 से ऊपर होने पर, उस लड़ाके का दूसरा हाथ पूरी एबिलिटी रखता है, `ability` कुछ भी कहे, जैसे 5e की Two-Weapon Fighting style करती है।

- `floor`: हिट कम से कम कितना नुकसान करता है, लिखा हुआ या आइटम के नंबर स्टैट से पढ़ा हुआ। पूल वाली लड़ाई का सोखने के बाद का नुकसान, या जोड़ वाली लड़ाई का नुकसान, प्रतिरोध के आधा करने से पहले इस तक बढ़ाया जाता है, और लॉग यह बताता है। खर्च करने वाला वार अपने करने वाले की संख्या फेंकता है और कभी नहीं बढ़ाया जाता।
- `onHit`: आपकी अधिकतम चार स्थितियाँ जो लक्ष्य पर लगती हैं जब वार का नुकसान `atLeast` तक पहुँचा हो, उसके अपने `rounds` टर्न के लिए, या इसके बिना तब तक जब तक कुछ उसे हटा न दे। नुकसान वह है जो सोखने और उनके प्रतिरोधों के बाद उन तक पहुँचा; लेने वाला वार नुकसान के बजाय इनिशिएटिव लेता है, इसलिए वह कोई स्थिति नहीं डालता। एंट्री में `save: { "save": <save id>, "difficulty": n }` भी हो सकता है, जिसे लक्ष्य स्थिति लगते समय रोल करता है, और सफलता उसे दूर रखती है, और `saveEnds: { "save", "difficulty", "at": "turn-start" | "turn-end" | "damaged" }` भी, जो स्थिति को तब तक बनाए रखता है जब तक उसका धारक अपने हर टर्न की शुरुआत या अंत में, या शून्य से ऊपर के नुकसान पर, वह सेव न कर ले (तब उसमें कोई `rounds` नहीं होता)। दोनों उस स्थिति के विरुद्ध सेव गिने जाते हैं, और हथियार जादुई हो तो जादू के विरुद्ध भी (Capability API 1.169)। 5e का sword of wounding: `{ "condition": "wounded", "atLeast": 1, "saveEnds": { "save": "con_save", "difficulty": 15, "at": "turn-start" } }`।
- `plus`: हर हिट पर अधिकतम तीन और मात्राएँ, हर एक `{ "dice", "flat", "type", "save", "targetIs", "when" }`, जो अपने आप में रोल होती है, प्रकार पाती है और जिसका अलग प्रतिरोध होता है (Capability API 1.169)। `save` अपनी `difficulty` और `onSuccess` (`half` या `none`) बताता है। `targetIs` इसे सिर्फ़ उन जीव प्रकारों या टैग वाले लक्ष्य को देता है (लड़ाई वाले पेज पर [हर कुंजी](ruleset-combat.md#every-key) के तहत जीव प्रकार और लक्ष्य की जाँच देखें)। `when: "critical"` इसे सिर्फ़ क्रिटिकल हिट पर देता है; किसी भी खंड के डाइस क्रिटिकल हिट पर हथियार के डाइस की तरह दोगुने होते हैं। javelin of lightning `{ "dice": "4d6", "type": "lightning" }` है; dragon slayer `{ "dice": "3d6", "type": "slashing", "targetIs": { "types": ["dragon"] } }`; sword of sharpness `{ "flat": 14, "type": "slashing", "when": "critical" }`। अनुमान किसी खंड को सिर्फ़ उस लक्ष्य के विरुद्ध गिनता है जिस तक वह पहुँचता है, और सिर्फ़ क्रिटिकल वाले खंड को कभी नहीं। `when: "toggled"` इसे सिर्फ़ तब देता है जब आइटम का स्विच चालू हो (Capability API 1.170, नीचे `toggle` देखें)।

हथियार का ब्योरा और Game Master की लाइन यह सब बताते हैं: `modes Volley (2 shots, -2 to hit, up to 2 targets)`, `off hand (Quick)`, `at least 1 on a hit before resistance`, `+3d6 slashing against Dragon` और `Marked for 2 rounds when a hit deals 2 or more`।

<a id="armor-and-worn-effects-in-a-fight"></a>

## लड़ाई में कवच और पहनने के असर

पहने या साथ रखे होने पर आइटम जो करता है, वह लड़ाई भी बदल सकता है (Capability API 1.56), उसके धारक के लिए, उसकी स्थितियों और स्तरों के साथ। हर एक में स्थिति के वे हिस्से होते हैं जिन्हें लड़ाई पढ़ती है:

- `effects`: स्थिति के असर में से कोई भी, सिवाय उन पाँच के जो स्तर में नहीं हो सकते (`half-move-to-stand`, `ends-on-damage`, `cannot-target-source`, `cannot-target-source-side`, `cannot-approach-source`), क्योंकि किसी ने आइटम को उसके धारक पर नहीं डाला और वह कभी अपने आप खत्म नहीं होता: `own-attacks-advantage`, `attacks-against-disadvantage`, `resist-all`, `speed-zero` और बाकी।
- `modifiers`: चेक और सेव के साथ-साथ डिफ़ेंस, अटैक और रफ़्तार के लिए `to` वाले बदलाव, बिल्कुल स्थिति की तरह; `dice-pool` लड़ाई में अटैक में बदलाव डाइस की स्थिर संख्या है, जैसे स्थिति का होता है।
- `resist`, `vulnerable` और `immune`: नुकसान के प्रकार जिनका उसका धारक आधा, दोगुना या कुछ नहीं लेता, जैसे जीव के (और `combat.damageTypes` घोषित करने पर उनसे जाँचे जाते हैं)। `conditionImmunities`: आपकी अपनी स्थितियाँ जो उसके धारक पर कभी नहीं लगतीं।

Gravewatch की श्रापित widow's ring हर अटैक पर एक डाइस घटाती है, उसकी बाइंड की गई Dawn bell अपने धारक को rattled होने से बचाती है, और साथ रखा Ember Roads का waystone गर्मी दूर रखता है:

```json
"worn": { "modifiers": [{ "to": "attacks", "flat": -1 }] }
```

```json
"worn": { "modifiers": [{ "to": "checks", "skills": ["ward"], "flat": 1 }], "conditionImmunities": ["rattled"] }
```

```json
"carried": { "modifiers": [{ "to": "checks", "skills": ["sway"], "flat": 1 }], "resist": ["burn"] }
```

लड़ाई हर आइटम को एक बार पढ़ती है, स्टैक के नाम से (लॉग में रोल के साथ "Widow's ring", और डिफ़ेंस पर भी), जैसे चेक करता है; पूरी न हुई शर्त का `otherwise` लड़ाई में भी गिना जाता है, इसलिए पहनने वाले के लिए बहुत भारी कवच रफ़्तार घटा सकता है। आइटम का ब्योरा और Game Master की लाइन यह सब बताते हैं ("While worn: -1 on attacks", "worn: +1 on checks (Ward), immune to Rattled")। जो कवच बस डिफ़ेंस या सोखने में जोड़ता है, वह `itemStat` से पढ़ा जाने वाला आइटम स्टैट है (शीट पर आइटम देखें), जैसे Ember Roads का Guard पहना हुआ कोट पढ़ता है।

**कठोरता।** जहाँ इनिशिएटिव ऐसी संख्या है जिसे अटैक बदलते हैं, वहाँ `combat.pool.hardness` लड़ाके की कठोरता है, जो लड़ाई शुरू होते समय उसकी शीट से पढ़ी जाती है (`itemStat` के रास्ते उसके कवच की), और जीव अपनी `hardness` देता है। खर्च करने वाला वार जिसके डाइस इससे नीचे हों, लगता है और कुछ नहीं करता: करने वाले की संख्या फिर भी बेस पर लौटती है, लॉग यह बताता है ("Ada's Grave spade lands on the warden with 5 dice, below a hardness of 6, and does nothing."), और मेनू उसके लिए कोई नुकसान नहीं बताता। यह सिर्फ़ खर्च करने वाली शैली वाले नियमसेट में हो सकता है, और शीट के रूप में लिखा जीव इसे शीट से लेता है।

<a id="using-items-in-a-fight"></a>

## लड़ाई में आइटम इस्तेमाल करना

आइटम लड़ाई में इस्तेमाल किया जा सकता है (Capability API 1.59): कट पर दबाई गई पुल्टिस, निगला गया टॉनिक, बजाई गई घंटी। उसका `use` बताता है कि इस्तेमाल करने से क्या होता है, उन्हीं शब्दों में जो कैटलॉग एंट्री का `mechanics` इस्तेमाल करता है ([लड़ाई `mechanics` से क्या पढ़ती है](ruleset-combat.md#what-a-fight-reads-from-mechanics) देखें): `kind` (`heal`, `attack`, `buff` या `debuff`), `amount`, `damageType`, `plus`, `attackRoll`, `save`, `applies`, `temporary`, `range`, `area`, `targets`, `targetCount`, `friendlyFire`, और Capability API 1.174 से `concentration` और `zone`, उसके खर्च होने वाले `budget` के साथ, या `free`। Ember Roads की पुल्टिस, और Gravewatch का गर्माहट वाला टॉनिक और भोर की घंटी:

```json
"use": { "kind": "heal", "budget": "act", "range": 0, "targets": "ally", "amount": { "dice": "1d4", "flat": 1 }, "consumes": true }
```

```json
"use": { "kind": "heal", "budget": "quick", "targets": "self", "amount": { "flat": 1 }, "consumes": true }
```

```json
"stack": 1,
"use": {
  "kind": "debuff",
  "budget": "act",
  "targets": "enemy",
  "save": { "save": "steel", "onSuccess": "negates" },
  "saveDifficulty": 7,
  "applies": [{ "condition": "rattled", "duration": { "rounds": 2 } }],
  "charges": 1
},
"charges": { "max": 3 }
```

- इस्तेमाल लड़ाई के मेनू पर **Items** (आइटम) के नीचे होता है, आइटम के नाम से ("Poultice"), स्टैक का नाम कुछ भी हो। स्लॉट लेने वाला या बाइंड होने वाला आइटम तब इस्तेमाल होता है जब वह पहना हुआ हो (और जहाँ बाइंड होता है वहाँ बाइंड), जैसे घंटी; बाकी कोई भी तब जब वह साथ रखा हो।
- यह बजट खर्च करता है, या `free` है, और खुद से भुगतान करता है: `cost`, `perCostStep`, `check`, `concentration`, `reaction`, `scales`, `gives`, `standard` या `rider` शीट में रखी कैटलॉग एंट्री के लिए हैं, और इस्तेमाल पर अस्वीकार होते हैं।
- `attackRoll` वाले इस्तेमाल पर `toHit` बताता है कि वह हिट के लिए क्या जोड़ता है, जैसे हथियार का `toHit` बताता है (लड़ाई में हथियार देखें): एबिलिटी, स्किल, बोनस और, पूल वाली लड़ाई में, हर डाइस का लक्ष्य। इसके बिना रोल कुछ नहीं जोड़ता।
- `saveDifficulty`: वह संख्या जिसके विरुद्ध उसका माँगा सेव रोल होता है (उसका अपना, उसकी लगाई स्थिति को खत्म करने वाला, या बिना `difficulty` वाले खंड का), लिखी हुई या आइटम के नंबर स्टैट से पढ़ी हुई। शीट पर एंट्री यह संख्या अपने कैटलॉग के स्रोत से पढ़ती है; आइटम का कोई स्रोत नहीं, इसलिए वह अपनी संख्या खुद बताता है।
- `consumes: true` हर इस्तेमाल पर आइटम के स्टैक से एक घटाता है, और मेनू बताता है कि कितने बचे हैं। आखिरी इस्तेमाल स्टैक को साथ ले जाता है।
- `restore` (Capability API 1.60) जिस शीट पर लगता है उसके किसी पूल का कुछ हिस्सा लौटाता है, जैसे खून की थैली खून लौटाती है: `{ "pool": "resolve", "amount": { "flat": 1 } }`, `dice` और `flat` के साथ, जैसे `amount` में होते हैं। यह आपके किसी लाइव पूल का नाम देता है, स्वास्थ्य पूल का कभी नहीं (स्वास्थ्य हील से लौटता है), और मदद करने वाले इस्तेमाल पर होता है, `heal` या `buff`। जीव के पास पूल नहीं होते, इसलिए उसे कुछ नहीं मिलता। लॉग यह बताता है ("Ada gets back 1 Resolve, and is on 3 of 4."), और Engine का खेला पार्टी सदस्य भरे पूल को छोड़ देता है। Gravewatch का गर्माहट वाला टॉनिक अपनी हीलिंग के साथ Resolve का एक पॉइंट लौटाता है।
- `charges` आइटम के अपने `charges` में से उतने खर्च करता है, जिनका `max` बताता है कि उसमें कितने हैं, 1 से 100 तक, लिखा हुआ या आइटम के नंबर स्टैट से पढ़ा हुआ (जो आइटम वह स्टैट 1 से कम देता है वह अस्वीकार होता है, और 100 से ऊपर वाला 100 रखता है)। गिनती आइटम के इन्वेंटरी स्टैक पर रखी जाती है, इसलिए एक लड़ाई में दो बार बजाई गई घंटी में अगली लड़ाई में एक चार्ज बचता है, और जिसे किसी ने नहीं बजाया वह भरी हुई है। चार्ज एक आइटम के होते हैं, इसलिए उन्हें रखने वाले आइटम का `stack` 1 होता है। इस्तेमाल या तो आइटम खत्म करता है या चार्ज खर्च करता है, दोनों कभी नहीं, और आइटम के चार्ज हमेशा उसके इस्तेमाल से ही खर्च होते हैं। `charges` की दो और कुंजियाँ होती हैं (Capability API 1.61), जैसे Gravewatch की भोर की घंटी में:

  ```json
  "charges": { "max": 3, "recharge": { "rests": ["vigil"], "amount": "max" }, "breaksOn": { "die": 20, "atMost": 1 } }
  ```

  - `recharge`: आपके कौन से `rests` चार्ज वापस लाते हैं, और कितने: `"max"` आइटम को भर देता है, और कोई मात्रा (`{ "dice": "1d6", "flat": 1 }`) उतने लौटाती है, `max` से कभी आगे नहीं। आराम उसके कैरेक्टर के साथ रखे हर उस आइटम के चार्ज लौटाता है जो उसका नाम देता है, चाहे शीट का Rest बटन उसे ले या Game Master का `[sheet: op="rest"]`; शीट और थैला साथ लिखे जाते हैं, और दोबारा जनरेट हुआ जवाब सिर्फ़ एक बार रीचार्ज करता है। शीट बताती है कि आराम के बाद क्या लौटा ("Dawn bell 3/3 charges"), और Game Master इन्वेंटरी में हर आइटम के साथ उसके बचे चार्ज देखता है ("2 of 3 charges left")।
  - `breaksOn`: जब कोई इस्तेमाल आखिरी चार्ज खर्च करता है, तो Engine d`die` रोल करता है, और `atMost` या उससे कम आने पर आइटम टूट जाता है और थैले से चला जाता है, लड़ाई में और उसके बाहर। लड़ाई का लॉग यह बताता है ("Dawn bell breaks (a 1 on its die)."), Use बटन की रिपोर्ट भी ("Its last charge spent, it breaks."), और जर्नल उसे खोया हुआ गिनता है।

- `gate` (Capability API 1.62) ऐसा चेक है जिसे इस्तेमाल करने वाला आइटम के काम करने से पहले पास करता है, जैसे पढ़ने वाले के अपने स्तर से ऊपर के स्पेल का स्क्रॉल माँगता है। `check` बताता है कि क्या रोल होता है: `{ "skill": "ward" }`, `{ "ability": "wits" }`, या शीट का कोई मान (`{ "value": { "derived": "spell_mod" } }`, ऐसी संख्या के लिए जो हर कैरेक्टर के लिए अलग हो, जैसे 5e के कैस्टर का स्पेलकास्टिंग मॉडिफ़ायर)। `difficulty` 1 से 100 तक है, लिखी हुई या आइटम के नंबर स्टैट से पढ़ी हुई (जो आइटम इसे नहीं देता वह मेनू से बाहर रहता है, और उसका Use बटन यह साफ़ बताता है)। `unless` तब चेक छोड़ देता है जब इस्तेमाल करने वाले की शीट का कोई मान कम से कम `atLeast` हो। विफल चेक आइटम को बेकार में खत्म कर देता है (या उसके चार्ज खर्च कर देता है)। लड़ाई में चेक आइटम खर्च होते समय रोल होता है, लड़ाई के अपने डाइस से (पूल वाली लड़ाई में पूल, जहाँ `difficulty` ज़रूरी सफलताएँ हैं) और लड़ाई शुरू होते समय पढ़ी गई शीट की संख्या से, और इस्तेमाल करने वाले की स्थितियाँ और पहने आइटम उस चेक में जो जोड़ते हैं वह गिना जाता है, स्किल का अपना भी। लॉग यह बताता है ("Ada rolls Ward to use Page of the vigil litany: 2 successes from 2 dice at 7 or more (8, 9), needing 2 successes, a success.")। Gravewatch के जागरण-प्रार्थना वाले पन्ने में एक है:

  ```json
  "gate": { "check": { "skill": "ward" }, "difficulty": 2, "unless": { "value": { "abilityScore": "nerve" }, "atLeast": 3 } }
  ```

लड़ाई जो खत्म करती है और जो चार्ज छोड़ती है, वे हर कदम के साथ इन्वेंटरी में लिखे जाते हैं, जैसे हथियार के शॉट, और जर्नल बताता है कि क्या इस्तेमाल हुआ। लड़ाई का लॉग हर इस्तेमाल बताता है ("Poultice: 1 of 2 left.", "Dawn bell: 2 of 3 left.")। Engine का खेला पार्टी सदस्य हील सिर्फ़ घायल पर इस्तेमाल करता है, और कोई भी दूर जाते व्यक्ति पर वार करने के लिए आइटम इस्तेमाल नहीं करता। आइटम का ब्योरा और Game Master की लाइन बताते हैं कि इस्तेमाल करने से क्या होता है: "Use (Action): heals 1d4 + 1, range 0 paces, used up" और `use (Act): Steel 7 save negates it, Rattled, 1 of 3 charges`, और ब्योरा बचे चार्ज दिखाता है। Game Master का आपके किसी आइटम के `like=` गढ़ा आइटम उसी की तरह इस्तेमाल होता है, चार्ज समेत।

## Classic और Tactical बैटल में आइटम

जो नियमसेट अपनी लड़ाइयाँ खुद हल नहीं करता, वह उन्हें Game Mode की अपनी Classic और Tactical बैटल पर छोड़ता है, जहाँ लड़ाई शुरू होने पर एक मॉडल से पूछा जाता है कि इन्वेंटरी के आइटम क्या करते हैं। आपके आइटम का अंदाज़ा नहीं लगाया जाता: `use` वाला हर आइटम Engine की अपनी संख्याओं पर वही करता है जो वह कहता है, और Game Master का अंदाज़ा सिर्फ़ उन आइटम के लिए माँगा जाता है जो आपके नहीं हैं (और `native: false` होने पर किसी के लिए नहीं)।

- `heal` हील करता है और `attack` लक्ष्य के अधिकतम स्वास्थ्य के एक हिस्से जितना नुकसान करता है, उसके `amount` के औसत से: 7 का औसत, जो बुनियादी हथियार का `1d8+3` है, उसके पाँचवें हिस्से से थोड़ा ज़्यादा है, बीसवें हिस्से से कभी कम नहीं और ज़्यादा से ज़्यादा पूरा। यही वह पैमाना है जिस पर combat ब्रिज कैटलॉग एंट्री की संख्याएँ पढ़ता है। `damageType` एलिमेंट है।
- `applies` की पहली स्थिति अपने ही नाम से स्टेटस के रूप में लगती है, अपने `rounds` के लिए (उनके बिना 2), और `buff` या `debuff` अकेला वही स्टेटस है, जो Engine के अपने स्टेटस की तरह डिफ़ेंस बढ़ाता या घटाता है।
- `targets` बताता है कि वह किस पर इस्तेमाल होता है। इसके बिना हील या बफ़ दोस्त पर और अटैक या डीबफ़ दुश्मन पर जाता है।
- `consumes: true` स्टैक से एक घटाता है, और इसके बिना वाला इस्तेमाल आइटम को वहीं छोड़ देता है।
- हिट के लिए रोल, सेव, क्षेत्र, अस्थायी पॉइंट और वापस भरा पूल, इन बैटल में इनकी कोई जगह नहीं, जैसे वहाँ कैटलॉग एंट्री के `mechanics` के लिए नहीं: मेनू पर आइटम का विवरण फिर भी इन्हें बताता है।
- स्लॉट लेने वाला आइटम सिर्फ़ पहने होने पर इस्तेमाल होता है, और बाइंड होने वाला सिर्फ़ बाइंड होने पर, जैसे नियमसेट वाली लड़ाई में। खत्म होने वाला आइटम पहने हुए में से लिया जाता है, थैले में रखे फ़ालतू से कभी नहीं।
- जिस आइटम का इस्तेमाल `charges` खर्च करता है, वह तब तक दिया जाता है जब तक एक इस्तेमाल बचा है, और Items मेनू उसके इस्तेमाल गिनता है। हर इस्तेमाल उन्हें आइटम के स्टैक से खर्च करता है, पहले खिलाड़ी के अपने से, और आखिरी खर्च उसका `breaksOn` रोल करता है: टूटने पर वह थैले से चला जाता है, और जर्नल उसे खोया हुआ गिनता है।
- पहले चेक माँगने वाले आइटम (`gate`) का चेक तब सर्वर पर रोल होता है जब कोई पार्टी सदस्य उसे इस्तेमाल करता है, उस सदस्य की शीट और पहने सामान के साथ (अपने कार्ड के बिना साथी खाली शीट पर रोल करता है, और सिर्फ़ खिलाड़ी की अपनी यूनिट खिलाड़ी के कार्ड का सहारा लेती है), जैसे Use बटन उसे रोल करता है, और `unless` सही होने पर छोड़ दिया जाता है। विफल होने पर आइटम खर्च हो जाता है (या उसके चार्ज) और कुछ नहीं करता, और लॉग यह बताता है: "Ada rolls Ward to use Page of the vigil litany: 0 against 2, failed, and it is used up for nothing."
- बिना `use` वाला आइटम इन बैटल में नहीं दिया जाता, और न ही बिना `amount` वाली हील।

Engine हर आइटम का असर खुद निकालता है, इसलिए स्क्रीन जो भेजती है वह कभी तय नहीं करता कि आपका कोई आइटम क्या करता है।

## लूट

जीती हुई लड़ाई हर Game Mode गेम में, एक बार, पार्टी के थैलों में लूट गिराती है। नियमसेट के बिना वह Game Mode की अपनी टेबल से आती है (कठिन गेम पर ज़्यादा और ज़्यादा दुर्लभ), और ऐसे नियमसेट में भी जो कोई लूट टेबल घोषित नहीं करता और `native` चालू छोड़ता है। लूट टेबल घोषित करने वाला नियमसेट इसके बजाय अपने आइटम गिराता है, और `native: false` वाला व बिना टेबल वाला नियमसेट कुछ नहीं गिराता।

`items` ब्लॉक में `lootTables` (Capability API 1.63) इन्हें सूचीबद्ध करता है, जैसे Gravewatch का कब्र का सामान:

```json
"lootTables": [
  {
    "id": "grave_goods",
    "label": "Grave goods",
    "rolls": "1d2",
    "entries": [
      { "item": "kit/shot-and-powder", "weight": 4, "count": "1d4" },
      { "item": "kit/warming-tonic", "weight": 3 },
      { "item": "kit/litany-page", "weight": 2 },
      { "filter": { "category": "arm" }, "weight": 1 },
      { "coins": "shilling", "weight": 2, "count": "1d6" }
    ]
  }
]
```

- `rolls` बताता है कि टेबल कितनी बार चुनती है: 0 से 20 तक की संख्या, या डाइस (`"1d2"`), डिफ़ॉल्ट 1।
- हर चुनाव दूसरी लाइनों की तुलना में `weight` (डिफ़ॉल्ट 1) के हिसाब से एक लाइन निकालता है। लाइन आपके किसी आइटम का नाम `<catalog>/<entry>` के रूप में देती है, या `rarity`, `category` और `tag` से `filter`, जो मेल खाने वाले हर आइटम में से बराबर संभावना से चुनता है, या (Capability API 1.64) `coins`, यानी आपका कोई सिक्का उसके ID से। `count` बताता है कि कितने गिरते हैं, संख्या या डाइस, डिफ़ॉल्ट 1। लेयर से हटाया गया आइटम या सिक्का कुछ नहीं गिराता, और न ही ऐसा फ़िल्टर जिसे कुछ न मिले।
- जीव-संग्रह का जीव अपनी साथ रखी टेबल का नाम `loot` से देता है ([जीव](ruleset-combat.md#creatures-a-bestiary-a-fight-reads) देखें)। जीती हुई नियमसेट वाली लड़ाई हराए गए हर जीव की टेबल रोल करती है, और जो लड़ाई Engine आपके नियमों से हल नहीं करता उसमें जीव-संग्रह के जीव नहीं होते, इसलिए वह कुछ नहीं गिराती।
- जो गिरता है वह जोड़ने (add) की तरह साझा व्यू में जाता है, पहले खिलाड़ी के थैले से पूछकर, और जो कोई नहीं उठा सकता वह पीछे छूट जाता है। Game Master को मिलने वाला सारांश बताता है कि क्या गिरा और वह पहले से थैलों में है, जर्नल यह बताता है, और एक नोटिफ़िकेशन इसे दिखाता है।
- Game Master कहानी में `[loot: table="grave_goods" who="Ada"]` से टेबल रोल करता है (एक कैरेक्टर के थैले के लिए `who=`), जो उसके इन्वेंटरी टैग की तरह टर्न की शुरुआत से मापा जाता है, इसलिए दोबारा जनरेट हुआ जवाब एक ही बार गिराता है। गिरने वाले हर आइटम का जवाब जोड़ने की तरह दिया जाता है, और उसके निर्देश आपकी टेबल सूचीबद्ध करते हैं।

## पैसे

आपकी `currencies` पार्टी के पैसे हैं। सिक्का थैलों में एक आइटम है, हर सिक्के का किसी भी दूसरे आइटम की तरह एक स्टैक, जिसका नाम उसका `label` है:

- उसके परिवार के हर `perWeight` सिक्कों का वज़न आपके carry स्टैट की एक इकाई होता है, वह अपने धारक के बोझ में गिना जाता है और आने पर उठाने के नियम से रखा जाता है। बिना `perWeight` वाले परिवार का कोई वज़न नहीं।
- खिलाड़ी पिकर की **Coins** (सिक्के) सूची से सिक्के जोड़ता है, और किसी भी स्टैक की तरह उन्हें बाँटता, देता और मिलाता है।
- इन्वेंटरी के स्टैक के ऊपर एक लाइन व्यू में मौजूद हर परिवार के सिक्के और परिवार के सबसे छोटे सिक्के में उनका मूल्य दिखाती है। Game Master हर थैले के साथ वह मूल्य देखता है (`Coin worth 432 pennies`, या खाली बटुए के लिए `no coins`, और खिलाड़ी का थैला कुछ न होने पर भी सूचीबद्ध होता है), और आइटम के साथ आइटम का `cost` (`costs 3 shillings`)।
- Game Master `[inventory: action="pay" amount="3 shillings" who="Ada"]` से भुगतान करता है और `action="earn"` से भुगतान पाता है। `amount` एक गिनती और एक सिक्का है, सिक्का उसके ID या लेबल से, एक या कई, छोटे-बड़े अक्षर कुछ भी हों (`1 penny`, `12 pennies`)। भुगतान एक थैले से निकलता है (`who=` के बिना खिलाड़ी के), सिर्फ़ सिक्के के अपने परिवार में: पहले समा सकने वाले सबसे बड़े सिक्के जाते हैं, फिर बाकी देनदारी पूरी करने वाला सबसे छोटा बचा सिक्का तोड़ा जाता है, और छुट्टा परिवार के छोटे सिक्कों में, सबसे बड़े पहले, लौटता है। जवाब बताता है कि क्या चुकाया गया और क्या लौटा: एक crown वाले बटुए से 3 shillings का भुगतान `Paid with crowns ×1; shillings ×2 back.` है। जो भुगतान थैला पूरा न कर सके वह अस्वीकार होता है (`cannot-afford`), और ऐसे ही आपके पास न होने वाला सिक्का (`unknown-coin`) और बिना मुद्रा वाले नियमसेट में कोई भी भुगतान (`no-currencies`)। कमाई उस सिक्के को जोड़ना है, `who` के थैले में या उठाने के नियम से बाँटकर। जर्नल खर्च और कमाई सूचीबद्ध करता है, और एक नोटिफ़िकेशन इसे दिखाता है। उसके निर्देश आपके सिक्के सूचीबद्ध करते हैं, और ये सिर्फ़ सिक्कों वाले नियमसेट में होते हैं।
- खरीदना एक भुगतान और फिर जोड़ना है, या बाज़ार वाले नियमसेट में `buy` (नीचे)। कोई दुकान स्क्रीन नहीं है।

## शुरुआती सामान

`items.startingGear` (Capability API 1.78) वह सामान सूचीबद्ध करता है जिसे कैरेक्टर शुरुआत में अपने थैले में ले सकता है: क्लास की किट, बैकग्राउंड की, calling की। यह कभी अपने आप नहीं दिया जाता। इन्वेंटरी **Starting gear** (शुरुआती सामान) पंक्ति दिखाती है, और खिलाड़ी एक सामान, उसके हर विकल्प के लिए एक विकल्प और हर सूची से एक आइटम चुनता है, फिर उसे खिलाड़ी के थैले में या किसी पार्टी सदस्य के थैले में ले लेता है। जिस सामान का `fits` कैरेक्टर की शीट पर सही बैठता है, वह पहले सूचीबद्ध होता है, फिर बिना `fits` वाला सामान (किसी भी कैरेक्टर के लिए, जैसे बैकग्राउंड का); हर सामान दिया जाता है, क्योंकि कैरेक्टर की अवधारणा पर खिलाड़ी और Game Master को आपस में सहमत होना है।

```json
"startingGear": [
  {
    "id": "fighter", "label": "Fighter", "group": "class",
    "fits": { "value": { "field": "level_fighter" }, "atLeast": 1 },
    "lines": [{ "item": "equipment/shield", "equip": true }],
    "choices": [
      {
        "label": "Armor",
        "options": [
          { "label": "Chain mail", "lines": [{ "item": "equipment/chain-mail", "equip": true }] },
          { "label": "Leather armor and a longbow", "lines": [
            { "item": "equipment/leather-armor", "equip": true },
            { "item": "equipment/longbow" }, { "item": "equipment/arrow", "count": 20 }
          ] }
        ]
      },
      { "label": "A martial weapon", "options": [
        { "label": "Pick one", "lines": [{ "oneOf": ["equipment/longsword", "equipment/battleaxe"] }] },
        { "label": "A greataxe", "lines": [{ "item": "equipment/greataxe" }] }
      ] }
    ]
  },
  { "id": "acolyte", "label": "Acolyte", "group": "background", "lines": [{ "coins": "gp", "count": 15 }, { "name": "Vestments" }] }
]
```

- लाइन नियमसेट का एक आइटम (`item`), सिक्के (`coins`, इकाई ID), तय सूची से खिलाड़ी का चुना एक आइटम (`oneOf`, 2 से 48 आइटम), या नाम से एक साधारण आइटम (`name`, जहाँ `freeform` साधारण आइटम की इजाज़त देता है; लेबल के नियमों में रखा गया, इसलिए ब्रैकेट, `{{` या लाइन ब्रेक नहीं) होती है। `count` 1 से 999 है; `equip: true` लेते समय आइटम पहना देता है, जहाँ उसके स्लॉट खाली हों, इसलिए कवच शुरुआत से गिना जाता है।
- `choices` 0 से 8 होते हैं, हर एक में अपनी लाइनों के 2 से 6 विकल्प।
- `group`: वह सामान जिसे कैरेक्टर हर समूह का एक बार लेता है (क्लास का और बैकग्राउंड का)। वही समूह फिर लेना खिलाड़ी का डायलॉग में किया गया चुनाव है, और थैले में पहले से मौजूद में जुड़ता है। बिना समूह वाला सामान अपना अलग समूह है, उसी नाम के समूह जैसा कभी नहीं।
- `fits` शीट को उसकी लाइव स्टेट के बिना पढ़ता है, जैसे साथ ले जाना पढ़ता है। यह सिर्फ़ सूची का क्रम तय करता है।
- लेना पूरा या कुछ नहीं है: अपने उठाने वाले के लिए बहुत भारी सामान पूरा अस्वीकार होता है, और डायलॉग बताता है कि उसका वज़न कितना है और वे अभी कितना और उठा सकते हैं। जिस आइटम को कोई लेयर गेम से बाहर करती है वह छोड़ दिया जाता है और उसका नाम बताया जाता है, और ऐसी सूची भी जिसके सारे आइटम वह बाहर करती है; जिस सिक्के को कोई लेयर बाहर करती है उसके सिक्के उसी मूल्य के बचे सबसे बड़े सिक्के में चुकाए जाते हैं, और डायलॉग उन्हें उसी तरह दिखाता है। जिस सामान में से कुछ न बचे वह अस्वीकार होता है, ताकि वह कभी बेकार में लिया हुआ चिह्नित न हो। service कभी सूची से नहीं दी जाती।
- इंपोर्ट हर आइटम (इनलाइन कैटलॉग में; अपनी अलग फ़ाइल वाला कैटलॉग सामान लेते समय जाँचा जाता है), सिक्के, साधारण आइटम और `fits` हवाले की जाँच करता है, service को अस्वीकार करता है, और ऐसी गिनती को अस्वीकार करता है जिसके लिए थैले में एक बार में आने से ज़्यादा स्टैक चाहिए।

## बाज़ार

`items` ब्लॉक में `market` (Capability API 1.65) बताता है कि कोई जगह क्या बेचती है और किस कीमत पर, ताकि हर दुकान हर चीज़ अपनी सूची की कीमत पर न बेचे। Gravewatch का, थोड़ा छोटा करके:

```json
"market": {
  "prices": [
    { "id": "cheap", "label": "cheap", "times": 0.75 },
    { "id": "fair", "label": "fair", "times": 1, "default": true },
    { "id": "dear", "label": "dear", "times": 1.5 }
  ],
  "places": [
    { "id": "hamlet", "label": "hamlet" },
    { "id": "village", "label": "village" },
    { "id": "town", "label": "market town" },
    { "id": "city", "label": "city" }
  ],
  "sold": [
    { "filter": { "rarity": "rare" }, "place": "town" },
    { "filter": { "category": "arm" }, "place": "village" }
  ],
  "sellers": [
    { "id": "chandler", "label": "chandler", "sells": [{ "category": "coat" }, { "category": "tonic" }] },
    { "id": "smith", "label": "smith", "sells": [{ "category": "arm" }], "place": "village" },
    {
      "id": "chapel",
      "label": "chapel of the Vigil",
      "sells": [{ "category": "page" }],
      "place": "town",
      "only": { "value": { "abilityScore": "nerve" }, "atLeast": 3, "label": "wardens of Nerve 3 or more" }
    }
  ]
}
```

- `prices`: एक से आठ स्तर, हर एक आइटम के `cost` पर गुणक (`times`, 0 से ऊपर), और उनमें से एक `default`। कीमत परिवार के सबसे छोटे सिक्के में लागत को स्तर से गुणा करके वहीं राउंड की जाती है (कुछ भी कीमत वाली चीज़ के लिए एक सिक्के से कभी कम नहीं), और उस सिक्के में बताई जाती है जिसमें उसकी लागत लिखी है, अगर वह सिक्का उसे ठीक-ठीक चुका सके, वरना आपकी लेयर के छोड़े सबसे बड़े ऐसे सिक्के में जो चुका सके: `dear` पर 8 shillings वाला कोट 12 shillings का है, और 50 gp वाला 5e पोशन 50 gold pieces का है, 5 platinum का कभी नहीं। मोलभाव या विक्रेता का मूड स्तर बदलता है, संख्या कभी नहीं।
- `places`: जगह के एक से बारह आकार, सबसे छोटा पहले, आपके अपने शब्दों में।
- `sold`: फ़िल्टर से चुने आइटम बेचने वाली सबसे छोटी जगह के नियम। फ़िल्टर `rarity`, `category` और `tag` में से किसी का भी नाम देता है, और ऐसे आइटम से मेल खाता है जिसमें उसकी बताई हर चीज़ हो; आइटम से मेल खाने वाला पहला नियम फ़ैसला करता है। आइटम का अपना `sold` नियमों से ऊपर है, और जिस आइटम का कोई नाम नहीं लेता वह कहीं भी बिकता है।
- `sellers`: विक्रेताओं के प्रकार, हर एक के साथ वह क्या `sells` करता है (फ़िल्टर, जिनमें से कोई भी आइटम चुनता है), सबसे छोटी `place` जहाँ वह होता है (इसके बिना कहीं भी), और वैकल्पिक रूप से वह किसे `only` बेचता है: खरीदार की शीट का कोई मान, उसकी लाइव स्टेट और साथ रखे सामान के साथ, कम से कम `atLeast`, जिसे Game Master को `label` के रूप में बताया जाता है। `sellers` के बिना किसी जगह पर कोई भी वह बेचता है जो वह जगह बेचती है।
- `unsold` (Capability API 1.813): उन चीज़ों के फ़िल्टर जो किसी विक्रेता के माल में नहीं होतीं, चाहे `sold` और `sells` उन्हें कहीं भी रखें। विक्रेता की `stock` टेबल अब भी ऐसा आइटम रोल कर सकती है, इसलिए उसे खरीदने का एकमात्र तरीका स्टॉक में आया ऐसा अलग सामान है, और विक्रेता अब भी उसे वापस खरीदते हैं। लेयर इसमें जोड़ सकती है (कम जादू वाली दुनिया के लिए `[{ "tag": "magical" }]`, देखें [लेयर](ruleset-layers-and-translations.md))।
- बिना `cost` वाला आइटम बिक्री के लिए नहीं है, और न ही लेयर से छिपाया गया आइटम या ऐसा आइटम जिसके सिक्के लेयर ने हटा दिए।

**पार्टी कहाँ है।** Game Master `[place: name="Millbrook" size="market town"]` से बताता है कि सीन किस जगह पर है और उसका आकार क्या है, आकार उसके ID या लेबल से, और बिना बाज़ार वाली जगह (सड़क, बियाबान) के लिए आकार छोड़ देता है। Engine हर टैग का जवाब वहीं देता है, आपके पास न होने वाले आकार को अस्वीकार करते हुए, और खिलाड़ी को दिखने वाले उसके अपने जवाबों में, सबसे नई बातचीत की शुरुआत से, आखिरी जिस जगह का उसने जवाब दिया, वही तब तक लागू जगह है जब तक कोई दूसरी न बताई जाए। खिलाड़ी का टाइप किया जगह टैग कभी नहीं गिना जाता। दोबारा जनरेट हुआ जवाब सिर्फ़ वही पढ़ता है जो उस जवाब से पहले आया जिसकी जगह वह ले रहा है।

**खरीदना।** Game Master `[inventory: action="buy" item="Hand axe" count="1" level="dear" seller="smith" who="Ada"]` से खरीदता है, जिसमें `level` (इसके बिना डिफ़ॉल्ट) और `seller` (इसके बिना यहाँ का कोई भी विक्रेता जो आइटम बेचता है) वैकल्पिक हैं। Engine जवाब खत्म होने पर लागू जगह पर उसकी कीमत लगाता है, खरीदार के बटुए से (`who=` के बिना खिलाड़ी के) भुगतान की तरह छुट्टे के साथ कीमत निकालता है, और आइटम उसके थैले में डालता है, या सेवा के लिए सिर्फ़ भुगतान करता है। या तो दोनों होते हैं या कोई नहीं। जवाब बताता है कि उसकी कीमत क्या थी (`price="12 shillings"`) और क्या चुकाया और लौटाया गया, और एक नोटिफ़िकेशन इसे दिखाता है। खरीद अस्वीकार होती है, और कुछ नहीं बदलता, जब कोई जगह न बताई गई हो (`no-place`), स्तर, आइटम या विक्रेता आपके पास न हो (`unknown-level`, `unknown-item`), कीमत न हो (`not-for-sale`), जगह आइटम के लिए बहुत छोटी हो (`not-here`), यहाँ उसे बेचने वाला कोई विक्रेता न हो (`no-seller`), खरीदार विक्रेता के `only` पर खरा न उतरे (`not-to-you`), बटुआ कीमत न चुका सके (`cannot-afford`), या थैला उसे उठा न सके।

**Game Master क्या देखता है।** जब सीन बाज़ार वाली जगह पर हो, तो एक MARKET ब्लॉक जगह और उसका आकार, कीमत के स्तर, और वहाँ के हर विक्रेता को डिफ़ॉल्ट स्तर पर उसकी बेची एक दर्जन चीज़ों के साथ, सबसे सस्ती पहले, बताता है; वे जो कुछ भी बेचते हैं वह नाम से खरीदा जा सकता है। उसके निर्देश `[place:]` और `buy` सिखाते हैं, और ये सिर्फ़ बाज़ार वाले नियमसेट में होते हैं।

### बाज़ार का दिन

बाज़ार का दिन (Capability API 1.69) किसी जगह की अलमारियों को बदलने और खाली होने देता है, और पार्टी को वापस बेचने देता है। Gravewatch का, थोड़ा छोटा करके:

```json
"places": [
  { "id": "hamlet", "label": "hamlet", "purse": { "amount": 10, "unit": "shilling" } },
  { "id": "town", "label": "market town", "purse": { "amount": 100, "unit": "shilling" } }
],
"buyBack": 0.5,
"sold": [{ "filter": { "rarity": "rare" }, "place": "town", "limited": "1d2" }],
"sellers": [
  { "id": "smith", "label": "smith", "sells": [{ "category": "arm" }], "stock": { "table": "smiths_odd_lot" } }
]
```

- **दिन।** किसी जगह पर दिन तब तक चलता है जब तक Game Master किसी दूसरी जगह का नाम न दे; वह उसी जगह को `day="new"` के साथ फिर बताकर वहीं नया दिन शुरू करता है (`[place: name="Millbrook" size="market town" day="new"]`)। नीचे की हर चीज़ हर दिन के लिए खिलाड़ी को दिखने वाले Game Master के जवाबों से निकाली जाती है, इसलिए स्वाइप, दोबारा जनरेट हुए जवाब या ब्रांच के लिए कुछ सेव करने की ज़रूरत नहीं, और एक दिन हमेशा वही अलमारी रोल करता है।
- **`limited`** किसी `sold` नियम पर या आइटम के अपने `sold` पर: कोई जगह एक दिन में कितने रखती है, संख्या या दिन के लिए रोल हुए डाइस। नियम बिना जगह के सीमा बता सकता है (कहीं भी बिकता है, थोड़ा-थोड़ा करके); आइटम की जगह जगह का नाम देने वाले पहले नियम से आती है, और उसकी सीमा सीमा बताने वाले पहले नियम से। उनके खरीद लिए जाने के बाद नए दिन तक खरीद अस्वीकार होती है (`sold-out`)।
- **`stock`** विक्रेता पर: आपकी कोई लूट टेबल, जो दिन में एक बार रोल होती है, यह तय करने के लिए कि उस विक्रेता के पास उसकी बेची चीज़ों के अलावा क्या स्टॉक में है। जो वह रोल करती है (सिर्फ़ आइटम, सिक्के कभी नहीं), वह सिर्फ़ वही विक्रेता बेचता है, जितने रोल हुए उतने, `sells` और `sold` कुछ भी कहें; विक्रेता का `only` फिर भी लागू होता है।
- **`buyBack`**: किसी आइटम की डिफ़ॉल्ट कीमत का वह हिस्सा (0 से ऊपर, ज़्यादा से ज़्यादा 1) जो विक्रेता उसके लिए देता है। यहाँ उस तरह की चीज़ बेचने वाला विक्रेता उसे खरीदता है (विक्रेताओं के बिना, कोई भी)। `buyBack` के बिना कोई कुछ वापस नहीं खरीदता।
- **`purse`** जगह के आकार पर: उसके विक्रेता एक दिन में, सब मिलाकर, ज़्यादा से ज़्यादा कितना चुकाते हैं, आपके किसी सिक्के में। उस सिक्के के परिवार में चुकाई गई बिक्री इसमें गिनी जाती है; बटुए के बिना वे बिना सीमा के खरीदते हैं।
- **बेचना।** Game Master `[inventory: action="sell" item="Silver coffin nail" count="1" seller="smith" who="Ada"]` से बेचता है। Engine उसकी कीमत लगाता है, उसे बेचने वाले के थैले से निकालता है (`who=` के बिना खिलाड़ी के; बाइंड किया श्रापित आइटम कभी नहीं) और उसके सिक्के, सबसे बड़े पहले, डालता है, या अस्वीकार करता है और कुछ नहीं बदलता: कोई जगह नहीं बताई गई, यहाँ कोई उसे नहीं खरीदता (`not-bought`), कीमत नहीं (`not-for-sale`), आज का बटुआ खर्च हो चुका (`purse-spent`), पास में कोई नहीं, या ऐसे सिक्के जिन्हें थैला उठा न सके। जवाब बताता है कि उससे क्या मिला (`price="4 shillings"`), जर्नल उसे बिका हुआ सूचीबद्ध करता है, और एक नोटिफ़िकेशन इसे दिखाता है।
- MARKET ब्लॉक यह जोड़ता है कि आज हर विक्रेता के पास स्टॉक में क्या है, सीमित आइटम कितने बचे हैं, और यहाँ के विक्रेता क्या देते हैं और आज के बटुए में कितना बचा है; उसके निर्देश `sell` और `day="new"` सिखाते हैं।

### ईमानदार और बेईमान विक्रेता

Capability API 1.79 आइटम को जोखिम भरा या नकली, और विक्रेता को बेईमान होने देता है।

```json
"items": { "market": { "sellers": [
  { "id": "fence", "label": "Fence", "sells": [{ "tag": "magical" }], "place": "town", "honest": false, "stock": { "table": "fences_odd_lot" } }
] } }
```

```json
{ "id": "bag-of-devouring", "label": "Bag of Devouring", "item": { "category": "wondrous", "passesFor": "magic_items/bag-of-holding", "cost": { "amount": 5, "unit": "gp" } } }
{ "id": "wand-of-wonder", "label": "Wand of Wonder", "item": { "category": "wand", "risky": "every wave is a gamble; some effects turn on the one who waves it" } }
```

- आइटम पर **`risky`**: बेचने से पहले ईमानदार विक्रेता किस बात की चेतावनी देता है। MARKET ब्लॉक इसे ईमानदार विक्रेता के माल के बगल में "(warn the buyer first: ...)" के साथ सूचीबद्ध करता है; बेईमान विक्रेता कुछ नहीं कहता।
- आइटम पर **`passesFor`** उसे किसी दूसरे आइटम (`<catalog>/<entry>`) का नकली बनाता है: उसी श्रेणी का असली, बिकने लायक आइटम, उन्हीं स्लॉट में पहना जाने वाला, जो बाइंड होता है अगर नकली बाइंड होता है। इसकी जाँच इंपोर्ट पर होती है जहाँ दोनों पढ़े जा सकें, इंस्टॉल पर हर कैटलॉग फ़ाइल के लिए, और फिर जब बाज़ार इसे देता है, इसलिए ऐसा नकली कभी नहीं बिकता जिसका लक्ष्य गायब हो या किसी लेयर से छिपा हो। श्रापित आइटम (`binds.cursed`) या नकली कभी किसी के माल में नहीं होता, और कभी ईमानदार विक्रेता के स्टॉक में नहीं।
- विक्रेता पर **`honest: false`**: उसकी `stock` टेबल जो नकली रोल करती है, वह उस आइटम के रूप में दिया जाता है जिसका वह नकली है, उसी आइटम की कीमत पर, और MARKET ब्लॉक उसके बगल में Game Master को सच दिखाता है। जो खरीद उस विक्रेता और उस आइटम का नाम देती है उसे नकली मिलता है; जो खरीद किसी विक्रेता का नाम नहीं देती उसे कभी नहीं।
- **थैले में नकली** हर उस जगह जहाँ खिलाड़ी देखता है (थैला, जर्नल, नोटिफ़िकेशन, लड़ाइयाँ), उस आइटम के रूप में दिखता है जिसका वह नकली है, और अपनी असलियत रखता है। Game Master का इन्वेंटरी ब्लॉक उसे `[FAKE: really ...]` चिह्नित करता है और उससे कहता है कि उसे उसी नाम से बुलाता रहे जिससे वह दिखता है।
- **पकड़ा जाना**: `[inventory: action="reveal" item="Bag of Holding" who="Ada"]`, उसे बाइंड करना (attune करने पर श्राप दिख जाता है), उसे इस्तेमाल करना (जो वह सच में करता है वह होता है; जब वह ऐसा कुछ हो जिसका हिसाब नियम नहीं लगाते, तो Game Master उसे बताता है), या उसे किसी ईमानदार खरीदार को बेचना, जो बताता है कि वह असल में क्या है और उसकी असली कीमत (उसकी अपनी `cost`) देता है, या जहाँ उसकी कोई कीमत नहीं वहाँ मना कर देता है। बेईमान खरीदार नकली को वैसा ही ले लेता है जैसा वह दिखता है। तब से वह अपना असली आइटम है।
- **पहना या साथ रखा**: नकली कैरेक्टर की शीट पर वही करता है जो वह सच में करता है (उसके `worn` या `carried` असर और उसके स्टैट)। इन्वेंटरी का पहला बदलाव जिसके बाद शीट कोई ऐसी संख्या, या चेक में ऐसा जोड़, दिखाती है जो वह आइटम नहीं दिखाता जिसका वह नकली है, उसे पकड़ लेता है, और जर्नल और स्क्रीन बताते हैं कि वह क्या था। ऐसा अंतर जिसे सिर्फ़ लड़ाई पढ़ती है (प्रतिरोध) उसे नहीं पकड़ता, और न अकेले शीट में बदलाव, अगले इन्वेंटरी बदलाव तक। लड़ाई में पहना हुआ नकली हथियार फिर भी उस हथियार की तरह अटैक करता है जिसका वह नकली है।
- सिंगल-प्लेयर भरोसे में, Peek Prompt Game Master का नज़रिया दिखाता है, सच समेत।

### नकली चीज़ों की पहचान

Capability API 1.802 कैरेक्टर को नकली चीज़ की असलियत पहचानने देता है, उसके किए चेक से या किसी के कीमत चुकाने से पहले ही उसे पहचान लेने से। Engine किसी भी चेक को उसके नाम से नहीं जानता: नियमसेट उन्हें लिखता है।

```json
{
  "id": "potion-of-poison",
  "label": "Potion of Poison",
  "item": {
    "category": "potion",
    "passesFor": "magic_items/potion-of-healing",
    "tells": [
      {
        "check": { "value": { "derived": "poisoners_kit_check" } },
        "dc": 13,
        "carries": { "anyOf": ["gear/poisoners-kit"] },
        "says": "a faint bitterness under the sweetness"
      },
      { "check": { "skill": "arcana" }, "dc": 18, "says": "its magic does not feel like healing magic" }
    ],
    "foolsReveal": ["identify"]
  }
}
```

```json
"items": {
  "namesItAt": 5,
  "revealsFakes": [{ "id": "identify", "label": "Identify" }, { "id": "detect-poison", "label": "Detect Poison and Disease", "items": ["magic_items/potion-of-poison"] }],
  "market": { "sellers": [
    { "id": "fence", "label": "Fence", "honest": false, "sells": [{ "tag": "magical" }],
      "manner": { "check": { "skill": "insight" }, "dc": 13, "advantageIf": [{ "value": { "derived": "knows_trade" }, "atLeast": 1 }], "says": "their eyes slide away when you ask about it" } }
  ] }
}
```

- नकली आइटम पर **`tells`** (ज़्यादा से ज़्यादा छह): हर एक ऐसा चेक है जो कोई भी कर सकता है (`check` कोई स्किल, एबिलिटी या शीट से पढ़ा गया मान है, जैसे किसी इस्तेमाल का `gate` किसी का नाम देता है), उसकी कठिनाई `dc`, और सफलता पर क्या दिखता है (`says`)। चेक करने के लिए शीट को जो शर्तें पूरी करनी हों, वे `needs` में होती हैं (`needsAny` के साथ उनमें से कोई एक), और `carries` वह आइटम है जो चेक करने वाले के अपने थैले में होना चाहिए, जैसे वह किट जिससे टूल चेक किया जाता है। `advantageIf` की कोई भी एक पंक्ति पूरी होने पर एडवांटेज के साथ डाइस रोल किया जाता है, और `disadvantageIf` की कोई भी एक पंक्ति पूरी होने पर डिसएडवांटेज के साथ।
- बेईमान विक्रेता पर **`manner`**: उन्हीं हिस्सों वाला चेक, जो आइटम के बजाय विक्रेता पर होता है। सफलता बताती है कि उसके बेचे जाने वाले सामान में कुछ गड़बड़ है, पर कभी यह नहीं बताती कि वह क्या है।
- **जाँच करना**: `[inventory: action="inspect" item="Potion of Healing" who="Mira"]` Mira के थैले के आइटम की जाँच करता है, और `seller="Fence"` यहाँ किसी विक्रेता के आज दिखाए गए माल की जाँच करता है, किसी के खरीदने से पहले। जिस नियमसेट में नकली आइटम पहचाने जा सकते हैं, उसमें इन्वेंटरी का **Inspect** (जाँचें) बटन Game Master से टैग लिखवाने के लिए कहता है, "भरोसा करने से पहले मैं अपने Potion of Healing को ध्यान से जाँचता हूँ।" Engine नियमसेट के अपने डाइस से उस बारे में कैरेक्टर का सबसे अच्छा चेक रोल करता है: नकली आइटम के पहचान के संकेत, और बेईमान विक्रेता का तौर-तरीका। नकली आइटम पर सफलता उसे संदिग्ध पाती है: जवाब बताता है कि कैरेक्टर को क्या दिखा, और थैले में "Mira को लगता है कि यह नकली है" दिखता है, जबकि उसका नाम अब भी उसी आइटम का रहता है जिसकी वह नकल है। पहचान के किसी संकेत पर `items.namesItAt` या उससे ज़्यादा के अंतर से मिली सफलता (5e में 5) उसकी असलियत भी बताती है, और तब से वह अपना असली आइटम होता है। असली आइटम पर उन नकली आइटमों के पहचान के संकेतों के चेक रोल होते हैं जो उसकी नकल करते हैं, इसलिए पूछने से कोई भेद नहीं खुलता, और सफलता बताती है कि वह असली लगता है। हर कैरेक्टर हर आइटम पर एक बार कोशिश करता है (स्टैक याद रखता है कि कौन कोशिश कर चुका है; माल के लिए यह बाज़ार के उस दिन भर याद रहता है); असफलता बताती है कि कैरेक्टर पहचान नहीं सकता। जिस आइटम की असलियत कोई चीज़ नहीं खोल सकती, या जिसे कैरेक्टर बिल्कुल भी जाँच नहीं सकता, उसे `nothing-to-check` के साथ अस्वीकार किया जाता है, और कोशिश खर्च नहीं होती।
- **खरीदने से पहले ध्यान जाना**: जब किसी खरीद से बेईमान विक्रेता का नकली आइटम मिलता, तो पार्टी का हर दूसरा सदस्य उस आइटम और विक्रेता के बारे में अपने हर मुमकिन चेक का हिसाब लगाता है, बिना डाइस के: `items.passiveBase` (डिफ़ॉल्ट 10) और उसकी संख्या, एडवांटेज के साथ 5 ज़्यादा और डिसएडवांटेज के साथ 5 कम। जो सबसे पहले किसी कठिनाई तक पहुँचता है, उसका ध्यान जा चुका है: कुछ चुकाया नहीं जाता, और खरीद के जवाब में `reason="held"` के साथ बताया जाता है कि किसने क्या देखा। Game Master से इसे उस साथी के अपने कैरेक्टर में रहकर खरीदार को चेतावनी देने के रूप में दिखाने को कहा जाता है, विक्रेता के मुँह पर आरोप लगाए बिना, जब तक उस साथी का व्यक्तित्व ऐसा न हो, और खरीदार को फ़ैसला लेने देने को कहा जाता है। खिलाड़ी को और कुछ नहीं बताया जाता। उस दिन उसी विक्रेता से वही खरीद दोबारा माँगने पर हो जाती है। `items.warnBy: "roll"` इसके बजाय उन चेक के लिए डाइस रोल करता है।
- **नकली आइटम की असलियत देखना**: `items.revealsFakes` नकली आइटम की असलियत देखने के वे तरीके सूचीबद्ध करता है जिन्हें कैरेक्टर किसी आइटम पर कास्ट कर सकता है (स्पेल, रस्म), हर एक के साथ `id`, उसका `label` और, सिर्फ़ कुछ नकली आइटमों की असलियत देखने वाले तरीके के लिए, उन आइटमों के `tags` या रेफ़रेंस से खुद वे नकली आइटम (`items`, जिनमें सिर्फ़ नकली आइटम हो सकते हैं)। नकली आइटमों का नाम देने से उन पर भेद खोलने वाला टैग लगाने की ज़रूरत नहीं रहती: "poison" टैग वाला ज़हर का पोशन उस हीलिंग पोशन के बगल में अपनी असलियत खोल देगा जिसकी वह नकल करता है। `[inventory: action="inspect" item="Potion of Healing" who="Mira" with="Identify"]` किसी एक तरीके का नाम देता है: वह जिस नकली आइटम की असलियत पढ़ सकता है, उसका असली नाम बताया जाता है, जिस आइटम के `foolsReveal` में उस तरीके का नाम है, वह उसी आइटम के रूप में दिखता है जिसकी वह नकल है, और जिस नकली आइटम की असलियत वह नहीं पढ़ सकता, या कोई असली आइटम, कुछ नहीं दिखाता (हर नकली आइटम की असलियत पढ़ने वाले तरीके के लिए "genuine", वरना "unsure")। इसमें कोई कोशिश खर्च नहीं होती; उसे कास्ट करने की जो भी कीमत हो, वह Game Master संभालता है, जैसे किसी भी स्पेल की।
- इनमें से कुछ भी इस्तेमाल करने वाले नियमसेट को Capability API 1.802 चाहिए। जो आइटम नकली नहीं है उस पर नकली आइटम का `tells` या `foolsReveal`, ऐसा `carries` आइटम या `revealsFakes` आइटम जो नियमसेट का अपना न हो (`items` के लिए, नकली आइटम), और ऐसी `foolsReveal` ID जो `revealsFakes` में सूचीबद्ध न हो, इंस्टॉल पर अस्वीकार होते हैं।

## लड़ाई के बाहर आइटम इस्तेमाल करना

वही `use` लड़ाई के बाहर भी काम करता है (`restore` के लिए Capability API 1.60; बाकी के लिए कुछ नया नहीं चाहिए)। `use` वाले आपके किसी आइटम पर इन्वेंटरी का **Use** बटन, और Game Master का `[inventory: action="use" item="Poultice" who="Juno"]`, दोनों Engine के डाइस से, उसे साथ रखने वाले पर वही करते हैं जो आइटम करता है:

- हील स्वास्थ्य लौटाती है: स्वास्थ्य पूल या साधारण स्वास्थ्य ट्रैक पर मात्रा, या घाव ट्रैक पर एक निशान साफ़, जैसे लड़ाई में हील करती है। `temporary` पॉइंट स्वास्थ्य पूल पर लगते हैं, `restore` अपना पूल लौटाता है, और उसकी `applies` वाली हर स्थिति लगाई जाती है, तब तक जब तक कुछ उसे हटा न दे।
- नुकसान करने वाला, या दूसरी तरफ़ निशाना लगाने वाला इस्तेमाल (`kind` `attack` या `debuff`, या `targets` `enemy`) किसी पर नहीं लगता: लड़ाई के बाहर बोर्ड पर मारने को कोई नहीं होता। आइटम फिर भी इस्तेमाल होता है, और Game Master को बताया जाता है कि वह क्या करता है, ताकि वह नैरेशन कर सके।
- यह स्टैक से एक घटाता है या उसके चार्ज खर्च करता है, बिल्कुल लड़ाई की तरह, और जिसमें कुछ न बचा हो, या जो स्लॉट लेता या बाइंड होता है और पहना हुआ नहीं है, वह अस्वीकार होता है और कुछ नहीं बदलता। शीट और थैला साथ लिखे जाते हैं।
- `gate` पहले रोल होता है, जैसे चेक होता है: शीट की संख्या के साथ नियमसेट के अपने डाइस, इस्तेमाल करने वाले की घाव पेनल्टी, और उसकी स्थितियाँ और पहने या साथ रखे आइटम उस चेक पर जो करते हैं। विफल होने पर आइटम बेकार में खत्म हो जाता है, और लाइन यह बताती है ("Ada uses Page of the vigil litany: Ward check 1 against 2, failed; it is used up for nothing. 1 left.")।

जो हुआ वह एक लाइन में बताया जाता है: "Juno uses Poultice: heals 4 (Grit 6/11). 1 left." Use बटन इसे "I use my Poultice." के बाद `[item_used]` ब्लॉक में Game Master को भेजता है, जिसे चैट बैज के रूप में दिखाती है; Game Master के अपने टैग का जवाब इसी से दिया जाता है, जो उसके दूसरे टैग की तरह टर्न की शुरुआत से मापा जाता है, इसलिए दोबारा जनरेट हुआ जवाब कभी किसी आइटम को दो बार इस्तेमाल नहीं करता। बिना `use` वाला आइटम, या बिना नियमसेट वाले गेम में कोई आइटम, अब भी बस कहा जाता है: "I use my rope."
