# पर्सनल एक्सटेंशन

**Personal Extensions** (पर्सनल एक्सटेंशन) वे निजी कोड ड्राफ़्ट हैं जो Professor Mari आपके लिए बनाती है। **Settings** (सेटिंग्स) > **Addons** (ऐडऑन) > **Personal Extensions** खोलें।

डिफ़ॉल्ट संदेश यह है:

> Ask Professor Mari to create an extension for you. Nothing runs until you enable it and approve the exact code hash.

इस सेक्शन में **New Draft** जैसी कोई कार्रवाई नहीं है और इंपोर्ट के कंट्रोल भी नहीं हैं। ड्राफ़्ट बनवाने या बदलवाने के लिए Professor Mari से कहें। वह कोड सेव कर सकती है, पर उसे न मंज़ूरी दे सकती है और न चालू कर सकती है।

अपना पैकेज लिखने और इंपोर्ट करने के लिए [पर्सनल एक्सटेंशन लिखने की गाइड](writing-personal-extensions.md) देखें। अपने लिखे पैकेज अलग से अनुमति माँगने वाले External Extensions फ़्लो का इस्तेमाल करते हैं।

## जाँचें और चालू करें

हर ड्राफ़्ट शुरुआत में बंद रहता है। Marinara चलने वाले कोड का ठीक-ठीक फ़िंगरप्रिंट SHA-256 से बनाता है। ड्राफ़्ट खोलें, कोड पढ़ें, दिख रहे हैश से मिलाएँ, और उसी वर्ज़न पर भरोसा हो तभी **Review and Run** चुनें। कोड में कोई भी बदलाव या कोई पुराना रिविज़न वापस लाने पर एक्सटेंशन बंद हो जाता है और नई मंज़ूरी माँगता है।

सैंडबॉक्स अधिकार घटाता है, पर किसी भी कोड को भरोसेमंद नहीं बना देता। नुकसान पहुँचाने वाला एक्सटेंशन फिर भी वॉचडॉग के रोकने तक CPU खर्च कर सकता है, तय सीमा के भीतर अपना स्टोरेज भर सकता है, या लॉग के ज़रिए धोखा दे सकता है। फ़ुल पेज एक्सटेंशन यह अलगाव जान-बूझकर छोड़ देते हैं। चालू करने से पहले कोड हमेशा खुद पढ़ें।

## रनटाइम आइसोलेशन

ब्राउज़र एक्सटेंशन opaque-origin वाले सैंडबॉक्स्ड iframe के अंदर, अपने अलग वर्कर में चलता है। यह Marinara के पेज, DOM, कुकीज़, ब्राउज़र स्टोरेज, origin API या नेटवर्क तक नहीं पहुँच सकता। इसे बस इतनी क्षमताएँ मिलती हैं: अपना निजी एक्सटेंशन स्टोरेज, लॉगिंग, नियंत्रित टाइमर, क्लीनअप रजिस्टर करना, सीमित विंडो, होस्ट में जोड़ने के सुरक्षित स्लॉट, और चालू चैट तथा कैरेक्टर ID का सिर्फ़-पढ़ने वाला स्नैपशॉट। चालू कैरेक्टर कार्ड या चुने हुए पर्सोना के कुछ चुनिंदा फ़ील्ड इसे तभी मिलते हैं, जब उनसे जुड़ी परमिशन घोषित और मंज़ूर हों।

एक्सटेंशन `marinara.ui.registerContribution(...)` से टॉप बार में कार्रवाइयाँ, **Extensions** मेन्यू में आइटम और दाईं तरफ़ टिके रहने वाले पैनल जोड़ सकते हैं। Marinara इन सतहों को मौजूदा थीम और कंट्रोल के एक तय सेट से बनाता है: हेडिंग, टेक्स्ट, प्रीफ़ॉर्मैटेड आउटपुट, बटन, टेक्स्ट इनपुट, सिलेक्ट, टॉगल, स्लाइडर, कलर कंट्रोल और स्पेसर। एक्सटेंशन सिर्फ़ सामग्री और स्टेट देता है, HTML, CSS, URL, React कंपोनेंट या होस्ट के इवेंट हैंडलर कभी नहीं।

ये UI क्षमताएँ और नियम हर सैंडबॉक्स्ड ब्राउज़र एक्सटेंशन पर एक जैसे लागू होते हैं, चाहे वह कहीं से भी आया हो। इंपोर्ट किया गया थर्ड-पार्टी (External) एक्सटेंशन भी इसी सुरक्षित रनटाइम में चलता है, बशर्ते उसका पैकेज साफ़ तौर पर **Full page access** न माँगे या नीचे बताए गए सैंडबॉक्स-पूर्व `marinara.extension` फ़ॉर्मैट का इस्तेमाल न करे।

### Marinara से बना पैनल जोड़ें

```js
const panel = marinara.ui.registerContribution({
  id: "weather-settings",
  kind: "panel",
  label: "Weather controls",
  description: "Tune a weather scene without leaving Marinara.",
  icon: "sparkles",
  elements: [
    { kind: "heading", text: "Atmosphere" },
    {
      kind: "select",
      id: "weather",
      label: "Weather",
      value: "rain",
      options: [
        { value: "rain", label: "Rain" },
        { value: "snow", label: "Snow" },
        { value: "aurora", label: "Aurora" },
      ],
    },
    { kind: "slider", id: "intensity", label: "Intensity", min: 0, max: 100, value: 60 },
    { kind: "toggle", id: "lightning", label: "Lightning", checked: false },
    { kind: "color", id: "tint", label: "Tint", value: "#6d8cff" },
    { kind: "button", id: "apply", label: "Apply" },
  ],
  onActivate: async () => {
    const settings = await marinara.storage.get();
    // Update the panel when stored state should be reflected in the controls.
  },
  onEvent: async ({ elementId, values }) => {
    if (elementId !== "apply") return;
    await marinara.storage.patch(values);
  },
});

marinara.onCleanup(() => panel.remove());
```

छोटी कार्रवाई के लिए `kind: "button"` और Extensions-menu action के लिए `kind: "menu-item"` इस्तेमाल करें। Button की default जगह `surface: "top-bar"` है। वे `position` को `header`, `before-content` या `after-content` रखकर `chats`, `bots`, `characters`, `personas`, `lorebooks`, `presets`, `connections`, `agents` या `settings` को भी target कर सकते हैं। `icon` में Marinara से supported कोई kebab-case Lucide icon name दिया जा सकता है। दोनों action kind `onActivate` चलाते हैं। `panel` खुलते ही `onActivate` चलाता है और उसके button सभी panel control की मौजूदा value के साथ `onEvent` चलाते हैं। Handle में kind के हिसाब से update मिलता है: `button` में `label`, `description`, `icon`, `surface` और `position`; `menu-item` में `label`, `description` और `icon`; `panel` में `label`, `description`, `icon` और `elements`। सभी handle `remove()` support करते हैं। ID में अक्षर, अंक, `.`, `_` और `-` आ सकते हैं।

यह उदाहरण Presets panel content के ऊपर native action रखता है:

```js
marinara.ui.registerContribution({
  id: "preset-helper",
  kind: "button",
  label: "Preset helper",
  description: "Run the preset helper",
  icon: "list-sparkles",
  surface: "presets",
  position: "before-content",
  onActivate: () => {
    // Run extension behavior here.
  },
});
```

जटिल टूल किसी इवेंट के बाद पैनल के एलिमेंट अपडेट करके कई स्टेप वाला इंटरफ़ेस बना सकते हैं। ऐप का स्टेट `marinara.storage` में रखें, मार्कअप में मत भरें।

### चालू चैट का कॉन्टेक्स्ट इस्तेमाल करें

Browser Extension API का वर्ज़न 5 उस चैट के लिए opaque आइडेंटिफ़ायर देता है जो अभी Marinara में खुली है:

```js
const renderForContext = async ({ chatId, characterId, characterIds, personaId, characters, persona }) => {
  if (!chatId) return; // Home, a library, or another surface without an active chat.

  const storage = await marinara.storage.get();
  const tab = storage.tabsByChat?.[chatId];

  // characterId is available only for a single-Character chat.
  // Use characterIds for group chats.
  marinara.log.debug("Loaded Notepad tab", {
    chatId,
    characterId,
    characterIds,
    personaId,
    characterNames: characters.map((character) => character.name),
    personaName: persona?.name ?? null,
    tab,
  });
};

const unsubscribe = marinara.context.subscribe(renderForContext);
marinara.onCleanup(unsubscribe);
```

`marinara.context.get()` वही मौजूदा स्नैपशॉट बिना सब्सक्राइब किए लौटाता है। कोई चैट चालू न हो तो `chatId` `null` रहता है और `characterIds` खाली रहता है। `characterId` तभी भरता है जब चैट में ठीक एक कैरेक्टर हो। ग्रुप चैट में हर भागीदार `characterIds` में आता है और `characterId` `null` रह जाता है। `personaId` तभी भरता है जब `read_active_persona` मंज़ूर हो।

चैट और कैरेक्टर ID हमेशा मिलते हैं, जिनसे एक्सटेंशन अपने निजी स्टोरेज को अलग-अलग नाम दे सकता है। रिकॉर्ड के फ़ील्ड पाने के लिए एक्सटेंशन मैनिफ़ेस्ट में इनमें से एक या दोनों वैकल्पिक परमिशन चाहिए:

```json
{
  "runtime": "client",
  "capabilities": ["read_active_characters", "read_active_persona"]
}
```

- `read_active_characters` से चालू चैट में शामिल कार्ड के लिए `characters` भरता है।
- `read_active_persona` से चालू चैट में चुने हुए पर्सोना के लिए `persona` भरता है।

परमिशन के बिना इनकी वैल्यू `[]` या `null` ही रहती है। Marinara हर माँगी गई परमिशन **Requested access** में दिखाता है, और फिर हैश-मंज़ूरी वाली विंडो में दोबारा दिखाता है। कोई परमिशन जोड़ने या हटाने से कोड का हैश बदल जाता है, एक्सटेंशन बंद हो जाता है और नई मंज़ूरी की ज़रूरत पड़ती है।

कैरेक्टर के स्नैपशॉट में सिर्फ़ `id`, `name`, `description`, `personality`, `scenario`, `firstMessage`, `exampleDialogue`, `creator`, `characterVersion`, `tags`, `backstory`, `appearance`, `aboutMe` और `conversationDisplayName` आते हैं। पर्सोना के स्नैपशॉट में सिर्फ़ `id`, `name`, `description`, `personality`, `scenario`, `backstory`, `appearance`, `tags`, `aboutMe` और `conversationDisplayName` आते हैं। सैंडबॉक्स की सीमा पार करने से पहले टेक्स्ट की लंबाई सीमित कर दी जाती है।

Marinara संदेश, क्रिएटर नोट, सिस्टम प्रॉम्प्ट, पोस्ट-हिस्ट्री निर्देश, कमेंट, अवतार के पथ, पूरी कैरेक्टर या पर्सोना लाइब्रेरी, बिना घोषित फ़ील्ड, चैट का मेटाडेटा, डेटाबेस हैंडल, नेटवर्क एक्सेस या बदलाव करने वाली कार्रवाइयाँ कभी नहीं भेजता। कॉन्टेक्स्ट के अपडेट भी मंज़ूर किए गए कोड हैश से बँधे रहते हैं, और तभी आते हैं जब चालू चैट, उसकी कैरेक्टर लिस्ट या उसका चुना हुआ पर्सोना बदलता है।

### पुराने और फ़ुल पेज एक्सटेंशन

वेदर कंट्रोलर, प्रॉम्प्ट एडिटर और ऐसे ही बड़े काम इस कॉन्ट्रिब्यूशन तरीके के लिए बिल्कुल सही हैं। इनके सुरक्षित रूप मेन्यू या टॉप बार से खुलने वाले लॉन्चर और धीरे-धीरे अपडेट होते पैनल इस्तेमाल कर सकते हैं। जो पुराने पैकेज DOM पर ओवरले चढ़ाते हैं, Marinara के CSS सिलेक्टर खोजते हैं, React के अंदरूनी हिस्सों में घुसते हैं, या same-origin `/api` रूट कॉल करते हैं, उन्हें ज्यों का त्यों इस सुरक्षित रनटाइम में इंपोर्ट नहीं किया जा सकता।

UI में जोड़े गए हिस्से सिर्फ़ इंटरफ़ेस देते हैं, आम अधिकार नहीं। कॉन्टेक्स्ट API हमेशा चालू चैट और कैरेक्टर ID देता है, और ऊपर गिनाए गए घोषित फ़ील्ड ही दे सकता है, वह भी चालू रिकॉर्ड के। जिन फ़ीचर को संदेश, प्रीसेट, लोरबुक, बिना घोषित कैरेक्टर या पर्सोना डेटा, या सीन के विज़ुअल इफ़ेक्ट चाहिए, उनके लिए Marinara की तरफ़ से अलग और बहुत सीमित ब्रोकर क्षमता चाहिए। एक्सटेंशन को होस्ट के DOM या खुले नेटवर्क रिक्वेस्ट से ऐसी क्षमता खुद नहीं गढ़नी चाहिए।

अगर किसी एक्सटर्नल एक्सटेंशन को सचमुच होस्ट के DOM की ज़रूरत है, तो वह यह माँग सकता है:

```json
{
  "runtime": "client",
  "capabilities": ["full_page_access"]
}
```

**Full page access सैंडबॉक्स की क्षमता नहीं है।** मंज़ूर किया गया JavaScript और CSS सीधे Marinara के पेज के अंदर चलता है। यह कोड ब्राउज़र के मौजूदा सेशन में दिख रही हर चीज़ पढ़ या बदल सकता है, चैट और कार्ड देख सकता है, ब्राउज़र स्टोरेज इस्तेमाल कर सकता है, नेटवर्क रिक्वेस्ट भेज सकता है और same-origin Marinara API कॉल कर सकता है। पेज पर इसका अधिकार उतना ही है जितना ब्राउज़र कंसोल में पेस्ट किए गए कोड का होता है। Professor Mari के ड्राफ़्ट यह क्षमता नहीं माँग सकते।

अगर पुराने `kind: "marinara.extension"` v1 एनवेलप में `capabilities` फ़ील्ड नहीं है, तो Marinara उसे सैंडबॉक्स-पूर्व पैकेज मानता है और इंपोर्ट के समय **Full page access** दे देता है। इससे WeatherTweaker जैसे पुराने पैकेज वर्कर में चुपचाप फ़ेल होने की जगह सही रिव्यू प्रक्रिया तक पहुँच जाते हैं। नया पैकेज उसी एनवेलप का इस्तेमाल करते हुए सुरक्षित रनटाइम चाहता हो, तो उसमें `"capabilities": []` होना चाहिए।

एक्सटर्नल एक्सटेंशन के दोनों गेट और हैश-मंज़ूरी फिर भी लागू रहते हैं। कोड, CSS या परमिशन में बदलाव होते ही एक्सटेंशन बंद हो जाता है और नई मंज़ूरी माँगता है। बंद करने पर Marinara अपने स्क्रिप्ट और स्टाइलशीट नोड हटा देता है, कंपैटिबिलिटी API से बने टाइमर रद्द कर देता है, और `marinara.onCleanup(...)` में रजिस्टर किए गए कॉलबैक चलाता है। पेज पर चलने वाला कोड बिना रजिस्टर किए लिसनर, टाइमर, ग्लोबल या DOM बदलाव बना सकता है, इसलिए सफ़ाई पूरी होने की गारंटी नहीं है। एक्सटेंशन बंद करने के बाद कुछ बचा दिखे तो पेज रीलोड करें।

पुराना `marinara.ui.showWindow(...)` API अब भी मौजूद है, जिससे opaque-origin वाले iframe के अंदर अस्थायी विंडो खुलती है। यह वही तय कंट्रोल इस्तेमाल करता है और `update(...)` तथा `close()` हैंडल लौटाता है। अगर टूल तक Marinara के सामान्य नेविगेशन से पहुँचना हो, तो कॉन्ट्रिब्यूशन ही बेहतर हैं।

सर्वर एक्सटेंशन एक अलग Node प्रोसेस में चलता है, जिसकी परमिशन सीमित होती हैं और जो macOS Seatbelt या Linux Bubblewrap के अंदर रहता है। यह Marinara की फ़ाइलों, आपकी फ़ाइलों, सर्वर से विरासत में मिले सीक्रेट, नेटवर्क, चाइल्ड प्रोसेस, वर्कर या नेटिव ऐडऑन तक नहीं पहुँच सकता। अगर Marinara को OS का सपोर्टेड सैंडबॉक्स न मिले, तो सर्वर एक्सटेंशन बंद ही रहते हैं।

### प्लैटफ़ॉर्म सपोर्ट

ब्राउज़र एक्सटेंशन को सैंडबॉक्स ब्राउज़र खुद देता है, इसलिए ये हर जगह चलते हैं। सर्वर एक्सटेंशन के लिए OS का सपोर्टेड सैंडबॉक्स चाहिए। जहाँ वह नहीं है, वहाँ ये बंद ही रहते हैं और चालू नहीं किए जा सकते। Marinara इन्हें सैंडबॉक्स के बिना चलाने का रास्ता कभी नहीं अपनाता।

| प्लैटफ़ॉर्म | सैंडबॉक्स्ड ब्राउज़र एक्सटेंशन | फ़ुल पेज एक्सटर्नल एक्सटेंशन | सर्वर एक्सटेंशन |
| ----------------------- | ---------------------------- | ----------------------------- | ------------------------------------- |
| macOS | ✅ सैंडबॉक्स में | ⚠️ साफ़ तौर पर भरोसा जताना ज़रूरी | ✅ सैंडबॉक्स में (Seatbelt) |
| Linux (Bubblewrap के साथ) | ✅ सैंडबॉक्स में | ⚠️ साफ़ तौर पर भरोसा जताना ज़रूरी | ✅ सैंडबॉक्स में (Bubblewrap) |
| Linux (`bwrap` के बिना) | ✅ सैंडबॉक्स में | ⚠️ साफ़ तौर पर भरोसा जताना ज़रूरी | ⛔ बंद, `bwrap` इंस्टॉल करें |
| Windows | ✅ सैंडबॉक्स में | ⚠️ साफ़ तौर पर भरोसा जताना ज़रूरी | ⛔ बंद, ब्राउज़र एक्सटेंशन इस्तेमाल करें |
| Android | ✅ सैंडबॉक्स में | ⚠️ साफ़ तौर पर भरोसा जताना ज़रूरी | ⛔ बंद, ब्राउज़र एक्सटेंशन इस्तेमाल करें |

Windows और Android पर OS का कोई सपोर्टेड प्रोसेस सैंडबॉक्स नहीं है, इसलिए वहाँ सर्वर एक्सटेंशन जान-बूझकर नहीं दिए जाते। इसकी जगह ब्राउज़र एक्सटेंशन इस्तेमाल करें, या सर्वर एक्सटेंशन ज़रूरी हो तो Marinara सर्वर को macOS या Linux (`bwrap` के साथ) पर चलाएँ।

## एक्सटर्नल एक्सटेंशन

थर्ड-पार्टी इंपोर्ट डिफ़ॉल्ट रूप से बंद और छिपे रहते हैं। इसके लिए दो कदम ज़रूरी हैं:

1. Marinara होस्ट पर `.env` में `ENABLE_EXTERNAL_EXTENSIONS=true` सेट करें।
2. **Settings** > **Advanced** > **Danger Zone** खोलें, डेटा मिटाने वाले कंट्रोल से नीचे स्क्रॉल करें, चेतावनी पढ़ें और **Allow third-party extension imports** चालू करें।

इसके बाद ही **Settings** > **Addons** में **External Extensions** दिखता है, फ़ाइल और फ़ोल्डर इंपोर्ट के कंट्रोल के साथ। ये फ़ॉर्मैट हमेशा खुले दिखते हैं:

- `.personal-extension.zip` और इससे मिलते-जुलते `.zip` पैकेज;
- `.json` मैनिफ़ेस्ट;
- `.css`;
- `.js`, `.mjs` और `.cjs`;
- `.server.js`, `.server.mjs` और `.server.cjs`।

इंपोर्ट के साथ मंज़ूरी कभी नहीं आती और वे खुद को चालू भी नहीं कर सकते। पुराने, प्रोफ़ाइल से आए, हाथ से रखे गए और अनजान स्रोत वाले रिकॉर्ड भी एक्सटर्नल ही माने जाते हैं। ये छिपे रहते हैं, इन्हें मंज़ूरी नहीं मिल सकती, और दोनों गेट खुलने तक ये दोनों रनटाइम से बाहर रहते हैं।

किसी हैश को मंज़ूरी देने से पहले **Requested access** की लिस्ट पढ़ें। ज़्यादातर ब्राउज़र एक्सटेंशन को सुरक्षित सैंडबॉक्स में ही रहना चाहिए। **Full page access** वाला पैकेज जान-बूझकर अलग-थलग नहीं रखा जाता, इसलिए उसे तभी चालू करें जब आपने उसी वर्ज़न को खुद पढ़ लिया हो और उस पर भरोसा हो।

कोई भी गेट बंद करते ही चालू एक्सटर्नल सर्वर प्रोसेस रुक जाते हैं, ब्राउज़र वर्कर और फ़ुल पेज रनटाइम के नोड हट जाते हैं, और सेव किए गए एक्सटर्नल रिकॉर्ड बंद हो जाते हैं। गेट दोबारा खोलने पर ये अपने आप नहीं चलते। किसी फ़ुल पेज एक्सटेंशन ने ऐसे बदलाव छोड़े हों जो क्लीनअप में रजिस्टर नहीं थे, तो पेज रीलोड करें।

थर्ड-पार्टी एक्सटेंशन में नुकसानदेह या खतरनाक कोड हो सकता है। डाउनलोड करने, इंपोर्ट करने या चालू करने से पहले हर लाइन खुद पढ़ें। इसकी पूरी ज़िम्मेदारी आपकी अपनी है।

## एक्सपोर्ट, रिविज़न और रिकवरी

पोर्टेबल पैकेज डाउनलोड करने के लिए एक्सटेंशन की एक्सपोर्ट कार्रवाई इस्तेमाल करें। एक्सपोर्ट किए और वापस लाए गए पैकेज बंद ही रहते हैं। कोई रिविज़न वापस लाने पर भी वह बंद ड्राफ़्ट बन जाता है।

एक्सटेंशन गड़बड़ करे तो **Disable** चुनें। इंटरफ़ेस ही न खुल रहा हो, तो Marinara बंद करें और `installed_extensions` के उस रिकॉर्ड की `enabled` वैल्यू `"false"` कर दें। `approvedHash` हाथ से कभी सेट न करें।
