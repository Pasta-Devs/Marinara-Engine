## Architecture Rules

### State Management Division

| What                                                              | Where                                        | Persist?           |
| ----------------------------------------------------------------- | -------------------------------------------- | ------------------ |
| UI preferences (theme mode, fonts, sidebar, appearance)           | `ui.store.ts` (Zustand)                      | Yes (localStorage) |
| Server data (characters, chats, messages, presets, synced themes) | React Query hooks                            | No (cache)         |
| Chat runtime (active chat, streaming, drafts)                     | `chat.store.ts` (Zustand)                    | No                 |
| Agent execution (thoughts, debug, echo)                           | `agent.store.ts` (Zustand)                   | No                 |
| Game state (scene, combat, encounters)                            | `game-state.store.ts` / `encounter.store.ts` | No                 |
| Component-local toggles                                           | `useState`                                   | No                 |

**Rules:**

- Async server calls belong in **hooks** (React Query mutations), not in Zustand stores.
- Zustand stores are synchronous state + actions only.
- Use `useShallow()` from `zustand/react/shallow` when selecting multiple fields.
- Only `ui.store.ts` uses `persist` middleware.

### Navigation Model

Navigation is **state-based, not URL-based**. There is no URL router.

- **Editor routing:** Setting `characterDetailId`, `lorebookDetailId`, `presetDetailId`, etc. in `ui.store.ts` causes `AppShell` to render the corresponding editor in place of `ChatArea`.
- **Panel routing:** Setting `rightPanel` in `ui.store.ts` switches the panel content. Chats (`sidebarOpen`) and a panel (`rightPanelOpen`) share one sidebar and are exclusive: opening one closes the other. `sidebarSide` docks it on the right (default) or left on desktop.
- **Modal routing:** Setting `modal: { type, props? }` in `ui.store.ts` triggers `ModalRenderer`.

```typescript
// Open a character editor
useUIStore.getState().openCharacterDetail(characterId);

// Open a panel
useUIStore.getState().openRightPanel("lorebooks");

// Open a modal
useUIStore.getState().openModal("create-character");
useUIStore.getState().openModal("docs-viewer", { initialDoc: docId });
```

### Code Splitting

All heavy editors are lazy-loaded in `AppShell.tsx`:

```typescript
const CharacterEditor = lazy(() =>
  import("../characters/CharacterEditor").then((m) => ({ default: m.CharacterEditor })),
);
```

**When adding a new editor or heavy component**, always lazy-load it in `AppShell` with `Suspense`.

### Component Pattern

```typescript
// Standard component structure
interface Props {
  someId: string;
  onClose: () => void;
}

export function MyComponent({ someId, onClose }: Props) {
  // 1. Zustand selectors
  const setting = useUIStore((s) => s.someSetting);

  // 2. React Query hooks
  const { data, isLoading } = useSomething(someId);
  const mutation = useUpdateSomething();

  // 3. Local state
  const [editing, setEditing] = useState(false);

  // 4. Memos and callbacks
  const filtered = useMemo(() => /* ... */, [data]);
  const handleSave = useCallback(async () => {
    await mutation.mutateAsync({ /* ... */ });
  }, [mutation]);

  // 5. Render
  if (isLoading) return <Loader2 className="animate-spin" />;
  return <div>...</div>;
}
```

### React Query Conventions

- **Query key factories:** `chatKeys.list()`, `chatKeys.detail(id)`, `chatKeys.messages(chatId)`
- **Stale times:** 5 minutes for data queries, 30 seconds for streaming-adjacent, `Infinity` for static resources (fonts)
- **Enabled guards:** `enabled: !!id` for nullable ID params
- **Invalidation on mutation:** Always `onSuccess: () => qc.invalidateQueries({ queryKey: ... })`
- **Optimistic updates:** Used for message edits — cancel, snapshot, update, rollback on error

### API Client Usage

All server calls go through `@/lib/api-client`:

```typescript
import { api } from "@/lib/api-client";

// Standard CRUD
const data = await api.get<Character[]>("/characters");
const created = await api.post<Character>("/characters", body);
await api.patch(`/characters/${id}`, body);
await api.delete(`/characters/${id}`);

// File upload (multipart)
await api.upload("/avatars", formData);

// File download (triggers save dialog)
await api.download(`/characters/${id}/export`, "character.json");

// SSE streaming (all event types, preferred for generation)
for await (const event of api.streamEvents("/generate", body, abortController.signal)) {
  // event: { type: "token" | "agent_update" | "game_state" | "done" | "error", data, ... }
  if (event.type === "token") buffer += String(event.data ?? "");
}
```

**All requests use `cache: "no-store"`.** Do not add caching headers.

### Styling Rules

- Use **Tailwind utility classes** as the primary styling method.
- Theme colors use CSS custom properties: `var(--primary)`, `var(--background)`, `var(--border)`, etc.
- **Do not write inline styles** for things Tailwind can handle.
- Global styles live in `src/styles/globals.css`, organized into 20 labeled sections. Mari's and the omnibar's rules live in `mari.css`, `omnibar.css` and `omnibar-settings.css`, each `@import`-ed by `globals.css` where the rules used to be, so the cascade order is unchanged; keep new imports in place, not at the top.
- Don't write `inset-inline-start`/`-end`, a two-value `inset-inline` or logical corner radii (`border-start-start-radius` and the like; Tailwind `start-*`, `end-*`, `rounded-s-*`, `rounded-e-*`). `cssTarget: "safari14"` compiles them to `:lang()` selector lists that Chromium drops with the whole rule, and the client build fails on one (#8709). Write physical `left`/`right` or corner radii, flipped by a `:where([dir="rtl"])` rule where the side matters (`i18n.ts` sets `dir` on `<html>`).
- Custom themes are injected via `<style>` tags by `CustomThemeInjector.tsx`.
- Synced custom themes come from `/api/themes` and migrate out of localStorage on first load; the client reaches them via `api.get("/themes")` since the API client prefixes `/api`. Only per-browser UI preferences like theme mode and fonts stay local in `ui.store.ts`.
- The app supports dark and light mode via `data-theme` on `<html>`.
- Two visual themes exist: `"default"` and `"sillytavern"`.

### Modal & Panel Conventions

**Modals:**

- All modals use `<Modal open={open} onClose={onClose} title="..." width="max-w-lg">` from `components/ui/Modal.tsx`.
- Register new modal types in `ModalRenderer.tsx`'s switch statement.
- Pass data via `openModal(type, { props })`.
- On phones (below `sm`), `Modal` is the shared bottom sheet. Do not build your own sheet. Pass `mobileFullscreen` for long editors and pages; `modeless` and `dragThrough` modals keep their desktop shape. `ContextMenu` becomes an action sheet on touch phones.
- A phone surface that is not a `Modal` uses `BOTTOM_SHEET_CLASS` and `SHEET_GRABBER_CLASS` from `components/ui/neutral-surface-styles.ts`.

**Panels:**

- Panels are registered in `RightPanel.tsx`'s `PANEL_CONFIG` (title, icon, gradient) and `right-panel-panels.ts`'s `RIGHT_PANELS` (lazy components). On desktop they open in the one sidebar in place of Chats; on phones and tablets, in the full-screen sheet.
- `RightPanel` keeps each visited panel mounted while it is mounted itself, hidden with React `Activity` and CSS, so panels keep their scroll position and local state. The visited set is a per-mount `useState` (`mountedPanels`), not module-level, so a remount, such as the phone sheet opening again, starts with only the current panel.
- Settings tabs use the same per-mount pattern with `mountedSettingsTabs`.

**Overlays & Popovers:**

- Use `createPortal(content, document.body)` to escape parent stacking contexts.
- Position with `useLayoutEffect` + computed coordinates.

**Row Action Buttons (Settings Panels):**

- Action buttons (delete, duplicate, set-as-default, etc.) live in an **absolutely positioned pill container** that overlays the row content.
- Container classes: `absolute right-2 top-1/2 -translate-y-1/2 flex shrink-0 items-center gap-0.5 rounded-lg bg-[var(--sidebar)] px-1 py-0.5 opacity-0 shadow-sm ring-1 ring-[var(--border)] transition-opacity group-hover:opacity-100 max-md:opacity-100`
- The parent row element must have `group relative` in its className.
- **Desktop:** hidden by default (`opacity-0`), revealed on hover (`group-hover:opacity-100`).
- **Mobile:** always visible (`max-md:opacity-100`).
- Icon size inside action buttons: `0.75rem` (consistent across all panels).
- All action buttons use `active:scale-90` for press feedback.
- Delete buttons always show the icon in `text-[var(--destructive)]` (not muted with hover-to-red).
- Duplicate / neutral action icons use `text-[var(--muted-foreground)]` as default color.
- Destructive actions (delete) must include a `confirm()` dialog.
- Do **not** add a redundant Edit button — clicking the row itself opens the detail/editor view.

### Chat Settings

Chat Settings lives in `features/chat-settings/`. `ChatSettingsDrawer.tsx` holds the floating window, which sections show in each chat mode and in what order, the values every section needs, the state two or more sections share, the windows its sections open, and the guarded close. Some older pieces are still in the drawer: small chat tool sections written inline as `<Section>` (message search, branches, the chat summary, Active Context, author notes, background, gallery and others), and the drafts for the chat name, scene instructions and game special instructions. Don't add to them.

- **A new section gets its own file** in `sections/` (Agents' parts in `agents/`). It takes the chat, its metadata and the mode as props, and calls React Query and store hooks itself. Newer sections save through their own `useUpdateChatMetadata`. State that two or more sections use stays in the drawer and goes down as props, like the character and persona pickers and the inline card editor.
- **Drafts and effects go in the section's wrapper**, the component that renders `ChatSettingsSection`, never in its collapsible body. `components/ui/Drawer.tsx` renders the body only while the section is expanded, and popping a section out remounts it, so a draft there is lost and an effect there stops running while the section is collapsed. A change that moves a draft adds a test that collapsing or popping out the section keeps it.
- **Code order is screen order.** The drawer renders the sections in the order they show, with no CSS `order`, so keyboard and screen reader order matches the screen. `e2e/chat-settings-sections.e2e.ts` lists each mode's sections and fails if one of the sections its chats show is placed by CSS `order`. The agent cards inside Agents still use CSS `order`.
- **A section's id is saved.** It keys each person's remembered open and popped-out state, so renaming it resets that state for everyone.
- **Save-before-close checks.** `requestClose` runs each check (Agent Suite, Prose Guardian's drafts, the inline card editor) and keeps Chat Settings open if one fails. The next change that needs another check should replace them with one `registerCloseGuard(check)` that returns an unregister function, instead of adding another slot: two sections sharing a slot would overwrite each other's check.
- **Moving code can quietly empty a source-text regression.** Many scripts in `scripts/regressions/` read Chat Settings files by path and match their text. When code moves, re-point them: a `doesNotMatch` check against the old file keeps passing once the code is gone from it. Keep a check only if it guards real behaviour (a save or close guard, a lazy-loading boundary, a fixed bug); otherwise replace it with a behavioural test or delete it.
- **Agents** is one hook, `agents/use-chat-agents.ts`, which the drawer calls once, plus one face per mode that reads its result: `ConversationAgentsSection.tsx`, `RoleplayAgentsSection.tsx` and `GameAgentsSection.tsx`. Render helpers the faces share are in `agents/agent-settings-renderers.tsx`, and the Roleplay and Game faces' common pieces (the note when no agents are downloaded, the Enable Agents switch, the Agent Suite button) are in `agents/agents-section-parts.tsx`. The add-agent window is `agents/AgentAddModal.tsx`; the drawer renders it outside the Agents section, because the agent setup queue opens it while Agents is collapsed. A new built-in agent's card needs:
  - a row in `agents/built-in-agent-cards.ts` (its id, and the name and description to show when the agent doesn't supply them). The hook turns each row into `builtInAgentCards[id]` (name, description, on or off) and the card's link in the jump menu;
  - its `AgentSettingsCard`, reading `builtInAgentCards[id]`: in `RoleplayAgentsSection.tsx` (or `GameAgentsSection.tsx` for a Game card), or in `agent-settings-renderers.tsx` if more than one face shows it (like Haptic Feedback's);
  - its icon in `agents/roleplay-agent-menu-icon.tsx`.

  Add the row and the card together: a row without a card puts a link in the jump menu that goes nowhere. The card's position comes from its manifest, through `src/lib/agent-settings-order.ts`.

### Animation Patterns

- **Sidebar slide-in/out:** on desktop, CSS transitions on the sidebar slot (`mari-shell-panel-enter-*` / `mari-shell-panel-exit-*`); the phone and tablet sheet uses Framer Motion `AnimatePresence` with a spring.
- **Message entrance:** `motion.div` with stagger.
- **Modals:** CSS transitions (not Framer Motion) for React StrictMode compatibility.
- **Background transitions:** `CrossfadeBackground` component for smooth image swaps.

## Shared Package Contract

All types, schemas, and constants are in `packages/shared`. The frontend imports from `@marinara-engine/shared`.

- **Schemas (Zod):** Input validation for forms — use `z.infer<typeof schema>` for types.
- **Types:** Interfaces for API responses and store shapes.
- **Constants:** `APP_VERSION`, `DEFAULT_GENERATION_PARAMS`, `PROVIDERS`, `CHAT_MODES`, model lists.
- **Utilities:** `resolveMacros()` for template variables. XML/Markdown section wrapping lives server-side in `packages/server/src/services/prompt/format-engine.ts` (`wrapContent()`), not in the shared package.

**When adding a new entity or modifying data shapes, update `packages/shared` first**, then update hooks and components.

## How to Add Common Things

### New Entity (e.g., "Playlists")

1. Add Zod schemas + types in `packages/shared/src/schemas/` and `packages/shared/src/types/`.
2. Export from `packages/shared/src/index.ts`.
3. Add server routes in `packages/server/src/routes/`.
4. Create a hook file: `packages/client/src/hooks/use-playlists.ts` following the React Query pattern.
5. Create a panel: `packages/client/src/components/panels/PlaylistsPanel.tsx`.
6. Register the panel in `RightPanel.tsx` (`PANEL_CONFIG`) and `right-panel-panels.ts` (`RIGHT_PANELS`).
7. Add a toggle button in `TopBar.tsx`.
8. Create an editor: `packages/client/src/components/characters/PlaylistEditor.tsx` (lazy-loaded in `AppShell`).
9. Add UI store fields: `playlistDetailId`, `openPlaylistDetail()`, `closePlaylistDetail()`.

### New Modal

1. Create the modal component in `components/modals/`.
2. Accept `{ open, onClose }` props, wrap content in `<Modal>`.
3. Add the type string to the switch in `ModalRenderer.tsx`.
4. Open with `openModal("your-type", { optionalProps })`.

### New Setting

1. Add the field + setter to `UIState` interface in `ui.store.ts`.
2. Initialize the default value in the store creator.
3. Add the control in the appropriate settings subtab component.
4. Use `ToggleSetting` from `SettingControls.tsx` for booleans.
5. Add every user-visible label, description, tooltip, placeholder, and accessibility name to the canonical English
   locale and render it through `t("semantic.key")`. Community locale files may omit the new key and will fall back
   to English; do not edit every locale merely to keep their key lists equal.

### New Hook

1. Create `use-your-feature.ts` in `hooks/`.
2. Define query key factory at the top of the file.
3. Export individual hooks: `useThings()`, `useThing(id)`, `useCreateThing()`, `useUpdateThing()`, `useDeleteThing()`.
4. Follow the established mutation → invalidation pattern.

## Common Mistakes to Avoid

- **Don't hard-code new user-visible UI copy.** Add a semantic key to `localization/locales/en.json` and use
  `useTranslation`. Missing community translations deliberately fall back to English, so a feature PR should not
  duplicate English into every locale file.
- **Don't create index.ts barrel files.** This project uses direct imports everywhere.
- **Don't use URL-based routing.** Navigation is state-based via `ui.store.ts`.
- **Don't put async logic in Zustand stores.** Use React Query mutations in hooks.
- **Don't forget to lazy-load new editors** in `AppShell.tsx`.
- **Don't add React Query `refetchOnWindowFocus`.** It's disabled globally in `lib/query-client.ts`.
- **Don't use `any` without good reason** — but `@typescript-eslint/no-explicit-any` is OFF, so it compiles either way.
- **Don't modify `packages/shared` without checking server impact.** It's a shared contract.
- **Don't use `fetch()` directly.** Always use `api.*` from `@/lib/api-client`.
