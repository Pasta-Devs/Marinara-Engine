# Настройки сервера: справочник

Это руководство объясняет, как менять настройки уровня сервера в приложении Marinara Engine через переменные окружения. Переменная окружения – это настройка, которую вы пишете в обычном текстовом файле, а сервер его читает. Большинству эта страница никогда не понадобится. Полный список переменных находится ближе к концу.

## Когда нужно менять настройки

Приложение Marinara Engine работает сразу и без настройки. Эта страница нужна только для нескольких задач. Почти все они связаны с тем, что сервером пользуется больше одного устройства.

Настройки стоит поменять, если вы хотите:

- Открыть доступ к серверу другим устройствам в сети (управление доступом).
- Защитить общий сервер паролем или списком разрешенных IP-адресов.
- Изменить место, где данные хранятся на диске.
- Повысить подробность журнала сервера, чтобы разобраться в проблеме.
- Дать медленным задачам генерации изображений, видео или эмбеддингов больше времени (тайм-ауты).
- Разрешить особые действия с удаленного устройства – например, резервные копии или обновления.

Почти все остальное – ключи провайдеров ИИ, персонажи, параметры чата – настраивается в самом приложении, а не здесь. О добавлении провайдера ИИ читайте в разделе [Подключение к провайдеру ИИ](connections/connecting-to-a-provider.md).

Дополнительные официальные агенты тоже управляются внутри приложения. Откройте **Agents → Download Agents**, чтобы установить или удалить их. Marinara сама выбирает в каталоге [Pasta-Devs/Marinara-Agents](https://github.com/Pasta-Devs/Marinara-Agents) ту ветку, которая соответствует основной версии Engine.

Жизненный цикл пакетов и их хранение:

- **Обновления:** Marinara проверяет, есть ли совместимые обновления для уже установленных официальных пакетов, и спрашивает перед скачиванием каждой новой версии. Ответ **No** оставляет текущую версию, а действие **Update** остается доступным вручную в разделе Download Agents. После свежей установки список пуст, пока вы не выберете пакеты.
- **Платформы:** Поведение одинаково для компьютера, контейнера Docker и установки на Android через Termux. Клиенты на iOS и другие браузерные клиенты используют пакеты, установленные на их сервере Marinara.
- **Хранение:** Пакеты лежат в папке `DATA_DIR/capability-packages`. Тома Docker, свои папки данных, резервные копии и обычные обновления их сохраняют.
- **Место на диске:** Marinara хранит текущую версию каждого пакета и предыдущую, чтобы неудачное обновление можно было откатить. Более старые версии и временные копии в `DATA_DIR/capability-runtime-snapshots` она удаляет сама. Данные пакетов никогда не удаляются.
- **Работа без сети:** Уже установленные пакеты продолжают работать в своей версии, если исходящий доступ к GitHub по HTTPS недоступен, обновление отклонено или не прошло проверку.

### Импорт своих агентов

Пользовательские агенты могут включить **Previous output** (предыдущий результат) в разделе **Context Sources** (источники контекста), чтобы читать свой последний успешный результат из видимой истории сообщений. При включенном **JSON context output** (вывод контекста в JSON) возвращайте `{"text":"main prompt content","agent-context":"private continuation context"}`. В основной промпт попадает только `text`; необязательное поле `agent-context` предназначено для следующего запуска этого же агента. **Hide output as spoilers** (скрывать результаты как спойлеры) оставляет сохраненные результаты свернутыми, пока вы их не раскроете. При повторной генерации заменяемый ход исключается. Удаленные сообщения и неактивные свайпы не могут передавать контекст для продолжения.

Внешние файлы агентов, папки и свои репозитории по умолчанию запрещены. Чтобы их разрешить, откройте **Settings** (настройки) **→ Advanced → Danger Zone** и включите **Allow custom Agent imports**. В отличие от внешних расширений, этот переключатель находится полностью в ваших руках, и переменная окружения ему не нужна. Пока он выключен, элементы импорта остаются неактивными.

Перед сохранением каждый импорт показывает, какие возможности запрашивает агент. Разрешения нужно подтвердить явно; вложенные функции и наборы инструментов не импортируются; сгенерированный код CSS проходит очистку; действия из результата сверяются с одобренным набором возможностей. Если переключатель выключить, импортированные извне агенты перестают работать. Свои агенты, созданные в приложении Marinara, и официальные пакеты из **Download Agents** продолжают работать и от этого переключателя не зависят.

### Свои репозитории агентов

Свои репозитории по умолчанию выключены: их промпты и наборы инструментов – это непроверенный сторонний материал. Задайте `ENABLE_CUSTOM_AGENT_REPOS=true`, включите **Allow custom Agent imports** в разделе Danger Zone, затем откройте **Agents → Download Agents → Custom Sources**, чтобы посмотреть публичный репозиторий GitHub. И добавление источника, и применение любых последующих изменений требуют отдельного подтверждения. Синхронизация только ручная: Marinara не клонирует репозитории и не опрашивает их в фоне.

Репозиторий может публиковать агентов, наборы правил Game Mode или и то и другое. Нужен хотя бы один из этих видов.

В корне репозитория может лежать массив `agents.json` в том же формате определений агентов, что и у загружаемых пакетов агентов. Минимальный файл выглядит так:

```json
[
  {
    "id": "continuity-helper",
    "name": "Continuity Helper",
    "description": "Checks recent turns for contradictions.",
    "phase": "post_processing",
    "enabledByDefault": false,
    "category": "writer",
    "defaultPromptTemplate": "Check {{messages}} for continuity errors."
  }
]
```

В корне репозитория также может быть папка `rulesets`: каждый файл `.json` в ней содержит один набор правил Game Mode, всего до 32 файлов размером до 512 KB каждый. Читаются только файлы, лежащие прямо в `rulesets`, поэтому содержимое подпапок игнорируется. Каждый набор правил показывается в предпросмотре с именем, версией и тем, что он охватывает. Текст набора правил для Game Master отправляется модели в каждой игре, которая его использует, поэтому устанавливайте наборы правил только от тех, кому доверяете.

Имя импортированного набора правил строится от владельца репозитория, например `alice/my-5e`, поэтому он никогда не займет имя официального набора, а два автора могут оба опубликовать набор под названием `v20`. Каждая импортированная версия сохраняется, и игра всегда идет на той версии, на которой ее создали. Если та же версия приходит снова с другим содержимым, Marinara оставляет установленную и предлагает попросить автора повысить номер версии. Файл, который Marinara не может прочитать, показывается в списке с причиной и пропускается; остальное содержимое репозитория все равно устанавливается.

Marinara принимает только URL корня репозитория GitHub и до показа предпросмотра проверяет архив ограниченного размера и каждое определение агента. При синхронизации промпты, настройки и инструменты из репозитория заменяют управляемые репозиторием значения, показанные в предпросмотре. Выбор подключений и изображений остается локальным. Если агент исчезает из источника, Marinara оставляет его обычным локальным пользовательским агентом и убирает только связь с репозиторием. Удаление источника следует тому же правилу – все остается локально, а поставленные им наборы правил остаются установленными, чтобы закрепленные за ними игры продолжали работать.

### Внешние расширения

Импорт внешних расширений требует двух независимых разрешений. Задайте `ENABLE_EXTERNAL_EXTENSIONS=true` в файле `.env`, затем откройте **Settings → Advanced → Danger Zone**, прокрутите ниже элементов удаления данных, прочитайте предупреждение и включите **Allow third-party extension imports**. Только после этого раздел **External Extensions** появится в **Settings → Addons**.

Переменная окружения – это разрешение от того, кто держит сервер; переключатель в Danger Zone – ваше явное согласие. Раздел, маршруты импорта, маршруты одобрения и оба загрузчика во время работы проверяют оба условия. Закрытие любого из них отключает записи внешних расширений и останавливает выполнение внешнего кода. Записи, добавленные вручную, старые, пришедшие из профиля и с неизвестным источником считаются внешними, поэтому просто положить файлы в папку расширений недостаточно.

Черновики от Professor Mari доступны и без этого флага. Они создаются выключенными, и их точный хеш кода все равно требует одобрения.

По умолчанию расширения работают в режиме Sandboxed Browser Extensions. Часть старых сторонних пакетов помечена как **Full page access** (полный доступ к странице), потому что они зависят от структуры DOM приложения Marinara. В этом режиме одобренный код выполняется прямо на странице Marinara и получает доступ к содержимому страницы, хранилищу браузера, сетевым интерфейсам и текущей сессии того же источника. Режим доступен только для раздела **External Extensions**, когда открыты оба разрешения, и требует отдельного подтверждения предупреждения. Если после расширения остаются изменения внешнего вида или поведения, выключите режим и перезагрузите страницу.

## Необязательный многопользовательский режим

Многопользовательский режим по умолчанию выключен. Пока хотя бы одно из двух разрешений выключено, фоновых проверок сессий, сертификатов и участников нет; клиент читает доступность один раз, если вы явно не обновите Settings. Поддерживаются частные комнаты Conversation, Roleplay и Game без фиксированного ограничения числа людей или ИИ-персонажей. Каждый гость использует собственную доверенную установку Marinara; телефон может использовать доверенный сервер Engine своего владельца. Гостям не нужны подключения к ИИ. Их предоставляет хост, который может читать и сохранять общее содержимое.

1. Задайте `MULTIPLAYER_ENABLED=true` в `.env` каждого участвующего Engine и перезапустите его. Только точное значение `true` включает это предварительное условие; горячая перезагрузка его не меняет.
2. Откройте **Settings → Advanced → Multiplayer** (настройки → дополнительные → многопользовательский режим), прочитайте предупреждение и включите отдельную настройку. Это не открывает порт и не подключает к комнате.
3. Для размещения используйте **Create shared session** (создать общую сессию) или **Play together** (играть вместе) в существующем выборе режима/настройки. Проверьте настройки, отображаемое имя и точный текст персоны для отправки. Из существующего чата берутся только настройки; его частная история, заметки и воспоминания не копируются.
4. Настройте `SSL_CERT` и `SSL_KEY` на хосте с сертификатом, действительным для имени хоста комнаты и доверенным для Engine гостя. Выберите отдельные HTTPS-адрес и порт, например `https://room.example.org:7861`. Порт открывает только явное действие размещения. Через брандмауэр/роутер публикуйте только порт комнаты, не обычный API Engine. Проброс портов, аккаунт ретранслятора и обход сертификатов автоматически не настраиваются.
5. Задайте пароль комнаты длиной не менее 12 символов, отличный от учетных данных Engine/администратора. Передавайте временное приглашение и пароль отдельно доверенным людям. Гость в своем клиенте проверяет отпечаток, привязанный к имени хоста, имя комнаты и текст персоны, соглашается и запрашивает допуск. Хост одобряет каждый запрос в **Players** (игроки) до отправки истории.

TLS проверяет цепочку сертификата и имя хоста, а перед отправкой пароля также отпечаток сертификата из приглашения. Самоподписанные сертификаты не принимаются молча. Обновленный или измененный сертификат требует нового приглашения и повторной проверки. Приглашение истекает через 30 минут; допущенная сессия длится не более 12 часов. Замена/отзыв предотвращает новые допуски через неиспользованные приглашения; Kick отзывает доступ допущенного участника.

Хост управляет автоматическими/ручными ответами, ограниченным бюджетом генерации, Pause/Resume и Stop. По умолчанию доступны 100 координированных ходов генерации за сессию размещения; групповой ход или настройка Game может вызвать модель несколько раз. Это лимит ходов, не оценка стоимости. Расписания Conversation используют существующий планировщик хоста. Гости не запускают второй планировщик и не выполняют локальные команды из полученного текста.

В Game проверьте допущенную группу людей перед Start Game. Каждый обязательный участник отправляет действие или пропускает ход. GM разрешает раунд только после готовности всех. Отключенный игрок остается обязательным до возвращения либо явного пропуска/удаления хостом. Новые игроки и изменения персон вступают в силу со следующего раунда. Приостановленное/прерванное разрешение никогда автоматически не повторяет платные запросы или уже сохраненные изменения мира; перед продолжением проверьте историю.

Stop, Leave, выключение в Settings и перезапуск сервера завершают соответствующую активную сессию. Перезапуск не размещает комнату и не подключается автоматически. Комнатой владеет сервер хоста; закрытие его браузера не передает управление гостю. Приостановка мобильного браузера может задержать обновления, но не запускает вторую генерацию.

Подключайтесь только к доверенным людям. Используйте собственный доверенный клиент Marinara; не устанавливайте клиент, расширение или обязательный файл от хоста. Он может читать, сохранять и передавать общее содержимое своим провайдерам ИИ. Прямые подключения раскрывают сетевые адреса. Не делитесь паролями, ключами API и чувствительными личными данными. Сразу выходите при подозрительных признаках.

Общее содержимое ограничено текстом с лимитом размера. Нет передачи файлов/медиа между участниками, исполняемого содержимого, импорта пакетов, загрузки удаленных ресурсов или нативных действий. Пользовательские/пакетные инструменты и небезопасные команды недоступны. Нативная оболочка Android не может подключаться. Точные ограничения и проверенные платформы описаны в [записи о совместимости и проверках](development/multiplayer.md); эти меры не гарантируют защиту от любой уязвимости браузера/ОС или независимой внешней загрузки.

## Где лежит файл .env

Настройки хранятся в файле с именем `.env`. Это обычный текстовый файл: одна настройка в строке, в виде `KEY=value`. Строки, начинающиеся с `#`, – это комментарии, сервер их не читает.

Файл `.env` – это данные, а не сценарий оболочки. Marinara не выполняет `$`, подстановки команд вида `$(...)` и другой синтаксис оболочки внутри значения. Скрипты запуска для macOS/Linux и Termux применяют то же правило без вычислений к небольшому набору настроек, которые нужны им до старта сервера. Значение, уже заданное в окружении скрипта запуска, имеет приоритет над одноименной строкой в `.env`.

Marinara создает пустой файл `.env` при первом запуске, так что вручную его делать не нужно.

- При обычной установке файл `.env` лежит в корневой папке проекта.
- В официальных образах Docker или Podman он находится по пути `/app/data/.env`, в том же томе хранения, где и данные.

Файл `.env.example` в той же папке перечисляет все настройки со значениями по умолчанию. Чтобы поменять настройку, скопируйте строку из `.env.example` в `.env` и отредактируйте значение после знака `=`.

Вот пример файла `.env`, который меняет порт и включает пароль:

```
PORT=8080
BASIC_AUTH_USER=alice
BASIC_AUTH_PASS=correct-horse-battery-staple
```

Сервер читает `.env` сам, независимо от способа запуска. В том числе при прямом вызове `pnpm start`. Скрипты запуска (`start.bat`, `start.sh`, `start-termux.sh`) добавляют две вещи: они задают `HOST=0.0.0.0`, чтобы сервер был доступен другим устройствам, и открывают браузер. При запуске просто через `pnpm start` сервер слушает только этот компьютер, пока вы сами не зададите `HOST`.

<a id="restart-or-hot-reload"></a>

## Перезапуск или применение на ходу

Marinara следит за файлом `.env` во время работы. После сохранения изменений большинство настроек применяется почти сразу, без перезапуска. Каждый раз, когда сервер применяет изменение, он пишет в журнал строку, начинающуюся с `[env-watcher]`. Если в вашей файловой системе не удается настроить слежение за файлом, сервер переходит на проверку файла раз в 30 секунд и сообщает об этом в журнале.

Одна оговорка: в некоторых конфигурациях слежение запускается нормально, но события изменений так и не приходят – обычно когда файл правят _с другой машины или из другого окружения_, например через сетевую папку или с хоста в примонтированную папку контейнера (bind mount). Если правки `.env` не подхватываются, задайте `MARINARA_ENV_WATCH=poll`, и сервер будет вместо этого проверять файл раз в 30 секунд – так он видит каждую запись. Чтобы полностью отключить слежение, задайте `MARINARA_ENV_WATCH=0` (в окружении оболочки или в самом `.env` до запуска) – тогда изменения требуют перезапуска. Оба варианта рассчитаны на опытных пользователей: именно применение на ходу позволяет менять настройки управления доступом без простоя, поэтому оставьте значение по умолчанию, если у вас нет конкретной причины.

Небольшая группа низкоуровневых настроек фиксируется при старте сервера. Их изменение требует полного перезапуска. Это такие настройки:

- `PORT`, `HOST`
- `SSL_CERT`, `SSL_KEY`
- `DATA_DIR`, `FILE_STORAGE_DIR`
- `ENCRYPTION_KEY`
- `MARINARA_ENV_FILE`, `MARINARA_ENV_WATCH`
- `TZ`
- `AUTO_OPEN_BROWSER`, `AUTO_UPDATE_ENABLED`, `AUTO_CREATE_DEFAULT_CONNECTION`
- `LOG_DISABLE_REQUEST_LOGGING`
- `STORAGE_CACHE_WINDOWS_BOOT_ID`, `SHUTDOWN_WINDOWS_CONSOLE_SIGNALS`, `SHUTDOWN_FORCE_EXIT_ON_REPEAT`
- Настройки тайм-аутов и опроса для изображений, видео, спрайтов и ComfyUI (`IMAGE_GEN_TIMEOUT_MS`, `IMAGE_GEN_MAX_RESPONSE_BYTES`, `VIDEO_GEN_TIMEOUT_MS`, `VIDEO_GEN_MAX_RESPONSE_BYTES`, `SPRITE_GENERATION_TIMEOUT_MS`, `SPRITE_ANIMATED_FFMPEG_TIMEOUT_MS`, `COMFYUI_GEN_TIMEOUT` и четыре настройки `*_VIDEO_POLL_INTERVAL_MS`)

При изменении любой из них журнал предупреждает, что нужен перезапуск. Настройки управления доступом и секреты – `BASIC_AUTH_USER`, `BASIC_AUTH_PASS`, `IP_ALLOWLIST`, `ADMIN_SECRET`, `CSRF_TRUSTED_ORIGINS` – перезапуска не требуют.

## Управление доступом

Управление доступом определяет, кому разрешено обращаться к работающему серверу. Этот раздел – краткая справка. Пошаговый разбор с примерами есть в руководстве [Удаленный доступ: Basic Auth и список разрешенных адресов](REMOTE_ACCESS.md).

Несколько терминов, которые встречаются ниже:

- Loopback – это тот же компьютер, на котором работает сервер. Обращаться к нему можно по адресу `127.0.0.1` или `localhost`.
- Диапазон CIDR – короткая запись целого блока IP-адресов, например `192.168.1.0/24`. Сокращение CIDR означает Classless Inter-Domain Routing.
- Диапазоны RFC 1918 – это стандартные частные диапазоны адресов, которые используются в домашних и офисных сетях: например, `10.x.x.x` и `192.168.x.x`.

По умолчанию, когда пароль не задан, сервер принимает подключения только из доверенных источников. Это loopback, любой адрес из `IP_ALLOWLIST`, сеть Tailscale и трафик моста или шлюза Docker с того же хоста. Все остальные, включая обычную домашнюю сеть, получают ответ `403 Forbidden`, пока вы не выберете один из вариантов ниже.

Основные настройки управления доступом:

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `BASIC_AUTH_USER` | пусто | Имя пользователя для запроса пароля. Задайте вместе с `BASIC_AUTH_PASS`, чтобы включить вход. |
| `BASIC_AUTH_PASS` | пусто | Пароль для запроса при входе. Оставьте любое из двух полей пустым, чтобы отключить вход. |
| `BASIC_AUTH_REALM` | `Marinara Engine` | Текст, который браузер показывает в окне запроса пароля. |
| `IP_ALLOWLIST` | пусто | IP-адреса или диапазоны CIDR через запятую, которым доступ разрешен всегда. Прямой loopback разрешен всегда, а обратный прокси на той же машине – нет. |
| `IP_ALLOWLIST_ENABLED` | `true` | Значение `false` сохраняет список, но приостанавливает его действие. |
| `ALLOW_UNAUTHENTICATED_PRIVATE_NETWORK` | `false` | Возвращает доступ без пароля из частных сетей, когда вход не настроен. Некоторые интернет- и мобильные провайдеры выдают клиентам адреса из `100.64.0.0/10`. Если у этого компьютера такой адрес, другие клиенты провайдера считаются клиентами частной сети. |
| `ALLOW_UNAUTHENTICATED_REMOTE` | `false` | Разрешает доступ без пароля с любого адреса, включая интернет. Не рекомендуется. |
| `TRUSTED_PRIVATE_NETWORKS` | встроенные значения | Заменяет стандартные диапазоны частных сетей. Перечислите и те стандартные, которые хотите оставить. |
| `BYPASS_AUTH_TAILSCALE` | автоматически | Пустое значение доверяет прямому сокету Tailscale, только когда оба его конца используют адреса tailnet, а в запросе нет заголовков пересылки (Tailscale Serve и Funnel требуют входа). Задайте `true` для прежнего обхода всего диапазона `100.64.0.0/10` или `false`, чтобы требовать обычный контроль доступа. |
| `BYPASS_AUTH_DOCKER` | автоматически | Пустое значение доверяет только определенному интерфейсу контейнера и его точному шлюзу, и только пока не заданы ни Basic Auth, ни `IP_ALLOWLIST`. Задайте `true` для совместимости со старыми или нестандартными сетями либо `false`, чтобы требовать обычный контроль доступа. |
| `REQUIRE_AUTH_FOR_DOCKER_PROXY` | `true` | Требует обычной проверки входа и списка разрешенных адресов для трафика Docker, который передает прокси (заголовки пересылки, Host с именем другого компьютера или HTTP/1.0). Ставьте `false`, только если сам прокси требует входа от каждого посетителя. |
| `REQUIRE_AUTH_FOR_LOOPBACK_PROXY` | `true` | Считает запросы, которые пересылает обратный прокси или туннель на той же машине, запросами удаленных посетителей, в том числе запросы HTTP/1.0, например от `proxy_pass` nginx по умолчанию. Ставьте `false`, только если сам прокси требует входа от каждого посетителя. |
| `TRUSTED_HOSTS` | пусто | Дополнительные публичные имена или имена обратного прокси, на которые Marinara может отвечать. Прямой IP-адрес, localhost, `.local`, `.home.arpa` и однословные локальные имена работают сами. |
| `SSL_CERT` | пусто | Путь к файлу сертификата TLS. Задайте вместе с `SSL_KEY`, чтобы сервер сам работал по HTTPS. |
| `SSL_KEY` | пусто | Путь к файлу закрытого ключа TLS. |
| `CSRF_TRUSTED_ORIGINS` | пусто | Дополнительные браузерные источники, которым разрешено сохранять изменения. Нужно для публичного домена или нестандартного порта. Буквальное значение `null` игнорируется, и его нельзя использовать для APK на Android; маршруты входа с собственной аутентификацией работают без глобального доверия непрозрачному источнику. |

Basic Auth – это сокращение от HTTP Basic Authentication, простого запроса имени пользователя и пароля. Эти данные только кодируются, но не шифруются, поэтому всегда сочетайте их с HTTPS, если сервер доступен из интернета. HTTPS – это защищенная, зашифрованная версия HTTP. Чтобы включить его напрямую, задайте `SSL_CERT` и `SSL_KEY` вместе, либо поставьте перед Marinara обратный прокси.

Чтобы другие устройства вообще могли обратиться к серверу, он должен слушать доступный сетевой интерфейс. Задайте `HOST=0.0.0.0`. Скрипты запуска делают это сами, а `pnpm start` слушает только loopback.

Телефоны, планшеты, узлы Tailscale и другие компьютеры могут и дальше подключаться по IP-адресу сервера, и добавлять его в `TRUSTED_HOSTS` не нужно. Если вы публикуете Marinara под публичным именем или именем обратного прокси, добавьте это имя точно, например `TRUSTED_HOSTS=chat.example.com`. Имена, уже перечисленные в `CSRF_TRUSTED_ORIGINS` или `CORS_ORIGINS`, тоже принимаются – для совместимости. Такая проверка имени хоста не дает подменить имя DNS публичного сайта на адрес loopback, где работает Marinara.

## Хранение данных

Настройки хранения задают, где лежат локальные данные. К данным относятся чаты, персонажи, аватары и сгенерированные медиафайлы.

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `DATA_DIR` | `packages/server/data` | Корневая папка всех пользовательских данных. В образах Docker задан путь `/app/data`. |
| `FILE_STORAGE_DIR` | папка `storage` внутри `DATA_DIR` | Переопределяет папку хранения файлов. |
| `ENCRYPTION_KEY` | пусто | Ключ для шифрования сохраненных ключей API. Сгенерируйте его командой ниже. |
| `MARINARA_MAX_RESIDENT_CHATS` | `0` (без ограничений); `8` на SteamOS/Termux | Ограничивает, сколько чатов сервер одновременно держит в памяти. Чат загружается при первом открытии; при превышении предела после каждого сохранения чат, к которому дольше всего не обращались и в котором нет несохраненных изменений, убирается из памяти, но с диска не удаляется никогда. В Termux (Android) и SteamOS (Steam Deck) сервер по умолчанию использует `8`: у телефонов мало памяти, а на Deck большую часть общей памяти забирают игры. Задайте допустимое неотрицательное целое число, чтобы переопределить значение платформы по умолчанию: недопустимый текст вызывает предупреждение, и берется это значение по умолчанию; положительные значения меньше `2` повышаются до `2`; явно заданный `0` отключает вытеснение (незаданная переменная отключает его только на платформах без ограничений по памяти). |
| `MARINARA_EAGER_STORAGE` | выключено | Задайте `1`, чтобы при запуске загружать в память все чаты и вернуть поведение версий до 2.4.5. На больших профилях расходует намного больше памяти; чтобы изменить значение, нужен перезапуск. |

Marinara хранит данные в обычных файлах JSON. Так резервные копии проще копировать и просматривать.

Чтобы сгенерировать ключ шифрования, выполните эту команду и вставьте результат в `ENCRYPTION_KEY`:

```
openssl rand -hex 32
```

О том, что лежит в каждой папке данных, читайте в разделе [Где Marinara хранит ваши данные](data/where-data-is-stored.md).

## Уровни логирования

Логирование определяет, насколько подробно сервер пишет в консоль. Основная настройка – `LOG_LEVEL`. Все, что ниже выбранного уровня, сервер скрывает.

| Уровень | Что показывает |
| --- | --- |
| `error` | Только серьезные, неустранимые сбои. |
| `warn` | Ошибки и некритичные предупреждения. Это значение по умолчанию. |
| `info` | Предупреждения, а также записи о старте и о каждом запросе. |
| `debug` | Все, включая полные промпты и ответы модели. Очень подробно. |

Что стоит выбрать:

- Для обычной работы оставьте `warn`. Этот уровень тихий и показывает только реальные проблемы.
- Уровень `info` подойдет, если хочется видеть запросы и основные события, но без потока сообщений.
- Уровень `debug` нужен, когда важно увидеть точный промпт, отправленный модели, и ответ. Вывода будет много.

Чтобы видеть подробности про промпты и подключения без обычных записей о запросах, задайте не уровень, а пресет:

```
LOG_PRESET=prompt-connections
```

Этот пресет показывает те же подробности про промпты и модель, что и `debug`, но скрывает повторяющиеся строки запросов вида `GET /api/chats`. Чтобы убрать только эти рутинные строки, сохранив текущий уровень, задайте настройку ниже и перезапустите сервер:

```
LOG_DISABLE_REQUEST_LOGGING=true
```

Логирование в браузере работает отдельно, и `LOG_LEVEL` на него не влияет.

## Тайм-ауты

Откройте **Settings → Advanced → Request timeouts** (тайм-ауты запросов), чтобы задать в секундах лимиты для текста, агентов, промптов изображений Game, изображений, видео, ComfyUI и эмбеддингов. Более высокие лимиты помогают медленным локальным бэкендам успеть завершить работу, но не отменяют ограничение, которое устанавливает сам провайдер. Для сохранения нужен доступ администратора сервера.

Эти настройки действуют для всех профилей и сохраняются рядом с активным `.env` в файле `.env.timeouts.json` (или `<custom-env-path>.timeouts.json`). Они имеют приоритет над соответствующими переменными окружения, не переписывая `.env`. Изменения для текста, агентов, промптов изображений Game и эмбеддингов применяются к новым запросам. Для изменений медиа и установленных пакетов агентов перезапустите сервер. Чтобы вернуться к настройкам из окружения, удалите файл настроек тайм-аутов и перезапустите сервер.

Тайм-аут – это максимальное время, которое сервер ждет медленную задачу, прежде чем прекратить попытку. Медиазадачи вроде генерации изображений и видео бывают долгими, поэтому их тайм-ауты по умолчанию щедрые. Все значения тайм-аутов указаны в миллисекундах, если в названии не сказано иначе.

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `CHAT_GENERATION_TIMEOUT_MS` | `300000` (5 минут) | Тайм-аут на заголовки провайдера, на первый токен и на промежутки между частями ответа для обычных генераций в режимах Conversation, Roleplay и Game, а также лимит на первый токен и на промежутки между частями ответа для фоновых генераций без своего тайм-аута (Professor Mari, обновление ленты Noodle, ответы Slurp). Допустимый диапазон: `10000`-`3600000`. Тайм-ауты агентов, медиа, эмбеддингов и инструментов эта настройка не меняет. |
| `AGENT_CALL_TIMEOUT_MS` | `300000` (5 минут) | Ограничение общей длительности одного обращения агента к модели (трекеры, переформатирование HTML и другие агенты); действует и во время стриминга ответа. Повысьте его для медленных локальных моделей, которым нужно больше 5 минут на один проход агента. Допустимый диапазон: `10000`-`3600000`. У агента Illustrator сохраняется собственный лимит не меньше 30 минут. |
| `GAME_DYNAMIC_IMAGE_PROMPT_TIMEOUT_MS` | `45000` (45 секунд) | Ограничение общей длительности обращения к модели, которое превращает текущую сцену режима Game в динамический промпт для изображения. Повысьте его для более медленных локальных моделей. Допустимый диапазон: `10000`-`3600000`. |
| `EMBEDDING_TIMEOUT_MS` | `300000` (5 минут) | Время на один запрос эмбеддинга. Значение побольше помогает медленным локальным серверам эмбеддингов. |
| `IMAGE_GEN_TIMEOUT_MS` | `1800000` (30 минут) | Время на один запрос генерации изображения. |
| `IMAGE_GEN_MAX_RESPONSE_BYTES` | `31457280` (30 MiB) | Максимальный размер ответа с изображением, который сервер согласится принять от провайдера изображений. Увеличьте значение, если локальный ComfyUI встраивает в файлы большие метаданные. |
| `VIDEO_GEN_TIMEOUT_MS` | `1800000` (30 минут) | Время на один запрос генерации видео сцены, включая локальные процессы видео в ComfyUI. |
| `VIDEO_GEN_MAX_RESPONSE_BYTES` | `167772160` (160 MiB) | Максимальный размер видео сцены, которое сервер согласится скачать. |
| `COMFYUI_GEN_TIMEOUT` | `2400` (40 минут, в секундах) | Время на один процесс изображения в ComfyUI после постановки в очередь. |
| `SPRITE_GENERATION_TIMEOUT_MS` | берется из `IMAGE_GEN_TIMEOUT_MS` | Время на одну задачу генерации спрайта средствами ИИ. |
| `CUSTOM_TOOL_TIMEOUT_MS` | `60000` (1 минута) | Время на один вызов своего инструмента. |
| `MAX_TOOL_ROUNDS` | `100` | Сколько кругов вызова инструментов допустимо, прежде чем модель обязана дать окончательный ответ. Ход Game Mode получает не больше 4, агент – 16, а дозаполнение лорбука – 64, или значение этой переменной, если оно меньше. |

Тайм-ауты изображений, видео, спрайтов и ComfyUI фиксируются при старте, поэтому их изменение требует перезапуска. Тайм-ауты генерации чата, агентов, динамического промпта изображения в режиме Game, эмбеддингов и своих инструментов применяются к следующему запросу или проходу агента, без перезапуска. Недопустимые, нулевые, отрицательные или выходящие за диапазон значения для проверяемых тайм-аутов чата, агентов и динамического промпта изображения в режиме Game вызывают предупреждение в журнале, а сервер безопасно берет описанные значения по умолчанию. Повышайте медиатайм-аут, если крупные или высококачественные задачи срываются на середине. Подробнее о задачах видео – в разделе [Генерация видео сцены](media/scene-video.md).

## Особые действия по API (ADMIN_SECRET)

Некоторые действия разрушительны или рискованны, поэтому им нужен отдельный секрет вдобавок к обычным проверкам доступа. Это, например, резервные копии, очистка данных, применение обновлений и установка тем оформления.

Задайте на сервере длинное случайное значение `ADMIN_SECRET`:

```
ADMIN_SECRET=replace-this-with-a-long-random-secret
```

На той машине, где работает сервер (loopback), такие действия обычно проходят и без секрета. По умолчанию запросы, которые передает дальше обратный прокси или туннель на этой машине, считаются удаленными. Если вы сознательно зададите `REQUIRE_AUTH_FOR_LOOPBACK_PROXY=false`, такие пересланные запросы будут считаться локальными, и исключение для loopback, позволяющее обойтись без секрета, будет действовать и для них. Для публичного прокси или туннеля оставьте эту защиту включенной. Прямым запросам с другого устройства секрет по-прежнему нужен. Вставьте то же значение в приложении: **Settings**, затем **Advanced**, затем **Admin Access**. После этого приложение отправляет секрет само.

Связанные настройки особых действий:

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `ADMIN_SECRET` | пусто | Общий секрет, нужный для особых действий с удаленных устройств. |
| `MARINARA_REQUIRE_ADMIN_SECRET_ON_LOOPBACK` | `false` | При значении `true` секрет требуется даже на локальной машине. |
| `UPDATES_APPLY_ENABLED` | `false` | Разрешает браузеру применять обычные обновления в том же канале. Осознанное переключение канала выпуска из браузера на машине сервера работает и без этого флага. Только для установок из Git. |
| `UPDATES_APPLY_DISABLED` | не задано | Полный запрет на применение обновлений на стороне сервера: блокирует любое применение, включая переключение канала через loopback, и имеет приоритет над `UPDATES_APPLY_ENABLED`. Скрипты запуска для разработки и для e2e задают его, чтобы вкладка браузера никогда не смогла переписать рабочую копию для разработки. |
| `UPDATES_ALLOW_REMOTE_APPLY` | `false` | Разрешает удаленному устройству применять обновления при верном секрете. |
| `HAPTICS_ALLOW_REMOTE` | `false` | Разрешает управлять устройствами обратной связи с удаленного устройства при верном секрете. |
| `CUSTOM_TOOL_SCRIPT_ENABLED` | `false` | Включает свои инструменты-сценарии. Держите выключенным для непроверенных или импортированных инструментов. |

## Разрешения для локальных адресов

По умолчанию исходящие запросы к провайдерам, сервисам изображений и вебхукам не могут обращаться к частным или локальным адресам. Это закрывает класс атак под названием SSRF (подделка запроса на стороне сервера), когда запрос обманом направляют на внутренний адрес. Адреса провайдеров на loopback остаются разрешенными, чтобы локальные серверы моделей продолжали работать.

Включайте только тот переключатель, который нужен для вашего сервиса на другой машине в частной сети.

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `PROVIDER_LOCAL_URLS_ENABLED` | `false` | Разрешает адресам провайдеров ИИ обращаться к частным или локальным сетевым адресам. На Android включено по умолчанию. |
| `IMAGE_LOCAL_URLS_ENABLED` | `false` | Разрешает адресам провайдеров изображений обращаться к частным или локальным сетевым адресам. Частные адреса готовых изображений все равно должны точно совпадать с источником настроенного провайдера. |
| `TTS_LOCAL_URLS_ENABLED` | `false` | Разрешает адресам синтеза речи обращаться к частным или локальным сетевым адресам. |
| `STT_LOCAL_URLS_ENABLED` | `false` | Разрешает адресу сервера распознавания речи обращаться к частным или локальным сетевым адресам. Сервер на той же машине работает и без этого. |
| `DEEPLX_LOCAL_URLS_ENABLED` | `false` | Разрешает адресам перевода DeepLX обращаться к частным или локальным сетевым адресам. |
| `WEBHOOK_LOCAL_URLS_ENABLED` | `false` | Разрешает вебхукам своих инструментов обращаться к частным или локальным сетевым адресам. |

О подключении локальной модели читайте в разделе [Подключение локальной модели или модели на своем сервере](connections/local-self-hosted.md).

### Устойчивость

Все настройки по умолчанию выключены и сохраняют прежнее поведение; каждая работает независимо. `STORAGE_CACHE_WINDOWS_BOOT_ID`, `SHUTDOWN_WINDOWS_CONSOLE_SIGNALS` и `SHUTDOWN_FORCE_EXIT_ON_REPEAT` читаются при запуске и требуют перезапуска; остальные применяются к следующему запросу, сохранению или остановке после изменения `.env`. `PROVIDER_RETRY_TRANSIENT_ERRORS` закрепляет **Retry failed provider calls** в Settings > Advanced > Features: заданная переменная выше переключателя, иначе решает он (см. [Переключатели функций](configuration/features.md)).

| Переменная | По умолчанию | Действие |
| --- | --- | --- |
| `PROVIDER_RETRY_TRANSIENT_ERRORS` | `false` | Повторяет отказ/недоступность соединения или ошибку шлюза 502/503 до двух раз с короткой случайной паузой (не более 5 с, даже если шлюз просит больше), только до получения текста. 504 и оборванное соединение не повторяются. Если есть fallback, он пробуется сразу вместо повтора. Тайм-аут соединения считается недоступностью: медленно отказывающий хост может задержать ошибку примерно на 20 с. |
| `STORAGE_SKIP_UNCHANGED_WRITES` | `false` | Пропускает перезапись файла чата или `manifest.json`, если содержимое совпадает с последней записью этого сервера и файл на диске не менялся. Только что восстановленный из `.bak` файл всегда перезаписывается. |
| `STORAGE_YIELDING_SERIALIZE` | `false` | Готовит большие файлы чатов к сохранению короткими порциями, чтобы очень длинный чат не приостанавливал другие запросы и потоки. Записанные байты остаются теми же. |
| `STORAGE_CACHE_WINDOWS_BOOT_ID` | `false` | Только Windows. Запоминает до следующей загрузки ОС проверку времени ее запуска, выполняемую блокировкой хранилища каждый раз (около 1,5–2 с PowerShell), в `.writer-boot-id.json` внутри `DATA_DIR`. |
| `SHUTDOWN_WINDOWS_CONSOLE_SIGNALS` | `false` | Только Windows. Ctrl+Break и закрытие консоли также корректно останавливают сервер с записью ожидающих сохранений, а не завершают сразу. Для закрытия консоли сроки сокращены, чтобы уложиться примерно в 5 с, отведенных Windows. |
| `SHUTDOWN_FORCE_EXIT_ON_REPEAT` | `false` | Повторное Ctrl+C (или Ctrl+Break) более чем через 1,5 с после первого немедленно завершает сервер. Незавершенные сохранения могут потеряться. Без настройки повторы игнорируются и действует обычный предел завершения 8 с. |
| `SHUTDOWN_EARLY_FLUSH` | `false` | Начинает запись ожидающих сохранений сразу при сигнале остановки (Ctrl+C, SIGTERM), пока соединения еще закрываются. Перезапуск через Advanced Settings это не использует. |
| `SHUTDOWN_RUNTIME_STOP_BUDGET_MS` | `0` | Сколько сигнал остановки ждет фоновые среды (пакеты возможностей, расширения, вспомогательный процесс), прежде чем все равно закрыть хранилище. Перезапуск Advanced Settings по-прежнему ждет все среды. `0` ждет все, как раньше. Максимум `2500`, чтобы закрыть хранилище в пределах 8 с. |

| `SIDECAR_RUNTIME_INSTALL_ENABLED` | `false` (скрипт запуска для Windows задает `true`) | Разрешает установку среды локальной модели без заголовка администратора на loopback. |
| `SSL_CERT` | пусто | Путь к сертификату TLS. Смотрите раздел про управление доступом выше. |
| `SSL_KEY` | пусто | Путь к закрытому ключу TLS. Смотрите раздел про управление доступом выше. |

Про ключ Giphy стоит помнить: поиск файлов GIF недоступен, пока вы не задали `GIPHY_API_KEY` и не перезапустили сервер. О встроенной локальной модели читайте в разделе [Настройка модели Local Model](connections/local-model.md).

<a id="outbound-http-proxy"></a>

### Исходящий HTTP-прокси

В некоторых сетях выход в интернет возможен только через HTTP-прокси, например v2rayN без режима TUN. Marinara может отправлять через такой прокси свои запросы к провайдерам ИИ, сервисам изображений, серверам эмбеддингов и каталогу агентов. Задайте эти переменные в окружении, из которого запускается Marinara, или в `.env`, затем перезапустите Marinara.

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `NODE_USE_ENV_PROXY` | не задано | Задайте `1`, чтобы использовать прокси ниже. Без этого Marinara, как и сам Node.js, игнорирует настройки прокси, поэтому прокси, заданный только для других программ, ничего не меняет. |
| `HTTP_PROXY` | пусто | Адрес прокси, например `http://127.0.0.1:10809`. Используется для всех запросов, если не задан `HTTPS_PROXY`. |
| `HTTPS_PROXY` | пусто | Прокси для адресов `https://`, если он отличается от `HTTP_PROXY`. |
| `NO_PROXY` | пусто | Хосты через запятую, которые обходят прокси. Добавьте сюда серверы моделей в вашей локальной сети. `localhost`, `127.0.0.1` и `::1` обходят прокси всегда, поэтому локальные модели продолжают работать. |
