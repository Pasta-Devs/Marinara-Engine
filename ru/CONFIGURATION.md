# Настройки сервера: справочник

Это руководство объясняет, как менять настройки уровня сервера в приложении Marinara Engine через переменные окружения. Переменная окружения – это настройка, которую вы пишете в обычном текстовом файле, а сервер его читает. Большинству эта страница никогда не понадобится. Полный список переменных находится ближе к концу.

## Когда нужно менять настройки

Приложение Marinara Engine работает сразу и без настройки. Эта страница нужна только для нескольких задач. Почти все они связаны с тем, что сервером пользуется больше одного устройства.

Настройки стоит поменять, если вы хотите:

- Открыть доступ к серверу другим устройствам в сети (управление доступом).
- Защитить общий сервер паролем или списком разрешенных IP-адресов.
- Изменить место, где данные хранятся на диске.
- Повысить подробность журнала сервера, чтобы разобраться в проблеме.
- Дать медленным задачам генерации изображений, видео или эмбеддингов больше времени (тайм-ауты).
- Разрешить особые действия с удаленного устройства – например, резервные копии или обновления.

Почти все остальное – ключи провайдеров ИИ, персонажи, параметры чата – настраивается в самом приложении, а не здесь. О добавлении провайдера ИИ читайте в разделе [Подключение к провайдеру ИИ](connections/connecting-to-a-provider.md).

Дополнительные официальные агенты тоже управляются внутри приложения. Откройте **Agents → Download Agents**, чтобы установить или удалить их. Marinara сама выбирает в каталоге [Pasta-Devs/Marinara-Agents](https://github.com/Pasta-Devs/Marinara-Agents) ту ветку, которая соответствует основной версии Engine.

Жизненный цикл пакетов и их хранение:

- **Обновления:** Marinara проверяет, есть ли совместимые обновления для уже установленных официальных пакетов, и спрашивает перед скачиванием каждой новой версии. Ответ **No** оставляет текущую версию, а действие **Update** остается доступным вручную в разделе Download Agents. После свежей установки список пуст, пока вы не выберете пакеты.
- **Платформы:** Поведение одинаково для компьютера, контейнера Docker и установки на Android через Termux. Клиенты на iOS и другие браузерные клиенты используют пакеты, установленные на их сервере Marinara.
- **Хранение:** Пакеты лежат в папке `DATA_DIR/capability-packages`. Тома Docker, свои папки данных, резервные копии и обычные обновления их сохраняют.
- **Работа без сети:** Уже установленные пакеты продолжают работать в своей версии, если исходящий доступ к GitHub по HTTPS недоступен, обновление отклонено или не прошло проверку.

### Импорт своих агентов

Внешние файлы агентов, папки и свои репозитории по умолчанию запрещены. Чтобы их разрешить, откройте **Settings** (настройки) **→ Advanced → Danger Zone** и включите **Allow custom Agent imports**. В отличие от внешних расширений, этот переключатель находится полностью в ваших руках, и переменная окружения ему не нужна. Пока он выключен, элементы импорта остаются неактивными.

Перед сохранением каждый импорт показывает, какие возможности запрашивает агент. Разрешения нужно подтвердить явно; вложенные функции и наборы инструментов не импортируются; сгенерированный код CSS проходит очистку; действия из результата сверяются с одобренным набором возможностей. Если переключатель выключить, импортированные извне агенты перестают работать. Свои агенты, созданные в приложении Marinara, и официальные пакеты из **Download Agents** продолжают работать и от этого переключателя не зависят.

### Свои репозитории агентов

Свои репозитории по умолчанию выключены: их промпты и наборы инструментов – это непроверенный сторонний материал. Задайте `ENABLE_CUSTOM_AGENT_REPOS=true`, включите **Allow custom Agent imports** в разделе Danger Zone, затем откройте **Agents → Download Agents → Custom Sources**, чтобы посмотреть публичный репозиторий GitHub. И добавление источника, и применение любых последующих изменений требуют отдельного подтверждения. Синхронизация только ручная: Marinara не клонирует репозитории и не опрашивает их в фоне.

В корне репозитория должен лежать файл `agents.json` с массивом в том же формате описания агентов, что и у скачиваемых пакетов. Минимальный файл выглядит так:

```json
[
  {
    "id": "continuity-helper",
    "name": "Continuity Helper",
    "description": "Checks recent turns for contradictions.",
    "phase": "post_processing",
    "enabledByDefault": false,
    "category": "writer",
    "defaultPromptTemplate": "Check {{messages}} for continuity errors."
  }
]
```

Marinara принимает только адреса корня репозитория GitHub и проверяет архив ограниченного размера и каждое описание агента, прежде чем показать предварительный просмотр. При синхронизации промпт, настройки и инструменты из репозитория заменяют те значения, которые в этом просмотре помечены как управляемые репозиторием. Выбор подключения и оформления остается локальным. Если агент исчезает в репозитории, Marinara сохраняет его как обычного локального агента и убирает только связь с репозиторием. Удаление источника работает по тому же принципу: локальная копия остается.

### Внешние расширения

Импорт внешних расширений требует двух независимых разрешений. Задайте `ENABLE_EXTERNAL_EXTENSIONS=true` в файле `.env`, затем откройте **Settings → Advanced → Danger Zone**, прокрутите ниже элементов удаления данных, прочитайте предупреждение и включите **Allow third-party extension imports**. Только после этого раздел **External Extensions** появится в **Settings → Addons**.

Переменная окружения – это разрешение от того, кто держит сервер; переключатель в Danger Zone – ваше явное согласие. Раздел, маршруты импорта, маршруты одобрения и оба загрузчика во время работы проверяют оба условия. Закрытие любого из них отключает записи внешних расширений и останавливает выполнение внешнего кода. Записи, добавленные вручную, старые, пришедшие из профиля и с неизвестным источником считаются внешними, поэтому просто положить файлы в папку расширений недостаточно.

Черновики от Professor Mari доступны и без этого флага. Они создаются выключенными, и их точный хеш кода все равно требует одобрения.

По умолчанию расширения работают в режиме Sandboxed Browser Extensions. Часть старых сторонних пакетов помечена как **Full page access** (полный доступ к странице), потому что они зависят от структуры DOM приложения Marinara. В этом режиме одобренный код выполняется прямо на странице Marinara и получает доступ к содержимому страницы, хранилищу браузера, сетевым интерфейсам и текущей сессии того же источника. Режим доступен только для раздела **External Extensions**, когда открыты оба разрешения, и требует отдельного подтверждения предупреждения. Если после расширения остаются изменения внешнего вида или поведения, выключите режим и перезагрузите страницу.

## Где лежит файл .env

Настройки хранятся в файле с именем `.env`. Это обычный текстовый файл: одна настройка в строке, в виде `KEY=value`. Строки, начинающиеся с `#`, – это комментарии, сервер их не читает.

Файл `.env` – это данные, а не сценарий оболочки. Marinara не выполняет `$`, подстановки команд вида `$(...)` и другой синтаксис оболочки внутри значения. Скрипты запуска для macOS/Linux и Termux применяют то же правило без вычислений к небольшому набору настроек, которые нужны им до старта сервера. Значение, уже заданное в окружении скрипта запуска, имеет приоритет над одноименной строкой в `.env`.

Marinara создает пустой файл `.env` при первом запуске, так что вручную его делать не нужно.

- При обычной установке файл `.env` лежит в корневой папке проекта.
- В официальных образах Docker или Podman он находится по пути `/app/data/.env`, в том же томе хранения, где и данные.

Файл `.env.example` в той же папке перечисляет все настройки со значениями по умолчанию. Чтобы поменять настройку, скопируйте строку из `.env.example` в `.env` и отредактируйте значение после знака `=`.

Вот пример файла `.env`, который меняет порт и включает пароль:

```
PORT=8080
BASIC_AUTH_USER=alice
BASIC_AUTH_PASS=correct-horse-battery-staple
```

Сервер читает `.env` сам, независимо от способа запуска. В том числе при прямом вызове `pnpm start`. Скрипты запуска (`start.bat`, `start.sh`, `start-termux.sh`) добавляют две вещи: они задают `HOST=0.0.0.0`, чтобы сервер был доступен другим устройствам, и открывают браузер. При запуске просто через `pnpm start` сервер слушает только этот компьютер, пока вы сами не зададите `HOST`.

## Перезапуск или применение на ходу

Marinara следит за файлом `.env` во время работы. После сохранения изменений большинство настроек применяется примерно за 2 секунды, без перезапуска. Каждый раз сервер пишет в журнал строку, начинающуюся с `[env-watcher]`.

Небольшая группа низкоуровневых настроек фиксируется при старте сервера. Их изменение требует полного перезапуска. Это такие настройки:

- `PORT`, `HOST`
- `SSL_CERT`, `SSL_KEY`
- `DATA_DIR`, `FILE_STORAGE_DIR`
- `ENCRYPTION_KEY`
- `MARINARA_ENV_FILE`
- `TZ`
- `AUTO_OPEN_BROWSER`, `AUTO_UPDATE_ENABLED`, `AUTO_CREATE_DEFAULT_CONNECTION`
- `LOG_DISABLE_REQUEST_LOGGING`
- Настройки тайм-аутов и опроса для изображений, видео, спрайтов и ComfyUI (`IMAGE_GEN_TIMEOUT_MS`, `VIDEO_GEN_TIMEOUT_MS`, `VIDEO_GEN_MAX_RESPONSE_BYTES`, `SPRITE_GENERATION_TIMEOUT_MS`, `SPRITE_ANIMATED_FFMPEG_TIMEOUT_MS`, `COMFYUI_GEN_TIMEOUT` и четыре настройки `*_VIDEO_POLL_INTERVAL_MS`)

При изменении любой из них журнал предупреждает, что нужен перезапуск. Настройки управления доступом и секреты – `BASIC_AUTH_USER`, `BASIC_AUTH_PASS`, `IP_ALLOWLIST`, `ADMIN_SECRET`, `CSRF_TRUSTED_ORIGINS` – перезапуска не требуют.

## Управление доступом

Управление доступом определяет, кому разрешено обращаться к работающему серверу. Этот раздел – краткая справка. Пошаговый разбор с примерами есть в руководстве [Удаленный доступ: Basic Auth и список разрешенных адресов](REMOTE_ACCESS.md).

Несколько терминов, которые встречаются ниже:

- Loopback – это тот же компьютер, на котором работает сервер. Обращаться к нему можно по адресу `127.0.0.1` или `localhost`.
- Диапазон CIDR – короткая запись целого блока IP-адресов, например `192.168.1.0/24`. Сокращение CIDR означает Classless Inter-Domain Routing.
- Диапазоны RFC 1918 – это стандартные частные диапазоны адресов, которые используются в домашних и офисных сетях: например, `10.x.x.x` и `192.168.x.x`.

По умолчанию, когда пароль не задан, сервер принимает подключения только из доверенных источников. Это loopback, любой адрес из `IP_ALLOWLIST`, сеть Tailscale и трафик моста или шлюза Docker с того же хоста. Все остальные, включая обычную домашнюю сеть, получают ответ `403 Forbidden`, пока вы не выберете один из вариантов ниже.

Основные настройки управления доступом:

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `BASIC_AUTH_USER` | пусто | Имя пользователя для запроса пароля. Задайте вместе с `BASIC_AUTH_PASS`, чтобы включить вход. |
| `BASIC_AUTH_PASS` | пусто | Пароль для запроса при входе. Оставьте любое из двух полей пустым, чтобы отключить вход. |
| `BASIC_AUTH_REALM` | `Marinara Engine` | Текст, который браузер показывает в окне запроса пароля. |
| `IP_ALLOWLIST` | пусто | IP-адреса или диапазоны CIDR через запятую, которым доступ разрешен всегда. Loopback разрешен всегда. |
| `IP_ALLOWLIST_ENABLED` | `true` | Значение `false` сохраняет список, но приостанавливает его действие. |
| `ALLOW_UNAUTHENTICATED_PRIVATE_NETWORK` | `false` | Возвращает доступ без пароля из частных сетей, когда вход не настроен. |
| `ALLOW_UNAUTHENTICATED_REMOTE` | `false` | Разрешает доступ без пароля с любого адреса, включая интернет. Не рекомендуется. |
| `TRUSTED_PRIVATE_NETWORKS` | встроенные значения | Заменяет стандартные диапазоны частных сетей. Перечислите и те стандартные, которые хотите оставить. |
| `BYPASS_AUTH_TAILSCALE` | автоматически | Пустое значение доверяет прямому сокету Tailscale, только когда оба его конца используют адреса tailnet. Задайте `true` для прежнего обхода всего диапазона `100.64.0.0/10` или `false`, чтобы требовать обычный контроль доступа. |
| `BYPASS_AUTH_DOCKER` | автоматически | Пустое значение доверяет только определенному интерфейсу контейнера и его точному шлюзу. Задайте `true` для совместимости со старыми или нестандартными сетями либо `false`, чтобы требовать обычный контроль доступа. |
| `REQUIRE_AUTH_FOR_DOCKER_PROXY` | `true` | Требует обычной проверки входа и списка разрешенных адресов для трафика Docker, пришедшего через прокси. Ставьте `false`, только если все клиенты выше по цепочке доверенные. |
| `TRUSTED_HOSTS` | пусто | Дополнительные публичные имена или имена обратного прокси, на которые Marinara может отвечать. Прямой IP-адрес, localhost, `.local`, `.home.arpa` и однословные локальные имена работают сами. |
| `SSL_CERT` | пусто | Путь к файлу сертификата TLS. Задайте вместе с `SSL_KEY`, чтобы сервер сам работал по HTTPS. |
| `SSL_KEY` | пусто | Путь к файлу закрытого ключа TLS. |
| `CSRF_TRUSTED_ORIGINS` | пусто | Дополнительные браузерные источники, которым разрешено сохранять изменения. Нужно для публичного домена или нестандартного порта. Буквальное значение `null` игнорируется, и его нельзя использовать для APK на Android; маршруты входа с собственной аутентификацией работают без глобального доверия непрозрачному источнику. |

Basic Auth – это сокращение от HTTP Basic Authentication, простого запроса имени пользователя и пароля. Эти данные только кодируются, но не шифруются, поэтому всегда сочетайте их с HTTPS, если сервер доступен из интернета. HTTPS – это защищенная, зашифрованная версия HTTP. Чтобы включить его напрямую, задайте `SSL_CERT` и `SSL_KEY` вместе, либо поставьте перед Marinara обратный прокси.

Чтобы другие устройства вообще могли обратиться к серверу, он должен слушать доступный сетевой интерфейс. Задайте `HOST=0.0.0.0`. Скрипты запуска делают это сами, а `pnpm start` слушает только loopback.

Телефоны, планшеты, узлы Tailscale и другие компьютеры могут и дальше подключаться по IP-адресу сервера, и добавлять его в `TRUSTED_HOSTS` не нужно. Если вы публикуете Marinara под публичным именем или именем обратного прокси, добавьте это имя точно, например `TRUSTED_HOSTS=chat.example.com`. Имена, уже перечисленные в `CSRF_TRUSTED_ORIGINS` или `CORS_ORIGINS`, тоже принимаются – для совместимости. Такая проверка имени хоста не дает подменить имя DNS публичного сайта на адрес loopback, где работает Marinara.

## Хранение данных

Настройки хранения задают, где лежат локальные данные. К данным относятся чаты, персонажи, аватары и сгенерированные медиафайлы.

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `DATA_DIR` | `packages/server/data` | Корневая папка всех пользовательских данных. В образах Docker задан путь `/app/data`. |
| `FILE_STORAGE_DIR` | папка `storage` внутри `DATA_DIR` | Переопределяет папку хранения файлов. |
| `ENCRYPTION_KEY` | пусто | Ключ для шифрования сохраненных ключей API. Сгенерируйте его командой ниже. |

Marinara хранит данные в обычных файлах JSON. Так резервные копии проще копировать и просматривать.

Чтобы сгенерировать ключ шифрования, выполните эту команду и вставьте результат в `ENCRYPTION_KEY`:

```
openssl rand -hex 32
```

О том, что лежит в каждой папке данных, читайте в разделе [Где Marinara хранит ваши данные](data/where-data-is-stored.md).

## Уровни логирования

Логирование определяет, насколько подробно сервер пишет в консоль. Основная настройка – `LOG_LEVEL`. Все, что ниже выбранного уровня, сервер скрывает.

| Уровень | Что показывает |
| --- | --- |
| `error` | Только серьезные, неустранимые сбои. |
| `warn` | Ошибки и некритичные предупреждения. Это значение по умолчанию. |
| `info` | Предупреждения, а также записи о старте и о каждом запросе. |
| `debug` | Все, включая полные промпты и ответы модели. Очень подробно. |

Что стоит выбрать:

- Для обычной работы оставьте `warn`. Этот уровень тихий и показывает только реальные проблемы.
- Уровень `info` подойдет, если хочется видеть запросы и основные события, но без потока сообщений.
- Уровень `debug` нужен, когда важно увидеть точный промпт, отправленный модели, и ответ. Вывода будет много.

Чтобы видеть подробности про промпты и подключения без обычных записей о запросах, задайте не уровень, а пресет:

```
LOG_PRESET=prompt-connections
```

Этот пресет показывает те же подробности про промпты и модель, что и `debug`, но скрывает повторяющиеся строки запросов вида `GET /api/chats`. Чтобы убрать только эти рутинные строки, сохранив текущий уровень, задайте настройку ниже и перезапустите сервер:

```
LOG_DISABLE_REQUEST_LOGGING=true
```

Логирование в браузере работает отдельно, и `LOG_LEVEL` на него не влияет.

## Тайм-ауты

Тайм-аут – это максимальное время, которое сервер ждет медленную задачу, прежде чем прекратить попытку. Медиазадачи вроде генерации изображений и видео бывают долгими, поэтому их тайм-ауты по умолчанию щедрые. Все значения тайм-аутов указаны в миллисекундах, если в названии не сказано иначе.

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `CHAT_GENERATION_TIMEOUT_MS` | `300000` (5 минут) | Тайм-аут на заголовки провайдера, на первый токен и на промежутки между частями ответа для обычных генераций в режимах Conversation, Roleplay и Game, а также лимит на первый байт для фоновых генераций без своего тайм-аута (обновление ленты Noodle, ответы Noodler). Допустимый диапазон: `10000`-`3600000`. Тайм-ауты агентов, медиа, эмбеддингов и инструментов эта настройка не меняет. |
| `AGENT_CALL_TIMEOUT_MS` | `300000` (5 минут) | Ограничение общей длительности одного обращения агента к модели (трекеры, переформатирование HTML и другие агенты); действует и во время стриминга ответа. Повысьте его для медленных локальных моделей, которым нужно больше 5 минут на один проход агента. Допустимый диапазон: `10000`-`3600000`. У агента Illustrator сохраняется собственный лимит не меньше 30 минут. |
| `GAME_DYNAMIC_IMAGE_PROMPT_TIMEOUT_MS` | `45000` (45 секунд) | Ограничение общей длительности обращения к модели, которое превращает текущую сцену режима Game в динамический промпт для изображения. Повысьте его для более медленных локальных моделей. Допустимый диапазон: `10000`-`3600000`. |
| `EMBEDDING_TIMEOUT_MS` | `300000` (5 минут) | Время на один запрос эмбеддинга. Значение побольше помогает медленным локальным серверам эмбеддингов. |
| `IMAGE_GEN_TIMEOUT_MS` | `1800000` (30 минут) | Время на один запрос генерации изображения. |
| `VIDEO_GEN_TIMEOUT_MS` | `1800000` (30 минут) | Время на один запрос генерации видео сцены, включая локальные процессы видео в ComfyUI. |
| `VIDEO_GEN_MAX_RESPONSE_BYTES` | `167772160` (160 MiB) | Максимальный размер видео сцены, которое сервер согласится скачать. |
| `COMFYUI_GEN_TIMEOUT` | `2400` (40 минут, в секундах) | Время на один процесс изображения в ComfyUI после постановки в очередь. |
| `SPRITE_GENERATION_TIMEOUT_MS` | берется из `IMAGE_GEN_TIMEOUT_MS` | Время на одну задачу генерации спрайта средствами ИИ. |
| `CUSTOM_TOOL_TIMEOUT_MS` | `60000` (1 минута) | Время на один вызов своего инструмента. |
| `MAX_TOOL_ROUNDS` | `100` | Сколько кругов вызова инструментов допустимо, прежде чем модель обязана дать окончательный ответ. |

Тайм-ауты изображений, видео, спрайтов и ComfyUI фиксируются при старте, поэтому их изменение требует перезапуска. Тайм-ауты генерации чата, агентов, динамического промпта изображения в режиме Game, эмбеддингов и своих инструментов применяются к следующему запросу или проходу агента, без перезапуска. Недопустимые, нулевые, отрицательные или выходящие за диапазон значения для проверяемых тайм-аутов чата, агентов и динамического промпта изображения в режиме Game вызывают предупреждение в журнале, а сервер безопасно берет описанные значения по умолчанию. Повышайте медиатайм-аут, если крупные или высококачественные задачи срываются на середине. Подробнее о задачах видео – в разделе [Генерация видео сцены](media/scene-video.md).

## Особые действия по API (ADMIN_SECRET)

Некоторые действия разрушительны или рискованны, поэтому им нужен отдельный секрет вдобавок к обычным проверкам доступа. Это, например, резервные копии, очистка данных, применение обновлений и установка тем оформления.

Задайте на сервере длинное случайное значение `ADMIN_SECRET`:

```
ADMIN_SECRET=replace-this-with-a-long-random-secret
```

На той машине, где работает сервер (loopback), такие действия обычно проходят и без секрета. С другого устройства приложение обязано его отправить. Вставьте то же значение в приложении: **Settings**, затем **Advanced**, затем **Admin Access**. После этого приложение отправляет секрет само.

Связанные настройки особых действий:

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `ADMIN_SECRET` | пусто | Общий секрет, нужный для особых действий с удаленных устройств. |
| `MARINARA_REQUIRE_ADMIN_SECRET_ON_LOOPBACK` | `false` | При значении `true` секрет требуется даже на локальной машине. |
| `UPDATES_APPLY_ENABLED` | `false` | Разрешает браузеру применять обычные обновления в том же канале. Осознанное переключение канала выпуска из браузера на машине сервера работает и без этого флага. Только для установок из Git. |
| `UPDATES_ALLOW_REMOTE_APPLY` | `false` | Разрешает удаленному устройству применять обновления при верном секрете. |
| `HAPTICS_ALLOW_REMOTE` | `false` | Разрешает управлять устройствами обратной связи с удаленного устройства при верном секрете. |
| `CUSTOM_TOOL_SCRIPT_ENABLED` | `false` | Включает свои инструменты-сценарии. Держите выключенным для непроверенных или импортированных инструментов. |
| `ENABLE_CUSTOM_AGENT_REPOS` | `false` | Включает ручной просмотр и синхронизацию репозиториев агентов с GitHub в разделе Agents Manager. Сторонние агенты не проверены и требуют явного подтверждения перед импортом или обновлением. |
| `ENABLE_EXTERNAL_EXTENSIONS` | `false` | Первое из двух разрешений на импорт сторонних расширений. Второе нужно включить самостоятельно в Settings → Advanced → Danger Zone. |
| `IMPORT_ALLOWED_ROOTS` | пусто | Папки, из которых массовый импорт может читать без токена выбора файлов. |
| `PROFILE_EXPORT_JSON_LIMIT_BYTES` | `268435456` (256 MiB) | Максимальный размер одного экспорта профиля в JSON, который сервер соберет. |

Если `ADMIN_SECRET` на сервере не задан, особые действия не выполняются ни с одного устройства, кроме локальной машины. Сообщение об ошибке предлагает задать секрет и вставить его в **Admin Access**.

## Разрешения для локальных адресов

По умолчанию исходящие запросы к провайдерам, сервисам изображений и вебхукам не могут обращаться к частным или локальным адресам. Это закрывает класс атак под названием SSRF (подделка запроса на стороне сервера), когда запрос обманом направляют на внутренний адрес. Адреса провайдеров на loopback остаются разрешенными, чтобы локальные серверы моделей продолжали работать.

Включайте только тот переключатель, который нужен для вашего сервиса на другой машине в частной сети.

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `PROVIDER_LOCAL_URLS_ENABLED` | `false` | Разрешает адресам провайдеров ИИ обращаться к частным или локальным сетевым адресам. На Android включено по умолчанию. |
| `IMAGE_LOCAL_URLS_ENABLED` | `false` | Разрешает адресам провайдеров изображений обращаться к частным или локальным сетевым адресам. Частные адреса готовых изображений все равно должны точно совпадать с источником настроенного провайдера. |
| `TTS_LOCAL_URLS_ENABLED` | `false` | Разрешает адресам синтеза речи обращаться к частным или локальным сетевым адресам. |
| `DEEPLX_LOCAL_URLS_ENABLED` | `false` | Разрешает адресам перевода DeepLX обращаться к частным или локальным сетевым адресам. |
| `WEBHOOK_LOCAL_URLS_ENABLED` | `false` | Разрешает вебхукам своих инструментов обращаться к частным или локальным сетевым адресам. |

О подключении локальной модели читайте в разделе [Подключение локальной модели или модели на своем сервере](connections/local-self-hosted.md).

## Полный справочник переменных окружения

В этом разделе собраны остальные настройки, сгруппированные по назначению. Таблицы выше уже описали управление доступом, хранение данных, логирование, тайм-ауты, особые действия и разрешения для локальных адресов.

### Сервер и запуск

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `PORT` | `7860` | Порт, который слушает сервер. На Android, в Docker и в Termux держите одно и то же значение. |
| `HOST` | `127.0.0.1` (`0.0.0.0` в скриптах запуска) | Сетевой интерфейс для прослушивания. Для доступа из локальной сети используйте `0.0.0.0`. |
| `MARINARA_ANDROID_SECRET` | пусто | Внутренний секрет локальной аутентификации для установок Termux под управлением APK. Это не поле установщика: оболочка Android сама создает и передает секрет, а скрипт запуска Termux автоматически экспортирует его. Не просите пользователей APK вводить его и не задавайте его для обычных настольных и ручных установок Termux. Если значение задано, оно должно состоять ровно из 64 шестнадцатеричных символов. Неправильное непустое значение приводит к ответу HTTP 503 на локальные запросы устройства, а не ослабляет аутентификацию. |
| `MARINARA_ANDROID_SECRET_FILE` | `~/.marinara-engine/android-secret` | Путь к закрытому файлу секрета, который используют скрипт запуска Termux и локальная CLI `mari`. APK и скрипт запуска управляют этим файлом автоматически; обычным пользователям APK не нужно читать или копировать его. |
| `AUTO_OPEN_BROWSER` | `true` | Открывать ли адрес приложения в браузере при запуске через скрипты. Значение `false` это отключает. Настройка под управлением APK запрещает автоматическое открытие браузера при своем запуске, чтобы подключилось уже аутентифицированное приложение Android. |
| `AUTO_UPDATE_ENABLED` | `true` | Скачивают и применяют ли скрипты запуска для Windows, macOS/Linux и Termux обновления Engine до старта (для установок из Git). Значение `false` отключает это навсегда и действует со следующего запуска. Скрипт все равно выполняет проверку без изменений и напоминает о скачивании, если вышел новый выпуск; при этом ручные проверки, применение обновлений в приложении, обновления пакетов и обновления моделей остаются доступны. Ключ `--skip-update` пропускает обе проверки для одного запуска. |
| `MARINARA_ENV_FILE` | `.env` в корне проекта | Необязательный другой путь к файлу `.env`. Задайте его до запуска. |
| `TZ` | системный | Резервный часовой пояс хоста для серверных задач. Расписания в режиме Conversation используют общий часовой пояс, выбранный в их настройках расписания, если он сохранен. Оставьте `TZ` незаданным, чтобы взять часовой пояс хоста; пустое `TZ=` тоже считается незаданным. |
| `CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | Браузерные источники, которым разрешены межсайтовые запросы. |
| `AUTO_CREATE_DEFAULT_CONNECTION` | `true` | Устаревший флаг. Текущие сборки не включают стартовый ключ, поэтому он ничего не создает. Добавьте свое подключение в приложении. |

Флаг `AUTO_CREATE_DEFAULT_CONNECTION` оставлен только для старых установок. Новые сборки больше не поставляются со встроенным стартовым подключением, поэтому включенное значение ничего не делает. Чтобы начать общение, добавьте подключение по инструкции [Подключение к провайдеру ИИ](connections/connecting-to-a-provider.md).

Настройки расписания в режиме Conversation по умолчанию берут часовой пояс, о котором сообщает браузер или устройство с приложением. Пояс **Schedule timezone** можно поменять при настройке режима Conversation, в панели Chat Settings этого режима или в редакторе расписания персонажа. Выбранный часовой пояс IANA – это один общий параметр для всех чатов Conversation, и он синхронизируется с другими клиентами Marinara, подключенными к тому же серверу.
