# Групповые чаты в режимах Conversation и Roleplay

Групповой чат – это любой чат Conversation или Roleplay, в котором два персонажа или больше. В этом руководстве показано, как создать такой чат, управлять его участниками и выбирать, кто говорит. У Game Mode своя система отряда, и здесь она не рассматривается.

Отдельной кнопки "групповой чат" нет. Чат становится групповым, когда вы добавляете второго персонажа. Групповой чат – это не **Folder** (папка, то есть сохраненный список персонажей, который можно использовать снова) и не **Chat Branch** (ветка чата, то есть альтернативная версия одного чата).

## Создание группового чата

1. В панели **Chats** (чаты) нажмите кнопку **+** для нужного режима (**New Conversation** или **New Roleplay**).
2. Откроется мастер настройки. На шаге **Persona & Characters** (персона и персонажи) введите текст в поле **Search characters...** и нажмите на персонажа, чтобы добавить его.
3. Точно так же добавьте второго персонажа.
4. Завершите мастер, чтобы открыть чат.

Подпись над списком выбора меняется. В Conversation на ней написано **Group Chat** (групповой чат) и число участников. В Roleplay – **Characters** (персонажи) и число. Если не переименовать чат, Marinara называет его по именам персонажей, например "Alice, Bob, Carol".

Жесткого предела на число персонажей нет. Чем больше персонажей, тем длиннее промпт и тем дороже каждый ответ, поэтому добавляйте только тех персонажей, которые нужны сцене.

Чтобы добавить сразу целую папку, на том же шаге откройте **Add from Folder** (добавить из папки), выберите папку и нажмите **Add** (добавить). Персонажи, которые уже есть в чате, пропускаются. Этот элемент появляется, только если у вас есть хотя бы одна папка. См. [Порядок в библиотеке персонажей](../characters/library-organization.md). Строка **Random** (с подписью **Dice pick**) добавляет одного случайного персонажа из тех, кого в чате еще нет.

## Управление участниками

Откройте **Chat Settings** (настройки чата) и найдите раздел **Characters**. В Game Mode его нет. В строке каждого участника есть аватар, имя, ручка для перетаскивания, иконка глаза и иконка корзины.

| Что нужно сделать | Как это сделать |
| --- | --- |
| Добавить персонажа | Нажмите **Add Character** (добавить персонажа) и найдите его поиском. |
| Добавить папку | Нажмите **Add Character**, затем **Add all** (добавить всех) в строке папки. |
| Изменить сразу нескольких | Нажмите **Add Character**. Участники, которые уже есть в чате, отмечены. Нажмите имя, чтобы добавить или убрать персонажа. |
| Открыть полную карточку участника | Нажмите имя участника (**Open character card**, открыть карточку персонажа). Панель **Chat Settings** закроется, и откроется карточка. |
| Убрать персонажа | Нажмите иконку корзины (**Remove from chat**, убрать из чата). |
| Изменить порядок | Перетащите ручку (**Drag to reorder**, перетащите, чтобы изменить порядок). При порядке **Sequential** (по очереди) персонажи отвечают в этом порядке. |
| Временно выключить | Нажмите глаз (**Disable in chat**, выключить в чате). Нажмите еще раз, чтобы включить (**Enable in chat**, включить в чате). |

Выключенный персонаж остается в списке, но не участвует ни в одном ответе. Его карточка не отправляется модели, и его нельзя выбрать говорящим. Если выключить всех персонажей, Marinara считает активными их всех, чтобы ответ никогда не оказался пустым. Это состояние сохраняется для каждого чата отдельно и больше ни на что не влияет. В группе Roleplay в режиме Merged его может задавать за вас [автоматизация активных персонажей](#automate-active-characters-merged-only).

## Выбор говорящего

Откройте **Chat Settings → Group Chat**. Этот раздел появляется, только когда в чате два персонажа или больше. В обоих режимах используется один и тот же переключатель **Mode** (режим).

- Один ответ говорит за всех персонажей. В Roleplay это **Merged (Narrator)** (объединенный, с рассказчиком), в Conversation – **Grouped** (групповой). Этот вариант стоит по умолчанию. В Roleplay рассказчик – это голос, который описывает сцену, и он входит в тот же ответ.
- **Individual** (по отдельности) дает каждому персонажу собственный ответ.

В Conversation при переключении на **Individual** появляется предупреждение **Individual replies can use many tokens**. Каждый отвечающий персонаж использует отдельный запрос к модели, а большие группы с Autonomous Messaging быстро расходуют токены.

### Automate active characters (Roleplay, только Merged)

Эта настройка включает и выключает персонажей за вас, когда состав большой. См. [Automate active characters](#automate-active-characters-merged-only) в конце этого руководства.

### Color Dialogues (Roleplay, только Merged)

**Color Dialogues** (цветные реплики) по умолчанию выключена. Когда настройка включена, реплики каждого персонажа показываются в его собственных цветах с вкладки **Colors** (цвета) редактора персонажа. В группе Conversation реплики раскрашиваются по говорящему автоматически, и переключателя нет.

<a id="response-order-individual-only"></a>

### Response Order (только для Individual)

Когда **Mode** стоит на **Individual**, появляется **Response Order** (порядок ответов). По умолчанию стоит **Sequential**.

| Порядок | Что происходит |
| --- | --- |
| **Sequential** | Персонажи отвечают по очереди, в порядке списка **Characters**. В Conversation персонажи не в сети пропускаются. |
| **Smart** | Короткий скрытый вызов модели выбирает, кто отвечает следующим, обычно одного персонажа. Упоминание `@Alice` в вашем сообщении отменяет этот выбор. В Conversation он учитывает ход разговора, статус по расписанию и разговорчивость. |
| **Manual** | Никто не отвечает сам. В Roleplay используйте список **Trigger Response** (вызвать ответ). В Conversation упомяните через `@mention` одного или нескольких персонажей или используйте этот список. |

При порядке **Smart** модель может выстроить в очередь несколько персонажей. Сразу отвечает только первый. Чтобы получить ответ следующего персонажа из очереди, используйте список **Trigger Response** или отправьте пустое сообщение.

Если вы выбрали [модель решений](../connections/decision-models.md), под ней можно включить **Also use it to pick who speaks in Smart response order** (выбирать также говорящего в порядке Smart). Тогда порядок Smart запрашивает оценку "да или нет" для каждого кандидата.

- Все вопросы получают одни и те же последние пять сообщений и список кандидатов с именем, статусом, активностью, разговорчивостью и коротким фрагментом личности каждого. Удаленный сервис тоже получает этот список. См. [Что видит модель](../connections/decision-models.md#what-the-model-sees).
- Скорость и стоимость зависят от модели и числа кандидатов.
- В Roleplay Marinara выбирает наиболее вероятного говорящего. В Conversation отвечает каждый, у кого есть причина ответить, начиная с наиболее вероятного. Персонаж, который только что говорил, ждет, если у кого-то другого есть причина ответить.
- Если модель решений не дает ответа, порядок Smart делает свой обычный вызов модели.

В Roleplay в режиме **Individual** с порядком **Smart** или **Manual** первым пунктом списка выбора будет **Smart** со значком людей. Он просит модель выбрать следующего говорящего для одного этого ответа. Сохраненный порядок не меняется.

### Вызов ответа вручную

Чтобы выбрать говорящего, используйте список **Trigger Response**. На компьютере это кнопка рядом с **Send** (отправить) с подписью **Trigger character response** (вызвать ответ персонажа). На телефоне он находится под заголовком **Trigger Response** в панели инструментов, которая открывается из строки сообщения. Чтобы назвать говорящего в тексте, введите `@` и имя персонажа. Появится список автодополнения.

### Другие настройки Individual

- **Add Turn To Prompt** по умолчанию включен. Он добавляет короткую инструкцию с именем персонажа, который должен ответить.
- **Name Prefix History** (только Roleplay) по умолчанию выключен. Он меняет то, как прошлые сообщения подписываются именами говорящих. Оставьте его выключенным, если только персонаж не путает постоянно, кто что сказал.

### Scenario Override (Roleplay)

**Scenario Override** (общий сценарий) задает всей группе единый сценарий. Текст в поле заменяет в промпте собственный сценарий каждого персонажа. Если поле пустое, сценарии остаются как есть. Отдельного переключателя нет. Чтобы редактировать в большом окне, нажмите иконку разворачивания (**Expand editor**, развернуть редактор; окно называется **Group Scenario Override**). Этот текст остается в одном чате и не попадает в профили настроек.

### Character Exchanges (Conversation)

Включите **Character Exchanges** (общение персонажей друг с другом) в **Chat Settings → Autonomous Messaging**, чтобы персонажи разговаривали друг с другом, пока вас нет. По умолчанию настройка выключена и появляется только в групповом чате. Она работает, только пока приложение Marinara открыто в браузере, и делит дневной лимит сообщений с автономными сообщениями. Она работает как с расписаниями персонажей, так и без них. В группе **Individual** такое общение и ответы на упоминания `@mention` никогда не расходуют последнее за день обращение группы.

## Настройки и значения по умолчанию

| Настройка | Где | По умолчанию |
| --- | --- | --- |
| **Mode** | раздел Group Chat | **Merged (Narrator)** в Roleplay, **Grouped** в Conversation |
| **Color Dialogues** | Roleplay, Merged | выключено |
| **Automate active characters** | Roleplay, Merged | выключено |
| **Response Order** | Individual | Sequential |
| **Add Turn To Prompt** | Individual | включено |
| **Name Prefix History** | Roleplay, Individual | выключено |
| **Scenario Override** | Roleplay | пусто |
| **Character Exchanges** | Conversation, Autonomous Messaging | выключено |

Профили настроек сохраняют эти настройки, кроме **Scenario Override** и закреплений автоматизации. См. [Профили настроек](settings-profiles.md).

## Справочник

<a id="automate-active-characters-merged-only"></a>

### Automate active characters (только для Merged)

В режиме Merged карточка каждого активного персонажа попадает в промпт при каждом ответе. В Roleplay **Automate active characters** (автоматизировать активных персонажей) может включать и выключать карточки за вас, чтобы большой состав не заполнял контекст. У настройки три варианта, по умолчанию стоит **Off** (выключено).

| Вариант | Что делает |
| --- | --- |
| **Off** | Вы сами выбираете, кто активен, переключателями с глазом. |
| **Decision model** | Перед каждым ответом ваша [модель решений](../connections/decision-models.md) отвечает на один вопрос "да или нет" по каждому персонажу: находится ли персонаж в сцене, которую продолжает ответ, или входит в нее? Персонаж, которого только упоминают или вспоминают, остается выключенным. |
| **Character Tracker** | Кто активен, определяют персонажи, которых [Character Tracker](../agents/built-in-agents.md#character-tracker) отметил присутствующими в последнем ответе. Дополнительный вызов модели не нужен, но выбор отстает на один ход: персонаж, который входит сейчас, включается к следующему ответу. |

Подсказка под настройкой сообщает, когда чего-то не хватает: не выбрана модель решений, Character Tracker выключен в этом чате или трекер запускается вручную и меняет список только после того, как вы его запустите.

- **Закрепления.** Пока автоматизация включена, в каждой строке персонажа слева от глаза есть значок закрепления. Нажмите его, чтобы закрепить персонажа в нынешнем состоянии, включенным или выключенным, и автоматизация не будет его трогать. Переключение глаза вручную тоже закрепляет персонажа. Нажмите значок еще раз, чтобы открепить. Если перевести автоматизацию в **Off**, все закрепления снимаются.
- **Рассказчик остается активным.** Назначенный рассказчик (Narrator) никогда не выключается.
- **Нет ответа – список сохраняется.** В режиме **Decision model**, если модель не дает ответа, используется последняя сцена Character Tracker, если она есть. Это касается и модели, которая сначала думает, если не включено **Also gate agents that run before the reply** (проверять также агентов до ответа), и состава, слишком большого для входных данных модели решений. Если ответа нет ни от одного из них, список остается как есть.
- **Результат без активных персонажей игнорируется.** Результат, при котором выключились бы все, не применяется.
- **Агент Character Activity главнее.** В чате с пользовательским агентом, у которого тип результата **Character Activity**, управление остается за этим агентом.

Character Tracker записывает для каждого персонажа собственное имя. Marinara сопоставляет его с карточкой сначала по id карточки, затем по имени, затем по псевдонимам имени на вкладке **Colors**. Если в списке трекера нет ни одного персонажа чата, текущий список сохраняется. Автоматизация запускается перед каждым ответом, свайпом и повторной генерацией, а для **Continue** (продолжить) и Impersonate пропускается. Настройка сохраняется в профилях настроек. Закрепления остаются в одном чате.
