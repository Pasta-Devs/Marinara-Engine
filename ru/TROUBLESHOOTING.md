# Устранение неполадок в приложении Marinara Engine

Здесь собраны частые проблемы приложения Marinara Engine и способы их решения. Найдите раздел, который совпадает с вашими симптомами, и выполните шаги по порядку. Если ничего не помогло, откройте последний раздел, Как получить помощь.

## Что попробовать в первую очередь

Многие проблемы снимаются двумя быстрыми действиями.

1. Обновите страницу принудительно. Нажмите **Ctrl+Shift+R** в Windows или Linux, либо **Cmd+Shift+R** на Mac.
2. Посмотрите в консоль сервера – это окно терминала, в котором запущена Marinara – и найдите красные строки с ошибками. Обычно они прямо называют настоящую причину.

Если вы собираетесь обратиться за помощью к команде, сначала включите режим **Debug mode** (режим отладки), чтобы сервер записал промпт и ответ. Промпт – это текст, который Marinara отправляет ИИ. Подробности в разделе Как получить помощь в конце руководства.

## Проблемы установки и запуска

### Windows: ошибка EPERM или проверки подписи corepack при установке pnpm

pnpm – это менеджер пакетов, с помощью которого Marinara устанавливает свой код. Сообщение `EPERM: operation not permitted` или сбой проверки подписи corepack означает, что corepack не смог записать файлы в папку установки Node.

Выберите один из способов:

1. Нажмите правой кнопкой мыши на терминал, выберите Run as administrator, затем запустите скрипт запуска снова.
2. Установите pnpm самостоятельно. Выполните команду, затем запустите скрипт запуска снова:

```bash
npm install -g pnpm
```

3. Обновите corepack в терминале с правами администратора, затем запустите скрипт запуска снова:

```bash
npm install -g corepack
```

### Windows: `'pnpm' is not recognized` при сборке общего пакета

Marinara v2.3.0 успешно запускала pnpm через Corepack, а затем падала на сборке общего пакета, потому что эта сборка пыталась вызвать второй, глобальный исполняемый файл `pnpm`. В v2.3.1 такой вложенный вызов убран. Закройте окно неудачного запуска и запустите `start.bat` снова, чтобы получить исправленный скрипт сборки перед новой сборкой. Данные удалять не нужно.

Если сама рабочая копия не обновляется, выполните `git pull` в папке Marinara и запустите приложение снова. Как временное решение для v2.3.0 установите закрепленную версию менеджера пакетов глобально, повторите запуск, а затем обновитесь обычным способом:

```bash
npm install -g pnpm@10.33.2
```

### Обновление программы запуска до pnpm 10.34.5

В Marinara v2.4.1 закрепленный менеджер пакетов обновлен до pnpm 10.34.5. Существующая программа запуска с версией 10.33.2 может завершить эту разовую передачу управления в том же запуске; после этого обновленная программа будет выбирать 10.34.5 при следующих стартах. Corepack проверяет выпуск по дайджесту SHA-512, закрепленному в `package.json`, а резервный путь через npm также запрашивает строго 10.34.5, а не незакрепленную latest-версию.

Если предыдущая staging-сборка v2.4.1 уже остановилась с сообщениями `Expected version: >=10.34.5` и `Got: 10.33.2`, запустите программу еще раз: перед остановкой эта сборка скачала ее обновленную версию. Если программа по-прежнему не может автоматически получить закрепленный выпуск, установите точную версию и повторите запуск:

```bash
npm install -g pnpm@10.34.5
```

### Linux: ERR_PNPM_ENAMETOOLONG при установке

Это значит, что от предыдущей установки остались слишком длинные пути к папкам. Из папки Marinara удалите незавершенную установку и запустите скрипт запуска снова:

```bash
rm -rf node_modules .pnpm .pnpm-store
```

Затем запустите Marinara командой `./start.sh`. При установке вручную выполните `pnpm install` после удаления этих папок.

### ERR_PNPM_TRUST_DOWNGRADE при установке

Почти всегда причина в незавершенной установке. Сначала запустите скрипт запуска снова, чтобы он восстановил рабочую область. При установке вручную выполните из папки Marinara одну команду:

```bash
pnpm --config.trustPolicy=off --config.confirmModulesPurge=false install --frozen-lockfile
```

## Пустой экран или старый вид приложения

Бывает, что сервер работает, но браузер показывает пустую страницу, либо приложение после обновления выглядит как прежняя версия. Значит, браузер держит в кеше старую копию веб-приложения.

1. Обновите страницу принудительно (**Ctrl+Shift+R** или **Cmd+Shift+R**).
2. Если это не помогло, откройте панель **Settings** (настройки), перейдите на вкладку **Advanced**, найдите раздел **Updates** и нажмите кнопку **Refresh App**.

Кнопка **Refresh App** очищает service worker браузера – фоновый скрипт, который кеширует веб-приложение – и кеш браузера, а затем перезагружает страницу. Данные при этом не меняются. Чаты, настройки и остальные локальные данные остаются на месте. Код сервера тоже не обновляется, так что настоящее обновление это не заменяет. Само приложение обновляется по инструкции [Обновление приложения Marinara Engine](UPGRADING.md).

## Проблемы со скачиваемыми агентами

Если в разделе **Agents → Download Agents** написано, что каталог недоступен, значит доступ к официальному каталогу [Pasta-Devs/Marinara-Agents](https://github.com/Pasta-Devs/Marinara-Agents) по HTTPS через GitHub нужен именно машине с сервером Marinara, а не только браузеру. Уже установленные агенты продолжают работать без сети в своей текущей версии. Восстановите подключение сервера, затем нажмите кнопку **Refresh** или **Try again**, чтобы просмотреть каталог и проверить обновления.

Если установленная карта или звонок не появляются, полностью закройте Marinara Engine и запустите заново. Такие пакеты добавляют свои маршруты и остаются в состоянии **Restart required** до следующего запуска процесса. С играми для режима Conversation иначе: текущие сборки Engine включают их сразу. Если установка не удалась, обновите каталог и убедитесь, что игра отмечена как готовая. Добавлять ее в настройках **Commands** конкретного чата нужно только тогда, когда вы хотите, чтобы персонажи начинали игру сами; для ручной слеш-команды игры это не требуется.

Если на старой установке не проходит первая миграция пакетов, не удаляйте папку `data/capability-packages` и данные чатов. Marinara оставляет миграцию незавершенной и повторяет ее при следующем запуске. Пока каталог недоступен, выбранные ранее пакеты и настройки остаются сохраненными.

Marinara отклоняет скачивание пакета, если его контрольная сумма, заявленный список файлов, диапазон версий Engine или пути внутри архива не совпадают с официальным каталогом. Сначала обновите Marinara Engine, обновите каталог и повторите. Не распаковывайте пакет в папку данных вручную.

Обновления агентов никогда не применяются при запуске. Когда доступна более новая совместимая версия, Marinara спрашивает, применять ли ее. Ответ **No** оставляет установленную версию; кнопка **Update** остается доступной в разделе **Agents → Download Agents**. После неудачного обновления установленная версия тоже остается зарегистрированной, а только что обновленная среда выполнения сервера, не прошедшая самопроверку при старте, откатывается к прежней версии.

## Доступ к Marinara с другого устройства

Если Marinara не открывается с телефона, планшета или другого компьютера в вашей сети, пройдите по этим проверкам.

- Привяжите сервер к доступному адресу. По умолчанию сервер слушает `127.0.0.1` – это loopback, то есть только ваша машина. Скрипты запуска сами выставляют `HOST=0.0.0.0`. Если вы запускали `pnpm start` вручную, сначала укажите `HOST=0.0.0.0` в файле `.env`.
- Проверьте, что оба устройства в одной сети Wi-Fi.
- Проверьте, что порт не закрыт файрволом. Порт по умолчанию – `7860` или тот, который вы задали в `PORT`.
- Настройте контроль доступа. Для обычных клиентов в сети или в интернете задайте `BASIC_AUTH_USER` и `BASIC_AUTH_PASS` в `.env`. Для loopback пароль не запрашивается. Прямой трафик через Tailscale, а также через мост Docker на том же хосте или через распознанный шлюз контейнера считается доверенным по умолчанию. Трафику Docker, проброшенному через прокси, нужна обычная авторизация – если только вы явно не задали `REQUIRE_AUTH_FOR_DOCKER_PROXY=false`.
- Для привилегированных действий с этого устройства (резервные копии, очистка данных, обновления) задайте `ADMIN_SECRET` в файле `.env` сервера. Затем вставьте то же значение в **Settings** > **Advanced** > **Admin Access** на этом устройстве и нажмите кнопку **Save**.
- Если вы работаете через публичный домен или обратный прокси и видите сообщение **Untrusted request host**, добавьте точное имя этого хоста в `TRUSTED_HOSTS` в `.env`. Прямые IP-адреса, которые используют телефоны, компьютеры локальной сети и узлы Tailscale, принимаются автоматически.

Полный разбор – в руководствах [Удаленный доступ](REMOTE_ACCESS.md) и [Частые вопросы](FAQ.md).

## Сохранение заблокировано, настройки не сохраняются

Если сохранение вроде бы проходит, но после перезагрузки страницы все возвращается назад, его блокирует межсайтовая защита приложения Marinara. Защита CSRF (подделка межсайтовых запросов) охраняет действия, которые меняют данные, и доверяет только определенным источникам браузера.

Об этом говорит один или оба признака:

- Красная полоса сверху экрана предупреждает, что сохранение будет молча срываться, потому что этот источник не считается доверенным.
- Всплывающее сообщение с заголовком **Save blocked: missing CSRF header**, **Save blocked: cross-site request rejected** или **Save blocked: origin not trusted**.

Loopback, адресам частных сетей, Tailscale и мосту Docker доверие есть автоматически. Обычно такое случается только при обращении к Marinara по публичному IP-адресу или доменному имени. Добавьте этот адрес в `CSRF_TRUSTED_ORIGINS` в `.env`. Несколько адресов перечисляются через запятую, например:

```bash
CSRF_TRUSTED_ORIGINS=http://203.0.113.10:7831,https://chat.example.com
```

Перезапуск не нужен. В предупреждающей полосе есть кнопка Copy, которая копирует готовую строку целиком. Подробнее в руководстве [Удаленный доступ](REMOTE_ACCESS.md).

## Ошибки подключения и генерации

Ошибки генерации показываются всплывающим сообщением внизу экрана. Если подключение не сработало, сообщение называет причину. Оно висит достаточно долго, чтобы его прочитать и скопировать.

- **No API connection configured for this chat**: для чата не выбрано подключение. Откройте панель **Connections** (подключения), создайте подключение и выберите его для чата. См. [Подключение к провайдеру ИИ](connections/connecting-to-a-provider.md). Ключ API – это секретный код от провайдера, который открывает приложению Marinara доступ к его моделям.
- Модель не принимает параметр: сообщение называет, какой именно. Откройте **Chat Settings** (настройки чата) > **Advanced Parameters** и найдите этот параметр. Выключите переключатель рядом с его названием (всплывающая подсказка читается "This parameter is sent to the model").
- Модель сообщает, что параметр обязателен: сделайте то же самое, но переключатель рядом с параметром включите.
- **The AI returned an empty response. Try sending your message again.**: отправьте сообщение заново. Если это повторяется, попробуйте другую модель или другое подключение.
- **A generation is already in progress for this chat**: предыдущий ответ еще генерируется. Дождитесь конца или нажмите кнопку Stop, затем повторите.
- **No connections are marked for the random pool**: случайный выбор подключений включен, но ни одно подключение для него не отмечено. Отметьте хотя бы одно подключение или выключите случайный выбор.

## Проблемы с Local Model

**Local Model** (локальная модель) – это модель ИИ, которая работает на вашей машине и не требует ключа API. В некоторых сообщениях об ошибках эта функция называется словом sidecar.

- Если установка среды выполнения падает с сообщением **Sidecar runtime install is disabled**, значит на сервере это действие отключено из осторожности. На своей машине задайте `SIDECAR_RUNTIME_INSTALL_ENABLED=true` в `.env`. С другого устройства сначала вставьте свой секрет администратора в **Settings** > **Advanced** > **Admin Access**.
- Если скачивание или настройка модели не проходит с другого устройства (по сетевому адресу или из Docker), секрет администратора может понадобиться и здесь. На своей машине он не нужен. Куда вставлять секрет, написано в предыдущем пункте.
- Если проверка встроенного llama.cpp, MLX, uv или файла блокировки зависимостей MLX сообщает о несовпадении размера файла или суммы SHA-256, значит Marinara отклонила его до распаковки или установки. Обновите или переустановите Marinara и повторите попытку. Не запускайте, не распаковывайте, не правьте и не обходите отклоненный файл вручную.

### Сопровождающим: обновление закрепленных локальных сред выполнения

Архивы исходников, которые генерирует GitHub, не гарантируют побайтовую стабильность – даже когда содержимое коммита не меняется. Никогда не "исправляйте" несовпадение у пользователя, принимая байты с его машины или ослабляя проверку. Перезакреплять входные файлы среды выполнения можно только изменением в Engine, прошедшим проверку:

1. Выберите неизменяемую ревизию или файл выпуска в исходном проекте и изучите изменения на его стороне.
2. Скачайте файл во временную папку, запишите его точный размер в байтах и независимо вычислите его хеш SHA-256.
3. Впишите ревизию, адрес URL, размер и хеш в `runtime-integrity-manifest.ts`. Для MLX заново соберите `packages/server/src/assets/mlx-runtime-requirements.lock` из файла `.in` закрепленной версией uv на Apple Silicon и Python 3.12, проверьте каждое изменение зависимостей и обновите `requirementsLockSha256`.
4. Выполните `pnpm regression:runtime-integrity` и `pnpm check`, а затем настоящую чистую установку среды выполнения на затронутой платформе.
5. Выпустите проверенное обновление Engine и только потом просите пользователей повторить попытку. Не добавляйте ручное переопределение контрольной суммы.

Полная настройка описана в руководстве [Настройка модели Local Model](connections/local-model.md).

## Память и сводки

### Memory Recall ничего не вспоминает

Функция **Memory Recall** ищет в прежних сообщениях самые подходящие и незаметно возвращает их в промпт. Если кажется, что она ничего не помнит, проверьте следующее.

1. Откройте **Chat Settings** > **Memory Recall** и убедитесь, что переключатель **Enable Memory Recall** включен.
2. Откройте **Access memories for this chat**. В окне **Memories for This Chat** посмотрите статус каждого фрагмента.
3. Статус **Waiting for vector** означает, что воспоминание еще обрабатывается. Подождите и напишите в чат снова.
4. Статус **Embedding unavailable** означает, что ни один источник эмбеддингов не работает. Эмбеддинг – это числовое представление текста. Настройте подключение для эмбеддингов или дайте загрузиться встроенной локальной модели. См. [Настройка модели Local Model](connections/local-model.md).

Воспоминание создается только после появления минимум 5 новых сообщений. Кроме того, Memory Recall показывает лишь воспоминания, близкие по смыслу к новому сообщению, поэтому результат может быть пустым даже тогда, когда воспоминания есть.

### Сводки не генерируются

Чтобы писать сводки чата, нужно работающее текстовое подключение.

- В режиме Roleplay откройте всплывающую панель **Chat Summary** и проверьте, что подключение выбрано. Кнопка **Backfill Summary** догоняет старый чат.
- В режиме Conversation откройте **Automatic Summarization** и нажмите **Backfill**, чтобы повторить неудавшиеся дни.
- Если в чате включено подтверждение записи от агентов, сводка от ИИ ждет вашей проверки и только потом применяется.
- Сводку, которая срывается повторно (например, из-за неверного ключа API), Marinara пробует снова с задержкой. Исправьте подключение, затем нажмите **Backfill**.

## Проблемы с Card Browser

Раздел **Card Browser** ищет карточки персонажей на публичных сайтах и импортирует их. Откройте его по значку **Card Browser** в верхней панели и нажмите кнопку **Download Cards**.

- Если поиск на JannyAI или страница персонажа блокируется Cloudflare, Marinara показывает сообщение. Оно просит один раз зайти на сайт JannyAI в этом же браузере, чтобы пройти проверку, и повторить попытку.
- Если после перезапуска сервера перестает работать вход на CharacterTavern или Pygmalion, это нормально. Такие сессии хранятся только в памяти сервера и сбрасываются при перезапуске. Откройте окно входа и вставьте cookie или токен заново.

## Проблемы с генерацией медиа

### Очистка фона спрайта не справляется со сложной сценой

Обычно сгенерированные статичные спрайты используют собственную прозрачность или адаптивную однотонную подложку. Встроенная очистка распознает и старые белые подложки, сохраняет детали внутри контура персонажа, смягчает край альфа-канала и убирает подтеки цвета подложки. Сфотографированная комната, подробный пейзаж, густые тени или персонаж в цветах фона все же могут потребовать дополнительной очистки через ИИ:

```bash
pnpm backgroundremover:install
```

Затем перезапустите Marinara и нажмите кнопку **Reapply Cleanup** в окне генерации спрайтов. Marinara по-прежнему сначала пробует встроенный путь с подложкой и обращается к модели ИИ только тогда, когда край выглядит неоднородным. Если установка не удалась:

- Проверьте, что установлен Python версии от 3.9 до 3.11. Более новые версии Python могут запустить медленную сборку из исходников.
- Пересоберите инструмент командой `pnpm backgroundremover:reinstall`.
- Чтобы на время разбирательств принудительно оставить только автоматическую очистку по подложке, без ИИ, задайте `SPRITE_BACKGROUND_REMOVAL_ENGINE=builtin` в `.env`.

### Раскадровки в Game Mode или Roleplay не появляются

Раскадровки в Game Mode превращают завершенное повествование GM в ключевые кадры и, по желанию, в короткие клипы. Раскадровки в Roleplay объединяют завершенные обмены репликами и показывают результат прямо под ответом ИИ.

- Проверьте, что агент **Storyboard** установлен через **Agents** > **Download Agents**, затем включите для чата **Enable Agents** (включить агентов) и **Enable Storyboards** (включить раскадровки).
- Для видео сцены вручную сначала сгенерируйте или загрузите изображение в разделе **Gallery**, затем примените к нему действие **Video** или **Animate**. Раздел **Gallery** разделен на вкладки **Images** и **Videos**, поэтому смотрите на вкладке **Videos**.
- Для автоматических раскадровок в Game Mode откройте **Chat Settings** > **Agents** > **Storyboards** и проверьте, что переключатель **Automatic Storyboard Illustrations** включен. Если нужны и клипы, включите также **Automatic Storyboard Animations**.
- В режиме Roleplay добавьте в чат агента **Storyboard**. Выберите **Still images** или **Animations**, задайте значение **Messages per episode** и укажите подключение для изображений раскадровки. Вариант **Manual only** запускается иначе – кнопкой **Create storyboard** в разделе Gallery.
- Ключевым кадрам нужно подключение для изображений. Клипам нужно еще и подключение для видео.
- Если ваш промпт работает лучше, когда все персонажи описаны вместе, выключите **Use NovelAI Character Prompts**.
- У медленных провайдеров может истечь тайм-аут – это время, которое сервер ждет медленную задачу. Увеличьте `IMAGE_GEN_TIMEOUT_MS` или `VIDEO_GEN_TIMEOUT_MS` в `.env`, затем перезапустите Marinara. Сервер читает эти значения только при запуске.

Оба сценария работы разбирает [Руководство по агенту Storyboard](game/storyboard.md), а настройку игры – [Game Mode: начало работы](game/getting-started.md).

### Генерация мира в Game Mode выдает ошибку JSON

Если игра не запускается из-за того, что модель вернула испорченный JSON, Marinara открывает окно **Repair JSON** вместо того, чтобы выбросить весь ход. JSON – это структурированный текстовый формат, в котором модель обязана отвечать.

1. Исправьте скобки, запятые или поля в редакторе. Как только текст разбирается, полоса сообщает **JSON is valid.**
2. Нажмите кнопку **Format**, чтобы привести оформление в порядок.
3. Нажмите кнопку **Apply Repaired JSON**, чтобы применить исправленный текст без повторной генерации всего ответа.

## Голос, звонки и TTS

- Если во время звонка персонажи молчат, значит синтез речи не настроен. Откройте **Connections** > **Text to Speech**, включите его, выберите источник, введите ключ, выберите голос и сохраните. Персонаж без голоса отвечает только текстом.
- Если не работает микрофон, может понадобиться локальная модель распознавания речи. Установите пакет **Calls** в разделе **Agents > Download Agents**, затем откройте **Connections** > **Local Model**, разверните карточку, найдите **Local Speech Model**, выберите модель Whisper и нажмите кнопку **Download Whisper**. Особенно это нужно в Firefox, где нет браузерного распознавания речи. При удалении пакета Calls его модели Whisper тоже удаляются, чтобы освободить место на диске.
- В сборке Lite сообщение **Local Whisper is disabled in Lite mode** означает, что эта облегченная сборка не может запускать локальную модель речи. Используйте полную установку Marinara.

### Вход в Spotify для Music DJ не работает при удаленной или сетевой установке

Режим Spotify у агента Music DJ работает через OAuth. OAuth – это передача входа наружу: Spotify возвращает вас обратно на адрес обратного вызова. Redirect URI и есть этот адрес, причем Spotify принимает только адреса `https://` или loopback-адрес `http://127.0.0.1`. Обычные сетевые IP-адреса он отклоняет.

- Если вы открываете Marinara по localhost, редактор показывает адрес обратного вызова с `127.0.0.1`. Зарегистрируйте его в Spotify, и вход пройдет.
- Если вы открываете Marinara по HTTPS, редактор показывает ваш адрес обратного вызова с HTTPS. Зарегистрируйте его.
- Если HTTPS завершается на внешнем прокси и хост не совпадает, задайте в `.env` переменную `SPOTIFY_REDIRECT_URI` со своим публичным адресом обратного вызова.
- При сетевой установке по обычному HTTP всплывающее окно загрузиться не может, но в адресной строке все равно остается действующий код. Скопируйте полный адрес URL из всплывающего окна. Затем разверните **Browser couldn't reach the callback?** под кнопкой Connect и вставьте его. Вставленный адрес действует 10 минут.

Самое надежное решение на будущее – поставить сервер за HTTPS. Последняя проверка проводилась на Marinara Engine 2.2.0. Spotify ужесточил эти правила в феврале 2025 года.

## Хранилище и данные

### При запуске говорится, что каталог данных может использовать другой процесс

Marinara разрешает только одному запущенному серверу записывать в локальный каталог данных. Если при запуске для каталога появляется **Another Marinara Engine process ... may be using**, закройте другой процесс Marinara и запустите снова.

После сбоя или перемещения тома данных Docker вместо этого может появиться **The storage writer lease ... is incomplete or invalid** либо указание на процесс, которого уже нет на этом хосте. Сначала убедитесь, что остановлены все процессы и контейнеры Marinara, использующие этот каталог данных. Затем удалите только каталог `.writer-lease`, названный в ошибке, и перезапустите Marinara. Не удаляйте окружающий каталог `storage` и файлы таблиц.

### После обновления данные как будто пропали

Если после обновления чаты или пресеты выглядят пропавшими, не спешите удалять папки с данными. Marinara держит рабочие данные в папке `storage` внутри своей папки данных.

Поищите папку `storage` в обоих локальных местах:

1. `packages/server/data/`
2. `data/`

Сервер печатает при запуске, какие папки данных и хранилища он определил.

### После перехода на старую версию в чатах не видно сообщений

Новые версии Marinara хранят данные каждого чата (сообщения, свайпы, воспоминания, изображения и другие записи чата) в отдельных файлах вместо одного большого файла на таблицу. Благодаря этому длинные чаты сохраняются гораздо быстрее. Старые версии не понимают такую структуру. После перехода на старую версию чаты выглядят пустыми — данные по-прежнему лежат на диске, просто старая версия их не видит.

Marinara самостоятельно отклоняет очевидные понижения версии: программа запуска пропускает автообновление, которое привело бы к несовместимой версии, а встроенный механизм обновления блокирует его с ошибкой, ведущей к этому разделу.

Чтобы все же понизить версию:

1. Остановите сервер Marinara.
2. В папке Marinara выполните:

   ```bash
   node scripts/protect-launcher-data.mjs unshard
   ```

3. Переключитесь на старую версию и запустите ее как обычно.

Команда восстанавливает прежнюю однофайловую структуру из файлов отдельных чатов. Ничего не удаляется: файлы чатов сохраняются рядом с каждым восстановленным файлом в каталогах с именем `<table>.post-unshard-<timestamp>` (например, `messages.post-unshard-…`), а оригиналы до миграции остаются файлами `.pre-shard`. При последующем обновлении Marinara автоматически преобразует данные обратно.

Docker и Podman хранят данные в томе `marinara-data`, поэтому выполните команду в одноразовом контейнере: остановите работающий контейнер, запустите `docker compose run --rm marinara node scripts/protect-launcher-data.mjs unshard`, затем запустите старый образ.

### Резервная копия или экспорт возвращает 403

В сессиях через loopback резервные копии создаются без секрета администратора. С другого устройства, по сетевому адресу или из Docker для резервных копий и экспорта профилей нужно больше. Задайте `ADMIN_SECRET` на сервере и сохраните то же значение в **Settings** > **Advanced** > **Admin Access**. Если секрет нужен и для loopback, задайте `MARINARA_REQUIRE_ADMIN_SECRET_ON_LOOPBACK=true`.

## Android и Docker

### Приложение Android застряло на Connecting или Waiting for Server

Приложение для Android – это небольшая оболочка вокруг Termux. Termux – это приложение с терминалом Linux для Android, и настоящий сервер Marinara работает именно в нем.

1. Нажмите кнопку **Install / Start Marinara**.
2. Если Android предлагает установить Termux, подтвердите запросы.
3. Если Android просит разрешение выполнять команды в Termux, дайте его.
4. Дождитесь, пока скрипт запуска закончит работу и запустит сервер, затем вернитесь в приложение.

Обычная установка через APK никогда не просит вставить секрет Marinara. Приложение создает закрытые учетные данные для localhost, передает их в Termux и входит автоматически. Диалоги установки приложения и разрешений Termux остаются обязательными системными запросами Android. Не добавляйте `null`, `http://null` или секрет APK в `CSRF_TRUSTED_ORIGINS`: ни одно из этих действий не нужно и не считается правильной настройкой Android.

Проверьте также, что приложение и Termux используют один порт. По умолчанию это `7860`. Если вы собрали приложение с другим портом, укажите такой же `PORT` и в файле `.env` внутри Termux.

### Android localhost открывает страницу входа или возвращает 401/503

Установки Termux под управлением APK защищают localhost отдельным закрытым секретом для каждой установки. Приложение Android аутентифицируется автоматически и не должно показывать эту страницу входа во время настройки. Если страница появляется внутри приложения Marinara Engine, установите [последнюю версию APK](https://github.com/Pasta-Devs/Marinara-Engine/releases/latest/download/marinara-engine-android.apk), снова нажмите **Install / Start Marinara** и вернитесь в приложение после завершения работы Termux.

Ошибка с источником `null` означает, что старая пара APK и сервера пропустила непрозрачный источник Android WebView к общей проверке CSRF до закрытого обмена. Редактирование `.env` этого не исправит: буквальное значение `null` намеренно игнорируется, а глобальное доверие непрозрачному источнику ослабило бы все небезопасные маршруты API. Обновите APK и Engine; современные маршруты входа Android проверяют собственное одноразовое доказательство или секрет установки, а `null` везде в остальных местах остается запрещенным.

Ручная локальная аутентификация нужна только отдельному браузеру на том же телефоне. В нем откройте `/android-login` и вставьте значение, которое покажет эта команда Termux:

```bash
cat ~/.marinara-engine/android-secret
```

Локальная CLI `mari` автоматически читает тот же файл. Код 401 означает, что вставленный секрет или запрос аутентификации был отклонен; перезагрузите `/android-login` и вставьте текущее значение. Код 503 означает, что сервер получил настроенный секрет в неправильном формате. Перезапустите через `./start-termux.sh`. Если скрипт запуска сообщает, что файл секрета неправильный или пустой, вернитесь в приложение Android и нажмите **Install / Start Marinara**, чтобы APK создал его снова. Не помещайте этот секрет на снимки экрана и в отчеты о проблемах.

### Обновление на Android останавливается с кодом 134

Код завершения 134 обычно означает, что Android не хватило памяти на одном из шагов сборки. Обновитесь снова свежим скриптом запуска:

```bash
./start-termux.sh
```

Если процесс все равно останавливается, закройте другие приложения Android, откройте Termux заново и повторите команду.

### Termux закрывается или перезапускается во время работы Marinara

Пока сервер работает, скрипт запуска запрашивает блокировку сна Android и сохраняет каждую серверную сессию в `~/.marinara-engine/logs/`. После неожиданного перезапуска приложите к отчету самый новый файл `server-*.log`. Если файл заканчивается без ошибки Marinara или Node, скорее всего, Android или производитель телефона завершил Termux вне серверного процесса.

Разрешите Termux работать в фоне и отключите для него оптимизацию батареи в настройках Android. На устройствах с поддержкой дополнения Termux:API установите это дополнение и пакет `termux-api`, чтобы стала доступна команда `termux-wake-lock`. Эти настройки не предотвратят все фирменные остановки процессов, но устранят частую причину приостановки в простое, а постоянный журнал сохранит данные об ошибках на уровне приложения.

### При установке зависимостей на Android заканчивается место

Собранное приложение Marinara не занимает несколько гигабайт, и Noodle не скачивает собственные модели ИИ. Большой временный объем при обновлении обычно дают хранилище зависимостей pnpm и его виртуальное хранилище – особенно после нескольких выпусков или прерванной принудительной переустановки.

Текущий скрипт запуска вычищает пакеты, оставшиеся от прежних выпусков, и не пересобирает хранилище зависимостей дважды в рамках одного обновления. Если устройство уже забил старый скрипт запуска, обновите его и освободите неиспользуемый кеш перед новой попыткой:

```bash
cd Marinara-Engine
git pull --ff-only
pnpm store prune
./start-termux.sh
```

Не удаляйте `data`, `storage` и `marinara-engine.db`: там могут лежать ваши чаты и настройки. Если команда все равно останавливается, сохраните строки вывода начиная с `Installing dependencies` и приложите к отчету данные о свободном месте и памяти телефона.

### Встроенное обновление не проходит при переключении Stable и Staging на Android

Смена канала (Stable ↔ Staging) вызывает почти полную переустановку зависимостей, а на медленном хранилище Termux это занимает намного больше времени, чем обычное обновление. Встроенный механизм обновления теперь дает каждому шагу на Android дополнительное время, поэтому смена канала, которая раньше срывалась с сухим `Update failed: Command failed: corepack pnpm ... install`, должна доходить до конца.

Если обновление все же не проходит, текст ошибки теперь называет сорвавшийся шаг и содержит конец его вывода. Прочитайте это сообщение: настоящая ошибка зависимости или файла блокировки описана именно там. Другой вариант: выполнить обновление вручную из Termux командой, указанной в подсказке к ошибке, либо сначала освободить место:

```bash
cd Marinara-Engine
pnpm store prune
./start-termux.sh
```

### Noodle показывает `Etc/Unknown` или расписания идут по чужому часовому поясу

Для расписаний режима Conversation откройте Chat Settings режима Conversation или редактор расписания персонажа и выберите **Schedule timezone**. Этот общий выбор действует на все чаты Conversation, включая фоновые автономные сообщения, и сбрасывается кнопкой **Use device**.

Для Noodle и серверных задач без переопределения из Conversation удалите из `.env` пустую строку `TZ=`, если она там есть, и перезапустите Marinara, чтобы сервер унаследовал часовой пояс хоста. Чтобы задать резервный пояс хоста явно, укажите корректное имя IANA, например `TZ=Europe/Warsaw` или `TZ=America/New_York`. Текущие выпуски считают пустое значение незаданным, но перезапуск все равно нужен, чтобы состояние часового пояса в Node и запланированные задачи пересобрались согласованно.

### Контейнер выдает permission denied на подключенном томе

Если контейнер Docker или Podman падает с ошибками прав доступа на томе с данными:

- Для именованных томов после обновления скачайте свежий образ и перезапустите: `docker compose pull && docker compose up -d`. Официальный образ исправляет владельца при запуске.
- Для монтирования папок хоста откройте запись в папку для пользователя и группы с идентификатором `1000` либо используйте именованный том.
- В системах с SELinux, таких как Fedora или RHEL, добавьте к точке монтирования суффикс `:Z`.

### Контейнер lite падает на Raspberry Pi 4

Если контейнер lite перезапускается каждый раз, когда отправляет запрос к ИИ на Raspberry Pi 4 или похожем устройстве ARM, посмотрите код завершения. Код 132 или SIGILL указывает на известную проблему сборки Node в образе lite на некоторых чипах ARM. SIGILL означает, что программа наткнулась на инструкцию, которую процессор выполнить не может.

Обычный образ, не lite, этой проблемы не имеет. Пока исправление не вышло, используйте на таком устройстве обычный образ. Среди затронутых образов lite известны `1.5.7-lite` и `1.5.8-lite`. Последняя проверка проводилась на Marinara Engine 2.2.0.

### В разделе Addons нет External Extensions

Раздел специально скрыт, пока не открыты оба защитных барьера:

1. Задайте `ENABLE_EXTERNAL_EXTENSIONS=true` в файле `.env` на хосте.
2. Подождите около двух секунд, пока сработает наблюдатель за конфигурацией, затем откройте **Settings → Advanced → Danger Zone**, прокрутите ниже элементов удаления данных и включите **Allow third-party extension imports**.

Если переключатель в разделе Danger Zone неактивен, значит флаг на хосте все еще выключен или приложение не заметило изменение. Проверьте, что вы правили тот файл `.env`, который используется на самом деле, – его путь описан в руководстве [Настройки сервера: справочник](CONFIGURATION.md). В Docker это обычно `/app/data/.env`.

Пока закрыт хотя бы один барьер, записи расширений не показываются и не запускаются – ни внешние, ни устаревшие, ни импортированные из профиля, ни добавленные вручную, ни с неизвестным источником. Повторное открытие барьеров не включает их автоматически.

### Импортированное Browser Extension появляется, но не работает

Откройте расширение в разделе **Settings → Addons → External Extensions** и посмотрите на **Requested access** (запрошенный доступ). Старые пакеты в формате `marinara.extension` версии 1 без объявления возможностей должны показывать **Full page access** (полный доступ к странице). Подтверждайте только тот хеш, который вы проверили сами и которому доверяете.

Если старый пакет экспортировали заново с явно пустым списком возможностей, Marinara считает его безопасным расширением в песочнице, и код, который работает с DOM, там не заработает. Добавляйте `full_page_access` в его манифест, только если понимаете: этот код получит доступ ко всей странице Marinara, к хранилищу браузера, к сетевым API и к сессии того же источника.

Если после выключения расширения с полным доступом к странице остался элемент на панели инструментов, наложение, обработчик или изменение вида, перезагрузите страницу Marinara. Очистка выполняется по мере возможности: код страницы может оставить побочные эффекты вне отслеживаемого API совместимости приложения Marinara.

### Server Extension сообщает, что нет поддерживаемой песочницы

Server Extensions и необработанные команды оболочки Professor Mari запускаются только с Seatbelt в macOS или Bubblewrap в Linux. Официальный образ Docker уже содержит Bubblewrap, но стандартный контейнер с минимальными правами не может создавать вложенные пространства имен и подключения. Marinara обнаруживает это состояние и отключает функции системной песочницы, а не запускает заведомо неработающие команды.

Если вы принимаете более широкие права контейнера и нуждаетесь в этих функциях Docker, сохраните следующее как `docker-compose.override.yml` рядом с `docker-compose.yml`:

```yaml
services:
  marinara:
    environment:
      MARINARA_DOCKER_USER: root
    cap_add:
      - SYS_ADMIN
    security_opt:
      - apparmor=unconfined
```

После этого пересоздайте контейнер. Сервер должен оставаться запущенным от root, чтобы дополнительная возможность не отбрасывалась при обычном переходе точки входа Marinara к пользователю `node`. root с `SYS_ADMIN` — широкое повышение прав, а отключение AppArmor дополнительно ослабляет внешнюю границу безопасности. Не включайте это только ради исчезновения сообщения. В актуальном Docker общее `seccomp=unconfined` не должно требоваться.

Server Extensions работают только с Seatbelt в macOS или Bubblewrap в Linux. Установите `bwrap` на хосте Linux, затем перезапустите Marinara. В Windows, Android и других неподдерживаемых системах запуск Server Extension намеренно отклоняется, вместо того чтобы выполнять код в основном процессе сервера. Browser Extensions при этом продолжают работать в своей песочнице Worker с непрозрачным источником.

## Как получить помощь

Если помощь все еще нужна, сначала соберите подробности.

1. Откройте **Settings** > **Advanced** > **Message Tools** и включите **Debug mode**. Тогда сервер пишет содержимое промпта и ответа в консоль, и его можно приложить к обращению.
2. Запишите свою операционную систему, версию Node.js и полный текст ошибки из консоли сервера.

Перед отправкой отладочного вывода удалите из него ключи API, токены доступа, секреты администратора, личные промпты и содержимое личных чатов.

Дальше обращайтесь к сообществу:

- Читайте открытые issue по адресу https://github.com/Pasta-Devs/Marinara-Engine/issues
- Заходите за помощью сообщества в Discord: https://discord.com/invite/KdAkTg94ME
- Создайте отчет об ошибке по адресу https://github.com/Pasta-Devs/Marinara-Engine/issues и приложите собранные выше подробности.
