# Memory Recall и сводки чата

Это руководство объясняет функцию **Memory Recall** (память чата, поиск по прошлым сообщениям), включаемую по желанию функцию **Advanced Memory Recall** (расширенная память чата) для автоматического управления контекстом Roleplay, панель **Chat Summary** (сводка чата) и раздел **Automatic Summarization** (автоматические сводки) в Conversation.

## Две системы памяти

Любая модель ИИ читает за один раз лишь ограниченный объем текста. Этот предел называют контекстным окном. Когда чат становится длинным, самые старые сообщения выпадают из окна, и ИИ их забывает. В приложении Marinara Engine (далее – Marinara) есть две отдельные системы, которые решают эту проблему.

- **Memory Recall** ищет в старых сообщениях места, ближе всего связанные с тем, что вы только что написали, и незаметно возвращает их в промпт. Функция работает во всех режимах чата.
- Сводки сжимают старые сообщения в короткие пересказы, которые занимают в промпте место исходных сообщений. В чатах Roleplay за это отвечает панель **Chat Summary**, в чатах Conversation – раздел **Automatic Summarization**.

Чатам Game Mode доступна только функция **Memory Recall**. Ни одной из функций сводки в них нет.

Обе системы можно использовать одновременно. Они делают разную работу и друг другу не мешают.

## Настройка Memory Recall

**Memory Recall** находит подходящие фрагменты из более ранней части чата и вставляет их в промпт как воспоминания. Для этого нужен эмбеддинг – числовой отпечаток смысла сообщения. Marinara сравнивает отпечаток нового сообщения с сохраненными отпечатками прошлых сообщений и добавляет самые близкие совпадения.

### Включение Memory Recall

1. Откройте чат и нажмите кнопку **Chat Settings** (настройки чата) в чате (изначально она справа вверху).
2. Найдите раздел **Memory Recall** (у него значок мозга).
3. Включите переключатель **Enable Memory Recall**.

**Enable Memory Recall** – настройка отдельного чата. Значение по умолчанию зависит от режима:

- Включено в чатах Conversation.
- Включено в чатах Roleplay и Game, где есть активная сцена.
- Выключено во всех остальных чатах.

Если выключить переключатель, найденные воспоминания перестают попадать в промпт. Уже сохраненные данные при этом не удаляются.

### Источник эмбеддингов

Чтобы строить отпечатки смысла, функции **Memory Recall** нужен источник эмбеддингов. Он задается в подключении, а не в настройках чата. Подключение – это сохраненные настройки доступа к провайдеру ИИ.

1. Откройте панель **Connections** (подключения) и начните править подключение.
2. Найдите раздел **Semantic Search (Embeddings)**.
3. Введите название модели эмбеддингов в поле модели. Пример значения – `text-embedding-3-small`.
4. При необходимости укажите в поле **Embedding Endpoint URL** другой адрес.
5. При необходимости выберите в раскрывающемся списке **Embedding Connection** подключение, у которого можно позаимствовать ключ и адрес. Среди вариантов – **Same as this connection** и **Local Model (sidecar)**.

Некоторые провайдеры эмбеддинги не предлагают. Тогда Marinara выводит примечание с просьбой выбрать отдельное подключение для эмбеддингов: совместимое с OpenAI, подключение к Google или к встроенной модели Local Model.

Если подключение для эмбеддингов не задано вовсе, Marinara берет встроенную локальную модель эмбеддингов. Она скачивается один раз и работает на вашем компьютере, ключ API для нее не нужен. Подробнее о встроенной модели – в руководстве [Настройка модели Local Model](../connections/local-model.md).

Тот же параметр **Semantic Search (Embeddings)** отвечает и за семантический поиск в лорбуках, так что достаточно настроить его один раз – и работают обе функции.

### Окно **Memories for This Chat**

Чтобы посмотреть, что чат запомнил, откройте панель **Chat Settings**, перейдите в раздел **Memory Recall** и нажмите **Access memories for this chat**. Если Advanced Memory включена, просмотр остается внутри выдвижной панели Roleplay; иначе открывается окно **Memories for This Chat**.

В окне видно число сохраненных фрагментов памяти и примерную оценку в токенах. На карточке каждого фрагмента показаны охваченный диапазон дат, число сообщений, статус и время создания. Статус бывает таким:

- **Vectorized** – отпечаток построен и готов к поиску.
- **Waiting for vector** – отпечаток еще создается.
- **Embedding unavailable** – ни один источник эмбеддингов не смог его построить.

На панели инструментов есть значки экспорта воспоминаний, импорта, перестроения и полной очистки. У каждого фрагмента есть свой значок корзины, чтобы забыть только его.

- Значок корзины у фрагмента открывает окно **Forget Memory**. Подтвердите кнопкой **Forget**.
- Значок корзины для полной очистки открывает окно **Clear Memories**. Подтвердите кнопкой **Clear**. Так удаляются воспоминания, но сообщения чата остаются на месте.
- Значок обновления пересобирает все фрагменты памяти из текущих сообщений чата. Пользуйтесь им после смены модели эмбеддингов.
- Экспорт сохраняет файл `.marinara.json`. Импорт принимает файлы `.json` и `.marinara` и объединяет их с уже существующими воспоминаниями.

### Как ведет себя Memory Recall

Стоит помнить о нескольких моментах:

- Marinara сохраняет фрагменты памяти в фоне всегда, когда доступен источник эмбеддингов – даже при выключенном **Enable Memory Recall**. Переключатель отвечает только за то, попадают ли сохраненные воспоминания в промпт. Чтобы сохранение прекратилось, уберите источник эмбеддингов или время от времени очищайте воспоминания.
- Фрагмент создается, только когда накопится не менее 5 новых сообщений. Более мелкие порции ждут следующего ответа.
- Найденные фрагменты проходят проверку на схожесть и должны быть достаточно близки по смыслу. Слабые совпадения отбрасываются, поэтому поиск иногда не возвращает ничего, хотя воспоминания есть.
- На найденные воспоминания отводится небольшая доля промпта, так что добавляются лишь несколько самых подходящих.
- Если сменить модель эмбеддингов, когда воспоминания уже есть, старые фрагменты перестанут совпадать. Пересоберите их значком обновления.
- Удаление сообщений чата удаляет и его фрагменты памяти.

В некоторых контейнерных сборках, известных как Marinara Lite, функция **Memory Recall** выключена полностью. Там раздел **Memory Recall** вообще не появляется.

## Advanced Memory Recall (Roleplay)

Откройте **Chat Settings → Memory Recall** и включите **Advanced Memory Recall**. В мастере настройки Roleplay также можно включить **Automatic context and memory handling** (автоматическое управление контекстом и памятью) под разделом Agents. Этот необязательный режим вместе управляет окном несжатой истории, сводками для связности и подходящими старыми фрагментами. На компьютере и телефоне настройки и ход подготовки доступны и в мастере, и в выдвижной панели Chat Settings. Просмотр архива остается в панели Chat Settings.

### Настройка

- Установите **Maximum allowed context before compression (tokens)** в пределах контекста модели чата. Предел охватывает оценку исходящего промпта: инструкции, сообщения, извлеченную память, инструменты и вложения, как для чата, так и для обработки памяти. Токены ответа и запас безопасности учитываются отдельно. Общий предел контекста модели сохраняется; это не точный подсчет токенизатора и не предел оплаты.
- Выберите **Summary and recall budget (tokens)** (бюджет сводок и извлечения) в этих пределах. Целевой размер активных постоянных сводок – не более **70%** значения. Приоритет: постоянные сводки, сводки выбранных сцен, затем отрывки сообщений. Вся память при необходимости может занять до **2,000 дополнительных токенов**, если позволяет общий контекст. Для 10k цель постоянных сводок – до 7k, общий размер – до 12k; для других значений действуют те же пропорции. Текущие сообщения не входят в постоянную долю и не запускают ее объединение.
- По умолчанию: **Helper model** (вспомогательная модель) определяет границы сцен, создает их сводки и сжимает связность истории. По умолчанию используется подключение агентов, затем подключение чата. Первичное определение исторических сцен может использовать основную или вспомогательную модель; сводки всегда создает вспомогательная. Выбранные модели показаны до подготовки.
- Все запросы сводок памяти используют **Chat Summary → Maximum output size**, выделяя не менее **8,196 выходных токенов**, чтобы оставить место для рассуждений. Это относится к сценам и объединению постоянных сводок; большие значения сохраняются. Обычный предел ответа вспомогательного подключения не заменяет эту настройку. Вход и резерв ответа по-прежнему должны помещаться в общий контекст модели.
- Запрос сводки сцены содержит инструкции, доступные сообщения этой сцены, применимые исправления по диапазонам и формат ответа JSON. Слишком большие сцены обрабатываются сохраняемыми порциями, затем объединяются. Для сводки запрашиваются **2–3 абзаца**. Стандартный промпт описывает прошлые события без разделов текущей ситуации и открытых конфликтов; пользовательские промпты из **Summaries** продолжают действовать. Advanced Memory не зависит от главного переключателя Agents и не требует загружаемого агента.
- **Maximum recalled scenes** (максимум извлекаемых сцен) по умолчанию равен **3**. Это верхняя граница; слабые совпадения пропускаются. **0** отключает необязательные сцены, сохраняя необходимую связность. Каждая сцена дает сводку, затем не более одного фрагмента.
- **Moving context** (подвижный контекст) задает сообщения в одном фрагменте, по умолчанию **3–10**. Оба лимита **0** оставляют только сводки; минимум **0** делает фрагменты необязательными. Релевантность, доступ персонажа и место могут уменьшить число сообщений до нуля. Каждая извлеченная сцена получает минимальный фрагмент, прежде чем какой-либо фрагмент будет расширен. Если у извлеченной сцены фрагмента все равно нет, отчет поиска объясняет причину: после сводок не осталось места или ни одно из ее сообщений нельзя процитировать.

В старом групповом чате Individual один раз подтвердите отсутствующие диапазоны знаний персонажей. Первая реплика не доказывает, что персонаж знал все до нее. Выбирайте реального персонажа как **Narrator** (рассказчик), только если он должен обходить ограничения участия. Скрытие для отдельных персонажей и подтвержденные диапазоны знаний по-прежнему ограничивают память. Глобальное **Hide from AI** (скрыть от ИИ), заданное вручную или автоматическими сводками, лишь убирает сообщение из живой истории: Advanced Memory все равно сканирует его, определяет участников сцены, составляет сводку и индексирует для разрешенного воспоминания. Начальные метки обрезают живую историю. Диапазоны можно исправить позже; новые персонажи требуют отдельного подтверждения.

Для существующего чата сначала нажмите **Prepare existing history** (подготовить существующую историю). Если восстановленная история меняет границы сцены с ручной правкой, отключите эту память, чтобы сохранить текст для справки, либо удалите ее, затем подготовьте историю снова. Кнопка **Fix** (исправить; см. [Исправление проблем с памятью](#fixing-memory-problems)) пропускает такую сцену и показывает ее в списке, а не останавливается. Сохранение той же правки не может безопасно присвоить текст другому диапазону источника. Подготовка обрабатывает старую историю пакетами и показывает текущий этап рядом с колесом хомяка Professor Mari. **Cancel** (отмена) сохраняет выполненное; **Resume** (продолжить) возобновляет работу после закрытия панели, перезапуска сервера или обновления приложения. Неудачный вызов модели сохраняет ранее корректную память и показывает ошибку для повторной попытки. Не сбрасывайте память для исправления ошибки вызова: Resume использует готовые сводки и неизмененное определение сцен. Последняя текущая сцена остается открытой и получает сводку после закрытия; если ее живые сообщения превышают лимит контекста, используются ограниченные исходные выдержки.

Откройте сводку в **Access memories for this chat** и нажмите внизу **Delete summary** (удалить сводку). Подтвердите сводку и аудиторию. Это действует и для старых записей **Continuity** (связность) и **Ongoing scene** (текущая сцена). Обычная подготовка не создает удаленные сводки сцен заново. Исходные сообщения сохраняются. Новые постоянные сводки находятся в **Chat Summaries**, где действуют прежние команды редактирования, включения, объединения и удаления. Старая связность в хранилище не используется как дополнительная постоянная сводка.

<a id="fixing-memory-problems"></a>

### Исправление проблем с памятью

Если в памяти чата что-то сломалось, вы увидите это, не открывая настройки памяти. В углу кнопки **Chat Settings** появляется немигающая точка акцентного цвета, а уведомление сообщает, в скольких сценах есть проблемы. О каждом наборе проблем уведомление появляется один раз; точка остается, пока они не будут решены. В **Chat Settings → Memory Recall** те же проблемы перечислены над настройками, а в **Access memories for this chat** видна та же точка.

Нажмите **Fix** в уведомлении или в этом списке, чтобы за один запуск исправить все отмеченные сцены. Fix использует **Helper model** и обычную полосу прогресса. **Pause processing** (приостановить обработку) останавливает работу, а **Resume processing** (продолжить обработку) возобновляет Fix; уже сделанное сохраняется. Fix делает следующее:

- заново спрашивает вспомогательную модель, кто был в сценах с пометкой **Check who was there**, и сохраняет четкий ответ. Если модель по-прежнему не может определить участников, новый доступ никто не получает: у сцены остаются только те прежние персонажи, которых модель не исключила, а сама сцена попадает в список для вашей проверки;
- проверяет участников старых сцен, сохраненных до появления проверки участников, включая сцены, автоматическая проверка которых не удалась;
- пишет новые сводки для сцен, у которых изменились сообщения, скрытые сообщения, имена персонажей или сводки, на которых они основаны, а также для завершенных сцен без сводки. Удаленные вами сводки остаются удаленными;
- возобновляет обработку памяти, прерванную ошибкой.

Fix никогда не переписывает сводку, отредактированную вручную. Если такая сводка больше не соответствует своим сообщениям, не учитывает снова показанные сообщения или границы ее сцены сдвинулись, Fix не трогает ее, а добавляет в список **need your review** и переходит к остальным сценам. Настройки, которые Fix не может изменить за вас, например подтверждение диапазона знаний каждого персонажа или выбор работающего подключения модели решений, остаются в списке, пока вы их не измените.

По завершении Fix показывает номера сцен в двух списках: **Fixed N scenes** – исправленные сцены, **need your review** – сцены, которые нужно проверить вам. Выберите номер, чтобы открыть эту сцену в **Access memories for this chat**. Если панель Chat Settings была закрыта, туда приведет уведомление с кнопкой **Show** (показать). Если по сцене решение принять не удалось, следующий запуск Fix не будет спрашивать о ней снова; сохраните доступ персонажей к ней сами.

### Необязательная модель решений

Включите **Use Decision model** (использовать модель решений) в Advanced Memory и выберите модель в списке **Memory Decision connection** (подключение модели решений для памяти). В группе **Local models** (локальные модели) он показывает те же локальные модели, что и глобальная настройка **Decision model** (модель решений), например **Primary local model** (основная локальная модель), запущенную на карточке **Local Model**. Модель, которая пока не может отвечать, показана серой с указанием причины, а остановленная модель запускается, когда к ней обращается Advanced Memory. В группе **Connections** перечислены ваши сохраненные подключения модели решений. Создайте такое подключение в **Connections** через TypeSafe, OpenRouter или совместимый источник решений; см. [Модели решений](../connections/decision-models.md). По умолчанию опция выключена и сохраняется отдельно для каждого чата Roleplay. Сделанный здесь выбор не зависит от глобальной настройки модели решений.

Выбранная модель определяет границы сцен при подготовке истории и текущих проверках. Перед новым ответом она выбирает воспоминания в два прохода. Сначала обычный поиск отбирает до 24 сводок сцен (или до значения **Maximum recalled scenes**, если оно больше) с помощью текстового поиска и, где есть сохраненные векторы, эмбеддингов. Из этого списка модель выбирает подходящие сцены, затем оценивает до 12 исходных сообщений каждой выбранной сцены – ее лучшие совпадения текстового поиска, – чтобы выбрать фрагмент этой сцены. Лучшее из выбранных сообщений становится центром, а остальные удлиняют фрагмент до значения **Maximum messages per excerpt** (максимум сообщений во фрагменте). Если модель не принимает ни одного сообщения сцены, центр фрагмента задает текстовый поиск, и отчет поиска это отмечает. Если ни одно из этих сообщений сцены не помещается даже по отдельности в место, оставшееся после сводок, сцена не может получить фрагмент, поэтому модель не оценивает ее сообщения; если это относится ко всем выбранным сценам, второй запрос не отправляется. При неуверенности сцена остается открытой. **Helper model** по-прежнему пишет все сводки и обновления непрерывности истории. Сохраняются ограничения числа сцен, длины фрагментов, доступа персонажей и токенов. Корректное решение может не выбрать ничего.

Внешние провайдеры получают недавний разговор и отобранные для оценки сводки или сообщения и могут брать плату за несколько запросов на один ответ. Перед отправкой кандидатов поиск проверяет доступ персонажей и применяет условия приватных разделов сводок. Отправляются только исходные сообщения, которые видели в чате персонажи, вспоминающие сцену, а каждый персонаж по-прежнему получает только предназначенные ему части сводки. Запросы разбиваются на ограниченные пакеты в пределах контекста подключения; заявленный контекст чат-маршрутизатора Jev не считается лимитом запросов решений.

У каждого прохода поиска воспоминаний собственный лимит решений – 10 секунд. Отсутствие подключения, неполные ответы, слишком большие кандидаты, ошибки и тайм-ауты возвращают обычный поиск: сцены выбираются по ранжированию самого списка отобранных, а фрагменты – текстовым поиском; недоступные решения о сценах возвращают существующую проверку сцен. При включенной опции подготовка индексирует текст без новых эмбеддингов. Существующие векторы остаются доступны как запасной вариант. После выключения используйте **Reindex**, если нужны эмбеддинги для записей, подготовленных в режиме решений.

Просмотр промпта остается доступным только для чтения и показывает обычный поиск без обращения к провайдеру решений. В **Peek Prompt → Decision diagnostics** (Peek Prompt → диагностика решений) раздел **Advanced Memory activity** (активность Advanced Memory) показывает сохраненные результаты последнего извлечения и проверки конца сцены: модель, время, оценки, выбранные воспоминания или окончания, состояние резервного механизма и причину, по которой у извлеченной сцены нет фрагмента. Отчеты записываются для новых вызовов после этого обновления и хранят до 128 результатов, сначала выбранные. Это прошлая активность, а не прогноз для предпросмотра; открытие панели или проверка утверждений промпта не запускает решения памяти повторно. Проверки конца сцены через модель решений всегда используют собственный запрос, отдельно от пакетов трекеров и агентов. Отчет поиска отмечает решения и запасные варианты. Совместимые варианты ответа и продолжения используют сохраненный выбор; изменение этих настроек делает несовместимые сохраненные наборы памяти недействительными.

<a id="deciding-who-sees-new-messages"></a>

### Кто видит новые сообщения

В групповом чате Roleplay, где персонажи отвечают по очереди, Advanced Memory может решать, какие персонажи видят каждое новое сообщение, чтобы вам не приходилось вручную скрывать каждое сообщение от персонажа, который покинул сцену. Включите в Advanced Memory опцию **Decide who sees new messages** (решать, кто видит новые сообщения). По умолчанию она выключена и появляется только в групповых чатах, где персонажи отвечают по очереди; в объединенных групповых чатах и в чатах с одним персонажем ее нет.

Когда опция включена, каждое новое сообщение – ваше или персонажа – скрывается от персонажей, которых нет в этой сцене. Для этого используется то же скрытие **Hide from AI** для отдельных персонажей, что и у кнопки на самом сообщении, поэтому значок перечеркнутого глаза показывает, кому сообщение не видно. Решение по вашему собственному сообщению принимается сразу после его отправки, даже если ни один персонаж не отвечает. Прежде чем ответит следующий персонаж, решение по предыдущим сообщениям уже принято, поэтому он никогда не прочитает сообщение, которое ему видеть не положено.

- Выбранный здесь **Narrator** и **Narrator character** (персонаж-рассказчик), выбранный в **Roleplay Commands** (команды Roleplay), всегда видят все сообщения. Автор сообщения всегда видит свое сообщение. Адресат шепота, которого нет в сцене, не получает остальной текст сообщения, но шепот по-прежнему получает.
- При включенной опции **Use Decision model** модель решений для каждого персонажа отвечает на вопрос, точно ли он не может видеть или слышать сообщение, например потому что находится в другом месте или ушел. Персонаж, которого сюжет ни разу не помещает в сцену, считается находящимся в другом месте. Персонаж, который присутствует, но не входит в число адресатов шепота, все равно видит остальной текст сообщения. Иначе решает **Helper model**. В обоих случаях сообщение скрывается, только если модель уверена; если нет, персонаж продолжает его видеть. Если после ответа подошла очередь проверки сцены, тот же запрос заодно определяет, кто присутствует, поэтому для этих сообщений дополнительный вызов не нужен.
- Модель читает сообщения текущей сцены, написанные к этому моменту, и в любом случае не менее нескольких последних сообщений, даже если новая сцена только началась. Она также получает список персонажей, которые говорили с начала текущей сцены. Этот список – лишь подсказка: персонаж, который молча слушает, все равно считается присутствующим, даже если ничего не сказал.
- Если вы сами измените **Hide from AI** у сообщения или примените к нему `/hide` или `/unhide`, до или после автоматического выбора, ваш выбор сохраняется, и Advanced Memory больше никогда не меняет это сообщение. Сообщения, которые вы уже скрыли от кого-либо, остаются без изменений.
- Решение по каждому сообщению принимается один раз. Если модель дает сбой или не отвечает вовремя, это сообщение ни от кого не скрывается, а ошибка появляется в журнале сервера.

### Во время чата

Определение сцен выполняется после сохранения главного ответа Roleplay. Значение **Standalone scene check interval (messages)** по умолчанию – **5**. Проверяющая модель получает последние пронумерованные сообщения, одно предыдущее для контекста, инструкции и формат ответа. Она указывает точные номера сообщений, завершающих сцены, или не возвращает окончаний, если сцена продолжается. Учитываются сообщения персон и персонажей. Частота не зависит от расписаний агентов отслеживания. При выключенном режиме решений очередная проверка использует общий вызов такого агента после генерации, если позволяют видимость источников и бюджет; иначе выполняется отдельный вспомогательный вызов. Новый диапазон начинается после предыдущего окончания и включает указанное новое окончание. Только обнаруженное завершение запускает фоновую подготовку сводки и индекса закрытой сцены, даже если ее заканчивает последний ответ. Неопределенный переход оставляет сцену открытой. Раздел **Chat Settings → Agent activity** (настройки чата → активность агентов) показывает **Advanced Recall**, прогресс, ошибки и восстановление, даже при отключенных обычных агентах. Статус опрашивается лишь во время работы с памятью; готовые архивы в простое не опрашиваются. При включенном режиме решений эту проверку выполняет выбранное подключение модели решений.

При выключенном режиме решений: Извлечение читает подготовленную память. Необязательный эмбеддинг запроса имеет короткий тайм-аут и при недоступности заменяется текстовым поиском. Текстовый поиск придает больший вес характерным словам из последнего сообщения пользователя, поэтому короткая деталь может найти длинное резюме сцены. Больше всего весит упомянутое в нем имя, например имя питомца. Имена отвечающих персонажей и вашей персоны такого веса не получают, как и имя, которое встречается в большинстве воспоминаний. Индексированные исходные сообщения также позволяют находить сцены при отключенном выводе фрагментов. Ни один из этих механизмов не добавляет вызов модели. Извлечение работает только для основной генерации Roleplay: агенты, ручные перезапуски и вспомогательные пробные генерации его не запускают и не получают найденные сводки или фрагменты. Просмотр основного промпта ничего не изменяет.

Повторные варианты используют самую раннюю совместимую память этой реплики: связность, сводки сцен и точные фрагменты. Неизмененные варианты не повторяют поиск или вызов модели сводок. Продолжение сохраняет исходную память. Старые реплики без снимка сохраняют его при следующей генерации и затем используют повторно; сброс не нужен. Фоновое добавление и объединение сохраняют совместимые снимки. Изменения пользователем истории, доступа, сводок или памяти делают несовместимые снимки недействительными. Текущий лимит контекста действует всегда. Свайп также заново извлекает память, если после того ответа более ранняя сцена, которую мог вспомнить его персонаж, была сохранена, изменена, включена или выключена. Сцену, которая еще входит в историю чата этого ответа, пока нельзя извлечь, поэтому ее сохранение не запускает повторное извлечение.

Главная генерация сразу читает сохраненную память. Она никогда не запускает генерацию сводок непрерывности и не ждет ее, даже при работающем фоновом помощнике. Когда исходящий промпт достигает предела, окно текущих сообщений начинается с начала последней сцены для **всех персонажей**, затем растет до следующего достижения предела. Автоматическая отсечка видна в **Mark as new start** с выбранным **All**; снимите All, чтобы отменить ее. Личные начальные флаги продолжают действовать. Если открытая сцена или слишком большая постоянная сводка не помещается, запрос использует явно обозначенные отрывки, сохраняя последние сообщения. Временная подгонка не создает еще один постоянный флаг. Сохраненные сводки и оригинальные сообщения не перезаписываются.

После главного ответа Advanced Memory дополняет существующие **Chat Summaries** по диапазонам только еще не покрытыми архивными сообщениями, по возможности используя готовые сводки сцен. Существующие записи, включая неактивные, означают уже обработанные диапазоны. Когда допустимые активные постоянные сводки превышают 70% **Summary and recall budget**, **Updating continuity** объединяет только их тексты после ответа, с выбранным помощником и **Chat Summary → Maximum output size**. Сводки, пересекающиеся с текущими сообщениями, исключаются из бюджета и сжатия; старые записи без диапазона остаются допустимыми. Ответ, пересекающий порог, создается как обычно с сохраненными допустимыми сводками и не ждет сжатия. Дополнительные 2,000 токенов относятся ко всей памяти, не к постоянной доле. Сводки с приватными частями для отдельных персонажей в разделах `{{#if char == "Name"}}…{{/if}}`, написанные Advanced Memory, объединяются с другими сводками, которые читают те же персонажи. Вспомогательная модель получает их вместе с этими условиями и вашим **Combine prompt** (промпт объединения) и должна сохранить каждую приватную часть ровно для тех персонажей, которые ее знали. Если результат изменил бы круг персонажей, которые могут читать приватную часть, он не сохраняется: эти сводки остаются как есть, а сокращаются только остальные. Сводки, которые вы написали или отредактировали сами, и другие сводки, макросы которых раскрываются по-разному для разных персонажей, не меняются; если они одни превышают цель, нужна ручная правка. Другие группы получают пропорциональные рекомендации по длине, а не жесткий порог отказа. Более короткая завершенная замена получает название с диапазоном сообщений и сохраняется одновременно с отключением заменяемых записей. Ошибочный или незавершенный результат не сохраняется; прежние записи доступны, а **Resume processing** повторяет незавершенную работу. Сводки сцен остаются в хранилище.

Архив извлекает подходящие сводки сцен и точные диалоги с исходными номерами и авторами. В едином разделе **Recalled Scenes** за каждой сводкой сразу следует доступный отрывок с одним заголовком диапазона. Сцены без отрывков остаются там же. Блок указывает текущий диапазон и номер последнего сообщения пользователя. Сцена извлекается, только когда все ее источники находятся вне отправляемой текущей истории; отрывки тоже исключают текущие сообщения. **Chat Summaries** по диапазонам также пропускаются, пока хоть одно покрытое сообщение остается в контексте. Они сохраняются включенными и снова становятся допустимыми после выхода всего диапазона из окна. Допустимые постоянные сводки важнее необязательного извлечения и сохраняют условия персонажей. Место для всех выбранных сводок сцен резервируется до отрывков. Ограничения доступа и исторических источников сохраняются. Иллюстрации и подписи изображений исключаются из извлеченных сообщений и новых входных данных для сводок; читаемые текстовые вложения остаются. Учитываются персоны и персонажи. Историческая регенерация использует лишь источники до целевого ответа, даже раньше управляемого окна. Правка, смена варианта, скрытие или удаление источника вызывает повторную проверку производной памяти перед использованием.

Откройте **Access memories for this chat** в той же панели, чтобы искать хронологически пронумерованные сводки сцен, проверять их время и аудитории, менять **Summary text** (текст сводки) или читать полные оригинальные сообщения через **Inspect source messages** (проверить исходные сообщения). Внутренние дословные выдержки не являются отдельными сводками сцен. Вспоминаемый контекст сопровождается временем сюжета из источников; неизвестные даты остаются неизвестными. Можно отключать записи воспоминаний, переиндексировать, экспортировать и импортировать либо подтвердить **Delete all memories** (удалить всю память), чтобы начать подготовку заново, сохранив исходный чат и настройки. Правки исходных ручных сводок сохраняются и делают зависимую непрерывность недействительной. Чтобы исключить сцену из воспоминаний, отключите ее запись памяти. Скрытие источника для отдельных персонажей по-прежнему определяет доступ; глобальное скрытие не удаляет сцену из архива.

В каждой сводке сцены также записано, кто в ней участвовал. Имя участника, которое отличается от карточки персонажа, например "Kaito" для **Kaito Nakamura**, все равно засчитывается, если оно подходит ровно одному персонажу и не может быть именем вашей персоны. Имена, общие для двух персонажей или для персонажа и вашей персоны, описания вроде "Kaito's sister" и имена с пометками вроде "(mentioned)" никогда не дают персонажу доступ. Имя вашей персоны – не ошибка, и доступа персонажам оно не дает. Если вспомогательная модель не сказала, кто участвовал, сцена становится доступна всем персонажам: в чате с одним персонажем – ему, в групповом чате – всем сразу. В групповом чате Advanced Memory считает это проблемой памяти и помечает сцену как **Check who was there** в **Access memories**, чтобы вы могли убрать тех, кого там не было, через **Edit character access** (изменить доступ персонажей) или позволить **Fix** заново спросить вспомогательную модель. Имена, которые не подходят ни одному персонажу, не дают доступа и помечаются так же, чтобы вы могли указать участников сцены. Сцена, в которой, по явному ответу вспомогательной модели, были только вы, остается доступной только рассказчику. Сводки сцен, сохраненные до появления проверки участников, остаются доступными только рассказчику, пока их не проверят: **Fix** и **Prepare existing history** проверяют их все, а каждый ответ, завершающий сцену, дополнительно проверяет до трех. Сцена, автоматическая проверка которой не удалась, ждет **Fix** или **Prepare existing history**.

Персонаж, присутствовавший в части сцены, может иметь доступ к ее воспоминанию вместе с другими участниками, даже если некоторые сообщения от него скрыты. Сцена без доступных исходных сообщений остается недоступной. Новые инструкции резюме обозначают видимость сообщений, описывают общие события обычным текстом и оставляют `{{#if character == "Name"}}…{{/if}}` для приватных разделов. Упоминание отсутствующего персонажа не делает его участником. Если изменится видимость источников или имя персонажа, для которого написано резюме, старое резюме не передается читателям с частичным доступом, пока вы снова не подготовите сцену (**Fix** делает это для каждой такой сцены) либо не проверите условия приватных разделов и не сохраните исправленный текст. Если персонаж присоединяется к чату позже, это не считается изменением, кроме случая, когда ему видна только часть сцены. В резюме, сохраненных более ранними версиями, не записано, для каких персонажей они написаны, поэтому после присоединения персонажа для них нужно один раз запустить **Fix**. Старые резюме без сохраненных сведений о видимости требуют такой же проверки перед частичным доступом; изменение только списка получателей не подтверждает текст. Читатели с доступом ко всем исходным сообщениям по-прежнему могут извлечь воспоминание, а исправленный вручную текст никогда не переписывается незаметно. Эти проверки не вызывают модель при извлечении. Даты и временные рамки сцены являются общими метаданными для всех назначенных участников, даже если часть исходных сообщений скрыта. Дословные фрагменты никогда не включают ни сообщения, скрытые от персонажа, ни шепот. Резюме с частями, предназначенными только для некоторых персонажей, все равно получает фрагмент: он цитирует только сообщения, которые этот персонаж видел в чате, поэтому не раскрывает ничего, чего персонаж еще не видел. Чтобы сообщение не попало в память персонажа, скройте его от этого персонажа. Постоянные Chat Summaries по-прежнему включают сообщения, скрытые от ИИ; условия для персонажей ограничивают доступ к приватным деталям, не исключая эти сообщения из охвата резюме.

В объединенном групповом чате один ответ может говорить за всех персонажей, поэтому извлечение включает то, что помнит хотя бы один персонаж чата. Сцена или приватная часть сводки, известная не всем персонажам чата, помечается списком тех, кому она известна, например "known only to Kaito". Добавление персонажа посреди чата больше не скрывает ранние воспоминания от остальных. Сообщение, скрытое от одного персонажа, по-прежнему не попадает в общую текущую историю, но персонажи, которые могли его видеть, сохраняют воспоминание, помеченное как их собственное. Фрагмент извлеченной сцены цитирует только те сообщения, которые видел каждый персонаж, помнящий эту сцену. Воспоминания, которых нет ни у одного персонажа чата, например сцены, доступные только рассказчику, не включаются. В групповых чатах, где персонажи отвечают по очереди, каждому персонажу по-прежнему доступны только его собственные воспоминания.

Пока Advanced включен, этот режим управляет поиском, поэтому переключатель Standard Recall не вставляет вторую копию. Он также заменяет обычное расписание автоматических сводок Roleplay для этого чата. Отключение Advanced Memory возвращает обычные настройки. Существующие лорбуки и скачиваемые агенты сохраняют собственные правила области действия; Advanced Memory не может сделать произвольный пользовательский или внешний контекст приватным.

### Размещение в пресете

Авторы пресетов могут размещать следующие обычные маркеры содержимого с помощью существующих настроек порядка секций, имени, роли и группы:

| Маркер | Содержимое |
| --- | --- |
| `chat_summary` | Допустимые постоянные записи из Chat Summaries. |
| `current_scene_summary` | Ограниченные исходные фрагменты старой части текущей сцены. |
| `recalled_scenes` | Все выбранные сводки сцен, каждая сразу сопровождается доступным историческим фрагментом. |

В выборе маркеров пресета для извлечения предлагается только **Recalled Scenes**. Существующие `recalled_messages` остаются совместимыми псевдонимами с названием Recalled Scenes. Включенный `recalled_scenes` имеет приоритет; два отдельных раздела не создаются.

Каждый компонент следует формату пресета **XML**, **Markdown** или **None** и кратко объясняет назначение. Пустые компоненты ничего не добавляют. Первое включенное вхождение задает место; без включенного маркера содержимое появляется один раз перед историей для совместимости со старыми пресетами. Отрывки – контекст, не новые текущие сообщения или команды. Расширенные маркеры сцен пусты, когда Advanced Memory выключена.

Предпросмотр использует подготовленную память без вызовов моделей и эмбеддингов. Инициализируйте архив или возобновите неудачную фоновую обработку в панели. Отчет показывает оценку контекста, границу и источники. Если ничего не извлечено, он сообщает причину: более ранних сцен для извлечения не было, в запросе не осталось места или ничего не оказалось подходящим. Итоговый инспектор показывает реально отправленный промпт.

### Ограничения и восстановление

Извлечение избирательно, а сводки могут терять нюансы. Храните важные исправления в исходной переписке или редакторе сводок. Нельзя восстановить незаписанные детали. При отказе эмбеддингов остаются ограниченный лексический поиск и корректная непрерывность; весь архив не вставляется. Если обязательные инструкции или вложение превышают предел промпта, уменьшите их или увеличьте предел. Если резерв ответа не помещается в общий контекст модели, уменьшите выход или выберите модель с большим контекстом. Advanced Memory останавливается, а не молча удаляет инструкции.

## Chat Summary (Roleplay)

**Chat Summary** сжимает старые сообщения в короткие пересказы – записи сводки. Каждую запись пишет либо ИИ, либо вы сами, и каждую можно включить или выключить отдельно. Функция есть только в чатах Roleplay. Сохранение переключателя не блокирует остальные записи; Activate All и Deactivate All сохраняют весь выбор одним запросом.

Откройте **Chat Settings** и разверните раздел **Chat Summary** под разделом **Lorebooks**. На компьютере его можно вынести в отдельное окно (см. [Обзор настроек чата](../chats/chat-settings.md#popping-a-section-out-into-its-own-window)).

### Создание записи сводки

1. В блоке **Summary Scope** выберите **Last**, чтобы свести самые свежие сообщения, или **Range**, чтобы задать конкретный диапазон сообщений.
2. Нажмите кнопку **Generate**, и ИИ напишет запись по этому объему.
3. Либо нажмите кнопку **Write**, чтобы создать пустую запись и набрать пересказ самостоятельно.

Каждая запись в списке показывает заголовок, исходный диапазон или число сообщений и примерный размер в токенах. Запись можно включить или выключить, развернуть, изменить кнопкой **Edit** или удалить кнопкой **Delete**. Групповые кнопки **Show Inactive** и **Hide Inactive** показывают или скрывают неактивные записи, а **Activate All** и **Deactivate All** включают или выключают сразу все.

Отметьте записи флажками, чтобы выбрать их; на компьютере нажмите на другую запись, удерживая Shift, чтобы выбрать видимый диапазон между ними. Затем нажмите **Enable selected** (включить выбранные) или **Disable selected** (выключить выбранные), чтобы изменить только выбранные записи.

В объединенном групповом чате один ответ может говорить за всех персонажей. Часть записи, написанная для определенных персонажей, например `{{#if char == "Kaito"}}…{{/if}}`, сохраняется для всех персонажей чата, к которым она относится, и помечается списком тех, кому она известна, например "known only to Kaito". Части, которые получает только **Narrator** в Advanced Memory, не включаются. В групповых чатах, где персонажи отвечают по очереди, и в чатах с одним персонажем каждый персонаж читает записи так же, как раньше.

### Automatic Summaries

Панель **Automatic Summaries** обновляет сводки по ходу чата. Она есть только в чатах Roleplay.

- Включите переключатель **Enabled** внутри панели **Automatic Summaries**.
- Частоту задайте в поле **Every** – она измеряется в сообщениях пользователя. По умолчанию 5, диапазон – от 1 до 200.
- Кнопка **Backfill Summary** догоняет старый чат, у которого сводок никогда не было. Обработка идет порциями, и во время работы видна полоса прогресса. Нажмите кнопку **Stop**, чтобы прервать ее раньше.

### Шаблоны Summary Prompt

Панель **Summary Prompt** управляет инструкцией, по которой ИИ пишет сводку. Кнопка **Edit** меняет активный промпт. Кнопка **Templates** открывает менеджер шаблонов. Там кнопка **New template** сохраняет промпт под именем. У каждого сохраненного шаблона есть свои кнопки **Duplicate**, **Edit** и **Delete**.

Сохраненные шаблоны – общая настройка всего приложения. Правка или выбор шаблона в одном чате Roleplay меняет промпт сводки во всех чатах Roleplay.

### Подключение Summary Connection и размер ответа

Панель **Summary Connection** выбирает подключение, которое пишет сводки. По умолчанию там стоит **Agent default (falls back to chat connection)**. Это значит, что сначала используется подключение агента по умолчанию, а вторым – собственное подключение чата.

Поле **Maximum output size** задает предельную длину сгенерированной сводки. По умолчанию 4096 токенов, диапазон – от 1 до 32768.

### Параметры отображения

Элементы **Display** в разделе **Chat Summary** решают, как сообщения со сводкой выглядят на экране:

- **Hide summarised messages** – скрывает исходные сообщения, как только их накрывает сводка. По умолчанию выключено.
- **Recent message tail** – сколько самых новых сообщений остаются полностью видимыми даже при включенном скрытии. По умолчанию 10, принимается любое целое неотрицательное число. Значение 0 скрывает всю сведенную порцию. Чем больше значение, тем больше промпт и дороже обращение к модели.
- **Collapse hidden messages** – задает, как скрытые сообщения выглядят в тексте чата.

Если в чате включено подтверждение записи агентом (отдельная настройка в разделе **Agents**), сводки от ИИ ждут вашей проверки и только потом вступают в силу.

## Automatic Summarization (Conversation)

Чаты Conversation работают с другой системой – **Automatic Summarization**. Она подводит итог каждого календарного дня, а затем собирает завершенные недели дневных сводок в недельную сводку. Дальше в промпт уходят только недельные сводки, дневные сводки текущей недели и сегодняшние сообщения. Так каждый запрос остается небольшим.

Эта функция работает сама, и для чатов Conversation ее нельзя выключить.

### Открытие редактора

1. Откройте чат Conversation и нажмите кнопку **Chat Settings**.
2. Найдите раздел **Automatic Summarization** (у него значок календаря).
3. Нажмите кнопку **Edit Summaries** – откроется окно **Automatic Summarization**.

В окне сначала идут недельные записи, а за ними дни, еще не собранные в неделю. Разверните запись, чтобы изменить текст **Summary** и список **Key Details**, где можно добавлять и убирать строки.

### Настройки Day Rollover Hour и Recent Message Tail

Два параметра в разделе **Automatic Summarization** определяют, как делятся дни:

- **Day Rollover Hour** – час, с которого для сводок начинается новый день. По умолчанию 4 AM, выбрать можно любой час от 12 AM (полночь) до 11 AM. Сообщения, отправленные раньше этого часа, относятся к предыдущему дню. Выберите время, когда вы никогда не общаетесь, чтобы ночная сессия не разрезалась пополам.
- **Recent Message Tail** – сколько самых новых сообщений за сегодня остаются дословно даже после того, как попали в сводку. По умолчанию 10, принимается любое целое неотрицательное число. Чем больше значение, тем больше промпт и дороже обращение к модели.

Если изменить **Day Rollover Hour**, когда сводки уже есть, Marinara предупредит, что старые сводки строились по прежней настройке.

### Заполнение пропущенных дней

Иногда день остается без сводки – например, после импорта старого чата. В окне есть панель **Missing Summaries** с кнопкой **Backfill**: она повторяет попытку для недавних дней, у которых сводки нет. За один раз просматриваются до 14 дней назад.

Смена подключения или модели для сводок не переписывает уже существующие дневные и недельные записи.

## Устранение неполадок

### Memory Recall ничего не находит

- Проверьте, что источник эмбеддингов настроен. Если у фрагментов в окне **Memories for This Chat** стоит статус **Embedding unavailable**, настройте раздел **Semantic Search (Embeddings)** в подключении или обойдитесь встроенной локальной моделью. См. [Настройка модели Local Model](../connections/local-model.md).
- Если у фрагментов стоит **Waiting for vector**, дайте им время. Отпечатки строятся после ответов.
- Поиск добавляет только те воспоминания, что тесно связаны с вашим последним сообщением. Если похожего нет, не добавляется ничего. Это нормально.
- Если модель эмбеддингов менялась недавно, нажмите значок обновления в окне **Memories for This Chat**, чтобы старые фрагменты подошли новой модели.

### Сводки не генерируются

- Проверьте, что у чата есть рабочее текстовое подключение. **Chat Summary** берет подключение из панели **Summary Connection**, а **Automatic Summarization** – вычисленное подключение для сводок. Если не работает ни одно, генерация пропускается.
- Если в чате включено подтверждение записи агентом, сводки от ИИ сначала ждут вашего одобрения.
- Неудачная сводка автоматически повторяется через паузу. Если дело застряло, запустите вручную **Backfill Summary** (Roleplay) или **Backfill** (Conversation).
