# Game Mode: броски кубиков и проверки навыков

В этом руководстве вы узнаете, как бросать кубики в режиме Game Mode приложения Marinara Engine. Здесь описаны меню быстрых бросков, собственная запись броска и ограничения на такие броски. Также показано, как Game Master (ведущий игры) проводит проверку навыка против класса сложности DC.

## Броски кубиков

В чате Game Mode на панели ввода сообщения есть кнопка с кубиком. Наведите на нее курсор – появится всплывающая подсказка **Roll dice**. Нажмите эту кнопку, чтобы открыть меню быстрых бросков.

В меню восемь готовых бросков в одно нажатие:

| Вариант | Что бросается |
|---|---|
| d20 | один 20-гранный кубик |
| d6 | один 6-гранный кубик |
| 2d6 | два 6-гранных кубика |
| d10 | один 10-гранный кубик |
| d100 | один 100-гранный кубик |
| d4 | один 4-гранный кубик |
| d8 | один 8-гранный кубик |
| d12 | один 12-гранный кубик |

Чтобы сделать быстрый бросок:

1. Откройте панель ввода сообщения в чате Game Mode.
2. Нажмите кнопку с кубиком.
3. Выберите один из восьми вариантов, например **d20**.
4. В панели ввода появится небольшая плашка вида `🎲 d20`.

Бросок отправляется не сразу, а становится в очередь. Чтобы убрать бросок из очереди, нажмите на плашке кнопку очистки. Ее подсказка – **Clear queued roll**.

Кубики бросаются в момент отправки следующего сообщения. Результат приложение добавляет в конец сообщения отдельной пометкой. Один кубик без бонуса выглядит так:

```
[dice: d20 = 14]
```

Бросок нескольких кубиков или бросок с бонусом показывает еще и слагаемые:

```
[dice: 3d8+2 = 18 (4, 6, 6 +2)]
```

Game Master читает эту пометку и строит свое описание вокруг результата.

Если Game Master делает несколько бросков за ход, каждая карточка броска занимает отдельное место в очереди. Закройте карточку, чтобы увидеть следующую. Все броски сохраняются в активном свайпе (альтернативном ответе) этого хода и остаются в **Logs** (журнале) после перезагрузки. Продолжение хода сохраняет прежние броски; повторная генерация создает отдельный набор для нового свайпа.

Game Master также может запросить бросок в повествовании через `[dice: 3d8+2]`. Движок предоставляет реальные числа и показывает ту же анимированную карточку. Это работает и с подключениями, поддерживающими только текст, включая подписки Claude и Grok. Используются те же обозначения и ограничения, что и в меню кубиков.

## Собственная запись броска

В меню кубиков есть и текстовое поле для собственного броска. Оно принимает стандартную запись `NdM`. Здесь `N` – сколько кубиков бросить, а `M` – сколько у каждого граней. В конце можно добавить бонус или штраф.

Подсказка в поле показывает пример: `3d8+2`. Это значит – бросить три 8-гранных кубика и прибавить к сумме 2.

Чтобы задать свой бросок:

1. Нажмите кнопку с кубиком, чтобы открыть меню.
2. Введите запись в текстовое поле, например `2d6+1`.
3. Нажмите Enter или маленькую кнопку с бумажным самолетиком (отправка) рядом с полем.
4. Бросок встанет в очередь плашкой и будет готов к отправке.

Еще несколько примеров, которые можно ввести:

- `d20` бросает одну 20-гранную кость.
- `4d8-1` бросает четыре 8-гранные кости и вычитает 1.
- `2d6+3` бросает две 6-гранные кости и прибавляет 3.
- `4d6kh3` бросает четыре 6-гранные кости и сохраняет три наибольших результата. `kl` сохраняет наименьшие, а `dh` и `dl` вместо этого отбрасывают наибольшие или наименьшие соответственно, поэтому `2d20kl1` – это бросок с помехой, а `4d6dl1+2` отбрасывает кость с наименьшим результатом и прибавляет 2. Записывается каждая брошенная кость, а складываются только сохраненные результаты.

Есть два жестких ограничения: за раз можно бросить не больше 100 кубиков, а у каждого кубика может быть не больше 1000 граней. Если обычный бросок запрашивает больше, приложение сокращает его до этих пределов, а не отклоняет. Карточка результата показывает сокращенную запись: ввод `500d6` дает карточку `100d6` для ста действительно брошенных кубиков. Бросок с сохранением или отбрасыванием костей, выходящий за пределы, например `101d6kh3`, вместо этого отклоняется с ошибкой выхода за допустимый диапазон, поскольку сокращение числа костей изменило бы то, какие из них сохраняются. Если текст не соответствует записи `NdM` или отдельной записи `dM`, например `d20`, после которой могут стоять `kh`, `kl`, `dh` или `dl` и число, бросок не выполняется, а ошибка указывает ожидаемый формат.

<a id="symbol-dice-by-name"></a>

### Символьные кости по имени

В игре, чей набор правил бросает символьные кости (набор `symbol-pool`, например система в духе Genesys), поле собственного броска также принимает имена этих костей. Укажите количество и имя кости для каждого вида, например `2 ability 1 proficiency vs 2 difficulty`. Именем может быть id кости или ее подпись в любом регистре; разделять их можно пробелами, запятыми, `+` или `vs`.

Карточка показывает каждую кость с символами на выпавшей грани, затем символы, оставшиеся после взаимной отмены, и успешен ли бросок. Пометка, добавляемая к сообщению, содержит то же самое, например `[dice: 2 ability vs 1 difficulty = 1 Success, 1 Advantage; success]`. В одном броске можно указать до 40 костей. Когда Game Master бросает кости своим инструментом, он тоже может использовать эти имена. Обычная запись `NdM` по-прежнему работает во всех играх, как описано выше.

<a id="skill-checks"></a>

## Проверки навыков

Проверка навыка определяет, удастся ли вам что-то рискованное: подкрасться, заметить улику, убедить персонажа NPC (неигровой персонаж). Сами вы проверку не начинаете – ее объявляет Game Master прямо в своем описании. Приложение превращает объявление в анимированный бросок d20 и показывает баннер с результатом.

Проверка, запрошенная текстом, начинается с попытки действия. Движок определяет результаты бросков, затем делает один дополнительный запрос к модели с реальными результатами, чтобы Game Master завершил описание исхода в том же ходе. Это также исправляет черновик, в котором исход был угадан до броска. Дополнительный запрос повторно отправляет промпт и расходует больше входных и выходных токенов. Если он завершается ошибкой, ход сохраняет полученные результаты без угаданного или неполного описания исхода. На ходе остается уведомление с кнопкой **Regenerate turn** (перегенерировать ход), в том числе после перезагрузки чата.

Отключите **Narrate dice outcomes immediately** (сразу описывать результаты бросков) в **Chat Settings → Function Calling** (настройки чата → вызов функций), чтобы сохранить реальные результаты для следующего хода без дополнительного запроса. По умолчанию эта настройка включена. Запросы, в которых не было реальных бросков, никогда не запускают дополнительное описание результатов.

Есть и третий способ: оставить исход в том же ходу без второго запроса. См. ниже [Завершение хода с бросками одним запросом](#finishing-a-rolled-turn-in-one-request).

При подключении с поддержкой инструмента бросков Game Master может получить реальный результат во время генерации. Карточка появляется сразу после ответа инструмента; завершенная проверка сохраняет этот результат без повторного броска. Каждая разрешенная проверка навыка получает отдельный баннер после карточек бросков в очереди.

На баннере видны навык и целевое число, например **Stealth Check** и рядом **DC 15**. DC – это Difficulty Class, класс сложности: число, которого бросок должен достичь или превысить.

### Как определяется результат

При проверке бросается один 20-гранный кубик, а к результату прибавляются два модификатора:

- Модификатор навыка – от уровня навыка, который игра ведет для вашего персонажа. Если уровня для этого навыка еще нет, модификатор равен 0.
- Модификатор характеристики – от той характеристики, которая отвечает за этот навык.

Бросок кубика вместе с двумя модификаторами дает итог. Если итог достигает DC или превышает его, проверка пройдена. Если итога не хватает, проверка провалена. Характеристика для каждого навыка выбирается автоматически. Например, Stealth опирается на Dexterity, Perception – на Wisdom, а Persuasion – на Charisma. Незнакомый приложению навык считается по Intelligence.

### Критический успех и критический провал

Два броска отменяют всю математику:

- Натуральная 20 (на самом кубике выпало 20) – это **CRITICAL SUCCESS** (критический успех). Такая проверка проходит всегда, даже при высоком DC.
- Натуральная 1 (на самом кубике выпала 1) – это **CRITICAL FAILURE** (критический провал). Такая проверка провалена всегда, даже с большими модификаторами.

Баннер показывает один из четырех итогов: **CRITICAL SUCCESS**, **SUCCESS** (успех), **FAILURE** (провал) или **CRITICAL FAILURE**.

### Другие системы костей

Game Master может указать другую запись, например `[skill_check: skill="Endurance" dc="12" dice="3d6+2"]`. Такие проверки используют фиксированный модификатор из записи вместо модификаторов d20 из листа персонажа и успешны, когда сумма достигает DC. Правила натуральной 1 и натуральной 20 действуют только для стандартной проверки d20, описанной выше.

Пулы успехов должны указывать и порог для отдельной кости, и нужное число успехов: `[skill_check: skill="Intimidation" dc="4" dice="6d10" resolution="successes" threshold="6"]` бросает шесть d10, считает каждую кость с результатом не меньше 6 один раз и дает успех при наличии хотя бы четырех успехов. Движок не угадывает отсутствующий порог и не реализует взрывающиеся кости, правила botch или другие особые правила пулов. Пул без корректного порога остается неразрешенным, а выдуманные моделью числа удаляются.

Этот пул не меняется для игр **без набора правил**. Игра с набором для пулов костей следует правилам, которые выполняет движок; см. раздел [Проверки с набором правил](rulesets.md#checks-on-a-ruleset).

Атрибут `dice=` проверки принимает только обычную запись `NdM`. Такие запросы в нем, как `4d6kh3`, `3d6!` или `4dF`, не выполняются. Движок записывает неподдерживаемую запись в лог и удаляет выдуманные числа из записей проверок. Эти исходы остаются неопределенными; движок не заменяет систему костей молча.

### Преимущество и помеха

Game Master может объявить проверку с преимуществом или с помехой. Одновременно и то и другое к одной проверке не применяется.

- С преимуществом приложение бросает два 20-гранных кубика и берет больший результат.
- С помехой приложение бросает два кубика и берет меньший результат.

Если Game Master запросит оба режима одновременно, приложение оставит проверку без обработки, а не станет угадывать намерение, поэтому баннер для нее не появится.

Когда включено одно из двух, баннер показывает этот режим рядом с DC и отмечает, какой кубик пошел в счет.

### Свой бросок заранее

Свой `d20` можно поставить в очередь из меню кубиков заранее, до самой проверки. Тогда проверка навыка возьмет выпавшее у вас число вместо нового броска. Модификаторы навыка и характеристики все равно прибавляются к нему.

<a id="games-that-use-a-ruleset"></a>

## Игры с набором правил

В игре с набором правил, например 5e (SRD 5.1), проверки проводятся по правилам набора: с его собственными костями, шкалой сложности и модификаторами из листа персонажа, а в некоторых наборах правил – с запасом костей или символьными костями. См. раздел [Проверки с набором правил](rulesets.md#checks-on-a-ruleset).

<a id="finishing-a-rolled-turn-in-one-request"></a>

## Завершение хода с бросками одним запросом

Без этой настройки ход с броском требует двух запросов к модели: черновика и переписывания исхода с настоящими числами. **Finish rolled turns in one request** (завершать ходы с бросками одним запросом) в **Chat Settings → Function Calling** убирает второй. Настройка включена по умолчанию; выключите ее в чате, чтобы каждый ход с броском в нем переписывался с настоящими числами.

GM фиксирует текст до появления любого числа. Он не видит бросок до выбора событий и не может подогнать исход под полученную кость. Движок бросает позже и сохраняет собственную запись.

С этой настройкой GM выбирает одну из трех форм по типу результата.

**Если возможны два исхода, он пишет оба.** За проверкой без чисел следует блок с текстами успеха и неудачи. Движок бросает, оставляет выбранную половину и удаляет другую до того, как вы прочтете ход. Видно одно событие, как если бы бросок был первым.

**Если результат – только число, он пишет заполнитель и продолжает.** Урон, лечение, золото, длительность, количество или расстояние: GM вставляет в предложение `[[roll: 2d6+3]]`, а движок подставляет число. Вместо значения можно назвать модификатор листа, например `[[roll: 1d8+STR]]`; движок прибавит его сам. Эта форма предлагается только при наличии читаемого листа. Неизвестное имя отклоняется, а не принимается за ноль. Наведите указатель на подставленное число, чтобы увидеть кости; каждый такой бросок также имеет отдельную строку в **Logs**.

**Если само число выбирает один из трех или более исходов, он запрашивает его и останавливается.** Это прежняя краткая проверка или запрос `[dice:]`. Движок бросает и записывает результат, а ход заканчивается без рассказа об исходе. GM объясняет его в начале следующего хода, как при выключенном **Narrate dice outcomes immediately**.

Проверка вне этих форм использует то же запасное поведение: ни один бросок не пропускается и ничего не выдумывается.

Перед включением учтите:

- **Narrate dice outcomes immediately временно не используется.** Переключатель виден, но недоступен и снабжен пояснением. Сохраненное значение остается; после выключения режима одного запроса прежняя настройка снова действует.
- **Существующие ходы не меняются.** Настройка влияет только на новые ходы, не переписывая сохраненную историю.
- **В двух случаях ход все еще может стоить нескольких запросов.** Если включено **Enable Tool Use** и инструмент костей есть в списке, GM может вызвать его, что стоит полного дополнительного раунда. **Game tool connection**, отличное от **Same as narrator**, всегда делает собственный запрос планирования. Это не переписывание исхода, которое убирает переключатель.
- **Если бросок невозможен, вы узнаете об этом.** Нечитаемое число заменяется коротким уведомлением, а не выдуманным значением. Нечитаемое разветвление оставляет записанный бросок и удаляет оба текста. В обоих случаях **Logs** поясняет, что пропущено.
- **Во время написания** заполнители и блоки ветвления скрыты в потоке текста: число не появляется с последующей заменой. Готовое предложение показывается после завершения хода.

### Показ GM одной кости каждого размера

Ниже находится **Let the Game Master see one die of each size** (позволить GM видеть одну кость каждого размера), выключенное по умолчанию. Оно предназначено для случая, который не покрывают две слепые формы: число выбирает минимум три исхода, например степень успеха, запись в таблице попаданий или бросок реакции. Без него проверка заканчивает ход, а рассказ ждет начала следующего.

При включении движок перед ходом бросает по одной кости стандартных размеров и показывает GM следующее значение каждой. GM может потратить одну и описать ее смысл за тот же проход.

**Внимательно прочитайте об этом компромиссе.** GM видит число до выбора проверки и ее сложности. Он может направлять исход иначе, чем в слепых формах: выбрать сложность, которую пройдет известная кость, или вовсе не запрашивать проверку, пока держит плохое число. Движок не умеет определять, подходит ли сложность истории, поэтому не может это обнаружить. Игрок, не знающий, что GM видел кости, может принять подозрительно героическую сессию за удачу.

Независимо от сотрудничества GM движок обеспечивает следующее:

- **Значения выдаются по порядку и только один раз.** Движок владеет очередью и выдает следующее значение независимо от текста хода.
- **Каждое число в записи принадлежит движку.** Бросок, модификатор, сумма и исход пересчитываются из очереди и листа. Несовпадающее число GM заменяется с отметкой в **Logs**.
- **Сложность ограничена.** Она остается в диапазоне 1–40, чего прежде не требовали от проверок в тексте. Игра с набором правил может вместо этого использовать его шкалу сложности.
- **Повторный вопрос не улучшает удачу.** Свайп, повторная генерация и продолжение того же хода получают те же значения: перебирать броски до удачного не получится.
- **Видно лишь следующее значение каждого размера.** Это задает **Values shown per size** (показываемые значения каждого размера), по умолчанию 1. Дальнейшие броски того же размера за ход остаются невидимыми и описываются лишь в следующем ходу.
- **Неиспользованная кость через некоторое время бросается заново.** Это задает **Rethrow after idle turns** (перебросить после ходов без использования), по умолчанию 3. Иначе плохое число могло бы оставаться в начале очереди весь чат, пока GM избегает этого размера. Значение 0 отключает переброс и снова допускает такое поведение.
- **Запрос сверх запаса не дает броска.** Проверка сохраняет вопрос, теряет числа и описывается в следующем ходу. **Logs** указывает, в каком ходу это произошло.
