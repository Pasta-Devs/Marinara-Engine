# Раскадровки LTX 2.3 в Game Mode

В этом руководстве локальный рабочий процесс ComfyUI для LTX 2.3 (изображение в видео) подключается к раскадровкам режима Game Mode в приложении Marinara Engine. Некоторые игроки называют это Story Mode; в приложении Marinara элементы называются **Game Mode** (режим игры) и **Storyboards** (раскадровки).

Описанная ниже конфигурация собиралась с генерацией первого кадра через **Krea 2** и со стилем изображений **Z-Image Turbo Narrative**, который написан на естественном языке. Другие подключения для изображений тоже должны работать, если они принимают описательные промпты сцены на естественном языке. Промпт – это текст, который Marinara отправляет ИИ. Видео LTX собирается локально в ComfyUI. Локальной или удаленной будет генерация первого кадра – зависит от выбранного подключения для изображений.

Итоговый путь выглядит так:

```text
GM narration
  -> Animation Planner
     -> imagePrompt -> image connection -> first-frame illustration
     -> narrationBeat -> Narration Passthrough -> %prompt%
  -> first frame + prompt -> ComfyUI LTX 2.3 workflow -> MP4 clip
```

Сгенерированная иллюстрация становится первым кадром клипа. Поэтому LTX получает и визуальную отправную точку, и промпт, который сосредоточен на дальнейшем движении.

## Перед началом

Что нужно:

1. Работающая локальная установка ComfyUI, доступная приложению Marinara.
2. Редактируемый рабочий процесс `ltx-director-simple` или равнозначный граф LTX 2.3 (изображение в видео), который успешно проходит внутри ComfyUI.
3. Его экспорт в формате API – файл `ltx-director-simple-api` – для подключения в приложении Marinara.
4. Подключение для генерации изображений, из которого берутся иллюстрации первого кадра.
5. Агент **Storyboard**, установленный через **Agents > Download Agents** и включенный для игры в **Chat Settings > Agents**.

Редактируемый рабочий процесс ComfyUI и его экспорт в формате API – это разные файлы. Откройте `ltx-director-simple` в ComfyUI, установите все недостающие пользовательские узлы, о которых сообщает ComfyUI Manager, и проверьте граф там же. Файл `ltx-director-simple-api` импортируйте в подключение приложения Marinara. После каждой замены узла или модели экспортируйте граф в формате API заново и замените JSON, сохраненный в подключении. Обычный рабочий процесс из визуального редактора вставлять в Marinara нельзя.

Общий порядок экспорта и настройки подключения описан в руководстве [Настройка рабочего процесса ComfyUI](../media/comfyui.md).

## Выбор модели LTX 2.3

Формат модели выбирайте под архитектуру GPU и под ту память, которая остается после загрузки текстового энкодера, VAE и апскейлера в ComfyUI. Значения ниже – отправные точки, а не обещание, что любой рабочий процесс поместится на любую карту.

| Семейство GPU | Практическая отправная точка | Примечания |
| --- | --- | --- |
| Серия RTX 30 (Ampere) | INT8 ConvRot | Отправная точка при нехватке памяти для карт класса 3070, 3080 и 3090. |
| Серия RTX 40 с 16-24 ГБ | FP8 input-scaled | Использует ускоренный путь FP8, доступный на оборудовании поколения Ada. |
| Серия RTX 40 с 8-12 ГБ | INT8 ConvRot, если выгрузка при FP8 слишком медленная | Сравните оба варианта на своем рабочем процессе: объем VRAM и поведение выгрузки все равно важны. |
| Серия RTX 50 (Blackwell) | Рабочий процесс NVFP4 dev | Нужны ComfyUI, CUDA и набор узлов с поддержкой NVFP4. |
| RTX 50 с уже существующим рабочим процессом distilled | FP8 input-scaled | Этот путь совместимости нужен до появления официального чекпоинта distilled в формате NVFP4. |

В проверенном рабочем процессе для RTX 3080 используется:

```text
ltx-2.3-22b-distilled-1.1_transformer_only_int8_convrot.safetensors
```

Эти суффиксы обозначают разные форматы квантования и разные пути исполнения, а не уровни качества, которые всегда можно поменять на месте:

- **INT8 ConvRot** – практичный путь сообщества для малой памяти: карты серии RTX 30 и младшие карты Ada.
- **FP8 input-scaled** использует ускоренные матричные операции FP8 – примерно на оборудовании NVIDIA серии RTX 40 и новее.
- **NVFP4** – четырехбитный путь, родной для Blackwell; его использует рабочий процесс для серии RTX 50.
- Рабочие процессы **Dev** и **distilled** исходят из разных допущений о сэмплировании. Не подставляйте чекпоинт dev в приложенный граф distilled, не переделав под него сам рабочий процесс.

На карте с 8 ГБ первый совместный тест лучше начинать с 480p и одного ключевого кадра. То, что чекпоинт поместился, еще не значит, что поместится более длинное видео или видео с большим разрешением: память тратят также латенты видео, текстовый энкодер, VAE, звук и апскейлинг.

В официальном рабочем процессе для начинающих используются такие компоненты:

- `ltx-2.3-22b-dev-fp8.safetensors`
- `ltx-2.3-22b-distilled-lora-384.safetensors`
- `gemma_3_12B_it_fp4_mixed.safetensors`
- `ltx-2.3-spatial-upscaler-x2-1.1.safetensors`

В собственных рабочих процессах может использоваться чекпоинт distilled v1.1, сторонний вариант квантования, другие узлы загрузки или другие папки моделей. Имена файлов, сохраненные в рабочем процессе формата API, должны в точности совпадать с файлами, которые видит ComfyUI.

## Подготовка рабочего процесса ComfyUI в формате API

Сначала поставьте редактируемый рабочий процесс в очередь прямо в ComfyUI – с настоящим исходным изображением и простым промптом. Убедитесь, что он сохраняет файл MP4 со звуком, и только потом приспосабливайте его экспорт формата API для приложения Marinara.

Простой путь в приложении Marinara использует один готовый промпт во входе глобального промпта узла LTX Director:

```json
{
  "global_prompt": "%prompt%",
  "local_prompts": "",
  "segment_lengths": ""
}
```

Узел LTX Director при этом по-прежнему может отвечать за обусловливание изображением, направляющие данные, звук и две стадии сэмплирования. Слово "простой" относится только к договору о промпте: Marinara отправляет один связный абзац для перехода из изображения в видео, а не таймлайн Prompt Relay.

### Обязательные подстановки

Замените соответствующие значения в экспорте формата API на подстановки Marinara в кавычках:

| Подстановка | Что подставляется |
| --- | --- |
| `%prompt%` | Готовый промпт, который создают выбранный **Animation Planner** (планировщик анимации) для раскадровки и шаблон видео |
| `%reference_image_name%` | Изображение первого кадра, загруженное в ComfyUI |
| `%duration_seconds%` | Длительность клипа раскадровки в секундах |
| `%length%` | Та же длительность, переведенная в кадры по договору Marinara – 16 FPS |
| `%fps%` | Частота кадров, которую Marinara использует для клипа |
| `%width%`, `%height%` | Размеры, взятые из разрешения и соотношения сторон подключения для видео |
| `%seed%` | Новое случайное начальное число для запроса |
| `%model%` | Необязательное значение модели из подключения – если рабочий процесс не задает модель в узле загрузки жестко |

Опорное изображение лежит внутри массива `segments` в `timeline_data` узла LTX Director. В рабочем процессе формата API `timeline_data` – это сериализованная строка JSON. Подстановка `%length%` держит длительность клипа динамической через `normalDurationFrames`; у сегмента с опорным изображением на нулевом кадре намеренно остается собственное короткое фиксированное значение `"length":16`:

```json
{
  "timeline_data": "{\"global_prompt\":\"\",\"normalStartFrame\":0,\"normalDurationFrames\":%length%,\"segments\":[{\"id\":\"marinara-reference\",\"start\":0,\"length\":16,\"prompt\":\"\",\"type\":\"image\",\"imageFile\":\"%reference_image_name%\",\"isEndFrame\":false}],\"motionSegments\":[],\"audioSegments\":[]}"
}
```

Не ставьте `%reference_image_name%` рядом с `timeline_data` или в отдельное поле изображения верхнего уровня. Число кадров, секунды и частоту кадров держите связанными с внешними входами рабочего процесса через `%length%`, `%duration_seconds%` и `%fps%`; числовые значения, которые показывает редактируемый граф ComfyUI, – это не значения Marinara по умолчанию.

Строковые подстановки вроде `%reference_image_name%` оставляйте в кавычках. Точные числовые входы узлов могут заключать `%length%`, `%duration_seconds%` и `%fps%` в кавычки – Marinara превращает их в числа. Внутри сериализованной строки `timeline_data` оставьте `%length%` без кавычек, как показано выше, чтобы в раскодированном таймлайне значение было числовым.

### Экспорт после каждого изменения

1. Поставьте редактируемый рабочий процесс в очередь в ComfyUI.
2. Проверьте, что текущий граф выдает воспроизводимый файл MP4.
3. Выберите **Save (API Format)**, **Export (API)** или **Export to API**.
4. Добавьте подстановки в новый файл JSON формата API или проверьте, что они на месте.
5. Замените рабочий процесс, сохраненный в подключении приложения Marinara.

Если узел удален, а старый экспорт формата API остался в работе, в нем сохраняются ссылки на несуществующий узел. Тогда ComfyUI отклоняет запрос еще до начала генерации.

## Создание подключения для видео

1. Откройте панель **Settings** (настройки), затем раздел **Connections** (подключения).
2. Добавьте подключение типа **Video Generation** (генерация видео).
3. Выберите **ComfyUI**.
4. Введите базовый адрес ComfyUI – обычно это `http://127.0.0.1:8188`, если он запущен на том же компьютере.
5. Вставьте полный рабочий процесс формата API в поле **ComfyUI Workflow**.
6. Для первого теста при малом объеме VRAM выберите длительность по умолчанию шесть секунд, **16:9** и 480p.
7. Сохраните подключение.

Проверка подключения только по тексту не задействует `%reference_image_name%`. После сохранения подключения проверьте переход из изображения в видео на изображении из раздела **Gallery** (галерея) или на раскадровке.

## Настройка чата Game Mode

Откройте чат Game Mode, затем откройте панель **Chat Settings** (настройки чата) и перейдите в раздел **Agents** (агенты). Включите **Enable Agents** и **Enable Storyboards**, прежде чем настраивать разделы ниже. Стиль подачи Storyboard Optimized в мастере создания игры агента не включает.

### Раздел **Illustrator**

| Настройка | Рекомендуемое значение |
| --- | --- |
| **Game Illustrator** | On |
| **Image Connection** | **Krea 2** |
| **Image Style** | **Z-Image Turbo Narrative** |
| **Use Campaign Art Style** | Off |
| **Attach Card Appearance** | Off |
| **Send Avatar References** | Off для этого проверенного рабочего процесса |

**Animation Planner** и так получает описание внешности персонажей для хода раскадровки. Поэтому здесь **Attach Card Appearance** выключен: иначе та же информация добавится еще раз при итоговом форматировании изображения. Формат **Storyboard First Frame** тоже не повторяет художественные указания кампании вокруг готовой сцены T=0 от планировщика.

Переключатель **Send Avatar References** управляет опорными изображениями, которые уходят провайдеру изображений первого кадра, а не входом первого кадра для LTX. LTX получает готовую иллюстрацию раскадровки через `%reference_image_name%`. В этой проверенной конфигурации с Krea опорные аватары оставьте выключенными. Включать их стоит отдельно и только после того, как выяснится, что выбранное подключение для изображений их поддерживает и от них выигрывает.

Изображение первого кадра сильно влияет на качество анимации. На нем должен быть виден тот самый момент прямо перед запланированным движением, причем персонаж, путь, руки, дверь, предмет или цель должны читаться отчетливо.

### Раздел **Scene Videos**

| Настройка | Рекомендуемое значение |
| --- | --- |
| **Video Connection** | Созданное выше подключение к ComfyUI для LTX 2.3 |
| **Game Video Prompt** | **Narration Passthrough** |

Общая настройка **Game Video Prompt** отвечает за анимации, которые запускаются вручную из раздела **Gallery** и из раздела **Game Assets**. У клипов раскадровки может быть свой промпт – остальные действия с анимацией от этого не меняются.

### Раздел **Storyboards**

Начните с такого набора настроек:

| Настройка | Рекомендуемое начальное значение |
| --- | --- |
| **Automatic Storyboard Illustrations** | On |
| **Automatic Storyboard Animations** | On |
| **Use NovelAI Character Prompts** | Off |
| **Keyframes per Turn** | обычно 3; для первой проверки на 8 ГБ VRAM начните с 1 |
| **Animation Clip Duration** | 5 секунд |
| **Viewer Display** | Floating на время тестов |
| **Illustration Planner** | **Still Keyframes**; остается запасным вариантом для режима без анимации |
| **Animation Planner** | **LTX Simple Image-to-Video** |
| **Use Storyboard Template** | On |
| **Storyboard Illustration Prompt** | **Storyboard First Frame** |
| **Storyboard Video Prompt** | **Narration Passthrough** |

**LTX Simple Image-to-Video** – рекомендуемый вариант по умолчанию. Он планирует один первый кадр, готовый к анимации, и один прямой промпт движения на 4-8 предложений. Ставка делается на одно главное действие, одно поведение камеры, сдержанное движение окружения и уместный звук или короткую реплику.

**LTX Director Storyboard** остается вариантом для продвинутых. Он дает более подробные указания с учетом длительности и правила связности. Попробуйте его, когда простой путь уже работает стабильно или когда длинному клипу действительно нужно несколько связанных фаз. Оба планировщика работают по одному и тому же договору рабочего процесса с `%prompt%`.

Пока анимации включены, вариант **Still Keyframes** в **Illustration Planner** промпт для Krea не создает. В режиме анимации оба результата создает **LTX Simple Image-to-Video**: `imagePrompt` на естественном языке для Krea и `narrationBeat` для LTX. Выбор **Still Keyframes** нужен только для ходов, которые генерируются без видео.

**Storyboard First Frame** передает Krea готовую сцену T=0 от **Animation Planner** на естественном языке как есть – без заголовка ключевого кадра, подписей промпта, повторного описания внешности и художественных указаний кампании. Оставьте **Use Storyboard Template** включенным, иначе это форматирование не применится.

**Narration Passthrough** намеренно сделан коротким. Он проводит готовый `narrationBeat` от **Animation Planner** через универсальный договор промпта для видео и не обкладывает его еще одним пересказом сцены.

Каждый ключевой кадр создает одну задачу изображения в Krea и одну локальную задачу видео в LTX. Значит, три ключевых кадра запускают три отрисовки первого кадра и три отрисовки видео. На видеокарте с 8 ГБ VRAM начните с одного ключевого кадра в 480p. Когда он получится, переходите к трем ключевым кадрам и более высоким разрешениям.

## Первый тест

Возьмите завершенный ход GM (ведущего игры) с одним очевидным зримым действием: открыть дверь, посмотреть в сторону звука, сделать несколько шагов или произнести одну короткую фразу.

1. Для самой быстрой проверки при малом объеме VRAM временно поставьте **Keyframes per Turn** в 1, а **Animation Clip Duration** оставьте на 5 секундах. В обычной проверенной конфигурации используется 3 ключевых кадра.
2. Включите обе автоматические настройки раскадровки после того, как текущий ход GM уже завершен.
3. Откройте раздел **Gallery** и выберите **Create storyboard** для этого завершенного хода GM. Так весь путь от иллюстрации до анимации запускается вручную, без ожидания следующего хода.
4. Если показ промптов включен, просмотрите промпт первого кадра перед отправкой.
5. Убедитесь, что на сгенерированном первом кадре поза действительно годится как начальная.
6. Дождитесь отрисовки первого кадра, а затем готового клипа из ComfyUI.
7. Когда ручной путь заработает, верните **Keyframes per Turn** на 3 и оставьте обе автоматические настройки включенными для следующих ходов.

На этапе настройки держите режим просмотра **Floating**: так проще рассмотреть каждое изображение и каждый клип. Когда рабочий процесс работает надежно, переключитесь на **Background**, если хотите, чтобы медиа раскадровки встраивались в сцену Game Mode.

## Как промпт передается дальше

Для каждого ключевого кадра **Animation Planner** возвращает:

- `imagePrompt` – только то, что видно на первом кадре в момент T=0;
- `narrationBeat` – полный промпт LTX для перехода из изображения в видео: что происходит дальше.

Оба поля заполняет выбранный **Animation Planner**. **Storyboard First Frame** форматирует `imagePrompt` и отправляет эту сцену T=0 на естественном языке в Krea 2. Когда изображение готово, **Narration Passthrough** разворачивается в `narrationBeat`. Marinara подставляет его в поле `prompt` обычного запроса на видео, заменяет `%prompt%` в рабочем процессе ComfyUI, загружает первый кадр и заменяет `%reference_image_name%` его именем файла в ComfyUI.

Создавать два локальных сегмента промпта не нужно. Для этих пресетов раскадровки обычный путь – один глобальный промпт.

## Каким должен быть хороший промпт для LTX

Исходное изображение уже задает внешность персонажа, композицию, место, освещение, палитру и текстуру. Промпт для видео должен сосредоточиться на движении:

- один связный абзац в настоящем времени;
- одно сфокусированное действие, которое укладывается в длительность клипа;
- движение камеры, описанное относительно персонажа;
- зримые реакции – взгляд, лицо, поза, дыхание, жест;
- не больше одного полезного движения в окружении;
- фоновый звук, эффекты, музыка или короткая реплика в кавычках, если они к месту;
- естественное завершение, затухающее движение или короткая пауза в конце.

Избегайте смены сцен, склеек, телепортации, нескольких несвязанных действий, сложной физики, перегруженной хореографии, точного читаемого текста и повторных перечислений деталей, которые уже видны на первом кадре.

Пример:

```text
She pushes the door open and walks outside as the camera follows closely behind her. A light breeze moves her hair while her pace remains steady. She glances toward the empty street and says, "Stay close." Footsteps and distant traffic continue as the camera settles behind her.
```

## Запись воспроизводимой конфигурации

Результат "на 8 ГБ" зависит не только от чекпоинта. Делясь рабочим процессом, укажите:

- точную модель GPU и объем VRAM;
- версию или коммит ComfyUI;
- версии драйвера NVIDIA, CUDA, PyTorch и Python;
- нужные пакеты пользовательских узлов и их версии;
- точные имена файлов моделей и папки ComfyUI, где они лежат;
- разрешение на выходе, длительность, число ключевых кадров и примерное время отрисовки;
- работает ли Krea 2 локально или через удаленное подключение для изображений в этой конфигурации.

Приложенный файл JSON формата API хранит снимок идентификаторов узлов, путей к моделям и имен входов. Если модели лежат в другой папке, например `LTX2/`, значения в узлах загрузки нужно поправить и экспортировать свежую копию формата API. Рабочий процесс, который идет в ComfyUI у автора, может отказать в другом месте: отличается пользовательский узел или путь к модели.

## Устранение неполадок

### ComfyUI отвечает HTTP 400 или "Prompt outputs failed validation"

Рабочий процесс формата API не совпадает с тем графом, который установлен сейчас. Ищите удаленный узел, висящий идентификатор узла, отсутствующий пользовательский узел, вход, переименованный после обновления узла, или имя файла модели, которого больше нет. Экспортируйте свежий рабочий процесс формата API из работающего графа ComfyUI.

### Изображения создаются, а видео нет

Проверьте настройку **Automatic Storyboard Animations** и **Video Connection** в режиме Game Mode. Для анимации нужны и иллюстрация первого кадра, и выбранное подключение для видео.

### LTX не получает начальное изображение

Убедитесь, что `%reference_image_name%` есть в сохраненном рабочем процессе формата API и что он подается в сегмент изображения узла LTX Director. Marinara загружает первый кадр только при наличии этой подстановки.

### Клип расплывается, меняет персонажей или превращается в хаос

Вернитесь к **LTX Simple Image-to-Video**, оставьте один ключевой кадр и проверьте ход с одним действием. Одно исходное изображение не может чисто превратиться в несколько мест, поз и исходов за короткий непрерывный клип. Посмотрите и на первый кадр: путаная начальная поза усложняет задачу анимации даже при хорошем промпте движения.

### Все генерации выходят слишком похожими

Замените жестко заданное начальное число сэмплирования на `%seed%`. Когда получится удачный результат, фиксируйте это число в рабочем процессе временно – только чтобы сравнить изменения промпта или сэмплирования.

### Генерации не хватает памяти

Начните с 480p. Если нужно, следующим шагом сократите длительность. На время тестов держите один ключевой кадр на ход, закройте другие программы, использующие GPU, и не оставляйте локальную языковую модель загруженной на том же GPU с малым объемом VRAM. Квантованный чекпоинт уменьшает память под саму модель, но не убирает память, которую занимают латенты видео, текстовый энкодер, VAE, звук и апскейлинг.

### Marinara перестает ждать, а ComfyUI продолжает отрисовку

Если запрос в браузере закрыт или связь с клиентом потеряна, опрос со стороны Marinara прекращается, но задача, уже стоящая в очереди ComfyUI, не отменяется. Прежде чем запускать ту же отрисовку заново, посмотрите очередь, историю и папку вывода в ComfyUI.

### Рабочий процесс работает в ComfyUI, но не работает из приложения Marinara

Сравните JSON, сохраненный в подключении, с самым свежим экспортом формата API. Проверьте базовый адрес, написание подстановок, нужные пользовательские узлы, пути к моделям, узел вывода, размеры и поля длительности. Редактируемый граф может работать, пока в приложении Marinara лежит устаревший снимок экспорта.

Для подробных трассировок сервера включите уровень логирования debug и ищите `[debug/game/storyboard-video]` и `[video-gen/comfyui]`. В исправном запросе видны готовый глобальный промпт, имя файла загруженного опорного изображения, длительность, число кадров и идентификатор промпта, поставленного в очередь ComfyUI.
