# Проверка готовности интеграции подписки через Antigravity CLI

Это исследовательская заметка для разработчиков по [#8143](https://github.com/Pasta-Devs/Marinara-Engine/issues/8143), проверенная 2026-10-23. В приложении Marinara Engine **нет** подключения к Antigravity по подписке. Остается обязательное условие: поддерживаемый и проверяемый способ запретить выполнение инструментов CLI и глобальных настроек, включая обработчики событий жизненного цикла, во время запроса генерации текста из движка.

## Подтвержденные официальные интерфейсы

Официальная CLI `agy` поддерживает вход в аккаунт по сохраненным учетным данным и генерацию текста без интерактивного интерфейса. Документированный протокол включает события `init`, `step_update` и `result`; для потокового ввода сообщения пользователя передаются в формате JSON через stdin. Команда `agy models` перечисляет доступные модели, включая документированные примеры `gemini-4-argon-high` и `gemini-4-argon-medium`. Доступность моделей для аккаунта нужно получать из установленной CLI, а не выводить из этих примеров. Параметр `--print-timeout 0` ожидает завершения, а `--disable-slash-commands` отключает раскрытие команд в режиме print. См. [режим без интерактивного интерфейса](https://www.antigravity.google/docs/cli/headless/) и [справочник параметров CLI](https://www.antigravity.google/docs/cli/reference/).

Для входа в аккаунт CLI использует хранилище учетных данных операционной системы. Отдельный режим с API-ключом Gemini требует `modelProvider: "gemini"` и `GEMINI_API_KEY`; адаптер подписки не должен незаметно выбирать этот способ оплаты. Документированные способы программной аутентификации Python SDK – API-ключи Gemini, учетные данные Vertex/Google Cloud и локальные модели. Они не подтверждают аутентификацию по потребительской подписке для замены CLI на SDK. См. [аутентификацию](https://www.antigravity.google/docs/install/#programmatic-authentication) и [обзор SDK](https://www.antigravity.google/docs/sdk/overview/).

## Отсутствующая гарантия изоляции выполнения

Официальные определения пользовательских агентов предоставляют настройки инструментов, MCP и персонализации. В журнале изменений также описаны `inheritCustomizations`, `inheritMcp` и `excludeDefaultComponents`. Однако в объявлении `excludeDefaultComponents: true` явно сохранены обработчики событий после вызова модели. Поэтому сама эта настройка не доказывает, что запрос генерации текста исключает все исполняемые обработчики. См. [пользовательские подагенты](https://www.antigravity.google/docs/subagents/) и [журнал изменений CLI](https://www.antigravity.google/docs/changelog).

Обработчики событий могут поступать из рабочего пространства, глобального файла `~/.gemini/config/hooks.json` и установленных плагинов. Они охватывают события сессии, вызова модели, инструментов и остановки. В текущей документации настроек и [официальной схеме настроек](https://antigravity.google/schemas/v1/settings.json) прямо сказано, что запись `hooks` в `settings.json` не загружается. Пустая запись в этом файле не отключит настоящие источники обработчиков. См. [обработчики событий](https://www.antigravity.google/docs/hooks) и [настройки CLI](https://www.antigravity.google/docs/settings?tab=cli).

Документированные параметры и настройки CLI не предоставляют отключение обработчиков для отдельного запроса или изолированный каталог конфигурации/профиля с сохранением аутентификации аккаунта. Доступный только для чтения список `/hooks` дает полезные сведения, но документация не гарантирует, что последующий вызов модели использует неизменную конфигурацию без обработчиков. Смена каталога, пустой список `tools`, инструкция не использовать инструменты или прерывание после запуска не доказывают изоляцию выполнения.

Отчеты о сторонних интеграциях служат направлениями для исследования. Утверждения о бездействующих инструментах, журналах разрешения агентов или наследовании персонализации нужно воспроизвести на официальном выпуске, прежде чем движок сможет считать их гарантией.

## Локальная проверка выпуска

[Официальный установщик](https://antigravity.google/cli/install.sh) и его [манифест выпуска для Darwin ARM64](https://antigravity-cli-auto-updater-974169037036.us-central1.run.app/manifests/darwin_arm64.json) были изучены без запуска установщика. Манифест выбрал [версионированный архив `agy` 1.4.6 для Darwin ARM64](https://storage.googleapis.com/antigravity-public/antigravity-cli/1.4.6-4884751325200384/darwin-arm/cli_mac_arm64.tar.gz) со следующей суммой SHA-512:

```text
25af49004dd6d6013e6231278e2711b95641c8e54b661be871b3519c0a850053d4e707f46b47aa66e84ff9480041b13908194b48b1a97f84f2a22071d9c9fd3f
```

Контрольная сумма архива совпала. Двоичный файл был распакован во временный каталог этой задачи. Выполнялись только `--version` и `--help`, в песочнице macOS, запрещавшей доступ к сети, чтение/запись домашнего каталога и доступ к службе связки ключей. Оба вызова завершились успешно. В справке не было параметров отключения обработчиков, изолированного профиля или каталога конфигурации.

Эта проверка **не** устанавливала и не аутентифицировала CLI, не изучала учетные данные, не вызывала модель, не перечисляла модели авторизованного аккаунта и не тестировала выполнение обработчиков событий. Она подтверждает публичный список параметров, но не доказывает невозможность изоляции и не проверяет генерацию по подписке.

## Необходимые доказательства перед выпуском адаптера

1. Установите поддерживаемый способ исключить глобальные и локальные для рабочего пространства обработчики событий, плагины, навыки, правила, подагенты, серверы MCP и способные выполнять действия инструменты до того, как любой запрос сможет их запустить. Обычный вход в аккаунт должен оставаться внутри официальной CLI; не извлекайте и не копируйте токены.
2. Проверьте этот механизм с настоящей официальной CLI и контролируемыми локальными заглушками моделей. Подготовьте наблюдаемые тестовые маркеры в глобальных обработчиках и обработчиках рабочего пространства, а также в плагинах/MCP, вместе с правилами и запросами инструментов. Проверьте как изолированный запуск, так и отрицательные контрольные прогоны, показывающие, что без изоляции маркеры наблюдаемы.
3. Докажите до выполнения, что CLI корректно находит выбранного пользовательского агента. Отклоняйте неподдерживаемые версии, имена агентов, которые не удается найти, неизвестные форматы списков и неубедительные результаты проверок изоляции; не полагайтесь на внутренние формулировки журналов или кажущийся пустым список инструментов при запуске.
4. Добавьте ограничения ввода/вывода подпроцесса, закрытые временные файлы и их очистку, отмену, обработку ненулевых кодов завершения и ошибок результата, а также тесты тайм-аутов с учетом активности, включая долгое рассуждение без видимого текста. Получайте модели конкретного аккаунта официальной командой и сохраняйте выбранную модель и поддерживаемый уровень усилий.
5. Используйте существующие контракты подключений/провайдеров. Параметры SDK для Claude, такие как `settingSources: []`, относятся только к этому провайдеру и не могут переноситься в `agy`. Явно указывайте оставшиеся пробелы проверки настоящей аутентификации, оплаты подписки и физических платформ.

Пока граница выполнения не установлена, #8143 остается открытой, а запись провайдера для среды выполнения добавлять нельзя.
