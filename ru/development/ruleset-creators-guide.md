# Руководство для авторов наборов правил

Эта страница поможет спланировать набор правил Game Mode для вашей настольной системы, прежде чем переходить к справочным страницам. Здесь объясняется, как связаны части набора правил, какие решения важнее всего и чему нас научил перенос 16 очень разных систем. Справочник по отдельным ключам начинается со страницы [Создание наборов правил Game Mode](../extending/writing-rulesets.md), а каждый раздел ниже ссылается на страницу, содержание которой он обобщает.

Набор правил – это один JSON-файл (или пакет файлов), который объясняет Marinara Engine, как работает ваша система. Затем Engine выполняет каждую проверку, применяет каждое изменение листа и может проводить целые бои по вашим правилам. В наборе правил нет кода, поэтому вы проектируете систему, заполняя механику, которую Engine уже знает. Если механика ему неизвестна, нужен запрос функции для Engine.

Для каждого ключа ниже указана минорная версия Capability API, в которой он появился. Пакет, использующий этот ключ, объявляет эту минорную версию или более новую (см. [Версии, тестирование и публикация](#versioning-testing-and-publishing)).

Два понятия легко перепутать:

- **Classic и Tactical** – это _стили боя_: бой через меню с передним и задним рядами или бой на поле. Любая игра, с набором правил или без него, использует один из них.
- **Собственные правила Marinara** используются в игре, когда у нее нет набора правил. Набор правил заменяет их.

## Устройство набора правил

Набор правил – один JSON-файл размером до 512 KB, который целиком проверяется при импорте. Более крупные наборы выносят каталоги в пакет. Начните с копии примера, наиболее близкого к вашим кубикам:

- [`ember-roads.json`](../examples/rulesets/ember-roads.json): 2d6 плюс характеристика.
- [`gravewatch.json`](../examples/rulesets/gravewatch.json): пул d10.
- Полный [пакет 5e (SRD 5.1)](https://github.com/Pasta-Devs/Marinara-Agents/tree/staging/packages/ruleset-5e-2014) в Marinara-Agents.

Укажите редактору [JSON Schema](../extending/ruleset.schema.json) строкой `$schema`, чтобы включить автодополнение и проверку опечаток.

| Ключ | Содержимое | Справочник |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `schemaVersion`, `id`, `version`, `name`, `edition`, `license` | Идентификационные данные. `version` – целое число, которое повышается при каждой публикации изменения | [Создание наборов правил](../extending/writing-rulesets.md) |
| `coverage` | Что охватывает набор правил (проверки, бой и так далее) и краткое описание в одну строку для мастера настройки | [Создание наборов правил](../extending/writing-rulesets.md) |
| `resolution` | Как бросается проверка: один из пяти видов, а также степени исхода, расходы и перебросы | [Проверки набора правил](../extending/ruleset-checks.md) |
| `sheet` | Характеристики, навыки, поля, списки, текущие запасы, шкалы, состояния, шкалы ран, штрафы, миграции | [Листы набора правил](../extending/ruleset-sheets.md) |
| `party`, `clocks` | Общий лист отряда (банда, корабль, сюжетные очки) и часы прогресса | [Листы набора правил](../extending/ruleset-sheets.md) |
| `rests` | Что восстанавливает и очищает каждый вид отдыха | [Листы набора правил](../extending/ruleset-sheets.md) |
| `gm`, `gmReference` | Текст Game Master, сводка по каждому персонажу, кто играет за противников, и справочник правил объемом до 16,000 символов | [Листы набора правил](../extending/ruleset-sheets.md) |
| `catalogs` | Готовые записи (заклинания, таланты, существа), каждая с необязательным блоком `mechanics` | [Каталоги набора правил](../extending/ruleset-catalogs.md), [Механика записей набора правил](../extending/ruleset-mechanics.md), [Конструктор персонажей набора правил](../extending/ruleset-character-builder.md) |
| `items` | Категории, оружие, доспехи, боеприпасы, добыча, деньги, начальное снаряжение, рынки | [Предметы набора правил](../extending/ruleset-items.md) |
| `battle` | Передает числа из вашего листа собственным боям Classic и Tactical приложения Marinara | [Бой по набору правил](../extending/ruleset-combat.md) |
| `combat` | Проводит весь бой по вашим правилам, с бестиарием, полем боя, реакциями и состязаниями | [Бой по набору правил](../extending/ruleset-combat.md) |
| `layers` | Варианты, которые игрок включает для одной игры (Low magic, Hard winter) | [Слои, переводы и миграции наборов правил](../extending/ruleset-layers-and-translations.md) |

**Идентификаторы.** Идентификатор набора правил состоит из строчных букв, цифр и одиночных дефисов (`ember-roads`). Идентификаторы внутри листа состоят из строчных букв, цифр и подчеркиваний и начинаются с буквы (`grit_max`). После публикации сохраняйте идентификаторы неизменными: на них ссылаются сохраненные персонажи, другие наборы правил, заимствующие ваши каталоги, и наложения Experience.

**Текст, безопасный для промпта.** Все, что передается модели (имена, подписи, текст Game Master), должно занимать одну строку без квадратных скобок, `{{` и `}}`.

**Пакеты.** Набор правил, который слишком велик для одного файла, распространяется как `<id>.ruleset.json`: манифест, `ruleset.json`, до 12 файлов `catalogs/<id>.json` по 2 MB и до 40 переводов, все в base64. Zip-архивы отклоняются. Редактор наборов правил, например Pixelforge, собирает этот файл за вас. Манифест объявляет минорную версию Capability API, необходимую вашему набору правил.

**Как регистрируется набор правил.** Импортированный файл получает имя `local/<id>`, файл из репозитория GitHub – `<owner>/<id>`, а набор из официального каталога сохраняет идентификатор без префикса. Два автора могут опубликовать каждый свой `v20` без конфликта.

## Проверки, кубики и лист

Первое и самое важное решение – `resolution.kind`, потому что все остальное читается с его учетом. Game Master только называет навык и сложность. Engine бросает кубики, выполняет вычисления по листу и сообщает модели результат, поэтому никогда не просите модель считать в тексте Game Master.

| Вид | Как бросается | Подходящие системы |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `dice-sum` | Бросить кубики, прибавить числа из листа, достигнуть сложности или превысить ее. Поддерживаются собственные грани, цепочки открытых бросков и взрывающиеся кубики | Игры d20, 2d6 плюс характеристика, Fate (4dF с гранями −1/0/+1), Rolemaster |
| `dice-pool` | Бросить число кубиков из листа и сосчитать те, что достигли цели. Цель может браться из листа для каждой проверки, с успехом выше или ниже нее | World of Darkness, Exalted, системы в духе Shadowrun, Lasers & Feelings |
| `dice-highest` | Бросить пул и взять наибольший кубик или сложить несколько наибольших. Поддерживаются правило для нуля кубиков и второй "темный" набор | Blades in the Dark и другие игры Forged in the Dark, Trophy Dark |
| `roll-against` | Выбросить не больше (или не меньше) числа из листа | Call of Cthulhu, GURPS, BRP, олдскульные проверки X-из-6 |
| `symbol-pool` | Набрать и улучшить повествовательные кубики, взаимно отменить противоположные символы | Genesys и подобные системы |

Затем добавьте то, что нужно вашей системе. Все это описано на странице [Проверки набора правил](../extending/ruleset-checks.md):

- **Степени исхода** (`resolution.outcomes`, 1.135): от двух до восьми именованных результатов по разнице или итогу, например степени успеха, "успех ценой потерь" или трудные и экстремальные успехи. Каждая степень может содержать строку, объясняющую Game Master, что она означает за столом. Эта возможность оказалась самой востребованной среди перенесенных нами систем.
- **Проверки с собственным способом броска** (`resolution.overrides`, 1.140): несколько навыков на других кубиках, например навыки вора на d100 и Open Doors на d6 в игре d20.
- **Расходы, меняющие бросок** (`resolution.spend`), и бесплатные перебросы (`resolution.reroll`): сила воли ради успеха, Luck, очки героя. `perCheck` ограничивает покупки для одного броска, чтобы даже полный запас не позволял купить гарантированный успех.
- **Талисман, меняющий бросок**: добавьте `mechanics.check` к записи каталога, которую выбрал персонаж; ее применение оплачивается собственной ценой записи.

**Чего проверка пока не умеет.** Встречные пулы (сравнение двух бросающих) и суммируемые пулы с диким кубиком, как в OpenD6. Для обоих нужен новый вид разрешения внутри Engine. Если ваша система зависит от одного из них, откройте запрос функции в репозитории Engine с несколькими полностью разобранными бросками; они станут тестами.

**Лист** ([Листы набора правил](../extending/ruleset-sheets.md)) содержит характеристики, навыки, поля, списки и производные значения, а также текущее состояние, которое Engine меняет во время игры:

- **Запасы**, например очки здоровья, сила воли, моты или ячейки заклинаний, расходуемые и восстанавливаемые командами листа и отдыхом.
- **Шкалы**, например стресс, Ruin или XP, с условиями срабатывания при заполнении.
- **Шкалы ран**, где здоровье представлено именованными уровнями или пронумерованными клетками вместо числа, со штрафами к броскам.
- **Текущие состояния**, например форма, стойка или анима, которые могут менять броски, пока действуют.
- **Лист отряда и часы**: банда, корабль или общие сюжетные очки, а также часы прогресса из 4, 6 или 8 сегментов.

Game Master меняет лист командами листа, которым Engine обучает его автоматически, используя ваши идентификаторы, поэтому объяснять их в `gm.sheetGuidance` не нужно. Постоянное развитие (XP, новые точки рейтинга, повышение уровня) использует команды листа для каталогов; см. [Каталоги набора правил](../extending/ruleset-catalogs.md).

**Создание персонажей.** [Конструктор персонажей набора правил](../extending/ruleset-character-builder.md) проводит игрока по заданным вами шагам: происхождение и класс, показатели (брошенные, купленные или назначенные), владения, заклинания, снаряжение и начальные деньги, с проверкой допустимости и совместным созданием отряда. Каталоги могут заимствовать каталог другого установленного набора правил через `from` (1.220), поэтому вариант 5e может использовать существ и заклинания SRD без копирования.

**Текст Game Master.** `gm.checkGuidance` и `gm.sheetGuidance` (по 1,500 символов) отправляются каждый ход, поэтому пишите кратко. `gm.worldGuidance` читается один раз, при создании мира ("нет пороха", "магия редка"). `gmReference` содержит до 16,000 символов более подробных правил в стабильном системном промпте. `gm.sheetSummary` выбирает, что модель видит для каждого персонажа, и все это тратит токены каждый ход. Пишите все своими словами, никогда не копируйте текст книги правил.

## Бой

Набор правил участвует в боях на одном из трех уровней. Можно начать с поверхностного и углубиться позже. Выбирайте по тому, насколько особенности вашей системы связаны с ее боями.

| Уровень | Что вы пишете | Что происходит в бою | Для чего подходит |
| -------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Без участия | Нет блока `battle` или `combat` | Собственная боевая система Classic или Tactical приложения Marinara сама создает участников боя. Лист не меняется | Повествовательные системы, в которых бои описываются сюжетом (Fate, Blades, Trophy) |
| Передать лист | Блок `battle`: запас здоровья, необязательный запас энергии, ячейки заклинаний, до 8 списков навыков | Вычисления и кубики Marinara, но начальная доля здоровья на полосе совпадает с долей в листе, а результат записывается обратно | Простые системы, которым нужно сохранять последствия |
| Собственные правила | Блок `combat` | Ваши кубики разрешают каждую атаку, спасбросок и состязание. Противники берутся из вашего бестиария или шкалы угроз, а каждый расход записывается в лист по мере возникновения | Тактические системы с подробной механикой (5e, Pathfinder, Storyteller, Genesys) |

**Блок `combat`** задает параметры одного из трех видов боя, известных Engine: `attack-vs-defense` (кубики против числа защиты), `dice-pool` (ваши пулы с подсчетом успехов) или `symbol-pool` (повествовательные кубики с расходами, 1.382). Основа – `health` (убывающий запас, отмечаемая шкала ран или обычная заполняемая шкала, 1.383), `defense`, `initiative`, `attackRoll`, `economy` действий и списки, которые становятся `attacks` и `abilities`. Небольшой законченный блок занимает около 25 строк; хороший шаблон – блок Ember Roads на странице [Бой по набору правил](../extending/ruleset-combat.md#combat-a-fight-your-own-rules-resolve).

Помимо основы добавьте то, что нужно вашей системе:

- **Состояния** с эффектами из закрытого списка (защита, броски атаки, спасброски, состязания, скорость, максимальное здоровье, наносимый и получаемый урон).
- **Спасброски**, концентрация, правила умирания и реакции, ожидающие в **окнах** (запись может ждать `used`, `aimed`, `hit`, `harmed`, `falls` или `turn-start`).
- **Состязания** для захвата, толчка и освобождения.
- **Существа**: каталог бестиария, который читает бой, с блоками характеристик, действиями, чувствами и колдовством. **Шкала угроз** позволяет Game Master придумать противника на один бой, а `combat.threat.budget` (1.803) собирает столкновения по лимиту опыта для каждой сложности.
- **Механика записей** каталога: формы областей, длительные зоны, стены, призывы, исцеления и чувства. См. [Механика записей набора правил](../extending/ruleset-mechanics.md).

**Classic или Tactical.** Бои по вашим правилам получают поле, только если `combat` объявляет `distance` (`label`, `perCell`), а лист или существа задают перемещение. Без них игра Tactical все равно использует ваши правила, но бой идет в воображении. Если ваши правила зависят от позиции (области, досягаемость, обход с фланга), задайте `"styles": ["tactical"]` (1.379), чтобы в каждой игре с вашим набором правил было поле.

**Изображения существ** отделены от правил: [пакет существ](../extending/writing-creature-packs.md) (`.creatures.json`, проще всего создать в Pixelforge) отображает ваш бестиарий на поле Tactical по совпадению идентификаторов существ. Все, у кого нет изображения, остаются фишками.

**Известные ограничения** перечислены в разделе [Пока нет](../extending/ruleset-combat.md#not-yet). При переносе чаще всего встречались встречные защитные броски (Dodge и Fight Back, Parry и Block), зоны попадания, инициатива по сторонам и реакции на реакции. Game Master описывает их в повествовании вокруг боя Engine.

## ИИ боя: разум, характер и управление противниками

Engine играет за каждого противника и спутника под управлением ИИ, которым не управляет никто другой, без вызова модели на каждый ход. Он не зависит от набора правил: мы проверяли его на переносах Storyteller, Exalted, олдскульных систем, Call of Cthulhu, GURPS и Genesys, а также 5e. Он работает, даже если ни один из ключей ниже не задан; они позволяют вашим существам сражаться в соответствии со своей природой. Все описаны на странице [Механика записей набора правил](../extending/ruleset-mechanics.md), а устройство ИИ – на странице [ИИ боя Game Mode](game-combat-ai.md).

| Ключ | Что определяет | API |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| `mind` у существа или уровни `combat.minds`, определяемые характеристикой | Насколько осмысленно оно действует: `mindless`, `instinct`, `cunning`, `tactical`, `genius`. Звери по умолчанию действуют инстинктивно, конструкты и слизи – без разума | 1.761 |
| `behavior.temperament` | Как оно сражается: reckless, cautious, opportunistic, protective, supportive, disciplined, cowardly, patient, methodical, coordinated | 1.763 |
| Характеры, назначаемые только по сюжету | `fanatical` (никогда не теряет стойкость), `arrogant` (сдерживается; если обладает легендарными действиями и проигрывает, взлетает), `territorial`, `cruel`, `honourable` (предлагает отряду **Surrender** (сдаться)), `hungry` (уволакивает жертву). Никогда не назначаются случайно | 1.778 до 1.784 |
| `behavior.role` | bruiser, bulwark, skirmisher, marksman, spellcaster, supporter, controller, `solo` (1.776). Если не указана, назначается по его способностям | 1.763 |
| `behavior.targets`, `opens`, `pack`, `ambush` | Приоритеты целей, первое действие, стайная тактика, ожидание в укрытии | 1.763 |
| `behavior.shifts` | Характер, который меняется при падении здоровья ниже половины, падении союзника или лидера либо когда существо загнано в угол | 1.779 |
| `combat.morale` | Когда и как враги проверяют стойкость (2d6 ниже показателя или спасбросок) и кто сдается | 1.762, 1.775 |
| `gm.opposition: "game-master"` | Game Master играет за каждого противника, выбирая из допустимых вариантов Engine; если это не удается, управление берет Engine | 1.774 |

`behavior` может задаваться для всего блока `combat`, типа существа или одного блока характеристик, причем каждый следующий вариант переопределяет предыдущий. Примеры из SRD: волк `{"targets": ["wounded"], "pack": true}`, гоблин `{"temperament": "cowardly", "targets": ["weakest"]}`, упырь `{"ambush": true}`.

**Для боя на поле ИИ нужны** `combat.distance`, перемещение (`combat.economy.movement` или `speed` существа), `range` у дальних атак и строк оружия, а также `area` у всего, что поражает зону. Без дальности пистолет работает только на расстоянии вытянутой руки. Без областей ИИ никогда не рассредоточивается.

**Повествовательные системы.** По умолчанию Engine играет за обычных врагов, а Game Master – за боссов. В системе, где противодействие строится на повествовании, а не на уроне (Fate, Blades, Trophy, Lasers & Feelings), `gm.opposition: "game-master"` позволяет модели отыгрывать каждого противника. Это действует только тогда, когда игрок включил **GM directs bosses** (GM управляет боссами) при настройке: так он дает согласие на вызовы модели во время боев.

**Без блока боя** в ваших играх все равно действует боевой дух в боях Classic и Tactical: каждый враг, который не является боссом и не лишен разума, получает показатель от 2 до 12 на основе разума и характера, а разумные враги могут сдаваться. Автор столкновения может пометить `leader` стороны.

**Характер отряда.** Каждый участник отряда получает характер на основе своего поля **Description** (описание) при начале игры, и он меняется только по сюжетным причинам при разборе в конце сессии. Спутники под управлением ИИ сражаются в соответствии с ним. Набор правил его не задает, но ваш текст Game Master может на него опираться.

## Слои, наложения и миграции

Три механизма меняют набор правил без создания отдельного набора. Используйте слой для варианта, который выбирает игрок, наложение – для содержимого одного приключения, а миграцию – при изменении структуры листа.

**Слои** (`layers`, до 12) – это переключатели в мастере **New Game** (новая игра), зафиксированные на все время игры. Слой может только сужать возможности или добавлять текст, но никогда не добавляет правил:

- дополнять указания Game Master (`gm.guidance`, `gm.worldGuidance`; 4,000 символов на слой);
- убирать значения из поля-перечисления, заменять шкалу сложностей или скрывать записи каталога по объявленному фильтру;
- убирать монеты (1.64), убирать продавцов с рынка, помечать предметы как не продающиеся или заменять таблицы добычи (1.813);
- объявлять `conflicts` с другими слоями.

Слой не может добавить поле, значение, навык, запас, отдых, продавца или таблицу добычи, изменить вид разрешения или затронуть боевые числа. Персонажи сохраняют все, что убирает слой. Хороший образец – слой **Low magic** (мало магии) из SRD: заклинания ограничены 5-м уровнем, предметы выше необычной редкости встречаются реже и обычно не продаются, существа с сильной магией исключены из случайных столкновений, а указания о мире просят Game Master объяснить, почему магия редка. Другие авторы могут его копировать. Слои для чужого набора правил пока не поддерживаются.

**Наложения** (1.355) позволяют пакету карт Experience добавлять в ваш набор правил существ, состояния, состояния листа, предметы и шкалы (1.367), пока этот Experience включен. Храните чудовищ и добычу конкретного приключения в наложении, а не в базовом наборе правил. Наложение, которое повторно использует один из ваших идентификаторов или не подходит, отбрасывается целиком; это еще одна причина сохранять идентификаторы неизменными. Справочник: [наложения наборов правил](optional-agent-packages.md#capability-api-1355-ruleset-overlays).

**Миграции** (`sheet.migrations`, 1.77) описывают перенос сохраненных персонажей при переименовании поля, разделении одного уровня на уровни по классам или разделении запаса. Для добавлений миграция не нужна; повышайте `sheet.version`, когда меняется структура листа. Справочник: [Слои, переводы и миграции наборов правил](../extending/ruleset-layers-and-translations.md).

## Переводы

Пишите набор правил на английском и распространяйте каждый другой язык отдельным файлом перевода (1.811). Переводы влияют только на отображение: правила, команды листа и все, что передается Game Master, остаются на английском, поэтому перевод никогда не может сломать игру.

Ключ перевода – английская строка, слово в слово:

```json
{
  "_meta": { "locale": "ru", "direction": "ltr" },
  "package": { "name": "5e (SRD 5.1)" },
  "ruleset": { "Prone": "Лежащий", "Fire Bolt": "Огненный снаряд", "Goblin": "Гоблин" }
}
```

- Коды языков совпадают с кодами Engine (`ru`, `pt-BR`, `zh-Hans`). Отсутствующая или пустая строка показывается на английском, а для `pt-BR` сначала используется перевод `pt`.
- **В файле пакета для распространения** поместите их в `locales/<language>.json`, до 40 файлов по 8 MB. При импорте сохраняется только текущий язык Engine; чтобы переключить язык, измените его и импортируйте снова.
- **В официальном каталоге** каждый язык – отдельный пакет `<id>-<version>.<language>.json`, указанный в `locales` записи каталога вместе с URL, sha256, размером, переведенными названием и описанием для магазина. Engine скачивает только пакет своего текущего языка и заменяет его при смене языка. Размещение всех 11 языков SRD в одном файле увеличивало загрузку с 7 MB до 34 MB, поэтому пакеты разделены.
- Исправление перевода не требует новой `version`.

Пакет SRD распространяет таким образом 11 языков и служит образцом. Справочник: [Переводы](../extending/ruleset-layers-and-translations.md#translations).

## Пакет 5e (SRD 5.1): полноразмерный пример

[Пакет ruleset-5e-2014](https://github.com/Pasta-Devs/Marinara-Agents/tree/staging/packages/ruleset-5e-2014) в Marinara-Agents использует почти все возможности с этой страницы, поэтому обращайтесь к нему, когда хотите увидеть ключ в настоящем наборе. Что стоит перенять:

- **Структура**: `ruleset.json` плюс отдельный файл для каждого каталога в `catalogs/` (существа, заклинания, магические предметы и прочее), собранные в пакет `.ruleset.json`. Его README и MODELING.md объясняют, как была смоделирована каждая механика.
- **Лицензирование**: указание авторства CC BY 4.0 в `license`, строка об отсутствии связи с правообладателем и отсутствие где-либо названий продуктов, защищенных товарными знаками.
- **Полноценный бой**: блок d20 `attack-vs-defense` с бюджетами действия, бонусного действия и реакции, концентрацией, реакциями вроде Shield и Counterspell, полем боя, полным бестиарием с разумом и характерами и лимитом столкновения.
- **Конструктор**: раса, класс, брошенные или купленные показатели, владения, заклинания и начальное снаряжение.
- **Слой** (Low magic) и **11 переводов** в виде пакетов, загружаемых по запросу.
- **Стабильные идентификаторы**: другие наборы правил заимствуют его существ и заклинания, поэтому его идентификаторы никогда не меняются.
- **Регрессионные тесты** запускаются отдельной задачей CI при каждом изменении.

Если ваша система – вариант d20, подумайте о заимствовании ее каталогов через `from` (1.220) вместо копирования.

## Проектирование похожих систем: чему научил перенос

Мы перенесли в этот формат 16 систем из коллекции сообщества, от повествовательных игр с простыми правилами до Rolemaster. Главный урок: набор правил здесь обязателен к исполнению, а не служит рекомендацией. Engine бросает каждую проверку и применяет каждое изменение листа, поэтому все, что вы оставите на "GM разберется", действительно останется необработанным. Заранее решите, чем ведает Engine, а что описывает Game Master.

| Семейство систем | Примеры | Разрешение | Ключи, которые помогли | Что оставлено Game Master |
| ------------------ | ----------------------------------- | -------------- | ---------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Подробная механика d20 и d% | 5e, Pathfinder 2e, Rolemaster | `dice-sum` | Степени исхода для степеней успеха; `openEnded` и `unmodified` для Rolemaster; `gmReference` для больших таблиц | Нескладывающиеся типы бонусов Pathfinder; таблицы критических результатов Rolemaster за пределами степеней |
| Олдскульные | OSE | `dice-sum` | `resolution.overrides` для навыков вора (d100) и X-из-6 (d6); боевой дух на 2d6 | Инициатива по сторонам (разыгрывается как индивидуальная) |
| Бросок не выше показателя | Call of Cthulhu 7e, GURPS Lite | `roll-against` | `against`, бонусные и штрафные кубики `tens`, критические грани, трудные и экстремальные степени | Встречные Dodge, Fight Back, Parry; зоны попадания GURPS |
| Пулы Storyteller | V20, W20, Exalted 3e, Exalted WoD | `dice-pool` | Шкалы ран со штрафами, текущие состояния (формы, анима), переопределения для выпавших 1, которые не отменяют успехи, блок `combat` на пулах | Дисциплины и Дары с областями действия, если они не описаны записями |
| Forged in the Dark | Blades in the Dark, Trophy Dark | `dice-highest` | `keep`, `zeroDice`, набор кубиков `dark`, степени (6 / от 4 до 5 / от 1 до 3), шкалы с `onFull`, часы, лист отряда для банды | Бои через `gm.opposition: "game-master"` |
| Пулы со стойками | Lasers & Feelings, авторская игра | `dice-pool` | `target` из листа, `stances` (ниже или выше), `exact` для точного совпадения, лист отряда для корабля | Бои как повествование |
| Fate | Fate Core | `dice-sum` | Собственные грани для 4dF, степени для ничьей и стильного успеха | Использование и навязывание аспектов как сюжет; бои как повествование |
| Повествовательные кубики | Genesys | `symbol-pool` | `combat.kind: "symbol-pool"` с `symbols.spends`, поглощение урона и здоровье на заполняемой шкале Wounds | Расходы на проверках вне боя |

**Практические советы по итогам переноса:**

1. **Начните с кубиков, затем займитесь листом, затем текстом Game Master.** Добейтесь правильного броска одной проверки, прежде чем добавлять каталоги или бой.
2. **Используйте степени исхода везде, где они есть в вашей системе.** `text` каждой степени сообщает модели, что происходит за столом, а именно на этом строятся повествовательные системы.
3. **Лучше обойтись без блока боя, чем описать его наполовину верно.** Повествовательная система лучше играется с собственными боями Marinara (или противниками под управлением Game Master), чем с блоком боя, который лишь наполовину моделирует ее правила.
4. **Если вы описываете бой, задайте основу для поля**: `distance`, перемещение, дальность дальнего оружия и хотя бы одну атаку по области. В каждом переносе, который мы тестировали с ИИ, чего-то из этого не хватало, и бои застревали или совсем не использовали позиции.
5. **Сверьте перемещение со своим масштабом.** При 2 метрах на клетку существо со скоростью 2 не могло подняться на холмы, и бои застревали.
6. **Записывайте источники.** Для каждого набора правил ведите файл заметок со списком исходных правил и описанием их переноса, особенно там, где вы выбирали между противоречащими трактовками. Это первое, что спрашивают рецензенты.
7. **Если Engine действительно не хватает механики**, оставьте ее Game Master в `gmReference` и откройте запрос функции с разобранными примерами. Многие возможности с этой страницы (степени исхода, `dice-highest`, `roll-against`, бои на символах, часы, листы отряда) появились потому, что понадобились при переносе.

## Версии, тестирование и публикация

**Важны два номера версии.** `version` вашего набора правил – целое число, которое вы повышаете при каждой публикации изменения. Установленная версия никогда не перезаписывается, а каждая игра остается привязана к точной версии, с которой была создана, поэтому вычисления в текущей кампании никогда не меняются. Версия **Capability API** указывает, какие возможности Engine нужны вашему файлу. Манифест пакета объявляет `schemaVersion: 2` и `capabilityApi: { "major": 1, "minor": N }`, где N – наибольшая минорная версия среди всех используемых ключей, чтобы старой версии Engine никогда не предлагался ваш набор правил. Для наборов из официального каталога требуется как минимум 1.374. Обычному импортируемому файлу ничего не нужно, потому что читающий его Engine сам его проверяет.

**Цикл работы над черновиком.** Измените файл, повысьте `version`, импортируйте, создайте новую игру. Импорт той же версии с другим содержимым отклоняется. Старые версии остаются установленными, пока вы не удалите набор правил. Повышайте `sheet.version` при изменении структуры листа и пишите миграцию при переносе значений.

**Тестирование.**

- Используйте строку `$schema`, чтобы редактор находил опечатки и неверные типы по мере ввода.
- Импортируйте файл: включите **Settings → Advanced → Danger Zone → Allow custom Agent imports** (настройки → дополнительно → опасная зона → разрешить импорт своих агентов), затем выберите **Agents → Import agents → Game Mode ruleset** (агенты → импорт агентов → набор правил Game Mode). До сохранения проверка перечисляет все проблемы с их путями, включая имена, которые ни на что не ссылаются.
- Выполните несколько проверок каждого объявленного вида, включая переопределения, расходы и каждую степень исхода. Журнал показывает настоящие вычисления.
- Если у вас есть блок `combat`, проведите бои и в Classic, и в Tactical, со спутниками под управлением ИИ, против существ с каждым типом разума. Следите за застреванием (никто не может ни до кого добраться), уроном по своим от областей и врагами, которые никогда не используют лучшие действия.
- Включите и выключите каждый слой, а если распространяете переводы, переключите язык Engine.
- Если Experience накладывает содержимое на ваш набор правил, `POST /api/game/experience/check` сообщает, что не подходит.
- Попросите тестировщика, который не знает вашей системы, создать персонажа в конструкторе.

**Публикация.** Есть пять способов, начиная с самого простого (подробности в разделе [Как поделиться набором правил](../extending/writing-rulesets.md#sharing-your-ruleset)):

1. Отправьте файл `.json`.
2. Отправьте пакет `.ruleset.json` с каталогами и переводами внутри.
3. Поместите его в открытый репозиторий GitHub в `rulesets/` (не более 32 файлов). Пользователи добавляют репозиторий как свой источник, а набор регистрируется под вашим именем GitHub.
4. Предложите его для официального каталога через запрос на включение изменений в [Marinara-Agents](https://github.com/Pasta-Devs/Marinara-Agents), со структурой как у `ruleset-5e-2014`. Этот путь предназначен для широко используемых систем с чистым лицензированием.
5. Выпустите Experience, пакет карт которого дополняет ваш набор правил содержимым приключения через наложение.

**Лицензирование.** Публикуйте только тот текст правил, которым вправе делиться. У многих систем есть справочный документ по открытой лицензии; укажите его идентификатор SPDX и требуемое указание авторства в `license`. Набору правил в основном нужны названия и числа, поэтому весь текст Game Master пишите своими словами.

### Перед распространением

- [ ] Идентификаторы окончательны и соответствуют правилам идентификаторов.
- [ ] В `license` есть идентификатор SPDX и указание авторства, а названия, защищенные товарными знаками, не используются без разрешения.
- [ ] Каждый вид проверки, переопределение, расход и степень были опробованы броском в игре хотя бы один раз.
- [ ] `gm.checkGuidance` и `gm.sheetGuidance` кратки, никогда не просят модель считать и написаны вашими словами.
- [ ] Бои были сыграны в каждом стиле, разрешенном вашим набором правил, либо `combat.styles` их ограничивает.
- [ ] Манифест пакета объявляет правильную минорную версию Capability API.
- [ ] `version` повышена по сравнению с последним файлом, который есть у кого-либо еще.
- [ ] Файл заметок объясняет, как было перенесено каждое исходное правило.
