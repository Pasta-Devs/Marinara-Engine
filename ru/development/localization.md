# Локализация интерфейса

Marinara Engine переводит текст интерфейса приложения. Промпты для модели, ваши материалы, сгенерированный текст
чатов, идентификаторы, значения протоколов, пути к файлам и сохраненные машинные значения остаются без изменений.

Английский – исходная локаль и запасной вариант во время работы. Поэтому вместо отсутствующего перевода от
сообщества показывается английский текст, а не ключ перевода и не пустой элемент.

Язык интерфейса выбирается в **Settings > General > App Behavior > Language** (настройки > основное > поведение
приложения > язык). Выбор меняет элементы управления и пояснения приложения Marinara, но не промпты для модели, не
созданные материалы и не сообщения чата.

При выборе языка, отличного от английского, его пакет при необходимости загружается. **Refresh language pack** (обновить языковой пакет) получает новые переводы. Загруженные пакеты хранятся в `DATA_DIR/ui-packs` и работают без сети. При неудачной загрузке текущий язык и установленный пакет не меняются. Пакеты никогда не загружаются автоматически при запуске или обновлении.

При первом обновлении с версии, в которую переводы входили изначально, ранее выбранный язык, отличный от английского, возвращается к английскому. Снова выберите язык, чтобы загрузить его. Пользовательский контент и другие настройки не меняются.

## Поддерживаемые языки интерфейса

| Язык | Файл локали | Направление письма |
| --- | --- | --- |
| Арабский | `ar.json` | Справа налево |
| Китайский, упрощенное письмо | `zh-Hans.json` | Слева направо |
| Английский | `en.json` | Слева направо |
| Французский | `fr.json` | Слева направо |
| Немецкий | `de.json` | Слева направо |
| Хинди | `hi.json` | Слева направо |
| Японский | `ja.json` | Слева направо |
| Корейский | `ko.json` | Слева направо |
| Польский | `pl.json` | Слева направо |
| Португальский, Бразилия | `pt-BR.json` | Слева направо |
| Русский | `ru.json` | Слева направо |
| Испанский | `es.json` | Слева направо |

Английский поддерживается как исходный каталог. Каталоги сообщества начинались как переводы с машинной помощью и открыты для исправлений от людей, свободно владеющих языком. Выделение текстов интерфейса еще продолжается, поэтому текст без ключа перевода остается английским.

## Файлы локалей

Основной английский каталог по-прежнему находится здесь:

```text
packages/client/src/localization/locales/en.json
```

Пакеты сообщества находятся в [`ui/` на ветке `docs-i18n`](https://github.com/Pasta-Devs/Marinara-Engine/tree/docs-i18n/ui), отдельно от языковых папок документации. Каждый язык BCP-47 использует один JSON-файл, например `ui/pl.json`, `ui/ko.json` или `ui/pt-BR.json`, и общий генерируемый `ui/manifest.json` с размерами файлов и хешами SHA-256. Точно сохраняйте регистр кода языка. Арабский интерфейс поддерживается и без арабского пакета документации. Английский загружается вместе с приложением; пакеты сообщества загружаются по явному запросу и читаются с локального сервера.

```json
{
  "_meta": {
    "locale": "pl",
    "direction": "ltr"
  },
  "chat.input.placeholder": "Napisz odpowiedź…",
  "common.actions.save": "Zapisz"
}
```

Используйте смысловые ключи, сгруппированные по областям интерфейса. Не берите английское предложение в качестве
ключа: тогда обычная правка формулировки обнулит все переводы.

## Правила перевода

- Переводите только значения. Не переименовывайте смысловые ключи.
- Сохраняйте подстановки вида `{{name}}` и теги разметки вида `<strong>`.
- Держите ключи перевода отсортированными по алфавиту.
- Названия продуктов, такие как Marinara Engine, не переводятся, пока проект не примет официальное локализованное
  название.
- Передавайте смысл и тон файла `en.json`. Не добавляйте поведение и обещания, которых нет в английском источнике.
- Проверьте, что переведенные подписи умещаются на экране компьютера и телефона.

В пакетах сообщества могут временно отсутствовать ключи, пока готовится перевод определенной области. Для отсутствующих ключей используется английский. Валидатор пакетов сообщает о покрытии и устаревших ключах, которые Engine игнорирует. Пустые переводы (кроме существующих исключений для намеренно пустых суффиксов), неверные метаданные и измененные токены интерполяции или форматированного текста не проходят проверку. Переименования и удаления ключей нужно отразить в пакетах либо отслеживать в отдельном issue `[ui-i18n]`.

PR с новой функциональностью должен добавить или обновить основной английский ключ, но не обязан менять пакеты сообщества. Переводите значение для сообщества, только если можете предложить полезный перевод. Не копируйте английский во все файлы ради одинаковых списков ключей: резервный механизм уже показывает этот текст, а отсутствие ключа избавляет переводчиков от ненужных конфликтов слияния.

Машинный перевод как черновик приветствуется, если pull request прямо об этом говорит. Прежде чем называть локаль
проверенной, носитель языка должен просмотреть терминологию, тон, обрезанные строки и вид на телефоне.

## Как предложить правку к существующему переводу

Для небольшой правки формулировки достаточно веб-редактора GitHub:

1. Откройте файл локали в папке
   [`ui/`](https://github.com/Pasta-Devs/Marinara-Engine/tree/docs-i18n/ui).
2. Нажмите значок карандаша, чтобы отредактировать файл. При необходимости GitHub предложит создать копию
   репозитория.
3. Меняйте только переведенное значение. Сохраните его ключ, чувствительные к пунктуации подстановки вида `{{name}}`
   и синтаксис JSON.
4. Зафиксируйте изменение в отдельной ветке своей копии репозитория.
5. Обновите манифест и проверьте пакет командой ниже, затем откройте pull request в **`docs-i18n`**, а не в `staging` или `main`.
6. В описании pull request укажите язык, объясните исправленный смысл и напишите, владеете ли вы языком свободно или
   пользовались машинным переводом.

Заголовок делайте в духе `Improve French UI translation`. Несколько связанных правок одной локали можно собрать в
один pull request. Не смешивайте их с посторонними изменениями кода.

## Как предложить новую локализацию

Для нового языка сохраните рабочую копию Engine на ветке `staging` как источник английского текста и работайте в `docs-i18n`:

```bash
git clone https://github.com/YOUR-NAME/Marinara-Engine.git
cd Marinara-Engine
git checkout docs-i18n
git pull
git checkout -b translation/LOCALE
```

Далее:

1. Скопируйте основной `en.json` из рабочей копии Engine в `ui/<locale>.json`, например `ui/it.json` или `ui/pt-PT.json`.
2. В `_meta.locale` оставьте имя файла без `.json`.
3. В `_meta.direction` укажите `ltr` или `rtl`.
4. Переведите значения по правилам выше. Для новой локали лучше перевести английский каталог целиком, хотя неполный
   каталог тоже работает: пропуски заполнит английский текст.
5. Создайте манифест и запустите валидатор пакетов (только Node.js, без зависимостей). Он показывает покрытие относительно английского каталога вашей рабочей копии Engine:

   ```bash
   node scripts/ui-i18n/validate-packs.mjs /path/to/Engine/packages/client/src/localization/locales/en.json --write-manifest
   node scripts/ui-i18n/validate-packs.mjs /path/to/Engine/packages/client/src/localization/locales/en.json
   ```

6. Для нового языка также нужен небольшой PR в Engine, добавляющий его код в `UI_LANGUAGE_CODES` в `packages/shared/src/utils/ui-locales.ts`. Обновления существующих пакетов не требуют изменений Engine. После публикации выберите язык в **Settings > General** и проверьте его на компьютере и телефоне: длинные подписи, подсказки, состояния загрузки и ошибок, а также направление текста.
7. Отправьте ветку в свою копию репозитория и
   [создайте pull request](https://github.com/Pasta-Devs/Marinara-Engine/compare), выбрав основой
   `Pasta-Devs/Marinara-Engine:docs-i18n`.

В описании pull request укажите локаль, источник перевода, уровень владения языком или проверки, выполненные команды
проверки и области, которым еще нужен взгляд носителя языка. Заполняйте шаблон pull request честно и отмечайте только
те пункты ручной проверки, которые выполнили сами.

## Использование переводов в коде клиента

Компоненты React используют `useTranslation`:

```tsx
import { useTranslation } from "react-i18next";

const { t } = useTranslation();
return <button>{t("common.actions.save")}</button>;
```

В настройках интерфейса на уровне модуля храните ключи перевода, а не переведенные значения. Тогда язык меняется на
ходу, без перезагрузки страницы. Вспомогательный код клиента вне React может использовать экспортируемую функцию
`translate` из `packages/client/src/localization/i18n.ts`.

Переводите весь видимый текст: подписи, подсказки в полях, всплывающие подсказки, названия для программ чтения с
экрана, замещающий текст, состояния загрузки и пустых списков, всплывающие уведомления, подтверждения и встроенные
обучающие подсказки. Не пропускайте через переводчик интерфейса промпты и созданные материалы.

Общие устаревшие элементы – элементы управления в настройках, справочные всплывающие подсказки, заголовки окон –
дополнительно распознают точные канонические английские значения из каталога, пока идет перевод старых мест вызова.
Это мост совместимости, а не рекомендуемый способ: новые и существенно переработанные компоненты обязаны напрямую
использовать смысловые ключи вида `t("area.control.label")`. Английское предложение, которого нет в `en.json`,
перевести невозможно.

Проверка локализации в репозитории заодно ищет непереведенный текст интерфейса в файлах TSX клиента:

```bash
pnpm localization:ui-check
```

Она охватывает видимый код JSX, подписи и уведомления, подставленные напрямую, названия для программ чтения с
экрана, подсказки в полях, состояния загрузки и пустых списков, всплывающие уведомления и подтверждения. Содержимое
элементов `code`, `pre`, `script` и `style` исключено намеренно, чтобы команды, настройки, адреса URL, макросы и
другие машинные примеры оставались точными. Динамические значения – созданные вами, сгенерированные, сохраненные,
промпты и значения протоколов – тоже должны оставаться вне переводчика интерфейса.

## Интерфейсы скачиваемых агентов

Экраны агентов, принадлежащие Engine, используют основной английский каталог и загруженные пакеты `docs-i18n/ui`. Загружаемые клиенты расширений хранят собственные переводы в репозитории Marinara-Agents.

Каждый пользовательский элемент возможности получает выбранную локаль через атрибуты `lang` и `dir`, а также так:

```ts
capabilityProps.localization = {
  locale: "pl",
  direction: "ltr",
};
```

Существующее событие `marinara-capability-props` срабатывает при смене локали. Интерфейс пакета должен выбрать свою
встроенную локаль, при отсутствии перевода взять английский текст пакета и перерисоваться после этого события.
