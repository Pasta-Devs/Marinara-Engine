# Карта архитектуры (для разработчиков)

Это руководство для тех, кто участвует в разработке. Оно описывает, как устроен код приложения Marinara Engine: общие основы, системы функций, принадлежность режимов и место каждой части кода. Здесь же перечислены нынешние крупные файлы и направление будущей переработки.

Область охвата: `packages/client/src`, `packages/server/src` и `packages/shared/src`. Обычного набора файлов `.test.ts` в репозитории нет. Автоматическую проверку дают отслеживаемые регрессионные скрипты и дымовые тесты Playwright; временные файлы-доказательства `.test.ts` попадают в gitignore и удаляются после использования.

Число файлов, строк и маршрутов меняется вместе с репозиторием. Эта карта дает приблизительные очертания и названия. Точные числа всегда смотрите в текущем дереве.

## Коды разделов

Используйте эти коды, когда планируете перенос кода, размечаете задачи или добавляете короткий заголовок в файл, который пока нельзя перенести.

| `SERVER-APP` | Запуск приложения Fastify, промежуточный слой, регистрация маршрутов, конфигурация времени выполнения | `packages/server/src/app.ts`, `index.ts`, `middleware`, `config` |
| `SERVER-SHARED` | Только серверные основы: хранилище, база данных, LLM, промпты, лорбуки, импорт, интеграции | `packages/server/src/services`, `db`, `utils`, `lib` |

| `MODE-GAME` | Интерфейс Game Mode, промпты GM, кубики, отряд, карта, бой, ресурсы, сессии | `components/game`, `/api/game`, службы игры |
| `FEATURE-AGENTS` | Определения агентов, выполнение, отладочное состояние, маршрутизация знаний | компоненты агентов, хранилище агентов, маршруты и службы агентов |

| `TEST` | Отслеживаемые регрессионные и браузерные дымовые проверки, а при необходимости – временные тесты-доказательства | `scripts/regressions`, `e2e` и временные файлы `packages/server/src/**/__tests__/`, удаляемые после использования |

Лучше, чтобы раздел был виден по самому пути. Комментарий вида `// Section: MODE-GAME` полезен только пока файл лежит в смешанной папке.

## Границы пакетов

### packages/shared

`CORE-CONTRACT`. Этот пакет не должен зависеть от среды выполнения.

Что здесь сейчас лежит:

- `types`: чат, персонаж, игра, состояние игры, бой, сцена, sidecar, TTS, агенты, промпты, лорбуки, экспорт, темы оформления.
- `schemas`: схемы Zod для сохраняемых и общих сущностей.
- `constants`: провайдеры, значения по умолчанию, режимы чата, списки моделей, промпты агентов.
- `utils`: чистые вспомогательные функции – раскрытие макросов, обертывание в XML, подбор музыки.
- `features`: манифесты и реестр агентов, определения вызовов функций, пакеты папок, движки пошаговых игр UNO, Chess и Poker, наборы правил Game Mode и их бой (`rulesets`, `ruleset-combat`, `tactical-combat` и файлы `combat-*`), а также генератор миров с его файлами для обмена (наборы мира, миры, пакеты тайлов, полей и существ) в `world`.

Правила:

- Никакого кода React, DOM, Fastify, серверного хранилища, файловой системы, сети и SDK провайдеров.
- Переносите код сюда только тогда, когда один и тот же контракт или чистый алгоритм нужен и клиенту, и серверу.
- Не превращайте `shared` в общую свалку для вспомогательных функций, нужных только клиенту.

### packages/client

React 19 и Vite PWA. Сейчас здесь несколько сотен файлов исходного кода.

Как выглядит верхний уровень:

- `App.tsx`, `main.tsx`: запуск приложения, React Query, PWA, глобальные эффекты.
- `components/layout`: оболочка приложения, боковые панели, верхняя полоса, отрисовщик окон.
- `components/ui`: переиспользуемые примитивы интерфейса.
- `components/chat`: смешанный интерфейс общего чата, Conversation, Roleplay, сцен, спрайтов и сражений.
- `components/game`: поверхность и панели Game Mode.
- `components/panels`, `components/modals`, редакторы сущностей: настройки и управление ресурсами.
- `features`: выделенные модули функций – пока это разделы настроек чата, части панели трекеров, многопользовательский режим, а также контракт, настройка, сцена и средства отрисовки агентов аватаров (`features/avatars`).
- `hooks`: хуки React Query и хуки времени выполнения для большинства функций API.
- `lib`: вспомогательные функции браузера и клиента. Сейчас здесь смешаны общие функции и функции, нужные только Game Mode.
- `stores`: хранилища Zustand для интерфейса, времени выполнения чата, агентов, состояния игры, Game Mode, ресурсов, sidecar, перевода, галереи, сражений и пошаговых игр.
- `styles`: глобальная таблица стилей и CSS отдельных тем оформления.

Важные нынешние пересечения:

- `components/game` импортирует `components/chat` ради общих визуальных частей – например, погоды и выдвижных панелей галереи.
- `components/chat` импортирует состояние игры и состояние сражения для функций Roleplay.
- `hooks/use-generate.ts` затрагивает состояние чата, агентов, игры, Game Mode, перевода и настройки интерфейса.
- Вспомогательные функции `lib/game-*` нужны только Game Mode, но лежат рядом с глобальными.

### packages/server

API на Fastify, файловое хранилище и интеграции с провайдерами. Сейчас здесь несколько сотен файлов исходного кода.

Как выглядит верхний уровень:

- `app.ts`, `index.ts`: фабрика приложения, запуск, отдача статики, наполнение файлового хранилища, начальные данные.
- `routes`: много файлов маршрутов. Большинство – тонкие API для CRUD, но `generate.routes.ts` и `game.routes.ts` – крупные файлы оркестрации. В папке `routes/generate/` лежат части, выделенные из пути генерации на данный момент, включая цепочку вывода токенов (`generation-stream-output.ts`), раунды вызовов инструментов (`tool-rounds.ts`), разбор команд ответа и очистку текста, а также сохранение ответа (`save-generated-reply.ts`).
- `services/storage`: слой-фасад хранилища для чатов, персонажей, промптов, лорбуков, настроек, ресурсов, тем оформления, состояния игры.
- `services/llm`: реестр провайдеров, базовый контракт провайдера, провайдеры, совместимые с OpenAI, мост к локальному sidecar.
- `services/prompt`: общая сборка промпта для генерации вне Game Mode.
- `services/conversation`: расписания, автономные сообщения, осведомленность, профили Conversation, обработка команд Conversation.
- `services/game`: промпты GM, кубики, бой, конечный автомат, промпты отряда, карты, погода, время, сессии, контрольные точки, репутация, ресурсы.
- `services/sidecar`: локальная среда выполнения, управление моделями, анализ сцены, постобработка сцены.
- `services/agents`: выполнение агентов и маршрутизация знаний.
- Основы функций: `services/import`, `services/lorebook`, `services/image`, `services/haptic`, `services/tools`, `services/regex`, `services/professor-mari`, `services/mari-db`, `services/turn-games`, `services/spotify`, `services/video`, `services/generation`, `services/chat-summary`, `services/achievements`, `services/prompt-overrides`, `services/setup`, `services/noodle`, `services/memory-recall`, `services/avatars` (хранение моделей аватаров, генерация и классификатор эмоций для агентов аватаров), `speech-to-text.service.ts` и `discord-webhook.ts`.
- `db/schema`: определения файловых таблиц для данных, которые лежат в `DATA_DIR/storage`.
- `db/file-schema.ts`, `db/file-query.ts`: собственные метаданные таблиц и выражения запросов.
- `db/file-backed-store.ts`: хранилище таблиц в памяти, граница транзакции, восстановление после сбоя и сохранение снимков в формате JSON. См. [Файловое хранилище](file-storage.md).

Важные нынешние пересечения:

- Маршруты напрямую импортируют хранилище, LLM, промпты, лорбуки, игру, sidecar и службы функций.
- `generate.routes.ts` обслуживает основной путь генерации для Conversation и Roleplay, а также конвейер агентов.
- `game.routes.ts` отвечает за оркестрацию игры и вместе с этим дотягивается до LLM, sidecar, лорбуков, изображений, хранилища и поведения вебхука Discord.
- Анализ сцены живет в службах sidecar, но Game Mode может выполнять его либо через sidecar, либо через выбранное подключение LLM.

## Принадлежность режимов

### Общее для всех режимов

Это глобальные основы:

- Сохранение чатов и сообщений: `packages/server/src/routes/chats.routes.ts`, `packages/server/src/services/storage/chats.storage.ts`, общие типы и схемы чата.
- Персонажи и персоны: маршруты персонажей, хранилище, схемы, а также клиентские хуки и редакторы персонажей.
- Подключения и провайдеры: маршруты подключений, хранилище, общие константы провайдеров и `services/llm`.
- Пресеты промптов, лорбуки, регулярные выражения, свои инструменты: общие основы создания и вставки промптов.
- Транспорт генерации: `packages/client/src/hooks/use-generate.ts`, `packages/server/src/routes/generate.routes.ts` и реестр провайдеров.
- TTS, перевод, галерея, темы оформления, настройки, импорт, резервные копии.

### Режим Conversation

Основной код:

- Клиент: `components/chat/ChatConversationSurface.tsx`, `ConversationView.tsx`, `ConversationMessage.tsx`, `ConversationInput.tsx` и связка быстрого старта Conversation в `ChatArea.tsx`.
- Клиентские хуки: `use-autonomous-messaging.ts`, `use-background-autonomous.ts`.
- Сервер: `/api/conversation`, `services/conversation/*`.
- Общие метаданные: `conversationSchedulesEnabled`, `characterSchedules`, `scheduleWeekStart`, а также сводки по дням и неделям.

Ожидаемая граница:

- Conversation отвечает за расписания, автономные проверки связи, активность в Conversation и показ сообщений вне Roleplay.
- Conversation не должен знать про игровые кубики, теги GM, события на время, игровые карты и бой.

### Режим Roleplay

Основной код:

- Клиент: `components/chat/ChatRoleplaySurface.tsx`, `ChatMessage.tsx`, `ChatInput.tsx`, компоненты `RoleplayHUD`, `SpriteOverlay.tsx`, `SceneBanner.tsx`, `CyoaChoices.tsx` и `EncounterModal.tsx`.
- Сервер: `/api/scene`, `/api/encounter`, `/api/sprites` и части `/api/generate`.
- Общие контракты: `scene`, поля метаданных чата, связанные с Roleplay, и типы размещения спрайтов.

Ожидаемая граница:

- Roleplay отвечает за сцены, показ спрайтов, выбор CYOA, панель HUD режима Roleplay и вспомогательные сценарии сражений в Roleplay.
- Общие визуальные эффекты, которыми пользуется и Game Mode, стоит вынести из `components/chat`.

### Режим Game Mode

Основной код:

- Клиент: `components/game/*`, `hooks/use-game.ts`, `hooks/use-scene-analysis.ts`, `stores/game-mode.store.ts`, `stores/game-state.store.ts`, `stores/game-asset.store.ts`, `lib/game-*`, `lib/party-dialogue-parser.ts`.
- Сервер: `/api/game`, `/api/game-assets`, `services/game/*`, а также игровые части `services/sidecar/scene-analyzer.ts` и `scene-postprocess.ts`.
- Общие контракты: `types/game.ts`, `types/game-state.ts`, `types/combat-encounter.ts` и игровые поля в `ChatMetadata`.

Ожидаемая граница:

- Game Mode отвечает за промпты GM, промпты отряда, кубики, проверки навыков, события на время, игровой бой, карты, путешествия и отдых, погоду и время, репутацию персонажей NPC, сводки игровых сессий, сгенерированные игровые ресурсы и игровые журналы.
- Game Mode не должен зависеть от интерфейса режимов чата – только от общих примитивов или явно общих компонентов функций.

Первая уборка в общем пакете все равно должна идти на уровне типов и небольшими шагами, а не массовым переносом файлов.

## Правила переноса

1. Размещайте новый код в самом узком подходящем разделе.
2. Если клиентский компонент нужен двум режимам или больше, перенесите его в `CLIENT-SHARED`, прежде чем добавлять новое поведение под конкретный режим.
3. Если тип, схема или чистая вспомогательная функция нужны и клиенту, и серверу, перенесите их в `CORE-CONTRACT`.
4. Если что-то нужно только серверу, не держите это в `packages/shared`.
5. Файлы маршрутов должны проверять входные данные HTTP и вызывать службы. Решения предметной области стоит перенести в службы.
6. Хранилище должно быть либо глобальным (`ui`, `chat`, `sidecar`), либо привязанным к режиму (`game-mode`, `encounter`). Не допускайте, чтобы одно хранилище незаметно отвечало сразу за несколько режимов.
7. Метаданные стоит разделить по признаку `ChatMode`: базовые метаданные плюс поля Conversation, Roleplay и Game Mode.
8. Переносите по одной функции за раз. Оставляйте экспорт или обертки для совместимости, если иначе широко используемый путь импорта перетряхнет весь репозиторий.
9. После каждого переноса запускайте линтер:

   ```bash
   pnpm lint
   ```

   Затем прогоните Prettier точечно по затронутым файлам.

## Первые кандидаты на переработку

С этих проходов удобно начинать: они снижают сцепленность и не меняют поведение.

1. Разделите `components/chat` на группы: общее, Conversation и Roleplay.
   - Кандидаты в общее: `ChatCommonOverlays`, `ChatBranchSelector`, `ChatGalleryDrawer`, `WeatherEffects`, а также общие примитивы сообщений и ввода.
   - Кандидаты в Conversation: `ChatConversationSurface`, `ConversationView`, `ConversationMessage`, `ConversationInput`.
   - Кандидаты в Roleplay: `ChatRoleplaySurface`, `SpriteOverlay`, `SceneBanner`, `CyoaChoices`, `EncounterModal`. Панель HUD режима Roleplay уже частично разделена: `RoleplayHUDActionsMenu.tsx` и `RoleplayHUDPanels.tsx`.
2. Перенесите клиентские вспомогательные функции, нужные только Game Mode, в игровой модуль.
   - Кандидаты: `game-audio`, `game-tag-parser`, `game-full-body-pose`, `game-character-name-match`, `game-segment-edits`, `party-dialogue-parser`.
3. Разделите `GameSurface.tsx` на хуки времени выполнения и контейнеры поменьше.
   - Кандидаты в хуки: повествование, ресурсы, анализ сцены, бой, журнал и история, звук.
4. Разделите `GameNarration.tsx` на разбор и форматирование команд плюс компоненты отображения.
5. Разделите `game.routes.ts` по группам обработчиков.
   - Возможные группы: настройка и сессия, генерация хода, кубики, проверки навыков и события на время, дневник и инвентарь, карта, путешествия и погода, бой, ресурсы и анализ сцены.
6. Разделите `generate.routes.ts` на транспорт генерации, обработку конвейера агентов, маршруты повтора, а также вспомогательные функции команд и постобработки. Задача #7573 начала эту работу: цепочка вывода токенов, раунды инструментов, команды ответа, очистка текста ответа, сведения о генерации в сохраненном сообщении, привязка скрытых команд и сохранение ответа теперь находятся в `routes/generate/`, и у каждой из этих частей есть собственный регрессионный тест.
7. Разделите `ChatMetadata` на контракты метаданных под каждый режим.
8. Вынесите общую графику Roleplay и Game Mode из `components/chat`, пока Game Mode не начал импортировать еще больше внутренних частей чата.

## С чего начать на практике

Для следующего PR с уборкой используйте такой порядок:

1. Создайте целевые папки только для одной области.
2. Сначала перенесите чистые вспомогательные функции.
3. Затем перенесите конечные компоненты.
4. Крупный оркестратор оставьте на месте, пока его импорты в основном не будут указывать на новый модуль.
5. Добавляйте реэкспорт для совместимости только там, где перетряска импортов отвлекала бы от сути изменения.
6. Запустите линтер:

   ```bash
   pnpm lint
   ```

   Затем прогоните Prettier точечно по затронутым файлам.
