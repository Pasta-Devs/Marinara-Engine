# Запуск в контейнере (Docker / Podman)

В этом руководстве вы узнаете, как запустить Marinara Engine в контейнере Docker или Podman. Контейнер – это готовый пакет, в который упакованы само приложение и все, что нужно ему для работы. Node.js и другие инструменты на компьютер устанавливать не придется. Если вы только начинаете и хотите просто запустить Marinara, это самый простой путь.

## Что нужно заранее

Перед началом установите на машину, которая будет запускать Marinara, одно из двух:

- Docker Desktop (Windows или macOS) либо Docker Engine (Linux). Docker – самый распространенный инструмент для контейнеров.
- Либо Podman. Podman полностью заменяет Docker. Он работает без фоновой службы и не требует прав root.

Несколько терминов, которые встретятся дальше:

- **Образ** (image): шаблон только для чтения, который скачивается и содержит Marinara Engine. Запуская образ, вы получаете работающий контейнер.
- **Том** (volume): область хранения, которой управляет сам инструмент контейнеров. Данные в томе сохраняются, даже если контейнер удалить и создать заново.
- **LAN**: локальная сеть – домашняя или офисная, по Wi-Fi или по кабелю.

Официальные образы Marinara публикуются в `ghcr.io/pasta-devs/marinara-engine`.

## Скачивание и запуск

В корне репозитория уже лежит готовый файл `docker-compose.yml`. Compose читает его и сам поднимает контейнер. Это рекомендуемый способ запуска.

1. Получите копию репозитория. Если папка с Marinara Engine у вас уже есть, откройте в ней терминал. Если нет – сначала клонируйте репозиторий:

```bash
git clone https://github.com/Pasta-Devs/Marinara-Engine.git
```

2. Перейдите в папку:

```bash
cd Marinara-Engine
```

3. Запустите контейнер в фоне:

```bash
docker compose up -d
```

Файл `docker-compose.yml` использует образ `ghcr.io/pasta-devs/marinara-engine:latest` и скачивает его при первом запуске этой команды. Первое скачивание может занять несколько минут.

## Проверка работы

1. Откройте браузер.
2. Перейдите по адресу:

```text
http://127.0.0.1:7860
```

Должна открыться главная страница приложения Marinara Engine. Если она открылась – контейнер работает. Адрес `127.0.0.1` означает "этот же компьютер", а `7860` – порт, который Marinara слушает по умолчанию.

Если страница не открывается, посмотрите раздел "Устранение неполадок" ниже.

## Где хранятся данные

Данные – чаты, персонажи, загруженные файлы, шрифты и стандартные фоны – хранятся обычными файлами. Marinara использует файловое хранилище: все лежит отдельными файлами, а не внутри одного файла базы данных. Compose держит эти файлы в именованном томе `marinara-data`.

Compose подставляет имя папки проекта перед именем тома, поэтому настоящее имя выглядит как `PROJECT_marinara-data`. Чтобы узнать точное имя на своей машине, выведите список томов:

```bash
docker volume ls --filter name=marinara-data
```

Затем посмотрите свойства нужного тома из списка и узнайте, где он лежит:

```bash
docker volume inspect PROJECT_marinara-data
```

Вместо `PROJECT_marinara-data` подставьте имя, которое напечатала предыдущая команда.

При каждом запуске контейнер готовит папку с данными. По умолчанию он стартует от имени root. Сначала контейнер исправляет владельца папки, чтобы приложение могло в нее писать, а затем ради безопасности переключается на обычного пользователя. Это работает и для именованного тома, и для папки, подключенной с хоста. Благодаря этому старые установки переходят на файловое хранилище без ручных команд смены владельца.

При первом запуске Marinara также создает в томе пустой файл настроек `/app/data/.env`. Позже в него можно дописать настройки сервера. Файл лежит в томе, поэтому настройки переживают и перезапуск контейнера, и обновление образа. Полный список настроек собран в документе [Настройки сервера: справочник](../CONFIGURATION.md).

## Открытие доступа к Marinara в локальной сети

По умолчанию Compose разрешает открывать Marinara только с этого же компьютера. Это безопасный вариант. Чтобы зайти с телефона или другого компьютера в той же сети, нужно сделать две вещи: изменить проброс порта и включить вход по паролю, иначе доступ получат посторонние.

Basic Auth – это простой запрос имени пользователя и пароля, который закрывает приложение. Никогда не открывайте Marinara в сеть без него.

1. Откройте `docker-compose.yml` в текстовом редакторе.

2. Найдите строку с портом. Она выглядит так:

```yaml
ports:
  - "127.0.0.1:${PORT:-7860}:7860"
```

3. Уберите часть `127.0.0.1:`, чтобы приложение стало доступно другим устройствам:

```yaml
ports:
  - "${PORT:-7860}:7860"
```

4. В том же файле добавьте в список `environment:` логин, пароль и секрет администратора. Значения подставьте свои:

```yaml
environment:
  - BASIC_AUTH_USER=yourname
  - BASIC_AUTH_PASS=a-long-random-password
  - ADMIN_SECRET=another-long-random-value
```

5. Сохраните файл и перезапустите контейнер:

```bash
docker compose up -d
```

Теперь другие устройства в сети открывают Marinara по адресу `http://YOUR_COMPUTER_IP:7860`, если переменная `PORT` не задана. Если `PORT` задана, вместо `7860` подставьте этот порт хоста. При входе устройства спросят заданные имя пользователя и пароль.

В Docker Desktop, OrbStack и rootless Docker все устройства попадают в контейнер с одного и того же адреса, включая ваш собственный браузер. Поэтому, как только вход настроен, этот компьютер тоже его запрашивает, а список разрешенных IP-адресов не может различить устройства. Никогда не убирайте `127.0.0.1:` без настроенного входа: в этих средах Marinara не может отличить другие устройства от этого компьютера. О том, как разрешить доступ только определенным устройствам и зачем нужен секрет администратора, читайте в руководстве [Удаленный доступ: Basic Auth и список разрешенных адресов](../REMOTE_ACCESS.md).

## Выбор образа: latest, staging или lite

Marinara публикует несколько тегов образа. Выберите подходящий.

- `latest` – рекомендуемый стабильный выпуск. Файл `docker-compose.yml` использует его по умолчанию.
- `X.Y.Z` – фиксированная версия, например `ghcr.io/pasta-devs/marinara-engine:2.0.6`. Берите этот вариант, когда нужен ровно один конкретный выпуск.
- `staging` – нестабильная тестовая сборка из свежего кода разработки. Ее стоит брать только для того, чтобы посмотреть на еще не вышедшие изменения. Она может ломаться, менять поведение без предупреждения и не дать вернуть данные обратно в стабильную сборку.
- `lite` – облегченный образ. О нем – следующий раздел.

Если вы запускаете образ `staging`, подключите отдельный том, чтобы нестабильная сборка не тронула стабильные данные:

```bash
docker run -d --name marinara-staging -p 127.0.0.1:7860:7860 -v marinara-staging-data:/app/data ghcr.io/pasta-devs/marinara-engine:staging
```

### Образ lite

Образ lite меньше по размеру: часть офлайн-возможностей в нем убрали ради заметно меньшего скачивания. Он собран на Wolfi – минимальной основе Linux, созданной для контейнеров.

В образе lite нет возможностей, которым нужны большие локальные файлы:

| Убрано в lite | Что теряется |
| --- | --- |
| Local Model (Gemma, запускается на вашем компьютере) | Модель ИИ нельзя запустить на своем оборудовании. |
| Локальная модель эмбеддингов | Эмбеддинги текста на устройстве недоступны. |
| Memory Recall (семантический поиск) | Зависит от локальной модели эмбеддингов. |
| Локальный голосовой ввод Whisper | Распознавание речи в звонках режима Conversation недоступно. |
| Определение настроения для аватаров | 2D- и 3D-аватары выбирают выражение лица по списку слов, а не с помощью небольшой локальной модели эмоций. |

Остальное работает как обычно: чат, ролевая игра, Game Mode, агенты, лорбуки, персонажи и подключения к удаленным провайдерам ИИ. Чтобы в образе lite заработали функции ИИ, подключите внешнего провайдера – например OpenRouter, OpenAI или модель на своем сервере. См. руководство [Подключение к провайдеру ИИ](../connections/connecting-to-a-provider.md).

Тег облегченного образа – `ghcr.io/pasta-devs/marinara-engine:lite`; кроме того, у каждого выпуска есть тег lite с привязкой к версии, например `ghcr.io/pasta-devs/marinara-engine:X.Y.Z-lite`. Запуск:

```bash
docker run -d --name marinara-lite -p 127.0.0.1:7860:7860 -v marinara-data:/app/data ghcr.io/pasta-devs/marinara-engine:lite
```

Некоторые старые образы lite падают на Raspberry Pi 4 и похожих компьютерах на ARM. При обращении к провайдеру ИИ появляется ошибка `SIGILL` – процессор сообщает о недопустимой инструкции. На таких устройствах запускайте обычный образ `latest`. Актуальные подробности – в руководстве [Устранение неполадок в приложении Marinara Engine](../TROUBLESHOOTING.md).

## Обновление

Образы контейнеров сами не обновляются. Новый образ нужно скачать и перезапустить контейнер вручную. Сначала сделайте резервную копию, чтобы можно было вернуться точно туда, где вы были. См. [Резервное копирование и восстановление Marinara](../data/backup-and-restore.md).

Для Docker Compose достаточно одной команды:

```bash
docker compose pull && docker compose up -d
```

Для Podman Compose достаточно одной команды:

```bash
podman compose pull && podman compose up -d
```

Версию можно посмотреть и в самом приложении. Откройте панель **Settings** (настройки), перейдите на вкладку **Advanced** (дополнительно) и найдите раздел **Updates** (обновления). Нажмите кнопку **Check for Updates** (проверить обновления). При установке в контейнере Marinara определяет, что работает в Docker, и показывает тег образа выпуска вместе с командой для хоста. Обновиться из браузера приложение не может, поэтому команду выше все равно запускаете на хосте.

Чтобы вернуться к более старому выпуску, укажите его тег версии в строке `image:` файла `docker-compose.yml`, например `ghcr.io/pasta-devs/marinara-engine:2.5.0`, затем выполните `docker compose up -d`. Возврат на 2.5.0 работает, и ваши чаты нормально открываются, но версия 2.5.0 не знает о настройках и игровых данных, которые добавили новые функции. Любой чат или подключение, которое сохранит 2.5.0, теряет эти данные, и повторное обновление их не возвращает. См. раздел [Возврат на версию 2.5.0](../UPGRADING.md#going-back-to-250).

## Podman

Podman запускает те же образы, что и Docker. В большинстве случаев в командах выше достаточно заменить `docker` на `podman`.

Запуск через Compose:

```bash
podman compose up -d
```

Запуск одного контейнера без Compose:

```bash
podman run -d -p 127.0.0.1:7860:7860 -v marinara-data:/app/data ghcr.io/pasta-devs/marinara-engine:latest
```

Команде `podman compose` нужен вспомогательный пакет `podman-compose`. Установите его командой для своей системы.

В Fedora:

```bash
sudo dnf install podman-compose
```

В Debian или Ubuntu:

```bash
sudo apt install podman-compose
```

Через pip:

```bash
pip install podman-compose
```

## Самостоятельная сборка образа

Если вместо скачивания образ хочется собрать из исходников:

```bash
docker build -t marinara-engine .
```

Затем запустите собственную сборку:

```bash
docker run -d -p 127.0.0.1:7860:7860 -v marinara-data:/app/data marinara-engine
```

Чтобы собрать из исходников образ lite, укажите Docker на файл сборки lite:

```bash
docker build -f Dockerfile.lite -t marinara-engine:lite .
```

## Устранение неполадок

**Страница не открывается или порт уже занят.** Возможно, порт `7860` использует другая программа. Пропишите в списке `ports:` свободный порт, например `8080:7860`. Затем перезапустите контейнер командой `docker compose up -d` и откройте `http://127.0.0.1:8080`.

**Marinara не может записывать файлы или появляются ошибки доступа.** При каждом запуске контейнер исправляет владельца папки с данными. Это работает и для именованных томов, и для папок, подключенных с хоста. На некоторых файловых системах хоста исправление не срабатывает, а при `MARINARA_SKIP_DATA_CHOWN=true` оно пропускается. Если ошибки не проходят, используйте стандартный именованный том `marinara-data` – это самый надежный вариант.

**Образ lite падает на Raspberry Pi 4.** Смотрите замечание об образе lite выше. На этом оборудовании используйте обычный образ `latest`.

Если нужна дополнительная помощь, читайте руководство [Устранение неполадок в приложении Marinara Engine](../TROUBLESHOOTING.md).
