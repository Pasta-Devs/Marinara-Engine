# Обновление приложения Marinara Engine

В этом руководстве вы узнаете, как обновить приложение Marinara Engine до новой версии. Здесь разобраны все способы установки, встроенные средства обновления и порядок действий, если обновление не удалось. Чаты и настройки при обновлении сохраняются.

## Данные сохраняются

Обновление приложения Marinara Engine не удаляет данные. Чаты, персонажи, персоны, лорбуки, пресеты, подключения и настройки остаются на месте.

Marinara хранит данные в локальной папке на той машине, где работает сервер. В контейнерах Docker и Podman они лежат в томе `marinara-data`. Обновление заменяет только код приложения, а эту папку и том не трогает.

При обновлении с версии, где встроенные агенты, карты, звонки и игры режима Conversation поставлялись в комплекте, первый запуск скачивает соответствующие дополнительные пакеты из официального каталога. Выбор элементов в существующих чатах, настройки агентов, сохраненные рабочие данные и история сохраняются. Для этого первого запуска сервер должен быть в сети. Если каталог недоступен, Marinara повторяет перенос при следующем запуске и не удаляет и не отключает сохраненные настройки.

Если вы скачали документацию на другом языке (**Settings** (настройки) → **General** (общие) → **Documentation Language** (язык документации)), при первом запуске после обновления языковой пакет тоже проверяется на изменения и обновляется автоматически. Если источник скачивания недоступен, Marinara оставляет уже установленный пакет (руководства, которых в нем нет, показываются по-английски) и повторяет попытку при следующем запуске. Выбранный язык обновление никогда не сбрасывает.

Где именно лежат данные и как сохранить их копию, описано в руководстве [Резервное копирование и восстановление Marinara](data/backup-and-restore.md).

## Сначала сделайте резервную копию

Обновление безопасно, но резервная копия – дешевая страховка. Сделайте ее перед любым большим переходом между версиями.

1. Откройте панель **Settings**.
2. Перейдите на вкладку **Advanced** (дополнительно).
3. Найдите раздел **Backup & Export** (резервные копии и экспорт).
4. Нажмите кнопку **Download Backup** (скачать резервную копию).
5. Сохраните файл `.zip` в надежном месте.

Пока идет работа, надпись на кнопке меняется на **Creating backup…**. По завершении браузер сохраняет архив `.zip` с вашими данными.

Полные инструкции по резервному копированию и восстановлению собраны в руководстве [Резервное копирование и восстановление Marinara](data/backup-and-restore.md).

## Обновление на разных платформах

Выберите раздел, который соответствует способу установки приложения Marinara. Запись "git checkout" ниже означает копию, установленную с помощью программы Git. "Clone" – это скачанная копия, сделанная средствами Git.

### Windows

Если вы пользовались установщиком для Windows или копией git checkout, скрипт запуска обновляет приложение сам.

1. Закройте приложение Marinara Engine.
2. Откройте его снова через ярлык в меню "Пуск" или запустите `start.bat`.

Скрипт запуска скачивает свежий код, переустанавливает изменившиеся части, собирает приложение заново и запускает новую версию. Так работает и установщик, и склонированная вручную копия.

Чтобы пропустить обновление один раз, запустите `start.bat --skip-update`. Чтобы версия Engine оставалась прежней при каждом запуске, укажите `AUTO_UPDATE_ENABLED=false` в файле `.env` проекта. Это отключает только автоматическое обновление Engine; команды вручную и пункт **Settings → Advanced → Check for Updates** (проверить обновления) остаются доступны.

Если скрипт запуска сообщает, что версия Node.js слишком старая, установите Node.js 24 LTS и запустите Marinara снова. LTS – это Long Term Support, долгосрочная поддержка: рекомендуемый стабильный выпуск Node.js.

Другой вариант: скачать свежий установщик со страницы GitHub Releases и запустить его. Он использует тот же путь на основе Git, поэтому дальнейшие обновления снова идут через скрипт запуска.

### macOS и Linux

Закройте приложение Marinara Engine, затем запустите скрипт запуска из папки Marinara.

```bash
./start.sh
```

Скрипт запуска скачивает свежий код, переустанавливает изменившиеся зависимости, собирает приложение и запускает новую версию.

Для одного запуска используйте `./start.sh --skip-update`, а для постоянного отказа укажите `AUTO_UPDATE_ENABLED=false` в файле `.env`. Команды обновления вручную и встроенные элементы управления обновлением остаются доступны.

Если сообщается, что версия Node.js слишком старая, установите Node.js 24 LTS и запустите скрипт запуска снова.

### Docker или Podman

Установки в контейнере обновляются скачиванием нового образа, а не через скрипт запуска. Выполните команду из папки, где лежит файл Compose.

```bash
docker compose down && docker compose pull && docker compose up -d
```

Для Podman те же команды выполняются с `podman`.

```bash
podman compose down && podman compose pull && podman compose up -d
```

Образы выпусков публикуются как `ghcr.io/pasta-devs/marinara-engine:X.Y.Z` и `:latest`, а также с парными тегами `-lite`. Скачивайте `:latest` или самый новый тег версии, если только вы не хотите специально остаться на старом выпуске. Данные в томе `marinara-data` при скачивании образа не затрагиваются.

### Android (Termux)

Termux – это терминал и окружение Linux для Android. Его скрипт запуска обновляет Marinara при каждом запуске.

1. Откройте приложение Termux.
2. Запустите скрипт запуска.

```bash
cd Marinara-Engine
./start-termux.sh
```

Скрипт запуска обновляет код, при необходимости обновляет Node.js, собирает приложение и запускает локальный сервер.

Если обновление сломано и нужно остаться на текущей копии, пропустите проверку обновлений.

```bash
cd Marinara-Engine
./start-termux.sh --skip-update
```

Для постоянного отказа укажите `AUTO_UPDATE_ENABLED=false` в файле `.env` проекта. Это касается только обновлений Engine, которыми управляет скрипт запуска; обновление вручную и встроенные элементы управления обновлением остаются доступны.

Если вы пользуетесь значком приложения на Android (файл APK), [скачайте последнюю версию APK](https://github.com/Pasta-Devs/Marinara-Engine/releases/latest/download/marinara-engine-android.apk) и откройте файл, чтобы Android обновил саму оболочку. Затем откройте Marinara Engine и нажмите **Install / Start Marinara**, чтобы обновить и запустить копию Termux. Приложение автоматически сохраняет и передает закрытые учетные данные для localhost; обновление никогда не просит учетные данные подписи или этот секрет.

### iPhone и iPad

На iPhone и iPad сервер Marinara не работает. С них вы через браузер Safari открываете сервер, запущенный на другом устройстве. Копия на домашнем экране – это приложение PWA, то есть Progressive Web App. Приложение PWA – это сайт, добавленный на домашний экран: он открывается как обычная программа.

1. Обновите компьютер, хост Docker или устройство Android, на котором действительно работает сервер Marinara. Используйте раздел для этого устройства выше.
2. Перезагрузите приложение PWA с домашнего экрана или вкладку Safari на iPhone или iPad.

Если Safari продолжает показывать старую сборку после обновления хоста, сбросьте кешированную копию.

1. Удалите значок с домашнего экрана.
2. Очистите данные сайта Safari для хоста Marinara.
3. Снова добавьте его на домашний экран.

## Проверка и установка обновлений в приложении

Marinara умеет проверять наличие новой версии на GitHub прямо из приложения. Некоторые установки могут еще и установить обновление из браузера.

1. Откройте панель **Settings**.
2. Перейдите на вкладку **Advanced**.
3. Найдите раздел **Updates** (обновления).

### Release Channel

Раскрывающийся список **Release Channel** (канал выпусков) задает, за какими сборками вы следите. В нем два варианта.

- **Latest Stable**: отслеживает выпуски с тегами `vX.Y.Z`. Обычный выбор в большинстве случаев.
- **Staging/UAT**: отслеживает предварительные сборки для тестирования. Они могут быть незавершенными. Сделайте резервную копию данных перед их использованием.

При выборе **Staging/UAT** появляется предупреждение: "Staging builds are pre-release tester builds. Back up your app data before applying them."

Смена канала считается осознанным решением. Выберите другой канал в браузере на той машине, где работает сервер, – и надпись на кнопке обновления сменится на **Switch to** с названием канала. Такая кнопка работает даже при выключенных обычных обновлениях из приложения. Во время работы она показывает **Switching…**. Обычным обновлениям внутри того же канала по-прежнему нужны настройки из раздела Apply Update ниже, а удаленным устройствам – всегда.

### Check for Updates

Нажмите кнопку **Check for Updates**. Во время работы кнопка показывает **Checking…**.

Под кнопкой видны версия **Release** и код коммита **Build**. Строка **Branch** появляется, когда ветка известна.

- Если у вас последняя версия, зеленая строка с галочкой сообщает "You're on the latest ... target" и показывает номер версии.
- Если новая версия есть, появляется плашка "vX.Y.Z available" со ссылкой **Release notes**.
- Если установка из Git просто отстала, плашка вместо этого показывает "N commits behind". Коммит – это одно сохраненное изменение в коде, поэтому в этот счет может попасть и невыпущенная работа.

Результаты проверки обновлений кешируются. Проверка версии выпуска кешируется примерно на 15 минут, счетчик "commits behind" – примерно на 5 минут. Повторное нажатие кнопки **Check for Updates** сразу же может показать те же числа.

### Apply Update

Кнопка **Apply Update** (применить обновление) появляется только тогда, когда установка умеет обновляться сама из браузера. Для этого нужны два условия.

- Установка на основе Git (Docker и упакованные установки так обновляться не могут).
- В файле `.env` сервера указано `UPDATES_APPLY_ENABLED=true`. В файле `.env` хранятся настройки сервера.

Если нажать кнопку **Apply Update** на той машине, где работает сервер, этого достаточно. Секрет там не нужен.

Применение обновления с другого устройства по умолчанию выключено. Для него нужны три условия.

- В файле `.env` указано `UPDATES_ALLOW_REMOTE_APPLY=true`.
- В файле `.env` задан `ADMIN_SECRET` – пароль для защищенных действий.
- Этот же секрет сохранен в разделе **Settings -> Advanced -> Admin Access** на вашем устройстве.

После нажатия кнопки **Apply Update** на ней появляется **Updating...**. Сервер скачивает новый код, переустанавливает зависимости, собирает приложение и затем выключается. Дальше вы увидите сообщение: "Update applied successfully. Please relaunch the app to use the new version." Запустите Marinara снова, чтобы завершить обновление.

Если кнопка **Apply Update** недоступна, Marinara объясняет причину и что делать вместо этого.

- Установки в контейнере показывают тег образа и команду `docker compose pull && docker compose up -d`, которую нужно выполнить на хосте.
- Установки из Git с выключенным применением обновлений показывают команду обновления вручную – ее можно скопировать.
- Остальные установки показывают ссылку **Download** на выпуск в GitHub.

Если не удалась сама проверка, появляется сообщение: "Could not check for updates. Try again later." Обычно это значит, что дело в сети или в проблеме на стороне GitHub, поэтому попробуйте через минуту.

## Кнопка Refresh App

Кнопка **Refresh App** (обновить приложение) находится в том же разделе **Updates**. Это не обновление сервера. Она обновляет только приложение в текущем браузере.

Кнопка **Refresh App** отменяет регистрацию service worker, очищает кеш браузера и перезагружает страницу. Service worker – это небольшой скрипт, с помощью которого браузер быстро загружает приложение и работает без сети. Сохраненные чаты, настройки и другие локальные данные остаются нетронутыми.

Нажимайте кнопку **Refresh App**, когда после обновления приложение выглядит устаревшим или показывает пустой экран, а сервер уже работает на новой версии. Так лечится зависшая веб-страница. Код сервера при этом не меняется, поэтому настоящее обновление кнопка не заменяет.

Во время работы кнопка показывает **Refreshing…**, а затем приложение перезагружается.

## Переход на старую версию

Обновления всегда безопасны, но напрямую вернуться назад можно не всегда. Новые версии Marinara хранят сообщения чатов в более новом дисковом формате, который не может прочитать версия старше формата ваших данных. Для защиты истории программа запуска пропускает автообновления на несовместимые версии, а встроенный механизм обновления отказывается их применять.

Если старая версия все же нужна, одна команда преобразования сначала возвращает данные в старый формат. Инструкции приведены в разделе [После перехода на старую версию в чатах не видно сообщений](TROUBLESHOOTING.md#chats-show-no-messages-after-switching-to-an-older-version).

## Если обновление не удалось

Чаще всего проблемы с обновлением вызывает старая версия Node.js, недокачанные файлы или устаревший кеш браузера.

- Если скрипт запуска сообщает, что версия Node.js слишком старая, установите Node.js 24 LTS и запустите приложение снова.
- Если после обновления сервера приложение выглядит сломанным, попробуйте кнопку **Refresh App** выше.
- Если установка из Git не может обновиться без ошибок, выполните команды обновления вручную для вашей платформы – они приведены в соответствующем руководстве по установке.

Тексты ошибок и пошаговые решения собраны в руководстве [Устранение неполадок в приложении Marinara Engine](TROUBLESHOOTING.md).
