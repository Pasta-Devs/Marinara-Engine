# Проверки набора правил

Эта страница – часть руководства [Создание наборов правил Game Mode](writing-rulesets.md). Как набор правил выполняет проверку или спасбросок: пять видов разрешения, степени исхода, проверки с собственным способом броска и расходы или талисманы, меняющие бросок.

<a id="resolution-kinds"></a>

## Виды разрешения

`resolution.kind` выбирает способ броска проверки. Все виды читают один лист и имеют три общих ключа, поэтому части файла ниже `resolution` не меняются при переключении:

- `abilityModifier`: преобразование показателя листа в число. При `identity` показатель и есть число. `floorHalfMinusTen` – правило 5e. `stepTable` позволяет перечислить собственные пороги как `[[score, number], ...]`.
- `proficiencyTiers`: уровни подготовки навыка или спасброска. Неуказанный навык получает первый. Уровень добавляет `flat`, либо `multiplier`, умноженное на бонус мастерства, либо оба. Если в системе есть бонус мастерства, укажите его источник через `"proficiency": { "bonus": { "derived": "proficiency_bonus" } }`.
- `proficiency`: необязательно, нужно лишь уровню с умножением.

Значение полученного числа зависит от вида: `dice-sum` прибавляет его к броску, `dice-pool` и `dice-highest` бросают столько костей. `symbol-pool` держит характеристику и подготовку раздельно, чтобы набирать и улучшать повествовательные кости.

### `dice-sum`: сложение костей

```json
"resolution": {
  "kind": "dice-sum",
  "dice": { "count": 2, "sides": 6 },
  "abilityModifier": { "op": "identity" },
  "proficiencyTiers": [
    { "id": "untrained", "label": "Untrained" },
    { "id": "trained", "label": "Trained", "flat": 1 }
  ],
  "advantage": false,
  "difficultyLadder": [
    { "label": "Easy", "dc": 6 },
    { "label": "Hard", "dc": 10 }
  ]
}
```

- `dice`: число костей и граней. Сумма сравнивается со сложностью.
- `advantage`: может ли Game Master попросить дважды бросить кости и оставить один бросок.
- `naturals`: влияние высшей и низшей грани одной кости на проверки и спасброски: `none`, `both`, `max-only` или `min-only`. Для чистой арифметики опустите. Требует одной кости, поэтому система 2d6 должна использовать `none`.
- `dice.faces`: ценность каждой грани, начиная с низшей, если грани не равны своим числам (Capability API 1.136). Четыре кости Fudge в Fate – это `{ "count": 4, "sides": 3, "faces": [-1, 0, 1] }`: карточка показывает минус, пустую грань и плюс и складывает их, а вероятности в точности такие же, как в Fate. Укажите по одному значению на каждую грань.
- `openEnded`: одна кость, бросок которой продолжается (1.136). Грань не ниже `high` бросается снова и прибавляется, и так снова, пока новая кость показывает `high` или больше; грань не выше `low` бросается снова и вычитается, и этот бросок точно так же продолжается на `high`. Открытый процентный бросок Rolemaster – это `{ "high": 96, "low": 5 }` на одной d100. Один бросок бросает не больше 20 костей. Естественные грани и сдвиг по степеням исхода читают первую кость.
- `unmodified`: грани одной кости, которые запись помечает, когда их показывает первая кость (1.136), чтобы можно было применять таблицы, где "немодифицированное 66" рассматривается отдельно: `[66, 100]`. В записи появляется `unmodified="66"`, карточка тоже это показывает, а Game Master получает указание применить то, что о таком броске говорят правила.
- `difficultyLadder`: сложности, из которых должен выбирать Game Master. `dc` – число, которого должна достичь сумма. Game Master может назвать ступень вместо ее числа, например `difficulty="Hard"`, и Engine возьмет число из ступени.

### `dice-pool`: бросок костей и подсчет результатов

Число листа – **размер пула**, а не добавочный бонус. Рейтинг 3 и профессиональный навык стоимостью 2 дают пять костей. В этом вся идея: без нового словаря листа и нового редактора; система с рейтингами в виде горстей костей использует те же `abilities`, `skills` и `proficiencyTiers`, что и любая другая.

```json
"resolution": {
  "kind": "dice-pool",
  "die": { "sides": 10 },
  "abilityModifier": { "op": "identity" },
  "proficiencyTiers": [
    { "id": "rating_0", "label": "Untried" },
    { "id": "rating_1", "label": "Shown once", "flat": 1 }
  ],
  "pool": { "min": 1, "max": 15, "abilityPlusAbility": true },
  "target": { "default": 7, "min": 5, "max": 9 },
  "explode": { "from": 10, "min": 8 },
  "cancel": { "upTo": 1 },
  "botch": { "upTo": 1 },
  "exceptional": { "successes": 5 },
  "situationalDice": { "min": -3, "max": 3 },
  "reroll": [{ "id": "careful", "upTo": 6, "mode": "once" }],
  "difficultyLadder": [
    { "label": "Plain work", "successes": 1, "target": 6 },
    { "label": "Grim", "successes": 3, "target": 8 }
  ]
}
```

- `die`: число граней одной кости пула, от 2 до 100.
- `pool`: пределы числа листа до любых взрывов. `min` 0 позволяет пустому пулу провалиться вообще без броска; `max` – не более 100. `abilityPlusAbility: true` позволяет проверке характеристики назвать вторую характеристику через `with=` и бросить обе – для систем, где бросают два атрибута вместе; без него `with=` в проверке характеристики ничего не значит.
- `target`: грань, которой должна достичь кость для зачета. Задайте `min` ниже `max`, чтобы Game Master мог менять порог проверки через `threshold=`; равенство всех трех значений фиксирует порог.
- `double`: необязательно. Грань не ниже `from` считается дважды.
- `explode`: необязательно. Грань не ниже `from` бросает еще одну кость, которая тоже может взорваться. Дополнительных костей не больше `pool.max` сверх самого пула, поэтому проверка бросает максимум удвоенное `pool.max`, и низкое `from` не создает бесконечного броска.
- Оба правила могут иметь `min`: наименьшую грань, до которой проверка может опустить правило через `explode="N"` или `double="N"` в теге либо через использованную персонажем запись. С `min` можно опустить `from`, и тогда правило срабатывает только в проверке, которая его запрашивает: специализация, при которой десятки одного навыка бросаются снова, – это `"explode": { "min": 10 }`. `from` не может быть ниже `min`.
- `cancel`: необязательно. Грань не выше `upTo` отнимает один успех. Число не опускается ниже нуля.
- `botch`: необязательно. Если **ни одна** кость не успешна и выпала грань не выше `upTo`, проверка критически провалена. Пул с единственным отмененным успехом дает обычный, не критический провал. `"rule": "halfOrMore"` читает правило иначе: грани не выше `upTo` хотя бы на половине изначально брошенных костей (без учета взрывов) дают критический провал, если ни одна кость не успешна, а иначе оставляют результат в силе и помечают его `complication="true"`: одновременно с ним что-то идет не так. По умолчанию действует `"noSuccesses"`.
- `exceptional`: необязательно. Такое или большее число чистых успехов в успешной проверке дает критический успех.
- `situationalDice`: необязательно. Диапазон костей, добавляемых или убираемых Game Master для одной проверки через `bonus=` за трюки, раны или плохое освещение.
- `reroll`: необязательно. Перебросы, которые система дает бесплатно, до шести, каждый с `id`, который Game Master называет в проверке через `reroll=`. Грани не выше `upTo` бросаются снова: при `"once"` новая грань остается, какой бы ни была, а при `"until"` – пока не выпадет грань выше. `upTo` – от 1 до числа граней кости минус один, поскольку переброс всех граней никогда бы не закончился, а `until` в любом случае останавливается после сотни перебросов за проверку. Переброс не делается, если проверка его не называет. Одна проверка делает один переброс: если его купили также расход или использованная персонажем запись, бросается тот, что охватывает больше граней, а при равном охвате `until` побеждает `once`.
- `difficultyLadder`: `successes` задает необходимое число успехов. Ступень может назвать `target`, но только если порог регулируется и в его пределах. С этим порогом считается проверка на этой ступени: когда Game Master называет ступень через `difficulty=` или пишет `dc=`, нужное ровно одной ступени. Если нескольким ступеням нужно одинаковое число успехов, один `dc=` не скажет, какая имелась в виду, поэтому порог остается по умолчанию; назовите ступень.

- `target.from`: необязательно. Берет порог каждого персонажа из его листа, как Number в Lasers & Feelings, которое персонаж выбирает один раз (подходит любая ссылка на значение: характеристика, поле, производное значение). Порог ограничен диапазоном `min`..`max`, и `threshold=` его не сдвигает, потому что это собственное число персонажа; порог, купленный использованной персонажем записью, по-прежнему действует. `threshold=` в записи показывает, какой порог был использован.
- `stances`: необязательно. До шести, каждая с `id`, `label`, `count` (`"below"` или `"above"`) и охватываемыми навыками `skills`. Проверка одного из этих навыков считает кости **ниже** порога или **выше** него вместо костей, достигших порога: в Lasers & Feelings стойка Lasers считает ниже, а стойка Feelings – выше, и каждый навык входит в одну из них. Навык может входить только в одну стойку. Стойки обходятся без `explode`, `double`, `cancel` и `botch`, которые читаются относительно "не ниже порога".
- `exact`: необязательно. Кость, показавшая ровно порог: `label` дает ей имя (`"LASER FEELINGS"`), `text` может пояснить, что она дает за столом, и она считается одним успехом, если `counts` не равно `false`. Запись несет `exact="N"` – число таких костей, а карточка броска показывает его рядом с результатом, чтобы Game Master мог дать игроку то озарение, которое она приносит.

Грани `cancel` и `botch` должны быть ниже минимального порога, а все грани этих правил должны существовать на кости. Невыполнимое правило отклоняется при импорте, а не обнаруживается в игре.

Набор с пулом в составе пакета требует Capability API 1.24; `min` у `explode` или `double`, `pool.abilityPlusAbility` и `botch.rule` требуют 1.37, `reroll` – 1.38, `target.from`, `stances` и `exact` – 1.137. Импортируемый набор сообщества проверяет читающий его Engine, поэтому дополнительное требование не нужно.

### Что Game Master может писать в проверке пула

```
[skill_check: skill="Ward" dc="2" who="Bram the Quiet" threshold="8" bonus="-2" with="Sinew"]
[skill_check: skill="Ward" difficulty="Grim" explode="9"]
[skill_check: skill="Nerve" dc="1" with="Warmth"]
[skill_check: skill="Ward" dc="2" reroll="careful"]
```

- `dc` – число необходимых **успехов**, не порог кости. Допустимо от 1 до максимума, который можно насчитать за бросок: максимум пула, удвоенный при взрывах и еще раз удвоенный при двойном зачете граней.
- `threshold=` меняет порог кости и предлагается только при `target.min` ниже `target.max`.
- `bonus=` добавляет или убирает кости и предлагается только при объявленном `situationalDice`.
- `with=` использует для навыка или спасброска другую характеристику. Работает в обоих видах, так что набор 5e получает "Strength (Intimidation)" через тот же атрибут. В проверке характеристики он вместо этого добавляет вторую характеристику, если включено `pool.abilityPlusAbility`.
- `difficulty=` называет ступень лестницы вместо `dc=` в обоих видах: ее число успехов (или ее сложность при сумме) и, для пула, ее порог. Записанный рядом `dc=` по-прежнему главнее для числа, а `threshold=` – для порога. Имя, которому не соответствует ни одна ступень или которое носят две ступени, игнорируется.
- `explode=` и `double=` сдвигают грани этих правил для данной проверки и предлагаются, только если у правила есть `min`.
- `reroll=` называет один из ваших перебросов `reroll` для данной проверки и предлагается, только если вы их объявили. Имя, которому не соответствует ни один из них, игнорируется.

Все ограничено декларацией файла: выходящее за диапазон значение прижимается к ближайшей границе, а отсутствующая в наборе характеристика игнорируется вместо отказа проверки. Запись показывает фактически использованные значения: сложность и порог числами, бонусные кости после ограничений, `with=` – только если характеристику действительно заменили или добавили, грань – только если проверка ее сдвинула, `reroll=` – только если брошен именно названный переброс и он что-то перебросил, и `complication="true"`, если по правилу `halfOrMore` что-то пошло не так одновременно с результатом. Engine всегда сам бросает кости. Результат пула от модели заменяется, `mode="advantage"` игнорируется, потому что вид не имеет преимущества, а брошенная игроком до хода кость не применяется.

### `dice-highest`: бросок костей и выбор наибольшей

Blades in the Dark и Trophy Dark бросают горсть d6 и смотрят только на наибольшую. Capability API 1.138.

```json
"resolution": {
  "kind": "dice-highest",
  "die": { "sides": 6 },
  "abilityModifier": { "op": "identity" },
  "proficiencyTiers": [{ "id": "rating_0", "label": "0" }, { "id": "rating_1", "label": "1", "flat": 1 }],
  "pool": { "min": 0, "max": 6 },
  "zeroDice": "lowest-of-two",
  "critical": { "count": 2 },
  "situationalDice": { "min": -1, "max": 2 },
  "difficultyLadder": [{ "label": "Partial", "dc": 4 }, { "label": "Full", "dc": 6 }],
  "outcomes": {
    "by": "total",
    "tiers": [
      { "id": "critical", "label": "Critical", "on": "critical-success", "success": true },
      { "id": "full", "label": "Full success", "atLeast": 6, "success": true },
      { "id": "partial", "label": "Partial success", "atLeast": 4, "success": true, "text": "You do it, with a consequence." },
      { "id": "bad", "label": "Bad outcome" }
    ]
  }
}
```

- Число листа – количество костей, как в пуле, в пределах `pool` (не больше 20). Раны, `adjust`, состояния и предметы добавляют или убирают кости.
- `keep`: необязательно, от 1 до 3, по умолчанию 1. Сколько наибольших костей складывается: 1 – это Blades, 2 – бои Trophy Dark.
- `zeroDice`: что делает персонаж без костей. `"lowest-of-two"` (по умолчанию) бросает две кости, оставляет меньшую и никогда не дает критического успеха; `"fail"` проваливает проверку без броска.
- `critical`: необязательно. `count` костей с высшей гранью (или с гранью `face` и выше) дают критический успех: две шестерки в Blades.
- `dark`: необязательно, темные кости Trophy Dark. `label`, `max` (от 1 до 10) и `text`. Game Master добавляет их к одной проверке через `dark="N"`. `outcome` по умолчанию равно `"all"`: темные кости читаются вместе с остальными. При `"outcome": "light"` (Capability API **1.149**) оставляемые кости, сумму, степени исхода и критические результаты определяют только светлые кости. Если светлых костей нет, к светлой стороне применяется `zeroDice`: бросить две светлые кости и оставить меньшую или провалиться, все равно бросив темные кости. Темные кости всегда бросаются и записываются последними; `darkHighest="true"` означает, что темная кость строго превзошла каждую светлую (включая запасные светлые кости; если светлых не бросали, побеждает любая темная). Что это стоит (Ruin), применяет Game Master. Объявление `dark.outcome`, включая `"all"`, требует capabilityApi 1.149.
- `situationalDice`: необязательно, кости, которые Game Master может добавить или убрать через `bonus=` (помощь, усилие).
- `spend` может покупать только кости.
- `difficultyLadder`: ступени с `dc` – числом, которого должны достичь оставленные кости. `dc=` в проверке – это то же число, от 1 до `keep`, умноженного на число граней кости.
- `outcomes` читают `by: "total"` по оставленным костям, а степень с `on: "critical-success"` ловит критический успех.

Запись сохраняет форму суммы (`resolution="sum"`, `modifier="0"`, оставленные кости как сумма) и добавляет `highest="1"`, а также `zeroDice="true"` и `dark="N"`, где они применимы; темные кости идут последними в `rolls`. Исход только по светлым костям также записывает `darkOutcome="light"`, поэтому карточка подсвечивает только оставленные светлые кости, в том числе после перезагрузки. У набора такого вида нет собственного боя, поэтому `combat` рядом с ним отклоняется.

### `roll-against`: бросок не выше (или не ниже) числа листа

Call of Cthulhu, GURPS и процентные навыки вора в играх старой школы бросают против числа листа, а не прибавляют его к костям. Capability API 1.139.

```json
"resolution": {
  "kind": "roll-against",
  "dice": { "count": 1, "sides": 100 },
  "abilityModifier": { "op": "identity" },
  "proficiencyTiers": [{ "id": "base", "label": "Base" }],
  "against": "at-most",
  "criticalSuccess": [{ "from": 1, "to": 1 }],
  "criticalFailure": [{ "from": 100, "to": 100 }, { "from": 96, "whenTarget": { "below": 50 } }],
  "tens": { "max": 2 },
  "difficultyLadder": [
    { "label": "Regular", "dc": 0 },
    { "label": "Hard", "dc": 0, "divide": 2 },
    { "label": "Extreme", "dc": 0, "divide": 5 }
  ],
  "outcomes": {
    "by": "fraction",
    "tiers": [
      { "id": "critical", "label": "Critical", "on": "critical-success", "success": true },
      { "id": "extreme", "label": "Extreme success", "atLeast": 5, "success": true },
      { "id": "hard", "label": "Hard success", "atLeast": 2, "success": true },
      { "id": "regular", "label": "Regular success", "atLeast": 1, "success": true },
      { "id": "fail", "label": "Failure" },
      { "id": "fumble", "label": "Fumble", "on": "critical-failure" }
    ]
  }
}
```

- Число листа для проверки – это порог. Процент навыка – это бонус листа для этого навыка (`bonusRange` доходит до 100) без характеристики и без бонуса уровня подготовки; навык GURPS – это его атрибут плюс этот бонус.
- `dice`: что бросается и складывается, по умолчанию 1d100 (3d6 для GURPS, 1d20 для спасброска).
- `against`: при `"at-most"` (по умолчанию) успех наступает при результате не выше порога, при `"at-least"` – не ниже.
- `difficultyLadder`: `dc` каждой ступени сдвигает порог, а `divide` (от 2 до 10) сначала делит число листа. Game Master называет ступень через `difficulty=`; `dc=` в теге сдвигает число, от -100 до 100. `dc` в записи – число, относительно которого читался бросок, и запись указывает `against="at-most"`.
- `criticalSuccess` и `criticalFailure`: до шести правил каждого вида. Правило называет грани (`from`, `to`, любую границу можно оставить открытой) или, для провала, `pastTarget` – бросок, ушедший на столько же или дальше в сторону провала. `whenTarget` (`atLeast`, `below`) ограничивает правило некоторыми порогами: 5 в GURPS – критический успех только при пороге 15 или больше. Критический успех всегда успешен, а критический провал всегда проваливается.
- `tens`: необязательно, только на одной d100. `bonus="+N"` бросает N дополнительных костей десятков и оставляет лучший бросок, `bonus="-N"` – худший, до `max`.
- `outcomes` могут читать `by: "fraction"` при броске `at-most`: `atLeast` каждой степени делит порог, и бросок не выше этой доли попадает в степень. Меры `margin` (насколько ниже порога) и `total` тоже работают.

### `symbol-pool`: бросок повествовательных костей и чтение символов

Genesys набирает пул из характеристики и ранга навыка, затем добавляет противостоящие кости. На гранях вместо чисел – успех, преимущество, триумф, провал, угроза и отчаяние. Capability API 1.141.

```json
"resolution": {
  "kind": "symbol-pool",
  "abilityModifier": { "op": "identity" },
  "proficiencyTiers": [
    { "id": "untrained", "label": "Untrained", "flat": 0 },
    { "id": "rank_one", "label": "Rank 1", "flat": 1 }
  ],
  "symbols": [
    { "id": "s", "label": "Success" },
    { "id": "f", "label": "Failure", "cancels": "s" },
    { "id": "a", "label": "Advantage" },
    { "id": "h", "label": "Threat", "cancels": "a" },
    { "id": "t", "label": "Triumph", "counts": "s" },
    { "id": "d", "label": "Despair", "counts": "f" }
  ],
  "dice": [
    { "id": "ability", "label": "Ability", "faces": [[], ["s"], ["s"], ["s", "s"], ["a"], ["a"], ["s", "a"], ["a", "a"]] },
    { "id": "proficiency", "label": "Proficiency", "faces": [[], ["s"], ["s"], ["s", "s"], ["s", "s"], ["a"], ["s", "a"], ["s", "a"], ["s", "a"], ["a", "a"], ["a", "a"], ["t"]] },
    { "id": "difficulty", "label": "Difficulty", "faces": [[], ["f"], ["f", "f"], ["h"], ["h"], ["h"], ["h", "h"], ["f", "h"]] },
    { "id": "challenge", "label": "Challenge", "faces": [[], ["f"], ["f"], ["f", "f"], ["f", "f"], ["h"], ["h"], ["f", "h"], ["f", "h"], ["h", "h"], ["h", "h"], ["d"]] },
    { "id": "boost", "label": "Boost", "faces": [[], [], ["s"], ["s", "a"], ["a", "a"], ["a"]] },
    { "id": "setback", "label": "Setback", "faces": [[], [], ["f"], ["f"], ["h"], ["h"]] }
  ],
  "success": { "symbol": "s", "needed": 1 },
  "pool": { "die": "ability", "upgrade": "proficiency", "max": 6 },
  "difficulty": { "die": "difficulty", "upgrade": "challenge", "max": 5 },
  "boost": { "die": "boost", "max": 3 },
  "setback": { "die": "setback", "max": 3 },
  "criticalSuccess": "t",
  "criticalFailure": "d",
  "difficultyLadder": [{ "label": "Easy", "dc": 1 }, { "label": "Average", "dc": 2 }, { "label": "Hard", "dc": 3 }]
}
```

- `symbols`: от 2 до 10 именованных символов. `counts` также добавляет один экземпляр другого символа до взаимной отмены: триумф добавляет успех и остается триумфом. Он называет символ без собственного `counts`; цепочки и ссылки на себя отклоняются. `cancels` связывает два символа один к одному, у каждого не больше одного партнера. Обратное объявление необязательно. `text` объясняет символ для Game Master.
- `dice`: от 2 до 8 именованных костей, у каждой от 2 до 20 граней. Грани – массивы не более чем из трех идентификаторов символов; `[]` – пустая грань, а повторенные идентификаторы считаются дважды. Все ссылки должны существовать.
- `pool`: `larger-upgraded` (по умолчанию) бросает большее из значений характеристики и ранга и улучшает столько костей, сколько составляет меньшее, если объявлено `upgrade`. `sum` складывает оба значения и ничего не улучшает. `max` по умолчанию равно 6 и не может превышать 12. Характеристика использует `abilityModifier`, поэтому для характеристик Genesys используйте `identity`. Ранг берется из уровня подготовки навыка или спасброска; у простой проверки характеристики ранг нулевой. `with=` заменяет характеристику, как в других проверках. Бонусы листа, раны, поправки и эффекты добавляют кости усиления или помехи через знаковый бонус, описанный ниже.
- `difficulty`: `dc=` считает противостоящие кости от 0 до `max` (по умолчанию 5, предел 12). `difficulty=` вместо этого называет ступень лестницы. `upgrade="N"` заменяет столько противостоящих костей улучшенной костью, но не больше, чем действительно брошено. Сверх сложности кости никогда не добавляются.
- `boost` и `setback`: необязательные кости, добавляемые соответственно через `bonus="+N"` и `bonus="-N"`, до `max` каждой (по умолчанию 3, предел 6). Знаковые поправки складываются до применения этого предела. Capability API **1.150** также принимает отдельный `setback="N"`: `bonus="2" setback="1"` бросает обе стороны. Отрицательный бонус добавляется к `setback`, и общее число костей помехи ограничено `setback.max`; кости усиления по-прежнему ограничены `boost.max`.
- `allowOwnUpgrade`: необязательно, при отсутствии равно false. При `true` `upgradeOwn="N"` улучшает еще N костей персонажа до `pool.upgrade` (его нужно объявить) после улучшений из листа и купленных костей. Когда все имеющиеся кости уже улучшены, каждое лишнее улучшение добавляет одну улучшенную кость, по-прежнему в пределах `pool.max`. Это работает и с `pool.build: "sum"`. Объявление этого ключа, даже со значением `false`, требует capabilityApi **1.150**. Имена атрибутов пишутся в camel case, как `zeroDice`; `upgradeOwn` действует на кости бросающего, а `upgrade` по-прежнему действует только на кости сложности. И `setback`, и `upgradeOwn` принимают неотрицательные целые числа и игнорируются вне символьных пулов; `upgradeOwn` игнорируется, если не включен.
- `success`: нужно столько своего символа после взаимной отмены, по умолчанию один. Критический успех и провал отмечают любое появление названного символа, даже если добавленный им успех или провал отменяется. Обе отметки могут появиться вместе, и ни одна не меняет того, прошла ли проверка по чистым успехам.
- `outcomes` могут читать чистое число успехов (`total`) или `net successes - needed + 1` (`margin`). Степени по-прежнему решают успех обычным образом; исходные критические символы остаются отмеченными. `spend` покупает только дополнительные базовые кости персонажа в пределах `pool.max`. Бои этого набора используют `symbol-pool` (Capability API 1.382, см. [Бой на символьных костях](ruleset-combat.md#a-fight-thrown-in-symbol-dice-symbol-pool)); любой другой вид боя рядом с ним отклоняется.
- Вне проверки игра с этим набором правил может бросать его кости по имени: поле собственного броска в панели ввода сообщения и инструмент `roll_dice` Game Master читают `2 ability 1 proficiency vs 2 difficulty` (`id` или `label` каждой кости, в любом регистре), считают символы и взаимно отменяют их, как при проверке, но без листа, улучшений и шкалы сложности. Для включения не нужен отдельный ключ.
- Запись сохраняет `resolution="sum"` с `symbols="2s 1a 1t"`, `thrown=`, обозначающим каждую кость, и `rolls=`, хранящим ее грань с отсчетом от 1. Закодированный `symbolDetails` сохраняет подписи, символы граней и обе критические отметки. `setback` записывает отдельные кости помехи, действительно добавленные после общего предела помехи, а `upgradeOwn` – действительно примененные дополнительные улучшения; проигнорированные или нулевые добавки опускаются. Карточка и сводка называют чистые символы, включая пустой результат, вместо сложения чисел граней. Переопределения могут менять правила этого вида, но не могут заменить `symbols` или `dice`.

### Что вне области действия и почему

Этим механикам по-прежнему нужен собственный вид разрешения:

- **Встречные пулы** разрешают двух персонажей одновременно; проверка имеет одного бросающего.
- **Суммируемые пулы с дикой костью** (как в OpenD6) складывают кости и отдельно обрабатывают одну из них.

Обе ранее исключенные возможности теперь моделируются; раздел Расходы для изменения броска ниже объясняет как. Собственное правило системы, "потратить очко за успех" или "потратить очко, чтобы перебросить неудачи", – это `resolution.spend`. Переброс, который система дает бесплатно, когда этого требует ситуация, – это `resolution.reroll` выше. Переброс, принадлежащий выбранной персонажем вещи, – это `mechanics.check` записи каталога, оплачиваемый собственной стоимостью записи.

## Степени исхода: больше, чем успех или провал

Многие системы читают проверку как один из нескольких результатов, а не просто успех или провал: четыре степени успеха Pathfinder, "еле-еле", которое удается ценой потерь, трудные и экстремальные успехи Call of Cthulhu, "стильный успех" Fate. `resolution.outcomes` называет эти степени, и Engine в каждой проверке сообщает, в какую из них она попала (Capability API 1.135). Это работает с любым видом разрешения.

```json
"outcomes": {
  "by": "margin",
  "naturals": "shift",
  "tiers": [
    { "id": "critical_success", "label": "Critical success", "atLeast": 10, "success": true, "critical": true },
    { "id": "success", "label": "Success", "atLeast": 0, "success": true },
    { "id": "failure", "label": "Failure", "atLeast": -9 },
    { "id": "critical_failure", "label": "Critical failure", "critical": true }
  ]
}
```

- `by`: то, по чему читаются степени. `"margin"` (по умолчанию) – насколько результат превысил то, что требовалось проверке: итоговая сумма минус сложность или чистые успехи пула минус нужное число успехов. `"total"` – сам результат: итоговая сумма или чистые успехи, какой бы ни была сложность.
- `tiers`: от двух до восьми степеней, **начиная с лучшей**. `atLeast` – наименьшее число, попадающее в степень; у каждой степени оно ниже, чем у предыдущей, а у последней его нет, потому что она ловит все, что ниже. `success` говорит, успешна ли степень, а `critical` отмечает ее как критическую в своем роде (критический успех, если `success` равно true, и критический провал, если нет). Хотя бы одна степень должна быть успешной и хотя бы одна – провальной. `text` – необязательная строка до 200 символов, объясняющая Game Master, что степень означает за столом ("Вы справляетесь, но Game Master добавляет осложнение").
- `on`: `"critical-success"` или `"critical-failure"` делает степень той, в которую попадает критический результат, что бы ни говорило число, и больше туда ничего не попадает. У такой степени нет `atLeast`, степень на критическом успехе – успех, а на критическом провале – нет, и каждой может быть не больше одной. "Две шестерки" в Blades in the Dark – это степень на критическом успехе над степенью для одной шестерки; остальные степени, читаемые по числу, подчиняются между собой правилам выше.
- `naturals: "shift"`: высшая грань одной кости сдвигает результат на одну степень вверх, а низшая – на одну вниз, но никогда не дальше крайних степеней. Требует одной кости и заменяет `resolution.naturals`, поэтому рядом с ним задайте `none` для обоих случаев.

Степень решает исход: успех и оба критических результата берутся из нее, а не из простого сравнения. Если `naturals` суммирующего набора делают грань автоматическим успехом или провалом, эта грань попадает в степень соответствующего критического результата, а иначе – в лучшую или худшую степень, и остается критической. Критический провал пула (botch) действует так же внизу шкалы, а пул со степенями обходится без `exceptional`, потому что степени уже говорят, что такое критический успех.

Пул, читаемый `by: "total"`, – это то, как система с фиксированной сложностью описывает свои результаты: "1 успех: вы еле справляетесь, 2: справляетесь хорошо, 3: критический успех" в Lasers & Feelings – это три степени на 3, 2 и 1 успехе и промах ниже.

Запись называет степень через `outcome="Critical success"`, карточка броска показывает ее вместо простого слова, а Game Master получает описание степеней и их `text` и указание описывать именно степень. Набору в составе пакета, объявляющему степени, нужен Capability API 1.135.

## Проверки, которые бросаются по-своему

Некоторые игры бросают большинство проверок одним способом, а несколько – другим: игра старой школы бросает d20 ниже значения характеристики, но навыки вора – на d100, а Open Doors – на d6. `resolution.overrides` называет такие проверки и ключи разрешения, которыми они бросаются вместо обычных. Capability API 1.140.

```json
"overrides": [
  { "id": "thief", "label": "Thief skills", "skills": ["open_locks", "pick_pockets"], "set": { "dice": { "count": 1, "sides": 100 } } },
  { "id": "x_in_6", "label": "X-in-6", "skills": ["open_doors", "listen"], "set": { "dice": { "count": 1, "sides": 6 } } },
  { "id": "favored", "label": "Favored", "skills": ["athletics"], "when": { "field": "favored_athletics" }, "set": { "cancel": null } }
]
```

- Каждое переопределение называет `skills`, `saves` или `abilities` (одно или несколько из трех), `label` и необязательный `text` для Game Master.
- `set` содержит ключи разрешения собственного вида набора, которые заменяют ключи набора для этих проверок. `null` убирает ключ: единицы exwod, которые не отменяют успехи для избранной характеристики, – это `"cancel": null`. Вид, математику листа (`abilityModifier`, `proficiency`, `proficiencyTiers`, `penaltyFrom`, `spend`, `adjust`) и `difficultyLadder` изменить нельзя. Символьный пул также фиксирует свои `symbols` и `dice`. Разрешение, которое дает переопределение, проверяется так же, как собственное разрешение набора, поэтому названная им грань должна быть на его костях.
- `when`: необязательно. Значение из листа бросающего; переопределение применяется, только если оно не равно 0, например числовое поле 0 или 1 для избранной характеристики. Без него переопределение действует всегда.
- Используется первое переопределение, которое называет проверку и чье условие `when` выполняется. Проверка входит не более чем в одно переопределение без `when`.

## Расходы для изменения броска

Некоторые системы позволяют платить за предстоящий бросок: очко воли за автоматический успех. `resolution.spend` описывает это как постоянное правило системы, а не купленную персонажем вещь:

```json
"spend": [{ "pool": "resolve", "amount": 1, "successes": 1, "perCheck": 2 }]
```

- `pool` – один из `live.pools`. Он не может начинаться пустым, иначе в начале игры тратить нечего.
- `amount` – стоимость ОДНОЙ покупки. `successes`, `dice` и `reroll` задают приобретаемое; покупка должна давать хотя бы одно из них. Успехи добавляются после подсчета костей и отмен, поскольку их никто не выбрасывал. Кости бросаются вместе с пулом в его собственных пределах. `reroll` имеет вид `{ "upTo": 6, "mode": "once" }`, читается так же, как `resolution.reroll`, и покупается один раз, сколько бы покупок ни сделала проверка: кость, переброшенная дважды, – все равно один переброс.
- `perCheck` – число покупок за проверку; максимум – на `amount * perCheck` очков. Ограничение не дает полному запасу купить беспроигрышный бросок. Это число от 1 до 10, значение из листа в той же форме, в какой его читает производное значение (`{ "abilityScore": "nerve" }`, `{ "derived": "focus" }`), или `"pool"`: столько, сколько у проверки костей, то есть число листа для нее до ран, бонусных костей и модификаторов. Значение из листа читается для бросающего, округляется вниз и удерживается между 0 и 100, а персонаж с пределом 0 ничего не покупает и ничего не платит.
- Набор `dice-pool` может покупать успехи, кости или перебросы. `dice-highest` и `symbol-pool` покупают только кости. Остальные виды не могут объявлять `spend`.
- До четырех записей, и две не могут назвать один запас, иначе проверка не укажет, какая из них нужна.
- Расход, покупающий `reroll`, `perCheck`, не являющийся числом, и более двух записей требуют Capability API 1.38 для набора в составе пакета.

**Это указывается в самой проверке.** Game Master пишет `[skill_check: skill="Nerve" dc="2" spend="resolve:1"]`, а не отдельную команду `[sheet:]`: кости бросаются до применения команд листа, и позже менять было бы нечего. Одно разрешение бросает кости и оплачивает изменивший их эффект.

## Талисман, меняющий бросок

`resolution.spend` – правило системы. Фактически ВЫБРАННАЯ персонажем запись тоже может изменить проверку через `mechanics.check` записи каталога:

```json
"mechanics": {
  "kind": "utility",
  "cost": [{ "pool": "blood", "amount": 1 }],
  "perCostStep": { "flat": 1 },
  "check": { "reroll": { "upTo": 1, "mode": "once" }, "successes": 1 }
}
```

- `reroll` перебрасывает кости с гранью не выше `upTo`. `once` заменяет каждую один раз и оставляет новую грань; `until` продолжает. `upTo` должно быть ниже высшей грани, иначе весь пул перебрасывался бы бесконечно; Engine ограничивает число перебросов проверки независимо от файла.
- `dice` добавляет кости до броска, `successes` – успехи после подсчета, а `threshold` задает порог кости для этого броска в диапазоне `target`.
- `explode` и `double` сдвигают грани этих правил для одного броска, и только если у вашего правила есть `min`, в его пределах: `"check": { "explode": 8 }` – запись, при которой восьмерки бросаются снова. Они главнее написанного Game Master в теге, как и `threshold`. Capability API 1.37.
- Нужно хотя бы одно из этих полей; иначе запись ничего не определяет и отклоняется.
- Все это поддерживает только `dice-pool`, поэтому `dice-sum` с `mechanics.check` отклоняется при импорте.

**Стоимость – собственное `cost` записи**, оплачиваемое тем же механизмом, что использование любой другой вещи: запас и одно использование каждого счетчика этой записи. `perCostStep` задает МАСШТАБИРОВАНИЕ: запись с ним покупается столько раз, сколько оплачена цена, а без него – один раз независимо от предложенной суммы.

**Game Master называет запись в проверке:** `[skill_check: skill="Brawl" dc="3" use="Potence" spend="blood:3"]`. Не отдельной командой листа, по той же причине: бросок предшествует любому учету.

**Все или ничего.** Если запаса не хватает, покупки нет и ничего не списывается: бросок остается ровно таким, каким был бы без покупки. Очки, не составляющие целое число покупок, тоже ничего не дают. Превышение `perCheck` ограничивается, а не отклоняется, и оплачивается только предел. Все вычисляет Engine; Game Master называет объявленный игроком расход и не касается костей. Запись показывает фактическую оплату, примененную запись, число успехов без броска и переброшенных костей. Невыбранный талисман или талисман с недоступным Engine каталогом ничего не делает вместо применения на доверии.
