# Создание наборов правил Game Mode

Набор правил объясняет Game Mode настольную систему: какие кости бросает проверка, что есть в листе персонажа, какие ресурсы тратятся и что возвращает отдых. Руководство предназначено тем, кто хочет написать собственный набор и поделиться им. Для игры с чужим набором начните с [Выбора правил](../game/getting-started.md#choosing-rules).

Набор правил — один JSON-файл. Это данные, не код. Ничего из него не выполняется, поэтому импорт не может ничего сделать с компьютером. Перед импортом чужого файла внимательно прочитайте текст Game Master: он передается модели в каждой игре с этим набором.

## Прочтите сначала: что набор правил может и чего не может

Набор может лишь заполнять параметры механики, уже известной Engine. Сейчас Engine знает два способа разрешения проверки; файл выбирает один через `resolution.kind`:

- **`dice-sum`**: бросить кости, прибавить числа листа и достигнуть либо превысить сложность. Подходит для d20, 2d6 плюс характеристика и многих других систем.
- **`dice-pool`**: бросить число костей персонажа и сосчитать достигшие цели. Подходит системам, где рейтинг означает горсть костей вместо бонуса.

Оба полностью описаны в разделе [Виды разрешения](#resolution-kinds).

Механику, не соответствующую ни одной форме, нельзя записать в файле набора. Примеры: выбор наибольшей кости пула, процентные проверки с броском ниже порога, символьные кости и встречные пулы. Каждому нужен новый вид разрешения внутри Engine, то есть изменение кода с тестами, а не JSON-файл. Если ваша система требует такого вида, откройте запрос функции в репозитории Engine и опишите механику несколькими полностью разобранными бросками. Они станут тестами.

Game Mode разрешает бой по собственным правилам Marinara или правилам вашего набора. Необязательный блок `battle` передает бою Marinara числа листов персонажей: см. [Битвы](#battles-lending-the-sheet-to-marinaras-combat). Необязательный `combat` вместо этого определяет разрешение боя самим набором: см. [Бой](#combat-a-fight-your-own-rules-resolve). Engine уже применяет эти правила. **Combat Preference** (предпочтительный вид боя) выбирает представление Classic или поле Tactical, если набор определяет расстояние.

## Быстрый старт

1. Скопируйте пример, подходящий броскам вашей системы. [`ember-roads.json`](https://github.com/Pasta-Devs/Marinara-Engine/blob/staging/docs/examples/rulesets/ember-roads.json) — небольшая система 2d6 с тремя характеристиками, показывающая, что формат не предполагает d20 или шесть характеристик. [`gravewatch.json`](https://github.com/Pasta-Devs/Marinara-Engine/blob/staging/docs/examples/rulesets/gravewatch.json) — небольшой пул десятигранных костей с тремя рейтингами и шестью профессиональными навыками. Полноразмерный пример 5e (SRD 5.1) находится в [`ruleset-5e-2014.example.json`](https://github.com/Pasta-Devs/Marinara-Engine/blob/staging/docs/development/ruleset-5e-2014.example.json).
2. Замените `id` своим. Идентификатор состоит из строчных букв, цифр и одиночных дефисов, например `ember-roads`.
3. Измените лист, отдых и текст Game Master.
4. Импортируйте файл (см. [Проверка своего набора](#trying-your-ruleset)). Импорт проверяет весь файл и построчно сообщает ошибки до любого сохранения.
5. Создайте игру, выберите набор в **Rules** (правила) и выполните несколько проверок.

Для подсказок при вводе укажите редактору JSON Schema, добавив следующую первую строку внутри внешних фигурных скобок файла:

```json
"$schema": "https://raw.githubusercontent.com/Pasta-Devs/Marinara-Engine/staging/docs/extending/ruleset.schema.json",
```

Схема при вводе находит ошибки в именах ключей и типах. Она не проверяет, ссылаются ли имена на существующие сущности, например называет ли навык существующую характеристику. Это делает импорт.

В любой объект файла можно добавить строку `"$comment": "..."` с заметкой. Engine ее игнорирует.

## Части файла

| Ключ | Содержимое |
| --- | --- |
| `schemaVersion` | Всегда `1`. |
| `id`, `version` | Имя набора для Engine и целое число, повышаемое при каждой публикации изменения. |
| `name` | То, что игроки видят в мастере настройки. |
| `edition` | Необязательно. Строка об издании или черновике. |
| `license` | Необязательно. Идентификатор SPDX и требуемый источником текст указания авторства. |
| `coverage` | Область действия набора и краткое описание в мастере настройки. |
| `resolution` | Как бросается проверка или спасбросок. |
| `sheet` | Все содержимое листа персонажа. |
| `rests` | Что восстанавливает и очищает каждый вид отдыха. |
| `gm` | Текст модели Game Master и значения листа, которые она видит для каждого персонажа. |
| `catalogs` | Необязательно. Готовые записи редактора листа вместо ручного ввода длинных списков. |
| `battle` | Необязательно. Что бой читает из листа и записывает обратно после завершения. |
| `combat` | Необязательно. Разрешение боя по собственным правилам и то, что разыгрывает экран боя. |
| `layers` | Необязательно. Варианты набора, включаемые при создании игры. |

Размер файла — до 256 KB. Текст, попадающий в промпт (имена, подписи, текст Game Master), не может содержать переносов строк, квадратных или двойных фигурных скобок.

Идентификаторы листа (характеристики, навыки, поля, запасы и прочее) состоят из строчных букв, цифр и подчеркиваний, начиная с буквы, например `grit_max`.

### Виды разрешения

`resolution.kind` выбирает способ броска проверки. Оба вида читают один лист и имеют три общих ключа, поэтому части файла ниже `resolution` не меняются при переключении:

- `abilityModifier`: преобразование показателя листа в число. При `identity` показатель и есть число. `floorHalfMinusTen` — правило 5e. `stepTable` позволяет перечислить собственные пороги как `[[score, number], ...]`.
- `proficiencyTiers`: уровни подготовки навыка или спасброска. Неуказанный навык получает первый. Уровень добавляет `flat`, либо `multiplier`, умноженное на бонус мастерства, либо оба. Если в системе есть бонус мастерства, укажите его источник через `"proficiency": { "bonus": { "derived": "proficiency_bonus" } }`.
- `proficiency`: необязательно, нужно лишь уровню с умножением.

Значение полученного числа зависит от вида: `dice-sum` прибавляет его к броску, `dice-pool` бросает столько костей.

#### `dice-sum`: сложение костей

```json
"resolution": {
  "kind": "dice-sum",
  "dice": { "count": 2, "sides": 6 },
  "abilityModifier": { "op": "identity" },
  "proficiencyTiers": [
    { "id": "untrained", "label": "Untrained" },
    { "id": "trained", "label": "Trained", "flat": 1 }
  ],
  "advantage": false,
  "difficultyLadder": [
    { "label": "Easy", "dc": 6 },
    { "label": "Hard", "dc": 10 }
  ]
}
```

- `dice`: число костей и граней. Сумма сравнивается со сложностью.
- `advantage`: может ли Game Master попросить дважды бросить кости и оставить один бросок.
- `naturals`: влияние высшей и низшей грани одной кости на проверки и спасброски: `none`, `both`, `max-only` или `min-only`. Для чистой арифметики опустите. Требует одной кости, поэтому система 2d6 должна использовать `none`.
- `difficultyLadder`: сложности, из которых должен выбирать Game Master. `dc` — число, которого должна достичь сумма.

#### `dice-pool`: бросок костей и подсчет результатов

Число листа — **размер пула**, а не добавочный бонус. Рейтинг 3 и профессиональный навык стоимостью 2 дают пять костей. В этом вся идея: без нового словаря листа и нового редактора; система с рейтингами в виде горстей костей использует те же `abilities`, `skills` и `proficiencyTiers`, что и любая другая.

```json
"resolution": {
  "kind": "dice-pool",
  "die": { "sides": 10 },
  "abilityModifier": { "op": "identity" },
  "proficiencyTiers": [
    { "id": "rating_0", "label": "Untried" },
    { "id": "rating_1", "label": "Shown once", "flat": 1 }
  ],
  "pool": { "min": 1, "max": 15 },
  "target": { "default": 7, "min": 5, "max": 9 },
  "explode": { "from": 10 },
  "cancel": { "upTo": 1 },
  "botch": { "upTo": 1 },
  "exceptional": { "successes": 5 },
  "situationalDice": { "min": -3, "max": 3 },
  "difficultyLadder": [
    { "label": "Plain work", "successes": 1, "target": 6 },
    { "label": "Grim", "successes": 3, "target": 8 }
  ]
}
```

- `die`: число граней одной кости пула, от 2 до 100.
- `pool`: пределы числа листа до любых взрывов. `min` 0 позволяет пустому пулу провалиться вообще без броска; `max` — не более 100.
- `target`: грань, которой должна достичь кость для зачета. Задайте `min` ниже `max`, чтобы Game Master мог менять порог проверки через `threshold=`; равенство всех трех значений фиксирует порог.
- `double`: необязательно. Грань не ниже `from` считается дважды.
- `explode`: необязательно. Грань не ниже `from` бросает еще одну кость, которая тоже может взорваться. Дополнительных костей не больше `pool.max` сверх самого пула, поэтому проверка бросает максимум удвоенное `pool.max`, и низкое `from` не создает бесконечного броска.
- `cancel`: необязательно. Грань не выше `upTo` отнимает один успех. Число не опускается ниже нуля.
- `botch`: необязательно. Если **ни одна** кость не успешна и выпала грань не выше `upTo`, проверка критически провалена. Пул с единственным отмененным успехом дает обычный, не критический провал.
- `exceptional`: необязательно. Такое или большее число чистых успехов в успешной проверке дает критический успех.
- `situationalDice`: необязательно. Диапазон костей, добавляемых или убираемых Game Master для одной проверки через `bonus=` за трюки, раны или плохое освещение.
- `difficultyLadder`: `successes` задает необходимое число успехов. Ступень может назвать `target`, но только если порог регулируется и в его пределах.

Грани `cancel` и `botch` должны быть ниже минимального порога, а все грани этих правил должны существовать на кости. Невыполнимое правило отклоняется при импорте, а не обнаруживается в игре.

Набор с пулом в составе пакета требует Capability API 1.24. Импортируемый набор сообщества проверяет читающий его Engine, поэтому дополнительное требование не нужно.

#### Что Game Master может писать в проверке пула

```
[skill_check: skill="Ward" dc="2" who="Bram the Quiet" threshold="8" bonus="-2" with="Sinew"]
```

- `dc` — число необходимых **успехов**, не порог кости. Допустимо от 1 до максимума, который можно насчитать за бросок: максимум пула, удвоенный при взрывах и еще раз удвоенный при двойном зачете граней.
- `threshold=` меняет порог кости и предлагается только при `target.min` ниже `target.max`.
- `bonus=` добавляет или убирает кости и предлагается только при объявленном `situationalDice`.
- `with=` использует для навыка или спасброска другую характеристику. Работает в обоих видах, так что набор 5e получает "Strength (Intimidation)" через тот же атрибут.

Все ограничено декларацией файла: выходящее за диапазон значение прижимается к ближайшей границе, а отсутствующая в наборе характеристика игнорируется вместо отказа проверки. Запись показывает фактически использованные значения: порог и бонусные кости после ограничений, а `with=` — только если характеристику действительно заменили. Engine всегда сам бросает кости. Результат пула от модели заменяется, `mode="advantage"` игнорируется, потому что вид не имеет преимущества, а брошенная игроком до хода кость не применяется.

#### Что вне области действия и почему

Каждой из этих механик нужен собственный вид разрешения, потому что ни одна не выражается подсчетом костей относительно порога:

- **Наибольшая кость** (как в Blades in the Dark) требует ступени частичного успеха, которой у результата проверки нет.
- **Пулы позиции против характеристики** (как в Lasers and Feelings) выбирают "выше или ниже" для каждой проверки: это другое сравнение.
- **Символьные кости** (как в Genesys) вообще не дают чисел.
- **Встречные пулы** разрешают двух персонажей одновременно; проверка имеет одного бросающего.
- **Броски ниже порога и открытые процентные броски** сравнивают в другую сторону.
- **Суммируемые пулы с дикой костью** (как в OpenD6) складывают кости и отдельно обрабатывают одну из них.

Обе ранее исключенные возможности теперь моделируются; раздел Расходы для изменения броска ниже объясняет как. Собственное правило системы "потратить очко за успех" — это `resolution.spend`, покупающее успехи или кости, но никогда переброс. Переброс относится к выбранной персонажем вещи, поэтому задается как `mechanics.check` записи каталога и оплачивается собственной стоимостью записи.

### Расходы для изменения броска

Некоторые системы позволяют платить за предстоящий бросок: очко воли за автоматический успех. `resolution.spend` описывает это как постоянное правило системы, а не купленную персонажем вещь:

```json
"spend": [{ "pool": "resolve", "amount": 1, "successes": 1, "perCheck": 2 }]
```

- `pool` — один из `live.pools`. Он не может начинаться пустым, иначе в начале игры тратить нечего.
- `amount` — стоимость ОДНОЙ покупки. `successes` и `dice` задают приобретаемое; покупка должна давать хотя бы одно из них. Успехи добавляются после подсчета костей и отмен, поскольку их никто не выбрасывал. Кости бросаются вместе с пулом в его собственных пределах.
- `perCheck` — число покупок за проверку; максимум — на `amount * perCheck` очков. Ограничение не дает полному запасу купить беспроигрышный бросок.
- Только `dice-pool` может иметь это правило: у суммируемого броска нет успехов или пула для добавления костей, поэтому `dice-sum` с `spend` отклоняется при импорте.
- Две записи не могут назвать один запас, иначе проверка не укажет, какая из них нужна.

**Это указывается в самой проверке.** Game Master пишет `[skill_check: skill="Nerve" dc="2" spend="resolve:1"]`, а не отдельную команду `[sheet:]`: кости бросаются до применения команд листа, и позже менять было бы нечего. Одно разрешение бросает кости и оплачивает изменивший их эффект.

### Талисман, меняющий бросок

`resolution.spend` — правило системы. Фактически ВЫБРАННАЯ персонажем запись тоже может изменить проверку через `mechanics.check` записи каталога:

```json
"mechanics": {
  "kind": "utility",
  "cost": [{ "pool": "blood", "amount": 1 }],
  "perCostStep": { "flat": 1 },
  "check": { "reroll": { "upTo": 1, "mode": "once" }, "successes": 1 }
}
```

- `reroll` перебрасывает кости с гранью не выше `upTo`. `once` заменяет каждую один раз и оставляет новую грань; `until` продолжает. `upTo` должно быть ниже высшей грани, иначе весь пул перебрасывался бы бесконечно; Engine ограничивает число перебросов проверки независимо от файла.
- `dice` добавляет кости до броска, `successes` — успехи после подсчета, а `threshold` задает порог кости для этого броска в диапазоне `target`.
- Нужно хотя бы одно из четырех полей; иначе запись ничего не определяет и отклоняется.
- Все это поддерживает только `dice-pool`, поэтому `dice-sum` с `mechanics.check` отклоняется при импорте.

**Стоимость — собственное `cost` записи**, оплачиваемое тем же механизмом, что использование любой другой вещи: запас и одно использование каждого счетчика этой записи. `perCostStep` задает МАСШТАБИРОВАНИЕ: запись с ним покупается столько раз, сколько оплачена цена, а без него — один раз независимо от предложенной суммы.

**Game Master называет запись в проверке:** `[skill_check: skill="Brawl" dc="3" use="Potence" spend="blood:3"]`. Не отдельной командой листа, по той же причине: бросок предшествует любому учету.

**Все или ничего.** Если запаса не хватает, покупки нет и ничего не списывается: бросок остается ровно таким, каким был бы без покупки. Очки, не составляющие целое число покупок, тоже ничего не дают. Превышение `perCheck` ограничивается, а не отклоняется, и оплачивается только предел. Все вычисляет Engine; Game Master называет объявленный игроком расход и не касается костей. Запись показывает фактическую оплату, примененную запись, число успехов без броска и переброшенных костей. Невыбранный талисман или талисман с недоступным Engine каталогом ничего не делает вместо применения на доверии.

### Лист

- `sections` группирует содержимое редактора.
- `abilities` — основные показатели. `skills` и `saves` могут называть используемую характеристику.
- `fields` — одиночные значения. Типы: `number`, `text`, `longtext`, `boolean`, `enum` (фиксированные варианты) и `dice` (текст вроде `1d8`).
- Значения `derived` вычисляются из других и не перезаписываются вводом. Операции: `sum`, `min`, `max`, `scale` (умножить и округлить), `stepTable` (найти по порогам, как уровень дает бонус мастерства).
- `lists` — таблицы со своими столбцами: снаряжение, заклинания, особенности. Список с `pools` превращает каждую строку в ресурс с собственным максимумом для классовых особенностей с ограниченными использованиями.
- `live` меняется в игре: `pools` (хиты, ячейки заклинаний, Grit), `tracks` (число на шкале, например истощение, или шкала ран с отметками), `text` (короткие заметки, например предмет концентрации) и `conditions`.

Любой читатель числа указывает ссылку на значение — объект ровно с одним ключом: `const`, `field`, `derived`, `abilityScore`, `abilityMod`, `abilityModFromField`, `skillMod` или `saveMod`. Пример запаса с производным максимумом: `"max": { "derived": "grit_max" }`.

`hideWhen` скрывает поле, список или запас при определенном значении другого поля. Файл 5e так скрывает ячейки заклинаний у немагического персонажа.

### Шкалы ран: здоровье как шкала вместо числа

Многие системы вообще не считают хиты. Вместо них — столбец ячеек, каждая хуже предыдущей, и при ранении ставится отметка. Добавьте `levels` и `kinds` записи `live.tracks`, и число на шкале станет такой шкалой ран:

**Какая форма нужна вашей системе?** Запас хранит СКОЛЬКО вреда получено; шкала — сколько И какого вида была каждая часть. Если рана бывает ударной, летальной или усугубленной, и вид важен после удара — усугубленная медленнее лечится, не поглощается или окончательно убивает, — он должен где-то сохраниться после броска. Вид несет только отметка. Запас очков этого не умеет: вычтенный урон оставляет меньшее число, а лист не помнит вид отдельных очков. Поэтому `combat.damageKinds` отклоняется при здоровье-запасе, а не игнорируется. Запас все еще может иметь `damageTypes`, а противник — сопротивление или иммунитет к ним: это определяет дошедшую часть удара, а не последующий вид раны.

```json
{
  "id": "harm",
  "label": "Harm",
  "min": 0,
  "max": 4,
  "levels": [
    { "label": "Scuffed", "penalty": 0 },
    { "label": "Winded", "penalty": -1 },
    { "label": "Bleeding", "penalty": -3 },
    { "label": "Down", "penalty": -99 }
  ],
  "kinds": [
    { "id": "knock", "label": "K", "severity": 0 },
    { "id": "tear", "label": "T", "severity": 1 }
  ]
}
```

- `levels` — 1–16 ступеней от лучшей к худшей. У каждой `label` и целый `penalty`, не превышающий 0. Большое отрицательное число означает выбывание, поэтому `-99` допустимо.
- `kinds` — 1–6 видов вреда с `id`, коротким `label` для ячейки и `severity`. Тяжести должны различаться; числа задают лишь порядок, интервалы произвольны.
- Оба нужны вместе. `kinds` без `levels` отклоняется: нечего отмечать. `levels` без `kinds` тоже отклоняется: отметка должна иметь вид.
- **Различайте два слова.** `kinds` — то, чем отметка МОЖЕТ БЫТЬ по правилам. ОТМЕТКА — один из этих видов на шкале во время игры. Определение хранит виды, лист персонажа — отметки.
- Длина шкалы равна числу уровней: `min` — 0, `max` — `levels.length`. Другое значение отклоняется, не исправляется молча, поэтому противоречащих длин в файле быть не может.

**Точные правила**, потому что расплывчатое прочтение дает неправильную шкалу:

- Отметки отсортированы, **самые тяжелые первыми**. Семь уровней вмещают максимум семь отметок.
- Отметка **вставляется по тяжести** среди имеющихся, не добавляется в конец. Она занимает высший положенный тяжести уровень и сдвигает легкие вниз.
- Действует штраф **самого нижнего отмеченного уровня**, не сумма. Три отметки на шкале выше дают `-3`, не `0 + -1 + -3`.
- `amount` — число отметок одного вида, **применяемых по одной**: шкала, заполненная в процессе, обрабатывается так же, как изначально полная.
- Отметка на **полной** шкале **повышает самый легкий вид на одну ступень** вместо добавления. На одну ступень собственной лестницы видов независимо от вида новой отметки.
- Повышение выше максимальной тяжести оставляет максимум, а невместившаяся отметка учитывается как **переполнение**. Оно сохраняется, поэтому перезагрузка не забывает уже полученный вред.
- **Лечение — та же команда с отрицательным количеством.** Сначала удаляет легкие отметки, а переполнение — раньше любой отметки.

**Отметки в игре.** Game Master пишет `[sheet: op="damage" track="harm" kind="knock" amount="1"]` и лечит отрицательным `amount`. Форма `damage` с `pool=` не меняется. Простая команда `track` для шкалы ран отклоняется: одно число не называет виды новых отметок. Игрок также может вручную отмечать и очищать ячейки листа, как предполагают такие системы.

**Бой тоже ставит отметки.** Направьте `combat.health` на шкалу вместо запаса. Попадание отмечает столько ячеек, сколько говорит `combat.damageKinds.marks`, видом, сопоставленным этим блоком типу урона. Персонаж с полной шкалой падает, что и читает правило умирания. Лечение очищает одну отметку. Временные очки отклоняются: у шкалы нет буфера для них. Engine читает шкалу как число ОСТАВШИХСЯ уровней, поэтому остальной бой, падение, возвращение, журнал и пересказ не меняются.

**Отдых может лечить шкалу ран.** Шаг восстановления с `"to"` очищает ее до указанного числа отметок, вместе с переполнением; шаг с `"by"` убирает столько отметок, начиная с переполнения. Шаг, ДОБАВЛЯЮЩИЙ отметки, ничего не делает: отдых не называет их вид.

### Штраф к броскам

`resolution.penaltyFrom` указывает шкалу ран, штраф которой действует на каждую проверку набора. Это декларация, не предположение: без нее броски работают точно как до появления шкал ран.

ДЕЙСТВИЕ штрафа определяет вид разрешения, как и значение числа листа:

- При `dice-pool` **убираются кости из пула**, не ниже собственного `pool.min`. При `pool.min` 1 даже на последней ступени бросается одна кость; при `pool.min` 0 не бросается ни одной и наступает провал без броска.
- При `dice-sum` это **фиксированный модификатор броска**, включенный в то же число, куда добавляются характеристика и подготовка.

Ссылка должна указывать шкалу ран. Обычная шкала не имеет штрафа и отклоняется при импорте. Результат называет примененный штраф, чтобы игрок понимал меньшее число костей, а блок листа для Game Master показывает ступень и ее цену.

### Отдых

Отдых — список шагов восстановления и очищаемых вещей. Каждый шаг называет одну цель (`pool`, `poolGroup`, `listPools` или `track`) и задает значение (`"to": "max"`, `"to": "min"` либо число) или меняет его (`"by": { "const": 1 }` либо `"by": { "fractionOfMax": 0.5 }`). Шаг шкалы ран может только лечить; см. выше.

### Текст Game Master

- `checkGuidance` заменяет встроенный абзац о запросе проверки. Назовите систему и случаи бросков. Game Master указывает лишь навык и сложность; Engine бросает и считает по листу, поэтому не просите модель вычислять.
- `sheetGuidance` представляет листы в промпте. Объясните важные ресурсы и когда их тратить.
- `worldGuidance` необязательно и читается один раз при генерации мира, чтобы придуманные условия подходили правилам: нет пороха, редкая магия, ходячие мертвецы. На ход оно не попадает.
- `sheetSummary` выбирает поля, производные значения и строки списков, видимые Game Master для персонажа. Engine всегда показывает модификаторы характеристик, освоенные навыки и спасброски, а также текущие значения. Остальное держите коротким: оно отправляется каждый ход.

## Каталоги: готовые записи для списков листа

Построчно вводить заклинания, снаряжение или страницу классовых особенностей утомительно. Каталог — именованная коллекция готовых записей в наборе. Редактор предлагает их в выборе каждой питаемой каталогом таблицы; выбор заполняет строку.

Каталоги необязательны. Набор может иметь до двенадцати; Engine не знает их назначения: все ID, столбцы, фильтры и слова поступают из файла.

### Заголовок

Заголовок находится в `catalogs` верхнего уровня рядом с `gm`.

```json
"catalogs": [
  {
    "id": "knacks",
    "label": "Knacks",
    "feeds": ["knacks", "tricks"],
    "filters": [
      { "id": "grit", "label": "Grit cost", "type": "number" },
      { "id": "road", "label": "Road", "type": "text" },
      { "id": "callings", "label": "Calling", "type": "tags", "startFrom": { "field": "calling" } }
    ],
    "units": { "distance": { "label": "paces", "perCell": 2 } },
    "entries": []
  }
]
```

- `id` и `label`: ID соответствует правилам идентификаторов листа; подпись называет окно выбора.
- `holds`: `"rows"` (по умолчанию и во всех каталогах до этого выпуска) или `"creatures"`. Каталог существ — читаемый боем бестиарий: ничего не пишет в лист, не объявляет `feeds` и не предлагается в выборе. См. [Существа](#creatures-a-bestiary-a-fight-reads) ниже.
- `feeds`: от одного до восьми списков листа, куда могут писать записи. Обязательно для строк и запрещено для существ. Запись не пишет в неуказанный список или значение, недопустимое для его столбцов.
- `filters`: необязательно, до восьми фильтров выбора. Фильтр — `number`, значение `text` или `tags` (несколько слов). `startFrom` называет поле листа, с которым открывается выбор: персонаж с Calling Tinker сначала видит записи Tinker.
- `units`: необязательно. Значение дальности или размера области в `mechanics` записи для вашей системы.

### Запись

```json
{
  "id": "road-sense",
  "label": "Road Sense",
  "summary": "You read a road the way other people read a face.",
  "filters": { "grit": 0, "road": "Ash Flats", "callings": ["Scout", "Courier"] },
  "rows": [
    {
      "list": "knacks",
      "values": { "name": "Road Sense", "notes": "Sneak to notice where a road turns bad." }
    }
  ]
}
```

- `id`: строчные буквы, цифры и одиночные дефисы; уникально внутри каталога.
- `label` и `summary`: отображаемое в выборе. Сводка необязательна, одна строка до 300 символов.
- `filters`: значения объявленных заголовком фильтров. `number` принимает число, `text` одну строку, `tags` список строк.
- `rows`: записываемое при выборе, от одной до шести строк. `list` — один из `feeds`, а ключи `values` — ID столбцов списка.
- `creature`: противник вместо строк в каталоге, чей `holds` содержит существ. У записи ровно одно из `rows` и `creature`; у существа нет `mechanics`, оно описывает поведение собственными действиями.

Каждое значение проверяется по столбцам целевого списка, поэтому неверное имя столбца или число вне диапазона сообщается вместе с исходной записью. Записи внутри файла набора проверяются при загрузке, для импортируемого файла — при импорте. Отдельный каталог пакета проверяется при первом запросе окна выбора; ошибочный файл показывает там причины вместо записей.

### Одна запись, несколько списков

Особенность с ограниченными использованиями — две строки: сама особенность и счетчик. Выбирается она по-прежнему один раз.

```json
{
  "id": "last-ember",
  "label": "Last Ember",
  "rows": [
    {
      "list": "knacks",
      "values": { "name": "Last Ember", "notes": "Spend 1 Grit to give a downed friend 3 Grit back." }
    },
    { "list": "tricks", "values": { "name": "Last Ember", "uses": 1, "recharge": "camp" } }
  ]
}
```

### Значения, обновляемые набором

После выбора числа строки принадлежат игроку. Полезное исключение — следующий за персонажем максимум: использования по значению характеристики или ресурс класса, растущий с уровнем. Строка может назвать до четырех числовых столбцов в карте `scaled`, и редактор поддерживает их значения.

```json
{
  "list": "tricks",
  "values": { "name": "Last Ember", "uses": 1, "recharge": "camp" },
  "scaled": { "uses": { "from": { "abilityScore": "heart" } } }
}
```

- Ключ — один из столбцов `number` списка.
- `from` — обычная ссылка на значение из того же закрытого словаря. Сложное вычисление становится объявленной листом величиной `derived`, на которую указывает `from` (`"from": { "derived": "lay_on_hands_max" }`). Новая арифметика не добавляется.
- `table` необязательно. Ищет значение ссылки в таблице ступеней, например число по уровню: `"scaled": { "max": { "from": { "field": "level" }, "table": [[1, 2], [3, 3], [6, 4]] } }`.
- `values` по-прежнему должно иметь обычное число столбца; строка без него отклоняется. Оно используется до появления листа и сохраняется в листе без указанной ссылки.
- Строка с `scaled` должна быть единственной строкой записи для этого списка, чтобы отмеченная строка листа соответствовала одной спецификации.

Значение вычисляется при редактировании, никогда при чтении: сохраненная строка всегда содержит показанное число. Оно ограничивается `min` и `max` столбца и округляется вниз для целых значений. В примере Heart 3 дает три использования, Heart 0 и ниже — ни одного. Строка остается с 0 использований; счетчик с максимумом 0 не является запасом, поэтому тратить в игре нечего.

Масштабируемые столбцы пакета требуют Capability API 1.23. Импортируемый набор сообщества проверяет читающий Engine, поэтому ничего дополнительного не нужно.

### Выбранные строки являются копиями

Выбранная строка копируется в лист с дополнительным ключом `_catalog`, содержащим `<catalog id>/<entry id>`. ID столбцов начинаются буквой, поэтому ключ не может совпасть с вашим.

Копия принадлежит персонажу. Игрок может менять ее содержимое, лист работает без установленного набора, а публикация новой версии никогда не переписывает чужого персонажа. Метка позволяет окну выбора показать уже имеющееся и используется обновлением ниже.

### Обновление из набора правил

Выбранная строка сохраняет метку, поэтому редактор листа может сообщить игроку, что ваш новый текст отличается от содержимого строки. Короткая строка под списком показывает число строк с обновленным текстом, а кнопка **Review** (просмотреть) сопоставляет для каждой содержимое листа и набора правил, с флажком выбора. До нажатия **Update selected** (обновить выбранное) ничего не записывается; затем меняются только различающиеся столбцы отмеченных строк. Все остальное, включая метку, сохраняется.

Область сравнения намеренно узкая:

- Существующие значения сравниваются только в столбцах `text`, `longtext`, `dice` и `enum`. Значения `number` и `boolean` принадлежат игроку и сохраняются, включая 0 и false. Еще отсутствующий в строке столбец можно предложить с типизированным значением, в том числе числом или переключателем. Масштабируемый столбец исключен: он уже следует за листом.
- Только столбцы, заданные вашим элементом. Пропущенный в нем столбец никогда не меняется, что бы ни хранилось в листе.
- Значение, которое сам столбец не примет, например больше не предлагаемый вариант `enum` или текст длиннее `maxLength`, пропускается, а не записывается.
- Строка сопоставляется с породившей ее строкой элемента по позиции среди строк с той же меткой в данном списке, пока их на листе столько же, сколько записывает элемент. Иначе это работает только для элемента, записывающего одну строку в этот список. Если игрок удалил одну из двух строк элемента, элемент оставляют без изменений, не пытаясь угадать.
- Строка, чей элемент больше не существует в каталоге, остается без изменений и без уведомления.

Таким образом, новый текст или название элемента могут попасть к уже выбравшим его персонажам, если те примут обновление. Изменить таким способом смысл числа нельзя и не получится: как только строка принадлежит игроку, этот столбец тоже его.

### `mechanics`: действие элемента в числах

Элемент может содержать необязательный блок `mechanics`, описывающий его действие в числах: `kind` (`attack`, `heal`, `buff`, `debuff`, `utility`, `rider`), `range`, `area`, `targets`, `targetCount`, `friendlyFire`, `amount` (кости, например `2d6`, или постоянное число), `damageType`, `attackRoll`, `autoHit`, `save` (один из спасбросков листа и эффект успеха), `applies` (накладываемые состояния), `temporary` (временные очки в запасе здоровья), `scales` (величина, растущая вместе с листом), `cost` (расходуемый при использовании запас), `perCostStep`, `budget` (расходуемая часть экономики действий), `concentration`, `reaction`, `plus`, `free`, `gives`, `standard`, `rider` и `check`.

Селектор показывает этот блок одной строкой. Кто читает остальное, зависит от блока, который включен в наборе правил:

- С [блоком `combat`](#combat-a-fight-your-own-rules-resolve) бой читает боевые эффекты. `range`, `area` и `friendlyFire` применяются на поле боя с позициями; `reaction` обозначает элемент, отвечающий на событие, и пока элемент не умеет указать ожидаемый триггер, такой элемент не появляется ни в одном меню. `check` применяется к проверкам навыков, как описано выше.
- Только с [блоком `battle`](#battles-lending-the-sheet-to-marinaras-combat) бой читает `kind`, `range`, `area`, `friendlyFire`, `amount`, `damageType` и `cost`: для этих частей есть место в собственной боевой системе Marinara.

Словарь закрытый: ключ или значение, которых нет в списке выше, отклоняются, а не молча игнорируются.

`cost` также задает цену, которую вне боя платит команда `use` Мастера игры; ей посвящен следующий раздел.

### Команда `use`: Мастер игры платит заданную вами цену

В ходе повествования Мастер игры обновляет каждый лист командами `[sheet: ...]`: `spend`, `restore` (`heal` означает то же самое), `damage`, `temp`, `track`, `condition`, `note` и `rest`. Набор правил с каталогами получает еще одну:

```
[sheet: who="Mira" op="use" name="Fireball"]
[sheet: who="Mira" op="use" name="Fireball" pool="3rd-level slots"]
```

`op="cast"` означает то же, что `op="use"`, а `spell=` – то же, что `name=`. Поэтому привычная Мастеру игры формулировка работает, хотя формату не нужно знать слово «заклинание».

Имя сопоставляется без учета регистра со строками листа этого персонажа, полученными из одного из ваших каталогов. Строка отзывается на имя, показанное Мастеру игры (столбец имени `sheetSummary` для списка, затем `pools.nameColumn` списка, затем его первый текстовый столбец), и на `label` исходного элемента, поэтому переименование строки игроком не лишает ее доступа. Отклоняется как имя без совпадений, так и имя, соответствующее двум разным элементам.

Что расходуется:

- Каждое слагаемое `mechanics.cost` элемента. Слагаемое с именем текущего запаса оплачивается из него; с именем ГРУППЫ запасов – из первого запаса этой группы в порядке объявления, способного покрыть цену. Автоматического перехода к более высокому запасу нет: группа не всегда представляет лестницу.
- Плюс единица из каждого запаса в строке списка, записанного тем же элементом, например счетчика использований способности. Это вторая строка элемента `Last Ember` выше. Счетчик с максимумом 0 не имеет доступных использований, поэтому команда отклоняется, а не проходит бесплатно.

`pool=` – применение на более высоком уровне: та же единственная цена оплачивается из другого запаса той же группы. Оно допускается, только если в цене ровно одно слагаемое, а указанный запас входит в его группу. Все остальное отклоняется без переосмысления.

Все или ничего. Если любую часть оплатить нельзя, вся команда отклоняется, ничего не меняется, а игрок получает сообщение. Элемент вообще без цены, например заговор или пассивная способность, принимается и ничего не меняет.

### Встроенный каталог или отдельный файл

Небольшой каталог размещается прямо в `ruleset.json`, в `entries` заголовка. Большой живет в собственном файле, который заголовок указывает через `asset`. У каталога ровно один из этих вариантов.

```json
{ "id": "knacks", "label": "Knacks", "feeds": ["knacks"], "asset": "catalogs/knacks.json" }
```

Путь всегда имеет вид `catalogs/<the catalog's id>.json`. Сам файл выглядит так:

```json
{ "schemaVersion": 1, "catalog": "knacks", "entries": [] }
```

Отдельные файлы каталогов предназначены для пакетов из официального каталога: пакет перечисляет файл в `contributions.assets.paths` рядом с `ruleset.json` и требует Capability API 1.21. Каталог существ, встроенный или отдельный, требует Capability API 1.27. **Набор правил, импортируемый одним файлом или публикуемый через репозиторий GitHub, хранит каталоги внутри**, поэтому они должны уместиться в ограничение 256 КБ на весь файл набора правил. Этого хватит на несколько сотен коротких элементов.

Ограничения: 12 каталогов на набор правил, 2000 элементов на каталог в обоих вариантах и 1 МБ на отдельный файл каталога.

## Сражения: передача листа боевой системе Marinara

По умолчанию сражение ничего не знает о листе. Оно создает бойцов как прежде, и персонаж может выйти из боя с неизменившимися очками здоровья в листе.

Необязательный блок `battle` меняет это только в одном направлении: передает бою числа листа и записывает результат обратно. **Он не заставляет бой следовать вашим правилам.** Математика костей остается за Marinara, как и определение того, кто кого поразил и на сколько. Поэтому здоровье переносится как доля максимума, а не ваше собственное число: персонаж с половиной здоровья в листе начинает бой с половиной полосы здоровья, которую построила для него Marinara. Ваш запас здоровья в 9 очков никогда не попадает напрямую в бой, где один удар наносит 12.

```json
"battle": {
  "health": { "pool": "grit" },
  "energy": { "pool": "luck" },
  "skills": [{ "list": "knacks" }]
}
```

- `health`: обязательно. Текущий запас, задающий очки здоровья персонажа в бою. Это должен быть один из запасов в `sheet.live.pools`, а не список, чьи строки служат запасами.
- `energy`: необязательно. Текущий запас, расходуемый в бою и становящийся полосой MP. Он должен отличаться от `health`, поскольку бой не может расходовать здоровье как топливо.
- `slots`: необязательно. Текущие запасы, которые бой расходует по одному, каждый с `level` от 1 до 9: `[{ "pool": "slots_1", "level": 1 }]`. Каждый уровень и каждый запас используются однократно.
- `skills`: необязательно, до восьми. Списки листа, чьи строки становятся боевыми навыками персонажа. Учитываются только строки из ваших каталогов и лишь когда исходный элемент имеет блок `mechanics`: вручную набранная строка ничего не описывает в числах. `onlyWhen` указывает логический столбец, который должен быть включен в строке, например подготовленное заклинание. `alwaysWhen` указывает столбец и значение, пропускающие строку независимо от этого условия, например заклинания, не требующие подготовки. Это исключение из `onlyWhen`, поэтому без него оно отклоняется.

### Что передается в бой и что возвращается

**В бой**, для каждого участника группы, чей лист есть у игры: доля текущего запаса здоровья от максимума задает начальную точку на собственной полосе здоровья Marinara, запас энергии становится MP, каждый запас ячеек становится ячейками своего уровня, а отмеченные строки – навыками. Максимум здоровья, атака, защита, скорость и уровень остаются собственными числами Marinara. Персонаж с нулем здоровья в листе начинает бой поверженным, как указано в листе; персонаж со здоровьем выше нуля никогда не начинает с менее чем одним очком, поэтому округление малой доли не может вывести его из строя.

**Из боя**, после его окончания: оставшаяся бойцу доля полосы здоровья переводится обратно в шкалу его запаса, а разница с началом боя применяется как урон или лечение. Энергия и ячейки – количества, а не доли, поэтому записываются как есть. Все проходит по тем же правилам, что используют кнопки листа; изменение, отвергнутое листом, пропускается с сообщением, а не навязывается. Бой, не изменивший здоровье бойца, вообще не записывает изменения здоровья, поэтому две конвертации сами по себе никогда не меняют лист.

**Ни в одну сторону**: броски атаки, спасброски, концентрация и прибавка от более высокой цены. Они хранятся в `mechanics`, чтобы однажды их прочла полноценная боевая система; этот мост их не применяет, и набор правил не должен заявлять обратное.

Брошенное сражение ничего не записывает обратно. Если удалить сообщение, в котором бой начался, или бой так и не закончится, лист останется прежним: боя не было.

### Как элемент становится навыком

Блок `mechanics` элемента каталога читается следующим образом:

- `kind` становится типом навыка. Элементы `utility` и все с отметкой `reaction` исключаются: в боевой системе Marinara для них нет места.
- `amount` задает силу эффекта как множитель собственной атаки бойца, а не число урона. Более крупные кости никогда не дают более слабый удар, а множитель остается в диапазоне, уже используемом генерируемыми навыками.
- `range` и `area.size` делятся на `units.distance.perCell` каталога для получения клеток сетки и никогда не округляются до нуля. Взрыв становится своим радиусом, конус – половиной этого значения, линия – одной клеткой. Эффект с областью выбирает всех покрытых ею врагов; `friendlyFire` соблюдается.
- `damageType` становится стихией навыка. `targets` не переносится: боевая система Marinara определяет допустимые цели лечения, усиления или атаки по типу навыка.
- `cost` запаса энергии становится ценой MP, несколько затрат энергии суммируются. `cost` ровно одной ячейки расходует одну ячейку этого уровня. Боевая система Marinara берет одно количество энергии или одну ячейку, но не оба ресурса, поэтому элемент ценой в две ячейки, ячейки двух уровней либо ячейку плюс энергию исключается из боя. То же касается затрат любого другого запаса, например здоровья или классового ресурса: иначе Engine выдавал бы эффект бесплатно.
- `buff` или `debuff` становится собственным усилением или ослаблением Marinara. Другие обещания текста элемента, например снятие состояния в листе, в бою не выполняются. Не добавляйте `mechanics` элементу, чей эффект имеет смысл лишь вне сражения.

`coverage.combat` остается отдельным и сохраняет прежний смысл: включайте его, только если сражения действительно следуют правилам вашей системы.

<a id="combat-a-fight-your-own-rules-resolve"></a>

## Бой: сражение, которое разрешают ваши правила

Блок `battle` выше передает бою числа листа, оставляя арифметику Marinara. Необязательный `combat` делает другое: задает, как ваши правила РАЗРЕШАЮТ бой. Он параметризует принадлежащий Engine вид боя, как `resolution` параметризует вид проверки; каждое имя внутри принадлежит вам. Сейчас существует один вид.

**Игра, чей набор правил объявляет `combat`, сражается по вашему блоку.** Числа группы читаются из собственных листов, противники берутся из вашего бестиария или шкалы угрозы, каждый ход разрешается вашими костями, а все расходы и потери персонажа сразу записываются в его лист: закрытие вкладки посреди боя ничего не теряет. Экран сражения использует ваши слова: ваши атаки и способности в меню, ваши бюджеты, состояния и журнал с реальной арифметикой. Пока отсутствующие возможности перечислены в разделе «Пока нет».

```json
"combat": {
  "kind": "attack-vs-defense",
  "health": { "pool": "grit" },
  "defense": { "derived": "guard" },
  "initiative": { "dice": { "count": 2, "sides": 6 }, "modifier": { "abilityMod": "wits" } },
  "attackRoll": { "dice": { "count": 2, "sides": 6 } },
  "economy": { "budgets": [{ "id": "act", "label": "Action", "per": "turn", "count": 1 }] },
  "attacks": [
    {
      "list": "gear",
      "budget": "act",
      "name": "name",
      "toHit": { "ability": { "column": "swing" } },
      "damage": { "dice": { "column": "damage" }, "ability": { "column": "swing" }, "type": { "column": "harm" } }
    }
  ],
  "abilities": [{ "list": "knacks", "budget": "act" }],
  "standard": ["dodge", "help"],
  "conditions": [
    { "condition": "shaken", "effects": ["own-attacks-disadvantage", "ends-on-damage"] },
    { "condition": "pinned", "effects": ["cannot-act", "speed-zero"] }
  ]
}
```

Это весь блок Ember Roads, по которому сражается игра на Ember Roads. Черновик 5e использует те же ключи для системы d20:

```json
"combat": {
  "kind": "attack-vs-defense",
  "health": { "pool": "hp" },
  "defense": { "field": "ac" },
  "initiative": { "dice": { "count": 1, "sides": 20 }, "modifier": { "derived": "initiative" } },
  "attackRoll": {
    "dice": { "count": 1, "sides": 20 },
    "advantage": true,
    "naturals": { "max": "critical", "min": "miss" },
    "critical": "double-dice"
  },
  "economy": {
    "budgets": [
      { "id": "action", "label": "Action", "per": "turn", "count": 1 },
      { "id": "bonus", "label": "Bonus action", "per": "turn", "count": 1 },
      { "id": "reaction", "label": "Reaction", "per": "turn", "count": 1 }
    ],
    "movement": { "field": "speed" }
  },
  "abilities": [
    {
      "list": "spells",
      "onlyWhen": "prepared",
      "alwaysWhen": { "column": "level", "equals": 0 },
      "budget": "action",
      "toHit": { "derived": "spell_attack" },
      "saveDifficulty": { "derived": "spell_save_dc" }
    }
  ],
  "concentration": { "text": "concentration", "save": "con_save", "floor": 10, "fromDamage": 0.5 }
}
```

### Все ключи

- `kind`: `"attack-vs-defense"`. Одна сторона бросает кости против защиты другой; попадание наносит урон.
- `health`: обязательно. То, что отнимает бой. Либо `{ "pool": "grit" }`, уменьшаемый текущий запас, чей временный буфер при наличии поглощает урон первым; либо `{ "track": "harm" }`, шкала ран, на которой ставятся ОТМЕТКИ. Шкала требует рядом `damageKinds` и не дает временных очков.
- `defense`: обязательно, ссылка на значение. Поле, вводимое игроком, или вычисляемое вами производное значение.
- `initiative`: обязательно. Кости, бросаемые один раз в начале, и необязательная ссылка на модификатор. При равенстве выигрывает больший модификатор, затем порядок создания участников боя.
- `attackRoll`: обязательно. Кости, бросает ли система дважды с выбором одного результата (`advantage`), действие крайних граней единственной кости (`naturals.max`: `critical`, `hit` или `none`; `naturals.min`: `miss` или `none`) и влияние критического попадания на урон (`critical`: `double-dice` бросает кости урона еще раз, `max-dice` один раз добавляет их максимальные грани, `none` означает обычное попадание). Особые натуральные результаты требуют одной кости, как и в проверках. Спасброски внутри боя используют эти же кости.
- `economy`: обязательно. `budgets` задает, что вмещает ход: id, подпись, `per` (`turn` восполняет в начале собственного хода владельца, `round` – в начале нового раунда) и `count`. ПЕРВЫЙ объявленный бюджет – основной; его расходует стандартное действие. `movement` – необязательная ссылка на значение: дальность перемещения за ход в вашей единице расстояния. Читается боем на поле (см. Позиции).
- `attacks`: необязательно. Списки листа, чьи строки являются оружием. `name` – текстовый столбец имени строки, `damage.dice` – столбец костей, а каждый из `toHit.ability`, `toHit.proficiency`, `toHit.bonus`, `damage.ability`, `damage.bonus` и `damage.type` именует столбец того же списка. Столбец `ability` – `enum` с одним из id ваших характеристик; другое значение ничего не добавляет. Столбец `proficiency` – `boolean`; если он включен, добавляется бонус мастерства. Строка без читаемых костей не является атакой, поэтому веревка в том же списке остается веревкой. `strikes` – необязательная ссылка на значение, показывающее, сколько ударов покупает ОДИН расход бюджета списка: выбор строки без ударов в запасе тратит бюджет и оставляет остальные удары в запасе; пока запас есть, любая строка с `strikes` вообще не расходует бюджет. Поэтому меню естественно позволяет сменить оружие, цель и пройти между ударами. `strikesCappedBy` именует логический столбец, ограничивающий ЕГО СОБСТВЕННУЮ строку одним ударом независимо от числа, купленного списком, для оружия, стреляющего раз в ход независимо от числа атак владельца: он создан для свойства Loading из SRD 5.1. Для списка, и так покупающего один удар за расход, он бессмыслен и отклоняется. Запас ударов принадлежит БОЙЦУ, а не списку: персонаж с двумя списками оружия, объявляющими `strikes`, тратит один и тот же запас любой из строк. Он очищается в конце хода, на котором куплен. Список без этого объявления покупает один удар за расход, как любой бой до появления этой возможности.

  ```json
  {
    "list": "attacks",
    "budget": "action",
    "name": "name",
    "strikes": { "field": "attacks_per_action" },
    "damage": { "dice": { "column": "damage" } }
  }
  ```

- `abilities`: необязательно. Списки листа, чьи отмеченные каталогом строки являются способностями, фильтруемыми через `onlyWhen` и `alwaysWhen` точно как `battle.skills`. Действие каждой определяет собственный `mechanics` элемента; блок задает расходуемый по умолчанию `budget`, добавляемый `toHit` для элемента с броском попадания и `saveDifficulty`, против которого делается спасбросок элемента. Элемент, требующий спасброска, собственного или снимающего наложенное им состояние, отклоняется, если у целевого списка нет `saveDifficulty`: спасбросок против ничего всегда был бы успешен.
- `standard`: необязательно, из закрытого списка `dash`, `disengage`, `dodge`, `help`, `hide`, `ready`. `dodge` (атаки по уклоняющемуся бросаются дважды с худшим результатом) и `help` (следующая атака поддержанного союзника бросается дважды с лучшим результатом) разрешаются всегда. `dash` (еще такой же запас перемещения) и `disengage` (никто не ударяет за отход в этом ходу) разрешаются на поле и фиксируются вне поля. `hide` и `ready` принимаются, но пока ничего не делают.
- `standardEffects`: необязательно, для части стандартного действия, не выраженной его флагом. Сейчас такая часть есть только у `dodge`: `{ "dodge": { "saves": ["dex_save"] } }` задает, какие ваши спасброски уклоняющийся бросает дважды с лучшим результатом, пока длится уклонение. Указывайте только объявленные листом спасброски и только если в `standard` есть `dodge`. Без этого уклонение остается прежним: в персонажа труднее попасть, и больше ничего.
- `conditions`: необязательно. Сопоставляет ВАШИ id состояний с их действием, поэтому состояния листа и боя – одна запись, а отравленный персонаж остается отравленным после боя. Эффекты образуют закрытый список: `own-attacks-advantage`, `own-attacks-disadvantage`, `attacks-against-advantage`, `attacks-against-disadvantage`, `attacks-against-adjacent-advantage`, `attacks-against-far-disadvantage`, `attacks-from-adjacent-critical`, `cannot-act`, `cannot-react`, `speed-zero`, `half-move-to-stand`, `ends-on-damage`, `own-saves-advantage`, `own-saves-disadvantage`, `resist-all`, `cannot-target-source` и `cannot-approach-source`. `failsSaves` именует спасброски, проваливаемые состоянием без броска. Шесть эффектов, требующих расстояния или перемещения (`attacks-against-adjacent-advantage`, `attacks-against-far-disadvantage`, `attacks-from-adjacent-critical`, `speed-zero`, `half-move-to-stand`, `cannot-approach-source`), читаются боем на поле и ничего не значат без него (см. Позиции). `cannot-react` исключает владельца из окна, открываемого перемещением, поэтому его никогда не спрашивают. Рядом с эффектами есть еще три ключа:
  - `saves`: каких спасбросков касаются два эффекта спасбросков. При отсутствии – всех; указание без одного из этих двух эффектов отклоняется.
  - `whileSourceInSight`: что действует лишь пока наложивший состояние находится в поле зрения владельца. `true` ограничивает все состояние; список его собственных эффектов ограничивает только их, оставляя остальные действовать. Это нужно для страха, запрещающего приближаться независимо от видимости источника. Указание отсутствующего в состоянии эффекта отклоняется. Без поля нет линии видимости, которую можно прервать, поэтому в обоих случаях действует все.
  - `endsWhenSourceDown`: состояние снимается сразу, как наложивший его падает.

`own-saves-advantage` и противоположный эффект бросают спасбросок дважды с выбором одного результата, точно как атаку, и взаимно отменяются. `resist-all` делит пополам любой вид урона в дополнение к собственной защите цели и аналогично отменяется уязвимостью. `cannot-target-source` запрещает владельцу направлять что-либо на наложившего состояние, а `cannot-approach-source` запрещает приближаться к нему ближе текущей клетки, включая весь маршрут: обход к равноудаленной клетке остается доступным, но маршрут, проходящий ближе и выходящий с другой стороны, – нет.

  ```json
  { "condition": "restrained", "effects": ["own-saves-disadvantage"], "saves": ["dex_save"] }
  ```

- `concentration`: необязательно. Текущее поле `text`, записывающее удерживаемый эффект, `save`, вызываемый уроном, нижний порог сложности `floor` и `fromDamage` – доля полученного урона, задающая сложность, если она выше. Запуск второй способности с концентрацией завершает первую; провал спасброска завершает ее и снимает поддерживаемые ею состояния.
- `dying`: необязательно, `kind: "saves"`. Две шкалы, считающие броски (нужное количество задается максимумом каждой), `dice`, `succeedAt`, действие крайних граней (`naturals.max`: `revive-1` или `success`; `naturals.min`: `one-failure` или `two-failures`), цена урона в поверженном состоянии (`damageWhileDown`, `criticalWhileDown`) и `condition` поверженного персонажа. Без блока персонаж на нуле просто повержен, а лечение возвращает его.
- `damageTypes`: необязательно. Типы вашей системы, сопоставляемые без учета регистра.
- `damageKinds`: обязательно, когда `health` именует шкалу ран, и отклоняется при запасе, потому что только отметка хранит вид, а запасу очков хранить его негде (см. Шкалы ран выше). Задает, какой из `kinds` шкалы отмечает удар и сколько клеток заполняет. `default` – вид для всего без сопоставления, включая удар вообще без типа; `byType` сопоставляет ваши `damageTypes` видам, а его ключи, как сами типы, сравниваются без регистра: `"Fire"` и `"fire"` – один ключ, и указание обоих отклоняется. У `marks` нет значения по умолчанию, поскольку ответы противоположны: `"per-point"`, когда бросок урона считает уровни здоровья, так что удар на три отмечает три клетки и смягчить его на единицу полезно; и `"per-blow"`, когда удар либо попадает, либо нет, и отмечает одну клетку независимо от силы. Удар с несколькими составляющими урона все равно отмечает одну клетку самым тяжелым попавшим видом. Укажите вариант вашей системы. `{ "default": "bashing", "byType": { "fire": "aggravated" }, "marks": "per-point" }`.
- `threat`: необязательно; требуется бестиарию. `tiers` – шкала выбора противника: id, подпись, диапазон `health`, `defense`, `toHit`, диапазон `damagePerRound` и `saveDifficulty`. Каждое поставляемое существо именует одну из этих ступеней, а не написанный заранее противник приводится к ступени, запрошенной Мастером игры, чтобы никто не вышел за шкалу. Диапазон `damagePerRound` означает действие существа на ОДНУ цель за раунд, включая всю последовательность.

### Что бой читает из `mechanics`

`kind` определяет, является ли `amount` уроном или лечением; все с отметкой `reaction` исключается из меню, как и элемент `utility`, если он не меняет возможности самого хода (см. ниже). `attackRoll` выполняет бросок против защиты цели с `toHit` списка; `autoHit` полностью его пропускает. `save` бросает собственный спасбросок цели против `saveDifficulty` списка, а `onSuccess` определяет, остается при успехе половина или ничего. `targetCount` – допустимое число целей. Способность без броска атаки (область, против которой все спасаются, или автоматическое попадание) бросает кости ОДИН раз для всех; способность с броском попадания по каждой цели бросает урон заново при каждом попадании. `applies` накладывает состояния на затронутых, каждое с `duration`: `instant` (без собственного таймера: остается, пока что-то не снимет), `until-save` (требует рядом `saveEnds`) или `{ "rounds": n }`, и необязательным `saveEnds`, именующим спасбросок и повторение в `turn-end` или `turn-start`. `temporary` дает временные очки запаса здоровья; они не складываются – остается больший буфер. `scales` увеличивает величину дополнительными КОСТЯМИ, которые его таблица дает для прочитанного значения. `cost` оплачивается собственной командой листа `use`, а `budget` переопределяет расходуемую часть экономики действий.

`plus` – до трех ДОПОЛНИТЕЛЬНЫХ величин того же удара рядом с `amount`, каждая бросается и получает тип отдельно («and 2d6 fire»). Составляющая имеет вид `{ "dice": "2d6", "flat": 1, "type": "fire" }` и может иметь собственный `save`, `{ "save": "con_save", "difficulty": 13, "onSuccess": "none" | "half" }`, который ЦЕЛЬ бросает независимо от уже потребованного действием: `none` при успехе полностью убирает эту составляющую, `half` оставляет половину; остальной удар не меняется. Без `difficulty` берется число собственного спасброска действия, затем `saveDifficulty` списка. Критическое попадание удваивает кости каждой составляющей по тому же правилу, что кости первой величины; составляющая без `type` имеет собственный вид урона удара, а весь удар по-прежнему вызывает ОДНУ проверку концентрации по суммарному урону и одну проверку падения. Составляющей нужен базовый `amount`; у `heal` их не бывает.

```json
{
  "kind": "attack",
  "attackRoll": true,
  "amount": { "dice": "1d8" },
  "damageType": "piercing",
  "plus": [{ "dice": "2d6", "type": "fire" }]
}
```

Три ключа задают действие элемента на экономику самого хода; элемент `utility`, объявляющий любой из них, предлагается, а не исключается:

- `free`: вообще не расходует бюджет. Указанный `cost` все равно оплачивается; одновременно указывать `budget` нельзя.
- `gives`: `[{ "budget": "action", "count": 1 }]`, до четырех. В момент использования увеличивает эти бюджеты, ограничивая результат вместимостью хода плюс подарок, поэтому ничего нельзя накопить для будущего хода.
- `standard`: `{ "actions": ["dash", "disengage", "hide"], "budget": "bonus" }`. Владелец может выполнять эти стандартные действия за ЭТОТ бюджет. Они предлагаются рядом с обычными как `standard:<id>@<budget>`; сам элемент не появляется в меню, если он только дает разрешение, поскольку разрешение не выполняют.

Элемент нового вида `kind: "rider"` ПАССИВЕН: никто его не выполняет, его никогда нет в меню, и он автоматически добавляет еще одну составляющую урона к первому подходящему попаданию периода. Он содержит `rider` и ничего другого, что можно выполнять:

```json
{
  "kind": "rider",
  "rider": {
    "on": "hit",
    "sources": ["attacks"],
    "requires": { "column": "finesse" },
    "when": ["advantage", "ally-adjacent"],
    "oncePer": "turn",
    "amount": { "dice": "1d6" }
  },
  "scales": {
    "from": { "field": "level" },
    "table": [
      [1, 0],
      [3, 1]
    ]
  }
}
```

`sources` именует списки атак, от которых он срабатывает, а `requires` – один истинный столбец их строк, поэтому дополнительный эффект для определенного оружия указывает его без знания Engine о том, что такое оружие; отсутствие обоих означает любое попадание владельца. `when` означает ЛЮБОЕ условие: `advantage` – окончательное преимущество броска атаки, а `ally-adjacent` – стоящий союзник атакующего, способный действовать, в пределах одной клетки от цели на поле или где угодно без поля. `oncePer` – `turn` (обновляется в начале каждого хода, поэтому удар во время чужого действия тоже может его нести) либо `round`. `amount` растет с собственным `scales` элемента, а `type` задает вид урона, по умолчанию вид самого удара.

### Существа: бестиарий, который читает бой

Каталог с `"holds": "creatures"` содержит противников вместо строк листа. Он не наполняет списки, селектор редактора листа никогда его не предлагает, а все числа записаны в ключах, уже объявленных вашим `combat`. Ему нужны блок `combat` и шкала `threat`, поскольку существо относится к одной из ваших ступеней.

```json
{
  "id": "road_trouble",
  "label": "Road trouble",
  "holds": "creatures",
  "filters": [{ "id": "tier", "label": "How bad", "type": "text" }],
  "entries": [
    {
      "id": "rust-jackal",
      "label": "Rust Jackal",
      "summary": "A lean thing that lives on the metal roads.",
      "filters": { "tier": "Pack trouble" },
      "creature": {
        "health": { "dice": "3d6" },
        "defense": 6,
        "initiativeModifier": 1,
        "speed": 16,
        "abilities": { "brawn": 1, "wits": 0, "heart": -1 },
        "tier": "pack",
        "actions": [
          {
            "id": "bite",
            "name": "Bite",
            "budget": "act",
            "toHit": 2,
            "damage": { "dice": "1d6", "flat": 1, "type": "cut" },
            "reach": 2
          },
          {
            "id": "worry",
            "name": "Worry",
            "budget": "act",
            "toHit": 2,
            "damage": { "dice": "1d4", "type": "cut" },
            "applies": [{ "condition": "shaken", "duration": { "rounds": 2 } }]
          },
          {
            "id": "snap_and_worry",
            "name": "Snap and worry",
            "budget": "act",
            "sequence": [
              { "action": "bite", "times": 1 },
              { "action": "worry", "times": 1 }
            ]
          }
        ]
      }
    }
  ]
}
```

Числа ниже – прямой способ записать существо. Записанное в собственных терминах набора правил, как `sheet`, берет `health`, `defense`, `initiativeModifier`, `speed`, `abilities` и `saves` из этого листа (см. «Существо в собственных терминах набора правил» ниже).

- `health`: число либо `{ "dice": "3d6", "flat": 2 }`, бросаемое один раз при создании боя. Прогноз читает среднее, поэтому меню никогда не обещает результат еще не брошенной кости.
- `defense`, `initiativeModifier`, `speed`: против чего бросается атака, прибавка к инициативе и дальность движения за ход в вашей единице расстояния.
- `abilities` и `saves`: ключами служат id характеристик и спасбросков листа. Неуказанный спасбросок равен нулю.
- `resist`, `vulnerable`, `immune`: типы урона, сопоставляемые без регистра и проверяемые по `combat.damageTypes`, если вы их объявили. `conditionImmunities` именует ваши состояния.
- `tier`: ступень `combat.threat`, к которой относится существо.
- `traits`: короткие пары имени и текста, показанные Мастеру игры. Они никогда не разрешаются, поэтому все с числами должно находиться в действии.
- `signaturePoints`: очки, возвращаемые в начале собственного хода и расходуемые на действия `signature`.
- `riders`: до четырех, то же, что `rider` элемента каталога, но записанное в блоке. Каждый имеет вид `{ "id": "pack", "name": "Pack", "on": "hit", "oncePer": "turn" | "round", "amount": { "dice": "1d6" } }` с необязательным `type` и необязательным `actions`, указывающим собственные действия блока, при которых он срабатывает. Дополнительный эффект блока не читает списки листа, поэтому у него нет двух ключей: `sources` и `requires`. Существо с листом получает дополнительные эффекты своих списков, как персонаж.
- `actions`: до двенадцати, каждое с собственным `id`. Действие содержит то же, что написанный вручную блок статистик (`toHit`, `autoHit`, `damage`, `save`, `applies`, `targetCount`, `reach`, `range`, `area`), плюс четыре свойства только для существ. `reach` – дальность удара, `range` – дальность броска или выстрела, `area` – форма области, все в вашей единице расстояния; `range` может быть числом или `{ "normal": 30, "long": 120 }`, если дальше можно достать со штрафом, а `area` имеет вид `{ "shape": "burst" | "cone" | "line", "size": n, "friendlyFire": false }` (см. Позиции):
  - `uses`: `{ "per": "encounter" | "day", "count": n }`. Когда использования заканчиваются, действие исчезает из меню.
  - `recharge`: `{ "dice": { "count": 1, "sides": 6 }, "from": 5 }`. В начале боя доступно, расходуется при использовании; в начале собственного хода существа бросает кости: `from` или выше возвращает его. Кости записываются в журнал при любом результате.
  - `sequence`: другие действия того же блока по порядку, каждое со своей целью. **Так записывается существо, бьющее дважды за одно действие.** Один бюджет оплачивает всю последовательность. У последовательности нет собственного эффекта, и она никогда не может именовать другую последовательность.
  - `signature`: `{ "cost": n }`, оплачивается собственными очками существа вместо бюджета и только во время чужого действия: бой предлагает его в окне между ходами (см. Окна).
- Спасброску нужна сложность на самом действии: `save.difficulty` для спасброска, вызываемого действием, либо `saveDifficulty` для состояния, снимаемого спасброском, если у действия нет собственного. Действие блока записывается обычными числами даже у существа с листом, поэтому число хранится на действии. Собственный спасбросок составляющей может опустить `difficulty` и взять то же число.
- `damage.plus` – тот же список составляющих, что `plus` элемента каталога, читаемый точно так же: `"damage": { "dice": "1d6", "flat": 2, "type": "piercing", "plus": [{ "dice": "1d4", "type": "fire" }] }` – укус с отдельной величиной жара, к которой отдельно применяется сопротивление и которая отдельно удваивается.

Собственный бестиарий черновика 5e – пять написанных вручную существ в `docs/development/ruleset-5e-2014.example.json`, покрывающих последовательность, перезарядку, спасбросок с состоянием, сопротивления и иммунитеты, ограниченные использования, особые очки и одно существо с листом.

#### Существо в собственных терминах набора правил

Существо не обязательно записывать обычными числами. Дайте ему `sheet` точно такой же формы, как лист персонажа, и бой построит его как участника группы: здоровье, защита, спасброски, инициатива, скорость и все атаки и способности списков будут такими, какими их делают ваши формулы листа. Так набор правил сообщает, что у противников те же характеристики, навыки и списки, что у персонажей, какими бы они ни были. Toll Warden из Ember Roads:

```json
{
  "id": "toll-warden",
  "label": "Toll Warden",
  "creature": {
    "tier": "pack",
    "traits": [{ "name": "Knows the road", "text": "It will not follow anyone past the last milestone." }],
    "sheet": {
      "abilities": { "brawn": 2, "wits": 1, "heart": 1 },
      "skills": { "sway": "trained" },
      "fields": { "calling": "Hauler", "toughness": 3 },
      "lists": {
        "gear": [{ "name": "Toll hook", "swing": "brawn", "damage": "1d6", "harm": "cut" }],
        "knacks": [{ "name": "Hold the Line", "_catalog": "knacks/hold-the-line" }]
      }
    }
  }
}
```

- **Каждая часть необязательна**: `abilities`, `skills`, `saves`, `bonuses`, `fields` и `lists`, с ключами по id листа. Все пропущенное принимает собственное значение листа по умолчанию, как у пустого персонажа. Grit стража равен 9, поскольку `grit_max` складывает 4, его Toughness и Brawn; Guard равен 7 по аналогичной причине.
- **У каждого числа один источник.** Существо с листом не задает одновременно `health`, `defense`, `initiativeModifier`, `speed`, `abilities` или `saves`; иначе Engine отклоняет файл. У него может не быть собственных `actions`, поскольку его действия задаются списками. Существо без листа по-прежнему задает первые три числа и хотя бы одно действие.
- **Оно проверяется как авторские данные.** Каждый id должен быть объявлен листом; навык или спасбросок получает одну из предлагаемых ему ступеней мастерства; поле, показатель, бонус или столбец содержит объявленное значение (целое число в диапазоне, один из вариантов и т. п.); список не превышает допустимое число строк. Части `live` нет, поскольку расходы существа хранит бой.
- **Строка может поступать из каталога.** `_catalog: "<catalog>/<entry>"` именует выбранный элемент, как в листе персонажа; оттуда бой читает стоимость и действие строки. Каталог должен наполнять этот список. Встроенный каталог обязан содержать элемент; у отдельного файла строка с отсутствующим в нем элементом просто ничего не дает существу. Каталоги, на которые ссылаются листы бестиария, загружаются в бой вместе с бестиарием.
- **Данные элемента рядом с листом все еще учитываются**: `tier`, `traits`, `actions`, `signaturePoints`, `riders`, `resist`, `vulnerable`, `immune` и `conditionImmunities`.
- **Оно платит из собственных запасов.** Они начинают полными, расходуются на действия из списков, и существу предлагаются более дорогие варианты оплаты (заклинание из более высокой ячейки), как участнику группы, независимо от того, решает Engine или Мастер игры. Hold the Line стража стоит ему Luck.
- **При шкале ран его здоровье – сама шкала.** Удар отмечает собственную шкалу существа по вашему `damageKinds` после применения `resist`, `vulnerable` и `immune`, поэтому существо с иммунитетом к виду урона не получает от него отметку.
- **Оно остается противником.** При нуле выбывает, а не умирает, никогда не делает спасбросков от смерти; экран показывает обычные сведения противника и ничего из листа; потраченные ресурсы нигде не записываются обратно, даже если персонаж носит то же имя.
- **Лист, вообще не дающий здоровья**, исключается из боя с объяснением в начальном журнале, вместо появления существа, которому никто не может навредить.
- Слой, удаляющий значение одного из полей-перечислений, никогда не лишает вас использующего его существа: пока слой включен, поле принимает для существа значение по умолчанию, как для персонажа; существо из-за этого не отклоняется.
- Мастер игры тоже может придумать такое существо; оно ограничивается своей ступенью (см. Противники, которых никто не написал).
- Пакет с таким существом объявляет Capability API 1.34.

Toll Sergeant из черновика 5e – то же самое на листе d20: его Класс Доспеха, здоровье, спасброски и два удара за действие происходят из собственных полей и списка атак.

#### Противники, которых никто не написал

Когда Мастер игры придумывает противника, Engine приводит предложение к вашей шкале `threat` до бросков: здоровье – в диапазон ступени, защиту, бонус попадания и сложности спасбросков – не выше значений ступени плюс два, урон уменьшает, пока лучший раунд существа (самая тяжелая последовательность или отдельное действие против одной цели) не войдет в `damagePerRound` ступени. Сначала сокращается число костей, затем постоянная часть, затем удар последовательности, и лишь потом размер кости; ничто не уменьшается до нуля. Отсутствующие в наборе правил имена убираются: неизвестные типы урона, состояния и спасброски, а также все действия после первых шести. Необъявленная ступень заменяется нижней ступенью шкалы. Каждое изменение возвращается обычным предложением, чтобы журнал мог объяснить сделанное.

Придуманное существо тоже можно записать как `sheet`, как существо бестиария; так придуманный маг получает ячейки и заклинания. Мастер игры видит id листа и допустимое содержимое, читаемые боем списки и предлагаемые им каталогами имена, чтобы заклинание называлось, а не описывалось: строка, именующая элемент каталога в любом регистре, становится этим элементом, а собственные значения Мастера игры (например, подготовка заклинания) накладываются сверху. Лист читается терпимо, поскольку его написал модельный генератор: отсутствующее имя убирается, значение подгоняется к полю или столбцу, а числа рядом с листом не используются.

Придуманное существо, не являющееся боссом, ограничено тем, что открывает ему набор правил. Фильтр каталога с `startFrom` именует поле листа, по которому организованы элементы (список заклинаний пакета 5e по `class`); существо сохраняет только элементы, чей фильтр соответствует его значению этого поля, тем же способом, которым открывается селектор. Поэтому Чародей никогда не получает весь список заклинаний, а существо без класса – ничего из каталога по классам. Оставленные выборы затем заполняются без нового запроса Мастеру игры: для каждого списка, чьи строки действуют лишь после выбора (`onlyWhen` у источника боевых способностей), из доступных и оплачиваемых собственными запасами элементов для каждого запаса добирается небольшое число элементов (больше у более компетентного существа), как и для действий без ограничения использований. Выбор опирается на темперамент и компетентность, с которыми существо сражается: защитное или поддерживающее выбирает поддержку своей стороны, безрассудное – урон, методичное или терпеливое – сдерживание врага; чем выше компетентность, тем вероятнее реакция, контрмера или иной способ изменить ход. Выбор использует собственное зерно боя, поэтому один и тот же бой всегда заполняется одинаково. Строка такой таблицы, названная Мастером игры, считается выбранной.

Босса Мастер игры пишет целиком как возможное исключение: ничего не убирается и ничего не дополняется.

Затем оба варианта ограничиваются своей ступенью:

- Здоровье приводится к диапазону ступени через единственное поле, из которого читается: максимум запаса является этим полем либо `sum` с ровно одним полем (максимум здоровья в 5e, Toughness в Ember Roads). Формула здоровья без единственного поля остается как написано, и журнал это сообщает. Длина шкалы ран принадлежит вам и никогда не меняется.
- После построения существа защита, бонус попадания и сложности спасбросков ограничиваются значениями ступени плюс два; урон уменьшается, пока лучший раунд не войдет в `damagePerRound` ступени, с учетом самой большой доступной оплаты. Сначала убирается прибавка от более дорогой оплаты, затем кости, постоянная часть, удар и лишь потом размер кости.

Ваш собственный бестиарий никогда не ограничивается. Это написанные вами данные, и Engine принимает их как есть.

### Позиции: бой на поле

Бой остается театром воображения, пока блок не задаст цену одной клетки поля. Объявите `distance`, чтобы сражаться на сетке: тогда перемещение, досягаемость, дальность, области, линия видимости, укрытие и удары по уходящим обретают смысл. Каждое значение – ваше число; Engine дает только поле.

```json
"distance": { "label": "ft", "perCell": 5 },
"ranged": { "long": "disadvantage", "adjacentFoe": "disadvantage" },
"cover": { "bonus": 2 },
"opportunity": { "budget": "reaction" }
```

Ember Roads объявляет одну строку и больше ничего; в этом и смысл: остальное не обязательно.

```json
"distance": { "label": "paces", "perCell": 2 }
```

**Клетка.** `distance.perCell` задает, сколько ВАШИХ единиц стоит клетка, а `label` – название единицы. В ней выражены все расстояния мира блока: `economy.movement`, `speed` существа, `reach` и `range` оружия, `reach` и `range` действия существа. Каталог с собственным `units.distance` переводит собственные `mechanics.range` и `area.size` своим `perCell`; без него использует это объявление. Положительное расстояние округляется до ближайшей клетки, но никогда до нуля, поэтому все, чему вы дали число, достигает хотя бы одной. Ноль не означает короткое расстояние, а сохраняет собственный смысл: `mechanics.range` 0 – на себя или касанием (касание другого достигает соседней клетки); 0 в столбце оружия `reach` или `range` означает, что у строки нет такой дальности.

**Будет ли бой на поле.** Должны совпасть два условия: блок объявляет `distance`, а в игре выбран стиль боя Tactical. При стиле Classic или наборе правил без `distance` бой остается театром воображения, как прежде: любой может целиться в любого, и ничто ниже вообще не читается.

**Что видит игрок.** Поле рисуется с собственным рельефом тактического стиля. Каждая клетка – кнопка, доступная указателем или стрелками, сообщающая, что это, кто на ней и что для нее значит еще не законченный выбор. Перемещение подсвечивает предложенные меню клетки, каждую с ценой В ВАШЕЙ ЕДИНИЦЕ, рисует маршрут и выделяет янтарным клетки, чей путь вызовет чей-то удар, называя нападающих под полем. Вариант с целью одновременно подсвечивает допустимых участников на поле и в списке. Вариант с `area` направляется на клетку; клетка под указателем сообщает, кого заденет, включая друзей. Остаток движения показан рядом с бюджетами, снова в вашей единице. Экран ничего не измеряет: каждая клетка, цена, маршрут, цель и точка прицеливания поступают с сервера.

**Перемещение.** Запас хода – `economy.movement` участника группы либо собственный `speed` существа, поделенный на `perCell` и округленный ВНИЗ; не меньше одной клетки, пока движение вообще возможно. Восполняется в начале собственного хода владельца и может расходоваться до, между и после действий: пройти, ударить, пройти снова. Вход на клетку стоит один или больше на трудной местности. Восемь направлений стоят одинаково, как на настольных сетках, для которых это сделано. Через друга можно пройти, но ни на ком нельзя остановиться; противник – стена; в твердую преграду входить нельзя, как и срезать угол между двумя твердыми клетками.

**Досягаемость и дальность.** Строка оружия получает их из `combat.attacks[].reach` и `.range`, каждое – столбец того же списка или одинаковое число для всех строк:

```json
"attacks": [
  {
    "list": "attacks",
    "budget": "action",
    "name": "name",
    "toHit": { "ability": { "column": "ability" } },
    "damage": { "dice": { "column": "damage" } },
    "reach": { "column": "reach" },
    "range": { "normal": { "column": "range" }, "long": { "column": "long_range" } }
  }
]
```

Ноль в столбце означает, что у строки нет такой дальности; так обычный меч находится в одном списке с метательным топором. Строка вообще без досягаемости достигает одной клетки. Действие существа использует собственный `reach` или `range`, способность каталога – `mechanics.range` (0 – на себя или касанием, то есть одна клетка при направлении на другого).

Строка с ОБОИМИ значениями – метательное оружие: в пределах досягаемости это взмах, дальше – выстрел. Поэтому правила выстрела ниже не касаются его в руке; им можно ударить проходящего мимо, в отличие от лука.

Действие существа также может содержать свой `area` в вашей единице: `{ "shape": "cone",
"size": 15 }`, с `"friendlyFire": false` для защиты своей стороны. Так дыхательное оружие становится настоящим конусом на поле, а не числом целей. У последовательности нет собственной формы; она есть у именуемых действий. Бой без поля игнорирует форму и использует `targetCount`, поэтому элемент существа может указать оба варианта и быть корректным в обоих режимах.

**Как далеко можно послать область.** Это задает `range`: у шара, брошенного на сто футов, оно есть. Без дальности взрыв происходит там, где его поставили, на собственной клетке действующего, а конус или линию можно направить на любую клетку в пределах рисуемой длины: здесь клетка задает только направление. Это относится и к `mechanics.area` элемента каталога, и к области существа.

`ranged` задает цену выстрела за пределами обычной дистанции `normal` либо при враге на соседней клетке. Каждый вариант – `"disadvantage"` или `"normal"`; без блока оба не имеют цены. Взмах никогда не является выстрелом, поэтому оба правила его не касаются, как и метательного оружия в пределах досягаемости.

**Области.** `mechanics.area` элемента становится реальной формой на поле, направленной на клетку, а не участника; `targetCount` к ней не относится: число целей определяет форма. Задеты все стоящие в клетках, друзья и враги, если элемент не задает `"friendlyFire": false`.

```
burst, size 2, aimed at X        cone, size 3, aimed right      line, size 3, aimed right
. . . . .                        . . . .                        . . . .
. # # # .                        . . # .                        A # # #
. # X # .                        A # # #                        . . . .
. # # # .                        . . # .
. . . . .                        . . . .
```

Взрыв покрывает все клетки в пределах своего размера от целевой клетки. Конус идет от действующего к ней, на каждом шаге имея ширину, равную расстоянию. Линия идет так же с шириной в одну клетку. Все три останавливаются на твердой преграде.

**Линия видимости и укрытие.** Прямая линия клеток между двумя участниками: твердая преграда блокирует выстрел и распространение области за нее, а цель просто отсутствует в меню. Местность, дающая укрытие, прибавляет `cover.bonus` к защите против атаки, и журнал это сообщает. Нет укрытия на три четверти, полного укрытия или высоты.

**Удары по уходящим.** Объявите `opportunity.budget`; когда боец выходит из досягаемости стоящего врага, который способен действовать, имеет этот бюджет и оружие ближнего боя, перемещение ОСТАНАВЛИВАЕТСЯ на месте, а врага спрашивают, ударить ли. Согласие тратит бюджет и разрешается как та же атака в его собственный ход; пропуск ничего не стоит. Затем перемещение продолжается с места задержки, оплачивая каждую действительно пройденную клетку; удар, поваливший движущегося, заканчивает путь там, где тот упал. У каждого одна возможность на весь путь независимо от того, сколько раз он выходит из той же досягаемости. `disengage` предотвращает это до конца хода; у набора правил без `opportunity` ничего из этого нет.

Запрос – это ОКНО, удерживающее весь бой: ничто не движется, пока все спрошенные не ответят. За участника группы отвечает игрок, выбирая удар или соседнее Pass; за остальных – тот, кто ими играет, а за босса Мастера игры – собственное решение Мастера игры. См. Окна ниже.

**Как противник использует поле.** Противник, которым никто не играет, оценивает каждую достижимую клетку относительно всех вариантов оттуда, вычитает за каждый удар на пути и предпочитает не двигаться, если уже способен на лучший вариант с места. Когда ничто не в досягаемости, сокращает дистанцию, начиная с рывка, если в `standard` есть `dash`.

**Возможные отказы.** `out-of-reach` (дальше досягаемости), `no-line-of-sight` (твердая преграда), `unreachable` (клетка, которую нельзя оплатить движением или на которой нельзя закончить путь), `bad-cell` (область направлена в недопустимое место).

### Что бой делает с вашим блоком на сервере

Игра, чей набор правил объявляет `combat`, получает бой по этому блоку на том же сохраненном сражении, которое Engine использовал всегда:

- **Кто участвует.** Мастер игры говорит, кто сражается; Engine читает числа каждого участника группы из его листа. Участник без листа вашего набора правил отклоняется по имени, а не получает числа, которых вы не писали.
- **Откуда числа противника**, по порядку: существо, названное Мастером игры в бестиарии; существо с подписью, совпадающей с именем противника; предложенный Мастером игры для боя блок статистик, ограниченный вашей шкалой угрозы; наконец, простое существо из чисел ступени. Каждый запасной вариант и каждое ограничение фиксируются обычными словами, чтобы бой мог объяснить сделанное. Набор правил без элемента бестиария, предложения и шкалы угрозы отклоняет бой, а не выдумывает его.
- **Листы – источник записи.** Здоровье, запасы, состояния, концентрация и счетчики правила умирания записываются по собственным правилам листа после каждого принятого действия, поэтому перезагрузка посреди боя показывает ровно оставленное боем; итогового подсчета после сражения, который мог бы противоречить этому, нет.
- **Меню – единственный источник допустимости.** Каждый действующий, игрок или противник, выбирает id из одного и того же меню блока. Противник Engine выбирает по собственной тактике Engine; противнику Мастера игры предлагается выбрать один id из того же меню, с вашими числами, но без сведений о будущих результатах костей.
- **Ваши кости.** У боя собственные зерно и курсор, поэтому прочитанный с диска бой продолжается с теми же костями, которые бросил бы.

### На экране

Бой идет на экране сражения в ваших терминах. Меню содержит ваши атаки, способности и перечисленные стандартные действия; каждое показывает расход из ваших бюджетов и запасов. Видны порядок ходов, раунд, все названные состояния с оставшимися раундами, временные очки, концентрация и два счетчика правила умирания. Журнал выводит настоящую арифметику в ваших терминах: "Juno attacks Rust jackal with Road axe: 8 (5 + 3) + 3 = 11 against Guard 6, a hit." Каждое принятое действие сразу записывается в лист, поэтому перезагрузка посреди боя точна, а Мастеру игры после этого сообщают не менять эти числа повторно.

Бой с позициями рисуется на поле вместо сцены портретов; действия игрока описаны в разделе Позиции. Любое расстояние на поле, в меню и журнале выражается в ВАШЕЙ единице: "Juno moves to 4, 6 for 6 paces and has 2 paces left."

### Окна: приостановка боя

Некоторые моменты принадлежат не действующему сейчас участнику, а другому. Engine оставляет бой открытым для его решения вместо решения за него; такая пауза – окно.

Его открывают четыре ситуации; две уже следуют из ваших объявлений:

- **Кто-то отходит.** Перемещение, выходящее из досягаемости способного ударить врага, останавливается на этом шаге и спрашивает его. См. Удары по уходящим выше.
- **Между ходами.** После конца хода, до начала следующего, каждого противника с `signaturePoints`, которому доступна оплата собственного действия `signature`, спрашивают о покупке. Это единственный момент покупки: особого действия нет ни в чьем меню хода, включая собственное.
- **На кого-то направлено действие.** До разрешения спрашивают всех на ДРУГОЙ стороне, на кого оно направлено и у кого есть элемент, ожидающий такого момента. Лечащий друг не является угрозой, требующей ответа, поэтому действие друга не открывает окно.
- **Кому-то причинили урон.** После разрешения спрашивают всех пострадавших с элементом, ожидающим ЭТОГО момента, независимо от виновника. Полученный урон – факт о вас; элемент, направленный обратно на виновника, все равно нельзя направить на друга.

Последние две ситуации элемент каталога запрашивает, указывая ожидаемый момент.

Что делает окно независимо от причины открытия:

- **Пока оно открыто, ничто другое не движется.** Ни действующий участник, ни конец его хода, ни другое окно. Бой ждет.
- **Спрашивает по одному**, в порядке ходов, каждого один раз. Пропуск всегда допустим и бесплатен. Участник без доступных вариантов пропускается без вопроса.
- **Продолжается ровно с места задержки.** Перемещение проходит оставшиеся клетки, оплачивая каждую реально пройденную.
- **Отвечает тот, кто играет участником.** Окно вашего участника группы принадлежит вам: вариант и соседнее Pass в меню; за противника отвечает управляющий им, а за босса Мастера игры – Мастер игры, с пропуском момента как одним из ответов.
- **Сохраняется вместе с боем.** Игра, закрытая посреди движения, возвращается с теми же ожидающими ответа участниками и оставшимися клетками.

Для первых двух ничего дополнительно не объявляется: набор правил с `opportunity.budget` получает первое, бестиарий с `signaturePoints` – второе, а набор без обоих никогда их не видит.

**Указать, какого момента ждет элемент.** Запишите `mechanics.reaction` объектом вместо `true`:

```json
"reaction": { "on": "aimed", "at": "source", "cancels": true }
```

- `on` – `aimed` или `harmed`; именно оно помещает элемент в меню окна. Engine следит только за этими двумя моментами. Элемент с прежним `"reaction": true` сообщает лишь, что не выполняется в ход; этого недостаточно для предложения где-либо, поэтому его нет ни в одном меню.
- `at` – `source` (по умолчанию) или `chosen`. `source` направляет действие на вызвавшего момент и подставляет цель без запроса выбора; `chosen` сохраняет собственные цели элемента и спрашивает.
- `cancels` полностью останавливает событие, которое удерживало окно. Задать его может только элемент `aimed`: уже случившееся отменить нельзя.

Задайте также `budget`, иначе тратится бюджет списка по умолчанию. Реакция почти всегда расходует собственный бюджет, который не дает вместить несколько в один ход.

**Цена тратится до того, как кого-либо спросят.** Отмененное действие не происходит, но уже куплено: бюджет и запасы потрачены. Если ваша система возвращает их, выразить это пока нельзя.

Пакету, именующему момент, нужен Capability API 1.33.

### Пока нет

Прямо, поскольку набор правил не должен обещать того, чего Engine не делает:

- **За пределами простого поля**: нет укрытия на три четверти или полного укрытия, высоты, полета над препятствиями, протискивания, верховой езды, перемещения захватом или толчком, скрытности или внезапности; ничто никого никуда не отталкивает.
- **Элемент может ждать только два момента**, `aimed` и `harmed` (см. Окна выше). Engine замечает их от имени элемента; два остальных окна, отход и пауза между ходами, открывает сам бой, и элемент не может их запросить. Нет момента броска спасброска, заклинания как такового, смерти, начала хода или падения чего-либо.
- **Цепочек нет.** Бой хранит одно окно вместо стека, поэтому ничто внутри окна не открывает следующее: контрмеру нельзя контрить, а урон реакции не вызывает новый момент.
- **Реакция останавливает или делает что-то, но не меняет число действия.** Нельзя выразить «труднее попасть до следующего хода»: состояние – имя из закрытого списка, а не модификатор. Это ограничение состояний, а не реакций.
- **Ничего не возвращается.** Цена отмененного действия остается потраченной.
- Состояния делают только то, что выражает закрытый список эффектов. Состояние с помехой к ПРОВЕРКАМ характеристик или нарастающее по уровням, как истощение, сегодня просто запись в листе.
- **У существа, записанного обычными числами, нет шкалы ран.** В наборе правил со здоровьем-шкалой такое существо все еще теряет очки; дайте ему `sheet`, чтобы удары отмечали клетки после применения его `resist`, `vulnerable` и `immune`.
- **Дополнительный эффект срабатывает сам.** У `on` одно значение, `hit`, поэтому его получает первое подходящее попадание периода; момента с вопросом, потратить ли его, нет.

## Слои: варианты вашего набора правил

Слой – именованный вариант набора правил, который игрок включает при создании игры: мало магии, суровая зима, более жесткая сложность. Слои живут в файле набора правил в необязательном массиве `layers`, поэтому путешествуют с ним и никогда не пропадают из использовавшей их игры. Мастер настройки показывает их переключателями под набором правил; выбор закреплен на весь срок игры, как и сам набор.

```json
"layers": [
  {
    "id": "hard_winter",
    "label": "Hard winter",
    "summary": "Cold, hunger and short days. Everything is harder.",
    "conflicts": ["mud_season"],
    "gm": {
      "guidance": "Hard winter is on. Let a failed check cost warmth, food or daylight as well as progress.",
      "worldGuidance": "Hard winter is on. Build a world of closed roads, thin stores and rationed settlements."
    },
    "fields": [{ "id": "calling", "removeValues": ["Sailor"], "default": "Hauler" }],
    "difficultyLadder": [{ "label": "Easy", "dc": 7 }],
    "catalogs": [{ "id": "knacks", "hide": { "filter": "grit", "above": 0 } }]
  },
  {
    "id": "mud_season",
    "label": "Mud season",
    "summary": "Thaw, flooded roads and slow going."
  }
]
```

**Что может слой.** Список закрыт; каждый эффект что-то сужает либо добавляет текст:

- `gm.guidance` добавляется к `gm.checkGuidance` после вашего текста и текстов предыдущих слоев. `gm.worldGuidance` аналогично добавляется к `gm.worldGuidance`.
- `fields` убирает значения из поля **enum**. `removeValues` именует уже имеющиеся значения; хотя бы одно должно сохраниться, и если `default` поля удаляется, слой вместо него именует сохраняющийся `default`.
- `difficultyLadder` заменяет вашу шкалу другой в форме вашего вида разрешения: `{label, dc}` для `dice-sum`, `{label, successes, target?}` для `dice-pool`. Проходит ровно те же проверки, что ваша шкала. Если ее объявляют несколько активных слоев, побеждает последний.
- `catalogs` скрывает элементы из селектора редактора листа. Каждое правило именует один из объявленных `filters` каталога и ровно одно сравнение: `above` или `below` для фильтра `number`, `equals` или `notIn` для `text` или `tags`. Элемент, вообще не задающий этот фильтр, никогда не скрывается.

**Чего слой не может.** Он не добавляет значение перечисления, поле, навык, запас или отдых, не меняет вид разрешения, текущее состояние или боевые числа, не добавляет вызов модели. Значение, _добавленное_ слоем, было бы неизвестно остальным читателям листа, поэтому значения могут только убираться. Все вне списка – изменение самого набора правил или второй набор.

**Конфликты.** `conflicts` именует слои, которые нельзя включать вместе. Достаточно указать одну сторону пары. Мастер настройки блокирует другой переключатель; если сохраненный выбор все же содержит оба, объявленный **позже** отбрасывается, поэтому те же два выбора всегда дают те же правила.

**Лист, уже хранящий удаленное значение, сохраняет его.** Ничто не переписывает персонажа. Редактор просто перестает предлагать значение; персонаж, уже имевший его, показывает его как есть. Выключите слой в новой игре – значение снова предлагается. То же со скрытым элементом каталога: он отсутствует в селекторе, но уже выбранная игроком строка остается в листе.

**Ограничения.** 12 слоев на набор правил и 4000 символов указаний на слой, считая обе строки вместе. Пакетный набор с `layers` или базовым `gm.worldGuidance` требует Capability API 1.25. Импортируемый набор проверяет читающий его Engine, поэтому ему ничего такого не нужно.

**Слои другого автора** (слой малой магии для чужого набора правил, поставляемый своим файлом) – будущее дополнение. Сегодня слой поставляется внутри набора, которому принадлежит.

## Как опробовать набор правил

Наборы правил сообщества используют тот же переключатель, что импортированные агенты. Откройте **Settings** (настройки) > **Advanced** (дополнительно) > **Danger Zone** (опасная зона) и убедитесь, что включено **Allow custom Agent imports** (разрешить импорт пользовательских агентов). Для импорта также нужен доступ через localhost или настроенный **Admin Access** (доступ администратора).

1. Откройте панель **Agents** и выберите **Import agents** (импортировать агентов; значок загрузки в ряду кнопок вверху панели).
2. Выберите **Game Mode ruleset** (набор правил Game Mode) и свой файл JSON.
3. Прочитайте обзор: имя, версия, лицензия, покрываемые возможности и текст Мастера игры. Выберите **Import** (импортировать).

Набор появится в разделе **Rules** (правила) панели и в выборе **Rules** мастера настройки новых игр. Импорт из файла получает имя `local/<your id>`, поэтому его нельзя спутать с официальным или чужим набором.

### Изменение уже импортированного набора правил

Импортированная версия никогда не переписывается. Если изменить файл и снова импортировать с тем же `version`, импорт отклоняется с просьбой поднять номер. Это намеренно: игра связана с точной версией создания, поэтому идущая кампания никогда не проснется с другой математикой.

Цикл разработки: отредактировать, поднять `version`, импортировать, начать новую игру. Старые версии остаются рядом с новой, пока вы не удалите набор из **Rules**. Удаление набора, который еще использует игра, заставляет ее сообщать об отсутствии правил до повторного импорта.

При изменении формы листа (добавлении, удалении или переименовании) поднимите также `sheet.version`. Существующие листы читаются терпимо: неизвестные новому листу значения сохраняются, отсутствующие получают значения по умолчанию.

## Как поделиться набором правил

**Файлом.** Отправьте JSON другу; он импортирует его так же, как вы.

**Из репозитория GitHub.** Если работа хранится в публичном репозитории GitHub, поместите каждый набор в папку `rulesets` в корне, по одному файлу на набор:

```text
your-repository/
  agents.json        (optional, only if you also share agents)
  rulesets/
    ember-roads.json
    another-system.json
```

Пользователь один раз добавляет репозиторий через список пользовательских репозиториев агентов, просматривает содержимое и позже синхронизирует новые версии. Этот список – расширенная возможность, которую оператор сервера включает через `ENABLE_CUSTOM_AGENT_REPOS=true`. Наборы из репозитория записываются под именем владельца, например `alice/ember-roads`, поэтому два автора могут публиковать набор `v20` без конфликта.

Есть два ограничения. В репозитории может быть не более 32 файлов JSON непосредственно в `rulesets`; репозиторий с большим числом отклоняется. Аккаунт `local` не может публиковать наборы, поскольку `local/` зарезервирован для импорта из файла.

**В официальном каталоге.** Широко используемую систему с ясной лицензией можно предложить всем через **Download Agents** (загрузить агентов). Для этого нужен pull request в репозиторий [Marinara-Agents](https://github.com/Pasta-Devs/Marinara-Agents). Пример структуры – пакет `ruleset-5e-2014` там.

## Лицензирование

Публикуйте только текст правил, которым вправе делиться. Многие системы выпускают справочный документ по открытой лицензии; копировать можно именно из него. Поместите id лицензии и требуемый ею текст атрибуции в `license`. Не копируйте текст из книг правил без открытой лицензии. Набору в основном нужны названия и числа, а текст Мастера игры следует писать своими словами.

## Устранение неполадок

- **Импорт сообщает, что имя не существует.** Что-то в файле ссылается на необъявленный id, например навык именует удаленную характеристику. Сообщение дает путь к строке.
- **Импорт сообщает, что версия уже установлена с другим содержимым.** Поднимите `version` и импортируйте снова.
- **Набора нет в мастере настройки.** Проверьте **Allow custom Agent imports**. Пока он выключен, импортированные наборы недоступны новым играм. Уже использующие их игры продолжают работать.
- **Игра сообщает об отсутствии набора.** Точная версия, на которой создана игра, не установлена. Импортируйте эту версию файла снова.
