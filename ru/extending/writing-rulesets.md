# Создание наборов правил Game Mode

Набор правил объясняет Game Mode настольную систему: какие кости бросает проверка, что есть в листе персонажа, какие ресурсы тратятся и что возвращает отдых. Руководство предназначено тем, кто хочет написать собственный набор и поделиться им. Для игры с чужим набором начните с [Игры с набором правил](../game/rulesets.md).

Набор правил – один JSON-файл. Это данные, не код. Ничего из него не выполняется, поэтому импорт не может ничего сделать с компьютером. Перед импортом чужого файла внимательно прочитайте текст Game Master: он передается модели в каждой игре с этим набором.

## Прочтите сначала: что набор правил может и чего не может

Набор может лишь заполнять параметры механики, уже известной Engine. Сейчас Engine знает пять способов разрешения проверки; файл выбирает один через `resolution.kind`:

- **`dice-sum`**: бросить кости, прибавить числа листа и достигнуть либо превысить сложность. Подходит для d20, 2d6 плюс характеристика и многих других систем.
- **`dice-pool`**: бросить число костей персонажа и сосчитать достигшие цели. Подходит системам, где рейтинг означает горсть костей вместо бонуса.

- **`dice-highest`**: бросить пул и взять его наибольшую кость или сложить несколько наибольших. Подходит для Blades in the Dark и Trophy Dark.
- **`roll-against`**: выбросить не больше (или не меньше) числа листа. Подходит для процентных навыков и проверок GURPS.
- **`symbol-pool`**: набрать и улучшить повествовательные кости, затем взаимно отменить противоположные символы. Подходит для проверок Genesys, а с Capability API 1.382 – и для боев.

Все пять полностью описаны в разделе [Виды разрешения](ruleset-checks.md#resolution-kinds).

Механику, не соответствующую этим формам, нельзя записать в файле набора. Один из примеров – встречные пулы. Каждой такой механике нужен новый вид разрешения внутри Engine, то есть изменение кода с тестами, а не JSON-файл. Если ваша система требует такого вида, откройте запрос функции в репозитории Engine и опишите механику несколькими полностью разобранными бросками. Они станут тестами.

Game Mode разрешает бой по собственным правилам Marinara или правилам вашего набора. Необязательный блок `battle` передает бою Marinara числа листов персонажей: см. [Сражения](ruleset-combat.md#battles-lending-the-sheet-to-marinaras-combat). Необязательный `combat` вместо этого определяет разрешение боя самим набором: см. [Бой](ruleset-combat.md#combat-a-fight-your-own-rules-resolve). Engine уже применяет эти правила. Combat Preference (предпочтительный вид боя) выбирает представление Classic или поле Tactical, если набор определяет расстояние. Набор может ограничить доступные своим играм стили через `combat.styles` (см. [Какие стили доступны игре](ruleset-combat.md#combat-a-fight-your-own-rules-resolve)).

## Быстрый старт

1. Скопируйте пример, подходящий броскам вашей системы. [`ember-roads.json`](https://github.com/Pasta-Devs/Marinara-Engine/blob/staging/docs/examples/rulesets/ember-roads.json) – небольшая система 2d6 с тремя характеристиками, показывающая, что формат не предполагает d20 или шесть характеристик. [`gravewatch.json`](https://github.com/Pasta-Devs/Marinara-Engine/blob/staging/docs/examples/rulesets/gravewatch.json) – небольшой пул десятигранных костей с тремя рейтингами и шестью профессиональными навыками. Полноразмерный пример см. в официальном [пакете 5e (SRD 5.1)](https://github.com/Pasta-Devs/Marinara-Agents/tree/staging/packages/ruleset-5e-2014): его `ruleset.json` и `catalogs/` – то, что устанавливает Agent Organizer.
2. Замените `id` своим. Идентификатор состоит из строчных букв, цифр и одиночных дефисов, например `ember-roads`.
3. Измените лист, отдых и текст Game Master.
4. Импортируйте файл (см. [Как опробовать набор правил](#trying-your-ruleset)). Импорт проверяет весь файл и построчно сообщает ошибки до любого сохранения.
5. Создайте игру, выберите набор в **Rules** (правила) и выполните несколько проверок.

Для подсказок при вводе укажите редактору JSON Schema, добавив следующую первую строку внутри внешних фигурных скобок файла:

```json
"$schema": "https://raw.githubusercontent.com/Pasta-Devs/Marinara-Engine/staging/docs/extending/ruleset.schema.json",
```

Схема при вводе находит ошибки в именах ключей и типах. Она не проверяет, ссылаются ли имена на существующие сущности, например называет ли навык существующую характеристику. Это делает импорт.

В любой объект файла можно добавить строку `"$comment": "..."` с заметкой. Engine ее игнорирует.

## Части файла

| Ключ | Содержимое |
| --- | --- |
| `schemaVersion` | Всегда `1`. |
| `id`, `version` | Имя набора для Engine и целое число, повышаемое при каждой публикации изменения. |
| `name` | То, что игроки видят в мастере настройки. |
| `edition` | Необязательно. Строка об издании или черновике. |
| `license` | Необязательно. Идентификатор SPDX и требуемый источником текст указания авторства. |
| `coverage` | Область действия набора и краткое описание в мастере настройки. |
| `resolution` | Как бросается проверка или спасбросок. |
| `sheet` | Все содержимое листа персонажа. |
| `rests` | Что восстанавливает и очищает каждый вид отдыха. |
| `gm` | Текст модели Game Master и значения листа, которые она видит для каждого персонажа. |
| `catalogs` | Необязательно. Готовые записи редактора листа вместо ручного ввода длинных списков. |
| `items` | Необязательно. Слова, которыми описаны ваши предметы: категории, редкости, параметры, слоты, деньги. |
| `battle` | Необязательно. Что бой читает из листа и записывает обратно после завершения. |
| `combat` | Необязательно. Разрешение боя по собственным правилам и то, что разыгрывает экран боя. |
| `layers` | Необязательно. Варианты набора, включаемые при создании игры. |

Размер файла – до 512 KB (до Capability API 1.340 – 256 KB). Текст, попадающий в промпт (имена, подписи, текст Game Master), не может содержать переносов строк, квадратных или двойных фигурных скобок.

Идентификаторы листа (характеристики, навыки, поля, запасы и прочее) состоят из строчных букв, цифр и подчеркиваний, начиная с буквы, например `grit_max`.

## Страницы руководства

Эта страница объясняет, что такое набор правил, как начать его создавать, а затем опробовать и поделиться им. Остальная часть руководства разделена по темам:

- [Проверки набора правил](ruleset-checks.md): Как набор правил выполняет проверку или спасбросок: пять видов разрешения, степени исхода, проверки с собственным способом броска и расходы или талисманы, меняющие бросок
- [Листы набора правил](ruleset-sheets.md): Что входит в лист персонажа набора правил: характеристики, навыки, поля и списки, текущие состояния, шкалы ран, штрафы, отдых и текст Game Master, а также лист отряда и часы прогресса
- [Каталоги набора правил](ruleset-catalogs.md): Готовые записи, которые редактор листа предлагает в окне выбора: заголовок каталога, записи, значения, поддерживаемые набором правил, команды листа и команда использования
- [Механика записей набора правил](ruleset-mechanics.md): Что запись каталога делает в числах: блок `mechanics` записи, который читают проверки, отдых и бои
- [Конструктор персонажей набора правил](ruleset-character-builder.md): Пошаговый конструктор: создание персонажа по шагам, от расы и класса до показателей, владений, заклинаний и снаряжения
- [Предметы набора правил](ruleset-items.md): Что носит отряд: категории, оружие, доспехи, боеприпасы, добыча, деньги, начальное снаряжение и рынки
- [Бой по набору правил](ruleset-combat.md): Как набор правил участвует в бою: блок `battle`, передающий боевой системе Marinara лист персонажа, и блок `combat`, разрешающий весь бой по собственным правилам набора, с его бестиарием, полем боя, реакциями и состязаниями
- [Слои, переводы и миграции набора правил](ruleset-layers-and-translations.md): Варианты, которые игрок включает для одной игры, переводы текста набора правил и перенос значений на новые идентификаторы при изменении листа персонажа

## Как опробовать набор правил

Наборы правил сообщества используют тот же переключатель, что импортированные агенты. Откройте **Settings** (настройки) > **Advanced** (дополнительно) > **Danger Zone** (опасная зона) и убедитесь, что включено **Allow custom Agent imports** (разрешить импорт пользовательских агентов). Для импорта также нужен доступ через localhost или настроенный **Admin Access** (доступ администратора).

1. Откройте панель **Agents** и выберите **Import agents** (импортировать агентов; значок загрузки в ряду кнопок вверху панели).
2. Выберите **Game Mode ruleset** (набор правил Game Mode) и свой файл JSON или файл пакета набора правил с окончанием `.ruleset.json` (см. [Как поделиться набором правил](#sharing-your-ruleset)).
3. Прочитайте обзор: имя, версия, лицензия, покрываемые возможности и текст Game Master. Выберите **Import** (импортировать).

Набор появится в разделе **Rules** (правила) панели и в выборе **Rules** мастера настройки новых игр. Импорт из файла получает имя `local/<your id>`, поэтому его нельзя спутать с официальным или чужим набором.

### Изменение уже импортированного набора правил

Импортированная версия никогда не переписывается. Если изменить файл и снова импортировать с тем же `version`, импорт отклоняется с просьбой поднять номер. Это намеренно: игра связана с точной версией создания, поэтому идущая кампания никогда не проснется с другой математикой.

Цикл разработки: отредактировать, поднять `version`, импортировать, начать новую игру. Старые версии остаются рядом с новой, пока вы не удалите набор из **Rules**. Удаление набора, который еще использует игра, заставляет ее сообщать об отсутствии правил до повторного импорта.

При изменении формы листа (добавлении, удалении или переименовании) поднимите также `sheet.version`. Существующие листы читаются терпимо: неизвестные новому листу значения сохраняются, отсутствующие получают значения по умолчанию.

## Как поделиться набором правил

**Файлом.** Отправьте JSON другу; он импортирует его так же, как вы.

**Файлом пакета.** Набор правил, слишком большой для одного файла, с каталогами в отдельных файлах, передается одним простым файлом JSON с именем `<name>.ruleset.json`. Он содержит манифест пакета и документы набора правил, каждый – его точными байтами в base64:

```json
{
  "format": "marinara-ruleset",
  "version": 1,
  "manifest": { "kind": ["ruleset"], "…": "the package manifest" },
  "files": {
    "ruleset.json": "<base64>",
    "catalogs/spells.json": "<base64>"
  }
}
```

Манифест перечисляет `ruleset.json` и каждый `catalogs/<id>.json` в `contributions.assets.paths` и в `files`, с размером и sha256 каждого. Такой файл создает редактор наборов правил, например Pixelforge. **Import agents** → **Game Mode ruleset** принимает файл и показывает тот же обзор, что и для файла набора правил, с каждым каталогом и числом его записей. Ничто в нем не сжато, поэтому он никогда не содержит больше собственного размера. Он читается как данные и никогда не устанавливается как пакет: он отклоняется с указанием причины, если содержит что-либо еще (другой ключ, любой другой файл, документ, который не является строгим base64 или текстом UTF-8), если его манифест больше манифеста набора правил (любой код, разрешения или другие вклады), если файл не тот, который перечисляет манифест, если `$comment` длиннее 2 000 символов или `$schema` называет что-либо, кроме собственной схемы Engine, или если набор правил или каталог не читается. Он записывается как `local/<its id>`, как файл набора правил, размером не больше 132 MB и не больше чем с 12 файлами каталогов по 2 MB каждый и 40 переводами по 8 MB каждый (см. ниже). Версия – это набор правил вместе с его каталогами, поэтому измененному каталогу тоже нужна более высокая `version`. Пакеты наборов правил не принимаются в виде zip.

**Через официальный каталог агентов.** Набор правил, опубликованный в каталоге, – файл пакета набора правил именно такой формы, `<id>.ruleset.json`, никогда не zip-пакет (Capability API 1.374). Его манифест объявляет Capability API 1.374 или новее, поэтому более старому Engine он никогда не предлагается. Engine читает его тем же средством и с теми же проверками, что и импортируемый файл пакета, сверяет с манифестом, указанным в каталоге, и устанавливает как любой пакет каталога. Набор правил из каталога, чей артефакт – zip, отклоняется до начала скачивания; уже установленные наборы правил продолжают работать.

**Из репозитория GitHub.** Если работа хранится в публичном репозитории GitHub, поместите каждый набор в папку `rulesets` в корне, по одному файлу на набор:

```text
your-repository/
  agents.json        (optional, only if you also share agents)
  rulesets/
    ember-roads.json
    another-system.json
```

Пользователь один раз добавляет репозиторий через список пользовательских репозиториев агентов, просматривает содержимое и позже синхронизирует новые версии. Этот список – расширенная возможность, которую оператор сервера включает через `ENABLE_CUSTOM_AGENT_REPOS=true`. Наборы из репозитория записываются под именем владельца, например `alice/ember-roads`, поэтому два автора могут публиковать набор `v20` без конфликта.

Есть два ограничения. В репозитории может быть не более 32 файлов JSON непосредственно в `rulesets`; репозиторий с большим числом отклоняется. Аккаунт `local` не может публиковать наборы, поскольку `local/` зарезервирован для импорта из файла.

**В официальном каталоге.** Широко используемую систему с ясной лицензией можно предложить всем через **Agent Organizer (организатор агентов)** . Для этого нужен pull request в репозиторий [Marinara-Agents](https://github.com/Pasta-Devs/Marinara-Agents). Пример структуры – пакет `ruleset-5e-2014` там.

## Лицензирование

Публикуйте только текст правил, которым вправе делиться. Многие системы выпускают справочный документ по открытой лицензии; копировать можно именно из него. Поместите id лицензии и требуемый ею текст атрибуции в `license`. Не копируйте текст из книг правил без открытой лицензии. Набору в основном нужны названия и числа, а текст Game Master следует писать своими словами.

## Устранение неполадок

- **Импорт сообщает, что имя не существует.** Что-то в файле ссылается на необъявленный id, например навык именует удаленную характеристику. Сообщение дает путь к строке.
- **Импорт сообщает, что версия уже установлена с другим содержимым.** Поднимите `version` и импортируйте снова.
- **Набора нет в мастере настройки.** Проверьте **Allow custom Agent imports**. Пока он выключен, импортированные наборы недоступны новым играм. Уже использующие их игры продолжают работать.
- **Игра сообщает об отсутствии набора.** Точная версия, на которой создана игра, не установлена. Импортируйте эту версию файла снова.
