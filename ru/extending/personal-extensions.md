# Личные расширения

Личные расширения – это закрытые черновики кода, которые пишет для вас ассистент Professor Mari. Откройте **Settings** (настройки) > **Addons** (дополнения) > **Personal Extensions** (личные расширения).

По умолчанию раздел показывает такое сообщение:

> Ask Professor Mari to create an extension for you. Nothing runs until you enable it and approve the exact code hash.

Кнопки создания черновика здесь нет, средств импорта тоже. Попросите Professor Mari написать или переделать черновик. Ассистент сохраняет код, но не может его одобрить или включить.

Чтобы написать и импортировать собственный пакет, воспользуйтесь [руководством по созданию личных расширений](writing-personal-extensions.md). Самостоятельно созданные пакеты проходят отдельно защищенный процесс External Extensions.

## Проверка и включение

Каждый черновик изначально выключен. Marinara снимает отпечаток исполняемого кода алгоритмом SHA-256. Откройте черновик, изучите код, сверьте показанный хеш и только потом нажмите кнопку **Review and Run** (проверить и запустить) – если вы принимаете именно эту версию. Любая правка исполняемого кода и любая восстановленная версия выключают расширение и требуют нового одобрения.

Песочница ограничивает права, но не делает произвольный код надежным. Вредоносное расширение все равно способно нагружать процессор, пока его не остановит сторожевой механизм, забивать собственное хранилище до разрешенного предела или вводить в заблуждение записями в журнале. Расширения с полным доступом к странице отказываются от такой изоляции намеренно. Всегда читайте код перед включением.

## Изоляция во время работы

Браузерное расширение работает в отдельном Worker внутри изолированного iframe с непрозрачным источником (opaque origin). Ему недоступны страница приложения Marinara Engine, DOM, cookie, браузерное хранилище, API источника и сеть. Его возможности – это закрытое хранилище расширения, ведение журнала, управляемые таймеры, регистрация очистки, ограниченные окна, безопасные слоты для добавления элементов в интерфейс и снимок активного чата и идентификаторов персонажей – только для чтения. Отдельные поля активных карточек персонажей и выбранной персоны расширение получает лишь тогда, когда соответствующие разрешения объявлены и одобрены.

Расширение может добавить действия на верхнюю панель, пункты в меню **Extensions** и постоянные панели справа – через `marinara.ui.registerContribution(...)`. Marinara рисует эти элементы активной темой оформления и строго заданным набором средств управления: заголовки, текст, форматированный вывод, кнопки, текстовые поля, раскрывающиеся списки, переключатели, ползунки, выбор цвета и отступы. Расширение передает только содержимое и состояние – никогда HTML, CSS, адреса URL, компоненты React или обработчики событий приложения.

Эти возможности интерфейса и правила одинаковы для любого браузерного расширения в песочнице, откуда бы оно ни пришло. Импортированное сторонним разработчиком (внешнее) расширение работает в этой безопасной среде – если только его пакет прямо не запрашивает разрешение **Full page access** (полный доступ к странице) или не использует описанный ниже формат `marinara.extension` времен до песочницы.

### Добавление панели, которую рисует Marinara

```js
const panel = marinara.ui.registerContribution({
  id: "weather-settings",
  kind: "panel",
  label: "Weather controls",
  description: "Tune a weather scene without leaving Marinara.",
  icon: "sparkles",
  elements: [
    { kind: "heading", text: "Atmosphere" },
    {
      kind: "select",
      id: "weather",
      label: "Weather",
      value: "rain",
      options: [
        { value: "rain", label: "Rain" },
        { value: "snow", label: "Snow" },
        { value: "aurora", label: "Aurora" },
      ],
    },
    { kind: "slider", id: "intensity", label: "Intensity", min: 0, max: 100, value: 60 },
    { kind: "toggle", id: "lightning", label: "Lightning", checked: false },
    { kind: "color", id: "tint", label: "Tint", value: "#6d8cff" },
    { kind: "button", id: "apply", label: "Apply" },
  ],
  onActivate: async () => {
    const settings = await marinara.storage.get();
    // Update the panel when stored state should be reflected in the controls.
  },
  onEvent: async ({ elementId, values }) => {
    if (elementId !== "apply") return;
    await marinara.storage.patch(values);
  },
});

marinara.onCleanup(() => panel.remove());
```

Значение `kind: "button"` создает компактное действие, а `kind: "menu-item"` — действие в меню Extensions. По умолчанию кнопки используют `surface: "top-bar"`. Они также могут выбирать `chats`, `bots`, `characters`, `personas`, `lorebooks`, `presets`, `connections`, `agents` или `settings`, задав `position` как `header`, `before-content` или `after-content`. Поле `icon` принимает любое поддерживаемое Marinara имя значка Lucide в kebab-case. Оба вида действий вызывают `onActivate`. Панель (`panel`) вызывает `onActivate` при открытии, а ее кнопки вызывают `onEvent` с текущими значениями элементов. Обработчик поддерживает обновления по виду: `button` принимает `label`, `description`, `icon`, `surface` и `position`; `menu-item` — `label`, `description` и `icon`; `panel` — `label`, `description`, `icon` и `elements`. Все обработчики поддерживают `remove()`. В идентификаторах допустимы буквы, цифры, `.`, `_` и `-`.

Этот пример помещает нативное действие над содержимым панели Presets:

```js
marinara.ui.registerContribution({
  id: "preset-helper",
  kind: "button",
  label: "Preset helper",
  description: "Run the preset helper",
  icon: "list-sparkles",
  surface: "presets",
  position: "before-content",
  onActivate: () => {
    // Run extension behavior here.
  },
});
```

Сложные инструменты могут строить пошаговый интерфейс, обновляя элементы панели после события. Состояние держите в `marinara.storage` и не кодируйте его в разметке.

### Использование контекста активного чата

API браузерных расширений версии 5 открывает непрозрачные идентификаторы того чата, который приложение Marinara Engine показывает сейчас:

```js
const renderForContext = async ({ chatId, characterId, characterIds, personaId, characters, persona }) => {
  if (!chatId) return; // Home, a library, or another surface without an active chat.

  const storage = await marinara.storage.get();
  const tab = storage.tabsByChat?.[chatId];

  // characterId is available only for a single-Character chat.
  // Use characterIds for group chats.
  marinara.log.debug("Loaded Notepad tab", {
    chatId,
    characterId,
    characterIds,
    personaId,
    characterNames: characters.map((character) => character.name),
    personaName: persona?.name ?? null,
    tab,
  });
};

const unsubscribe = marinara.context.subscribe(renderForContext);
marinara.onCleanup(unsubscribe);
```

Метод `marinara.context.get()` возвращает тот же текущий снимок без подписки. Когда активного чата нет, `chatId` равен `null`, а `characterIds` пуст. Поле `characterId` заполняется, только если в чате участвует ровно один персонаж; групповые чаты перечисляют всех участников в `characterIds`, а `characterId` оставляют равным `null`. Поле `personaId` заполняется только при одобренном разрешении `read_active_persona`.

Идентификаторы чата и персонажей доступны всегда – по ним расширение может разделять собственное закрытое хранилище. Для полей самих записей нужно одно или оба необязательных разрешения в манифесте расширения:

```json
{
  "runtime": "client",
  "capabilities": ["read_active_characters", "read_active_persona"]
}
```

- `read_active_characters` заполняет `characters` карточками, которые участвуют в активном чате.
- `read_active_persona` заполняет `persona` персоной, выбранной для активного чата.

Без разрешения значение остается пустым: `[]` или `null`. Marinara показывает каждое запрошенное разрешение в блоке **Requested access** (запрошенный доступ) и еще раз – в окне одобрения точного хеша. Добавление и удаление разрешения меняет хеш исполняемого кода, выключает расширение и требует нового одобрения.

Снимок персонажа содержит только `id`, `name`, `description`, `personality`, `scenario`, `firstMessage`, `exampleDialogue`, `creator`, `characterVersion`, `tags`, `backstory`, `appearance`, `aboutMe` и `conversationDisplayName`. Снимок персоны содержит только `id`, `name`, `description`, `personality`, `scenario`, `backstory`, `appearance`, `tags`, `aboutMe` и `conversationDisplayName`. Длину текста Marinara ограничивает до передачи через мост песочницы.

Marinara никогда не передает сообщения, заметки автора, системные промпты, инструкции после истории, комментарии, пути к аватарам, полные библиотеки персонажей и персон, необъявленные поля, метаданные чата, дескрипторы базы данных, доступ к сети и операции изменения данных. Обновления контекста привязаны к одобренному хешу кода и приходят при смене активного чата, его списка персонажей или выбранной персоны.

### Старые расширения и расширения с полным доступом к странице

Управление погодой, редакторы промптов и другие серьезные рабочие сценарии – вполне подходящие случаи для добавления элементов интерфейса. При безопасном переносе такой инструмент запускается из меню или с верхней панели, а дальше работает через панель, которая обновляется по шагам. Готовые пакеты, которые накладывают свои элементы на DOM, ищут элементы по селекторам CSS приложения Marinara Engine, копаются во внутренностях React или обращаются к маршрутам `/api` того же источника, импортировать в безопасную среду без переделки нельзя.

Добавленные элементы дают интерфейс, а не права на все вокруг. API контекста всегда открывает идентификаторы активного чата и персонажей, а из полей записей – только объявленные и перечисленные выше. Функциям, которым нужны сообщения, пресеты, лорбуки, необъявленные данные персонажей и персон или визуальные эффекты сцены, по-прежнему нужна отдельная узко очерченная возможность-посредник со стороны Marinara. Расширение не должно подменять ее доступом к DOM приложения или свободными сетевыми запросами.

Если внешнее расширение действительно зависит от доступа к DOM страницы, оно может запросить:

```json
{
  "runtime": "client",
  "capabilities": ["full_page_access"]
}
```

**Разрешение Full page access не относится к возможностям песочницы.** Одобренный код JavaScript и таблицы стилей CSS выполняются прямо на странице приложения Marinara Engine. Такой код может прочитать и изменить все, что видно текущей сессии браузера, изучать чаты и карточки, пользоваться браузерным хранилищем, отправлять сетевые запросы и обращаться к API приложения Marinara Engine того же источника. На практике права у него на странице те же, что у кода, вставленного в консоль браузера. Черновики от Professor Mari запросить это разрешение не могут.

Старую оболочку `kind: "marinara.extension"` версии 1 без явного поля `capabilities` Marinara считает пакетом времен до песочницы и при импорте назначает ей **Full page access**. Так старые пакеты вроде WeatherTweaker попадают на правильную проверку, а не отказывают молча внутри Worker. Современный пакет, который использует эту оболочку, но хочет безопасную среду, должен указать `"capabilities": []`.

Оба разрешения для внешних расширений и одобрение точного хеша действуют и здесь. Изменение кода, CSS или набора разрешений выключает расширение и требует нового одобрения. При выключении Marinara удаляет свои узлы скрипта и таблицы стилей, отменяет таймеры, созданные через API совместимости, и вызывает обработчики, зарегистрированные через `marinara.onCleanup(...)`. Код страницы способен создавать незарегистрированные обработчики событий, таймеры, глобальные переменные и изменения DOM, поэтому очистка идет по мере возможного – если после выключения что-то осталось, перезагрузите страницу.

Более старый API `marinara.ui.showWindow(...)` по-прежнему доступен и открывает временное окно внутри iframe с непрозрачным источником. Он использует тот же заданный набор средств управления и возвращает обработчики `update(...)` и `close()`. Если инструмент должен быть доступен через обычную навигацию приложения Marinara Engine, лучше добавлять элементы интерфейса.

Серверное расширение работает в отдельном процессе Node с урезанными правами – внутри Seatbelt на macOS или Bubblewrap на Linux. Ему недоступны файлы приложения Marinara Engine, файлы пользователя, унаследованные секреты сервера, сеть, дочерние процессы, воркеры и нативные модули. Если Marinara не может поднять поддерживаемую песочницу операционной системы, серверные расширения остаются выключенными.

### Поддержка платформ

Браузерные расширения изолирует сам браузер, поэтому они работают везде. Серверным расширениям нужна поддерживаемая песочница операционной системы: там, где ее нет, они остаются выключенными и включить их нельзя – Marinara никогда не запускает их без песочницы.

| Платформа | Браузерные расширения в песочнице | Внешние расширения с полным доступом к странице | Серверные расширения |
| ----------------------- | ---------------------------- | ----------------------------- | ------------------------------------- |
| macOS | ✅ В песочнице | ⚠️ Нужно явное доверие | ✅ В песочнице (Seatbelt) |
| Linux (с Bubblewrap) | ✅ В песочнице | ⚠️ Нужно явное доверие | ✅ В песочнице (Bubblewrap) |
| Linux (без `bwrap`) | ✅ В песочнице | ⚠️ Нужно явное доверие | ⛔ Выключены – установите `bwrap` |
| Windows | ✅ В песочнице | ⚠️ Нужно явное доверие | ⛔ Выключены – возьмите браузерное расширение |
| Android | ✅ В песочнице | ⚠️ Нужно явное доверие | ⛔ Выключены – возьмите браузерное расширение |

На Windows и Android поддерживаемой песочницы для процессов нет, поэтому серверные расширения там недоступны намеренно. Используйте браузерное расширение или запустите сервер Marinara на macOS либо Linux (с `bwrap`), если серверное расширение действительно нужно.

## Внешние расширения

Импорт сторонних расширений по умолчанию закрыт и скрыт. Нужны два шага:

1. На машине, где работает Marinara, задайте `ENABLE_EXTERNAL_EXTENSIONS=true` в файле `.env`.
2. Откройте **Settings** > **Advanced** > **Danger Zone**, прокрутите ниже блока удаления данных, прочитайте предупреждение и включите переключатель **Allow third-party extension imports** (разрешить импорт сторонних расширений).

Только после этого в разделе **Settings** > **Addons** появляется блок **External Extensions** (внешние расширения) со средствами импорта файлов и папок. Поддерживаемые форматы всегда перечислены полностью:

- `.personal-extension.zip` и совместимые пакеты `.zip`;
- манифесты `.json`;
- `.css`;
- `.js`, `.mjs` и `.cjs`;
- `.server.js`, `.server.mjs` и `.server.cjs`.

Импорт никогда не приносит с собой одобрение, и расширение не может включить себя само. Записи из старых версий, попавшие в приложение вместе с профилем, добавленные в хранилище вручную и любые записи неизвестного происхождения тоже считаются внешними. Они остаются скрытыми, одобрить их нельзя, и обе среды исполнения их не видят, пока не открыты оба разрешения.

Перед одобрением точного хеша прочитайте список **Requested access**. Большинству браузерных расширений стоит оставаться в безопасной песочнице. Пакет с отметкой **Full page access** намеренно не изолирован: включайте его, только если вы изучили именно эту версию и доверяете ей.

Если выключить любое из двух разрешений, активные внешние серверные процессы останавливаются, браузерные воркеры и узлы среды с полным доступом к странице удаляются, а сохраненные внешние записи выключаются. Обратное включение разрешений не запускает их снова. Если расширение с полным доступом к странице оставило после себя изменения, не зарегистрированные для очистки, перезагрузите страницу.

Сторонние расширения могут содержать вредоносный или опасный код. Всегда проверяйте каждую строку перед скачиванием, импортом и включением. Вся ответственность лежит на вас.

## Экспорт, версии и восстановление

Чтобы скачать переносимый пакет, воспользуйтесь действием экспорта у расширения. Экспортированные и восстановленные пакеты остаются выключенными. Восстановление прежней версии тоже возвращает расширение в состояние выключенного черновика.

Если расширение ведет себя не так, как надо, нажмите кнопку **Disable** (выключить). Если интерфейс недоступен, остановите Marinara и задайте значение `"false"` в поле `enabled` нужной записи `installed_extensions`. Никогда не правьте `approvedHash` вручную.
