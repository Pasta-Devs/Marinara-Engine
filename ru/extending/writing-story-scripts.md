# Создание сюжетных сценариев Game Mode

Сюжетный сценарий позволяет автору направлять развитие игры Game Mode: сцены, которые разыгрываются, когда отряд куда-то прибывает; поручения Game Master (ведущему игры на базе ИИ), которые он получает, когда выполнено условие; цели, за которыми игрок следит в журнале приключений; и моменты, которые Game Master может отметить сам. Это руководство для тех, кто пишет собственные сценарии. Чтобы играть в мире, у которого есть сюжет, начните с раздела [Создание мира](../game/getting-started.md#making-a-world).

Сюжетный сценарий – это данные, а не код. Ничего из него не выполняется. Engine проверяет его по миру, для которого он написан, разыгрывает ход за ходом и отклоняет все, что не подходит.

## Где хранится сюжет

Сюжет принадлежит одному миру. Он называет места и людей этого мира, поэтому имеет смысл только вместе с миром, для которого написан (с его зерном, описанием и ручными правками).

- В **файле мира** (`.world.json`) – как ключ верхнего уровня `story` рядом с `world`. Engine, который не знает о сюжетах, все равно прочитает мир.
- В **наборе карт** Experience: каждый файл мира может нести свой сюжет, и новая игра получает его вместе с картой. См. [Дополнительные пакеты агентов и возможностей](../development/optional-agent-packages.md).
- В мире, который хранится в библиотеке вне какой-либо игры: `GET`, `PUT` и `DELETE /api/game-worlds/:id/story`, так же как у игры. Новая игра, начатая с этого мира, забирает сюжет с собой.
- В игре, после ее начала: `GET`, `PUT` и `DELETE /api/game/:chatId/story` читают, сохраняют и удаляют сюжет. Сохранение проверяется по миру игры с учетом ручных правок, а ручные правки, которые убрали бы что-то названное в сюжете, отклоняются.

При настройке новой игры сюжет, прочитанный из файла или набора карт, сохраняется, пока зерно и описание мира остаются прежними.

## Структура

```json
{
  "storyVersion": 1,
  "flags": [],
  "directions": [],
  "events": [],
  "cutscenes": []
}
```

Идентификатор – это от 1 до 40 строчных латинских букв, цифр, `_` или `-`; он уникален в пределах своего списка. Сюжет содержит не более 64 флагов, 64 указаний, 128 событий и 64 заставок. Ни один текст в нем не может содержать перенос строки, квадратные скобки или `{{`, а имена, вписанные в тег (группа, фон), не могут содержать двойную кавычку: ничто сказанное сюжетом не должно сойти за тег Game Master.

### Флаги

Флаг – это значение, которое хранит сюжет: `"bool"` (истина или ложь) или `"number"` (число).

```json
{ "id": "trust", "kind": "number", "initial": 0, "gm": true, "note": "How far the town trusts the party" }
```

- `gm: true` позволяет Game Master задавать флаг (см. [Теги Game Master](#the-game-masters-tags)); `note` объясняет ему, что флаг означает.
- Флаги скрыты от игрока. С `quest` флаг становится **целью квеста** в журнале приключений:

```json
{
  "id": "favours",
  "kind": "number",
  "initial": 0,
  "quest": { "title": "Favours", "text": "Do the town three favours", "goal": 3 }
}
```

Цель с логическим флагом выполнена, когда флаг истинен; числовая – когда флаг достигает своего `goal` (1, если не указано), а если `goal` записан явно, журнал показывает прогресс. Цель с `"hidden": true` не видна в журнале, пока ее не покажет событие.

### Указания

Указание – это постоянная инструкция для Game Master, которая действует, пока выполняются ее условия:

```json
{ "id": "wary", "text": "The town is wary of strangers.", "if": [{ "flag": "trust", "is": "<", "value": 2 }] }
```

### Условия

`{ "flag": "<id>", "is": "=" | "!=" | ">" | ">=" | "<" | "<=", "value": <value> }`. Должны выполняться все условия списка `if`. Логический флаг сравнивается только через `=` или `!=`.

### События

Событие – это то, что происходит: когда срабатывает его триггер и выполняются его условия, оно выполняет свои действия.

```json
{
  "id": "gates",
  "when": { "on": "arrive", "place": "p11" },
  "if": [{ "flag": "banished", "is": "=", "value": false }],
  "do": [{ "cutscene": "gates" }, { "set": "arrived", "value": true }, { "show": "key" }]
}
```

Событие происходит один раз, если у него нет `"repeat": true` (`start`, `turn` и `day` это игнорируют). За один ход происходит не более 32 событий, каждое не более одного раза, в том порядке, в котором их перечисляет сценарий.

**Триггеры** (`when.on`); все они читаются из того, что записала игра:

| Триггер | Срабатывает |
| --- | --- |
| `start` | На первом ответе игры. |
| `turn` | На ответе Game Master с номером `turn` за всю игру, с учетом всех сессий, или позже. |
| `day` | Когда день мира (его сдвигают течение времени, о котором говорит Game Master, и переходы) становится равен `day` или больше. |
| `arrive` | Пока отряд находится в `place` (идентификатор места) или в месте внутри него, попав туда при старте игры, переходом по общей карте мира, посещением в городе или потому, что это место назвал Game Master. С `repeat` – снова при каждом возвращении откуда-то еще. |
| `meet` | Когда ответ назвал `person` (идентификатор человека, например `p11-3`, или `p11-e1` для добавленного вручную) полным именем. С `repeat` – снова для каждого ответа, где он назван. Имена ищутся только в ответах текущей сессии. |
| `deed` | Когда мир записал поступок отряда вида `deed` и, если указано, в месте `place`. С `repeat` – снова для каждого ответа, который записывает такой поступок. |
| `fight` | Когда бой заканчивается результатом `outcome`: `victory`, `defeat` или `flee`. |
| `broke` | Когда бой разрушил предмет обстановки с именем `prop` (Capability API 1.316); регистр не учитывается. Назвать можно только предмет, нарисованный на одном из полей боя мира. |
| `flags` | Когда выполняются его условия. С `repeat` – снова каждый раз, когда они становятся истинными после того, как были ложными. |
| `gm` | Только когда его запускает Game Master (событию нужно `"gm": true`). |
| `step` | Когда переход проходит по клетке `x`, `y` (отсчет с 0 от левого верхнего угла) в `place`: по городу поселения (путь посещения, от двери до двери) или по карте места, созданной вручную (переход по ней). На клетку должен иметь возможность ступить отряд: в городе – земля, до которой можно дойти от площади, но не свободный участок, где сюжет может строить; на карте – пол, до которого можно дойти от входа. У сгенерированной карты нет клеток, которые можно назвать. С `repeat` – снова в каждый ход, переход которого проходит по ней. |

Ручные правки, которые отнимают клетку у события шага (на нее поставлено здание, пол карты обнесен стеной), отклоняются при сохранении, и в сообщении называется это событие.

Повторяющееся событие `meet`, чья собственная сцена называет этого человека, или повторяющееся событие `deed`, которое само совершает ожидаемый поступок, запускало бы себя каждый ход, поэтому Engine его отклоняет.

**Действия** (`do`):

| Действие | Что делает |
| --- | --- |
| `{ "set": "<flag>", "value": <value> }` | Задает флаг. |
| `{ "add": "<flag>", "amount": <number> }` | Прибавляет к числовому флагу. |
| `{ "tell": "<text>" }` | Просит Game Master о чем-то один раз, на этом ходу. |
| `{ "cutscene": "<id>" }` | Показывает заставку. |
| `{ "show": "<flag>" }` | Показывает скрытую цель квеста в журнале. |
| `{ "world": { "deed": "<kind>", "group": "...", "with": "...", "place": "<place id>", "who": "..." } }` | Записывает поступок в мир; он обрабатывается так же, как поступок, записанный самим Game Master. |

Сюжет не выдает предметы, не начинает бои, не перемещает отряд и не завершает игру: это остается за Game Master и игроком. Попросите об этом Game Master через `tell`.

### Заставки

Заставка либо показывается игроку точно так, как написана, либо передается Game Master, чтобы он ее рассказал.

```json
{
  "id": "gates",
  "kind": "pages",
  "background": "backgrounds:generated:town-gates",
  "pages": [
    { "text": "The gates creak open." },
    { "speaker": "p11-3", "expression": "happy", "text": "Welcome, travellers." },
    { "speaker": "player", "text": "We come in peace." }
  ]
}
```

Заставка `pages` разыгрывается перед ответом Game Master, в повествовании, по одной странице: страница без говорящего – это повествование, страница с говорящим – реплика этого человека под его именем в мире (или под именем игрока для `player`), с выражением `expression` из собственного списка Game Master. `background` – это фон, который есть в игре, или `backgrounds:generated:<words>`, чтобы фон был создан, когда включена генерация изображений. Game Master сообщают, что сцена показана, и он продолжает с нее.

```json
{ "id": "dusk", "kind": "beats", "beats": ["Lamps are lit.", "A bell tolls."] }
```

Заставку `beats` Game Master рассказывает своими словами на этом же ходу, бит за битом (бит – короткое описание того, что происходит). Биты события `gm` сообщаются Game Master вместе с событием, и он рассказывает их в ответе, который отмечает этот момент. Поэтому сцена из битов, которую использует событие `gm`, известна Game Master с самого начала, даже если ее разыгрывает и событие Engine. Поскольку биты сообщаются ему на каждом ходу, биты всех событий `gm` вместе ограничены 16 000 символов.

<a id="the-intro-message"></a>

### Вступительное сообщение

`intro` (Capability API 1.339) задает начало игры – тот же выбор, который настройка GM предлагает любой игре:

```json
"intro": { "mode": "defined", "text": "The leaves have not fallen in Hollowmere for nine years.", "locked": true }
```

`"defined"` делает первое сообщение игры точно равным `text`: Game Master ничего для него не пишет, а повторная генерация дает тот же текст. `"guided"` лишь направляет начало, которое пишет Game Master: это указание он читает только для первого ответа. `text` занимает от 1 до 8000 символов и может содержать переносы строк (единственный текст сюжета, которому это разрешено), но никогда `{{`; в направляющем тексте нельзя использовать и квадратные скобки. С `locked` игрок видит вступление в настройке GM и не может его изменить; без него вступление лишь заполняет поле настройки, и игрок может изменить или очистить его. У игры, первый ответ которой уже написан или которая переносит свой отряд из прежней игры, вступления нет.

## Как разыгрывается сюжет

Один раз за ход, перед ответом Game Master, Engine читает, что сюжет уже сделал и что приносит этот ход (переход, посещение, конец боя), и запускает события. Все произошедшее записывается в начало этого ответа: тег для каждого события и того, что оно задало, и каждая сцена, показанная как написано. Поскольку сюжет восстанавливается из ответов, свайп или повторная генерация отменяют то, что сделал их ответ, а сюжет, измененный посреди игры, никогда не переписывает уже произошедшее. Сюжет переходит в следующую сессию игры.

<a id="the-game-masters-tags"></a>

### Теги Game Master

Каждый ход Game Master получает значения сюжета (скрытые от игрока) и действующие указания. Из остального сценария ему сообщается только то, что сценарий отдает ему самому: события `gm` (с их `note` и битами `beats`, которые нужно рассказать вместе с ними) и флаги `gm`, а также какие из этих событий он сейчас не может отметить (уже выполнены или сдерживаются условиями). Он отмечает их в своем ответе:

- `[story: event="<id>"]` запускает событие `gm`, условия которого выполняются (один раз, если оно не повторяется).
- `[story: flag="<id>" value="<value>"]` или `add="<number>"` для числового флага задает флаг `gm`.

Engine отвечает на каждый тег на месте, на событие – не более одного раза за ход, а все остальное отклоняет с указанием причины. В игре без сюжета отклоняется любой тег сюжета. То, что запускает Game Master, действует сразу (его флаги, его поступки); его сцены и поручения приходят в начале следующего ответа, кроме `beats` (их Game Master просили рассказать вместе с моментом). Пишите `pages` события `gm` как то, что следует за моментом, ведь сам момент Game Master уже рассказал.

## Как опробовать сюжет

Сохраните сюжет в игру через `PUT /api/game/:chatId/story` с телом `{ "story": { ... } }`: неподходящий сюжет отклоняется со всеми причинами. Вкладка World игры показывает цели, которые сюжет уже открыл, а промпт Game Master каждый ход содержит значения и указания сюжета.
