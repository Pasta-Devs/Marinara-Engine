# Семантический поиск в лорбуках

В этом руководстве объясняется, как работает семантический поиск в лорбуках приложения Marinara Engine. Семантический поиск позволяет записи лорбука активироваться по смыслу, а не только по точным ключевым словам. Вы увидите, как выбрать источник эмбеддингов, векторизовать записи и настроить точность совпадений.

## Что дает семантический поиск

Лорбук – это набор записей. У каждой записи есть ключевые слова для активации и блок текста. Обычно запись активируется только тогда, когда в недавних сообщениях чата встречается одно из ее точных ключевых слов. Если в тексте использовано другое слово, запись молчит.

Семантический поиск решает эту проблему. Он сравнивает смысл недавних сообщений чата со смыслом ваших записей. Тогда запись активируется даже без совпадения по точному ключевому слову. Например, запись с ключевым словом "меч" сработает и на сообщение, где сказано только "клинок".

Работает это на эмбеддингах. Эмбеддинг – это набор чисел, который передает смысл фрагмента текста. Marinara хранит для каждой записи один эмбеддинг, его также называют вектором. Этот шаг называется векторизацией. Во время чата Marinara строит эмбеддинг недавних сообщений и находит записи с самым близким смыслом.

При включенном семантическом поиске совпадения по ключевым словам продолжают работать. Семантический поиск только добавляет новые совпадения. Ключевые слова он не заменяет.

Когда Marinara применяет лимит на число записей лорбука и лимит токенов, совпадения по ключевым словам и по смыслу имеют одинаковый приоритет. Если все подходящие записи не помещаются, выбор между текущими совпадениями по ключевым словам и по смыслу решает заданный вами порядок записей; сам способ активации преимущества не дает.

## Перед началом: выберите источник эмбеддингов

Семантическому поиску нужна модель, которая умеет создавать эмбеддинги. Есть два варианта.

Какой бы вариант вы ни выбрали, его можно сделать общим по умолчанию для всего приложения: откройте **Connections** (подключения), затем **Connection defaults** (подключения по умолчанию) и выберите его в поле **Embeddings**. Все подключения, у которых нет собственной модели эмбеддингов и собственного поля **Embedding Connection**, тогда используют его. Собственная настройка подключения по-прежнему главнее, а строка показывает, сколько подключений используют свои настройки. Значение **None** оставляет запасным вариантом встроенную локальную модель.

Вариант 1: подключение с моделью эмбеддингов.

1. Откройте панель **Connections** (подключения).
2. Откройте подключение для редактирования.
3. Найдите раздел **Semantic Search (Embeddings)** (семантический поиск).
4. Введите название модели эмбеддингов в поле модели. Часто используют `text-embedding-3-small`.
5. Сохраните подключение.

Эмбеддинги поддерживает не каждый провайдер. Если провайдер их не умеет, редактор предложит выбрать отдельное подключение для эмбеддингов.

Вариант 2: встроенная локальная модель.

Marinara может запустить небольшую модель эмбеддингов прямо на вашем компьютере, без ключа API. В списке выбора внутри лорбука этот вариант называется **Local Model (sidecar)**. Он появляется только после скачивания локальной модели. Как ее установить, описано в руководстве [Настройка модели Local Model](../connections/local-model.md).

В сборке Marinara Lite вариант **Local Model (sidecar)** скрыт. Там семантическому поиску нужно подключение с моделью эмбеддингов.

## Включение переключателя Vectors для лорбука

В новых лорбуках семантический поиск выключен. Включать его нужно отдельно для каждого лорбука.

1. Откройте лорбук, по которому хотите искать по смыслу.
2. Останьтесь на вкладке **Overview** (обзор).
3. Найдите переключатель **Vectors** (векторы) и включите его.

Подсказка к переключателю **Vectors** читается: "When on, entries in this lorebook may use semantic embeddings. When off, keyword matching still works and vectorization skips this lorebook."

Пока **Vectors** выключен, семантическая панель показывает примечание: "Semantic search is disabled by the lorebook-level Vectors toggle."

## Панель Semantic Search (Embeddings)

Когда **Vectors** включен, на вкладке **Overview** появляется панель **Semantic Search (Embeddings)**. Плашка статуса показывает, сколько записей векторизовано – например, "8/12 entries vectorized". Как только готовы все записи, плашка становится зеленой и получает галочку.

В панели три числовых настройки.

| Настройка | Что делает | По умолчанию | Диапазон |
|---|---|---|---|
| **Query Messages** (сообщения для запроса) | Сколько недавних сообщений чата брать для эмбеддинга при поиске по этому лорбуку. | 10 | от 0 до 100 |
| **Score Threshold** (порог сходства) | Минимальное калиброванное сходство, при котором запись активируется. Чем выше, тем строже. | 0.3 | от 0 до 1 |
| **Vector Limit** (лимит векторов) | Сколько совпадений по смыслу этот лорбук добавляет к одной генерации максимум. | 10 | от 1 до 100 |

Значение 0 в поле **Query Messages** включает поиск по всей истории чата вместо последних сообщений.

Настройка **Score Threshold** задает, насколько близким должен быть смысл. Низкое значение вроде 0.2 пропускает больше записей, но растет риск совпадений не по теме. Высокое значение вроде 0.5 строже и оставляет только близкие по смыслу записи. Начните со стандартного значения и меняйте его, если совпадений слишком много или слишком мало.

Marinara калибрует эту оценку по нескольким нейтральным фрагментам, не связанным между собой и полученным от той же модели эмбеддингов. Так снимается неестественно высокий общий порог косинусного сходства: у некоторых локальных и OpenAI-совместимых движков эмбеддингов даже несвязанные тексты получают около 0.95 и выше. Поэтому настройка остается полезной для любой модели эмбеддингов, и не приходится подбирать для каждой модели отдельное пороговое значение около 1.0.

Настройка **Vector Limit** ограничивает только совпадения по смыслу. Обычные лимиты токенов действуют поверх нее.

## Векторизация записей

Векторизация – это построение и сохранение эмбеддинга для каждой записи. Без нее совпадения по смыслу не работают.

1. Включите **Vectors** для лорбука.
2. В панели **Semantic Search (Embeddings)** выберите источник эмбеддингов в раскрывающемся списке. Первый вариант – **No semantic search**. Следующим идет **Local Model (sidecar)**, когда он доступен. За ним – подходящие подключения.
3. Нажмите кнопку векторизации. Если у части записей вектора нет, на кнопке написано **Vectorize N missing** – например, "Vectorize 5 missing".
4. Дождитесь окончания прогона. Плашка статуса обновится и покажет, что векторизованы все записи.

Если модели эмбеддингов нет ни в одном подключении, вместо раскрывающегося списка панель показывает примечание: "No connections with an embedding model configured. Set an Embedding Model on a connection first." Сначала настройте источник эмбеддингов по шагам выше.

Когда вектор есть у каждой записи, главная кнопка меняется на **Re-vectorize N entries**. Она перестраивает все сохраненные векторы. Перед перезаписью приложение просит подтверждение.

Отдельная кнопка **Re-vectorize all** появляется, когда у части записей векторы есть, а у остальных еще нет. Ею можно перестроить все за один проход.

Чтобы удалить сохраненные векторы, нажмите кнопку **Delete vectors**. Удаляются только эмбеддинги. Текст записей и ключевые слова остаются как были. После удаления векторов совпадения по ключевым словам работают по-прежнему.

### Пропуск отдельной записи

Одну запись можно оставить без векторизации, а остальные векторизовать. Откройте запись и включите переключатель **No Vector**. Его подсказка читается: "When enabled, bulk vectorization skips this entry and removes any stored embedding." Такая запись по-прежнему активируется по ключевым словам. Она просто не совпадает по смыслу.

## Повторная векторизация после смены модели

Сохраненные векторы привязаны к той модели эмбеддингов, которая их создала. Если перейти на другую модель эмбеддингов, старые векторы могут перестать сходиться.

После смены модели эмбеддингов перестройте все векторы. Нажмите **Re-vectorize N entries** или **Re-vectorize all**, чтобы все записи использовали одну модель.

После смены модели не запускайте частичную векторизацию. Если прогон только по недостающим записям вернет вектор другого размера, чем у сохраненных, сервер откажет с сообщением: "Embedding dimensions changed. Use Re-vectorize all entries instead of only missing entries before switching embedding models."

Есть один тихий сбой, о котором стоит знать. Во время чата Marinara строит эмбеддинг недавних сообщений моделью запроса. Модель запроса – это модель эмбеддингов активного подключения или, если оно задано, модель из его поля **Embedding Connection**. Если в подключении не задано ни то ни другое, Marinara берет значение **Embeddings** из **Connection defaults**, а при **None** – встроенную локальную модель. Модель запроса может выдать вектор другого размера, чем модель, которой векторизованы записи. Тогда Marinara пропускает такие записи при поиске по смыслу. Ошибки вы не увидите. Чтобы этого не случилось, векторизуйте записи тем же источником эмбеддингов, который работает во время чата. Поможет и значение **Embeddings** по умолчанию: при векторизации выбор сначала стоит на нем, если раньше вы не выбирали ничего другого, а подключения без собственных настроек эмбеддингов запрашивают с его помощью. После любой смены модели векторизуйте заново.

## Как это помогает агенту Knowledge Router

Семантический поиск помогает и агенту **Knowledge Router**. Этот агент выбирает подходящие записи лорбука и вставляет их в промпт – это нужно для больших лорбуков. Если лорбук векторизован, агент строит короткий список записей-кандидатов и по совпадениям по смыслу, и по вашим ключевым словам.

Для агента этот шаг необязателен. Если лорбук не векторизован или источник эмбеддингов недоступен, агент опирается только на совпадения по ключевым словам. Векторизация просто дает ему более удачный короткий список. Как работает этот агент, описано в руководстве [Источники знаний: агенты Knowledge Retrieval и Knowledge Router](../agents/knowledge-sources.md).
