# Лимиты токенов и рекурсия в лорбуках

Это руководство объясняет, как Marinara Engine ограничивает объем текста из лорбуков, который доходит до ИИ. Здесь разобраны поля **Token Budget** (лимит токенов) и **Entry Limit** (лимит записей) у каждого лорбука, а также общий для чата параметр **Lorebook Token Budget**. Вы также увидите, как Marinara отсекает записи при заполненном лимите и что делает сканирование в режиме **Recursive** (рекурсивно).

Токен – это небольшой кусочек текста, примерно несколько символов. У каждой модели контекстное окно ограничено: это весь объем текста, который она способна прочитать за один раз. Лимиты не дают лорбукам занять все окно и вытеснить из него сам чат.

## Два лимита токенов

Каждый раз при сборке промпта Marinara применяет два независимых лимита токенов. Если запись выводит любой из них за предел, Marinara ее пропускает.

1. У каждого лорбука есть собственное поле **Token Budget**. Оно ограничивает объем текста, который этот лорбук добавляет к одному ответу.
2. У чата есть одно поле **Lorebook Token Budget**. Оно ограничивает суммарный текст всех активных лорбуков этого чата.

Оба предела работают одновременно. Одну запись может заблокировать лимит лорбука, лимит чата или сразу оба.

## Настройка полей Token Budget и Entry Limit у лорбука

Откройте лорбук в панели **Lorebooks** и перейдите на вкладку **Overview**. Рядом с настройками сканирования находятся два числовых поля.

- **Token Budget** (по умолчанию **2048**): максимум токенов, который этот лорбук добавляет к одному ответу. Значение **0** снимает ограничение.
- **Entry Limit** (по умолчанию **100**): максимум записей, которые этот лорбук добавляет к одному ответу. Допустимы значения от **1** до **1000**.

Поле **Entry Limit** – это отдельный предел, не связанный с лимитом токенов. Он считает записи, а не токены. Даже когда в лимите токенов остается место, лорбук перестает добавлять записи, как только достигает этого предела. И наоборот: лимит токенов пропускает записи и тогда, когда лорбук еще не дошел до значения **Entry Limit**.

Например: в лорбуке поле **Token Budget** равно **2048**, а одна запись занимает 3000 токенов. Такую запись лорбук не добавит никогда. Уменьшайте лимит только тогда, когда лорбук занимает слишком много места. Увеличивайте его, если важные записи постоянно пропускаются.

## Общий для чата параметр Lorebook Token Budget

Предел на уровне чата задается в выдвижной панели **Settings** (настройки) конкретного чата, в разделе **Lorebooks**.

1. Откройте чат.
2. Откройте выдвижную панель **Settings** этого чата.
3. Найдите раздел **Lorebooks**.
4. Задайте значение в поле **Lorebook Token Budget**.

По умолчанию – **8192**. Значение **0** снимает ограничение. Этот лимит считается суммарно по всем лорбукам, активным в этом чате. Он действует вместе с собственным полем **Token Budget** каждого лорбука.

## Как отсекаются записи

Когда совпадений больше, чем позволяет лимит, Marinara оставляет самые важные записи и отбрасывает остальные. Перед отсечением записи сортируются, чтобы уцелели те, которые нужны с наибольшей вероятностью.

- Первыми идут записи типа **Constant**. Это записи, которые вставляются всегда, пока лорбук активен.
- Дальше – записи, совпавшие с последним сообщением.
- Остальные записи следуют в обычном порядке вставки.

Marinara идет по этому списку сверху вниз и добавляет каждую запись, которая еще помещается. Запись, выводящую лимит за предел, Marinara пропускает и переходит к следующей. При этом проверяются все записи ниже пропущенной. Поэтому запись поменьше попадает в промпт даже после того, как более крупная была пропущена.

## Пропущенные записи в панели Active Context

Догадываться, какие записи отброшены, не нужно. Откройте **Chat Settings** (настройки чата) и разверните раздел **Active Context** (активный контекст). В нем видно текущий результат последнего сканирования лорбуков.

Если какие-то совпавшие записи были пропущены, сверху появляется желтое уведомление. Оно читается "N matching lore entries were skipped by token budget." Разверните его, чтобы увидеть каждую пропущенную запись.

Для каждой пропущенной записи указан лорбук, из которого она пришла, и причина блокировки. Причина бывает одной из трех:

- **lorebook budget**: запись не поместилась в поле **Token Budget** этого лорбука.
- **chat budget**: запись не поместилась в общий для чата параметр **Lorebook Token Budget**.
- **lorebook and chat budgets**: оба предела уже были заполнены.

Разверните пропущенную запись, чтобы увидеть подробности: совпавшие ключевые слова, оценку размера в токенах и уже израсходованную часть лимита. Если крупные лорбуки пропускаются постоянно, **Active Context** предлагает агентов **Knowledge Retrieval** и **Knowledge Router**. Для больших лорбуков они обычно подходят лучше, чем увеличение пределов.

## Рекурсивное сканирование

Обычно Marinara ищет совпадения по ключевым словам только в последних сообщениях. Когда сканирование **Recursive** включено, проверяется еще и текст только что активированных записей. Так активированная запись подтягивает связанные записи, чьи ключевые слова встречаются в ее тексте.

Включается на вкладке **Overview** лорбука.

1. Откройте лорбук.
2. Перейдите на вкладку **Overview**.
3. Включите переключатель **Recursive**. По умолчанию он выключен.
4. Задайте значение **Max Depth**, если нужно изменить длину цепочки.

Поле **Max Depth** (по умолчанию **3**) задает число дополнительных проходов сканирования. Каждый проход ищет новые совпадения ключевых слов в записях, активированных на предыдущем шаге. Допустимы значения от **1** до **10**. Чем больше значение, тем больше связанных фактов находится, но тем выше нагрузка.

Рекурсию нужно разрешить и для каждой записи отдельно. В развернутой выдвижной панели записи переключатель **Recursion** задает, может ли содержимое этой записи активировать другие записи. По умолчанию он выключен. Оставьте его выключенным, если запись не должна вытягивать за собой другие факты. Полный разбор настроек записи – в руководстве [Записи лорбука: ключевые слова, позиция и время срабатывания](entries.md).

Рекурсия не обходит лимиты. Записи, найденные рекурсивным проходом, учитываются в полях **Token Budget** и **Entry Limit**, а также в общем для чата параметре **Lorebook Token Budget**, наравне со всеми остальными.
