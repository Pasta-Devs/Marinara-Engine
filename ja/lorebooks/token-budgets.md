# ロアブックのトークン予算と再帰

このガイドでは、Marinara EngineがAIに渡すロアブックの分量をどう制限するのかを説明します。ロアブックごとの**Token Budget**(トークン予算)と**Entry Limit**(エントリー数の上限)、そしてチャット全体に効く**Lorebook Token Budget**(ロアブックのトークン予算)を取り上げます。予算がいっぱいになったときにエントリーがどう削られるのか、**Recursive**(再帰)スキャンが何をするのかもあわせて説明します。

トークンとは、文章を区切った小さな単位で、だいたい数文字ぶんにあたります。どのモデルにもコンテキストウィンドウの上限があり、これが一度に読み込めるテキストの総量です。予算を設けておけば、ロアブックがコンテキストウィンドウを埋め尽くして肝心のチャットを押し出してしまうのを防げます。

## 2つのトークン予算

Marinaraはプロンプトを組み立てるたびに、2つのトークン予算を別々に適用します。どちらか一方でも上限を超えてしまうエントリーは、Marinaraが追加を見送ります。

1. ロアブックはそれぞれ**Token Budget**を持ちます。これは、そのロアブック1冊が1回の返信で追加できるテキスト量の上限です。
2. チャットには**Lorebook Token Budget**が1つあります。これは、そのチャットで有効なすべてのロアブックを合計したテキスト量の上限です。

2つの上限は同時に働きます。1つのエントリーが、ロアブックの予算で止まることも、チャットの予算で止まることも、その両方で止まることもあります。

## ロアブックのToken BudgetとEntry Limitを設定する

**Lorebooks**パネルからロアブックを開き、**Overview**(概要)タブを開きます。スキャン設定の近くに、数値を入力する欄が2つあります。

- **Token Budget**(デフォルトは**2048**): このロアブックが1回の返信で追加できるトークン数の上限です。**0**にすると無制限になります。
- **Entry Limit**(デフォルトは**100**): このロアブックが1回の返信で追加できるエントリー数の上限です。**1**から**1000**まで設定できます。

**Entry Limit**はトークン予算とは別の上限です。数えるのはトークンではなくエントリーの数です。トークン予算に余裕が残っていても、この上限に達した時点でロアブックはエントリーの追加をやめます。逆に、**Entry Limit**に達していなくてもトークン予算のほうでエントリーが見送られることがあります。

たとえば、**Token Budget**が**2048**のロアブックに3000トークンのエントリーが1つある場合を考えてみます。このロアブックは、そのエントリーを追加できません。予算を下げるのは、ロアブックが場所を取りすぎているときだけにします。重要なエントリーが何度も見送られるようなら、予算を上げてください。

## チャット全体のLorebook Token Budget

チャット単位の上限は、チャットの**Settings**(設定)パネルにある**Lorebooks**の項目です。

1. チャットを開きます。
2. チャットの**Settings**パネルを開きます。
3. **Lorebooks**の項目を探します。
4. **Lorebook Token Budget**の欄を設定します。

デフォルトは**8192**です。**0**にすると無制限になります。この予算は、このチャットで有効なすべてのロアブックの合計にかかります。ロアブックごとの**Token Budget**に加えて働く上限です。

## エントリーが削られる仕組み

予算に収まりきらない数のエントリーが一致した場合、Marinaraは重要なものを残して残りを落とします。必要になりそうなエントリーが生き残るように、削る前に並べ替えます。

- **Constant**のエントリーが先頭に来ます。これは、ロアブックが有効なあいだ毎回挿入されるよう設定されたエントリーです。
- 次に、直前のメッセージに一致したエントリーが続きます。
- 残りのエントリーは、通常の挿入順に並びます。

Marinaraはこの並びを上から順にたどり、まだ収まるエントリーを追加していきます。予算の上限を超えてしまうエントリーは飛ばして、次に進みます。飛ばしたエントリーより下も、最後まで確認します。つまり、大きいエントリーが見送られたあとでも、小さいエントリーなら入れることがあります。

## Active Contextで見送られたエントリーを確認する

どのエントリーが落ちたのかを推測する必要はありません。**Chat Settings**(チャット設定)を開き、**Active Context**(現在のコンテキスト)セクションを展開してください。ここには、直近のロアブックスキャンの結果がそのまま表示されます。

一致したエントリーが見送られた場合は、上部に黄色の通知が出ます。文言は「N matching lore entries were skipped by token budget.」です。展開すると、見送られたエントリーを1つずつ確認できます。

見送られたエントリーには、どのロアブックのものか、なぜ止まったのかが示されます。理由は次のいずれかです。

- **lorebook budget**: そのロアブック1冊の**Token Budget**に収まりませんでした。
- **chat budget**: チャット全体の**Lorebook Token Budget**に収まりませんでした。
- **lorebook and chat budgets**: 両方の上限がすでにいっぱいでした。

見送られたエントリーを展開すると、さらに詳しい情報が見られます。一致したキーワード、推定トークン数、予算をすでにどれだけ使っているかがわかります。大きなロアブックが何度も見送られる場合は、**Active Context**が**Knowledge Retrieval**エージェントや**Knowledge Router**エージェントを提案します。上限を引き上げるより、大きなロアブックにはこちらのほうが向いていることが多いためです。

## 再帰スキャン

通常、Marinaraはキーワードの一致を直近のメッセージだけで探します。**Recursive**スキャンをオンにすると、いま発動したばかりのエントリーの本文も探索の対象になります。これで、発動したエントリーの中にキーワードがある関連エントリーを、そこから芋づる式に引き込めます。

オンにするのは、ロアブックの**Overview**タブです。

1. ロアブックを開きます。
2. **Overview**タブを開きます。
3. **Recursive**スイッチをオンにします。デフォルトはオフです。
4. どこまで連鎖させるかを変えたいときは、**Max Depth**(最大深度)を設定します。

**Max Depth**(デフォルトは**3**)は、追加のスキャンを何回行うかを決めます。1回ごとに、新しく発動したエントリーからさらにキーワードの一致を探します。**1**から**10**まで設定できます。値を大きくするほど関連するロアブックの内容が多く見つかりますが、処理の負荷も増えます。

再帰はエントリーごとにもオンにする必要があります。エントリーを展開したパネルにある**Recursion**トグルが、そのエントリーの本文からさらにエントリーを発動できるかどうかを決めます。デフォルトはオフです。ほかのロアブックの内容へ連鎖させたいエントリー以外は、オフのままにしておいてください。エントリー側の設定は[ロアブックのエントリー: キー、位置、タイミング](entries.md)にまとめてあります。

再帰でも予算は迂回できません。再帰のスキャンで見つかったエントリーも、ほかのエントリーと同じように**Token Budget**、**Entry Limit**、チャット全体の**Lorebook Token Budget**を消費します。
