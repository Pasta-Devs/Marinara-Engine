# ロアブックのセマンティック検索

このガイドでは、Marinara Engineのロアブックで使えるセマンティック検索を説明します。セマンティック検索を使うと、キーワードがそのまま一致しなくても、意味の近さでロアブックのエントリーが発動します。埋め込みソースの用意、エントリーのベクトル化、一致の調整までがわかります。

## セマンティック検索でできること

ロアブックはエントリーの集まりです。エントリーにはキーワードと本文があります。通常、エントリーが発動するのは、直近のチャットにそのキーワードがそのままの形で現れたときだけです。同じ意味でも別の言葉が使われていると、エントリーは反応しません。

セマンティック検索はこの弱点を補います。直近のチャットの意味とエントリーの意味を比べるので、キーワードが1つも一致しなくてもエントリーが発動します。たとえば「sword」をキーワードにしたエントリーは、「blade」としか書かれていないメッセージにも反応します。

この仕組みを支えるのが埋め込みです。埋め込みとは、文章の意味を表した数値の並びのことです。Marinaraはエントリーごとに埋め込みを1つ保存します。埋め込みはベクトルとも呼ばれ、それを作って保存する処理をベクトル化と呼びます。チャット中は、Marinaraが直近のメッセージを埋め込みに変換し、意味がいちばん近いエントリーを探します。

セマンティック検索をオンにしても、キーワードによる一致はそのまま働きます。セマンティック検索は一致を増やすだけで、キーワードを置き換えるものではありません。

Marinaraがロアブックのエントリー数とトークンの上限を適用するとき、キーワードによる一致とセマンティック検索による一致は同じ優先度です。一致したエントリーが全部は入りきらない場合、どれを残すかを決めるのは設定したエントリーの並び順です。発動のしかたの違いで優劣は付きません。

## 事前準備: 埋め込みソースの選択

セマンティック検索には、埋め込みを作れるモデルが必要です。方法は2つあります。

どちらを選んでも、アプリ全体のデフォルトにできます。**Connections**(接続)を開き、**Connection defaults**(接続のデフォルト)の**Embeddings**で選びます。埋め込みモデルも**Embedding Connection**も個別に設定していない接続は、そのデフォルトを使います。接続ごとの設定は引き続き優先され、その行には、個別の設定を使っている接続の数が表示されます。**None**にすると、内蔵のLocal Modelが代替として使われます。

方法1: 埋め込みモデルを設定した接続を使う。

1. **Connections**(接続)パネルを開きます。
2. 編集したい接続を開きます。
3. **Semantic Search (Embeddings)**(埋め込みによるセマンティック検索)のセクションを探します。
4. モデルの欄に埋め込みモデル名を入力します。よく使われる値は`text-embedding-3-small`です。
5. 接続を保存します。

すべてのプロバイダーが埋め込みに対応しているわけではありません。対応していないプロバイダーでは、埋め込み専用の接続を選ぶよう編集画面が案内します。

方法2: 内蔵のLocal Modelを使う。

Marinaraは、APIキーなしで小さな埋め込みモデルを手元のコンピューターで動かせます。ロアブックの選択欄では、この方法は**Local Model (sidecar)**という名前で表示されます。表示されるのは、Local Modelをダウンロードした後だけです。導入のしかたは[Local Modelのセットアップ](../connections/local-model.md)を参照してください。

Marinara Liteをお使いの場合、**Local Model (sidecar)**の選択肢は表示されません。Liteでセマンティック検索を使うには、埋め込みモデルを設定した接続が必要です。

## ロアブックでのVectorsの有効化

新しいロアブックでは、セマンティック検索はデフォルトでオフです。ロアブックごとにオンにします。

1. 意味で検索したいロアブックを開きます。
2. **Overview**(概要)タブを開いたままにします。
3. **Vectors**(ベクトル)スイッチを見つけて、オンにします。

**Vectors**の説明文は次のとおりです: 「When on, entries in this lorebook may use semantic embeddings. When off, keyword matching still works and vectorization skips this lorebook.」

**Vectors**がオフの間、セマンティック検索のパネルには次の注記が表示されます: 「Semantic search is disabled by the lorebook-level Vectors toggle.」

## Semantic Search (Embeddings)パネル

**Vectors**をオンにすると、**Overview**タブに**Semantic Search (Embeddings)**パネルが表示されます。ステータスチップには、ベクトル化が済んだエントリー数が「8/12 entries vectorized」のように表示されます。すべてのエントリーが終わると、チェックマークが付いて緑色に変わります。

このパネルには数値の設定が3つあります。

| 設定 | 内容 | デフォルト | 範囲 |
|---|---|---|---|
| **Query Messages** | このロアブックを検索するとき、直近のチャットメッセージを何件分埋め込みに変換するか。 | 10 | 0から100 |
| **Score Threshold** | エントリーが発動するために必要な、補正後の類似度の下限。大きいほど厳しくなります。 | 0.3 | 0から1 |
| **Vector Limit** | 1回の生成でこのロアブックが追加できるセマンティック検索の一致の上限。 | 10 | 1から100 |

**Query Messages**を0にすると、直近の範囲ではなくチャット履歴全体を対象に検索します。

**Score Threshold**は、意味がどれだけ近ければよいかを決めます。0.2のような低い値にすると多くのエントリーが通りますが、話題と関係のない一致も増えます。0.5のような高い値は厳しく、意味がよく似たものだけに一致します。まずはデフォルトのまま使い、一致が多すぎたり少なすぎたりしたら調整してください。

Marinaraはこのスコアを、同じ埋め込みモデルで作った無関係な中立の文章いくつかを基準に補正します。ローカルやOpenAI互換の埋め込みバックエンドの中には、無関係な文章どうしでも軒並み0.95以上になるほど、共通の下限値が異常に高いものがあります。補正はこの下限値を取り除きます。そのため、この設定はモデルごとに1.0近くの値を探さなくても、どの埋め込みモデルでもそのまま役に立ちます。

**Vector Limit**が制限するのはセマンティック検索の一致だけです。通常のトークンの上限は、その上にさらに適用されます。

## エントリーのベクトル化

ベクトル化とは、エントリーごとに埋め込みを作って保存することです。セマンティック検索による一致を働かせるには、先にこの処理が必要です。

1. ロアブックの**Vectors**をオンにします。
2. **Semantic Search (Embeddings)**パネルのドロップダウンで埋め込みソースを選びます。最初の選択肢は**No semantic search**です。次に、使える場合は**Local Model (sidecar)**が並びます。その後ろに、条件を満たす接続が続きます。
3. ベクトル化のボタンをクリックします。ベクトルのないエントリーがあるときは、ボタンの表示が**Vectorize N missing**になり、たとえば「Vectorize 5 missing」と出ます。
4. 処理が終わるまで待ちます。ステータスチップの表示が変わり、すべてのエントリーのベクトル化が済んだことがわかります。

埋め込みモデルを設定した接続が1つもない場合、パネルにはドロップダウンの代わりに次の注記が表示されます: 「No connections with an embedding model configured. Set an Embedding Model on a connection first.」上の手順に従って、先に埋め込みソースを用意してください。

すべてのエントリーにベクトルがある状態では、メインのボタンが**Re-vectorize N entries**に変わります。これは保存済みのベクトルをすべて作り直します。上書きの前に確認を求めます。

一部のエントリーにだけベクトルがあり、残りが未処理のときは、**Re-vectorize all**ボタンが別に表示されます。すべてを一度に作り直したいときに使います。

保存したベクトルを消すには、**Delete vectors**をクリックします。消えるのは埋め込みだけです。エントリーの本文やキーワードは変わりません。ベクトルを削除しても、キーワードによる一致は働き続けます。

### 特定のエントリーの除外

ほかはそのままに、1つのエントリーだけをベクトル化の対象から外せます。そのエントリーを開き、**No Vector**トグルをオンにします。説明文は次のとおりです: 「When enabled, bulk vectorization skips this entry and removes any stored embedding.」対象から外したエントリーも、キーワードでは発動します。意味による一致だけが行われなくなります。

## モデルを変えた後の再ベクトル化

保存したベクトルは、それを作った埋め込みモデルと結び付いています。別の埋め込みモデルに切り替えると、古いベクトルは噛み合わなくなることがあります。

埋め込みモデルを変えたら、すべてのベクトルを作り直してください。**Re-vectorize N entries**か**Re-vectorize all**を使い、全エントリーを同じモデルで揃えます。

モデルを変えた後に、足りない分だけのベクトル化を実行しないでください。「不足分のみ」の実行が保存済みのベクトルと違うサイズの結果を返すと、サーバーは次のメッセージを出して処理を拒否します: 「Embedding dimensions changed. Use Re-vectorize all entries instead of only missing entries before switching embedding models.」

気づきにくい失敗のしかたが1つあります。チャット中、Marinaraは直近のメッセージをクエリー用のモデルで埋め込みに変換します。クエリー用のモデルとは、使用中の接続に設定された埋め込みモデル、または**Embedding Connection**を設定している場合はそのモデルのことです。どちらも設定がなければ、**Connection defaults**の**Embeddings**の設定を使い、それが**None**なら内蔵のLocal Modelを使います。このクエリー用のモデルが、エントリーをベクトル化したモデルと違うサイズのベクトルを返すことがあります。その場合、Marinaraは該当するエントリーをセマンティック検索の対象から外します。エラーは表示されません。これを避けるには、チャットで使うのと同じ埋め込みソースでエントリーをベクトル化してください。**Embeddings**のデフォルトを設定しておくと役立ちます。ベクトル化の選択欄は、以前に別のものを選んでいない限りそのデフォルトで始まり、埋め込みの設定を個別に持たない接続もそれでクエリーを行います。モデルを変えたら必ず作り直します。

## Knowledge Routerエージェントとの連携

セマンティック検索は**Knowledge Router**エージェントの役にも立ちます。このエージェントは、大きなロアブックから関係のあるエントリーを選び、プロンプトに挿入します。ロアブックがベクトル化されていると、Knowledge Routerはキーワードによる一致に加えて、セマンティック検索の一致からも候補エントリーの絞り込みリストを作ります。

Knowledge Routerにとって、この処理は必須ではありません。ロアブックがベクトル化されていない場合や、使える埋め込みソースがない場合は、キーワードによる一致だけを使います。ベクトル化は絞り込みリストの質を上げるだけです。このエージェントの動作は[知識ソース: Knowledge RetrievalとKnowledge Routerエージェント](../agents/knowledge-sources.md)を参照してください。
