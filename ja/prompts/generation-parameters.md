# 生成パラメーター

生成パラメーターとは、モデルが1回の返信をどう書くかを決める設定で、**Temperature**(温度)や**Max Output Tokens**(最大出力トークン数)などがあります。プリセットとアカウントがデフォルト値を提供し、**Chat Settings**(チャット設定)の**Advanced Parameters**(詳細パラメーター)セクションで1つのチャットだけ上書きできます。通常のチャットやロールプレイならデフォルトで十分なので、変更するのは、はっきりした問題を直したいときだけにしてください。

## 設定の場所

| 対象 | 場所 |
| --- | --- |
| プリセットの初期値 | **Presets**(プリセット)でプリセットを開き、**Parameters**(パラメーター)タブ |
| アカウントに保存した値 | **Connections**(接続)でアカウントを開き、**Chat defaults**(チャットのデフォルト)セクション |
| 1つのチャットだけの上書き | **Chat Settings**の**Advanced Parameters**セクション |

プリセットは、コンテキストや出力のトークン上限を設定しません。コンテキストウィンドウは**Connections**で、出力の上限は**Connections**か**Advanced Parameters**で設定してください。古いプリセットファイルも読み込めますが、保存されているトークン上限は無視されます。組み込みの**Marinara's Universal Preset**(Marinaraの汎用プリセット)は、生成パラメーターを一切指定しません。

1つのチャットでパラメーターを上書きするには:

1. チャットを開きます。
2. **Chat Settings**を開きます。
3. **Advanced Parameters**を探し、クリックして展開します。
4. **Temperature**などのパラメーターを探し、新しい値を入力します。
5. 名前の隣にある小さなスイッチを確認します。オフならオンにしてください。スイッチがオフのパラメーターは送信されないため、変更しても効果がありません。**Temperature**のスイッチは最初はオフです([Sendスイッチ](#the-send-switch)を参照)。

「Change generation settings for this chat only. Leave these alone unless you know what they do.」という注記が表示されます。**Advanced Parameters**は、Conversation、Roleplay、Gameのチャットで使えます。

## 各パラメーターの意味

数値のパラメーターには、それぞれ入力欄とSendスイッチ(下記を参照)が付いています。

| パラメーター | 働き | 範囲 |
| --- | --- | --- |
| **Temperature** | ランダムさです。低いほど的を絞った予測しやすい返信になり、高いほど創造的になります。中間の目安としては1前後がよく使われます。 | 0から2 |
| **Max Output Tokens** | モデルが1ターンで書ける返信の長さの上限です。トークンとは、文章を区切った小さな単位です。返信が途中で切れるときは上げてください。 | 決まった上限なし |
| **Top P** | モデルは、確率の高い単語から順に足して、合計がこの値に達するまでの範囲だけから選びます。1にするとすべてを検討します。 | 0から1 |
| **Top K** | 各ステップでモデルが選べる単語を、確率の高い上位いくつかに制限します。0にするとオフになります。多くのサービスはこの設定を無視します。 | 0から500 |
| **Frequency** | すでに出てきた回数が多い単語ほど、強くペナルティーを与えます。正の値にすると、同じ単語の繰り返しが減ります。 | -2から2 |
| **Presence** | 一度でも出てきた単語にペナルティーを与えます。正の値にすると、新しい話題へ向かいやすくなります。 | -2から2 |

**Frequency**と**Presence**は、繰り返しのペナルティーです。

**Reasoning Effort**は、思考できるモデルに、答える前にどれだけ考えるかを指示します。思考できるモデルとは、まず隠れた手順で問題を検討してから答えるモデルのことです。選択肢は**Off**、**Low**、**Medium**、**High**、**Extra high**、**Maximum**です。選んだ段階にモデルが対応していない場合、Marinaraはそのモデルが許すいちばん強い段階まで下げます。モデルを選ぶと、ボタンにはそのモデルに送られる段階の名前が表示されるため、**Maximum**が**Max**、**Extra high**、**High**と表示されることがあります。

- Sendスイッチがオンのとき、**Off**は、モデルが対応しているとわかっている場合に、思考をオフにするようサービスに要求します。思考をオフにできないモデルもあり、それでも推論を返すことがあります。思考を確実になくしたいときは、推論しないモデルを選んでください。
- Sendスイッチがオフのときは、推論に関する指定を何も送らず、サービス自身のデフォルトが使われます。

**Verbosity**は、返信をどれだけ長く詳しくするかを決めます。選択肢は**None**、**Low**、**Medium**、**High**です。この設定を使うのは一部のモデルだけです。

## 調整のヒント

何が効いたかわかるように、設定は1つずつ変えてください。これらは経験則で、モデルによって反応は違います。

| 症状 | 試すこと |
| --- | --- |
| 返信が固い、または繰り返しが多い | **Temperature**を少し上げて、1.1から1.3の間にします。 |
| 返信が支離滅裂、または話題からずれる | **Temperature**を下げて、0.7から0.9の間にします。 |
| 返信が途中で切れる | **Max Output Tokens**を上げます。 |
| キャラクターが同じ言い回しを繰り返す | **Frequency**か**Presence**を少し上げて、0.3から0.6の間にします。 |

あるメッセージでどのパラメーターが送られたかを確認するには、**Peek Prompt**を使います。組み立てられたプロンプトに加えて、モデル、temperature、最大トークン数、reasoning effortなどが表示されます。

<a id="the-send-switch"></a>

## Sendスイッチ

すべての数値パラメーターと、**Reasoning Effort**、**Verbosity**には、名前の隣に小さなスイッチがあります。このスイッチには文字のラベルがありません。カーソルを重ねると「This parameter is sent to the model」または「This parameter is not sent to the model.」と表示されます。

- オン: Marinaraはそのパラメーターをリクエストに含めます。
- オフ: Marinaraはそのパラメーターを省き、サービス自身のデフォルトが使われます。これは0や1といった値を設定するのとは違います。値を設定した場合は、何を使うかがサービスに伝わります。

2つの設定は同時に使えないとサービスに言われたとき(一方をオフにします)や、パラメーターが受け付けられない(オフにします)、または必須だ(オンにします)というエラーが出たときに使います。

チャットの**Advanced Parameters**で、デフォルトで送信されるのは**Max Output Tokens**と**Reasoning Effort**だけです。

## デフォルト値

表の値はエディターに表示される値で、そのまま送信されるとは限りません。プリセットがない場合、アカウントとチャットの上書きを適用する前の出力は4096トークンから始まります。有効なシーンでは8192を使うことがあります。**Effective**(実効値)の行には、最終的に決まった値が表示されます。

| パラメーター | 開始値 | デフォルトで送信 |
| --- | --- | --- |
| Temperature | 1 | いいえ |
| Max Output Tokens | Conversationは4096、Roleplayは8192。Gameによる上書きなし | はい |
| Top P | 1 | いいえ |
| Top K | 0(オフ) | いいえ |
| Frequency | 0 | いいえ |
| Presence | 0 | いいえ |
| Reasoning Effort | Maximum | はい |
| Verbosity | High | いいえ |

Sendスイッチがオフでも、値は入力欄に表示されます。スイッチをオンにするまで送信されません。

## プレフィルと思考タグ

**Assistant Prefill**(アシスタントの書き出し)は、AIの返信の先頭に追加する任意のテキストです。モデルが対応していない限り、空のままにしてください。

- 送信される最後の要素で、自分のメッセージと、その後に続くすべての指示の後に入ります。
- チャットがAIの返信で終わっていて、**Post-Processing Messages**(メッセージの後処理)が**Apply**の場合、プレフィルはその返信の末尾に追加されます。
- AI自身の言葉で終わるプロンプトを拒否するモデルもあり、**Claude (Subscription)**ではどのモデルもこれにあたります。こうしたモデルでは、Marinaraはプレフィルを代わりにAIの最後の返信の先頭に追加するため、新しい返信はプレフィルから始まりません。
- AIの返信がまだないチャットでは、プレフィルは末尾に自分のメッセージとして送られます。

**Assistant Reasoning Prefill**(アシスタントの推論の書き出し)は、表示される返信の前に、AIの推論の先頭へ追加する任意の隠しテキストです。Kimi K3のように、推論用の別個のプレフィルに対応したモデルでだけ使ってください。**Assistant Prefill**と一緒に使うこともできます。

**Thinking Tags**(思考タグ)は、モデルが隠れた推論を通常のテキストの中でどう示すかをMarinaraに伝え、その推論を**View model thoughts**の裏に隠せるようにします。囲みは1行に1つずつ書き、真ん中に隠すテキストの入る場所を空けます。think、thinking、thought、pipe、channel、括弧の組み合わせなど、よくある囲みはすでに認識します。これが必要なのは、珍しい囲み方の場合だけです。

## Custom Parameters

**Custom Parameters**(カスタムパラメーター)を使うと、Marinaraに専用の欄がない設定をそのまま追加できます。JSONオブジェクトを入力すると、Marinaraがそれをリクエストに統合します。

- アカウントのデフォルトとして保存すると、そのアカウントを使うすべてのテキスト生成で送られます。対象はConversation、Roleplay、Game、Noodle、要約、エージェント、インストールしたエージェントパッケージです。自分のコンピューターで動かしているカスタムエンドポイントも含みます。
- チャットごとのCustom Parametersはそのチャットに追加され、同じキーがあればアカウントの値より優先されます。
- キーを間違えると、サービスがリクエストを拒否することがあります。`true`、`false`、`null`は小文字で書いてください。サービスのガイドでキーを追加するよう指示されていない限り、空のままにしてください。

## Service Tier

**Service Tier**(サービス階層)は、チャットのアカウントがOpenRouterまたはNanoGPTを使っているときだけ表示されます。サービスがリクエストをどう振り分けるかを選べます。**Default**は階層を何も送りません。**Flex**は安くなる代わりに遅くなることがあります。**Priority**は速くなる代わりに費用が増えることがあります。

## コンテキストのメッセージ数の制限

**Limit Context Messages**(コンテキストのメッセージ数制限)は、チャット全体ではなく直近のN件のメッセージだけを送ります。**Context message limit**というラベルで表示される場合もあります。デフォルトはオフです。オンにすると件数は50から始まり、1から9999まで設定できます。数を小さくすると費用が下がって処理も速くなりますが、AIが覚えている内容は少なくなります。

**Advanced Memory Recall**(高度な記憶の呼び出し)がオンのRoleplayチャットでは、この上限は使われません。Advanced Memory Recallは、**Maximum allowed context before compression (tokens)**(圧縮前に許容する最大コンテキスト、トークン単位)で送る履歴の量を決めます。送る量を減らすには、**Chat Settings → Memory Recall**(チャット設定 → 記憶の呼び出し)でその設定を下げてください。[Advanced Memory Recall](../agents/memory.md#advanced-memory-recall-roleplay-and-game-mode)を参照してください。

## Exclude Past Reasoning

**Exclude Past Reasoning**(過去の推論を除外)は、デフォルトでオンです。前のターンで保存された推論を、新しいプロンプトに入れないようにします。古い推論をあえてモデルへ戻したい理由がない限り、オンのままにしてください。

この設定をオフにすると、**Past reasoning blocks**(過去の推論ブロック数)が表示されます。デフォルトの1では、利用できる最新の推論ブロックを残します。0にすると、利用できるすべてのブロックを含めます。保存済みの思考は削除されません。また、再送できるのは、現在のアカウントが対応している推論だけです。

## Image captioning

**Image captioning**(画像の説明文生成)をオンにすると、Marinaraは画像を送る代わりに、別のモデルを使って添付画像を1枚ずつ文章で説明します。画像を見られないモデルで使います。デフォルトはオフです。

1. **Advanced Parameters**で**Image captioning**をオンにします。
2. **Captioning model**(説明文生成用のモデル)ドロップダウンでモデルを選びます。
3. 必要に応じて、**Captioning Prompt**(説明文生成用のプロンプト)を編集します。これは画像ごとに一緒に送る指示です。リセットボタンを押すか欄を空にすると、デフォルトに戻ります。プロンプトはこのチャットにだけ保存され、**Save as Connection Default**(接続のデフォルトとして保存)でもコピーされません。

うまくいかなかった場合: 説明文生成用のアカウントが壊れている、削除されている、何も返さないといった理由で説明文の生成に失敗すると、返信は**Image captioning failed**エラーで止まります。Marinaraが代わりに画像を送ることはありません。説明文生成用のモデルを直すか変更するか、**Image captioning**をオフにしてください。

## Save as Connection Default

**Advanced Parameters**の下部にある**Save as Connection Default**(接続のデフォルトとして保存)は、現在の値をアカウントに書き込みます。以降、そのアカウントを使う新しいチャットは、この値から始まります。このボタンは、保存済みの通常のアカウントでだけ表示されます。ランダムなプールと内蔵モデルでは表示されません。

**Reset to Defaults**(デフォルトに戻す)は、チャットごとの変更をすべて消し、チャットを継承元の設定に戻します。継承したSendスイッチは、選択中のアカウントに従います。自分で変更したSendスイッチは、リセットするまでチャットごとの上書きとして残ります。

## デフォルトが重なる順序と優先関係

Marinaraは、各パラメーターを次の順番で決めます。後の項目が前の項目を上書きします。

1. プリセットの**Parameters**。プリセットを使わない場合は、組み込みのデフォルト値です。プリセットは出力の上限を設定できないため、出力は4096トークンから始まります。Roleplayでは、アカウントに設定したプリセットの上書きが、チャットで選んだプリセットより優先されます。
2. アカウントの**Chat defaults**(チャットのデフォルト)。
3. このチャットの**Advanced Parameters**。
4. モードのルール。有効なシーンチャットでは、出力を8192、推論を**Maximum**、詳しさを**High**にします。Gameは、アカウントとチャットに保存されたパラメーターを使い、サンプリング、推論、出力の最小サイズを強制しません。
5. 出力の上限。Gameはモデルの既知の出力上限を適用し、アカウントの**Max output tokens override**(最大出力トークンの上書き)は、すべてのモードでリクエストを制限します。利用できるコンテキストによって、予算がさらに減ることがあります。

パラメーターの隣にある**Effective**(実効値)の行には、最終的に採用された値と、それがどの層から来たかが表示されます。たとえば**Effective: 16384 · this chat**、アカウントの上限が適用される場合は**Effective: 4096 · output token cap**です。Sendスイッチがオフのときは**not sent**と表示されます。それでも、サービスがパラメーターを必須にしたり、対応していない値を調整したりすることがあります。Custom Parametersやコンテキストに収める処理によって、最終的なリクエストが変わることもあります。チャットのパラメーターをリセットすると、このチャットの上書き(項目3)だけが消えます。その後の値は、アカウントの**Chat defaults**が設定されていればそこから、なければプリセットから取られます。モードのルールと出力の上限(項目4と5)は、その後も適用されます。

<a id="parameters-for-agents"></a>

## エージェントのパラメーター

エージェントの呼び出しには、実行するアカウントに保存された**Chat defaults**(チャットのデフォルト)が使われます。エージェント自身のアカウントか、エージェントにアカウントがなければチャットのアカウントです。Sendスイッチとモデルの制限は、チャットの返信と同じように適用されます。以下の温度のルールを除き、プリセットやチャットの**Advanced Parameters**は、エージェントの呼び出しを変えません。

- **エージェントに送信される設定:** Temperature、Top P、Top K、Frequency、Presence、Reasoning Effort、Verbosity、Service Tier、Custom Parameters、独自のヘッダー、および**Settings**(設定)、**Advanced**(詳細設定)、**Parameters**の順に開いて追加したパラメーター(Top Aやシードなど)です。Sendスイッチがオフのパラメーターは送信されません。
- **エージェントに送信されない設定:** Max Output Tokens、停止シーケンス、プレフィル、Thinking Tagsなど、プロンプトの形式に関する設定です。各エージェントは、自身の**Max Output Tokens**を保ちます。
- **Temperature:** エージェントはアカウントの温度を使い、保存された値がなければ0.7を使います。Beholderは常に0を使い、Illustratorのプロンプト作成機能は専用の値を使います。チャットの返信中は、チャットと同じアカウントのエージェントは、チャットで決まった温度とSendスイッチを使います。再試行では、アカウントに保存された値を使います。
- **Reasoning Effort:** 選んだレベル、または**Off**(オフ)は、そのアカウントを使い、モデルがそれに対応しているすべてのエージェントに適用されます。**Use custom defaults for this model**(このモデルで独自のデフォルトを使う)では、ほとんどのアカウントでReasoning Effortが**Maximum**から始まります(Codexでは**Default**)。そのためエージェントは最高レベルで思考し、時間と費用が増えます。思考を減らすには、低いレベルを選ぶか、Sendスイッチをオフにしてください。レベルが保存されていない場合、JSONで答えるエージェントは思考をオフにするよう要求し、ほかのエージェントはモデルのデフォルトのままにします。
- **思考用の余裕:** アカウントにReasoning Effortが保存されている場合、Marinaraはエージェントの**Max Output Tokens**に思考用の余裕を追加します。この余裕は、アカウントの出力上限、モデルの上限、空いているコンテキストの範囲内です。カスタムエンドポイントでは、レベルを送信しない場合にもこの余裕を確保します。

インストールしたエージェントパッケージも、同じアカウントの値に従います。アカウントに保存され、送信される値は、パッケージが要求する値を置き換えます。未設定の項目は、パッケージ自身の設定を保ちます。アカウントでオフになっている**Reasoning Effort**や**Max Output Tokens**は、パッケージが要求しても送信されません。TemperatureとVerbosityは最初はオフなので、パッケージ自身の値が保たれます。

## 一部のパラメーターを無視するモデル

すべてのモデルが、すべてのパラメーターを受け付けるわけではありません。あるモデルがある設定を拒否するとMarinaraが把握している場合、その設定はリクエストから外されます。操作部は表示されたままですが、変更しても効果はありません。これは推論モデルでよく起こります。推論モデルは、temperatureのようなサンプリング設定を受け付けません。回答するモデルが毎回変わる自動振り分けのモデルでは、パラメーターの効き方がターンごとに変わることがあります。挙動を安定させるには、1つのモデルに固定してください。
