# 生成パラメーター

このガイドでは、Marinara Engineの生成パラメーターを説明します。生成パラメーターとは、AIが1回の返信をどう書くかを決める設定で、**Temperature**(温度)や**Max Output Tokens**(最大出力トークン数)などがあります。変更はチャットごとに**Advanced Parameters**(詳細パラメーター)パネルで行います。

## 生成パラメーターの働き

生成パラメーターは、サンプリングの設定です。モデルがプロンプトを文章に変えるときの書き方を左右します。AIに伝える内容そのものは変わりません。変わるのは、AIの書き方です。

例えば、返信をより意外で創造的にするパラメーターがあります。別のパラメーターは、モデルが書ける返信の長さの上限を決めます。ほとんどの場合、これらに触れる必要はありません。通常のチャットやロールプレイなら、デフォルトのままで十分です。

これらの設定を変えるのは、はっきりした問題を直したいときだけにしてください。よくある症状と、試すとよいパラメーターは、このガイドの終わり近くにまとめています。

## 設定の場所

生成パラメーターは全体の設定メニューではなく、チャットごとに保存されます。

1. 変更したいチャットを開きます。
2. **Chat Settings**(チャット設定)を開きます(アクティブなチャットの歯車アイコンです)。
3. **Advanced Parameters**セクションを探し、クリックして展開します。

「Override generation parameters for this chat. Only change these if you know what you're doing.」という補足が表示されます。以下で説明する設定は、すべて**Advanced Parameters**の中にあります。

**Advanced Parameters**は、すべてのチャットモード(Conversation、Roleplay、Game)で使えます。

## 各パラメーターの意味

数値のパラメーターには、それぞれ入力欄と専用のオン/オフスイッチが付いています。このスイッチで、そのパラメーターをモデルに送るかどうかが決まります。詳しくは次のセクションで説明します。

**Temperature**はランダムさを決めます。範囲は0から2です。値を下げると、返信は的を絞った予測しやすいものになります。値を上げると、より創造的で変化に富んだ返信になります。中間の目安としては1前後がよく使われます。

**Max Output Tokens**は、モデルが1ターンで書ける返信の長さの上限です。トークンとは文章を区切った小さな単位で、短い単語1つ、または単語の一部くらいの大きさです。返信が途中で切れ続けるときは、この値を上げます。入力欄に決まった上限はありません。

**Top P**はnucleus samplingと呼ばれる方式です。範囲は0から1です。モデルは確率の高い候補から順に足していき、合計がこの値に達するまでの範囲だけから単語を選びます。値を下げると、返信は的が絞られます。1にすると、モデルはすべての候補を検討できます。

**Top K**は、各ステップでモデルが選べる候補を確率の高い上位いくつかに制限します。範囲は0から500です。0にすると、この制限は無効になります。多くのプロバイダーはこの設定を無視します。

**Frequency**は、すでに出てきた回数が多い単語ほど強くペナルティーを与えます。範囲は-2から2です。正の値にすると、同じ単語の繰り返しが減ります。これはfrequency penaltyのことで、アプリでは**Frequency**と表示されます。

**Presence**は、回数に関係なく、一度でも出てきた単語にペナルティーを与えます。範囲は-2から2です。正の値にすると、モデルは新しい話題へ向かいやすくなります。これはpresence penaltyのことで、アプリでは**Presence**と表示されます。

**Frequency**と**Presence**は、あわせて繰り返しのペナルティーと呼ばれます。

**Reasoning Effort**は、思考できるモデルに対して、答える前にどれだけ考えるかを指示します。思考できるモデルとは、まず隠れた手順で問題を検討してから答えるモデルのことです。選択肢は**None**、**Low**、**Medium**、**High**、**Xhigh**、**Maximum**です。選んだ段階にモデルが対応していない場合、Marinaraはそのモデルが許す範囲でいちばん強い段階まで下げます。

パラメーターのスイッチがオンのとき、**None**は、努力の設定を単に省くのではなく、思考を明示的に無効にするようプロバイダーへ要求します。Marinaraは、プロバイダー固有のオフ指定に対応するとわかっているモデルにだけ、この指定を送ります。推論が必須のモデルは思考をオフにできず、それでも推論を返すことがあります。思考を確実になくしたいときは、推論しないモデルを選んでください。パラメーターのスイッチ自体をオフにするのは、これとは別です。その場合は推論に関する指定を何も送らないので、プロバイダーのデフォルトの動作がそのまま使われます。

**Verbosity**は、返信をどれだけ長く詳しくするかを決めます。選択肢は**None**、**Low**、**Medium**、**High**です。**Low**にすると返信は短くなります。**High**にすると、より長く描写の多い返信になります。この設定を使うモデルは一部だけです。

## Sendスイッチ

すべての数値パラメーターと、**Reasoning Effort**、**Verbosity**には、名前の隣に小さなオン/オフスイッチが付いています。アプリではこのスイッチに文字のラベルがないため、このガイドではSendスイッチと呼びます。カーソルを重ねると「This parameter is sent to the model」または「This parameter is not sent to the model.」と表示されます。

パラメーターのSendスイッチがオンのとき、Marinaraはそのパラメーターをプロバイダーへのリクエストに含めます。オフのときは、そのパラメーターを完全に省きます。その設定には、プロバイダー自身のデフォルトが使われます。

Sendスイッチをオフにすることは、1や0といった値を設定することとは違います。1という値も、何を使うかをプロバイダーに伝えています。スイッチをオフにすると何も伝えないので、モデルが決めます。

2つの設定は同時に使えないとプロバイダーに言われたときは、Sendスイッチを使います。どちらか一方をオフにして、もう一度試します。パラメーターが受け付けられない、または必須だというエラーが出たときにも使います。受け付けられない場合はそのパラメーターのスイッチをオフに、必須の場合はオンにします。

チャットの**Advanced Parameters**では、デフォルトでSendスイッチがオンになっているのは**Max Output Tokens**と**Reasoning Effort**だけです。ほかはオフから始まります。

## デフォルト値

新しいチャットは、内蔵の基準値から始まります。下の表は、その開始値と、デフォルトで送信されるかどうかを示しています。

| パラメーター | 開始値 | デフォルトで送信 |
|---|---|---|
| Temperature | 1 | いいえ |
| Max Output Tokens | Conversationは4096、RoleplayとGameは8192 | はい |
| Top P | 1 | いいえ |
| Top K | 0(オフ) | いいえ |
| Frequency | 0 | いいえ |
| Presence | 0 | いいえ |
| Reasoning Effort | Maximum | はい |
| Verbosity | High | いいえ |

Sendスイッチがオフでも、値は入力欄に表示されたままです。スイッチをオンにするまで送信されないだけです。

## Assistant Prefill

**Assistant Prefill**(アシスタントの書き出し)は、AIの返信のいちばん先頭、つまり送信したメッセージの直後に差し込む任意のテキストです。ほとんどの場合は空のままにします。

プレフィルや決まった開始タグに対応したモデルでだけ使ってください。例えば、入力欄のプレースホルダーに示されているような開始タグを入力すると、モデルの書き出しを固定できます。必要かどうか判断できないときは、空のままにします。

## Assistant Reasoning Prefill

**Assistant Reasoning Prefill**(アシスタントの推論の書き出し)は、AIが表示される返信を書く前に、その推論のいちばん先頭へ差し込む任意の隠しテキストです。ほとんどの場合は空のままにします。

Kimi K3のように、推論用の別個のプレフィルに対応したモデルでだけ使ってください。**Assistant Prefill**と一緒にも使えます。一方はモデルの隠れた推論の書き出しを、もう一方は表示される返信の書き出しを指定します。モデルが対応しているか判断できないときは、空のままにします。

## Thinking Tags

**Thinking Tags**(思考タグ)は、モデルが隠れた推論を通常のテキストの中でどう囲むかをMarinaraに伝える設定です。モデルによっては、推論をタグで囲んで出力します。その囲みをMarinaraが把握していれば、推論を返信にそのまま表示せず、**View thoughts**の操作の裏に隠せます。

囲みは1行に1つずつ書き、真ん中に隠すテキストの入る場所を空けます。think、thinking、thought、pipe、channel、括弧の組み合わせなど、よくある囲みはすでに認識します。この欄が必要になるのは、珍しい囲み方をするモデルだけです。

## Custom Parameters

**Custom Parameters**(カスタムパラメーター)を使うと、Marinaraが専用の欄として用意していない設定をそのまま追加できます。JSONオブジェクトを入力すると、Marinaraがそれをプロバイダーへのリクエストに統合します。

接続のデフォルトとして保存したCustom Parametersは、その接続を使うAPI経由のテキスト生成すべてに送られます。Conversation、Roleplay、Game、Noodle、要約、エージェントも対象です。自分のコンピューターで動かしているカスタムエンドポイントでも同じです。チャットごとのCustom Parametersはそのチャットにだけ追加され、同じキーがあれば接続側の値より優先されます。

これは上級者向けの欄です。キーを間違えると、プロバイダーがリクエストを拒否することがあります。オブジェクトの中では`true`、`false`、`null`を小文字で書く必要があります。プロバイダーのガイドで特定のキーを追加するよう指示されていない限り、空のままにしてください。

## OpenRouter Service Tier

**OpenRouter Service Tier**(OpenRouterのサービス階層)は、チャットの接続がOpenRouterプロバイダーを使っているときだけ表示されます。OpenRouterがリクエストをどう振り分けるかを選べます。選択肢は**Default**、**Flex**、**Priority**です。**Flex**は安くなる代わりに遅くなることがあります。**Priority**は速くなる代わりに費用が増えることがあります。**Default**は階層を何も送りません。

## コンテキストのメッセージ数の制限

**Limit Context Messages**(コンテキストのメッセージ数制限)は、モデルに送るチャット履歴の量を決めます。オンにすると、チャット全体ではなく直近のN件のメッセージだけを送ります。

オンにすると、件数は50から始まります。1から9999までの任意の数を設定できます。数を小さくすると送る履歴が減るので、費用を抑えて処理を速くできます。その代わり、AIが覚えている過去のチャットの内容も少なくなります。この設定はデフォルトでオフです。

## Exclude Past Reasoning

**Exclude Past Reasoning**(過去の推論を除外)は、デフォルトでオンです。前のターンで保存された思考や推論を、新しいプロンプトに入れないようにします。その推論がモデルに再び送られることはありません。

古い推論をあえてモデルへ戻したい理由がない限り、オンのままにしてください。

## Image Captioning

**Image Captioning**(画像の説明文生成)は、添付画像のAIでの扱い方を変えます。オンにすると、Marinaraは画像そのものを送る代わりに、選んだ接続を使って添付画像を1枚ずつ文章で説明します。

画像を見られないモデルではこれを使います。オンにしたら、**Captioning Connection**ドロップダウンで接続を選びます。テキストしか扱えないエンドポイントを指定すると、失敗することがあります。この設定はデフォルトでオフです。

## Save as Connection Default

**Advanced Parameters**の下部にある**Save as Connection Default**(接続のデフォルトとして保存)ボタンは、現在のパラメーターの値を接続そのものに書き込みます。以降、その接続を使う新しいチャットは、この値から始まります。

このボタンは、通常の保存済みの接続でだけ表示されます。ランダムな接続プールと内蔵のローカルモデルでは表示されません。

その下にある**Reset to Defaults**(デフォルトに戻す)ボタンは、チャットごとのパラメーター変更をすべて消し、このチャットをモードの基準値に戻します。

## デフォルトが重なる順序と優先関係

実際に使われるパラメーターは、3つの層から決まります。設定1つずつについて、後の層が前の層に優先します。

1. モードの基準値。チャットのモードごとに用意された、内蔵の出発点です。
2. 接続に保存されたデフォルト。**Save as Connection Default**で保存した値です。
3. このチャットの**Advanced Parameters**。ここで設定した値で、いちばん強く効きます。

つまり、**Advanced Parameters**で設定した値は、接続のデフォルトにもモードの基準値にも必ず勝ちます。

Game Modeは例外です。Game Modeは、決まった形式のターンを保つために一部のパラメーターを自分で設定します。そのためGame Modeでは、**Advanced Parameters**での変更が完全には反映されない場合があります。これは仕様です。

## 一部のパラメーターを無視するモデル

すべてのモデルが、すべてのパラメーターを受け付けるわけではありません。あるモデルがある設定を拒否するとMarinaraが把握している場合、その設定はリクエストから外されます。アプリにはスライダーや入力欄が表示されたままですが、そのモデルでは変更しても効果がありません。

これは一部の推論・思考モデルでよく起こります。こうしたモデルはtemperatureのようなサンプリング設定を受け付けません。設定が何も効いていないように見えるときは、モデルが受け付けていない可能性があります。モデルの挙動は選んだモデルによって大きく変わるので、同じ値でもモデルが違えば結果の印象は変わります。

回答するモデルが毎回変わる自動振り分けのモデルを使っていると、パラメーターの効き方がターンごとに変わることがあります。1つのモデルに固定すれば、挙動は安定します。

## 症状別の調整のヒント

ほとんどの場合、これらを変更する必要はありません。試すときは、何が効いたかわかるように、設定は1つずつ変えてください。

- 返信が固い、または繰り返しが多いとき: **Temperature**を少し上げます。例えば1から、1.1から1.3の間の値にします。
- 返信が支離滅裂、または話題からずれるとき: **Temperature**を下げます。例えば0.7から0.9の間の値にします。
- 返信が途中で切れるとき: **Max Output Tokens**を上げます。
- キャラクターが同じ言い回しを繰り返すとき: **Frequency**か**Presence**を少し上げます。例えば0.3から0.6の間の値にします。

これらは経験則であり、検証済みの推奨値ではありません。モデルによって反応が違うので、ある接続でうまくいった値が別の接続でも通用するとは限りません。

あるメッセージで実際にどのパラメーターが送られたかを確認するには、**Peek Prompt**を使います。組み立てられたプロンプトに加えて、モデル、temperature、最大トークン数、reasoning effortなども表示されます。
