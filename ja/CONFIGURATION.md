# サーバー設定リファレンス

このガイドでは、環境変数で変更できるサーバーの設定を一覧にします。環境変数とは、サーバーが`.env`という名前のテキストファイルから読み込む設定のことです。Marinaraは設定なしで動きます。設定が必要になるのは、たいていほかのデバイスから接続できるようにするとき、共有するサーバーを保護するとき、データフォルダーを移すとき、ログの詳しさを上げるとき、時間のかかる処理に長めの時間を与えるときだけです。

AIのアカウント、キャラクター、チャットのオプションは、アプリの中で設定します。AIのアカウントを追加する方法は[AIプロバイダーへの接続](connections/connecting-to-a-provider.md)を参照してください。

<a id="edit-the-env-file"></a>

## .envファイルを編集する

Marinaraは初回起動時に空の`.env`を作成します。各行は`KEY=value`の形です。`#`で始まる行はコメントです。

| インストールの種類 | `.env`の場所 |
| --- | --- |
| 通常のインストール | プロジェクトのルートフォルダー |
| 公式のDockerイメージまたはPodmanイメージ | `/app/data/.env`(データと同じボリュームの中) |

1. 同じフォルダーにある`.env.example`を開きます。すべての設定とそのデフォルト値が並んでいます。
2. 必要な行を`.env`にコピーします。
3. `=`の後ろの値を変更して、ファイルを保存します。

```text
PORT=8080
BASIC_AUTH_USER=alice
BASIC_AUTH_PASS=correct-horse-battery-staple
```

`.env`はデータであって、シェルスクリプトではありません。Marinaraは、値の中の`$`、`$(...)`、そのほかのシェル構文を実行しません。ランチャーの環境にすでに設定されている値は、`.env`の同じ設定より優先されます。

サーバーは、どの方法で起動しても`.env`を読み込みます。ランチャー(`start.bat`、`start.sh`、`start-termux.sh`)は、さらにほかのデバイスから接続できるように`HOST=0.0.0.0`を設定し、サーバーの準備ができたらブラウザーを開きます。`AUTO_OPEN_BROWSER=false`にすると、ブラウザーは開きません。`pnpm start`だけで起動した場合は、`HOST`を設定しないかぎり、サーバーはこのコンピューターからの接続だけを待ち受けます。

<a id="restart-or-hot-reload"></a>

## 再起動とホットリロード

Marinaraは実行中も`.env`を監視しています。ほとんどの設定は、再起動しなくてもほぼすぐに反映されます。変更のたびに、ログに`[env-watcher]`の行が出ます。監視を開始できない場合、サーバーは30秒ごとにファイルを確認し、そのことをログに出力します。

別のコンピューターから編集した場合や、コンテナーのバインドマウントの中を編集した場合などに、編集が反映されないときは`MARINARA_ENV_WATCH=poll`を設定してください。監視をオフにするには、`MARINARA_ENV_WATCH=0`を設定します。どちらも上級者向けの設定です。

次の設定は起動時にだけ読み込まれます。変更するには再起動が必要で、ログにも警告が出ます。

- `PORT`、`HOST`、`SSL_CERT`、`SSL_KEY`
- `DATA_DIR`、`FILE_STORAGE_DIR`、`ENCRYPTION_KEY`、`MARINARA_EAGER_STORAGE`
- `MARINARA_ENV_FILE`、`MARINARA_ENV_WATCH`、`TZ`
- `AUTO_OPEN_BROWSER`、`AUTO_CREATE_DEFAULT_CONNECTION`
- `LOG_DISABLE_REQUEST_LOGGING`、`LOG_FORMAT`
- `STORAGE_CACHE_WINDOWS_BOOT_ID`、`SHUTDOWN_WINDOWS_CONSOLE_SIGNALS`、`SHUTDOWN_FORCE_EXIT_ON_REPEAT`
- 画像、動画、スプライト、ComfyUIのタイムアウトとポーリングの設定: `IMAGE_GEN_TIMEOUT_MS`、`IMAGE_GEN_MAX_RESPONSE_BYTES`、`VIDEO_GEN_TIMEOUT_MS`、`VIDEO_GEN_MAX_RESPONSE_BYTES`、`SPRITE_GENERATION_TIMEOUT_MS`、`SPRITE_ANIMATED_FFMPEG_TIMEOUT_MS`、`COMFYUI_GEN_TIMEOUT`、4つの`*_VIDEO_POLL_INTERVAL_MS`設定

`AUTO_UPDATE_ENABLED`はサーバーの起動前にランチャーが読み込むため、変更は次回の起動から反映され、ログに警告は出ません。

アクセス制御の設定と秘密の値(`BASIC_AUTH_USER`、`BASIC_AUTH_PASS`、`IP_ALLOWLIST`、`ADMIN_SECRET`、`CSRF_TRUSTED_ORIGINS`)には、再起動は必要ありません。

<a id="access-control"></a>

## アクセス制御

アクセス制御は、実行中のサーバーに誰が接続できるかを決めます。手順と例については[リモートアクセス: ログインとIP許可リスト](REMOTE_ACCESS.md)を参照してください。

ログインは`.env`を使わずに設定することもできます。すでにサインインしているブラウザーで**Settings → Advanced → Access**(設定 → 詳細設定 → アクセス)を使うか、サーバーのログに出る1回限りのセットアップコードを使います。サーバーがこのコードを出力するのは、ログインが未設定で、ループバックの外でも待ち受けているあいだだけです。ログインは`DATA_DIR/.remote-login.json`に保存されます。Marinaraのフォルダーで`node scripts/reset-login.mjs`を実行すると、これを削除し、すべてのブラウザーをサインアウトします。`.env`のログインはこれより優先されます。ログインを変更または削除するには、現在のパスワードが必要です。ログイン用プロキシについては[ログイン用プロキシ(forward auth)](REMOTE_ACCESS.md#login-proxies-forward-auth)を参照してください。

この後で使う用語は次のとおりです。

- **ループバック**: サーバーが動いているコンピューター自身のことです。アドレスは`127.0.0.1`または`localhost`です。
- **CIDR範囲**: `192.168.1.0/24`のように、IPアドレスのまとまりを短く書く記法です。
- **Basic Auth**: リクエストごとに送るユーザー名とパスワードです。スクリプトやAPIクライアントはこれを使い、ブラウザーは`/login`ページを使います。エンコードされているだけで暗号化はされていないため、公開するサーバーではHTTPSを使ってください。

ログインを設定していない場合、サーバーは信頼できる送信元からの接続だけを受け付けます。ループバック、`IP_ALLOWLIST`に登録したアドレス、Tailscale、同じホスト上のDockerのブリッジからの通信です。それ以外は、自宅のネットワークも含めて`403 Forbidden`になります。そもそもほかのデバイスから接続できるようにするには、サーバーが外から届くアドレスで待ち受ける必要があります。`HOST=0.0.0.0`を設定してください。

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `BASIC_AUTH_USER` | 空 | ログインのユーザー名。`BASIC_AUTH_PASS`と合わせて設定します。 |
| `BASIC_AUTH_PASS` | 空 | ログインのパスワード。どちらかを空にすると、ログインはオフになります。 |
| `BASIC_AUTH_REALM` | `Marinara Engine` | Basic Authの認証要求に含まれるレルム名。 |
| `IP_ALLOWLIST` | 空 | 常に許可するIPアドレスまたはCIDR範囲(カンマ区切り)。ループバックからの直接の接続は常に許可されます。同じコンピューター上のリバースプロキシは許可されません。 |
| `IP_ALLOWLIST_ENABLED` | `true` | `false`にすると、リストを残したまま適用だけを止めます。 |
| `ALLOW_UNAUTHENTICATED_PRIVATE_NETWORK` | `false` | ログインを設定していないとき、プライベートネットワークからのパスワードなしの接続を許可します。インターネットプロバイダーが顧客どうしで共有する`100.64.0.0/10`は含まれません。信頼できる場合にだけ、`TRUSTED_PRIVATE_NETWORKS`に追加してください。 |
| `ALLOW_UNAUTHENTICATED_REMOTE` | `false` | インターネットを含む任意のアドレスから、パスワードなしで接続できるようにします。推奨しません。 |
| `TRUSTED_PRIVATE_NETWORKS` | 組み込みの範囲 | デフォルトのプライベートな範囲を置き換えます。残したいデフォルトの範囲も含めてください。 |
| `BYPASS_AUTH_TAILSCALE` | 自動 | 空の場合: このコンピューターのTailscaleアドレスへ直接接続したデバイスだけがログインを省略します。Tailscale Serve、Funnel、そのほかのプロキシを経由する場合は、引き続きログインが必要です。`true`: 以前の方式で、`100.64.0.0/10`全体をバイパスします。`false`: 通常のアクセス制御を使います。 |
| `BYPASS_AUTH_DOCKER` | 自動 | 空の場合: 検出したコンテナーのインターフェイスとそのゲートウェイだけを、ログイン、`IP_ALLOWLIST`、`TRUSTED_AUTH_PROXY`のいずれも設定されていないあいだに限って信頼します。`true`: 以前の構成や独自のネットワーク向けです。`false`: 通常のアクセス制御を使います。 |
| `REQUIRE_AUTH_FOR_DOCKER_PROXY` | `true` | プロキシが中継するDockerの通信にも、ログインまたは許可リストを求めます。プロキシ自体がすべての訪問者にログインを求める場合にだけ`false`にしてください。 |
| `REQUIRE_AUTH_FOR_LOOPBACK_PROXY` | `true` | 同じコンピューター上のプロキシやトンネルが転送したリクエストを、nginxのデフォルトの`proxy_pass`のようなHTTP/1.0のリクエストも含めて、リモートとして扱います。プロキシ自体がすべての訪問者にログインを求める場合にだけ`false`にしてください。 |
| `TRUSTED_AUTH_PROXY` | 空 | すべての訪問者にログインを求めるforward authプロキシ(tinyauth、Authelia、Authentik、oauth2-proxy)のIPアドレスまたはCIDR範囲。そのリクエストは、ログインと`IP_ALLOWLIST`を通らずに入れます。プロキシはすべてのパスを保護する必要があり、プロキシを迂回してMarinaraに到達できてはいけません。 |
| `TRUSTED_HOSTS` | 空 | Marinaraが応答する、`chat.example.com`のような公開ホスト名やプロキシのホスト名を追加します。IPアドレスの直接指定、`localhost`、`.local`、`.home.arpa`、ラベルが1つだけのLAN名は、この設定がなくても使えます。`CSRF_TRUSTED_ORIGINS`や`CORS_ORIGINS`にある名前も受け付けます。 |
| `SSL_CERT` | 空 | TLS証明書のパス。`SSL_KEY`と合わせて設定すると、HTTPSを直接提供します。 |
| `SSL_KEY` | 空 | TLSの秘密鍵のパス。 |
| `CSRF_TRUSTED_ORIGINS` | 空 | 変更の保存を許可するブラウザーのオリジンを追加します。公開ドメインや通常と異なるポート向けです。リテラルの`null`は、Android APKの場合も含めて無視されます。 |

> **Warning:** `0.0.0.0/0`のような広い公開範囲を`IP_ALLOWLIST`に指定すると、インターネット上のクライアントがログインなしで入れてしまうことがあります。信頼できるアドレスだけを記載してください。

## ストレージ

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `DATA_DIR` | `packages/server/data` | すべてのユーザーデータを置くルートフォルダー。Dockerイメージでは`/app/data`に設定されます。 |
| `FILE_STORAGE_DIR` | `DATA_DIR`の中の`storage` | ファイルの保存先フォルダーを上書きします。 |
| `ENCRYPTION_KEY` | 空 | 保存するAPIキーを暗号化する鍵。 |
| `MARINARA_MAX_RESIDENT_CHATS` | `0`(無制限)、SteamOSとTermuxでは`8` | 同時にメモリー上に保持するチャットの最大数。上限を超えると、保存のたびに、未保存の変更がないチャットのうち最後に使われてから最も時間が経ったものをメモリーから外します(ディスクから削除することはありません)。無効な文字列は、プラットフォームのデフォルトに戻ります。`2`未満の正の値は`2`になります。`0`にすると、メモリーからの解放をオフにします。 |
| `MARINARA_EAGER_STORAGE` | オフ | `1`にすると、2.4.5より前と同じように、起動時にすべてのチャットを読み込みます。大きなプロファイルではメモリーの使用量がかなり増えます。変更には再起動が必要です。 |

暗号化の鍵を生成し、`ENCRYPTION_KEY`に貼り付けます。

```bash
openssl rand -hex 32
```

Marinaraはデータをそのままの形のJSONファイルとして保存するため、バックアップをコピーしたり、中身を読んだりできます。各フォルダーの中身については[Marinaraがデータを保存する場所](data/where-data-is-stored.md)を参照してください。

<a id="logging-levels"></a>

## ログレベル

`LOG_LEVEL`は、サーバーがどこまで詳しく出力するかを決めます。選んだレベルより下の内容は表示しません。

| レベル | 表示される内容 |
| --- | --- |
| `error` | 重大な障害だけ。 |
| `warn` | エラーと警告。これがデフォルトです。 |
| `info` | 起動時のログとリクエストごとのログを追加します。 |
| `debug` | プロンプトとモデルの返答の全文を含むすべて。出力は非常に多くなります。 |

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `LOG_LEVEL` | `warn` | 上のレベル。 |
| `LOG_PRESET` | `default` | `prompt-connections`は、`debug`と同じプロンプトとモデルの詳細を表示しつつ、`GET /api/chats`のような定型のリクエストの行を隠します。 |
| `LOG_DISABLE_REQUEST_LOGGING` | `false` | `true`にすると、定型のリクエストの行を隠し、レベルはそのままにします。変更には再起動が必要です。 |
| `LOG_FORMAT` | 自動 | `pretty`は、どこでも読みやすい行で出力します。たとえば`docker logs`で**Debug mode**(デバッグモード)のプロンプトを読むときに使います。`json`は、1行に1つのJSONオブジェクトを出力します。変更には再起動が必要です。 |

ターミナルでは、サーバーは読みやすい行で出力します。Dockerのログなどそれ以外の場所では、本番用のサーバーはJSONの行を出力します。Termuxのランチャーは読みやすい行を指定します。ブラウザー側のログは別の仕組みで、`LOG_LEVEL`では制御しません。

## タイムアウト

タイムアウトとは、時間のかかる処理をサーバーが待つ上限時間のことです。**Settings → Advanced → Request timeouts**(設定 → 詳細設定 → リクエストのタイムアウト)を開くと、テキスト、エージェント、Gameの画像プロンプト、画像、動画、ComfyUI、埋め込みの上限時間を秒単位で変更できます。上限を長くすると、低速なローカルバックエンドで役立ちます。サービス側が設けている上限は変更できません。保存にはサーバーの管理権限が必要です。

これらの設定はすべてのプロファイルに適用され、有効な`.env`と同じ場所に`.env.timeouts.json`(または`<custom-env-path>.timeouts.json`)として保存されます。`.env`を書き換えずに、対応する環境変数より優先されます。テキスト、エージェント、Gameの画像プロンプト、埋め込みの変更は、新しいリクエストから適用されます。メディアの変更と、インストール済みのエージェントパッケージへの反映には再起動が必要です。環境変数に戻すには、そのファイルを削除して再起動します。

名前に別の単位が示されていないかぎり、値の単位はミリ秒です。値を検証するチャット、エージェント、Gameの画像プロンプトのタイムアウトに、不正な値、0、負の値、範囲外の値を指定すると、警告をログに出してデフォルト値を使います。動画の処理については[シーン動画](media/scene-video.md)を参照してください。

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `CHAT_GENERATION_TIMEOUT_MS` | `300000`(5分) | Conversation、Roleplay、Gameの返信で、最初のトークンまでの時間とチャンク間の間隔の上限。独自のタイムアウトを持たないバックグラウンド処理(Professor Mari、Noodleの更新、Slurpの返信)の上限時間にもなります。範囲は`10000`-`3600000`です。エージェント、メディア、埋め込み、ツールのタイムアウトは変わりません。 |
| `AGENT_CALL_TIMEOUT_MS` | `300000`(5分) | ダウンロードしたエージェントも含め、エージェントのモデル呼び出し1回で、開始前または実行中に何も届かない状態が続いてよい最長時間。データを受信するとリセットされます。範囲は`10000`-`3600000`です。Illustratorには、少なくとも組み込みの30分の無通信時間が確保されます。 |
| `GAME_DYNAMIC_IMAGE_PROMPT_TIMEOUT_MS` | `45000`(45秒) | Gameのシーンを画像プロンプトに変換するモデル呼び出しの、合計時間の上限。範囲は`10000`-`3600000`です。 |
| `EMBEDDING_TIMEOUT_MS` | `300000`(5分) | 埋め込みのリクエスト1件に許される時間。 |
| `IMAGE_GEN_TIMEOUT_MS` | `1800000`(30分) | 画像生成のリクエスト1件に許される時間。 |
| `IMAGE_GEN_MAX_RESPONSE_BYTES` | `31457280`(30 MiB) | 受け入れる画像レスポンスの最大サイズ。ローカルのComfyUIが大きなメタデータを埋め込む場合は、値を大きくしてください。 |
| `VIDEO_GEN_TIMEOUT_MS` | `1800000`(30分) | ComfyUIの動画ワークフローを含む、シーン動画のリクエスト1件に許される時間。 |
| `VIDEO_GEN_MAX_RESPONSE_BYTES` | `167772160`(160 MiB) | 受け入れるシーン動画のダウンロードの最大サイズ。 |
| `COMFYUI_GEN_TIMEOUT` | `2400`(40分、単位は秒) | キューに入った後のComfyUIの画像ワークフロー1件に許される時間。 |
| `SPRITE_GENERATION_TIMEOUT_MS` | `IMAGE_GEN_TIMEOUT_MS` | AIによるスプライト生成の処理1件に許される時間。 |
| `CUSTOM_TOOL_TIMEOUT_MS` | `60000`(1分) | カスタムツールの呼び出し1回に許される時間。 |
| `MAX_TOOL_ROUNDS` | `100` | モデルが回答しなければならなくなるまでの、ツール呼び出しの最大ラウンド数。Gameの1ターンは最大4回、エージェントは16回、ロアブックのバックフィルは64回までで、この値のほうが小さい場合はこの値が上限になります。 |

## 特権API(ADMIN_SECRET)

バックアップ、データの消去、アップデートの適用、テーマのインストールなど、破壊的な操作や危険な操作には、通常のアクセス確認に加えて追加の秘密の値が必要です。サーバーが動いているコンピューター上の**Settings → Advanced → Admin Access**(設定 → 詳細設定 → 管理者アクセス)で作成するか([Admin Access](REMOTE_ACCESS.md#admin-access-and-privileged-actions)を参照)、サーバー側に長いランダムな値を設定します。

```text
ADMIN_SECRET=replace-this-with-a-long-random-secret
```

サーバーが動いているコンピューター上では、これらの操作はたいてい秘密の値なしで実行できます。そのコンピューター上のプロキシやトンネルが転送したリクエストは、`REQUIRE_AUTH_FOR_LOOPBACK_PROXY=false`でないかぎりリモートとして扱われます。ほかのデバイスからの直接のリクエストには、秘密の値が必要です。同じ値を**Settings → Advanced → Admin Access**に貼り付けると、アプリが代わりに送信します。`.env`の`ADMIN_SECRET`は、アプリで作成した秘密の値より優先されます。管理者用の秘密の値がない場合、特権操作はサーバーのコンピューター以外のすべてのデバイスから失敗し、エラーで設定するよう案内されます。インストール済みのエージェントは、ログインでサインインしたどのデバイスからでも使えますが、インストール、アップデート、削除には秘密の値が必要です。

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `ADMIN_SECRET` | 空 | リモートのデバイスから特権操作を行うための秘密の値。 |
| `MARINARA_REQUIRE_ADMIN_SECRET_ON_LOOPBACK` | `false` | `true`にすると、サーバーのコンピューター上でも秘密の値を求めます。 |
| `UPDATES_APPLY_ENABLED` | `false` | 同じチャンネル内のアップデートを、ブラウザーの**Apply Update**(アップデートの適用)で適用できるようにします。サーバーのコンピューター上のブラウザーからリリースチャンネルを切り替える操作は、この設定がなくても行えます。Gitからのインストールのみ対象です。 |
| `UPDATES_APPLY_DISABLED` | 未設定 | チャンネルの切り替えも含め、サーバー側でのアップデートの適用をすべて拒否します。`UPDATES_APPLY_ENABLED`より優先されます。開発用とe2e用のランチャーはこれを設定します。 |
| `UPDATES_ALLOW_REMOTE_APPLY` | `false` | 有効な秘密の値があれば、リモートのデバイスからアップデートを適用できるようにします。 |
| `HAPTICS_ALLOW_REMOTE` | `false` | 有効な秘密の値があれば、リモートのデバイスから触覚デバイスの操作を実行できるようにします。 |
| `CUSTOM_TOOL_SCRIPT_ENABLED` | `false` | カスタムのスクリプトツールをオンにします。信頼できないツールやインポートしたツールを使う場合は、オフのままにしてください。 |
| `MARI_DB_ALLOW_UNSAFE_TRANSFORMS` | `false` | Professor Mariのデータベース変換スクリプトを、OSのサンドボックス(macOSのSeatbelt、LinuxのBubblewrap。ある場合は使います)がないホストでも実行できるようにします。スクリプトを自分で確認した場合以外は、オフのままにしてください。 |
| `ENABLE_CUSTOM_AGENT_REPOS` | `false` | Agent Organizerで、GitHubのエージェントリポジトリーを手動でプレビューし、同期できるようにします。[カスタムエージェントのリポジトリー](#custom-agent-repositories)を参照してください。 |
| `MARINARA_OVERWORLD_GAMES` | `false` | プレイヤーがOverworldゲーム(舞台設定キットと生成された世界)を作成し、以前の形式のゲームをOverworldゲームに変換できるようにします。オフの場合、ウィザードではVNゲームだけを作成できます。 |
| `ENABLE_EXTERNAL_EXTENSIONS` | `false` | サードパーティー製の拡張機能をインポートするための2つの許可のうち、1つ目です。[外部拡張機能(External Extensions)](#external-extensions)を参照してください。 |

## ローカルアドレスへの接続の許可

デフォルトでは、AIサービス、画像サービス、Webhookへの外向きのリクエストは、プライベートアドレスやローカルアドレスへの接続を拒否します。これにより、リクエストをだまして内部のアドレスへ向かわせるSSRF(サーバーサイドリクエストフォージェリ)を防ぎます。ループバック上のモデルサーバーはそのまま使えます。プライベートネットワーク上の別のコンピューターでセルフホストしているサービスに必要なスイッチだけをオンにしてください。

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `PROVIDER_LOCAL_URLS_ENABLED` | `false` | AIサービスのURLが、プライベートアドレスやLANのアドレスに接続できるようにします。Androidではデフォルトでオンです。 |
| `IMAGE_LOCAL_URLS_ENABLED` | `false` | 画像サービスのURLが、プライベートアドレスやLANのアドレスに接続できるようにします。プライベートアドレスの結果URLは、引き続きサービスのオリジンと完全に一致する必要があります。 |
| `TTS_LOCAL_URLS_ENABLED` | `false` | 音声合成のURLが、プライベートアドレスやLANのアドレスに接続できるようにします。 |
| `STT_LOCAL_URLS_ENABLED` | `false` | 音声認識(Speech to text)サーバーのURLが、プライベートアドレスやLANのアドレスに接続できるようにします。同じコンピューター上のサーバーは、この設定がなくても使えます。 |
| `DEEPLX_LOCAL_URLS_ENABLED` | `false` | DeepLXの翻訳URLが、プライベートアドレスやLANのアドレスに接続できるようにします。 |
| `WEBHOOK_LOCAL_URLS_ENABLED` | `false` | カスタムツールのWebhookが、プライベートアドレスやLANのアドレスに接続できるようにします。 |

<a id="marinara-notices"></a>

## Marinaraのお知らせ

お知らせは、メンテナーからの短い警告です。たとえば、セキュリティ上の問題や、お使いのバージョンに必要な手動の手順を伝えます。お知らせはバナーで表示されます。

- 起動時と、その後1時間ごとに、サーバーはMarinara Engineリポジトリーの`notices`ブランチから、小さなファイル`notices.json`を1つダウンロードします。保持するのは、お使いのバージョンを対象にしたお知らせだけです。ブラウザーは、ページの読み込み時に1回、その後1時間ごとに、自分のサーバーへお知らせを問い合わせます。
- ダウンロードに失敗した場合、サーバーはすでに持っているお知らせを保持し、起動も遅れません。
- このリクエストは、利用者本人、チャット、設定に関するデータを送信しません。`notices`ブランチを変更できるのはメンテナーだけで、変更はそれぞれレビューされます。
- お知らせは、サイズ制限のあるプレーンテキストです。リンクは、`https://github.com/Pasta-Devs/`を指す場合だけ残ります。お知らせが何かをインストール、実行、変更することはできません。
- お知らせが表示されるのは利用者本人だけです。対象は、サーバーのコンピューター上、`IP_ALLOWLIST`内のアドレスから、またはサインインした後です。それ以外の訪問者には空のリストが返ります。

お知らせをオフにするには、`MARINARA_NOTICES_ENABLED=false`を設定します。

> **Warning:** お知らせをオフにすると、Marinaraはセキュリティ修正や必要な手順を伝えられません。[GitHubのリリース](https://github.com/Pasta-Devs/Marinara-Engine/releases)を自分で確認してください。

フォークは、`MARINARA_NOTICES_URL`を自分のファイルに向けられます。

<a id="optional-multiplayer"></a>

## オプションのマルチプレイヤー

マルチプレイヤーはデフォルトでオフです。オンにすると、Conversation、Roleplay、Gameの非公開ルームを、参加人数の固定上限なしで共有できます。各ゲストは、自分の信頼できるMarinaraを使います。ゲストにAIのアカウントは不要です。ホストがAIのアカウントを用意し、共有された内容を読んで保存できます。2つの有効化条件のどちらかがオフのあいだ、Marinaraはセッション、証明書、接続相手のバックグラウンドでの確認を行いません。

1. 参加する各Marinaraの`.env`に`MULTIPLAYER_ENABLED=true`を設定し、再起動します。有効になるのは正確に`true`の値だけで、ホットリロードでは反映されません。
2. **Settings → Advanced → Multiplayer**(設定 → 詳細設定 → マルチプレイヤー)を開き、警告を読んで設定をオンにします。これだけでは待ち受けを開始せず、ルームにも参加しません。
3. ホストするには、モードの選択やセットアップの流れの中で**Create shared session**(共有セッションを作成)または**Play together**(一緒にプレイ)を使います。セットアップ、表示名、共有するペルソナの文章を確認してください。既存のチャットから共有されるのはセットアップの選択だけで、履歴、メモ、記憶は共有されません。
4. ホストでは、ルームのホスト名に対して有効で、ゲストが信頼する証明書を`SSL_CERT`と`SSL_KEY`に設定します。`https://room.example.org:7861`のように、別のHTTPSルームアドレスとポートを選びます。ホストの操作でそのポートが開きます。ファイアウォールやルーターでは、ルームのポートだけを通してください。通常のMarinara APIは公開しないでください。ポート転送、リレー、証明書確認の回避は自動では設定されません。
5. 管理者の認証情報とは異なる、12文字以上のルームパスワードを設定します。有効期限付きの招待とパスワードを、信頼する相手に別々に送ります。ゲストはホスト名のフィンガープリント、ルーム名、ペルソナの文章を確認してから、参加を申請します。ホストが**Players**(プレイヤー)で各申請を承認するまで、履歴は一切送られません。

制限と動作は次のとおりです。

- パスワードを送る前に、TLSが証明書チェーンとホスト名、そして招待に含まれる証明書のフィンガープリントを確認します。自己署名証明書を黙って受け入れることはありません。証明書を更新した場合は、新しい招待が必要です。
- 招待は30分で期限切れになります。承認済みのセッションは最長12時間です。招待を置き換えるか取り消すと、未使用の招待は使えなくなります。**Kick**(退出させる)は、承認済みのゲストを外します。
- ホストは、自動または手動の返信、**Pause**(一時停止)/**Resume**(再開)、**Stop**(停止)を管理します。デフォルトの上限は、ホストするセッションごとに100回の調整された生成ターンです。グループの1ターンやGameのセットアップでは、複数回のモデル呼び出しが発生することがあります。これはターンの上限であり、料金の見積もりではありません。
- Gameでは、**Start Game**(ゲームを開始)の前にパーティーを確認します。必要な各プレイヤーが行動を提出するかパスし、全員の準備ができるとGMが処理します。切断されたプレイヤーは、戻ってくるか、ホストがパスまたは削除するまで、必要な参加者のままです。一時停止や中断したラウンドが、有料のリクエストや確定済みの世界への効果を勝手に繰り返すことはありません。
- **Stop**、**Leave**(退出)、設定のオフ、サーバーの再起動で、ライブセッションは終了します。再起動したときに、自動でホストしたり参加したりすることはありません。
- カスタムツール、パッケージのツール、安全でないコマンドは、ルームでは使えません。ゲストが、受信したテキストからスケジューラーやローカルのコマンドを実行することはありません。Conversationのスケジュールはホストのスケジューラーを使います。
- 新しいプレイヤーとペルソナの変更は、次のラウンドから反映されます。
- ルームで扱えるのは、サイズ制限のあるテキストだけです。ファイル、メディア、拡張機能、パッケージの転送はありません。Androidのネイティブラッパーは参加できません。

> **Warning:** 信頼できる相手にだけ接続し、自分のMarinaraクライアントを使ってください。ホストが提供するクライアント、拡張機能、ファイルは絶対にインストールしないでください。ホストは共有した内容を読むことができ、共有した内容はホストのAIサービスに送られることがあります。直接接続ではネットワークアドレスが相手に伝わります。パスワード、APIキー、個人情報は共有しないでください。少しでもおかしいと感じたら、すぐに退出してください。

制限の詳細とテスト済みのプラットフォームについては[互換性と検証の記録](development/multiplayer.md)を、問題が起きたときは[トラブルシューティング](TROUBLESHOOTING.md#multiplayer-connection-or-turn-problems)を参照してください。

## エージェントと拡張機能

任意で追加できる公式のエージェントは、アプリの**Agents → Agent Organizer**(エージェント → エージェント管理)からインストールします。Marinaraは、自分のメジャーバージョンに合った[Pasta-Devs/Marinara-Agents](https://github.com/Pasta-Devs/Marinara-Agents)のカタログを選びます。

- **アップデート:** Marinaraは、インストール済みのパッケージの新しいバージョンをダウンロードする前に確認します。**Not now**(今はしない)を選ぶと現在のバージョンのままになり、Agent Organizerに**Update**(アップデート)が残ります。新規インストールの直後は、パッケージは入っていません。
- **パッケージの保存場所:** `DATA_DIR/capability-packages`です。Dockerのボリューム、独自のデータフォルダー、バックアップ、通常のアップグレードでも失われません。これはデスクトップ、Docker、Termuxに当てはまります。iOSやそのほかのブラウザーは、接続先のサーバーにあるパッケージを使います。
- **ディスク使用量:** Marinaraは各パッケージの現在のバージョンと1つ前のバージョンを残し、それより古いバージョンと、`DATA_DIR/capability-runtime-snapshots`にある一時的なコピーを削除します。パッケージのデータが削除されることはありません。
- **オフライン時:** GitHubに到達できないとき、アップデートを断ったとき、検証に失敗したときも、インストール済みのパッケージはそのバージョンのまま動き続けます。

### カスタムエージェントのインポート

外部のエージェントのファイル、フォルダー、リポジトリーはロックされています。許可するには、**Settings → Advanced → Danger Zone**(設定 → 詳細設定 → 危険な操作)で**Allow custom Agent imports**(カスタムエージェントのインポートを許可)をオンにします。環境変数は必要ありません。オンにするまで、インポートの操作はグレー表示のままです。

インポートするたびに、まずそのエージェントが要求する機能を表示します。権限は明示的に承認する必要があります。同梱された関数やツールの選択はインポートされず、生成されたCSSは無害化され、結果の動作は承認済みの機能と照らし合わせて検査されます。この設定をオフにすると、インポートしたエージェントは止まります。Marinaraの中で作ったエージェントと公式パッケージには影響しません。

<a id="custom-agent-repositories"></a>

### カスタムエージェントのリポジトリー

リポジトリーのプロンプトやツールは検証されていないため、リポジトリーはデフォルトでオフです。`ENABLE_CUSTOM_AGENT_REPOS=true`を設定し、**Allow custom Agent imports**(カスタムエージェントのインポートを許可)をオンにしてから、**Agents → Agent Organizer → Custom Sources**(エージェント → エージェント管理 → カスタムソース)を開いて、公開されているGitHubリポジトリーをプレビューします。ソースの追加にも、その後の変更の適用にも、確認が必要です。同期は手動で、Marinaraがバックグラウンドでリポジトリーをクローンしたり、確認しに行ったりすることはありません。受け付けるのは、リポジトリーのルートを指すGitHubのURLだけです。

リポジトリーでは、エージェント、Game Modeのルールセット、またはその両方を公開します。ルートには次のものを置きます。

- `agents.json`は、ダウンロードできるエージェントと同じ形式の配列です。

  ```json
  [
    {
      "id": "continuity-helper",
      "name": "Continuity Helper",
      "description": "Checks recent turns for contradictions.",
      "phase": "post_processing",
      "enabledByDefault": false,
      "category": "writer",
      "defaultPromptTemplate": "Check {{messages}} for continuity errors."
    }
  ]
  ```

- `rulesets`には、`.json`ファイル1つにつき1つのルールセットを入れます。ファイルは最大32個、1つあたり512 KBまでです。読み込むのは直下にあるファイルだけです。プレビューには、各ルールセットの名前、バージョン、扱う範囲が表示されます。ルールセットのGame Master向けの文章は、それを使うすべてのゲームでモデルに送られるため、信頼できる相手のものだけをインストールしてください。

インポートしたルールセットには、`alice/my-5e`のようにリポジトリーの所有者の名前が付くため、公式の名前と重なることはありません。すべてのバージョンが保持され、ゲームは開始したときとまったく同じバージョンでプレイされます。同じバージョンが異なる内容で届いた場合、Marinaraはインストール済みのものを残し、作者にバージョン番号を上げてもらうよう案内します。Marinaraが読み取れないファイルは、理由とともに一覧に表示され、スキップされます。

同期すると、プレビューに表示された、リポジトリーが管理するプロンプト、設定、ツールの値が、リモートの値に置き換わります。アカウントとアートワークの選択はローカルのまま残ります。上流からエージェントが消えた場合、そのエージェントは通常のローカルのエージェントとして残り、リポジトリーとの関連付けだけが外れます。ソースを削除したときも同じで、そのルールセットはインストールされたまま残ります。

カスタムエージェントは、Context Sources(コンテキストソース)で**Previous output**(前回の出力)をオンにすると、自身の直近の成功した出力を読み取ることもできます。**JSON context output**(JSON形式のコンテキスト出力)では、`{"text":"main prompt content","agent-context":"private continuation context"}`を返します。メインプロンプトに入るのは`text`だけです。**Hide output as spoilers**(出力をスポイラーとして隠す)を使うと、保存済みの出力は折りたたまれたままになります。再生成では置き換えられるターンが除外され、削除済みのメッセージや非アクティブなスワイプはコンテキストに使われません。

<a id="external-extensions"></a>

### 外部拡張機能(External Extensions)

サードパーティー製の拡張機能をインポートするには、2つの許可が必要です。環境変数は、サーバーを運用する側の許可です。Danger Zoneのスイッチは、利用者本人の同意です。

1. `.env`に`ENABLE_EXTERNAL_EXTENSIONS=true`を設定します。
2. **Settings → Advanced → Danger Zone**(設定 → 詳細設定 → 危険な操作)を開き、データ削除の操作より下までスクロールして、警告を読んでから**Allow third-party extension imports**(サードパーティー製拡張機能のインポートを許可)をオンにします。

すると、**Settings → Addons**(設定 → アドオン)の下に**External Extensions**(外部拡張機能)セクションが表示されます。どちらかの許可を閉じると、外部のレコードは無効になり、そのコードも停止します。手動で保存したもの、以前の形式のもの、プロファイルからインポートしたもの、出所が不明なものは外部として扱われます。そのため、フォルダーにファイルを置くだけでは、この2つの許可を回避できません。Professor Mariの下書きには、どちらの許可も必要ありません。下書きは無効の状態で作られ、実行するにはそのコードのハッシュそのものを承認する必要があります。

デフォルトは、サンドボックス化されたブラウザー拡張機能です。古いパッケージの一部は、Marinaraのページを必要とするため**Full page access**(ページ全体へのアクセス)と表示されます。このモードでは、承認したコードがMarinaraのページ内で動き、ページの内容、ブラウザーのストレージ、ネットワークAPI、セッションにアクセスできます。このモードを使えるのは、2つの許可が両方とも開いているExternal Extensionsだけで、別途警告への同意も必要です。無効にした後は、ページを再読み込みしてください。

アクセス制御、ストレージ、ログ、タイムアウト、特権操作、ローカルアドレスへの接続の許可は、上の表で説明しました。残りの設定はここにまとめます。

### サーバーと起動

| `MARINARA_ANDROID_SECRET_FILE` | `~/.marinara-engine/android-secret` | Termuxランチャーとローカルの`mari`コマンドが使うシークレットファイル。APKとランチャーが管理します。 |
| `AUTO_OPEN_BROWSER` | `true` | ランチャーがアプリのURLを開くかどうか。`false`にすると開きません。APKが管理するセットアップでは、これをオフにします。 |
| `AUTO_UPDATE_ENABLED` | `true` | Gitを使うランチャーが、起動前にアップデートを取得して適用するかどうか。`false`にすると、次回の起動から無効になります。この場合もランチャーは、新しいリリースがないかを読み取りだけで確認し、リマインダーを表示します。`--skip-update`を使うと、1回の起動だけ両方の確認を省略します。 |
| `MARINARA_NOTICES_ENABLED` | `true` | サーバーがメンテナーのお知らせを取得するかどうか。[Marinaraのお知らせ](#marinara-notices)を参照してください。 |
| `MARINARA_NOTICES_URL` | `notices`ブランチの`notices.json` | フォークやミラー向けに、お知らせファイルを上書きします。同じ方法で検証され、`https://github.com/Pasta-Devs/`以外を指すリンクは削除されます。 |
| `MARINARA_ENV_FILE` | プロジェクトルートの`.env` | `.env`ファイルのパスを変更します。起動前に設定してください。 |
| `MARINARA_MEDIA_GENERATION_CONCURRENCY` | `4` | サーバー全体で同時に実行する画像・動画リクエストの最大数。ローカルのComfyUIやSwarmUIでVRAMが足りなくなる場合は、1-2に下げてください。`0`にすると上限をなくします。無効な値は警告を出して無視されます。一括処理が最後の枠を使うことはありません。この上限は、**Queue media generation requests**(メディア生成リクエストを順番待ちにする)に加えて適用されます。この設定は**Settings → Generations → Overall Generations**(設定 → 生成 → 生成全般)にあってデフォルトでオンになっており、画像と動画のジョブをアカウントごとに順番待ちにします。 |
| `MARINARA_MEDIA_GENERATION_WAIT_TIMEOUT_MS` | `600000`(10分) | リクエストが空き枠を待つ時間。これを過ぎると失敗します。`0`にすると無期限に待ちます。 |
| `MARINARA_SHARED_GPU_HOSTS` | 空 | ローカルモデルとローカルの画像・動画バックエンドが1台のGPUを共有する場合(llama-swapなど)の、カンマ区切りの`host:port`一覧。一覧内のホストへのテキストとメディアのリクエストは交互に処理されるため、画像がチャットの返信の後ろでいつまでも待たされることはありません。画像やクリップが待つ時間は、最長で`MARINARA_MEDIA_GENERATION_WAIT_TIMEOUT_MS`です。埋め込みは待機させません。再起動しなくても新しいリクエストに適用されます。 |
| `MARINARA_ENV_WATCH` | `1` | `.env`の監視方法。デフォルト: 変更の通知を使い(約250 msの待ち合わせ)、予備として30秒ごとに確認します。`poll`: 常に30秒ごとの確認を使います。`0`: オフ。[再起動とホットリロード](#restart-or-hot-reload)を参照してください。 |
| `TZ` | システムのデフォルト | サーバーの処理に使う、ホストの予備のタイムゾーン(例: `Europe/Warsaw`)。ホストのタイムゾーンを使うには、未設定のままにするか空にしてください。スケジュールでは、保存したConversationの**Schedule timezone**(スケジュールのタイムゾーン)が優先されます。 |
| `CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | クロスオリジンのリクエストを許可するブラウザーのオリジン。 |
| `AUTO_CREATE_DEFAULT_CONNECTION` | `true` | 古い形式のフラグ。現在のビルドには最初から使えるキーが同梱されていないため、何も作成しません。アプリで自分のアカウントを追加してください。 |

**Schedule timezone**のデフォルトは、デバイスのタイムゾーンです。Conversationのセットアップ中、ConversationのChat Settings、キャラクターのスケジュール編集画面で変更できます。これはすべてのConversationのチャットで共有される1つのグローバルな設定で、同じサーバーのほかのクライアントにも同期されます。

<a id="lorebooks"></a>

### ロアブック

どちらもデフォルトでオフで、`.env`を変更した後の次の生成から適用されます。`LOREBOOK_STABLE_GROUP_WINNERS`を設定すると、**Settings → Advanced → Features**(設定 → 詳細設定 → 機能)の**Stable lorebook picks**(ロアブックの選択を固定)スイッチより優先されます。設定しない場合は、スイッチで決まります。[機能スイッチ](configuration/features.md)を参照してください。

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `LOREBOOK_STABLE_GROUP_WINNERS` | `false` | 候補が変わらないあいだ、包含グループで選ばれるエントリーをチャットごとに同じに保ち、生成のたびに選び直しません。プロバイダーのプロンプトキャッシュのために、プロンプトの先頭を安定させます。 |
| `LOREBOOK_COMPACT_STORED_SCANS` | `false` | 有効化されたエントリーの全文を、最新のアシスタントまたはナレーターのメッセージにだけ保存します。古いメッセージには、エントリーのID、キー、スコアが残ります。大きなロアブックを使うチャットがかなり小さくなります。新しいメッセージを削除した場合、再び最新になったメッセージのActive Contextとエージェントの再試行では、そのエントリーの現在の本文を表示します。 |

`scripts/compact-lorebook-scans.mjs`は、以前のチャットにも同じ規則を適用します。先にサーバーを停止してください。`--apply`を渡さないかぎり試行(ドライラン)だけを行い、書き込む前に両方のメッセージテーブルをバックアップします。

<a id="robustness"></a>

### 堅牢性

どれもデフォルトでオフで、従来の動作のままになります。`STORAGE_CACHE_WINDOWS_BOOT_ID`、`SHUTDOWN_WINDOWS_CONSOLE_SIGNALS`、`SHUTDOWN_FORCE_EXIT_ON_REPEAT`の変更には再起動が必要です。それ以外は、`.env`を変更すると適用されます。`PROVIDER_RETRY_TRANSIENT_ERRORS`を設定すると、**Settings → Advanced → Features**(設定 → 詳細設定 → 機能)の**Retry failed provider calls**(失敗したプロバイダー呼び出しを再試行)スイッチより優先されます。設定しない場合は、スイッチで決まります。

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `PROVIDER_RETRY_TRANSIENT_ERRORS` | `false` | 接続が拒否されたか到達できなかった場合、または502か503の場合に、最大5秒の待機を挟んで最大2回再試行します。対象は、テキストが届き始める前だけです。504や途中で切れた接続は再試行しません。アカウントにフォールバックがある場合は使われず、すぐにフォールバックを試します。失敗の確定が遅いホストでは、エラーの表示が約20秒遅れることがあります。 |
| `STORAGE_SKIP_UNCHANGED_WRITES` | `false` | チャットファイルまたは`manifest.json`の内容が、このサーバーが最後に書き込んだものと同じで、ディスク上のファイルも変わっていない場合、保存時に書き直しを省略します。`.bak`から復元した直後のファイルは必ず書き直します。 |
| `STORAGE_YIELDING_SERIALIZE` | `false` | 大きなチャットファイルの保存準備を短い区間に分けて行い、非常に長いチャットの保存でほかのリクエストが止まらないようにします。書き込まれるバイト列は同じです。 |
| `STORAGE_CACHE_WINDOWS_BOOT_ID` | `false` | Windowsのみ。ストレージロックが起動のたびに行う起動時刻の確認(約1.5～2秒のPowerShell処理)の結果を、次の再起動まで`DATA_DIR`内の`.writer-boot-id.json`に記憶します。 |
| `SHUTDOWN_WINDOWS_CONSOLE_SIGNALS` | `false` | Windowsのみ。<kbd>Ctrl</kbd>+<kbd>Break</kbd>やコンソールを閉じる操作でも、サーバーを正常に停止し、保留中の保存を書き込みます。コンソールを閉じる場合は、Windowsが許す約5秒に収まるよう、短い期限を使います。 |
| `SHUTDOWN_FORCE_EXIT_ON_REPEAT` | `false` | 最初の<kbd>Ctrl</kbd>+<kbd>C</kbd>または<kbd>Ctrl</kbd>+<kbd>Break</kbd>から1.5秒より後にもう一度押すと、サーバーをすぐに終了します。書き込まれていない保存が失われる場合があります。この設定がない場合、繰り返しは無視され、8秒の終了期限が適用されます。 |
| `SHUTDOWN_EARLY_FLUSH` | `false` | 停止シグナルを受け取ると、接続を閉じている途中でも保留中の保存を書き始めます。Advanced Settingsの再起動では使いません。 |
| `SHUTDOWN_RUNTIME_STOP_BUDGET_MS` | `0` | 停止シグナルを受け取ったとき、ストレージを閉じる前にバックグラウンドのランタイム(パッケージ、拡張機能、内蔵モデル)を待つ時間。`0`にするとすべてを待ちます。最大は`2500`で、8秒の期限内にストレージを閉じます。Advanced Settingsの再起動は、引き続きすべてを待ちます。 |

<a id="outbound-http-proxy"></a>

### 外向きのHTTPプロキシ

ネットワークによっては、HTTPプロキシを経由しないとインターネットに出られないことがあります。たとえば、TUNモードを使わないv2rayNがそうです。Marinaraは、AIサービス、画像サービス、埋め込みサーバー、エージェントのカタログへのリクエストを、そのプロキシ経由で送れます。Marinaraを起動する環境か`.env`に次の設定を書き、再起動してください。

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `NODE_USE_ENV_PROXY` | 未設定 | `1`にすると、プロキシを使います。これがない場合、MarinaraはNode.jsと同じくプロキシの設定を無視します。 |
| `HTTP_PROXY` | 空 | `http://127.0.0.1:10809`のようなプロキシのアドレス。`HTTPS_PROXY`を設定していない場合は、すべてのリクエストに使います。 |
| `HTTPS_PROXY` | 空 | `HTTP_PROXY`と異なる場合に、`https://`のアドレスに使うプロキシ。 |
| `NO_PROXY` | 空 | プロキシを通さないホストのカンマ区切りの一覧。ネットワーク上のモデルサーバーを追加してください。`localhost`、`127.0.0.1`、`::1`は常にプロキシを通りません。 |
