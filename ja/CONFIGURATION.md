# サーバー設定リファレンス

このガイドでは、環境変数を使ってMarinara Engineのサーバー側の設定を変更する方法を説明します。環境変数とは、サーバーが読み込むテキストファイルに書き込む設定のことです。このページが必要になる場面はほとんどありません。変数の一覧はページの後半にまとめてあります。

## どんなときにMarinaraを設定するのか

Marinara Engineは設定なしでそのまま動きます。このページが必要になるのは、ごく限られた作業のときだけです。その多くは、複数のデバイスからサーバーを使う場合に関係します。

設定を編集するのは、たとえば次のような場合です。

- ネットワーク上のほかのデバイスからサーバーに接続できるようにする(アクセス制御)。
- 共有するサーバーをパスワードやIP許可リストで保護する。
- データをディスクのどこに保存するかを変更する。
- 問題を切り分けるためにログの詳しさを上げる。
- 時間のかかる画像、動画、埋め込みの処理に、完了までの猶予を長く与える(タイムアウト)。
- バックアップやアップデートのような特権操作を、リモートのデバイスから実行できるようにする。

AIプロバイダーのキー、キャラクター、チャットの設定など、それ以外のほとんどはここではなくアプリの中で設定します。AIプロバイダーを追加する方法は[AIプロバイダーへの接続](connections/connecting-to-a-provider.md)を参照してください。

任意で追加できる公式エージェントも、アプリの中で管理します。**Agents → Download Agents**(エージェントのダウンロード)を開くと、インストールとアンインストールができます。Marinaraは、Engineのメジャーバージョンに合った[Pasta-Devs/Marinara-Agents](https://github.com/Pasta-Devs/Marinara-Agents)のカタログレーンを自動で選びます。

パッケージの扱いと保存場所は次のとおりです。

- **アップデート:** Marinaraはインストール済みの公式パッケージに対応するアップデートがないかを調べ、新しいバージョンをダウンロードする前に毎回確認します。**No**を選ぶと現在のバージョンのままになり、Download Agentsの手動の**Update**操作もそのまま使えます。新規インストールの直後は、パッケージを選ぶまで何も入っていません。
- **対応環境:** デスクトップ、Docker、TermuxでホストするAndroidのインストールでも動作は同じです。iOSやそのほかのブラウザークライアントは、接続先のMarinaraサーバーにインストールされたパッケージを使います。
- **保存場所:** パッケージは`DATA_DIR/capability-packages`の下にあります。Dockerのボリューム、独自のデータフォルダー、バックアップ、通常のアップデートでも失われません。
- **オフライン時の動作:** GitHubへの外向きのHTTPS通信ができないとき、アップデートを断ったとき、アップデートの検証に失敗したときも、インストール済みのパッケージはそのバージョンのまま動き続けます。

### 独自のエージェントのインポート

カスタムエージェントは**Context Sources**(コンテキストソース)で**Previous output**(前回の出力)を有効にすると、表示中のメッセージ履歴にある自身の直近の成功した出力を読み取れます。**JSON context output**(JSON形式のコンテキスト出力)では、`{"text":"main prompt content","agent-context":"private continuation context"}`を返します。メインプロンプトに挿入されるのは`text`だけです。任意の`agent-context`フィールドは、同じエージェントの次回実行用です。**Hide output as spoilers**(出力をスポイラーとして隠す)を有効にすると、保存済みの出力は開くまで折りたたまれます。再生成では置き換え対象のターンが除外され、削除済みメッセージや非アクティブなスワイプは継続用コンテキストに使われません。

外部のエージェントのファイル、フォルダー、独自リポジトリーは、デフォルトでは使えません。使えるようにするには、**Settings → Advanced → Danger Zone**(設定 → 詳細設定 → 危険な操作)を開き、**Allow custom Agent imports**(独自エージェントのインポートを許可)をオンにします。External Extensionsとは違い、この設定は利用者本人が操作するだけでよく、環境変数は必要ありません。オンにするまで、インポート関連の操作はグレー表示のままです。

インポートするときは、保存前に必ずそのエージェントが要求する権限を表示します。権限は明示的に承認する必要があり、同梱された関数やツールの選択はインポートされません。生成されたCSSは無害化され、実行結果の動作は承認済みの権限の範囲に収まっているかどうかを検査します。この設定をオフにすると、外部からインポートしたエージェントは動かなくなります。Marinaraの中で作った独自エージェントと、**Download Agents**からインストールした公式パッケージは、この設定に関係なくそのまま動きます。

### 独自のエージェントリポジトリー

独自リポジトリーは、そのプロンプトやツールの選択が検証されていない第三者のコンテンツであるため、デフォルトでは無効です。使うには、`ENABLE_CUSTOM_AGENT_REPOS=true`を設定し、Danger Zoneで**Allow custom Agent imports**をオンにしたうえで、**Agents → Download Agents → Custom Sources**を開き、公開されているGitHubリポジトリーをプレビューします。ソースを追加するときも、その後の内容の変更を適用するときも、どちらも明示的な確認が必要です。同期は手動です。Marinaraがリポジトリーをクローンすることはなく、自動的に監視することもありません。

リポジトリはエージェント、Game Modeルールセット、または両方を公開できます。少なくともどちらかが必要です。ルートの任意ファイル `agents.json` は、ダウンロード可能なエージェント定義形式の配列です。最小例：

```json
[
  {
    "id": "continuity-helper",
    "name": "Continuity Helper",
    "description": "Checks recent turns for contradictions.",
    "phase": "post_processing",
    "enabledByDefault": false,
    "category": "writer",
    "defaultPromptTemplate": "Check {{messages}} for continuity errors."
  }
]
```

ルートの `rulesets` フォルダーには、1セットずつの `.json` を最大32個置けます。各ファイルは256 KB以下です。サブフォルダーは無視されます。プレビューには名前、版、対応範囲が表示されます。GM指示はそのセットを使うゲームでモデルに送られるため、信頼できる作者だけからインストールしてください。

IDには `alice/my-5e` のように所有者が入り、公式セットや他の作者の `v20` を置き換えません。取り込んだ各版は保持され、ゲームは固定した版を使います。同じ版番号で内容が違う場合は上書きせず、版番号の更新を求めます。無効なファイルだけ理由付きで除外し、残りはインストールできます。

GitHubリポジトリのルートURLだけに対応します。プレビュー前にアーカイブサイズと定義を検証します。同期はリポジトリ管理のプロンプト、設定、ツールをプレビュー値に更新し、接続や画像はローカルに残します。上流から消えたエージェントは関連付けを解除した通常のローカルエージェントとして残ります。ソースの削除も関連付けを解除しますが、既存ゲーム用のルールセットはインストール済みのままです。

### 外部拡張機能(External Extensions)

外部拡張機能のインポートには、独立した2つの許可が必要です。まず`.env`に`ENABLE_EXTERNAL_EXTENSIONS=true`を設定します。次に**Settings → Advanced → Danger Zone**を開き、データ削除の操作より下までスクロールして、警告を読んだうえで**Allow third-party extension imports**(第三者製拡張機能のインポートを許可)をオンにします。この2つがそろって初めて、**Settings → Addons**の下に**External Extensions**セクションが表示されます。

環境変数はサーバーを運用する側の許可、Danger Zoneのトグルは利用者本人の明示的な同意にあたります。セクションの表示、インポートの経路、承認の経路、そして2つの実行時ローダーは、いずれもこの両方がそろっているかを確認します。どちらか一方を閉じると、外部拡張機能のレコードは無効になり、実行中の外部コードも停止します。手動で保存したもの、以前の形式のもの、プロファイルからインポートしたもの、出所が不明なものは、いずれも外部として扱います。そのため、拡張機能に関係するフォルダーにファイルを置くだけでは、この2つの許可を回避できません。

Professor Mariが作成した下書きは、このフラグがなくても使えます。作成時は無効の状態で、実行するにはコードのハッシュそのものを承認する必要があります。

デフォルトはサンドボックス化されたブラウザー拡張機能です。古い第三者製パッケージの一部は、MarinaraのDOMに依存するため**Full page access**(ページ全体へのアクセス)と表示されます。このモードでは、承認したコードがそのままMarinaraのページ内で動き、ページの内容、ブラウザーのストレージ、ネットワークAPI、同一オリジンの現在のセッションにアクセスできます。利用できるのは、2つの許可が両方とも開いているExternal Extensionsだけで、別途警告への同意も必要です。拡張機能を無効にした後も見た目や動作の変化が残る場合は、このモードをオフにしてページを再読み込みしてください。

## オプションのマルチプレイヤー

マルチプレイヤーは既定でオフです。2つの有効化条件のどちらかがオフなら、セッション、証明書、接続先のバックグラウンド確認は行いません。クライアントは、Settingsを明示的に更新しない限り、利用可否を1回だけ読み取ります。Conversation、Roleplay、Gameの非公開ルームに対応し、人間やAIの参加人数に固定上限はありません。各ゲストは自分の信頼できるMarinara環境を使います。スマートフォンでは所有者の信頼できるEngineサーバーを利用できます。ゲストにAI接続は不要です。ホストがAI接続を提供し、共有内容を読んで保存できます。

1. 参加する各Engineの`.env`に`MULTIPLAYER_ENABLED=true`を設定して再起動します。正確に`true`の場合だけ前提条件が有効になります。ホットリロードでは変わりません。
2. **Settings → Advanced → Multiplayer**(設定 → 詳細 → マルチプレイヤー)を開き、警告を読んで別の設定もオンにします。これだけでは待ち受けを開始せず、ルームにも参加しません。
3. ホストするには、既存のモード選択・設定フローで**Create shared session**(共有セッションを作成)または**Play together**(一緒にプレイ)を使います。設定、表示名、共有するペルソナ本文を確認します。既存チャットから使うのは設定の選択だけで、非公開の履歴、メモ、記憶はコピーしません。
4. ホストの`SSL_CERT`と`SSL_KEY`を、ルームのホスト名に有効でゲストEngineが信頼する証明書で設定します。`https://room.example.org:7861`など、専用のHTTPSルームアドレスとポートを選びます。明示的なホスト操作でそのポートが開きます。ファイアウォールやルーターではルームの待ち受けだけを公開し、通常のEngine APIは公開しないでください。ポート転送、リレーアカウント、証明書検証の回避は自動設定されません。
5. Engine・管理者の認証情報とは異なる12文字以上のルームパスワードを設定します。有効期限付き招待とパスワードを、信頼する相手に別々に共有します。ゲストは自分のクライアントでホスト名に結び付いたフィンガープリント、ルーム名、ペルソナ本文を確認し、同意して参加を申請します。ホストが**Players**(プレイヤー)で各申請を承認するまで、ルーム履歴は送られません。

TLSは証明書チェーンとホスト名を検証し、パスワード送信前に招待の証明書フィンガープリントも確認します。自己署名証明書は黙って受け入れません。証明書の更新・変更には新しい招待と再確認が必要です。招待は30分で期限切れになり、承認済みセッションは最長12時間です。招待の置換・取り消しは未使用の招待による新規参加を防ぎ、Kickは承認済み参加者の権限を取り消します。

ホストは自動・手動返信、上限付き生成回数、Pause/Resume、Stopを管理します。既定はホストセッションごとに100回の調整された生成ターンです。グループの1ターンやGame設定で複数のモデル呼び出しが発生する場合があります。これはターン上限であり、料金見積もりではありません。Conversationのスケジュールは既存のホスト側スケジューラーを使います。ゲストは別のスケジューラーや、受信テキストに含まれるローカルコマンドを実行しません。

GameではStart Gameの前に承認済みの人間のパーティーを確認します。必要な各プレイヤーは行動を提出するかパスします。GMが処理するのは全員の準備ができてからです。切断されたプレイヤーも、戻るかホストが明示的にパス・削除するまで必要な参加者のままです。新規プレイヤーとペルソナ変更は次のラウンドから反映されます。一時停止・中断した処理は、有料リクエストや確定済みの世界への効果を自動で繰り返しません。続行前に履歴を確認してください。

Stop、Leave、Settingsの無効化、サーバー再起動は該当するライブセッションを終了します。再起動時に自動でホストや参加はしません。ルームはホストサーバーが所有するため、ホストのブラウザーを閉じてもゲストへ権限は移りません。モバイルブラウザーの休止で更新が遅れることはありますが、2回目の生成は起こしません。

信頼できる相手にだけ接続してください。自分の信頼できるMarinaraクライアントを使い、ホストが提供するクライアント、拡張機能、必須とされるファイルはインストールしないでください。ホストは共有内容を読んで保持し、設定済みAIプロバイダーへ送る場合があります。直接接続ではネットワークアドレスが相手に伝わります。パスワード、APIキー、機微な個人情報は共有しないでください。不審に感じたらすぐ退出してください。

共有できるのはサイズ制限付きのテキストだけです。参加者間のファイル・メディア転送、実行可能な内容、パッケージのインポート、リモートアセットの読み込み、ネイティブ操作はありません。カスタム・パッケージのツールや危険なコマンドはルームで利用できません。Androidのネイティブラッパーは参加できません。制限とテスト済みプラットフォームの詳細は[互換性と検証の記録](development/multiplayer.md)を参照してください。これらはすべてのブラウザー・OSの脆弱性や独立した外部ダウンロードに対する安全を保証するものではありません。

## .envファイルの場所

設定は`.env`という名前のファイルに保存します。これは1行に1つの設定を`KEY=value`の形で書いたテキストファイルです。`#`で始まる行はコメントで、サーバーは無視します。

`.env`はデータであって、シェルスクリプトではありません。Marinaraは値の中の`$`、`$(...)`のようなコマンド置換、そのほかのシェル構文を実行しません。macOS/LinuxとTermuxの起動スクリプトも、サーバーの起動前に必要となるわずかな設定について、同じく評価しない方式で読み取ります。起動スクリプトの環境にすでに値がある場合は、そちらが`.env`の同じ設定より優先されます。

`.env`は初回起動時にMarinaraが空のファイルとして作成するので、手作業で用意する必要はありません。

- 通常のインストールでは、`.env`はプロジェクトのルートフォルダーにあります。
- 公式のDockerイメージやPodmanイメージでは、データと同じストレージボリュームの中の`/app/data/.env`にあります。

同じフォルダーにある`.env.example`には、すべての設定とそのデフォルト値が並んでいます。設定を変更するときは、`.env.example`から該当する行を`.env`にコピーし、`=`の後ろの値を書き換えます。

ポートを変更してパスワードを有効にする`.env`の例です。

```
PORT=8080
BASIC_AUTH_USER=alice
BASIC_AUTH_PASS=correct-horse-battery-staple
```

サーバーは起動方法にかかわらず、自分で`.env`を読み込みます。`pnpm start`を直接実行した場合も同じです。シェルの起動スクリプト(`start.bat`、`start.sh`、`start-termux.sh`)は、これに加えて2つのことを行います。ほかのデバイスからサーバーに接続できるように`HOST=0.0.0.0`を設定し、ブラウザーを自動で開きます。`pnpm start`だけで起動した場合は、`HOST`を自分で設定しないかぎり、サーバーはこのコンピューターからの接続だけを受け付けます。

## 再起動とホットリロード

Marinaraは実行中も`.env`ファイルを監視しています。変更を保存すると、ほとんどの設定は再起動なしで2秒ほどで反映されます。変更を適用するたびに、サーバーは`[env-watcher]`で始まるログを1行出力します。

一部の低レベルな設定は、サーバーの起動時に確定します。これらを変更するには完全な再起動が必要です。対象は次の設定です。

- `PORT`、`HOST`
- `SSL_CERT`、`SSL_KEY`
- `DATA_DIR`、`FILE_STORAGE_DIR`
- `ENCRYPTION_KEY`
- `MARINARA_ENV_FILE`
- `TZ`
- `AUTO_OPEN_BROWSER`、`AUTO_UPDATE_ENABLED`、`AUTO_CREATE_DEFAULT_CONNECTION`
- `LOG_DISABLE_REQUEST_LOGGING`
- `STORAGE_CACHE_WINDOWS_BOOT_ID`, `SHUTDOWN_WINDOWS_CONSOLE_SIGNALS`, `SHUTDOWN_FORCE_EXIT_ON_REPEAT`
- 画像、動画、スプライト、ComfyUIのタイムアウトとポーリングの設定(`IMAGE_GEN_TIMEOUT_MS`、`VIDEO_GEN_TIMEOUT_MS`、`VIDEO_GEN_MAX_RESPONSE_BYTES`、`SPRITE_GENERATION_TIMEOUT_MS`、`SPRITE_ANIMATED_FFMPEG_TIMEOUT_MS`、`COMFYUI_GEN_TIMEOUT`、および4つの`*_VIDEO_POLL_INTERVAL_MS`設定)

これらを変更すると、再起動が必要である旨の警告がログに出ます。`BASIC_AUTH_USER`、`BASIC_AUTH_PASS`、`IP_ALLOWLIST`、`ADMIN_SECRET`、`CSRF_TRUSTED_ORIGINS`のようなアクセス制御の設定や秘密の値には、再起動は必要ありません。

## アクセス制御

アクセス制御は、実行中のサーバーに誰が接続できるかを決めます。この節は簡易的なリファレンスです。例を使った手順の説明は[リモートアクセス: Basic AuthとIP許可リスト](REMOTE_ACCESS.md)を読んでください。

この後で使う用語を先に説明します。

- ループバックとは、サーバーが動いているのと同じコンピューターのことです。`127.0.0.1`または`localhost`で接続します。
- CIDR範囲は、`192.168.1.0/24`のようにIPアドレスのまとまりを短く書く記法です。CIDRはClassless Inter-Domain Routingの略です。
- RFC 1918の範囲は、`10.x.x.x`や`192.168.x.x`のように、家庭や職場のネットワークの内部で使われる標準的なプライベートアドレスの範囲です。

パスワードを設定していない初期状態では、サーバーは信頼できる送信元からの接続だけを受け付けます。具体的には、ループバック、`IP_ALLOWLIST`に登録したアドレス、Tailscale、同じホスト上のDockerのブリッジおよびゲートウェイからの通信です。それ以外の接続元は、通常の家庭内ネットワークも含めて、下記のいずれかを設定するまで`403 Forbidden`になります。

アクセス制御の主な設定は次のとおりです。

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `BASIC_AUTH_USER` | 空 | パスワード入力を求めるときのユーザー名。`BASIC_AUTH_PASS`と合わせて設定するとログインが必須になります。 |
| `BASIC_AUTH_PASS` | 空 | ログイン画面のパスワード。どちらかを空にするとログインは無効になります。 |
| `BASIC_AUTH_REALM` | `Marinara Engine` | ブラウザーのパスワード入力欄に表示される文字列。 |
| `IP_ALLOWLIST` | 空 | 常に許可するIPアドレスまたはCIDR範囲を、カンマ区切りで指定します。ループバックは常に許可されます。 |
| `IP_ALLOWLIST_ENABLED` | `true` | `false`にすると、リストを残したまま適用だけを止めます。 |
| `ALLOW_UNAUTHENTICATED_PRIVATE_NETWORK` | `false` | ログインを設定していないとき、プライベートネットワークからのパスワードなしの接続を再び許可します。 |
| `ALLOW_UNAUTHENTICATED_REMOTE` | `false` | インターネットを含む任意のアドレスから、パスワードなしで接続できるようにします。推奨しません。 |
| `TRUSTED_PRIVATE_NETWORKS` | 組み込みのデフォルト | デフォルトのプライベートネットワークの範囲を置き換えます。残したいデフォルトも書き足してください。 |
| `BYPASS_AUTH_TAILSCALE` | 自動 | 空の場合、直接接続されたTailscaleソケットの両端がtailnetのアドレスであるときだけ信頼します。以前と同様に`100.64.0.0/10`全体をバイパスするには`true`、通常のアクセス制御を必須にするには`false`を設定します。 |
| `BYPASS_AUTH_DOCKER` | 自動 | 空の場合、検出されたコンテナーのインターフェイスとその正確なゲートウェイだけを信頼します。以前の構成や独自ネットワークとの互換性を保つには`true`、通常のアクセス制御を必須にするには`false`を設定します。 |
| `REQUIRE_AUTH_FOR_DOCKER_PROXY` | `true` | プロキシ経由で転送されたDockerの通信にも、通常のログインと許可リストの確認を求めます。上流のクライアントがすべて信頼できる場合だけ`false`にしてください。 |
| `TRUSTED_HOSTS` | 空 | Marinaraが応答してよい公開ホスト名やリバースプロキシのホスト名を追加します。IPアドレスの直接指定、localhost、`.local`、`.home.arpa`、ラベルが1つだけのLAN名は自動的に扱われます。 |
| `SSL_CERT` | 空 | TLS証明書ファイルのパス。`SSL_KEY`と合わせて設定すると、HTTPSを直接提供します。 |
| `SSL_KEY` | 空 | TLSの秘密鍵ファイルのパス。 |
| `CSRF_TRUSTED_ORIGINS` | 空 | 変更の保存を許可するブラウザーのオリジンを追加します。公開ドメインや通常と異なるポートを使う場合に指定します。リテラルの`null`は無視されるため、Android APKには使わないでください。自己認証するログインルートは、不透明なオリジンを全体で信頼しなくても動作します。 |

Basic AuthはHTTP Basic Authenticationの略で、ユーザー名とパスワードを入力させる簡単な仕組みです。この認証情報はエンコードされているだけで暗号化はされていないため、インターネットに公開するサーバーでは必ずHTTPSと組み合わせてください。HTTPSはHTTPを暗号化した安全な方式です。直接有効にするには`SSL_CERT`と`SSL_KEY`の両方を設定するか、Marinaraの前段にリバースプロキシを置きます。

そもそもほかのデバイスから接続できるようにするには、サーバーが外部から届くインターフェイスで待ち受ける必要があります。`HOST=0.0.0.0`を設定してください。シェルの起動スクリプトはこれを自動で行いますが、`pnpm start`はループバックだけで待ち受けます。

スマートフォン、タブレット、Tailscaleのピア、ほかのコンピューターは、`TRUSTED_HOSTS`に追加しなくてもサーバーのIPアドレスで接続できます。公開ホスト名やリバースプロキシのホスト名でMarinaraを公開する場合は、その名前をそのまま追加してください。たとえば`TRUSTED_HOSTS=chat.example.com`のように書きます。互換性のため、`CSRF_TRUSTED_ORIGINS`や`CORS_ORIGINS`にすでにある名前も受け付けます。このHostの確認は、公開サイトのDNS名がMarinaraのループバックアドレスに付け替えられるのを防ぎます。

## ストレージ

ストレージの設定は、ローカルのデータをどこに置くかを決めます。データにはチャット、キャラクター、アバター、生成したメディアが含まれます。

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `DATA_DIR` | `packages/server/data` | すべてのユーザーデータを置くルートフォルダー。Dockerイメージでは`/app/data`になります。 |
| `FILE_STORAGE_DIR` | `DATA_DIR`の中の`storage`フォルダー | ファイルの保存先フォルダーを上書きします。 |
| `ENCRYPTION_KEY` | 空 | 保存するAPIキーの暗号化に使う鍵。下のコマンドで生成できます。 |
| `MARINARA_MAX_RESIDENT_CHATS` | `0`(無制限) | サーバーが同時にメモリー上に保持するチャットの数に上限を設けます。チャットは最初に開いたときに読み込まれます。上限を超えると、保存のたびに、未保存の変更がないチャットのうち最後に使われてから最も時間が経ったものをメモリーから外します(ディスクから削除することはありません)。Termuxランチャーは、スマートフォンのメモリーを守るためにこの値をデフォルトで`8`にします。`2`未満の正の値は`2`に引き上げます。`0`(または未設定)にすると、メモリーからの解放を行いません。 |
| `MARINARA_EAGER_STORAGE` | オフ | `1`にすると、起動時にすべてのチャットをメモリーへ読み込み、2.4.5より前の動作に戻します。大きなプロファイルではメモリーの使用量がかなり増えます。変更には再起動が必要です。 |

Marinaraはデータをそのままの形のJSONファイルとして保存します。そのため、バックアップのコピーも中身の確認も簡単です。

暗号化の鍵を作るには次のコマンドを実行し、結果を`ENCRYPTION_KEY`に貼り付けます。

```
openssl rand -hex 32
```

各データフォルダーの中身については[Marinaraがデータを保存する場所](data/where-data-is-stored.md)を参照してください。

## ログレベル

ログの設定は、サーバーがコンソールにどこまで詳しく出力するかを決めます。主な設定は`LOG_LEVEL`です。選んだレベルより下の内容は表示しません。

| レベル | 表示される内容 |
| --- | --- |
| `error` | 復旧できない重大な障害だけ。 |
| `warn` | エラーに加えて、致命的ではない警告。これがデフォルトです。 |
| `info` | 警告に加えて、起動時のログとリクエストごとのログ。 |
| `debug` | プロンプトとモデルの返答の全文を含むすべて。出力は非常に多くなります。 |

おすすめの使い分けは次のとおりです。

- 通常はデフォルトの`warn`のままにします。出力が少なく、本当の問題だけが見えます。
- コンソールを埋め尽くさずにリクエストや処理の節目を見たいときは`info`にします。
- モデルに送られたプロンプトそのものと返答を確認したいときは`debug`にします。出力はかなり多くなります。

通常のリクエストログを出さずに、プロンプトと接続の詳細だけを読みたいときは、レベルではなくプリセットを設定します。

```
LOG_PRESET=prompt-connections
```

このプリセットは`debug`と同じプロンプトとモデルの詳細を表示しつつ、`GET /api/chats`のような繰り返し出るリクエストの行は隠します。現在のレベルはそのままに、こうした定型のリクエストログだけを止めたい場合は、次を設定して再起動します。

```
LOG_DISABLE_REQUEST_LOGGING=true
```

ブラウザー側のログは別の仕組みで、`LOG_LEVEL`では制御しません。

## タイムアウト

タイムアウトとは、時間のかかる処理をあきらめるまでサーバーが待つ上限時間のことです。画像生成や動画生成のようなメディアの処理は時間がかかるため、デフォルトの上限は長めにしてあります。名前に別の単位が示されていないかぎり、タイムアウトの値の単位はミリ秒です。

**Settings → Advanced → Request timeouts**で、テキスト、エージェント、Gameの画像プロンプト、画像、動画、ComfyUI、埋め込みの上限時間を秒単位で設定できます。長めに設定すると低速なローカルバックエンドが処理を完了しやすくなりますが、プロバイダー自体の制限は変更できません。保存にはサーバーの管理権限が必要です。

この設定はすべてのプロファイルに適用され、有効な`.env`と同じ場所の`.env.timeouts.json`（独自のパスでは`<custom-env-path>.timeouts.json`）に保存されます。`.env`を書き換えずに、対応する環境変数より優先されます。テキスト、エージェント、Gameの画像プロンプト、埋め込みの変更は新しいリクエストから適用されます。メディアの変更とインストール済みエージェントパッケージへの反映にはサーバーを再起動してください。環境変数による設定に戻すには、タイムアウト設定ファイルを削除してサーバーを再起動します。

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `CHAT_GENERATION_TIMEOUT_MS` | `300000`(5分) | 通常のConversation、Roleplay、Gameの生成における、プロバイダーのヘッダー受信と最初のトークンまでの時間、およびチャンク間のタイムアウトです。独自のタイムアウトを持たない裏側での生成(Professor Mari、Noodleのタイムライン更新、Slurpの返信)では、最初のトークンが届くまでの時間とチャンク間の待ち時間の上限としても使われます。有効範囲は`10000`から`3600000`です。エージェント、メディア、埋め込み、ツールのタイムアウトは変わりません。 |
| `AGENT_CALL_TIMEOUT_MS` | `300000`(5分) | エージェントのLLM呼び出し1回にかかる合計時間の上限です(トラッカー、HTMLの整形、そのほかのエージェント)。応答をストリーミングしている最中にも適用されます。1回のエージェント処理に5分以上かかる遅いローカルモデルでは、値を大きくしてください。有効範囲は`10000`から`3600000`です。Illustratorには、組み込みの30分の上限が最低限確保されます。 |
| `GAME_DYNAMIC_IMAGE_PROMPT_TIMEOUT_MS` | `45000`(45秒) | 現在のGameのシーンを動的な画像プロンプトに変換するモデル呼び出しの、合計時間の上限です。遅いローカルモデルでは値を大きくしてください。有効範囲は`10000`から`3600000`です。 |
| `EMBEDDING_TIMEOUT_MS` | `300000`(5分) | 埋め込みのリクエスト1件に許される時間です。遅いローカルの埋め込みサーバーでは、値を大きくすると改善します。 |
| `IMAGE_GEN_TIMEOUT_MS` | `1800000`(30分) | 画像生成のリクエスト1件に許される時間です。 |
| `VIDEO_GEN_TIMEOUT_MS` | `1800000`(30分) | ローカルのComfyUIの動画ワークフローを含む、シーン動画の生成リクエスト1件に許される時間です。 |
| `VIDEO_GEN_MAX_RESPONSE_BYTES` | `167772160`(160 MiB) | サーバーが受け入れるシーン動画のダウンロードの最大サイズです。 |
| `COMFYUI_GEN_TIMEOUT` | `2400`(40分、単位は秒) | キューに入った後のComfyUIの画像ワークフロー1件に許される時間です。 |
| `SPRITE_GENERATION_TIMEOUT_MS` | 未設定のときは`IMAGE_GEN_TIMEOUT_MS` | AIによるスプライト生成の処理1件に許される時間です。 |
| `CUSTOM_TOOL_TIMEOUT_MS` | `60000`(1分) | 独自ツールの呼び出し1回に許される時間です。 |
| `MAX_TOOL_ROUNDS` | `100` | モデルが最終的な回答を返すまでに許される、ツール呼び出しの最大回数です。 |

画像、動画、スプライト、ComfyUIのタイムアウトは起動時に確定するため、変更には再起動が必要です。チャット生成、エージェント、Gameの動的な画像プロンプト、埋め込み、独自ツールのタイムアウトは、再起動なしで次のリクエストやエージェントの実行から反映されます。チャット、エージェント、Gameの動的な画像プロンプトのタイムアウトに、不正な値、0、負の値、範囲外の値を指定した場合は、警告をログに出したうえで、ここに記載したデフォルト値を安全に使います。大きな処理や高品質な処理が途中で失敗する場合は、メディアのタイムアウトを長くしてください。動画の処理について詳しくは[シーン動画](media/scene-video.md)を参照してください。

## 特権API(ADMIN_SECRET)

一部の操作は破壊的だったり危険度が高かったりするため、通常のアクセス確認に加えて秘密の値が必要です。バックアップ、データの消去、アップデートの適用、テーマのインストールなどが該当します。

サーバー側で`ADMIN_SECRET`に長いランダムな値を設定します。

```
ADMIN_SECRET=replace-this-with-a-long-random-secret
```

サーバーが動いているコンピューター上(ループバック)では、これらの操作はたいてい秘密の値なしで実行できます。ほかのデバイスからの場合は、アプリが秘密の値を送る必要があります。**Settings**、**Advanced**、**Admin Access**の順に開き、同じ値を貼り付けてください。以降はアプリが自動で送信します。

関連する特権の設定は次のとおりです。

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `ADMIN_SECRET` | 空 | リモートのデバイスから特権操作を行うために必要な、共有の秘密の値。 |
| `MARINARA_REQUIRE_ADMIN_SECRET_ON_LOOPBACK` | `false` | `true`にすると、ローカルのコンピューターでも秘密の値を求めます。 |
| `UPDATES_APPLY_ENABLED` | `false` | 同じチャンネル内の通常のアップデートを、ブラウザーから適用できるようにします。サーバー機のブラウザーから意図的にリリースチャンネルを切り替える操作は、このフラグがなくても行えます。Gitからのインストールのみ対象です。 |
| `UPDATES_APPLY_DISABLED` | 未設定 | サーバー側でのアップデート適用を完全に拒否します。ループバックからのチャンネル切り替えを含め、あらゆる適用を止め、`UPDATES_APPLY_ENABLED`よりも優先されます。開発用とe2e用のランチャーはこれを設定し、ブラウザーのタブが開発用のチェックアウトを書き換えられないようにしています。 |
| `UPDATES_ALLOW_REMOTE_APPLY` | `false` | 有効な秘密の値があれば、リモートのデバイスからアップデートを適用できるようにします。 |
| `HAPTICS_ALLOW_REMOTE` | `false` | 有効な秘密の値があれば、リモートのデバイスから触覚デバイスの操作を行えるようにします。 |
| `CUSTOM_TOOL_SCRIPT_ENABLED` | `false` | 独自のスクリプトツールを有効にします。信頼できないツールやインポートしたツールを使う場合は、オフのままにしてください。 |
| `ENABLE_CUSTOM_AGENT_REPOS` | `false` | Agents ManagerでGitHubのエージェントリポジトリーを手動でプレビューし、同期できるようにします。第三者製のエージェントは検証されていないため、インポートやアップデートの前に明示的な確認が必要です。 |
| `ENABLE_EXTERNAL_EXTENSIONS` | `false` | 第三者製の拡張機能をインポートするための2つの許可のうち、1つ目です。加えて、Settings → Advanced → Danger Zoneでの同意も必要です。 |
| `IMPORT_ALLOWED_ROOTS` | 空 | ピッカーのトークンなしで一括インポートが読み取れるフォルダー。 |
| `PROFILE_EXPORT_JSON_LIMIT_BYTES` | `268435456`(256 MiB) | サーバーが作成するJSONのプロファイルエクスポート1件の最大サイズ。 |

サーバーに`ADMIN_SECRET`を設定していない場合、ローカルのコンピューター以外からの特権操作はすべて失敗します。エラーメッセージには、秘密の値を設定して**Admin Access**に貼り付けるよう表示されます。

## ローカルアドレスへの接続の許可

デフォルトでは、プロバイダー、画像サービス、Webhookへの外向きのリクエストは、プライベートアドレスやローカルアドレスへの接続を拒否します。これはSSRF(サーバーサイドリクエストフォージェリ)と呼ばれる攻撃を防ぐためのもので、リクエストをだまして内部のアドレスへ向かわせる手口です。ローカルのモデルサーバーが動き続けるように、ループバックのプロバイダーアドレスは許可されたままです。

プライベートネットワーク上のほかのコンピューターで自己ホストしているサービスを使う場合に、必要なものだけをオンにしてください。

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `PROVIDER_LOCAL_URLS_ENABLED` | `false` | AIプロバイダーのURLが、プライベートアドレスやLANのアドレスに接続できるようにします。Androidではデフォルトでオンです。 |
| `IMAGE_LOCAL_URLS_ENABLED` | `false` | 画像プロバイダーのURLが、プライベートアドレスやLANのアドレスに接続できるようにします。生成された画像の結果URLがプライベートアドレスの場合も、設定したプロバイダーのオリジンと完全に一致する必要があります。 |
| `TTS_LOCAL_URLS_ENABLED` | `false` | 音声合成のURLが、プライベートアドレスやLANのアドレスに接続できるようにします。 |
| `STT_LOCAL_URLS_ENABLED` | `false` | 音声認識(Speech to Text)サーバーのURLが、プライベートアドレスやLANのアドレスに接続できるようにします。同じコンピューター上のサーバーは、この設定がなくても使えます。 |
| `DEEPLX_LOCAL_URLS_ENABLED` | `false` | DeepLXの翻訳URLが、プライベートアドレスやLANのアドレスに接続できるようにします。 |
| `WEBHOOK_LOCAL_URLS_ENABLED` | `false` | 独自ツールのWebhookが、プライベートアドレスやLANのアドレスに接続できるようにします。 |

ローカルモデルや自己ホストのモデルに接続する方法は[ローカルモデルやセルフホストモデルへの接続](connections/local-self-hosted.md)を参照してください。

## 機能スイッチ

失敗したプロバイダー呼び出しの再試行やロアブックグループの選択固定など、サーバーのオプション動作は**Settings > Advanced > Features**(設定 > 詳細 > 機能)で有効にします。すべて既定でオフです。一部は環境変数を持ち、設定されていればスイッチより優先します。各スイッチの既定値と変数は[機能スイッチ](configuration/features.md)を参照してください。

## 環境変数の完全なリファレンス

この節では、残りの設定を目的別にまとめます。アクセス制御、ストレージ、ログ、タイムアウト、特権操作、ローカルアドレスの許可については、上の表ですでに説明しました。

### サーバーと起動

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `PORT` | `7860` | サーバーが待ち受けるポート。Android、Docker、Termuxでは同じ値にそろえてください。 |
| `HOST` | `127.0.0.1`(シェルの起動スクリプトでは`0.0.0.0`) | 待ち受けるネットワークインターフェイス。LANから接続するには`0.0.0.0`にします。 |
| `MARINARA_ANDROID_SECRET` | 空 | APKが管理するTermuxインストール向けの内部ローカル認証シークレット。インストーラーに入力する値ではありません。Androidラッパーが生成して渡し、Termuxランチャーが自動的に環境変数として渡します。APKの利用者に入力を求めたり、通常のデスクトップや手動のTermuxインストールで設定したりしないでください。設定する場合は、ちょうど64文字の16進数でなければなりません。空でない無効な値を受け取ると、認証を弱める代わりに端末内からのリクエストをHTTP 503で拒否します。 |
| `MARINARA_ANDROID_SECRET_FILE` | `~/.marinara-engine/android-secret` | Termuxランチャーとローカルの`mari` CLIが使う非公開シークレットファイルのパス。APKとランチャーがこのファイルを自動で管理します。通常のAPK利用者が読み取ったりコピーしたりする必要はありません。 |
| `AUTO_OPEN_BROWSER` | `true` | シェルのランチャーがアプリのURLを自動で開くかどうかです。`false`にすると無効になります。APKが管理するセットアップでは、シェルによるブラウザーの自動起動を無効にします。保存されたアプリとブラウザーの選択や認証は、APKが別途処理します。 |
| `AUTO_UPDATE_ENABLED` | `true` | Gitを使うWindows、macOS/Linux、Termuxの起動スクリプトが、起動前にEngineのアップデートを取得して適用するかどうか。`false`にすると継続的に無効になり、次回の起動から反映されます。この場合も起動スクリプトは、新しい公開リリースがないかを読み取りだけで確認し、あればダウンロードを促すメッセージを表示します。手動での確認、アプリ内での適用、パッケージのアップデート、モデルのアップデートはそのまま使えます。1回の起動だけ両方の確認を省略するには`--skip-update`を使います。 |
| `MARINARA_ENV_FILE` | プロジェクトルートの`.env` | `.env`ファイルのパスを任意で変更します。起動前に設定してください。 |
| `TZ` | システムのデフォルト | サーバー側の処理で使う、ホストの予備のタイムゾーン。Conversationのスケジュールは、スケジュールの設定で保存したグローバルなタイムゾーンがあればそれを使います。ホストのタイムゾーンを引き継ぐには`TZ`を設定しないでください。`TZ=`のように空にした場合も、未設定として扱います。 |
| `CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | クロスオリジンのリクエストを許可するブラウザーのオリジン。 |
| `AUTO_CREATE_DEFAULT_CONNECTION` | `true` | 古い形式のフラグ。現在のビルドには最初から使えるキーが同梱されていないため、これを有効にしても何も作成しません。接続はアプリの中で自分で追加してください。 |

`AUTO_CREATE_DEFAULT_CONNECTION`は古いインストール向けに残しているだけです。新しいビルドには最初から使える接続が同梱されていないため、オンのままでも何も起こりません。チャットを始めるには、[AIプロバイダーへの接続](connections/connecting-to-a-provider.md)を参考に接続を追加してください。

Conversationのスケジュールの設定は、デフォルトではブラウザーやアプリのデバイスが報告するタイムゾーンを使います。**Schedule timezone**(スケジュールのタイムゾーン)は、Conversationのセットアップ中、ConversationのChat Settings、キャラクターのスケジュール編集画面のいずれでも変更できます。選んだIANAタイムゾーンは、すべてのConversationのチャットで共有される1つのグローバルな設定で、同じサーバーに接続しているほかのMarinaraのクライアントにも同期されます。

<a id="lorebooks"></a>

### ロアブック

どちらも既定でオフで、`.env`変更後の次の生成から適用されます。`LOREBOOK_STABLE_GROUP_WINNERS`はSettings > Advanced > Featuresの**Stable lorebook picks**を固定します。変数が設定されていればそれを優先し、未設定ならスイッチで決まります([機能スイッチ](configuration/features.md)を参照)。

| 変数 | 既定値 | 動作 |
| --- | --- | --- |
| `LOREBOOK_STABLE_GROUP_WINNERS` | `false` | 一致する候補が変わらない間、チャットごとにロアブック包含グループの採用項目を維持し、生成のたびに抽選し直しません。プロバイダーのプロンプトキャッシュのために接頭部を安定させます。 |
| `LOREBOOK_COMPACT_STORED_SCANS` | `false` | 有効化されたエントリーの全文は、チャット内の最新のアシスタントまたはナレーターメッセージだけに保存します(その行とスワイプ。ユーザーになり代わるターンでは置き換えません)。古いメッセージはエントリーID、キー、スコアを保ち、大きなロアブックを使うチャットのディスク・メモリー使用量を減らします。新しいメッセージを削除すると、再び最新になったメッセージのActive Contextとエージェント再試行には、エントリーの現在の保存済み本文を表示します。 |

`scripts/compact-lorebook-scans.mjs`は有効化前に保存したチャットにも同じ規則を適用します。先にサーバーを停止してください。`--apply`なしでは試行だけを行い、書き込み前に両方のメッセージテーブルをバックアップします。

<a id="robustness"></a>

### 堅牢性

ここでの設定はすべて既定でオフで、従来の動作を保ち、それぞれ独立して機能します。`STORAGE_CACHE_WINDOWS_BOOT_ID`、`SHUTDOWN_WINDOWS_CONSOLE_SIGNALS`、`SHUTDOWN_FORCE_EXIT_ON_REPEAT`は起動時に読むため再起動が必要です。ほかは`.env`変更後の次のリクエスト、保存、停止から適用します。`PROVIDER_RETRY_TRANSIENT_ERRORS`はSettings > Advanced > Featuresの**Retry failed provider calls**を固定し、設定されていれば変数、なければスイッチを使います([機能スイッチ](configuration/features.md)を参照)。

| 変数 | 既定値 | 動作 |
| --- | --- | --- |
| `PROVIDER_RETRY_TRANSIENT_ERRORS` | `false` | 接続拒否・到達不能、またはゲートウェイの502・503を短いランダムな待機の後、最大2回再試行します(ゲートウェイが長く要求しても最大5秒)。テキスト到着前だけが対象です。504や途中で切れた接続は再試行しません。フォールバックがあれば直ちにそちらを試します。接続タイムアウトは到達不能扱いなので、失敗確定が遅いホストではエラー表示が最大約20秒遅れる場合があります。 |
| `STORAGE_SKIP_UNCHANGED_WRITES` | `false` | チャットファイルまたは`manifest.json`の内容がこのサーバーの最後の書き込みと同じで、ディスク上のファイルも変わっていなければ再書き込みを省略します。`.bak`から復元した直後のファイルは必ず書き直します。 |
| `STORAGE_YIELDING_SERIALIZE` | `false` | 大きなチャットファイルの保存準備を短い区間に分け、非常に長いチャットの保存でほかのリクエストやストリームを止めないようにします。書き込むバイト列は同一です。 |
| `STORAGE_CACHE_WINDOWS_BOOT_ID` | `false` | Windowsのみ。ストレージロックが起動ごとに行うOS起動時刻の確認(約1.5～2秒のPowerShell処理)を、次のOS再起動まで`DATA_DIR`内の`.writer-boot-id.json`に記憶します。 |
| `SHUTDOWN_WINDOWS_CONSOLE_SIGNALS` | `false` | Windowsのみ。Ctrl+Breakやコンソールを閉じる操作でも、即時終了ではなく未保存分を書き込んで正常終了します。コンソールを閉じる場合は、Windowsが許す約5秒以内に終える短い期限を使います。 |
| `SHUTDOWN_FORCE_EXIT_ON_REPEAT` | `false` | 最初のCtrl+C(またはCtrl+Break)から1.5秒より後でもう一度押すと即時終了します。未書き込みの保存分を失う場合があります。無効時は繰り返しを無視し、通常の8秒の終了期限が適用されます。 |
| `SHUTDOWN_EARLY_FLUSH` | `false` | 停止シグナル(Ctrl+C、SIGTERM)を受け取ると、接続を閉じている途中でも保留中の保存を書き始めます。Advanced Settingsの再起動では使いません。 |
| `SHUTDOWN_RUNTIME_STOP_BUDGET_MS` | `0` | 停止シグナルでバックグラウンドランタイム(機能パッケージ、拡張機能、サイドカー)を待ってから、ストレージを強制的に閉じるまでの時間です。Advanced Settingsの再起動はすべてを待ちます。`0`も従来どおりすべてを待ちます。最大`2500`で、8秒の終了期限内にストレージを閉じます。 |
