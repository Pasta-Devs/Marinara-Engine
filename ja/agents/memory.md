# Memory Recallとチャットの要約

このガイドでは、過去のメッセージを検索する**Memory Recall**(記憶の呼び出し)、Roleplayのコンテキストを自動管理する任意の**Advanced Memory Recall (Alpha)**(高度な記憶の呼び出し・アルファ版)、**Chat Summary**(チャット要約)、Conversationの**Automatic Summarization**(自動要約)を説明します。

## 2つの記憶の仕組み

AIモデルが一度に読めるテキストの量には限りがあります。この上限をコンテキストウィンドウと呼びます。チャットが長くなると古いメッセージはこの範囲から外れ、AIはその内容を忘れます。Marinara Engine(以降はMarinaraと表記します)には、これを補う独立した仕組みが2つあります。

- **Memory Recall**は、直前の発言と関係の深い部分を過去のメッセージから探し出し、プロンプトにそっと戻します。どのチャットモードでも使えます。
- **要約**は古いメッセージを短いあらすじにまとめ、プロンプトの中で元のメッセージと置き換えます。Roleplayチャットでは**Chat Summary**、Conversationチャットでは**Automatic Summarization**を使います。

Game Modeのチャットで使えるのは**Memory Recall**だけです。どちらの要約機能もありません。

2つの仕組みは同時に使えます。役割が違うので、互いに干渉しません。

## Memory Recallの設定

**Memory Recall**は、チャットの前半から関連する断片を見つけ出し、記憶としてプロンプトに挿入します。使うのは埋め込み(embedding)で、これはメッセージの意味を数値で表した指紋のようなものです。Marinaraは新しいメッセージの指紋と保存済みの過去メッセージの指紋を比べ、もっとも近いものを追加します。

### Memory Recallをオンにする

1. チャットを開き、チャットヘッダーの**Chat Settings**(チャット設定)ボタンをクリックします。
2. **Memory Recall**セクション(脳のアイコン)を探します。
3. **Enable Memory Recall**トグルをオンにします。

**Enable Memory Recall**はチャットごとの設定です。デフォルトはモードによって変わります。

- Conversationチャットではデフォルトでオンです。
- シーンが有効になっているRoleplayチャットとGameチャットでもデフォルトでオンです。
- それ以外のチャットではデフォルトでオフです。

トグルをオフにすると、呼び出した記憶がプロンプトに追加されなくなります。すでに保存されている記憶が消えるわけではありません。

### 埋め込みソース

Memory Recallが意味の指紋を作るには、埋め込みソースが必要です。これはチャット設定ではなく接続側で指定します。接続とは、AIプロバイダーへの接続情報をまとめて保存したものです。

1. **Connections**(接続)パネルを開き、接続を編集します。
2. **Semantic Search (Embeddings)**セクションを探します。
3. モデルの欄に埋め込みモデルの名前を入力します。例えば`text-embedding-3-small`です。
4. 必要に応じて**Embedding Endpoint URL**にアドレスを入力し、接続先を上書きします。
5. 必要に応じて**Embedding Connection**ドロップダウンで、別の接続のキーとアドレスを借りることもできます。選択肢には**Same as this connection**と**Local Model (sidecar)**があります。

埋め込みに対応していないプロバイダーもあります。その場合Marinaraは、OpenAI互換の接続やGoogle、Local Modelなど、埋め込み専用の接続を選ぶよう促すメッセージを表示します。

埋め込み用の接続を1つも指定しない場合、Marinaraは内蔵のローカル埋め込みモデルを使います。このモデルは最初の1回だけダウンロードされ、以降は手元のコンピューターで動きます。APIキーも必要ありません。内蔵モデルについて詳しくは[Local Modelのセットアップ](../connections/local-model.md)を参照してください。

この**Semantic Search (Embeddings)**の設定は、ロアブックのセマンティック検索にも使われます。一度設定しておけば、両方の機能で役立ちます。

### Memories for This Chat

チャットが何を記憶しているかを見るには、**Chat Settings**を開いて**Memory Recall**セクションに移動し、**Access memories for this chat**をクリックします。Advanced Memoryがオンの場合はRoleplayの設定ドロワー内にビューアーが表示され、それ以外の場合は**Memories for This Chat**ウィンドウが開きます。

このウィンドウには、保存されている記憶チャンクの数とおおよそのトークン数が表示されます。チャンクのカードごとに、対象となる期間、メッセージ数、状態、作成日時がわかります。状態は次の3つのいずれかです。

- **Vectorized**: 指紋の作成が終わり、検索に使える状態です。
- **Waiting for vector**: 指紋をまだ作成中です。
- **Embedding unavailable**: 埋め込みソースがなく、指紋を作れませんでした。

ツールバーには、記憶のエクスポート、インポート、再構築、全消去のアイコンが並びます。チャンクごとのゴミ箱アイコンで、そのチャンクだけを忘れさせることもできます。

- チャンクのゴミ箱アイコンをクリックすると**Forget Memory**ウィンドウが開きます。**Forget**で確定します。
- 全消去のゴミ箱アイコンは**Clear Memories**ウィンドウを開きます。**Clear**で確定します。この操作で消えるのは記憶だけで、チャットのメッセージは削除されません。
- 更新アイコンを押すと、現在のチャットのメッセージからすべての記憶チャンクを作り直します。埋め込みモデルを変更したあとに使ってください。
- エクスポートすると`.marinara.json`ファイルが保存されます。インポートは`.json`と`.marinara`のファイルに対応し、既存の記憶に統合します。

### Memory Recallの挙動

次の点を覚えておいてください。

- 埋め込みソースが使える状態なら、Marinaraは**Enable Memory Recall**がオフでも記憶チャンクを裏側で保存し続けます。トグルが制御するのは、保存済みの記憶をプロンプトに挿入するかどうかだけです。保存そのものを止めるには、埋め込みソースを外すか、記憶をときどき消去してください。
- チャンクが作られるのは、新しいメッセージが5件たまってからです。それより少ないうちは次の返信を待ちます。
- 呼び出される断片は、類似度の判定を通るくらい関連が強いものだけです。関連の弱いものは除外されるので、記憶があっても何も呼び出されないことがあります。
- 呼び出した記憶に使えるプロンプトの枠はわずかなので、実際に追加されるのは関連の強い数件だけです。
- 記憶ができたあとに埋め込みモデルを変えると、古いチャンクは一致しなくなります。再構築のアイコンで作り直してください。
- チャットのメッセージを削除すると、そのチャットの記憶チャンクも削除されます。

コンテナ版のMarinaraのうち、Marinara Liteと呼ばれるビルドではMemory Recallが完全に無効です。この場合、**Memory Recall**セクション自体が表示されません。

## Advanced Memory Recall(Alpha、Roleplay)

**Chat Settings → Memory Recall**を開き、**Advanced Memory Recall (Alpha)**をオンにしてください。この任意のモードは、そのまま使う履歴の範囲、話の継続に必要な要約、関連する過去の抜粋をまとめて管理します。デスクトップでもモバイルでも、設定、準備の進捗、アーカイブビューアーはChat Settingsのドロワー内に表示されます。

### セットアップ

- チャットモデルが対応する**maximum context**(最大コンテキスト)を選んでください。上限には推定プロンプトトークン、ツール、添付、返信用の枠、安全のための余裕を含みます。推定値であり、正確なトークナイザーの計測値や利用料金の上限ではありません。
- その上限内で**constant-summary budget**(常時要約の予算)を選んでください。継続に必要な短いスナップショットを、各リクエストに1回だけ含めます。リクエスト全体が収まる間、直近のメッセージは圧縮しません。
- **helper connection**(補助接続)はシーンに関する小さな判断を行います。デフォルトはエージェント接続で、使えない場合はチャット接続を使います。最初の履歴処理にはメインモデルか補助モデルを使えます。実際に使うモデルは準備の前に表示されます。
- シーンの要約と圧縮には、既存の**Summaries**(要約)のモデルとプロンプトを使います。Advanced MemoryはメインのAgentsスイッチとは独立して動作し、ダウンロードするエージェントは不要です。
- 前後のメッセージを含める希望範囲は、デフォルトで**3–10**件です。関連性、キャラクターのアクセス範囲、空き容量によっては、0件を含む少ない件数になります。

以前からあるIndividual(個別)グループチャットでは、未設定のキャラクター知識範囲を一度確認してください。キャラクターの最初の発言は、それ以前の内容をすべて知っていた証拠にはなりません。参加範囲の制限を外してよい場合だけ、実際のキャラクターを**Narrator**(語り手)に選んでください。明示的に隠したメッセージと手動の開始マーカーは、引き続き記憶を制限します。範囲は後から修正でき、新しく追加したキャラクターには個別の確認が必要です。

準備では古い履歴を小分けに処理し、Professor Mariのハムスターの回し車の横に現在の段階を表示します。**Cancel**(キャンセル)しても完了分は残ります。ドロワーを閉じたりサーバーを再起動したりした後も、**Resume**(再開)で続きを処理できます。モデル呼び出しが失敗しても、それまで有効だった記憶は保ち、再試行できるエラーを表示します。

### チャット中の動作

リクエスト全体が上限に達すると、Advanced Memoryはまず任意の呼び出し内容を外し、次に古い完了済みシーンを継続用の要約へ移します。未完了のシーン1つが大きすぎる場合は、シーンを開いたまま古い部分を一時的に要約します。元のメッセージと、手動の開始位置・表示設定は保持します。

アーカイブからは、関連するシーンの要約や、元のメッセージ番号と発言者を付けた正確な対話を呼び出せます。ペルソナとキャラクターの両方のメッセージを数えます。過去の返信を再生成するときは、対象が現在の管理範囲より前でも、その対象より前の情報だけを使います。元のメッセージを編集、スワイプ、非表示、削除すると、影響する派生記憶を使用前に再確認します。

同じドロワー内の**Access memories for this chat**を開くと、シーンの出典とアクセスできるキャラクターの確認、要約の編集、呼び出しレコードの無効化、再インデックス、エクスポートとインポートができます。元の手動要約への修正は保持し、それに依存する継続用の要約を無効にします。レコードの無効化と元のメッセージを隠す操作は別です。キャラクターの知識範囲を決める基準は、元のメッセージの非表示設定です。

Advancedモードがオンの間はこのモードが検索を担当するため、Standard Recallのスイッチで同じ内容が重複挿入されることはありません。そのチャットの通常のRoleplay自動要約スケジュールも置き換えます。Advanced Memoryをオフにすると、通常の設定に戻ります。既存のロアブックやダウンロードするエージェントは、それぞれの適用範囲の規則に従います。Advanced Memoryで、任意のユーザー作成コンテキストや外部コンテキストを非公開にすることはできません。

### プリセット内の配置

プリセットの作成者は、既存のセクション順序、名前、ロール、グループの設定を使い、次の通常のコンテンツマーカーを配置できます。

| マーカー | 内容 |
| --- | --- |
| `chat_summary` | キャラクターの継続に必要な、長さを制限したスナップショット。 |
| `current_scene_summary` | 進行中のシーンの古い部分をまとめた一時要約。 |
| `recalled_scenes` | 関連するアーカイブ済みシーン。 |
| `recalled_messages` | 発言者と出典のラベルを付けた、過去の正確な抜粋。 |

各要素はプリセットの**XML**、**Markdown**、**None**(書式なし)に従い、目的を短く説明する文を含みます。空の要素は何も出力しません。最初に有効になっている同種のマーカーが配置を決めます。有効なマーカーのない要素は履歴の前に1回だけ入るため、古いプリセットでも使えます。抜粋はコンテキストであり、新しいメッセージやコマンドではありません。新しい3つのマーカーは、Advanced Memoryがオフの間は空です。

プロンプトのプレビューは、モデルや埋め込みの呼び出しを始めず、準備済みの記憶を使います。初期化や圧縮が必要な場合は、先にドロワーで準備してください。記憶の処理記録には、推定コンテキストサイズ、選択した境界、呼び出した出典が表示されます。最終プロンプトの検査画面では、実際にモデルへ送った内容を確認できます。

### 制限と復旧

呼び出しは選択的で、要約は細かな意味を落とすことがあります。重要な修正は元のチャット履歴か要約エディターに残してください。記録されなかった情報は復元できません。埋め込みが失敗しても、量を制限した字句検索と有効な継続用の要約は使えます。アーカイブ全体を一括挿入することはありません。必須の指示、添付、返信用の予約枠だけでも収まらない場合は、それらを減らすか上限を増やしてください。Advanced Memoryは指示を黙って削除せず、処理を停止します。

## Chat Summary(Roleplay)

**Chat Summary**は古いメッセージを短いあらすじにまとめます。このまとまりを要約エントリーと呼びます。エントリーはAIに書かせることも自分で書くこともでき、1件ずつオンとオフを切り替えられます。この機能はRoleplayチャットだけにあります。

Roleplayチャットのヘッダーにある**Chat Summary**ボタン(巻物のアイコン)をクリックすると、**Chat Summary**パネルが開きます。

### 要約エントリーの作成

1. **Summary Scope**では、直近のメッセージをまとめるなら**Last**を、範囲を指定するなら**Range**を選びます。
2. **Generate**をクリックすると、その範囲からAIがエントリーを書きます。
3. 自分で書く場合は**Write**をクリックして空のエントリーを作り、あらすじを入力します。

一覧の各エントリーには、タイトル、元になった範囲またはメッセージ数、推定トークン数が表示されます。エントリーは有効と無効を切り替えたり、展開したり、**Edit**で編集したり、**Delete**で削除したりできます。まとめて操作するボタンもあり、**Show Inactive**と**Hide Inactive**で無効なエントリーの表示を切り替え、**Activate All**と**Deactivate All**で全件をまとめて有効または無効にできます。

### Automatic Summaries

**Automatic Summaries**パネルは、チャットを続けるあいだ要約を最新の状態に保ちます。Roleplayチャットにだけ表示されます。

- **Automatic Summaries**パネル内の**Enabled**スイッチをオンにします。
- 実行する間隔は**Every**欄で指定します。単位は自分が送ったメッセージの件数です。デフォルトは5で、1から200まで指定できます。
- 要約のないまま長くなったチャットに追いつかせるには**Backfill Summary**をクリックします。チャットを少しずつまとめて処理し、実行中は進捗バーが表示されます。途中でやめるときは**Stop**をクリックします。

### Summary Promptのテンプレート

**Summary Prompt**パネルでは、AIが要約を書くときの指示を設定します。**Edit**をクリックすると現在のプロンプトを編集できます。**Templates**をクリックするとテンプレートの管理画面が開きます。ここで**New template**を使うと、名前を付けてプロンプトを保存できます。保存したテンプレートには、それぞれ**Duplicate**、**Edit**、**Delete**の操作があります。

保存したテンプレートはアプリ全体で共通の設定です。あるRoleplayチャットでテンプレートを編集したり選んだりすると、すべてのRoleplayチャットの要約プロンプトが変わります。

### Summary Connectionと出力の長さ

**Summary Connection**パネルでは、要約を書く接続を選びます。デフォルトは**Agent default (falls back to chat connection)**です。つまり、まずデフォルトのエージェント接続を使い、それが使えない場合はチャット自身の接続を使います。

**Maximum output size**欄では、生成する要約の長さの上限を決めます。デフォルトは4096トークンで、1から32768まで指定できます。

### 表示の設定

パネルの**Display**の項目は、要約済みのメッセージを画面にどう表示するかを決めます。

- **Hide summarised messages**: 要約に含まれた元のメッセージを隠します。デフォルトはオフです。
- **Recent message tail**: 隠す設定がオンでも、新しいメッセージをこの件数だけそのまま表示し続けます。デフォルトは10で、0以上の整数を指定できます。0にすると要約されたぶんをすべて隠します。値を大きくするとプロンプトが長くなり、モデルの利用料も増えます。
- **Collapse hidden messages**: 隠したメッセージをチャットの流れの中でどう見せるかを設定します。

チャットでエージェントの書き込み承認(Agentsの別の設定)を必須にしている場合、AIが生成した要約は確認してから反映されます。

## Automatic Summarization(Conversation)

Conversationチャットでは**Automatic Summarization**という別の仕組みを使います。まず1日分のメッセージをその日の要約にまとめ、1週間が終わると、その週の日ごとの要約を週の要約にまとめます。プロンプトに送るのは、週の要約、今週の日ごとの要約、そして今日のメッセージだけです。こうすることで1回のリクエストが小さく収まります。

この機能は自動で動き、Conversationチャットではオフにできません。

### 編集画面を開く

1. Conversationチャットを開き、**Chat Settings**をクリックします。
2. **Automatic Summarization**セクション(カレンダーのアイコン)を探します。
3. **Edit Summaries**をクリックすると、**Automatic Summarization**ウィンドウが開きます。

このウィンドウには週の項目が先に並び、そのあとにまだ週へまとまっていない日が続きます。項目を展開すると、**Summary**の本文と**Key Details**の一覧を編集でき、行の追加と削除もできます。

### Day Rollover HourとRecent Message Tail

**Automatic Summarization**セクションには、1日の区切り方を決める設定が2つあります。

- **Day Rollover Hour**: 要約のうえで新しい1日が始まる時刻です。デフォルトは4 AMで、12 AM(深夜0時)から11 AMまでの任意の時刻を選べます。この時刻より前に送ったメッセージは前日ぶんとして数えます。夜遅いやり取りが途中で分断されないよう、チャットをしない時間帯を選んでください。
- **Recent Message Tail**: 要約されたあとも、今日の新しいメッセージを何件そのままの文章で残すかを決めます。デフォルトは10で、0以上の整数を指定できます。値を大きくするとプロンプトが長くなり、モデルの利用料も増えます。

要約がすでにある状態で**Day Rollover Hour**を変更すると、古い要約は以前の設定で作られていることをMarinaraが警告します。

### 足りない日の要約を補う

古いチャットをインポートしたあとなど、ある日の要約が作られないことがあります。ウィンドウの**Missing Summaries**パネルにある**Backfill**ボタンを押すと、要約のない直近の日をやり直します。一度にさかのぼるのは最大14日ぶんです。

要約に使う接続やモデルを変えても、すでにある日ごとの要約や週の要約は書き直されません。

## トラブルシューティング

### Memory Recallが何も呼び出さない

- 埋め込みソースが設定されているか確かめます。**Memories for This Chat**のチャンクが**Embedding unavailable**になっている場合は、接続の**Semantic Search (Embeddings)**セクションを設定するか、内蔵のローカルモデルを使ってください。[Local Modelのセットアップ](../connections/local-model.md)を参照してください。
- チャンクが**Waiting for vector**の場合は、少し待ってください。指紋は返信のあとに作られます。
- 呼び出されるのは、直近のメッセージと関連の強い記憶だけです。関連するものがなければ何も追加されません。これは正常な動作です。
- 埋め込みモデルを最近変えた場合は、**Memories for This Chat**の再構築アイコンを使い、古いチャンクを新しいモデルに合わせてください。

### 要約が生成されない

- チャットで使えるテキスト接続があるか確かめます。Chat Summaryは**Summary Connection**を、Automatic Summarizationは自動で選ばれた要約用の接続を使います。どれも使えない場合、生成は行われません。
- チャットでエージェントの書き込み承認を必須にしている場合、AIの要約は承認するまで反映されません。
- 失敗した要約は、少し時間をおいて自動的に再試行されます。それでも進まないときは、**Backfill Summary**(Roleplay)または**Backfill**(Conversation)を実行して手動でやり直してください。
