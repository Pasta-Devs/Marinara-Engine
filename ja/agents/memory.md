# Memory Recallとチャットの要約

このガイドでは、過去のメッセージを検索する**Memory Recall**(記憶の呼び出し)、Roleplayのコンテキストを自動管理する任意の**Advanced Memory Recall (Alpha)**(高度な記憶の呼び出し・アルファ版)、**Chat Summary**(チャット要約)、Conversationの**Automatic Summarization**(自動要約)を説明します。

## 2つの記憶の仕組み

AIモデルが一度に読めるテキストの量には限りがあります。この上限をコンテキストウィンドウと呼びます。チャットが長くなると古いメッセージはこの範囲から外れ、AIはその内容を忘れます。Marinara Engine(以降はMarinaraと表記します)には、これを補う独立した仕組みが2つあります。

- **Memory Recall**は、直前の発言と関係の深い部分を過去のメッセージから探し出し、プロンプトにそっと戻します。どのチャットモードでも使えます。
- **要約**は古いメッセージを短いあらすじにまとめ、プロンプトの中で元のメッセージと置き換えます。Roleplayチャットでは**Chat Summary**、Conversationチャットでは**Automatic Summarization**を使います。

Game Modeのチャットで使えるのは**Memory Recall**だけです。どちらの要約機能もありません。

2つの仕組みは同時に使えます。役割が違うので、互いに干渉しません。

## Memory Recallの設定

**Memory Recall**は、チャットの前半から関連する断片を見つけ出し、記憶としてプロンプトに挿入します。使うのは埋め込み(embedding)で、これはメッセージの意味を数値で表した指紋のようなものです。Marinaraは新しいメッセージの指紋と保存済みの過去メッセージの指紋を比べ、もっとも近いものを追加します。

### Memory Recallをオンにする

1. チャットを開き、チャットヘッダーの**Chat Settings**(チャット設定)ボタンをクリックします。
2. **Memory Recall**セクション(脳のアイコン)を探します。
3. **Enable Memory Recall**トグルをオンにします。

**Enable Memory Recall**はチャットごとの設定です。デフォルトはモードによって変わります。

- Conversationチャットではデフォルトでオンです。
- シーンが有効になっているRoleplayチャットとGameチャットでもデフォルトでオンです。
- それ以外のチャットではデフォルトでオフです。

トグルをオフにすると、呼び出した記憶がプロンプトに追加されなくなります。すでに保存されている記憶が消えるわけではありません。

### 埋め込みソース

Memory Recallが意味の指紋を作るには、埋め込みソースが必要です。これはチャット設定ではなく接続側で指定します。接続とは、AIプロバイダーへの接続情報をまとめて保存したものです。

1. **Connections**(接続)パネルを開き、接続を編集します。
2. **Semantic Search (Embeddings)**セクションを探します。
3. モデルの欄に埋め込みモデルの名前を入力します。例えば`text-embedding-3-small`です。
4. 必要に応じて**Embedding Endpoint URL**にアドレスを入力し、接続先を上書きします。
5. 必要に応じて**Embedding Connection**ドロップダウンで、別の接続のキーとアドレスを借りることもできます。選択肢には**Same as this connection**と**Local Model (sidecar)**があります。

埋め込みに対応していないプロバイダーもあります。その場合Marinaraは、OpenAI互換の接続やGoogle、Local Modelなど、埋め込み専用の接続を選ぶよう促すメッセージを表示します。

埋め込み用の接続を1つも指定しない場合、Marinaraは内蔵のローカル埋め込みモデルを使います。このモデルは最初の1回だけダウンロードされ、以降は手元のコンピューターで動きます。APIキーも必要ありません。内蔵モデルについて詳しくは[Local Modelのセットアップ](../connections/local-model.md)を参照してください。

この**Semantic Search (Embeddings)**の設定は、ロアブックのセマンティック検索にも使われます。一度設定しておけば、両方の機能で役立ちます。

### Memories for This Chat

チャットが何を記憶しているかを見るには、**Chat Settings**を開いて**Memory Recall**セクションに移動し、**Access memories for this chat**をクリックします。Advanced Memoryがオンの場合はRoleplayの設定ドロワー内にビューアーが表示され、それ以外の場合は**Memories for This Chat**ウィンドウが開きます。

このウィンドウには、保存されている記憶チャンクの数とおおよそのトークン数が表示されます。チャンクのカードごとに、対象となる期間、メッセージ数、状態、作成日時がわかります。状態は次の3つのいずれかです。

- **Vectorized**: 指紋の作成が終わり、検索に使える状態です。
- **Waiting for vector**: 指紋をまだ作成中です。
- **Embedding unavailable**: 埋め込みソースがなく、指紋を作れませんでした。

ツールバーには、記憶のエクスポート、インポート、再構築、全消去のアイコンが並びます。チャンクごとのゴミ箱アイコンで、そのチャンクだけを忘れさせることもできます。

- チャンクのゴミ箱アイコンをクリックすると**Forget Memory**ウィンドウが開きます。**Forget**で確定します。
- 全消去のゴミ箱アイコンは**Clear Memories**ウィンドウを開きます。**Clear**で確定します。この操作で消えるのは記憶だけで、チャットのメッセージは削除されません。
- 更新アイコンを押すと、現在のチャットのメッセージからすべての記憶チャンクを作り直します。埋め込みモデルを変更したあとに使ってください。
- エクスポートすると`.marinara.json`ファイルが保存されます。インポートは`.json`と`.marinara`のファイルに対応し、既存の記憶に統合します。

### Memory Recallの挙動

次の点を覚えておいてください。

- 埋め込みソースが使える状態なら、Marinaraは**Enable Memory Recall**がオフでも記憶チャンクを裏側で保存し続けます。トグルが制御するのは、保存済みの記憶をプロンプトに挿入するかどうかだけです。保存そのものを止めるには、埋め込みソースを外すか、記憶をときどき消去してください。
- チャンクが作られるのは、新しいメッセージが5件たまってからです。それより少ないうちは次の返信を待ちます。
- 呼び出される断片は、類似度の判定を通るくらい関連が強いものだけです。関連の弱いものは除外されるので、記憶があっても何も呼び出されないことがあります。
- 呼び出した記憶に使えるプロンプトの枠はわずかなので、実際に追加されるのは関連の強い数件だけです。
- 記憶ができたあとに埋め込みモデルを変えると、古いチャンクは一致しなくなります。再構築のアイコンで作り直してください。
- チャットのメッセージを削除すると、そのチャットの記憶チャンクも削除されます。

コンテナ版のMarinaraのうち、Marinara Liteと呼ばれるビルドではMemory Recallが完全に無効です。この場合、**Memory Recall**セクション自体が表示されません。

## Advanced Memory Recall(Alpha、Roleplay)

**Chat Settings → Memory Recall**を開き、**Advanced Memory Recall (Alpha)**をオンにしてください。Roleplayのセットアップウィザードでも、Agentsの下にある**Automatic context and memory handling (alpha)**(コンテキストと記憶の自動管理)をオンにできます。この任意のモードは、そのまま使う履歴の範囲、話の継続に必要な要約、関連する過去の抜粋をまとめて管理します。デスクトップでもモバイルでも、ウィザードとChat Settingsのドロワーの両方で設定と準備の進捗を確認できます。アーカイブビューアーはChat Settingsのドロワー内に表示されます。

### セットアップ

- **Maximum allowed context before compression (tokens)**をチャットモデルの対応コンテキスト内に設定します。この上限は、指示、メッセージ、呼び出した記憶、ツール、添付ファイルを含む送信プロンプトの推定量に適用され、チャットと記憶処理の両方で使われます。応答トークンと安全余裕は別枠です。モデルの総コンテキスト制限も有効で、正確なトークナイザー計数や課金上限ではありません。
- その上限内で**Summary and recall budget (tokens)**（要約と呼び出しの予算）を選びます。有効な常時要約は、この値の最大**70%**を目標とします。優先順位は常時要約、選択したシーン要約、メッセージ抜粋の順です。必要なら記憶全体で最大**2,000トークン追加**できますが、全コンテキストの上限内に収めます。10kなら常時要約は最大7kが目標、記憶全体は最大12kです。他の設定値でも同じ割合を使います。現在のメッセージは常時要約の枠に含まれず、その統合も発動させません。
- **Helper model**（補助モデル）は独立したシーン判定、シーン要約、連続性の圧縮を担当します。既定ではエージェント接続、次にチャット接続を使います。初回の履歴シーン検出はメインか補助モデルを選べますが、要約は必ず補助モデルを使います。使用モデルは準備前に表示されます。
- 記憶の要約呼び出しはすべて**Chat Summary → Maximum output size**を使い、推論の余裕として少なくとも**8,196出力トークン**を確保します。シーン要約と常時要約の統合が対象で、より大きい設定は保持します。補助接続の通常の応答上限で置き換えません。入力と出力予約はモデルの総コンテキストに収まる必要があります。
- シーン要約リクエストには、要約指示、そのシーンのアクセス可能なメッセージ、該当範囲の修正、JSON出力形式だけを送ります。大きすぎるシーンは保存可能なバッチに分けて処理し、後で統合します。シーンの振り返りには**2–3段落**を要求します。既定プロンプトは過去の出来事をまとめ、現在の状況や未解決の緊張を列挙する節を作りません。**Summaries**で選んだ独自プロンプトは引き続き有効です。Advanced MemoryはAgentsの主スイッチと独立して動き、ダウンロードするエージェントを必要としません。
- **Maximum recalled scenes**（想起するシーンの最大数）は既定で**3**です。上限であり、関連性が弱い結果は除外します。**0**なら任意のシーン想起を無効にし、必要な連続性は保ちます。各シーンは要約と、その後に最大1つの抜粋を提供します。
- **Moving context**（移動コンテキスト）は抜粋ごとのメッセージ数で、既定は**3–10**です。両方を**0**にすると要約のみ、最小値だけを**0**にすると抜粋は任意になります。関連性、キャラクターのアクセス権、空き容量によって0件になることもあります。

以前からあるIndividual(個別)グループチャットでは、未設定のキャラクター知識範囲を一度確認してください。キャラクターの最初の発言は、それ以前の内容をすべて知っていた証拠にはなりません。参加範囲の制限を外してよい場合だけ、実際のキャラクターを**Narrator**(語り手)に選んでください。キャラクターごとの非表示設定と確認済みの知識範囲は、引き続きメモリーを制限します。全体の**Hide from AI**(AIから隠す)は、手動でも自動要約による設定でも、そのターンをライブの会話記録から取り除くだけです。Advanced Memoryは引き続き走査し、シーンの参加者を判断し、要約して、許可された呼び出し用にインデックスへ登録します。開始マーカーはライブの会話記録を切り詰めます。範囲は後から修正でき、新しく追加したキャラクターには個別の確認が必要です。

既存のチャットでは、まず**Prepare existing history**(既存履歴を準備)をクリックしてください。復元した履歴によって手動修正が対象とするシーンの境界が変わった場合、参照用の文章を残すにはそのメモリーを無効にするか、削除してから履歴を再度準備します。同じ修正を保存し直しても、その文章を別のソース範囲へ安全に割り当てることはできません。準備は古い履歴をバッチで処理し、Professor Mariの回し車の横に現在の段階を表示します。**Cancel**(キャンセル)は完了済みの作業を保持します。**Resume**(再開)はドロワーを閉じた後、サーバー再起動後、アプリ更新後も続きから処理します。モデル呼び出しが失敗しても有効なメモリーは保持され、再試行できるエラーを表示します。失敗した呼び出しから復旧するためにリセットしないでください。再開は完了済みの要約と変更のないシーン検出を再利用します。最後の進行中シーンは開いたままで、閉じた時点で要約します。そのライブメッセージがコンテキスト上限を超えた場合は、制限されたソース抜粋を使います。

**Access memories for this chat**で要約を開き、下部の**Delete summary**（要約を削除）を選び、対象要約と閲覧者を確認します。旧形式の**Continuity**（連続性）や**Ongoing scene**（進行中シーン）にも使えます。通常の準備では削除したシーン要約を再生成しません。元のメッセージは残ります。新しい常時要約は**Chat Summaries**に入り、既存の編集、有効化、結合、削除機能を使います。保管庫の旧形式の連続性は追加の常時要約として使いません。

### チャット中の動作

シーン検出はRoleplayの主応答を保存した後に実行します。**Standalone scene check interval (messages)**は既定で**5**です。検査には番号付きの直近メッセージ、その1つ前の補足メッセージ、シーン指示、出力形式を渡します。各シーンを終える正確なメッセージ番号を返し、継続中なら終了点を返しません。ペルソナとキャラクターの両方のメッセージを数えます。間隔はトラッカーの予定と独立していますが、対象の可視性と予算が合えば生成後のトラッカー呼び出しを共有し、合わなければ補助モデルを単独で呼びます。新しい範囲は前回の終了直後から今回指定された終了メッセージまでです。終了を検出した場合だけ、その完了シーンの要約と索引をバックグラウンドで準備します。最新の応答がシーンを終える場合も対象です。不明確な転換ではシーンを開いたままにします。左上の**Agents**メニューに**Advanced Recall**として進行、エラー、復旧操作が表示され、通常エージェントが無効でも動作します。進行状況の定期確認は記憶タスク実行中だけで、準備済みアーカイブを待機中にポーリングしません。

通常の想起は準備済みメモリを読みます。任意の検索埋め込みには短い時間制限があり、利用できなければ文字列検索に切り替えます。文字列検索では最新のユーザーメッセージにある特徴的な語を重く評価するため、短い手掛かりでも長いシーン要約を見つけられます。抜粋の出力がオフでも、インデックス化した元のメッセージからシーンを検索できます。どちらもモデル呼び出しは増えません。想起はRoleplayのメイン生成専用です。エージェント呼び出し、手動再実行、補助的な試行生成は想起を起動せず、その要約や抜粋も受け取りません。メインプロンプトの確認は読み取り専用です。

再生成したスワイプは、その応答に保存された最初の互換性のあるメモリを再利用します。連続性、シーン要約、正確な抜粋を含みます。変更のないスワイプは再検索や要約モデル呼び出しを行いません。続きを生成するときも開始時のメモリを保ちます。保存済みメモリのない古い応答は次の生成で保存し、その後は再利用します。リセットは不要です。バックグラウンドの常時要約追加や統合は互換性のある保存内容を保持します。ユーザーが履歴、アクセス、要約、メモリを変えると、互換性を失った保存内容は無効になります。現在のコンテキスト上限は常に適用されます。

主生成は保存済み記憶をすぐに読みます。バックグラウンド補助モデルが動いていても、連続性の生成を開始したり完了を待ったりしません。送信プロンプトが上限に達すると、**すべてのキャラクター**の現在の履歴を最新シーンの先頭までリセットし、再び上限に達するまで増やします。自動切り替えは既存の**Mark as new start**で**All**が選択された状態で表示されます。Allを外すと取り消せます。個別の開始フラグも引き続き適用されます。未完のシーンや大きすぎる常時要約が収まらない場合は、明示されたソース抜粋と最新メッセージを使います。この一時調整では別の永続フラグを作りません。保存済み要約と元メッセージは上書きしません。

主応答の後、Advanced Memoryはまだ対象になっていないアーカイブ済みメッセージだけを既存の範囲付き**Chat Summaries**へ追加し、可能なら完成済みシーン要約を再利用します。無効なものも含め、既存項目の範囲は処理済みと扱います。利用可能な有効常時要約が**Summary and recall budget**の70%を超えると、**Updating continuity**が応答後にその要約文だけを統合し、選んだ補助モデルと**Chat Summary → Maximum output size**を使います。現在のメッセージと重なる常時要約は予算にも圧縮にも含めず、旧形式の範囲なし項目は対象に残ります。しきい値を超えた応答も保存済みの利用可能な要約で通常どおり生成し、圧縮を待ちません。追加2,000トークンは記憶全体用で、常時要約の枠ではありません。キャラクターごとにマクロ展開が異なる共有テンプレートは維持し、それだけで目標を超えるなら手動編集が必要です。他のグループには比例した長さの目安を渡し、固定の拒否上限にはしません。短く完全な置換要約をメッセージ範囲のタイトルで保存すると同時に、置換元を無効にします。失敗または未完の出力は保存せず、既存項目は使えるままです。**Resume processing**は未完の処理を再試行します。シーン要約は記憶保管庫に残ります。

アーカイブは関連するシーン要約と正確な対話を元のメッセージ番号・話者とともに呼び出します。1つの**Recalled Scenes**内で各要約の直後に利用可能な抜粋を置き、抜粋全体に1つの範囲見出しを使います。抜粋なしのシーンも同じ節に残ります。現在の履歴範囲と最後のユーザーメッセージ番号も示します。シーンは全ソースが送信する現在履歴の外にある場合だけ呼び出し、抜粋も現在のメッセージを除きます。範囲付き**Chat Summaries**も対象メッセージが1つでも現在の文脈に残れば省きます。保存・有効状態は維持し、全範囲が窓の外に出ると再び対象になります。対象常時要約は任意の呼び出しに優先し、キャラクター条件を保ちます。すべての選択シーン要約の領域を確保してから抜粋を追加します。キャラクターのアクセスと歴史上のソース制限も適用されます。呼び出すメッセージと新要約入力ではイラスト添付と画像説明を省き、読み取れるテキスト添付は残します。ペルソナとキャラクター双方を数えます。過去応答の再生成は管理中の窓より前でも対象応答以前のソースだけを使います。編集、スワイプ、非表示、削除によって影響する派生記憶は利用前に再検査します。

同じドロワー内の**Access memories for this chat**を開くと、時系列で番号を付けたシーン要約の検索、物語内の時期とアクセスできるキャラクターの確認、**Summary text**(要約本文)の編集ができます。**Inspect source messages**(元のメッセージを確認)では元のメッセージ全文を読めます。内部で使う原文抜粋は、独立したシーン要約エントリーとしては表示しません。呼び出したコンテキストには、出典に基づく物語内の時期を付けます。不明な日付は不明のままにします。呼び出しレコードの無効化、再インデックス、エクスポートとインポートもできます。**Delete all memories**(すべての記憶を削除)を確認すると、元のチャットと設定を残したまま記憶の準備をやり直せます。元の手動要約への修正は保持し、それに依存する継続用の要約を無効にします。シーンを呼び出しから除外するには、そのメモリーレコードを無効にしてください。キャラクターごとのソース非表示は、引き続きアクセスできる相手を制御します。全体の非表示ではアーカイブから取り除かれません。

シーンの一部に参加したキャラクターは、一部のメッセージが非表示でも、他の参加者とその記憶へのアクセスを共有できます。アクセスできる元のメッセージが1つもないシーンは利用できません。新しい要約指示ではメッセージの可視性を示し、共有する出来事は通常の文章で書き、`{{#if character == "Name"}}…{{/if}}`は非公開部分だけに使います。不在のキャラクターに言及しても、そのキャラクターが参加者になることはありません。元のメッセージの可視性やキャラクター名が変わると、シーンを再準備するか、非公開部分の条件を確認して修正した文章を保存するまで、部分的なアクセス権しかない読み手には古い要約を渡しません。可視性情報が保存されていない古い要約にも、部分的なアクセスを許可する前に同じ確認が必要です。対象者だけを変更しても、文章を確認したことにはなりません。すべての元のメッセージにアクセスできる読み手は引き続き想起でき、手動で修正した文章が黙って書き換えられることはありません。この確認で想起中にモデルを呼び出すことはありません。シーンの日付と期間は、一部の元のメッセージが非表示でも、割り当てられた全参加者の共有メタデータです。原文の抜粋にキャラクターから非表示にしたメッセージが含まれることはありません。条件付きの要約に付随する抜粋は、引き続きナレーター専用です。メッセージの可視性だけでは、すべての非公開情報を表せないためです。常時使用するChat Summariesには、AIから非表示にしたメッセージも引き続き含めます。キャラクター条件で非公開部分へのアクセスを制御し、それらのメッセージを要約対象から外すことはありません。

Advancedモードがオンの間はこのモードが検索を担当するため、Standard Recallのスイッチで同じ内容が重複挿入されることはありません。そのチャットの通常のRoleplay自動要約スケジュールも置き換えます。Advanced Memoryをオフにすると、通常の設定に戻ります。既存のロアブックやダウンロードするエージェントは、それぞれの適用範囲の規則に従います。Advanced Memoryで、任意のユーザー作成コンテキストや外部コンテキストを非公開にすることはできません。

### プリセット内の配置

プリセットの作成者は、既存のセクション順序、名前、ロール、グループの設定を使い、次の通常のコンテンツマーカーを配置できます。

| マーカー | 内容 |
| --- | --- |
| `chat_summary` | Chat Summariesの利用可能な常時要約。 |
| `current_scene_summary` | 進行中シーンの古い部分から取った、制限付きの元の抜粋。 |
| `recalled_scenes` | 選択したすべてのシーン要約。それぞれの直後に、利用可能な過去の抜粋を配置します。 |

プリセットの呼び出しマーカー選択には**Recalled Scenes**だけを表示します。既存の`recalled_messages`は互換エイリアスとして残り、Recalled Scenesと表示されます。有効な`recalled_scenes`が優先され、2つの別々の節は作りません。

各構成要素はプリセットの**XML**、**Markdown**、**None**形式に従い、役割を短く説明します。空の要素は何も出力しません。最初の有効マーカーが位置を決め、マーカーがなければ履歴前に1回だけ補うため、旧プリセットも動作します。抜粋は文脈であり、新しい現在メッセージやコマンドではありません。Advanced Memoryが無効なら高度なシーンマーカーは空です。

プロンプトのプレビューは準備済みメモリを使い、モデルや埋め込みを呼び出しません。未初期化アーカイブの準備や失敗したバックグラウンド処理の再開はドロワーで行います。メモリ記録には推定コンテキスト、境界、出典が表示され、最終インスペクターで実際の送信内容を確認できます。

### 制限と復旧

呼び出しは選択的で、要約は細部を失うことがあります。重要な修正は元の履歴か要約エディターに残してください。記録されていない情報は復元できません。埋め込みが失敗しても、範囲を絞った語彙検索と有効な連続性は利用できます。アーカイブ全体を挿入することはありません。必須指示や添付がプロンプト上限に収まらなければ縮小するか上限を増やします。応答予約がモデルの総コンテキストに収まらなければ出力を減らすか、コンテキストの大きいモデルを選びます。Advanced Memoryは指示を黙って削除せず停止します。

## Chat Summary(Roleplay)

**Chat Summary**は古いメッセージを短いあらすじにまとめます。このまとまりを要約エントリーと呼びます。エントリーはAIに書かせることも自分で書くこともでき、1件ずつオンとオフを切り替えられます。この機能はRoleplayチャットだけにあります。 1項目の切り替えを保存している間も他の項目は操作でき、Activate AllとDeactivate Allは選択全体をまとめて保存します。

Roleplayチャットのヘッダーにある**Chat Summary**ボタン(巻物のアイコン)をクリックすると、**Chat Summary**パネルが開きます。

### 要約エントリーの作成

1. **Summary Scope**では、直近のメッセージをまとめるなら**Last**を、範囲を指定するなら**Range**を選びます。
2. **Generate**をクリックすると、その範囲からAIがエントリーを書きます。
3. 自分で書く場合は**Write**をクリックして空のエントリーを作り、あらすじを入力します。

一覧の各エントリーには、タイトル、元になった範囲またはメッセージ数、推定トークン数が表示されます。エントリーは有効と無効を切り替えたり、展開したり、**Edit**で編集したり、**Delete**で削除したりできます。まとめて操作するボタンもあり、**Show Inactive**と**Hide Inactive**で無効なエントリーの表示を切り替え、**Activate All**と**Deactivate All**で全件をまとめて有効または無効にできます。

### Automatic Summaries

**Automatic Summaries**パネルは、チャットを続けるあいだ要約を最新の状態に保ちます。Roleplayチャットにだけ表示されます。

- **Automatic Summaries**パネル内の**Enabled**スイッチをオンにします。
- 実行する間隔は**Every**欄で指定します。単位は自分が送ったメッセージの件数です。デフォルトは5で、1から200まで指定できます。
- 要約のないまま長くなったチャットに追いつかせるには**Backfill Summary**をクリックします。チャットを少しずつまとめて処理し、実行中は進捗バーが表示されます。途中でやめるときは**Stop**をクリックします。

### Summary Promptのテンプレート

**Summary Prompt**パネルでは、AIが要約を書くときの指示を設定します。**Edit**をクリックすると現在のプロンプトを編集できます。**Templates**をクリックするとテンプレートの管理画面が開きます。ここで**New template**を使うと、名前を付けてプロンプトを保存できます。保存したテンプレートには、それぞれ**Duplicate**、**Edit**、**Delete**の操作があります。

保存したテンプレートはアプリ全体で共通の設定です。あるRoleplayチャットでテンプレートを編集したり選んだりすると、すべてのRoleplayチャットの要約プロンプトが変わります。

### Summary Connectionと出力の長さ

**Summary Connection**パネルでは、要約を書く接続を選びます。デフォルトは**Agent default (falls back to chat connection)**です。つまり、まずデフォルトのエージェント接続を使い、それが使えない場合はチャット自身の接続を使います。

**Maximum output size**欄では、生成する要約の長さの上限を決めます。デフォルトは4096トークンで、1から32768まで指定できます。

### 表示の設定

パネルの**Display**の項目は、要約済みのメッセージを画面にどう表示するかを決めます。

- **Hide summarised messages**: 要約に含まれた元のメッセージを隠します。デフォルトはオフです。
- **Recent message tail**: 隠す設定がオンでも、新しいメッセージをこの件数だけそのまま表示し続けます。デフォルトは10で、0以上の整数を指定できます。0にすると要約されたぶんをすべて隠します。値を大きくするとプロンプトが長くなり、モデルの利用料も増えます。
- **Collapse hidden messages**: 隠したメッセージをチャットの流れの中でどう見せるかを設定します。

チャットでエージェントの書き込み承認(Agentsの別の設定)を必須にしている場合、AIが生成した要約は確認してから反映されます。

## Automatic Summarization(Conversation)

Conversationチャットでは**Automatic Summarization**という別の仕組みを使います。まず1日分のメッセージをその日の要約にまとめ、1週間が終わると、その週の日ごとの要約を週の要約にまとめます。プロンプトに送るのは、週の要約、今週の日ごとの要約、そして今日のメッセージだけです。こうすることで1回のリクエストが小さく収まります。

この機能は自動で動き、Conversationチャットではオフにできません。

### 編集画面を開く

1. Conversationチャットを開き、**Chat Settings**をクリックします。
2. **Automatic Summarization**セクション(カレンダーのアイコン)を探します。
3. **Edit Summaries**をクリックすると、**Automatic Summarization**ウィンドウが開きます。

このウィンドウには週の項目が先に並び、そのあとにまだ週へまとまっていない日が続きます。項目を展開すると、**Summary**の本文と**Key Details**の一覧を編集でき、行の追加と削除もできます。

### Day Rollover HourとRecent Message Tail

**Automatic Summarization**セクションには、1日の区切り方を決める設定が2つあります。

- **Day Rollover Hour**: 要約のうえで新しい1日が始まる時刻です。デフォルトは4 AMで、12 AM(深夜0時)から11 AMまでの任意の時刻を選べます。この時刻より前に送ったメッセージは前日ぶんとして数えます。夜遅いやり取りが途中で分断されないよう、チャットをしない時間帯を選んでください。
- **Recent Message Tail**: 要約されたあとも、今日の新しいメッセージを何件そのままの文章で残すかを決めます。デフォルトは10で、0以上の整数を指定できます。値を大きくするとプロンプトが長くなり、モデルの利用料も増えます。

要約がすでにある状態で**Day Rollover Hour**を変更すると、古い要約は以前の設定で作られていることをMarinaraが警告します。

### 足りない日の要約を補う

古いチャットをインポートしたあとなど、ある日の要約が作られないことがあります。ウィンドウの**Missing Summaries**パネルにある**Backfill**ボタンを押すと、要約のない直近の日をやり直します。一度にさかのぼるのは最大14日ぶんです。

要約に使う接続やモデルを変えても、すでにある日ごとの要約や週の要約は書き直されません。

## トラブルシューティング

### Memory Recallが何も呼び出さない

- 埋め込みソースが設定されているか確かめます。**Memories for This Chat**のチャンクが**Embedding unavailable**になっている場合は、接続の**Semantic Search (Embeddings)**セクションを設定するか、内蔵のローカルモデルを使ってください。[Local Modelのセットアップ](../connections/local-model.md)を参照してください。
- チャンクが**Waiting for vector**の場合は、少し待ってください。指紋は返信のあとに作られます。
- 呼び出されるのは、直近のメッセージと関連の強い記憶だけです。関連するものがなければ何も追加されません。これは正常な動作です。
- 埋め込みモデルを最近変えた場合は、**Memories for This Chat**の再構築アイコンを使い、古いチャンクを新しいモデルに合わせてください。

### 要約が生成されない

- チャットで使えるテキスト接続があるか確かめます。Chat Summaryは**Summary Connection**を、Automatic Summarizationは自動で選ばれた要約用の接続を使います。どれも使えない場合、生成は行われません。
- チャットでエージェントの書き込み承認を必須にしている場合、AIの要約は承認するまで反映されません。
- 失敗した要約は、少し時間をおいて自動的に再試行されます。それでも進まないときは、**Backfill Summary**(Roleplay)または**Backfill**(Conversation)を実行して手動でやり直してください。
