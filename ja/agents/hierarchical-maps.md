# World Maps: 設定、作成、移動

> **対応バージョン:** このガイドはWorld Maps **1.3.1**に対応しています。パッケージはMarinara Engine **2.3.5～3.x**をサポートし、RoleplayとGameのチャットで使えます。Marinara Engine **2.4.1**では、移動ストリームの対応した消去と、ポータブルインポート後のLorebooks即時更新が加わります。Engine **2.3.5～2.4.0**も互換ですが、インポート後にLorebooksの手動更新が必要で、このストリーム消去は含まれません。

World Mapsは、RoleplayとGameに永続的な世界の状態を追加します。場所を1つの自由入力テキストとして持つのではなく、入れ子になった場所の集まりとして世界を表現します。

```text
The Shattered Coast
└── Brinewatch
    ├── Harbor District
    │   ├── Tideglass Inn
    │   └── Quest Hall
    └── Old Sewers
```

Marinaraは、この階層のどこが現在地なのかを正式な情報として保持します。現在のパンくず、その場所の詳細、近くの行き先、条件を満たしたリンク済みのロアが、次の返答の土台になります。さらに、直近のユーザーメッセージがはっきり示した移動や発見に追従することもできます。表示されるAIの描写はその結果を語れますが、描写だけでマップを動かしたり新しい場所を作り出したりすることはできません。

マップはチャットごとに独立させることも、アカウントが所有する1つの共有ワールドにリンクすることもできます。テンプレートはきれいなコピーを作り、そこから内容を変えていけます。一方で共有ワールドは正式な階層と画像一式を1つに保ち、リンクした各チャットは自分の現在地、移動履歴、スナップショット、Gameのひも付けを個別に保持します。

## 機能の概要

World Maps 1.3.1でできることは次のとおりです。

- 地域、集落、場所、建物、フロア、部屋の入れ子構造
- パンくず表示と、正式な現在の物語上の場所
- 子の場所を見せるリスト表示、配置マップ表示、レイヤー順表示
- 親子間の移動、直通リンク、複数ターンにわたるルートの計画
- 直近のユーザーメッセージが示した、検証済みの移動と発見
- RoleplayとGameのチャットをまたいでリンクできる、アカウント所有の共有ワールド
- チャットごとの下書きを確認したうえでの公開、破棄、競合の扱い、切り離しの操作
- 手動、AI、インポートのいずれでも作れるアカウント全体のマップテンプレート
- 設定内容や選んだロアを土台にした、AI支援によるマップの下書きと拡張
- 公開用の説明文、モデル向けの非公開メモ、その場所限定のロア
- 場所ごとに1枚選べる、チャットまたはGlobal Galleryの参照画像
- 配置マップごとに個別に指定できる、チャットまたはGlobal Galleryの背景
- 画像が未設定の場所に対する、確認付きの一括生成
- 変数を使える、Mapsの画像プロンプトの全体上書き
- Roleplayのイラストと、Gameの絵コンテで使える場所参照
- インポート、エクスポート、アーカイブ、履歴を考慮した編集、Gameマップとのひも付け
- AIによるマップ作成と、実行時の場所挿入文のための全体プロンプトライブラリー

行ける場所はモデルのコンテキストにも含まれます。そのためCYOAの選択肢を有効にしていると、モデルは現在地の子の場所や直通でつながった場所を次の選択肢として提示できます。実際にどれを出すかはモデルが決めます。

## 適切なマップの関係を選ぶ

ライブラリーには、アカウントが所有する再利用できるリソースが2種類あります。一方で、実行時の現在地と履歴はチャットごとに保持されます。表示上の名前はリソースの識別子ではありません。World Maps 1.3.1は、新しく保存するリソースの名前が既存のものと重なる場合に、**(copy)**または番号を付けます。

| リソースまたは状態             | 所有者                             | 選ぶ場面                                                       | あとからの編集が影響する範囲             |
| ------------------------------ | ---------------------------------- | -------------------------------------------------------------- | ---------------------------------------- |
| **独立したチャットのマップ**   | RoleplayまたはGameのチャット1つ    | この物語だけの世界を持たせたいとき                             | そのチャットだけ                         |
| **独立したテンプレート**       | アカウント                         | 繰り返し使える出発点がほしいとき                               | 新しいコピーだけ。作成済みのチャットは更新されません |
| **正式な共有ワールド**         | アカウント                         | 複数のチャットで1つの階層を維持して使いたいとき                | リンクしたチャットが使う共有の定義       |
| **リンクしたチャットの下書き** | 公開するまでは、リンクしたチャット1つ | リンクした物語で見つけたものや編集した内容が共有ワールドに入るかもしれないとき | **Publish**を選ぶまで、他のチャットには影響しません |
| **切り離した独立コピー**       | かつてリンクしていたチャット1つ    | 現在のマップを残したまま、共有ワールドの編集を受け取らないようにしたいとき | 切り離したチャットだけ                   |

コピーとリンクは別物です。**Use template**、**Add to chat**、**Independent copy**は、それぞれ別のマップを作ります。Gameの初期設定の**Use shared world**と、ライブラリーの**Link to chat**は、そのチャットを正式な共有ワールドにつなぎます。

## クイックスタート

1. **Agents**(エージェント)を開き、**Download Agents**(エージェントのダウンロード)をクリックして**World Maps**をインストールします。
2. 再起動を求められたらMarinaraを再起動します。このパッケージにはサーバー側のコードが含まれます。
3. RoleplayまたはGameのチャットを開きます。
4. 専用の**World Maps**の地球儀アイコンが用意されている場合はそれを開き、ない場合は**Agents → World Maps**を開いて、現在のチャットで有効にします。同じ操作は、そのチャットの**Chat Settings → Agents**(チャット設定)からも行えます。
5. **Use template**、**Create with AI**、**Build manually**のいずれかでマップを作成します。既存のチャットではマップファイルのインポートもできます。
6. 作業中の階層を確認し、開始する場所を選び、マップを有効にして**Save**(保存)をクリックします。
7. チャット中に**Story map**を開きます。到達できる行き先を選んで次のターンを送るか、送信するメッセージの中でパーティーの移動をはっきり示して、Mapsに到着を検証させて反映させます。
8. 必要に応じてGalleryの画像を場所に割り当てるか、**Location artwork**で未設定の画像を確認して生成します。

テンプレートの適用、AIの下書き、ファイルのインポートは、いずれもエディターの作業用コピーだけを変更します。階層を有効にして保存するまで、返答には反映されません。

## パッケージのインストールと有効化

右サイドバーのSparklesタブから**Agents**を開きます。**Download Agents**をクリックし、**World Maps**を選んで**Install**をクリックします。続けてカタログに**Update**が表示された場合は、それもインストールします。使い始める前に、再起動の案内に従ってください。

World Mapsのページには、インストール済みのパッケージのバージョンと利用できる状態かどうかが表示され、アカウント全体のワールドマップライブラリー、現在の操作対象になっているチャットの名前、そのチャットのマップの状態も確認できます。パッケージをインストールしても使える状態になるだけで、すべてのチャットで有効になるわけではありません。

### Roleplay

1. Roleplayのチャットを開きます。
2. 歯車ボタンで**Chat Settings**を開きます。
3. **Enable Agents**をオンにします。
4. **Tracker Agents**の下で**World Maps**を有効にします。
5. **Edit world map**または**World map library**を開きます。対応しているEngineのビルドでは、デスクトップの上部バーにある地球儀のアイコンから同じライブラリーを開けます。モバイルではChatsのパネルにある地球儀のアイコンを使います。

ライブラリーの動作は、Agentsのメインページから開いても、RoleplayのChat Settingsから開いても同じです。独立したテンプレートのコピーがほしいときは**Add to chat**、継続して使う共有ワールドにつなぐときは**Link to chat**を使います。

### Game

Gameの初期設定でWorld Mapsを選ぶと、次のいずれかの作成方法を選べます。

- **Create with AI**は、生成した階層を確認用に用意します。
- **Use template**は、Gameを作成する前にワールドライブラリーを開きます。
- **Build manually**は、編集できる空の階層から始めます。

**Use template**を選ぶと、選択画面には最初に**Shared worlds**が、次に**Independent templates**が表示されます。

- **Use shared world**は、新しいGameをアカウント所有の正式なワールドにリンクします。Gameは自分の現在地、履歴、スナップショット、ひも付け、未公開の発見を引き続き個別に保持します。
- **Use template**は、確認用にGameが所有する作業用コピーを作ります。アカウントのテンプレート自体が編集されることはありません。

選んだリソースの場所が、そのまま階層の初期状態の世界になります。代わりの通常のGameマップが繰り上がって使われることはありません。

既存のGameにあとからWorld Mapsを追加することもできます。**Chat Settings → Agents**から行います。

## マップテンプレートの作成と再利用

**World Maps → Open world library**を開きます。テンプレートは1つのチャットではなくアカウントに属するので、繰り返し使う二次創作の世界、キャンペーンの舞台、ダンジョン、都市、自分用の出発点マップに向いています。

ライブラリーからは次のことができます。

- テンプレートを手動で作成する
- **Create with AI**で下書きを作る
- `.hierarchical-map.json`ファイルをインポートする
- テンプレートを検索、表示、編集、エクスポート、削除する
- 開いているRoleplayまたはGameのチャットで**Add to chat**を使う
- Gameの初期設定で**Use template**を選ぶ

適用するたびに独立した作業用コピーが作られます。あとからテンプレートを編集しても、すでにコピー済みのチャットは変わりません。逆にチャット側の編集もテンプレートには影響しません。

テンプレートは、アカウント全体で使えるGlobal Galleryの画像への参照を保持します。チャットで**Save as template**を使うと、Mapsは参照されているチャットの画像をGlobal Galleryへ引き上げ、同じ画像がすでにあればそれを再利用します。以降、そのテンプレートを適用した各チャットは、Galleryのコピーを増やさずに同じ共有画像を参照します。

共有されるのは画像だけです。適用されたマップの定義そのものは独立した作業用コピーのままで、テンプレートを編集してもチャットに追加済みのマップは更新されません。

## 複数のチャットを1つの共有ワールドにリンクする

複数のRoleplayまたはGameのチャットで同じ正式な階層を参照したいときは、World map libraryの**Shared worlds**を使います。空の共有ワールドを新規作成する、インポートする、既存のテンプレートを**Make shared**で引き上げる、保存済みのチャットのマップを開いて**Make shared**を選ぶ、のいずれかで用意できます。最後の方法では、参照しているチャットの画像がGlobal Galleryへ引き上げられ、アカウント所有のワールドが作られ、元のチャットがそこにリンクされます。

ライブラリーに操作対象として表示されているチャットをつなぐには**Link to chat**を選びます。現在地と、キャンペーンの履歴がすでに使っている場所IDは、共有ワールド側に存在している必要があります。存在しない場合は**Independent copy**を使うか、先にそのチャットの現在のマップを新しい共有ワールドへ移行してください。

リンクしたチャットが共有するのは、マップの定義とGlobal Galleryの画像だけです。メッセージ、現在地、移動のスナップショット、Gameの状態、Gameマップとのひも付け、プロバイダーへの接続、認証情報は共有されません。

リンクしたチャットの中で行った編集や発見は、そのチャットの未公開の下書きとして保存されます。**Publish**を選ぶまで、正式なワールドにも他のチャットにも反映されません。下書きは**Discard**で破棄することも、**Detach and keep copy**でチャットの現在のバージョンを保ったまま共有をやめることもできます。下書きが残っている間に正式なワールドが変更された場合、Mapsは競合として報告し、どちらかを黙って上書きせずに切り離しか破棄を求めます。

ライブラリーから共有ワールドを編集した場合は、正式な定義が直接更新されます。共有ワールドのエディターには、場所を完全に削除する操作がありません。IDを安定して残せるようにアーカイブしてください。リンクしたチャットでも、**Detach and keep copy**を選ぶまでは場所を完全に削除できません。共有ワールド自体も、リンクしているチャットをすべて切り離すかリンクし直すまで削除できません。

共有ワールドとテンプレートは、画像ファイルを各チャットにコピーせずにGlobal Galleryの画像への参照を保持します。保存済みのテンプレート、共有ワールド、独立したチャットのマップ、リンクしたチャットの下書きのいずれかがまだ参照している間、MarinaraはGlobal Galleryの画像の削除をブロックします。画像そのものを削除したいときは、先に参照を外してください。

## 切り離し、差し替え、作り直し

これらの操作は、それぞれ目的が異なります。

- リンクしたチャットの現在の階層を残したまま共有をやめるには、エディターの未保存の変更を保存するか破棄してから、**Detach and keep copy**を選びます。そのチャットは独立したものになり、以降は正式なワールドの更新を受け取りません。
- 共有は続けたまま別の正式なワールドに切り替えるには、操作対象として表示されているチャットのワールドライブラリーを開き、差し替え先で**Link to chat**を選びます。履歴との整合性の確認は同じように行われます。
- 独立したチャットのマップを差し替えるには、そのエディターを開いて**Replace / start over**を選びます。先にテンプレートとして保存したりバックアップをエクスポートしたりしてから、**Create with AI**、**Use template or shared world**、**Import map file**、**Start blank**のいずれかを選べます。
- まったく関係のないマップに入れ替えたいときも、同じ差し替えの流れを使います。エージェントをいったん削除して追加し直しても、マップはリセットされません。

差し替えた内容は**Save**をクリックするまで作業用コピーのままです。差し替えを保存すると、予約中の行き先やルートは取り消されます。メッセージ履歴が場所IDを参照するようになったあとは、過去のパンくずを守るために、無関係なマップへの差し替えが拒否されることがあります。その場合は独立したコピーを保ったまま、既存のマップを拡張するかアーカイブしてください。

## マップエディターの見方

デスクトップでは、エディターは3つのペインに分かれます。画面が狭いときは**Hierarchy**、**Local**、**Details**のタブを切り替えます。

- **Hierarchy**は階層全体を表示します。場所を選ぶとその内容を編集できます。**Enter**で表示する階層の位置が変わるだけで、物語上の現在地は動きません。
- **Local**は現在地の直下の子を、リスト、配置マップ、レイヤー順のいずれかで表示します。
- **Details**では、場所の文章、階層、ロア、画像、リンク、状態、Gameマップとのひも付けを編集します。

エディターのヘッダーには、AIによる作成の操作、**Templates**、**Export**、**Import**、Enabledスイッチ、**Save**があります。保存していない変更があると**Unsaved**と表示されます。保存せずに離れようとすると、破棄してよいか確認されます。

### 場所に設定できる内容

場所ごとに次の情報を持てます。

- 親1つと、任意の数の子
- Region、Settlement、Place、Building、Floor、Roomのいずれかの種類
- 名前とアイコン
- 公開用の説明文と、モデル向けの非公開メモ
- 短い認識用の要約
- その場所限定のロアブックへのリンク
- 他の場所への一方向または双方向の直通リンク
- 子の見せ方(List、Map、Layers)
- 場所の参照画像と、画像を使うかどうかのトグル
- Map表示を使うときの、子マップ専用の背景
- 有効またはアーカイブ済みの状態

**Map**表示では、子をドラッグして配置するか、XとYの座標を0から100までの数値で入力します。選んだ親には、子の背後に表示するGalleryの画像も設定できます。**Layers**では、子ごとに重ならないレイヤー順を指定します。

直通リンクは、階層の中で条件を満たす場所どうしを自由につなげます。町と町を結ぶ渡し船、選んだフロアどうしをつなぐ階段、世界間のポータル、別の建物の部屋どうしをつなぐ隠し通路などです。

25階建ての塔は、25段の親子の連なりではなく、1つの塔の下に並ぶ兄弟としてフロアを表すのが基本です。マップは最大500か所、階層は20段までです。

## AIでマップを下書き・拡張する

空のマップからは**Create with AI**または**Draft with AI**をクリックします。すでにマップがある場合は**Expand with AI**をクリックします。

### 何を読ませるかを選ぶ

**Build from**で、次のいずれかの情報源を選びます。

- **Game setup**は現在の設定内容とキャラクターを使います。Gameでは、世界の概要とパーティーのキャラクターが含まれます。
- **Selected lore**は選んだロアブックを使います。**Strict canon**はロアに根拠のある場所だけを作ります。**Canon + expansion**は、世界観に合う場所の追加を許可します。

作成機能はターンの履歴を読みません。設定内容やロアに書かれていないことは、**What should this world include?**または**What should be added?**に書き足してください。

規模を選びます。

| 規模       | 生成される場所の目安 |
| ---------- | ------------------ |
| **Small**  | 8か所           |
| **Medium** | 16か所             |
| **Large**  | 28か所             |

生成されるのは下書きで、保存済みのマップではありません。プレビュー全体を検索したり展開したりして場所を選び、パス、説明文、モデル向けの非公開メモ、どのロアに基づくかを確認します。続ける前に**Edit prompt**、**Regenerate**、**Discard draft**を使えます。

新しいマップなら**Continue to editor**、拡張なら**Add to working map**をクリックします。キャンペーンの履歴が場所IDを参照するようになったあとは、Mapsが既存の参照を守るため、無関係な全面差し替えではなく拡張だけを許可します。

## マップを手動で作成・編集する

空のマップからは**Build manually**をクリックします。Mapsは大きなくくりの開始地点を1つ作ります。それを階層で選んでから、次の操作を使います。

- **Add child**: 選んだ場所の内側に場所を作る
- **Add sibling**: 同じ親の下に、隣り合う場所を作る
- **Duplicate**: 場所とその配下をコピーしてから編集する
- **Archive**: 過去の参照を消さずに場所を使わなくする

物語の出発点は**Set as starting location**で決めます。階層を有効にするには、有効な開始地点が必要です。エディターに表示された問題を解決してから**Enabled**をオンにし、**Save**をクリックします。

## モデルに届く情報を理解する

有効かつ保存済みのマップがあると、生成のたびに次の内容を含む正式な空間コンテキストのブロックが1つ渡されます。

- 現在のパンくずのパス
- 現在地の正確なIDと公開用の説明文
- 現在地のモデル向け非公開メモ(設定されている場合)
- 1回の移動で行ける行き先
- 有効な既知の場所とその正確なIDの、件数を制限した一覧

既知の場所の一覧があることで、返答は保存済みの世界の別の場所への到着も認識できます。近くの行き先は、通常の描写やCYOAの選択肢にも活かせます。

親の名前は位置関係の手がかりになりますが、親の説明文、親の非公開メモ、親の画像、親にリンクしたロアは引き継がれません。現在地が`Tower → Floor 7 → Alchemy Lab`なら、有効になるのは実験室の情報だけで、塔とフロアはパンくずに名前を提供するだけです。

**Private model memory**は保存したAI専用のメモで、自動で更新される記憶機能ではありません。秘密、雰囲気、その場に残り続ける危険、土地固有のルール、その場所でだけ有効にしたい事実に使ってください。モデルに必ず届けたい情報は、認識用の要約だけに頼らず、公開用の説明文かモデル向けの非公開メモに書きます。

## 物語の中で移動する

Mapsは、予約した移動、あらかじめ計画したルート、ユーザー主導の到着の検証に対応しています。移動はターンと一緒に保存されるので、現在地は選ばれているメッセージ履歴とスワイプに追従します。Marinaraを再起動しても、現在地が意図的にリセットされることはありません。メッセージの分岐やスワイプを切り替えると、その履歴と一緒に保存された空間のスナップショットが復元されます。

### 行き先を明示して予約する

行き先を選ぶと移動が予約され、その場では移動しません。次に送るメッセージと同時に移動が確定するので、現在地とターンのずれが起きません。

1回の移動で行ける場所は次のとおりです。

- 現在地の親
- 現在地の有効な子
- 使える直通リンクでつながった場所

1ターンで確定できる階層の移動は1段階だけです。予約した行き先はXで取り消せます。送信前にマップの版か現在地が変わった場合、予約中の移動は**Needs review**になります。

### 複数ターンのルートを計画する

ワールドマップで離れた有効な場所を選びます。親子関係と使えるリンクの経路がつながっていれば、Mapsは最短ルートを表示し、**Plan route**を提示します。

ルートは最初の1歩を予約します。以降はユーザーのターンを送るたびに1歩ずつ確定し、次の1歩を予約しながら目的地まで進みます。ルートを進めるための専用のボタンはありません。ルートはいつでも取り消せます。マップや現在地が想定外に変わった場合、ルートは新しい経路を推測せずに**Needs review**になります。

たとえばFloor 1から兄弟のFloor 25へ移動するには、通常は塔へ出るのに1ターン、Floor 25へ入るのにもう1ターンかかります。直通リンクがあれば、この移動は1歩で済みます。

### ユーザー主導の移動への追従と、新しい場所の発見

マップの自動更新の根拠になるのは、直近のユーザーメッセージです。

- 焦点になっているパーティーの移動を現在形または命令形で直接書くと、到着が確定します。「Kitchenへ行く」「彼女が屋外の区画へ入っていくので、私たちもついていく」のような文で、一致する既知の場所へ移動できます。
- 名前があり、その後も残り、また訪れられる重要な場所への到着や発見をはっきり書くと、その場所を世界に追加できます。「隠し部屋を見つける」と書けば、その場所を作ってそこへ入れます。
- 表示される返答はその結果を描写できますが、AIの描写だけで移動や新しい場所が認められることはありません。
- これからの意図、失敗した移動や途中で終わった移動、言及、NPCだけの移動、想像上の場所、一時的な野営地、廊下、乗り物といった一時的な要素では、場所は作られず現在地も動きません。

書き方を解釈して隠しMapsディレクティブを出力するのは、あくまでモデルの役目です。アプリはその内容を検証します。あいまいな文章では、言語モデルごとに判断が分かれることがあります。次のターンで確実に移動させたいときは**Set destination**を、すでに保存された状態を直したいときは**Set current story location**を使ってください。

検証を通ったユーザー主導の到着は、1回の移動で行ける範囲という制限を越えられます。必要な場合、Mapsは現在地からの直通リンクを使えるものとして記録します。すでに行き先を予約していた場合は、その予約分がまずユーザーのメッセージと一緒に保存され、続いてユーザー主導の到着が返答側の最終的な現在地になります。1回かぎりの予約はこの時点で解除されます。ルートを計画している場合、次の予定どおりの場所へ到着すれば通常どおり進みます。それ以外の場所へ到着した場合は、ルートの先の段階へ飛んだときも含めて、ルートは**Needs review**になり、Mapsが計画を黙って書き換えることはありません。そのルートは、到着後の現在地から取り消すか計画し直してください。

### 開始地点と現在の物語上の場所の違い

**開始地点**は、新しい物語を始めるときのデフォルトの場所です。**現在の物語上の場所**は、そのチャットが今いる場所です。開始地点を変更しても、すでに進んでいるチャットの現在地は直りません。

保存済みの状態を直すには、エディターの**Details**ペインで有効な場所を選び、**Set current story location**を選びます。これは物語として移動するのではなく、管理上の修正です。**Save**をクリックした時点で反映され、予約中の行き先やルートは取り消されます。過去のメッセージが書き換えられることはありません。

### Roleplayでの移動

**Story location**の操作はメッセージ入力欄の上に表示されます。

1. 物語のマップを開いて、階層と現在のパンくずを確認します。
2. 場所を選んで説明文を読みます。
3. **Explore inside**、**Browse up**、パンくずを使うと、移動せずに見て回れます。
4. 到達できる場所には**Set destination**、到達できる遠くの目的地には**Plan route**をクリックします。
5. 次のメッセージを送ると、予約した1歩が確定します。

### Gameでの移動

Game Modeには**Hierarchical world map**が加わります。**You are here**が現在の物語上の場所を示します。見て回る、中心に合わせる、内容を確認するといった操作ではパーティーは動きません。行き先かルートを予約してから、次のGameのターンを送ってください。

直近のユーザーメッセージがパーティーの到着をはっきり示している場合、生成されたGameの返答は、階層上の場所を更新する隠しコマンドを出力できます。更新後は現在地の情報が、GM、パーティー、シーンの画像、条件を満たす絵コンテの参照の土台になります。

## 階層のワールドマップと通常のGameマップの違い

Gameには2種類のマップの仕組みが共存できます。

- **World Maps**は、`The Shattered Coast → Brinewatch → Tideglass Inn`のような、物語や世界の中での正式な場所です。
- 通常のGameのグリッドマップやノードマップは、その物語上の場所の内側にある局所的・戦術的な情報で、Gameの時間と天候にも関わります。

World MapsがGameの初期設定を担当する場合、選んだテンプレートまたは確認済みの下書きが初期状態の世界になります。通常のGameマップは、プロンプトの入力として使い回されることも、代わりの階層として繰り上げられることもありません。

さらに踏み込んだ使い方として、階層上の場所をGameマップ全体、1つのグリッドのマス、1つのノードにひも付けられます。ひも付けたGameの位置を選ぶと、対応する階層の移動が準備されます。ひも付けていない位置は、通常どおりの戦術的な動作のままです。ひも付けを編集する前に階層を保存してください。ひも付けを解除しても、どちらのマップも削除されません。

## 場所に見た目の個性を与える

場所の参照画像と子マップの背景は、同じGalleryの画像を使っていても別々に扱われます。

| 画像                      | 用途                                                                                                                 | 画像生成に送られるか                                                                                 |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **Location reference image** | 現在いるその場所の見た目を固定します。チャットまたは共有のGlobal Galleryの画像を選ぶか、AIで作成します。    | 送られます。**Use for Roleplay illustrations and Game storyboards**が有効で、条件を満たすリクエストの場合のみです。 |
| **Child map background**     | Map表示を使う親の下で、動かせる子の場所の背後に表示します。マップのレイヤーごとに別々の背景を設定できます。 | 送られません。表示専用です。                                                                                   |

キャラクターやペルソナの参照が「誰がいるか」を保つのに対し、場所の参照は「どこで起きているか」を保ちます。プロバイダーが対応していれば、両方を組み合わせることで、複数の画像にわたってキャラクターと背景の両方を一貫させやすくなります。

条件を満たす場所の参照が添付されると、画像生成のパイプラインは次の指示を追加します。

> Location handling: an attached location reference image is available. Use it
> to set the scene location.

参照画像の上限はプロバイダーごとに異なります。リクエストで明示した参照やキャラクターの参照が多いと、自動で付く参照の入る余地はその分減ります。

### 場所の参照画像を設定する

エディターで場所を選び、**Location reference image**を開きます。

- **Choose artwork**は、現在のチャットまたは共有のGlobal Galleryから、確認済みの画像を割り当てます。選択画面には画像ごとの出どころが表示されます。
- **Create with AI**は、編集できる情景描写のプロンプトを開き、使うかどうかを決める前に結果をGalleryへ保存します。
- **Use for Roleplay illustrations and Game storyboards**は、選んだ画像を条件を満たす生成に使うかどうかを切り替えます。

Map表示を使う親では、**Child map background**を別途開きます。Galleryの画像を選び、子のマーカーの背後に配置します。この画像は、マップ上に表示されているというだけでプロバイダーに送られることはありません。

### 未設定の場所の画像をまとめて生成する

エディターの**Location artwork**では、参照画像や子マップの背景が未設定の場所を探せます。

1. **Review requests**をクリックします。
2. プロバイダーへのリクエストを消費する前に、件数を確認します。
3. 画像用の接続、モデル、Engineのスタイル、キャンペーンの画風の設定、保存済みの画像への指示、出力サイズを確認します。
4. 必要に応じて、ポジティブとネガティブのプロンプトをすべて編集します。
5. 確認を取り消すか、**Generate N images**をクリックして確定します。
6. 生成された画像を作業中のマップで確認し、**Save**をクリックします。

未設定の画像1枚ごとに、プロバイダーへのリクエストが1回発生します。大きな世界では時間も費用もかさむため、確認画面はスクロールでき、件数も常に見える状態を保ちます。既存の画像は、可能なかぎり追加のリクエストなしで再利用します。新しく生成した画像は場所の参照画像になり、そのマップに背景が必要な場合は子マップの背景にもなります。

確認画面に表示されている、編集後のポジティブとネガティブのプロンプトがそのままプロバイダーへ送られます。ポジティブのプロンプトの内容がネガティブ側へコピーされることはありません。

## 自動生成の画像プロンプトをカスタマイズする

**Settings → Generations → Prompt Overrides**を開き、**Maps location artwork**を選びます。これは、Mapsが場所の画像をプレビューして自動生成するときに使う全体のテンプレートです。変数は`${variableName}`の形式で書き、エディターから挿入できます。

| 変数                                            | 意味                                                    |
| --------------------------------------------------- | ---------------------------------------------------------- |
| `${locationName}`                                   | 場所の名前                                              |
| `${locationDescription}`                            | その場所の公開用の説明文                        |
| `${locationType}`                                   | Region、Settlement、Place、Building、Floor、Roomのいずれか        |
| `${locationPrompt}`                                 | Mapsが用意した、情景描写の完全な代替プロンプト     |
| `${parentLocationName}`                             | 直接の親の名前。ルートでは空                           |
| `${parentLocationDescription}`                      | 直接の親の公開用の説明文。ない場合は空                             |
| `${locationPath}`                                   | ルートからその場所までのパンくず全体                           |
| `${genre}` / `${genreLine}`                         | Gameのジャンル(そのまま/句読点付き)。Game以外では空           |
| `${campaignArtStyle}` / `${campaignArtStyleLine}`   | **Use campaign art style**がオンのときだけ入るキャンペーンの画風  |
| `${imageInstructions}` / `${imageInstructionsLine}` | Chat Settingsに保存した画像への指示(そのまま/整形済み) |

組み込みのテンプレートは、その場所のプロンプトに加えて、任意でジャンル、キャンペーンの画風、保存済みの画像への指示を使います。親の説明文とパス全体をデフォルトで含めないのは意図的な設計で、塔のような親の目印がすべての子やフロアの画像に入り込むのを防いでいます。

よくあるカスタマイズは次のとおりです。

- 自動生成のマップ画像にGameのジャンルを入れたくない場合は、`${genreLine}`を削除します。
- チャットごとの**Use campaign art style**トグルでその内容を制御したい場合にだけ、`${campaignArtStyleLine}`を残します。トグルがオフのとき、この変数は空になります。
- `${parentLocationName}`、`${parentLocationDescription}`、`${locationPath}`は、プロバイダーに広い文脈が必要なときだけ追加します。
- 組み込みのテンプレートに戻すには**Reset to default**を使います。

Engineのスタイルプロファイルと、全体のポジティブとネガティブの画像設定は、このテンプレートのあとに適用されます。これらはMaps専用の設定ではなく、Illustratorや画像生成で共通の設定です。ネガティブのプロンプトに身に覚えのない文字列が残る場合は、全体のネガティブ画像設定と、確認画面の編集欄を確認してください。

## 場所にロアをリンクする

World Mapsは、ロアを2つの形で使います。

1. AIによる作成機能が、下書きや拡張のときに選んだロアブックを読みます。
2. 保存済みの場所が、そこが現在地である間だけエントリーを有効にします。

実行時のロアをひも付けるには、場所を選んで**Linked lore**を開き、使えるエントリーを検索して、必要なものをひも付けてから保存します。

ひも付けたロアブックのエントリーを開くと、マップエディターから離れます。ほかに保存していない変更を残したいときは先にマップを保存し、破棄してよい場合はその点を確認したうえで進めてください。World Maps 1.3.1は、この操作で未保存のマップの変更が失われる可能性があるときに警告します。

ひも付けたエントリーは親から子へ引き継がれません。Brinewatchにひも付けたロアは、Tideglass Innにも同じくひも付けないかぎり、そこでは有効になりません。

現在地のロアはキーワードの一致を必要としませんが、ロアブック側の制御を素通りするわけではありません。無効になっているロアブックやエントリー、そのチャットから除外されているロアブックやエントリーは使えないままで、エントリーの条件、タイミング、確率、トークンの上限も引き続き適用されます。参照が見つからない場合もエディターには表示されるので、修復するか、ひも付けを外せます。

## Mapsの高度なプロンプト設定

**Agents → World Maps**のメインページには、全体に効く2つのプロンプトの仕組みがあります。

- **Generation prompt**は、AIによるマップの下書きと拡張のための、Roleplay/Game向けの名前付きライブラリーです。チャットごとに別々の選択肢を選べます。プレビューは、モデルへのリクエストを発生させずに、実際の設定内容、キャラクター、ロア、マップのコンテキストを使って解決結果を表示します。
- **Turn prompt insert**は、通常のターンで現在地を提示する、Roleplay/Game共通のシステム文を制御します。Marinaraはその周囲に、アプリが管理する`<spatial_context>`の囲みと、正式な情報であることを示す必須の変数を維持します。

同じページの**Connection Override**は、AIによるマップの下書きと拡張に影響します。現在のチャットの接続を使う場合は空のままにします。これらの設定は、全体のGeneration設定にある**Maps location artwork**の上書きとは別物で、置き換えるものではありません。

これらは高度なカスタマイズ向けの設定です。必要な変数を残し、保存する前に解決結果のプレビューで確認してください。

## 安全にインポート、エクスポート、アーカイブする

### ポータブルマップをエクスポートする

チャット、テンプレート、共有ワールドのエディターで**Export**を使うと、作業中の階層を`.world-map.json`ファイルとしてダウンロードできます。先に、リンク済みロアをどこまで含めるか選びます。

| ロアのオプション | ファイルの内容 |
| --- | --- |
| **Map only** | 階層と読み取り可能な場所・ロアの出典情報。ロアブック内容はなく、欠けたエントリーを再作成できません。 |
| **Map + linked entries** | マップがリンクするエントリーと、整理に必要なフォルダーパスだけ。推奨のポータブル形式です。 |
| **Map + complete lorebooks** | リンク済みロアブックの全エントリーとフォルダー。マップと無関係な内容も含みます。 |

共有前にロアブック一覧、エントリー数、推定サイズ、展開可能な場所とロアの対応を確認してください。完全なロアブックには非公開または無関係なメモが含まれる場合があります。**Include map artwork**を有効にすると、参照画像と子マップ背景も同梱されます。小さなバックアップには無効にします。古い`.hierarchical-map.json`も引き続きインポートできます。

### マップをインポートしてポータブルロアを復元する

**Import**は、階層をチャットの作業用コピー、独立したテンプレート、共有ワールドへ読み込みます。ファイルにロアブック内容がある場合、**Restore portable map lore**に**Exact IDs**、**Unique content**、**Need a choice**、**New entries**の4グループが表示されます。

完全なエントリーIDが確定扱いになるのは、インポート先のロアブックに属する場合だけです。別ソースのIDは曖昧なので、正しい`Lorebook → Entry (ID)`行か**Import a new copy**を選びます。ID以外では、ポータブル内容と設定の全体が一意に一致するときだけ再利用され、名前だけでは一致しません。

結果を確認して方針を選びます。

- **Import separate copies**はエントリーを再利用せず、`Original Lorebook - Map Name (World Map)`のような独立ロアブックを作り、名前の衝突には**(copy)**または**(copy N)**を付けます。
- **Reuse matches & import the rest**は完全一致と一意一致を保ち、曖昧な行の選択を適用し、残りにだけ新しいロアブックを作ります。

Mapsは再利用・作成したロアブックを一覧表示します。作成したコピーはマップを削除してもライブラリーに残ります。Engine **2.4.1**以降はLorebooksを即時更新し、**2.3.5～2.4.0**では復元後にMarinaraを1回更新します。

同梱画像も復元・再対応されます。チャット画像は読み込み先のGalleryへ戻り、共有画像はGlobal Galleryから再利用または一度だけ追加されます。結果を確認して**Save**してください。インポートだけでは保存されません。**Map only**は出典情報と既存の完全IDリンクを保ちますが、内容がないため削除済みロアブックやエントリーを再作成できません。

キャンペーンの履歴がマップを参照するようになったあとは、インポートする変更でも既存の場所IDを保つ必要があります。階層を無関係なIDで置き換えるのではなく、場所を追加または更新してください。

### 場所をアーカイブまたは完全に削除する

アーカイブは古い参照を保ちます。場所をアーカイブする前に、次の点を確認してください。

- 有効な子は移動するかアーカイブする
- 必要であれば別の有効な開始地点を選ぶ
- その場所が実行時の現在地であれば、代わりの有効な場所を選ぶ

アーカイブした場所は、Detailsのペインから元に戻せます。World Maps 1.3.1では、アーカイブ済みの場所や、配下がすべてアーカイブ済みの枝を安全に取り除ける場合に、**Delete permanently**も使えます。保存済みの開始地点または現在の物語上の場所である、メッセージ履歴に登場する、Gameマップとひも付いている、予約中の行き先やルートに含まれる、共有ワールドにまだリンクしているチャットに属している、のいずれかに当てはまる場合、エディターはこの操作を無効にします。共有ワールドとテンプレートのエディターには、場所を完全に削除する操作がありません。まず表示された依存関係を解消するか、必要に応じてリンクしたチャットを切り離すか、その場所をアーカイブしたままにしてください。

完全な削除は、**Save**をクリックした時点で作業中の下書きからその場所を取り除き、階層と直通リンクの参照も整理します。保存せずに閉じた場合、削除は破棄されます。削除した場所はエクスポートに含まれなくなります。一方、保護されたまま残っているアーカイブ済みの場所は、履歴やひも付いたデータを支えるIDを安定して残すために、引き続きエクスポートされます。この保護を回避するために、エクスポートしたJSONを編集しないでください。

## トラブルシューティング

### Chat SettingsにWorld Mapsが表示されない

パッケージがインストールされていて、Marinaraを再起動したか確認します。対象のチャットはRoleplayまたはGameである必要があります。**Enable Agents**をオンにしてから、**Tracker Agents**の下で**World Maps**を有効にします。

### ワールドライブラリーにAdd to chatやLink to chatがない

ライブラリーを開く前に、対応しているRoleplayまたはGameのチャットを開いてください。ライブラリーには操作対象のチャットの名前が表示され、テンプレートには**Add to chat**、共有ワールドには**Link to chat**が表示されます。Gameの初期設定では、これに相当する操作が**Use template**と**Use shared world**です。

Gameの初期設定でライブラリーに共有ワールドが並んでいるのに**Use shared world**が表示されない場合は、ブラウザーがアップデート前の古いパッケージのクライアントを読み込んだままになっている可能性があります。開いているマップエディターがあれば、マップを保存するか下書きを意図的に破棄してから、エディターを閉じます。ほかの作業を保存し、Marinaraを1回だけ強制的に再読み込みしてから、Gameの初期設定を開き直してください。新しいEngineのビルドでは、パッケージのアップデートに再読み込みが必要な場合にその旨を明示します。

### Gameの初期設定で意図しない場所や代わりの場所が使われた

Gameの初期設定を完了する前に、**Use template**を選び、独立したコピーがほしい場合は**Use template**を、正式なワールドにリンクしたい場合は**Use shared world**を確定してください。そのうえでGameのマップを確認して保存します。テンプレートは変更されません。リンクしたGameでは、**Publish**を選ぶまで変更が未公開のまま保持されます。

### リンクしたチャットに古い共有ワールドが表示される

公開に使ったブラウザータブ内でキャッシュされている、未編集のリンク済みチャットエディターは自動的に更新されます。未保存または未公開の変更があるチャットは下書きを保ち、競合を表示します。別のタブやウィンドウにあるチャットは開き直して、新しい正式リビジョンを読み込んでください。

### マップを有効にできない

有効な場所を1つ以上作り、有効な開始地点を設定します。エディター上部に表示されている問題をすべて解決してから、もう一度有効にして保存してください。

### AIによるマップ生成が使えない

チャット、またはMapsの**Connection Override**に、動作する言語モデルの接続が設定されているか確認します。AIによる作成画面を開き直す前に、エディターの変更を保存するか破棄してください。拡張の場合は有効な対象を選びます。ロアに基づく生成の場合は、有効でチャットから除外されていないロアブックを1つ以上選びます。

### AIマップ生成で不完全または不正なJSONが報告される

完全なJSONが得られる前に返信が終わった場合は、接続の**Max Output Tokens**を増やすか小さいマップサイズを選び、再生成します。World Mapsは不完全な返信の修復に追加リクエストを使いません。

不正なJSONの場合は、構文だけの修復をすでに1回試しています。再生成し、同じモデルが繰り返し失敗する場合は別の接続またはモデルを使ってください。**Max Output Tokens**の変更は不完全な出力向けです。

### メッセージを送っても現在地が変わらない

自動での移動には、直近のユーザーメッセージが焦点となるパーティーの到着をはっきり示していることと、モデルが有効な隠しMapsディレクティブを出力することが必要です。AIの描写だけ、意図、相談、失敗した移動、NPCだけの移動、一時的な場所では現在地は動きません。「Kitchenへ行く」のような直接的な書き方を試してください。次のターンで確実に移動させたいときは**Set destination**を使ってください。

### チャットを開き直したら現在地が変わっていた

選ばれているメッセージの分岐とスワイプを確認してください。現在地は、その履歴と一緒に保存された空間のスナップショットに追従します。選ばれている履歴は正しいのに現在地が合わない場合は、マップエディターを開いて正しい有効な場所を選び、**Set current story location**を選んでから**Save**をクリックします。

### 行き先やルートがNeeds reviewと表示される

移動を予約したあとに、マップの版か現在地が変わっています。物語のマップを開いて現在のパスを確認し、行き先かルートを選び直してください。表示されている行き先がまだ予約中の場合は、いったん取り消してから選び直します。

### 計画したルートが進まない

ユーザーのターンを送るたびに、表示されている次の1歩が確定し、その次の1歩が予約されます。ルートを進めるための専用の操作はありません。1ターン送り終えてもルートが進まない場合は、いったん取り消して現在地から計画し直してください。保存されている現在地がすでに間違っている場合は、**Set current story location**を選んで**Save**をクリックします。この管理上の修正で、古いルートは取り消されます。

### このチャットにまったく別のマップを使いたい

マップエディターを開いて**Replace / start over**を選びます。必要ならテンプレートとして保存するかエクスポートしてから、新しいマップを作成、インポート、コピー、リンクのいずれかで用意します。リンクしたチャットで現在の階層を残したい場合は、先に**Detach and keep copy**を使ってください。World Mapsを削除して追加し直しても、そのマップが消えるわけではありません。

### 離れた場所を選べない

有効な親子関係やリンクの経路があれば**Plan route**を使います。経路がない場合は、使える直通リンクを追加するか、到達できる場所を1ターンずつ経由して移動してください。見て回る操作では物語は動きません。

### 自動生成の画像プロンプトに必ずGameのジャンルが入る

**Settings → Generations → Prompt Overrides → Maps location artwork**を開き、テンプレートから`${genreLine}`を削除します。上書き設定を保存してから、画像の確認画面を開き直してください。

### オフのはずのキャンペーンの画風が反映される

**Chat Settings → Illustrator → Use campaign art style**を確認します。このトグルがオフなら、`${campaignArtStyle}`と`${campaignArtStyleLine}`は空になります。確認画面の要約では、キャンペーンの画風が**Off**と表示されるはずです。

### 親の目印がすべての子の画像に写り込む

必要な場合を除き、全体の画像テンプレートでは`${parentLocationDescription}`と`${locationPath}`を使わないでください。デフォルトの場所プロンプトはその場所だけに絞られており、こうした広い範囲の項目は含みません。

### ネガティブの画像プロンプトに身に覚えのない内容が入る

確定する前に、ネガティブの欄を確認して編集します。そのうえで、共通の全体ネガティブ画像設定を確認してください。Mapsの画像テンプレートが組み立てるのはポジティブのプロンプトで、その内容がネガティブの欄にコピーされることはありません。

### 場所の参照画像が画像や絵コンテで使われない

Galleryの画像がまだ存在していること、そして現在いるその場所で**Use for Roleplay illustrations and Game storyboards**が有効になっていることを確認します。子マップの背景は表示専用なので、同じGalleryの画像を場所の参照画像としても割り当てないかぎり、参照の代わりにはなりません。

### モデルがマップを無視する

そのチャットでWorld Mapsが有効になっていること、階層が**Enabled**になっていること、最新の変更が保存されていること、Story locationの操作に現在地が表示されていることを確認します。詳しく調べるときは、**Turn prompt insert**の解決結果のプレビューを使ってください。

### リンクしたロアが有効にならない

エントリーが、現在いるその場所にひも付いているか確認します。あわせて、エントリーとロアブックが有効になっていること、そのロアブックがチャットから除外されていないことも確認してください。

**World Maps 1.3.1のその他の規則:** ガイド付き生成、再生成、続きの生成は新しいユーザーターンを作らないため、予約中の行き先やルート段階を消費しません。**Impersonate**はユーザーメッセージを作成します。成功時は移動を1回確定し、プロバイダー失敗時は何も確定せず、古い移動は**Needs review**へ戻ります。

Marinara Engine **2.4.1**以降では、完全なMapsの移動・発見指示がストリーミング本文と保存メッセージから削除され、通常の角括弧付き文章と空白は変わりません。生のMaps指示が表示されたらEngineとWorld Mapsを更新し、求められた場合は再起動して、該当メッセージを再生成または削除してください。

1枚のGallery画像が両方の役割を持つ場合、**Remove reference only**は子マップ背景として残し、**Reject both and create replacement**は両方を置換し、**Use for both**は新しい画像を両方へ割り当てます。保存済みGalleryリンクの画像が消えている場合も不足扱いです。編集中に完了した生成結果は、まだ不足している役割だけを埋め、新しい置換画像、参照スイッチ、背景位置、アーカイブ状態、その他の下書き変更を上書きしません。

リンク済みロアの**Open**はマップ作業領域を離れてロアブックを開きます。変更がなければ直接閉じ、未保存変更があれば先に保存するか破棄を明示します。インポートしたロアが有効にならない場合、概要を確認してください。**Map only**には復元できる内容がありません。**Map + linked entries**または**Map + complete lorebooks**を使い、完全一致、曖昧な宛先、別コピーのいずれかを選びます。親にリンクしたロアは子場所へ継承されません。
