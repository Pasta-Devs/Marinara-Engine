# 知識ソース: Knowledge RetrievalとKnowledge Routerエージェント

このガイドでは、Marinara Engineに用意された2つの知識系エージェント、**Knowledge Retrieval**(知識の取得)と**Knowledge Router**(知識の振り分け)を説明します。どちらも、シーンで必要になったときだけロアブックから設定を取り出してチャットに渡します。細かい設定をすべて毎回プロンプトに詰め込む必要はありません。

## 2つのエージェントの役割

ロアブックとは、世界やキャラクターの設定をあらかじめ書きためたものです。1つ1つのメモをエントリーと呼びます。チャットが長くなるほど、毎ターンすべてのエントリーを送るのはトークンの無駄になります。トークンとは、AIが読み取る文章の小さな単位で、数が増えるほど費用も上がります。さらに、全部を送るとAIが混乱することもあります。

知識系エージェントはこの問題をRAGで解決します。RAGはretrieval-augmented generation(検索拡張生成)の略です。今のシーンに合うエントリーだけをアプリが探し出し、そのターンのプロンプトにはそれだけを追加します。

Marinaraでは、次の2つのエージェントを任意で使えます。

- **Knowledge Retrieval**は、選んだソースを読み、重要な内容を要約してプロンプトに追加します。
- **Knowledge Router**は、エントリーの短い一覧を読み、シーンに合うものを選んで、そのエントリーをそのまま追加します。

どちらのエージェントも**Roleplay**チャットでのみ動作します。Conversation ModeやGame Modeでは追加できません。どちらもデフォルトではオフです。使いたいほうを自分でチャットに追加します。

## Knowledge RetrievalとKnowledge Routerの違い

選ぶときはこの表を目安にしてください。決める前に、表の下の説明も読んでください。

| 比較の観点 | Knowledge Retrieval | Knowledge Router |
|---|---|---|
| 内容の追加のしかた | ソースをまず要約する | 選んだエントリーをそのまま追加する |
| 1ターンあたりの費用 | 高め | 低め |
| アップロードしたファイルを読めるか | 読める | 読めない |
| 向いている場面 | ソースが小さいとき、要約をすっきりまとめたいとき | エントリーの説明が充実した大きなロアブック |

**Knowledge Retrieval**は、選んだロアブックの有効なエントリーをすべて読み、アップロードしたファイルの本文も読み込みます。そのうえで、直近のメッセージに合う内容を短くまとめるようAIに依頼します。AIが元の資料を丸ごと読むため、1ターンあたりの費用は高くなります。

**Knowledge Router**は費用を抑えられる選択肢です。エントリーの小さなカタログを作り、1行ごとにID、名前、いくつかのキーワード、短い要約を持たせます。AIはそのカタログを読んでシーンに合うエントリーを選び、Marinaraが選ばれたエントリーを全文で追加します。AIがすべてのエントリーを全文で読むことはないため、大きなロアブックでも費用は低いままです。

1つのチャットに両方のエージェントを追加することもできますが、内容が重複してトークンの費用が増えることがあります。両方を設定するとエージェントエディターが警告を表示します。プロンプトをすっきり保ちたいときは、どちらか一方だけにしてください。

## 知識系エージェントをチャットに追加する

次の操作は**Roleplay**チャットの中で行います。

1. **Chat Settings**(チャット設定)を開きます。
2. **Agents**(エージェント)セクションを探します。
3. **Enable Agents**(エージェントを有効にする)をオンにします。エージェントの一覧が操作できるようになります。
4. **Add Agent**(エージェントの追加)をクリックします。
5. **Writer Agents**(執筆エージェント)のグループを開きます。
6. **Knowledge Retrieval**か**Knowledge Router**を選びます。

設定ウィンドウが開き、その場でソースを選べます。追加が終わると、そのエージェントの設定カードが**Agents**セクションに表示されます。以降は新しいターンごとにエージェントが自動で動きます。

**Knowledge Retrieval**の実行中は、進行状況の表示に**Retrieving knowledge...**というフェーズが出ることがあります。

補足: 既存の返信を再生成するときには、これらのエージェントは動きません。動くのは新しいターンのときだけです。

## Knowledge Retrievalにファイルをアップロードする

アップロードしたファイルを読めるのは**Knowledge Retrieval**だけです。**Knowledge Router**が使うのはロアブックだけです。

**Knowledge Retrieval**の設定には、ファイルの一覧と**Upload file**(ファイルのアップロード)ボタンがあります。アップロードしたファイルは、今のチャットだけでなく、**Knowledge Retrieval**を使うすべてのチャットで利用できます。

対応するファイル形式は.txt、.md、.csv、.json、.xml、.html、.htm、.log、.yaml、.yml、.tsv、.pdfです。それ以外の形式はファイル選択の時点で弾かれます。一覧の各ファイルには名前とサイズが表示され、その隣に削除ボタンが並びます。

次の制限に注意してください。

- PDF以外のファイルはすべてプレーンテキストとして読み込みます。画像の拡張子を.txtに変えたファイルのように、実体がテキストでないものもアップロードはできますが、読めない文字列が中身として追加されます。
- スキャンした画像だけのPDFにはテキスト情報がないため、エージェントは中身を読み取れません。抽出に失敗すると、エージェントは本来の内容の代わりにプレースホルダーを挿入します。文字を選択できるPDFを使ってください。

## ソースの選び方: 固定の上書きとチャットのロアブック

どちらのエージェントも、設定カードにある同じソース選択の項目を使います。

**Use chat-active lorebooks**(チャットで有効なロアブックを使う)トグルはデフォルトでオンです。エージェントエディターでは、同じトグルが**Use this chat's active lorebooks**と表示されます。オンのまま固定のロアブックを選ばなければ、そのチャットで有効になっているロアブックをそのまま使います。

トグルの下にあるのが**Fixed source override**(固定ソースの上書き)です。設定ウィンドウでは**Fixed Source Lorebooks**と表示されます。ここでロアブックを1つ以上選ぶと、エージェントが読むソースをその組み合わせに固定できます。固定した選択は、このエージェントを使うすべてのチャットで、チャット側で有効なロアブックより優先されます。

いつも同じ資料用のロアブックを読ませたいときは、固定ソースを使います。チャットが使っているロアブックに合わせたいときは、トグルをオンにしたまま固定の選択を空にしておきます。

## エントリーの説明の書き方

この節がとくに重要になるのは**Knowledge Router**です。何を追加するかは、各エントリーの**Description**(説明)を読んで決まります。適切なエントリーが選ばれるかどうかは、この説明文しだいです。

説明はロアブックのエントリーエディターにある**Description**欄に書きます。そのエントリーが何を扱うのかを、短く具体的にまとめてください。この文章はエントリーを選ぶためだけに使われ、物語の内容としてメインのAIに送られることはありません。

説明が空のエントリーでは、代わりにエントリー本文の冒頭部分が使われます。この代用は精度が落ちます。見つけてほしいエントリーには、必ず説明を書いてください。

**Knowledge Router**のソースにロアブックを選ぶと、**Fixed source override**の横に小さなカバー率のバッジが表示されます。説明が入力されているエントリーの割合と件数が、たとえば**75% described (9/12)**のように示されます。点の色は75パーセント以上で緑、25から74パーセントで黄色、25パーセント未満で赤になります。選んだロアブックが空のときは**No entries yet**と表示されます。緑を目指してください。

## 任意の機能: 意味による候補の絞り込み

**Knowledge Router**は、キーワードだけでなく意味からも候補のエントリーを探せます。これをセマンティックマッチングと呼びます。この処理にはエンベッダーを使います。エンベッダーとは、意味を比べられるように文章を数値へ変換する小さなモデルです。この機能は任意で、使わなくても**Knowledge Router**は動きます。

有効にするには、ロアブックをベクトル化します。ベクトル化とは、各エントリーに一度だけエンベッダーを実行し、その結果を保存する処理です。ロアブックエディターを開き、**Semantic Search (Embeddings)**(セマンティック検索と埋め込み)セクションを探します。埋め込みモデルを使える接続か、**Embedding Connection**(埋め込み用の接続)を選びます。**Connections**(接続)の**Defaults**(デフォルト)で**Embeddings**(埋め込み)のデフォルトを選んでいる場合は、以前に別のソースを選んでいない限り、それが自動で選ばれます。ベクトル化する前に、選ばれているソースを確認してください。また、チャットで使う接続と同じ埋め込みソースを使ってください。サイズの違うベクトルは、セマンティックマッチングでは使われません。続いて**Vectorize N missing**をクリックします。Nは、まだベクトルがないエントリーの件数です。**Re-vectorize**をクリックすれば、すべてのエントリーをやり直せます。詳しくは、下にリンクしたセマンティック検索のガイドを参照してください。

ロアブックにベクトルがない場合や、使えるエンベッダーがない場合は、キーワードの一致で候補の一覧を作ります。動作が壊れるわけではなく、キーワードだけが手がかりになります。
