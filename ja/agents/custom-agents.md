# カスタムエージェントの作成

このガイドでは、Marinara Engineで独自のエージェントを作る方法を説明します。エージェントとは、チャットの裏で自動的に動く小さなAIヘルパーです。実行フェーズ、権限、出力の種類、起動キーワードと質問、ツール、プロンプトの設定方法が、完成した作例1つとあわせてわかります。

エージェントを使うのが初めての場合は、まず[エージェント: チャットを支えるAIヘルパー](agents-overview.md)で基本を確認してから、このページに戻ってきてください。

## カスタムエージェントが必要になる場面

Marinara Engineには、ダウンロードできる公式のエージェントが多数用意されています。自分で作り始める前に、[ダウンロードできるエージェント一覧](built-in-agents.md)と公開パッケージリポジトリーの[Pasta-Devs/Marinara-Agents](https://github.com/Pasta-Devs/Marinara-Agents)を確認してください。やりたいことがカタログのエージェントですでに実現できるかもしれませんし、公式のマニフェストは動作するパッケージの実例にもなります。

カスタムエージェントを作るのは、組み込みのエージェントでは足りないことをしたいときです。たとえば次のような場合が挙げられます。

- 独自の指示や口調を持つヘルパーを用意したいとき
- すべてのプロンプトに特定のメモを挿入したいとき
- 返信を毎回、決まった文体に書き換えたいとき
- 自作のカスタムツールをエージェントから呼び出したいとき

インストール済みの公式エージェントに近いものがあれば、それをコピーするほうが簡単です。**Agents**(エージェント)パネルでカードにマウスを合わせ、**Copy agent**(エージェントをコピー)をクリックします。これで編集できるカスタムコピーが作られます。

## 始める前に

作り始める前に押さえておきたい点が2つあります。

1. エージェントはキャラクターごとではなく、チャットごとに設定します。ライブラリーでエージェントを作っただけでは動きません。チャットに追加したうえで、**Chat Settings**(チャット設定)の**Enable Agents**(エージェントを有効にする)をオンにする必要があります。
2. カスタムエージェントは、Roleplay、Game Mode、Conversationのどのチャットモードでも動きます。公式パッケージは対応するモードにしか表示されませんが、自作のカスタムエージェントはどこでも使えます。

## カスタムエージェントの作り方

新しいカスタムエージェントを一から作る手順は次のとおりです。

1. **Agents**パネルを開きます。
2. 上部にある**New**(新規)ボタン(プラスアイコン)をクリックします。
3. 空のカスタムエージェントが入った全画面のエージェントエディターが開きます。
4. 上部のタイトル欄に名前を入力します。たとえば`Weather Reporter`のようにします。
5. 何をするエージェントか後から思い出せるように、**Description**(説明)欄と**Author**(作者)欄を記入します。
6. **Pipeline Phase**(実行フェーズ)を選びます(後述)。
7. **Custom Agent Abilities**(カスタムエージェントの権限)で必要な権限をオンにします。
8. エージェントに出力させたい内容に合う**Result Type**(結果の種類)を選びます。
9. **Prompt Template**(プロンプトテンプレート)にエージェントへの指示を書きます。
10. 上部バーの**Save**(保存)をクリックします。緑色の**Saved**バッジが表示されます。

作成したエージェントは、**Agents**パネルの**Custom Agents**(カスタムエージェント)セクションに表示されます。使うときは、チャットを開いて**Chat Settings**に移動し、**Enable Agents**をオンにしてから、そこにある**Custom Agents**セクションでエージェントを追加します。

## Pipeline Phase

**Pipeline Phase**は、エージェントが動くタイミングを決めます。3つのボタンから1つを選びます。

- **Pre-Generation**: AIが返信する前に動きます。コンテキストを追加したり、プロンプトを変更したりできます。
- **Parallel**: 返信の生成と同時に動きます。完成した返信は見えません。
- **Post-Processing**: 返信が完成したあとに動きます。返信を読めるほか、一部の結果の種類では返信を編集できます。

結果の種類によっては、フェーズが自動的に決まります。**Text Rewrite**を選ぶと、フェーズは**Post-Processing**に切り替わります。**Prompt Patch**を選ぶと、フェーズは**Pre-Generation**に切り替わります。これらの処理は、そのフェーズでしか意味を持たないためです。

Post-Processingのカスタムエージェントには、**Turn Data Access**(ターンデータへのアクセス)セクションも表示されます。ここには**Pre-generation injections**と**Parallel agent results**という2つの任意のトグルがあります。オンにすると、同じターンで他のエージェントが生成した内容を読めるようになります。オフのままにすれば、エージェントは他から独立して動きます。

## Custom Agent Abilities

**Custom Agent Abilities**は、明示的にオンにしたときだけ使える権限です。トグルをオンにするまで、その権限はブロックされたままです。この仕組みによって、カスタムエージェントはデフォルトで安全に保たれます。用意されている権限は次のとおりです。

| 権限 | エージェントにできるようになること |
|---|---|
| **Create lorebooks** | ロアの出力に対象が指定されていないとき、エージェント用のロアブックを新しく作ります。 |
| **Edit lorebooks** | ロアブックのエントリーを書き込んだり、ロアブックの更新結果を作ったりします。 |
| **Edit messages** | 生成されたメッセージのテキストを書き換えた文章に差し替えたり、続きの選択肢を追加したりします。 |
| **Edit trackers** | ゲーム、キャラクター、ペルソナ、カスタムの各トラッカーの状態を更新します。 |
| **Frontend styling** | 生成中に一時的な視覚効果を適用します。 |
| **Change chat backgrounds** | チャットに選ばれている背景を変更し、そのまま保存します。 |
| **Change character sprites** | チャットに表示されるキャラクターとペルソナの表情を変更します。 |
| **Control media playback** | Spotify、YouTube、手元の音楽の再生を操作します。 |
| **Control haptic devices** | 接続されたハプティックデバイスに、範囲を限定したコマンドを送ります。 |
| **Edit About Me details** | チャットごとの**About Me**(自己紹介)のテキストを変更します。公開されるカードの変更には、別途承認が必要です。 |
| **Image generation** | 画像プロンプトを渡して画像生成を実行します。 |
| **Vectors/embeddings** | ベクトルや埋め込みのコンテキストを使います。ベクトルとは、意味からテキストを検索する仕組みです。 |
| **Main prompt edits** | メインのAIモデルに送るプロンプトを編集します。 |

ロアブックとは、AIがシーンに応じて引き出せる背景設定のメモをまとめたものです。トラッカーとは、能力値、気分、現在地といった情報を保持して表示するパネルです。

**Edit lorebooks**をオンにすると、**Lorebook Writer**(ロアブックへの書き込み)セクションが表示されます。**Allow lorebook entry writes**をオンにして、**Target lorebook**ドロップダウンでロアブックを1つ選びます。エージェントが書き込めるのは、そのロアブックだけです。

## Result Type

**Result Type**は、エージェントの出力をMarinaraがどう読み取るかを決めます。ほとんどの結果の種類では、エージェントがJSONを返すことを前提にしています。JSONは波括弧と引用符で書く、単純なテキスト形式です。どの結果の種類にも、上の表にある対応する権限が必要です。

| 結果の種類 | 動作 | 必要な権限 |
|---|---|---|
| **Context Injection** | 生成前にテキストを追加するか、生成後にメモを記録します。 | なし |
| **Text Rewrite** | 返信のあとに動き、メッセージのテキストを置き換えます。 | Edit messages |
| **Lorebook Update** | ロアブックのエントリーを作成または更新します。 | Edit lorebooks |
| **Character Tracker** | キャラクタートラッカー(その場にいるキャラクター)を更新します。 | Edit trackers |
| **Persona Stats** | ペルソナの能力値、状態、インベントリーを更新します。 | Edit trackers |
| **Custom Tracker** | 自作のカスタムトラッカーの項目を置き換えます。 | Edit trackers |
| **Game State** | 世界の状態にあたるゲームデータを更新します。 | Edit trackers |
| **Image Prompt** | 画像生成にシーンを描かせます。 | Image generation |
| **Prompt Patch** | プロンプトのセクションを追加、先頭に挿入、または置き換えます。 | Main prompt edits |
| **Frontend Style** | 一時的なスタイル効果を適用します。 | Frontend styling |
| **Background Change** | 使えるチャット背景を選び、そのまま保存します。 | Change chat backgrounds |
| **Sprite Change** | チャットに表示されるキャラクターとペルソナの表情を変更します。 | Change character sprites |
| **Spotify Control** | Spotifyの再生を操作します。 | Control media playback |
| **YouTube Control** | YouTubeの再生を操作します。 | Control media playback |
| **Local Music Control** | 手元の音楽コレクションの再生を操作します。 | Control media playback |
| **Haptic Command** | 接続されたハプティックデバイスに、範囲を限定したコマンドを送ります。 | Control haptic devices |
| **About Me Update** | チャットごとの**About Me**のテキストを更新し、公開用の変更を提案します。 | Edit About Me details |
| **Interactive Choices** | 生成されたメッセージに続きの選択肢を追加します。 | Edit messages |

いちばん扱いやすい出発点は**Context Injection**です。権限のトグルも、厳密な出力形式も必要ありません。プロンプトに短いメモを足したいとき、要約を記録したいときに使います。

結果の種類がグレーアウトしている場合は、その権限がまだオンになっていません。**Custom Agent Abilities**で対応するトグルをオンにすると、選べるようになります。

### 画像エージェントのチャット別コントロール

**Image generation**能力を持つエージェントでは、すべてのカスタムエージェントにあるプロンプトテンプレート選択に加え、**Chat Settings → Agents → Custom Agents**のカードに2つのコントロールが表示されます。

- **Image Connection** — このチャットでのみ、エージェントが使う画像接続を上書きします。エージェント自身の設定にある接続を使うには**Agent default**のままにします。チャット単位の**Image Style**もカスタムエージェントの画像へ適用されるため、エージェントを複製せずチャットごとに異なる描画ができます。
- **Camera button** — 有効化キーワードを待たず、今すぐそのエージェントで画像を生成します。プロンプトを書くのは引き続きエージェントです。テンプレートがプロンプトを生成しなかった場合は、画像の代わりにエラートーストが表示されます。

## Activation Keywords

カスタムエージェントは、デフォルトでは通常の周期で動きます。**Activation Keywords**(起動キーワード)を設定すると、場面が関係ないときはエージェントを動かさずに済みます。これでトークンの消費と費用を抑えられます。トークンとは、AIが数える文章の小さなまとまりです。

設定の手順は次のとおりです。

1. **Activation Keywords**セクションに、キーワードやフレーズを1行に1つずつ入力します。たとえば次のように書きます。

```
tavern
secret door
moonlit ritual
```

2. **Scan Depth**(検索する深さ)には、さかのぼって検索する直近のメッセージ数を設定します。デフォルトは5、最大は200です。
3. これで、指定した数の直近メッセージにキーワードが1つ以上現れたときだけエージェントが動きます。

キーワード欄を空にすると、キーワードフィルターが無効になります。頻度と起動質問は引き続き適用されます。

## 起動質問

**Activation question**(起動質問)は、最近の場面でカスタムエージェントが必要かを尋ねます。例は`In the latest message, the characters move to a different location.`です。キーワードでは拾えない言い換えも認識できます。空のままなら既存の動作を保ちます。

回答するのは**Decision model**(判定モデル)です。Connectionsパネルの**Decision model**で、すでに動かしているローカルモデル、ホスト型Decision接続、Marinaraがインストールする判定モデルから選びます。[Decisionモデル](../connections/decision-models.md)では、各方式、選び方、設定方法を説明しています。デフォルトの**None**(なし)では、エージェントエディターの質問欄は無効のままになり、質問があるエージェントも質問がない場合と同じように実行されます。

### エージェントの設定

起動質問またはプロンプト内に判定文があるエージェントをインポートすると、Decisionモデルのガイドへの通知が表示されます。Decisionモデルが未選択の場合、起動質問はキーワードと**Trigger Cadence**(起動頻度)が許せば実行を通し、プロンプトの判定文はいいえとなって`{{else}}`分岐を使うことを説明します。Decisionモデルがないときに毎ターン実行させたくない場合は、頻度も設定してください。Agentカタログからパッケージをインストールするときも同じ通知が表示されます。

Decisionモデルを選択した状態でカスタムエージェントを開き、最大500文字の**Question**(質問)を入力します。`{{user}}`や`{{char}}`などの標準エージェントマクロを使えます。**Scan Depth**はキーワードと質問の両方が参照する最近のメッセージ数を制御します。

欄の名前は質問ですが、疑問文ではなく、最新のメッセージについての事実を述べる文にしてください。テストでは、小型判定モデルは`Did the scene change?`より`The latest message moves the scene to a new place.`のほうが安定して答えました。プロンプト内の判定文と同じ助言が当てはまります。[判定文の書き方](../prompts/conditional-prompts.md#writing-statements)を参照してください。

- **Run when probability is at least**(実行に必要な最小確率)は、このエージェントのしきい値です。「はい」の確率がその値以上なら実行します。高くすると実行を省く回数が増えます。エディターの推奨値は、ローカルチャットモデルとDecision接続では0.5、管理対象サイドカーではマニフェストの値(組み込みOpen-Jevは0.1)です。独自エンドポイントにはモデル別の校正が自動適用されません。特にモデル変更後は、自分のチャットでしきい値を確認してください。変更の対象はこの起動質問で、エージェントのプロンプト内の判定文ではありません。[しきい値](../connections/decision-models.md#thresholds)を参照してください。
- **Bypass the question after this many messages without a successful run**(指定メッセージ数の間に実行が成功しなければ質問を省略)は任意です。前回の正常実行からユーザー・アシスタントのメッセージが指定数進むと、質問を省略します。有効なら、新しいエージェントや前回のメッセージが削除されたエージェントも質問を省略します。キーワードと頻度は引き続き実行を許可する必要があります。重要なエージェントには設定を検討してください。どのモデルも間違うことがあり、「いいえ」が続いて永遠に実行されなくなるのを防げます。
- 生成前・並行エージェントは返信前の会話を使います。後処理エージェントは完成した返信も読みます。

キーワードと頻度を先に確認するため、すでに省かれたエージェントは有料の判定リクエストを行いません。同じスキャン深度の質問をフェーズごとにまとめます。時間切れ、モデルの利用不可、無効な回答の場合、該当エージェントは通常どおり実行できます。時間枠はDecision接続の**Time limit**(デフォルト1.5秒)、ローカルモデルは4秒、先に推論が必要なら20秒です。生成をキャンセルすると判定リクエストも中止します。通常のログはチャット内容を省き、デバッグ用プロンプトログには評価したメッセージと質問を含めます。

この設定はカスタムエージェントに適用されます。組み込みエージェントの起動とキャラクターの活動評価は既存の動作を保ちます。

### エージェントのプロンプト内の判定文

起動質問はエージェントの実行を決めます。**Prompt Template**内の判定文は、実行中のエージェントに何を伝えるかを決めます。両方が同じDecisionモデルを使い、構文は[条件付きプロンプト](../prompts/conditional-prompts.md#asking-the-decision-model)と同じです。

```
{{#if decision:"In the latest message, the characters move to a different location"}}
Update the location field.
{{else}}
Leave the location as it is.
{{/if}}
```

組み合わせると、何も起きないターンを丸ごと省き、実行するターンにも小さなプロンプトを送れます。例:

- トラッカーは毎ターン場所を導き直さず、場所が変わったときだけ更新指示を含めます。
- 画像エージェントは場面の見た目が変わったときだけ、新しい画像を記述します。
- 音楽エージェントには、雰囲気が変わったときだけ曲を変えるよう伝えます。
- 複数の指示群を選択で切り替えます。`{{#if decision_choice:"The kind of scene in the latest message" == "combat"}}`、`{{else if decision_choice:"The kind of scene in the latest message" == "dialogue"}}`などです。

実行の仕組み:

- 生成前・並行エージェントはメインプロンプトと同じ返信前のターンを読み、回答を共有します。後処理エージェントは完成した返信を最新のメッセージとして読み、それを含めて判定文を再度問い合わせます。
- トラッカーの更新ボタン、失敗したエージェントの再試行、注入の**Re-run**(再実行)などでは、同じターン、モデル、判定文の正常な回答がまだキャッシュにあれば再利用します。失敗した回答は再試行でき、サーバー再起動、キャッシュからの除外、入力変更でも新しいリクエストが発生する場合があります。[回答の再利用](../prompts/conditional-prompts.md#answer-reuse)を参照してください。
- エージェントのプロンプトでは、`{{char}}`はチャット内の全キャラクターを一度に表すため、グループの`{{char}} is angry`は「Kaelen, Alyssa is angry」になります。キャラクター名を指定するか、「あるキャラクター」と書いてください。
- 回答がなければ判定文はいいえとなります。Decisionモデルを持たない利用者も多いため、`{{else}}`分岐でも妥当な動作をする必要があります。

Marinara-Agentsからインストールしたエージェントも同じ方法でプロンプトテンプレートを処理するため、判定文を利用できます。

## ツールの追加(Function Calling)

エージェントはツールを呼び出せます。ツールとは、AIが実行して何かを取得したり変更したりし、その結果を読み取れる関数のことです。function calling(関数呼び出し)とも呼ばれます。

ツールを追加するには、**Tools / Function Calling**セクションを開き、各ツールのトグルをオン、オフで切り替えます。一覧には組み込みのツールと、自分で作ったカスタムツールが並びます。自分でツールを作る方法は[カスタムツール](../extending/custom-tools.md)を参照してください。

ツールが動くのは、チャット側で許可されている場合だけです。**Chat Settings**の**Function Calling**セクションを開き、**Enable Tool Use**(ツールの使用を有効にする)をオンにします。このチャット設定がオフのままだと、ここでトグルをオンにしてもエージェントのツールは使えません。

インポートしたエージェントのファイルに、ツールの利用権限は付いてきません。エージェントをインポートしたら、プロンプトと設定を確認したうえで、使わせたいツールを自分で選んでください。

## Named prompt options

1つのエージェントに、複数のプロンプトの候補を持たせられます。これが**Named prompt options**(名前付きプロンプト)機能です。チャット側では、エージェント本体を編集しなくても候補を1つ選べます。

候補を追加する手順は次のとおりです。

1. **Prompt Template**の下にある**Named prompt options**を開きます。
2. **Add option**(候補の追加)をクリックします。
3. 候補に名前と短い説明を付けます。
4. その候補で使うプロンプト本文を最後まで書きます。

このエージェントをチャットに追加すると、名前付きの候補が並ぶ**Prompt Mode**(プロンプトモード)ドロップダウンが表示されます。候補を1つも追加していない場合は、チャットのメニューにデフォルトのプロンプトだけが表示されます。

## 調整できるその他の設定

カスタムエージェントには、組み込みのエージェントと共通の設定もあります。

- **Connection Override**(接続の上書き): このエージェントだけ別のAI接続を使います。たとえば、裏方の処理には安価なモデルを使うといった具合です。空のままにすると、チャットの接続を使います。
- **Agent Budget**(エージェントの割り当て): **Context Size**(コンテキストの長さ)で、エージェントが読む直近のメッセージ数を設定します(デフォルトは5)。**Max Output Tokens**(最大出力トークン)では、出力用に確保する枠を設定します(デフォルトは4096、範囲は128から32768まで)。
- **Add as Prompt Section**(プロンプトセクションとして追加): オンにすると、エージェントの最新の出力を、プロンプトプリセットに挿入できるセクションとして使えます。

**Prompt Template**の中では`{{user}}`や`{{char}}`などのマクロが使えます。一覧は[マクロ](../prompts/macros.md)を参照してください。

## 作例

ここでは、返信をすべてイギリス英語に書き換えるカスタムエージェントの完成例を紹介します。

エディターでの設定:

1. 名前を`British English Editor`にします。
2. **Custom Agent Abilities**で**Edit messages**をオンにします。
3. **Result Type**で**Text Rewrite**を選びます。フェーズは自動的に**Post-Processing**へ切り替わります。
4. **Prompt Template**に次の内容を貼り付けます。

```
You are a copy editor. Rewrite the latest reply into British English.
Change spelling and vocabulary only. Do not change the meaning, tone, or events.
Return JSON with an "editedText" field holding the full rewritten reply,
and a "changes" array of short notes describing what you changed.
```

5. **Save**をクリックします。
6. Roleplayのチャットを開き、**Chat Settings**で**Enable Agents**をオンにして、**Custom Agents**セクションから`British English Editor`を追加します。

このエージェントは、返信のたびに次のようなJSONを返します。

```
{"editedText":"The colour of the harbour caught her eye.","changes":[{"description":"color to colour, harbor to harbour"}]}
```

Marinaraは`editedText`を読み取り、返信と差し替えます。メッセージはイギリス英語で表示されます。`changes`のメモは、エージェントが直した内容の短い要約として表示されます。

## エージェントのインポートとエクスポート

カスタムエージェントは、ファイルとして共有できます。

エディターから書き出すには、上部バーの**Export agent**(エージェントのエクスポート)ボタン(アップロードアイコン)をクリックします。エージェントのプロンプトと設定がパッケージとして保存されます。エージェントのパッケージにカスタムツールの定義が含まれることはありません。

複数のエージェントをまとめて書き出すには、**Agents**パネルの**Select agents**(エージェントの選択)を使い、対象のエージェントを選んでまとめてエクスポートします。

外部のエージェントのインポートは、デフォルトでロックされています。まず**Settings → Advanced → Danger Zone**を開き、**Allow custom Agent imports**(カスタムエージェントのインポートを許可)を有効にします。このトグルに`.env`の変更は必要ありません。対象になるのは、ファイル、フォルダー、カスタムリポジトリーから取り込むエージェントだけです。Marinaraで自分が作ったエージェントと、**Download Agents**でインストールした公式エージェントは、これまでどおり使えます。

インポートするには、**Agents**パネルを開き、ファイル1つなら**Import agents**(エージェントのインポート)、フォルダーごとなら**Import agent folder**(エージェントフォルダーのインポート)をクリックします。保存の前に、Marinaraが権限の確認画面を表示します。承認するのは、そのエージェントに必要な機能だけにしてください。チェックを外した機能はブロックされたままです。ファイルからのインポートには毎回新しいカスタムの識別子が割り当てられるため、同じ内部タイプを持つ公式エージェントを置き換えてしまうことはありません。

安全のため、Marinaraは同梱された関数を無視し、インポートした設定からツールの選択を消去し、一時的なCSSを無害化してから適用します。さらに、インポートしたエージェントがメッセージ、トラッカー、ロアブック、背景、スプライト、メディア、ハプティクス、About Meのデータ、プロンプト、生成画像を変更する前に、承認済みの機能かどうかを確認します。信頼できる関数は**Function Calls**から別途インポートし、内容を確認したうえで、あらためてエージェントに明示的に紐付けてください。Danger Zoneのトグルをオフに戻すと、外部からインポートしたエージェントは動かなくなります。自分で作ったエージェントと公式エージェントには影響しません。
