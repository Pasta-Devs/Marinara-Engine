# エージェントの承認とAgent Suite

エージェントは、ロアブックのエントリー、要約、キャラクターカードの編集といった形で、チャットに書き込むことがあります。このガイドでは、そうした書き込みを保存前に確認する方法と、エージェントが保存した内容を**Agent Suite**(エージェントスイート)で確認して直す方法を説明します。

## 保存前にエージェントの書き込みを確認する

デフォルトでは、エージェントの書き込みの一部は自動的に保存されます。**Review Agent Outputs**(エージェント出力の確認)は、それぞれの書き込みに承認を待たせます。

1. チャットを開き、**Chat Settings**(チャット設定)をクリックします。
2. **Agents**(エージェント)セクションまでスクロールします。
3. Roleplayのチャットでは、**Trackers Control**(トラッカーの管理)を開きます。Gameでは、この手順を飛ばします。
4. **Review Agent Outputs**をオンにします。

オンのときは、ロアブックの更新、要約の更新、そのほか確認の対象になる書き込み系エージェントの出力が、承認を待ちます。オフのときは、ロアブックと要約の更新が自動的に保存されることがあります。

キャラクターカードの編集は、**Review Agent Outputs**がオフでも、必ず先に承認を求めます。この確認はオフにできません。

### ロアブックや要約の更新を確認する

エージェントが書き込みを提案すると、**Review Lorebook Update**または**Review Summary Update**というタイトルのウィンドウが開きます。ウィンドウには、エージェントの名前と、編集できる**Proposed Text**(提案されたテキスト)欄が表示されます。ロアブックへの書き込みでは、各エントリーを`###`見出しの下に置くよう注意書きも表示されます。

- **Accept**(承認)は、編集した内容も含めてテキストを保存します。
- **Regenerate**(再生成)は、そのエージェントだけをもう一度動かし、新しい提案を作らせます。
- **Discard**(破棄)は、提案を保存せずに捨てます。

ほかにも提案が待っている場合は、その件数がウィンドウに表示されます。今の提案を処理すると、次の提案のためにウィンドウが開き直します。

**Create character cards**(キャラクターカードの作成)の能力を持つエージェントは、新しいキャラクターカードを提案することもできます。その場合は、カードのテキストを表示する確認ウィンドウが開きます。承認するまで何も保存されません。

### キャラクターカードの更新を確認する

**Card Evolution Auditor**エージェントは、ロールプレイで起きたできごとをもとに、キャラクターカードへの編集を提案します。Conversationでは、組み込みの`update_about_me`ツールも、公開されるAbout Meの変更を提案できます。どちらもカードを勝手に書き換えることはありません。どちらも**Review Character Card Updates**ウィンドウを開きます。

提案された編集ごとに、ウィンドウには対象となるカードの項目、エージェントが理由を付けている場合はその短い説明、現在のテキストを示す**Before**(変更前)ブロック、編集できる**After**(変更後)欄が表示されます。

- **Approve**(承認)は、編集を反映します。ボタンの中の数字は、反映される編集の件数です。適用するとキャラクターのバージョン番号が上がり、バージョン履歴のエントリーが保存されます。
- **Regenerate**(再生成)は、エージェントをもう一度動かし、新しい提案を作らせます。
- **Reject**(却下)は、カードを変更せずに提案を取り下げます。

エージェントが提案を書いたあとでカードが変わっていた場合、その編集は古くなったものとして示され、薄く表示されます。そのときは、件数の付いた**Override stale**(古い編集を強制的に適用)ボタンが現れます。それでもそのテキストがほしいときだけ使ってください。Marinaraは確認を求めたうえで、一致しなくなったテキストを置き換えるのではなく、古くなったテキストを項目に追加します。

## エージェントが保存した内容を表示・編集する

**Agent Suite**(エージェントスイート)は、このチャットのエージェントが保存しているものをすべて表示します。トラッカーのデータ(現在のシーン、その場にいるキャラクター、ペルソナの状態値など)と、カスタムエージェントの保存済み出力です。間違った名前を直したり、状態値を修正したり、乱れたテキストを整えたりするのに使います。

1. **Chat Settings**を開き、**Agents**までスクロールします。
2. **Agent Suite**をクリックします。
3. 左側の一覧からエージェントを選びます。

右側には、編集できるブロックが最大3つのグループに分かれて表示されます。**Stored Memory**(保存された記憶)、**Tracker Data**(トラッカーのデータ。トラッカーのエージェントのみ)、**Recent Outputs**(最近の出力。カスタムエージェントのみ)です。データを追跡しないエージェントでは、**Stored Memory**だけが表示されます。

各ブロックはテキストまたはJSONのエディターです。JSONブロックには行番号が付き、不正なJSONはすぐに知らせます。解析できるようになるまで**Save**(保存)は押せません。すべてのトラッカーデータを検索したり、フィールドとして編集したりするには、**Tracker Data**のヘッダーで**Open in State Editor**をクリックします。[State Editor](../roleplay/hud-and-trackers.md#the-state-editor)を参照してください。

ブロックを変更したあとは、残すなら**Save**を、保存済みの値に戻すなら**Reset**(リセット)をクリックします。

### ブロックをAIに書き換えさせる

1. ブロックの**AI Edit**(AIで編集)をクリックします。
2. 一部だけを変更するには、先にそのテキストを選択します。何も選択しないと、ブロック全体が書き換わります。
3. 指示を入力します。たとえば「文字化けしたキャラクター名を直して。彼女の名前はMiraです」のように書きます。
4. 任意: **Add Context**(コンテキストの追加)をクリックして、キャラクターカードやロアブックのエントリーを添えます。データの意味をAIが理解できるようになります。
5. 書き換えを実行する接続(AIのサービスとモデル)を選びます。
6. **Rewrite**(書き換え)をクリックします。

結果は、保存されていない下書きとしてブロックに入ります。内容を確認し、**Save**か**Reset**をクリックします。

- このチャットでエージェントがまだ動いている間は、保存はエージェントが終わるまで待ちます。
- **Clear memory**(記憶の削除)は、エージェントが保存したデータがあるときだけ**Stored Memory**に表示されます。そのエージェントがこのチャットで保存したものをすべて一度に削除し、取り消せません。Marinaraはまず確認を求めます。
- **Narrative Director**では、保存されたネタバレが隠されています。表示して編集するには、**Reveal spoilers**(ネタバレの表示)を使います。

## キャッシュされたプロンプト挿入を見る

返信が生成される前に、一部の書き込み系エージェントがプロンプトにテキストを追加します。**Prose Guardian**、**Narrative Director**、独自の挿入用エージェントでよく起こります。**Cached prompt injections**(キャッシュされたプロンプト挿入)パネルには、直近の返信で追加されたそのテキストが表示されます。トラブルシューティング用の画面です。

始める前に: **Debug mode**(デバッグモード)をオンにします([エージェント: チャットを支えるAIヘルパー](agents-overview.md#tell-whether-an-agent-ran)を参照)。Roleplayのチャットで、**Agent activity**(エージェントの動作)の**Injections**タブを開きます。[Agent activity](../roleplay/getting-started.md#agent-activity)を参照してください。

挿入ごとに、展開してテキストを読んで編集したり、**Save**アイコンをクリックして編集を残したり、**Re-run**(再実行)アイコンをクリックしてそのエージェントに新しい挿入を書かせたりできます。

**Knowledge Retrieval**と**Knowledge Router**の挿入は、ここでは再実行できません。編集と再実行が反映されるのは、同じ返信を再生成した場合だけです。再実行では、その時点までのチャット履歴が使われ、それより新しいメッセージは使われません。
