# よくある質問

このガイドでは、Marinara Engineについて特に多く寄せられる質問に答えます。回答はトピックごとにまとめてあります。詳しく知りたいときは、各回答から詳細ガイドへ移動できます。

## スマートフォンやほかのデバイスからMarinara Engineを使うには?

Marinara Engineは1台のコンピューターでローカルサーバーとして動き、ブラウザーから開いて使います。ここでは、同じネットワーク上のスマートフォン、タブレット、ほかのコンピューターからアクセスする方法を説明します。

起動スクリプト(`start.sh`、`start.bat`、`start-termux.sh`)は、最初からすべてのネットワークインターフェイス(`0.0.0.0`)で待ち受けるように設定してあります。ネットワーク上のほかのデバイスからもサーバーに届きますが、デフォルトではアクセス制御がブロックします。ホストのコンピューターでアクセスを設定するまで、離れたデバイスには設定手順を載せた**Access blocked**ページだけが表示されます。

次の手順で設定します。

1. ホストのコンピューターでMarinaraを起動したままにします。
2. ホストのコンピューターでアクセス制御を設定します。方法はBasic Auth(ユーザー名とパスワード)か、IP許可リスト(信頼するデバイスのアドレスの一覧)です。[リモートアクセス](REMOTE_ACCESS.md)では、完全に信頼できるプライベートネットワーク向けの回避方法も含めて、それぞれの選択肢を順に説明しています。
3. ホストのコンピューターのローカルIPアドレスを調べます。Windowsでは次のコマンドを実行し、**IPv4 Address**の値を読み取ります。

```
ipconfig
```

macOSとLinuxでは次のコマンドを実行します。

```
hostname -I
```

4. ほかのデバイスでブラウザーを開き、ホストのIPアドレスに続けてポート番号を入力します。デフォルトのポートは`7860`です。

```
http://192.168.1.42:7860
```

`192.168.1.42`は自分のホストのIPアドレスに置き換えます。

5. ブラウザーがBasic Authのユーザー名とパスワードを求めたら入力します。代わりに**Access blocked**ページが表示される場合は、先にホスト側で手順2を終わらせてください。

通常のデスクトップインストールでは、同じコンピューター(`127.0.0.1`)からのアクセスにパスワードは要りません。APKが管理するAndroidインストールでは、ほかのAndroidアプリがMarinaraになりすますのを防ぐため、localhostに非公開のログインを追加しますが、その認証情報はAndroidラッパーが自動で作成して使います。ほかのデバイスは、アクセス制御(Basic AuthかIP許可リスト)を設定するまでブロックされます。それぞれの方法は[リモートアクセス](REMOTE_ACCESS.md)で説明しています。

2台が同じネットワークにない場合は、Tailscaleのようなツールが役に立ちます。Tailscaleは各デバイスに固定のプライベートアドレスを割り当てます。これでMarinaraをインターネットに公開せずに、どこからでも接続できます。接続できないときは[トラブルシューティング](TROUBLESHOOTING.md)を参照してください。

## Marinaraのモバイルアプリはありますか?

専用のネイティブモバイルアプリはありません。スマートフォンやタブレットでも、ブラウザーで同じWebアプリを使います。多くのモバイルブラウザーには**Add to Home Screen**(ホーム画面に追加)や**Install App**(アプリをインストール)の機能があり、これを使うとアドレスバーが消えて本物のアプリのような使い心地になります。この仕組みをPWA(Progressive Web App、アプリのようにインストールできるWebサイト)と呼びます。

Androidでは、[最新のAPKを直接ダウンロード](https://github.com/Pasta-Devs/Marinara-Engine/releases/latest/download/marinara-engine-android.apk)することもできます。Termuxを通じてスマートフォン内でMarinaraが動きます。インストールに署名キー、パスワード、ローカルアクセス用シークレットは必要ありません。Androidの権限確認については[Android(Termux)インストールガイド](installation/android-termux.md)を参照してください。iPhoneとiPadについては[iOS / iPadOS PWAガイド](installation/ios-pwa.md)を参照してください。

Androidラッパーは、APKが管理するTermuxサーバーを開くと自動的にログインします。非公開の認証情報が見えるのは、同じスマートフォンの別のブラウザーで意図的にサーバーを開く場合だけです。`/android-login`を開き、Termuxで`cat ~/.marinara-engine/android-secret`を実行して、表示された値を貼り付けます。ローカルの`mari` CLIも、ランチャーが管理する同じシークレットを自動で読み込みます。手動のTermuxインストールでは、localhostとネットワークアクセスに通常の規則が適用されます。

## 3つのチャットモードとは?

Marinaraには3つのチャットモードがあり、チャット一覧を開くとタブとして並びます。

- **Conversation**: メッセージアプリでキャラクターにメッセージを送るような、テキストメッセージ形式のチャットです。
- **Roleplay**: 語りの文章、キャラクターのアバター、任意のキャラクターアートを伴う、没入感のある物語のシーンです。
- **Game Mode**: ゲームマスターが進行するテキストアドベンチャーです。シーンの画像や動画を付けることもできます。

各モードには専用の入門ガイドがあります。まず使いたいモードから始めて、そのあと詳細ガイドへ進んでください。

## Conversationのスケジュールで使うタイムゾーンを変更するには?

Conversationを開き、**Chat Settings**(チャット設定)で**Schedule timezone**(スケジュールのタイムゾーン)を選びます。Conversationの初期設定でスケジュールを作るときにも選べます。Marinaraは最初、デバイスが報告するタイムゾーンを使いますが、対応しているIANAタイムゾーンなら自由に選べますし、**Use device**(デバイスに合わせる)を選べば元に戻せます。これはすべてのConversationチャットに共通する設定です。サーバー側から自動で送られるメッセージにも適用され、同じMarinaraサーバーにつながっているほかのデバイスにも同期します。

## Marinaraを使うにはAPIキーが必要ですか?

ほとんどの場合は必要です。**接続**とは、1つのAIサービスへ到達する方法をまとめて保存したものです。どのプロバイダーか、どのモデルか、そのサービスへのログイン情報が含まれます。**APIキー**は、パスワードのような秘密の文字列です。AIプロバイダーから受け取ると、Marinaraがそのプロバイダーに接続できるようになります。

チャットを始めるには接続が1つ以上必要です。作成するには、**Connections**(接続)パネルを開き、**New**(新規)をクリックし、プロバイダーを選び、**API Key**欄にAPIキーを貼り付けて、モデルを選びます。手順の詳細は[AIプロバイダーへの接続](connections/connecting-to-a-provider.md)を参照してください。

APIキーをまったく使わないプロバイダーもいくつかあります。サブスクリプション方式の選択肢(Claude、ChatGPT、Grok)はコマンドラインツールでログインします。組み込みのLocal Modelは、キーなしで自分のコンピューター上で動きます。

## 対応しているAIプロバイダーは?

Marinaraは多くのプロバイダーに対応しています。1つの接続につき1つのプロバイダーを選びます。

チャットとロールプレイの文章生成では、**OpenAI**、**OpenAI (ChatGPT)**、**Anthropic**、**Claude (Subscription)**、**Grok CLI (Subscription)**、**Google Gemini**、**Google Vertex AI**、**Mistral**、**Cohere**、**OpenRouter**、**NanoGPT**、**xAI / Grok**、そしてOllama、LM Studio、KoboldCppなどローカルや自前のサーバーで動かすモデル向けの**Custom (OAI-Compatible)**から選べます。

画像生成では、**OpenAI (DALL-E)**、**Stability AI**、**Together AI**、**NovelAI**、**OpenRouter Images**、**xAI / Grok Imagine**、**Venice.ai**、**Atlas Cloud**、**Pollinations**、**Stable Horde**、**SD Web UI (AUTOMATIC1111 / Forge)**、**ComfyUI**、**RunPod Serverless (ComfyUI)**、**Draw Things**、**NanoGPT**、**Block Entropy**などが選べます。

動画生成では、**Google AI Studio**、**xAI Imagine**、**OpenRouter Video**、**Atlas Cloud**、**Seedance 2.0**、そしてローカルの**ComfyUI**のAPI形式ワークフローから選べます。

接続はいくつでも保存でき、チャットごとに別の接続を割り当てられます。[AIプロバイダーへの接続](connections/connecting-to-a-provider.md)を参照してください。

## Marinaraの利用にお金はかかりますか?

Marinara自体は無料で、自分のコンピューター上で動きます。費用がかかるのは選んだAIプロバイダーの料金で、金額はプロバイダーとモデルによって変わります。

無料で試せる選択肢もあります。**Pollinations**の画像生成にキーは要りません。**Stable Horde**は無料で、キーは処理を優先してもらいたいときだけ使います。組み込みの**Local Model**も、キーなしで自分のコンピューター上で動きます。サブスクリプション方式の選択肢(Claude、ChatGPT、Grok)は、従量課金のAPIキーではなく、すでに契約している有料プランを使います。

## APIキーは安全ですか?

はい。APIキーはすべてAES-256で暗号化してからディスクに保存します。接続とプロファイルのエクスポートでは、
秘密の値を取り除きます。フルバックアップだけは扱いが異なります。暗号化されたレコードと、それを復号する
ための暗号鍵ファイル(ある場合)が含まれるので、フルバックアップのZIPは他人の目に触れないように保管してください。

プロファイルのインポートは意図的に秘密の値を除外します。そのため、プロファイルをインポートしたあとは
APIキーを1つずつ入力し直す必要があります。フルバックアップのZIPに**Import Profile**(プロファイルのインポート)を
使った場合も同じです。データフォルダーごと手動で復元する場合は、対応する暗号鍵ファイルもいっしょに戻せば、暗号化されたキーはそのまま使えます。

## キャラクターカードとは?

**キャラクターカード**は、AIキャラクターの設定を保存したものです。名前、アバター、性格、背景の設定、挨拶メッセージが含まれます。カードの作成と編集は**Character Editor**(キャラクターエディター)で行います。ほかのアプリで作ったカードをインポートすることもできます。[キャラクターの作成と編集](characters/creating-and-editing-characters.md)を参照してください。

## ロアブックとは? 複数のキャラクターで使うには?

**ロアブック**は、世界の設定を書いたエントリーの集まりです。各エントリーは、キーワードがチャットに現れたときだけプロンプトに情報を追加します。おかげでトークンを節約でき、設定の一貫性も保てます。1つのロアブックの適用範囲を決める方法は3つあります。用途に合うものを選んでください。

1. キャラクターやペルソナに紐付けます。ロアブックエディターで**Linked Characters**(紐付けるキャラクター)または**Linked Personas**(紐付けるペルソナ)を入力します。これで、紐付けたキャラクターが参加しているチャットや、紐付けたペルソナを使っているチャットでロアブックが有効になります。どちらの欄も複数を指定できるので、必要なキャラクターをすべて追加してください。
2. 1つのチャットに付けます。**Chat Settings**を開き、**Lorebooks**セクションから**Add Lorebook**(ロアブックの追加)を使います。設定が特定のチャットだけのものであるときは、この方法が向いています。
3. エントリーごとにキャラクターで絞り込みます。共有のロアブックの中では、特定のキャラクターがいるときだけ発動するようにエントリー単位で指定できます。一部のエントリーだけがキャラクター固有になる、大きな世界観のロアブックに向いています。

機能の全体像は[ロアブック](lorebooks/overview.md)を参照してください。

## エージェントとは?

**エージェント**は、チャット中に動いて決まった役割をこなす、任意のAIの補助機能です。たとえば今のシーンを追跡する、文章の質を見張る、マップや通話を追加する、Conversationでテーブルゲームを進行する、といったものがあります。インストール直後の状態では、任意のエージェントは1つも入っていません。**Agents**(エージェント)パネルを開き、**Download Agents**(エージェントのダウンロード)をクリックし、項目の説明を読んでからインストールします。そのあと、**Chat Settings**でチャットごとに対応するエージェントを有効にします。インストール済みの公式パッケージに対応するアップデートが出たときは、Marinaraがダウンロードの前に確認します。**No**を選ぶと今のバージョンのまま残り、Download Agentsに**Update**が表示され続けるので、あとからでもアップデートできます。配信元がオフラインのときや検証に失敗したときは、インストール済みのバージョンがそのまま動きます。カタログからはパッケージの完全な削除もできます。[エージェント](agents/agents-overview.md)と、公開されている[Marinara-Agentsリポジトリー](https://github.com/Pasta-Devs/Marinara-Agents)を参照してください。

## Noodleを設定するには?

Noodleは、キャラクターのためにMarinaraが用意した、ローカルで動く架空のソーシャルネットワークです。**Noodle**タブを開き、その**Settings**(設定)を開きます。キャラクターかキャラクターのフォルダーを招待し、**Refresh**(更新)で生成に使う接続を選んでから、**Refresh now**(今すぐ更新)を選ぶと最初の投稿が生成されます。自動で更新する時刻、画像生成、ランダムなユーザー、チャットへの引き継ぎも設定できます。

詳しくは[Noodle: アプリ内のソーシャルタイムライン](noodle/overview.md)と[Noodleの設定とチャットへの引き継ぎ](noodle/settings.md)を参照してください。

## キャラクターが前のメッセージを覚えていないのはなぜ?

AIモデルが一度に扱える文章の量には限りがあるので、長いチャットでは古いメッセージが視界から外れていきます。Marinaraには、これを補う仕組みが2つあります。

- **Memory Recall**(記憶の呼び出し)は過去のメッセージを検索し、関連の深い部分だけをそっとプロンプトに挿入します。**Chat Settings**の**Memory Recall**でオンにします。
- 要約は古いメッセージを短くまとめます。Roleplayのチャットでは**Chat Summary**、Conversationのチャットでは**Automatic Summarization**を使います。

設定方法と詳細は[Memory Recallとチャットの要約](agents/memory.md)を参照してください。

## データをバックアップするには?

**Settings**を開き、**Advanced**(詳細設定)タブに移動し、**Backup & Export**(バックアップとエクスポート)セクションの**Download Backup**(バックアップのダウンロード)をクリックします。データとアップロードしたファイルをまとめた`.zip`が1つ保存されます。あとで復元するときは、**Settings**の**Imports**(インポート)タブにある**Import Profile (JSON/ZIP)**を選び、同じ`.zip`を指定します。

同じセクションでは、日次、週次、月次で世代を入れ替える自動バックアップも有効にできます。フルバックアップのZIPには、
暗号化されたレコードと、それを復号するための鍵ファイルが含まれることがあるので、他人の目に触れないように保管して
ください。**Import Profile**を使ってもプロバイダーの秘密の値は空のままなので、インポートしたあとはAPIキーを入力し直してください。詳しい手順は
[バックアップと復元](data/backup-and-restore.md)を参照してください。

## 拡張機能はどのような仕組みですか? 第三者のコードをインポートできますか?

デフォルトでは、Personal Extensionの下書きを作れるのはProfessor Mariだけです。作られた時点では無効になっていて、実行するにはコードを自分で確認し、SHA-256ハッシュが完全に一致することを承認する必要があります。

ブラウザー向けのコードは、デフォルトでは不透明なオリジンのiframeの中にある専用のWorkerで動きます。限定的なログ出力、専用ストレージ、タイマー、後始末、宣言的なUIの機能に加えて、今開いているチャットとキャラクターの不透明なIDを受け取ります。これにより、Notepadのような拡張機能はチャットごとの状態を保てます。Browser Extensionはこれとは別に、そのチャットに参加しているキャラクターカードや、そのチャットで選ばれているペルソナだけに限った範囲のスナップショットを要求できます。こうした権限はハッシュの承認画面に表示され、承認しなければ該当するデータは渡りません。サンドボックス内の拡張機能は、メッセージ、キャラクターやペルソナのライブラリー全体、宣言していない項目、チャットのメタデータ、DOMへのアクセス、ネットワークへのアクセス、データを書き換えるAPIを一切受け取りません。サーバー向けのコードは、対応するmacOSとLinuxのホストではOSのサンドボックス内の別プロセスで動き、ブラウザー側のチャットの情報は受け取りません。

第三者の拡張機能のインポートは、デフォルトでは表示されません。まずホストの管理者が`.env`で`ENABLE_EXTERNAL_EXTENSIONS=true`を設定し、そのうえで**Settings → Advanced → Danger Zone**の警告に同意する必要があります。この2つの条件がそろうまで、外部のレコードは、手動で保存したものやプロファイルからインポートしたものも含めて表示されず、承認もできず、実行もされません。

External Extensionは、古い実装との互換性のためにどうしてもMarinaraのDOMが必要な場合に、**Full page access**(ページ全体へのアクセス)を要求することがあります。これはサンドボックス化されません。承認したそのコードがMarinaraのページの中で動き、ページの内容、ブラウザーのストレージ、ネットワークAPI、今の同一オリジンのセッションにアクセスできます。Professor Mariの下書きがこれを要求することはありません。有効にするのは、そのバージョンのコードを確認して信頼できると判断したあとだけにしてください。無効にしたあとも登録が残っている場合は、ページを再読み込みします。[個人用拡張機能](extending/personal-extensions.md)を参照してください。

## データはどこに保存されますか?

すべてMarinaraを動かしているコンピューターの中、インストール先の`data`フォルダーに保存されます。キャラクター、チャット、ペルソナ、ロアブック、プリセット、設定はすべてここにあります。クラウドには何も保存しません。[Marinaraがデータを保存する場所](data/where-data-is-stored.md)を参照してください。

## アップデートするとデータは消えますか?

消えません。Marinaraをアップデートしても、キャラクター、チャット、設定はそのまま残ります。とはいえ、大きなアップデートの前には念のためバックアップを取っておくと安心です。プラットフォームごとの手順は[アップデート](UPGRADING.md)を参照してください。

## Professor Mariには何ができますか?

Professor Mariは、ホーム画面に組み込まれているアシスタントです。**Ask Professor Mari**(Professor Mariに聞く)ボタンから開きます。アプリの説明や設定の手助けをしてくれます。ふだんの言葉で頼めば、キャラクター、ペルソナ、ロアブック、プロンプトプリセット(保存したプロンプトの雛形)、新しいチャットの作成や編集もできます。

入力欄の上には返信候補のチップも表示されるので、何段階かに分かれる作成や編集を、細かい指示をすべて打ち込まずに進められます。

データが変更されると、**Keep**(残す)と**Restore**(元に戻す)のボタンが付いた確認カードが表示されるので、望まない変更はいつでも取り消せます。Professor Mariはあくまで補助役で、バージョン固有の内容についてはこのガイド類の代わりにはなりません。できることの一覧は[Professor Mari](home/professor-mari.md)を参照してください。

Professor MariはMarinaraの通常のソースファイルなら編集できます。依存関係のファイル、起動用のスクリプト、インストーラー、CIのワークフローについては、明示的な確認を待ちます。変更に公開されたnpmライブラリーが必要な場合、Marinaraはインストール前に解決されたバージョンとレジストリーの整合性情報を表示し、ライフサイクルスクリプトを無効にしたうえでインストールします。

注記: 通常のリモートアドレスからアクセスしている場合、Professor Mariがデータを変更するにはBasic Authと管理者用のシークレットの両方が必要です。信頼済みまたは許可リストに載っているネットワーク経路では、[リモートアクセス](REMOTE_ACCESS.md)で説明している回避方法を使えます。

## Storyboardエージェントとは何ですか? Game Modeではどう使いますか?

ダウンロードして使う**Storyboard**エージェントは、できあがった物語の文章を、順番に並んだキーフレーム画像に変えます。各キーフレームを短いクリップとして動かすこともできます。**Game Mode**では、終了したゲームマスター(GM)の語り1ターン分を絵コンテにして、フローティングのビューアーかGameの背景にキーフレームを表示します。**Roleplay**では、新しくそろったやり取りをまとめ、チャット内のエピソードとして表示します。

Game Modeで使うには、**Agents > Download Agents**から**Storyboard**をインストールします。Gameを開いて**Chat Settings > Agents**に移動し、**Enable Agents**(エージェントを有効にする)と**Enable Storyboards**(絵コンテを有効にする)をオンにして、Game側かStoryboardの全体設定で画像生成の接続を指定します。GMの語りが1ターン分終わったら、**Gallery**(ギャラリー)を開いて**Create storyboard**(絵コンテの作成)をクリックします。ビューアーを開き直すときは**View storyboard**(絵コンテの表示)を使います。

Gameの絵コンテを自動で作るには、**Automatic Storyboard Illustrations**をオンにします。クリップも欲しいときは、**Automatic Storyboard Animations**もオンにして、Video Generationの接続を選びます。新規Gameの設定ウィザードにある**Storyboard Optimized**の演出は、GMの語り方を整えるだけです。エージェントのインストールや有効化は行いません。GameとRoleplayの設定、プロンプト、ビューアー、移行時の動作、トラブル対処については、[Storyboardエージェントガイド](game/storyboard.md)を参照してください。

## 通話でキャラクターに声を出してもらえますか?

はい。**Conversation**モードで使えます。音声通話とビデオ通話はConversation専用の機能です。キャラクターの声を聞くには、まず**Connections**パネルで**Text to Speech**を設定します。

マイクで話しかけたいのに、ブラウザー内蔵の音声認識がうまく働かない場合は、まず**Agents > Download Agents**から**Calls**をインストールします。次に**Connections**パネルを開き、**Local Model**カードを広げ、**Local Speech Model**で**Whisper Tiny (Multilingual)**か**Whisper Base (Multilingual)**を選び、**Download Whisper**をクリックします。Callsをアンインストールすると、ダウンロードしたWhisperのデータも削除され、ディスクの空き容量が戻ります。通話の設定の詳細は[Conversationの音声通話とビデオ通話](conversation/calls.md)を参照してください。

## Marinaraは画像を生成できますか?

はい。画像生成の接続を追加してください。たとえば**Pollinations**(キーが不要)や、有料のプロバイダーが使えます。追加すると、キャラクターのアバター、シーンのアート、自撮り写真、RoleplayやGame ModeでのStoryboardエージェントのキーフレームを生成できるようになります。追加方法は[AIプロバイダーへの接続](connections/connecting-to-a-provider.md)を参照してください。

## アプリの中でドキュメントを読むには?

どのインストール環境にもガイド一式が同梱されています。アプリを離れずに読めます。

- ホーム画面のフッターで、**Replay Tutorial**の隣にある**Documentation**(ドキュメント)ボタンをクリックします。
- ホーム画面のFAQで、ドキュメントに関する質問を開き、**Open Documentation**(ドキュメントを開く)をクリックします。

どちらのボタンからも同じアプリ内ビューアーが開きます。すべてのガイドが一覧表示され、Marinaraの中でそのまま読めます。

## 助けを求めたり、バグを報告したりするには?

まずは症状ごとにまとめてある[トラブルシューティング](TROUBLESHOOTING.md)を確認してください。ホーム画面のフッターでは、**Discord**ボタンからコミュニティのチャットへ、**Support**ボタンからプロジェクトのサポートページへ移動できます。バグの報告と機能の要望には、プロジェクトのGitHubページを使ってください。
