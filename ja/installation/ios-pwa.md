# iOS / iPadOS PWAガイド

このガイドでは、iPhoneやiPadでMarinara Engineを使う方法を説明します。iOSとiPadOSでは、Marinaraのサーバー自体を動かせません。別のデバイスで動いているサーバーに接続し、それをWebアプリとしてホーム画面に保存して使います。

## iOSではサーバーを別のデバイスで動かす

Marinara Engineは2つの部分でできています。実際の処理を行うサーバーと、ブラウザーで表示するWebアプリです。iPhoneとiPadでは、Appleがサーバーの動作を許可していません。そのため、サーバーは別の場所で動かし、iPhoneやiPadのSafariから開きます。

サーバーは次のいずれかで動かせます。

- Windowsのコンピューター([Windowsインストールガイド](windows.md)を参照)。
- MacまたはLinuxのコンピューター([macOS / Linuxインストールガイド](macos-linux.md)を参照)。
- Termuxを入れたAndroidのスマートフォン([Android(Termux)インストールガイド](android-termux.md)を参照)。
- DockerまたはPodmanのコンテナー([コンテナーでの実行](containers.md)を参照)。

iPhoneやiPadは、ネットワーク経由でそのサーバーに接続します。普通のWebサイトを開くのと同じ仕組みで、違いはそのWebサイトが自分のMarinaraサーバーだという点だけです。

## Safariから接続する

サーバーがホスト側のデバイスで動き始めたら、次の手順で接続します。

1. ホスト側のデバイスとiPhoneまたはiPadが同じネットワーク、あるいは同じTailscaleネットワークにつながっているか確かめます。LANとは、自宅のWi-Fiのような手元のネットワークのことです。Tailscaleは、インターネット越しに複数のデバイスをプライベートなネットワークでつなぐ無料のツールです。
2. ホスト側のサーバーのアドレスを調べます。形式は下の例のとおりです。`<host-ip>`は、ホスト側のデバイスのLANまたはTailscaleのIPアドレスに置き換えます。デフォルトのポートは`7860`です。

```
http://<host-ip>:7860
```

3. iPhoneまたはiPadで**Safari**を開きます。
4. Safariのアドレスバーにそのアドレスを入力して開きます。
5. ブラウザーにMarinaraのホーム画面が表示されます。

ページが開かない場合や、パスワードの入力を求められた場合は、下の「トラブルシューティング」を参照してください。ネットワークへのアクセスとパスワードは、サーバーの管理者が決めます。これらはサーバー側の設定で、iPhoneやiPad側の設定ではありません。詳しくは[リモートアクセス](../REMOTE_ACCESS.md)を参照してください。

## ホーム画面に追加する

MarinaraはPWAとして保存でき、普通のアプリのように開けるようになります。PWAはProgressive Web Appの略で、専用のウィンドウで動き、ホーム画面に独自のアイコンを持つWebサイトのことです。

1. 上の手順に従って、**Safari**でMarinaraのサーバーを開きます。
2. 共有ボタンをタップします。上向きの矢印が付いた四角のアイコンです。
3. 共有シートを下にスクロールし、**Add to Home Screen**(ホーム画面に追加)をタップします。
4. 必要なら名前を変更し、**Add**(追加)をタップします。
5. ホーム画面にMarinaraのアイコンが追加されます。

このアイコンをタップすると、Safariのアドレスバーのない専用のウィンドウでMarinaraが開きます。

## HTTPSについての注意

PWAはHTTPSで使うのがいちばん安定します。HTTPSは暗号化された安全なWeb接続のことで、アドレスの先頭に付く`https://`が目印です。

LAN内で暗号化なしのHTTPを使っても、Safariでの通常の利用には支障ありません。ただしiOSやiPadOSのバージョンによっては、`http://`のアドレスに対してPWA単体での動作が制限されることがあります。その場合は、MarinaraをHTTPSで配信してください。

Tailscaleを使うと、各デバイスに固定のプライベートアドレスが割り当てられ、つながりやすくなります。ただしTailscaleだけでは、`http://`のアドレスがHTTPSに変わるわけではありません。HTTPSで配信する設定のTailscaleを使うか、サーバーの管理者にMarinaraをHTTPS経由にしてもらってください。

これらの方法は[リモートアクセス](../REMOTE_ACCESS.md)で説明しています。暗号化なしのHTTPのアドレスではホーム画面のアプリとしてうまく動かない場合は、Safariのブックマークとして使ってください。

## PWAの削除と再インストール

Safariが古いバージョンのアプリを表示し続けたり、保存したWebアプリが反応しなくなったりすることがあります。たいていは、ホーム画面のアプリを入れ直せば直ります。

1. ホーム画面のMarinaraのアイコンを長押しします。
2. アプリを削除する項目をタップし、確認します。
3. iPhoneまたはiPadで**Settings**(設定)アプリを開きます。
4. **Safari**をタップします。新しいバージョンのiOSやiPadOSでは、**Apps**の中に**Safari**がある場合があります。
5. **Advanced**(詳細)をタップし、続いて**Website Data**(Webサイトデータ)をタップします。
6. Marinaraのホストアドレスのエントリーを探します。見つからない場合は、**Show All Sites**(すべてのサイトを表示)をタップします。
7. そのエントリーを左にスワイプし、**Delete**(削除)をタップします。これで、そのサーバー用に保存されていた古いファイルが消えます。
8. 「Safariから接続する」の手順で、もう一度**Safari**からMarinaraを開きます。
9. 「ホーム画面に追加する」の手順で、もう一度ホーム画面に追加します。

チャット、キャラクター、設定はサーバーに保存されていて、iPhoneやiPadの中にはありません。ホーム画面のアプリを入れ直しても消えません。

## トラブルシューティング

**Safariでページが開かない。** サーバーがホスト側のデバイスでまだ動いているか確認します。2台のデバイスが同じネットワークかTailscaleにつながっているかも確認します。IPアドレスとポート`7860`が正しいか確かめてください。ネットワークまわりのさらに詳しい対処は、[リモートアクセス](../REMOTE_ACCESS.md)と[Marinara Engineのトラブルシューティング](../TROUBLESHOOTING.md)で説明しています。

**Safariがユーザー名とパスワードを求めてくる。** サーバーの管理者が、外部のデバイス向けにパスワード保護を有効にしています。ユーザー名とパスワードは、サーバーを動かしている人から教えてもらってください。設定方法は[リモートアクセス](../REMOTE_ACCESS.md)で説明しています。

**Safariが古いビルドを表示し続ける。** まずページを再読み込みします。それでも古いままなら、上の「PWAの削除と再インストール」の手順を試してください。

**生成中にホーム画面アプリが閉じる、または真っ白になる。** アプリを開き直してチャットに戻ってください。正常なサーバーを再起動する必要はありません。ブラウザーの接続が失われても、自動のチャット返信とIllustratorだけを使う手動・再試行の画像要求はサーバーで続きます。開き直したチャットは未完了の処理を確認し、完了すると保存済みメッセージとギャラリー画像を更新します。**Stop**(停止)は引き続き選択中のチャットの生成をキャンセルします。白い画面が繰り返される場合は、Support Diagnosticsと、開き直すとチャットが戻るかを報告してください。この復旧動作は、iOSブラウザーのあらゆる障害を診断・防止するものではありません。

**保存が黙って失敗するという赤いバナーが出る。** これはサーバーが出しているネットワークの信頼に関する警告で、iPhoneやiPadの問題ではありません。サーバーの管理者が、こちらのアドレスを信頼済みにする必要があります。[リモートアクセス](../REMOTE_ACCESS.md)と[Marinara Engineのトラブルシューティング](../TROUBLESHOOTING.md)を参照してください。

**権限が必要な操作がブロックされる。** メンテナンス用の操作には、サーバーの管理者が発行する管理者用シークレットが必要です。iPhoneやiPadでは、**Settings**、**Advanced**、**Admin Access**(管理者アクセス)の順に進み、その値を保存します。管理者用シークレットが何か、どう入手するかは[リモートアクセス](../REMOTE_ACCESS.md)で説明しています。
