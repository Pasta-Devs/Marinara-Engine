# iOS / iPadOS PWAガイド

iPhoneやiPadでMarinara Engineを使います。AppleはこれらのデバイスでMarinaraのサーバーを動かすことを許可していないため、別のデバイスで動いているサーバーをSafariで開きます。そのあと、PWAとしてホーム画面に保存できます。PWA(Progressive Web App)とは、アプリのように専用のウィンドウで開くWebサイトのことです。

## 最短の手順

1. コンピューター、自宅のサーバー、Androidのスマートフォンのいずれかで、Marinaraをインストールして起動します(下の一覧を参照)。起動したままにしておきます。
2. そのコンピューターでログインを設定します。[リモートアクセス](../REMOTE_ACCESS.md#option-1-login-recommended)を参照してください。
3. そのコンピューターのIPアドレスを調べます(下を参照)。
4. iPhoneまたはiPadで**Safari**を開き、`http://`のあとにそのIPアドレスと`:7860`を続けたアドレスにアクセスします。

iPhoneやiPadでは`127.0.0.1`を使わないでください。このアドレスはiPhone自身を指します。

## サーバーを動かす場所

サーバーは次のいずれかで動かせます。

- WindowsのPC: [Windowsインストールガイド](windows.md)。
- MacまたはLinuxのコンピューター: [macOS / Linuxインストールガイド](macos-linux.md)。
- Termuxを入れたAndroidのスマートフォン: [Android(Termux)インストールガイド](android-termux.md)。
- DockerまたはPodmanのコンテナー: [コンテナーでの実行](containers.md)。

## Safariから接続する

始める前に: サーバーが動いていて、手元のデバイスの接続を許可している必要があります。通常はログインを使います。[リモートアクセス](../REMOTE_ACCESS.md)を参照してください。

1. サーバーのデバイスとiPhoneまたはiPadを、自宅のWi-Fiなどの同じネットワークにつなぎます。別の場所から接続するには、Tailscaleを使います。Tailscaleは、インターネット越しに複数のデバイスをプライベートなネットワークでつなぐ無料のツールです。
2. サーバーのデバイスのIPアドレスを調べます。サーバーのコンピューターでターミナル(コマンドを入力するウィンドウ)を開いて次のコマンドのどれかを実行し、`192.168.1.42`のような形のアドレスを読み取ります。

   - Windows(コマンドプロンプト): `ipconfig`。**IPv4 Address**(IPv4アドレス)を読み取ります。
   - Linux: `hostname -I`。
   - macOS: `ipconfig getifaddr en0`。

3. **Safari**を開いて、次のアドレスにアクセスします。`<host-ip>`はそのIPアドレスに置き換えます。デフォルトのポートは`7860`です。

```text
http://<host-ip>:7860
```

4. Marinaraのホーム画面が表示されます。

サインインのページが表示された場合は、サーバーのユーザー名とパスワードでサインインします。セットアップのページが表示された場合は、サーバーのログにある1回限りのセットアップコードを入力し、ユーザー名とパスワードを決めます。[リモートアクセス](../REMOTE_ACCESS.md)を参照してください。

うまくいかなかった場合: サーバーがまだ動いているか、両方のデバイスが同じネットワークかTailscaleにつながっているかを確認してください。IPアドレスとポートも確認します。[Marinara Engineのトラブルシューティング](../TROUBLESHOOTING.md)を参照してください。

## ホーム画面に追加する

1. **Safari**でMarinaraのサーバーを開きます。
2. 共有ボタン(上向きの矢印が付いた四角のアイコン)をタップします。
3. 共有シートを下にスクロールし、**Add to Home Screen**(ホーム画面に追加)をタップします。
4. 必要なら名前を変更し、**Add**(追加)をタップします。

ホーム画面にMarinaraのアイコンが追加されます。タップすると、Safariのアドレスバーのない専用のウィンドウでMarinaraが開きます。

## アプリがうまく動かないときはHTTPSを使う

PWAは、HTTPS(`https://`で始まる安全な接続)で使うのがいちばん安定します。暗号化なしの`http://`のアドレスでも、Safariでは動きます。ただしiOSやiPadOSのバージョンによっては、暗号化なしの`http://`のアドレスではホーム画面のアプリが制限されます。その場合は、MarinaraをHTTPSで配信するか、Safariのブックマークとして使ってください。

Tailscaleを使うだけでは、アドレスはHTTPSになりません。HTTPSで配信する設定のTailscaleを使うか、サーバーの管理者にMarinaraをHTTPS経由にしてもらってください。[リモートアクセス](../REMOTE_ACCESS.md#serving-over-https)を参照してください。

## PWAの削除と再インストール

Safariが古いバージョンのアプリを保持し続けたり、保存したアプリが反応しなくなったりすることがあります。たいていは、入れ直せば直ります。チャット、キャラクター、設定はサーバーにあるので、入れ直しても消えません。

1. ホーム画面のMarinaraのアイコンを長押しします。
2. アプリを削除する項目をタップし、確認します。
3. iPhoneまたはiPadで**Settings**(設定)アプリを開きます。
4. **Safari**をタップします。新しいバージョンのiOSやiPadOSでは、**Apps**(アプリ)の中の**Safari**にある場合があります。
5. **Advanced**(詳細)をタップし、続いて**Website Data**(Webサイトデータ)をタップします。
6. MarinaraのアドレスのWebサイトの項目を探します。見つからない場合は、**Show All Sites**(すべてのサイトを表示)をタップします。
7. その項目を左にスワイプし、**Delete**(削除)をタップします。
8. 上の手順で、もう一度**Safari**でMarinaraを開き、ホーム画面に追加し直します。

## トラブルシューティング

**Safariでページが開かない。** サーバーが動いているか、両方のデバイスが同じネットワークかTailscaleにつながっているか、IPアドレスとポート`7860`が正しいかを確認してください。[リモートアクセス](../REMOTE_ACCESS.md)と[Marinara Engineのトラブルシューティング](../TROUBLESHOOTING.md)を参照してください。

**アップデート後、Safariにサインインまたはセットアップのページが表示される。**

- `/login`で、サーバーのユーザー名とパスワードでサインインします。
- ログインがまだない場合は、サーバーのログにある1回限りのセットアップコードを、セットアップページで入力します。
- サーバーがコードを表示しない場合は、サーバーのデバイスで**Settings → Advanced → Access**(設定 → 詳細設定 → アクセス)からログインを設定します。
- **403**は、iPhoneが`IP_ALLOWLIST`に入っていないことを意味する場合があります。そのリストは、サーバーの管理者が変更します。
- PWAからサーバーのログインをリセットすることはできません。サーバーの管理者が、サーバー上のMarinaraのフォルダーで`node scripts/reset-login.mjs`を実行するか(Dockerでは`docker exec <container> node scripts/reset-login.mjs`)、`.env`で設定したログインを変更します。

[アップデート後にログインできなくなった場合](../REMOTE_ACCESS.md#locked-out-after-updating)を参照してください。

**Safariが古いビルドを表示し続ける。** ページを再読み込みします。それでも古いままなら、上の手順でPWAを入れ直してください。

**生成中にホーム画面のアプリが閉じる、または真っ白になる。** アプリを開き直して、チャットに戻ってください。正常なサーバーは処理を続けます。チャットの返信とIllustratorの画像の要求はサーバーで続き、開き直したチャットは処理が終わると更新されます。**Stop**(停止)は引き続き、選択中のチャットの生成をキャンセルします。白い画面が繰り返される場合は、Support Diagnosticsを添えて報告してください。

**保存が黙って失敗するという赤いバナーが表示される。** これはサーバーが出しているネットワークの信頼に関する警告で、iPhoneやiPadの問題ではありません。サーバーの管理者が、こちらのアドレスを信頼済みにする必要があります。[リモートアクセス](../REMOTE_ACCESS.md#why-is-my-save-blocked-csrf)を参照してください。

**権限が必要な操作がブロックされる。** 一部のメンテナンス用の操作には、サーバーの管理者から受け取る管理者用シークレット(2つ目のパスワード)が必要です。iPhoneやiPadの**Settings → Advanced → Admin Access**(設定 → 詳細設定 → 管理者アクセス)に保存してください。[リモートアクセス](../REMOTE_ACCESS.md#admin-access-and-privileged-actions)を参照してください。
