# Decisionモデル

このガイドでは**Decision model**(判定モデル)の役割、利用する3つの方法、それぞれの設定方法、Marinaraでの用途を説明します。これは任意の機能です。設定しなくてもチャットは生成されますが、各機能は後述するフォールバックを使います。

## Decisionモデルとは

Decisionモデルは、特定の種類の問いに答えます。チャットの最近のメッセージと"The latest message moves the scene to a new place"のような文を受け取り、その文が真である確率を0から1の数値で返します。Marinaraはその数値をしきい値と比較し、結果をはい、またはいいえとして扱います。"angry", "sad", "none of these"といった短いリストから答えを1つ選ぶこともできます。

回答はMarinaraの動作を制御するもので、チャットの返信として投稿されません。判定専用モデルは文を直接採点します。ローカルチャットモデルには通常、はい、またはいいえの1トークンを求めますが、先に推論が必要なモデルもあります。判定は返信全体の生成より速く済むことがありますが、文の数が多い場合や推論モデルの場合は、待ち時間が目立つこともあります。

<a id="where-marinara-uses-it"></a>

## Marinaraでの用途

- **[起動質問](../agents/custom-agents.md#activation-questions)**は、各フェーズでカスタムエージェントが作業を始める前に、実行するかを決めます。回答がなければ質問によって実行は止まりません。キーワードと**Trigger Cadence**(起動頻度)は引き続き適用されます。
- **[プロンプト内の判定文](../prompts/conditional-prompts.md#asking-the-decision-model)**は、チャットやエージェントのプロンプトを準備するときにテキストを選びます。回答がなければ判定はいいえとなり、単純な判定ブロックは`{{else}}`分岐があればそれを使います。
- **[ロアブックのDecision欄](../lorebooks/entries.md#decision-activation)**は、チャットのロアブックスキャン中にRequireまたはTriggerを確認します。回答がなければRequireは新しいエントリーを通せず、Triggerは起動経路を追加しません。既存のStickyによる保持と、Triggerエントリーの通常の起動経路は引き続き適用されます。
- **[Smart応答順](../chats/group-chats.md#response-order-individual-only)**は、有効な場合、グループチャットで次に誰が話すかを採点します。回答がなければSmart順序は通常のAI呼び出しを行います。

起動質問はエージェントを実行するかを制御し、プロンプト内の判定文は、実行中のエージェントに何を伝えるかを制御します。はい・いいえのプロンプト条件には`{{#if decision:"..."}}`を、複数の回答からの選択には`{{#if decision_choice:"..." == "..."}}`を使います。

<a id="what-the-model-sees"></a>

## モデルが受け取る情報

起動質問とプロンプト・ロアブックの判定文では、モデルは判定文と、チャットに保存された最近のメッセージを受け取ります。組み立て済みプロンプトの残りの部分、つまりプリセット、キャラクターカード、ペルソナの説明、ロアブックエントリー(Constantも含む)、要約、エージェント出力は受け取りません。**@ Depth**に配置したプリセットやロアブックエントリーなど、メッセージ間に挿入されるテキストも含まれません。それらの情報に依存する判定文には、必要な事実自体を含めてください。

**Smart応答順ではキャラクター一覧も送信します。** 利用可能な場合は各候補の名前、状態、活動、発言頻度と、最大300文字の性格、性格が空なら説明を含めます。ホスト型Decisionプロバイダーは、最近のメッセージとこの一覧を受け取ります。

- プロンプトとロアブックエントリー内の判定文、およびSmart応答順は、直近5件のメッセージを読みます。この数は固定です。
- 起動質問はエージェントの**Scan Depth**(スキャン深度)を使い、デフォルトは5です。
- 各メッセージには発言者名が付けられます。AIから隠したメッセージは除外されます。
- 後処理エージェントの起動質問やプロンプト内の判定文など、返信後に確認するものには、書き終えた返信も含まれます。
- 判定文のマクロは先に展開されるため、`{{char}}`はキャラクター名として渡ります。
- メッセージがモデルの予算に収まらない場合は、古いメッセージから除外します。ホスト型の予算は[Decision接続の設定](#set-up-a-decision-connection)を参照してください。

## Decisionモデルの選択

**Connections**(接続)を開き、**Connection defaults**(接続のデフォルト)から**Decision model**を選びます。リストは3つのグループに分かれています。

- **None**(なし)がデフォルトです。問い合わせは行われず、エージェントエディターの起動質問欄は無効のままです。
- **Local models**(ローカルモデル): すでに実行している**Primary local model**(主ローカルモデル)または**Utility local model**(補助ローカルモデル)です。ダウンロードは発生せず、情報はコンピューターの外に出ません。**Decision sidecar**(判定サイドカー)をインストール済みなら、ここにも表示されます。
- **Connections**: 作成したDecision接続で、ホスト型と自分で運用する接続の両方が含まれます。

現在回答できない項目も理由付きでグレー表示されるため、直すべき点を確認できます。選択後に**Test**(テスト)をクリックしてください。テストでは固定サンプルを送り、チャットは送りません。

### 選択の目安

すでにローカルモデルを使っているなら、まずそれを試してください。あるRoleplayの1場面を使った小規模な表現テストでは、Gemma 4 E4Bは推奨する32文すべてに正しく回答し、Open-Jev 2Bと9Bはそれぞれ31文に正しく回答しました。これは表現の重要性を示す例で、一般的な精度ランキングではありません。自分のチャットの代表的なターンで試してください。[判定文の書き方](../prompts/conditional-prompts.md#writing-statements)を参照してください。

**JevとOpen-Jevは別のモデルです。** JevはTypeSafeのホスト型モデルで、直接またはOpenRouter経由で利用できます。[Open-Jev](https://huggingface.co/ZefanCai/Open-Jev-2B)はQwenを基盤に別途公開されたモデルで、Marinaraでローカル実行できます。Open-Jevの表現テストは、ホスト型Jevの精度を測定したものではありません。

| 選択肢 | 費用 | 必要なもの | 向いている用途 |
| --- | --- | --- | --- |
| すでに実行しているモデル | 追加費用なし | **Local Model**(ローカルモデル)内のモデル | ローカルモデルを利用する多くの人 |
| ホスト型Decision接続 | リクエスト課金。1ターンで複数回になる場合あり | APIキー(TypeSafeまたはOpenRouter) | スマートフォンやローカルモデルを実行しないPC |
| インストール式判定モデル | 別途ディスク容量とGPUメモリーを使用。[モデルサイズ](#let-marinara-install-a-decision-model)を参照 | Linux x86-64と対応NVIDIA GPU | チャットモデルと並行して専用の判定モデルを実行する場合 |

**Android (Termux)では、**インストール式判定モデルは動作しません。NVIDIA GPUを搭載したPCが必要だからです。スマートフォンのプロセッサーで動く小型ローカルモデルも、制限時間に間に合わないことがあります。スマートフォンでは、OpenRouter経由のJevなど、ホスト型Decision接続が実用的です。[Decision接続の設定](#set-up-a-decision-connection)を参照してください。

プリセット、カード、エージェントは「Decisionモデル」を前提に記述し、「Jev必須」としないでください。どのモデルを選んでも同じ判定文の構文を使いますが、モデルによって回答は異なることがあります。

判定を使うコンテンツをインポートすると、Marinaraはこのガイドへのリンク付き通知を表示します。カスタムエージェントやAgentカタログからのインストールも対象です。Decisionモデルが未選択の場合、通知はフォールバックを説明します。プロンプトの判定文はいいえとなり、ロアブックエントリーは判定によって起動できず、エージェントの起動質問はキーワードと**Trigger Cadence**が許す限り実行を通します。Decisionモデルがないときに毎ターン実行させたくないエージェントには、頻度も設定してください。プロファイル全体のZIP復元では、このインポート通知は表示しません。

<a id="use-a-model-you-already-run"></a>

## すでに実行しているモデルの利用

**Local Model**にローカルモデルがあれば、接続を作成したりリクエスト料金を支払ったりせずに判定へ利用できます。

1. **Connections**で**Connection defaults**を開き、**Decision model**を**Primary local model**、または設定済みなら**Utility local model**にします。
2. **Test**をクリックしてください。成功すると確率と所要時間に加え、ローカルモデル特有の2項目、対数確率が利用できたか、モデルが直接回答するかが表示されます。

Marinaraはモデルに1つのはい・いいえの質問を送り、1トークン生成させ、そのトークンの確率から回答を読み取ります。返信は書かれないため、短いリクエストになります。複数の回答から選ぶ場合は、選択肢ごとに1つのはい・いいえの質問を行います。何件の最近のメッセージが収まるかは、そのスロットのコンテキストサイズから計算します。

**推論。** 多くのモデルは1語で答えます。指示に関係なく、常に先に推論するモデルもあります。ドロップダウンの下にある**Thinking**(推論)で制御します。

- **Auto**(自動、デフォルト)は高速な1語方式を試し、2回続けて回答できなければ、そのモデルに先に推論させ、通知します。
- **Off**(オフ)は常に1語方式を使います。この方式で答えられないモデルは回答なしとなります。
- **Allowed**(許可)は、推論を省略するようモデルに求めません。

先に推論するモデルには数秒かかるため、デフォルトでは後処理エージェントなど、返信の表示後に行う処理にのみ回答します。返信前の処理では回答なしとなります。**Also gate agents that run before the reply**(返信前に実行するエージェントも判定)をオンにすると、各返信が判定を待つようになります。

**数値について。** 汎用チャットモデルのはい・いいえの確率はしきい値に利用できますが、判定専用モデルのように校正する訓練は受けていません。対数確率を返さないランタイムの回答は、単純な1または0です。デフォルトをそのまま信頼せず、自分のチャットでしきい値を調整してください。

<a id="set-up-a-decision-connection"></a>

## Decision接続の設定

1. **Connections**で、プロバイダーが**Decision**の接続を作成します。
2. **TypeSafe**、**OpenRouter**、**Custom System One endpoint**(独自System Oneエンドポイント)のいずれかを選びます。ホスト型にはAPIキーが必要です。CustomではOpen-Jevを含め、自分で実行しているSystem Oneサーバーを指定できます。`/v1/systemone`を含めずにベースURLを入力し、サーバーが対応するモデル名を使ってください。
3. OpenRouterでは**API key source**(APIキーの取得元)で保存済みOpenRouter接続を選ぶか、別のキーを入力します。接続エディターには**Use this key for decisions (Jev)**(このキーを判定に使用)もあります。リンクしたキーは後から変更されても自動的に追従します。Custom接続が独自チャット接続のキーを借用できるのは、両方のURLのオリジン(スキーム、ホスト、ポート)が同じ場合だけです。
4. 保存後、**Decision model**で選択して**Test**をクリックします。成功すると確率、回答までの時間、接続の制限時間が表示されます。Testは最低10秒、制限時間がそれより長い場合はその5秒後まで待つため、遅い回答も実際の所要時間で報告されます。制限時間を超えた場合はその旨が表示され、チャットでは回答なしとして扱われることがわかります。

Decisionのデフォルトは、チャット、エージェント、画像、動画、音声のデフォルトとは別です。**None**を選ぶと、起動質問や判定文を削除せずに判定をオフにできます。

ホスト型の判定は、選択した最近のメッセージと判定文を指定プロバイダーに送信し、料金が発生する場合があります。Smart応答順では[キャラクター一覧](#what-the-model-sees)も含めます。**Recent-message token budget**(最近のメッセージのトークン予算)のデフォルトは、ホスト型で推定30,000トークン、独自サーバーで3,500です。サーバーのコンテキスト上限が小さければ減らしてください。Marinaraは古いメッセージから除外し、続いて最新メッセージの先頭側を切り詰めます。トークン推定値はサーバーのトークナイザーと異なる場合があり、拒否されたリクエストや予算超過は回答なしとなります。

**Time limit (seconds)**(制限時間、秒)は、チャット中に各Decision接続が回答を待つ時間です。0.5から30秒の範囲で、デフォルトは1.5秒です。それ以降の回答は回答なしとなります。ホスト型プロバイダーには1.5秒を超えることがあり、判定が不規則に失敗しているように見えます。**Test**を数回実行し、最も遅い回答より長く設定してください。その分、プリセット内の判定や返信前のエージェントの起動質問などは、最大でこの時間だけ返信を遅らせる可能性があります。

リンクしたキーの提供元接続を削除すると警告が表示され、Decision接続は再リンクが必要になります。単体の接続ファイルをインポートした場合も、キーまたはリンクを復元する必要があります。これらのファイルにはAPIキーも借用元接続IDも含まれません。

<a id="let-marinara-install-a-decision-model"></a>

## Marinaraによる判定モデルのインストール

Marinaraに判定専用モデルをダウンロード・実行させることもできます。ローカルチャットモデルの有無に関係なく、独立したローカルプロセスとして動作します。使用メモリーはチャットモデルの使用分に加算されます。ローカルモデルがすでにあるなら、別モデルをダウンロードする前にその判定を試してください。

組み込みOpen-JevモデルにはLinux **x86-64**、コンピュート能力7.5以降のNVIDIA GPU(Turing、RTX 20シリーズ以降)、580以降のドライバーが必要です。このパッケージはLinux ARM機器やPascal以前のカードには対応しません。実行できない環境でも項目は表示され、理由とDecision接続を設定する代替案が示されます。

| 組み込みモデル | モデルのダウンロード | ランタイムを含むディスク容量 | GPUメモリー |
| --- | --- | --- | --- |
| Open-Jev 2B | 約4.6 GB | 約10 GB | 約4.8 GB (4.5 GiB) |
| Open-Jev 9B | 約19.4 GB | 約25.3 GB | 約23.6 GB (22 GiB) |

これは固定されたモデルバージョンと測定した処理内容に基づくカタログの推定値です。GPU使用量と速度は処理内容で変わります。9Bモデルでは24 GB GPUの余裕がほとんどなくなります。選択したカードとほかの実行中モデルについて、インストーラーの判定を確認してください。

1. **Connections**で**Local Model**を展開し、**Decision sidecar (experimental)**(実験的な判定サイドカー)を選びます。
2. 警告を読み、**Enable decision sidecar**(判定サイドカーを有効化)をオンにします。確認すると機器の判定が表示され、警告の場合はボタンが**Enable anyway**(それでも有効化)になります。
3. モデルを選び、サイズ、ハードウェア判定、ライセンスを確認します。それまでは何もダウンロードされません。**Open-Jev 2B**は**Open-Jev 9B**よりはるかに少ないメモリーで動きますが、どちらもチャットへの正しい回答を保証しません。
4. **Decision model**で**Decision sidecar**を選びます。

判定モデルのHuggingFaceリポジトリーを貼り付けることもできます。Marinaraはそのリポジトリー自身のマニフェストを読み、このビルドに同梱されたランタイムでアーティファクト形式を扱えるか確認し、取得する基盤重みと合計サイズを表示してからインストールを提案します。確認できないリポジトリーは、見切りでインストールせず理由付きで拒否します。

複数のNVIDIA GPUがある機器では、**GPU**メニューで読み込み先カードを選びます。判定はそのカードが対象です。変更するとモデルを停止し、新しいカードで再起動します。

サイドカーをオフにするとプロセスは停止し、ファイルは残ります。**Remove files**(ファイルを削除)はモデルとランタイムを削除し、サイドカーがオフの間も利用できます。

<a id="thresholds"></a>

## しきい値

確率はモデル間で直接比較できません。同じ肯定例でも、あるモデルは0.99、別のモデルは0.2を返すことがあります。Marinaraのデフォルトしきい値は接続方法によって異なります。

| 選択したバックエンド | はい・いいえのデフォルトしきい値 |
| --- | --- |
| PrimaryまたはUtilityローカルチャットモデル | 0.5 |
| TypeSafe、OpenRouter、Custom System OneのDecision接続 | 0.5 |
| 管理対象Decision sidecar | モデルマニフェストの推奨値。組み込みOpen-Jev 2Bと9Bでは0.1 |

エージェントの**Run when probability is at least**(実行に必要な最小確率)でこのデフォルトを上書きできます。保存値が異なると、エディターはバックエンド推奨値への復元を提案します。モデルを切り替えるたびに設定を確認してください。

プロンプトの判定文とロアブックのDecision欄は、バックエンドのデフォルトを使います。エージェントのしきい値を変えても、これらは変わりません。**Custom System One接続の背後で自分で運用するOpen-Jevも0.5を使います。** Marinaraは任意の独自エンドポイントを自動識別・校正できません。そのため、0.5未満の肯定結果をいいえと扱う場合など、管理対象Open-Jevサイドカーとは結果が異なることがあります。

<a id="time-limits"></a>

## 制限時間

時間内に届かない判定は回答なしとなります。生成は[各機能のフォールバック](#where-marinara-uses-it)を使って続行するため、プロンプト分岐や必要なロアブックエントリーが省かれることがあります。

- Decision接続は**1.5秒**です。**Time limit**(制限時間)で変更できます。[Decision接続の設定](#set-up-a-decision-connection)を参照してください。
- ローカルモデルと判定サイドカーは**4秒**です。1ターンで多数の文を尋ねる場合、Open-Jev 9Bには追加の文ごとに少し長い時間が与えられます。
- 先に推論が必要なローカルモデルは**20秒**です。

生成をキャンセルすると判定リクエストも停止します。

## Decision modelのほかの設定

- **Also use it to pick who speaks in Smart response order.**(Smart応答順の発言者選択にも使用)はデフォルトでオフです。[グループチャット](../chats/group-chats.md#response-order-individual-only)を参照してください。
- **Decision statements per turn.**(1ターンあたりの判定文数)は、プロンプトとロアブックの判定文の計画を制限し、デフォルトは32、最大255です。枠は複数の段階で適用され、1ターンの全Decisionリクエスト数や支出に対する単一の上限ではありません。エージェントの起動質問とSmart応答順は別枠です。範囲、バッチ処理、優先順位の規則は[制限と費用](../prompts/conditional-prompts.md#limits-and-cost)を参照してください。
- ローカルモデルには**Also gate agents that run before the reply**と**Thinking**も表示されます。[すでに実行しているモデルの利用](#use-a-model-you-already-run)を参照してください。

## 精度: 誤回答を想定した設計

どのモデルも誤回答することがあります。先述の小規模な表現テストでは、Open-Jev 2Bの正しい「はい」のいくつかは、しきい値をわずかに上回るだけでした。判定の見落としや誤りを想定してください。

- 判定は微調整に使い、チャットに不可欠な内容には使わないでください。見落とした場合も、返信の個別調整が少し減るだけで、壊れないようにします。
- 同意、コンテンツ警告、安全上の指示を判定条件の対象にしないでください。
- 起動質問だけで実行するエージェントには、**Bypass the question after this many messages**(指定メッセージ数の後で質問を省略)を設定し、「いいえ」が続いて永久に実行されなくなるのを防いでください。

具体的な表現例と自分のチャットで試す方法は、[判定文の書き方](../prompts/conditional-prompts.md#writing-statements)を参照してください。

## トラブルシューティング

- **Testが失敗する。** メッセージに理由が示されます。キーの拒否、プロバイダーのレート制限、ローカルモデルの停止、判定モデルの未インストール、はい・いいえで答えなかった場合、時間切れなどです。
- **Testで制限時間超過と表示される、または判定が時々しか動かない。** プロバイダーの回答が、少なくとも一部の回で接続の**Time limit**より遅くなっています。数回テストし、最も遅い回答より長く設定してください。
- **起動質問があるエージェントが毎ターン動く。** Decisionモデルが未設定か回答していないため、質問がない場合と同じように動いています。**Test**を確認してください。
- **プロンプトの判定分岐が一度も使われない。** [判定分岐が表示されない場合](../prompts/conditional-prompts.md#when-a-decision-branch-never-appears)を参照してください。
- **Smart応答順が通常のAI呼び出しを続ける。** スイッチがオフか、そのターンにDecisionモデルが回答しませんでした。
- **各判定文と回答を確認するには、**ログレベルをdebugにします。[ログレベル](../CONFIGURATION.md#logging-levels)を参照してください。
