# ローカルモデルやセルフホストモデルへの接続

このガイドでは、自分のコンピューターや自分のサーバーで動くAIモデルにMarinara Engineを接続する方法を説明します。Ollama、LM Studio、KoboldCppといった代表的なローカルモデルサーバーと、それらを動かすために必要な設定を取り上げます。

## セルフホストとは

セルフホストのモデルとは、自分で管理するハードウェアで動くAIモデルのことです。ローカルモデルサーバーをインストールすると、そのサーバーがモデルを読み込み、コンピューター上のWebアドレスでリクエストに応答します。Marinara Engineは、有料のクラウドサービスの代わりにこのアドレスと通信します。

代表的なローカルモデルサーバーには、Ollama、LM Studio、KoboldCppがあります。どれも自分のコンピューターで動き、専用のエンドポイントを用意します。エンドポイントとは、サーバーがリクエストを待ち受けるWebアドレスのことです。

このガイドが扱うのは、自分でインストールして動かす外部のローカルサーバーです。Marinaraには、別のサーバーを用意しなくても使える小さな組み込みモデルも付属しています。そちらを使いたいときは、[Local Modelのセットアップ](local-model.md)を参照してください。

始める前に、ローカルモデルサーバーをインストールして起動し、モデルを読み込ませておく必要があります。Marinaraがそのサーバーを起動することはありません。接続するだけです。

## Custom接続の作成

Marinaraは**Custom (OAI-Compatible)**プロバイダーを介してローカルサーバーに接続します。OAI互換とは、そのサーバーがOpenAI Chat Completions APIと同じリクエスト形式を扱えるという意味です。Ollama、LM Studio、KoboldCppはいずれもこの形式に対応しています。

次の手順で接続を作成します。

1. アプリの右側から**Connections**(接続)パネルを開きます。
2. **Add**(追加)をクリックします。**Add account**(アカウントの追加)ウィンドウが開きます。
3. ステップ1で**Custom (OAI-Compatible)**を選びます。これは**On your computer**(このコンピューター上)の下にあります。
4. ステップ2で、**Address**(アドレス)欄にローカルサーバーのアドレスを入力します(下の表を参照してください)。
5. **API key**(APIキー)欄は空のままにします。ほとんどのローカルサーバーにキーは不要です。接続に`Ollama Local`のような名前を付けるには、**More options**(その他のオプション)を開き、**Name (optional)**(名前、任意)に入力します。
6. **Connect**(接続)をクリックします。
7. ステップ3で、サーバーが返す一覧からモデルを選びます。モデルIDを手で入力することもできます。**Done**(完了)をクリックします。

これで**Connections**パネルに接続が表示され、そのモデルが接続の下にまとめられます。チャットで使う前に動作を確認してください。下の「接続のテスト」を参照してください。

**API Key**欄はローカルサーバーでは任意です。**Custom (OAI-Compatible)**プロバイダーを選ぶと、この欄の下に案内が表示されます。Ollama、LM Studio、KoboldCppのようなローカルモデルではキーを空のままにできる、という内容です。代わりに**Address**だけを設定してください。

## 代表的なローカルサーバーのBase URL

**Address**(Base URLとも呼びます)は、ローカルサーバーがどこで待ち受けているかをMarinaraに伝える設定です。サーバーごとにデフォルトのアドレスとポートが決まっています。ポートとは、サーバーがコンピューター上で使う番号付きの通信路のことです。使っているサーバーに合わせてアドレスを指定します。

| ローカルサーバー | エンドポイント |
|---|---|
| Ollama | `http://localhost:11434/v1` |
| LM Studio | `http://localhost:1234/v1` |
| KoboldCpp | `http://localhost:5001/v1` |

ここでの`localhost`は「同じコンピューター」という意味です。Marinaraがモデルサーバーと同じコンピューターで動いているなら、これらのアドレスをそのまま使えます。

**Address**欄には、「Only use URLs from providers you trust. A malicious endpoint could intercept your messages and API keys.」という安全上の警告が表示されます。自分で用意したアドレス、または完全に信頼できるアドレスだけを入力してください。

### Windowsのファイアウォールに関する注意

Windowsでは、ローカルサーバーが動いていても接続が遮断されることがあります。**Custom (OAI-Compatible)**プロバイダーを選ぶと、編集画面に次の注意が表示されます。プロキシやローカルサーバーが検出されない場合、Windows Defender Firewallが接続を遮断している可能性があります。解決するには、Windows Securityを開き、Firewall and network protection、Allow an app through firewallの順に進んで、Node.jsまたは使用中のサーバーアプリを追加します。

## Treat as local/custom endpointトグル

接続の編集画面には**Local / Custom Endpoint**(ローカル/カスタムエンドポイント)セクションがあり、その中に**Treat as local/custom endpoint**(ローカル/カスタムエンドポイントとして扱う)というトグルがあります。デフォルトはオフです。セルフホストのエンドポイントやプロキシ経由のエンドポイント、とくにローカルネットワーク上のモデルサーバーを指すカスタムWebアドレスを使うときはオンにします。

このトグルがオフのとき、Marinaraは認識できないモデルに対してツール呼び出しを控えめに扱います。オンにすると、Marinaraは常にツール呼び出しを試みるようになります。さらにProfessor Mariも、ネイティブのツール呼び出しだけに頼らず、代替のツール方式(JSONのツールプロトコル)を使うようになります。Professor Mariはアプリ内のアシスタントです。

Professor Mariがツールを使った後で止まってしまう場合は、このトグルをオンにしてください。エンドポイントがOpenAI互換をうたっていてもツール呼び出しが安定しない場合も同じです。オフのままでローカルモデルが問題なく動いているなら、そのままでかまいません。

## 別のコンピューターにあるサーバーへの接続

Marinaraは自分のコンピューターへの接続を常に許可します。`localhost`や`127.0.0.1`のようなアドレスはループバックアドレスと呼ばれ、「同じコンピューター」を意味します。これらは追加の設定なしで必ず接続に使えます。

モデルサーバーが家庭や職場のネットワーク内の別のコンピューターで動いている場合、そのアドレスはプライベートネットワークのアドレスになります。Marinaraは安全のため、プライベートネットワークのアドレスをデフォルトで遮断します。許可するには、Marinaraサーバーを運用している人が環境変数を設定する必要があります。環境変数とは、サーバーが起動時に読み込む設定のことです。

サーバーの`.env`ファイルに次の行を追加します。

```
PROVIDER_LOCAL_URLS_ENABLED=true
```

変更を反映するには、ファイルを保存してMarinaraサーバーを再起動します。その後は、`http://192.168.1.50:11434/v1`のように、ネットワーク上の別のコンピューターを指すBase URLを使えます。

Androidでは、この設定を指定しない場合はデフォルトでオンになります。`.env`ファイルとサーバーの設定について詳しくは、[サーバー設定リファレンス](../CONFIGURATION.md)を参照してください。

## 接続のテスト

Addの流れの**Connect**で、接続はすでに確認されています。モデルの編集画面の下部には、もう一度確認するための**Connection Tests**(接続テスト)カードがあります。チャットでその接続を使い始める前に確認してください。

1. **Connections**パネルでモデルをクリックします。モデルの編集画面が開きます。
2. **Test Connection**(接続をテスト)をクリックします。Base URLと設定に到達できるかどうかを確認し、かかった時間を表示します。
3. モデルをまだ選んでいなければ、ここで選びます。
4. **Send Test Message**(テストメッセージを送信)をクリックします。選んだモデルに「hi」という単語を送り、その返答を表示します。

どちらのテストも成功すれば、ローカルモデルをチャットで使えます。チャットを開き、その設定からこの接続を選ぶか、チャット入力欄の**Connections**メニューを使ってください。

同じモデルでエージェントの起動判定などの判断にも答えられ、Marinaraが2つ目のコピーを読み込む必要はありません。接続設定の**Use this model for decisions**(このモデルを判断に使用)をクリックしてください。[Decisionモデル](decision-models.md#on-a-server-you-already-run)を参照してください。

テストが失敗したときは、まずローカルサーバーが動いているか、モデルが読み込まれているかを確かめます。次に、**Address**がサーバーのアドレスとポートに正確に一致しているかを確認します。別のコンピューターにあるサーバーの場合は、`PROVIDER_LOCAL_URLS_ENABLED`が設定されていること、そしてMarinaraサーバーを再起動したことを確かめてください。
