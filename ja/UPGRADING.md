# Marinara Engineのアップデート

このガイドでは、Marinara Engineを新しいバージョンにアップデートする方法を説明します。すべてのインストール方法、アプリ内のアップデート機能、アップデートに失敗したときの対処をまとめています。アップデートしてもチャットと設定はそのまま残ります。

## データの保持

Marinara Engineをアップデートしてもデータは消えません。チャット、キャラクター、ペルソナ、ロアブック、プリセット、接続、設定はすべてそのまま残ります。

Marinaraは、サーバーを動かしているコンピューターのローカルのデータフォルダーにデータを保存します。DockerとPodmanでは`marinara-data`ボリュームに保存します。アップデートで置き換わるのはアプリのコードだけで、このデータフォルダーやボリュームには手を付けません。

公式のエージェント、マップ、通話、Conversationのゲームが同梱されていたバージョンからアップデートすると、最初の起動時に、対応する任意のパッケージを公式カタログからダウンロードします。既存のチャットの選択、エージェントの設定、保存済みの実行データ、履歴はそのまま保持します。この最初の起動の間は、サーバーをオンラインのままにしてください。カタログに接続できない場合、Marinaraは保存済みの設定を削除したり無効にしたりせず、次回の起動時に移行をやり直します。

ダウンロードしたドキュメント言語(**Settings**(設定) → **General**(全般) → **Documentation Language**(ドキュメント言語))を使っている場合は、アップデート後の最初の起動時にその言語パックの変更も確認し、自動的に最新の状態にします。ダウンロード元に接続できない場合は、インストール済みのパックをそのまま使い(そのパックにないガイドは英語で表示します)、次回の起動時にもう一度試します。言語の選択がアップデートでリセットされることはありません。

データの保存場所と控えの取り方は[Marinaraのバックアップと復元](data/backup-and-restore.md)で説明しています。

## 事前のバックアップ

アップデートは安全ですが、バックアップを取っておくと安心です。バージョンを大きく飛ばすときは、必ず先に作成してください。

1. **Settings**を開きます。
2. **Advanced**(詳細設定)タブを開きます。
3. **Backup & Export**(バックアップとエクスポート)セクションを探します。
4. **Download Backup**(バックアップのダウンロード)をクリックします。
5. `.zip`ファイルを安全な場所に保存します。

処理中はボタンの表示が**Creating backup…**に変わります。完了すると、ブラウザーがデータをまとめた`.zip`アーカイブを保存します。

バックアップと復元の詳しい手順は[Marinaraのバックアップと復元](data/backup-and-restore.md)にあります。

## プラットフォーム別のアップデート

Marinaraをどの方法でインストールしたかに合わせて、該当する節を読んでください。以下で言う「git checkout」とは、Gitというツールでインストールしたコピーのことです。「clone」は、Gitで取得したコピーを指します。

### Windows

Windowsのインストーラーまたはgit checkoutを使った場合は、ランチャーが自動でアップデートします。

1. Marinara Engineを終了します。
2. スタートメニューのショートカットから開き直すか、`start.bat`を実行します。

ランチャーが最新のコードを取得し、変更部分を再インストールし、アプリをビルドし直して新しいバージョンを起動します。インストーラーでも手動のcloneでも同じように動きます。

1回だけアップデートを飛ばしたいときは`start.bat --skip-update`を実行します。起動のたびにインストール済みのEngineのバージョンを保ちたいときは、プロジェクトの`.env`に`AUTO_UPDATE_ENABLED=false`を設定します。これで無効になるのはEngineの自動アップデートだけで、手動のコマンドと**Settings → Advanced → Check for Updates**は引き続き使えます。

Node.jsが古いとランチャーが表示した場合は、Node.js 24 LTSをインストールしてからMarinaraを起動し直します。LTSはLong Term Supportの略で、Node.jsの推奨される安定版を指します。

GitHubのReleasesページから最新のインストーラーをダウンロードして実行する方法もあります。こちらも同じgitベースの仕組みを使うので、以降のアップデートも引き続きランチャー経由で動きます。

### macOSとLinux

Marinara Engineを終了し、Marinaraのフォルダーからランチャーを実行します。

```bash
./start.sh
```

ランチャーが最新のコードを取得し、変更された依存パッケージを再インストールし、ビルドし直して新しいバージョンを起動します。

1回だけ飛ばしたいときは`./start.sh --skip-update`を使います。常に無効にしたいときは、`.env`に`AUTO_UPDATE_ENABLED=false`を設定します。手動のアップデートコマンドとアプリ内のアップデート機能は引き続き使えます。

Node.jsが古いと表示された場合は、Node.js 24 LTSをインストールしてからランチャーを実行し直します。

### DockerまたはPodman

コンテナーでインストールした場合は、ランチャーではなく新しいイメージを取得してアップデートします。Composeファイルのあるフォルダーで次のコマンドを実行してください。

```bash
docker compose down && docker compose pull && docker compose up -d
```

Podmanの場合は、同じコマンドを`podman`で実行します。

```bash
podman compose down && podman compose pull && podman compose up -d
```

リリースイメージは`ghcr.io/pasta-devs/marinara-engine:X.Y.Z`と`:latest`、および対応する`-lite`付きのタグとして公開しています。意図して古いリリースにとどまりたい場合を除き、`:latest`か最新のバージョンタグを取得してください。`marinara-data`ボリュームの中のデータはpullの影響を受けません。

### Android (Termux)

TermuxはAndroid向けのターミナルとLinux環境です。そのランチャーは、実行するたびにMarinaraをアップデートします。

1. Termuxを開きます。
2. ランチャーを実行します。

```bash
cd Marinara-Engine
./start-termux.sh
```

ランチャーがコードをアップデートし、必要に応じてNode.jsを新しいバージョンに入れ替え、ビルドし直してローカルのサーバーを起動します。

アップデートに問題があり、今のコピーのまま使いたいときは、アップデートの確認を飛ばします。

```bash
cd Marinara-Engine
./start-termux.sh --skip-update
```

常に無効にしたいときは、プロジェクトの`.env`に`AUTO_UPDATE_ENABLED=false`を設定します。これが影響するのはランチャーが管理するEngineのアップデートだけで、手動のアップデートとアプリ内のアップデート機能は引き続き使えます。

Androidのアプリアイコン(APK)を使っている場合は、[最新のAPKをダウンロード](https://github.com/Pasta-Devs/Marinara-Engine/releases/latest/download/marinara-engine-android.apk)し、ダウンロードしたファイルを開いてAndroidラッパー自体を更新します。その後Marinara Engineを開き、**Install / Start Marinara**をタップしてTermux側のコピーを更新、起動します。アプリは非公開のlocalhost認証情報を自動的に保持して受け渡します。更新時に署名情報やこのシークレットを求めることはありません。

### iPhoneとiPad

iPhoneとiPadではMarinaraのサーバーは動きません。別のデバイスで動いているサーバーにSafariから接続して使います。ホーム画面にあるコピーはPWA(Progressive Web Appの略)です。PWAとは、ホーム画面に追加してアプリのように開けるWebサイトのことです。

1. Marinaraのサーバーを実際に動かしているコンピューター、Dockerホスト、Androidデバイスをアップデートします。そのデバイスの節を参照してください。
2. iPhoneやiPadでホーム画面のPWA、またはSafariのタブを再読み込みします。

サーバー側をアップデートしてもSafariが古いビルドを表示し続ける場合は、キャッシュされたコピーをリセットします。

1. ホーム画面のアイコンを削除します。
2. MarinaraのホストについてSafariのWebサイトデータを消去します。
3. もう一度ホーム画面に追加します。

## アプリ内でのアップデートの確認と適用

Marinaraはアプリの中からGitHubを確認して、新しいバージョンの有無を調べられます。インストール方法によっては、ブラウザーからそのままアップデートを適用することもできます。

1. **Settings**を開きます。
2. **Advanced**タブを開きます。
3. **Updates**(アップデート)セクションを探します。

### Release Channel

**Release Channel**(リリースチャンネル)ドロップダウンで、どのビルドを追いかけるかを選びます。選択肢は2つです。

- **Latest Stable**: `vX.Y.Z`のタグが付いたリリースを追います。ほとんどの場合はこちらを選びます。
- **Staging/UAT**: 公開前のテスター向けビルドを追います。未完成の場合があります。使う前にデータをバックアップしてください。

**Staging/UAT**を選ぶと、「Staging builds are pre-release tester builds. Back up your app data before applying them.」という警告が表示されます。

チャンネルの切り替えは、意図した操作として扱います。サーバーを動かしているコンピューター上のブラウザーから別のチャンネルを選ぶと、アップデートのボタンが**Switch to**とチャンネル名の表示に変わり、アプリ内のアップデートがオフになっていても動きます。実行中は**Switching…**と表示されます。同じチャンネル内での通常のアップデートには、後述のApply Updateの条件が必要で、別のデバイスからの場合は常に必要です。

### Check for Updates

**Check for Updates**(アップデートの確認)をクリックします。処理中はボタンに**Checking…**と表示されます。

ボタンの下には**Release**のバージョンと**Build**のコミットコードが表示されます。ブランチがわかる場合は**Branch**の行も出ます。

- 最新の状態なら、緑のチェックが付いた行に「You're on the latest ... target」とバージョンが表示されます。
- 新しいバージョンがある場合は、「vX.Y.Z available」と表示されたカードに**Release notes**リンクが付きます。
- gitでインストールしていて単にコミットが遅れているだけの場合は、代わりに「N commits behind」と表示されます。コミットはコードに保存された変更1件を指すので、この数にはまだリリースされていない作業も含まれます。

アップデートの確認結果はキャッシュします。リリースバージョンの確認は約15分、「commits behind」の数は約5分キャッシュされます。**Check for Updates**をすぐにもう一度クリックしても、同じ数字が表示されることがあります。

### Apply Update

**Apply Update**(アップデートの適用)ボタンは、ブラウザーからアップデートできるインストールの場合にだけ表示されます。次の2つが両方とも必要です。

- gitベースのインストールであること(Dockerやパッケージ版はこの方法で適用できません)。
- サーバーの管理者がサーバーの`.env`ファイルに`UPDATES_APPLY_ENABLED=true`を設定していること。`.env`ファイルにはサーバーの設定が入っています。

サーバーを動かしているコンピューター上で**Apply Update**をクリックする場合は、これだけで足ります。秘密の文字列は不要です。

別のデバイスからの適用はデフォルトでオフです。次の3つがすべて必要になります。

- サーバーの管理者が`.env`に`UPDATES_ALLOW_REMOTE_APPLY=true`を設定していること。
- サーバーの管理者が`.env`に`ADMIN_SECRET`(保護された操作のためのパスワード)を設定していること。
- 手元のデバイスの**Settings -> Advanced -> Admin Access**に同じ秘密の文字列を保存していること。

**Apply Update**をクリックすると、ボタンが**Updating...**に変わります。サーバーが新しいコードを取得し、依存パッケージを再インストールし、ビルドし直してから停止します。その後「Update applied successfully. Please relaunch the app to use the new version.」と表示されます。Marinaraを起動し直せば完了です。

**Apply Update**が使えない場合は、その理由と代わりの手順をMarinaraが表示します。

- コンテナーでインストールした場合は、イメージのタグと、ホストで実行する`docker compose pull && docker compose up -d`コマンドを表示します。
- gitでインストールしていて適用がオフの場合は、コピーして使える手動のアップデートコマンドを表示します。
- それ以外のインストールでは、GitHubのリリースへの**Download**リンクを表示します。

確認そのものに失敗した場合は「Could not check for updates. Try again later.」と表示されます。たいていはネットワークかGitHub側の問題なので、少し待ってからもう一度試してください。

## Refresh Appボタン

**Refresh App**(アプリの再読み込み)ボタンは、同じ**Updates**セクションにあります。これはサーバーのアップデートではありません。今使っているブラウザーの中でアプリを読み込み直すだけです。

**Refresh App**はサービスワーカーの登録を解除し、ブラウザーのキャッシュを消してからページを再読み込みします。サービスワーカーとは、アプリを速く、またオフラインでも読み込むためにブラウザーが使う小さなスクリプトです。保存済みのチャット、設定、その他のローカルデータはそのまま残ります。

サーバーはすでに新しいバージョンで動いているのに、アップデート後のアプリの表示が古いままだったり画面が真っ白になったりするときは、**Refresh App**を使います。直せるのは固まったWebページだけです。サーバーのコードは変わらないので、本来のアップデートの代わりにはなりません。

処理中はボタンに**Refreshing…**と表示され、その後アプリが再読み込みされます。

## 古いバージョンへダウングレードする

アップグレードは常に安全ですが、直接元へ戻せるとは限りません。新しいMarinaraはチャットメッセージを新しいディスク形式で保存し、データ形式より古いバージョンはそれを読み取れません。チャット履歴を守るため、ランチャーは互換性のないバージョンへ移る自動更新をスキップし、アプリ内アップデーターも適用を拒否します。

それでも古いバージョンが必要な場合は、1つの変換コマンドで先にデータを旧形式へ戻せます。手順は[古いバージョンへ切り替えたらチャットのメッセージが表示されない](TROUBLESHOOTING.md#chats-show-no-messages-after-switching-to-an-older-version)を参照してください。

## アップデートに失敗したとき

アップデートの問題のほとんどは、古いNode.js、途中で終わったダウンロード、ブラウザーの古いキャッシュが原因です。

- Node.jsが古いとランチャーが伝えてきた場合は、Node.js 24 LTSをインストールしてから起動し直します。
- サーバーのアップデート後にアプリの表示が崩れている場合は、上の**Refresh App**ボタンを試します。
- gitでインストールしたコピーがうまくアップデートできない場合は、そのインストールガイドに載っているプラットフォーム別の手動アップデートコマンドを実行します。

エラーメッセージと手順ごとの対処は[Marinara Engineのトラブルシューティング](TROUBLESHOOTING.md)で説明しています。
