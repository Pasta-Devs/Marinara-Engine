# Game Mode: はじめに

Game Modeを使うと、Marinara EngineはAIのゲームマスターが進行する1人用のロールプレイングゲームになります。このガイドでは、Game Modeとは何か、始める前に何が必要かを説明します。続いて設定ウィザードの流れをたどり、各ゲーム機能がどこにあるかを示します。ひととおり読んだらゲームを始めて、さらに詳しい内容は最後のリンクから読み進めてください。

## Game Modeとは

Game ModeはMarinaraのチャットモードの1つです。ほかにConversationとRoleplayがあります。

Game Modeでは、AIのゲームマスター(GM)が物語を進行します。ゲームマスターとは、世界の様子を語り、出会うキャラクター全員を演じ、次に何が起こるかを決めるAIです。テーブルトークRPGのダンジョンマスターと同じ役割だと考えてください。

ターンをまたいだ世界の状態は、エンジンが自動で追跡します。マップ、パーティー、プレイヤー以外のキャラクター(NPC)、持ち物、クエスト、ゲーム内の時刻、天候などが対象です。ゲームは多くのターンにわたって進みます。長いゲームは複数の**セッション**に分けられます。テーブルトークのグループが1つのキャンペーンを何日かの集まりに分けて遊ぶのと同じです。キャンペーンとは、続いていく物語の全体を指します。

すべての仕組みを使う必要はありません。戦闘とダイスを使わず、物語と映像を楽しむためだけにGame Modeを使うプレイヤーもいます。RPGの各システムは、使いたいときにだけ使えば十分です。

## 始める前に

ゲームを始めるのに必要なものは1つだけです。GM用のAIプロバイダーとの接続です。接続があると、Marinaraがそのプロバイダーに文章を生成させられるようになります。まだ用意していない場合は[AIプロバイダーへの接続](../connections/connecting-to-a-provider.md)を参照してください。

これ以外はすべて任意で、デフォルトではオフです。後から追加できます。

- **画像生成。** Game Modeには背景とキャラクターの絵を表示するビジュアルなレイアウトがあります。ここを埋めるには画像生成用の接続が必要です。設定ウィザードの**Visual Generation**はデフォルトでオフなので、自分でオンにしてください。オフのままでも、物語、状態の追跡、戦闘は問題なく動きますが、画像の領域は空のままになります。
- **シーン演出用のローカルモデル。** Marinaraは自分のコンピューターで小さなモデルを動かせます。画面上の表記は**Local Model (Gemma)**です。追加費用なしで背景と音楽の提案を担当します。設定ウィザードではこれがデフォルトの選択肢です。[Local Modelのセットアップ](../connections/local-model.md)を参照してください。
- **Storyboardエージェント。** **Agents > Download Agents**からインストールします。静止画または動く絵コンテを使いたいときは、ゲームができあがったあとに**Chat Settings > Agents**で有効にします。
- **動画生成用の接続。** シーンの動画や動く絵コンテを使う場合にだけ必要です。
- **音楽。** **Music DJ**エージェントはゲーム中の音楽を再生できます。Spotifyかローカルの音楽フォルダーが必要で、デフォルトではオフです。

## 設定ウィザード

Game Modeのチャットを作成すると、**設定ウィザード**が開きます。ステップは7つです。必須の入力は最初のステップのGM接続だけで、ほかの項目には妥当なデフォルトが入っています。手早く進めて、残りはMarinaraに任せてかまいません。

7つのステップは次のとおりです。

1. **Connection。** ゲーム名を決め、GM用の接続を選びます。必要ならシーン演出用の接続も指定します。シーン演出のデフォルトは**Local Model (Gemma)**です。
2. **World。** ジャンル、舞台、トーン、難易度、コンテンツレーティング、言語を設定します。
3. **Party。** 自分が演じるペルソナ、**Game Master Mode**、パーティーメンバーを選びます。
4. **Goals。** 冒険に何を求めるかをGMに伝えます。
5. **Lorebooks。** GMが事実として扱うロアブックを添付します。ロアブックとは、世界の背景設定をまとめたものです。[ロアブック](../lorebooks/overview.md)を参照してください。
6. **Features。** Visual Generation、Music DJ、HUDウィジェットなど、任意の機能をオンにします。インストールして使うエージェントは、ゲームの作成後にChat Settingsから有効にできます。
7. **GM。** 演出のスタイルを選び、世界が生成される前にGM向けの詳細な指示を確認します。

入力が終わったら**Start Game**をクリックします。

### 覚えておきたいデフォルト

次の値は**World**、**Party**、**Features**の各ステップの初期値です。どれも変更できます。

| 設定 | デフォルト | 備考 |
|---|---|---|
| Genre | Fantasy | 複数選択できます。独自の項目も追加できます |
| Tone | Heroic | 複数選択できます |
| Difficulty | Normal | Casual、Normal、Hard、Brutalから選びます。上の設定ほど戦闘が厳しくなります |
| Content Rating | SFW | SFWまたはNSFW。NSFWはアダルト表現を許可するだけで、強制はしません |
| Language | English | ゲーム内のテキストはすべてこの言語で書かれます |
| Game Master Mode | Standalone GM | Standalone GMはGMを自動で用意します。Character GMは手持ちのキャラクターカードをGMとして使います |
| Visual Generation | Off | 画像を使うならオンにします。画像生成用の接続が必要です |
| Game Presentation | Standard | **Storyboard Optimized**はStoryboard Game PromptでGMの語り方を整えます。Storyboardエージェントのインストールや有効化は行いません |
| Music DJ | Off | Spotifyかローカルの音楽フォルダーが必要です |
| Custom HUD Widgets | On | 生成された世界に合わせてAIが作る状態ウィジェットを使います |
| Start Muted | Off | 音声をミュートした状態でゲームを始めます |

Game Modeが初めてなら、**Game Master Mode**は**Standalone GM**のままにしてください。Marinaraが公平で少し皮肉っぽいGMを用意するので、独自のGMカードを書く前にモードの雰囲気をつかめます。

GMのターンを映像化しやすい見せ場として書かせたいときは、最後のステップで**Storyboard Optimized**を選びます。この設定は、GMの語り用に内蔵の**Storyboard Game Prompt**を選びます。Storyboardエージェントのインストールや有効化は行いません。画像生成や動画生成がオンになることも、選択済みの接続が変わることも、エージェントのプランナーや整形処理のデフォルトが置き換わることもありません。ゲームができあがったら、Storyboardを別途インストールして有効にし、キーフレーム、プランナー、画像、動画の設定を**Chat Settings > Agents > Storyboards**で調整してください。

アニメ調の1ショット構成も、設定の完了後に選べます。Animation Plannerに**Anime Episode Director**を、Storyboard Video Promptに**Anime Game Video**を選んでください。

**GM Prompt**エディターでは、選択中の演出で実際に使われるプロンプトをプレビューできます。**Storyboard Optimized**を選んだ状態でエディターを開くと、キーフレーム数のマクロを含むStoryboard Game Promptが表示されます。この文章を変更しなければ内蔵プリセットが選択されたままです。編集すると、演出のプリセットより優先される独自のプロンプトになります。

## 3種類のAI呼び出し

Game Modeは3種類のAI呼び出しを使い分けます。これを知っておくと、費用とエラーがどこから来るのかを理解しやすくなります。

1. **世界の生成。** **Start Game**をクリックしたときに1回だけ実行します。GM用の接続が、JSONという形式で構造化された大きな文書を1つ返します。この文書には世界の概要、開始時のマップ、NPC、パーティーのゲームシート、画面上のウィジェットが含まれます。JSONは厳密なテキスト形式で、AIが正確に返さないとゲーム側が読み取れません。もっとも負荷の高いステップなので、モデルの選択がここでいちばん効いてきます。
2. **ゲームのターン。** メッセージを送るたびに、そのときの状態を含む新しいプロンプトを組み立てます。GMはそれを受けて物語を語り、世界を更新します。戦闘のラウンドの計算はモデルではなくエンジンが行うので、結果は公平で一貫しています。
3. **セッションの要約。** セッションを終了すると、GMが構造化された振り返りと継続用のメモを書きます。新しいセッションを始めるときは、次の章がなめらかに始まるように短いつなぎのメッセージを書きます。古いセッションは要約に圧縮されるので、長いキャンペーンでもモデルが処理しきれなくなりません。

## 宛先モード: 誰に話しかけるか

入力バーには、ファイル添付ボタンの隣に小さな吹き出しのボタンがあります。ツールチップには**Choose who to address**と表示されます。このボタンでメッセージの宛先を切り替えます。状態は3つあります。

- デフォルトでは、メッセージはシーンに向けて送られます。ゲーム内の行動やせりふとして扱われ、GMとパーティーが物語の中で応じます。
- **Talk to Party**は`[To the party]`という目印を付け、仲間に直接話しかけます。「ここではどうしますか」のような作戦の相談に使います。この選択肢はパーティーにメンバーがいるときだけ表示されます。
- **Talk to GM**は`[To the GM]`という目印を付け、キャラクターの外側からGMに尋ねます。「自分のキャラクターはその神殿を知っているか」のような質問や、展開の速さについての要望に使います。

選択中のモードには、メニュー内に**On**の印が付きます。**Talk to Party**や**Talk to GM**をオフにするには、同じメニュー項目をもう一度クリックします。メッセージの宛先はシーンに戻ります。

## 任意のツール計画とロア検索

プレイ中に**Chat Settings → Function Calling**(チャット設定→関数呼び出し)を開きます。**Let the GM search lore**(GMによるロア検索を許可)を使うと、他の任意ツールをすべて有効にせずに、GMが意味に基づいて情報を検索できます。まず対象のロアブックでベクトル化を有効にし、エントリーをベクトル化してください。検索は有効なブックやフォルダー、チャットごとのエントリーの切り替えに従います。設定された埋め込み接続を使い、モデルへの追加リクエストが発生する場合があります。

**Game tool connection**(ゲーム用ツール接続)の初期値は**Same as narrator**(ナレーターと同じ)で、通常のツールループを維持します。別の接続を選ぶと、物語の生成前に独立した計画リクエストを1回だけ実行します。そのモデルがツールを選び、ナレーターは実際の結果をテキストで受け取ります。追加リクエストは選択した接続に課金されます。安価なモデルならツールの費用を抑えられますが、選ぶツールが変わる可能性があります。この1回の計画では、最初の検索結果を基に2回目の検索を続けることはできません。ナレーターに複数回のツール呼び出しを通して考えさせたい場合は、**Same as narrator**を使ってください。

ClaudeとGrokのサブスクリプション接続はネイティブのツール呼び出しに対応していません。該当する操作項目に説明が表示され、対応するGame用ツール接続を選ぶまでは無効になります。テキストコマンドとダイスタグは引き続き動作します。別の接続が見つからない場合やリクエストに失敗した場合、要求したツール処理を黙って省略して物語を進めず、そのターンにエラーを表示します。

## エージェントをオンにする

エージェントは、GMと並行して動く任意のAIの助け手です。ゲームで使うには、プレイ中に**Chat Settings**(チャット設定)を開き、**Agents**セクションで**Enable Agents**をオンにします。エージェントは追加の呼び出しを行うため、動かすと費用が増えます。

Game Modeで特に知っておきたいエージェントは2つです。

- **Game Session Keeper**は、セッションをまたいだ話のつながりを保つ手助けをします。
- **Music DJ**は背景の音楽を選びます。Spotifyかローカルの音楽フォルダーが必要です。

Game Modeでは**Review Agent Outputs**も使えるので、エージェントが何を出力したかを確認できます。エージェントの全体像は[エージェント: チャットを支えるAIヘルパー](../agents/agents-overview.md)を参照してください。

## モデルの選び方

Game Modeでもっとも難しいのは世界の生成です。項目の欠けがない、長く厳密なJSON文書をモデルに要求します。ふだんのチャットを上手にこなすモデルでも、このステップで失敗することがあります。

世界の生成には、有料の接続で使える性能の高い最新の上位モデルを選んでください。2026年時点では、主要プロバイダーの最上位クラスで良い結果が出たという報告が多くあります。たとえばAnthropic Claude、OpenAI GPT、Google Geminiです。具体的なモデル名はよく変わるので、固定の一覧ではなく例として受け取ってください。

その後のゲームのターンは、安いモデルに落として問題ない場合もあります。ターンで求められるのは厳密なJSONではなく地の文だからです。GMがNPCを忘れ始めたり、前の描写と矛盾したりしたら、また強いモデルに戻してください。

世界の生成では、無料モデルと自動振り分けのモデルは避けてください。世界生成用のJSONを正しく作れない小さなモデルに振り分けられることがあります。小規模なオープンウェイトのモデルも、たいていこのステップで失敗します。

パラメーターの詳しい説明は[生成パラメーター](../prompts/generation-parameters.md)を参照してください。

## トラブルシューティング

### 世界の生成がJSONエラーや422エラーで失敗する

いちばん多い原因は、モデルが構造化されたJSONを最後まで作れなかったことです。次の順に試してください。

1. GMがどの接続を使っているか確認します。無料モデルや自動振り分けのモデルを指している場合は、性能の高い有料のモデルに切り替えます。
2. もう一度試します。一時的な失敗もあり、同じ設定でも2回目で通ることがあります。
3. 長すぎる舞台設定や希望を書いた欄を短くします。入力が長いと、JSONを出力する余地がモデルに残りません。

生成がほぼ成功していて、JSONが少しだけ壊れていた場合は、**Repair JSON**ウィンドウが使えます。モデルの生の出力を、行番号付きのエディターで開けます。状態を示す行に、JSONが正しいかどうか、あるいは解析エラーの内容が表示されます。正しいJSONを整形するには**Format**をクリックします。続いて**Apply Repaired JSON**をクリックすると、最初からやり直して費用をかけることなく、修正した内容を使えます。**Repair JSON**はセッションの要約など、ほかの構造化された呼び出しでも表示されます。

ほかの症状と対処は[Marinara Engineのトラブルシューティング](../TROUBLESHOOTING.md)を参照してください。

### 暗いトーンを選んだのにGMが明るく語る

トーンにかかわらず明るいままのモデルもあります。方法は2つあります。設定ウィザードの希望欄に「地の文は重い調子を保ち、失敗を和らげないこと」のようなはっきりした指示を書き足します。あるいは、求めるトーンに近い語り口をもともと持つモデルに切り替えます。
