# Game Mode: ダイスとスキル判定

このガイドでは、Marinara EngineのGame Modeでダイスを振る方法を説明します。クイックダイスメニュー、独自のダイス記法、独自のダイスロールにかかる上限を取り上げます。さらに、ゲームマスター(GM)が難易度(DC)に対してスキル判定を行う仕組みも説明します。

## ダイスを振る

Game Modeのチャットでは、メッセージ入力バーにダイスボタンがあります。ボタンにカーソルを合わせると**Roll dice**(ダイスを振る)というヒントが表示されます。クリックするとクイックダイスメニューが開きます。

メニューには、1クリックで使えるプリセットが8つあります。

| プリセット | 振るダイス |
|---|---|
| d20 | 20面ダイス1個 |
| d6 | 6面ダイス1個 |
| 2d6 | 6面ダイス2個 |
| d10 | 10面ダイス1個 |
| d100 | 100面ダイス1個 |
| d4 | 4面ダイス1個 |
| d8 | 8面ダイス1個 |
| d12 | 12面ダイス1個 |

手早くダイスを振る手順は次のとおりです。

1. Game Modeのチャットでメッセージ入力バーを開きます。
2. ダイスボタンをクリックします。
3. 8つのプリセットのどれか、たとえば**d20**をクリックします。
4. 入力バーに`🎲 d20`のような小さなチップが表示されます。

ダイスロールはすぐには送信されません。いったん予約された状態になります。予約を取り消すときは、チップにある消去ボタンをクリックします。このボタンのヒントは**Clear queued roll**(予約したダイスロールの取り消し)です。

ダイスの計算は、次のメッセージを送信したときに実行されます。結果はタグとしてメッセージの末尾に追加されます。ボーナスなしでダイスを1個だけ振ると、次のような形になります。

```
[dice: d20 = 14]
```

ダイスが2個以上ある場合やボーナスが付く場合は、内訳も表示されます。

```
[dice: 3d8+2 = 18 (4, 6, 6 +2)]
```

ゲームマスターはこのタグを読み取り、結果に沿って物語を進めます。

ゲームマスターが1ターンで複数回ダイスを振ると、各ダイスカードが個別にキューへ入ります。カードを閉じると次のカードが表示されます。すべてのロールはそのターンのアクティブなスワイプ(別の回答候補)に保存され、再読み込み後も**Logs**(ログ)に残ります。ターンを続行すると以前のロールを維持し、再生成すると新しいスワイプ用に別のロール一式を作成します。

ゲームマスターは物語の中で`[dice: 3d8+2]`を使ってロールを要求することもできます。エンジンが実際の数値を決め、同じアニメーション付きカードを表示します。ClaudeやGrokのサブスクリプションを含む、テキスト専用の接続でも動作します。記法と上限はダイスメニューと同じです。

## 独自のダイス記法

ダイスメニューには、独自のダイスロールを入力するテキスト欄もあります。記法は一般的な`NdM`形式です。`N`は振るダイスの個数、`M`は1個あたりの面数を表します。末尾にボーナスやペナルティーを付けることもできます。

欄のプレースホルダーには`3d8+2`という例が表示されます。これは8面ダイスを3個振り、合計に2を足すという意味です。

独自のダイスロールを使う手順は次のとおりです。

1. ダイスボタンをクリックしてメニューを開きます。
2. テキスト欄に記法を入力します。たとえば`2d6+1`です。
3. Enterを押すか、欄の横にある紙飛行機の形をした送信ボタンをクリックします。
4. ダイスロールがチップとして予約され、送信できる状態になります。

入力できる例をもう少し挙げます。

- `d20`は20面ダイスを1個振ります。
- `4d8-1`は8面ダイスを4個振り、合計から1を引きます。
- `2d6+3`は6面ダイスを2個振り、合計に3を足します。

上限は2つあります。一度に振れるダイスは100個まで、1個あたりの面数は1000までです。これを超える指定は拒否せず、上限に合わせて切り詰めます。結果カードには調整後の記法を表示するため、`500d6`と入力すると、実際に振った100個分の`100d6`カードが表示されます。入力が正しいダイス記法でない場合、つまり`NdM`でも`d20`のような単独の`dM`でもない場合は、ロールが失敗し、期待される形式を示すエラーが表示されます。

## スキル判定

スキル判定は、忍び足、手がかりの発見、NPCの説得のように、失敗の可能性がある行動が成功するかどうかを決めるものです。スキル判定を自分から始めることはできません。ゲームマスターが物語の中で判定を求め、アプリがそれをアニメーション付きのd20のダイスロールと結果バナーに変えます。

テキストで要求された判定は、行動の試みから始まります。エンジンがダイスを解決した後、実際の結果を添えてモデルに追加で1回リクエストし、ゲームマスターが同じターン内で結末を描写できるようにします。ロールの前に結果を推測してしまった下書きも修正します。追加のリクエストではプロンプトを再送するため、入力・出力トークンをさらに消費します。失敗した場合、確定した結果はターンに残りますが、推測や書きかけの結末は保存されません。チャットを再読み込みした後も、そのターンには通知と**Regenerate turn**(ターンを再生成)ボタンが残ります。

**Chat Settings → Function Calling**(チャット設定 → 関数呼び出し)で**Narrate dice outcomes immediately**(ダイスの結果をすぐに描写)をオフにすると、追加リクエストを行わず、実際の結果を次のターンに引き継ぎます。この設定はデフォルトでオンです。実際のロールが発生しなかったリクエストでは、追加の描写リクエストを行いません。

2回目のリクエストなしで同じターンに結果を描写する、3つ目の選択肢もあります。下の[ダイスを使うターンを1リクエストで完了する](#finishing-a-rolled-turn-in-one-request)を参照してください。

ダイスツールに対応した接続では、ゲームマスターが生成中に実際のロール結果を取得できます。ツールが結果を返すとすぐにカードが表示され、完了した判定は振り直さずにその結果を記録します。解決したスキル判定にはそれぞれ個別のバナーが付き、キュー内のダイスカードに続いて表示されます。

バナーにはスキル名と目標値が表示されます。たとえば**Stealth Check**の隣に**DC 15**と出ます。DCはDifficulty Class(難易度)の略で、ダイスロールが到達すべき数値です。

### 結果の決まり方

判定では20面ダイスを1個振り、次の2つの修正値を足します。

- スキル修正値。ゲームがそのキャラクターについて記録しているスキルレベルから決まります。そのスキルのレベルがまだない場合、修正値は0です。
- 能力値修正値。そのスキルに対応する能力値から決まります。

ダイスの目に2つの修正値を足した数が合計値です。合計値がDC以上なら判定は成功、届かなければ失敗です。どのスキルがどの能力値に対応するかは自動的に決まります。たとえばStealthはDexterity、PerceptionはWisdom、PersuasionはCharismaを使います。アプリが認識できないスキルはIntelligenceとして扱われます。

### クリティカル成功とクリティカル失敗

次の2つの出目は、計算結果より優先されます。

- ナチュラル20(ダイスの目そのものが20)は**CRITICAL SUCCESS**(クリティカル成功)です。DCがどれほど高くても必ず成功します。
- ナチュラル1(ダイスの目そのものが1)は**CRITICAL FAILURE**(クリティカル失敗)です。修正値がどれほど大きくても必ず失敗します。

バナーには**CRITICAL SUCCESS**、**SUCCESS**、**FAILURE**、**CRITICAL FAILURE**の4つのうち1つが表示されます。

### その他のダイスシステム

ゲームマスターは`[skill_check: skill="Endurance" dc="12" dice="3d6+2"]`のような別の記法も指定できます。これらの判定ではキャラクターシートのd20修正値の代わりに記法内の固定修正値を使い、合計がDCに達すれば成功します。出目1と出目20の特別ルールは、上記の標準的なd20判定にのみ適用されます。

成功数を数えるダイスプールでは、ダイス1個ごとのしきい値と必要な成功数の両方を指定します。`[skill_check: skill="Intimidation" dc="4" dice="6d10" resolution="successes" threshold="6"]`はd10を6個振り、6以上の目が出たダイスをそれぞれ1回数え、成功数が4以上なら成功します。エンジンは未指定のしきい値を推測せず、エクスプローディングダイス、ボッチなどの特殊なプールルールも実装していません。有効なしきい値がないプールは未解決のままとなり、モデルが作り出した数値は削除されます。

これは**ルールセットのない**ゲーム用のプールで、動作は変わりません。ダイスプール方式のルールセットを持つゲームでは、エンジンが実際にルールを保持する別の方式を使います。下の[ルールセットを使うゲーム](#games-that-use-a-ruleset)を参照してください。

`4d6kh3`、`3d6!`、`4dF`などの未対応の指定ではダイスを振りません。エンジンは未対応の記法をログに記録し、モデルが作り出した数値を判定レコードから削除します。これらの結果は未確定のままです。エンジンが別のダイスシステムに黙って置き換えることはありません。

### アドバンテージとディスアドバンテージ

ゲームマスターは、アドバンテージ付きまたはディスアドバンテージ付きで判定を求めることもできます。両方が同時に付くことはありません。

- アドバンテージ付きの場合、アプリは20面ダイスを2個振り、大きいほうの目を採用します。
- ディスアドバンテージ付きの場合、アプリはダイスを2個振り、小さいほうの目を採用します。

ゲームマスターが両方を同時に指定した場合、アプリは意図を推測せず、その判定を処理しないため、バナーは表示されません。

どちらかが有効なときは、バナーのDCの隣にその状態が表示され、どちらのダイスを使ったかも示されます。

### ダイスを先に振っておく

判定が発生する前に、ダイスメニューから`d20`を予約しておくこともできます。予約しておくと、スキル判定は新しくダイスを振らず、予約した出目をそのまま使います。スキル修正値と能力値修正値は、その出目に対して同じように加算されます。

## ルールセットを使うゲーム

ゲームでは、Marinara独自のルールの代わりに5e (SRD 5.1)などのルールセットを使えます。ルールセットはそのゲームに属し、変更されません。作成時にセットアップウィザードの**Rules**(ルール)で選びます([ルールの選択](getting-started.md#choosing-rules)を参照)。ルールセットがないゲームは上記のとおり動作します。

ルールセットがあるゲームでは、次のようになります。

- Game Masterは引き続きスキルまたはセーヴの名前と難易度だけを指定します。組み込みの難易度表の代わりに、そのルールセットの難易度段階が伝えられます。難易度はその段階の範囲まで指定でき、Marinara独自の1～40を超えることもあります。ただし、保存済みターンで未実行の判定をロールするフォールバック経路だけは、ルールセットのゲームでも1～40です。
- Engineはルールセットのダイスを振り、キャラクターの**ルールセットのシート**の修正値を加えます。内訳はルールセットの宣言によって決まり、スキルやセーヴが能力値を指定する場合はその修正値、習熟段階のボーナス(習熟ボーナスの倍数、固定値、または両方)、シートに入力された追加ボーナスを使います。組み込みのスキルボーナスと属性は使いません。
- 仲間の判定もできます。Game Masterがタグに`who="Name"`を加えると、Engineはそのキャラクターのシートを使います。`who`がなければプレイヤーの判定です。シートがまだない仲間は、ルールセットの既定値を持つ空のシートでロールします。名前がパーティーの誰にも一致しない場合や2人に一致する場合は、一切の修正値なしで振ります。例外は自身のキャラクター名で、仲間と同名でも自身のシートを使います。Engineが別人のシートを借りることはありません。
- 自然出目はルールセットに従います。5e (SRD 5.1)では、判定とセーヴにナチュラル20や1の特殊効果はありません。ナチュラル20でも難易度に届かなければ失敗します。これは意図的にMarinara独自のルールと異なります。
- Game Master自身が書く数値は信頼されません。完成済みに見えるタグでも、修正値がシートと異なる、ダイスの数や面数がルールセットと異なる、採用したダイスがロールモードの指定と異なる、またはルールセットにない自然出目の効果を主張する場合は、振り直して置き換えます。
- 事前に自身で振ったダイスを使えるのは、ルールセットがd20を1個振る場合だけです。2d6やダイスプールなどの場合は無視し、通常どおり振ります。
- Game Masterはタグに`with="Ability"`を加え、通常とは異なる能力値でスキルやセーヴを判定できます。ルールセットで宣言された能力値だけが有効で、それ以外は無視して本来の能力値を使います。
- Game Masterは難易度を数値で書く代わりに、`difficulty="Hard"`のように難易度表の段階名で指定することもできます。Engineはその段階の数値に対してロールし、保存された判定には数値が表示されます。難易度表にない名前は無視されます。
- ロールプレースホルダーではルールセットの能力値、スキル、セーヴを指定でき、習熟ボーナスがあれば`PROF`も使えます。
- ルールセットのパッケージがないか、ゲーム作成時より古い場合、判定は数値なしで保存され、未実行のまま残ります。別のシステムのルールで振ることはありません。
- 失敗したダイスを振り直すチャームなど、シート上の要素がロールを変える場合、Game Masterが判定でその名前を指定し、あとはEngineが処理します。チャームのコストを引き、効果を適用して振ります。未取得のチャームやコストを払えないチャームは効果も消費もありません。
- ロールを安定させるためにリソースを使えるルールセットでは、Game Masterが判定自体にその消費を指定し、Engineがポイントの支払いと得られる効果の加算、ロールをまとめて行います。プールが不足していれば何も消費せず、通常のロールになります。記録には要求量ではなく実際に支払った量が表示されます。1回の判定で得られる量はルールセットが決めます。固定の数、シート上の数値、または判定のダイス数までのいずれかです。
- すべてのBrawnロールに重い荷物が影響するなど、シート上の数値が特定のロールに常に加わるとルールセットが定めている場合、Engineは該当するすべての判定にそれを加え、シートが加えた値をダイスカードに表示します。
- ルールセットは、スキルの訓練がない場合に判定がどうなるかを定められます。ダイスやポイントが減る、1段階難しくなる、そもそも判定できない、のいずれかです。訓練なしでは試みられない判定はロールされず、結果を表示する代わりにナレーションでその旨が語られます。そうしたスキルは、訓練するまでシートに数値が表示されません。
- 負傷トラックのペナルティをロールに適用するルールセットでは、負傷するとすべての判定が難しくなります。ダイスプール方式ではその数だけダイスを減らしますが、ルールセットの最小プールを下回りません。システムによっては最小が0です。合計方式では固定のペナルティとして適用します。いずれも判定に適用量が表示されるため、ダイスが減った理由を確認できます。[ルールセットのシート](party-and-npcs.md#the-ruleset-sheet)を参照してください。
- Game Masterは各キャラクターのリソース、状態、休息もシートに反映し、Engineはシートの許可しない変更を拒否します。[ルールセットのシート](party-and-npcs.md#the-ruleset-sheet)を参照してください。

### ダイスプールを振るルールセット

ロールにボーナスを加える代わりに、シートの数値だけダイスを振り、目標以上の出目を数えるシステムもあります。この方式のルールセットも作成でき、そのゲームは少し異なります。

- **シートの数値はダイス数です。** 評価値3と専門技能2なら5個振ります。編集画面でもGame Masterに渡す内容でも、"+5"ではなく"5 dice"と表示されます。
- **難易度は成功数です。** 難しい仕事に必要なのは合計15ではなく成功3回です。各段階に必要な成功数はルールセットの難易度表が定めます。
- **Engineが振って数えます。** どの出目を成功とするか、高い出目で追加ダイスを振るか2成功とするか、低い出目で成功を相殺するか、ファンブルや突出した成功の条件など、すべてルールセットが定めます。ダイスカードには振ったすべてのダイスが表示され、目標に届いたものと届かなかったものを区別し、必要数に対する成功数を示します。大きなプールは縮小せず複数行に折り返し、加算していないダイスの合計を表示することはありません。
- **Game Masterは個別の判定を調整できます。** ルールセットが許可する場合、各ダイスの目標を難しくも易しくもでき、状況に応じてダイスを増減でき、追加で振るか2成功とする出目を下げることもできます。いずれもルールセットの宣言範囲内に制限されます。難易度表の段階は独自のダイスごとの目標を持つことができ、Game Masterがその段階を選んだときに適用されます。ルールセットの通常とは異なる出目で追加ダイスを振ったり2成功としたりした場合は、ダイスカードにその旨が表示されます。
- **ダイスを振り直せます。** ルールセットにそのルールがある場合、状況に応じてGame Masterが判定でそれを指定し、低い出目のダイスを1回、または高い出目が出るまで振り直します。リソースを消費して同じ効果を得ることもできます。1回のロールで振り直しに使われる方法は1つだけで、2つが当てはまる場合は、より多くのダイスに届く方法が使われます。
- **2つの能力値をまとめて振れます。** ルールセットがそう定めている場合、能力値判定に2つ目の能力値のダイスを加え、2つの評価値を1つのプールとして振れます。
- **結果と同時に何かがうまくいかないルールセットもあります。** ダイスの半数以上が低い出目ならファンブルとするルールセットでは、それでも必要な成功数を得た判定は結果を保ち、ダイスカードに、同時に何かがうまくいかなかったことが追記されます。成功が1つもなければクリティカルな失敗です。
- **Game Masterは数値を与えません。** ナレーションに書かれたプールの結果は必ずEngine自身のロールで置き換えます。有利も、事前に自身で振ったダイスも適用されません。
- **Game Masterに各面数のダイスを1個見せる設定は、これらの判定には適用されません。** 見せるダイスは20面です。プール判定はEngineが事前非公開で振り、ほかの非公開ロールと同じように描写します。

### ルールセットのその他のロール方法

ルールセットは、ほかの方法で判定を振ることもできます。ダイスを振るのは引き続きEngineで、ダイスカードはルールセットに従います。

- **最も高いダイスを採用。** 数個のダイスを振り、ルールセットの指定に従って、最も高い1個、2個、または3個を読みます。
- **シートの数値以下を出す。** ダイスにボーナスを加える代わりに、スキルの百分率などシート上の数値以下を出すように振ります。
- **独自の面を持つダイス。** 面の価値が数字とは異なる場合があり、たとえばマイナス、空白、プラスです。数字の代わりに、成功、有利、それらの反対といった記号を持つダイスもあります。
- **段階で分かれる結果。** 判定は単なる成功か失敗ではなく、クリティカルな成功や代償を伴う成功など、複数の結果のいずれかになることがあります。ダイスカードにその段階の名前が表示され、Game Masterがそれを描写します。
- **一部の判定だけ別の方法で振る。** ルールセットはほとんどの判定を1つの方法で振り、いくつかの判定だけを別の方法で振るよう指定できます。

<a id="finishing-a-rolled-turn-in-one-request"></a>

## ダイスを使うターンを1リクエストで完了する

既定では、ダイスを振るターンは下書きと実際の数値による結果の書き直しの2回、モデルへリクエストします。**Chat Settings → Function Calling**(チャット設定→関数呼び出し)の**Finish rolled turns in one request**(ダイスを使うターンを1リクエストで完了)で2回目を省けます。既定はオフで、有効にしたチャットだけに適用されます。

数値が存在する前にGame Masterが文章を確定させることで実現します。何が起こるかを決める前にロールを見ることはなく、渡された出目に結果を合わせられません。あとからエンジンが振り、エンジンの記録が保存されます。

オンの間、Game Masterは結果の性質に応じて次の3つの形式から選び、判定を書くよう求められます。

**結果が2通りなら両方を書きます。** 数値なしの判定に続き、成功時と失敗時の文章を持つブロックを書きます。エンジンが振り、出目で選ばれた側を残し、読む前に他方を削除します。見えるのは、先に振った場合と同じ1つの結果です。

**結果が数値だけならプレースホルダーを書いて続けます。** ダメージ、回復、金額、持続時間、個数、距離などでは、Game Masterが文中に`[[roll: 2d6+3]]`を書き、エンジンが数値を入れます。`[[roll: 1d8+STR]]`のようにシートの修正値を指定すれば、エンジンが加算します。この形式は実際に読み取るシートがあるゲームだけで提供され、解決できない名前は0扱いせず拒否されます。置換された数値にカーソルを合わせるとダイスの内訳が見え、それぞれ**Logs**(ログ)にも独立したロール行として表示されます。

**数値自体で3通り以上の結末を選ぶ場合は、数値を求めて止まります。** Game Masterが従来使っている数値なしの簡潔な判定や`[dice:]`要求です。エンジンが振って記録し、結果の描写なしでターンが終わります。次のターンの冒頭でGame Masterが意味を描写します。**Narrate dice outcomes immediately**(ダイスの結果をすぐ描写)がオフの場合と同じです。

これら以外の形式で書かれた判定も同じ動作へフォールバックするので、未解決のまま放置したり結果を創作したりしません。

有効にする前に知っておきたい点があります。

- **有効な間はNarrate dice outcomes immediatelyを使いません。** 注記付きで表示されたまま無効になります。保存された値は変わらないため、1リクエスト方式をオフに戻すと元の設定に戻ります。
- **既存のターンは変わりません。** 有効にしたあとに生成するターンだけに作用し、保存済みの会話記録は従来どおり読めます。
- **2つの場合には複数リクエストになることがあります。** **Enable Tool Use**(ツール使用を有効化)がオンで、ツール一覧にダイスツールがあれば、Game Masterは引き続きそれを呼べます。ツール呼び出しには丸1往復分の追加リクエストが必要です。また、**Game tool connection**(ゲームツール接続)が**Same as narrator**(ナレーターと同じ)以外なら、必ず独自の計画リクエストを行います。いずれも、この設定で省く結果の書き直しとは別です。
- **振れない場合は通知します。** 読めない数値は作り物の値ではなく短い通知に置き換えます。読めない分岐はロールの記録を残し、両方の文章を削除します。いずれも**Logs**に省略した内容を示す行が出ます。
- **ターンを書いている間**、プレースホルダーや分岐ブロックはストリーミング表示から保留されるため、一度出た数値が変わる様子は見えません。ターン完了時に完成した文が表示されます。

### Game Masterに各面数のダイスを1個見せる

その下に**Let the Game Master see one die of each size**(Game Masterに各面数のダイスを1個見せる)があり、既定はオフです。これは、成功度、命中部位表、反応ロールのように数値で3通り以上の結末を選ぶ、2つの非公開形式では対応できない場合のための設定です。使わなければ、その種の判定はターンを終え、次の冒頭で描写します。

オンにすると、エンジンはターンの前に標準的な各面数のダイスを1個振り、それぞれの次の値をGame Masterに見せます。Game Masterは1個を消費し、同じ処理で意味を描写できます。

**このトレードオフはよく確認してください。** Game Masterは何をどの難易度で判定するか決める前に数値を見ます。そのため、非公開方式ではできない結果への誘導が可能です。渡された出目で成功する難易度を選んだり、悪い数値を持つ間は判定そのものを避けたりできます。難易度が物語に適しているかをエンジンが判断する方法はなく、この誘導も検出できません。Game Masterが出目を見たと知らないプレイヤーには、不自然に英雄的な展開が幸運に見えてしまいます。

Game Masterの協力を求めずに、エンジンが強制するのは次の点です。

- **数値は順番に使い、再利用しません。** ターンの記述に関係なく、エンジンがキューを管理して次の1個を渡します。
- **記録内の数値はすべてエンジンのものです。** ロール、修正値、合計、結果をキューとキャラクターシートから再計算します。Game Masterの記述が一致しなければ置き換え、**Logs**に記録します。
- **難易度には範囲があります。** これまでの記述式判定にはなかった1～40の制限があります。ルールセットのゲームでは、その難易度段階の上限まで使えます。
- **再要求しても運は良くなりません。** 同じターンのスワイプ、再生成、続きはすべて同じ数値を使い、良い目が出るまで振り直せません。
- **各面数の次の値だけを見せます。** **Values shown per size**(各面数の表示数)の既定は1です。同じターンの同面数で2回目以降のロールは見せず、次のターンで描写します。
- **未使用のダイスは一定時間後に振り直します。** **Rethrow after idle turns**(未使用ターン後に振り直す)の既定は3です。これがなければ、Game Masterがその面数を避け続けることで、悪い値がチャットの最後までキューの先頭に残れます。0にすると振り直しをオフにし、その動作に戻ります。
- **キューより多く要求しても追加のロールは出ません。** 判定の問いだけを残してすべての数値を除き、次のターンで描写します。どのターンで起きたかは**Logs**に記録されます。
