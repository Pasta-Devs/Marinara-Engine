# Game Mode: ダイスとスキル判定

Game Modeでは、ダイスボタンを使ってゲームマスター(GM)のためにダイスを振ります。このガイドでは、GMが難易度(DC、Difficulty Class)に対してスキル判定を行う仕組みも説明します。DCとは、ロールが到達するか上回る必要がある数値です。

## ダイスを振る

メッセージ入力バーにはダイスボタンがあります。ツールチップは**Roll dice**(ダイスを振る)です。

1. ダイスボタンをクリックして、クイックダイスメニューを開きます。
2. プリセットをクリックします。d20、d6、2d6、d10、d100、d4、d8、d12があります。
3. 入力バーに`🎲 d20`のようなチップが表示されます。ロールは予約された状態で、まだ送信されていません。
4. メッセージを送信します。Marinaraがダイスを振り、結果をタグとしてメッセージの末尾に追加します。GMはこのタグを読み取り、結果に沿って物語を語ります。

送信前に予約したロールを取り消すには、チップの**Clear queued roll**(予約したダイスロールの取り消し)をクリックします。

ボーナスなしでダイスを1個だけ振ると、次のようになります。

```text
[dice: d20 = 14]
```

ダイスが2個以上ある場合やボーナスが付く場合は、内訳も表示されます。

```text
[dice: 3d8+2 = 18 (4, 6, 6 +2)]
```

GMは物語の中で`[dice: 3d8+2]`を使ってロールを求めることもできます。Marinaraが実際の数値を決め、同じアニメーション付きのカードを表示します。これは、ClaudeやGrokのサブスクリプションを含む、テキスト専用の接続でも動作します。GMが1ターンに複数回ダイスを振ると、各ダイスカードは順番を待ちます。1枚を閉じると次のカードが表示されます。すべてのロールはそのターンのアクティブなスワイプに保存され、再読み込み後も**Logs**(ログ)に残ります。ターンを続行すると、以前のロールは維持されます。再生成すると、新しいスワイプ用に新しいロール一式が作られます。

## 独自のダイスを振る

ダイスメニューには、`NdM`記法で独自のロールを入力するテキスト欄があります。`N`はダイスの個数、`M`は1個あたりの面数で、末尾に任意でボーナスやペナルティーを付けられます。欄には例として`3d8+2`(8面ダイスを3個振り、2を足す)が表示されます。

1. ダイスメニューを開きます。
2. 記法を入力します。たとえば`2d6+1`です。
3. <kbd>Enter</kbd>を押すか、紙飛行機のボタンをクリックします。ロールがチップとして予約されます。

| 記法 | 意味 |
| --- | --- |
| `d20` | 20面ダイスを1個 |
| `4d8-1` | 8面ダイスを4個振り、1を引く |
| `4d6kh3` | 6面ダイスを4個振り、高い3個を残す |
| `2d20kl1` | 低い1個を残す。ディスアドバンテージでのロール |
| `4d6dl1+2` | 最も低いダイスを除き、2を足す |

`kh`と`kl`は、出目の最も高いダイスまたは最も低いダイスを残します。`dh`と`dl`は、それらを除きます。振ったダイスはすべて記録され、残したダイスだけが合計されます。

うまくいかなかった場合: `NdM`または単独の`dM`(任意でその後に`kh`、`kl`、`dh`、`dl`のいずれかと数値を続けたもの)ではないテキストは、期待される形式を示すエラーで失敗します。

一度に振れるダイスは100個まで、各ダイスの面数は1000までです。通常のロールでこれを超えた場合は上限に合わせて切り詰められ、カードには切り詰めた後の記法が表示されます。そのため、`500d6`では`100d6`のカードになります。`101d6kh3`のように、残すダイスや除くダイスを指定するロールで上限を超えた場合は、範囲外エラーで拒否されます。切り詰めると、残すダイスが変わってしまうためです。

<a id="skill-checks"></a>

## スキル判定

スキル判定は、忍び足、手がかりの発見、NPCの説得のように、失敗の可能性がある行動を試すものです。スキル判定を自分から始めることはありません。GMが物語の中で判定を求め、Marinaraがそれをアニメーション付きのd20のロールと結果バナーに変えます。バナーにはスキルと目標値が表示されます。たとえば**Stealth Check**と**DC 15**です。解決した判定にはそれぞれ専用のバナーが付き、順番待ちのダイスカードのあとに表示されます。

<a id="how-the-result-is-decided"></a>

### 結果の決まり方

判定ではd20を1個振り、2つの修正値を足します。

- スキル修正値。ゲームが自分のキャラクターについて記録しているスキルレベルから決まります。そのスキルのレベルがまだない場合は0です。
- ステータス修正値。そのスキルが依存するステータスから決まります。どのステータスかはゲームによって異なり、以下のとおりです。

共有ゲームでは、各判定はそこに指定されたキャラクターのステータスを読みます。

<a id="mrpg-games"></a>

#### MRPGゲーム

新しいゲームすべてで使われる**MRPG**クラスのゲームでは、ステータス修正値は現在のクラスから得られるMRPGステータスから決まります([MRPGクラス](mrpg-classes.md#what-the-stats-mean)を参照)。アップグレード後もカードに残っているLegacyの能力値は使いません。各スキルは次のステータスを使います。

| ステータス | スキル |
| --- | --- |
| Strength | Athletics、Intimidation |
| Speed | Acrobatics、Stealth |
| Skill | Sleight of Hand、Investigation、Perception、Medicine、Survival、Animal Handling、およびここにないすべてのスキル |
| Defense | Endurance、Constitution |
| Magic | Arcana、History、Nature、Intelligence |
| Resistance | Insight、Religion、Wisdom |
| Luck | Persuasion、Deception、Performance、Charisma |

判定では、そのステータスの5分の1を切り捨て、最大+5まで加えます。これは、新しいキャラクターの最も高いステータスではおよそ+1、レベル10では+2または+3、最高レベルでは+5です。低いステータスでは何も加算されません。ステータスは現在のクラスに従うため、クラスを切り替えるとこれらのボーナスも変わります。

<a id="legacy-games"></a>

#### Legacyゲーム

**Legacy**ゲームでは、修正値はキャラクターシートにある、そのスキルを司る能力値から決まります。各スキルは自動的に1つの能力値に対応します。StealthはDexterity、PerceptionはWisdom、PersuasionはCharismaを使います。Marinaraが認識できないスキルはIntelligenceを使います。

<a id="the-result"></a>

#### 結果

合計がDC以上なら、判定は成功です。次の2つの出目は、計算より優先されます。

- ナチュラル20(ダイスの目そのものが20)は**CRITICAL SUCCESS**で、必ず成功します。
- ナチュラル1(ダイスの目そのものが1)は**CRITICAL FAILURE**で、必ず失敗します。

バナーには**CRITICAL SUCCESS**、**SUCCESS**、**FAILURE**、**CRITICAL FAILURE**のどれかが表示されます。

### アドバンテージとディスアドバンテージ

GMは、アドバンテージ(d20を2個振り、高いほうを採用)またはディスアドバンテージ(低いほうを採用)付きで判定を求めることができます。バナーにはDCの隣にそのモードが表示され、使ったダイスに印が付きます。GMが両方を同時に求めた場合、Marinaraは推測せずにその判定を処理しないので、その判定のバナーは表示されません。

### 自分のd20を先に振っておく

判定が起こる前に、ダイスメニューから`d20`を予約しておきます。すると判定は新しくダイスを振らず、予約した出目を使います。スキル修正値とステータス修正値は、その場合も加算されます。

ロールのあとにGMがターンをどう締めくくるか、それにどれだけのコストがかかるかについては、[ダイスを振ったターンの描写](#how-a-rolled-turn-is-narrated)を参照してください。

<a id="games-that-use-a-ruleset"></a>

### ルールセットを使うゲーム

5e (SRD 5.1)などのルールセットを使うゲームでは、判定はルールセット独自のダイス、難易度の段階、シートの修正値を使います。ルールセットによっては、ダイスプールやシンボルダイスを使います。[ルールセットでの判定](rulesets.md#checks-on-a-ruleset)を参照してください。

## リファレンス

<a id="how-a-rolled-turn-is-narrated"></a>

### ダイスを振ったターンの描写

GMがテキストで判定を求めると、Marinaraがダイスを解決します。結果の描写を仕上げる方法は3つあり、3つとも**Chat Settings → Function Calling**(チャット設定 → 関数呼び出し)にあります。

| 設定 | デフォルト | 動作 |
| --- | --- | --- |
| **Finish rolled turns in one request**(ダイスを使うターンを1リクエストで完了) | オン | リクエストは1回です。GMが数値なしで結果を書き、Marinaraが数値を入れます。下記を参照してください。 |
| **Narrate dice outcomes immediately**(ダイスの結果をすぐに描写) | オン | リクエストは2回です。GMが下書きし、Marinaraがダイスを振ったあと、もう1回のリクエストで実際の結果とともにプロンプトを再送し、GMが同じターンのうちに結果を書き上げます。入力トークンと出力トークンの消費が増えます。 |
| 両方オフ | | 実際の結果は次のターンに引き継がれ、追加のリクエストはありません。 |

**Narrate dice outcomes immediately**を使っている場合、追加のリクエストが失敗すると、そのターンは解決済みの結果をログに残し、推測した結果や書きかけの結果は保存しません。**Regenerate turn**(ターンを再生成)ボタン付きの通知は、再読み込み後もそのターンに残ります。実際のロールがなかったリクエストでは、追加のリクエストは行われません。

ダイスツールに対応した接続では、代わりにGMが生成中に実際のロールを得ることができます。ツールが結果を返すとすぐにダイスカードが表示され、完了した判定は振り直さずにその結果を記録します。

<a id="finishing-a-rolled-turn-in-one-request"></a>

#### ダイスを使うターンを1リクエストで完了する

この設定がなければ、ダイスを振るターンには2回のリクエストがかかります。**Finish rolled turns in one request**(ダイスを使うターンを1リクエストで完了)は2回目をなくします。デフォルトはオンです。チャットでオフにすると、そのチャットでは代わりに、ダイスを振った各ターンを実際の数値で書き直します。

これが成り立つのは、数値が存在する前にGMが文章を確定させるからです。GMは何が起こるかを決める前にロールを見ることがないので、結果を誘導できません。Marinaraはそのあとでダイスを振り、自身の記録を保存します。このスイッチがオンの間、GMは次の3つのどれかの形で判定を書きます。

- **結果が2通り。** GMは数値なしで判定を書き、続けて成功時の文と失敗時の文を書きます。Marinaraがダイスを振り、出目で選ばれた側を残して、ターンが読まれる前にもう一方を削除します。
- **数値だけ。** ダメージ、回復、金額、持続時間、個数、距離では、GMが文の途中に`[[roll: 2d6+3]]`のようなプレースホルダーを書き、Marinaraがその位置に数値を入れます。プレースホルダーでは、`[[roll: 1d8+STR]]`のようにシートの修正値を指定できます。この形式は、読み取るシートがゲームにある場合にだけ提供されます。Marinaraが解決できない名前は、0として扱われずに拒否されます。プレースホルダーから入った数値にカーソルを合わせると、そのダイスが表示されます。それぞれの数値は、**Logs**にも独立したロール行として表示されます。
- **結末が3通り以上。** GMは値を求めて止まります。Marinaraがダイスを振って記録し、ターンは結果なしで終わります。次のターンの冒頭で、GMがその数値の意味を描写します。

これらのどの形でも書かれていない判定は、最後の動作にフォールバックします。そのため、未解決のまま残るものも、作り出されるものもありません。

- この設定がオンの間、**Narrate dice outcomes immediately**は使われません。表示されたまま無効になり、保存されている値は、この設定をオフにしたときのために残されます。
- 既存のターンは変わりません。このスイッチは、オンにしたあとに生成されるターンにだけ作用します。
- 次の2つの場合には、1ターンに複数のリクエストがかかることがあります。**Enable Tool Use**(ツールの使用を有効にする)がオンで、ツール一覧にダイスツールがある場合(ツール呼び出しには丸1往復分の追加がかかります)と、**Game tool provider**(ゲーム用ツールのプロバイダー)に**Same as narrator**(ナレーターと同じ)以外が設定されている場合(必ず計画リクエストを行います)です。
- 振れないものがあるときは、作り物の値ではなく、短い通知が数値の代わりに入ります。何が省かれたかは**Logs**に示されます。
- ターンが書かれている間、プレースホルダーと分岐ブロックはストリーミング中のテキストに出さずに保留されるので、数値が変わる様子が見えることはありません。

<a id="symbol-dice-by-name"></a>

### シンボルダイスを名前で指定

シンボルダイスを振るルールセット(Genesys風のシステムなどの`symbol-pool`ルールセット)を使うゲームでは、独自のロールの欄でそのダイスを名前でも指定できます。種類ごとに個数とダイスの名前を入力します。たとえば`2 ability 1 proficiency vs 2 difficulty`です。名前にはダイスのIDまたはラベルを使え、大文字と小文字は区別しません。区切りにはスペース、カンマ、`+`、`vs`を使えます。1回のロールで指定できるダイスは40個までです。

カードには各ダイスとその面のシンボルが表示され、続いて相殺後に残ったシンボルと、それが成功かどうかが表示されます。メッセージのタグにも同じ内容が入ります。たとえば`[dice: 2 ability vs 1 difficulty = 1 Success, 1 Advantage; success]`です。GMのダイスツールも、これらの名前を受け付けます。通常の`NdM`は、どのゲームでも引き続き使えます。

### スキル判定でのその他のダイス

GMは`[skill_check: skill="Endurance" dc="12" dice="3d6+2"]`のような別の記法も指定できます。これらの判定では、d20用のシートの修正値の代わりに記法内の固定修正値を使い、合計がDCに達すれば成功します。ナチュラル1とナチュラル20のルールは、標準のd20判定にだけ適用されます。

成功数を数えるプールでは、ダイス1個ごとのしきい値と必要な成功数の両方を指定する必要があります。`[skill_check: skill="Intimidation" dc="4" dice="6d10" resolution="successes" threshold="6"]`はd10を6個振り、6以上の目が出たダイスをそれぞれ数え、4個以上なら成功します。Marinaraは指定されていないしきい値を推測せず、エクスプローディングダイス、ボッチ、その他の特殊なプールのルールも実装していません。有効なしきい値がないプールは未解決のまま残り、作り出された数値は削除されます。

これは、ルールセットのないゲームで使われるプールです。ダイスプールを基にしたルールセットを使うゲームは異なります。[ルールセットでの判定](rulesets.md#checks-on-a-ruleset)を参照してください。

判定の`dice=`属性には、通常の`NdM`だけを指定できます。`4d6kh3`、`3d6!`、`4dF`などを求められてもダイスは振りません。Marinaraは未対応の記法をログに記録し、作り出された数値を削除します。結果は未確定のままです。

### Game Masterに各面数のダイスを1個見せる

**Let the Game Master see one die of each size**(Game Masterに各面数のダイスを1個見せる)は、**Finish rolled turns in one request**の下にあります。デフォルトはオフです。これは、数値を見ない形式では対応できない1つの場合のための設定です。成功の度合いや命中部位表のように、数値で3通り以上の結末から1つを選ばなければならない場合です。この設定がなければ、そうした判定ではターンが終わり、次のターンで描写されます。

オンにすると、Marinaraはターンの前に標準的な各面数のダイスを1個ずつ振り、それぞれの次の値をGMに見せます。そのため、GMは同じ処理の中でその意味を書けます。

> **Warning:** この場合、GMは何を判定するか、どれだけ難しくするかを決める前に数値を見ます。手元のダイスで成功できる難易度を選んだり、悪い数値を持っている間は判定を求めるのを避けたりできます。難易度が物語に合っているかどうかをMarinaraは判断できないので、これを検出できません。不自然なほど英雄的なセッションは、運が操作されている可能性があります。

GMの協力がなくても、Marinaraが強制するのは次の点です。

- 値は順番に出て、同じ値が二度出ることはありません。
- 記録内の数値はすべてMarinaraのものです。ロール、修正値、合計、結果は、キューとキャラクターシートから再計算されます。一致しない数値は置き換えられ、そのことが**Logs**に示されます。
- 難易度は1～40の範囲に保たれます。ルールセットを使うゲームでは、そのルールセットの難易度の段階の上限まで使えます。
- 同じターンのスワイプ、再生成、続きはすべて同じ値を使うので、運を求めて振り直すことはできません。
- **Values shown per size**(各面数の表示数)は、GMが面数ごとにいくつの値を見られるかを設定します。デフォルトは1です。1ターンの中で、それより後に振られる同じ面数のロールはGMに見えず、次のターンで描写されます。
- **Rethrow after idle turns**(未使用ターン後に振り直す。デフォルトは3)は、使われなかったダイスを、その数のターンが過ぎたあとに振り直します。これがないと、低い値がチャットの最後までキューの先頭に残り続けることがあります。0にすると振り直しがオフになります。
- GMがキューにある以上のロールを求めた場合、その判定は問いだけを残してすべての数値を失い、次のターンで描写されます。どのターンかは**Logs**に示されます。
