# Game Mode: セッションとセーブデータ

このガイドでは、Marinara EngineがGame Modeの進行を複数のセッションにまたがってどう記録するのかを説明します。セッションの終了と開始、**Session History**(セッション履歴)で過去のセッションを読む方法を扱います。さらに**Show Spoilers**(ネタバレ表示)の画面、ゲームのデータを手で直す方法、ゲームのデータが保存される仕組みも説明します。

## セッションとは

Game Modeは冒険を番号付きのセッションに区切ります。セッションとは、卓上ゲームの1晩と同じように、途切れなく続く1回分の遊びのことです。各セッションの語り手はゲームマスター(GM、ゲームを進行するAI)です。セッションを終了すると、GMが要約を書き、後から読み返せます。

最初のセッションは**Session 1**です。これを終了してもう一度始めると**Session 2**になり、以降も同じように増えていきます。

<a id="opening-session"></a>

## Sessionを開く

セッションの終了、新しいセッションの開始、履歴の閲覧は、すべて**Session**(セッション)で行います。

1. Game Modeのチャットを開始するか開いて、ゲーム画面を表示します。
2. **Session**ボタン(羽根のアイコン)をクリックまたはタップします。最初はチャットの右上付近にあります。別の場所へドラッグできます([操作ウィンドウとボタン](../chats/chat-settings.md#control-windows-and-their-buttons)を参照)。
3. **Session**は、コンピューターではウィンドウ、スマートフォンでは画面幅いっぱいのパネルとして開きます。最初の行には**Session**と現在の番号および状態が表示されます。
4. **Session History**と**Journal**(記録)の2つのタブがあります。セッションの操作と設定の共有は**Session History**で行うので、このタブのままにします。

**Put back in Chat Settings**(Chat Settingsに戻す)でこのウィンドウを移した場合は、代わりにChat Settings内の**Session**セクションを開いてください。

## ゲームを作成した設定を共有する

Game Modeは、新しいキャンペーンを作成したときの設定を、変更できないスナップショットとして保存します。そのため、まず遊んでみて、この組み合わせは良いと判断してから共有できます。開始前にすべての項目を手で書き留めておく必要はありません。

1. 共有したいGame Modeのキャンペーンを開きます。
2. **Session**を開きます(羽根のアイコンのボタン)。
3. **Session History**のまま、**Initial Game Setup**(初期のゲーム設定)を展開します。
4. 保存された冒険、登場キャラクター、モデル、プロンプト、実際に使われた生成パラメーター、ビジュアル、絵コンテ、世界ツールの設定を確認します。
5. **Copy setup**をクリックするとテキストがクリップボードにコピーされ、**Download .txt**をクリックすると共有用のテキストファイルとして保存できます。

コピーされるテキストには、長く書いたプレイヤーの好みやGMへのカスタム指示も含まれます。私的な内容が入っている場合は、公開する前に必ず中身を読んでください。接続の認証情報、サーバーのURL、APIキー、ローカルデータベースのIDは一切含まれません。キャラクターカード、ペルソナ、ロアブック、モデル、プロバイダーのアカウントは名前だけが参考として記載され、データ自体は同梱されません。そのため、受け取った側は自分の手元にある同等のものを用意するか選ぶ必要があります。

設定のスナップショットが導入される前に作成されたキャンペーンでは、そもそも保存されていない情報は復元できません。そのため**Initial Game Setup**は、信頼できる作成時のスナップショットがある場合にだけ表示されます。

## セッションを終了する

今の章をここで締めくくり、GMに要約してもらいたくなったら、セッションを終了します。

1. **Session**を開き、**Session History**タブのままにします。
2. 一番上に、現在のセッションが**Session N (Current)**として表示されます。
3. その行にある**End Session**(セッションの終了)ボタン(**Show Spoilers**の隣にある小さな四角のアイコン)をクリックします。
4. **End Session**というウィンドウが開き、確認を求められます。
5. 必要であれば、**What do you want to happen in the next session (optional)?**と書かれた欄に入力します。5000文字まで入力できます。
6. GMに自然に話を進めてほしいときは、この欄を空のままにします。
7. ウィンドウの**End Session**をクリックすると確定し、**Cancel**をクリックすると取り消せます。

確定すると、エンジンが要約を生成します。終わるまでこの画面のまま待ってください。処理中はウィンドウのタイトルが**Ending Session**に変わります。完了するとそのセッションは終了扱いになり、履歴に並びます。

## 新しいセッションを始める

現在のセッションが終了扱いになると、同じボタンの表示が**New Session**(新しいセッション)に変わります。

1. **Session**を開き、**Session History**タブに移動します。
2. 現在のセッションの行で、**New Session**ボタン(再生のアイコン)をクリックします。
3. GMが物語を再開します。このとき、前のセッションの要約と、終了時に書いた次回への要望が使われます。

生成された世界を持つゲームでは、世界は前のセッションが終わったところから続きます。経過した日数、パーティーの功績と評判、物語で加わった場所や集団、パーティーが向かった先は、すべて新しいセッションに引き継がれます。

## 過去のセッションを読む

**Session History**タブには、終了したセッションが新しい順に並びます。まだ1つも終了していないうちは**No completed sessions yet**と表示されます。

各行には、セッションの番号、日付、記録された発見の数が表示されます。行をクリックすると展開します。展開したセッションには、次の項目が表示されることがあります。

- **Summary**: そのセッションで起きたこと。
- **Resume Point**: 次のセッションをどこから再開するか。
- **Party Dynamics**: パーティーのメンバー同士の関係。
- **Key Discoveries**: 重要な事実、どんでん返し、判明したこと。
- **Character Moments**: キャラクターの印象的な場面。
- **Little Details To Recall**: 細かな癖、約束、覚えておきたい小さな出来事。
- **NPC Updates**: NPC(プレイヤー以外のキャラクター、GMが動かす人物)の変化。
- **Next Session Request**: セッションの終了時に書き残した要望。
- **Stats Snapshot**と**Party Status**: 保存された数値とパーティーの状態。

### 終了したセッションを見返す

終了したセッションは、キャンペーンに影響を与えずに再生できます。

1. **Session History**で、終了したセッションを展開します。
2. **Replay Session**をクリックします。
3. **Next**と**Next turn**で、当時の語りと会話を1つずつ進めます。
4. 再生が選択肢に到達すると、そのセッションで実際に選んだ選択肢だけが押せる状態になります。それをクリックすると、記録どおりの道筋を進めます。
5. 見終わったら、再生画面の上部にある閉じるボタン、または**Return to current session**をクリックします。

再生は読むだけの機能です。GMを呼び出すことも、メッセージを作ることも、インベントリーや能力値を変えることも、冒険の記録を更新することも、チェックポイントを復元することもありません。再生機能が追加される前のセッションでも、保存済みのテキスト、文中の演出、選択肢、利用できる素材はそのまま使えます。古いターンでは、当時保存されなかったシーンの演出が欠けている場合があります。

### 過去のセッションを編集する

終了したセッションの記録は手で書き直せます。以降のセッションに正しく引き継がせたいときに使います。

1. 変更したいセッションを展開します。
2. **Edit Details**をクリックします。
3. 任意の項目を書き換えてから**Save Details**をクリックします。編集内容を捨てるときは**Cancel**をクリックします。

展開したセッションには、さらに2つのボタンが表示されます。

- **Regenerate**: そのセッションの締めくくりをAIに作り直させます。要約もその他の項目もすべて書き換わるので、**Edit Details**で加えた変更は失われます。
- **Update Plot Arcs**: そのセッションの出来事をもとに、GMが隠し持っている物語の構想をAIに更新させます。この構想が、**Show Spoilers**の画面に表示される**Story Arc**、**Plot Twists**、**Party Arcs**です。

**Regenerate Lorebook**ボタンは、いちばん新しく終了したセッションにだけ、しかも任意機能のLorebook Keeperをオンにしている場合にだけ表示されます。ロアブックとは、AIが思い出せる世界の設定をまとめたものです。

## Show Spoilersの画面

**Show Spoilers**は、現在のセッションについてGMが隠している覚え書きを表示します。これは本来、プレイ中は伏せられている情報です。読むとどんでん返しが台無しになる場合があります。

1. **Session**を開き、**Session History**タブに移動します。
2. 現在のセッションの行で、**Show Spoilers**(目のアイコン)をクリックします。
3. GMの内部状態が表示されます。

ネタバレ表示には、次のセクションが出ることがあります。

- **World Overview**: 世界全体の設定。
- **Story Arc**: 物語をどこへ向かわせる予定か。
- **Plot Twists**: GMが伏せている驚きの展開。
- **Party Arcs**: パーティーそれぞれに用意された道のり。
- **Maps**、**NPCs**、**Character Cards**: 保存されたゲームのデータ。

もう一度隠すときは、同じボタンをクリックします。このときボタンの表示は**Hide Spoilers**に変わっています。

これらの秘密は編集もできて、ゲームマスター用の裏設定パネルのように使えます。**Edit Spoilers**をクリックしてテキストを書き換え、**Save Spoilers**をクリックします。一部の項目はJSONという構造化されたテキスト形式で表示されます。JSONの項目は形式を理解している場合にだけ編集してください。壊れたJSONは保存できません。

<a id="editing-game-data-by-hand"></a>

## ゲームデータを手で編集する

NPCの評判や、閉じないまま残っているクエストなど、ゲームマスターが何かを間違えたときは、ゲームに保存されたデータを自分で直せます。

1. **Game controls**(ゲームの操作)を開き、**Edit game data**(ゲームデータを編集)を選びます。スマートフォンでは、**Game controls**は3点アイコンの**Chat tools**(チャットツール)メニューの中にあります。
2. **Game Data**(ゲームデータ)のウィンドウが開きます。上部には「Hand edits can break a game. Every change is checked before it saves, and names can't change here.」という警告が表示されます。
3. 一覧からセクションを選びます。スマートフォンでは、横に並んだチップから選びます。検索ボックスに入力して、すべてのセクションから値を一度に探すこともできます。
4. **Fields**(フィールド)で値を変更するか、**JSON**に切り替えて生のデータを編集します。
5. **Review changes**(変更を確認)をクリックして何が変わるのかを正確に確認し、**Save changes**(変更を保存)をクリックします。

変更できるのは、**Party Cards**(パーティーカード)、**Party Sheet**(パーティーシート)、**NPCs**(NPC)、**Journal**(記録)、**Player Notes**(プレイヤーのメモ)、**Inventory**(インベントリー)、**Story**(物語)、**Session Summaries**(セッションの要約)、**World Edits**(世界の編集)、**Story Script**(物語の台本)、**HUD Widgets**(HUDウィジェット)です。セクションは、ゲームにそのデータがあるときだけ表示されます。そのため、世界を持たないゲームには**World Edits**がありません。**World**(世界)、**Maps & Position**(マップと現在地)、**Time, Weather & Morale**(時刻、天候、士気)、**Combat**(戦闘)、**Settings**(設定)など、それ以外のセクションには**Read-only**(読み取り専用)の印が付きます。読んだり検索したりはできますが、管理するのはゲーム自身です。プロンプト、画像、音楽、ダイスの好みは**Chat Settings**(チャット設定)で変更します。

変更はすべて、保存の前に確認されます。

- 名前は変更できません。カード、NPC、パーティー、バッグは、名前でお互いを見つけているからです。パーティーのメンバーの追加や削除も、ここではできません。
- NPCの評判は-100から100までです。
- **Inventory**では、アイテムの数量、愛称、持ち主と、装備しているか、同調しているか、オンになっているかを変更できます。スタックを取り除くとそのアイテムは削除され、IDのないスタックを加えるとアイテムが追加されます。
- **Session Summaries**で変更できるのは、セッションのテキストだけです。
- **World Edits**には、場所の名前の変更や人物の追加など、世界に対して手で加えた編集が入ります。世界そのものが変更されることはありません。

変更を保存できないときは、エディターがその理由を表示します。そのセクションには下書きが残るので、直してから保存し直せます。編集中にゲームが同じデータを変更した場合は、ゲームの変更を打ち消さないよう、保存は拒否されます。**Reload**(再読み込み)を押すとゲーム側の内容が表示され、下書きは破棄されます。

保存のたびに、ゲームはその前にチェックポイントを取ろうとします。このチェックポイントは、**Checkpoints**(チェックポイント)に**Before a State Editor save**と表示されます。編集がうまくいかなかったときは、そのチェックポイントを読み込むと元に戻せます(下記を参照)。

このウィンドウは、RoleplayのState Editorと同じように使えます。[State Editor](../roleplay/hud-and-trackers.md#the-state-editor)を参照してください。

<a id="how-your-game-saves"></a>

## ゲームの保存の仕組み

Game Modeは進行を自動で保存します。保存ボタンを押す必要はありません。世界、パーティー、マップ、インベントリー、ゲーム内の時間、セッションの要約は、遊んでいる間にすべて保存されます。

アプリは裏側で自動のチェックポイントも記録しています。記録されるのは、セッションの開始時、セッションの終了時、戦闘の開始時と終了時、新しい場所に着いたとき、そして一定の間隔ごとです。[ゲームデータのエディター](#editing-game-data-by-hand)も、保存のたびにその前にチェックポイントを取ろうとします。ただし、最初のターンがまだ保存されていないほど新しいゲームには、記録できるものがまだありません。チェックポイントは**Game controls → Checkpoints**(ゲームの操作 → チェックポイント)を開くと、新しい順に確認できます。**Load**(読み込む)を押すと、ゲームはその時点に戻ります。トラッカー、マップ、ゲームデータのエディターで行った**World Edits**(世界の編集)、そしてその後の物語が元に戻り、ゲームを巻き戻した位置にはシステムメッセージが残ります。パーティーのカードとシート、NPC、記録、自分のメモ、インベントリー、セッションの要約、GMの物語の計画、HUDウィジェット、そして時刻、天候、士気も、その時点に戻ります。設定はそのまま残ります。**Delete**(削除)を押すと、そのチェックポイントは完全に削除されます。

自動のチェックポイントは種類ごとに新しい5件まで保持されるため、遊ぶにつれて古いものは整理されます。

1つのターンだけをやり直したいときは、代わりに**Game controls**の**Retry turn**(ターンの再試行)かスワイプを使ってください。チェックポイントを読み込むと、物語もその時点まで戻ります。

データを自分の手元にも残しておきたいときは、アプリのバックアップ機能を使います。[バックアップと復元](../data/backup-and-restore.md)を参照してください。
