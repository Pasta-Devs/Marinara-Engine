# バージョン付き戦闘ルールセット: 実装引継ぎ

> **状況追記、2026年9月19日。** この文書で予約している`5e-2014`アダプターは、システム別のTypeScriptアダプターではなく、データ駆動の戦闘種別として実装中です。ルールセットは任意の`combat`ブロックを宣言し、Engineがそれを解決する種別を所有します。判定を解決する種別と同じ方式です。理由、構成、実装段階は`game-rulesets-and-sheets-implementation.md`の「Real ruleset combat」節にあり、[issue #6361](https://github.com/Pasta-Devs/Marinara-Engine/issues/6361)で追跡しています。この文書のほかの内容は引き続き有効です。Traditionalのルールセットと承認済みの速度動作、製品の契約、難易度はルールセットに属してダメージ倍率にならないという規則、ディレクターが持つサーバー管理の単一台帳、リアクションと伝説的アクションの受付時間、保存・UI・展開の契約が含まれます。C3a時点で接続済みです。戦闘は`classic`と`tactical`に並ぶ3つ目の`style`として既存のディレクター台帳で解決され、リビジョン、冪等性、ミューテックス、候補IDを1つ選ぶ単一のモデル呼び出しは共通です。C3b時点で画面に表示されます。`combat`を宣言するゲームはClassicの外枠で独自のメニューと用語を使い、ログに実際の計算を出力します。シートは終了後ではなく戦闘中に書き込まれます。C4a時点で位置を持ちます。`combat.distance`を宣言するルールセットはタクティカルエンジンが生成する盤面で戦え、移動、間合い、射程、爆発・円錐・直線の範囲、視線、遮蔽、離れる相手への攻撃を独自の数値で解決し、敵も移動します。C4b時点で盤面が表示されます。位置を持つ戦闘はタクティカルの地形上で行い、移動先とコスト、経路、誘発する相手、選べる対象、範囲を狙える場所をサーバーの情報から描画し、独自の距離で説明します。リアクションと特殊アクションの受付時間はC5で対応予定です。
> 戦場はC4b時点で画面に描画されます。C5a時点で1ターンに卓上ゲーム同様の動作ができます。1撃が2つ目のダメージ効果を持ち、1回の行動消費で複数回攻撃し、能力が行動枠を消費しない、返す、別の枠で標準行動を買うことができ、追加効果は期間内の最初の条件を満たす命中へ自動適用されます。状態は自身のセーヴを変え、すべてのダメージを半減し、付与者を狙ったり近づいたりするのを防ぎ、付与者が見える間だけ有効になり、または倒れると終了できます。C5b時点で戦闘を保留できます。相手の間合いを離れる移動はその場で止まり、自動攻撃の代わりに相手へ攻撃するか尋ねます。行動者間では、ポイントのある各ブロックへ独自の行動を購入するか尋ねます。受付中はほかの処理は進まず、保留した位置から正確に再開します。C5c時点でカタログ項目が待つ瞬間を指定します。`aimed`は所持者に効果が当たる前で、その効果を取り消せます。`harmed`は被害を受けたあとで、加害者へ向けられます。コストは誰かへ尋ねる前に支払い済みなので、取り消すのは効果の発生であり購入ではありません。連鎖は今後の対応です。戦闘はスタックではなく1つの受付枠を持つため、対抗行動への対抗はできません。

状態: 2026年9月17日の実装案です。AI刷新はこれらのルールセットを実装しません。Traditionalの速度追撃は合意済み製品方針ですが、以下の閾値/既定値は調整案です。関連作業を確認して最新`staging`へ実装します。

## 製品契約

四つの選択を独立させます。

| 選択 | 制御対象 | 例 |
| --- | --- | --- |
| 表示 | 空間情報と入力 | Classicメニュー、Tacticalグリッド |
| 参加 | 誰が戦うか | パーティー、将来のSummoning |
| ルールセット | 合法行動、資源、ターン順序、解決 | Traditional、版を明示した5e、V20 |
| 操作主体 | 誰が合法行動を選ぶか | プレイヤー、ローカルAI、GMボス |

Cautious Mageはどちらの表示でも慎重であるべきです。ルールセットは性格ではなく可能な行動を変えます。Summoningは参加方式であって第三の戦闘エンジンではなく、初期表示は非空間でも構いません。位置モデルなしにグリッド距離を捏造しません。

製品UIには読みやすい説明を出します。Traditional/Tacticalの説明で他ゲームと比較しません。実在システム名を使うルールセットは正確な対応版/範囲を示します。

### 難易度はルールセットに所属

現行の敵ダメージ倍率(Casual 0.6、Normal 1、Hard 1.3、Brutal 1.6)はTraditional専用の意図です。5e、V20、後続アダプターへ自動継承せず、各遭遇/解決モデルで難易度を定義します。敵AIの判断調整と算術倍率を分け、別ルール選択時にTraditional表を黙って適用しない回帰を追加します。この注記は現行旧機構を実装済みTraditionalと改名するものではありません。

## 現在のソースと制約

- `packages/shared/src/types/game.ts`: `Combatant`、`CombatSkill`、Classic結果/スナップショット。能力値は汎用数値で、`speed`は卓上Dexterity値やフィート移動量ではありません。
- `packages/server/src/services/game/combat.service.ts`: Classicは毎ラウンド順序を振り、一体一命令を汎用式で解決します。旧ゲームはクライアント経由で状態を往復し、新規ウィザードゲームはサーバーdirector台帳を使います。
- `packages/shared/src/features/tactical-combat/{engine,math,types}.ts`: 味方/敵交互フェーズ、クラス射程、速度由来移動、反撃。速度追撃は未実装です。
- `packages/shared/src/features/combat-ai.ts`とモードアダプター: 可能行動の優先順位。通常AIの情報境界を守り、GMボスには予測用の味方シート/資源を渡しますが、どちらも未来の出目/宣言前選択を見ません。
- `packages/server/src/routes/combat-director.routes.ts`と`services/game/combat-director.service.ts`: バージョン付き正規状態、行動位置、保留反応、伝説的予算、重複/古い応答防止。第二台帳を作らずこの受理経路を拡張します。現在のCounterspell確率、スロット支払い、取消費用は汎用Engine方針で5eではありません。
- `packages/server/src/routes/game.routes.ts`: 旧ラウンド/開始/行動検証。`GameCombatUI`、`TacticalCombatUI`、`use-game.ts`: 入力、予測、受理結果、永続化。
- `GameSurface.tsx`: 生成設計図復元/戦闘スナップショット。`encounter.routes.ts`: 遭遇プロンプト。`game-setup-share.ts`: 再利用設定のインポート/エクスポート。

合意済み速度動作を実装/検証せず現行式をTraditionalと改名しません。d20と汎用能力値だけで5e準拠を名乗りません。

## 最小構成

組込みの純粋TypeScriptアダプターの閉じた台帳から始めます。スクリプト言語や任意実行可能ルールパッケージは追加しません。既存行動/結果型を再利用し、両呼出元が必要になるまで共通ヘルパーを抽出しません。

新遭遇ごとに固定参照を保存します。

```ts
type RulesetRef = {
  id: "engine-legacy" | "traditional" | "5e-2014" | "v20";
  version: number;
  options: Record<string, boolean | number | string>;
};
```

各アダプターは例の自由なレコードをそのまま受けず、閉じた設定スキーマを検証します。移動、反撃、呪文枠、血の消費、召喚、ボス反応など対応能力を列挙し、明示的な未対応設定は有用なエラーで拒否します。参照欠損は`engine-legacy`で、Traditionalへ自動移行しません。

小さいインターフェースで次を扱います。

1. 変換を推測せず固有シートを検証/正規化。
2. 遭遇開始と規則上の時点で一度だけ順序を決定。
3. 行動開始時に許可予算を回復し、対応状態を更新。
4. パスを含む合法行動/任意反応の対象、射程、費用、窓を列挙。
5. 乱数を消費しない読取り専用予測。
6. 宣言を受理し資源確定を記録、効果解決前に対応発動窓を公開。
7. 保留効果/反応を順序付きイベント/資源差分へ解決。有効時だけ開始/終了ボス窓を公開。
8. 全参加者の行動後にラウンド終了し、ラウンド限定効果を一度進行。

同じアダプターを手動入力、通常AI、GM候補、予測へ使います。GMは最終HP、架空技ID、新順序、無料資源変更を返せません。合法性は受理状態を参照し、判断文脈は主体/窓に適した情報だけを公開します。GMは予測用に味方技、呪文ポイント/枠、クールダウン、利用可能所持品を知ります。未確定選択/他者待機命令は宣言まで非公開です。予測は期待値で、未来の出目ではありません。

固有シートは判別可能なunionにします。MP、枠数、Blood Pool、Willpower、毎ラウンド消費、休息ごとの使用回数をすべて`mp`へ押し込みません。UIバー/費用はアダプター記述を読み、現在/最大資源を別保存します。名前正規化は表示用だけで識別子には使いません。

## Traditional v1: 合意済み速度動作

**生存し参加資格のある各ユニットは、毎ラウンド通常行動開始一回、戦闘開始一回までです。速度追撃は同じ交換内の追加打撃で、別行動開始ではありません。**

初期バランス案:

| 規則 | v1案 |
| --- | --- |
| イニシアチブ | 有効Speed降順、同値は安定遭遇順。高速/同値で追加行動なし |
| Tactical進行 | 味方→敵フェーズ。手動は未行動味方を選択、自動は速度順 |
| Classic進行 | 有効Speedの統合降順。手動命令を待機し、各枠で現在合法な対象を解決 |
| 移動 | Speedと独立した明示予算。既定4マス案と制限付きクラス/能力修正 |
| Attack Speed | 明示ボーナス/ペナルティだけを加えた有効Speed。架空武器重量なし |
| 追撃閾値 | 攻撃側Attack Speedが防御側+5以上。変更は検証済みルール設定だけ |
| 対象行動 | 通常攻撃または明示`allowsSpeedFollowUp`技。技の既定はfalse |
| 交換 | 初撃→生存防御側の合法反撃→生存攻撃側の資格付き追撃 |
| 高速防御側 | v1は合法反撃一回。防御追撃は別調整設定、既定off |
| MP | 明示プール/技費用を選択発動一回ごとに消費。追撃費用は技で明記 |
| 移動回復 | 次の通常行動開始で一度。反撃/追撃では回復なし |

閾値5と交換順はMarinara案で、特定ゲーム再現の主張ではありません。要望は高速攻撃側の二回攻撃で、防御側の倍化は必要条件ではありません。

打撃間に生存、対象、射程、行動不能、残予算を再検証します。反撃で倒れた攻撃側は追撃不可、初撃外れだけでは速度追撃を取消しません。倒した対象を再攻撃/無断差替えせず、反撃への反撃再帰も防ぎます。反撃は防御側の通常開始を消費/付与しません。明示対応例外がなければ回復、強化、アイテム、召喚、伝説的行動は倍化しません。

交換開始時の受理有効能力値で資格を決めます。途中の行動不能は即適用しますが、途中速度強化で遡って打撃を追加しません。結果をイベントへ記録し、予測は一回/二回と反撃可否を示します。アニメーション中の更新は受理イベントを再生し、再抽選/二重消費しません。

Classicに移動射程はありません。移動を省くか別の交戦モデルを定義します。反撃には明示`canCounter`規則が必要で、配列位置にグリッド距離を適用しません。v1案は基本近接/遠隔交戦定義までClassic反撃を無効にし、攻撃側速度追撃を残します。

## 5eプロファイル: 実装前に版を指定

初期対象案はSRD 5.1固定の`5e-2014`です。後の2024/SRD 5.2には別ID/版/テストが必要で、暗黙に混ぜません。[公式SRD一覧](https://www.dndbeyond.com/srd)で版を確認し、[SRD 5.1](https://media.wizards.com/2023/downloads/dnd/SRD_CC_v5.1.pdf)を初期一次資料とします。

実装前に一次資料のDexterity順序、距離移動、アクション/ボーナス/リアクション、呪文枠、集中/状態、攻撃判定とセーヴを監査します。専用シート/解決fixtureが必要で汎用level/attack/defenseでは代用できません。呪文ポイントは独自資料/上限を検証して明示選択する変種で、枠プールの改名ではありません。

まず通常武器攻撃、移動、Dodge、少数呪文など正直な対応部分集合を提供し、未対応行動は選べなくします。一つの順序式だけで完全5eを主張しません。Traditional倍化は無効にし、追加攻撃は実装済み固有能力からだけ与えます。

## V20プロファイル: 専用監査が必要

対象はVampire: The Masquerade 20th Anniversary Editionで、V5/V20 Dark Agesではありません。順序、宣言順、複数行動、Celerity、ダメージ/soak、負傷ペナルティ、資源制限の正確な実装前に適切な一次資料を取得します。本書では正確なV20式を承認していません。

Attributes/Abilities、体力段階、Blood Pool、Willpowerと対応するターン消費制限を固有シートに用意します。血を汎用MPへ、CelerityをTraditional倍化へ変換しません。テストは版/参照箇所を示し、掲示板回答やDark Agesプレビューを現代V20の根拠にしません。文章/能力表の複製配布前に実際の資料の再利用/帰属条件を確認します。本書はそのコンテンツを提供しません。

## 伝説的行動、予測介入、リアクション

合意済み方針: Traditionalなど非5eでもGMボスに伝説的行動を与えられます。通常順序、性格、参加方式と独立した明示**ボス遭遇修正**です。AI設計のボス節を参照してください。

アダプターは`afterActivation`を公開し、Marinara予測修正の有効時は行動開始確定後の`activationStarted`も公開できます。両窓は**同じ**有限予算を使います。クリック、確認、メニュー取消、再読み込みで増やしません。GMはMageの能力/資源と実範囲/味方誤射から宣言前Fireballを予測できますが、未来命令は読めません。これは5eの行動後タイミングへのハウスルールで遭遇に固定します。忠実プロファイルは修正なしなら標準タイミングです。

Traditionalの開始一回規則は通常行動に適用し、伝説的行動で通常開始/速度追撃を与えません。Classicは一括入力中に早期介入せず実イニシアチブ枠で待機します。割込み後の待機命令を再検証し、確定前に違法なら再選択します。Tacticalは確認を無料にし、再選択で割込みを稼げない明示開始確定が必要です。

Counterspellなどは伝説的身分と独立した対応**イベント発動**です。発動、効果前後、視認/射程、資源費用、反応回数/回復、結果、元行動取消/返還を定義します。ボスGM/通常AIは同じ窓を使い、手動はReact/Passです。AIは性格、脅威価値、成功見込み、MP/枠希少性、反応喪失費用で評価し、パスできます。利用可能なだけで強制消費せず、通常体もボス化せず反応できます。

Counterspellには保留詠唱が必要で、Mage選択だけでは足りません。MP/ポイント/枠を分けます。[2014年の呪文](https://www.dndbeyond.com/spells/2051-counterspell)は呪文レベル/判定、[2024年の呪文](https://www.dndbeyond.com/spells/2619072-counterspell)はConstitutionセーヴを使い、成功した割込みでは元のスロット呪文の枠を消費しません。2024年の元呪文返還を全版/対抗術者の費用に広げません。Traditionalは明示調整処理、V20は自身の反応能力を定義し、名前だけでCounterspellを継承しません。

宣言/反応受理と資源確保/確定を原子的に行い、固有返還を別記録します。Traditional案は初期一回、明示条件がなければ利用可能、通常行動開始時に回復です。他アダプターは固有回数/境界を持ちます。伝説的行動/追撃で暗黙回復せず、既存交換反撃も明示対応付けまで別です。伝説的選択が呪文なら、そのルールが許す反応だけを公開します。

親/発動ID付き有限保存スタック、安定優先順、応答ごとの再検証で入れ子反応を扱います。取消済み詠唱を再対抗できず、パスは当該体/発動の機会を閉じます。限定アダプターは未対応連鎖を明示します。受理イベントを一度解決し描写を導きます。[PR #6110](https://github.com/Pasta-Devs/Marinara-Engine/pull/6110)の可逆文章割込みは保存/文脈の先例で、文章切断による戦闘巻戻しの許可ではありません。全ライフサイクル/受入行列はAI設計第16節です。

## 保存、UI、導入契約

- 遭遇スナップショットにルールID/版/有効設定、操作主体、シート、初期順序、現在/確定行動、伝説的/反応予算/回復点、保留スタック、発動/判断ID、資源確定/返還、クールダウン、乱数状態、受理割込みを固定します。
- 非同期GM判断前にサーバー管理リビジョン/台帳が必要です。古い同時送信を拒否し、再試行を冪等にします。ブラウザー内候補IDだけでは不十分です。
- 設定変更は次遭遇からです。輸入、チェックポイント/ブランチ復元、再接続、更新後も進行中の固定規則を保ちます。
- 旧進行戦闘は`engine-legacy`です。将来戦闘への明示変換では未対応能力/資源を事前表示し、シート/保存プールを黙って上書きしません。
- 未知の版は読取り専用/回復可能にし、最新版として暗黙解釈しません。
- ローカライズした**Combat rules**(戦闘ルール)を**Combat presentation**(戦闘表示)や将来の**Participation**(参加方式)と別にします。順序、資源、重要動作、開始前の互換制限を短く説明します。
- 必須シート項目がなければ開始前に求めます。旧規則の利用も明示選択とし、生成に正規能力値を捏造させません。
