# チャットへのリソースのドラッグ&ドロップ計画

## ステータス

フェーズ1からフェーズ4までは`drag-me-baby-one-more-time`ブランチで実装され、`staging`にマージ済みです。その後の作業(#7362)で、ライブラリーの行をハンドルなしでドラッグできるようになり、タッチ操作では2本目の指でタップして互換性のあるリソースを重ねて集められるようになり、並べ替え時には挿入位置に隙間が表示されるようになりました。

リゾルバーの自動テストは動いています。デスクトップ向けのPlaywrightのテストも、キャラクターの割り当てとペルソナの置き換えについて追加済みです。ただし現在の開発用コンテナーでは、Chromiumが`libnspr4.so`を読み込めないためローカルで実行できません。これらのブラウザーのテストは、CIか、Playwrightのシステム依存パッケージが入った環境で実行する必要があります。

残りのフェーズを始める前に、リポジトリーの調整ルールに従ってください。

1. チャットへのリソースのドラッグ&ドロップを扱う既存のissue、issueに紐づくブランチ、ドラフトPR、プロジェクトの項目がないかを確認します。
2. そのissue上で担当者を明示します。
3. 実装を始めたら`staging`向けのドラフトPRを作成します。

## 目的

チャットの設定画面を開かなくても、対応しているリソースを右パネルからアクティブなチャットへドラッグして割り当てられるようにします。

中央ペインには、ドロップ先の候補が2つあります。

- **チャット画面:** アクティブなチャットの保存される設定を変更します。
- **メッセージ入力欄:** 対応する添付ファイルを編集中の下書きに追加します。

どちらも何でも受け付けるドロップ先ではありません。ドラッグしている項目に対して、その場所で実際に対応している操作があるときだけ、ドロップ先が現れます。

## 製品としての方針

ドラッグで決まるのは、リソースとドロップ先だけです。実行する操作は、チャットのデータモデルと生成パイプラインにすでに存在するものに限ります。

- 追加系の有効な操作が1つだけの場合: すぐに適用し、Undo(取り消し)を提示します。
- 置き換え系の有効な操作が1つだけの場合: 既存の値を置き換えることになるなら確認を求めます。
- 実際に対応している操作が複数ある場合: それらの操作だけを並べた小さな選択メニューを表示します。
- 有効な操作がない場合: ドロップ先を有効にしません。
- すでに適用済みのリソースの場合: 重複するドロップは受け付けません。
- 見込みで作る1ターン限りのコンテキスト、見えないプロンプトの挿入、作り物のメンション、飾りのチップはいずれも作りません。

## 現在の取り決め

既存の`Chat`と`ChatMetadata`の取り決めでは、次の保存される操作に対応しています。

- キャラクター: `Chat.characterIds`を更新します。
- ペルソナ: `Chat.personaId`を更新します。
- プロンプトプリセット: `Chat.promptPresetId`を更新します。
- 接続: `Chat.connectionId`を更新します。
- ロアブック: `ChatMetadata.activeLorebookIds`を更新します。
- エージェント: `ChatMetadata.activeAgentIds`を更新し、承諾された場合は`ChatMetadata.enableAgents`も更新します。
- チャットの背景: `BackgroundPicker`が使っているのと同じ割り当て経路を通して、既存のチャット背景のメタデータを更新します。

既存のメッセージ入力欄はファイルの添付に対応しています。ただし、メッセージ単位でキャラクター、ロアブック、エージェント、ペルソナ、プリセット、接続を参照する仕組みには、現時点では対応していません。

## 対応する操作の一覧

ドロップ可否リゾルバーは、現在のチャットモードの制限と、リソースが使えるかどうかも判定する必要があります。この表は、アクティブなモードで既存のUIがすでに許可している場合の操作を示します。

| リソース | チャット画面 | メッセージ入力欄 | ドロップ時の動作 |
| --- | --- | --- | --- |
| キャラクター | `characterIds`にIDを追加 | なし | すぐに追加し、Undo付きのトーストを表示します |
| ロアブック | `activeLorebookIds`にIDを追加 | なし | すぐに追加し、Undo付きのトーストを表示します |
| エージェント | `activeAgentIds`にIDを追加 | なし | エージェントが有効ならすぐに追加します。無効なら、エージェントを有効にして追加してよいかを確認します |
| ペルソナ | `personaId`を設定 | なし | 未設定ならすぐに設定します。別のペルソナを置き換える場合は確認します |
| プロンプトプリセット | `promptPresetId`を設定 | なし | モードの制限に従います。未設定ならすぐに設定し、別のプリセットを置き換える場合は確認します |
| 接続 | `connectionId`を設定 | なし | 現在の接続を変更する場合は確認します。変更前と変更後の接続名も示します |
| チャットの背景 | 既存のチャット背景のメタデータを設定 | なし | 現在の背景割り当ての仕組みに従います。置き換えの確認は、既存の流れが求める場合だけ行います |
| 画像または対応するファイル | なし | 下書きの添付に追加 | 既存の添付ファイルの検証と準備の処理をそのまま使います |
| キャラクター/ロアブック/エージェントのフォルダー | なし | なし | ドロップ先なし |
| 設定のコントロール | なし | なし | ドロップ先なし |
| 正規表現スクリプト | なし | なし | チャット単位で割り当てる取り決めができるまではドロップ先なし |
| カスタム関数/ツール | なし | なし | チャット単位で割り当てる取り決めができるまではドロップ先なし |
| 拡張機能のコントリビューション | デフォルトでなし | デフォルトでなし | 将来の型付きコントリビューションAPIによるオプトインのみ |

### モードの規則

モードのポリシーをドラッグの処理側に二重に書かないでください。ドロップ可否リゾルバーは、既存のチャットのセットアップと設定のUIと同じ判定処理を使います。

少なくとも次の点を守ります。

- プロンプトプリセットはConversationモードでは引き続き使えません。`PresetsPanel`の挙動に合わせます。
- エージェントのドロップは、そのエージェントがインストール済みで、利用でき、現在のモードで有効な場合にだけ受け付けます。
- キャラクター、ペルソナ、ロアブック、接続、背景の操作は、既存の割り当て用のコントロールが使える場所でだけ提供します。
- アクティブなIDを持たないチャットでは、リソースのドロップ先を一切表示しません。
- ストリーミング中やエージェントの処理中でも、安全なメタデータの更新は妨げません。既存のミューテーション経路がすでに妨げている場合だけは例外です。置き換えの確認は、適用する前に現在のチャットの状態を読み直す必要があります。

## 操作の設計

### ドラッグの開始

対応するパネルの各行は、バージョン番号を持つリソースのペイロードを1つ書き込みます。

```ts
type ChatResourceDragPayload = {
  version: 1;
  kind: "character" | "lorebook" | "agent" | "persona" | "preset" | "connection" | "background";
  ids: string[];
  label: string;
};
```

カスタムのMIMEタイプは1つだけ使います。たとえば`application/x-marinara-chat-resource`です。移行のあいだは既存のフォルダー用のMIMEペイロードも残します。同じドラッグに対して、フォルダーの並べ替えという別の解釈も引き続き有効だからです。

リソースのドラッグでは、ドラッグ効果として`copyMove`を宣言します。

- フォルダーのドロップ先は、そのドラッグを移動として解釈します。
- チャットのドロップ先は、そのドラッグをコピー(割り当て)として解釈します。

アプリ内部のリソース操作で`text/plain`に頼らないでください。あいまいなうえ、現状ではIDがそのまま入っているだけです。

### ドロップ先の表示

ドロップ先の表示は、何もしていないあいだは隠しておきます。

認識できるリソースのドラッグが中央ペインに入ったときは、次の順で処理します。

1. 型付きのペイロードを解析して検証します。
2. 最新のアクティブなチャットに対して、有効な操作を判定します。
3. 有効なドロップ先だけを表示します。
4. 文言は`Add Maris to this chat`のように操作ごとに具体化し、`Drop here`のような一般的な表現は使いません。
5. 対象外の領域は見た目を変えず、ドロップも受け付けません。

対応するファイルのドラッグでは、メッセージ入力欄だけが光ります。キャラクター、ロアブック、エージェント、ペルソナ、プリセット、接続、背景のドラッグでは、最初のリリースではチャット画面だけが光ります。

### チャット画面へのドロップ

ドロップを受け付ける領域は現在のチャット画面全体で、履歴のスクロール位置とは関係ありません。古いメッセージの上でドロップしても、履歴が差し込まれたり、コンテキストが後からさかのぼって変わったりすることはありません。

ドロップ時の処理は次のとおりです。

1. アクティブなチャットのIDと現在のチャットデータを読み直します。
2. 古い判定や重複した操作を防ぐため、可否をあらためて判定します。
3. 追加系であいまいさがない場合は、すぐに適用します。
4. 置き換えの場合とエージェントを有効にする場合は、要点だけに絞った確認を表示します。
5. 成功したときは、ローカライズしたトーストとUndoの操作で知らせます。
6. 更新に失敗したときは、履歴を変えずにその旨を知らせます。

設定の変更を記録するために、ユーザー、アシスタント、ナレーター、システムのメッセージを作らないでください。メッセージのモデルには活動イベント専用の種別がなく、設定の変更がモデルから見える履歴に入ってはいけません。

### メッセージ入力欄へのドロップ

`ChatInput`と`ConversationInput`の両方で、現在のファイルの挙動をそのまま維持します。

- 対応する形式と20 MBというサイズ上限を検証します。
- 画像は`prepareImageAttachment`で準備します。
- 対応するテキストとPDFのファイルは、現在の添付処理の経路で読み込みます。
- チャットごとに保留中の添付を下書きとして保つ挙動も維持します。

メッセージ入力欄のドラッグ判定を厳しくして、アプリ内部のリソースのドラッグでファイルのドロップ表示が光り、そのまま何も起きないという状態をなくします。

### 確認

確認を求めるのは、その操作に意味のある影響があるときだけです。

- アクティブなペルソナを置き換えるとき。
- アクティブなプロンプトプリセットを置き換えるとき。
- アクティブな接続を切り替えるとき。
- エージェントの追加に伴って、エージェント機能を有効にするとき。
- 既存の背景割り当ての経路が、もともと選択や置き換えの確認を求めているとき。

確認の表示では、該当する場合に現在の値と変更後の値を示します。新しいチャットを始める、エージェントを1回だけ呼び出す、そのリソースをメッセージ内で参照するといった、無関係な操作を含めてはいけません。

### Undo

Undoはドロップ前の値をそのまま復元します。推測で組み立て直した値ではありません。

- キャラクター: 直前の`characterIds`の配列をまるごと復元します。
- ロアブック: 直前の`activeLorebookIds`の配列をまるごと復元します。
- エージェント: `activeAgentIds`と`enableAgents`の両方を復元します。
- ペルソナ、プリセット、接続、背景: 直前の値を復元します。

Undoを実行する前に、ドロップで設定された値がアクティブなチャットに今も残っているかを確かめます。その後に別の編集が同じ項目を変更していた場合は、上書きしないでください。古くなったUndoを取り下げ、チャットが変わったことを画面で伝えます。

## アーキテクチャ

### クライアント共通のユーティリティー

役割を絞ったクライアント側のモジュールを追加します。ファイル名は暫定で`packages/client/src/lib/chat-resource-drag.ts`とし、次を持たせます。

- MIMEタイプの定数。
- ペイロードの型と、実行時のパーサー。
- `writeChatResourceDragPayload(dataTransfer, payload)`。
- ファイルのドラッグの判別。
- リソースの種類のガード関数。

最初のリリースでは、このペイロードをクライアント内部に閉じたままにします。APIの取り決めではなく、ブラウザー上の操作状態にすぎないからです。

### ドロップ可否リゾルバー

副作用のないリゾルバーを追加します。ファイル名は暫定で`packages/client/src/lib/chat-resource-drop-capabilities.ts`です。

```ts
type ChatResourceDropAction =
  | { type: "add-characters"; ids: string[] }
  | { type: "add-lorebooks"; ids: string[] }
  | { type: "add-agents"; ids: string[]; mustEnableAgents: boolean }
  | { type: "set-persona"; id: string; replacesId: string | null }
  | { type: "set-preset"; id: string; replacesId: string | null }
  | { type: "set-connection"; id: string; replacesId: string | null }
  | { type: "set-background"; id: string };
```

入力は、解析済みのリソースのペイロード、アクティブなチャット、正規化したメタデータ、現在のモード、利用できるリソースのIDです。出力は具体的な操作1つか`null`のどちらかです。

リゾルバーが受け持つのは次の点です。

- 重複の抑制。
- モードによる制限。
- 複数IDの絞り込み。
- インストール済みか、利用できるかの確認。
- 置き換えの検出。
- 画面に出す操作の文言キーの選択。

リゾルバーは、更新も画面の描画も行いません。

### ミューテーションのコーディネーター

チャット画面の近くにフックを1つ追加します。ファイル名は暫定で`use-chat-resource-drop.ts`とし、次を担当させます。

- ドロップの時点で、React QueryとZustandから最新のアクティブなチャットを読みます。
- チャット本体の項目には`useUpdateChat`を呼びます。
- ロアブックとエージェントには`useUpdateChatMetadata`を呼びます。
- 背景は、既存の割り当て用のミューテーション経路をそのまま使います。
- 確認の表示には、既存のアプリ内ダイアログの補助機能を使い、ローカライズします。
- 成功と失敗のトースト、および保護つきのUndo操作を作ります。

非同期の更新ロジックをZustandストアに置かないでください。

### ドロップ用のオーバーレイ

表示専用のコンポーネントを1つ、共通の中央チャット領域の境界に追加します。履歴ごとに別々の実装を作らないでください。

- 現在のドラッグのペイロードと、判定済みの操作を受け取ります。
- メッセージ入力欄を覆わずに、チャット画面全体を覆います。
- 子要素をまたぐちらつきを防ぐため、`dragenter`と`dragleave`の深さを数えます。
- アイコン、リソースの名前、ローカライズした操作の文言を表示します。
- ポインターの種類とテーマに追従します。

ConversationとRoleplay/Gameのどちらの画面も、同じコーディネーターを経由させます。画面ごとのラッパーが配置や大きさを与えるのは構いませんが、可否のポリシーを二重に持たせてはいけません。

### パネル側の対応

ドラッグできる行は、次の順に少しずつ対応させます。

1. キャラクター。
2. ロアブック。
3. エージェント。
4. ペルソナ。
5. プリセット。
6. 接続。
7. 背景。ただし既存の割り当ての取り決めを無理なく再利用できる場合だけです。

各行は既存のフォルダー用のドラッグペイロードをそのまま持ち、チャットリソースのペイロードを追加します。フォルダーへの移動の挙動は変えないでください。

## 提供フェーズ

### フェーズ1: ドラッグの取り決めと中央のオーバーレイ

- 型付きのペイロードのユーティリティーとパーサーを追加します。
- キャラクター、ロアブック、エージェント向けの、副作用のない可否リゾルバーを追加します。
- 中央のチャット画面のオーバーレイと、ミューテーションのコーディネーターを追加します。
- キャラクター、ロアブック、エージェントの各パネルの行を対応させます。
- 操作、確認、成功、エラー、重複、Undoの各文言を追加し、ローカライズします。
- アプリ内部のリソースのドラッグで、メッセージ入力欄のファイル用の表示が光らないようにします。

このフェーズで、この機能に求められている中心的な追加の流れを実証します。

### フェーズ2: 置き換え系のリソース

- ペルソナ、プリセット、接続のペイロードを追加します。
- 置き換えの検出と、ローカライズした確認ウィンドウを追加します。
- 既存のモード制限とミューテーションのフックをそのまま使います。
- 置き換えの操作にも、保護つきのUndoを追加します。

### フェーズ3: 背景の割り当て

- 既存の背景選択の流れが、ポリシーを二重に持たずにドロップされた背景のIDを受け取れるかどうかを見極めます。
- 同じチャット単位の割り当ての挙動をそのまま再利用できる場合にだけ、背景のドラッグを追加します。
- 再利用できない場合は背景を対象外のままにし、その理由をissueかPRに記録します。

### フェーズ4: タッチ操作とドラッグ以外の手段の対等化

最初に実装するのは、デスクトップのHTMLドラッグ&ドロップです。モバイルでは、パネルをまたぐ精密なドラッグに依存させてはいけません。

- 対応する各行の既存の操作メニューに`Add to active chat`を追加します。
- 可否リゾルバー、確認、更新処理、Undoの挙動は同じものを使います。
- タッチでのドラッグを残す場合は、既存のタッチ用ドラッグハンドルを使い、中央のドロップ先は`elementFromPoint`で判定します。
- フォルダーの長押しの挙動に別の意味を重ねて、整理の操作が不安定になるようにしてはいけません。

モバイルでこの機能を完成と呼ぶには、このフェーズが必須です。

## アクセシビリティーと入力に関する要件

- 色だけに頼らず、リソースのアイコンと操作の文言も表示します。
- ドラッグ以外の手段は、カーソルを合わせないと見つからない作りにしません。
- 確認のウィンドウはキーボードで操作でき、閉じるとフォーカスが元に戻ります。
- Escを押すと、表示中の確認を取り消せます。
- 有効なドロップ先が現れたとき、および操作が成功または失敗したときに、スクリーンリーダーへ簡潔な読み上げを送ります。
- 認識できるドラッグが行われていないあいだ、ドラッグ用のオーバーレイが通常のスクロールを奪ってはいけません。
- タッチ操作の対象は、既存のモバイル向けの最小サイズに従います。
- 動きを減らす設定では、余計な動きを出さず、透明度と状態の変化だけで表します。

## ローカライズ

新しく画面に出る文言はすべて、意味のわかるローカライズキーを使います。更新するのは正となる英語カタログだけで、コミュニティ製の言語は英語にフォールバックしてかまいません。

対象となる文言は次のとおりです。

- リソースの種類ごとの操作ラベル。
- 置き換えの確認。
- エージェントを有効にする確認。
- 成功と失敗のトースト。
- Undoと、古くなったUndoのメッセージ。
- アクセシビリティー用の読み上げ。
- 重複やすでに有効であることを伝える表示(出す場合)。
- ドラッグ以外の`Add to active chat`の操作。

## テスト

一時的な`.test.ts`ファイルをリポジトリーに残さないでください。

### 純粋な回帰テスト

可否リゾルバーの恒久的なテストは、既存の対応している回帰テストの場所と形式にだけ追加します。

- キャラクターが未追加 -> 追加の操作。
- キャラクターが追加済み -> 操作なし。
- 複数のキャラクターが混在するペイロード -> 未追加で有効なIDだけを追加。
- ロアブックが未追加 -> 追加の操作。
- ロアブックがすでに有効 -> 操作なし。
- エージェントが未追加でエージェント機能が有効 -> 追加の操作。
- エージェントが未追加でエージェント機能が無効 -> 有効化を伴う追加の操作。
- エージェントが利用できない -> 操作なし。
- 現在のペルソナが未設定 -> 置き換えを伴わない設定の操作。
- 別のペルソナを置き換える -> 置き換えの操作。
- 対応していないモードでのプリセット -> 操作なし。
- 現在の接続と同じ接続 -> 操作なし。
- バージョンが不正、種類が不明、IDの形式が不正、ペイロードが大きすぎる -> いずれも拒否。

### ブラウザーのスモークテスト

無理のない範囲で`pnpm smoke:ui`を拡張します。

- パネルからキャラクターをチャット画面へドラッグし、割り当てられることを確認します。
- Undoを実行し、直前のキャラクターの一覧が復元されることを確認します。
- キャラクターをメッセージ入力欄の上でドラッグしても、ファイルのドロップ表示が出ないことを確認します。
- 対応するファイルをメッセージ入力欄の上へドラッグし、添付の挙動が変わっていないことを確認します。
- すでに有効なリソースには、ドロップ先が現れないことを確認します。
- 置き換えの確認を取り消すと、何も更新されないことを確認します。
- 置き換えを確定すると、チャットが更新されることを確認します。
- フォルダーへのドラッグ&ドロップで、パネル内のリソースが今までどおり移動することを確認します。

### 手動での確認

デスクトップでは、対応しているConversation、Roleplay、Gameの各モードについて次を確認します。

- ダークテーマとライトテーマ。
- 右パネルを開き、履歴が長くスクロールしている状態。
- 追加のドロップ、重複したドロップ、置き換え、取り消し、失敗、Undo、古くなったUndo。
- 入れ子になった履歴の要素をまたいでドラッグしても、オーバーレイがちらつかないこと。
- 既存のパネルのフォルダー移動。
- 両方のメッセージ入力欄での、既存のファイルと画像のドロップ。

モバイル、または粗いポインターの画面幅では次を確認します。

- ドラッグを使わない`Add to active chat`が同等に使えること。
- 既存のフォルダーのタッチドラッグが引き続き使えること。
- 確認の表示が画面に収まり、閉じられること。
- 文字やコントロールが重ならないこと。

必須のコマンドです。

```bash
pnpm localization:check
pnpm check
pnpm regression:prompt
pnpm smoke:ui
```

マージ前には`pnpm regression:prompt`が必須です。`LorebooksPanel.tsx`の変更はロアブックの有効化に影響し、それがプロンプトの組み立てにつながるためです。

## リスクと対策

### 既存のフォルダーのドラッグとの衝突

リスク: 同じ行では、フォルダーへ項目を移動するためにすでにドラッグ&ドロップを使っています。

対策: 既存のフォルダー用のMIMEタイプは残し、型付きのチャットリソース用のMIMEタイプを別に追加して、各ドロップ先には自分のペイロードだけを解釈させます。`copyMove`の挙動と、フォルダー周りの回帰も確認します。

### メッセージ入力欄の誤った表示

リスク: 現在のメッセージ入力欄の`dragover`の処理は、アプリ内部のリソースIDも含めて、あらゆるドラッグに反応します。

対策: メッセージ入力欄の表示を出す条件を絞ります。`DataTransfer.types`か`DataTransfer.items`が、ファイルか明示的に対応している添付のペイロードを示している場合だけにします。

### 古くなったチャットの状態

リスク: ドラッグの開始、ドロップ、確認、Undoのあいだに、アクティブなチャットや割り当て済みのリソースが変わることがあります。

対策: ドロップの時点と、更新やUndoの直前に、現在の状態に対してあらためて判定します。Undoが新しい変更を上書きしないように保護します。

### モードのポリシーのずれ

リスク: ドラッグ&ドロップが、セットアップや設定のUIでは禁止されている割り当てを許してしまうおそれがあります。

対策: 既存の割り当ての流れから共通の判定処理を切り出すか、そのまま再利用します。2つ目のポリシー表をパネルのコンポーネントに直接書き込まないでください。

### 見えないところでの挙動の拡大

リスク: メッセージ入力欄が見た目上リソースを受け付けると、サーバーが実際には扱わない1ターン限りのコンテキストがあるかのように見えてしまいます。

対策: メッセージ単位のコンテキストの取り決めを別途設計するまで、リソースをメッセージ入力欄へドロップする経路は無効のままにします。

### 大量選択のドロップ

リスク: 選択モードでのドラッグにより、想定外に大量のキャラクター、ロアブック、エージェントが追加されるおそれがあります。

対策: 無効なIDとすでに有効なIDを除外し、サーバーやモードの既存の上限に従い、複数項目のドロップが既存のしきい値を超える場合は確認を求めます。新しい上限を勝手に作らないでください。

## 明確な対象外

- 過去のメッセージの上へリソースをドロップすること。
- プロンプトの履歴をさかのぼって変えること。
- 設定の変更を履歴のメッセージとして追加すること。
- 1ターン限りのキャラクター、ロアブック、ペルソナ、プリセット、接続、エージェント。
- メッセージ入力欄へのドロップによるエージェントの呼び出し。
- 中央の画面へのドロップから新しいチャットを始めること。
- 任意の設定項目をチャットへドラッグすること。
- 最初のリリースでの、汎用のプラグイン向けドロップAPI。
- あるチャットの履歴から別のチャットへドラッグすること。

## 受け入れ基準

フェーズ1は、次をすべて満たしたときに受け入れ可能になります。

- キャラクター、ロアブック、エージェントを、右パネルの行から有効なアクティブなチャット画面へドラッグできます。
- 履歴にメッセージを作らずに、正しい既存のチャットの項目が更新されます。
- すでに有効なリソースと、利用できないリソースは受け付けません。
- エージェント機能が無効の状態でエージェントを追加するときは、明示的な確認が必要になります。
- 更新が成功したときは、必ず保護つきのUndoを提示します。
- リソースのドラッグでは、メッセージ入力欄の添付の表示が出ません。
- 既存のファイル添付のドロップは、両方のメッセージ入力欄で引き続き動きます。
- 既存のフォルダーへのドラッグ&ドロップの挙動は変わりません。
- 新しく画面に出る文言はすべてローカライズされています。
- デスクトップとモバイルで同等の操作ができます。モバイルではパネルをまたぐドラッグの代わりに、メニューの操作でもかまいません。
- `pnpm localization:check`、`pnpm check`、および関連するUIのスモークテストが通ります。

機能全体としては、フェーズ2の置き換え系のリソースと、必須のモバイル対応もそろった時点で受け入れ可能になります。背景の割り当ては任意のままです。既存の意味づけをポリシーを二重に持たずに再利用できるとフェーズ3で確認できるまでは、対象外のままにします。

## 先送りする拡張

将来メッセージ単位のコンテキスト機能ができれば、キャラクター、ロアブック、エージェント、ペルソナ、プリセット、接続をメッセージ入力欄へドロップできるようになるかもしれません。ただしその作業には、共通パッケージとサーバー側の別の取り決めが必要です。そこでは、永続化、プロンプトの組み立て、トークンの配分、プロバイダーへの振り分け、表示、下書きの復元、メッセージ履歴の扱いを定めます。クライアント側だけのチップとして、この機能にこっそり紛れ込ませてはいけません。
