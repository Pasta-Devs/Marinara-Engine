# UIのローカライズ

Marinara Engineはアプリの画面テキストをローカライズします。モデルへ送るプロンプト、作成したコンテンツ、生成されたチャットの
本文、識別子、プロトコルの値、ファイルパス、保存済みの機械向けの値は変更しません。

英語が正規のロケールであり、実行時のフォールバック先でもあります。コミュニティ翻訳が欠けている箇所には、翻訳キーや空の
コントロールではなく英語のテキストが表示されます。

画面の言語は**Settings > General > App Behavior > Language**(設定 > 一般 > アプリの動作 > 言語)で選びます。切り替わるのは
Marinaraの操作画面と説明文だけで、モデルへのプロンプト、作成したコンテンツ、チャットのメッセージは変わりません。

英語以外の言語を選ぶと、必要に応じて言語パックがダウンロードされます。**Refresh language pack**（言語パックを更新）で新しい翻訳を取得できます。ダウンロード済みのパックは`DATA_DIR/ui-packs`に保存され、オフラインでも使えます。ダウンロードに失敗しても、現在の言語やインストール済みのパックは変わりません。起動時や更新時にパックが自動でダウンロードされることはありません。

翻訳を同梱していたバージョンから初めて更新すると、それまで英語以外に設定していた言語は英語に戻ります。もう一度言語を選んでダウンロードしてください。ユーザーのコンテンツやほかの設定は変わりません。

## 対応している画面の言語

| 言語 | ロケールファイル | 文字の方向 |
| --- | --- | --- |
| アラビア語 | `ar.json` | 右から左 |
| 中国語(簡体字) | `zh-Hans.json` | 左から右 |
| 英語 | `en.json` | 左から右 |
| フランス語 | `fr.json` | 左から右 |
| ドイツ語 | `de.json` | 左から右 |
| ヒンディー語 | `hi.json` | 左から右 |
| 日本語 | `ja.json` | 左から右 |
| 韓国語 | `ko.json` | 左から右 |
| ポーランド語 | `pl.json` | 左から右 |
| ポルトガル語(ブラジル) | `pt-BR.json` | 左から右 |
| ロシア語 | `ru.json` | 左から右 |
| スペイン語 | `es.json` | 左から右 |

英語を原文のカタログとして管理しています。コミュニティのカタログは機械翻訳を利用して作成されており、その言語に堪能な方からの修正を受け付けています。UIテキストの抽出はまだ進行中のため、翻訳キーのないテキストは引き続き英語で表示されます。

## ロケールファイル

基準となる英語カタログの場所は変わりません。

```text
packages/client/src/localization/locales/en.json
```

コミュニティのパックは、ドキュメントの言語別フォルダーとは別に、[`docs-i18n`の`ui/`](https://github.com/Pasta-Devs/Marinara-Engine/tree/docs-i18n/ui)に置かれます。各BCP-47ロケールには`ui/pl.json`、`ui/ko.json`、`ui/pt-BR.json`などのJSONファイルが1つあり、共通の生成ファイル`ui/manifest.json`にファイルサイズとSHA-256ハッシュが記録されます。ロケールコードの大文字と小文字を正確に保ってください。アラビア語のドキュメントパックがなくても、アラビア語UIは利用できます。英語はアプリケーションとともに読み込まれます。コミュニティのパックは明示的な操作でダウンロードされ、ローカルサーバーから読み込まれます。

```json
{
  "_meta": {
    "locale": "pl",
    "direction": "ltr"
  },
  "chat.input.placeholder": "Napisz odpowiedź…",
  "common.actions.save": "Zapisz"
}
```

キーは画面の領域ごとに整理した意味ベースの名前にします。英語の文そのものをキーにしないでください。ふつうの文言修正のたびに、
すべての翻訳が無効になってしまいます。

## 翻訳のルール

- 翻訳するのは値だけです。意味ベースのキー名は変更しません。
- `{{name}}`のような補間トークンと、`<strong>`のようなリッチテキストのタグはそのまま残します。
- 翻訳キーはアルファベット順に並べたままにします。
- Marinara Engineのような製品名は変更しません。プロジェクトが公式の訳名を採用した場合だけ例外です。
- `en.json`の意味とトーンに合わせます。英語の原文にない動作や約束を足さないでください。
- 訳したラベルがデスクトップでもモバイルでも収まるか確かめます。

機能分野の翻訳を準備している間、コミュニティのパックでは一時的にキーを省略できます。欠けたキーには英語が使われます。パックの検証ツールは翻訳率と古いキーを報告し、Engineは古いキーを無視します。空の翻訳（既存の意図的に空にしている接尾辞の例外を除く）、不正なメタデータ、変更された補間トークンやリッチテキストのトークンは検証に失敗します。キーの名前変更や削除はパックにも反映するか、`[ui-i18n]`のフォローアップIssueで追跡してください。

機能を追加するPRでは基準となる英語キーの追加や更新が必要ですが、コミュニティのパックを変更する必要はありません。有用な翻訳を提供できる場合にだけコミュニティの値を翻訳してください。キーの一覧をそろえるためだけに、すべての言語ファイルへ英語の値をコピーしないでください。英語はフォールバックで表示されます。キーを省略しておけば、翻訳者にとって不要なマージ競合を減らせます。

機械翻訳も、PRでそうだと明示するなら最初の下書きとして歓迎します。そのロケールをレビュー済みと呼ぶ前に、堪能な方が用語、トーン、
文字切れ、モバイルでのレイアウトを確認してください。

## 既存の翻訳への修正を提出する

小さな言い回しの修正なら、GitHubのWebエディターだけで足ります。

1. [`ui/`](https://github.com/Pasta-Devs/Marinara-Engine/tree/docs-i18n/ui)でロケールファイルを
   開きます。
2. 鉛筆アイコンを選んでファイルを編集します。必要な場合はGitHubがフォークの作成を提案します。
3. 変更するのは訳文の値だけです。キー、`{{name}}`のような記号に敏感なトークン、JSONの構文はそのまま保ちます。
4. フォーク内の目的を絞ったブランチに変更をコミットします。
5. 以下のコマンドでパックのマニフェストを更新して検証し、`staging`や`main`ではなく**`docs-i18n`**を対象にプルリクエストを作成します。 ([`validate-packs.mjs`](#%E6%96%B0%E3%81%97%E3%81%84%E3%83%AD%E3%83%BC%E3%82%AB%E3%83%A9%E3%82%A4%E3%82%BA%E3%82%92%E6%8F%90%E5%87%BA%E3%81%99%E3%82%8B))
6. PRの説明には、言語、修正した意味、そして自分が堪能な話者なのか機械翻訳を使ったのかを書きます。

タイトルは`Improve French UI translation`のような形にします。1つのロケールに対する関連した修正は、まとめて1つのPRにできます。
無関係なコード変更は分けてください。

## 新しいローカライズを提出する

新しい言語を追加する場合は、英語の原文を参照するためにEngineの`staging`チェックアウトを用意し、`docs-i18n`で作業します。

```bash
git clone https://github.com/YOUR-NAME/Marinara-Engine.git
cd Marinara-Engine
git checkout docs-i18n
git pull
git checkout -b translation/LOCALE
```

続いて次の手順を行います。

1. Engineのチェックアウトにある基準の`en.json`を、`ui/it.json`や`ui/pt-PT.json`などの`ui/<locale>.json`にコピーします。
2. `_meta.locale`は`.json`を除いたファイル名と同じにします。
3. `_meta.direction`に`ltr`または`rtl`を設定します。
4. 上のルールに従って値を翻訳します。新しいロケールでは英語カタログ全体を訳しきるのが望ましいものの、途中までのカタログでも
   残りは英語にフォールバックします。
5. マニフェストを生成してパックの検証ツールを実行します（Node.jsのみ必要で、依存関係のインストールは不要です）。Engineのチェックアウトにある英語カタログに対する翻訳率が報告されます。

   ```bash
   node scripts/ui-i18n/validate-packs.mjs /path/to/Engine/packages/client/src/localization/locales/en.json --write-manifest
   node scripts/ui-i18n/validate-packs.mjs /path/to/Engine/packages/client/src/localization/locales/en.json
   ```

6. 新しい言語には、`packages/shared/src/utils/ui-locales.ts`の`UI_LANGUAGE_CODES`にコードを追加する小さなEngineのPRも必要です。既存のパックの更新にはEngineの変更は不要です。公開後、**Settings > General**で言語を選び、デスクトップとモバイルの両方で確認します。長いラベル、ツールチップ、読み込み中やエラーの状態、文字の方向を確認してください。
7. ブランチを自分のフォークへプッシュし、
   [プルリクエストを開きます](https://github.com/Pasta-Devs/Marinara-Engine/compare)。ベースには
   `Pasta-Devs/Marinara-Engine:docs-i18n`を選びます。

PRの説明には、ロケール、翻訳の出所、堪能さやレビューの度合い、実行した検証コマンド、そしてネイティブスピーカーの確認がまだ
必要な箇所を書きます。PRテンプレートは正直に埋め、自分で実際に確かめた手動の項目だけにチェックを入れてください。

## クライアントコードで翻訳を使う

Reactコンポーネントでは`useTranslation`を使います。

```tsx
import { useTranslation } from "react-i18next";

const { t } = useTranslation();
return <button>{t("common.actions.save")}</button>;
```

モジュール階層のUI設定には、訳文そのものではなく翻訳キーを保存します。こうすると、ページを再読み込みしなくても言語の切り替えが
その場で反映されます。React以外のクライアント側のヘルパーは、`packages/client/src/localization/i18n.ts`がエクスポートする
`translate`関数を使えます。

画面に見えるテキストはすべて翻訳します。ラベル、プレースホルダー、ツールチップ、アクセシビリティー用の名前、代替テキスト、
読み込み中と空の状態、トースト、確認メッセージ、静的なチュートリアルが対象です。プロンプトや作成したコンテンツをUIの翻訳機構に
通してはいけません。

Settingsのコントロール、ヘルプのツールチップ、ウィンドウのタイトルといった共有の旧来の部品は、古い呼び出し箇所の移行が終わるまで、
正規の英語カタログの値と完全に一致する文字列も認識します。これは互換性のための橋渡しであって、推奨されるAPIではありません。
新規のコンポーネントや大きく手を入れたコンポーネントでは、意味ベースの`t("area.control.label")`キーを直接使ってください。
`en.json`にない英語の文は翻訳できません。

リポジトリーのローカライズチェックでは、クライアントのTSXに未翻訳の画面テキストが残っていないかも検査します。

```bash
pnpm localization:ui-check
```

対象は、表示されるJSX、直接埋め込まれたラベルや注意書き、アクセシブルな名前、プレースホルダー、読み込み中と空の状態、トースト、
確認メッセージです。`code`、`pre`、`script`、`style`の各要素の中にあるリテラルは意図的に除外しています。コマンド、設定、URL、
マクロなど機械向けの例をそのまま保つためです。動的に作成された値、生成された値、保存された値、プロンプトの値、プロトコルの値も
同様に、画面の翻訳機構の外に置く必要があります。

## ダウンロードして追加するエージェントの画面

Engineが管理するエージェント画面は、基準の英語とダウンロード済みの`docs-i18n/ui`パックを使います。ダウンロード可能なCapabilityクライアントの翻訳は、Marinara-Agentsリポジトリでそれぞれ管理します。

機能のカスタム要素にはいずれも、選択中のロケールが`lang`属性と`dir`属性の両方で渡され、さらに次の値も渡されます。

```ts
capabilityProps.localization = {
  locale: "pl",
  direction: "ltr",
};
```

ロケールが変わると、既存の`marinara-capability-props`イベントが発生します。パッケージ側のUIは同梱のロケールを選び、
なければパッケージ内の英語にフォールバックし、このイベントの後に再描画してください。
