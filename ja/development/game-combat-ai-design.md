## 9月17日の範囲更新

メンテナーはClassic/Tacticalの通常AIと任意の仲間AI操作を承認した後、GMボス/リアクションの実装も承認しました。明示的に定義されたボスは、5eルールセットの選択にかかわらず伝説的アクションを使えます。GMはパーティーの戦闘シート/資源を受け取り、ユニットの行動開始時に予測できます。Counterspellなど資源を使うリアクションは、使用可能だから必ず使うのではなく、操作主体の判断が必要です。Summoningは設計拡張のままです。元の監査と詳細設計を残し、第13–17節の決定がTacticalのみの実装順、初期8性格案、調査のみという旧範囲、観測状態だけの旧ボスプロンプトに優先します。

実行時コードは効用評価ポリシーの最初の実装であり、全受け入れ条件の完了ではありません。境界は第13、16節にあります。[ルールセット実装の引き継ぎ](game-combat-rulesets-implementation.md)ではTraditionalの速度追撃、行動/移動順、資源プール、将来の版別プロファイルを扱います。

## 1. メンテナーの要望

- 通常の敵は、Reckless BruiserやCautious Spellcasterのような**形容詞1つと戦闘役割**で示すエンジン制御を使います。
- **行動ごとのGM操作はボス級の敵だけです。** 合法な行動と結果はエンジンが決定します。事前の台本生成だけでなく、戦闘中に行動を選びます。
- 性格割り当ては熟練度/レベル、役割、既知の人物像と乱数を考慮します。経験者は役割に合う習慣を持ちやすくしますが、全員同一にはしません。
- **BeastとMonstrosityはすべてMindlessです。** 相手のHPや地形の有利不利を無視し、最短の合法経路で最寄りのパーティーメンバーを追います。ボスや名前付きの個体を暗黙に除外しないでください。
- 戦略的な楽しさ、自然な行動、再プレイ性を重視し、特にTacticalと将来の卓上型ルールに備えます。このAI変更に5e/V20実装は必須ではありません。
- 後続開発用の詳細設計を残します。当初の調査範囲は通常AIと仲間操作に拡張済みです。上の範囲更新を参照してください。

[戦闘ロードマップ](game-combat-roadmap.md)のとおり、戦場ルール、パーティー/召喚参加、卓上ルールプロファイルは独立した選択です。敵の戦術も独立させます。Summoningの優先順位は後です。

### まだ設計承認が必要な推奨初期値

1. 初期性格はMindless、Reckless、Cautious、Opportunistic、Protective、Supportive、Disciplined、Cowardlyの8つです。
2. 敵の詳細に性格、役割、短い説明を表示します。確率、効用重み、人物像の生分析は通常UIに出しません。
3. Mindlessの最短経路は地形コスト最小ではなく、**合法な空間ステップ数の最小**です。長い平地の迂回が速くても短い森を通れます。移動時は実際の地形コストを払います。
4. Beast/MonstrosityのボスもMindlessです。GMは指定目標と追跡方針に合う行動だけを選びます。
5. 通常プロファイルは一度抽選して保存します。再登場する名前付きNPCは既存の性格を保持し、レベル上昇だけでは再抽選しません。
6. 改訂範囲ではTacticalとClassicの通常AIを一緒に実装します。全機能には実際のGMボス行動が必要で、エンジンだけの段階を完成とは呼びません。

## 2. 改修前のソース監査

メンテナーの2番目の仮説が近く、各稼働中の戦闘エンジンには共通の自動ポリシーがあります。GMは遭遇を作成しますが、現在のGame Mode戦闘UIで個別行動を選びません。

| 項目 | Classic Game Mode | Tactical Game Mode |
| --- | --- | --- |
| 行動順 | イニシアチブの出目と速度。全戦闘員が参加 | 新しいゲームはイニシアチブ順(1体ずつ、順番は1回だけ振る、combat C6c)。古いゲームは陣営順(プレイヤーフェーズ後、敵が速度順) |
| 敵ポリシー | 共通の技能選択。なければ生存敵からランダム | 回復優先、攻撃評価、接近の共通方針 |
| クラス差 | クラス別の意思決定なし | 6クラスで射程、移動、クリティカルが変わるが判断方針は共通 |
| 人物像/熟練度 | 戦術的性格や訓練モデルを保存しない | 戦術的性格や訓練モデルを保存しない |
| ボス判断 | 通常方針と対応するスクリプト機構 | 通常方針。ボス表示は配置/UIに影響 |
| 行動ごとのGM | 現行処理にはない | 現行処理にはない |
| 再現性 | シードなしの判断/出目 | シードと行動カウンターで判断/出目を決定 |
| 永続化 | クライアントがスナップショットを復元。ラウンド/アニメーションは不完全 | 全戦術スナップショットをチャットメタデータに保存 |

別の遭遇モーダルにはモデル駆動の`/encounter/action`と戦闘行動型があります。一般チャットの`EncounterModal`が`useEncounter`経由で使い、Game Modeの現行`GameCombatUI`は使いません。モデルは書き換えた戦闘状態を返せるため、エンジン検証型ボス制御にそのまま流用しないでください。再利用/削除前に実際の呼び出し元を追ってください。

Classicの明示的な**Special**(特殊行動)もGMに物語上の行為を裁定させ、対応する状態/属性タグを許可します。通常ラウンドや日常的な敵行動を選ぶ機能ではありません。GMプロンプトを更新する際も区別してください。「ボスのみがターンを制御する」という方針は、遭遇生成、物語上の裁定、戦闘後の叙述を禁止するものではありません。

### Classicのポリシー

`combat.service.ts`の`resolveCombatRound`は自動味方/敵に`chooseAutoSkill`を呼びます。

1. MPが足り、ラウンド番号の剰余によるクールダウン判定を通る技能を使用可能とします。
2. 回復技能があれば、HPが75%以下の対象可能な味方のうち最も負傷した者を回復します。
3. それ以外は45%でランダムな非回復技能と敵目標を選びます。
4. それ以外はランダムな敵を通常攻撃します。

敵は味方リストに自分だけを渡すため、他の敵を回復しません。非回復には強化も含むので、置き換えでは各技能の対象陣営を検証してください。後述の生成敵MP欠落により、有料技能が使えずランダム目標の通常攻撃に偏ります。最初の生存プレイヤー側戦闘員に入力命令が渡り、他の味方は自動です。敵戦術の変更で仲間操作やプレイヤーの識別を暗黙に変えないでください。

生成機構は通常行動後に別処理されます。実行されるのは`round_interval`と`hp_threshold`だけで、受理される`on_hit`、`on_attack`、`passive`は実行されません。HP閾値効果は後の該当ラウンドでも繰り返し、`damage_one`は先頭の敵対目標を選びます。これはGMのライブ判断ではありません。適用前に一回限りと反復を区別してください。

Classicの非回復技能はダメージ中心で、命中に名前付き状態を付けられてもTacticalの支援操作と同等ではありません。宣伝前に本来の強化/弱体/制御と使用ごとのクールダウンが必要です。自動防御/待機も処理側の対応が必要で、現行防御は操作プレイヤーの順番から効くため速い敵は先に動きます。難易度は現在、判断品質ではなく双方の攻撃ダメージを共通処理で変えます。性格調整とは別に扱ってください。

別件として、先頭がKOならサーバーは最初の生存味方に命令を渡しますが、UIのプレイヤー番号はゼロのままです。使用不能な技能IDが通常攻撃に置き換わることもあります。独立して再現/修正し、敵性格と抱き合わせないでください。

### Tacticalのポリシー

現在の`packages/shared/src/features/tactical-combat/ai.ts`は次の動作です。

1. 2マス以内でHP比率が最小かつ60%以下の味方へ、最初の使用可能な回復技能を試します。回復射程まで先に移動はしません。
2. 通常攻撃と使用可能な攻撃技能について、生存敵に対する到達可能な移動先を評価します。
3. 評価式は`1000 * likelyKill + expectedDamage - 0.75 * counterRisk`です。likelyKillは予測ダメージが現HP以上かつ命中率50%以上で、確実な撃破ではありません。
4. ときどき最良の非致死攻撃を別のランダムな合法攻撃に置き換えます。casual/normal/hard/brutalで60%/30%/10%/0%、回復採用率は50%/80%/100%/100%です。
5. 攻撃不能ならマンハッタン距離が最も近い敵へ、その距離が最小の到達可能マスで接近します。盤面全体の最短経路ではなく、障害物で進めないことがあります。

地形は移動とダメージ/命中予測に影響しますが、次のプレイヤーフェーズに受ける危険を一般的に評価しません。強化、弱体、防御、アイテムを意図して選ばず、技能射程も簡略化されています。生成されたAoE説明は完全な空間範囲処理を意味しません。

クラスはFighter、Knight、Rogue、Archer、Mage、Healerです。明示ヒント、回復技能、名前/技能の語、属性攻撃、能力値から推定します。役割ラベルだけで能力は生まれません。

### 性格システムの前提となる不足

以下はソース確認による指摘で、ブラウザーで再現済みという主張ではありません。

| 不足 | 根拠と影響 | 最小の次の作業 |
| --- | --- | --- |
| 生成敵にMPがない | `generatedEnemyToCombatant`がMP/maxMPを省略。生成技能には正の費用があり、両エンジンは欠落をゼロと扱うため使えない | 実際のブループリント復元で再現し、明示資源を保持するか生成敵ルールを文書化。無制限魔法は不可 |
| レベルをHPから推定 | 通常はmaxHP/20の丸め。頑丈さは訓練度ではない | 有界な熟練度ヒントを追加し、正式なルールデータまではレベルを明示的な代替値にする |
| ボスが推測 | Tacticalは2体以上からmaxHP + level\*10 + attackで最強を選ぶ。単体は対象外 | 敵ごとの明示的ボスID。遭遇音楽だけでGM対象は決まらない |
| 生成ボス機構がTacticalへ届かない | Classicは機構propsを受けるがTacticalはリストを使わない | 対応する検証済み操作へ変換し段階/トリガーを保存。非対応を実行済みと語らない |
| 生物分類と性格が実行契約でない | 敵説明は復元で捨てられ、Beast/Monstrosityは型付き分類でない | 全変換/保存境界に明示分類と有界入力を伝える |
| Tacticalの視線と遮蔽は共通(combat C6) | 壁や山はネイティブ戦闘でもルールセット戦闘でも視線を遮り、遮蔽も同じ判定で段階付けする(半遮蔽、4分の3遮蔽)。予測、行動、反撃、範囲、リアクション、脅威表示、AIが`hasLineOfSight`と`coverTier`を使う | すべての呼び出し元で、視線判定と遮蔽判定をそれぞれ1つに保つ |
| AI候補予測は候補タイルを読む | 両AIが攻撃とそのとき受けうる反撃を、攻撃するはずのタイルから予測する。そのため遮蔽(combat C6a-2)を実際の判定どおりに評価する | 予測と解決を1つの`hitChance`に保つ |

共通の変換不足として、攻撃種別を英語名/説明から推定しますが、遭遇本文は他言語でも生成されます。`AoE`/`both`も実際の複数目標効果に残りません。役割推定には明示的な検証済み能力フィールドを使い、翻訳名で回復/攻撃を決めないでください。

前提修正に全戦闘の書き直しを含めないでください。最小の実行証拠を追加し、関係する経路を直して、移動、予測、技能準備、行動処理の既存ヘルパーを再利用します。

## 3. 能力、性格、制御の分離

各敵に必要な問いは別々です。

| 軸 | 意味 | 例 |
| --- | --- | --- |
| 生物分類 | 強制タイプ規則 | BeastはMindless |
| 役割 | 実際の能力構成に適した仕事 | Supporterは使える回復/強化を持つ |
| 性格 | 合法選択肢の優先順位 | Cautiousは危険回避を重視 |
| 熟練度 | 習慣に従う一貫性 | 熟練Reckless Bruiserも危険を冒すが無駄行動は少ない |
| 操作主体 | 誰が行動を選ぶか | 通常敵はエンジン、明示ボスはGM |
| 遭遇目標 | 陣営が達成したいこと | 今はパーティー撃破、将来は防衛/脱出/捕獲 |

まず主性格は1つです。任意の特性積み重ね、人物像ベクトル編集、行動木依存、汎用計画基盤は不要です。共通の合法候補に小さなプロファイル表を適用すれば足ります。

### 能力に基づく役割

既存クラスは形状/能力値プリセットとして残し、実際の能力が根拠になる場合だけ小さな役割対応で補います。

| 役割案 | 能力上の根拠 | 主な仕事 | 適しやすい性格 |
| --- | --- | --- | --- |
| Bruiser | 強い近距離攻撃 | 接近してダメージ交換 | Reckless、Disciplined、Opportunistic |
| Bulwark | 頑丈な近接構成 | 弱い味方付近の有用位置を守る | Protective、Disciplined、Cautious |
| Skirmisher | 機動力と近接火力 | 有利な交戦を選ぶ | Opportunistic、Cautious、Reckless |
| Marksman | 継続的遠隔攻撃、場合によって最小射程 | 有効射撃距離を保つ | Cautious、Disciplined、Opportunistic |
| Spellcaster | 使用可能な攻撃魔法と資源 | 限定技能を浪費せず遠距離圧力 | Cautious、Disciplined、Opportunistic |
| Controller | 使用可能な弱体/制御 | 重要な脅威を弱める | Disciplined、Opportunistic、Cautious |
| Supporter | 使用可能な回復/強化 | 集団の有効性を保つ | Supportive、Protective、Cautious |

これは事前傾向で、禁止ではありません。Cowardly FighterやReckless Spellcasterも可能です。鎧と近接能力を持つClericはBulwarkになれ、回復役は後衛を好めます。クラスの固定観念だけで性格を決めず、一時的なMP枯渇で保存済み役割/性格を変えないでください。元から支援不能な構成にSupportiveを割り当てません。

## 4. 性格一覧

### 初期の8種類

| 性格 | 目標傾向 | 位置と危険 | 技能/資源 | プレイヤーの対処 |
| --- | --- | --- | --- | --- |
| **Mindless** | 第6節の最寄りの生存・到達可能なパーティーメンバー | 最短合法経路。地形利益、危険、隊形を無視 | 単純な合法攻撃。回復選別、集中攻撃、資源最適化なし | 距離、地形、狭路で誘導 |
| **Reckless** | 即時火力と届く圧力。最弱を自動選択しない | 積極接近し反撃/危険位置を許容 | 強い技能を使いやすく、防御はまれ | 深追いと不利な交換を誘う |
| **Cautious** | 反撃被害を抑えて脅かせる相手 | 安全位置、有効射程、防御地形 | 通常攻撃が近い価値なら希少資源を温存。必要なら回復/防御 | 安全空間を圧迫し慎重さを利用 |
| **Opportunistic** | 負傷、露出、弱体化した相手。確実性の高いとどめ | 具体的な好機に一定の危険を許す | 好機を作る/使う技能を評価 | 弱い味方を守り簡単な撃破を防ぐ |
| **Protective** | 指定した弱い味方や近隣集団への脅威 | 支援距離を保ち、合法な遮断位置に立つ | 保護対象の維持を優先。不要時は攻撃 | 集団を分断し複数方向から接近 |
| **Supportive** | 自分の火力より味方HPと有効な強化 | 余計に危険を冒さず支援射程へ | 実際の不足HPを回復し過回復/重複強化を避け、支援価値が低ければ攻撃 | 支援役を圧迫/分断 |
| **Disciplined** | 役割に合う目標と適切な撃破機会 | 火力、安全、位置、資源を均衡。適度に目標を維持 | 極端に偏らない確かな基本 | 役割を崩し不利な判断を迫る |
| **Cowardly** | 安全に届き反撃を招かない目標 | 負傷/局所的劣勢で保身が急増し味方側へ後退 | 自己回復/防御を好み高価な決断を避ける | 退路を断ち遠隔圧力を継続 |

Protectiveに自動の肩代わり、挑発、迎撃、リアクションはありません。占有による位置遮断は可能ですが、それ以上には能力が必要です。Cowardlyは後退/防御できますが、現行Tacticalの`flee`は戦闘全体を終えます。**単体敵の逃走に全体逃走を使わないでください。** 個別撤退/降伏には新しい明示規則が必要です。

健康なCautious Marksmanは良い射撃位置を取り、負傷したCowardly Marksmanは射撃を捨てて生き延びられます。Protectiveは人/場所の保護、Supportiveは支援の実益最大化という違いを出します。

### 独自の行動と証拠が必要な追加候補

| 性格 | 違い | 公開前の前提 |
| --- | --- | --- |
| Vengeful | 多少良い他目標より直近の攻撃者や目撃した味方殺害者を追う | 小さな保存戦闘記憶と目標不在時の合法再選択 |
| Patient | 有用位置で有利射程への侵入を待つ | 有界な待機/交戦規則と進展停止対策 |
| Predatory | 孤立目標を追い、好機に踏み込む | 孤立指標。Beast/MonstrosityのMindlessを上書きしない |
| Fanatical | 儀式、指導者、任務のため安全を捨てる | 進展/失敗条件が見える遭遇目標 |
| Methodical | 即時火力より対応する弱体/攻撃手順を組む | 明示コンボ依存、有界記憶、Disciplinedとの差 |
| Coordinated | 味方の意図で重複攻撃/支援を減らす | 全知ではない有界なチーム意図 |
| Territorial | 場所を守り境界外を追わない | 保存領域/目標と分かる追跡中止 |
| Deceptive | 実在するフェイント、囮、隠密を使う | 知覚/欺瞞機構。叙述だけで効果を作らない |

同じ評価の同義語を増やさないでください。Cruelは独自目標がなければほぼOpportunisticです。Strategicは万能の賢さではなく実際の有界計画用に残します。勇気と知性は同一軸の両端でなくて構いません。

## 5. 割り当て: 役割、経験、人物像、シード付き変化

### 優先順位

1. 明示分類を検証します。Beast/Monstrosityはレベル、人物像、難易度、ボスにかかわらずMindlessです。矛盾するモデルヒントは出所を記録して破棄します。明示作成/インポート済みの確定プロファイルが矛盾すれば分かるエラーで拒否し、保存選択を黙って書き換えません。
2. 再開遭遇の有効な確定プロファイルと、安定IDのある再登場NPCの既存性格を保持します。
3. 他の生物は構成に合う明示プロファイルを尊重します。非対応/矛盾する明示入力はエラー、不在は初期値です。
4. 実能力から役割を決め、曖昧な構成には検証済みヒントを使います。
5. 熟練度、役割事前重み、有界な人物像補正を計算します。
6. シード付き重み抽選で1プロファイルを選び、結果とポリシー版を保存します。

初期の通常抽選にMindlessは含めません。将来は明示したアンデッド/構造体にも使えますが、Beast/Monstrosityへの強制は残します。旧敵の不明分類は`unknown`とし、名前の「beast」を分類宣言と推測しません。

### 熟練度とHP、難易度、道徳の区別

ルールプロファイルの訓練段階や信頼できるNPCシートを優先し、次に検証済み遭遇ヒントを使います。両方ない場合だけ出所付きでレベルに代替します。HP由来レベルを知性の権威的指標にしません。

初期のルール非依存案ではnovice/trained/veteran/masterを`c = 0, 0.35, 0.7, 1`に対応できます。暫定レベル対応は1–2がnovice、3–7がtrained、8–14がveteran、15+がmasterです。卓上ルールではなく調整可能な設計曲線で、特にHP由来なら`level-fallback`を記録します。割り当て版に固定し、将来は正式プロファイル対応へ置き換えます。5e脅威度をキャラクターレベルと同一視せず、V20にも同一尺度を強制しません。

経験は初回の役割に合う性格の確率と、その性格を実行する一貫性の**両方**に影響します。通常AIに隠し技能や待機命令は見せません。GMボスは第16節の広いシート情報を知りますが、どちらも未来の出目/未確定選択は知りません。生存者の傾向は世界設定上の偏りで、全熟練魔法使いが慎重という法則ではありません。

### 具体的な重みモデル

小さな役割/性格表と1つの有界式を使います。次の初期例はプレイテスト対象です。

```text
w[a] = baseRoleWeight[role,a] * exp(1.2*c*roleAffinity[role,a] + 1.5*q*personalityMatch[a])
P[a] = 0.94 * w[a]/sum(w) + 0.06/N
```

- `c`: 能力、0..1。
- `roleAffinity`: 明示した適性、-1..1。複数役割に有効な性格もあります。
- `personalityMatch`: 有界な根拠、-1..1。モデルに自由な数値を作らせません。
- `q`: 既知の人物像への確信度、0..1。不明ならゼロです。
- `N`: 互換性のある性格数。正規化前に非互換を除き、残らなければ検証済みDisciplined/基本動作へ戻して入力問題を記録します。
- 6%の混合は珍しい互換プロファイルにも小さな可能性を残します。強制分類ルールは弱めません。

人物像の根拠がない**支援技能を持つ多用途の魔法使い**の例です。

| 性格 | 基本重み | 役割適性 | 新人確率 | 達人確率 |
| --- | --- | --- | --- | --- |
| Cautious | 4 | 1 | 23.0% | 35.8% |
| Disciplined | 4 | 1 | 23.0% | 35.8% |
| Opportunistic | 3 | 0.5 | 17.4% | 15.2% |
| Supportive | 1 | 0 | 6.4% | 3.5% |
| Protective | 1 | 0 | 6.4% | 3.5% |
| Reckless | 2 | -1 | 11.9% | 2.4% |
| Cowardly | 2 | -0.5 | 11.9% | 3.7% |

丸めで合計が100%にならない場合があります。既知の無謀な性格は高熟練でもRecklessを増やします。名前付きNPCをレベル変更ごとに再抽選しません。これは望む傾向の例で、最終バランスではありません。

### 毎行動のモデル呼び出しを使わない人物像抽出

既存の遭遇生成呼び出しで、既知の人物像を閉じた列挙値のヒント最大3つへ変換し、low/medium/highの確信と有界な出所参照を付けます。忠実、危険志向、保身、思いやり、忍耐などです。数値重みへの対応はエンジンが行い、任意の確率や実行コードをモデルに作らせません。

実際の人物像を使います。「傷のある魔法使い」という外見は慎重さの証拠ではなく、「臆病ではない」はCowardlyを増やしてはいけません。多言語/矛盾説明の回帰用例が必要です。抽出が不在、不正、非対応なら人物像補正なしとし、役割、熟練度、RNGだけで十分です。語の一致だけを意味理解と呼びません。

割り当て説明に必要な受理ヒント/出所を保存し、モデル思考全文は保存しません。NPCの安定IDは既存エンティティ参照から得て、表示名だけに依存しません。無名の繰り返し敵には新遭遇プロファイルを与えられますが、名前付き再登場人物のセッション間一貫性にはIDに紐づく保存が先に必要です。

### 乱数の境界

- 遭遇シード、安定敵ID、割り当て版から専用シードを作り、地形生成/戦闘出目と系列を分離します。
- 候補の列挙/採点や予測表示だけで戦闘RNGを消費しません。
- 確定プロファイルを保存し、更新、再試行、インポート、チェックポイント巻き戻し、同じ戦闘の再開で再抽選しません。
- 新遭遇/シードは編成と性格を変えられます。明示再抽選は新しい遭遇リビジョンにし、現在の戦闘を隠れて変えません。
- Tacticalは今、判断と結果でシード付きカーソルを共有しています。変更は版付きの動作変更で、進行中の旧ポリシーを守るか明示的な検証済み移行を用意します。
- Classicのシードなし処理には、正確な再現を主張する前に別のRNG/保存アダプターが必要です。

## 6. Mindlessの厳密な追跡契約

Beast/Monstrosityへのプロジェクト要件であり、公式卓上ルールや実際の動物の行動を意味しません。

### 目標と経路

1. 生存パーティーと、指定単純攻撃が届く合法位置を調べます。相手が占めるマス自体には止まれません。
2. 歩行は盤面全体で**グリッド歩数**最小の合法経路を探し、順位付けでは地形追加費用を無視します。壁、水、山は通常歩行を遮り、味方通過は現行規則どおりでも占有位置での停止は禁止です。
3. 攻撃位置までの歩数が最小の相手を選びます。同等なら空間的距離、安定ID、座標順で決め、HP、防御、回避、クラス、予測火力は使いません。
4. 実際の移動予算で選択経路を進みます。森は2移動点で、同経路上の最遠の合法な空き位置に止まり、戦術利益のため安い別経路を選びません。
5. 移動後に射程内なら指定単純攻撃、それ以外は待機します。通常攻撃が既定で、作成時に検証済み固有攻撃を指定できます。最大火力技能やAoE密集目標を探しません。
6. 次の行動で更新盤面から再計算します。塞がれたら次の到達可能目標へ、誰にも届かなければ待機します。不正な移動や無限ループは不可です。

意図的に単純な追跡者であって、経路探索の失敗ではありません。U字壁ではマンハッタン距離が一時的に増えても、全盤面探索で迂回を見つけます。

**地形例:** Aは森を3歩、Bは平原を5歩です。Mindlessは費用が高くてもAを選び、森に止まれば防御/回避を得て移動費用も払います。Cautiousは森の防御を意図的に選べますが、Mindlessには偶然の利益です。

飛行/テレポートは各移動契約に従います。飛行は遮断地面や占有マスを越え、通常通行不能な地形にも止まれます。テレポートは途中障害を越えますが着地地形は合法でなければなりません。両方とも占有マスには止まれず、距離は現行平面グリッドのマンハッタン距離で、「どこへでも1回」ではありません。複数行動のテレポート追跡には合法な中継着地点が必要で、全ての合法ジャンプより広い溝の先を近いだけで選びません。地形防御/回避は全移動に有効です。

Mindless専用の微妙に違う通行規則を作らず、既存の移動判定を共通化/再利用します。経路選好は費用を無視できても、実行は通常の合法性と費用に従います。

### 禁止事項とボス優先規則

Mindlessは目標HPによる犠牲者選択、撃破率最適化、遮蔽選択、集中攻撃、味方回復、恐怖による撤退、他クラスの価値による変更を行いません。難易度/熟練度も復活させません。

MindlessボスのGM候補を選択目標と必須追跡に制限し、固有/段階動作も制約を回避できなくします。候補が1つならモデルを呼ばず実行します。知的なBeast/Monstrosityの例外はメンテナー合意を要する意図的な製品規則変更で、実装都合ではありません。

Classicには空間距離がなく最短経路の最近接を正確には実装できません。提案する代替はHP/地形重みなしの保存済みシード付き交戦順で、最初の生存者を狙います。**改訂された非空間実装はこの抽象化を採用しています。** 正確な空間要件は満たさないと明示し、距離とは呼びません。本物の最近接には隊列/位置モデルが必要で、配列順を暗黙に距離にしません。将来の前衛/後衛で実現でき、ここではTacticalの経路規則を標準とします。

## 7. 通常敵の判断

### 処理を再利用し、優先順位を変える

先に合法候補を生成し、役割/性格の重みで採点します。移動、予測、準備状態を再利用し、AIとGM双方に必要な最小の合法性関数だけを加えます。状態変更専用の`performUnitAction`に未検証のモデル入力を渡しません。

候補には次を含めます。

- 通常攻撃と使用可能な攻撃技能。合法な移動後行動も含みます。
- 正しい陣営への回復/強化/弱体と支援射程への移動。
- 有用な攻撃/支援がない場合の防御、待機、目的を持つ移動。

処理が実際に対応する機構だけを含めます。敵アイテムには本物の所持品/収支が先に必要です。採点だけでAoE、召喚、挑発、新リアクション、機会攻撃、遮蔽、逃走を作れません。Tacticalには反撃/防御/待機がありますが、Classicの同等プロファイルには自動防御/待機と本来の強化/弱体が必要です。単なる重み変更ではありません。

期待火力、撃破確率、有効回復/支援、即時反撃危険、次フェーズ危険、役割射程への接近、資源費用を正規化し小さな重み表を掛けます。巨大な共通撃破ボーナスは性格差を消すため、有界なプロファイル別のとどめ価値へ置き換えます。

合法行動を共通尺度で比較し人物像で優先を変える小さな効用評価です。一般原理と判断慣性はDavid「Rez」Grahamの[An Introduction to Utility Theory](https://www.gameaipro.com/GameAIPro/GameAIPro_Chapter09_An_Introduction_to_Utility_Theory.pdf)を参照してください。具体的なプロファイル、式、初期値、統合案はMarinara独自の推奨です。

### 実用上の制約

- 仮の到着位置/地形から予測し、実状態/RNGは変えません。反撃確率は命中、生存、反撃規則と一致させ、50%を確定撃破としません。
- 現在観測できる位置/攻撃で次フェーズ危険を見積もります。未来の乱数や待機中のプレイヤー命令は見ず、深い探索の前に1行動分の有界評価にします。
- 過剰回復を避け、有効量、緊急度、機会費用、MPを考慮します。1HPの傷が常に重要行動に勝つことや、まだ有効な強化の無益な更新を避けます。
- より良い選択が明白でなければ目標/保護対象を維持し、必要最小の記憶を保存します。Mindlessはこの粘着性でなく最寄り規則に従います。
- 支援や撤退の進展がなければ有用な交戦へ寄せ、無限の引き撃ち/防御を防ぎます。ただし時間短縮だけのためCowardlyを自殺突撃させません。
- 全員に同じ事前フェーズ計画を使わせず、順に実行した更新状態で次を評価し、死者攻撃や無駄回復を減らします。
- Protectiveは役割/必要性で生存味方を選び、不正/明白に不適切になるまで保持します。特定ボスの保護は設定ヒントにできても全随伴敵の既定ではありません。
- **選んだ性格の範囲内**で近接する最良候補に小さなシード変化を加えます。全攻撃から一様に選ぶ現行方式を流用して性格を消さないでください。

初期案は固定尺度に正規化し、新人は最良評価との差0.15以内、達人は0.03以内から選び、中間を補間します。難易度の小さな補正は文書化/制限し、性格自体を変えません。閾値はシミュレーション/実遊戯が必要で、実証済みではありません。

## 8. GMが操作するボス

### 識別と責任

遭遇にユニットごとの明示ボス属性を追加します。全集団の最強個体を自動的にGMボスにしません。ordinary、elite、bossの案では、明示ボスでないeliteはエンジン制御です。遭遇音楽区分は別にできます。

GMは性格、遭遇意図、盤面、パーティー技能/資源/アイテム、対応機構から合法行動を選びます。広い知識は予測用で、未確定選択を読むものではありません。第16節が情報/中断契約を定めます。射程、移動、資源、出目、ダメージ、状態、行動予算はエンジンの所有です。ボスがいても通常随伴敵はローカルです。

完成機能は新規ゲームで有効にし、設定済みGM接続を使う**GM directs bosses**(GMがボスを操作)を明確に説明して提供します。応答待ちと通常のプロバイダー費用を伝えます。旧ゲームはユーザーが有効にするまで従来どおりで、遭遇開始時に設定を固定します。オフライン/エンジンのみでも同じプロファイルを使います。別の戦闘スタイル列挙や途中の隠れた制御切替は追加しません。

### 行動の進行管理

プロバイダー呼び出しは純粋な共通エンジンの外、サーバー管理サービスに置きます。

1. 遭遇ID、行動ID、期待リビジョンを持つプレイヤー行動を受け、受理済み状態で検証します。
2. 現行順の次の通常行動/中断へ進みます。宣言と効果を分け、詠唱待ちに反応できるようにし、全ラウンドを実行してから書き戻しません。
3. 待機行動/窓のユニットID、リビジョン、順番カーソル、トリガー/保留行動、ポリシー版、有界候補メニューを保存します。
4. GMに構造化した候補IDまたはパスを求めます。第16節に従い、パーティーシート、ボス意図、対応機構、この窓で許される情報だけを渡します。任意の短い叙述で状態は変えません。
5. 応答、現リビジョン、ユニット、候補所属、現在の合法性を検証し、判断記録と一度の行動適用を原子的に行います。
6. 更新状態から保留行動/参加者を再開します。中断後は再検証し、各予算/効果を規則の境界で一度だけ更新して操作を返します。

候補IDはエンジンが完全定義した行動で、モデルの任意座標ではありません。大盤面の近似候補を、有用な固有技、攻撃目標、支援、防御、移動を残す決定的な有界メニューへ絞ります。8–16種類程度を計測の出発点とし、GMへ渡す前に単一汎用性格で全代替案を落とさないでください。

### 遅延、失敗、再試行

初期上限は独立したボス判断窓ごとに1呼び出しです。随伴敵、単なる選択クリック、有用な選択がない窓では呼びません。通常、予測、行動後の伝説的アクション、反応は別窓なので複数ボスの合計遅延も制限します。初期案は設定可能な約5秒の目標、約10秒の厳格タイムアウトで、実プロバイダーで調整します。計測済み保証ではありません。合計予算を使い切れば決定的な代替/パスを保存します。

タイムアウト、利用不可、不正応答、不正候補は同じ保存済み代替方針を使います。遅い応答がそれを置換したり追加行動したりできません。UIを応答可能に保ち、考え中表示と、遭遇再開なしで受理するローカル代替への取消を提供します。

同じ行動IDは保存結果を返し、更新タブは待機判断に再接続します。複数タブで二度進めず、チャット変更で別遭遇へ返答を接続しません。チェックポイント/分岐は一貫したIDと履歴を復元/作成し、アニメーション再開で外部呼び出しを繰り返しません。

**永続化の前提:** 現行Tacticalはクライアント状態を受けてスナップショットを返すだけで、権威あるサーバー行動台帳がありません。Classicも受理済みラウンドと照合せず全戦闘員/機構を受けます。ブラウザーの候補IDだけでは再試行/同時実行を解決できません。外部ボス判断の公開前に既存保存キュー等で最小のサーバー版/判断ストアを用意します。呼び出し可否はサーバー設定と受理ボスIDが決め、クライアントフラグでは許可しません。`game_engine_state`採用前にturn-game/Experience名前空間を監査します。全ゲーム保存の再設計は不要です。

### ボス機構と分かりやすさ

対応する生成機構だけを構造化操作にします。一回限りの段階移行には安定IDと保存トリガー状態を持たせ、通常行動、段階移行、明示的追加行動を分けます。派手な説明は無料ダメージの許可ではありません。

機構が要求する大型攻撃はUI/ログで事前予告します。GMは受理イベントを演出できても実際の結果を語ります。合法選択が変わっても、学んだ性格と固有能力は再プレイで認識できるようにします。

GMがオフ/利用不能ならエンジン代替と明示し、GMが選んだと偽りません。GMの再現性は保存選択/出目の再生であり、同じシードで新モデル応答が一致する保証ではありません。

## 9. データと統合契約

既存の戦闘経路で渡す小さな共通メタデータ1つを優先します。確定形の例です。

```ts
type ResolvedEnemyTactics = {
  version: 1;
  creatureCategory: "beast" | "monstrosity" | "other" | "unknown";
  role: EnemyRole;
  adjective: EnemyAdjective;
  proficiency: "novice" | "trained" | "veteran" | "master";
};
```

最小分類は必要規則を分けるためで、5e全分類の実装ではありません。別途より豊かな正規分類が入れば保持します。遭遇ランクは性格と別に保存し、操作主体はランクと固定ボス設定から導出して編集可能な真実を二重化しません。

生成ヒントと確定実行データは別契約です。ブループリントに有界な役割/熟練度/人物像ヒントとNPC参照を持たせ、一度だけ確定します。出所は遭遇に一度、判断記憶は必要ポリシーだけ保存し、各ユニット毎行動に生の人物像を複製しません。

Classicでは`sanitizeCombatantForRound`、ラウンド要求スキーマ、`CombatantStats`にも伝播が必要です。現在のスナップショットはラウンド/イニシアチブ/キューを省くため、性格だけではGM再開、実クールダウン、決定的再生に足りません。必要な権威状態を保存し、アニメーションは受理結果を消費して再結算しません。

全境界を追ってください。

```text
known NPC/card data + scene
  -> encounter prompt/schema and generated blueprint
  -> accepted assignment inputs and explicit boss identity
  -> generatedEnemyToCombatant / fallback encounter construction
  -> Classic request OR Tactical start request
  -> resolved units + pinned AI version + encounter identity
  -> action resolution / optional server boss decision
  -> snapshot, checkpoint/branch restore, import/export, post-combat summary
```

外部境界ごとに列挙値と上限を検証します。`.passthrough()`だけでは新AIフィールドの検証になりません。旧保存の省略は維持し、不正な明示値は説明付きで拒否します。新ポリシー版で古いスナップショットを偶然読み替えないでください。

進行中の旧遭遇は旧方針のまま、新戦闘から適用します。分類がない旧スナップショットを後から正確に分類したと装わず、新方針へ入る既知のBeast/MonstrosityはMindlessにします。

生成、手動/代替戦闘、復元、将来の召喚を含む全作成経路が対象です。TypeScriptの型だけに足し、明示プロパティコピーで落とさないでください。

## 10. 楽しさ、自然さ、再プレイ性の確認

**楽しさ:** 習慣を見抜いて利用できる敵にします。Protectiveの護衛とSupportiveの回復役を分断して勝つ方が、万能評価器の偶然の悪手より満足できます。全員を完璧な集中攻撃機械にはしません。

**自然さ:** 敵に合う目標、限られた情報、熟練度を使います。臆病、忠義、攻撃性、訓練は別の性質です。Mindlessは2分類への要望による簡略化で、将来の士気/目標による降伏、領域防衛、逃走が今あると偽りません。

**再プレイ性:** シードで編成/プロファイルを変えつつ、戦闘中と再登場NPCのIDを保ちます。地形、役割、資源、目標でクリティカル以外の変化を作り、難易度を上げてもMindless Beastが突然回復役狩りを始めないようにします。

同じマップの遭遇例です。

- Reckless Bruiserは安全マスを離れ、届く前衛へ圧力を掛けます。
- Protective Bulwarkは突撃に加わらずSupportiveの魔法使い付近を守ります。
- Cautious Marksmanは射線を保ち、露出位置を避けます。
- Mindless Beastは遠い負傷術者を無視し、短い森経路で最寄りの到達可能な味方側ユニットを追います。
- 名前付き人型ボスはGM判断で合法な固有攻撃か退路防衛を選び、随伴敵は独自プロファイルで続けます。

別シードならCowardly BruiserとOpportunistic Marksmanで展開が変わりますが、更新だけでは変わりません。同じ名前付きボスの習慣は物語や明示編集が変えるまで残します。

## 12. 受け入れと検証

既存ランナーの小さな`*.regression.ts`を使い、一時的な`.test.ts`は残しません。重み定数の複写ではなく行動を証明します。

| シナリオ | 必要結果 |
| --- | --- |
| Beast/Monstrosityに矛盾性格、達人、既知人物像、ボス属性 | 生成ヒントはMindlessに確定、矛盾する明示/輸入済みプロファイルは説明付き拒否 |
| 近い健康な盾役と遠い負傷術者 | Mindlessは盾役、Opportunisticは術者も選べる |

| 挑発/迎撃なしのProtective | 位置取りだけで架空の肩代わりなし |
| 負傷Cowardly | 後退/防御できても全体逃走しない |

| 2体が負傷者を狙い先行敵が倒す | 次は更新状態を評価し死者攻撃/重複予約回復なし |

## 13. 現在の通常AIの実装境界

実装済みはMindless、Reckless、Cautious、Opportunistic、Protective、Supportive、Disciplined、Cowardly、**Patient、Methodical、Coordinated**です。以下の他性格はアイデアで、隠れた実行設定ではありません。

共通`features/combat-ai.ts`は保存役割、性格、訓練、シードを制御から分けます。新戦闘は割り当てを保存し、旧復元でプロファイルがなければ従来方針です。仲間の操作主体変更で再抽選しません。有限MP、明示技能種別/費用を伝え、敵MP欠落時は能力未設定の味方と同じ暫定`20 + 3 × level`、明示ゼロは保持します。汎用代替であり卓上資源ルールではありません。

v1は第5節の式より小さく、互換性格に正の重み、役割に合うものに訓練依存ボーナス、任意の閉じた人物像ヒントに有界優先を加えます。分類はMindlessを強制し、他分類でも明示Mindlessヒントを尊重します。既存生成呼び出しが両言語のヒントを出し、エンジンは本文の人物像を解析しません。他の性格ヒントは保証でなく傾向で、否定/多言語の理解品質は実プロバイダー評価が必要です。完全な出所、再登場NPCのID付き性格は後続です。ヒントなしのHP由来レベルは弱い訓練代理のままです。

各モードは実行可能な通常攻撃、技能、防御を列挙して火力、とどめ、有効回復、支援、費用、戦術を評価します。通常行動のモデル呼び出しは増やさず、持たない能力、無限MP、追加行動、未実装地形は与えません。

- **Classic:** 空間評価なし。MindlessはHP非依存の安定シード順で生存敵を選びます。支援は正しい味方範囲、強化/弱体は本物の名前付き防御修正を使います。新プロファイルは使用ごとの冷却を持ち、手動仲間は自分の順番に攻撃/技能/防御を予約します。所持品/物語操作はリーダーのみ、他仲間は従来どおりAI既定です。命令は元リーダーKO時も実行者を識別します。
- **Tactical:** 合法な攻撃/支援到達先を評価します。Mindlessは最少歩数と実費、飛行/転移は固有制限を守ります。支援前移動が可能で、新反撃予測は到着位置を使います。公開状態の保守的な到達推定で危険を評価しますが、完全な次行動経路探索ではありません。壁や山はすべての攻撃で視線を遮ります(combat C6)。
- **Patient:** 不利な交戦より有界の防御待機を好みます。Classicは架空移動ではなく近い冷却完了を待ち、有効行動があれば永遠に待てません。
- **Methodical:** 対応する防御低下を準備し、目標を維持して有用な状態で攻撃します。架空コンボ木/未来出目探索はありません。
- **Coordinated:** 味方の記録目標と有用な弱体を受理行動ごとに再評価します。全知の計画や未提出命令予約はありません。
- **仲間:** 戦闘内にローカライズされた各人のPlayer/AI選択があり、現リーダーは手動です。TacticalのAIは残りの手動命令後またはEnd Turn時に行動し、それまでは手動変更できます。制御、プロファイル、記憶は保存されます。
- **Classic永続化:** 受理ラウンド結果と次番号を演出前に既存スナップショットコールバックへ送り、使用ごとの冷却も保存します。出目は従来の乱数で、厳密再生やサーバー冪等台帳ではありません。同時タブ保証は後続ボス基盤に属します。

初段階はボスプロバイダー/反応前で止まり、その後の実装は第16節に記録します。個別逃走、挑発、豊富な目標、ルール別順番、完全資源正規化、再登場NPC登録は未完です。元設計の残項目を公開済みと扱わず、デスクトップ合成測定を実モバイル校正と呼びません。

## 14. クラスで使い方が異なる追加性格

可視性格1つと能力由来の役割を保ちます。「賢い」の同義語ではなく別の優先順位で、珍しくても機械的に有効な組合せを許します。

| 性格 | Fighter / Knight | Rogue / Archer | Mage / Healer | 違いと前提 |
| --- | --- | --- | --- | --- |
| **Frugal** | 限定技前に通常攻撃 | 特殊弾/瞬間火力を重要目標用に温存 | 効率的魔法、大きなHP不足に高価な回復 | 安全でも節約しCautiousと異なる。実有限資源が必要 |
| **Relentless** | 選んだ敵を圧迫し続ける | 同一標的を追跡/射撃 | 同一脅威への対応する火力/制御を継続 | Recklessな危険志向でなく目標固執。保存目標と無効/停滞時解除 |
| **Disruptive** | 実際の武装解除、中断、行動阻害 | 露出術者の対応する詠唱を止め弱体化 | 有用な解除、沈黙、浄化、制御 | 火力より重要行動阻止。名前だけの偽沈黙は不可 |
| **Vengeful** | 自分を傷つけた敵や保護対象の殺害者へ報復 | 直近攻撃者の合法な隙を探す | 攻撃者を呪うかその標的を守る | 最弱狙いでなくイベント由来の恨み。有界な攻撃/味方敗北記憶 |
| **Adaptive** | 観測した耐性/失敗後に変更 | 無効な攻撃を反復しない | 結果から属性/支援計画を変更 | 公開証拠だけ。有界観測履歴と隠し耐性表の禁止 |
| **Opportunistic**(実装済み) | 長い決闘より安全なとどめ | 負傷/露出を利用 | 実在する好機を魔法で確保 | 既存基準。「Cruel」として同じ評価を追加しない |
| **Resolute** | 低HPでも役割を継続 | 圧迫下で有用な射撃位置を維持 | 重要回復/対応詠唱を完了 | Recklessの攻勢ではなく低HPの冷静さ。意図維持と緊急解除 |
| **Territorial** | 指定門/区域を守る | 決めた進入路を監視し域外を追わない | 防衛域内の味方を支援 | Tacticalは実目標/境界、Classicは名前付き目標で架空座標なし |
| **Zealous** | 指定指導者/理念を生存より優先 | 目標の脅威に希少火力を使う | 自分を危険にさらして任務を支援 | 汎用Supportiveでなく目的への忠義。目標/ランク情報が必要 |
| **Deceptive** | 対応フェイント/構え | 実隠密、囮、誤誘導 | 対応する幻影/誘引 | 読み取れる対抗策と知覚/欺瞞機構。叙述だけでは無効 |
| **Merciful** | 対応する非致死決着 | 降伏可能なら殺さず無力化 | 拘束/制御して降伏を受理 | 非致死/降伏ルールが必要。敗者攻撃や架空効果なし |
| **Selective** | 必要時だけ頑丈な守り手を召喚 | 好機に追跡者/遠隔役を呼ぶ | 見える脅威に合う属性/支援召喚 | 将来の召喚編成方針で一般火力優先ではない。召喚収支が必要 |

現在の11種類の次は**Frugal、Relentless、Disruptive、Vengeful**が有力です。前2つは小さな保存変更、Disruptiveは実阻害/解除、Vengefulはイベント記憶が必要です。Adaptive/Territorialは再プレイ価値と前提が大きく、Resolute/Zealousは公開語彙を増やす前に重複を試します。

要望された3つもクラスごとに変化します。

| 性格 | Bruiser / Bulwark | Skirmisher / Marksman | Spellcaster / Supporter |
| --- | --- | --- | --- |
| Patient | 不利交換が改善するまで構え、Tacticalの重要接近路を保持 | 弱い射撃を強行せず合法で有効な射程を待つ | 近い冷却完了を待つ/無駄回復を避ける。存在しないMP回復は待たない |
| Methodical | 実弱体技後に同じ敵を攻撃 | 大火力の前に対応する弱点を作る | 弱体から火力、または対応防御手順。まだ有用な効果を重ねない |
| Coordinated | 味方の現目標を圧迫/準備支援 | チームが脅かす敵にとどめ | 重複しない支援/活用できる弱体を行動ごとに再評価 |

これは調整目標です。最初の実装は汎用防御強化/弱体を使い、豊かなクラス別コンボには対応能力と回帰例が必要です。

## 15. Summoningの設計拡張

最初はグリッドなしです。召喚体は安定遭遇ID、所有者、陣営、プロファイル、操作主体、寿命、資源費用、明示行動予算を持つ本物の戦闘員です。クラスが能力、性格がClassic同様に優先を変えます。

召喚者の**何を召喚するか**と召喚体の**戦闘方針**を分けます。Patientは後の脅威へ枠を温存し、Protective Knightは対応動作で保護、Methodical Mageは弱体準備、Coordinated回復役は重複回復を避けます。味方のBeast/Monstrosity召喚もMindlessです。

命令が所有者行動を使うか、即時/次ラウンドか、順番共有か、命令なしの動作はルールが決めます。汎用案は召喚で所有者の普通行動を使い、新体の初行動は次ラウンド、明示操作可能でなければAIです。同体の解除/再召喚で新しい普通行動を与えず、大量召喚前に個体上限と毎ラウンド一行動の安定収支を実装します。

所有者KO、魅了/陣営変更、解除、寿命、パーティー敗北、遭遇終了ごとに後始末規則が必要です。所有者/残り時間を更新/輸入で保ち、敗れた召喚をアイテムや永久仲間にしません。魔法/MPは受理作成で一度払い、固定ボス修正の資格を超えて伝説的窓を増やしません。

## 16. GMボス、伝説的アクション、リアクション

### 実装済み汎用Engineアダプター

ウィザードの新規ゲームはサーバー主導戦闘を有効にします。**GM directs bosses**がプロバイダー利用を制御し、通常敵/AI仲間はローカルのままです。`combatDirector`のない旧ゲームは旧処理です。遭遇でGM、難易度、シード、地形、能力を固定し、途中設定で上書きしません。生成器は`boss`を明示し、高HPや表示だけでは追加行動を与えません。単独ボスにも対応します。

`combat-director.routes.ts`は既存ゲーム状態ストアの`experience:marinara-engine.combat`に、遭遇開始メッセージを基準とするバージョン付きサーバースナップショットを保存します。イニシアチブ位置、保留効果スタック、選択肢、リアクション/伝説的行動予算、資源、受理リクエストID、最近のイベントを含みます。命令には遭遇ID、ストレージインスタンスID、リビジョンを付け、重複/古い送信には受理済み状態を返します。アイテム消費と戦闘保存は同じトランザクションです。応答も保存行の識別子、リビジョン、窓と照合し、遅延応答がフォールバック、チェックポイント復元、ブランチを越えないようにします。

- **Classic:** 各イニシアチブ枠で手動キャラクター/ボスの判断を待ちます。一体ずつ解決し、既存のラウンド終了機構/状態更新を一度実行します。旧ゲームは従来のラウンド一括入力です。
- **Tactical:** トークン確認/選択は無料です。**Begin [name]'s turn**(ターン開始)で行動開始を確定し、予測窓を開きます。移動だけでは追加行動開始/伝説的窓を作りません。AI仲間/敵はフェーズ構造を維持します。受理した地形概要、遭遇シード、設定サイズが正で、新遭遇では古いキャンペーンシード設定を無視します。
- **ボス:** 通常は伝説的ポイントを三つ設定し、追加行動は必ず正の費用を持ちます。ボスの通常行動開始時に回復します。予測窓と行動後窓で共有し、追加行動/リアクションから連鎖窓は生まれません。生成器が合法な攻撃/防御/移動とスキル費用を設定します。Mindlessは追跡制約を守り、選択肢が一つならローカル実行です。
- **プロバイダー:** 設定済みGMツール接続を使い、なければチャット接続です。両陣営のスキル、資源、アイテム数、状態、プロファイル、位置、受理イベントを渡します。非公開保留命令、乱数状態、入力中/ホバー中の選択は渡しません。GMは合法候補IDを一つ返し、状態を書き換えません。既存のデバッグ機能でプロンプト/結果を記録します。判断は十秒でタイムアウトし、現在の上限はラウンド全体で十二呼び出しです。通常行動はローカルAIへ切り替え、任意の伝説的窓はパスします。UIは代替実行を明示し、GM待機中にもローカルへの切替を提供します。固定の初期制限であり、設定可能な遅延保証ではありません。
- **リアクション:** 明示的な`counterspell`/`guard`スキルに発動窓があります。手動キャラクターには能力/対象/費用と**Pass**(パス)を表示し、ローカルAIは脅威/希少性を評価、GMボスは同じプロバイダー契約を使います。一体につきリアクション一回、行動開始時に回復し、明示クールダウンも適用します。Counterspellも呪文として打ち消せます。安定した順序と保存親スタックで、遭遇上限の四十体に解決を制限します。パスは無消費です。
- **費用:** 宣言スキルのMPか正確なレベルのスロット一つをリアクション前に確保/消費し、解決時に二重請求しません。汎用アダプターでは呪文/Counterspellが失敗しても消費します。リアクション回数も使い、伝説的スキルは設定済みスキル費用と伝説的ポイントの両方を払います。スロットは任意の明示能力データで、クラス/能力名から推測しません。高レベル発動や版固有の返還は未実装です。
- **汎用効果:** Counterspellのシード付き成功率は`clamp(65% + 3% × level difference, 20%, 95%)`で、保留効果だけを取り消します。Guardは対象攻撃に対して味方一体へ既存防御軽減を一時適用します。Tacticalのリアクションは、通常攻撃と同じく、設定射程と共通の射線(combat C6)を確認します。明示`areaRadius`/`friendlyFire`でTactical範囲攻撃を有効にし、Classicの`targetScope: all-enemies`は一回分の費用で敵全体へ適用します。意図的な汎用規則であり、5eのどちらの版のCounterspellでもありません。
- **操作:** 既存戦闘画面が正規受理状態、リアクション/伝説的予算、フォーカス可能なキーボード対応選択パネルを表示します。Tacticalの所持品は無限の仮ポーションではなく対応実アイテムです。再読み込みで保留判断を復元します。復元前リセットの修正により、React開発時の再マウントでも遭遇基準/機構を保持します。戦闘要約に資源合計も含みます。

**現時点の制限:** 正規行動/巻戻し契約のない自由記述**Special**やその場の再戦はdirectorにありません。旧戦闘には残ります。復元には物語/チェックポイント操作を使います。GM候補は通常/伝説的とも十六個までで、移動先候補も少数です。Guardは被ダメージ軽減で、移動迎撃/機会攻撃ではありません。Tacticalの既存反撃は自動交換のままです。Classicは従来の乱数ダイス/スクリプト機構を維持し、Tacticalへその機構は追加しません。完全な卓上アダプター、復活、召喚所有権、汎用集中、高レベル発動、継続NPCプロファイル台帳はありません。シート全体の正規化/遭遇間資源永続化はルールセット側の課題です。実プロバイダー品質/実機進行速度の評価も必要です。

### 受理済み設計要件

**受理済み:** 明示ボスの伝説的行動を5eルールセットと独立に提供します。GMはパーティーの戦闘能力/資源を知り、通常行動前に妥当な予測で介入できます。AIユニットは任意リアクションを評価し、資源温存のため見送れます。通常ターン方針とは別に、最初の汎用Engine実装が入りました。

### GMの認識と予測

各メンバーのスキル/呪文、合法射程/対応範囲、現在/最大HPとMP/呪文ポイント、レベル別スロット、クールダウン、状態、装備、使用可能アイテム数/残回数をリビジョン付きで渡します。共有所持品の所有権/アクセス、適用可能な位置、召喚体、最近の受理行動、今から行動するユニットも含めます。欠損は不明であり、ゼロ/無制限ではありません。モデル要約ではなく受理シート/所持品を参照します。ボスが読む権限は、味方アイテムの使用/削除権限ではありません。

GMは広い遭遇知識で脅威を予測できますが、ボスの性格/熟練度を守ります。通常ローカルAIの情報境界は変更しません。未来の乱数、私的下書き、ホバー中の技/対象、宣言前の他者保留命令は渡しません。呪文宣言時もルールで許された発動情報だけを渡します。呪文一覧を知っていても次の呪文が確定したわけではありません。サーバーは完全状態で検証しつつ、操作主体向け文脈を制限できます。

**Fireball例:** 選択中のMageにFireball、十分な資源、味方を巻き込まずボスを脅かす合法範囲があるとします。GMは発動の可能性が高いと推測し、伝説的ポイントで合法な移動、防護、圧力行動を選べます。予測は外れ得ます。単体呪文/別行動が良い理由も考慮します。存在しない回避、沈黙、無料移動は追加しません。実際の範囲、味方への誤射、視認規則を使います。元の単体近似ではこの空間予測は不可能でしたが、directorは明示範囲攻撃に対応しました。Classic/Summoningでは架空のグリッド距離ではなく実際の非空間対象群/脅威を使います。

### 三種類のタイミング窓

参照となる[2014年の伝説的アクション規則](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/monsters)は他のクリーチャーのターン後に使い、ボス自身のターンで回復します。選択されたMageの行動**前**の予測介入はMarinara独自拡張で、標準5eタイミングではありません。遭遇時に固定する明示ボス修正としてルールセットと独立に提供します。忠実な5eプロファイルは、このハウスルールを有効にしない限り標準タイミングです。[2024年モンスター規則](https://www.dndbeyond.com/sources/dnd/br-2024/how-to-use-a-monster)と暗黙に混ぜません。

| 窓 | 発動と取得できる情報 | 予算と続行 |
| --- | --- | --- |
| 予測伝説的行動 | 他ユニットの行動開始。GMは本人/シート/現在状態を知るが未確定行動は知らない | 既存予算を払い、本人が行動を選択/再検証 |
| 発動リアクション | 呪文開始など対応イベント。許された発動情報だけ公開 | リアクション回数とMP/スロット/使用回数を消費し、規則に従い保留行動を続行/取消 |
| 行動後伝説的行動 | 他ユニットの通常行動終了 | 同じ伝説的予算を払い、次の通常行動へ |

Tacticalでは確認/選択と**行動開始の確定**を区別します。最初の確定で移動/行動前の予測窓を一回開きます。受理後の選択変更、メニュー取消、再読み込み、入力方式変更で再度開いたり、別ユニットへ切り替えて判断を稼いだりできません。確認だけなら無料です。確定を見える形にし、実際の行動不能効果がなければ割込み後も通常行動を残します。クリックごとにボスが殴るより短い説明を用意します。

現在のClassicはラウンド全体の命令を集めてから解決します。入力時の選択は実際の行動開始ではありません。将来のresolverはイニシアチブ枠で停止し、保留命令を漏らさず本人を公開、予測介入後に命令を検証/宣言します。介入で違法になったら発動前に手動再選択/AI再評価します。各メニューでGMを呼んだり、未来の枠を先行実行したりしません。AI仲間/将来の召喚体も同じライフサイクルです。

汎用修正の既定値案:

- 明示ボス識別と小さい合法伝説的メニューを設定し、最大HPからGM特権を推測しません。
- 見える予算3ポイント、費用1–3、通常行動開始時の回復から始めます。初期予算/奇襲/行動不能方針を遭遇開始時に固定します。Marinaraの調整案であり、既刊モンスターの複製要件ではありません。
- 対象となる他者行動一回ごとに、ボスごとに予測一回/行動後一回まで、同じ有限予算を使います。ポイントを増やさず予測を可能にし、パスでも窓を閉じます。次の行動開始前に前の行動後窓を解決します。
- Tacticalの行動後窓は移動+行動かWaitの後です。移動クリック、各打撃、反撃、アニメーションフレーム、プレイヤーフェーズ全体の後ではありません。Classicでは解決済みイニシアチブ枠の後です。End Turnは対象となる未行動枠を各一度だけ閉じ、召喚体は固定資格規則に従います。
- `pass`と予算内の合法候補だけを提供します。伝説的行動は新しい伝説的窓や速度倍化を与えません。その呪文へのCounterspellは選択アダプターが対応する場合だけで、予算は別です。
- 判断要求/受理の前にボスの生存/行動可否、対象合法性、勝敗を再確認します。倒れたボスは遅延応答で消費できません。伝説的選択にもMindlessの対象/追跡制約を適用します。
- 通常行動、リアクション、伝説的行動、巣/フェーズイベントを別予算/発動として扱います。説明文で新ダメージや無料行動を作りません。
- 通常増援はローカルAIです。意味ある選択のあるボス窓だけGMを呼び、第8節のGM接続、デバッグ、保存代替結果、合計遅延上限を再利用します。

### Counterspellと任意リアクション

**評価は自動、消費は選択的。** Counterspell持ちは毎呪文を打ち消しません。発動時に対応リアクションか`pass`を選びます。AI仲間/通常敵は能力、性格、熟練、現在資源、阻止価値を使いローカル判断します。GMボスも同じ合法窓を使います。プレイヤーには費用付きReact/Passを示し、能力を持つだけで希少スロットを勝手に使いません。必須受動効果は独自規則で処理し、任意リアクションと偽りません。

防げる被害/制御、味方敗北回避、敵の重要回復/準備の阻止、成功見込み、資源と次回回復までのリアクション消費の機会費用を評価します。許可規則なら攻撃以外の回復/補助呪文も対象です。未来の乱数や私的選択は読みません。無害な呪文へ高価な対抗をするよりパスが良く、全滅回避には最後のスロットが値する場合があります。プレイヤーの明示的な厳格上限がなければ、温存希望は柔軟な優先度です。

| 方針/能力 | リアクション優先例 |
| --- | --- |
| Protective Knight/Mage | 対応する実能力がある場合だけ、味方を脅かす打撃を迎撃/致死呪文を打ち消す |
| Cautious/Patient Mage | 弱い呪文はパスし、重大脅威へ回数/希少資源を残す |
| Methodical Mage | 計画を壊す対応可能な解除、回復、制御を阻止 |
| Coordinated支援術者 | 他者の反応後に再評価し、既に取消済みの効果に二重消費しない |
| Reckless術者 | 明確な切迫脅威には惜しまず使うが、消費/範囲/合法性は守る |
| Frugal術者(性格案) | 十分安い対応かパスを選び、最後の枠を将来の回復/火力需要と比較 |

翻訳された「Counterspell」という語ではなく能力IDと明示発動/効果メタデータを使います。発動条件、タイミング、対象/視認要件、資源費用、リアクション費用/回復、解決処理が必要です。MP、呪文ポイント、スロットを分けます。Counterspellは詠唱開始後/効果前に発動し、Mage選択や呪文メニュー表示だけでは不十分です。[2014 Counterspell](https://www.dndbeyond.com/spells/2051-counterspell)と[2024 Counterspell](https://www.dndbeyond.com/spells/2619072-counterspell)は成功/資源結果が異なり、アダプターで明記します。Traditionalも偶然の混合ではなく固有の割込み式/費用が必要です。

確定前に発動、生存/行動可否、視認/射程、対象、残資源を再検証します。実装規則の返還以外は、対抗失敗でも選択リアクション費用を一度払います。元呪文の費用/行動消費は術者側のルールに従い、打消し側とは別です。パスはどちらも消費せず、アニメーション取消だけで返還しません。Traditional案は一体一回、明示遭遇条件がなければ初期利用可、通常行動開始時に回復です。他アダプターは量/回復境界を定め、割込み/速度追撃で暗黙回復しません。既存Tactical交換反撃は自動的に呪文リアクションにはせず、ルールの明示対応付けまで現状を保ちます。

### 割込み解決と永続化

[PR #6110](https://github.com/Pasta-Devs/Marinara-Engine/pull/6110)は、元の試行行動を残す、受理割込みを表示する、後続文脈を即更新する、復元/再試行が後の変更を上書きしない、という先例です。Roleplay実装は検証済みの文字通りの句で文章を切りますが、そのパーサーは戦闘タイミング/資源エンジンではありません。永続化/可視性の原則を再利用し、ダメージ成立を文章切断で判定しません。

通常行動を保存宣言、保留効果、解決結果で表します。提案順は、行動開始/予算回復→任意予測介入→合法宣言/資源確定→対応リアクション窓→残効果→行動終了→行動後伝説的窓です。Counterspellは保留効果を取消し、受理済みダメージを巻き戻しません。応答で状態が変わったら残行動の対象、射程、行動不能を再検証します。詠唱前の無効命令は無消費で再選択でき、開始後の取消/返還は選択規則に従います。ログ/GM描写は受理イベントを述べ、未実行の続きは事実にしません。

複数反応者は規則定義の安定優先順を使い、各応答後に合法性を再確認します。CounterspellへのCounterspellなどは明示ルール能力と有限の保留スタックでだけ対応します。各項目は親/発動IDを持ち、一体が同じ発動に応答できるのは残回数がある場合の一度だけです。尽きた/取消/解決済み発動は閉じます。無限再帰、パス再質問、二重支払い、伝説的行動の自己連鎖を認めません。限定初期アダプターは未対応連鎖を明示し、完全5eを名乗りません。

最小保存契約は、遭遇ID、リビジョン、行動ID/位置、確定ユニット、窓種/ID、発動イベント/保留行動/親ID、操作文脈/候補リビジョン、対象/解決済み反応者順、両予算、確保/確定/返還資源差分、受理選択/パス、解決状態、プロバイダー要求/代替結果、残効果です。判断/費用/結果を原子的に受理し、遅延/重複応答で再消費しません。復元は保留窓を再開/受理結果を再生し、ブランチ/巻戻しは文章だけでなく台帳全体を隔離します。文章だけのRestoreで受理リアクションを返還しません。後述のサーバー台帳が初期実装を担い、第8節は長期契約を残します。
