# Peek Prompt: AIが受け取った内容を確認する

Peek Promptは、Marinara Engineが返信を得るためにAIモデルへ送った文章そのものを表示します。送信前のプロンプトをその場でプレビューすることもできます。このガイドでは、ビューアーに何が表示されるのか、どう開くのか、**Stored guidance**(保存された指示)の読み方、そして返信の不具合を調べる手順を説明します。

プロンプトとは、Marinaraが組み立ててモデルに送る指示とチャット履歴のまとまりです。モデルはそのプロンプトを読んで返信を書きます。Peek Promptを使うと組み立て終わったあとのプロンプトをそのまま確認できるので、返信の理由がわからないままになることはありません。

## Peek Promptに表示される内容

Peek Promptを開くと、**Assembled Prompt**(組み立て済みプロンプト)というウィンドウが表示されます。中身は3つの部分に分かれています。

タイトルの隣、いちばん上にはソースを示すバッジがあります。どの版のプロンプトを見ているかがここでわかります:

- **Exact Text Model Request**: モデルに実際に送られたリクエストそのものです。
- **Live Preview**: いま新しく組み立てたプレビューです。
- **Raw Messages**: メッセージの生のリストです。
- **Prompt Preview**: 一般的なプレビューです。
- **Decision test preview**: 明示的に実行したDecisionテストの回答で組み立てたプロンプトです。チャットモデルには送信されていません。

バッジの下は生成情報のパネルです。プロバイダー名とモデル名、推定トークン数、そして返信が完了したあとは実際のプロンプトのトークン数を表示します。トークンとは、モデルが単語の代わりに数える文章の小さなかたまりです。このパネルには、使われた値も小さなタグとして並びます。**Temperature**、**Max Output Tokens**、**Thinking**、**Reasoning**、**Verbosity**、**Service Tier**、**Assistant Prefill**などです。**Top P**、**Top K**、**Min P**といったサンプリングの値がここに出ることもあります。返信を書くはずだった接続が失敗し、代わりにフォールバックの接続が返信を書いた場合は、失敗した接続、そのモデル、「key rejected」や「rate limited」のような短い理由もパネルに表示されます。

ウィンドウの残りはプロンプト本体で、折りたためるセクションに分かれています。各セクションにはラベルと、そのセクションのおおまかなトークン数の見積もりが付きます。チャットのメッセージは**Chat History**という1つのセクションにまとまります。保存された実際のリクエストでは、プロバイダーが複数のチャットのターンを1つのブロックにまとめている場合があります。各ブロックを展開すると、モデルから見えるテキストをすべて確認できます。セクションの見出しをクリックすると開閉します。

プロンプト全体をほかの場所で使いたいときは、ウィンドウ上部の閉じるボタンの隣にあるコピーボタンをクリックします。開いていないセクションも含め、すべてのセクションとチャットのメッセージが、送られた順にプレーンテキストとしてコピーされます。各メッセージは、`[system]`、`[user]`、`[assistant]`のように役割を示す行で始まります。保存された実際のリクエストの場合は、送られたとおりのリクエストがコピーされます。コピーしても、モデルに何かが送られたり、プロンプトが変わったりすることはありません。

## Peek Promptの開き方

ビューアーを開く方法は2つあります。

1つ目はメッセージのアクションバーです。手順は次のとおりです:

1. チャットのいちばん新しいAIメッセージにマウスを重ねます。
2. **Peek prompt**(プロンプトを見る)の操作を探します。アイコンは虫眼鏡です。
3. クリックすると、**Assembled Prompt**ウィンドウが開きます。

**Peek prompt**の操作は、チャットの最後のAIメッセージにだけ表示されます。それより前のメッセージには表示されません。

2つ目は入力欄に打ち込むショートカットです。AIの返信がまだ1つもない状態でも使えるので、送信前にプロンプトを確認できます。手順は次のとおりです:

1. メッセージの入力欄をクリックします。
2. 次のテキストをそのまま入力します:

```
{{prompt}}
```

3. Enterを押すか、Sendをクリックします。

メッセージは送信されず、Marinaraが入力欄を空にしてPeek Promptのビューアーを開きます。`{{prompt_preview}}`と`{{preview_prompt}}`のショートカットも同じ働きをします。

## Stored guidanceの読み方

ガイド付き生成を使うと、キャラクターの外側からの指示で返信の方向を決められます。指示を保存して作られたメッセージには、**Stored guidance**という別の操作が付きます。アイコンは小さな巻物です。この操作は`/impersonate`コマンドで作られたメッセージにも表示されます。

**Stored guidance**をクリックすると、そのメッセージに使われた指示を表示するウィンドウが開きます。ガイド付き生成のメッセージでは、指示がどこから来たのかがラベルでわかります:

- **/guided**: `/guided`スラッシュコマンドを使った場合です。
- **Guided regenerate**: 指示を入力して再生成した場合です。
- **Game start**: Game Modeの設定から渡された指示です。

**Copy /guided**ボタンは、**/guided**と**Guided regenerate**の指示にだけ表示されます。押すと、指示が`/guided`コマンドの形でコピーされます。あとから貼り付ければ、同じ方向づけをもう一度使えます。**Game start**の指示ではこのボタンは表示されません。

Impersonateで作られたメッセージの場合、ウィンドウには1つの指示ではなくimpersonateの詳細が表示されます。ガイド付き生成とImpersonateの全体の流れは、下にリンクしたガイドを参照してください。

## Peek Promptで返信の原因を調べる

思ったとおりにならなかった返信を理解するには、Peek Promptがいちばん役立ちます。キャラクターが設定を忘れる、ルールを無視する、らしくない振る舞いをするときに使ってください。

**Assembled Prompt**ウィンドウを開いて、次の点を確認します:

- 情報が抜けていないかを見ます。ロアブックのエントリー、記憶、ペルソナの内容がどのセクションにも見当たらなければ、モデルはそれを一度も見ていません。
- パラメーターのタグを確認します。**Temperature**が高すぎると返信がばらつき、**Max Output Tokens**が小さすぎると返信が途中で切れます。
- **Chat History**セクションを展開します。必要なメッセージがそろっているか、順序が正しいかを確かめます。
- 返信のあとに表示される実際のトークン数を読みます。プロンプトが大きすぎると、古いメッセージがモデルの上限からあふれます。

モデルが実際に受け取った内容がわかれば、原因を直せます。キャラクターカードを編集する、ロアブックのエントリーを調整する、生成パラメーターの値を変えるといった対処が考えられます。

## Decision文のテスト

Peek Promptの**Decision diagnostics**(Decision診断)を開くと、現在のチャットのプロンプト文とロアブックの判断を確認できます。パネルを開いたり**Preview inputs**(入力のプレビュー)を選んだりすると、Decisionモデルへの問い合わせやローカルモデルの起動をせずにリクエスト本文を準備します。**Prepared request bodies**(準備したリクエスト本文)を展開すると、最近のメッセージ、展開済みの文、選択肢、モデル固有のリクエスト形式が見られます。先行する判断に回答が得られた後で初めて、別のロアブック文に到達できる場合もあります。

**Test decisions**(判断をテスト)を選ぶと、対象になる質問を選択したDecisionモデルへ送ります。実際の判断リクエストなので、ホスト型モデルでは料金がかかる場合があります。チャットの返信生成、エージェントの実行、ゲーム状態の変更は行わず、テストの回答やタイマーをチャットに保存しません。

明示的なテストは、通常の返信前の判断が延期される場合でも、ローカルの推論モデルを待つことができます。通常の返信に対する設定は変わりません。入力のプレビューだけでは引き続きモデルにリクエストを送りません。

各結果には、利用できる場合はスコア、はい/いいえの文に使ったしきい値、最終的な回答が表示されます。はい/いいえの単語だけを返すモデルにはその旨を表示し、その回答を確率として扱いません。Choiceの結果には選ばれた選択肢が表示されます。保持中、延期、上限超過、利用不可、失敗にはそれぞれ説明があり、回答がない状態を低いスコアと混同せずに済みます。

テスト後、下のプロンプトにはテストの回答が使われます。**Show original prompt**(元のプロンプトを表示)で最初に開いた内容に戻り、**Show tested prompt**(テストしたプロンプトを表示)でテスト版に切り替えられます。**Requests sent and results**(送信したリクエストと結果)には、実際の判断リクエスト本文と返された結果が表示されます。認証ヘッダーは含まれません。

過去の返信からPeek Promptを開いても、テストでは現在のチャットと現在の設定を使います。元の判断リクエストは再現しません。対象はプロンプト文とロアブックの判断で、エージェントの起動判定や返信後の判断は実行しません。通常のPeek Promptは、明示的に**Test decisions**を選ぶまで受動的なままです。

Advanced Memoryで**Use Decision model**(Decisionモデルを使用)をオンにすると、パネルには**Advanced Memory activity**(Advanced Memoryの動作記録)も表示されます。保存済みレポートには、最新の記憶の呼び出しとシーン終了チェックについて、モデル、時間、スコア、選択結果、フォールバックの状態が記録されます。プロンプトにDecision文がなくても表示されることがあります。これは実際の過去の呼び出しの記録であり、現在のプレビューや、選択した過去の返信の再実行ではありません。互換性のあるスワイプは以前の記憶呼び出しレポートを再利用できます。1レポートにつき最大128件を、選択された結果から先に保存し、省略された件数も記録します。次の対象となるDecisionモデル呼び出し後に新しいレポートが表示され、閲覧だけではモデルにリクエストを送りません。
