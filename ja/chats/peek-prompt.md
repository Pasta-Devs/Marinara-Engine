# Peek Prompt: AIが受け取った内容を確認する

Peek Promptは、Marinara Engineが返信のためにモデルへ送った文章そのもの、または次の返信のライブプレビューを表示します。返信が期待どおりでなく、モデルが何を見たのかを知りたいときに使います。

プロンプトとは、Marinaraが組み立てて送る、指示とチャット履歴のまとまり全体です。モデルはそれを読んで返信を書きます。

## Peek Promptの開き方

**Assembled Prompt**(組み立て済みプロンプト)ウィンドウを開く方法は2つあります。

メッセージから開く場合:

1. いちばん新しいAIメッセージをタップして、アクションバーを表示します。
2. 虫眼鏡のアイコンの**Peek prompt**(プロンプトを確認)をクリックします。

このボタンは、最後のAIメッセージにだけ表示されます。それより前のメッセージには表示されません。

入力欄から開く場合(AIの返信がまだない状態でも使えます):

1. メッセージ入力欄に、次の文字列をそのまま入力します: `{{prompt}}`
2. <kbd>Enter</kbd>を押すか、**Send**(送信)をクリックします。

Marinaraはメッセージを送信せず、入力欄を空にしてウィンドウを開きます。`{{prompt_preview}}`と`{{preview_prompt}}`も同じ働きをします。

## ウィンドウに表示される内容

タイトルの隣のバッジで、どの版のプロンプトを読んでいるかがわかります。

| バッジ | 意味 |
| --- | --- |
| **Exact Text Model Request** | モデルに送られたリクエストそのものです。 |
| **Live Preview** | いま組み立てたプレビューです。 |
| **Raw Messages** | メッセージの生のリストです。 |
| **Prompt Preview** | 一般的なプレビューです。 |
| **Decision test preview** | 判断テストの回答で組み立てたプロンプトです。チャットモデルには送られていません。 |

その下の情報パネルには、サービスとモデル、推定トークン数、そして返信が終わったあとは実際のプロンプトのトークン数が表示されることがあります。トークンとは、モデルが単語の代わりに数える文章の小さなかたまりです。使われた値のタグも表示されます。**Temperature**、**Max Output Tokens**、**Thinking**、**Reasoning**、**Verbosity**、**Service Tier**、**Assistant Prefill**などのタグや、**Top P**、**Top K**、**Min P**のようなサンプリングの値です。**Service Tier**や**Assistant Prefill**などのタグとサンプリングの値は、モデルの高度な設定です。最初は気にしなくて構いません。最初のモデルが失敗し、フォールバックのモデルが返信を書いた場合は、失敗したモデルと、「key rejected」や「rate limited」のような短い理由がパネルに表示されます。

残りの部分はプロンプト本体で、折りたためるセクションに分かれています。各セクションには、そのセクションのおおまかなトークン数の見積もりが付きます。チャットのメッセージは**Chat History**の下にまとまります。保存された実際のリクエストでは、サービスが複数のチャットのターンを1つのブロックにまとめている場合があるので、各ブロックを展開してすべてのテキストを確認してください。セクションの見出しをクリックすると開閉します。

**Exact Text Model Request**は、その返信のために送られたとおりのリクエストです。自動要約やメッセージを隠す処理など、返信の後に実行された処理より前に保存されたものなので、次の返信には渡されないメッセージが含まれていることがあります。**Show current context**(現在のコンテキストを表示)をクリックすると、送信せずに、今のチャットの状態からプロンプトを組み立てます。**Show sent request**(送信したリクエストを表示)をクリックすると元に戻ります。

### プロンプトのコピー

閉じるボタンの隣にあるコピーボタンをクリックします。閉じているセクションも含め、すべてのセクションとメッセージが、送られた順にプレーンテキストとしてコピーされます。各メッセージは、`[system]`、`[user]`、`[assistant]`のように役割を示す行で始まります。保存された実際のリクエストの場合は、送られたとおりのリクエストがコピーされます。コピーしても何も送信されません。

### プロンプト内のテキスト検索

上部の**Find**(検索)フィールドを使うか、ウィンドウ内で<kbd>Ctrl</kbd>+<kbd>F</kbd>(Macでは<kbd>Cmd</kbd>+<kbd>F</kbd>)を押します。検索は大文字と小文字を区別せず、閉じたセクションやチャット履歴も含めてプロンプト全体を探します。カウンターには「2 of 5」のように現在の一致箇所が表示されます。一致箇所を移動するには、上下のボタンか、<kbd>Enter</kbd>と<kbd>Shift</kbd>+<kbd>Enter</kbd>を使います。どちらの端でも、反対側の端に戻ります。**Find**に文字が入っているあいだは、ウィンドウにメッセージの全文が表示されます。文字を消すと、セクションの表示に戻ります。

## Reply checkupで返信を点検する

Marinaraが、うまくいかなかった返信の原因らしきものを見つけると、ウィンドウのプロンプトの上に**Reply checkup**パネルが表示されます。次のような内容が表示されます。

- キャラクターカードが大きく、プロンプトの予算の大部分を占めています(**Large character card**)。
- 返信がトークンの上限に達し、文の途中で止まりました(**Cut off**)。
- モデルが目に見えるテキストを返しませんでした(**Empty reply**)。
- プロンプトに収まらなかったため、古いメッセージが送られませんでした(**N older messages not sent**)。
- ロアブックのエントリーが一致しましたが、予算に収まりませんでした(**N lorebook entries left out**)。
- プロンプトの場所を空けるために、返信の上限が下げられました(**Reply limit cut**)。

役立つ場合は、**Max output tokens**や**Lorebook token budget**など、変更すべき設定へ移動するリンクが表示されます。

## 思いがけない返信の原因を調べる

**Assembled Prompt**を開いて、次の点を確認します。

- **抜けている情報。** ロアブックのエントリー、記憶、ペルソナの内容がどのセクションにもなければ、モデルはそれを見ていません。
- **パラメーターのタグ。** **Temperature**が高いと返信がばらつき、**Max Output Tokens**が小さいと返信が途中で切れることがあります。
- **Chat History。** 必要なメッセージが正しい順序でそろっているかを確かめます。
- **トークン数。** プロンプトが大きいと、古いメッセージがモデルの上限からあふれることがあります。

そのうえで原因を直します。キャラクターカードを編集する、ロアブックのエントリーを調整する、生成の設定を変えるといった方法があります。[生成パラメーター](../prompts/generation-parameters.md)を参照してください。

方向づけされた返信の指示を読むには、メッセージの**Stored guidance**(保存された指示)を使います。[ガイド付き生成とImpersonate](guided-and-impersonate.md#read-stored-guidance)を参照してください。

## 判定文のテスト

[Decisionモデル](../connections/decision-models.md)は、ロアブックなどの機能のために、はい/いいえで答える質問に答えます。Peek Promptの中の**Decision diagnostics**(Decision診断)では、現在のチャットでのそうした質問を確認し、テストできます。

1. Peek Promptを開き、**Decision diagnostics**を探します。
2. これを開くか、**Preview inputs**(入力のプレビュー)をクリックすると、どのモデルにも問い合わせずにリクエスト本文を準備します。**Prepared request bodies**(準備したリクエスト本文)を展開すると、最近のメッセージ、展開済みの判定文、選択肢、リクエスト形式を確認できます。
3. **Test decisions**(判断をテスト)をクリックすると、対象になる質問をDecisionモデルに尋ねます。

**Test decisions**は実際のリクエストを送るので、ホスト型のモデルでは料金がかかる場合があります。チャットの返信を書いたり、エージェントを実行したり、ゲームの状態を変えたり、回答やタイマーをチャットに保存したりはしません。後のロアブックの判定文は、先の判定文に回答が得られてから初めて到達できる場合があります。明示的なテストは、通常の返信前の判断が延期される場合でも、ローカルの推論モデルを待つことがあります。これによって、通常の返信に対する設定が変わることはありません。

各結果には、スコアがあればそのスコア、はい/いいえの判定文に使うしきい値、回答が表示されます。「yes」か「no」だけを返すモデルにはその旨のラベルが付き、その回答は確率としては表示されません。Choiceの結果には、選ばれた選択肢が表示されます。保留、延期、上限超過、利用不可、失敗の判断には、それぞれ専用の説明があります。

テスト後は、下のプロンプトにテストの回答が使われます。**Show original prompt**(元のプロンプトを表示)をクリックすると最初に開いた内容に戻り、**Show tested prompt**(テストしたプロンプトを表示)でテスト版に戻ります。**Requests sent and results**(送信したリクエストと結果)には、実際のリクエスト本文と結果が、認証ヘッダーを除いて表示されます。

うまくいかなかった場合: **Could not prepare the decision test. Check the chat connection and try again.**と表示されたら、チャットに動作するモデルがあることを確認して、もう一度試してください。

テストでは、古い返信からPeek Promptを開いた場合でも、現在のチャットと設定を使います。元の判断リクエストを作り直すことはありません。対象はプロンプトの判定文とロアブックの判断で、エージェントの起動や返信後の判断は対象外です。

Advanced Memory(Marinaraの長期記憶機能。[Memory Recallとチャットの要約](../agents/memory.md)を参照)で**Use Decision model**(判断モデルを使用)がオンのときは、パネルに**Advanced Memory activity**(Advanced Memoryの動作記録)も表示されます。この保存済みレポートには、最新の記憶の呼び出しとシーン確認について、モデル、時間、スコア、選択結果、フォールバックの状態が表示されます。レポートは過去の呼び出しを記録したもので、現在のプレビューではありません。プロンプトに判定文がない場合でも表示されることがあります。互換性のあるスワイプは、以前の記憶の呼び出しのレポートを再利用できます。各レポートには、選ばれた結果を先頭に最大128件の結果が保存され、残りは件数だけが記録されます。新しいレポートは、次に対象となるDecisionモデルの呼び出しの後に表示されます。レポートを見るだけでは、モデルへのリクエストは発生しません。
