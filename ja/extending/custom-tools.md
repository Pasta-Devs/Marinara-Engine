# カスタムツールと関数呼び出し

このガイドでは、Marinara Engineのカスタムツール(Functionsとも呼びます)について説明します。カスタムツールを用意すると、AIがチャットの途中で小さな処理を実行できるようになります。決まった文章を返す、外部のWebアドレスを呼び出す、サーバー上で短いスクリプトを動かす、といったことが可能です。作り方、チャットでツール利用をオンにする手順、スクリプトツールを安全に扱う方法がわかります。

## 関数呼び出しとは

関数呼び出しは、AIがアプリに処理の実行を頼み、その結果を返信に使う仕組みです。アプリにはダイスロール、ロアブック検索、ゲーム状態の更新といった組み込みツールが最初から入っています。カスタムツールは、同じ**Function Calling**(関数呼び出し)の仕組みの中で、これらの組み込みツールと並んで扱われます。

カスタムツールは、たとえば次のような用途に向いています。

- 店の営業時間やハウスルールなど、決まった情報を返す。
- 天気やスマートホームデバイスの状態など、最新のデータを外部サービスに問い合わせる。
- 数値の足し算や独自の判定など、簡単な計算を行う。

カスタムツールはキャラクターカードには紐づきません。チャットごとにオンにするか、エージェントに紐づけて使います。エージェントとは、チャットと並行して動く補助役のことです。どちらの方法も以下で説明します。

ネイティブの関数呼び出しには、ツールに対応した接続が必要です。ClaudeとGrokのサブスクリプション経由ではネイティブのツール定義が無視されるため、Chat Settingsに利用可否の案内が表示され、その接続のツール操作は無効になります。テキストコマンドとダイスタグは引き続き利用できます。Gameチャットではツール計画用の接続を別に選べます。費用と動作については[任意のツール計画とロア検索](../game/getting-started.md#optional-tool-planning-and-lore-searches)を参照してください。

ロアブック検索は、有効なエントリーに互換性のあるベクトルがあれば意味に基づいて順位付けします。意味検索が利用できない場合、ConversationとRoleplayはテキスト照合を維持します。Gameのロア検索は個別に有効化する必要があり、ベクトルの欠落や非互換性を報告します。ブックを自動でベクトル化することはありません。

## Functionsセクション

カスタムツールの作成と管理は**Presets**(プリセット)パネルで行います。

1. 上部バーを開いて**Presets**をクリックします。
2. **Functions**(関数)セクションを探します(アイコンはレンチです)。
3. 見出しの下に**Custom function calls available from Chat Settings**という説明文が表示されます。

セクションの見出しには、3つのアイコンボタンがあります。

- **Create function**(関数の作成、プラスのアイコン)は、空のツールエディターを開きます。
- **Import functions from ZIP or JSON**(ZIPまたはJSONから関数をインポート、ダウンロードのアイコン)は、ファイル選択画面を開きます。
- **Export functions to ZIP**(ZIPへ関数をエクスポート、アップロードのアイコン)は、すべてのツールを1つのファイルに保存します。ツールが1つもないときはグレー表示になります。

一覧では、ツールごとに名前と2つの小さなラベル(種類とパラメーターの数)が表示されます。あわせて短い説明、オン/オフのスイッチ、**Edit function**(関数の編集)ボタン、**Delete function**(関数の削除)ボタンも並びます。サーバー側でスクリプトツールが無効になっている場合、**Script**ツールには黄色の**Script disabled**ラベルも付きます。有効にする方法は後述の「実行タイプ: Script」で説明します。ハンドルをつかんでドラッグすると、一覧の並び順を変更できます。並び順は表示上のものだけで、動作は変わりません。ツールがまだ1つもないときは、一覧に**No functions yet**と表示されます。

ツールの管理(作成、編集、削除、並べ替え、オン/オフの切り替え)は、アプリの保護された機能を使います。サーバーを動かしているコンピューター以外のデバイスから管理する場合は、先に管理者シークレットを保存しておく必要があります。[サーバー設定リファレンス](../CONFIGURATION.md)と、後述の「スクリプトの安全性」にある注意書きを参照してください。

## ツールの作成

次の手順でツールを作ります。

1. **Functions**セクションで**Create function**をクリックします。ツールエディターが開きます。
2. 上部の名前欄に、小文字のsnake_caseで名前を入力します。これがAIがツールを呼び出すときに使う正式な名前です。有効な名前は小文字で始まり、以降は小文字、数字、アンダースコアだけを使います。例: `check_weather`。
3. **Description**(説明)欄を入力します。AIはこの文章を読んで、いつツールを呼ぶかを判断します。AIへの指示として書いてください。例: `Get the current weather for a city the user names.`
4. ツールに必要な**Parameters**(パラメーター)を追加します(次のセクションを参照)。
5. **Execution Type**(実行タイプ)として**Static Result**、**Webhook**、**Script**のいずれかを選びます。
6. 選んだタイプに応じた欄を入力します。
7. **Save**(保存)をクリックします。ボタンの近くに緑色の**Saved**が一瞬表示されます。

覚えておきたい決まりがいくつかあります。

- 名前は1文字から100文字までです。説明は1文字から500文字までです。
- 2つのツールが同じ名前を持つことはできません。組み込みツールの名前も使えません(後述の「予約された名前」を参照)。
- 保存していない変更を残したままエディターを離れると、**Keep editing**、**Discard**、**Save & close**を選べるバナーが表示されます。

## パラメーターの設定

パラメーターは、AIがツールを呼び出すときに渡す入力値です。パラメーターごとに、名前、型、必須かどうか、説明を指定します。

1. **Parameters**グループで**Add Parameter**(パラメーターの追加)をクリックします。
2. `city`のように、パラメーターの名前を入力します。
3. ドロップダウンから型を選びます: `string`、`number`、`boolean`、`array`、`object`。
4. AIが必ずこの値を送る必要がある場合は**Required**(必須)をオンにします。
5. その値が何を意味するのかをAIに伝える説明を書きます。例: `The city name to look up, such as Tokyo.`

**Add Parameter**で行を増やせます。行を削除するには、その行のマイナスボタンを使います。名前が空のままの行は、保存時に削除されます。AIは説明を読んで何を送るべきかを学ぶので、パラメーターの説明は丁寧に書いてください。

ツールがまったく呼ばれない場合、パラメーターの設定が壊れていることがよくあります。これは主に、手で編集したファイルからパラメーターの設定が不正なツールをインポートしたときに起こります。この場合、アプリは生成時にそのツールを黙って飛ばし、サーバーログに記録を残すだけです。

## 実行タイプ: Static Result

**Static Result**ツールは、AIが呼び出すたびに決まった文章を返します。外部サービスは不要で、誰でもすぐに使えます。カードには**Returns a fixed string when called.**と表示されます。

入力欄は複数行の**Static Result** 1つだけです。ここに入力した内容が、ツール呼び出しの結果としてAIに返ります。空のままにすると、ツールは`OK`を返します。

具体例を挙げます。パラメーターなしで`store_hours`という名前のツールを作ります。**Static Result**の欄に次のように入力します。

```
We are open Monday to Friday, 9am to 5pm. We are closed on weekends.
```

これでAIが`store_hours`を呼び出すと、この文章が返り、営業時間をユーザーに伝えられます。AIはこの文章を、ツール名と送った引数とあわせて受け取ります。文章だけが単独で渡るわけではありません。

## 実行タイプ: Webhook

**Webhook**ツールは、ツール呼び出しを外部のWebアドレスへ送り、そのサービスからの応答をAIに返します。Webhookとは、データを受け取ってデータを返すWebアドレスのことです。カードには**Sends a POST request to an external URL.**と表示されます。

入力欄は**Webhook URL** 1つだけです。アプリはそのアドレスへPOSTリクエストを送ります。POSTリクエストとは、Webサービスにデータを送る方法の1つです。リクエストの本文は、構造化データを表すテキスト形式のJSONで、次のような形になります。

```
{ "tool": "your_tool_name", "arguments": { ... } }
```

サービス側はJSONまたはプレーンテキストで応答します。その応答がAIに返ります。

具体例を挙げます。`city`という必須のstring型パラメーターを1つ持つ、`check_weather`という名前のツールを作ります。**Webhook URL**の欄には、自分のサービスのアドレスを設定します。

```
https://api.example.com/weather
```

AIが`city`にTokyoを入れて`check_weather`を呼び出すと、サービスがリクエストを受け取り、天気を調べて応答します。AIはその応答をメッセージに使います。

Webhookについて知っておきたい点は次のとおりです。

- 応答のサイズは最大512 KBです。
- 1回の呼び出しにはサーバー側で決められた制限時間があります。デフォルトは60秒です。
- デフォルトでは`https://`のアドレスだけが許可されます。`localhost`や自宅ネットワークのアドレスなど、プライベートアドレスとローカルアドレスは遮断されます。ローカルアドレスを許可するには、サーバー管理者が設定をオンにする必要があります。[サーバー設定リファレンス](../CONFIGURATION.md)を参照してください。
- 呼び出しが失敗したりタイムアウトしたりしても、チャットは止まりません。AIにはエラーの結果が返ります。

## 実行タイプ: Script

**Script**ツールは、サーバー上で短いJavaScriptを実行し、その結果を返します。JavaScriptは広く使われているプログラミング言語です。カードには**Runs a JavaScript expression server-side.**と表示されます。

スクリプトツールは安全のため、デフォルトでは無効です。サーバー側で有効にしていない場合、**Script**のカードはグレー表示になり、警告が出ます。有効にするには、サーバー管理者がサーバーの`.env`ファイルに次の行を設定し、アプリを再起動します。

```
CUSTOM_TOOL_SCRIPT_ENABLED=true
```

入力欄は**Script Body** 1つだけです。スクリプトからは`args`(AIが送った値)を読み取れます。結果は必ず`return`してください。`JSON`、`Math`、`Date`も使えます。

具体例を挙げます。`x`と`y`という必須のnumber型パラメーターを2つ持つ、`add_numbers`という名前のツールを作ります。**Script Body**の欄に次のように入力します。

```
const result = args.x + args.y;
return { sum: result };
```

AIが`x`に2、`y`に3を入れて`add_numbers`を呼び出すと、ツールは合計の5を返します。スクリプトがエラーを投げた場合も停止はせず、AIにはエラーの結果が返ります。スクリプトを有効にする前に、後述の「スクリプトの安全性」を読んでください。

## 隠しチャットコンテキストを含める

**Webhook**ツールと**Script**ツールは、隠しコンテキストオブジェクトを受け取れます。これはツールの入力値としてはAIに見えない、追加のチャットデータです。ツールエディターで**Include hidden chat context**(隠しチャットコンテキストを含める)のスイッチをオンにしてください。デフォルトはオフです。

オンにすると、Webhookやスクリプトは引数とあわせて`context`の値を受け取ります。ここにはチャットのモード、使用中のペルソナ名、チャットに参加しているキャラクターの名前が入ります。保存されたチャット変数や、Game Modeであればゲームの状態も含まれます。これで、AIがすべてのデータを渡さなくても、ツール側で結果を状況に合わせられます。

## チャットでツール利用をオンにする

ツールを作っただけでは、AIはそれを使いません。チャットごとにツール利用をオンにする必要があります。

1. チャットを開き、歯車をクリックして**Chat Settings**(チャット設定)を開きます。
2. **Function Calling**セクションを開きます(アイコンはレンチです)。
3. **Enable Tool Use**(ツールの使用を有効にする)をオンにします。説明には**Allow AI to call functions (dice rolls, game state, etc.)**と表示されます。新しいチャットではデフォルトでオフです。

**Enable Tool Use**をオンにして、下にツールを追加していない場合、そのチャットでは全体で有効になっているツールをすべて使えます。つまり、ダイスロールやロアブック検索などの組み込みツールに加えて、**Functions**セクションでオンにしてあるカスタムツールがすべて対象になります。使えるツールを絞りたい場合は、個別のツールを追加します。

1. **Add Functions**(関数の追加)をクリックします。検索欄の付いた選択画面が開きます。
2. 使いたいツールにチェックを入れます。一覧には組み込みツールとカスタムツールが混在して並びます。
3. **Add Selected**(選択したものを追加)をクリックして追加します。

1つでもツールを追加すると、そのチャットでは追加したツールだけが動きます。選択画面の**New Custom Function**(新しいカスタム関数)をクリックすると、ツールエディターへ直接移動できます。選択画面の検索欄が照合するのはツール名だけで、説明は対象外です。

## エージェントへのツールの紐づけ

ツールはチャットではなく、エージェントに持たせることもできます。エージェントとは、ロアブックの管理役や音楽の選曲役のように、生成中に動く半自律的な補助役です。

1. **Agents**(エージェント)パネルを開き、エージェントを1つ開きます。
2. **Tools / Function Calling**グループを開きます。
3. そのエージェントに使わせたいツールをオンにします。

エージェントを設定した場合でも、チャットの**Function Calling**セクションで**Enable Tool Use**をオンにする必要があります。文言について1点補足します。エージェントエディターの下部には「Enable Function Calling」を有効にするようにと書かれていますが、実際にクリックするスイッチは**Enable Tool Use**です。どちらも同じ設定を指しています。エージェントについて詳しくは[カスタムエージェントの作成](../agents/custom-agents.md)を参照してください。

## スクリプトの安全性

**Script**ツールはサーバー上で実際にコードを実行するので、慎重に扱ってください。アプリは各スクリプトをサンドボックスの中で動かします。サンドボックスとは、コードにできることを制限する隔離された領域です。制限は次のとおりです。

- ネットワークにアクセスできません。スクリプトからインターネットやWebアドレスを呼び出すことはできません。
- ファイルにアクセスできません。スクリプトからサーバー上のファイルを読み書きすることはできません。
- 環境変数やサーバーの機密情報にはアクセスできません。
- 制限時間があります。長く動き続けるスクリプトは停止します。デフォルトの上限は60秒です。

この仕組みは事故を防ぎ、ネットワークとファイルへのアクセスを遮断します。ただし、オペレーティングシステムレベルの完全な隔離ではありません。ツールを作成できる人であれば、サーバーのCPUやメモリーを浪費するスクリプトを書くことは依然として可能です。スクリプトツールを有効にするのは、信頼できるサーバーだけにしてください。他の人が書いたスクリプトツールをインポートするときも注意が必要です。

別のデバイスからのツール管理も保護されています。サーバーを動かしているコンピューター以外から操作する場合は、**Settings**(設定)、**Advanced**(詳細設定)、**Admin Access**(管理者アクセス)の順に進み、管理者シークレットを保存してください。このシークレットはサーバー側の設定と一致している必要があります。サーバー側の設定については[サーバー設定リファレンス](../CONFIGURATION.md)を参照してください。

## エクスポートとインポート

ツールは別のインストール環境へ移せます。

- ツールを1つだけエクスポートするには、そのツールを開いて**Export function**(関数のエクスポート)をクリックします。`.json`ファイルとして保存されます。
- すべてのツールをエクスポートするには、**Functions**セクションで**Export functions to ZIP**をクリックします。
- インポートするには、**Import functions from ZIP or JSON**をクリックし、`.json`または`.zip`のファイルを選びます。インポートできたツールの数がメッセージで表示されます。

インポートしたWebhookツールとScriptツールは、ファイル側でどちらかの許可を求めていても、常に無効の状態で、かつ**Include hidden chat context**をオフにして保存されます。インポート後、Marinaraは実行タイプ、該当する場合はWebhookの送信先、およびファイルが要求した許可を表示します。インポートした実行型ツールを1つずつ開いて内容を確認し、信頼できる場合にだけ有効にしてください。Staticツールは、インポート元の有効/無効の状態を引き継ぎます。

既存のツールや組み込みツールと名前が重なるツールは、インポート時に飛ばされます。エージェントのパッケージにカスタムツールは含まれず、インポートもされません。信頼できる関数は別途エクスポートし、**Function Calls**で内容を確認したうえで、エージェントのインポート後に自分で紐づけてください。

## 予約された名前

カスタムツールの名前を、組み込みツールの名前と同じにはできません。組み込みの名前には`roll_dice`、`update_game_state`、`set_expression`、`trigger_event`、`search_lorebook`、`web_search`、`update_about_me`などがあります。これらを保存しようとすると、次のメッセージが表示されます。

```
"your_name" is a reserved built-in tool name.
```

2つのカスタムツールが同じ名前を持つこともできません。既に使われている名前を指定すると、同名のツールが既に存在するというメッセージが表示されます。

## トラブルシューティング

AIがツールをまったく呼んでくれない。

- チャットの**Function Calling**セクションで**Enable Tool Use**がオンになっているか確かめます。
- チャットに個別のツールを追加している場合は、目的のツールがその一覧に入っているか確かめます。
- **Functions**セクションで、そのツールのオン/オフのスイッチがオンになっているか確かめます。
- いつツールを呼ぶべきかAIが判断できるように、**Description**とパラメーターの説明をより具体的に書き直します。
- インポートしたツールの場合、パラメーターの設定が壊れているとアプリが飛ばすことがあります。パラメーターを手作業で作り直してください。

Scriptのカードがグレー表示になっている。

- このサーバーではスクリプトが無効です。管理者に`CUSTOM_TOOL_SCRIPT_ENABLED=true`を設定して再起動するよう依頼してください。[サーバー設定リファレンス](../CONFIGURATION.md)を参照してください。

Webhookが失敗する、またはタイムアウトする。

- アドレスが`https://`で始まっていて、接続できる状態か確かめます。
- 管理者がローカルアドレスを許可していない限り、ローカルアドレスは遮断されます。[サーバー設定リファレンス](../CONFIGURATION.md)を参照してください。
- 応答の遅いサービスは、60秒の制限時間に達することがあります。

スマートフォンや別のデバイスからツールを作成、編集できない。

- **Settings**、**Advanced**、**Admin Access**の順に進み、一致する管理者シークレットを保存してください。
