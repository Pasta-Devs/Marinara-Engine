# Game Modeのルールセットを作成する

ルールセットは卓上ゲームの仕組みをGame Modeに伝えます。判定で振るダイス、キャラクターシートの項目、消費するリソース、休息で回復するものを定めます。このガイドは独自のルールセットを作って共有したい方向けです。他の人が作ったルールセットで遊ぶには、[ルールセットで遊ぶ](../game/rulesets.md)から始めてください。

ルールセットは1つのJSONファイルです。コードではなくデータで、中の内容は実行されないため、インポートしてもコンピューター上で何かを実行することはありません。他の人のファイルをインポートする前に注意して読むべき部分はGame Master向けの文章です。そのルールセットを使うすべてのゲームで、モデルへ送られるためです。

## 最初に読むこと: ルールセットでできることとできないこと

ルールセットが埋められるのは、Engineがすでに理解している仕組みの設定値だけです。現在Engineは5種類の判定方式を持ち、ファイルの`resolution.kind`で選びます。

- **`dice-sum`**: ダイスを振り、シートの数値を加えて、難易度以上を目指します。d20方式、2d6に能力値を加える方式など、多くのシステムを扱えます。
- **`dice-pool`**: キャラクターの数値に応じた個数のダイスを振り、目標に届いたものを数えます。評価値がボーナスではなくダイスの個数を表す方式に対応します。

- **`dice-highest`**: プールを振って最大の出目を読むか、上位いくつかの出目を合計します。Blades in the DarkやTrophy Darkに対応します。
- **`roll-against`**: シートの数値以下(または以上)を出すように振ります。パーセンテージ制のスキルやGURPSの判定に対応します。
- **`symbol-pool`**: ナラティブダイスを組み立てて格上げし、対立するシンボルを相殺します。Genesysの判定と、Capability API 1.382以降では戦闘にも対応します。

五つすべてを[判定方式](ruleset-checks.md#resolution-kinds)で詳しく説明します。

これらの形に収まらない仕組みは、ルールセットファイルでは表現できません。対抗プールがその一例です。このような仕組みにはEngine内の新しい判定方式が必要で、JSONファイルではなくテストを伴うコードの貢献になります。必要な場合はEngineリポジトリに機能要望を開き、計算過程を示したロール例をいくつか添えて仕組みを説明してください。その例がテストになります。

Game ModeはMarinara独自の戦闘か、ルールセットの規則で戦闘を解決できます。任意の`battle`ブロックはキャラクターシートの数値をMarinaraの戦闘へ貸し出します。[戦闘への橋渡し](ruleset-combat.md#battles-lending-the-sheet-to-marinaras-combat)を参照してください。任意の`combat`ブロックは、ルールセットが戦闘を解決する方法そのものを定義します。[独自ルールの戦闘](ruleset-combat.md#combat-a-fight-your-own-rules-resolve)を参照してください。Engineは現在これらの規則で戦えます。ゲームのCombat PreferenceでClassic表示を選び、ルールセットが距離を定義する場合はTacticalの戦場も選べます。ルールセットは`combat.styles`で、ゲームで使えるスタイルを制限できます([ゲームで使えるスタイル](ruleset-combat.md#combat-a-fight-your-own-rules-resolve)を参照)。

## クイックスタート

1. 使用する判定方式に合うサンプルをコピーします。[`ember-roads.json`](https://github.com/Pasta-Devs/Marinara-Engine/blob/staging/docs/examples/rulesets/ember-roads.json)は三つの能力値を持つ小規模なシステム(2d6)です。この形式がd20や六つの能力値を前提にしていないことを示します。[`gravewatch.json`](https://github.com/Pasta-Devs/Marinara-Engine/blob/staging/docs/examples/rulesets/gravewatch.json)は三つの評価値と六つの専門技能を持つ、小さな十面ダイスプールです。大規模な例は、公式の[5e (SRD 5.1)パッケージ](https://github.com/Pasta-Devs/Marinara-Agents/tree/staging/packages/ruleset-5e-2014)を参照してください。その`ruleset.json`と`catalogs/`が、Agent Organizerによってインストールされるものです。
2. `id`を独自のものに変えます。`ember-roads`のように、小文字、数字、単独のハイフンで構成します。
3. シート、休息、Game Master向けの文章を編集します。
4. インポートします([ルールセットを試す](#trying-your-ruleset)を参照)。保存前にファイル全体を検査し、問題を行ごとに示します。
5. 新しいゲームを作成し、**Rules**(ルール)で作成したセットを選び、いくつか判定を試します。

入力中の補助を有効にするには、外側の波括弧の内側の先頭行に次を加え、エディターへJSON Schemaを指定します。

```json
"$schema": "https://raw.githubusercontent.com/Pasta-Devs/Marinara-Engine/staging/docs/extending/ruleset.schema.json",
```

スキーマは入力中のキーの誤字や型の間違いを検出します。スキルが指定する能力値など、ファイル内の名前が実在する項目を指すかは検査できません。それはインポート時に検査します。

ファイル内のどのオブジェクトにも`"$comment": "..."`を加え、メモを残せます。Engineは無視します。

## ファイルの構成

| キー | 内容 |
| --- | --- |
| `schemaVersion` | 常に`1`です。 |
| `id`, `version` | Engineが使うルールセット名と、変更を公開するたびに増やす整数です。 |
| `name` | セットアップウィザードに表示する名前です。 |
| `edition` | 任意です。版や草案を説明する1行です。 |
| `license` | 任意です。SPDX IDと、元資料が要求する帰属表示です。 |
| `coverage` | 対応範囲と、ウィザードに表示する1行の要約です。 |
| `resolution` | 判定やセーヴのロール方法です。 |
| `sheet` | キャラクターシートの全項目です。 |
| `rests` | 各休息が回復・解除するものです。 |
| `gm` | Game Masterモデルに渡す文章と、各キャラクターについて見せるシート値です。 |
| `catalogs` | 任意です。長いリストを手入力せずに済む、シート編集画面の既製項目です。 |
| `items` | 任意です。アイテムを記述する語彙です。カテゴリー、レアリティー、ステータス、スロット、お金です。 |
| `battle` | 任意です。戦闘がシートから読むものと、終了後に書き戻すものです。 |
| `combat` | 任意です。独自の戦闘解決規則と、戦闘画面が実行する内容です。 |
| `layers` | 任意です。ゲーム作成時にプレイヤーが有効にするバリエーションです。 |

ファイルは最大512 KBです(Capability API 1.340より前は256 KB)。プロンプトへ入る文章(名前、ラベル、Game Master向け文章)に改行、角括弧、二重波括弧は使えません。

シート内のID(能力値、スキル、フィールド、プールなど)は、`grit_max`のように英字で始まり、小文字、数字、アンダースコアで構成します。

## このガイドの各ページ

このページでは、ルールセットとは何か、作成の始め方、試し方、共有の方法を説明します。ガイドの残りは、内容ごとにページを分けています。

- [ルールセットの判定](ruleset-checks.md): ルールセットで判定やセーヴのダイスを振る方法。五つの判定方式、結果帯、独自の方法で振る判定、ロールを変える消費やチャーム
- [ルールセットのシート](ruleset-sheets.md): ルールセットのキャラクターシートに載せるもの。能力値、スキル、フィールドとリスト、ライブステート、負傷トラック、ペナルティ、休息、Game Master向けの文章に加え、パーティーシートと進行クロック
- [ルールセットのカタログ](ruleset-catalogs.md): シートエディターが選択画面に表示する用意済みのエントリー。カタログのヘッダー、エントリー、ルールセットが保持する値、シートコマンド、使用コマンド
- [ルールセットのエントリーの仕組み](ruleset-mechanics.md): カタログのエントリーが数値の面で何をするか。判定、休息、戦闘が読み取る、エントリーの`mechanics`ブロック
- [ルールセットのキャラクタービルダー](ruleset-character-builder.md): ガイド付きビルダー。種族とクラスから評価値、習熟、呪文、装備まで、ステップを踏んでキャラクターを作成する方法
- [ルールセットのアイテム](ruleset-items.md): パーティーが持ち運ぶもの。カテゴリー、武器、鎧、弾薬、戦利品、お金、初期装備、市場
- [ルールセットの戦闘](ruleset-combat.md): ルールセットが戦闘に関わる方法。Marinaraの戦闘にシートを貸し出す`battle`ブロックと、ルールセット独自の規則で戦闘全体を解決する`combat`ブロック、およびそのベスティアリ、盤面、リアクション、対抗判定
- [ルールセットのレイヤー、翻訳、移行](ruleset-layers-and-translations.md): プレイヤーがゲームごとにオンにするバリエーション、ルールセットの文章の翻訳、シートの変更時に値を新しいIDへ移す方法

## ルールセットを試す

コミュニティのルールセットは、インポートするエージェントと同じスイッチを使います。**Settings**(設定)>**Advanced**(詳細設定)>**Danger Zone**(危険な操作)を開き、**Allow custom Agent imports**(カスタムエージェントのインポートを許可)がオンであることを確認してください。インポートにはlocalhostからのアクセスか、設定済みの**Admin Access**(管理者アクセス)も必要です。

1. **Agents**(エージェント)パネルを開き、**Import agents**(エージェントをインポート)ボタン(パネル上部のボタン列のダウンロードアイコン)を選びます。
2. **Game Mode ruleset**(Game Modeのルールセット)を選び、JSONファイルか、`.ruleset.json`で終わるルールセットのパッケージファイルを指定します([ルールセットの共有](#sharing-your-ruleset)を参照)。
3. 確認画面を読みます。名前、バージョン、ライセンス、対応範囲、Game Master向け文章が表示されます。**Import**(インポート)を選びます。

ルールセットはパネルの**Rules**(ルール)セクションと、新しいゲームの設定ウィザードの**Rules**選択肢に表示されます。ファイルからインポートしたものは`local/<your id>`として分類するため、公式や他者のルールセットと混同することはありません。

### インポート済みルールセットの変更

インポートしたバージョンは上書きしません。ファイルを変更して同じ`version`で再インポートすると、拒否され、番号を上げるよう求められます。これは意図した動作です。ゲームは作成時の正確なバージョンに結び付くため、進行中のキャンペーンが突然別の計算方式になることはありません。

草案を作るときは、編集、`version`の更新、インポート、新しいゲームの開始を繰り返します。旧版は**Rules**セクションからルールセットを削除するまで、新版と並んでインストールされたままです。ゲームがまだ使っているルールセットを削除すると、再インポートするまでそのゲームにルールセットが見つからないと表示されます。

シートの形(項目の追加、削除、名前変更)を変えた場合は、`sheet.version`も上げてください。既存のシートは寛容に読み取ります。新しいシートにとって未知の値も保ち、ない値にはデフォルトを使います。

## ルールセットの共有

**ファイルで。** JSONファイルを友人に送ります。友人も同じ方法でインポートできます。

**パッケージファイルとして。** カタログを独立したファイルに持つ、1つのファイルに収まらないほど大きいルールセットは、`<name>.ruleset.json`という名前の1つの普通のJSONファイルとして配布します。パッケージのマニフェストとルールセットのドキュメントを、それぞれ正確なバイト列をbase64にして持ちます。

```json
{
  "format": "marinara-ruleset",
  "version": 1,
  "manifest": { "kind": ["ruleset"], "…": "the package manifest" },
  "files": {
    "ruleset.json": "<base64>",
    "catalogs/spells.json": "<base64>"
  }
}
```

マニフェストは、`ruleset.json`と各`catalogs/<id>.json`を`contributions.assets.paths`と`files`に、それぞれのサイズとsha256とともに列挙します。Pixelforgeのようなルールセットエディターがこれを作ります。**Import agents**(エージェントをインポート) → **Game Mode ruleset**(Game Modeのルールセット)がファイルを受け取り、ルールセットファイルと同じ確認画面を、各カタログとその項目数とともに表示します。中身は圧縮されていないため、自身のサイズを超えるものを持つことはありません。データとして読まれ、パッケージとしてインストールされることはありません。ほかのもの(別のキー、ほかのファイル、厳密なbase64でないかUTF-8のテキストでないドキュメント)を持つ場合、マニフェストがルールセット以上のもの(コード、権限、ほかの提供物)を含む場合、ファイルがマニフェストの列挙するものと異なる場合、`$comment`の長さが上限(2,000文字)を超えるか、`$schema`がEngine自身のスキーマ以外を指定する場合、ルールセットやカタログが読めない場合は、理由とともに拒否されます。ルールセットファイルと同じく`local/<its id>`として登録され、132 MBを上限に、12個までのカタログファイル(2 MBが各ファイルの上限)と、40個までの翻訳(8 MBが各翻訳の上限)を含められます(後述)。バージョンはルールセットとカタログを合わせたものなので、カタログを変えた場合も`version`を上げる必要があります。ルールセットのパッケージはzipでは受け付けません。

**公式エージェントカタログを通じて。** カタログで公開するルールセットは、厳密にこの形式の`<id>.ruleset.json`というルールセットのパッケージファイルで、パッケージのzipにはしません(Capability API 1.374)。マニフェストはCapability API 1.374以降を宣言するため、古いEngineには提示されません。Engineは、手動でインポートするパッケージファイルと同じ読み取り処理と検査を使い、カタログが列挙するマニフェストとの一致を確かめ、ほかのカタログパッケージと同じようにインストールします。配布物がzipのカタログのルールセットは、ダウンロード前に拒否されます。インストール済みのルールセットは引き続き動作します。

**GitHubリポジトリから。** 公開GitHubリポジトリで作業を管理している場合、リポジトリ直下の`rulesets`フォルダーに、ルールセットごとに1ファイルずつ置きます。

```text
your-repository/
  agents.json        (optional, only if you also share agents)
  rulesets/
    ember-roads.json
    another-system.json
```

ユーザーはカスタムエージェントのリポジトリ一覧から一度リポジトリを追加し、内容を確認して、後から同期して新版を取得できます。カスタムリポジトリ一覧は詳細機能で、サーバーの運用者が`ENABLE_CUSTOM_AGENT_REPOS=true`で有効にする必要があります。リポジトリ由来のルールセットは`alice/ember-roads`のように所有者名の下へ分類するため、2人の作者がどちらも`v20`という名前で公開しても競合しません。

制限は2つです。リポジトリの`rulesets`直下に置けるJSONファイルは最大32個で、超えるリポジトリは拒否されます。`local/`はファイルからインポートするルールセット用に予約しているため、`local`というアカウント名ではルールセットを公開できません。

**公式カタログで。** 広く遊ばれ、ライセンスが明確なシステムは、**Agent Organizer (エージェント管理)**(エージェントをダウンロード)を通じて全員へ提供できます。[Marinara-Agents](https://github.com/Pasta-Devs/Marinara-Agents)リポジトリへのプルリクエストで行います。構成はそこの`ruleset-5e-2014`パッケージを参考にしてください。

## ライセンス

共有する権利のあるルールの文章だけを公開してください。多くのシステムはオープンライセンスの参照文書を公開しており、複製してよいのはその文書です。ライセンスIDと、ライセンスが要求する帰属表示を`license`に入れてください。オープンライセンスでないルールブックの文章をコピーしないでください。ルールセットに主に必要なのは名前と数値で、Game Master向け文章は自分の言葉で書いてください。

## トラブルシューティング

- **インポート時に名前が存在しないと言われる。** ファイル内の何かが未宣言のIDを参照しています。削除した能力値をスキルが指定している場合などです。メッセージに該当箇所へのパスが表示されます。
- **インポート時に同じバージョンが別の内容でインストール済みと言われる。** `version`を上げて再インポートしてください。
- **設定ウィザードにルールセットが出ない。** **Allow custom Agent imports**がオンか確認してください。オフの間は、インポートしたルールセットを新しいゲームに提示しません。すでに使用しているゲームは動き続けます。
- **ゲームにルールセットが見つからないと表示される。** ゲーム作成時の正確なバージョンがインストールされていません。そのバージョンのファイルを再インポートしてください。
