# Game Modeのルールセットを作成する

ルールセットは卓上ゲームの仕組みをGame Modeに伝えます。判定で振るダイス、キャラクターシートの項目、消費するリソース、休息で回復するものを定めます。自分のシステムをGame Modeに持ち込んで共有するには、ルールセットを作成します。他の人が作ったルールセットで遊ぶには、[ルールセットで遊ぶ](../game/rulesets.md)を参照してください。

ルールセットは1つのJSONファイルです。コードではなくデータなので、中身が実行されることはなく、インポートしてもコンピューターに害を与えることはありません。他の人のファイルをインポートする前に、Game Master向けの文章を読んでください。その文章は、そのルールセットを使うすべてのゲームでモデルへ送られるためです。

## ルールセットを始める

1. 使うシステムのダイスの振り方に合うサンプルファイルをコピーします。
   - [`ember-roads.json`](https://github.com/Pasta-Devs/Marinara-Engine/blob/staging/docs/examples/rulesets/ember-roads.json)は、三つの能力値を持つ小規模な2d6システムです。この形式がd20や六つの能力値を前提にしていないことを示します。
   - [`gravewatch.json`](https://github.com/Pasta-Devs/Marinara-Engine/blob/staging/docs/examples/rulesets/gravewatch.json)は、三つの評価値と六つの専門技能を持つ、小規模な十面ダイスプールです。
   - 公式の[5e (SRD 5.1)パッケージ](https://github.com/Pasta-Devs/Marinara-Agents/tree/staging/packages/ruleset-5e-2014)は、大規模な例です。その`ruleset.json`と`catalogs/`が、Agent Organizerによってインストールされるものです。
2. `id`を自分のものに変えます。IDは`ember-roads`のように、小文字、数字、単独のハイフンで構成します。
3. コピーしたファイルをメモ帳やVS Codeなどのテキストエディターで開き、`.json`の拡張子で保存します。まず`name`を変え、次に`sheet`の能力値の名前、それから`rests`と`gm`の文章を変えます。[ファイルの構成](#parts-of-the-file)に各キーの一覧があり、[リファレンスページ](#reference-pages)にはそれらを説明するページへのリンクがあります。
4. インポートします([ルールセットを試す](#try-your-ruleset)を参照)。インポートは何かを保存する前にファイル全体を検査し、問題を行ごとに報告します。
5. 新しいゲームを作成し([Game Mode: はじめに](../game/getting-started.md)を参照)、**Rules**(ルール)で自分のルールセットを選んで、いくつか判定を試します。

うまくいかなかった場合は、[トラブルシューティング](#troubleshooting)を参照してください。

入力中にエディターの補助を受けるには、ファイルの外側の波括弧の内側の先頭行に次の行を加えます。この行はエディターにJSON Schemaを指定します。

```json
"$schema": "https://raw.githubusercontent.com/Pasta-Devs/Marinara-Engine/staging/docs/extending/ruleset.schema.json",
```

スキーマはキーの誤字や型の間違いを検出します。スキルが指定する能力値など、名前が実在するものを指しているかは検査できません。それはインポートが検査します。どのオブジェクトにも`"$comment": "..."`の行を加えて、自分用のメモを残せます。Engineはその行を無視します。

## ルールセットでできることとできないこと

ルールセットは、Engineがすでに知っている仕組みの空所を埋めるものです。Engineは5種類の判定方式を知っており、ファイルの`resolution.kind`でそのうち1つを選びます。

- **`dice-sum`**: ダイスを振り、シートの数値を加えて、難易度以上を目指します。d20方式、2d6に能力値を加える方式など、多くのシステムを扱えます。
- **`dice-pool`**: キャラクターの数値に応じた個数のダイスを振り、目標に届いたものを数えます。評価値がボーナスではなくダイスの個数を表す方式に対応します。
- **`dice-highest`**: プールを振って最大の出目を読むか、上位いくつかの出目を合計します。Blades in the DarkやTrophy Darkに対応します。
- **`roll-against`**: シートの数値以下(または以上)を出すように振ります。パーセンテージ制のスキルやGURPSの判定に対応します。
- **`symbol-pool`**: ナラティブダイスを組み立てて格上げし、対立するシンボルを相殺します。Genesysの判定と、Capability API 1.382以降では戦闘にも対応します。

五つすべてを[判定方式](ruleset-checks.md#resolution-kinds)で詳しく説明しています。

対抗プールのように、これらの形に収まらない仕組みは、ルールセットファイルでは表現できません。そうした仕組みにはEngine内の新しい判定方式が必要で、それはテストを伴うコードの貢献になります。必要な場合はEngineリポジトリーに機能要望を開き、計算過程を示したロール例をいくつか添えて仕組みを説明してください。そのロール例がテストになります。

Game Modeは、Marinara独自の戦闘か、ルールセットの規則のどちらかで戦闘を解決します。任意の`battle`ブロックは、キャラクターシートの数値をMarinaraの戦闘へ貸し出します。[戦闘への橋渡し](ruleset-combat.md#battles-lending-the-sheet-to-marinaras-combat)を参照してください。任意の`combat`ブロックは、ルールセットが戦闘そのものを解決する方法を定義します。[独自ルールの戦闘](ruleset-combat.md#combat-a-fight-your-own-rules-resolve)を参照してください。ゲームのCombat Preferenceは、Classic表示か、ルールセットが距離を定義する場合はTacticalの戦場を選びます。ルールセットは`combat.styles`で、そのルールセットを使うゲームがこれらのどれを使えるかを制限できます([ゲームで使えるスタイル](ruleset-combat.md#combat-a-fight-your-own-rules-resolve)を参照)。

## ファイルの構成

| キー | 内容 |
| --- | --- |
| `schemaVersion` | 常に`1`です。 |
| `id`, `version` | Engineが使うルールセット名と、変更を公開するたびに増やす整数です。 |
| `name` | プレイヤーが設定ウィザードで目にする名前です。 |
| `edition` | 任意です。版や草案を説明する1行です。 |
| `license` | 任意です。SPDX IDと、元資料が要求する帰属表示です。 |
| `coverage` | 対応範囲と、設定ウィザードに表示する1行の要約です。 |
| `resolution` | 判定やセーヴのロール方法です。 |
| `sheet` | キャラクターシートの全項目です。 |
| `rests` | 各休息が回復・解除するものです。 |
| `gm` | Game Masterモデルに渡す文章と、各キャラクターについて見せるシート値です。 |
| `catalogs` | 任意です。長いリストを手入力せずに済む、シートエディターが提示する既製のエントリーです。 |
| `items` | 任意です。アイテムを記述する語彙です。カテゴリー、レアリティー、ステータス、スロット、お金です。 |
| `battle` | 任意です。戦闘がシートから読むものと、終了後に書き戻すものです。 |
| `combat` | 任意です。独自の規則で戦闘を解決する方法と、そのうえで戦闘画面が実行する内容です。 |
| `layers` | 任意です。ゲーム作成時にプレイヤーがオンにする、ルールセットのバリエーションです。 |

ファイルは最大512 KBです(Capability API 1.340より前は256 KB)。プロンプトに入る文章(名前、ラベル、Game Master向けの文章)には、改行、角括弧、二重波括弧を使えません。

シート内のID(能力値、スキル、フィールド、プールなど)は、`grit_max`のように英字で始まり、小文字、数字、アンダースコアで構成します。

## ルールセットを試す

始める前に、**Settings → Advanced → Danger Zone**(設定 → 詳細設定 → 危険な操作)で**Allow custom Agent imports**(カスタムエージェントのインポートを許可)をオンにしてください。インポートしたルールセットは、インポートしたエージェントと同じ安全用のスイッチを使うため、自分でオンにするまではオフのままです。インポートには、localhostからのアクセスか、**Settings → Advanced → Admin Access**(設定 → 詳細設定 → 管理者アクセス)で設定する管理者用のシークレットも必要です。

1. **Agents**(エージェント)パネルを開き、**Import agents**(エージェントをインポート)ボタン(パネル上部のボタン列のダウンロードアイコン)を選びます。
2. **Game Mode ruleset**(Game Modeのルールセット)を選び、JSONファイルか、`.ruleset.json`で終わるルールセットのパッケージファイルを指定します([ルールセットの共有](#sharing-your-ruleset)を参照)。
3. 確認画面を読みます。名前、バージョン、ライセンス、対応範囲、Game Master向けの文章が表示されます。**Import**(インポート)を選びます。

ルールセットは、パネルの**Rules**(ルール)セクションと、新しいゲームの設定ウィザードの**Rules**の選択肢に表示されます。ファイルからインポートしたルールセットは`local/<your id>`として登録されるため、公式のルールセットや他の人のものと混同されることはありません。

### インポート済みのルールセットを変更する

インポートしたバージョンが書き換えられることはありません。変更したファイルを同じ`version`でインポートすると、インポートは拒否され、番号を上げるよう求められます。ゲームは作成時の正確なバージョンに結び付いているため、進行中のキャンペーンの計算方式が変わることはありません。

草案を作っている間は、編集し、`version`を上げ、インポートし、新しいゲームを始める、という流れを繰り返します。旧バージョンは、**Rules**セクションからルールセットを削除するまで、新バージョンと並んでインストールされたままです。ゲームがまだ使っているルールセットを削除すると、再インポートするまで、そのゲームはルールセットが見つからないと表示します。

シートの形(項目の追加、削除、名前変更)を変えた場合は、`sheet.version`も上げてください。既存のシートは寛容に読み取ります。新しいシートにとって未知の値も保ち、ない値にはデフォルトを使います。

<a id="sharing-your-ruleset"></a>

## ルールセットの共有

共有の方法は5つあります。

### ファイルとして

JSONファイルを友人に送ります。友人は同じ方法でインポートします。

### パッケージファイルとして

カタログを独立したファイルに持つ、1つのファイルに収まらないほど大きいルールセットは、`<name>.ruleset.json`という名前の1つの普通のJSONファイルとして配布します。このファイルは、パッケージのマニフェストとルールセットのドキュメントを持ち、それぞれをbase64(ファイルを普通のテキストとして書く方法)で保存します。

```json
{
  "format": "marinara-ruleset",
  "version": 1,
  "manifest": { "kind": ["ruleset"], "…": "the package manifest" },
  "files": {
    "ruleset.json": "<base64>",
    "catalogs/spells.json": "<base64>"
  }
}
```

マニフェストは、`ruleset.json`と各`catalogs/<id>.json`を`contributions.assets.paths`と`files`に、それぞれのサイズとsha256(ファイルの指紋)とともに列挙します。Pixelforgeのようなルールセットエディターがこれを作ります。**Import agents**(エージェントをインポート) → **Game Mode ruleset**(Game Modeのルールセット)がファイルを受け取り、ルールセットファイルと同じ確認画面を、各カタログとその項目数とともに表示します。

このファイルはデータとして読まれ、パッケージとしてインストールされることはありません。中身は圧縮されていないため、自身のサイズを超えるものを持つことはありません。制限は次のとおりです。

- ルールセットファイルと同じく、`local/<its id>`として登録されます。
- 上限は132 MBで、カタログファイルは12個まで(各2 MBまで)、翻訳は40個まで(各8 MBまで)です(後述)。
- バージョンはルールセットとカタログを合わせたものなので、カタログを変えた場合も`version`を上げる必要があります。
- ルールセットのパッケージはzipでは受け付けません。

次の場合は、理由とともに拒否されます。

- ほかのキーやほかのファイル、または厳密なbase64でないかUTF-8のテキストでないドキュメントを含む
- マニフェストが、ルールセットに必要な範囲を超えるもの(コード、権限、ほかの提供物)を求めている
- ファイルが、マニフェストの列挙するものと異なる
- `$comment`が2,000文字を超えるか、`$schema`がEngine自身のスキーマ以外を指定している
- ルールセットかカタログを読み取れない

### 公式エージェントカタログを通じて

カタログで公開するルールセットは、厳密にこの形式の`<id>.ruleset.json`というルールセットのパッケージファイルで、パッケージのzipにはなりません。マニフェストはCapability API 1.374以降を宣言するため、古いEngineには提示されません。Engineは、インポートするパッケージファイルと同じ読み取り処理と検査でこれを読み、カタログが列挙するマニフェストとの一致を確かめ、ほかのカタログパッケージと同じようにインストールします。配布物がzipのカタログのルールセットは、ダウンロード前に拒否されます。インストール済みのルールセットは引き続き動作します。

### GitHubリポジトリーから

公開GitHubリポジトリーで作業を管理している場合は、リポジトリー直下の`rulesets`フォルダーに、ルールセットごとに1ファイルずつ置きます。

```text
your-repository/
  agents.json        (optional, only if you also share agents)
  rulesets/
    ember-roads.json
    another-system.json
```

ユーザーはリポジトリーを一度追加し、内容を確認して、後から同期して新しいバージョンを受け取ります。カスタムリポジトリーの一覧は詳細機能です。サーバーの運用者が`ENABLE_CUSTOM_AGENT_REPOS=true`で有効にしてから、**Agents → Agent Organizer → Custom Sources**(エージェント → エージェント管理 → カスタムソース)を開きます。リポジトリー由来のルールセットは`alice/ember-roads`のようにリポジトリー所有者の名前の下に登録されるため、2人の作者がどちらも`v20`という名前のルールセットを公開しても競合しません。

制限は2つあります。リポジトリーの`rulesets`直下に置けるJSONファイルは最大32個で、それを超えるリポジトリーは拒否されます。`local/`はファイルからインポートしたルールセット用に予約されているため、`local`という名前のアカウントはルールセットを公開できません。

### 公式カタログで

広く遊ばれていて、ライセンスが明確なシステムは、**Agent Organizer**(エージェント管理)を通じて全員に提供できます。提案するには、[Marinara-Agents](https://github.com/Pasta-Devs/Marinara-Agents)リポジトリーへプルリクエストを開いてください。構成は、そこにある`ruleset-5e-2014`パッケージを参考にしてください。

## ライセンス

共有する権利のあるルールの文章だけを公開してください。多くのシステムはオープンライセンスで参照文書を公開しており、複製してよいのはその文書です。ライセンスID(SPDX ID。`CC-BY-4.0`のような短い標準名)と、ライセンスが求める帰属表示を`license`に入れてください。オープンライセンスでないルールブックの文章はコピーしないでください。ルールセットに主に必要なのは名前と数値です。Game Master向けの文章は自分の言葉で書いてください。

<a id="troubleshooting"></a>

## トラブルシューティング

- **インポート時に名前が存在しないと言われる。** ファイル内の何かが未宣言のIDを参照しています。削除した能力値をスキルが指定している場合などです。メッセージに該当箇所へのパスが表示されます。
- **インポート時に同じバージョンが別の内容でインストール済みと言われる。** `version`を上げて再インポートしてください。
- **設定ウィザードにルールセットが表示されない。** **Allow custom Agent imports**(カスタムエージェントのインポートを許可)がオンか確認してください。オフの間は、インポートしたルールセットは新しいゲームの選択肢から外れ、すでに使っているゲームは動き続けます。
- **ゲームにルールセットが見つからないと表示される。** ゲーム作成時の正確なバージョンがインストールされていません。そのバージョンのファイルを再インポートしてください。
