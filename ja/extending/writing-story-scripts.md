# Game Modeのストーリースクリプトの作成

ストーリースクリプトを使うと、作者はGame Modeのゲームの展開を方向付けられます。パーティーがある場所に着いたときに再生されるシーン、条件が満たされたときにGame Masterへ依頼すること、プレイヤーがJournal(記録)で追う目標、Game Master自身が印を付けられる場面などです。このガイドは、ストーリースクリプトを自作する方向けです。ストーリーのある世界で遊ぶには、[世界を作る](../game/getting-started.md#making-a-world)から始めてください。

ストーリースクリプトはコードではなくデータです。中身は何も実行されません。Engineは対象の世界と照らし合わせてスクリプトを検査し、ターンごとに進行させ、合わないものはすべて拒否します。

## ストーリーの置き場所

ストーリーは1つの世界に属します。その世界の場所や人物を名指しするため、書かれた対象の世界(シード、概要、手動編集)と組み合わせたときにだけ意味を持ちます。

- **ワールドファイル**(`.world.json`)の中に、`world`と並ぶトップレベルの`story`として置きます。ストーリーを知らないEngineでも、世界は読み込めます。
- Experienceの**マップパック**の中に置きます。各ワールドファイルがストーリーを持つことができ、新しいゲームはマップと一緒にストーリーを引き継ぎます。[任意のエージェントパッケージ](../development/optional-agent-packages.md)を参照してください。
- ゲームの外でライブラリーに保存されている世界の場合は、ゲームのストーリーと同じく`GET`、`PUT`、`DELETE /api/game-worlds/:id/story`を使います。その世界から始めた新しいゲームは、ストーリーも引き継ぎます。
- ゲームが始まった後は、ゲームの中に置きます。`GET`、`PUT`、`DELETE /api/game/:chatId/story`で、ストーリーを読み取り、保存、削除します。保存時には手動編集を含めてゲームの世界と照らし合わせて検査され、ストーリーが名指しするものを消してしまう手動編集は拒否されます。

新しいゲームの設定では、ファイルやマップパックから読み込んだストーリーは、世界のシードと概要が変わらない限り保持されます。

## 構造

```json
{
  "storyVersion": 1,
  "flags": [],
  "directions": [],
  "events": [],
  "cutscenes": []
}
```

IDは小文字の英字、数字、`_`、`-`からなる1から40文字で、同じリストの中で一意である必要があります。1つのストーリーに入れられるのは、フラグ64個、指示64個、イベント128個、カットシーン64個までです。ストーリー内のテキストには改行、角括弧、`{{`を含められません。タグに書き込む名前(グループ、背景)には二重引用符も含められません。こうして、ストーリーのどんな文言もGame Masterのタグになりすますことはできません。

### フラグ

フラグは、ストーリーが保持する値です。`"bool"`(trueまたはfalse)か`"number"`のどちらかです。

```json
{ "id": "trust", "kind": "number", "initial": 0, "gm": true, "note": "How far the town trusts the party" }
```

- `gm: true`を指定すると、Game Masterがそのフラグを設定できます([Game Masterのタグ](#the-game-masters-tags)を参照)。`note`はそのフラグの意味をGame Masterに伝えます。
- フラグはプレイヤーには見えません。`quest`を付けると、フラグはJournalの**クエスト目標**になります。

```json
{
  "id": "favours",
  "kind": "number",
  "initial": 0,
  "quest": { "title": "Favours", "text": "Do the town three favours", "goal": 3 }
}
```

真偽値の目標は、フラグがtrueになると達成です。数値の目標は、`goal`(指定しない場合は1)に達すると達成で、`goal`を書いておくとJournalに進み具合が表示されます。`"hidden": true`を指定した目標は、イベントで表示されるまでJournalに現れずに待機します。

### 指示

指示は、Game Masterへの常時の指示で、条件が成り立っている間は有効です。

```json
{ "id": "wary", "text": "The town is wary of strangers.", "if": [{ "flag": "trust", "is": "<", "value": 2 }] }
```

### 条件

`{ "flag": "<id>", "is": "=" | "!=" | ">" | ">=" | "<" | "<=", "value": <value> }`です。`if`リストの条件はすべて成り立つ必要があります。真偽値のフラグは`=`か`!=`でしか比較できません。

### イベント

イベントは起きる出来事です。トリガーが発動し、条件が成り立つと、アクションを実行します。

```json
{
  "id": "gates",
  "when": { "on": "arrive", "place": "p11" },
  "if": [{ "flag": "banished", "is": "=", "value": false }],
  "do": [{ "cutscene": "gates" }, { "set": "arrived", "value": true }, { "show": "key" }]
}
```

イベントは1回だけ起きます。ただし`"repeat": true`を指定した場合は繰り返します(`start`、`turn`、`day`では無視されます)。1ターンに起きるイベントは最大32個で、各イベントは1回までです。イベントはスクリプトに書かれた順に起きます。

**トリガー**(`when.on`)は次のとおりです。いずれもゲームが記録した内容から判定します。

| トリガー | 発動するタイミング |
| --- | --- |
| `start` | ゲームの最初の返信で発動します。 |
| `turn` | セッションをまたいだゲーム全体で、Game Masterの`turn`番目の返信以降に発動します。 |
| `day` | 世界の日付(Game Masterによる時間経過と移動で進みます)が`day`日目以降になると発動します。 |
| `arrive` | パーティーが`place`(場所ID)またはその内側の場所にいる間に発動します。そこへ来た方法は、そこから開始した場合、オーバーワールドでの移動、町での訪問、Game Masterが名指しした場所のいずれかです。`repeat`を指定すると、別の場所から戻ってくるたびに再び発動します。 |
| `meet` | 返信が`person`(`p11-3`のような人物ID、手動で追加した人物なら`p11-e1`)をフルネームで名指しした時点で発動します。`repeat`を指定すると、その人物を名指しした返信ごとに再び発動します。名前の検出に使うのは、現在のセッションの返信だけです。 |
| `deed` | 種類が`deed`である、パーティーの行いを世界が記録した時点で発動します。`place`を指定した場合は、その場所での行いに限ります。`repeat`を指定すると、行いを記録した返信ごとに再び発動します。 |
| `fight` | 戦闘が`outcome`で終わったときに発動します。`outcome`は`victory`、`defeat`、`flee`のいずれかです。 |
| `broke` | 戦闘で`prop`という名前の小道具が壊れたときに発動します(Capability API 1.316)。名前は大文字と小文字を区別せずに照合します。名指しできるのは、世界の戦場のいずれかに描かれた小道具だけです。 |
| `flags` | 条件が成り立ったときに発動します。`repeat`を指定すると、条件が偽から真に変わるたびに再び発動します。 |
| `gm` | Game Masterが発動させたときだけ発動します(イベントに`"gm": true`が必要です)。 |
| `step` | 移動が`place`のマス`x`、`y`(左上を0とする座標)を通ったときに発動します。`place`は、集落の町(訪問時の経路で、扉から扉まで)か、手作業で作った場所のマップ(その上での移動)です。マスはパーティーが歩いて入れるものでなければなりません。町では広場からつながる地面で、ストーリーの展開で建物が建つ可能性のある空き区画は除きます。マップでは入口からつながる床です。生成されたマップには名指しできるマスがありません。`repeat`を指定すると、移動がそのマスを通るターンごとに再び発動します。 |

手動編集でstepイベントのマスがなくなる場合(そのマスに建物を置く、マップの床を壁にするなど)、その編集は保存時にイベントを名指しして拒否されます。

自身のシーンでその人物を名指しする繰り返しの`meet`イベントや、自分が待っている行いを自ら行う繰り返しの`deed`イベントは、毎ターン自分自身を発動させてしまうため、Engineはこれを拒否します。

**アクション**(`do`)は次のとおりです。

| アクション | 内容 |
| --- | --- |
| `{ "set": "<flag>", "value": <value> }` | フラグを設定します。 |
| `{ "add": "<flag>", "amount": <number> }` | 数値フラグに加算します。 |
| `{ "tell": "<text>" }` | このターンに1回、Game Masterに何かを依頼します。 |
| `{ "cutscene": "<id>" }` | カットシーンを再生します。 |
| `{ "show": "<flag>" }` | 非表示のクエスト目標をJournalに表示します。 |
| `{ "world": { "deed": "<kind>", "group": "...", "with": "...", "place": "<place id>", "who": "..." } }` | 世界に行いを記録します。Game Master自身による記録と同じように扱われます。 |

ストーリーがアイテムを与えたり、戦闘を始めたり、パーティーを移動させたり、ゲームを終わらせたりすることはありません。これらはGame Masterとプレイヤーに任されています。必要なときは`tell`でGame Masterに依頼してください。

### カットシーン

カットシーンは、書かれたとおりにプレイヤーへ表示するか、Game Masterに語らせるかのどちらかです。

```json
{
  "id": "gates",
  "kind": "pages",
  "background": "backgrounds:generated:town-gates",
  "pages": [
    { "text": "The gates creak open." },
    { "speaker": "p11-3", "expression": "happy", "text": "Welcome, travellers." },
    { "speaker": "player", "text": "We come in peace." }
  ]
}
```

`pages`カットシーンは、Game Masterの返信の前にナレーションの中で1ページずつ再生されます。話者のないページはナレーションで、話者のあるページはその人物のせりふです。話者は世界での名前で表示され(`player`ならプレイヤーの名前)、Game Master自身の表情リストにある`expression`を付けられます。`background`は、ゲームにある背景か、`backgrounds:generated:<words>`です。後者は、画像生成がオンのときに背景を作らせます。Game Masterにはシーンが表示されたことが伝えられ、そこから続きを語ります。

```json
{ "id": "dusk", "kind": "beats", "beats": ["Lamps are lit.", "A bell tolls."] }
```

`beats`カットシーンは、そのターンにGame Masterが自分の言葉で、ビートごとに語ります。`gm`イベントのビートはイベントと一緒にGame Masterへ伝えられ、Game Masterはその場面に印を付ける返信の中でそれを語ります。そのため、`gm`イベントが使うbeatsのシーンは、Engineのイベントでも再生される場合であっても、最初からGame Masterに知られています。ビートは毎ターン伝えられるため、すべての`gm`イベントのビートは合計16,000文字までに制限されます。

<a id="the-intro-message"></a>

### 導入メッセージ

`intro`(Capability API 1.339)は、ゲームの始まり方を設定します。GMの設定画面がどのゲームにも用意している選択肢と同じものです。

```json
"intro": { "mode": "defined", "text": "The leaves have not fallen in Hollowmere for nine years.", "locked": true }
```

`"defined"`は、ゲームの最初のメッセージを`text`そのものにします。Game Masterはそのメッセージを書かず、再生成しても同じテキストになります。`"guided"`は、Game Masterが書く冒頭を方向付けるだけです。最初の返信のときだけ読むガイダンスとして渡されます。`text`は1から8000文字で、改行を含められます(ストーリーの中で改行を含められるのはこのテキストだけです)。ただし`{{`は含められず、guidedのテキストには角括弧も含められません。`locked`を指定すると、プレイヤーにはGMの設定画面で導入が表示され、変更できません。指定しない場合、導入は設定画面の欄に入力されるだけで、プレイヤーは変更したり消したりできます。最初の返信がすでに書かれているゲームや、パーティーを引き継いでいるゲームには、導入はありません。

## ストーリーの進み方

毎ターン1回、Game Masterが返信する前に、Engineはストーリーがここまでに行ったことと、このターンにもたらされるもの(移動、訪問、戦闘の終了)を読み取り、イベントを起こします。起きたことはその返信の冒頭に書き込まれます。各イベントとそれが設定した値を記録するタグと、書かれたとおりに表示されたシーンです。ストーリーは返信から読み直されるため、スワイプや再生成をすると、その返信が行ったことは取り消されます。また、ゲームの途中でストーリーを変更しても、すでに起きたことが書き換えられることはありません。ストーリーはゲームの次のセッションにも引き継がれます。

<a id="the-game-masters-tags"></a>

### Game Masterのタグ

毎ターン、Game Masterにはストーリーの値(プレイヤーには非表示)と有効な指示が伝えられます。スクリプトの残りの部分については、スクリプトがGame Masterに任せたものだけが伝えられます。つまり、`gm`イベント(その`note`と、一緒に語る`beats`を含む)と`gm`フラグ、そしてそれらのイベントのうち今は印を付けられないもの(達成済み、または条件で保留されているもの)です。Game Masterは返信の中で次のように印を付けます。

- `[story: event="<id>"]`は、条件が成り立っている`gm`イベントを発動させます(繰り返しでない限り1回だけ)。
- `[story: flag="<id>" value="<value>"]`、または数値フラグなら`add="<number>"`で、`gm`フラグを設定します。

Engineは各タグにその場で応答し(イベントは1ターンに1回まで)、それ以外のものは理由を示して拒否します。ストーリーのないゲームでは、ストーリーのタグはすべて拒否されます。Game Masterが発動させたものは、すぐに効果を持ちます(フラグや行い)。そのシーンと依頼内容は次の返信の冒頭に現れます。ただし`beats`は例外です(その場面と一緒に語るよう依頼されているためです)。Game Masterはすでにその場面自体を語っているので、`gm`イベントの`pages`は、その場面の後に続く内容として書いてください。

## ストーリーを試す

`PUT /api/game/:chatId/story`と`{ "story": { ... } }`でゲームに保存します。合わないストーリーは、すべての理由とともに拒否されます。ゲームのWorldタブにはストーリーが表示した目標が一覧で表示され、Game Masterのプロンプトには毎ターン、ストーリーの値と指示が含まれます。
